🛡️ AWS Network Security Manager

AWS European Sovereign Cloud および
31 の新規リージョンで利用可能に

📅 リリース日: 2026 年 11 月 11 日 | 提供拡大アップデート

📌 概要

AWS Network Security Manager が、AWS European Sovereign Cloud リージョンおよび追加の 31 リージョンで一般提供を開始しました。Network Security Manager は、ネットワークセキュリティポリシーの展開と適用を大規模環境で簡素化する、包括的なネットワークセキュリティ管理ソリューションです。European Sovereign Cloud では AWS WAF と AWS Shield をサポートします。

今回の拡大により、東京・大阪を含むアジアパシフィック 14 リージョンをはじめ、北米、欧州、南米、アフリカ、中東の主要リージョンで利用可能になりました。欧州のデータ主権要件に対応する組織や、マルチリージョン展開を行う組織にとって、セキュリティポリシーの一元管理を広範囲に適用できる重要なアップデートです。

❌ Before (アップデート前)
  • 限られたリージョンでのみ利用可能で、東京・大阪を含む多くのリージョンでは一元的なポリシー管理に利用できなかった
  • European Sovereign Cloud では、データ主権要件を満たしながら WAF / Shield の集中管理ができなかった
  • 未対応リージョンでは手動またはリージョンごとの個別管理が必要で、運用負荷と設定のばらつきが発生
➡
✅ After (アップデート後)
  • European Sovereign Cloud で WAF / Shield を対象としたポリシーの一元管理が可能に (データ主権要件に対応)
  • 東京・大阪を含む 31 の新規リージョンで集中管理、構成ドリフトの自動検出、修復の自動適用が可能に
  • グローバルワークロードに対して、より多くのリージョンで一貫したセキュリティ態勢を自動維持

🛠️ 設定方法

前提条件

✓AWS Organizations を利用した組織構成であること (複数アカウントへのポリシー適用を行う場合)
✓Network Security Manager を利用するリージョンがサポート対象であること
✓保護対象となる AWS WAF / AWS Shield Advanced の利用要件を満たしていること

手順

1
Network Security Manager のセットアップ

AWS マネジメントコンソールで Network Security Manager を開き、セットアップガイドに従って管理者アカウントと対象スコープを設定します。

2
セキュリティポリシーの作成

対象アカウント、OU、リソースタイプ、タグなどのスコープ条件を指定し、WAF ルールや Shield Advanced 保護を含むポリシーを定義。ポリシーはドラフト状態で検証したうえで公開します。

3
自動展開とドリフト監視の確認

ポリシー公開後、スコープ内のインターネット向けアセットへ保護が自動展開されます。コンソールで展開状況と構成ドリフトの検出・修復状況を確認します。

💡 メリット

💼 ビジネス面

✓データ主権要件への対応: European Sovereign Cloud リージョンで利用可能になり、欧州の規制要件を満たしながらセキュリティ管理を一元化できる
✓運用コストの削減: 手動のセキュリティ管理による運用負荷を削減し、セキュリティチームの工数をより付加価値の高い業務に振り向けられる
✓ガバナンスの強化: 東京・大阪を含む多数のリージョンで一貫したセキュリティポリシーを適用し、組織全体の統制を強化できる

⚙️ 技術面

✓広域での一元管理: 32 の追加リージョンにまたがる WAF ルールと Shield Advanced 保護を単一のポリシーから管理できる
✓構成ドリフトの自動修復: 意図した設定と実際の設定の乖離を自動検出・修復し、セキュリティ態勢を常に維持できる
✓新規リソースへの自動適用: ポリシー作成後に作成されたリソースにも保護が自動適用され、保護漏れを防止できる

⚠️ デメリット・制約事項

制限事項

✗European Sovereign Cloud リージョンでのサポート対象は AWS WAF と AWS Shield であり、利用可能な機能は標準リージョンと異なる場合がある
✗Network Security Manager の利用料金に加えて、AWS WAF や AWS Shield Advanced などの基盤となるファイアウォールサービスの料金が別途発生する
✗アカウント単位・リージョン単位の時間課金のため、多数のアカウント・リージョンで利用する場合はコストを事前に見積もる必要がある

考慮すべき点

⚠既に AWS Firewall Manager で WAF / Shield のポリシーを管理している場合は、Network Security Manager との役割分担や移行方針を検討する必要がある
⚠複数の保護 (WAF と Shield Advanced の両方など) を適用するアセットは、保護するファイアウォールごとに課金される点に注意が必要
⚠European Sovereign Cloud の料金は専用の料金ページ (aws.eu) で確認する必要がある

🎯 ユースケース

🗾 ユースケース 1: 東京・大阪リージョンでのマルチアカウント WAF 管理

シナリオ: 日本国内で東京・大阪リージョンに複数アカウントのワークロードを展開している企業が、各アカウントの ALB に適用する WAF ルールを一元管理したい。

手順実装例
1. Network Security Manager で組織全体のベースラインポリシーを作成
2. スコープに東京・大阪リージョンの対象 OU とリソースタイプ ALB を指定
3. ポリシーを公開し、全アカウントの ALB へ WAF ルールを自動展開

効果: アカウントごとの個別設定が不要になり、新規作成された ALB にも保護が自動適用されるため、保護漏れと設定のばらつきを防止できる。

🇪🇺 ユースケース 2: 欧州データ主権要件下でのセキュリティ統制

シナリオ: 欧州の公共部門や規制業種の組織が、AWS European Sovereign Cloud 上のワークロードに対して WAF / Shield による保護を一元的に適用したい。

手順実装例
1. AWS European Sovereign Cloud リージョンで Network Security Manager を有効化
2. インターネット向けアセットを対象とする WAF / Shield ポリシーを定義
3. 構成ドリフト検出により、ベースラインからの逸脱を自動修復

効果: データ主権要件を満たしながら、標準リージョンと同様のセキュリティポリシー管理と自動修復を実現できる。

🚨 ユースケース 3: セキュリティアドバイザリへの迅速な対応

シナリオ: 新たな脅威情報が公開された際に、グローバルに展開する全リージョンのインターネット向けアセットへ対策ルールを迅速に適用したい。

手順実装例
1. 該当ポリシーに新しい WAF ルールをドラフトとして追加
2. 検証後にポリシーを公開
3. スコープ内の全アカウント・全リージョンへ数分で展開

効果: リージョンごと・アカウントごとの手動展開が不要になり、脅威への対応時間を大幅に短縮できる。

🔗 関連サービス・機能

🔥 AWS WAF

Network Security Manager が自動展開する Web アプリケーションファイアウォール。ALB や CloudFront などへのルール適用を一元管理できる。

🛡️ AWS Shield Advanced

DDoS 保護サービス。Network Security Manager により保護対象リソースへの適用を自動化できる。

🧱 AWS Firewall Manager

WAF / Shield などのポリシーを組織全体で管理する既存サービス。Network Security Manager との役割分担の検討が必要。

🏢 AWS Organizations

マルチアカウント環境でのスコープ指定 (アカウント、OU) の基盤となるサービス。

📝 まとめ

AWS Network Security Manager が AWS European Sovereign Cloud と東京・大阪を含む 31 の新規リージョンに拡大し、グローバル規模での WAF / Shield 保護の一元管理と構成ドリフトの自動修復が広く利用可能になりました。マルチアカウント・マルチリージョンでインターネット向けワークロードを運用している場合は、既存の AWS Firewall Manager による運用との比較を含めて、Network Security Manager の採用を検討することをお勧めします。
