Amazon CloudWatch AI ファースト GA

📊 Amazon CloudWatch Omni

AI ファーストオブザーバビリティ体験が一般提供開始
🗓️ リリース日: 2026 年 9 月 23 日

💡 概要

Amazon CloudWatch Omni は、CloudWatch を進化させた AI ファーストのオブザーバビリティ体験である。アプリケーションと AI エージェントを単一の場所で観測・トラブルシューティングでき、OpenTelemetry の相互運用性と CloudWatch のスケール・信頼性を融合している。

SSO 対応のスタンドアロン Web 体験と IDE 拡張 (VS Code、Cursor、Kiro) の両方で利用でき、AWS マネジメントコンソールの外からアクセスできる点が従来との大きな違いである。中央アカウントに「スペース」を作成することで、複数の AWS アカウント・リージョン、さらに Azure などの他クラウドのテレメトリも横断的に可視化できる。

❌ Before: アップデート前の課題

  • CloudWatch の利用に AWS コンソールへのサインインが必要で、IDE や独自 URL から直接アクセスできなかった
  • アプリケーションのテレメトリと AI エージェントの品質評価が別々のツールに分断されていた
  • サービスマップや主要メトリクスの把握に手動のダッシュボード構築と SQL / 独自クエリ言語の習熟が必要だった
  • Azure など他クラウドを含む横断可視化にサードパーティ製ツールの併用が必要だった

✅ After: アップデート後の改善

  • SSO 対応の専用 URL と IDE 拡張から、コンソール外でオブザーバビリティ体験を利用可能に
  • サービス・依存関係を自動検出し、RED メトリクス (リクエストレート、エラー、レイテンシー) を設定なしで表示
  • 自然言語チャットで SQL / PromQL を自動生成、AWS DevOps Agent による根本原因調査も開始可能
  • LangGraph や CrewAI などで構築した AI エージェントをプロンプト・モデル呼び出し・ツール呼び出し単位で評価可能

複数の AWS アカウント・リージョンおよび他クラウドのテレメトリが中央アカウントのスペース配下の CloudWatch データセットに集約され、SSO 対応の Web 体験と IDE 拡張の両方からアクセスできる。

⚙️ 主要機能

📦 1. スペースによるマルチアカウント・マルチクラウドの一元可視化

  • 中央アカウントにスペースを作成し、複数の AWS アカウント・リージョンのテレメトリを横断表示
  • Azure など他クラウドのワークロードも OpenTelemetry 計装 + OTLP エンドポイントで観測可能
  • スペースは 1 つのアカウント・リージョンにマッピングされアクセス境界として機能。複数アカウントの集約は CloudWatch の集約ルールを利用

🔍 2. サービスの自動検出とゴールデンメトリクス

  • 手動設定なしでサービスと依存関係を自動検出し、アプリケーションマップとして可視化
  • 各サービスの RED メトリクス (リクエストレート、エラー、レイテンシー) を自動レポート
  • 既に CloudWatch に送信しているテレメトリは再設定なしでそのまま表示

🤖 3. AI による自然言語操作と根本原因調査

  • Omni エージェントに自然言語で質問すると SQL / PromQL クエリを自動生成して回答
  • チャットで関連テレメトリの検索、動的ビューの構築、根本原因分析を支援 (AWS DevOps Agent)
  • ガイド付きのポイント & クリック操作や Agent Toolkit for AWS からの利用にも対応
  • アラートは Slack 連携または Amazon SNS 経由で任意の宛先に通知可能

🧪 4. AI エージェント向けオブザーバビリティと評価駆動開発

  • プロンプト・モデル呼び出し・ツール呼び出しごとに応答品質を評価し、レイテンシー・エラー・トークン使用量と同じトレース上にスコアを表示
  • 本番の継続評価とデータセットへのオンデマンド評価に対応。ジャッジモデルによるカスタム評価基準の持ち込みも可能
  • リリース前に修正を検証する実験 (エクスペリメント) の実行をサポート
LangGraph CrewAI OpenAI Agents SDK Vercel AI SDK Strands

🔐 5. SSO 対応の Web 体験と IDE 拡張

  • ドメインをセットアップすると組織専用のサインイン URL が発行され、既存の ID プロバイダーでサインイン可能
  • VS Code、Cursor、Kiro 向けの無料拡張でローカルのエージェント計装・デバッグ・評価が可能。ローカル利用に AWS アカウントは不要

🚀 設定方法

✅ 前提条件

✓利用可能リージョン (米国東部 (バージニア北部)、米国西部 (オレゴン)、欧州 (アイルランド)) のいずれかを利用できること
✓ドメインのセットアップに使用する ID プロバイダー (SSO) を用意していること
✓複数アカウント・リージョンを観測する場合、CloudWatch の集約ルールを設定できる権限があること

📝 セットアップ手順

1
Omni ドメインとスペースの作成
CloudWatch コンソールから Omni のスペースを作成し、ドメイン名を選択する。ドメイン名が組織のサインイン URL となる。ID プロバイダーはスペースごとではなくドメインに対して接続する。
Bashサインイン URL の形式
# CloudWatch コンソールから Omni スペースを作成し、ドメイン名を設定する
# 設定後、以下の形式のサインイン URL が発行される
# https://<ドメイン名>.cloudwatch-omni.global.app.aws
2
SSO のセットアップとサインイン
発行されたドメイン URL に対して ID プロバイダーを接続し、既存の ID でスタンドアロンの Web 体験にサインインする。AWS マネジメントコンソールへのサインインは不要。
3
テレメトリの送信
既に CloudWatch に送信しているテレメトリは再設定なしで Omni に表示される。他クラウドのワークロードは OTLP エンドポイントに送信し、複数アカウント・リージョンは CloudWatch の集約ルールで中央アカウントに集約する。
4
IDE 拡張のインストール (エージェント開発者向け)
VS Code、Cursor、Kiro に無料の CloudWatch Omni 拡張をインストールすると、ローカルでエージェントの計装・デバッグ・評価ができる。ローカル利用に AWS アカウントは不要。
BashVS Code 拡張のインストール
# VS Code の場合、Marketplace から拡張機能をインストールする
# 拡張機能 ID: AmazonWebServices.amazon-cloudwatch-omni
code --install-extension AmazonWebServices.amazon-cloudwatch-omni

💼 ビジネス面のメリット

✓運用効率の向上: 自動検出とゴールデンメトリクスの自動表示で、ダッシュボード構築やクエリ作成の初期工数を削減
✓ツール統合によるコスト最適化: 監視・マルチクラウド可視化・AI エージェント評価を単一の体験に統合し、サードパーティ製ツールの併用を削減
✓オンボーディングの容易さ: AWS コンソールへのアクセス権を持たないメンバー (開発者、QA、サポート) もデータにアクセス可能

🛠️ 技術面のメリット

✓OpenTelemetry ネイティブ: 既存の計装を変更せず利用でき、ベンダーロックインを抑制
✓AI エージェントの品質観測: 「形式は正しいが内容が誤っている応答」を評価器で検出し、運用メトリクスと同じトレース上で確認
✓AI 支援による調査の高速化: 自然言語からのクエリ自動生成と DevOps Agent の根本原因調査でインシデント対応時間を短縮
✓既存資産との互換性: 既存のメトリクス・アラーム・ダッシュボード・API はそのまま動作し、段階的移行が可能

🚧 制限事項

✗一般提供は 3 リージョンのみ (バージニア北部、オレゴン、アイルランド)。東京リージョンは現時点で未対応
✗スペースは 1 つのアカウント・リージョンにマッピングされるため、横断観測には集約ルールによる中央化設定が別途必要
✗無料トライアルクレジット (30 日間 1,000 USD) は OpenTelemetry インジェストのみ対象、1 AWS Organization あたり 10 アカウントまで

⚠️ 考慮すべき点

⚠インジェスト・ストレージ・分析の従量課金が発生。テレメトリ量の多い環境では事前のコスト試算を推奨 (月間 5 TB 規模で約 2,393 USD)
⚠エージェント評価は Amazon Bedrock AgentCore Evaluations の料金で課金されるため、評価のサンプリング率の設計がコストに影響
⚠サインイン URL は AWS コンソール外のエンドポイントとなるため、組織のセキュリティポリシー (アクセス制御、監査) との整合確認が必要

🎯 ユースケース

🌐 ユースケース 1: マルチアカウント・マルチクラウド環境の一元監視

シナリオ: 複数の AWS アカウント・リージョンに加え、一部のワークロードを Azure で運用しており、監視ツールの分散で障害調査に時間がかかっている。

  1. 中央アカウントに Omni ドメインとスペースを作成
  2. CloudWatch の集約ルールで各アカウント・リージョンのテレメトリを中央化
  3. Azure 上のワークロードを OpenTelemetry で計装し、OTLP エンドポイントに送信
  4. アプリケーションマップで全体の依存関係と RED メトリクスを確認

✅ 効果: クラウドやアカウントの境界を越えた単一のオブザーバビリティ体験が実現し、障害の影響範囲特定と根本原因調査が高速化する。

🤖 ユースケース 2: 生成 AI エージェントの評価駆動開発

シナリオ: LangGraph で構築したカスタマーサポートエージェントが、エラーは発生していないものの誤った回答を返すことがあり、品質の定量評価と改善サイクルを確立したい。

  1. VS Code に CloudWatch Omni 拡張をインストール (AWS アカウント不要)
  2. エージェントを計装し、プロンプト・モデル呼び出し・ツール呼び出しをトレース
  3. 評価器で応答品質をスコアリングし、データセットに対するオンデマンド評価を実施
  4. 修正後にエクスペリメントを実行し、リリース前に品質改善を検証
  5. 本番リリース後は継続評価でスコアをレイテンシー・トークン使用量と併せて監視

✅ 効果: エラーレートでは検出できない品質劣化を早期に発見し、リリース前の実験による検証で本番品質のリグレッションを防止できる。

💬 ユースケース 3: 自然言語によるインシデント調査

シナリオ: オンコール担当者が SQL や PromQL に不慣れで、深夜のアラート対応時にクエリ作成に時間がかかっている。

  1. アラートを Slack に通知するよう設定
  2. アラート発報時に Omni エージェントへ自然言語で質問 (例:「直近 30 分でエラーレートが上昇したサービスとその依存先を表示して」)
  3. AWS DevOps Agent で調査を開始し、根本原因の候補を特定
  4. 調査内容をスレッド機能でチームと共有し、記録として残す

✅ 効果: クエリ言語の習熟度に依存せずに調査を進められ、平均復旧時間 (MTTR) の短縮とチーム内のナレッジ共有が実現する。

💰 料金

CloudWatch Omni の料金は「インジェスト」「ストレージ」「分析」の 3 つのディメンションで構成される (米国東部 (バージニア北部) の料金)。

📥 インジェスト

  • アプリケーションログ・カスタムログおよび OpenTelemetry メトリクス: 0.50 USD/GB
  • スパン・トレース: 0.35 USD/GB から (30 TB 超で 0.15 USD/GB)
  • クロスアカウント・リージョンの最初の集約コピーは無料、追加コピーは 0.05 USD/GB

🗄️ ストレージ

  • 標準: 0.030 USD/GB - 月
  • Intelligent Tiering 有効時、30 日間アクセスのないデータは 0.018 USD、90 日間で 0.006 USD に自動移行

📊 分析

  • ログ・トレースのクエリ: 0.005 USD/スキャン GB (月間インジェスト量の 5 倍までのスキャンは無料)
  • PromQL メトリクスクエリ: 100 万サンプルあたり 0.01 USD
  • エージェント評価: Amazon Bedrock AgentCore Evaluations の料金で課金

🎁 Omni を有効化すると、30 日間有効な 1,000 USD の無料トライアルクレジットが自動適用される (OpenTelemetry インジェストのみ対象、1 AWS Organization あたり 10 アカウントまで)。

📝 まとめ

Amazon CloudWatch Omni は、アプリケーションと AI エージェントのオブザーバビリティを AI ファーストの単一体験に統合する、CloudWatch の大きな進化である。既存の CloudWatch テレメトリを変更なしで活用でき、OpenTelemetry によりマルチクラウドにも対応する。

✓まずは無料トライアルクレジットを利用してスペースを作成し、自動検出されるアプリケーションマップと自然言語クエリを評価することを推奨
✓AI エージェントを開発しているチームは、AWS アカウント不要の IDE 拡張から評価駆動開発ワークフローを試すことが可能
