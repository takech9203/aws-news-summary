💰 Cost Optimization Hub
アイドル EC2 インスタンスを推奨事項から直接停止

AWS Cost Optimization Hub 📅 2026 年 11 月 17 日リリース

📌 概要

AWS Cost Optimization Hub で、アイドル状態の Amazon EC2 インスタンスを推奨事項から直接停止できるようになりました。 Savings opportunities ページの [Stop] ボタンから、その場でインスタンスを停止できます。

停止前の確認ダイアログでは、失われるデータ (インスタンスストア、メモリ上のデータなど) と停止後も課金が継続する項目 (EBS ボリューム、Elastic IP アドレスなど) が明示されます。 停止は終了 (terminate) ではないため EBS ボリュームは削除されず、EC2 コンソールからいつでも再起動できます。 追加のセットアップは不要で、ユーザー自身の既存の IAM 権限で実行されます。

❌ Before: コンソールの行き来が必要

  • 停止するには Cost Optimization Hub を離れて EC2 コンソールへ移動する必要があった
  • EC2 コンソールで該当インスタンスを自分で特定し直す必要があり、アカウント・リージョンをまたぐ場合は特に手間
  • 行き来の手間で対応が後回しになり、削減機会を逃しやすかった

✅ After: 単一コンソールで完結

  • Savings opportunities ページの [Stop] ボタンでその場で停止
  • 確認ダイアログで失われるデータと継続課金項目を停止前に把握
  • 追加セットアップ不要、既存の IAM 権限のみで利用可能
  • 各停止操作は AWS CloudTrail に記録され、監査可能

従来は Cost Optimization Hub と EC2 コンソールを行き来する必要がありましたが、今回のアップデートで Savings opportunities ページから確認ダイアログを経てその場で停止できるようになりました。

⚡ 主要機能

🖱️ 1. 推奨事項からの直接停止
  • Actions 列の [Stop]、または行選択で表示される分割ビューパネルの [Stop instance] から停止を実行
  • 対象はアイドル状態の EC2 インスタンスの推奨事項のみ (ライトサイジングなど他の推奨事項には非対応)
  • 停止後は Actions 列の表示が [Stopped] に変わり、次の推奨事項の対応へ進める
✅ 2. 停止前の確認ダイアログ
  • 対象インスタンス、所属アカウント、リージョンを表示
  • 失われるもの (インスタンスストアのデータ、メモリ上のデータ、自動割り当てのパブリック IPv4 アドレス) を明示
  • 停止後も課金が継続するもの (EBS ボリューム、Elastic IP アドレス) を明示
🔐 3. 既存権限での実行とガバナンス
  • 追加のセットアップ不要、ユーザー自身の認証情報で停止を実行
  • IAM ポリシーと SCP がそのまま適用され、許可されていない場合は停止が失敗
  • すべての停止操作は AWS CloudTrail に記録され、監査証跡として利用可能
🛡️ 4. 安全な停止動作
  • 停止は終了 (terminate) ではなく、EBS ボリュームは削除されない
  • 停止したインスタンスは EC2 コンソールからいつでも再起動可能
  • 停止保護が有効なインスタンスは停止できず、エラーバナーで理由を表示

🔧 技術仕様

🔑 必要な権限

操作必要な権限
推奨事項の閲覧CostOptimizationHubReadOnlyAccess 管理ポリシーなど
インスタンス状態の確認インスタンスの状態を参照する EC2 権限

🚫 停止ボタンが利用できないケース

✗Auto Scaling グループに所属、または他のサービスに管理されている (Karpenter ノード、Amazon EMR ノード、Amazon EKS Auto Mode や Amazon ECS Managed Instances が使用する EC2 マネージドインスタンスなど)
✗インスタンスがすでに存在しない
✗インスタンスが別のアカウントに属している
✗対象リージョンが応答しない

📝 IAM ポリシー例

停止操作に必要な EC2 権限を追加で付与するポリシーの例です。

JSON 停止に必要な EC2 権限の追加ポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:DescribeInstanceStatus",
        "ec2:StopInstances"
      ],
      "Resource": "*"
    }
  ]
}

🛠️ 設定方法

📋 前提条件

✓Cost Optimization Hub を有効化していること
✓AWS Compute Optimizer にオプトインしていること (アイドルリソースの推奨事項は Compute Optimizer が提供)
✓推奨事項の閲覧権限と ec2:StopInstances を含む EC2 権限を持っていること

🚀 手順

1
Cost Optimization Hub を開く

AWS Billing and Cost Management コンソールから Cost Optimization Hub を開き、Savings opportunities ページに移動します。

URLCost Optimization Hub へ直接アクセス
https://console.aws.amazon.com/costmanagement/home#/cost-optimization-hub
2
アイドルインスタンスの推奨事項を特定する

フィルターでアイドル状態の EC2 インスタンスの推奨事項を絞り込みます。Actions 列に [Stop] ボタンが表示されているものが停止可能なインスタンスです。

3
停止を実行する

Actions 列の [Stop] または分割ビューパネルの [Stop instance] を選択し、確認ダイアログで対象インスタンス・アカウント・リージョン、失われるデータ、継続課金項目を確認してから [Stop] を選択します。確認バナーが表示され、通常は数分以内に停止します。

4
停止結果を確認する

停止後、Actions 列の表示が [Stopped] に変わります。アイドルリソースの推奨事項は 1 日 1 回更新のため、推奨事項自体は最大 24 時間ページに残る場合があります。テーブルヘッダーの更新ボタンで状態を最新化できます。

👍 メリット

💼 ビジネス面

✓削減機会への即時対応: 確認からアクションまでが単一画面で完結し、コスト削減の実行までのリードタイムが短縮
✓追加コストなし: 本機能は追加料金なしで利用可能
✓監査性の確保: すべての停止操作が CloudTrail に記録され、誰がいつ停止したかを追跡可能

⚙️ 技術面

✓セットアップ不要: Hub と Compute Optimizer が有効化済みなら追加設定なしで利用可能
✓既存のガバナンスを継承: ユーザー自身の認証情報で実行され、IAM ポリシーや SCP による統制がそのまま機能
✓安全な操作設計: 終了ではなく停止で EBS は保持。停止前に影響範囲が明示され、停止保護も尊重

⚠️ デメリット・制約事項

🚧 制限事項

✗停止できるのはアイドル状態の EC2 インスタンスの推奨事項のみ (ライトサイジングなど他の推奨事項は非対応)
✗管理アカウントからメンバーアカウントの推奨事項は閲覧できるが、他アカウントのインスタンスは停止不可 (所有アカウントへのサインインが必要)
✗Auto Scaling グループ所属や、Karpenter、Amazon EMR、EKS Auto Mode、ECS Managed Instances などが管理するインスタンスは停止不可
✗スケジュール実行や自動停止の機能ではなく、停止のタイミングは都度ユーザーが判断
✗AWS GovCloud (US) リージョンと中国リージョンでは利用不可

🤔 考慮すべき点

⚠停止してもインスタンスは削除されないため、EBS ボリューム、Elastic IP アドレス、Reserved Instance / Savings Plans のコミットメントの課金は継続
⚠アイドルリソースの推奨事項は 1 日 1 回更新のため、停止済みインスタンスが最大 24 時間表示され続ける場合がある
⚠停止保護が有効な場合やオプトインリージョン未有効の場合など、停止が完了しないケースがある (エラーバナーに理由と EC2 コンソールへのリンクを表示)
⚠しきい値ベースの自動的なコスト制御が必要な場合は、AWS Budgets アクションの利用を検討

💵 料金・利用可能リージョン

💰 料金

本機能は追加料金なしで利用できます。Cost Optimization Hub 自体も無料で利用できます。

なお、インスタンス停止後も EBS ボリューム、Elastic IP アドレス、および対象インスタンスをカバーしていた Reserved Instance / Savings Plans の課金は継続する点に注意してください。

🌍 利用可能リージョン

AWS GovCloud (US) リージョンと中国リージョンを除く、すべての AWS リージョンで利用できます。

🔗 関連サービス・機能

🧠 AWS Compute Optimizer

アイドルリソースとライトサイジングの推奨事項の提供元。本機能の利用にはオプトインが必要。

🖥️ Amazon EC2

停止対象のインスタンス。停止後の再起動は EC2 コンソールから実行する。

📜 AWS CloudTrail

各停止操作を記録し、誰がインスタンスを停止したかの監査証跡を提供。

📉 AWS Budgets

しきい値ベースの自動アクションが必要な場合に利用するコスト制御機能。

🎯 まとめ

Cost Optimization Hub のアイドル EC2 インスタンス停止機能により、コスト最適化の「発見」から「実行」までが単一のコンソールで完結するようになりました。 追加のセットアップが不要で、既存の IAM 権限と CloudTrail によるガバナンスがそのまま機能するため、導入障壁は低く、すぐに活用できます。
