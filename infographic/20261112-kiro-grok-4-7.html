🤖 Kiro - Grok 4.7 モデルの提供開始

リリース日: 2026 年 11 月 12 日
Kiro New Model Grok 4.7 サポート (IDE / CLI / Crew / Web)

📋 概要

AWS が提供する AI エージェント開発環境 Kiro で、SpaceXSI の最新モデル Grok 4.7 が利用可能になりました。IDE、CLI、Crew、Web のすべてのサーフェスで本日から利用でき、Anthropic、OpenAI、SpaceXSI、主要なオープンウェイトプロバイダーのモデルを 1 つの環境で選択できます。

Grok 4.7 は、数時間に及ぶ長時間タスクへの持続力 (スタミナ) と、次のステップに進む前に成果物を検証する自己チェック能力を重視して構築されており、長いコーディング作業やターミナル作業で特に性能向上が見られます。

❌ Before (Grok 4.6 の課題)
  • 長時間のエージェント作業で序盤のミスが後続ステップに波及しやすく、Terminal-Bench 4.0 は 20.3% にとどまった
  • ハルシネーション率が AA-Omniscience テストで 34% と高め
  • フロンティア級のコーディング性能とコストのバランスで選択肢が限られていた
✅ After (Grok 4.7 の改善)
  • Terminal-Bench 4.0 が 37.6%、DeepSWE v1.1 が 71.0% へ向上し、長時間作業の信頼性が大幅改善
  • 各ステップの自己検証が Kiro のスペック駆動開発 (長いタスクリストの逐次実行) と適合
  • 500K トークンのコンテキストで、スペック、設計ドキュメント、コードベースの大部分を 1 セッションに収容可能

⚡ 主要機能

1️⃣ 全サーフェスでの Grok 4.7 サポート
  • Kiro IDE、CLI、Crew、Web のすべてで本日から利用可能
  • Pro、Pro+、Pro Max、Power、Enterprise プランで実験的 (experimental) サポートとして提供
  • モデルピッカーから「New」ラベル付きの Grok 4.7 を選択するだけで利用開始
2️⃣ 長時間エージェント作業向けの設計
  • 新しい大規模ベースモデルと、数時間かかるタスクに重みを置いた長期の強化学習により訓練
  • 自身の出力の検証能力と、長いタスクでのフルコンテキスト活用能力が向上
  • 序盤のミスが波及しやすい長時間実行で特に効果を発揮し、Kiro のスペック駆動開発と相性が良い
3️⃣ 4 段階の推論努力レベル
  • low、medium、high (デフォルト)、xhigh の 4 レベルから選択可能
  • 高いレベルほど長いタスク全体で自己チェックに使える余地が増える
4️⃣ 大規模コンテキストとマルチモーダル入力
  • 500K トークンのコンテキストウィンドウで、スペック全体、設計ドキュメント、コードベースの大部分を 1 セッションに収容可能
  • テキストと画像の入力に対応
5️⃣ 強化されたセーフガード
  • まったく新しいセーフガードスタックを搭載し、拒否応答とジェイルブレイク耐性で SpaceXSI がテストした中で最も強力なモデル
  • HackerBench v0.3 でリスクのあるデュアルユースのサイバープロンプトの通過率はわずか 3.3%。正当なセキュリティ作業をブロックすることはまれ

ステップ 1: モデルピッカーで Grok 4.7 を選択

Kiro IDE のチャットパネル、または Kiro Crew / Web / CLI のモデルピッカーを開き、「New」ラベルが付いた Grok 4.7 を選択します。

ステップ 2: 推論努力レベルを設定

タスクの性質に合わせて low / medium / high / xhigh から選択します。デフォルトは high です。クイックな調査には low、長時間のエージェント実行には xhigh を選びます。

ステップ 3: スペックを渡して実行

スペック駆動開発では、tasks.md の実装プランを Grok 4.7 に渡すと、各タスクについて「読み取り → 実装 → 自己検証 → 次のタスクへ」のループを繰り返して作業を進めます。

✓長時間作業の自動化: Kiro Crew と組み合わせることで、ログオフ後も数時間に及ぶ作業を任せられる

✓大規模コンテキスト: 500K トークンのウィンドウにより、スペック、設計ドキュメント、コードベースの大部分を 1 セッションで扱える
✓ハードウェア・電気工学分野の強み: EEBench で 64.0% と、Fable 5.1 (56.4%) や GPT-5.6 Sol (39.4%) を上回るトップスコア

⚠️ デメリット・制約事項

🚧 制限事項

✗実験的 (experimental) サポートとしての提供であり、対象は Pro、Pro+、Pro Max、Power、Enterprise プランの顧客に限られる
✗モデルのホストは us-east-1 (バージニア北部) のみ
✗クレジット倍率が 2.7 倍と高めに設定されており、200K トークンを超える長コンテキストリクエストでは 5.4 倍に倍増

🤔 考慮すべき点

⚠️Artificial Analysis の測定では、Intelligence Index タスクあたりの出力トークン数が約 38K から約 81K へ増加しており、タスクあたりのトークン消費が増える傾向がある
⚠️高い努力レベル (high / xhigh) ほど自己チェックに時間とトークンを使うため、簡単なタスクでは low / medium を選ぶ方が効率的

📝 ユースケース 1: スペック駆動での長時間コーディング

シナリオ: 大規模な機能追加をスペックに分解し、長いタスクリストを順に実装したい。

実装例Kiro IDE

選択して実装プランの実行を指示する。

効果: 各タスクの完了前に自己検証が行われるため、後続タスクへのミスの波及を抑えながら、複数時間に及ぶ実装を進められる。

🔀 ユースケース 2: 複数リポジトリへの修正の一括依頼

シナリオ: セキュリティ修正を複数のリポジトリへ適用し、それぞれプルリクエストとして受け取りたい。

実装例Kiro Web
Kiro Web で Grok 4.7 を選択し、対象リポジトリ群へのセキュリティ変更を依頼する。
セッション完了後、リポジトリごとのプルリクエストを確認する。

効果: 修正作業をハンドオフして PR として受け取れるため、横断的な修正の運用負荷を削減できる。

シナリオ: 壊れた PyTorch モデルの復旧など、ターミナル中心の調査・修復作業を自動化したい。

実装例Kiro CLI

効果: Terminal-Bench 4.0 のスコアが 20.3% から 37.6% へ大きく向上しており、ターミナル作業での成功率改善が期待できる。
