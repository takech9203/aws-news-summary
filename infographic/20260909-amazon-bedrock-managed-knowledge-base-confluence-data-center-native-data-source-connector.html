Managed Knowledge Base が
Confluence Data Center ネイティブコネクタをサポート

📅 リリース日: 2026 年 9 月 9 日 | 🧠 フルマネージド RAG サービスへセルフホスト Confluence を直接接続

📌 概要

Amazon Bedrock Managed Knowledge Base (フルマネージド型 RAG サービス) が、Confluence Data Center をネイティブデータソースコネクタとしてサポートしました。自社インフラ上でセルフホストしている Confluence Server / Data Center インスタンスに VPC 経由のプライベート接続で到達し、スペース内のページ、ブログ記事、添付ファイルを直接ナレッジベースに取り込めます。

認証情報を指定するだけで、データクローリング、メタデータ抽出、増分同期をコネクタが自動処理。カスタムのインジェストパイプラインを構築することなく、Confluence に蓄積された組織のナレッジを基盤とする社内アシスタントなどの生成 AI アプリケーションを構築できます。

❌ Before: アップデート前の課題
✗セルフホスト Confluence の取り込みにはカスタムインジェストパイプラインの構築・保守が必要
✗REST API 呼び出し、メタデータ抽出、変更差分の検出を自前で実装し、開発・運用コストが高い
✗プライベートネットワーク内への接続経路を含めて同期処理全体を独自に設計する必要
✅ After: アップデート後の改善
✓認証情報と VPC 設定を指定するだけで、ページ・ブログ記事・添付ファイルを自動取り込み
✓追加・更新・削除を増分同期でき、フルクロールの繰り返しが不要
✓スペース URL / ページ URL / MIME タイプのフィルタでクロール範囲を限定可能

💡 コネクタが VPC 設定で定義したプライベートネットワーク経路を通じてセルフホストの Confluence インスタンスに接続し、ページ、ブログ記事、添付ファイルをクロールして Managed Knowledge Base に取り込みます。取り込まれたコンテンツは、生成 AI アプリケーションからの RAG クエリで利用されます。

⚡ 主要機能

📄 ページ・ブログ記事・添付ファイルのクローリング

Confluence スペース全体を対象に、ページ、ブログ記事、それぞれの添付ファイルを取り込み可能。タイトル、著者、作成日・更新日などの一般的なドキュメントフィールドを自動検出。個人スペースのクロール可否も設定できます。

🔄 増分同期

追加・更新・削除されたコンテンツを増分同期。フルクロールを繰り返す必要がなく、Confluence 側の変更を効率的にナレッジベースへ反映します。

🎯 フィルタによるスコープ制御

スペース URL とページ URL の包含フィルタでクロール範囲を限定。MIME タイプの包含・除外フィルタでファイル種別を制御し、maxFileSizeInMegaBytes で単一ファイルの上限サイズを指定可能です。

🔐 Basic / Personal Access Token 認証

Basic 認証 (ユーザー名とパスワード) または Personal Access Token (PAT) 認証をサポート。認証情報は AWS Secrets Manager で管理し、UpdateDataSource で認証方式を後から変更することも可能です。

🔗 VPC 設定によるプライベート接続

VPC 設定で定義したプライベートネットワーク経路経由でセルフホストインスタンスに接続。アプリケーションコンテキストパス (例: /wiki) の指定や、Amazon S3 に配置した TLS 証明書による HTTPS 接続にも対応します。

🔧 技術仕様: コネクタの主な設定項目

項目詳細
データソースタイプCONFLUENCEONPREM (MANAGED_KNOWLEDGE_BASE_CONNECTOR)
認証方式Basic (BASIC) または Personal Access Token (PERSONAL_TOKEN)
認証情報の保管AWS Secrets Manager (Basic: username / password、PAT: patToken)
ネットワークVPC 設定 (vpcConfigurationId) によるプライベート接続が必須
コンテキストパスcontextPath で REST API のアプリケーションコンテキストパスを指定 (任意)
TLS 証明書certificateS3Path で S3 上の証明書を指定 (HTTPS 接続時、任意)
クロール対象ページ、ブログ記事、それぞれの添付ファイル、個人スペース
フィルタスペース URL / ページ URL の包含リスト、MIME タイプの包含・除外リスト
最大ファイルサイズmaxFileSizeInMegaBytes で単一ファイルの上限を指定 (例: "50")
同期方式追加・更新・削除を反映する増分同期

📝 データソース設定例 (CreateDataSource)

JSON confluence-onprem-connector.json 
{
    "type": "MANAGED_KNOWLEDGE_BASE_CONNECTOR",
    "managedKnowledgeBaseConnectorConfiguration": {
        "connectorParameters": {
            "type": "CONFLUENCEONPREM",
            "version": "1",
            "aclEnabled": false,
            "connectionConfiguration": {
                "authType": "BASIC",
                "secretArn": "arn:aws:secretsmanager:us-west-2:123456789012:secret:bedrock-confluence-onprem-creds",
                "contextPath": "/wiki",
                "vpcConfiguration": {
                    "vpcConfigurationId": "your-vpc-configuration-id"
                },
                "certificateS3Path": {
                    "s3BucketName": "my-cert-bucket",
                    "s3KeyName": "confluence-dc-cert.pem"
                }
            },
            "dataEntityConfiguration": {
                "crawlPage": true,
                "crawlBlog": true,
                "crawlPageAttachment": true,
                "crawlBlogAttachment": true
            },
            "filterConfiguration": {
                "inclusionSpaceUrls": ["https://confluence.example.com/spaces/ENG/"]
            }
        }
    }
}

🛠️ 設定方法

✅ 前提条件

✓Confluence Data Center インスタンスの URL を確認していること (デフォルト以外のパスの場合はコンテキストパスも確認)
✓内部ロードバランサー経由など、VPC からプライベートネットワーク経路でインスタンスに到達できること
✓クロール対象のスペース、ページ、ブログ記事すべてにアクセスできる Confluence アカウントまたは PAT を用意していること
✓認証情報を Secrets Manager のシークレット (ナレッジベースと同じリージョン) に保存し、ARN を控えていること
✓HTTPS で接続する場合、TLS 証明書を Amazon S3 バケットに保存していること (任意)
✓ナレッジベースの IAM ロールに、データソースへの接続に必要な権限が含まれていること

📋 手順

1
VPC 接続を設定する

Confluence Data Center インスタンスに到達できる VPC 設定をナレッジベースに作成し、VPC 設定の ID を後続のステップで使用します。

2
認証情報を AWS Secrets Manager に保存する
Bash シークレットの作成 
# Basic 認証の場合
aws secretsmanager create-secret \
  --name bedrock-confluence-onprem-creds \
  --secret-string '{"username":"YOUR_CONFLUENCE_USERNAME","password":"YOUR_CONFLUENCE_PASSWORD"}'

# Personal Access Token 認証の場合
aws secretsmanager create-secret \
  --name bedrock-confluence-onprem-creds \
  --secret-string '{"patToken":"YOUR_PERSONAL_ACCESS_TOKEN"}'

Basic 認証は username と password、PAT 認証は patToken をキーとして保存し、出力される ARN を次のステップで使用します。

3
Confluence Data Center データソースを作成する
Bash CreateDataSource 
aws bedrock-agent create-data-source \
  --name "Confluence-DataCenter-connector" \
  --knowledge-base-id "your-knowledge-base-id" \
  --data-source-configuration file://confluence-onprem-connector.json

PAT 認証を使用する場合は authType を PERSONAL_TOKEN に変更します。CreateDataSource は非同期で実行され、ステータスが CREATING → AVAILABLE に遷移すると作成完了です。マネジメントコンソールからも同様の設定が可能です。

4
データソースを同期する

同期を実行して Confluence のコンテンツをナレッジベースに取り込みます。以降は増分同期により、追加・更新・削除が自動反映されます。

✓社内ナレッジの活用促進: ドキュメント、ランブック、チーム Wiki を AI エージェントの基盤情報として活用
✓コスト効率の向上: フィルタで必要なコンテンツのみを取り込み、ナレッジベースを目的に集中
⚙️ 技術面
✓フルマネージドな同期処理: クローリング、メタデータ抽出、増分同期を自動処理し運用負荷を削減
✓プライベート接続: インターネット非公開のセルフホストインスタンスにも VPC 経由でセキュアに接続
✓柔軟な認証と証明書対応: Basic / PAT 認証、コンテキストパス指定、S3 上の TLS 証明書に対応

⚠️ デメリット・制約事項

🚫 制限事項

✗ドキュメントレベルの ACL をサポートしていない。クエリできる認証済みユーザーは、クロールされたすべてのコンテンツを参照可能
✗Confluence Cloud コネクタと異なり、アーカイブ済みスペース・ページのクロールは非対応
✗接続には VPC 設定が必須。VPC から Confluence Data Center インスタンスへ到達できるネットワーク構成が前提

🤔 考慮すべき点

⚠ACL 非適用のため、機密コンテンツを含む場合は包含フィルタで取り込み範囲を制限する設計が必要
⚠クロール用アカウントには対象のスペース、ページ、ブログ記事すべてへのアクセス権限が必要
⚠ホスト型の Confluence Cloud (SaaS) の場合は、Confluence Cloud 用コネクタを使用
⚠公式発表に利用可能リージョンの明記がないため、利用予定リージョンでの提供状況の確認が必要

🎯 ユースケース

1️⃣ エンジニアリングドキュメントに基づく社内アシスタント

シナリオ: 設計ドキュメントや技術仕様を Confluence Data Center で管理し、エンジニアからの技術的な質問に自動回答するアシスタントを構築。

  1. エンジニアリングスペースの URL を inclusionSpaceUrls に指定
  2. crawlPage と crawlPageAttachment を true に設定して設計書と添付資料を取り込み
  3. Bedrock の基盤モデルと組み合わせて社内チャットアシスタントを構築

✨ 効果: 最新の設計ドキュメントに基づく回答を即座に得られ、有識者への問い合わせやドキュメント検索の時間を削減。

2️⃣ ランブックを活用した運用支援エージェント

シナリオ: 障害対応手順やランブックを Confluence で管理し、インシデント発生時に適切な手順を素早く参照できる AI エージェントを構築。

  1. 運用スペースの URL を inclusionSpaceUrls に指定してランブックのみを取り込み
  2. inclusionMimeTypes で必要なファイル種別に限定
  3. エージェントが「データベース接続エラーの対応手順は」といった質問に該当ランブックの内容で回答

✨ 効果: 手順確認が迅速になり MTTR の短縮に寄与。増分同期により手順書の更新も自動反映。

3️⃣ 社内ブログ・ナレッジ共有の横断検索

シナリオ: 複数チームが Confluence のブログ機能で発信する技術ナレッジや事例を、自然言語で横断的に検索・要約。

  1. crawlBlog と crawlBlogAttachment を true に設定してブログ記事を取り込み
  2. 対象チームのスペース URL を inclusionSpaceUrls に指定
  3. RAG クエリで過去の事例や知見を要約して提示

✨ 効果: チームをまたいだ知見の再利用が進み、重複した調査や検討を削減。
