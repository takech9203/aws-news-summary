⚡ Kiro 設定のホットリロード
とリソース継承制御

Kiro v2.10.0
📅 リリース日
2026 年 6 月 26 日

📌 概要

Kiro v2.10.0 では、MCP (Model Context Protocol) のイテレーションにおける摩擦を除去し、 カスタムエージェント作成者がコンテキストをより細かく制御できるようになりました。中心となるのは 2 つの機能です。

♻️ 設定のホットリロード

エージェント設定と MCP 設定をディスクに保存した瞬間にライブ反映。影響を受けたサーバーのみ再起動し、会話コンテキストを保持します。

🎛️ リソース継承制御

新しい chat.disableInheritingDefaultResources 設定で、カスタムエージェントがデフォルトリソースを継承しないよう制御できます。

Kiro は AWS が提供するエージェント型 IDE であり、これらの改善は MCP サーバーやカスタムエージェントを頻繁に編集する開発者にとって有用です。

🔄 アップデート前後の比較

❌ Before (アップデート前)

  • ⚠️設定変更の反映にセッション再起動が必要
  • ⚠️再起動すると会話履歴やコンテキストが消失
  • ⚠️v2.7.0 以降、デフォルトリソースの継承を無効化できなかった

✅ After (アップデート後)

  • ✨ディスクに保存するだけで変更が即座に反映
  • ✨セッション再起動が不要、会話コンテキストを保持
  • ✨chat.disableInheritingDefaultResources で継承を無効化可能

設定保存時のホットリロードフロー。差分を検出し、変更があれば影響を受けたサーバーのみを再起動し、会話コンテキストを保持したままセッションを継続します。

🚀 主要機能

♻️ MCP とエージェント設定のホットリロード

  • エージェント設定・MCP 設定をディスクに保存すると変更がホットリロードされる
  • 設定編集、新しいエージェントファイルの追加、mcp.json の変更が再起動なしで反映
  • 影響を受けたサーバーのみが再起動され、会話コンテキストは保持
  • 差分は順序に依存しないため、環境変数の並べ替えだけでは再起動しない

🎛️ カスタムエージェントのリソース継承制御

  • 新設定 chat.disableInheritingDefaultResources で、デフォルトの steering / skills / AGENTS.md の継承を無効化
  • true にすると、カスタムエージェントのみ実行時にグローバルリソースが取り込まれない
  • v2.7.0 以降の自動継承動作を、設定で明示的に無効化できる

📝 設定例

JSON デフォルトリソースの継承を無効化 
{
  "chat.disableInheritingDefaultResources": true
}

この設定を true にすると、カスタムエージェントはデフォルトの steering、skills、AGENTS.md を継承しなくなります。

🔧 設定方法

前提条件

  • ✅Kiro v2.10.0 以降がインストールされていること
  • ✅MCP サーバーまたはカスタムエージェントを使用していること
  • ✅継承を無効化する場合は、カスタムエージェントのみを運用する構成であること

ステップ 1: 設定ファイルを編集して保存する

mcp.json やエージェント設定ファイルを編集してディスクに保存すると、Kiro が変更を検出し、影響を受けた MCP サーバーのみを自動的に再起動します。セッションの再起動は不要で、会話コンテキストはそのまま保持されます。

ステップ 2: デフォルトリソースの継承を無効化する

JSON settings 
{
  "chat.disableInheritingDefaultResources": true
}

カスタムエージェントのみを実行し、グローバルなデフォルトリソースを取り込みたくない場合に設定します。これにより、意図しないグローバルリソースの継承を防げます。

💡 メリット

📈 ビジネス面

  • 開発効率の向上: 再起動不要でイテレーションが高速化
  • コンテキストの維持: 会話履歴を失わず作業の中断を低減
  • 制御性の向上: 意図した構成での運用が容易に

🔬 技術面

  • 最小限の再起動: 影響サーバーのみ再起動しシステム全体への影響を抑制
  • 順序非依存の差分判定: 環境変数の並べ替えで不要な再起動が発生しない
  • 明示的な継承制御: グローバルリソースの継承を明示的に無効化

⚠️ デメリット・制約事項

  • 📍ホットリロードの対象はエージェント設定と MCP 設定。それ以外の設定変更の挙動は本リリースの対象範囲外
  • 📍chat.disableInheritingDefaultResources を true にすると steering / skills / AGENTS.md が継承されないため、これらに依存する運用では注意が必要
  • 📍デフォルトリソースの継承は v2.7.0 以降の動作。無効化前にカスタムエージェントが必要なリソースを個別保持しているか確認
  • 📍本機能の利用には Kiro v2.10.0 以降が必要

🎯 ユースケース

1. MCP サーバー設定の反復的な調整

シナリオ: 新しい MCP サーバーの追加や既存サーバー設定を試行錯誤しながら調整したい。

⚡ 効果: mcp.json を保存するだけで即反映。会話コンテキストを保持したまま素早く反復できる。

2. カスタムエージェントの追加

シナリオ: 作業中に新しいカスタムエージェントを追加したい。

⚡ 効果: セッションを継続したまま新しいエージェントが利用可能になり、作業を中断せずに済む。

3. カスタムエージェント専用環境の構築

シナリオ: グローバルなデフォルトリソースを取り込まず、カスタムエージェントのみで完結する環境を構築したい。

⚡ 効果: デフォルトの steering / skills / AGENTS.md が継承されず、意図したリソースのみで動作する。

📝 まとめ

Kiro v2.10.0 は、設定のホットリロードによって MCP とエージェントのイテレーションを高速化し、会話コンテキストを保持したまま設定変更を即座に反映できる重要なアップデートです。 あわせて chat.disableInheritingDefaultResources 設定により、カスタムエージェントのリソース継承をより細かく制御できるようになりました。 MCP サーバーやカスタムエージェントを頻繁に編集する開発者は、Kiro を v2.10.0 以降に更新してこれらの機能を活用することをお勧めします。
