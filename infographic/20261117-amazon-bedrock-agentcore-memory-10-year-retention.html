🧠 AgentCore Memory の短期メモリ保持期間が最大 10 年に拡張

📅 リリース日: 2026 年 11 月 17 日 | 機能: 短期メモリの最大 10 年保持サポート

📝 概要

Amazon Bedrock AgentCore Memory で、短期メモリ (short-term memory) のイベントを 最大 10 年間保持できるようになりました。従来の上限は 1 年間でしたが、 今回のアップデートにより、短期メモリをエージェントの会話・対話の長期的な記録として利用できます。

コンプライアンスや監査の要件で対話記録の長期保存が求められる場合、数か月ぶりに戻ってきたユーザーに過去のコンテキストを提供したい場合、 エージェントが過去のセッションを振り返る必要がある場合などで特に有効です。

保持期間はメモリリソース単位で設定され、イベント作成時点の設定値が各イベントに個別に適用されます。 設定を変更しても、既存イベントの保持期間は変わりません。

⚙️ 主要機能

1️⃣ 短期メモリの最大 10 年保持

保持期間の上限が 1 年から 10 年 (3,650 日) に拡張。CreateMemory / UpdateMemory API の eventExpiryDuration パラメータで日数を指定します。有効範囲は最小 3 日、最大 3,650 日です。

2️⃣ イベント作成時点での保持期間適用

保持期間はメモリリソースに設定し、イベント作成時にそのイベントへ適用。変更後に作成されたイベントにのみ新しい設定が適用され、既存イベントは元の保持期間を維持します (延長不可、失効後の復元不可)。

3️⃣ 長期記録としての短期メモリの活用

コンプライアンス・監査向けの会話記録の長期保存、数か月以上の間隔を空けて戻るユーザーへのコンテキスト提供、エージェントによる過去セッションの振り返り (ルックバック) に活用できます。

🔀 短期メモリと長期メモリの保持設定の違い

メモリ種別保持設定説明
短期メモリ (raw イベント) eventExpiryDuration セッション内のターンごとの対話イベントを保持。今回のアップデートで最大 3,650 日に拡張
長期メモリレコード recordExpiryDurationDays (最小 31 日) 戦略ごとに設定する TTL。未設定の場合はレコードが失効しない

🛠️ 設定方法

✅ 前提条件

✓Amazon Bedrock AgentCore Memory が利用可能なリージョンであること
✓bedrock-agentcore-control:CreateMemory または UpdateMemory を実行できる IAM 権限があること
✓AWS SDK、AWS CLI、または AgentCore コンソールが利用できること
1
メモリリソースの作成時に保持期間を指定する
BashAWS CLI
aws bedrock-agentcore-control create-memory \
  --name "ComplianceAgentMemory" \
  --event-expiry-duration 3650

eventExpiryDuration に 3,650 日 (10 年) を指定して新しいメモリリソースを作成します。このリソースに書き込まれるイベントは、作成時点から 10 年間保持されます。

2
既存メモリリソースの保持期間を更新する
BashAWS CLI
aws bedrock-agentcore-control update-memory \
  --memory-id <memory-id> \
  --event-expiry-duration 3650

この変更は更新後に作成されるイベントにのみ適用され、既存イベントは元の保持期間を維持する点に注意してください。

3
設定を確認する
BashAWS CLI
aws bedrock-agentcore-control get-memory \
  --memory-id <memory-id> \
  --query "memory.eventExpiryDuration"

メモリリソースの現在の eventExpiryDuration 設定値を確認します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓コンプライアンス・監査対応: 標準機能だけで長期保存要件に対応でき、外部アーカイブの仕組みが不要
✓ユーザー体験の向上: 数か月以上間隔を空けて戻るユーザーにも過去の対話コンテキストに基づいた応対を提供
✓運用コストの削減: 会話履歴のエクスポート・再取り込みといった独自実装の開発・保守が不要

🔩 技術面のメリット

✓シンプルな設定: eventExpiryDuration の値を変更するだけで拡張可能
✓予測可能な挙動: 保持期間はイベント作成時に確定し、設定変更が既存データに影響しない
✓過去セッションの参照: 長期間にわたる過去セッションのイベントをルックバック可能

🚧 制限事項

✗保持期間の変更は変更後に作成されたイベントにのみ適用され、既存イベントの保持期間は延長できない
✗失効したイベントは復元できない
✗保持期間の上限は 3,650 日 (約 10 年)

⚠️ 考慮すべき点

⚠保持期間中は標準の短期メモリストレージ料金が発生し続けるため、長期保持はコストとのトレードオフ
⚠個人情報を含む場合は保持ポリシーやデータ保護規制 (保存期間・削除要件) との整合性を確認
⚠長期的な知識の抽出・要約が目的なら、長期メモリ戦略の利用が適している場合がある

💰 料金と利用可能リージョン

💵 料金

短期メモリの保持期間自体に追加料金はありませんが、データを保持している期間は標準の短期メモリストレージ料金が継続して発生します。保持期間を延長するほどストレージコストが累積するため、要件に応じた期間設定が重要です。詳細は Amazon Bedrock AgentCore の料金ページを参照してください。

🌍 利用可能リージョン

Amazon Bedrock AgentCore Memory が利用可能なすべての AWS リージョンで利用できます。
