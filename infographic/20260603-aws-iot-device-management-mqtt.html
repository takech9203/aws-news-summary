📡 Connectivity Status API MQTT セッションデータ追加

IoT デバイスフリートの接続性トラブルシューティングと監査機能を大幅強化

2026 年 6 月 3 日

📋 概要

AWS IoT Device Management の Connectivity Status API に MQTT セッションデータが追加された。IoT デバイスフリート全体の接続性の問題をトラブルシューティングし、接続パターンを監査することが可能になる。

Connectivity Status API は AWS IoT Core の GetConnection API と完全に同等の機能を持つようになった上、データを無期限に保存 (GetConnection API は 30 分間のみ) という大きな優位性を持つ。

Before / After

Before

  • 接続ステータス、タイムスタンプ、切断理由のみ取得可能
  • MQTT セッション詳細情報にアクセス不可
  • ソケット情報は GetConnection API (30 分保持) でのみ確認可能
  • 長期的な接続情報の分析が不可能

After

  • MQTT セッションタイムアウト・有効期限を確認可能
  • ソース/デスティネーション IP、ポート、VPC エンドポイント ID 取得
  • 接続情報を無期限に保存
  • IAM ポリシーによるきめ細かなアクセス制御

⚡ 主要機能

1. MQTT セッションデータの取得

セッションタイムアウト値、セッション有効期限、KeepAlive 期間、Clean Session フラグ、クライアント ID を取得可能

2. ソケットレベル詳細情報

ソース/デスティネーション IP アドレスとポート番号、クライアント VPC エンドポイント ID を取得。IAM ポリシーによるきめ細かなアクセス制御対応

3. 無期限データ保持

デバイス切断後も接続情報を無期限に保存。GetConnection API の 30 分間保持と比較して大幅な改善。長期的な接続パターン分析と監査を実現

4. GetConnection API との完全互換性

AWS IoT Core の GetConnection API と同等のデータを提供。Thing 名ベースでのクエリに対応し、データ保持期間の優位性を維持

🛠️ 設定方法

前提条件

✓デバイスが AWS IoT Core Thing Registry に登録されていること
✓AWS IoT Device Management が有効化されていること
✓適切な IAM 権限が設定されていること

Step 1: Thing の接続データを取得

Bash 基本的な接続情報の取得 
aws iot get-thing-connectivity-data \
  --thing-name "my-iot-device"

Step 2: ソケット情報を含めて取得

Bash ソケットレベル詳細情報の取得 
aws iot get-thing-connectivity-data \
  --thing-name "my-iot-device" \
  --include-socket-information

Step 3: Fleet Indexing でフリート全体の接続性を検索

Bash 切断状態デバイスの検索 
aws iot search-index \
  --query-string "connectivity.connected:false"

Step 4: Fleet Indexing にソケット情報のインデックスを追加

Bash インデックス構成の更新 
aws iot update-indexing-configuration \
  --thing-indexing-configuration '{
    "thingIndexingMode": "REGISTRY_AND_SHADOW",
    "thingConnectivityIndexingMode": "STATUS",
    "filter": {
      "connectivity": {
        "includeSocketInformation": ["GET_THING_CONNECTIVITY_DATA"]
      }
    }
  }'

IAM ポリシー設定例

JSON GetThingConnectivityData の許可ポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "iot:GetThingConnectivityData",
      "Resource": "arn:aws:iot:*:*:thing/*"
    }
  ]
}

ソケット情報を含むリクエストの場合、includeSocketInformation パラメータを true に設定し、対応する IAM 権限が必要。

🎯 ユースケース

1. 大規模 IoT フリートの接続問題トラブルシューティング

シナリオ: 製造工場で数千台のセンサーデバイスが稼働し、一部が間欠的に切断される問題が発生。

Bash 切断パターンの分析 
# 切断デバイスの詳細情報を取得
aws iot get-thing-connectivity-data \
  --thing-name "factory-sensor-042" \
  --include-socket-information

# Fleet Indexing で切断パターンを分析
aws iot search-index \
  --query-string "connectivity.connected:false AND connectivity.disconnectReason:MQTT_KEEP_ALIVE_TIMEOUT"

効果: KeepAlive タイムアウトが切断原因であることを特定し、ファームウェアの設定を最適化。IP アドレス情報からネットワーク機器の障害箇所も特定可能。

2. セキュリティ監査とコンプライアンス

シナリオ: 医療 IoT デバイスを運用し、規制要件として接続ログの長期保持と不正アクセス検知が必要。

Bash 接続履歴と不正アクセス検出 
# 特定デバイスの接続履歴を確認
aws iot get-thing-connectivity-data \
  --thing-name "medical-device-001" \
  --include-socket-information

# sourceIp が許可リストにない場合にアラートを発行

効果: 接続情報が無期限に保持されるため、過去の接続パターンの異常を遡及的に調査可能。VPC エンドポイント ID による接続元の特定も容易。

3. MQTT セッション最適化

シナリオ: バッテリー駆動の IoT デバイスで、セッション有効期限と KeepAlive の設定を最適化してバッテリー寿命を延長。

Bash セッション設定の確認と比較 
# デバイスのセッション設定を確認
aws iot get-thing-connectivity-data \
  --thing-name "battery-sensor-100"

# Fleet 全体のセッション設定を検索して比較
aws iot search-index \
  --query-string "thingTypeName:battery-sensor"

効果: フリート全体のセッション設定を可視化し、KeepAlive 値の最適化によりバッテリー消費を削減。Clean Session の設定状況も一括で確認可能。

⚖️ メリット / デメリット

✅ ビジネス面のメリット

  • 接続問題の迅速なトラブルシューティングで運用コスト削減
  • 無期限保持により監査要件・コンプライアンス対応が容易
  • IP アドレスと VPC エンドポイント追跡で不正アクセス検出

✅ 技術面のメリット

  • MQTT セッションパラメータの可視化でデバッグ効率向上
  • 無期限データ保持でトレンド分析・季節パターン把握
  • IAM ポリシーで最小権限の原則を適用

⚠️ 制限事項・考慮点

  • ソケット情報の取得には追加の IAM 権限設定が必要
  • デバイスが Thing Registry に登録されている必要がある
  • Fleet Indexing でソケット情報を利用するには、明示的にインデックス構成を更新する必要がある
  • ソケット情報は機密性が高いため、IAM ポリシーの適切な管理が重要
  • 無期限データ保持に伴うストレージコストへの影響を確認する必要がある
  • GetConnection API と Connectivity Status API の使い分けを理解する必要がある
