Amazon Bedrock 📅 2026 年 10 月 30 日

🏛️ AWS GovCloud (US) で OpenAI GPT-5.6 が bedrock-runtime に対応

Responses / Chat Completions / Converse API のサポートと Cross-Region Inference による 2 リージョン自動ルーティング

📝 概要

Amazon Bedrock が、AWS GovCloud (US) において OpenAI GPT-5.6 モデル (Terra および Luna) を bedrock-runtime エンドポイントでサポートしました。 Responses API、Chat Completions API、Converse API の 3 つの API が利用可能になり、あわせて Cross-Region Inference にも対応しました。

🧩 Responses API
💬 Chat Completions API
🔁 Converse API

Cross-Region Inference は、推論リクエストを 2 つの GovCloud (US) リージョン間で自動的にルーティングする機能です。 ルーティングが GovCloud (US) 内で完結するため、米国のデータ主権を維持したままスケールでき、 需要急増時にも高いスループットと冗長性を確保できます。さらに bedrock-runtime 上で動作するため、 ログ記録、メトリクス、コスト配賦といった既存のアカウントレベル統制をそのまま適用できます。

❌ アップデート前の課題
✗GovCloud (US) では OpenAI GPT モデルを bedrock-runtime の Responses / Chat Completions / Converse API で利用できなかった
✗単一リージョンのキャパシティに依存し、需要急増時のスループット確保や冗長性の担保が難しかった
✗高可用性には複数リージョンへの振り分けやキャパシティ管理を自前で実装する必要があった
✅ アップデート後の改善
✓GovCloud (US) で GPT-5.6 (Terra / Luna) を 3 つの API から呼び出せるようになった
✓Cross-Region Inference により 2 リージョン間の自動ルーティングで高スループットと冗長性を追加実装なしで獲得
✓モデル呼び出しログ、CloudWatch メトリクス、Cost Explorer などの既存統制をそのまま利用可能

アプリケーションからのリクエストは bedrock-runtime エンドポイントの 3 つの API のいずれかで受け付けられ、 Cross-Region Inference が 2 つの AWS GovCloud (US) リージョン間で自動的にルーティングします。 利用状況はログ、メトリクス、コストレポートに統合されます。

⚙️ 主要機能

🤖 OpenAI GPT-5.6 モデルの bedrock-runtime エンドポイント対応
  • GovCloud (US) で GPT-5.6 (Terra および Luna) が bedrock-runtime エンドポイントで利用可能に
  • ネイティブな OpenAI API (Responses / Chat Completions) に加え、Bedrock 統一 API の Converse API をサポート
  • 既存の Bedrock アプリケーションと同じエンドポイント、同じ運用基盤で OpenAI モデルを利用可能
🔀 Cross-Region Inference による自動ルーティング
  • 推論リクエストを 2 つの GovCloud (US) リージョン間で自動ルーティング
  • 複数リージョンのキャパシティ管理をユーザー側で行わずに、より高いスループットを実現
  • リクエストは GovCloud (US) 内で完結し、米国のデータ主権を維持したままスケール可能
  • 需要急増時にも Bedrock キャパシティへの幅広いアクセスと高いスループットを確保
🛡️ アカウントレベル統制との統合
  • 利用状況は Bedrock モデル呼び出しログ (S3 または CloudWatch Logs に配信可能) に記録
  • CloudWatch メトリクスで呼び出し数、トークン数、レイテンシー、スロットリング、エラーを監視
  • Cost Explorer / Cost and Usage Report でモデル別にコストを明細化し、支出をモデル単位で把握

🔀 API の使い分け

API特徴
Responses APIOpenAI ネイティブの API 形式。OpenAI SDK ベースの既存コードを活かしやすい
Chat Completions APIOpenAI ネイティブのチャット形式 API。OpenAI 互換アプリケーションからの移行に適する
Converse APIBedrock の統一 API。モデルプロバイダーに依存しない共通インターフェースでマルチモデル構成に適する

🛠️ 設定方法

✅ 前提条件

✓AWS GovCloud (US) アカウントを保有していること
✓Amazon Bedrock で対象の OpenAI モデルへのアクセスが有効化されていること
✓呼び出し元の IAM プリンシパルに bedrock-runtime の呼び出し権限 (例: bedrock:InvokeModel) が付与されていること
1
モデルカードの確認

Amazon Bedrock User Guide で GPT-5.6 (Terra および Luna) のモデルカードを確認し、モデル ID や Cross-Region Inference 用の推論プロファイル ID を把握します。公式発表でも、利用開始にあたってモデルカードの確認が案内されています。

2
Converse API での呼び出し
Bash Converse API で OpenAI モデルを呼び出し 
aws bedrock-runtime converse \
  --region us-gov-west-1 \
  --model-id <モデルカードに記載の推論プロファイル ID> \
  --messages '[{"role": "user", "content": [{"text": "こんにちは"}]}]'

Cross-Region Inference を利用する場合は、モデル ID として推論プロファイル ID を指定します。具体的な ID はモデルカードで確認してください。

3
ログとメトリクスの確認
Bash CloudWatch メトリクスの確認例 
# CloudWatch メトリクスの確認例 (呼び出し数)
aws cloudwatch list-metrics \
  --region us-gov-west-1 \
  --namespace AWS/Bedrock

モデル呼び出しログを有効化している場合、利用状況が S3 または CloudWatch Logs に配信されます。上記コマンドで Bedrock 名前空間のメトリクス一覧を取得し、呼び出し数やトークン数などの監視項目を確認できます。

⚖️ メリット・制約事項

💼 ビジネス面のメリット

✓データ主権の維持: ルーティングが GovCloud (US) 内で完結し、米国のデータ主権要件を満たしながら最新の OpenAI モデルを活用できる
✓コストの可視化: Cost Explorer と CUR でモデル別に支出が明細化され、部門やワークロード単位のコスト配賦が容易
✓需要急増への対応: 需要スパイク時にも 2 リージョンのキャパシティを活用でき、サービスレベルを維持しやすい

🔧 技術面のメリット

✓運用負荷の削減: リクエスト振り分けやキャパシティ管理の自前実装が不要
✓既存統制との統合: 他の Bedrock モデルと共通の運用・監視基盤をそのまま利用可能
✓API の選択肢: OpenAI ネイティブ API と Converse API を用途に応じて使い分け可能

🚧 制限事項

⚠️Cross-Region Inference の対象は、OpenAI モデルが提供されている AWS リージョンに限られる
⚠️GovCloud (US) 内の Cross-Region Inference は 2 つの GovCloud (US) リージョン間のルーティングであり、商用リージョンとの間ではルーティングされない
⚠️対象モデルは GPT-5.6 (Terra / Luna) であり、利用前にモデルカードで仕様の確認が必要

💭 考慮すべき点

⚠️コンプライアンス要件上、処理されるリージョンの範囲が GovCloud (US) 内に限定されることを関係者に説明できるようにしておく
⚠️推論プロファイル ID の指定方法や利用可能な機能の詳細は、モデルカードおよび Cross-Region Inference のドキュメントで確認を推奨

💡 ユースケース

🏛️ ユースケース 1: 政府機関向け生成 AI アシスタント

シナリオ: 米国政府機関や公共部門向けの SaaS を GovCloud (US) で運用しており、データ主権要件を満たしたまま最新の OpenAI モデルで文書要約や質問応答機能を提供したい。

実装例:

  1. GovCloud (US) で GPT-5.6 のモデルアクセスを有効化
  2. Converse API で呼び出すアプリケーションを実装
  3. Cross-Region Inference の推論プロファイルを指定して冗長性を確保
✨ 効果: データを GovCloud (US) 内に保ちながら、高いスループットと冗長性を備えた生成 AI 機能を提供できる。
🔄 ユースケース 2: OpenAI 互換アプリケーションの GovCloud 移行

シナリオ: 商用環境で OpenAI の Chat Completions API を利用して構築したアプリケーションを、規制要件のために GovCloud (US) へ移行したい。

実装例:

  1. エンドポイントを bedrock-runtime の Chat Completions API に変更
  2. 認証を AWS IAM ベースの認証に置き換え
  3. モデル ID を GPT-5.6 のモデルカード記載の値に変更
✨ 効果: OpenAI ネイティブ API の形式を維持したまま、アプリケーションロジックの大きな変更なしに GovCloud (US) へ移行できる。
📈 ユースケース 3: 需要変動の大きいワークロードのスループット確保

シナリオ: 月次の報告書作成時期などに推論リクエストが集中するワークロードで、単一リージョンのキャパシティではスロットリングが懸念される。

実装例:

  1. Cross-Region Inference の推論プロファイルを使用して呼び出し
  2. CloudWatch メトリクスでスロットリングとレイテンシーを監視
  3. モデル呼び出しログを S3 に配信して利用傾向を分析
✨ 効果: 2 つの GovCloud (US) リージョンのキャパシティを自動的に活用し、需要スパイク時にも高いスループットを維持できる。

💰 料金と利用可能リージョン

💵 料金

処理した入出力トークン数に基づく従量課金です。モデル別の支出は AWS Cost Explorer および AWS Cost and Usage Report で明細化されます。GPT-5.6 (Terra / Luna) の具体的な単価および Cross-Region Inference 利用時の料金の詳細は、Amazon Bedrock の料金ページで確認してください。

🌎 利用可能リージョン
  • GPT-5.6 (Terra / Luna) の bedrock-runtime 対応: AWS GovCloud (US) リージョン
  • Cross-Region Inference (OpenAI モデル): OpenAI モデルが Amazon Bedrock で提供されているすべての AWS リージョンで利用可能

🔗 関連サービス・機能

→Amazon Bedrock Converse API: モデルプロバイダーに依存しない統一 API。OpenAI モデルを含む複数モデルを共通インターフェースで呼び出せる
→Amazon CloudWatch: 呼び出し数、トークン数、レイテンシー、スロットリング、エラーのメトリクス監視に使用
→Amazon S3 / CloudWatch Logs: Bedrock モデル呼び出しログの配信先として使用
→AWS Cost Explorer / AWS Cost and Usage Report: モデル別のコスト分析と配賦に使用

🎯 まとめ

AWS GovCloud (US) で OpenAI GPT-5.6 モデル (Terra / Luna) が bedrock-runtime エンドポイントの Responses、Chat Completions、Converse の 3 つの API で利用可能になり、 Cross-Region Inference による 2 リージョン間の自動ルーティングにも対応しました。 データ主権要件を維持しながら高スループットかつ冗長な生成 AI 基盤を構築できるため、 政府機関や規制業界のワークロードを GovCloud (US) で運用しているユーザーは、 モデルカードと Cross-Region Inference のドキュメントを確認のうえ、推論プロファイルを用いた構成への移行を検討することを推奨します。
