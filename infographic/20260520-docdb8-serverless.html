DocumentDB 8.0 でのサーバーレス提供開始

📋 概要

Amazon DocumentDB のサーバーレスオプションが、DocumentDB 8.0 エンジンで利用可能になった。これまでサーバーレスは DocumentDB 5.0 でのみ提供されていたが、今回のアップデートにより DocumentDB 8.0 の高度な機能をサーバーレス環境で活用できるようになった。

対象ユーザーは、MongoDB 6.0/7.0/8.0 互換アプリケーションを運用しており、インフラ管理の負荷を軽減しつつ最新のデータベース機能を活用したい開発者やアーキテクトである。

DocumentDB 8.0 Serverless は、アプリケーションから MongoDB 互換ドライバー経由でアクセスし、DCU による自動スケーリングコンピュート層と 3 つの AZ にまたがる分散ストレージ層で構成される。

🚀 主要機能

📊 新クエリプランナーによる最大 7 倍の集約パイプライン高速化
高度なパイプライン最適化により集約クエリのレイテンシーを大幅に削減。複雑なクエリパターンでの性能向上が期待でき、サーバーレス環境でも同等のクエリ最適化が適用される。
🔍 並列ベクトルインデックス構築による最大 30 倍の高速化
ベクトル検索インデックスの構築時間を大幅に短縮。Amazon Bedrock や Amazon SageMaker からのベクトルエンベディングの格納と検索を高速に実行。RAG アプリケーションの構築が容易になる。
📦 辞書ベース圧縮による最大 5 倍の圧縮率向上
ストレージ使用量を大幅に削減。サーバーレスのストレージコスト (GB 単位課金) の最適化に直結し、データ量の多いワークロードでの TCO 削減効果が高い。
🔄 MongoDB 6.0/7.0/8.0 互換性
MongoDB 8.0 アプリケーションからの移行を直接サポート。コリエーション (照合順序) とビューのサポート追加。6 つの新しい集約ステージと 3 つの新しい集約演算子を提供。
📝 テキストインデックス v2
メールアドレス、URL、ファイルパスなどの構造化フォーマットをパース可能。テキスト検索の精度と柔軟性が向上。

🛠️ 設定方法

前提条件

  • AWS アカウントと適切な IAM 権限
  • VPC およびサブネットグループの設定
  • MongoDB 互換ドライバー (pymongo, mongosh など)

Step 1: サーバーレスクラスターの作成

Bash AWS CLI - クラスター作成 
aws docdb create-db-cluster \
  --db-cluster-identifier my-docdb8-serverless \
  --engine docdb \
  --engine-version "8.0" \
  --serverless-v2-scaling-configuration MinCapacity=0.5,MaxCapacity=16 \
  --master-username admin \
  --master-user-password <password> \
  --vpc-security-group-ids sg-xxxxxxxx \
  --db-subnet-group-name my-subnet-group

Step 2: サーバーレスインスタンスの追加

Bash AWS CLI - インスタンス追加 
aws docdb create-db-instance \
  --db-instance-identifier my-docdb8-instance-1 \
  --db-cluster-identifier my-docdb8-serverless \
  --db-instance-class db.serverless \
  --engine docdb

Step 3: 接続確認

Bash MongoDB Shell - 接続 
mongosh --host my-docdb8-serverless.cluster-xxxx.us-east-1.docdb.amazonaws.com:27017 \
  --tls \
  --tlsCAFile global-bundle.pem \
  --username admin \
  --password <password>

⚠️ 制約事項・考慮点

  • サーバーレスの最大 DCU に上限があり、極めて大規模なワークロードではプロビジョンドインスタンスが必要な場合がある
  • コールドスタート時にレイテンシーが増加する可能性がある
  • サーバーレスではインスタンスタイプの直接指定不可。特定のハードウェア要件がある場合は不向き
  • 予測可能で安定した高負荷ワークロードでは、プロビジョンドインスタンスの方がコスト効率が高い場合がある
  • DocumentDB 5.0 からの移行にはエンジンバージョンのアップグレードが必要

💡 ユースケース

🤖 生成 AI アプリケーションのベクトル検索基盤

チャットボットや RAG システムで、ユーザーの質問に応じて関連ドキュメントをベクトル検索で取得。トラフィックは業務時間帯に集中し、夜間や週末は低負荷。

JavaScript ベクトル検索クエリ例 
db.documents.aggregate([
  {
    $vectorSearch: {
      queryVector: embeddingVector,
      path: "embedding",
      numCandidates: 100,
      limit: 10,
      index: "vector_index"
    }
  }
]);
✨ 業務時間帯のみ DCU がスケールアップし、夜間はコストを抑制。並列ベクトルインデックス構築により大量ドキュメント追加時のインデックス更新も高速。

🛒 E コマースのカタログ管理システム

商品カタログをドキュメントデータベースで管理し、セール期間中のトラフィック急増に対応。通常時は低負荷だがセール時には数十倍のアクセスが発生。

JavaScript 集約パイプライン例 
db.products.aggregate([
  { $match: { category: "electronics", inStock: true } },
  { $lookup: { from: "reviews", localField: "_id",
               foreignField: "productId", as: "reviews" } },
  { $addFields: { avgRating: { $avg: "$reviews.rating" } } },
  { $sort: { avgRating: -1 } },
  { $limit: 20 }
]);
✨ セール時に自動スケールアウトし、通常時はコストを最小化。新クエリプランナーにより集約パイプラインが最大 7 倍高速化。

📡 IoT デバイスデータの時系列蓄積

数万台の IoT デバイスからのテレメトリデータを蓄積。データ送信頻度がデバイスの稼働状況により大きく変動する。

JavaScript テレメトリデータ処理例 
db.telemetry.insertMany(deviceReadings);

// 時間帯別の集約分析
db.telemetry.aggregate([
  { $match: { timestamp: { $gte: startTime, $lt: endTime } } },
  { $group: { _id: { $hour: "$timestamp" },
              avgTemp: { $avg: "$temperature" } } }
]);
✨ 辞書ベース圧縮により反復的な IoT データのストレージコストを最大 5 倍削減。可変データ流入量にサーバーレスが自動対応。
