Amazon Application Recovery Controller

🔄 ARC Region Switch に
Amazon RDS Switchover Read Replica 実行ブロックが登場

📅 リリース日: 2026 年 8 月 20 日 ｜ Oracle Data Guard 構成の RDS for Oracle リージョンフェイルオーバーを自動化

📌 概要

ARC Region Switch に RDS Switchover Read Replica 実行ブロックが追加され、 Oracle Data Guard を使用してクロスリージョンリードレプリカを構成した Amazon RDS for Oracle のリージョン間フェイルオーバーを、 Region Switch プランのステップとして自動化できるようになった。

計画的なフェイルオーバーではデータ損失ゼロのスイッチオーバーを、 緊急時には速度優先のリードレプリカ昇格を自動実行する。 ネイティブなクロスアカウントサポートにより、別アカウントの RDS インスタンスの復旧も一元管理できる。

😰 Before (アップデート前)

  • Oracle Data Guard 構成のロール入れ替えやレプリカ昇格を手動で実施する必要があった
  • レプリケーション状態やバックアップ設定の確認など多くのチェック作業を伴い、復旧時間が長引く要因に
  • 複数アカウントにまたがる RDS インスタンスの復旧を単一プランで一元管理することが困難

😊 After (アップデート後)

  • Region Switch プランに実行ブロックを組み込み、ロール切り替えを自動化
  • Graceful パスはデータ同期を確認してデータ損失ゼロを実現
  • Ungraceful パスはレプリカを直接昇格し復旧速度を優先
  • エンジン互換性・レプリケーション状態などをプラン評価時に自動検証
  • クロスアカウントサポートで組織全体を単一プランで一元管理

Graceful パスでは検証後にスイッチオーバーを実行してデータ損失ゼロを保証し、 Ungraceful パスではリードレプリカを直接昇格して復旧速度を優先する。

GRACEFUL (デフォルト)

🛡️ データ損失ゼロ

  • SwitchoverReadReplica でロールを入れ替え
  • 同期・バックアップ・保留メンテナンスを事前確認
  • 計画フェイルオーバー / DR 訓練向け
UNGRACEFUL

⚡ 復旧速度を優先

  • PromoteReadReplica でレプリカを直接昇格
  • 同期未完了時はデータ損失の可能性あり
  • リージョン障害時の緊急フェイルオーバー向け

⚙️ 主要機能

1️⃣ Graceful スイッチオーバー (デフォルト)

  • ターゲットレプリカが available になるまで待機し、Oracle 19c 以降のレプリカが有効なスタンバイモード (mounted または open-read-only) であることを検証
  • レプリケーションがアクティブであること、スタンバイで自動バックアップが有効であることを確認
  • ブロッキングとなる保留中メンテナンスを確認した上で SwitchoverReadReplica を呼び出しスタンバイを昇格
  • 元のプライマリで Multi-AZ が有効だった場合、新プライマリでも Multi-AZ を有効化して構成を一致させる

2️⃣ Ungraceful 実行 (リードレプリカ昇格)

  • promoteReadReplica 動作を指定すると PromoteReadReplica でレプリカを直接昇格
  • 同期が未完了の場合はデータ損失の可能性があるが、復旧速度を優先できる
  • 昇格後、バックアップ保持期間・優先バックアップウィンドウ・Multi-AZ 設定を復元
  • 動作を指定しない Ungraceful 実行は Graceful スイッチオーバーパスにフォールバック

3️⃣ プラン評価時の自動検証

  • DB インスタンス ARN の有効性と各リージョンでのインスタンス存在を確認
  • リードレプリカ関係の有効性、Oracle 19c 以降であること (Aurora やカスタムエンジンは対象外)、エンジンバージョン一致を検証
  • オプショングループが無関係なインスタンスと共有されていないことを確認 (スイッチオーバー時の問題を防止)
  • 検証失敗時は警告メッセージを返し、コンソールまたは API で確認可能

4️⃣ ネイティブクロスアカウントサポート

  • Region Switch プランとは別アカウントの RDS インスタンスの復旧を管理可能
  • 組織全体の復旧管理を単一プランに集約できる

🛠️ 設定方法

前提条件

✓ARC Region Switch プランが作成済みであること
✓RDS for Oracle 19c 以降で、クロスリージョンリードレプリカ (Oracle Data Guard) が構成されていること
✓スタンバイが mounted または open-read-only モードで、自動バックアップが有効であること
✓プランの実行ロールに RDS スイッチオーバー操作に必要な IAM ポリシーが設定されていること

手順

1

実行ロールへの IAM ポリシー設定

プランの実行ロールに RDS スイッチオーバーに必要な権限を付与する。詳細は サンプルポリシーのドキュメントを参照。

2

実行ブロックの設定

ARC コンソールで Region Switch プランに実行ブロックを追加し、Step name、Step description (任意)、 各リージョンの DB Instance ARN (すべてのリージョン分が必須)、Timeout を入力して Save step を選択。

3

プランの評価と検証警告の確認

保存するとプラン評価として設定を自動検証。エンジンバージョン、レプリケーション状態、バックアップ設定、保留中メンテナンスなどのチェックに失敗した場合は警告が返されるため、コンソールまたは API で確認して構成を修正する。

💪 メリット

📈 ビジネス面

✓RTO の短縮と予測可能性: ロール切り替えの自動化により復旧時間を予測可能な範囲に収められる
✓運用負荷の軽減: 手動のスイッチオーバー手順やチェック作業が不要になり、障害対応時の負担が減少
✓組織全体の一元管理: クロスアカウントサポートで複数アカウントの復旧を単一プランで管理

🔬 技術面

✓データ損失ゼロの切り替え: Graceful パスは同期確認後に昇格し、計画フェイルオーバーでのデータ損失を防止
✓自動検証による安全性: 互換性・レプリケーション・バックアップ・メンテナンスを事前検証し失敗リスクを低減
✓柔軟な障害対応: 緊急時は promoteReadReplica で速度優先の復旧が可能
✓構成の自動復元: 切り替え後に Multi-AZ やバックアップ設定を元の構成に合わせて復元

⚠️ デメリット・制約事項

制限事項

✗対象は RDS for Oracle 19c 以降のみ (Aurora は Aurora Global Databases 実行ブロックを使用)
✗RDS Custom は対象外
✗スタンバイは mounted または open-read-only モードかつ自動バックアップ有効 (保持期間 1 以上) が必須
✗プラン内の各リージョンに対して DB インスタンス ARN の指定が必須

考慮すべき点

⚠Ungraceful 実行では、レプリケーションが完全に同期していない場合にデータ損失が発生する可能性がある
⚠Ungraceful 実行後は元のレプリケーション関係が解消されるため、フェイルバックにはレプリカの再構築が必要
⚠オプショングループを無関係なインスタンスと共有していると問題が発生する可能性があるため、プラン評価の警告を確認する
⚠クロスアカウント構成では IAM ロールの信頼関係と権限を適切に管理する必要がある

🎯 ユースケース

1. 基幹系 Oracle データベースの計画的リージョン切り替え

シナリオ: Oracle Data Guard でセカンダリリージョンにリードレプリカを構成した基幹系システム。DR 訓練やリージョンメンテナンスに合わせて、データ損失なしで計画的にリージョンを切り替えたい。

Text実装例
Region Switch プランのアクティブ化ワークフローに
RDS Switchover Read Replica 実行ブロックを追加

- Step name: switchover-oracle-primary
- DB Instance ARN for us-east-1: arn:aws:rds:us-east-1:123456789012:db:oracle-primary
- DB Instance ARN for us-west-2: arn:aws:rds:us-west-2:123456789012:db:oracle-replica
- Timeout: 60

効果: Graceful スイッチオーバーによりデータ損失ゼロでロールが入れ替わり、DR 訓練を安全かつ再現性のある手順で実施できる。

2. リージョン障害時の緊急フェイルオーバー

シナリオ: プライマリリージョンで障害が発生し、プライマリデータベースへのアクセスが不安定。多少のデータ損失リスクを許容してでも、可能な限り早くセカンダリリージョンでサービスを再開したい。

Text実装例
Region Switch プランを Ungraceful モードで実行し、
実行ブロックの動作として promoteReadReplica を指定

- Region Switch が PromoteReadReplica を呼び出しレプリカを直接昇格
- 昇格後、バックアップ保持期間・バックアップウィンドウ・Multi-AZ 設定を
  元のプライマリの構成に合わせて自動復元

効果: プライマリと通信できない状況でも復旧速度を優先してレプリカを昇格でき、RTO を最小化できる。

3. マルチアカウント環境での復旧一元管理

シナリオ: 復旧管理用の共有アカウントで Region Switch プランを運用し、ワークロードアカウントに RDS for Oracle インスタンスが存在するマルチアカウント構成。組織全体のフェイルオーバーを単一プランで管理したい。

Text実装例
共有アカウントの Region Switch プランに、
ワークロードアカウントの DB インスタンス ARN を指定した
RDS Switchover Read Replica 実行ブロックを追加

- クロスアカウントアクセス用の IAM ロールと権限を事前に設定
- Route 53、EKS、Lambda ESM など他の実行ブロックと組み合わせて
  アプリケーション全体のフェイルオーバーをオーケストレーション

効果: ネイティブなクロスアカウントサポートにより、複数アカウントにまたがる RDS インスタンスの復旧を単一の Region Switch プランで一元管理できる。

💰 料金

ARC Region Switch の利用料金に含まれる。RDS Switchover Read Replica 実行ブロックの追加による追加料金は発生しない。

項目料金
Region Switch プランARC Region Switch の標準料金に準拠
RDS Switchover Read Replica 実行ブロック追加料金なし
RDS インスタンスとクロスリージョンレプリケーション標準の Amazon RDS 料金が適用

🌏 利用可能リージョン

ARC Region Switch が利用可能なすべての商用リージョンおよび AWS GovCloud (US) リージョンで使用可能。 詳細は Region availability for Region switch を参照。

🔗 関連サービス・機能

→Amazon Application Recovery Controller (ARC): マルチリージョンアプリケーションの復旧制御を提供するサービス
→ARC Region Switch: リージョン間フェイルオーバーを自動化するプラン機能。Route 53、Aurora Global Databases、DocumentDB、EKS、Lambda ESM などの実行ブロックも提供
→Amazon RDS for Oracle: Oracle Data Guard を利用したクロスリージョンリードレプリカにより、マルチリージョンの DR 構成を実現
→Aurora Global Databases 実行ブロック: Aurora データベースのリージョン切り替えには本ブロックではなくこちらを使用

✅ まとめ

ARC Region Switch への Amazon RDS Switchover Read Replica 実行ブロックの追加により、 Oracle Data Guard を使用する RDS for Oracle のリージョンフェイルオーバーが自動化され、 計画フェイルオーバーではデータ損失ゼロ、 緊急時には速度優先の復旧を単一プランで実現できるようになった。

RDS for Oracle をマルチリージョンで運用しているユーザーは、既存の Region Switch プランに本実行ブロックを追加し、 プラン評価の検証結果を確認した上で DR 訓練に組み込むことを推奨する。
