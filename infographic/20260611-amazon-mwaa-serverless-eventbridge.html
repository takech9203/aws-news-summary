Amazon MWAA Serverless Amazon EventBridge 📅 2026年6月11日

☁️ MWAA Serverless が EventBridge 通知 をサポート

ワークフローとタスクの状態変更をイベント駆動で自動化

📌 概要

Amazon Managed Workflows for Apache Airflow (MWAA) Serverless が、 ワークフローおよびタスクの状態変更イベントを Amazon EventBridge に送信できるようになりました。 これにより、Apache Airflow ワークフローに対してイベント駆動型の自動化を構築できます。

ワークフローが状態間を遷移したとき (開始、実行中、成功、失敗など) や、 個々のタスクの状態が変化したとき (スケジュール済み、成功、失敗、リトライ待ちなど) にイベントを発行します。 失敗時のアラート発報、依存パイプラインの自動再起動、監査目的の S3 ロギングなどを実現できます。

❌ Before（アップデート前の課題）
  • 独自のポーリングロジックの実装が必要だった
  • 状態変化を手動で観察する必要があった
  • 失敗をリアルタイムに近い形で他システムへ通知する仕組みがなかった
✅ After（アップデート後の改善）
  • 状態変更を EventBridge イベントとして自動受信
  • ポーリングや手動確認が不要に
  • 状態変化をトリガーにイベント駆動型自動化を構築可能

MWAA Serverless がワークフローおよびタスクの状態変更イベントを EventBridge に発行し、 ルールにマッチしたイベントが SNS、Lambda、S3 などのターゲットへ配信されます。

⚡ 主要機能

🔄 ワークフロー状態変更イベント
  • ワークフロー実行が状態間を遷移するたびにイベントを発行
  • 本番ワークフローの失敗検知や後続処理のトリガーに活用できる
Started Queued Running Succeeded Failed Stopped Timeout
⚙️ タスク状態変更イベント
  • 個々のタスクの状態が変化するたびにイベントを発行
  • タスク単位での詳細な監視と自動化を可能にする
Queued Scheduled Upstream Failed Running Succeeded Failed Up For Retry Timeout
📨 EventBridge への直接配信
  • イベントは aws.airflow-serverless をソースとして直接送信
  • 配信タイプは Durable (耐久性のある配信) で信頼性が高い
  • イベントパターンで特定のイベントのみフィルタリング可能

Bash ステップ1: EventBridge ルールの作成 
aws events put-rule \
  --name "mwaa-serverless-workflow-failed" \
  --event-pattern '{"source":["aws.airflow-serverless"],"detail-type":["MWAA Serverless Workflow Run Failed"]}'
Bash ステップ2: ターゲットの設定 (SNS トピックへ送信) 
aws events put-targets \
  --rule "mwaa-serverless-workflow-failed" \
  --targets "Id"="1","Arn"="arn:aws:sns:ap-northeast-1:123456789012:mwaa-alerts"
💡 ステップ3 動作確認: ワークフローを実行し、状態遷移時にルールが発火してターゲットへ通知が届くことを確認。CloudWatch メトリクスや S3 ログでイベント配信状況を検証することを推奨します。

⚠️ デメリット・制約事項

制限事項

!MWAA Serverless が利用可能なリージョンでのみ提供
!配信先での処理 (Lambda、SNS など) には別途各サービス料金が発生

考慮すべき点

!イベントパターンを適切に設計しないと不要なイベントまで処理する可能性
!大量タスクのワークフローでは多数のイベントが発行され、ターゲット側のスケーラビリティ考慮が必要

🎯 ユースケース

1. 本番ワークフロー失敗時のアラート発報
シナリオ: 本番データパイプライン失敗時に運用チームへ即座に通知
効果: 失敗イベントを SNS へ連携しメール/Slack 通知。障害検知から対応までの時間を短縮
JSONdetail-type: Failed
{ "source": ["aws.airflow-serverless"],
  "detail-type": ["MWAA Serverless Workflow Run Failed"] }
2. 上流ワークフロー成功時の依存パイプライン自動起動
シナリオ: 上流の取り込み成功で下流の集計パイプラインを自動起動
効果: 成功イベントを Lambda へ連携。ワークフロー間の依存を自動化し手動オペを排除
JSONdetail-type: Succeeded
{ "source": ["aws.airflow-serverless"],
  "detail-type": ["MWAA Serverless Workflow Run Succeeded"] }
3. 状態遷移の監査ログ記録
シナリオ: 全ワークフロー/タスクの状態遷移を記録し長期保管
効果: 全イベントを S3 (Firehose 経由など) へ記録し監査証跡として活用
JSON全イベント
{ "source": ["aws.airflow-serverless"] }

💰 料金・リージョン・関連サービス

💵 料金

EventBridge のルールマッチ・イベント配信、ならびに配信先の SNS、Lambda、S3 などには、それぞれのサービス料金が適用されます。詳細は各サービスの料金ページを参照してください。

🌍 利用可能リージョン

Amazon MWAA Serverless が利用可能なすべての AWS リージョンで利用できます。

🔗 関連サービス

  • Amazon EventBridge: イベント受信とルールベースの配信を担う中核サービス
  • AWS Lambda: イベントをトリガーに依存パイプライン起動などのカスタム処理
  • Amazon SNS: ワークフロー失敗時のアラート通知
  • Amazon S3: 状態遷移を監査ログとして記録・保管
  • Amazon CloudWatch: メトリクス/ログと組み合わせて健全性を監視

📝 まとめ

MWAA Serverless の EventBridge 通知サポートにより、ポーリングや手動確認に頼らず、 ワークフローとタスクの状態変更をイベント駆動で扱えるようになりました。 失敗時のアラート、依存パイプラインの自動起動、監査ログ記録といった自動化を容易に構築できます。 まずは重要なワークフローの失敗イベントを EventBridge ルールで捕捉し、 アラート通知から段階的に導入することを推奨します。
