Oracle Database@AWS

🗄️ Oracle Autonomous AI Database Serverless サポート開始

📅 リリース日
2026 年 6 月 17 日

📌 概要

Oracle Database@AWS が Oracle Autonomous AI Database Serverless (ADB-S) のサポートを開始しました。ADB-S は Oracle Exadata インフラストラクチャ上で動作するフルマネージドサービスで、パッチ適用・チューニング・スケーリングを自動処理します。

これまで必要だった専用 Exadata インフラストラクチャや VM クラスターの事前プロビジョニングが不要になり、AWS マネジメントコンソール、AWS CLI、AWS API から Oracle のオートノマスデータベースを直接プロビジョニングできるようになりました。AWS Marketplace のパブリック / プライベートオファーを通じて提供され、BYOL と License Included の両方に対応します。

😓 アップデート前の課題

  • 専用 Exadata インフラや VM クラスターの事前プロビジョニングが必要
  • パッチ適用・チューニング・スケーリングを手動 / お客様側で管理
  • サーバーレス形態の選択肢がなく、柔軟なリソース割り当てが困難

🎉 アップデート後の改善

  • AWS コンソール・CLI・API から直接プロビジョニング可能
  • 専用 Exadata / VM クラスターのセットアップが不要
  • コンピューティングとストレージが需要に応じて独立スケール

AWS の各種インターフェースから ADB-S を直接プロビジョニングし、KMS・CloudWatch・EventBridge・S3 といった AWS ネイティブサービスと統合する構成。

⚡ 主要機能

🚀 AWS ネイティブから直接プロビジョニング

  • コンソール・CLI・API から直接作成
  • 専用 Exadata / VM クラスターのセットアップ不要
  • パッチ・チューニング・スケーリングを自動処理

🎯 4 種類のワークロードタイプ

  • AI Transaction Processing: トランザクション処理
  • AI Lakehouse: 分析・レイクハウス
  • AI JSON Database: JSON ドキュメント中心
  • Oracle APEX: ローコードアプリ開発

🛡️ 高可用性とディザスタリカバリ

  • Autonomous Data Guard による高可用性
  • Amazon S3 への自動バックアップ
  • クロスリージョン DR をサポート

🔗 AWS サービスとの統合

  • 暗号化: AWS KMS
  • モニタリング: Amazon CloudWatch
  • イベント管理: Amazon EventBridge

Bash AWS CLI でのプロビジョニング例 (概念例) 
# AWS CLI で Autonomous Database をプロビジョニングする例 (概念例)
aws odb create-autonomous-database \
  --display-name "my-adb-serverless" \
  --workload-type "AI_TRANSACTION_PROCESSING" \
  --compute-count 2 \
  --data-storage-size-in-gbs 1024

ワークロードタイプを選択し、コンピューティングとストレージのサイズを指定します。実際のコマンド名やパラメータは AWS CLI のリファレンスを参照してください。統合設定では暗号化に KMS キーを指定し、CloudWatch・EventBridge を構成、必要に応じて Autonomous Data Guard とクロスリージョン DR を有効化します。

✅ メリット

💼 ビジネス面

  • 運用負荷の軽減: 自動化により運用コストと工数を削減
  • 柔軟なライセンス: BYOL / License Included を選択可能
  • 調達の簡素化: AWS Marketplace で契約・課金を一元化

⚙️ 技術面

  • インフラ管理の不要化: 専用 Exadata 不要、ネイティブ I/F から利用
  • 独立したスケーリング: コンピューティングとストレージを最適化
  • AWS 統合: KMS・CloudWatch・EventBridge・S3 と連携

⚠️ デメリット・制約事項

制限事項

  • 利用可能リージョンは US East (バージニア北部) と US West (オレゴン) の 2 リージョンに限定
  • 東京リージョンを含むその他のリージョンでは未提供
  • 利用には AWS Marketplace を通じたサブスクリプションが前提

考慮すべき点

  • 自動パッチ適用・チューニングと変更管理プロセスの整合性を確認する必要がある
  • クロスリージョン DR は対応リージョンの組み合わせを確認する必要がある
  • ライセンスオプションによりコスト構造とコンプライアンス要件が異なるため事前検討が必要

💡 ユースケース

1. 運用負荷を抑えたトランザクション処理基盤

既存の Oracle データベースを AWS に移行しつつ、DBA の運用負荷を最小限に抑えたい企業。

🔧 ワークロード: AI Transaction Processing ／ ライセンス: BYOL ／ 高可用性: Autonomous Data Guard

➡️ 効果: パッチ適用やチューニングの自動化で運用工数を削減しつつ、既存 Oracle ライセンス資産を活用できる。

2. 分析向けレイクハウス

大規模なデータ分析ワークロードで、コンピューティングとストレージを独立してスケールさせたいデータ分析チーム。

🔧 ワークロード: AI Lakehouse ／ スケーリング: 需要に応じて自動拡張 ／ モニタリング: CloudWatch

➡️ 効果: 分析需要の変動に合わせてリソースを最適化し、コスト効率の高い分析基盤を構築できる。

3. ローコードアプリケーション開発

Oracle APEX を用いて社内向け業務アプリを迅速に開発したい開発チーム。

🔧 ワークロード: Oracle APEX ／ バックアップ: Amazon S3 ／ イベント管理: EventBridge

➡️ 効果: インフラ管理を意識せずに APEX アプリを構築でき、開発スピードを向上できる。
