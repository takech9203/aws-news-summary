📋 概要

Amazon Location Service の Routes API に、Transit および Intermodal の 2 つの新しいトラベルモードが追加された。CalculateRoutes オペレーションで公共交通機関と徒歩、自動車、タクシー、レンタカーを組み合わせた経路計画が単一 API コールで実現可能に。

❌ Before

  • Car / Pedestrian / Truck のみサポート
  • 公共交通を含むルート計算が不可
  • マルチモーダル計画にサードパーティ API が必要
  • パークアンドライド等を単一 API で計算不可

✅ After

  • Transit / Intermodal モード追加
  • バス、地下鉄、電車、フェリー等に対応
  • AWS ネイティブでマルチモーダル経路計算
  • 車椅子対応のアクセシビリティフィルタ

⚡ 主要機能

🚇 Transit トラベルモード
公共交通機関を利用したポイント間ルート計算。停留所までの徒歩案内、出発/到着時刻、路線情報を含む。
🚌 バス 🚇 地下鉄 🚆 電車 ⛴️ フェリー 🚊 路面電車 🚝 モノレール 🚄 高速鉄道
  • スケジュールベースのルーティング (出発/到着時刻)
  • 路線名、運行事業者、中間停留所の詳細情報
  • AllowedModes で特定交通タイプに限定可能
🔀 Intermodal トラベルモード
複数の交通手段を単一ルートに統合。EnabledFor パラメータで各交通手段の適用区間を制御。
🅿️ パークアンドライド
車両で駅まで移動し公共交通に乗り換え
🚕 タクシーアンドライド
タクシーで駅まで移動し公共交通に乗り換え
🏁 ラストマイル
公共交通から降りた後タクシー/レンタカーで目的地へ
♿ アクセシビリティ対応
AccessibilityAttributes で車椅子対応ルートをフィルタリング。停留所の車椅子対応状況も取得可能。
  • Available / Limited / Unavailable / Unknown の 4 段階で状況を返却
  • バリアフリー経路の計算に対応
📊 追加レッグ情報
LegAdditionalFeatures に IntermediateStops、NextDepartures、Bookings を追加。
  • PedestrianLegDetails: 徒歩区間の待機時間、案内指示
  • TransitLegDetails: 乗車/降車情報、路線詳細

💻 設定方法・コードサンプル

Transit ルートの計算

Python Transit モードで公共交通ルートを計算 
import boto3

client = boto3.client('geo-routes', region_name='ap-northeast-1')

response = client.calculate_routes(
    Origin=[139.7671, 35.6812],  # 東京駅
    Destination=[139.7454, 35.6586],  # 渋谷駅
    TravelMode='Transit',
    TravelModeOptions={
        'Transit': {
            'AllowedModes': ['Metro', 'CityTrain'],
            'AccessibilityAttributes': ['Wheelchair']
        }
    },
    DepartureTime='2026-06-02T09:00:00+09:00',
    LegAdditionalFeatures=['IntermediateStops', 'NextDepartures']
)

🎯 ユースケース

🏢 従業員通勤支援アプリ

大企業が従業員向けの通勤経路提案アプリを構築し、最適な通勤手段と経路を提案。従業員ごとに最適な通勤ルートと所要時間を自動提案し、通勤手当の最適化やフレックスタイム制度の設計に活用。

🚗 MaaS プラットフォーム

Mobility as a Service プラットフォームで、タクシー + 電車 + 徒歩の組み合わせルートを提供。予約情報 (Bookings) も含めたエンドツーエンドの移動体験を実現。

📦 物流ラストマイル最適化

都市部の渋滞を回避し、公共交通を活用した配送ルートの最適化により、配送時間の短縮と CO2 排出量の削減を実現。最終区間をタクシーで補完するパターン。

⚖️ メリット・デメリット

💼 ビジネス面のメリット

  • モビリティアプリの価値向上 - エンドユーザー体験の大幅改善
  • 開発コスト削減 - サードパーティ交通 API が不要に
  • 都市計画の最適化 - 通勤パターン分析に活用
  • 従業員満足度向上 - 最適通勤ルート提案が可能に

🔧 技術面のメリット

  • 単一 API コール - 複数交通手段を 1 回で取得
  • きめ細かな制御 - EnabledFor で区間単位のモード制御
  • アクセシビリティ - 車椅子対応がネイティブサポート
  • AWS 統合 - Places, Maps, Geofences との連携が容易

⚠️ 制限事項・注意点

  • 公共交通データのカバレッジは地域により異なる - 全都市/路線が網羅されているわけではない
  • リアルタイム遅延/運休情報は含まれない (スケジュールベース)
  • 利用可能リージョンが 13 リージョンに限定
  • ダイヤ改正時にルート計算結果が一時的に不正確になる可能性
  • Intermodal の応答サイズが大きいため帯域幅設計を考慮
  • 新しいレスポンス構造のためパーサー実装の更新が必要
