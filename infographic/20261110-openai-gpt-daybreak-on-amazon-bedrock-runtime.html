🛡️ OpenAI Daybreak モデルが bedrock-runtime エンドポイントに対応

📅 リリース日: 2026 年 11 月 10 日 | Daybreak Red: GPT-5.6 Cyber / Daybreak Blue: GPT-5.6 Sol

📌 概要

OpenAI のサイバーセキュリティ特化モデル Daybreak Red: GPT-5.6 Cyber と Daybreak Blue: GPT-5.6 Sol が、Amazon Bedrock の bedrock-runtime エンドポイント経由で利用可能になりました。対象は OpenAI の Daybreak アクセスプログラム (Trusted Access for Cyber) に登録済みの適格なお客様です。

推論データはモデルのトレーニングには使用されず、OpenAI とのデータ共有へのオプトインも不要です。US および Global のクロスリージョン推論 (CRIS) プロファイルを通じて、東京や大阪を含む多数のリージョンから利用できます。

事前に OpenAI の Daybreak アクセスに登録したうえで、bedrock-runtime エンドポイントから US または Global の CRIS プロファイルを指定して Daybreak モデルを呼び出す構成です。

⚙️ 主要機能

🔵 Daybreak Blue: GPT-5.6 Sol - 防御ワークフロー向けモデル

脆弱性の発見、検知エンジニアリング、インシデント対応など、防御的ワークフロー全般に対応。検証済みの防御者 (verified defenders) による高度かつ承認済みのセキュリティ業務を想定した、多くのセキュリティチームの標準的な選択肢です。

🔴 Daybreak Red: GPT-5.6 Cyber - 高度な承認済みタスク向けモデル

脆弱性リサーチ、エクスプロイトの再現、緩和策の開発向けに設計。拒否のしきい値を低く設定し、強力な本人確認・モニタリング・アクセス制御で補完することで、調査のスピードと深度を向上します。利用には OpenAI の Trusted Access for Cyber への登録が必須です。

🔌 bedrock-runtime エンドポイントでの提供

Converse API、Responses API、Chat Completions API をサポート (Invoke API は非サポート)。US Geo および Global の CRIS プロファイル経由で利用します (In-Region 推論は非対応)。Guardrails (Converse API のみ)、呼び出しログ、レスポンスストリーミング、プロンプトキャッシュ、構造化出力 (JSON Schema)、Reasoning Summaries などに対応します。

🔒 データプライバシー

推論データはモデルのトレーニングに使用されません。OpenAI とのデータ共有へのオプトインも不要です。

⚠️ 利用時の注意点

⚠️Converse API ではユーザーメッセージに text および image コンテンツブロックのみ受け付けます。document ブロックや toolResult 内の image ブロックは ValidationException となるため、ドキュメントを送る場合は Responses API の input_file を使用します
⚠️クォータは TPM (tokens per minute) で管理され、出力 1 トークンが 10 トークン分を消費する 10 倍のバーンダウンレートが適用されます
⚠️IAM アイデンティティには、推論プロファイルに加えてアカウントのデフォルトプロジェクト arn:aws:bedrock:{region}:{account-id}:project/default に対する bedrock:InvokeModel 権限が必要です

BashOpenAI SDK 用の認証設定
export OPENAI_API_KEY="<Bedrock API キー>"

ステップ 2: Daybreak Blue の呼び出し (Responses API)

PythonOpenAI SDK + US Geo CRIS プロファイル
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="us.openai.gpt-daybreak-blue-5.6-sol",
    input="検知ルールの改善案を提案してください。"
)
print(response)

bedrock-runtime では In-Region 推論は利用できないため、必ず us. または global. のプロファイル ID を指定します。

ステップ 3: Converse API での呼び出し (AWS SDK)

Pythonboto3 + Global CRIS プロファイル
import boto3

client = boto3.client("bedrock-runtime", region_name="us-east-1")

response = client.converse(
    modelId="global.openai.gpt-daybreak-blue-5.6-sol",
    messages=[{
        "role": "user",
        "content": [{"text": "このログから不審なアクティビティを分析してください。"}]
    }]
)
print(response["output"]["message"]["content"][0]["text"])

Converse API を使用することで、Guardrails やアプリケーション推論プロファイルなどの Bedrock 機能と組み合わせられます。

🚧 制限事項

✗サービスティアは Standard のみ (Priority / Flex / Reserved は不可)

🤔 考慮すべき点

⚠️CRIS により地理的に異なるリージョンへルーティングされるため、データレジデンシー要件がある場合は US Geo プロファイルの利用やルーティング先の確認が必要
⚠️出力トークンに 10 倍のバーンダウンレートが適用されるため、TPM クォータの消費計画に注意

🌏 利用可能リージョン

bedrock-runtime エンドポイントでは、US Geo および Global の CRIS プロファイル経由で利用できます (In-Region 推論は非対応)。

🇺🇸 US Geo プロファイル

us-east-1 (バージニア北部)、us-east-2 (オハイオ)、us-west-1 (北カリフォルニア)、us-west-2 (オレゴン)、ca-central-1 (カナダ)、ca-west-1 (カルガリー) をソースリージョンとして利用可能

🌍 Global プロファイル

上記に加え、欧州各リージョン、ap-northeast-1 (東京) や ap-northeast-3 (大阪) を含むアジアパシフィック各リージョン、中東、アフリカ、南米の多数のリージョンをソースリージョンとして利用可能

なお、bedrock-mantle エンドポイントでは us-east-2 (オハイオ) の In-Region 提供です (Daybreak Red は AWS GovCloud US-East でも利用可能)。

🔗 関連サービス・機能

✓Amazon Bedrock Guardrails: Converse API 経由で Daybreak モデルの入出力にコンテンツフィルタを適用
✓クロスリージョン推論 (CRIS): US Geo / Global プロファイルによる自動ルーティングで可用性とスループットを確保
✓Amazon Bedrock プロンプトキャッシュ: 暗黙的キャッシュは各 API で、明示的キャッシュは Responses API で利用でき、繰り返し分析のコストを削減
✓Amazon Bedrock モデル呼び出しログ: セキュリティ用途で重要となる呼び出しの監査証跡を記録

🎯 まとめ

OpenAI のサイバーセキュリティ特化モデル Daybreak Red / Daybreak Blue が bedrock-runtime エンドポイントに対応し、Converse API や CRIS プロファイルを通じて東京を含む多数のリージョンから利用できるようになりました。Guardrails や呼び出しログなどの Bedrock ネイティブ機能と組み合わせたセキュリティワークフローの構築が可能になります。

利用を検討する場合は、まず OpenAI の Trusted Access for Cyber への登録について AWS アカウントチームに相談することを推奨します。
