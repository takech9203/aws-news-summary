AWS Advanced JDBC Wrapper ElastiCache for Valkey

Valkey による自動クエリキャッシュ

JDBC クエリ結果を自動キャッシュし、データベース読み取り負荷を軽減
2026 年 3 月 26 日

📋 概要

AWS Advanced JDBC Wrapper が、Valkey を使用した JDBC クエリの自動キャッシュに対応しました。Aurora および RDS の PostgreSQL、MySQL、MariaDB データベースのクエリ結果セットを、数ステップの設定で自動的に Valkey キャッシュに保存・取得できるようになります。

Hibernate や Spring Data などの一般的な永続化フレームワークからのアノテーションベースのキャッシュ指定、および手動のクエリヒントにも対応しています。

🏗️ アーキテクチャ図

アプリケーションが JDBC クエリを実行すると、Query Cache Plugin がまず Valkey キャッシュを確認します。キャッシュヒットの場合はデータベースアクセスなしで結果を返却し、キャッシュミスの場合はデータベースにクエリを実行して結果をキャッシュに保存します。

🚀 設定方法

前提条件

☕ Java + JDBC
🗄️ Aurora / RDS
⚡ ElastiCache for Valkey
1

AWS Advanced JDBC Wrapper の依存関係を追加

プロジェクトのビルドファイルに依存関係を追加します。

XML Maven の場合 
<!-- Maven の場合 -->
<dependency>
    <groupId>software.amazon.jdbc</groupId>
    <artifactId>aws-advanced-jdbc-wrapper</artifactId>
    <version>LATEST_VERSION</version>
</dependency>
2

クエリキャッシュプラグインの有効化

JDBC Wrapper の設定でプラグインを有効化し、Valkey エンドポイントを指定します。

Properties JDBC 接続プロパティ 
wrapperPlugins=queryCache
queryCacheUrl=valkey://your-elasticache-endpoint:6379
3

キャッシュ対象クエリの指定

Hibernate / Spring Data ではアノテーションで、素の JDBC ではクエリヒントで指定します。

4

データベースエンドポイントの設定

AWS Advanced JDBC Wrapper を経由する接続 URL を設定します。

Properties データベース接続 URL 
jdbc:aws-wrapper:postgresql://your-aurora-endpoint:5432/your-database

⚖️ メリットと制約事項

✅ メリット

ビジネス面

  • データベース読み取りリクエスト削減によるコスト低減
  • 読み取りレイテンシ改善によるエンドユーザー体験向上
  • 手動キャッシュコード不要で開発者がビジネスロジックに集中

技術面

  • 数ステップの設定のみで導入可能
  • Hibernate / Spring Data とネイティブに統合
  • データベース負荷急増時のアプリケーション安定性向上

⚠️ 制約事項・注意点

制限事項

  • 対応は PostgreSQL / MySQL / MariaDB のみ
  • Java / JDBC アプリケーション限定
  • キャッシュ対象クエリは明示的な指定が必要

考慮すべき点

  • キャッシュ有効期限の適切な設定が必要
  • ElastiCache for Valkey の追加コストが発生
  • 書き込みが多いワークロードでは効果が限定的

💡 ユースケース

🛒 読み取り頻度の高い Web アプリケーション

E コマースサイトの商品カタログページで、商品情報や価格情報が頻繁に参照されるが更新頻度は低い場合に、クエリキャッシュを活用してデータベース負荷を軽減します。

Java Spring Data の場合 
@Repository
public interface ProductRepository extends JpaRepository<Product, Long> {
    // クエリキャッシュプラグインにより自動的にキャッシュされる
    List<Product> findByCategoryId(Long categoryId);
}
→ 商品カタログの読み取りレイテンシが大幅に低減。セール時のアクセス急増にも対応可能
📊 ダッシュボード・レポーティングシステム

集計クエリやレポートクエリの結果をキャッシュし、複数ユーザーが同じレポートを参照する際のデータベース負荷を削減します。

Java Hibernate でのクエリヒント使用例 
Query query = session.createQuery(
    "SELECT department, SUM(sales) FROM Orders " +
    "GROUP BY department"
);
// JDBC Wrapper のクエリキャッシュプラグインが自動的にキャッシュ
→ 同一レポートへの複数回アクセスでデータベースクエリが 1 回のみとなりレスポンス時間を短縮
🔗 マイクロサービス間の共有データ参照

複数のマイクロサービスが共通のマスターデータを参照する環境で、各サービスのデータベースアクセスを Valkey キャッシュ経由に集約します。

Properties 各マイクロサービスの JDBC 設定 
wrapperPlugins=queryCache
queryCacheUrl=valkey://shared-elasticache-endpoint:6379
→ 共通データへのアクセスが Valkey で処理され、データベースの接続数とクエリ負荷を大幅に削減
