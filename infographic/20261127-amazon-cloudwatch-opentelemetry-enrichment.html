☁️ Amazon CloudWatch

基本 OpenTelemetry エンリッチメントを
追加料金なしで提供

📅 2026 年 11 月 27 日 AWS サービスメトリクスの基本 OpenTelemetry エンリッチメント (Basic OpenTelemetry Enrichment)

📝 概要

AWS サービスが CloudWatch に発行するクラシックな vended メトリクス (例: InstanceId ディメンションを持つ Amazon EC2 の CPUUtilization) を、OpenTelemetry データポイントに変換し、PromQL でクエリ可能にする基本エンリッチメントが追加料金なしで利用できるようになりました。

エンリッチされたメトリクスにはリソース ARN (cloud.resource_id)、クラウドプロバイダー、リージョン、アカウント ID のリソース属性と、発行元サービスを識別するインストルメンテーションスコープが付与されます。既存の CloudWatch ディメンションはデータポイント属性として保持され、元のクラシックメトリクスは変更されずに既存の CloudWatch API から引き続き利用できます。さらに AWS リソースタグを PromQL ラベルとして使いたい場合は、上位レベルのリソースタグエンリッチメント (課金対象) にいつでも切り替え可能です。

❌ アップデート前の課題

  • クラシック vended メトリクスは CloudWatch 独自の名前空間・ディメンションモデルで、PromQL でそのままクエリできなかった
  • OTel 形式で扱えるのは、OTLP エンドポイントへネイティブ送信される一部メトリクスに限られていた
  • リソース ARN、アカウント、リージョンを示す標準リソース属性がなく、OTel ツールでの横断分析が困難だった

✅ アップデート後の改善

  • 基本エンリッチメントを無料で有効化し、クラシック vended メトリクスを OTel データポイントとして PromQL でクエリ可能に
  • ARN、プロバイダー、リージョン、アカウント ID のリソース属性とスコープが自動付与され、OTel 標準での分析が容易に
  • 必要に応じてリソースタグエンリッチメントに切り替え、AWS リソースタグを PromQL ラベルとして活用可能に
  • CloudWatch Omni セットアップ時はデフォルト有効。コンソール、CLI、CloudFormation、Terraform、SDK から有効化可能に

AWS サービスが発行するクラシック vended メトリクスは、OTel エンリッチメントにより OTel データポイントへ変換され、PromQL でクエリ可能になります。基本エンリッチメントは無料、リソースタグエンリッチメントは課金対象で、元のクラシックメトリクスは変更されずに既存 API から利用できます。

⚡ 主要機能

🆓 1. 基本エンリッチメント (追加料金なし)

  • リソース識別子ディメンションを持つクラシック vended メトリクスを OTel データポイントに変換
  • リソース属性としてリソース ARN (cloud.resource_id)、クラウドプロバイダー、リージョン、アカウント ID を付与
  • 発行元サービスを識別し OTel エンリッチ済みであることを示すインストルメンテーションスコープを付与
  • 既存の CloudWatch ディメンションはデータポイント属性として保持

🏷️ 2. リソースタグエンリッチメント (課金対象)

  • 基本エンリッチメントの内容に加え、各リソースの AWS リソースタグを PromQL ラベルとして付与
  • OTel Vended Metric Enrichment として課金。1 つ以上のタグラベルが付与されたデータポイントのみが課金対象
  • どの AWS リソースタグにもマッチしない場合、データポイントは無料でパススルー
  • 事前にアカウントで resource tags on telemetry の有効化が必要

🔄 3. 柔軟なレベル切り替えと有効化手段

  • EnableTagEnrichment パラメータでレベルを選択 (false で基本、true でリソースタグ)
  • レベルは UpdateOTelEnrichment でいつでも変更可能
  • CloudWatch コンソール、AWS CLI、CloudFormation、Terraform、AWS SDK から有効化可能
  • CloudWatch Omni のセットアップ時はデフォルトで有効

📈 4. PromQL クエリ対応

  • エンリッチ後のメトリクスは PromQL でクエリ可能になり、Prometheus 互換のワークフローで AWS サービスメトリクスを分析できる
  • 多くの場合は元の CloudWatch メトリクス名を維持 (一部は書き換えあり。例: API Gateway の 4XXError + Method ディメンションは 4XXErrorByMethod)

⚙️ 設定方法

📋 前提条件

✓基本エンリッチメントには前提条件なし
✓リソースタグエンリッチメントを使用する場合は、事前にアカウントで resource tags on telemetry を有効化する (コンソール使用時は自動で有効化)
✓cloudwatch:StartOTelEnrichment を実行できる IAM 権限

1️⃣ ステップ 1: 基本エンリッチメントの開始

Bash 基本エンリッチメントの有効化 
aws cloudwatch start-otel-enrichment --no-enable-tag-enrichment
⚠️ 注意: --no-enable-tag-enrichment を明示的に指定することで、無料の基本エンリッチメントのみを有効化します。省略するとデフォルトで課金対象のリソースタグエンリッチメントが有効になります。

2️⃣ ステップ 2: エンリッチメントレベルの確認・変更

Bash レベルの確認と切り替え 
# 現在のレベルを確認
aws cloudwatch get-otel-enrichment

# リソースタグエンリッチメントに切り替え
aws cloudwatch update-otel-enrichment --enable-tag-enrichment

GetOTelEnrichment のレスポンスには、エンリッチメント実行中であれば EnableTagEnrichment の値が含まれます。レベルの変更には UpdateOTelEnrichment を使用します (StartOTelEnrichment は実行中アカウントでは no-op となり、レベル変更には使えません)。なお、UpdateOTelEnrichment はフィルタリストを置き換えるため、既存フィルタを維持したい場合はリクエストに含める必要があります。

3️⃣ ステップ 3: PromQL でのクエリ

エンリッチメント有効化後、vended メトリクスを PromQL でクエリできます。コンソールの場合は [CloudWatch] → [Settings] の [Enable OTel Enrichment for AWS Metrics] ペインからも有効化できます。CloudFormation では AWS::CloudWatch::OTelEnrichment リソース、Terraform では aws_cloudwatch_otel_enrichment リソースを使用し、複数リージョンで有効化する場合は各リージョンで同じリソースを作成します。

💡 メリット

💼 ビジネス面

✓追加コストなしで OTel 対応: 基本エンリッチメントは無料のため、コスト増なしに AWS サービスメトリクスを OpenTelemetry 標準で扱える
✓段階的な投資判断: まず無料の基本レベルで価値を検証し、タグベースの分析が必要になった時点でリソースタグエンリッチメントへ切り替えられる
✓ツール統一によるスキル活用: Prometheus / Grafana / PromQL に慣れたチームの既存スキルをそのまま AWS マネージドサービスの監視に活かせる

🔧 技術面

✓PromQL クエリの実現: クラシック vended メトリクスを OTel データポイントに変換し、PromQL で柔軟に集計・フィルタリングできる
✓標準リソース属性の自動付与: ARN、リージョン、アカウント ID などが自動付与され、マルチアカウント・マルチリージョンの横断分析が容易になる
✓後方互換性の維持: 元のクラシックメトリクスは変更されず、既存のダッシュボード、アラーム、API 連携に影響しない

⚠️ デメリット・制約事項

🚧 制限事項

⚠対象はクラシック vended メトリクスのうち、リソース識別子ディメンションを持つサポート対象メトリクスに限られる (対応リソース・メトリクスはドキュメントの対応表を参照)
⚠リソースタグエンリッチメントは課金対象で、事前に resource tags on telemetry の有効化が必要
⚠一部メトリクスは OTel 名が書き換えられるため (例: 4XXErrorByMethod)、クエリ作成時に OTel 名の確認が必要

🤔 考慮すべき点

デフォルトは課金対象: EnableTagEnrichment を省略するとデフォルトで課金対象のリソースタグエンリッチメントが有効になるため、無料の基本エンリッチメントのみを使いたい場合は明示的に false を指定する
レベル切り替え時の影響: リソースタグエンリッチメントから基本エンリッチメントへ切り替えると、約 6 分以内に新しいメトリクスデータからタグラベルが付与されなくなり、タグラベルでフィルタ・グループ化している PromQL クエリ、ダッシュボード、アラームが新データにマッチしなくなる可能性がある
フィルタの再指定: UpdateOTelEnrichment はフィルタリストを毎回置き換えるため、フィルタ維持にはリクエストへの再指定が必要

🎯 ユースケース

📈 ユースケース 1: Prometheus / Grafana ベースの監視基盤への AWS メトリクス統合

シナリオ: Kubernetes ワークロードを PromQL ベースで監視しているチームが、EC2 や API Gateway などの AWS マネージドサービスのメトリクスも同じクエリ言語で扱いたい。

Bash基本エンリッチメントを無料で有効化
aws cloudwatch start-otel-enrichment --no-enable-tag-enrichment

効果: 追加コストなしで AWS サービスメトリクスが PromQL クエリ可能になり、アプリケーションメトリクスと AWS マネージドサービスメトリクスを単一のクエリ体系で分析できる。

🏷️ ユースケース 2: タグベースのコスト・チーム別メトリクス分析

シナリオ: team や environment などのリソースタグを全リソースに付与している組織が、チーム別・環境別にメトリクスを集計したい。

Bashタグエンリッチメントへ切り替え
# resource tags on telemetry 有効化後、タグエンリッチメントへ切り替え
aws cloudwatch update-otel-enrichment --enable-tag-enrichment

効果: リソースタグが PromQL ラベルとして付与され、タグ単位でのグルーピングやフィルタリングによるチーム別・環境別のメトリクス分析が可能になる。課金は実際にタグラベルが付与されたデータポイントのみに発生する。

📜 ユースケース 3: IaC による組織全体での標準化

シナリオ: 複数アカウント・複数リージョンで運用する組織が、OTel エンリッチメントの設定を CloudFormation / Terraform でコード管理したい。

YAMLCloudFormation テンプレート例
Resources:
  OTelEnrichmentExample:
    Type: AWS::CloudWatch::OTelEnrichment
    Properties:
      EnableTagEnrichment: false

効果: 各リージョンのスタックに同一リソースを配置することで、組織全体で一貫したエンリッチメント設定を宣言的に展開・維持できる。

💰 料金

基本エンリッチメントは追加料金なしで利用できます。リソースタグエンリッチメントは OTel Vended Metric Enrichment として課金されます。課金は 1 つ以上のリソースタグラベルが付与されたデータポイントにのみ適用され、メトリクスがどの AWS リソースタグにもマッチしない場合は無料でパススルーされます。

レベル料金
基本エンリッチメント追加料金なし
リソースタグエンリッチメントOTel Vended Metric Enrichment として課金 (タグラベル付与データポイントのみ)

詳細は Amazon CloudWatch 料金ページを参照してください。

🌍 利用可能リージョン

CloudWatch OpenTelemetry メトリクスがサポートされているすべての AWS リージョンで利用可能です。

🎁 まとめ

Amazon CloudWatch の基本 OpenTelemetry エンリッチメントにより、AWS サービスが発行するクラシック vended メトリクスを追加料金なしで OTel データポイントに変換し、PromQL でクエリできるようになりました。Prometheus / Grafana エコシステムを採用している組織は、まず無料の基本エンリッチメントを有効化して効果を検証し、タグベースの分析が必要な場合にリソースタグエンリッチメントへの切り替えを検討することを推奨します。

⚠️ 注意: EnableTagEnrichment 省略時のデフォルトは課金対象のリソースタグエンリッチメントである点に注意してください。
