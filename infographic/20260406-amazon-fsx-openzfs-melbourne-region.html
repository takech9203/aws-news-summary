📄 Overview

Amazon FSx for OpenZFS that AP Melbourne Region ap-southeast-4 is now available. Customers near Melbourne, Australia can now create fully managed OpenZFS file systems in a local region with sub-millisecond latency and multi-GB/s throughput.

Amazon FSx for OpenZFS is a fully managed shared file storage service built on the popular OpenZFS file system. NFS protocol support enables access from Linux, Windows, and macOS clients without infrastructure management.

Sub-millisecond latency and multi-GB/s throughput. SSD and HDD storage options optimize performance and cost.

🛠️ Setup Guide

Prerequisites

✅ AWS account with Melbourne region access
✅ VPC and subnet configuration
✅ Security group allowing NFS port 2049

Step 1: Create File System

Bash Create OpenZFS file system in Melbourne 
aws fsx create-file-system \
  --file-system-type OPENZFS \
  --storage-capacity 64 \
  --storage-type SSD \
  --subnet-ids subnet-xxxxxxxxxxxxxxxxx \
  --open-zfs-configuration '{
    "DeploymentType": "SINGLE_AZ_1",
    "ThroughputCapacity": 64,
    "RootVolumeConfiguration": {
      "DataCompressionType": "ZSTD"
    }
  }' \
  --region ap-southeast-4

Step 2: Mount File System

Bash Get DNS name and mount via NFS 
# Get DNS name
aws fsx describe-file-systems \
  --file-system-ids fs-xxxxxxxxxxxxxxxxx \
  --region ap-southeast-4 \
  --query 'FileSystems[0].DNSName' \
  --output text

# Mount on EC2 instance
sudo mount -t nfs -o nfsvers=4.1 \
  fs-xxxxxxxxxxxxxxxxx.fsx.ap-southeast-4.amazonaws.com:/fsx \
  /mnt/fsx

Step 3: Create Snapshot

Bash Create a point-in-time snapshot 
aws fsx create-snapshot \
  --name "daily-backup" \
  --volume-id fsvol-xxxxxxxxxxxxxxxxx \
  --region ap-southeast-4
