Amazon RDS for SQL Server

🗄️ 最新 CU と GDR アップデートのサポート

Microsoft SQL Server の累積更新プログラム (CU) と一般配布リリース (GDR) に対応 | リリース日: 2026 年 10 月 26 日

📌 概要

Amazon RDS for SQL Server が、Microsoft SQL Server の最新の 累積更新プログラム (CU) と 一般配布リリース (GDR) アップデートのサポートを開始しました。 SQL Server 2017 から SQL Server 2025 までの 4 つのメジャーバージョンに対して、 Microsoft が提供する最新のセキュリティ修正とバグ修正を適用した新しい RDS エンジンバージョンが利用可能になります。

😰 アップデート前の課題
  • 最新 CU/GDR のセキュリティ修正が未適用で、脆弱性リスクが残存
  • CU のバグ修正やパフォーマンス改善を RDS 環境で利用できない
  • オンプレミスとのパッチレベル差分で、互換性検証やコンプライアンス対応が困難
😊 アップデート後の改善
  • 最新 GDR により Microsoft 公開のセキュリティ修正を RDS 上でも適用可能
  • SQL Server 2017/2019/2022/2025 で最新 CU のバグ修正と改善を利用可能
  • マネジメントコンソール、AWS SDK、CLI から簡単にアップグレード

🔒 最新 GDR セキュリティアップデートのサポート

  • 累積更新プログラムに含まれるバグ修正、パフォーマンス改善を利用可能
  • SQL Server 2025 についても継続的に最新 CU へ追随
🚀 簡単なアップグレードプロセス
  • Amazon RDS マネジメントコンソールから数クリックでアップグレード

  • メンテナンスウィンドウ中の適用を選択して、業務影響を最小化可能

前提条件

✓Amazon RDS for SQL Server のインスタンスが稼働している
✓AWS マネジメントコンソールへのアクセス権限、または AWS CLI/SDK の設定
✓アップグレード前のバックアップ (推奨)

ステップ 1: バックアップの作成

Bash 手動スナップショットの作成 
aws rds create-db-snapshot \
  --db-instance-identifier mydbinstance \
  --db-snapshot-identifier mydbinstance-pre-upgrade-snapshot

ステップ 2: エンジンバージョンのアップグレード

Bash メンテナンスウィンドウ中に適用する場合 
aws rds modify-db-instance \
  --db-instance-identifier mydbinstance \
  --engine-version 16.00.4295.3.v1 \
  --no-apply-immediately

--apply-immediately を指定すると即時適用、 --no-apply-immediately を指定すると次のメンテナンスウィンドウで適用されます。 マネジメントコンソールの場合は、対象インスタンスを選択して [変更] から DB エンジンバージョンを選択します。

ステップ 3: アップグレードの確認

Bash エンジンバージョンとステータスを確認 
aws rds describe-db-instances \
  --db-instance-identifier mydbinstance \
  --query 'DBInstances[0].[EngineVersion,DBInstanceStatus]'

完了後はアプリケーションからの接続と主要機能の動作を確認してください。

⚠️ 制約・考慮点

✗アップグレード中はデータベースインスタンスが一時的に利用不可
✗エンジンバージョンのダウングレードは直接サポートされない (スナップショットからの復元が必要)
✗今回の発表では RDS Custom for SQL Server は対象として記載なし
⚠アップグレード前にテスト環境で互換性確認を推奨
⚠業務影響の少ない時間帯 (メンテナンスウィンドウ) での適用を計画
⚠CU 適用後にクエリプランが変化する可能性があるため、適用後のパフォーマンス監視を推奨

💡 ユースケース

1️⃣ 本番環境への計画的なセキュリティパッチ適用

シナリオ: 本番環境の RDS for SQL Server 2019 に GDR セキュリティアップデートを適用し、業務影響を最小化したい。

Bashスナップショット作成後、メンテナンスウィンドウ中に適用
# 1. 事前にスナップショットを作成
aws rds create-db-snapshot \
  --db-instance-identifier prod-sqlserver \
  --db-snapshot-identifier prod-sqlserver-pre-upgrade

# 2. メンテナンスウィンドウ中にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier prod-sqlserver \
  --engine-version 15.00.4490.9.v1 \
  --no-apply-immediately
✅ 効果: メンテナンスウィンドウ中にパッチが適用され、業務時間への影響を抑えながらセキュリティリスクを軽減
2️⃣ 開発・テスト環境での事前互換性検証

シナリオ: 本番適用前に、開発環境で SQL Server 2022 CU27 との互換性を検証したい。

Bash開発環境を即時アップグレード
aws rds modify-db-instance \
  --db-instance-identifier dev-sqlserver \
  --engine-version 16.00.4295.3.v1 \
  --apply-immediately

# アプリケーションのテストスイートを実行して互換性を確認
✅ 効果: クエリプランの変化や互換性の問題を本番適用前に検出し、安全なロールアウト計画を立案可能
3️⃣ SQL Server 2025 環境の最新化

シナリオ: 最新の SQL Server 2025 を RDS で利用しており、CU9 で提供される修正を早期に取り込みたい。

BashSQL Server 2025 を CU9 にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier sql2025-instance \
  --engine-version 17.00.5005.3.v1 \
  --apply-immediately
✅ 効果: 最新メジャーバージョンでも継続的に CU を適用でき、新機能利用と安定運用を両立

📝 まとめ

Amazon RDS for SQL Server が、SQL Server 2017/2019/2022/2025 の 4 バージョンに対する最新の CU と GDR アップデートをサポートしました。 GDR にはセキュリティ修正が含まれるため、RDS for SQL Server を利用しているすべてのユーザーは、 テスト環境での互換性確認とバックアップ取得のうえ、早期のアップグレード適用を推奨します。 アップグレードは RDS マネジメントコンソール、AWS SDK、CLI から簡単に実行できます。
