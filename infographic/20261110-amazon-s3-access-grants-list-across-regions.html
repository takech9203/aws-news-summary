Amazon S3 (S3 Access Grants)

🗂️ S3 Access Grants
複数 AWS アカウント横断でのグラント一覧表示

📅 リリース日: 2026 年 11 月 10 日 | 新パラメータ InstanceScope で 1 回の API 呼び出しによるクロスアカウント照会が可能に

📝 概要

Amazon S3 Access Grants が、複数の AWS アカウントにまたがるアクセスグラントを 1 回の API 呼び出しで一覧表示できるようになりました。 ListCallerAccessGrants API の新パラメータ InstanceScope を ALL に設定すると、自分のアカウントのインスタンスに加えて、 AWS RAM 経由で共有されたすべてのインスタンスのグラントが 1 つの結合されたレスポンスとして返されます。

さらに GetDataAccess API でも InstanceScope: ALL を指定でき、S3 パスの所有アカウントの特定とリクエストのルーティングをサービス側が自動で行います。 データポータルやファイルブラウザ (AWS Storage Browser for S3 など) を構築する開発者、マルチアカウント環境を管理する組織に有用です。

❌ Before: アップデート前の課題
  • アカウントごとに個別に ListCallerAccessGrants を呼び出す必要があり、全体像の把握に複数回の API 呼び出しが必要だった
  • どのアカウントのどのインスタンスにグラントが存在するかを、アプリケーション側で事前に把握・管理する必要があった
  • GetDataAccess の呼び出し時に、S3 パスの所有アカウントをアプリケーション側で特定する必要があった
✅ After: アップデート後の改善
  • InstanceScope: ALL を設定した 1 回の呼び出しで、自分のインスタンスと共有されたすべてのインスタンスのグラントを取得可能に
  • 各グラントに AccessGrantsInstanceArn が含まれ、所有アカウントの識別が容易に
  • GetDataAccess が所有アカウントの特定とルーティングを自動で行い、アカウント管理ロジックが不要に

InstanceScope を ALL に設定した 1 回の API 呼び出しで、自分のインスタンスと AWS RAM 経由で共有されたすべてのインスタンスのグラントが照会され、結合されたレスポンスとして返される流れを示しています。

⚡ 主要機能

1️⃣ 複数アカウント横断でのグラント一覧表示

ListCallerAccessGrants API に InstanceScope パラメータが追加。ALL を指定すると、自分のアカウントのインスタンスと AWS RAM 経由で共有されたすべてのインスタンスのグラントを 1 回の呼び出しで取得できます。デフォルト (パラメータ未指定) では従来どおり指定したアカウント ID のインスタンスのグラントのみが返されます。

2️⃣ 所有アカウントの識別

InstanceScope: ALL の場合、返される各グラントに AccessGrantsInstanceArn フィールドが含まれます。ARN にはアカウント ID が含まれるため、どのアカウントがグラントを所有しているかをプログラムで判別できます。

3️⃣ GetDataAccess の自動ルーティング

GetDataAccess API でも InstanceScope: ALL を設定可能。S3 パスを指定すると、サービスが所有アカウントを特定し、該当インスタンスにリクエストをルーティングして一時認証情報を返します。アプリケーション側でアカウントとパスの対応関係を管理する必要がなくなります。

🛠️ 設定方法

前提条件

✓S3 Access Grants インスタンスが作成済みで、IAM ID または IAM Identity Center ディレクトリ ID に対するグラントが設定されていること
✓他アカウントのグラントを参照する場合、データ所有者側のアカウントが AWS RAM を使用して S3 Access Grants インスタンスを共有していること
✓AWS CLI、SDK、または REST API を利用できる環境があること
1
自分のアカウントのグラントを一覧表示する
Bash従来どおりの呼び出し方法
aws s3control list-caller-access-grants \
  --account-id 111122223333 \
  --region us-east-2 \
  --max-results 5

指定したアカウント ID の S3 Access Grants インスタンスから、呼び出し元がアクセス可能なグラントの一覧を取得します。

2
共有されたすべてのインスタンスを横断してグラントを一覧表示する
BashInstanceScope ALL による横断照会
aws s3control list-caller-access-grants \
  --account-id 111122223333 \
  --instance-scope ALL \
  --region us-east-2 \
  --max-results 5

--instance-scope ALL により、自分のインスタンスに加えて AWS RAM 経由で共有されたすべてのインスタンスのグラントを 1 回の呼び出しで取得します。

JSONレスポンス例: 2 つの異なるアカウントのグラント
{
  "CallerAccessGrantsList": [
    {
      "Permission": "READWRITE",
      "GrantScope": "s3://amzn-s3-demo-bucket/prefix1/*",
      "ApplicationArn": "NA",
      "AccessGrantsInstanceArn": "arn:aws:s3:us-east-2:111122223333:access-grants/default"
    },
    {
      "Permission": "READ",
      "GrantScope": "s3://amzn-s3-demo-other-bucket/reports/*",
      "ApplicationArn": "NA",
      "AccessGrantsInstanceArn": "arn:aws:s3:us-east-2:444455556666:access-grants/default"
    }
  ]
}

上記のレスポンス例では、2 つの異なるアカウント (111122223333 と 444455556666) のインスタンスからグラントが返されています。

3
InstanceScope を指定して一時認証情報を取得する

GetDataAccess でも InstanceScope: ALL を設定することで、対象の S3 パスを所有するアカウントの特定とルーティングをサービス側に任せて、一致するグラントの一時認証情報を取得できます。アプリケーション側でパスとアカウントの対応表を管理する必要はありません。

💡 メリット

💼 ビジネス面

✓マルチアカウント環境の可視性向上: エンドユーザーがアクセスできる S3 データの全体像を 1 回の呼び出しで把握でき、データガバナンスの確認が容易になる
✓開発コストの削減: アカウントごとのループ処理やアカウント管理ロジックが不要になり、データポータルなどのアプリケーション開発が簡素化される
✓追加コストなし: 本機能は追加料金なしで利用できる

⚙️ 技術面

✓API 呼び出し回数の削減: アカウント数に比例していた ListCallerAccessGrants の呼び出しが 1 回にまとめられる
✓自動ルーティング: GetDataAccess が所有アカウントの特定とリクエストのルーティングを自動で行う
✓所有者の明示: レスポンスの AccessGrantsInstanceArn により、グラントの所有アカウントをプログラムで判別できる

⚠️ デメリット・制約事項

制限事項

✗横断的に照会できるのは、AWS RAM 経由で呼び出し元に共有されている S3 Access Grants インスタンスに限られる
✗IAM Identity Center のディレクトリ ID の場合、ID 対応セッションで使用される IAM ID のグラントが返される

考慮すべき点

⚠データ所有者側で事前に AWS RAM によるインスタンス共有の設定が必要であり、共有されていないアカウントのグラントは返されない
⚠結果が複数アカウントにまたがるため、ページネーション (NextToken) を考慮した実装が必要になる場合がある

🎯 ユースケース

1. マルチアカウント対応のデータポータル

シナリオ: 複数の事業部がそれぞれの AWS アカウントで S3 データを管理している企業で、エンドユーザーが自分のアクセス可能なデータを一覧できる社内データポータルを構築する。

Bash実装例
aws s3control list-caller-access-grants \
  --account-id 111122223333 \
  --instance-scope ALL \
  --region us-east-2 \
  --max-results 1000

効果: アカウントごとの照会処理が不要になり、1 回の API 呼び出しでユーザーがアクセス可能なすべての S3 データを表示できる。ポータルのツリー構造構築も容易になる。

2. AWS Storage Browser for S3 によるファイルブラウジング

シナリオ: オープンソースの UI コンポーネントである AWS Storage Browser for S3 を使用して、エンドユーザーに S3 バケットへのアクセス画面を提供する。ユーザーのグラントは複数アカウントに分散している。

実装: Storage Browser for S3 は ListCallerAccessGrants を使用して、エンドユーザーが S3 Access Grants に基づいてアクセスできるデータを表示する。InstanceScope: ALL により共有インスタンスのデータも同じ画面に表示できる。

効果: エンドユーザーは所属アカウントを意識することなく、アクセス権のあるすべての S3 データを単一のビューで参照できる。

3. クロスアカウントデータへの透過的なアクセス

シナリオ: データ分析チームが、他部門のアカウントで管理されているデータセットに対して一時認証情報を取得してアクセスする。どのアカウントがデータを所有しているかはアプリケーション側で管理したくない。

実装: GetDataAccess を InstanceScope: ALL で呼び出すと、指定した S3 パスの所有アカウントをサービスが特定し、該当インスタンスにルーティングして一時認証情報を返す。

効果: アプリケーションはパスとアカウントの対応表を持つ必要がなく、所有アカウントが変更された場合もコード修正なしで動作する。

✓利用可能リージョン: S3 Access Grants が提供されているすべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

🤝 AWS Resource Access Manager (AWS RAM)

S3 Access Grants インスタンスをアカウント間で共有するために使用する。本機能の横断照会は RAM 共有されたインスタンスが対象。

🪪 AWS IAM Identity Center

企業ディレクトリ ID に対するグラントの付与に使用。ID 対応セッションを通じてグラントの一覧を取得できる。

🖥️ AWS Storage Browser for S3

S3 バケットへのアクセス UI を提供するオープンソースコンポーネント。ListCallerAccessGrants を利用してユーザーがアクセス可能なデータを表示する。

✅ まとめ

S3 Access Grants の InstanceScope パラメータにより、複数の AWS アカウントにまたがるアクセスグラントを 1 回の API 呼び出しで一覧表示できるようになり、マルチアカウント環境でのデータアクセスの可視化とアプリケーション開発が大幅に簡素化されました。 複数アカウントの S3 データを扱うデータポータルやファイルブラウザを運用している場合は、アカウントごとの照会処理を InstanceScope: ALL による横断照会へ置き換えることを検討してください。
