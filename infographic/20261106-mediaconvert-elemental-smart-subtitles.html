🎬 Smart Subtitles とのネイティブ統合

📅 リリース日: 2026 年 11 月 6 日 | 🤖 AI による字幕自動生成をトランスコードジョブに統合

📝 概要

AWS Elemental MediaConvert が、AWS Elemental Inference 上に構築された AI 字幕生成ソリューション Smart Subtitles とのネイティブ統合を発表しました。最新の音声認識 (ASR) モデルを利用して音声から字幕を自動生成し、VOD のトランスコードおよびパッケージングワークフローの中で 字幕作成を 単一の MediaConvert ジョブ として直接実行できます。

サイドカー形式のテキスト字幕と映像への焼き込み (burn-in) の両方で出力でき、HLS や DASH などのストリーミング配信フォーマットにも対応します。カスタム辞書により固有名詞や専門用語の認識精度も向上できます。

🌍 ネイティブ対応 6 言語

🇺🇸 英語 (eng / eng-au / eng-gb / eng-us) 🇫🇷 フランス語 (fra) 🇩🇪 ドイツ語 (deu) 🇮🇹 イタリア語 (ita) 🇵🇹 ポルトガル語 (por) 🇪🇸 スペイン語 (spa)

❌ Before: アップデート前の課題

  • Amazon Transcribe などを組み合わせた外部キャプションパイプラインを別途構築・運用する必要があった
  • トランスコードと字幕生成が別ワークフローとなり、Step Functions や Lambda によるオーケストレーションや形式変換の手間が発生
  • 字幕ファイルとトランスコード出力のタイミング同期や成果物の管理を自前で実施

✅ After: アップデート後の改善

  • キャプションソースに「Smart subtitle」を選択するだけで、字幕生成からパッケージングまで 1 つのジョブで完結
  • サイドカー形式 (TTML など) と焼き込みの両方に対応し、HLS / DASH 配信用の字幕を直接出力
  • カスタム辞書で固有名詞や専門用語の認識精度をチューニング可能
  • 外部パイプラインが不要になり、運用負荷と配信リードタイムを削減

MediaConvert は Smart features を有効にしたジョブの実行中に Elemental Inference フィードを自動作成し、 入力メディアを送信して ASR による字幕メタデータを取得、トランスコード出力に組み込んだ後、 ジョブ終了時にフィードを 自動削除 します。

⚡ 主要機能

🎙️ 音声の自動文字起こしによる字幕生成
  • AWS Elemental Inference と最新の音声認識モデルによる自動字幕生成
  • 英語、フランス語、ドイツ語、イタリア語、ポルトガル語、スペイン語の 6 言語にネイティブ対応
  • 英語はオーストラリア英語 (eng-au)、イギリス英語 (eng-gb)、アメリカ英語 (eng-us) の地域バリアントも指定可能
🔗 トランスコードワークフローへのネイティブ統合
  • ジョブのキャプション設定で「Smart subtitle」をキャプションソースとして選択するだけで有効化
  • Elemental Inference フィードのライフサイクル (作成・メディア送信・メタデータ取得・削除) を MediaConvert が自動管理
  • サイドカー形式と焼き込みの両方に対応し、HLS / DASH などの配信形式で出力可能
📖 カスタム辞書による精度向上
  • 固有名詞、ブランド名、技術用語などを登録した辞書を参照して認識精度を向上
  • 辞書エントリには content (用語) と sounds_like (発音ヒント) を指定可能
  • CreateDictionary / UpdateDictionary などの Elemental Inference API またはコンソールで管理
⚙️ フィード設定ソース ARN によるオプション設定
  • 不適切表現フィルター (profanity filter) などのオプションは、事前作成した Elemental Inference フィードの ARN をジョブに指定して適用
  • フィルターは DISABLED (デフォルト)、CENSOR (アスタリスク置換)、DROP (削除) から選択可能 (英語、スペイン語、イタリア語のみ)

🛠️ 設定方法

📋 前提条件

✓Smart features が利用可能なリージョン (バージニア北部、オレゴン、アイルランド、ムンバイ、シドニー) で MediaConvert ジョブを実行すること
✓MediaConvert のサービスロールに Elemental Inference 関連の IAM 権限を追加していること
✓オンデマンドキューの「Maximum concurrent feeds」を 1 以上に設定していること (0 の場合、Smart features を使用するジョブは処理されない)
1
キューの最大同時フィード数を設定

コンソールの Queues -> 対象キュー -> Edit queue -> Maximum concurrent feeds を設定します。Smart features を有効にしたジョブは実行中に 1 つの Elemental Inference フィードを作成します。アカウント全体では「Active feeds per account」クォータを超えないようにします。上限を超えたジョブはキューイングされ、フィード容量が空き次第処理されます。

2
ジョブで Smart subtitle を有効化

MediaConvert コンソールで「Jobs」->「Create job」を選択し、出力グループと出力を追加。出力のエンコード設定で「Add captions」を選択し、「Captions source」で Smart subtitle を選択します。出力ビデオコーデックと互換性のある「Destination type」、「Audio source name」、音声ソースの言語に一致する「Language」を選択します。

3
オプション設定の適用 (必要に応じて)

不適切表現フィルターなどを設定したソースフィードを事前作成し、ジョブの「AWS integration」->「AWS Elemental Inference feed configuration source ARN」にその ARN を指定します。

Bash ソースフィードの作成例 
aws elemental-inference create-feed \
  --name "subtitle-config-feed" \
  --outputs '[{
    "name": "subtitles",
    "status": "ENABLED",
    "outputConfig": {
      "subtitling": {
        "language": "eng",
        "aspectRatio": {"width": 16, "height": 9},
        "profanityFilter": "CENSOR"
      }
    }
  }]'
4
カスタム辞書の作成 (必要に応じて)

ASR エンジンが認識しにくいブランド名や技術用語を辞書に登録し、ソースフィードの字幕出力設定から辞書 ID を参照します。辞書はベース言語コード (eng など) で作成し、エントリは JSON 配列で最大 40 KB まで登録できます。

Bash カスタム辞書の作成例 
aws elemental-inference create-dictionary \
  --name "my-terms" \
  --language "eng" \
  --entries '[{"content": "Kubernetes", "sounds_like": ["koo-ber-net-eez"]}]'

⚠アカウント全体の同時フィード数は「Active feeds per account」クォータに制限されるため、大量の並列実行時はクォータ引き上げを検討
⚠自動生成字幕の品質は音声の明瞭さに依存するため、公開前の品質確認プロセスや辞書によるチューニングを検討

🎯 ユースケース

1. VOD プラットフォームの字幕自動付与

シナリオ: 動画配信プラットフォームで、大量の VOD コンテンツに字幕を付与して HLS 配信したい。

実装: S3 に入力動画をアップロード → Apple HLS 出力グループを作成 → Captions source に Smart subtitle を選択 → Destination type に WebVTT などの HLS 互換形式を指定 → 字幕付き HLS 出力を CloudFront で配信

✅ 効果: 外部字幕パイプラインなしで、トランスコードと同時に配信用字幕を生成し、公開までのリードタイムを大幅に短縮
2. スポーツ・ニュース映像の専門用語対応字幕

シナリオ: 選手名、チーム名、専門用語が多いスポーツ映像の字幕精度を高めたい。

実装: CreateDictionary で選手名・チーム名を登録した辞書を作成 → 辞書 ID を参照するソースフィードを作成 → ジョブの AWS integration でソースフィード ARN を指定 → Smart subtitle を有効にしてジョブを実行

✅ 効果: ASR が認識しにくい固有名詞の誤変換を減らし、手動修正コストを削減
3. ファミリー向けコンテンツの不適切表現フィルタリング

シナリオ: 英語圏向けのファミリー向けコンテンツで、字幕中の不適切表現を自動的に伏せ字にしたい。

実装: profanityFilter を CENSOR に設定したソースフィードを作成 → ジョブでソースフィード ARN を指定し Smart subtitle を有効化 → 生成された字幕では不適切表現がアスタリスクに置換される

✅ 効果: 人手によるレビュー工数を削減しながら、ブランドセーフティ要件を満たした字幕を配信

💰 料金

Smart Subtitles を使用すると、Elemental Inference の推論料金 と MediaConvert のトランスコード料金 の両方が課金されます。 Smart features はすべて Professional Tier の機能であり、出力ごとに有効化されます。

💡 課金はジョブが正常に完了した場合のみ発生し、エラーまたはキャンセルされたジョブには両サービスとも課金されません。具体的な料金レートは各サービスの料金ページを参照してください。

🔗 関連サービス・機能

🤖 AWS Elemental Inference

メディアファイルから AI でメタデータを生成するマネージドサービス。Smart Subtitles のほか、Smart Cropping、コンテキストメタデータ、イベントクリッピングなどの機能を提供。

✂️ Smart Cropping

Elemental Inference を利用した既存の Smart feature。映像の主要被写体を検出して自動クロップを行う。Smart Subtitles はこれを補完するアドオン。

🪣 Amazon S3

入力メディアおよび字幕付きトランスコード出力の保存先。

📡 AWS Elemental MediaTailor / MediaLive

Elemental Inference のコンテキストメタデータと連携した広告挿入ワークフローを構成可能。

📌 まとめ

今回のアップデートにより、VOD ワークフローにおける字幕生成が MediaConvert ジョブ内で完結 するようになり、外部キャプションパイプラインの構築・運用が不要になりました。6 言語対応、カスタム辞書、 不適切表現フィルターなど実運用に必要な機能が揃っているため、対象リージョンで VOD 配信を行っている場合は、 既存の字幕ワークフローの置き換えを検討することを推奨します。

日本語は未対応のため、日本語コンテンツについては今後の言語拡大に注目してください。
