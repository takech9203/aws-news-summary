API Gateway API Portal による自動 API 検出 + AWS WAF API Security マネージドルールグループによる保護

📋 概要

AWS Organization 全体の API を自動的に検出し、AWS WAF で保護する自動 API 検出と保護機能が一般提供 (GA) になりました。Amazon API Gateway、Application Load Balancer、Amazon CloudFront の背後にあるすべての API が対象です。

検出はトラフィックログとサービス設定レコードから自動で行われるため、エージェントのデプロイやログ転送は不要です。保護はカスタムルールを一切書くことなく有効化できます。

❌ アップデート前の課題

  • API の全体像の把握には各アカウントの API Gateway、ALB、CloudFront を個別に棚卸しする必要があった
  • ゾンビ API やシャドー API を発見する仕組みがなく、未保護の API が放置されるリスクがあった
  • BOLA やクレデンシャルスタッフィングには WAF カスタムルールを独自に設計・運用する必要があった
  • API 検出にはエージェントのデプロイやログ転送基盤の構築など追加の運用負荷が発生していた

✅ アップデート後の改善

  • API Portal が Organization 全体の API をログと設定レコードから自動検出し、エージェントやログ転送が不要に
  • ゾンビ API・シャドー API の特定、態勢評価、WAF 未保護 API の報告が自動化
  • API Security マネージドルールグループで主要な API 攻撃への保護をカスタムルールなしで有効化
  • WAF 検出イベントが API Portal の findings に集約され、セキュリティ状況を一元把握

API Portal が API Gateway、ALB、CloudFront のトラフィックログと設定レコードから API を自動検出して findings を生成し、未保護の API に対して AWS WAF API Security マネージドルールグループによる保護を有効化できます。WAF が検出したイベントは API Portal の findings に集約されます。

⚡ 主要機能

🔍 1. API Gateway API Portal による自動 API 検出
✓AWS Organization 全体の API Gateway、ALB、CloudFront の背後にある API を検出
✓トラフィックログとサービス設定レコードから自動識別 — エージェントのデプロイやログ転送は不要
✓API を分類し、ゾンビ API (使われていないが残存) やシャドー API (管理外) を特定
📊 2. セキュリティ態勢の評価と findings のレポート
✓各 API のセキュリティ態勢を評価し、WAF 保護が欠如している API を含む findings をレポート
✓未保護の API には API Portal から WAF による保護を有効化可能
✓WAF の検出イベントも findings に集約され、API セキュリティの全体像を一元的に把握
🛡️ 3. AWS WAF API Security マネージドルールグループ

最も悪用されやすい API 攻撃カテゴリから API を保護します。他の AWS マネージドルールやカスタムルールと組み合わせて多層防御を構成できます。

💀 BOLA
Broken Object Level Authorization: リクエスト内のレコード ID を改ざんして他ユーザーのデータを読み取る攻撃
🔑 認証の不備・クレデンシャルスタッフィング
トークンの偽造や、窃取したパスワードの大規模な試行
🕵️ API の偵察と列挙
隠しルートの推測や公開ドキュメントの探査による API マッピング

🚀 設定方法

前提条件

  • AWS WAF を利用できる AWS アカウント (API Portal の組織全体での利用には AWS Organizations の設定が必要)
  • 保護対象の API が Amazon API Gateway、Application Load Balancer、または Amazon CloudFront の背後に存在すること
  • WAF Web ACL を作成・更新できる IAM 権限
1
API Portal で API を検出する

API Gateway コンソールの API Portal を開き、組織全体の API 検出を有効化します。トラフィックログと設定レコードから自動的に識別・分類・評価されます。エージェントのデプロイやログの転送作業は不要です。

2
findings を確認する

検出された API の一覧、ゾンビ API・シャドー API、セキュリティ態勢の評価結果、WAF 保護が欠如している API を確認します。

3
API Security マネージドルールグループで保護を有効化する
Bash Web ACL に API Security マネージドルールグループを追加する例 
aws wafv2 update-web-acl \
  --name my-web-acl \
  --scope REGIONAL \
  --id <web-acl-id> \
  --lock-token <lock-token> \
  --default-action Allow={} \
  --visibility-config SampledRequestsEnabled=true,CloudWatchMetricsEnabled=true,MetricName=my-web-acl \
  --rules '[{
    "Name": "APISecurityRules",
    "Priority": 0,
    "Statement": {
      "ManagedRuleGroupStatement": {
        "VendorName": "AWS",
        "Name": "AWSManagedRulesAPISecurity"
      }
    },
    "OverrideAction": { "None": {} },
    "VisibilityConfig": {
      "SampledRequestsEnabled": true,
      "CloudWatchMetricsEnabled": true,
      "MetricName": "APISecurityRules"
    }
  }]'

マネージドルールグループの正確な名称やパラメータは AWS WAF 開発者ガイド を確認してください。未保護の API に対しては、API Portal のコンソールから直接 WAF 保護を有効化することもできます。

4
イベントを確認する

WAF が検出したイベントは API Portal の findings に集約されます。ListEvents や GetEvent などの API で、イベントの詳細やタイムライン、関与したクライアントの情報を確認できます。

💡 メリット

💼 ビジネス面

✓API 資産の可視化: 組織全体の API インベントリを自動把握し、管理外 API によるリスクを低減
✓セキュリティ運用の省力化: カスタムルールの設計・運用なしで主要な API 攻撃への保護を有効化
✓コンプライアンス対応の強化: 態勢評価と findings で未保護 API を特定・是正するプロセスを確立

⚙️ 技術面

✓エージェントレスの検出: エージェントのデプロイやログ転送基盤の構築が不要
✓API 特有の攻撃への対応: BOLA やクレデンシャルスタッフィングをマネージドルールでカバー
✓既存ルールとの併用: 他のマネージドルールやカスタムルールと組み合わせた多層防御
✓検出から保護までの一貫性: findings と WAF イベントの統合で検出・保護・監視を単一ワークフロー化

⚠️ デメリット・制約事項

制限事項

✗API Portal は 32 の AWS リージョンで利用可能 (対象リージョンは Amazon API Gateway の FAQ を参照)
✗API Security は AWS GovCloud (US) リージョン、中国リージョン、AWS European Sovereign Cloud では利用不可
✗検出対象は API Gateway、ALB、CloudFront の背後にある API に限定される

考慮すべき点

⚠誤検知の可能性を考慮し、本番適用前にカウントモードでの評価を推奨
⚠組織全体での API 検出には AWS Organizations との連携設定が必要
⚠マネージドルールグループの利用には WAF の料金 (ルールグループ単位の課金) が発生するため、コストの事前確認を推奨

🎯 ユースケース

🏢 ユースケース 1: 組織全体の API インベントリの可視化とシャドー API の排除

シナリオ: 複数の AWS アカウントを運用する企業で、各開発チームが個別に API をデプロイしており、セキュリティチームが全体像を把握できていない。

実装: API Portal で Organization 全体の API を自動検出 → findings でゾンビ API・シャドー API を特定 → 不要な API を廃止し、必要な API には WAF 保護を有効化

✅ 管理外の API による攻撃面を削減し、組織全体の API セキュリティ態勢を継続的に監視できる
🛒 ユースケース 2: BOLA 攻撃からの顧客データ保護

シナリオ: EC サイトの注文照会 API で、攻撃者がリクエスト内の注文 ID を変更して他ユーザーの注文情報を取得しようとしている。

実装: Web ACL に API Security マネージドルールグループを追加 → BOLA 検出ルールでレコード ID 改ざんによるアクセスを検出・ブロック → 検出イベントを findings で確認し攻撃元クライアントを分析

✅ カスタムルールを書くことなく、オブジェクトレベル認可の不備を突く攻撃から顧客データを保護できる
🔐 ユースケース 3: クレデンシャルスタッフィング攻撃の防御

シナリオ: ログイン API に対して、漏洩したパスワードリストを使用した大規模なログイン試行が発生している。

実装: ログイン API を含む Web ACL にルールグループを適用 → 窃取クレデンシャルの大規模試行やトークン偽造を検出・ブロック → ListEventActors / GetEventActor API で攻撃に関与したクライアントを特定

✅ アカウント乗っ取りのリスクを低減し、攻撃の全体像をイベントのタイムラインで把握できる

💰 料金と利用可能リージョン

料金

AWS WAF のマネージドルールグループの料金体系に準じます。Web ACL、ルール、リクエスト数に応じた課金に加え、マネージドルールグループの利用料金が発生します。詳細は AWS WAF 料金ページ および Amazon API Gateway 料金ページ を参照してください。

💡 AWS WAF は 2026 年 11 月に簡素化された新料金体系を発表しており、あわせて確認することを推奨します。

🔗 関連サービス・機能

API Security ルールグループと併用可能な既存のマネージドルール群 (Core rule set、Known bad inputs など)。

🤖 AWS WAF AI Security

同時期に発表された AI エンドポイントの検出・保護機能。API Security と同様に検出から保護までを提供。

📝 まとめ

API Gateway API Portal と AWS WAF API Security マネージドルールグループの組み合わせにより、AWS Organization 全体の API の検出から保護までをカスタムルールなしで実現できるようになりました。複数アカウントで API を運用している組織は、まず API Portal で API インベントリと findings を確認し、保護されていない API に対して API Security ルールグループの適用を検討することを推奨します。
