CloudWatch Query Studio
一般提供開始

メトリクスの探索・クエリ・可視化を 1 画面で完結する統合ワークスペース
🗓️ 2026 年 6 月 15 日
✅ 一般提供 GA

💡 概要

AWS は Amazon CloudWatch Query Studio の一般提供を開始しました。CloudWatch コンソール内の単一インターフェイスから、クエリの作成からグラフ可視化までを 1 つの画面で完結できる、統合されたクエリ＆可視化エクスペリエンスです。

複数の AWS アカウントやリージョンにまたがるチームが、PromQL または Metrics Insights を使って OpenTelemetry メトリクスと AWS 標準メトリクスを単一ワークスペースからクエリできます。クエリごとのクロスアカウント / クロスリージョンセレクターにより、フリート全体のレイテンシーやエラー率を容易に相関分析できます。

😓 アップデート前の課題

  • 探索・クエリ作成・可視化で複数の画面や手順を行き来する必要があった
  • マルチアカウント / マルチリージョンの横断的な相関分析が容易ではなかった
  • PromQL や Metrics Insights の構文を手動で組み立てる必要があった

🚀 アップデート後の改善

  • 単一インターフェイスで探索・クエリ・可視化を完結できる
  • クエリごとのクロスアカウント / クロスリージョンセレクターでフリート全体を分析
  • ガイド付きビルダーで視覚的にクエリを構築できる

運用チームが複数のメトリクスソースを Query Studio で横断的にクエリし、可視化結果をダッシュボードやアラームに反映する流れを示しています。

⚙️ 主要機能

🪟 統合されたクエリ＆可視化エクスペリエンス

  • CloudWatch コンソール内の単一インターフェイスからメトリクスを探索
  • クエリ作成・実行・可視化を 1 つのワークスペースで完結
  • OpenTelemetry メトリクスと AWS 標準メトリクスの両方を対象にできる

🌐 クロスアカウント / クロスリージョンクエリ

  • クエリごとにクロスアカウント / クロスリージョンセレクターを指定可能
  • 複数アカウント・リージョンのフリート全体を単一ワークスペースから分析
  • レイテンシーやエラー率などの指標を横断的に相関分析

🛠️ ガイド付きクエリビルダー

  • PromQL と Metrics Insights (SQL) のそれぞれにガイド付きビルダーを用意
  • ビルダーモードでメトリクス名・ラベル・集計関数を参照しながら選択
  • エディターモードで直接クエリを記述することも可能
  • クエリ実行用のキーボードショートカットを提供

📈 豊富な可視化タイプ

  • デュアル Y 軸の設定に対応
  • シリーズオーバーライドに対応
折れ線 棒 散布図 ヒートマップ ヒストグラム 円 ゲージ 数値ウィジェット

📋 ダッシュボード統合と Grafana インポート

  • 任意の可視化を CloudWatch ダッシュボードのウィジェットとして追加
  • ウィジェットはダッシュボードの更新間隔でクエリを継続実行し最新状態を維持
  • Grafana のインポートをサポート
  • 単一の時系列を返すクエリから CloudWatch アラームを直接作成

🧭 設定方法

前提条件: ① CloudWatch を利用している AWS アカウント　② OTLP 経由または AWS 標準メトリクスが CloudWatch に取り込み済み　③ クロスアカウントクエリを使う場合はクロスアカウントオブザーバビリティの設定
1

Query Studio を開く

CloudWatch コンソールのナビゲーションペインで [Query Studio] を選択する。

2

クエリを構築する

[PromQL] / Metrics Insights を選び、[Builder] または [Editor] で記述。時間範囲を調整し [Run] で実行。

3

可視化を活用する

グラフ / テーブルを切替。[Add to dashboard] で保存、または [Create alarm] でアラーム作成。

✨ メリット

📊 ビジネス面

  • 運用効率の向上: 探索・クエリ・可視化を単一画面で完結し作業時間を短縮
  • マルチアカウント可視性: フリート全体を横断分析し問題特定を迅速化
  • 既存資産の活用: Grafana インポートで既存ダッシュボードを取り込み

🔩 技術面

  • オープン標準対応: PromQL と OpenTelemetry でオープンソース標準を活用
  • 柔軟な可視化: 8 種の可視化タイプ、デュアル Y 軸、シリーズオーバーライド
  • ガイド付き構築: ビルダーモードで構文の手動組み立て負担を軽減

⚠️ デメリット・制約事項

制限事項
  • 中東 (UAE)、中東 (バーレーン)、イスラエル (テルアビブ) リージョンでは利用できない
  • アラームの直接作成は、単一の時系列を返すクエリに限定される
考慮すべき点
  • クロスアカウントクエリには CloudWatch クロスアカウントオブザーバビリティの事前設定が必要
  • PromQL / Metrics Insights クエリやメトリクス取り込みに伴う CloudWatch の料金が発生

🎯 ユースケース

1. マルチアカウントフリートの障害調査

シナリオ: 複数アカウント・リージョンにマイクロサービスを展開するチームが、特定サービスのレイテンシー急増を調査する。

Steps
1. Query Studio を開く
2. クロスアカウント / クロスリージョンセレクターで対象を選択
3. PromQL でレイテンシーとエラー率をクエリし、ヒートマップで可視化

💡 効果: フリート全体のレイテンシーとエラー率を 1 ワークスペースで相関分析し、障害の発生源を迅速に特定。

2. OpenTelemetry メトリクスの可視化

シナリオ: OTLP 経由でアプリメトリクスを CloudWatch に取り込むチームが、アクティブリクエスト数をモニタリングする。

PromQL
{"http.server.active_requests"}

💡 効果: ガイド付きビルダーで構築し折れ線グラフで可視化、ダッシュボードに追加して継続的にモニタリング。

3. 既存 Grafana ダッシュボードの移行

シナリオ: 既存の Grafana ダッシュボードを CloudWatch に集約したいチームが可視化資産を移行する。

Steps
1. Query Studio で Grafana インポート機能を使用
2. インポートしたクエリと可視化を確認
3. CloudWatch ダッシュボードのウィジェットとして保存

💡 効果: 既存資産を再利用しながら CloudWatch に統合でき、移行コストを抑制。

💰 料金と利用可能リージョン

料金: Query Studio 自体の追加料金に関する記載は公式発表・ドキュメントに含まれていません。実際の費用は、実行する PromQL / Metrics Insights クエリやメトリクス取り込みに伴う Amazon CloudWatch の料金体系に基づきます。最新の料金は CloudWatch 料金ページで確認してください。
🌍 すべての商用 AWS リージョンで利用可能 除外: 中東 (UAE) / 中東 (バーレーン) / イスラエル (テルアビブ)

📝 まとめ

Query Studio の一般提供により、メトリクスの探索・クエリ・可視化を単一インターフェイスで完結できるようになりました。特にマルチアカウント・マルチリージョン環境を運用するチームにとって、フリート全体の横断的な分析を効率化する有力な選択肢です。まずは CloudWatch コンソールから Query Studio を開き、ガイド付きビルダーで PromQL や Metrics Insights のクエリを試してみましょう。
