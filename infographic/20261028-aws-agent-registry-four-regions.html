🗂️ AWS Agent Registry
4 つの追加リージョンで利用可能に

📅 リリース日: 2026 年 10 月 28 日
AWS Agent Registry Amazon Bedrock AgentCore リージョン拡大

📌 概要

AWS Agent Registry が、欧州 (ロンドン)、欧州 (フランクフルト)、米国東部 (オハイオ)、カナダ (中部) の 4 リージョンで新たに利用可能になりました。今回の拡大により、利用可能リージョンは合計 9 リージョンになります。

AWS Agent Registry は Amazon Bedrock AgentCore を通じて提供されるフルマネージドな検出サービスで、MCP サーバー、ツール、エージェント、エージェントスキル、カスタムリソースを検索可能なレジストリに公開し、承認ワークフローによるアクセス制御を行い、人間と AI エージェントの双方がハイブリッド検索、カタログブラウズ、ネイティブ MCP エンドポイントを通じて適切なリソースを発見できます。

❌ アップデート前の課題

  • 5 リージョン (バージニア北部、オレゴン、アイルランド、東京、シドニー) に限定され、英国、ドイツ、カナダにデータレジデンシー要件を持つ組織は利用が困難だった
  • 欧州ではアイルランドのみの提供で、ロンドンやフランクフルト主体のワークロードはレジストリへのアクセスにリージョン間通信が必要だった
  • 米国東部はバージニア北部のみの提供で、オハイオを利用するマルチリージョン構成ではレジストリを同一リージョンに配置できなかった

✅ アップデート後の改善

  • ロンドン、フランクフルト、オハイオ、カナダ中部でレジストリを作成し、エージェントやツールのカタログを同一リージョン内で運用可能に
  • 英国、ドイツ、カナダのデータレジデンシーやコンプライアンス要件に対応しながら、エージェント資産の一元管理とガバナンスを実現
  • ワークロードと同一リージョンにレジストリを配置し、検索や MCP エンドポイント呼び出しのレイテンシーを低減

今回の拡大により、既存の 5 リージョンに新規 4 リージョンが加わり、合計 9 リージョンで AWS Agent Registry を利用できます。各リージョンでレジストリを作成し、人間と AI エージェントの双方がリソースを検出できます。

⚙️ 主要機能

🌍 1. 4 リージョンへの提供拡大
  • 欧州 (ロンドン / eu-west-2)、欧州 (フランクフルト / eu-central-1)、米国東部 (オハイオ / us-east-2)、カナダ (中部 / ca-central-1) で新たに利用可能
  • 既存の 5 リージョンと合わせて合計 9 リージョンでの提供
  • 最新のリージョン別提供状況は AWS Regional Services List で確認可能
🔍 2. 新リージョンでも利用できる主要機能
  • MCP サーバー、ツール、エージェント、エージェントスキル、カスタムリソースの検索可能なレジストリへの公開
  • 承認ワークフローによるアクセス制御と、キュレーターによるレコードのライフサイクル管理
  • セマンティック検索とキーワード検索を組み合わせたハイブリッド検索、カタログブラウズ、ネイティブ MCP エンドポイントによる検出
🏢 3. エンタープライズ機能への対応
  • AWS RAM によるクロスアカウント共有、AWS Organizations 連携、Amazon EventBridge 通知、AWS CloudTrail による監査、AWS PrivateLink 対応などの既存機能を新リージョンでも活用可能
  • IAM 認証または corporate IdP の JWT 認証を選択してレジストリの MCP エンドポイントへのアクセスを制御可能

🛠️ 設定方法

📋 前提条件

✓AWS アカウントと、AWS Agent Registry を操作できる IAM 権限
✓新リージョン (ロンドン、フランクフルト、オハイオ、カナダ中部) のいずれかを利用する場合は、該当リージョンを指定して操作すること
✓クロスアカウント共有を利用する場合は AWS RAM の利用権限

ステップ 1: 新リージョンでレジストリを作成

Bashレジストリの作成
aws agent-registry create-registry \
  --region eu-west-2 \
  --name "uk-agent-registry" \
  --description "UK workloads agent registry"

--region に新しく利用可能になったリージョン (例: eu-west-2) を指定してレジストリを作成します。データレジデンシー要件に応じて、ワークロードと同一リージョンにレジストリを配置します。

ステップ 2: レコードの登録と承認

Bashレコードの登録
aws agent-registry create-registry-record \
  --region eu-west-2 \
  --registry-id <registry-id> \
  --name "customer-support-agent" \
  --record-type AGENT

MCP サーバー、エージェント、スキルなどのレコードを登録します。登録されたレコードは承認ワークフローを経て検出可能になります。

ステップ 3: リソースの検索

Bashハイブリッド検索
aws agent-registry search-discoverable-registry-records \
  --region eu-west-2 \
  --registry-id <registry-id> \
  --query-text "customer support automation"

承認済みレコードをハイブリッド検索で検索します。MCP 互換クライアントからレジストリの MCP エンドポイントに接続して検索することも可能です。

⚠️注意: 上記の CLI コマンドはパラメータ構造を示すための例です。正確なコマンド体系は AWS Agent Registry ドキュメントを参照してください。

💡 メリット

💼 ビジネス面

✓データレジデンシー対応: 英国、ドイツ、カナダにデータ所在地要件を持つ組織が、要件を満たしながらエージェント資産の一元管理を導入できる
✓ガバナンス適用範囲の拡大: より多くのリージョンでエージェントやツールのカタログ化と承認ワークフローを適用でき、組織全体の AI ガバナンスを強化できる
✓導入障壁の低減: これまでリージョン制約で導入を見送っていた組織が、既存ワークロードのリージョン内で利用を開始できる

🔧 技術面

✓レイテンシー低減: エージェントワークロードと同一リージョンにレジストリを配置することで、検索や MCP エンドポイント呼び出しのリージョン間通信を排除できる
✓マルチリージョン構成との整合: オハイオなどを利用するマルチリージョン構成において、レジストリを各リージョンに配置する設計が可能になる
✓既存機能をそのまま利用可能: ハイブリッド検索、承認ワークフロー、MCP ネイティブアクセスなどの機能を新リージョンでも同様に利用できる

⚠️ デメリット・制約事項

🚧 制限事項

⚠️利用可能リージョンは 9 リージョンであり、大阪リージョンなどその他のリージョンでは引き続き利用できない
⚠️最新の提供状況は AWS Regional Services List での確認が必要

🤔 考慮すべき点

⚠️レジストリはリージョナルリソースであるため、複数リージョンで運用する場合はレジストリの配置戦略 (リージョンごとに分けるか、単一リージョンに集約するか) の設計判断が必要
⚠️クロスアカウント・クロスリージョンでの利用形態に応じて、AWS RAM 共有や認証設定 (IAM / JWT) の構成を検討する必要がある

🎯 ユースケース

🇬🇧 ユースケース 1: 英国・ドイツのデータレジデンシー要件下でのエージェントカタログ構築

シナリオ: 英国の金融機関がエージェントや MCP ツールの社内カタログを構築したいが、データを英国内に保持する要件があり、これまでアイルランドリージョンの利用が難しかった。

Bash実装例
aws agent-registry create-registry \
  --region eu-west-2 \
  --name "uk-financial-agent-registry"

効果: ロンドンリージョン内でレジストリを完結させ、データレジデンシー要件を満たしながら、承認ワークフローとハイブリッド検索によるガバナンス付きのエージェント検出を実現できる。

🇨🇦 ユースケース 2: カナダのワークロードと同一リージョンでの低レイテンシー検出

シナリオ: カナダ (中部) で AgentCore 上のエージェントを運用しており、エージェントが実行時にレジストリの MCP エンドポイントからツールを検出する構成を取りたい。

Bash実装例
aws agent-registry create-registry \
  --region ca-central-1 \
  --name "ca-agent-registry"

効果: エージェントとレジストリが同一リージョンに配置され、リージョン間通信なしで低レイテンシーなツール検出が可能になる。

🇺🇸 ユースケース 3: 米国東部でのマルチリージョン構成への組み込み

シナリオ: バージニア北部とオハイオの 2 リージョンでワークロードを展開しており、各リージョンでエージェント資産のカタログを運用したい。

Bash実装例
# 各リージョンにレジストリを作成
aws agent-registry create-registry --region us-east-1 --name "use1-registry"
aws agent-registry create-registry --region us-east-2 --name "use2-registry"

効果: 両リージョンでレジストリを運用でき、リージョン単位の独立性を保ちながらエージェント資産を管理できる。

💰 料金

AWS Agent Registry は Amazon Bedrock AgentCore を通じて提供される従量課金制のサービスです。今回のリージョン拡大による料金体系の変更はアナウンスされていません。料金の詳細は Amazon Bedrock AgentCore の料金ページで確認してください。

🔗 関連サービス・機能

🤖 Amazon Bedrock AgentCore
AWS Agent Registry は AgentCore を通じて提供。AgentCore Runtime および Gateway 上のエージェント・MCP サーバーの自動検出にも対応
🤝 AWS Resource Access Manager
レジストリのクロスアカウント共有による組織全体レジストリの構築に使用
📨 Amazon EventBridge
レコードの承認ワークフローのイベント駆動連携に使用
📜 AWS CloudTrail
レジストリに対する全操作の監査証跡を記録
🔒 AWS PrivateLink
クローズドなネットワーク環境からのレジストリアクセスに対応

📝 まとめ

AWS Agent Registry が欧州 (ロンドン)、欧州 (フランクフルト)、米国東部 (オハイオ)、カナダ (中部) に拡大し、合計 9 リージョンで利用可能になりました。英国、ドイツ、カナダにデータレジデンシー要件を持つ組織や、米国東部でマルチリージョン構成を採用する組織は、ワークロードと同一リージョンでエージェント資産の一元管理とガバナンスを導入できます。

✓該当リージョンでエージェントや MCP サーバーを運用している場合は、レジストリの作成と既存資産のカタログ化から始めることを推奨します
