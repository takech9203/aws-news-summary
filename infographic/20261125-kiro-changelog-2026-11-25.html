🧠 GPT 6.2 Astra Preview、クレジットプーリング使用上限とオーバーエイジ、CLI 3.6 パッチ

GPT 6.2 Astra Preview (Kiro Enterprise 向け)、クレジットプーリング使用上限とオーバーエイジ (Enterprise Management)、CLI 3.6 のパッチ 3.6.1 / 3.6.2

📝 概要

2026 年 11 月 25 日付の Kiro Changelog では、Models、General、CLI の 3 カテゴリでアップデートが発表されました。Kiro Enterprise 組織向けの新しいフロンティアモデルの提供開始と、エンタープライズ管理機能の強化が中心です。

1️⃣ GPT 6.2 Astra Preview (Models)

Kiro Enterprise 組織向けに全 Kiro クライアントで Preview としてロールアウト開始。既存コードベースでの変更の実装とテストなど、複雑でマルチステップのプロジェクトに向けた OpenAI のフロンティアモデルで、1M トークンのコンテキストウィンドウを備えます。推論は US ジオグラフィーのみで実行されます。

2️⃣ クレジットプーリング使用上限とオーバーエイジ (General)

Enterprise 管理者が Controls で credit_pool.usage_limit (ユーザーごとのプールクレジット使用上限) と overages (アカウント全体のオーバーエイジのオン / オフ) を設定できるようになりました。

3️⃣ CLI 3.6 パッチ 3.6.1 / 3.6.2 (CLI)

SubagentStop フック、Hook 出力の完全保存、ガイド付きコンパクションを追加した CLI 3.6 リリースに、パッチ 3.6.1 と 3.6.2 が同日付で公開されました。

🧠 GPT 6.2 Astra Preview (Models)
  • Kiro Enterprise 組織向けに、全 Kiro クライアントで Preview としてロールアウトを開始
  • 既存コードベースでの変更の実装とテストなど、複雑でマルチステップのプロジェクトに向けた OpenAI のフロンティアモデル
  • 1M トークンのコンテキストウィンドウを搭載
  • クレジット倍率は 7.2 倍。272K トークンを超えるリクエストでは 14.4 倍に上昇
  • 推論は US ジオグラフィーのみで実行される
  • Preview 期間中はアクセスが制限されており、アクセスを持つ組織はモデルガバナンス経由で有効化できる
📊 クレジットプーリング使用上限とオーバーエイジ (General / Enterprise Management)
  • Enterprise 管理者が Controls でクレジットプーリングの使用上限とオーバーエイジを設定可能に
  • credit_pool.usage_limit で、各ユーザーが請求サイクルごとに使用できるプールクレジットの上限を設定
  • プロファイルの control に設定すると各ユーザーのデフォルト上限になり、グループまたはユーザーに割り当てた control にも設定できる
  • 優先順位は、ユーザー自身の上限が最優先、次にユーザーが所属するグループの中で最も高い上限、最後にプロファイルの上限
  • プロファイルの control の overages で、アカウント全体のオーバーエイジのオン / オフを切り替え
  • Controls に移行していないプロファイルは、引き続き Kiro コンソールの Credit sharing ページで使用上限を設定
💻 CLI 3.6 パッチ 3.6.1 / 3.6.2 (CLI)
  • SubagentStop フック、Hook 出力の完全保存、ガイド付きコンパクションを追加した CLI 3.6 リリースに、パッチ 3.6.1 / 3.6.2 が 2026 年 11 月 25 日付で公開
  • CLI 3.6 には、V3 セッションでサブエージェント終了時に追加指示を 1 回送信できる SubagentStop フック、3,000 文字を超える Hook 出力の完全保存、/compact にサマリーへ残す内容を指示できるガイド付きコンパクションが含まれる
  • このほか、会話のリキャップ、通知コントロール、マネージド V2 コントロール、全ユーザー向け Windows インストーラーも追加

🛠️ 設定方法

✅ 前提条件

✔GPT 6.2 Astra を利用するには、Kiro Enterprise 組織であり、Preview アクセスが許可されていること
✔クレジットプーリングの使用上限とオーバーエイジを Controls で設定するには、Enterprise Management (プレビュー、us-east-1 または eu-central-1) を利用し、プロファイルが Controls に移行済みであること
✔CLI 3.6 の新機能を使用するには、Kiro CLI を 3.6 系 (最新パッチは 3.6.2) へ更新し、V3 セッションを利用すること

📋 手順

1
モデルガバナンスで GPT 6.2 Astra を有効化する

Preview アクセスを持つ組織の管理者は、モデルガバナンスで GPT 6.2 Astra を有効化します。有効化後、ユーザーは IDE、CLI、Web などの各 Kiro クライアントでモデルを選択できます。

2
クレジットプーリングの使用上限を設定する

Controls でプロファイルの control に credit_pool.usage_limit を設定し、各ユーザーのデフォルト上限を定義します。特定のグループやユーザーに異なる上限を適用する場合は、グループまたはユーザーに割り当てた control に設定します。ユーザー自身の上限、所属グループの最も高い上限、プロファイルの上限の順に適用されます。

3
オーバーエイジを設定する

プロファイルの control で overages を設定し、アカウント全体のオーバーエイジのオン / オフを切り替えます。

4
CLI を最新パッチへ更新する

Kiro CLI を 3.6.2 へ更新し、V3 セッションで SubagentStop フックやガイド付きコンパクション (/compact に続けて指示を記述) を利用します。

💡 メリット

💼 ビジネス面
  • 大規模プロジェクトへの適用: 1M コンテキストウィンドウを持つ GPT 6.2 Astra により、既存コードベースでの変更の実装とテストのような複雑でマルチステップの作業を組織で検証できる
  • コスト管理の強化: credit_pool.usage_limit により、ユーザーごとのプールクレジット消費を請求サイクル単位で制御し、予算超過を防げる
  • 柔軟なガバナンス: オーバーエイジのオン / オフをアカウント全体で一括制御でき、組織のコストポリシーに合わせた運用ができる
⚙️ 技術面
  • モデル選択肢の拡大: Anthropic のモデルに加えて OpenAI のフロンティアモデルを同じ Kiro クライアントとガバナンスの枠組みで利用できる
  • きめ細かな上限設定: プロファイル / グループ / ユーザーの 3 レベルで上限を設定でき、明確な優先順位に基づいて適用される
  • CLI の安定性向上: CLI 3.6 系にパッチ 3.6.1 / 3.6.2 が提供され、SubagentStop フックやガイド付きコンパクションを含む最新機能を安定した環境で利用できる

⚠️ デメリット・制約事項

🚧 制限事項

✖GPT 6.2 Astra は Preview であり、アクセスが制限されている。利用にはアクセス許可とモデルガバナンスでの有効化が必要
✖GPT 6.2 Astra の推論は US ジオグラフィーのみで実行される
✖GPT 6.2 Astra は Kiro Enterprise 組織向けであり、個人プランでは利用できない
✖Enterprise Management はプレビューで、米国東部 (バージニア北部) us-east-1 と欧州 (フランクフルト) eu-central-1 のみで提供される
✖Controls に移行していないプロファイルでは、使用上限は従来どおり Kiro コンソールの Credit sharing ページで設定する

🤔 考慮すべき点

⚠GPT 6.2 Astra のクレジット倍率は 7.2 倍と高く、272K トークンを超えるリクエストでは 14.4 倍になるため、1M コンテキストを活用する長大なリクエストはクレジット消費が大きい
⚠データレジデンシー要件がある組織は、推論が US ジオグラフィーのみで実行される点を確認する必要がある
⚠使用上限はユーザー > グループ > プロファイルの優先順位で適用されるため、複数の control を併用する場合は意図した上限が適用されるか確認が必要
