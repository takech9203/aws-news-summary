Amazon MQ for RabbitMQ

🐰 プライベートネットワーク接続
のサポート

リリース日
2026.06.18

📌 概要

Amazon MQ for RabbitMQ が プライベートネットワーク接続 に対応しました。RabbitMQ ブローカーが、お客様の VPC 内のプライベートリソースへ パブリック公開なし で接続できるようになります。

接続は Amazon VPC Lattice、AWS RAM、AWS PrivateLink を用いて確立され、基盤インフラは Amazon MQ がお客様に代わってマネージドします。LDAP / OAuth 2.0 による認証、RabbitMQ Federation / Shovel によるブローカー間連携などを、運用負荷を抑えながら安全に構成できます。

❌ Before（これまで）
  • NLB と NAT Gateway を組み合わせた回避策の構築が必要
  • プライベート IdP (LDAP / OAuth 2.0) へ到達する標準的な手段がない
  • 回避策用リソースの構築・保守でコストと運用負荷が増大
➡
✅ After（今回）
  • VPC 内のプライベートリソースへ公開せず接続可能
  • NLB / NAT Gateway による回避策が不要に
  • VPC Lattice / RAM / PrivateLink の基盤を Amazon MQ が代理管理

RabbitMQ ブローカーは VPC Lattice・AWS RAM・PrivateLink を経由し、お客様の VPC 内のプライベートリソースへパブリック公開なしに接続する

⭐ 主要機能

🔐 VPC 内プライベートリソースへの接続
  • RabbitMQ ブローカーが VPC 内のプライベートリソースへ接続可能
  • 対象リソースをパブリックに公開する必要がない
  • セキュリティおよびコンプライアンス要件を満たしやすい
🔑 プライベートな認証バックエンドとの統合
  • プライベートな ID プロバイダー (LDAP、OAuth 2.0) にブローカーから到達
  • 認証情報をパブリックネットワークに露出させずに認証連携を構成
🔁 ブローカー間およびセルフホスト連携
  • 他の Amazon MQ for RabbitMQ ブローカーへの接続をサポート
  • セルフホストの RabbitMQ ブローカーへの接続をサポート
  • RabbitMQ Federation や Shovel によるメッセージ連携をプライベート経路で実現
⚙️ マネージドな接続基盤
  • VPC Lattice、AWS RAM、AWS PrivateLink を用いて接続を確立
  • 基盤インフラは Amazon MQ がお客様に代わって管理

🛠️ 設定方法

前提条件

✓Amazon MQ for RabbitMQ ブローカーが作成済みであること
✓利用するリージョンで Amazon VPC Lattice が利用可能であること
✓接続先のプライベートリソース (LDAP、OAuth 2.0、RabbitMQ など) が VPC 内に存在すること

セットアップ手順

1
VPC Lattice リソースゲートウェイの作成

接続先のプライベートリソースが存在する VPC に、VPC Lattice のリソースゲートウェイを作成。プライベートリソースへの接続経路の起点となる。

2
リソース構成を AWS RAM リソース共有にパッケージ化

接続対象のリソース構成 (resource configurations) を AWS RAM のリソース共有としてパッケージ化し、Amazon MQ ブローカーと共有できる状態にする。

3
ブローカーへの関連付け

作成したリソース共有を Amazon MQ for RabbitMQ ブローカーに関連付け。完了するとブローカーはプライベートリソースへパブリック公開なしに接続できる。

💡 メリット

ビジネス面

✓セキュリティ / コンプライアンス強化: リソースを公開せず接続できる
✓運用負荷の削減: NLB / NAT Gateway の構築・保守が不要
✓マネージド化の安心感: 接続基盤を Amazon MQ が管理し本業に集中

技術面

✓回避策の排除: 複雑なネットワーク構成が不要に
✓標準的な統合手段: VPC Lattice / RAM / PrivateLink を利用
✓連携の簡素化: Federation / Shovel をプライベート経路で構成

⚠️ デメリット・制約事項

制限事項

✗Amazon MQ for RabbitMQ ブローカーでのみ利用可能 (他エンジンは対象外)
✗Amazon VPC Lattice が利用可能なリージョンに限定
✗VPC Lattice / RAM / PrivateLink の利用に伴う追加料金が発生する可能性

考慮すべき点

●VPC Lattice リソースゲートウェイと AWS RAM リソース共有の設定が必要
●既存の NLB / NAT Gateway 回避策からの移行計画を検討する必要がある

🎯 ユースケース

1. プライベート ID プロバイダーによる認証

シナリオ: VPC 内の LDAP / OAuth 2.0 ID プロバイダーで RabbitMQ ブローカーの認証を行いたい。

ブローカー → VPC Lattice リソースゲートウェイ → プライベート LDAP / OAuth 2.0 サーバー

効果: 認証バックエンドを公開せずに、認証連携を安全に構成できる。

2. RabbitMQ Federation / Shovel によるブローカー間連携

シナリオ: 複数の Amazon MQ for RabbitMQ ブローカー間で Federation / Shovel を用いてメッセージを連携させたい。

ブローカー A → マネージド接続基盤 (VPC Lattice / RAM / PrivateLink) → ブローカー B

効果: NLB / NAT Gateway なしでプライベート経路のブローカー間連携を実現。

3. セルフホスト RabbitMQ との接続

シナリオ: VPC 内のセルフホスト RabbitMQ と Amazon MQ for RabbitMQ を連携させたい。

Amazon MQ ブローカー → マネージド接続基盤 → セルフホスト RabbitMQ ブローカー

効果: ハイブリッドなメッセージング構成をプライベートかつマネージドな経路で構成。

💰 料金とリージョン

プライベートネットワーク接続機能そのものに加え、接続に利用される Amazon VPC Lattice、AWS RAM、AWS PrivateLink の利用に応じた料金が発生する場合があります。詳細は Amazon MQ の料金ページおよび各サービスの料金ページを参照してください。

🌍 Amazon MQ for RabbitMQ で利用でき、Amazon VPC Lattice が利用可能なすべての AWS リージョン で提供されます。

🔗 関連サービス・機能

▸ Amazon VPC Lattice — リソースゲートウェイを通じてプライベートリソースへの接続経路を提供
▸ AWS Resource Access Manager (AWS RAM) — リソース構成をリソース共有としてパッケージ化しブローカーと関連付け
▸ AWS PrivateLink — プライベートで安全な接続を実現
▸ RabbitMQ Federation / Shovel — ブローカー間およびセルフホスト RabbitMQ とのメッセージ連携

📝 まとめ

Amazon MQ for RabbitMQ のプライベートネットワーク接続は、これまで NLB / NAT Gateway による回避策 を必要としていたプライベートリソースへの接続を、VPC Lattice・AWS RAM・PrivateLink を用いたマネージドな仕組みで実現します。LDAP / OAuth 2.0 認証、Federation / Shovel 連携、セルフホスト RabbitMQ との接続を、セキュリティとコンプライアンスを保ちながら構成できます。RabbitMQ 利用者は、既存の回避策の見直しと本機能への移行を検討することをお勧めします。
