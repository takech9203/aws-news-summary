🖼️ Dynamic Image Transformation for Amazon CloudFront
4 つの新機能を追加

📅 リリース日: 2026 年 9 月 8 日
拡張スマートクロッピング / マルチティアデバイス検出 / 画像変換プレイグラウンド / ECS・Lambda 機能パリティ

📌 概要

Dynamic Image Transformation for Amazon CloudFront (DIT、旧称 Serverless Image Handler) に 4 つの新機能が追加されました。DIT は画像の事前処理や複数バージョンの保持を不要にし、リアルタイムで画像の変換・最適化を行う AWS ソリューションです。E コマースやメディアなど、多様なデバイスに大量の画像を配信するワークロードで、運用コスト削減とユーザー体験向上の両面で価値があります。

4 つ
追加された新機能
約 30%
Client Hints 非対応で未最適化だったトラフィックを解消
6 MB / 100 MB
Lambda / ECS の最大対応画像サイズ

❌ アップデート前の課題

  • スマートクロッピングは顔検出が中心で、商品・テキスト・ロゴ・カスタムオブジェクトの保持を単一リクエストで組み合わせ不可
  • 自動最適化は Client Hints 依存で、非対応の約 30% のトラフィック (スマート TV など) は未最適化のまま配信
  • 変換ポリシーの動作・性能を事前検証する手段がなく、本番前テストに手間
  • Lambda と ECS で機能差があり、アーキテクチャ選択が機能要件に制約

✅ アップデート後の改善

  • 顔・ラベル・テキスト・ロゴ・カスタム Rekognition モデルを単一リクエストで組み合わせ、アスペクト比・パディング・グラビティ制約を優先度に応じて設定可能
  • Client Hints + CloudFront デバイス分類ヘッダー + フォールバックのティア型検出で、ブラウザ以外の全デバイスに最適サイズを配信
  • プレイグラウンドでサイズ・フォーマット・圧縮率・処理時間などの拡張メトリクスを確認し性能を検証可能
  • ECS / Lambda で同一機能セットとなり、性能・コスト要件のみでアーキテクチャを選択可能

多様なデバイスからのリクエストを CloudFront が受け付け、Client Hints・CloudFront デバイス分類ヘッダー・フォールバックの 3 層でデバイスを検出し、DIT (ECS または Lambda) が S3 上の元画像を Rekognition と連携しながら変換・最適化して配信するフローを示しています。

🚀 主要機能

1️⃣ 拡張スマートクロッピング (カスタムラベル検出 + 高度な構図コントロール)

  • 顔、ラベル、テキスト、ロゴ、カスタム Amazon Rekognition モデルなど複数の検出方法を単一リクエストで組み合わせ可能
  • クロップ後の画像内に商品、テキスト、ロゴ、カスタムオブジェクトを確実に保持
  • アスペクト比、パディング、グラビティ (重心位置) の制約をビジネス要件の優先度に応じて設定可能

2️⃣ 自動画像最適化の強化 (マルチティアデバイス検出)

  • Client Hints の背後に CloudFront のデバイス分類ヘッダーと設定可能なフォールバックを階層化するティア型検出
  • Client Hints 非対応により未最適化だった約 30% のトラフィックのギャップを解消
  • スマートフォン、タブレットからスマート TV まで、あらゆるデバイスタイプに適切なサイズの画像を配信

3️⃣ インタラクティブな画像変換プレイグラウンド

  • 変換後の画像を表示しながら変換のテスト・検証が可能
  • 元画像・出力画像のサイズ、フォーマット、ファイルサイズ、圧縮率、処理時間などの拡張メトリクスを表示
  • 変換ポリシーのパフォーマンスを本番適用前に検証可能

4️⃣ ECS / Lambda アーキテクチャ間の完全な機能パリティ

  • 従来 ECS のみで提供されていた機能を含め、両アーキテクチャで同一の機能セットを利用可能
  • 機能要件ではなく、画像サイズ・性能・コスト要件に基づいたアーキテクチャ選択が可能

⚙️ 設定方法

📋 前提条件

✓AWS アカウントと、CloudFormation スタックをデプロイできる IAM 権限
✓元画像を格納する Amazon S3 バケット (ECS アーキテクチャでは非 S3 オリジンも利用可能)
✓カスタムモデル使用時は、Amazon Rekognition Custom Labels のトレーニング済みモデル
1

CloudFormation テンプレートのデプロイ

BashCloudFormation スタックの作成
# 実装ガイドから CloudFormation テンプレートを取得してデプロイ
aws cloudformation create-stack \
  --stack-name dynamic-image-transformation \
  --template-url <実装ガイド記載のテンプレート URL> \
  --capabilities CAPABILITY_IAM

デプロイ時に Lambda または ECS アーキテクチャを選択します。ソースコードは GitHub リポジトリ (aws-solutions/serverless-image-handler) から取得し、AWS CDK でのデプロイも可能です。

2

画像変換の指定

TextURL クエリパラメータでの変換指定
# URL クエリパラメータまたは事前定義の変換ポリシーで変換を指定
https://<CloudFront ドメイン>/<画像パス>?width=800&format=auto

URL クエリパラメータ、または事前定義した変換ポリシーで指定します。自動最適化を有効にすると、マルチティアデバイス検出に基づきデバイスごとに適切なサイズ・フォーマットで配信されます。

3

プレイグラウンドでの検証

デプロイ後に利用できる画像変換プレイグラウンドで、変換結果の画像と拡張メトリクス (元画像・出力画像のサイズ、フォーマット、ファイルサイズ、圧縮率、処理時間) を確認し、変換ポリシーの動作とパフォーマンスを本番適用前に検証します。

💡 メリットと考慮点

📈 ビジネス面のメリット

✓コンバージョン率の向上: 商品・ロゴ・テキストを欠かさないクロッピングで、画像品質を維持したまま多様な表示枠に対応
✓配信コストの削減: 約 30% の未最適化トラフィックにも右サイズの画像を配信し、帯域幅コストを削減
✓ユーザー体験の向上: デバイスごとの最適配信でページ読み込み時間を短縮

🛠️ 技術面のメリット

✓画像パイプラインの簡素化: 事前処理・複数バージョン保持が不要、単一の元画像からオンデマンド変換
✓検証プロセスの効率化: 拡張メトリクスで変換ポリシーの効果を定量的に確認してから本番適用
✓アーキテクチャ選択の柔軟性: 画像サイズ (6 MB / 100 MB)、性能、コストの観点だけで選択可能

⚠️ 制限事項

✗処理可能な画像は Lambda で最大 6 MB、ECS で最大 100 MB
✗スマートクロッピングやコンテンツモデレーションは Amazon Rekognition の利用料金が別途発生
✗カスタムラベル検出には Rekognition Custom Labels モデルの事前トレーニングが必要

🤔 考慮すべき点

⚠CloudFront はデフォルトで従量課金だが、トラフィック量によっては固定料金プランへの切り替えでコスト最適化できる可能性があるため、月間データ転送量とリクエスト数を事前評価することを推奨
⚠既存の Serverless Image Handler / DIT からのアップグレード時は、アーキテクチャ間の機能差解消による設定変更の影響を確認

🎯 ユースケース

🛒 ユースケース 1: E コマースサイトの商品画像配信

シナリオ: 商品一覧、詳細ページ、レコメンドウィジェットなど、表示枠ごとに異なるアスペクト比で商品画像を表示したい。クロップ時に商品本体やブランドロゴが切れてしまうことを防ぎたい。

実装: ラベル検出 (商品) + ロゴ検出を組み合わせたスマートクロッピングを単一リクエストで指定し、表示枠ごとのアスペクト比とパディングを設定。グラビティ制約で商品を優先的に中央配置。

✅ 効果: 手動クロップ作業なしに、商品とロゴが常に収まった一貫性のある画像を全表示枠に配信できる。

📺 ユースケース 2: スマート TV を含むマルチデバイス向けメディア配信

シナリオ: 動画配信サービスのサムネイルをブラウザだけでなくスマート TV やセットトップボックスにも配信。Client Hints 非対応クライアントには最適化されていない大きな画像が配信されていた。

実装: 自動画像最適化を有効化し、Client Hints → CloudFront デバイス分類ヘッダー → フォールバックの順で判定。デバイスタイプごとに適切な解像度・フォーマットで配信。

✅ 効果: Client Hints 非対応の約 30% のトラフィックにも最適化が適用され、帯域幅コスト削減と表示速度向上を実現。

🧪 ユースケース 3: 変換ポリシー導入前のパフォーマンス検証

シナリオ: 新しい画像フォーマットや圧縮設定を本番導入する前に、画質とファイルサイズ削減効果、処理時間への影響を確認したい。

実装: 画像変換プレイグラウンドで代表的な画像に変換ポリシーを適用し、出力サイズ、フォーマット、圧縮率、処理時間のメトリクスを比較検証。

✅ 効果: 定量的なメトリクスに基づき変換ポリシーを調整でき、本番環境への影響を最小化しながら最適な設定を導入できる。

💰 料金

DIT ソリューション自体の利用に追加料金はなく、デプロイされる AWS サービス (CloudFront、Lambda または ECS、S3、Rekognition など) の利用料金が発生します。コストは選択するアーキテクチャ (Lambda / ECS) によって異なります。

CloudFront はデフォルトで従量課金モデルを使用しますが、想定トラフィックによっては固定料金プランへの切り替えでコストを最適化できる場合があります。デプロイ前に月間データ転送量と画像リクエスト数を評価することが推奨されます。詳細は実装ガイドの Cost ページを参照してください。

📝 まとめ

今回のアップデートは、スマートクロッピングの高度化とデバイス検出の多層化により、画像配信の品質とカバレッジを大きく向上させるものです。特に Client Hints 非対応の約 30% のトラフィックへの最適化拡大は、帯域幅コストとユーザー体験の両面で効果が期待できます。

既存の Serverless Image Handler / DIT 利用者は最新バージョンへのアップグレードを検討し、新規導入時はプレイグラウンドで変換ポリシーを検証した上で、画像サイズと性能要件に応じて Lambda / ECS アーキテクチャを選択することを推奨します。
