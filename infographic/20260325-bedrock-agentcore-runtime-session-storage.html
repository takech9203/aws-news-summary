Amazon Bedrock AgentCore Runtime

📝 概要

Amazon Bedrock AgentCore Runtime がマネージドセッションストレージのパブリックプレビューを開始。エージェントがセッションの停止と再開を跨いでファイルシステムの状態を永続化できるようになります。コードの作成、パッケージのインストール、アーティファクトの生成など、ファイルシステムを通じた作業結果を自動的に保持できます。

Before
❌セッション停止時にファイルシステム上の作業結果 (ソースコード、パッケージ、ビルドアーティファクトなど) をすべて失っていた
❌チェックポイントロジックや保存・復元コードをアプリケーション側で独自に実装する必要があった
❌コンピューティング環境終了後にエージェントの作業コンテキストを復元する標準的な仕組みが存在しなかった
After
✅マウントパスに書き込まれたデータが自動永続化、セッションの停止・再開を跨いで保持
✅チェックポイントロジックや保存・復元コードの実装が不要。アプリケーション変更なしで利用可能
✅同じセッション ID で再開するだけで、ソースファイル、パッケージ、Git 履歴がすべて復元

🔑 主要機能

1 透過的なファイルシステム永続化
設定したマウントパスへの書き込みが自動的に耐久ストレージにレプリケーション。エージェントアプリケーション側の変更不要。標準的な Linux ファイルシステム操作 (通常ファイル、ディレクトリ、シンボリックリンク) をサポート。
2 セッション停止・再開のサポート
停止時にグレースフルシャットダウンでデータフラッシュ。同じセッション ID で再開すると新しい microVM が同じストレージをマウント。ソースファイル、パッケージ、ビルドアーティファクト、Git 履歴がすべて復元。
3 セッション分離とセキュリティ
ストレージ通信は単一セッションのデータに限定。他のセッションや AgentCore Runtime 環境のデータにアクセス不可。セッションごとに独立したストレージ領域を確保。

⚙️ 設定方法

前提条件:
1️⃣ AgentCore Runtime の Agent Runtime が作成済み
2️⃣ 適切な IAM 権限が設定済み
3️⃣ エージェントが指定マウントパスにファイルを読み書きする構成
Step 1 API 設定 - filesystemConfigurations
JSON パラメータ設定 
{
    "filesystemConfigurations": [
        {
            "sessionStorage": {
                "mountPath": "/mnt/session-data"
            }
        }
    ]
}
Step 2 AWS CLI でのランタイム作成
Bash create-agent-runtime 
aws bedrock-agentcore create-agent-runtime \
  --agent-runtime-name "my-persistent-agent" \
  --agent-runtime-artifact '{
    "containerConfiguration": {
      "containerUri": "123456789012.dkr.ecr.us-east-1.amazonaws.com/my-agent:latest"
    }
  }' \
  --role-arn "arn:aws:iam::123456789012:role/AgentCoreRole" \
  --filesystem-configurations '[
    {
      "sessionStorage": {
        "mountPath": "/mnt/session-data"
      }
    }
  ]'
Step 3 Python SDK での設定
Python create_agent_runtime 
import boto3

client = boto3.client('bedrock-agentcore',
                       region_name='us-east-1')

response = client.create_agent_runtime(
    agentRuntimeName='my-persistent-agent',
    agentRuntimeArtifact={
        'containerConfiguration': {
            'containerUri': '123456789012.dkr.ecr....'
        }
    },
    roleArn='arn:aws:iam::123456789012:role/...',
    filesystemConfigurations=[
        {
            'sessionStorage': {
                'mountPath': '/mnt/session-data'
            }
        }
    ]
)
print(f"Runtime ID: {response['agentRuntimeId']}")
print(f"Status: {response['status']}")
Step 4 既存ランタイムへの追加
Python update_agent_runtime 
response = client.update_agent_runtime(
    agentRuntimeId='existing-runtime-id',
    agentRuntimeArtifact={...},
    roleArn='arn:aws:iam::...:role/...',
    filesystemConfigurations=[
        {
            'sessionStorage': {
                'mountPath': '/mnt/session-data'
            }
        }
    ]
)

💡 ユースケース

🛠️ ソフトウェア開発エージェント
AI エージェントがコードリポジトリをクローンし、パッケージをインストールして開発作業を実行。セッション再開時にリポジトリのクローンやパッケージの再インストールが不要になり、開発再開時間を大幅に短縮。
📈 データ分析エージェント
大規模データの分析を段階的に実行し、中間結果をファイルに保存。長時間の分析を複数セッションに分割して実行でき、コスト効率を改善しながら分析の継続性を維持。
📄 ドキュメント生成エージェント
複数ステップでドキュメントを生成し、生成済みファイルやテンプレートをセッション間で再利用。重複作業を排除して効率的に完了。

✅ メリット

ビジネス面
開発効率の向上: チェックポイントロジックの実装不要。エージェント開発に集中
コスト最適化: セッション停止中はリソース解放しつつ作業状態を維持。アイドルコスト削減
UX 改善: 中断した時点から即座に作業再開。待機時間を短縮
技術面
透過的な統合: アプリケーションのコード変更なしで永続化機能を利用可能
データ整合性: グレースフルシャットダウンによるフラッシュでデータ損失を防止
セッション分離: セッション間のデータアクセス制限でセキュリティを確保

⚠️ デメリット・制約事項

⚠️セッションあたり最大 1 GB の制限。大容量データセットやモデルファイルには不向き
⚠️アイドル状態のデータ保持期間は最大 14 日間。超過でデータ削除
⚠️パブリックプレビューのため、本番ワークロードでの使用には注意が必要
⚠️セッション再開時に新しい microVM 起動のため、マウントに若干の時間がかかる可能性
⚠️プレビュー期間中は機能仕様が変更される可能性あり
