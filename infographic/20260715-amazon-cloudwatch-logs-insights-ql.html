🎯 概要

Amazon CloudWatch Logs Insights のクエリ言語 (Logs Insights QL) に 25 個の新しいコマンドと関数が追加されました。統計的な集計、時系列データの null 処理、時間ウィンドウ間の比較、外れ値検出、ルックアップによるイベント拡充などの高度な分析を、追加ツールやデータのエクスポートなしにクエリ内で完結できます。

❌ アップデート前の課題

  • 分散・上位頻度値・外れ値などの統計分析をクエリ内で完結できず、別ツールへのエクスポートが必要だった
  • 時系列データの欠損値・null 値処理 (前方補完・欠損行補完) が標準機能では困難だった
  • 異なる時間ウィンドウ間のログ比較や CIDR 範囲によるルックアップ拡充が柔軟にできなかった

✅ アップデート後の改善

  • variance・topk・countFrequent でクエリ内で直接統計分析
  • filldown・fillmissing・accum・autoregress で null 処理・累積計算が完結
  • logcompare・sessionize・outlier・cidrlookup・appendcols で高度な相関分析が可能に

ログクラスのサポート

項目詳細
Standard ログクラスすべての Logs Insights QL コマンドをサポート
Infrequent Access ログクラスpattern・diff・unmask を除くすべてのコマンドをサポート

クエリ構文の基本

複数のコマンドをパイプ文字 (|) で連結してクエリを構成します。今回追加されたコマンドも既存コマンドと同様にパイプで連結できます。

Logs Insights QL 分散計算 + 前方補完の例 
fields @timestamp, @message
| filter status = 500
| stats variance(latency) as latencyVariance by bin(5m)
| filldown latencyVariance

🛠️ 設定方法

前提条件

✓CloudWatch Logs にログを送信しているロググループが存在すること
✓logs:StartQuery および logs:GetQueryResults などの IAM 権限を持つこと
✓pattern・diff・unmask を除くコマンドは Infrequent Access ログクラスでも利用できること

ステップ 1: CloudWatch Logs Insights を開く

CloudWatch コンソールで [ログのインサイト] を開き、対象のロググループを選択します。追加された新しいコマンドと関数は既存のクエリエディタからそのまま利用できます。

ステップ 2: 新しいコマンドを含むクエリを実行する

Logs Insights QL CIDR ルックアップ + 頻度集計 
fields @timestamp, srcIp, @message
| cidrlookup srcIp in "internal_ranges" as network
| stats countFrequent(network) as cnt by network

ステップ 3: 時系列分析と外れ値検出を組み合わせる

Logs Insights QL 欠損補完 + 外れ値検出 
fields @timestamp, latency
| stats avg(latency) as avgLatency by bin(1m)
| fillmissing avgLatency with 0
| outlier avgLatency

bin() による集計後、fillmissing で空の時間ビンを 0 で補完し、outlier で IQR に基づく外れ値を検出。欠損のない時系列に対して外れ値分析を実行できます。

💡 メリット

ビジネス面

✓分析の内製化: 統計分析・外れ値検出をログ分析基盤内で完結。外部ツールへのエクスポート不要
✓運用の迅速化: 時間ウィンドウ比較・セッション化で障害調査やトレンド分析を素早く実行
✓既存資産の活用: 既存のクエリエディタからそのまま利用でき、追加の環境構築が不要

技術面

✓表現力の向上: variance・topk・countFrequent でクエリ 1 本で統計的集計が可能
✓時系列処理の強化: filldown・fillmissing・accum・autoregress で null 処理・累積・ラグ計算が完結
✓相関分析の高度化: logcompare・sessionize・appendcols・cidrlookup で柔軟に構成

⚠️ デメリット・制約事項

▲pattern・diff・unmask は Infrequent Access ログクラスでは利用不可 (ログクラスによるコマンド差異に注意)
▲countFrequent は概算値を返すため、厳密な件数が必要な用途では留意が必要
▲クエリのスキャン対象データ量が大きいほど料金が増加。時間範囲とロググループの絞り込みが引き続き重要
💬 考慮すべき点: 高度なコマンドを多用する複雑なクエリは対象データ量によって実行時間・コストに影響する可能性があります。ダッシュボードに Logs Insights ウィジェットを配置する場合は、高頻度の更新がコスト増につながるため更新頻度を適切に設定してください。

📌 ユースケース

1. レイテンシーの外れ値検出

シナリオ: API のレイテンシーログから、通常とは異なる遅延が発生した時間帯を特定したい

Logs Insights QL
fields @timestamp, latency
| stats avg(latency) as avgLatency by bin(1m)
| fillmissing avgLatency with 0
| outlier avgLatency

➡️ 欠損のない時系列に対して IQR に基づく外れ値検出を実行し、異常な遅延が発生した時間帯を自動抽出

2. 期間比較によるトレンド分析

シナリオ: 直近のエラー発生状況を過去の同じ長さの期間と比較して増減傾向を把握したい

Logs Insights QL
fields @timestamp, @message
| filter @message like /ERROR/
| stats count(*) as errorCount by bin(5m)
| logcompare errorCount shift 1d

➡️ 現在の時間ウィンドウを 1 日前のベースラインと比較し、エラー件数のトレンドや急増を素早く把握

3. 送信元 IP のネットワーク別集計

シナリオ: アクセスログの送信元 IP を社内ネットワーク定義と照合し、ネットワークごとのアクセス傾向を分析したい

Logs Insights QL
fields @timestamp, srcIp
| cidrlookup srcIp in "internal_ranges" as network
| stats countFrequent(network) as cnt by network

➡️ IP を CIDR 範囲のルックアップテーブルと照合してネットワーク名で拡充し、ネットワーク単位でアクセス傾向を集計

💰 料金

今回追加されたコマンドと関数の利用に対する追加料金はありません。CloudWatch Logs Insights は、クエリがスキャンしたログデータ量に基づく従来の料金体系が適用されます。過度なコストを避けるため、対象ロググループと時間範囲をできるだけ絞り込むことが推奨されます。
