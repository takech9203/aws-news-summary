Amazon WorkSpaces for AI agents
一般提供開始 🤖

AI エージェントがマネージドデスクトップ上で業務アプリを人間と同じように操作
✅ GA

📅 2026 年 6 月 30 日

📌 概要

Amazon WorkSpaces for AI agents の一般提供 (GA) が開始されました。 AI エージェントはマネージドな WorkSpaces 環境を通じて、ERP・CRM・メインフレーム・独自開発ツールといった デスクトップアプリケーションへ安全にアクセスし操作できます。

エージェントは人間と同じように画面を認識してアプリを操作するため、 アプリの近代化やカスタム統合の開発は不要です。 さらにエージェントは人間のユーザーと同じ ID 制御・ネットワーク分離・コンプライアンス境界を継承するため、 ガバナンスを維持したまま業務ワークフローを自動化できます。 本機能は Model Context Protocol (MCP) を使うあらゆるエージェントフレームワークと連携し、 料金はアクティブなセッション時間に応じてスケールします。

❌ アップデート前の課題

  • デスクトップ業務アプリ (ERP / CRM / メインフレーム等) の自動化には、API 連携や近代化など大規模な開発が必要だった
  • AI エージェントが既存アプリを操作する標準的な手段がなく、独自統合を個別に構築する必要があった
  • 人間と同じセキュリティ・コンプライアンス境界の中で自動化を実行するのが難しかった

✅ アップデート後の改善

  • 近代化やカスタム統合なしで、AI エージェントがデスクトップアプリを人間と同じように操作できる
  • MCP 対応のあらゆるフレームワークから、標準 MCP エンドポイント経由で接続できる
  • 人間と同じ ID 制御・ネットワーク分離・コンプライアンス境界を継承し、ガバナンスを維持したまま自動化できる

AI エージェントは標準 MCP エンドポイント経由でマネージドデスクトップに接続し、業務アプリを操作します。 すべてのツール呼び出しは CloudTrail に記録され、セッションメトリクスは CloudWatch、スクリーンショットは S3 に保存されます。

⚡ 主要機能

🔀 MCP ツールフォワーディング

  • コンピュータ操作 (computer use) ツールではなく、直接的な MCP 呼び出しでアプリや OS とやり取り
  • 画面解析に依存する操作と比較して、精度が向上し、レイテンシーとコストが低減
  • サブタスクを最も効率的な経路にルーティングし、MCP ツールを優先、必要に応じて画面操作にフォールバック

🎛️ リアルタイムセッション制御

  • エージェントの活動状況をリアルタイムで可視化
  • 閲覧のみの監視に加え、セッション途中でアクセスを取り消す (一時停止・停止) ことが可能
  • 運用担当者は動作を監視しながら、問題があれば即座に介入できる

🪪 ドメイン参加フリートのサポート

  • エージェントは既存の Active Directory ID のもとで動作
  • 従業員向けに設定済みのアクセスポリシーを、そのままエージェントに適用できる
  • 監査時の操作主体の特定 (attribution) が容易になる

💡 メリット

📈 ビジネス面

  • 既存資産の活用: 近代化が難しい ERP・CRM・メインフレーム・独自ツールを改修なしで自動化対象に
  • ガバナンスの維持: 人間と同じ ID 制御・ネットワーク分離・境界を継承し、統制を維持したまま自動化
  • 業務効率の向上: 保険金請求処理、患者記録更新、取引決済、バックオフィス業務などを自動化

⚙️ 技術面

  • 開発コスト削減: カスタム統合や API 開発が不要、標準 MCP エンドポイントで接続
  • 精度とコストの最適化: MCP ツールフォワーディングで精度向上・レイテンシー / コスト低減
  • 監査性の確保: CloudTrail / CloudWatch / S3 で呼び出し・メトリクス・スクリーンショットを記録

⚠️ デメリット・制約事項

制限事項

!対応する AI エージェントフレームワークは MCP に対応している必要がある
!デスクトップ環境は Windows ベースの WorkSpaces Applications 環境を前提とする
!利用可能リージョンは公式発表時点で未明示のため、利用前に対応状況の確認が必要

考慮すべき点

→料金はアクティブなセッション時間でスケールするため、実行時間を考慮したコスト試算が必要
→画面解析を伴う操作はレイテンシーが高くなりうるため、可能な範囲で MCP ツールフォワーディングを活用する設計が望ましい
→リアルタイムでセッションを監視・制御する運用体制を整えることを推奨

🎯 ユースケース

① 保険金請求処理とコンプライアンス対応

保険会社が、複数の業務アプリにまたがる請求データの照合と、監査対応資料の取りまとめを行う。
効果: 請求データのクロスリファレンスと監査資料の作成を自動化し、処理時間を短縮しつつ CloudTrail で操作証跡を残せる。

② 患者記録の更新

医療機関が、独自の電子カルテシステムや関連アプリに対して患者記録を更新する。
効果: アプリの近代化なしにエージェントが人間と同じ操作で記録を更新。Active Directory ID 下で動作し、既存アクセスポリシーと監査要件を満たせる。

③ バックオフィス業務の自動化

管理部門が、請求書入力、勘定照合、アプリ間データ転送、HR・プロビジョニング・福利厚生システム間の異動処理などを行う。
効果: 複数のデスクトップアプリをまたぐ定型業務を自動化し、担当者の手作業を削減する。

💰 料金・リージョン・関連サービス

料金

料金はアクティブなセッション時間に基づいてスケールします。エージェントが実際に WorkSpaces 環境を利用している時間に応じて課金されるモデルです。具体的な単価やリージョン別料金は公式の料金ページを確認してください。

利用可能リージョン

公式発表時点では利用可能リージョンの一覧は明示されていません。利用前に最新のリージョン対応状況を公式ドキュメントおよび料金ページで確認してください。

📝 まとめ

Amazon WorkSpaces for AI agents の GA により、近代化が難しい既存のデスクトップアプリを、 AI エージェントが人間と同じように操作して自動化できるようになりました。 MCP ツールフォワーディング、リアルタイムセッション制御、 ドメイン参加フリートのサポートにより、精度・コスト・ガバナンスの面が強化されています。

まずは保険金請求処理やバックオフィス業務など定型性の高いワークフローを対象に、 リージョン対応状況と料金を確認したうえで概念実証 (PoC) を進めることが推奨されます。
