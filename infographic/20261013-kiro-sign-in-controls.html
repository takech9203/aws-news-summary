Kiro

🔐 エンタープライズ向けサインインコントロールの強化

📅 リリース日: 2026 年 10 月 13 日 🧩 Kiro IDE 1.2 以降 ⌨️ Kiro CLI 2.29.0 以降

📝 概要

Kiro は、エンタープライズ環境における管理対象デバイスでのサインイン方法を管理者が制御できる、サインインコントロール機能を発表しました。管理者は組織が許可するサインイン方法のみをユーザーに表示でき、ユーザーが制限を回避しようとした場合、Kiro はサインインを拒否します。

この機能は、管理者保護された設定ファイルである managed-settings.json にサインインルールを定義することで動作します。Kiro IDE と Kiro CLI の両方から開始されるサインイン (デバイスコードフローを含む) に適用されるため、組織全体で一貫したアイデンティティガバナンスを実現できます。IAM Identity Center のスタート URL やリージョンの事前入力、IT ヘルプページへのリンク表示といった、ユーザー体験を向上させる設定も提供されます。

❌ Before: アップデート前の課題
  • IAM Identity Center 必須の組織でも、個人アカウント (Google、GitHub、AWS Builder ID) でサインインできてしまった
  • ユーザーがスタート URL やリージョンを自分で調べて入力する必要があった
  • サインイン画面から IT サポートへ誘導する手段がなかった
  • ブラウザのない環境のデバイスコードフローを組織として管理できなかった
✅ After: アップデート後の改善
  • サインイン方法の制限: 許可した方法のみ表示し、それ以外を非表示にできる
  • IAM Identity Center 情報の事前入力: スタート URL とリージョンを事前入力できる
  • ヘルプリンクの追加: IT サポートページへ直接誘導できる
  • デバイスコードフローの有効化 / 無効化: Kiro コンソールから直接管理できる

管理者が managed-settings.json に定義したサインインルールを Kiro IDE / CLI が各マシンで読み込み、許可されたサインイン方法のみをユーザーに表示します。制限されたサインイン方法での認証は拒否されます。

⚙️ 主要機能

🚫 1. サインイン方法の制限

組織がサポートするサインインオプションのみを表示し、それ以外を非表示にします。ユーザーが制限を回避しようとした場合、Kiro はサインインを拒否します。deny エフェクトと exclude (許可リスト方式) または match (拒否リスト方式) を組み合わせてルールを定義します。

🏢 2. IAM Identity Center 情報の事前入力

idc_start_url でスタート URL を、idc_region でリージョンを事前入力できます。ユーザーがスタート URL やリージョンを自分で調べる必要がなくなり、サインイン画面には「Your organization」オプションとして表示されます。

🆘 3. ヘルプリンクの表示

signin_help_url で組織の IT ヘルプページへのリンクをサインイン画面に表示できます。サインインでつまずいたユーザーを適切なサポート窓口へ誘導できます。

🖥️ 4. デバイスコードフローの管理

ブラウザのないリモートマシンなどの環境からのサインインに使用されるデバイスコードフローを、Kiro コンソールから直接有効化 / 無効化できます。サインインコントロールは Kiro IDE と Kiro CLI の両方から開始されるサインイン (デバイスコードフローを含む) に適用されます。

📋 設定リファレンス

トップレベルの settings キー配下に追加します。各設定はすべてオプションです。

設定内容
idc_start_urlIAM Identity Center のスタート URL を事前入力する。https:// で始まる必要がある
idc_regionIAM Identity Center のリージョンを事前入力する。idc_start_url と併用した場合のみ使用される
signin_help_urlIT ヘルプページへのリンクをサインイン画面に表示する。https:// で始まる必要がある

💡 設定例: IAM Identity Center のみに制限

JSON managed-settings.json 
{
  "rules": [
    { "capability": "signin_method", "effect": "deny", "exclude": ["idc"] }
  ],
  "settings": {
    "idc_start_url": "https://my-org.awsapps.com/start",
    "idc_region": "us-east-1",
    "signin_help_url": "https://it.example.com/kiro-help"
  }
}

このルールは idc (IAM Identity Center) を除くすべてのサインイン方法を拒否します。ユーザーのサインイン画面には「Your organization」オプションのみが表示され、Identity Center のフォームが事前入力されるとともに、IT ヘルプページへのリンクが表示されます。

💡 設定例: 特定の方法のみを拒否

JSON 拒否リスト方式 match の例 
{ "capability": "signin_method", "effect": "deny", "match": ["social"] }

この例では Google と GitHub によるサインインのみを拒否し、AWS Builder ID と IAM Identity Center は引き続き利用できます。

🛠️ 設定方法

✅ 前提条件

✓Kiro IDE 1.2 以降、または Kiro CLI 2.29.0 以降がインストールされていること
✓管理対象デバイス上の managed-settings.json を管理者権限で配布・管理できること (MDM などのデバイス管理ツールの利用を想定)
✓IAM Identity Center を利用する場合、組織のスタート URL とリージョンを把握していること

📌 手順

  1. サインインルールの定義
    組織のポリシーに応じて、許可リスト方式 (exclude) または拒否リスト方式 (match) でルールを定義します。
    JSONIAM Identity Center 以外を拒否
    {
  "rules": [
    { "capability": "signin_method", "effect": "deny", "exclude": ["idc"] }
  ]
}
  2. ユーザー体験向上のための設定追加
    スタート URL とリージョンの事前入力、および IT ヘルプページへのリンクを設定します。これによりユーザーは接続情報を手動で入力する必要がなくなります。
    JSONsettings の設定例
    {
  "settings": {
    "idc_start_url": "https://my-org.awsapps.com/start",
    "idc_region": "us-east-1",
    "signin_help_url": "https://it.example.com/kiro-help"
  }
}
  3. managed-settings.json の配布
    作成した設定を管理者保護された managed-settings.json として各管理対象デバイスに配布します。Kiro は各マシンでこのファイルを読み込み、サインインコントロールを適用します。
  4. デバイスコードフローの制御
    ブラウザのない環境からのサインインを管理する場合は、Kiro コンソールからデバイスコードフローの有効化 / 無効化を設定します。

💪 メリット

💼 ビジネス面

✓ガバナンスの強化: 組織が承認したアイデンティティプロバイダーのみを使用するよう強制でき、シャドー IT のリスクを低減
✓コンプライアンス対応: 個人アカウントの利用が禁止されている場合でも、技術的に制限を適用可能
✓サポートコストの削減: スタート URL の事前入力とヘルプリンクにより、サインインに関する問い合わせを削減

🔧 技術面

✓IDE と CLI の一貫した制御: 両方のサインイン (デバイスコードフローを含む) に同じルールが適用される
✓宣言的な設定管理: 単一の設定ファイルで制御でき、MDM など既存のデバイス管理と組み合わせやすい
✓柔軟なルール定義: 許可リスト方式 (exclude) と拒否リスト方式 (match) の両方に対応

⚠️ デメリット・制約事項

🚧 制限事項

✗Kiro IDE 1.2 以降、Kiro CLI 2.29.0 以降が必要であり、ユーザーはこれらのバージョンにアップグレードする必要がある
✗本機能は米国東部 (バージニア北部) と欧州 (フランクフルト) リージョンで利用可能
✗idc_start_url と signin_help_url は https:// で始まる URL である必要がある
✗idc_region は idc_start_url と併用した場合のみ有効

🤔 考慮すべき点

⚠managed-settings.json は管理者保護されたファイルとして配布する必要があり、配布と更新の運用設計 (MDM などの利用) が必要
⚠既に個人アカウントでサインインしているユーザーへの移行手順を事前に周知することが望ましい
⚠デバイスコードフローの制御は managed-settings.json ではなく Kiro コンソールから行う点に注意

🎯 ユースケース

🏢 ユースケース 1: IAM Identity Center への一本化

シナリオ: 大企業の IT 部門が、開発者全員に会社の IAM Identity Center 経由でのみ Kiro を利用させたい。

JSON実装例
{
  "rules": [
    { "capability": "signin_method", "effect": "deny", "exclude": ["idc"] }
  ],
  "settings": {
    "idc_start_url": "https://my-org.awsapps.com/start",
    "idc_region": "us-east-1"
  }
}

効果: 個人アカウントによるサインインが不可能になり、組織のアイデンティティ基盤による一元的なアクセス管理と監査が実現。ユーザーはスタート URL を入力する必要がなく、スムーズにサインインできる。

🚫 ユースケース 2: ソーシャルアカウントのみを禁止

シナリオ: 中規模組織で、AWS Builder ID と IAM Identity Center は許可しつつ、Google / GitHub アカウントによるサインインのみを禁止したい。

JSON実装例
{
  "rules": [
    { "capability": "signin_method", "effect": "deny", "match": ["social"] }
  ]
}

効果: social 短縮形により Google と GitHub の両方を 1 つのルールで拒否でき、AWS 系のアカウントのみを許可する運用が簡潔に実現する。

🖥️ ユースケース 3: リモート開発環境でのサインイン管理

シナリオ: ブラウザのないリモート開発サーバー上で Kiro CLI を利用しており、デバイスコードフローによるサインインを組織として統制したい。

実装例: Kiro コンソールからデバイスコードフローの有効化 / 無効化を設定し、managed-settings.json のサインインルールと組み合わせる。

効果: ブラウザのない環境を含むすべてのサインイン経路に組織のポリシーが適用され、統制の抜け道がなくなる。

🌍 利用可能リージョン

Kiro はグローバルに利用できるサービスですが、サインインコントロール機能は米国東部 (バージニア北部) と欧州 (フランクフルト) リージョンで、Kiro IDE 1.2 および Kiro CLI 2.29.0 から利用可能です。利用にはこれらのバージョン以降へのアップグレードが必要です。

🔗 関連サービス・機能

🏢 AWS IAM Identity Center

組織のワークフォースアイデンティティを一元管理するサービス。本機能により Kiro のサインインを IAM Identity Center に限定できる。

⌨️ Kiro CLI

ターミナルから Kiro のエージェント機能を利用する CLI。本機能のサインインコントロールは CLI にも適用される。

🖥️ Kiro コンソール

デバイスコードフローの有効化 / 無効化を管理するための管理コンソール。

📌 まとめ

Kiro のサインインコントロールにより、エンタープライズ管理者は管理対象デバイス上でのサインイン方法を初めて技術的に強制できるようになりました。IAM Identity Center を標準とする組織では、managed-settings.json による許可リスト方式の設定とスタート URL の事前入力を組み合わせることで、ガバナンスとユーザー体験を両立できます。Kiro を組織導入している場合は、Kiro IDE 1.2 / Kiro CLI 2.29.0 以降へのアップグレードとあわせて本機能の適用を検討することを推奨します。
