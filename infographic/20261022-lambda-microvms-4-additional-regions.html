📝 概要

AWS Lambda MicroVMs が新たに 4 つのリージョン (アジアパシフィック (香港)、アジアパシフィック (マレーシア)、アジアパシフィック (タイ)、欧州 (スペイン)) で利用可能になりました。 Lambda MicroVMs は、VM レベルの分離、ほぼ瞬時の起動・再開、状態保持を提供するサーバーレスコンピューティングプリミティブです。

ユーザーや AI が生成したコードを実行するアプリケーションにおいて、仮想化基盤を自前で管理することなく、ユーザーやジョブごとに専用の分離環境を割り当てられます。AI コーディングアシスタント、インタラクティブな開発環境、脆弱性スキャナーなどのユースケースに適しています。

❌ Before: アップデート前の課題

✗香港・マレーシア・タイ・スペインでは MicroVMs を利用できなかった
✗遠隔リージョンからの提供によりレイテンシーが増加
✗データを特定の国・地域に保持するワークロードでは採用が困難

✓各地域のデータレジデンシー要件を満たしながら活用可能

Lambda MicroVMs の基本的な動作フローです。Dockerfile からイメージを作成し、スナップショットからユーザーやジョブごとに分離された MicroVM を高速起動します。各 MicroVM は専用の HTTPS URL を持ち、アイドル時はサスペンドしてコストを削減します。

🚀 主要機能

🌏 新規対応リージョン

アジアパシフィック (香港)、アジアパシフィック (マレーシア)、アジアパシフィック (タイ)、欧州 (スペイン) が追加され、今回の拡大により合計 14 リージョンで利用可能になりました。

🔒 VM レベルの分離と高速起動

  • Firecracker 仮想化技術により、MicroVM ごとに VM レベルの分離を提供
  • 初期化済み環境のスナップショットから起動するため、アプリケーションの初期化をスキップしてほぼ瞬時に起動・再開
  • システムパッケージのインストールやファイルシステムのマウントなど、完全な OS 機能を利用可能

💤 サスペンド・レジューム機能

  • アイドル時に MicroVM をサスペンドし、メモリとディスクの状態を保持したままコストを削減
  • ライフサイクルポリシーによる自動制御、または API 呼び出し (suspend-microvm / resume-microvm) によるプログラマブルな制御が可能
  • トラフィック到着時にはほぼ瞬時に再開

🌐 柔軟なネットワーキング

  • 各 MicroVM に専用の HTTPS URL が付与され、HTTP/2、gRPC、WebSockets をサポート
  • ロードバランサーやイングレス基盤の構築が不要
  • アウトバウンドはパブリックインターネットアクセスと VPC アクセスを設定可能

⚙️ 技術仕様

項目詳細
分離モデルFirecracker 仮想化による VM レベルの分離
イメージ作成コードと Dockerfile を zip 化して Amazon S3 にアップロードし、Lambda API でイメージ (スナップショット) を作成
起動方式初期化済みスナップショットからの高速起動
接続方式MicroVM ごとの専用 HTTPS URL (HTTP/2、gRPC、WebSockets 対応)、サービス提供の JWE 認証
ライフサイクルrun / suspend / resume / terminate を API または自動ポリシーで制御
リソース割り当てベースラインを設定し、ピーク時はベースラインの最大 4 倍まで垂直スケール可能
管理ツールLambda コンソール、CloudFormation、AWS CDK、Agent Toolkit for AWS

🔧 設定方法

📋 前提条件

  • AWS アカウントと AWS Lambda へのアクセス権限
  • アプリケーションコードと Dockerfile
  • zip アーカイブをアップロードする Amazon S3 バケット
1

イメージソースの準備とアップロード

アプリケーションコードと Dockerfile を 1 つの zip アーカイブにまとめ、Amazon S3 にアップロードします。

Bash S3 へのアップロード 
# アプリケーションコードと Dockerfile を zip 化して S3 にアップロード
zip -r my-microvm-app.zip ./app ./Dockerfile
aws s3 cp my-microvm-app.zip s3://my-bucket/my-microvm-app.zip
2

MicroVM イメージの作成

Lambda API を呼び出して MicroVM イメージを作成します。Lambda が Dockerfile を実行してアプリケーションを起動し、完全に初期化された環境のスナップショットを取得します。具体的な API 操作は開発者ガイドを参照してください。

3

MicroVM の起動と接続

ユーザーセッションやジョブごとに run-microvm を呼び出し、スナップショットから MicroVM を起動します。クライアントは発行された専用 HTTPS エンドポイント経由で接続します。アイドル時はライフサイクルポリシーまたは suspend-microvm / resume-microvm の API で状態を制御し、セッション終了時には MicroVM を終了してリソースを解放します。

💡 メリットと制約事項

📈 ビジネス面のメリット

✓レイテンシーの低減: 東南アジアや南欧のエンドユーザーに近いリージョンで実行し、応答性が向上
✓データレジデンシー対応: 香港、マレーシア、タイ、スペインでデータを域内に保持可能
✓コスト効率: アイドル時のサスペンドで待機コストを削減

🛠️ 技術面のメリット

✓運用負荷の軽減: 仮想化基盤、ロードバランサー、イングレス基盤の管理が不要
✓強力な分離: マルチテナント環境でもユーザーやジョブごとに VM レベルの分離を確保
✓高速な起動・再開: スナップショットベースの起動により初期化を待たずに利用開始

⚠️ 制限事項

⚠利用可能リージョンは 14 リージョンに限定 (全リージョンでは利用不可)
⚠既存の対応リージョン一覧は発表で明示されておらず、最新の対応状況は AWS Capabilities by Region ページで確認が必要

🤔 考慮すべき点

⚠垂直スケールはベースラインの最大 4 倍までのため、ワークロードに応じた適切なベースライン設定が必要
⚠ベースライン稼働分とベースラインを超えるアクティブ使用分で課金されるため、利用パターンの把握が重要

🎯 ユースケース

🤖 1. AI コード実行サンドボックス

シナリオ: AI コーディングアシスタントが生成したコードを、本番環境やほかのユーザーから分離された環境で安全に実行したい。

  1. 実行環境の Dockerfile からスナップショットイメージを作成
  2. AI エージェントのタスクごとに run-microvm で専用 MicroVM を起動
  3. 専用 HTTPS URL 経由でコードの実行とレスポンス取得
  4. タスク完了後に MicroVM を終了
✅ 効果: AI 生成コードを VM レベルで分離して実行でき、タスクごとに高速にクリーンな環境を用意できる

💻 2. インタラクティブな開発環境

シナリオ: ブラウザベースの IDE サービスで、ユーザーごとに分離された開発環境をリアルタイムに提供したい。ユーザーの離席中はコストを抑えたい。

  1. 開発環境のイメージを事前に作成
  2. ユーザーのセッション開始時に MicroVM を起動し、WebSockets で接続
  3. アイドル時はライフサイクルポリシーで自動サスペンド
  4. ユーザーが戻ったらメモリとディスク状態を保持したまま再開
✅ 効果: ユーザーの作業状態を保持しながら、アイドル時間のコストを削減できる

🔍 3. セキュリティスキャンとマルチテナント CI/CD

シナリオ: 脆弱性評価ツールやテナントごとの CI/CD タスク実行で、テナント間の分離を確保した実行環境が必要。

  1. スキャナーやビルド環境のイメージを作成
  2. テナントやジョブごとに MicroVM を起動して処理を実行
  3. ジョブ完了後に MicroVM を終了し、環境を完全に破棄
✅ 効果: テナント間の情報漏えいリスクを抑えつつ、ジョブごとに使い捨ての分離環境を高速に提供できる

💰 料金

MicroVM の稼働中はベースラインレートで課金され、ベースラインを超えるアクティブな使用分は追加で課金されます。サスペンド中はメモリとディスクの状態を保持しながらコストを削減できます。

具体的な料金は AWS Lambda 料金ページを参照してください。
