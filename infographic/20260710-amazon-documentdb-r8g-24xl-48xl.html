Amazon DocumentDB

☁️ R8g.24xlarge / R8g.48xlarge
インスタンスのサポート追加

📅 2026-07-10
with MongoDB compatibility

📌 概要

Amazon DocumentDB は、AWS Graviton4 プロセッサを搭載した R8g インスタンスファミリーに、R8g.24xlarge と R8g.48xlarge の 2 つの大規模インスタンスサイズを追加しました。より高い vCPU 数とメモリ容量を必要とする要求の厳しいワークロードに対応できます。

R8g インスタンスは Graviton4 と DDR5 メモリを採用し、従来世代より高いスループットと、より大きなインメモリワーキングセットをサポートします。Amazon DocumentDB 5.0 以降で、標準ストレージと IO-Optimized ストレージの両方で利用可能です。

🖥️ R8g.24xlarge
96 vCPU
768 GiB メモリ
🖥️ R8g.48xlarge
192 vCPU
1,536 GiB メモリ

⚠️ アップデート前の課題

  • R8g で利用できるサイズが限られ、大規模ワークロードに十分な vCPU/メモリを単一インスタンスで確保しにくい
  • 大きなワーキングセットをメモリに保持できず、ディスク I/O 増加でパフォーマンスが制約される
  • 高同時実行トランザクションや大規模ドキュメント処理を少ないインスタンス数に集約しにくい

✅ アップデート後の改善

  • 最大 192 vCPU / 1,536 GiB により単一インスタンスで大幅に高い演算能力とメモリ容量を確保
  • DDR5 と Graviton4 で、より大きなインメモリワーキングセットと高スループットを実現
  • 標準と IO-Optimized の両方から選択でき、ワークロード特性に応じた構成が可能

高同時実行のアプリケーションからのリクエストを Graviton4 搭載の大規模 R8g インスタンスが処理し、標準または IO-Optimized ストレージにデータを永続化します。

🚀 主要機能

1️⃣ 2 つの新しい大規模インスタンスサイズ

  • R8g.24xlarge: 96 vCPU / 768 GiB メモリ
  • R8g.48xlarge: 192 vCPU / 1,536 GiB メモリ
  • 既存 R8g ファミリーに追加される最大級のサイズで、単一インスタンスで高い集約度を実現

2️⃣ AWS Graviton4 プロセッサと DDR5 メモリ

  • AWS が独自設計した Graviton4 プロセッサを搭載
  • DDR5 メモリの採用で高いメモリ帯域幅とスループットを提供
  • より大きなインメモリワーキングセットをサポートし、ディスク I/O への依存を低減

3️⃣ ストレージ構成の柔軟性

  • 標準ストレージ (Standard) と IO-Optimized ストレージの両方で利用可能
  • I/O 使用量が多いワークロードでは IO-Optimized でコスト予測性を向上

🔧 設定方法

前提条件

✓R8g.24xlarge / R8g.48xlarge が利用可能なリージョンであること
✓クラスターのエンジンバージョンが Amazon DocumentDB 5.0 以降であること
✓インスタンスの作成・変更権限を持つ IAM プリンシパルであること

ステップ 1: 新規インスタンスを作成する

Bashcreate-db-instance
aws docdb create-db-instance \
    --db-instance-identifier my-docdb-instance \
    --db-cluster-identifier my-docdb-cluster \
    --engine docdb \
    --db-instance-class db.r8g.24xlarge

--db-instance-class に db.r8g.24xlarge を指定し、既存クラスターに大規模インスタンスを追加します。R8g.48xlarge の場合は db.r8g.48xlarge を指定します。

ステップ 2: 既存インスタンスのクラスを変更する

Bashmodify-db-instance
aws docdb modify-db-instance \
    --db-instance-identifier my-docdb-instance \
    --db-instance-class db.r8g.48xlarge \
    --apply-immediately

--apply-immediately を指定すると即時に、指定しない場合は次回メンテナンスウィンドウで適用されます。

ステップ 3: インスタンスクラスを確認する

Bashdescribe-db-instances
aws docdb describe-db-instances \
    --db-instance-identifier my-docdb-instance \
    --query "DBInstances[0].DBInstanceClass"

変更後のインスタンスクラスが反映されていることを確認します。マネジメントコンソールからも同様の操作が可能です。

💡 メリット

ビジネス面

✓集約によるコスト最適化: ワークロード集約で管理対象インスタンス数を削減できる可能性
✓成長への対応: 単一インスタンスでのスケールアップ余地が拡大
✓価格性能比の向上: Graviton4 の優れた価格性能比を活用

技術面

✓大きなインメモリワーキングセット: 最大 1,536 GiB で多くの作業データをメモリに保持
✓高いスループット: DDR5 と Graviton4 で高同時実行ワークロードに対応
✓ストレージ選択の柔軟性: 標準と IO-Optimized から最適化

⚠️ デメリット・制約事項

制限事項

!Amazon DocumentDB 5.0 以降でのみ利用可能
!大規模サイズのため時間あたりコストは小規模より高い
!リージョンによっては未提供の場合があり、事前確認が必要

考慮すべき点

!実際に大容量メモリ/vCPU が必要か事前にサイジング評価を行う
!過剰なサイズ選択はコスト増につながるため CloudWatch で使用率を監視
!I/O 使用量が多い場合は IO-Optimized がコスト予測性で有効

🎯 ユースケース

① 高同時実行のトランザクションアプリケーション

シナリオ: 多数のユーザーが同時アクセスする e コマースやゲームのバックエンドで、高い同時接続数と低レイテンシーが求められる。

実装: db.r8g.24xlarge (96 vCPU / 768 GiB) を採用し、多数の同時接続とトランザクションを処理。CloudWatch で接続数と CPU 使用率を監視。

✅ 効果: 高い同時実行性を単一インスタンスで処理でき、レイテンシーを抑えながらスケーラビリティを確保。

② 大規模ドキュメント処理

シナリオ: 大量の JSON ドキュメントを対象とした集計や分析処理を、可能な限りメモリ上で完結させたい。

実装: db.r8g.48xlarge (192 vCPU / 1,536 GiB) を採用し、大きなワーキングセットをメモリに保持。集計パイプラインをインメモリで高速実行。

✅ 効果: 1,536 GiB のメモリで大規模ワーキングセットを保持でき、ディスク I/O を削減して処理を高速化。

③ メモリ集約型の運用ワークロード

シナリオ: キャッシュ的に大量データをメモリに保持し、頻繁な読み取りに低レイテンシーで応答する必要がある。

実装: db.r8g.48xlarge でメモリ容量を最大化し、IO-Optimized で I/O コストの予測性を確保。ホットデータアクセスを最適化。

✅ 効果: 大容量メモリでホットデータを保持でき、読み取りレイテンシーを低減しつつ安定運用が可能。

💰 料金・利用可能リージョン

料金

R8g.24xlarge / R8g.48xlarge には Amazon DocumentDB の通常インスタンス料金が適用されます。料金はインスタンスタイプ、リージョン、ストレージ構成 (Standard または IO-Optimized) によって異なります。インスタンス使用料に加え、ストレージ、I/O (Standard の場合)、バックアップなどの料金が発生します。

利用可能リージョン

提供リージョンは Amazon DocumentDB の料金ページおよびドキュメントで確認できます。利用前に、対象リージョンでこれらのインスタンスタイプが提供されているかを確認してください。

🔗 関連サービス・機能

  • AWS Graviton4: R8g に搭載される AWS 独自設計プロセッサ。優れた価格性能比を提供
  • Amazon CloudWatch: CPU 使用率、メモリ、接続数などを監視し適切なサイジングを判断
  • Amazon DocumentDB IO-Optimized: I/O 使用量が多いワークロードでコスト予測性を高めるストレージ構成

📝 まとめ

R8g.24xlarge および R8g.48xlarge のサポートにより、Amazon DocumentDB は Graviton4 と DDR5 メモリを活用した最大 192 vCPU / 1,536 GiB の大規模インスタンスを提供できるようになりました。高同時実行のトランザクション処理、大規模ドキュメント処理、メモリ集約型ワークロードには、これらのインスタンスへの移行やスケールアップを検討してください。導入時は、対象リージョンでの提供状況を確認し、CloudWatch メトリクスによる使用率評価を通じて適切なサイジングを行うことを推奨します。
