AWS Transform

🐳 コンテナ化機能の追加

マイグレーション中のアプリケーションをコンテナにリプラットフォーム
📅 2026-05-11

📋 概要

AWS Transform にマイグレーション中のアプリケーションをコンテナにリプラットフォームする機能が追加されました。エージェント AI がソースコードのコンテナ化を自動化し、マイグレーションとモダナイゼーションを並行して実施できます。

GitHub、Bitbucket、GitLab、または .zip ファイルからソースコードをコンテナ化し、Docker イメージを生成して Amazon ECR にパブリッシュし、Amazon ECS または Amazon EKS にデプロイ可能です。

❌ Before

  • マイグレーションとモダナイゼーションは別フェーズで実施
  • Dockerfile 作成、イメージビルド、スキャン、IaC 生成を手動実行
  • 大規模コンテナ化には膨大な工数と専門知識が必要

✅ After

  • リホストとリプラットフォームのパスを選択し同時進行
  • AI が Dockerfile 生成、ビルド、CVE スキャン、IaC 生成を自動実行
  • モノレポ/マルチレポ対応で大規模コンテナ化が可能

🛠 設定方法

前提条件

  • AWS Transform へのアクセス権限
  • ソースコードリポジトリへの接続設定 (または .zip ファイル)
  • Amazon ECR リポジトリの作成
  • デプロイターゲット (ECS/EKS クラスター) の準備

手順

1
マイグレーションウェーブプランニングでパスを選択
各アプリケーションに対してリホストまたはリプラットフォーム (コンテナ化) パスを割り当てます。
2
ソースコードリポジトリの接続
GitHub、Bitbucket、GitLab のいずれかを接続設定。プライベートリポジトリは適切な認証情報を設定。
3
コンテナ化の実行
AI が Dockerfile 生成 → イメージビルド → CVE スキャン → ECR パブリッシュ → IaC 生成を自動実行。
4
デプロイ
生成された Terraform と Helm チャートを使用して ECS/EKS にデプロイします。
Bash Terraform デプロイ例 
# Terraform による ECS/EKS インフラのデプロイ

⚖ メリットとデメリット

✅ メリット

  • 移行期間の短縮: マイグレーションとモダナイゼーションを並行実施
  • コスト削減: 手動コンテナ化作業を AI が自動化
  • 早期のクラウドネイティブ活用: 移行完了時点でコンテナ化済み
  • 一貫した品質: AI 分析で人的ミスを減少
  • セキュリティ組込: CVE スキャンで脆弱性を防止
  • IaC ベース: 再現可能なインフラ管理

⚠ 制約事項・注意点

  • 自動生成 Dockerfile が全要件をカバーしない場合あり
  • 複雑な依存関係やレガシーフレームワークでは手動調整が必要
  • 実行時の脆弱性は別途監視が必要
  • ECS/EKS の運用知識が必要
  • モノリスのマイクロサービス分割は別途検討
  • CodeArtifact のセットアップが前提

💡 ユースケース

🏢 大規模エンタープライズのクラウド移行

数百のオンプレミスアプリケーションを AWS に移行する企業が、移行と同時にコンテナ化を実施するケース。
Text ウェーブプランニング例 
Wave 1: 重要度低のアプリ 50 本 → リプラットフォーム
Wave 2: 重要度中のアプリ 100 本 → リプラットフォーム
Wave 3: 重要度高のアプリ 30 本 → リホスト (安定性優先)
🚀 効果: 移行完了時に 150 本が既にコンテナ化され、追加のモダナイゼーションフェーズが不要に。

📁 モノレポからの段階的コンテナ化

単一のモノリシックリポジトリに複数のサービスが含まれている組織が、各サービスを個別のコンテナとして分離するケース。
Text モノレポ構造と生成成果物 
ソース: GitHub モノレポ
  /services/user-api/
  /services/order-api/
  /services/payment-api/

AWS Transform 生成成果物:
  - user-api: Dockerfile + Terraform + Helm chart
  - order-api: Dockerfile + Terraform + Helm chart
  - payment-api: Dockerfile + Terraform + Helm chart
🚀 効果: 各サービスが自動的に識別・分離され、個別のコンテナイメージとして ECR にパブリッシュ。

📜 まとめ

AWS Transform のコンテナ化機能は、「まず移行し、後からモダナイゼーション」という従来のアプローチを根本的に変える機能です。エージェント AI を活用してマイグレーションとコンテナ化を同時に実行できるため、クラウドネイティブアーキテクチャへの移行期間を大幅に短縮できます。

大規模な移行プロジェクトを計画している組織は、マイグレーションウェーブプランニングでリプラットフォームパスの活用を検討することを推奨します。
