Amazon MWAA

🏷️ コスト配分タグのサポート

Amazon Managed Workflows for Apache Airflow (MWAA) | リリース日: 2026 年 11 月 4 日

📋 概要

Amazon MWAA がコスト配分タグをサポートしました。環境に適用したタグが、環境を実行するコンピューティングリソース (ワーカー、スケジューラー、Web サーバー) にも伝播されるようになり、AWS Cost Explorer や AWS Cost and Usage Reports (CUR) でタグ単位の MWAA コストの内訳を確認できるようになりました。

プラットフォームチームは Airflow のコストを、各環境を所有するチーム、プロジェクト、コストセンターに対してショーバック / チャージバックできます。複数チームで MWAA を共有基盤上で運用している組織や、FinOps の観点でワークフロー基盤のコスト可視化を進めたい組織に有用なアップデートです。

1 タグ
環境と全コンポーネントのコストをカバー
1 ARN
使用量を単一の環境 ARN に集約
追加料金なし
コスト総額は変わらず帰属方法のみ変更
❌ アップデート前の課題
  • 環境のタグがワーカー、スケジューラー、Web サーバーのコストに反映されず、タグ集計が環境全体をカバーできない
  • Cost Explorer のリソース別表示で追加ワーカーや追加 Web サーバーが別リソースとして表示され、環境単位の合計コストの把握が困難
  • チームやプロジェクト単位の按分には手動での集計や推計が必要
✅ アップデート後の改善
  • 環境上の 1 つのタグで、環境本体と全コンポーネント (ワーカー / スケジューラー / Web サーバー) のコストをカバー
  • 環境とコンポーネントの使用量が単一の環境 ARN に集約されて表示
  • タグキーで Group by するだけで、チーム / プロジェクト / コストセンター単位のコスト配分を実現

環境に付与したタグがワーカー、スケジューラー、Web サーバーに伝播し、すべての使用量が単一の環境 ARN に集約されて Cost Explorer や CUR でタグ別に集計できる流れ

⚙️ 主要機能

1️⃣ タグのコンピューティングリソースへの伝播
  • 環境に適用したタグが、環境を実行するワーカー、スケジューラー、Web サーバーに伝播される
  • 環境上の 1 つのタグで、環境とすべてのコンポーネントのコストをカバー
  • 環境の新規作成時または更新時に、MWAA コンソール、AWS CLI (tag-resource)、TagResource API で付与可能
2️⃣ 環境 ARN への使用量の集約
  • オンボード後は、環境、ワーカー、スケジューラー、Web サーバーの使用量が単一の環境 ARN に帰属
  • オンボード前は個別の行だった追加ワーカー / 追加 Web サーバーが、環境 ARN の下に 1 行で表示
  • コストの帰属方法が変わるだけで、コストの総額自体は変わらない
3️⃣ Cost Explorer / CUR でのタグ別コスト分析
  • Billing and Cost Management コンソールでタグキーをアクティブ化すると、Cost Explorer や CUR でタグ別に集計可能
  • Cost Explorer の Group by でタグキーを選択すると、環境ごとの料金がタグキーで分類される
  • タグキーのアクティブ化は、組織の管理アカウントで 1 回実施すればよい

🔬 技術仕様: コスト帰属モデルの比較

項目 オンボード前 オンボード後
コストの帰属先 環境、追加ワーカー、追加スケジューラー、追加 Web サーバーが個別に計上 単一の環境 ARN に集約
タグによるコスト集計 環境タグがコンポーネントのコストをカバーしない 環境上の 1 つのタグで全コンポーネントをカバー
Cost Explorer のリソース別表示 コンポーネントごとに個別の行 環境 ARN の下に 1 行
コスト総額 変化なし 変化なし

タグ付与の例 (AWS CLI)

Bash MWAA 環境へのタグ付与 
aws mwaa tag-resource \
  --resource-arn arn:aws:airflow:ap-northeast-1:123456789012:environment/MyEnvironment \
  --tags '{"Team": "DataEngineering", "CostCenter": "CC-1234"}'

🛠️ 設定方法

前提条件

✓Amazon MWAA 環境が作成済みであること (既存環境は環境の更新によるオンボードが必要)
✓組織の管理アカウントで AWS Billing and Cost Management コンソールにアクセスできること
✓タグ操作のための IAM 権限 (airflow:TagResource など) があること

手順

1
環境にタグを付与する
Bash
aws mwaa tag-resource \
  --resource-arn arn:aws:airflow:ap-northeast-1:123456789012:environment/MyEnvironment \
  --tags '{"CostCenter": "CC-1234"}'

レポートに使用したいタグキー (例: CostCenter や Team) を付与。MWAA コンソールや TagResource API からも設定可能。

2
既存環境をオンボードする
Bash
aws mwaa update-environment \
  --name MyEnvironment

環境を更新すると、環境とすべてのコンポーネントがオンボードされる。新しいコスト追跡モデルの提供開始後に作成された環境は自動的にオンボードされる。

3
タグキーをコスト配分タグとしてアクティブ化する

管理アカウントで AWS Billing and Cost Management コンソールの [コスト配分タグ] ページを開き、対象のタグキーを選択して [アクティブ化]。組織で 1 回実施すればよく、反映まで最大 24 時間。

4
Cost Explorer でタグ別にコストを確認する

AWS Cost Explorer で Group by にタグキーを選択すると、各環境の料金がタグキーごとにグループ化されて表示される。

💡 メリット

💼 ビジネス面
✓ショーバック / チャージバックの実現: Airflow のコストをチーム、プロジェクト、コストセンターに正確に按分
✓FinOps の推進: タグベースのコスト可視化で組織的なコスト管理ポリシーを MWAA にも一貫して適用
✓コスト把握の簡素化: 手動集計や推計が不要になり、レポート作成の工数を削減
🔧 技術面
✓1 タグで全コンポーネントをカバー: コンポーネント単位のタグ管理が不要
✓環境 ARN への集約: 環境単位の合計コストを 1 行で確認でき分析が容易
✓既存の仕組みとの統合: Cost Explorer、CUR、コスト配分タグという AWS 標準の仕組みをそのまま利用

⚠️ デメリット・制約事項

制限事項

⚠️既存環境を完全にオンボードするには環境の更新が必要 (新モデル提供後に作成した環境は自動オンボード)
⚠️最近作成 / 更新された環境のワーカーと Web サーバーは置き換え時に新モデルへ移行されるが、長期間更新されていない環境は自動移行されないため環境の更新が必要
⚠️コンポーネントがオンボードされるまでは、その使用量はコンポーネント自身のリソースに計上され、環境のタグに含まれない

考慮すべき点

📌タグキーと値は大文字と小文字が区別される
📌タグのアクティブ化 / 非アクティブ化は、それ以降の使用量にのみ適用され、過去の請求期間のコストデータは変更されない
📌タグのアクティブ化後、コストレポートに表示されるまで最大 24 時間かかる

🎯 ユースケース

1. マルチチーム環境でのチャージバック

シナリオ: データプラットフォームチームが複数の事業部門向けに MWAA 環境を提供しており、各部門に実際の利用コストを請求したい。

Bash部門ごとの環境にタグを付与
aws mwaa tag-resource \
  --resource-arn arn:aws:airflow:ap-northeast-1:123456789012:environment/SalesAnalytics \
  --tags '{"BusinessUnit": "Sales"}'

aws mwaa tag-resource \
  --resource-arn arn:aws:airflow:ap-northeast-1:123456789012:environment/MarketingETL \
  --tags '{"BusinessUnit": "Marketing"}'

効果: Cost Explorer で BusinessUnit タグで Group by するだけで部門別の MWAA コストが自動集計され、チャージバックの根拠データとして利用できる。

2. プロジェクト別のコスト追跡

シナリオ: 複数のデータパイプラインプロジェクトが並行して進行しており、プロジェクトごとのワークフロー実行コストを予算管理に反映したい。

Bash
aws mwaa tag-resource \
  --resource-arn arn:aws:airflow:ap-northeast-1:123456789012:environment/ProjectAlpha \
  --tags '{"Project": "Alpha", "CostCenter": "CC-1001"}'

効果: ワーカーや Web サーバーのスケーリングによるコスト増も含めた総コストをプロジェクト単位で追跡でき、予算超過の早期検知につながる。

3. CUR と組み合わせた詳細なコスト分析

シナリオ: FinOps チームが CUR を Amazon Athena で分析しており、MWAA のコストも他サービスと同じタグ体系で横断分析したい。

SQLCUR に対する Athena クエリの例
SELECT
  resource_tags_user_team AS team,
  SUM(line_item_unblended_cost) AS total_cost
FROM cur_table
WHERE line_item_product_code = 'AmazonMWAA'
GROUP BY resource_tags_user_team
ORDER BY total_cost DESC;

効果: 組織共通のタグ体系で MWAA を含む全サービスのコストを横断的に分析でき、一貫したコストガバナンスを実現できる。

💰 料金・利用可能リージョン

💵 料金

コスト配分タグの利用自体に追加料金はかかりません。MWAA の料金体系 (環境の稼働時間、ワーカー / スケジューラー / Web サーバーのインスタンスサイズと数、ストレージなどに基づく従量課金) に変更はありません。今回のアップデートはコストの帰属方法を変更するものであり、コストの総額自体は変わりません。

🌏 利用可能リージョン

Amazon MWAA が利用可能なすべての AWS リージョンで利用できます (東京リージョン、大阪リージョンを含む)。詳細は AWS リージョン表 を参照してください。

🔗 関連サービス・機能

→AWS Cost Explorer: タグキーで Group by することで、MWAA のコストをチームやプロジェクト単位で可視化
→AWS Cost and Usage Reports (CUR): タグ情報を含む詳細な使用量データを取得し、Athena などで分析
→AWS Billing and Cost Management: ユーザー定義タグのコスト配分タグとしてのアクティブ化を管理
→AWS Organizations: 管理アカウントでタグキーを 1 回アクティブ化すれば、組織全体のコストレポートに適用

📝 まとめ

Amazon MWAA のコスト配分タグ対応により、環境上の 1 つのタグでワーカー、スケジューラー、Web サーバーを含む全コンポーネントのコストをカバーでき、チームやプロジェクト単位のショーバック / チャージバックが容易になりました。
