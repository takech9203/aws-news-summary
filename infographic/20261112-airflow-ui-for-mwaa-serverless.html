Amazon MWAA Serverless

🌬️ Apache Airflow UI の提供開始

📅 リリース日: 2026 年 11 月 12 日 | Amazon Managed Workflows for Apache Airflow (MWAA) Serverless

📝 概要

Amazon MWAA Serverless で、ネイティブの Apache Airflow UI が利用可能になりました。 ワークフローの閲覧、実行とタスクインスタンスの確認、タスクログの閲覧、ソースコードとバージョンの表示、実行の開始を、使い慣れた Airflow の画面から行えます。 Web サーバーの実行や管理は不要で、MWAA Serverless が UI をホストし、新しいブラウザタブで開きます。

最大の特徴は、UI を開いた IAM アイデンティティの権限でそのまま動作する点です。 そのアイデンティティが読み取れるワークフロー、実行、ログのみが表示され、StartWorkflowRun 権限を付与しないことで読み取り専用アクセスも簡単に構成できます。 UI がユーザーに代わって行う API 呼び出しはすべて AWS CloudTrail にそのユーザーのアイデンティティで記録されます。

❌ Before: アップデート前の課題
  • ワークフローの状態確認やログ閲覧は AWS CLI、API、CloudWatch Logs 経由で、Airflow に慣れたユーザーにとって可視性が低かった
  • タスクインスタンスの状態や実行履歴を一覧で視覚的に確認する手段がなかった
  • 従来の MWAA 環境の Airflow UI では Airflow 側のロールベース制御が必要で、IAM 権限との二重管理が発生しがちだった
✅ After: アップデート後の改善
  • ネイティブの Airflow UI でワークフロー、実行、タスクインスタンス、ログを視覚的に確認できる
  • IAM ポリシーだけでアクセス制御が完結し、読み取り専用アクセスも IAM で構成できる
  • UI の操作が CloudTrail にユーザーのアイデンティティで記録され、監査要件に対応しやすい
  • Web サーバーの運用が不要なまま、コンソール、CLI、API から UI を起動できる

⚙️ 主要機能

🌬️ ネイティブ Apache Airflow UI のホスティング
ワークフローの閲覧、実行とタスクインスタンスの確認、タスクログの閲覧、ソースコードとバージョンの表示、実行の開始に対応。Web サーバーの実行や管理は不要で、MWAA Serverless が UI をホストします。
🔐 IAM アイデンティティベースのアクセス制御
UI は開いた IAM アイデンティティの権限で動作し、ロールを UI に渡す必要がありません。アイデンティティが読み取れるワークフロー、実行、ログのみを表示し、airflow-serverless:StartWorkflowRun を付与しなければ読み取り専用アクセスになります。
📜 CloudTrail による監査証跡
起動 URL の作成は CreateAirflowUiUrl イベントとして記録。UI がユーザーに代わって行う ListWorkflowRuns や StartWorkflowRun などの呼び出しも、そのユーザーのアイデンティティで記録されます。
🔒 セキュアなセッション管理
起動 URL は 1 回限り有効で、最初に開いたブラウザでセッションが開始されます。セッションは起動 URL を開いた IP アドレスに紐付けられ、最大 12 時間で終了します (--session-duration-in-seconds で短縮可能)。

IAM ポリシー例

全ワークフローへの読み取りアクセスと実行開始を許可するポリシー例です。読み取り専用にする場合は airflow-serverless:StartWorkflowRun を除外します。

JSON IAM ポリシー例 (読み取り + 実行開始) 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "airflow-serverless:CreateAirflowUiUrl",
        "airflow-serverless:ListWorkflows"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "airflow-serverless:GetWorkflow",
        "airflow-serverless:ListWorkflowVersions",
        "airflow-serverless:ListWorkflowRuns",
        "airflow-serverless:GetWorkflowRun",
        "airflow-serverless:ListTaskInstances",
        "airflow-serverless:GetTaskInstance",
        "airflow-serverless:StartWorkflowRun"
      ],
      "Resource": "arn:aws:airflow-serverless:us-east-1:111122223333:workflow/*"
    },
    {
      "Effect": "Allow",
      "Action": "logs:FilterLogEvents",
      "Resource": "arn:aws:logs:us-east-1:111122223333:log-group:my-workflow-log-group:*"
    }
  ]
}

🚀 設定方法

前提条件

✓MWAA Serverless のワークフローが作成済みであること (UI は現在のリージョンのワークフローを表示)
✓UI を開く IAM アイデンティティに airflow-serverless:CreateAirflowUiUrl が許可されていること
✓Cookie を受け入れるブラウザを使用すること (セッションは UI のドメインの Cookie に保持)
✓UI 内で行う操作に応じた IAM 権限が付与されていること
1
コンソールから UI を開く
Amazon MWAA コンソールのナビゲーションペインで [Serverless workflows] を選択し、[Open Airflow UI] を選択します。UI が新しいブラウザタブで開きます。
2
CLI から起動 URL を作成する
Bash 起動 URL の作成 (URL 有効期間 60 秒、セッション 1 時間) 
aws mwaa-serverless create-airflow-ui-url \
  --expires-in-seconds 60 \
  --session-duration-in-seconds 3600 \
  --region us-east-1
出力の AuthorizedUrl を UrlExpiresAt の期限内にブラウザで開くと、UI セッションが開始されます。
3
セッションを管理する
起動 URL は 1 回限り有効です。最初に開いた人がその権限でセッションを取得するため、パスワードと同様に扱い、共有しないでください。 セッションは起動 URL を開いた IP アドレスからのみ有効です。早く終了するには UI のユーザーメニューからサインアウトし、再度開くには新しい起動 URL を作成します。

ビジネス面

✓運用の可視性向上: ワークフローの状態、実行履歴、ログを視覚的に確認でき、障害対応や日常運用のスピードが向上する
✓学習コストの削減: Airflow に慣れたチームは、サーバーレス環境でも従来と同じインターフェイスをそのまま利用できる
✓ガバナンスの強化: UI の全操作が CloudTrail にユーザー単位で記録され、監査やコンプライアンス要件に対応しやすい

技術面

✓IAM 一元管理: アクセス制御が IAM ポリシーだけで完結し、Airflow 側のロール管理との二重管理が不要
✓インフラ管理不要: Web サーバーのプロビジョニングや管理なしで UI を利用でき、MWAA Serverless の運用レスな特性を維持できる
✓セキュアなセッション設計: 1 回限りの起動 URL、IP アドレスへのセッション紐付け、最大 12 時間のセッション上限により、安全なアクセスを実現

⚠️ デメリット・制約事項

制限事項

✗UI からワークフローの一時停止・再開、実行やタスクインスタンスの停止・クリア・状態変更はできない (スケジュール変更は UpdateWorkflow、実行停止は StopWorkflowRun を使用)
✗接続 (Connections)、変数 (Variables)、プール、プロバイダー、設定、プラグイン、バックフィル、アセット、監査ログなどの管理機能は利用できない
✗UI はパブリック HTTPS で提供され、VPC エンドポイント (AWS PrivateLink) 経由ではアクセスできない。起動 URL を開くブラウザにはインターネットアクセスが必要 (CreateAirflowUiUrl の呼び出し自体はインターフェイス VPC エンドポイント経由で可能)

考慮すべき点

⚠️起動 URL は 1 回限り有効だが、期限内に第三者が先に開くとその人がユーザーの権限でセッションを取得するため、URL の取り扱いには注意が必要
⚠️タスクログの閲覧には CloudWatch Logs への logs:FilterLogEvents 権限が別途必要。ロググループが KMS カスタマーマネージドキーで暗号化されている場合はキーポリシーの許可も必要
⚠️セッションは最大 12 時間で自動的に終了するため、長時間の運用では URL の再作成が必要

🎯 ユースケース

1️⃣ 運用チームによる日常のワークフロー監視

シナリオ: データエンジニアリングチームが MWAA Serverless 上の ETL ワークフローの実行状況を毎日確認し、失敗したタスクのログを調査する。

Bash 実装例 
# コンソールの Serverless workflows ページから「Open Airflow UI」を選択
# または CLI で起動 URL を作成
aws mwaa-serverless create-airflow-ui-url --region ap-northeast-1

効果: CLI や CloudWatch Logs を個別に操作することなく、使い慣れた Airflow UI で実行履歴とタスクログを一元的に確認でき、障害調査の時間を短縮できる。

2️⃣ 監査担当者向けの読み取り専用アクセス

シナリオ: 監査やビジネス部門の担当者に、ワークフローの実行状況を閲覧のみ許可し、実行開始などの操作は禁止したい。

JSON 読み取り専用の IAM ポリシー抜粋 
{
  "Effect": "Allow",
  "Action": [
    "airflow-serverless:CreateAirflowUiUrl",
    "airflow-serverless:ListWorkflows",
    "airflow-serverless:GetWorkflow",
    "airflow-serverless:ListWorkflowRuns",
    "airflow-serverless:GetWorkflowRun",
    "airflow-serverless:ListTaskInstances",
    "airflow-serverless:GetTaskInstance"
  ],
  "Resource": "*"
}

効果: StartWorkflowRun を付与しないだけで読み取り専用の UI アクセスを実現でき、Airflow 側のロール設定なしに最小権限の原則を適用できる。

3️⃣ オンデマンドのワークフロー手動実行

シナリオ: 開発者が新しいバージョンのワークフローをデプロイした後、スケジュールを待たずに UI から手動で実行して動作を確認する。

Bash 実装例 
# セッション時間を 1 時間に制限した起動 URL を作成
aws mwaa-serverless create-airflow-ui-url \
  --expires-in-seconds 60 \
  --session-duration-in-seconds 3600
# UI 上でワークフローを選択し、実行を開始してタスクの進行とログを確認

効果: デプロイしたワークフローのソースとバージョンを UI で確認した上で手動実行でき、開発サイクルのフィードバックが速くなる。操作はすべて CloudTrail に記録される。

✅ まとめ

MWAA Serverless にネイティブの Apache Airflow UI が追加され、サーバーレスのメリットを維持したまま、ワークフローの可視性と運用性が大きく向上しました。 IAM 権限ベースのアクセス制御と CloudTrail による監査証跡により、エンタープライズのガバナンス要件にも対応しやすい設計です。

MWAA Serverless を利用中のチームは、UI を開くユーザーに airflow-serverless:CreateAirflowUiUrl と必要な読み取り権限を付与し、運用フローへの組み込みを検討することをお勧めします。
