☁️ Amazon MWAA

🦆 DuckDB オペレーターのネイティブサポート

Amazon Managed Workflows for Apache Airflow | リリース日: 2026 年 11 月 9 日

📌 概要

Amazon MWAA が DuckDB オペレーターのネイティブサポートを発表。 DuckDB は組み込み型の分析データベースで、Amazon S3 を含むデータソースに対して データ品質チェック、集計、変換を実行できます。

Apache Airflow v3.3.1 を使用する MWAA プロビジョンド環境では、 DuckDB がプリインストールされ、AWS 接続向けに事前設定済み。追加のセットアップなしに DuckDBExecuteQueryOperator を使用したタスクを記述できます。 インプロセス SQL エンジンのため、別途データベースサーバーやクラスターは不要です。

DAG タスク内の DuckDBExecuteQueryOperator が、ワーカー上で動作するインプロセスの DuckDB エンジンを呼び出し、自動作成される duckdb_default 接続と環境の実行ロールを通じて Amazon S3 のデータを読み書きする構成です。処理結果を Parquet 形式で S3 に書き出せば、Amazon Athena や BI ツールからも参照できます。

⚡ 主要機能

📦 1. DuckDB のプリインストール

Apache Airflow v3.3.1 以降の MWAA 環境に DuckDB がデフォルトで含まれ、requirements.txt へのパッケージ追加が不要。現在の v3.3.1 イメージには DuckDB 2.0.0、DuckDB プロバイダー 0.2.0、Amazon プロバイダー 9.38.0 を同梱。

🔗 2. duckdb_default 接続の自動作成

環境の作成時または更新時に MWAA が duckdb_default 接続を自動作成。duckdb_aws 接続タイプで環境の実行ロールを使って S3 にアクセスするため、アクセスキーの追加が不要。既存の接続は上書きされず、削除しても次回の環境更新時に再作成される。

🔒 3. インターネットアクセス不要の Amazon S3 サポート

S3 サポート用の DuckDB 拡張機能が MWAA イメージに同梱。デフォルトバージョンでは拡張機能のダウンロードが不要で、プライベートネットワーク構成の環境でもそのまま利用できる。

⚙️ 4. インメモリ実行

DuckDB はワーカー上のタスク内でインメモリ実行され、各タスクは空のデータベースから開始。タスク間のデータ共有は S3 への書き出しで行う。別途データベースサーバーやクラスターの運用は不要。

旧バージョンでの利用 (Airflow v2.11 から v3.2)

v3.2 以前の環境には DuckDB は含まれず、duckdb_default 接続も作成されません。 v2.11 から v3.2 では requirements.txt に apache-airflow-providers-duckdb と duckdb を追加し、 S3 アクセス時は SQL で拡張機能のロードと認証設定が必要です (v2.10 以前は利用不可)。

SQL 旧バージョンで必要な S3 アクセス設定 
INSTALL httpfs;
LOAD httpfs;
INSTALL aws;
LOAD aws;
CREATE SECRET (TYPE s3, PROVIDER credential_chain);

1
環境を Airflow v3.3.1 に更新する

更新が完了すると、DuckDB と関連プロバイダーがプリインストールされ、duckdb_default 接続が自動作成されます。DuckDB サポート提供前に作成した v3.3.1 環境の場合は、最新イメージ適用のための環境更新のみで利用できます。

Bash AWS CLI での環境更新 
aws mwaa update-environment \
  --name my-environment \
  --airflow-version 3.3.1
2
実行ロールに Amazon S3 権限を付与する

DuckDB のクエリで読み書きする S3 バケットへの権限を追加します。ワイルドカードパスの展開には s3:ListBucket が必要です。KMS 暗号化バケットの場合は KMS 権限も必要です。

JSON IAM ポリシー例 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-data-bucket",
        "arn:aws:s3:::my-data-bucket/*"
      ]
    }
  ]
}
3
DAG で DuckDBExecuteQueryOperator を使用する

接続 ID を指定しない場合、自動作成された duckdb_default 接続を使用し、実行ロールの認証情報で S3 にアクセスします。追加のセットアップは不要です。

Python DAG タスクの記述例 
from airflow.providers.duckdb.operators.duckdb import DuckDBExecuteQueryOperator

quality_check = DuckDBExecuteQueryOperator(
    task_id="quality_check",
    sql="""
        SELECT COUNT(*) AS row_count
        FROM read_parquet('s3://my-data-bucket/orders/*.parquet');
    """,
)

💡 メリット

💼 ビジネス面

✓運用コストの削減: 外部 DB やクエリエンジンが不要になり、インフラコストと管理負荷を削減
✓開発速度の向上: インストール・接続設定・認証情報管理が不要で、すぐに実装可能
✓セキュリティの向上: アクセスキーの埋め込みが不要で、IAM 実行ロールによる一元的な権限管理を維持

⚙️ 技術面

✓ゼロセットアップ: DuckDB、プロバイダー、S3 拡張機能がイメージに同梱
✓閉域環境での利用: デフォルトバージョンでは拡張機能のダウンロードが不要
✓Airflow エコシステムとの統合: アセットベースのスケジューリングと組み合わせ可能

⚠️ デメリット・制約事項

制限事項

⚠️ネイティブサポートは Airflow v3.3.1 以降の MWAA プロビジョンド環境が対象 (v2.11 から v3.2 では手動セットアップが必要、v2.10 以前は利用不可)
⚠️インメモリ実行のため各タスクは空のデータベースから開始し、タスク間のデータ共有には S3 への書き出しが必要
⚠️duckdb_aws 接続タイプには Amazon プロバイダー 9.38.0 以降が必要。requirements.txt で古いバージョンを指定すると S3 アクセスが失敗

考慮すべき点

💭ワーカー上で他のタスクとメモリを共有するため、大規模データでは環境クラスのサイズや memory_limit 設定に注意 (大規模データセットには Amazon Athena を検討)
💭デフォルト以外の DuckDB バージョンでは初回タスク実行時に拡張機能のダウンロードが発生 (閉域環境では起動スクリプトでの配置が必要)
💭DuckDB サポート提供前に作成した v3.3.1 環境では、最新イメージ適用のための環境更新が必要

🎯 ユースケース

✅ 1. パイプライン出力のデータ品質チェック

シナリオ: 上流の ETL ジョブが S3 に出力した Parquet ファイルについて、行数や NULL 値の有無を検証してから下流処理に進めたい。

Python品質チェックの実装例
check = DuckDBExecuteQueryOperator(
    task_id="validate_orders",
    sql="""
        SELECT
            COUNT(*) AS total_rows,
            COUNT(*) FILTER (WHERE order_id IS NULL) AS null_ids
        FROM read_parquet('s3://my-bucket/orders/dt=2026-11-09/*.parquet');
    """,
)

効果: 外部のクエリエンジンを起動することなく、DAG 内で軽量にデータ品質を検証でき、不正データの下流伝播を防止できる。

🔄 2. CSV から Parquet への変換と集計

シナリオ: 日次で S3 に届く CSV ファイルを集計し、分析用の Parquet 形式に変換して別のプレフィックスに保存したい。

Python変換・集計の実装例
transform = DuckDBExecuteQueryOperator(
    task_id="daily_summary",
    sql="""
        COPY (
            SELECT order_date, region, SUM(amount) AS total_amount
            FROM read_csv('s3://my-bucket/raw/orders/*.csv')
            GROUP BY order_date, region
        ) TO 's3://my-bucket/curated/daily_summary.parquet'
        (FORMAT parquet);
    """,
)

効果: 変換結果を Parquet として S3 に出力することで、Amazon Athena や BI ツールから効率的に参照できる分析基盤を低コストで構築できる。

⚡ 3. アセットベースのイベント駆動処理

シナリオ: 既存の DAG がデータを更新したタイミングで、その DAG を変更せずに DuckDB による検証タスクを自動実行したい。

Pythonアセット対応スケジューリングの実装例
from airflow.sdk import Asset

orders_asset = Asset("s3://my-bucket/orders/")

# データを書き込むタスクに outlets を追加
write_task = SomeOperator(task_id="write_orders", outlets=[orders_asset])

# DuckDB DAG はアセットをスケジュールとして使用
with DAG(dag_id="duckdb_checks", schedule=[orders_asset]):
    ...

効果: Apache Airflow のアセット対応スケジューリングと組み合わせ、データ更新をトリガーとした疎結合なデータ品質チェックのワークフローを実現できる。

🔗 関連サービス・機能

🪣 Amazon S3

DuckDB の読み書き対象となるデータストア。実行ロールの認証情報で CSV、JSON、Parquet ファイルにアクセスできる。

🔍 Amazon Athena

大規模データセットのクエリに適したサービス。DuckDB が出力した Parquet ファイルを Athena で参照する連携も可能。

🔑 AWS IAM

duckdb_default 接続は環境の実行ロールを使用するため、IAM ポリシーによる一元的なアクセス制御が適用される。

🔐 AWS KMS

暗号化された S3 バケットへアクセスする場合、実行ロールに KMS 権限の付与が必要。

📝 まとめ

Amazon MWAA の Apache Airflow v3.3.1 環境で DuckDB がネイティブサポートされ、 パッケージインストールや認証設定なしで DAG 内の軽量な SQL 処理を実装できるようになりました。 データ品質チェックや小規模な変換処理のために外部エンジンを用意していたワークロードでは、 アーキテクチャの簡素化とコスト削減が期待できます。
