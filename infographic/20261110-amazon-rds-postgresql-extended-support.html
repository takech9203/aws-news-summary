Amazon RDS for PostgreSQL

🐘 RDS Extended Support マイナーバージョン
13.23 / 12.22 / 11.22 リリース

📅 リリース日: 2026 年 11 月 10 日 | 🔒 重要な CVE 修正とバグ修正を提供

📋 概要

Amazon RDS for PostgreSQL が、RDS Extended Support 対象の新しいマイナーバージョンをリリースしました。 標準サポートが終了した PostgreSQL 13、12、11 を利用中のユーザー向けに、重要な CVE 修正とバグ修正を含むアップデートです。

❌ Before: アップデート前の課題
  • 標準サポート終了後の PostgreSQL 13、12、11 系では、コミュニティによる修正が提供されず脆弱性対応が困難
  • 旧バージョン利用時、重要な CVE やバグへの修正適用手段が限定的
  • メジャーバージョンアップグレードの検証期間中のセキュリティリスクが懸念
✅ After: アップデート後の改善
  • 13.23 / 12.22 / 11.22 で重要な CVE 修正とバグ修正を適用可能に
  • 標準サポート終了後も最大 3 年間、修正提供を受けながら移行計画を推進可能
  • マネジメントコンソールまたは AWS CLI から簡単に更新

Extended Support 対象バージョンへ重要な修正が提供される一方で、3 つの移行パスを通じて標準サポート対象の新しいメジャーバージョンへ移行する流れ

⚙️ 主要機能

1️⃣ Extended Support マイナーバージョンの提供

PostgreSQL 13 系は 13.23-rds.20260819、12 系は 12.22-rds.20260820、11 系は 11.22-rds.20260822 を提供。バージョン名の rds.YYYYMMDD 部分は、AWS が独自にビルドした Extended Support リリースであることを示します。

2️⃣ 重要な CVE 修正とバグ修正

標準サポート終了後のメジャーバージョンに対し、最大 3 年間にわたり重要な CVE 修正とバグ修正を提供。新しいメジャーバージョンへのアップグレード準備期間中も、セキュリティを維持したまま運用を継続できます。

3️⃣ 柔軟なアップグレードパス

Blue/Green Deployments: 本番環境のコピー (Green 環境) で変更を検証してから切り替え、ダウンタイムとリスクを最小化
インプレースアップグレード: 既存インスタンスを直接アップグレード
スナップショットからの復元: スナップショットを新バージョンのインスタンスとして復元

🛠️ 設定方法

前提条件

✓Amazon RDS for PostgreSQL 13、12、11 のいずれかの DB インスタンスを運用していること
✓RDS Extended Support が有効になっていること (標準サポート終了後に該当バージョンを継続利用している場合、自動的に Extended Support へ移行)
✓更新前にスナップショットなどのバックアップを取得しておくこと

ステップ 1: 現在のエンジンバージョンの確認

Bash現在のバージョンを確認
aws rds describe-db-instances \
  --db-instance-identifier my-postgres-instance \
  --query "DBInstances[0].EngineVersion"

ステップ 2: 利用可能なアップグレードターゲットの確認

Bashアップグレード可能なバージョン一覧を取得
aws rds describe-db-engine-versions \
  --engine postgres \
  --engine-version 13.22 \
  --query "DBEngineVersions[0].ValidUpgradeTarget[].EngineVersion"

ステップ 3: マイナーバージョンの適用

Bash新しい Extended Support マイナーバージョンへ更新
aws rds modify-db-instance \
  --db-instance-identifier my-postgres-instance \
  --engine-version 13.23 \
  --apply-immediately

💡 --apply-immediately を指定しない場合は、次回のメンテナンスウィンドウで適用されます。

💡 メリット

💼 ビジネス面

✓移行計画の柔軟性: 最大 3 年間の猶予で計画的なアップグレードが可能
✓コンプライアンス維持: CVE 修正の継続提供でセキュリティ・監査要件を満たしやすい
✓事業継続性: 旧バージョン依存のアプリを急いで改修せず安全に運用継続

🔧 技術面

✓セキュリティリスクの低減: コミュニティサポート終了後も重要な脆弱性修正を適用可能
✓検証済みのアップグレードパス: Blue/Green Deployments で本番影響を抑えて検証
✓運用の簡素化: コンソールや AWS CLI から標準手順で適用

⚠️ デメリット・制約事項

制限事項

✗Extended Support で提供されるのは重要な CVE 修正とバグ修正であり、新機能は追加されない
✗提供期間は標準サポート終了後、最大 3 年間に限られる
✗Extended Support 期間終了後は、新しいメジャーバージョンへのアップグレードが必要

考慮すべき点

⚠️標準の RDS 料金に加えて追加料金が発生するため、長期利用時のコストを考慮
⚠️あくまで移行までの猶予期間であり、早期に PostgreSQL 14 以降への移行計画を立てることを推奨
⚠️マイナーバージョン適用時に短時間のダウンタイムが発生する可能性があるため、メンテナンスウィンドウの計画が必要

🎯 ユースケース

1. レガシーアプリケーションのセキュリティ維持

シナリオ: PostgreSQL 11 に依存するレガシーアプリケーションを運用しており、改修とアップグレードの完了まで時間が必要。

Bash11.22-rds.20260822 へマイナーバージョンを更新
aws rds modify-db-instance \
  --db-instance-identifier legacy-app-db \
  --engine-version 11.22 \
  --no-apply-immediately

✅ 効果: アプリケーション改修期間中も重要な CVE 修正を適用し、セキュリティリスクを抑えながら運用を継続。

2. Blue/Green Deployments による安全なメジャーバージョン移行

シナリオ: PostgreSQL 13 から新しいメジャーバージョンへの移行を、本番影響を最小限に抑えて実施したい。

BashBlue/Green デプロイメントで新バージョンを検証
aws rds create-blue-green-deployment \
  --blue-green-deployment-name pg13-upgrade \
  --source arn:aws:rds:ap-northeast-1:123456789012:db:prod-db \
  --target-engine-version 17.4

✅ 効果: Green 環境で新バージョンの動作を十分に検証してから切り替えでき、移行リスクとダウンタイムを最小化。

3. フリート全体のバージョン棚卸しと計画的更新

シナリオ: 複数の RDS for PostgreSQL インスタンスを運用しており、Extended Support 対象のインスタンスを特定して最新マイナーバージョンへ統一したい。

BashPostgreSQL 11/12/13 系のインスタンスを一覧化
aws rds describe-db-instances \
  --query "DBInstances[?Engine=='postgres' && starts_with(EngineVersion, '1')].[DBInstanceIdentifier, EngineVersion]" \
  --output table

✅ 効果: Extended Support 対象インスタンスを把握し、最新の修正適用と新メジャーバージョンへの移行計画を組織的に推進。

💰 料金

💵RDS Extended Support の利用には、標準の RDS インスタンス料金に加えて追加料金が発生。料金は vCPU 時間単位で課金され、リージョンおよび Extended Support の経過年数によって異なります。
✓新しいマイナーバージョンの適用自体に追加費用はありません。

🌍 利用可能リージョン

公式発表にはリージョンに関する記載はありません。利用可能なバージョンはリージョンごとに異なる場合があるため、describe-db-engine-versions コマンドまたはドキュメントで確認してください。

📝 まとめ

PostgreSQL 13、12、11 を RDS Extended Support で運用しているユーザーは、重要な CVE 修正とバグ修正を含む今回のマイナーバージョン (13.23 / 12.22 / 11.22) を早期に適用することが推奨されます。あわせて、Extended Support はあくまで移行までの猶予期間であるため、Blue/Green Deployments などを活用して標準サポート対象のメジャーバージョンへの移行計画を進めることが重要です。
