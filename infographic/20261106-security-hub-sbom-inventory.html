🛡️ AWS Security Hub

コンピュートリソース向け SBOM インベントリの提供開始

📅 リリース日: 2026 年 11 月 6 日 | 機能: SBOM (Software Bill of Materials) インベントリ

📝 概要

AWS Security Hub が、コンピュートリソース向けの SBOM インベントリ の提供を開始しました。 Amazon Inspector がスキャン対象リソースに対して生成する SBOM をもとに、組織全体のソフトウェアインベントリを自動的に構築・維持します。

対象は EC2 インスタンスなどの仮想マシン、Amazon ECR のコンテナイメージ、AWS Lambda 関数で、Security Hub に接続した 他のクラウドプロバイダー (Microsoft Azure など) のリソースもカバーします。 追加設定は不要で、Security Hub Essentials の料金に含まれるため追加コストなしで利用できます。

❌ アップデート前の課題

  • 組織全体のパッケージ把握には、Inspector の SBOM を S3 にエクスポートして自前で集計・突合する必要があった
  • Log4Shell のような重大な脆弱性公開時に、影響リソースを迅速に特定する統一的な手段がなかった
  • マルチアカウント・マルチリージョン・マルチクラウド環境では独自の集約の仕組みの構築が必要だった

✅ アップデート後の改善

  • Inspector の SBOM をもとに、組織全体のインベントリが Security Hub 上で自動構築・自動更新
  • パッケージ名で横断検索し、特定パッケージを含む全リソースをコンソールまたは API で即座に特定
  • リソース詳細の「Installed software」タブでトリアージ時に全パッケージを確認
  • エクスポートや突合作業が不要になり、インベントリは常に最新に保たれる

Amazon Inspector がコンピュートリソースをスキャンして SBOM を生成し、Security Hub がそれを集約して組織全体の SBOM インベントリを構築します。セキュリティ担当者はコンソールまたは API からパッケージとリソースを横断的に検索できます。

⚙️ 主要機能

🗂️ 組織全体の SBOM インベントリの自動構築
  • Inspector が SBOM を生成すると Security Hub に自動送信され、リソースごとに最新の SBOM を保持
  • リソースの終了・削除や Inspector のカバレッジ外れ時は、該当ソフトウェアを自動削除
  • 定期的に Inspector との整合性確認を行い、インベントリを最新状態に維持
  • 管理者アカウントは組織全体を閲覧可能、メンバーアカウントは自アカウントのみ
📊 SBOM ページでのパッケージ一覧と可視化
  • コンソールの「Inventory」配下の「SBOM」ページで全パッケージを一覧表示
  • 「Packages by type」「Most common packages」チャートで分布を可視化
  • パッケージ名、バージョン、タイプ、インストール先リソース数を表示
  • パッケージ / アカウント / リージョン / リソースタイプ / クラウドプロバイダーでフィルタ・グルーピング可能。フィルタセットとして保存・再利用も可能
🔄 パッケージとリソース間の双方向ピボット
  • SBOM ページでパッケージ名またはリソース数を選択すると、該当リソースの一覧を表示
  • リソース詳細の「Installed software」タブで、全パッケージをバージョン・タイプとともに確認
  • トリアージ時にリソースの重要度、検出結果、インストール済みソフトウェアをまとめて確認
🔌 API によるプログラマティックなアクセス
  • 新しい Software API (GetSoftwareV2、GetSoftwareStatisticsV2、GetSoftwareResourcesV2) でインベントリを取得可能
  • 自動化ワークフローや外部ツールとの連携に活用

項目詳細
集約単位パッケージ (例: openssl バージョン 3.1.4) 単位で 1 行。複数リソースにインストールされていても 1 行で表示

チャート集計チャートはリソースごとに 1 インストールとしてカウントするため、チャート合計はテーブル行数より多くなる場合がある
更新遅延Inspector が新しい SBOM を生成してから反映まで数時間かかる場合がある

🛠️ 設定方法

前提条件

✓AWS アカウントとリージョンで Security Hub が有効化されていること
✓対象リソースタイプ (EC2、ECR、Lambda など) に対して Amazon Inspector が有効化されていること
✓他クラウドのリソースを対象にする場合は、該当プロバイダーが Security Hub に接続されていること (接続時に Inspector のスキャンが設定される)

自動化
  1. 前提条件の確認: Security Hub 側の追加設定は不要で、前提条件を満たすと自動的にデータが蓄積される。Inspector 未有効の場合は SBOM ページの [Enable Inspector] ボタンから有効化可能。なお、表示されるのは Inspector がスキャンするリソースタイプのソフトウェアのみ
  2. コンソールで SBOM ページを開く: Security Hub コンソールのナビゲーションペインで「Inventory」配下の [SBOM] を選択。パッケージ一覧、分布チャート、フィルタ・グルーピング機能を利用できる
  3. 特定パッケージを含むリソースの特定: パッケージ名またはリソース数を選択すると、インストール先リソースの一覧を表示。各リソースの重要度、検出結果、インストール済みソフトウェアを確認できる
  4. API からの利用: Software API で SBOM インベントリをプログラムから取得し、脆弱性対応の自動化や外部のアセット管理ツールとの連携に活用
Bash Software API の利用例

aws securityhub get-software-v2

# 集約されたソフトウェア統計を取得
aws securityhub get-software-statistics-v2

# 特定のソフトウェアパッケージを含むリソースを検索
aws securityhub get-software-resources-v2

✓インシデント対応時間の短縮: 新しい脆弱性の公開時に影響リソースを即座に特定でき、対応の初動を大幅に短縮
✓コンプライアンス対応の効率化: ソフトウェアサプライチェーンの最新記録が自動維持され、監査対応の工数を削減
✓追加コストなし: Security Hub Essentials に含まれるため、追加料金なしで利用可能

🔧 技術面

✓組織全体・マルチクラウドの可視性: 管理者アカウントから組織全体を一元把握、Azure など接続済み他クラウドもカバー
✓トリアージの効率化: 検出結果からインストール済みソフトウェアに直接ピボットでき、調査のコンテキストスイッチが減少

⚠️ デメリット・制約事項

制限事項

✗インベントリに含まれるのは Amazon Inspector がスキャンするリソースタイプのソフトウェアのみ (Inspector 未有効のリソースタイプは対象外)
✗Inspector が新しい SBOM を生成してから、インベントリに反映されるまで数時間かかる場合がある
✗メンバーアカウントは自アカウントのリソースのみ閲覧可能 (組織全体の閲覧は管理者アカウントのみ)

考慮すべき点

⚠️利用には Security Hub Essentials と Amazon Inspector の有効化が前提。未導入の場合はそれぞれの料金とカバレッジの確認が必要
⚠️チャートのインストール数はリソースごとにカウントされるため、テーブルのパッケージ行数とは集計方法が異なる点に注意

💰 料金・利用可能リージョン

💵 料金

SBOM インベントリは Security Hub Essentials に含まれており、追加料金なしで利用できます。新たな有効化作業も不要で、Amazon Inspector が有効化されている環境では自動的にインベントリが蓄積されます。 なお、前提となる Security Hub および Amazon Inspector 自体の料金は別途発生します。

🌍 利用可能リージョン

Security Hub が利用可能なすべての AWS リージョンで利用できます。

🔗 関連サービス・機能

🔍 Amazon Inspector

SBOM インベントリのデータソース。EC2 インスタンス、ECR コンテナイメージ、Lambda 関数をスキャンして SBOM を生成する。

🗂️ AWS Security Hub リソースインベントリ

Security Hub の Inventory 機能の一部として SBOM ページが提供され、リソース詳細パネルから検出結果やインストール済みソフトウェアを横断的に確認できる。

☁️ Microsoft Azure 統合

Security Hub に Azure を接続すると、Azure 仮想マシンや Azure Container Registry のコンテナイメージも SBOM インベントリの対象になる。

📌 まとめ

AWS Security Hub の SBOM インベントリにより、Amazon Inspector が生成する SBOM をもとに組織全体のソフトウェアインベントリが 追加設定・追加コストなしで自動構築されるようになりました。 新しい脆弱性公開時の影響範囲調査や検出結果のトリアージ、コンプライアンス対応を大きく効率化できます。

Security Hub と Amazon Inspector を利用中の環境では、まずコンソールの SBOM ページを開いてインベントリの内容を確認し、脆弱性対応の運用フローに組み込むことを推奨します。
