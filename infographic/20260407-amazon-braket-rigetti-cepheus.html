SDK からAmazon Braket API を通じて Cepheus-1-108Q QPU にジョブを送信し、結果は S3 バケットに保存されます。

🔑 主要機能

1. 108 量子ビット Cepheus-1-108Q QPU

  • Amazon Braket 初の 100 量子ビット超の超伝導 QPU
  • 9 量子ビットのチップレット 12 個による 3x4 配列のモジュラーマルチチップアーキテクチャ
  • チップレット間はチューナブルカプラとインターモジュールカプラで接続

2. CZ ゲートの導入

  • 従来の iSWAP ゲートに代わるネイティブゲート
  • 超伝導システムで一般的な位相エラーに対する耐性が向上
  • 断熱的 CZ 実装によりリーケージエラーを低減
  • より深い量子回路の実行が可能に

3. マルチフレームワーク対応とパルスレベル制御

Braket SDK Qiskit CUDA-Q Pennylane
  • パルスレベル制御で高度な実験が可能
  • ハイブリッドジョブで量子 - クラシカルワークロードを統合

💻 設定方法・コードサンプル

Bash ステップ 1: SDK のインストール 
pip install amazon-braket-sdk
Python ステップ 2: 量子回路の作成と実行 
from braket.circuits import Circuit
from braket.aws import AwsDevice

# Cepheus-1-108Q デバイスを指定
device = AwsDevice(
    "arn:aws:braket:us-west-1::device/qpu/rigetti/Cepheus-1-108Q"
)

# 量子回路を作成
circuit = Circuit()
circuit.h(0)       # Hadamard ゲート
circuit.cz(0, 1)   # CZ ゲート (ネイティブゲート)
circuit.h(1)

# タスクを送信
task = device.run(circuit, shots=1000)

# 結果を取得
result = task.result()
print(result.measurement_counts)
Python ステップ 3: Qiskit からの利用 
from qiskit import QuantumCircuit

# Qiskit で量子回路を作成
qc = QuantumCircuit(2)
qc.h(0)
qc.cz(0, 1)
qc.measure_all()

# Amazon Braket Provider 経由で実行
# braket-provider パッケージが必要

🎯 ユースケース

1. 分子シミュレーション

新薬候補の分子構造をシミュレーションし、化学反応のエネルギー計算を量子コンピュータで実行。108 量子ビットで従来より大きな分子系のシミュレーションが可能に。

VQE 新薬開発 化学シミュレーション

2. 組合せ最適化

サプライチェーンのルート最適化やポートフォリオ最適化を QAOA で解決。108 量子ビットで実問題に近いスケールの最適化アルゴリズム評価が可能に。

QAOA ルート最適化 ポートフォリオ

3. 量子機械学習

量子カーネル法や変分量子分類器でデータ分類。Pennylane 統合で効率的なワークフロー構築と CZ ゲートの高精度による学習安定性向上。

Pennylane 量子カーネル 分類器

✅ メリット

ビジネス面

+
自社で量子ハードウェアを保有せず 100 量子ビット超の QPU をクラウド利用可能
+
化学シミュレーションや最適化問題の研究開発サイクルが短縮
+
既存の Qiskit / Pennylane コード資産を活用し移行コストを抑制

技術面

+
CZ ゲートにより位相エラー耐性が向上し回路精度が改善
+
断熱的 CZ 実装でリーケージエラーを抑制
+
チップレットベース設計で将来的なスケーリング基盤を先行評価
+
パルスレベル制御でゲート動作の直接カスタマイズが可能

⚠️ デメリット・制約事項

!
利用可能リージョンは US West (N. California) のみ
!
NISQ 段階であり、実用的な量子優位性は限定的
!
QPU アクセスは可用性ウィンドウに依存
!
108 量子ビットは完全接続ではなく、トポロジーを考慮した回路設計が必要
!
CZ ゲートは iSWAP と異なるため、従来回路の再設計が必要な場合あり
!
量子エラー訂正なしの NISQ デバイスで回路深さに実質的制限
