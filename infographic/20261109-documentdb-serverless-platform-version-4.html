📝 概要

Amazon DocumentDB Serverless に新しいプラットフォームバージョン 4 が登場し、バージョン 3 と比較して最大 35% 高いスループットを提供します。プラットフォームバージョンは性能、スケーリング機能、機能面での改善を表すもので、クラスターレベルで自動的に管理されます。

新規クラスターは最新バージョンで自動起動し、既存のバージョン 3 クラスターは保留中のメンテナンスアクション serverless-platform-version-update を適用するだけでアップグレードできます。適用タイミングは「即時」または「次回メンテナンスウィンドウ」から選択可能です。

❌ Before: アップデート前の課題

  • バージョン 3 のベースライン性能がスループットの上限だった
  • 同じワークロードに多くの DCU を消費し、スパイク時のコストが増加しやすかった
  • プラットフォームレベルの性能改善を既存クラスターに取り込む標準手段がなかった

✅ After: アップデート後の改善

  • 同じ DCU レンジ (0.5 - 256 DCU) のまま最大 35% 高いスループットを利用可能
  • メンテナンスアクションの適用だけでバージョン 4 にアップグレード可能
  • 適用タイミング (即時 / 次回メンテナンスウィンドウ) をユーザーが制御可能
  • コンソールや DescribeDBClusters API でバージョンを確認可能

新規クラスターは自動的に最新のプラットフォームバージョン 4 で起動し、既存のバージョン 3 クラスターはメンテナンスアクションの適用により任意のタイミングでアップグレードできます。

⚡ 主要機能

🚀 最大 35% のスループット向上

  • バージョン 3 と比較して最大 35% 高いスループットを提供
  • DCU レンジは同じ 0.5 - 256 DCU のまま、性能のみが向上
  • アプリケーションコードや接続文字列の変更は不要

⚙️ クラスターレベルでの自動管理

  • プラットフォームバージョンは DocumentDB がクラスターレベルで自動管理
  • 新規クラスターはリージョンで利用可能な最新バージョンで起動
  • コンソールの設定タブ、または DescribeDBClusters API の ServerlessV2PlatformVersion フィールドで確認可能

🎛️ ユーザー制御によるアップグレード

  • 既存のバージョン 3 クラスターに保留中のメンテナンスアクション serverless-platform-version-update が表示される
  • 適用タイミングは immediate (即時) または next-maintenance (次回メンテナンスウィンドウ) から選択
  • アップグレード後は以前のバージョンへのダウングレード不可

🔍 プラットフォームバージョン確認用の新 API

  • 新しい DescribeServerlessV2PlatformVersions API で、利用可能なバージョンとその機能 (DCU レンジ、デフォルトバージョンなど) を確認可能

🛠️ 設定方法

前提条件

✓Amazon DocumentDB Serverless クラスター (エンジンバージョン 5.0 または 8.0) が稼働していること
✓利用リージョンでプラットフォームバージョン 4 が提供されていること
✓AWS CLI または AWS Management Console へのアクセス権限があること
1

現在のプラットフォームバージョンを確認する

Bash現在のバージョン確認
aws docdb describe-db-clusters \
    --db-cluster-identifier sample-cluster \
    --query 'DBClusters[0].ServerlessV2PlatformVersion'

出力が "3" の場合はアップグレード対象です。コンソールではクラスター詳細ページの設定タブに表示されます。

2

デフォルトのプラットフォームバージョンを確認する

Bash新 API でデフォルトバージョン確認
aws docdb describe-serverless-v2-platform-versions \
    --engine docdb \
    --default-only

リージョンのデフォルトプラットフォームバージョンと DCU レンジを確認します。バージョン 4 では「Version 4 offering scaling up to 256 DCUs, and performance improvement up to 35% compared to version 3」という説明が返されます。

3

保留中のメンテナンスアクションを確認する

Bash保留中アクションの確認
aws docdb describe-pending-maintenance-actions \
    --resource-identifier arn:aws:rds:ap-northeast-1:111122223333:cluster:sample-cluster

serverless-platform-version-update アクションが保留中の場合、「Upgrade to platform version 4」という説明が表示されます。

4

アップグレードを適用する

Bashメンテナンスアクションの適用
aws docdb apply-pending-maintenance-action \
    --resource-identifier arn:aws:rds:ap-northeast-1:111122223333:cluster:sample-cluster \
    --apply-action serverless-platform-version-update \
    --opt-in-type immediate

--opt-in-type に immediate を指定すると即時適用、next-maintenance を指定すると次回のメンテナンスウィンドウで適用されます。

💡 メリット

💼 ビジネス面

✓コスト効率の向上: 同じ DCU 消費でより多くのスループットを処理でき、DCU 時間ベースの課金コストの削減が期待できる
✓追加料金なしの性能向上: アップグレードに追加料金は発生せず、既存の料金体系のまま性能改善を享受できる
✓計画的な適用が可能: 即時適用と次回メンテナンスウィンドウ適用を選択でき、業務影響を考慮したアップグレードができる

🔧 技術面

✓アプリケーション変更不要: 接続文字列やコードの変更なしに最大 35% のスループット向上を得られる
✓運用の自動化: 新規クラスターは自動的に最新バージョンで起動するため、個別の設定が不要
✓可視性の向上: ServerlessV2PlatformVersion フィールドと新 API により、バージョン管理の状態を API で把握できる

⚠️ デメリット・制約事項

制限事項

✗一度新しいプラットフォームバージョンにアップグレードすると、以前のバージョンへのダウングレードはできない
✗バージョン 4 は一部のリージョンでは提供されていない (バージョン 3 は DocumentDB Serverless 対応の全リージョンで提供)
✗スループット向上は「最大 35%」であり、実際の向上幅はワークロードの特性に依存する

考慮すべき点

⚠️本番環境では事前にステージング環境での動作確認と、メンテナンスウィンドウでの適用を検討する
⚠️ダウングレードできないため、適用前にアプリケーションの互換性テストを実施しておく
⚠️アップグレード後は CloudWatch メトリクスの ServerlessDatabaseCapacity と DCUUtilization を監視し、DCU 消費の変化を確認する

🎯 ユースケース

🛒 ユースケース 1: 高トラフィックな EC サイトのピーク対策

シナリオ: プロモーションイベント時にアクセスが急増する EC サイトで、DocumentDB Serverless がピーク時に MaxCapacity 付近まで頻繁にスケールアップしている。

Bashアップグレード後の DCU 使用率監視
aws cloudwatch get-metric-statistics \
    --namespace AWS/DocDB \
    --metric-name DCUUtilization \
    --dimensions Name=DBClusterIdentifier,Value=sample-cluster \
    --start-time 2026-11-09T00:00:00Z \
    --end-time 2026-11-10T00:00:00Z \
    --period 3600 \
    --statistics Average Maximum

効果: 最大 35% のスループット向上により、同じ DCU 容量でより多くのリクエストを処理でき、ピーク時の MaxCapacity 到達によるパフォーマンス低下リスクを軽減できる。

💰 ユースケース 2: DCU コストの最適化

シナリオ: 変動の大きい分析系ワークロードを DocumentDB Serverless で運用しており、月間の DCU 時間コストを削減したい。

Bashメンテナンスウィンドウでの計画的なアップグレード
aws docdb apply-pending-maintenance-action \
    --resource-identifier arn:aws:rds:ap-northeast-1:111122223333:cluster:analytics-cluster \
    --apply-action serverless-platform-version-update \
    --opt-in-type next-maintenance

効果: 同一ワークロードをより少ない DCU で処理できるようになり、DCU 時間ベースの課金コストの削減が期待できる。業務時間外のメンテナンスウィンドウで適用することで、業務影響も最小化できる。

📋 ユースケース 3: 複数クラスターの一括バージョン管理

シナリオ: 複数の DocumentDB Serverless クラスターを運用しており、各クラスターのプラットフォームバージョンの状態を把握して計画的にアップグレードしたい。

Bash全クラスターのバージョン一覧と保留アクション確認
# 全クラスターのプラットフォームバージョンを一覧表示
aws docdb describe-db-clusters \
    --query 'DBClusters[?ServerlessV2PlatformVersion!=`null`].{Cluster:DBClusterIdentifier,PlatformVersion:ServerlessV2PlatformVersion}' \
    --output table

# 保留中のメンテナンスアクションを一覧表示
aws docdb describe-pending-maintenance-actions

効果: 組織内のクラスターのバージョン状態を API で可視化し、アップグレード計画の立案と進捗管理を効率化できる。

💵 料金

プラットフォームバージョン 4 の利用に追加料金は発生しません。DocumentDB Serverless の料金は従来どおり DCU 時間 (DCU-hour) ベースで課金されます。クラスター内のライターとリーダーの合計数を n とすると、無負荷時はおよそ n × MinCapacity、フル稼働時でも最大 n × MaxCapacity の DCU を消費します。

スループット向上により同じワークロードを少ない DCU で処理できる場合、実質的なコスト削減につながる可能性があります。詳細は Amazon DocumentDB 料金ページを参照してください。
