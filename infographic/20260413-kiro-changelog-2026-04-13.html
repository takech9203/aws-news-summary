📝 概要

Kiro CLI 2.0 がリリースされ、Windows 11 ネイティブサポート、CI/CD 自動化のためのヘッドレスモード、ターミナル UI のデフォルト化という 3 つの主要なアップデートが実施されました。これにより、全主要 OS でのエージェンティックコーディング体験が統一され、CI/CD パイプラインへの組み込みが可能になりました。

Before

  • macOS と Linux のみ対応。Windows ユーザーは利用不可
  • CI/CD パイプラインでの自動化には対話的操作が必要
  • ターミナル UI は実験的機能で --tui フラグの明示が必要

After

  • Windows 11 でネイティブ動作。全主要プラットフォームに対応
  • ヘッドレスモードで API キー認証による非対話的実行が可能
  • ターミナル UI がデフォルトに昇格。フラグ指定不要

🚀 主要機能

🪟 Windows 11 ネイティブサポート

WSL やコンテナを経由せず、Windows 11 上で直接動作。セットアップの手間とパフォーマンスオーバーヘッドを削減します。

  • ターミナル UI、ヘッドレスモード、カスタムエージェント、MCP サーバー統合の全機能を利用可能
  • PowerShell からのワンコマンドインストール
  • バックグラウンドでの自動アップデートにより最新バージョンを維持

⚙️ ヘッドレスモード

Kiro CLI を CI/CD パイプラインでプログラム的に実行可能にする新モードです。

  • API キー認証により対話的な入力なしにプロンプトを非対話的に実行
  • コードレビュー、テスト生成、コード品質チェックなどのタスクを自動化
  • GitHub Actions、GitLab CI、Jenkins など主要な CI/CD ツールと統合可能

🖥️ ターミナル UI のデフォルト化

以前は実験的機能であったターミナル UI がデフォルトエクスペリエンスに昇格しました。

  • --tui フラグの指定が不要に。起動時に自動でリッチ UI を表示
  • ファイル変更のプレビューやコンテキストの可視化が向上
  • 従来のターミナル体験は --classic フラグで引き続き利用可能

🔧 サブエージェント、フック、MCP 設定の強化

エージェンティックコーディングの中核機能がさらに強化されました。

  • カスタムサブエージェントの新機能が追加
  • スマートフックによるワークフロー自動化の改善
  • MCP サーバー設定の拡張により、外部ツールやデータソースとの接続がより柔軟に

💡 ユースケース

🔍 CI/CD パイプラインでの自動コードレビュー

開発チームが GitHub Actions を使用しており、プルリクエスト作成時に自動でコードレビューを実行したいシナリオ。
YAML GitHub Actions ワークフロー 
# .github/workflows/kiro-review.yml
name: Kiro Code Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install Kiro CLI
        run: curl -fsSL https://cli.kiro.dev/install | bash
      - name: Run Code Review
        env:
          KIRO_API_KEY: ${{ secrets.KIRO_API_KEY }}
        run: |
          kiro-cli --headless --prompt "Review the changes in this PR for security issues, performance problems, and code quality"
✅ プルリクエストごとに自動的にコードレビューが実行され、セキュリティ問題やパフォーマンスの懸念を早期に検出できる。

🪟 Windows チームのクロスプラットフォーム開発

🔒 カスタムエージェントとヘッドレスモードの組み合わせ

セキュリティチームが定期的なコンプライアンスチェックをスケジュール実行し、レポートを自動生成したいシナリオ。
Bash カスタムエージェントによるヘッドレス実行 
# カスタムエージェントを使用したヘッドレス実行
kiro-cli --headless --agent security-audit \
  --prompt "Run a comprehensive security audit on the current codebase and generate a compliance report"
✅ カスタムエージェントの専門知識とヘッドレスモードの自動化を組み合わせることで、定期的なセキュリティ監査を人手を介さずに実行できる。

⚖️ メリットと制約事項

✅ メリット

  • Windows を含む全チームメンバーが同一ツールを使用可能になり開発プロセスが統一される
  • ヘッドレスモードによりコードレビューやテスト生成を CI/CD パイプラインに組み込み品質管理を効率化
  • ターミナル UI のデフォルト化でリッチなインターフェースを全ユーザーに提供
  • WSL やコンテナ不要で Windows 上の直接動作によりセットアップの手間を削減
  • --classic フラグで後方互換性を確保

⚠️ 制約事項・考慮点

  • Windows サポートは Windows 11 に限定。Windows 10 以前は確認が必要
  • ヘッドレスモードは API キー認証が必要で、認証情報の安全な管理が求められる
  • リソース制約のある環境ではクラシックモードへの切り替えが必要な場合がある
  • CI/CD 導入時は API キーのシークレット管理や実行時間・コストへの影響を事前に評価すること
  • チーム全体で 2.0 へのアップグレード計画とワークフロー変更の周知が推奨
