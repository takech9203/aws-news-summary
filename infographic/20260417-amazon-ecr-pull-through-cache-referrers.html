Amazon ECR

📦 Pull Through Cache における
Referrer 自動検出・同期サポート

OCI Referrer Discovery and Sync | 2026 年 4 月 17 日

📋 概要

Amazon ECR の Pull Through Cache 機能が、OCI Referrer (イメージ署名、SBOM、アテステーションなど) の自動検出と同期をサポート。Pull Through Cache リポジトリに対して Referrers API をリクエストすると、ECR が自動的に上流レジストリから関連する Referrer アーティファクトを取得してプライベートリポジトリにキャッシュする。サプライチェーンセキュリティのワークフローが Pull Through Cache 上で完結するようになった。
❌ Before - アップデート前
🔴Referrers API で上流の Referrer が返されなかった
🔴cosign 署名検証には手動で上流から署名アーティファクトを取得する必要があった
🔴SBOM やアテステーション検出に上流レジストリへの直接アクセスが必要だった
🔴セキュリティワークフローと Pull Through Cache の統合が複雑で運用負荷が高かった
✅ After - アップデート後
🟢Referrers API リクエスト時に ECR が自動的に Referrer を検出・同期
🟢署名検証がクライアント側の回避策なしで Pull Through Cache 経由で動作
🟢SBOM ディスカバリーとアテステーション取得がシームレスに利用可能
🟢セキュリティツールチェーンを Pull Through Cache に直接使用可能

🏗️ アーキテクチャ図

Pull Through Cache リポジトリに対する Referrers API リクエスト時に、ECR が自動的に上流レジストリから Referrer アーティファクトを検出・同期し、クライアントに返却するフロー。

    Upstream-->>ECR: 署名 / SBOM / アテステーション返却

    ECR-->>Client: キャッシュ済み Referrer 返却

    Note over Client: 署名検証 / SBOM 検出が Pull Through Cache で完結

⚡ 主要機能

🔍
OCI Referrer の自動検出
Referrers API 呼び出し時に ECR が自動的に上流レジストリの Referrer を検出。OCI Distribution Spec v1.1 に準拠した Referrers API をサポート。
🔄
Referrer アーティファクトの自動同期
検出された署名、SBOM、アテステーションをプライベートリポジトリに自動キャッシュ。以降のリクエストではキャッシュされたアーティファクトを返却。
🔐
エンドツーエンドの署名検証
cosign などの署名検証ツールが Pull Through Cache リポジトリに対して直接動作。クライアント側の上流レジストリへの追加アクセスが不要。
📄
SBOM ディスカバリーとアテステーション取得
SBOM (Software Bill of Materials) の自動検出と取得。in-toto アテステーションなどの証明書アーティファクトの自動同期。

🛠️ 設定方法

前提条件

✓Amazon ECR プライベートレジストリが作成されていること
✓Pull Through Cache ルールが設定されていること
✓適切な IAM 権限が付与されていること

Step 1: Pull Through Cache ルールの確認

Bash 既存の Pull Through Cache ルールを確認 
aws ecr describe-pull-through-cache-rules \
  --region us-east-1

Step 2: Pull Through Cache 経由でイメージをプル

Bash Docker Hub のイメージを Pull Through Cache 経由でプル 
# Pull Through Cache ルールに従ったリポジトリ URI を使用
docker pull <account-id>.dkr.ecr.us-east-1.amazonaws.com/docker-hub/library/nginx:latest

Step 3: Referrer の検出と検証

Bash 署名検証と Referrer 一覧表示 
# cosign で Pull Through Cache リポジトリのイメージ署名を検証
cosign verify \
  <account-id>.dkr.ecr.us-east-1.amazonaws.com/docker-hub/library/nginx:latest \
  --certificate-identity=<identity> \
  --certificate-oidc-issuer=<issuer>

# ORAS CLI で Referrer を一覧表示
oras discover \
  <account-id>.dkr.ecr.us-east-1.amazonaws.com/docker-hub/library/nginx:latest

⚠️ デメリット・制約事項

制限事項

🟡Pull Through Cache ルールの事前設定が必要
🟡上流レジストリが OCI Referrers API をサポートしている必要がある
🟡Referrer の同期はオンデマンド - プロアクティブな事前同期ではない

考慮すべき点

🟡Referrer アーティファクトもストレージを消費 - ECR 料金に影響
🟡初回 Referrer 取得時は上流へのアクセスでレイテンシが増加する可能性
🟡アップストリーム認証情報 (Secrets Manager) の正しい設定が必要

🎯 ユースケース

🔐 UC1: CI/CD パイプラインでのイメージ署名検証
本番環境へのデプロイ前に、Pull Through Cache 経由で取得したコンテナイメージの署名を自動検証。これまで上流レジストリに直接アクセスする必要があったが、Pull Through Cache リポジトリに対して cosign verify を実行するだけで完結。
Bash CI/CD パイプラインでの署名検証ステップ 
IMAGE="<account-id>.dkr.ecr.us-east-1.amazonaws.com/docker-hub/library/nginx:latest"

# Pull Through Cache から署名を自動取得して検証
cosign verify $IMAGE \
  --certificate-identity="https://github.com/myorg/myrepo/.github/workflows/release.yml@refs/heads/main" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com"
効果: デプロイパイプラインの署名検証が簡素化。ネットワークポリシーで外部レジストリへのアクセスを制限している環境でも署名検証が可能。
📋 UC2: SBOM ベースの脆弱性管理
セキュリティチームが、Pull Through Cache 経由で使用しているサードパーティコンテナイメージの SBOM を自動的に収集し、脆弱性管理プラットフォームに連携。
Bash SBOM 取得と脆弱性スキャン連携 
IMAGE="<account-id>.dkr.ecr.us-east-1.amazonaws.com/docker-hub/library/python:3.12"

# ORAS で SBOM Referrer を検出
oras discover $IMAGE --artifact-type "application/spdx+json"

# SBOM をダウンロードして脆弱性スキャンツールに入力
oras pull $IMAGE --include-subject --artifact-type "application/spdx+json" -o /tmp/sbom/
効果: サードパーティイメージの SBOM 収集が自動化され、ソフトウェアサプライチェーンの可視性が向上。米国大統領令 14028 などの SBOM 要件への対応が容易に。
🛡️ UC3: SLSA アテステーションによるビルド来歴の検証
プラットフォームチームが、Pull Through Cache で取得したベースイメージの SLSA アテステーションを検証し、信頼できるビルドプロセスで生成されたことを確認。
Bash SLSA アテステーション検証 
IMAGE="<account-id>.dkr.ecr.us-east-1.amazonaws.com/ghcr/myorg/base-image:v1"

# cosign でアテステーションを検証
cosign verify-attestation $IMAGE \
  --type slsaprovenance \
  --certificate-identity="https://github.com/myorg/base-image/.github/workflows/build.yml@refs/heads/main" \
  --certificate-oidc-issuer="https://token.actions.githubusercontent.com"
効果: ベースイメージのビルド来歴を自動検証でき、サプライチェーン攻撃のリスクを軽減。Pull Through Cache を使用しながら SLSA レベル要件を満たすことが可能。
