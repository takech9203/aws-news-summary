🧩 Kiro for VS Code の一般提供開始

リリース日: 2026 年 11 月 20 日
Kiro VS Code ネイティブ拡張機能 macOS / Windows / Linux 全 Kiro プランで追加料金なし

📌 概要

Kiro は、VS Code 向けのネイティブ拡張機能「Kiro for VS Code」の一般提供を開始しました。 VS Code Marketplace または Open VSX からインストールし、サインインするだけで、使い慣れた VS Code を離れることなく Kiro エージェントを利用できます。 approve for me、スペック、ステアリング、MCP、ワークフロー、メモリといった Kiro の主要機能が VS Code に組み込まれた形で動作します。

Kiro for VS Code と Kiro IDE は同じ Kiro エージェントを実行し、 同じ .kiro フォルダの設定を読み取るため、チームメンバーごとに好みのエディタを選びながらプロジェクト設定を共有できます。

❌ アップデート前の課題

  • Kiro の全機能を利用するには Kiro IDE への切り替えが必要で、長年カスタマイズした VS Code 環境を手放す必要があった
  • ACP 経由での VS Code 利用は可能だったが、スペックのタスクボタンや CodeLens などのネイティブな統合体験は得られなかった
  • チーム内でエディタが異なると、スペックやステアリングなどのプロジェクト設定を共有しにくかった

✅ アップデート後の改善

  • サイドバー、コマンドパレット、CodeLens、差分ビューに統合されたネイティブな Kiro 体験が得られる
  • 同じ .kiro フォルダを読み取り、スペック、ステアリング、スキル、フック、パワー、MCP サーバーが変更なしでそのまま動作
  • スペックは双方向互換で、Kiro IDE と VS Code のどちらで作成してもそのまま動作
  • すべての Kiro プランに含まれ、プランや請求の変更なしで利用可能

Kiro for VS Code と Kiro IDE は同じ Kiro エージェントを実行し、同じ .kiro フォルダを共有するため、 チームメンバーごとに異なるエディタを使いながらプロジェクト設定を統一できます。

⚙️ 主要機能

1️⃣ .kiro 設定の完全互換
  • Kiro IDE で使用している .kiro フォルダをそのまま読み取り、スペック、ステアリングファイル、スキル、フック、パワー、MCP サーバーが変更なしで動作
  • スペックは双方向互換。Kiro IDE で開始したスペックは VS Code でタスクボタン付きで開き、その逆も可能
  • 回答時にどのステアリングファイルを参照したかが表示され、クリックしてソースを開きルールを調整できる
2️⃣ サイドバーでの vibe / spec セッション
  • VS Code のサイドバーに Kiro 専用ハブを追加。質問や軽微な変更は vibe セッション、計画が必要な作業は spec セッション
  • 応答とツールのアクティビティをリアルタイムにストリーミング表示。ターンはいつでも停止可能、ウィンドウをリロードしてもセッションは保持
  • # によるコンテキスト指定 (ファイル、フォルダ、診断情報、スペック、ターミナル出力など) や Kiro: Ask Kiro に対応
3️⃣ スペック駆動開発のフルサポート
  • 機能を記述すると、要件、設計、両者にトレースされたタスクリストを順に作成
  • バグ修正では、コード変更の前に「何が壊れているか」「何を維持すべきか」を bugfix チャットで整理
  • タイトルバーのボタンと CodeLens ラベルから、タスクを 1 つずつ実行することも残りすべてを一括実行することも可能
4️⃣ ワークフローとメモリ
  • 大きなタスクはワークフローエージェントが各ステップを個別セッションで処理し、その間もメインチャットで作業を継続できる (ワークフローはオプトイン)
  • メモリを有効にすると、リポジトリのコマンドや規約、過去の修正指示、除外済みのアプローチを記憶し、以降のセッションに引き継ぐ
5️⃣ 承認・レビュー・取り消しのコントロール
  • 手動承認に加え、approve for me で定型アクションは自動承認、安全でないものはブロック、不確かな場合のみ確認を要求
  • ターン終了時に変更ファイルを一覧表示。ターン全体の差分確認、ファイル単位の承認・却下、チェックポイントへの復元が可能
  • VS Code の Workspace Trust に準拠し、信頼されていないフォルダではワークスペース定義の MCP サーバーを起動しない

ステップ 2: サインイン

Kiro IDE と同じ方法でサインインします。既存のプランと請求がそのまま引き継がれます。

ステップ 3: セッションの開始

VS Code サイドバーの Kiro タブを開き、質問や軽微な変更には vibe セッション、計画が必要な作業には spec セッションを選択します。 ワークフローを使用する場合は、初回実行前に設定で有効化します。

⚠️ デメリット・制約事項

制限事項

⚠VS Code 1.147 以降が必要
⚠ワークフローはオプトイン機能のため、使用前に設定での有効化が必要
⚠信頼されていないフォルダ (Workspace Trust 未承認) では、ワークスペース定義の MCP サーバーは起動されない

考慮すべき点

💭Kiro IDE は引き続きエージェント中心の IDE 体験を進化させる場と位置づけられており、どちらが適するかはチームの働き方に応じて選択する
💭同日の Kiro Changelog には「Remote SSH, Dev Containers, and Cloud Sessions in the IDE」のエントリもあり、リモート開発環境での利用を検討する場合は併せて確認するとよい

🎯 ユースケース

1. VS Code 標準チームへの Kiro 導入

シナリオ: チーム全体が VS Code を標準エディタとしており、エディタを切り替えずにエージェントによるスペック駆動開発を導入したい。

  1. 各メンバーが VS Code Marketplace から Kiro 拡張機能をインストール
  2. 組織の ID プロバイダーでサインイン
  3. リポジトリの .kiro フォルダにステアリングファイルと MCP 設定をコミットして共有
✅ 効果: エディタ環境を変えずに、チーム全体で統一されたエージェント開発環境を構築できる。
2. Kiro IDE ユーザーと VS Code ユーザーの混在チーム

シナリオ: 一部のメンバーは Kiro IDE を使用し、他のメンバーは VS Code を使い続けたい。スペックやステアリングはプロジェクトで共有したい。

  1. Kiro IDE ユーザーがスペックを作成し、.kiro フォルダをリポジトリにコミット
  2. VS Code ユーザーが同じスペックをタスクボタン付きで開き、残りのタスクを実行
  3. ステアリングファイルの参照状況を双方のエディタで確認し、必要に応じてルールを調整
✅ 効果: エディタの違いを意識せず、スペック駆動のワークフローをチーム全体で共有できる。
3. 大きなタスクのバックグラウンド実行

シナリオ: 計画、実装、レビューを伴う大きめの機能追加をエージェントに任せつつ、自分は別の作業を続けたい。

  1. VS Code の設定でワークフローを有効化
  2. Kiro サイドバーからタスクを依頼し、ワークフローエージェントに処理を委任
  3. メインチャットで別の作業を継続し、完了後にターン全体の差分をレビューしてファイル単位で承認
✅ 効果: エージェントへの委任と人間によるレビューを両立し、開発スループットを向上できる。

🔗 関連サービス・機能

💻 Kiro IDE

同じ Kiro エージェントと .kiro 設定を使用するスタンドアロン IDE。同一プロジェクトで VS Code 版と切り替えて使用可能。

🔌 Agent Client Protocol ACP

Kiro を JetBrains IDE、Zed、Neovim などのエディタで利用するためのプロトコル。今回の発表以前から VS Code を含む各種エディタをサポート。

🤖 Kiro ワークフロー / メモリ

大きなタスクの分担処理とセッション間のコンテキスト引き継ぎを担う機能。VS Code 版でも利用可能。

🧰 MCP Model Context Protocol

.kiro フォルダで定義した MCP サーバーが VS Code 版でもそのまま動作。

📝 まとめ

Kiro for VS Code の一般提供により、VS Code ユーザーはエディタを切り替えることなく、 スペック駆動開発、ワークフロー、メモリ、approve for me といった Kiro の主要機能をネイティブに利用できるようになりました。 .kiro フォルダによる設定の完全互換により、Kiro IDE ユーザーとの混在チームでもプロジェクト設定を共有できます。 VS Code を利用中のチームは、Marketplace から拡張機能をインストールして既存プランのまま試すことを推奨します。
