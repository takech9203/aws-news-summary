2026 年 11 月の重要セキュリティパッチアップデート CSPU

📅 リリース日: 2026 年 11 月 17 日 | 🔒 四半期セキュリティ更新

📋 概要

Amazon Corretto の LTS バージョンと FR バージョン全系統に対する重要セキュリティパッチアップデート (CSPU) がリリースされました。Corretto は無償のマルチプラットフォーム対応 OpenJDK ディストリビューションで、OpenJDK の四半期セキュリティ更新サイクルに合わせてパッチが提供されます。

❌ アップデート前の課題
  • 旧バージョンの JDK には OpenJDK で報告された脆弱性が未修正のまま残存
  • セキュリティ要件の厳しい本番環境では修正済みランタイムへの速やかな入れ替えが必要
  • Java 8 〜 27 の複数バージョン併用環境では系統ごとの修正版入手が必要
✅ アップデート後の改善
  • LTS 版 (8 / 11 / 17 / 21 / 25) と FR 版 (27) の全系統で最新セキュリティ修正を適用可能
  • ホームページまたは Apt / Yum / Apk リポジトリ経由で速やかに更新できる
  • 無償ディストリビューションとして追加費用なしで本番環境のセキュリティを維持

今回の CSPU が対象とするバージョンと、更新版を入手するための配布チャネルの関係

⚙️ 主要機能

1️⃣ 全サポートバージョンへのセキュリティパッチ提供
✓LTS 版の Corretto 8 / 11 / 17 / 21 / 25 と FR 版の Corretto 27 すべてに更新版を提供
✓最新版は 27.0.1.1.4、25.0.5.1.2、21.0.13.1.2、17.0.21.1.2、11.0.33.1.1、8u514
✓複数の Java バージョンが混在する環境でも系統ごとに修正版へ移行可能
2️⃣ 複数の配布チャネルによる入手
✓Corretto ホームページから各バージョンを直接ダウンロード
✓Linux では Apt / Yum / Apk リポジトリ設定でパッケージマネージャー経由の更新に対応
✓Linux、Windows、macOS などマルチプラットフォームで利用可能
3️⃣ 無償での本番環境利用
✓無償 (no-cost) で提供される本番環境向け OpenJDK ディストリビューション
✓セキュリティパッチも追加費用なしで入手できる

🔧 設定方法

📌 前提条件

✓現在使用中の Corretto または他の JDK のバージョンを確認していること
✓更新前にアプリケーションの動作確認環境を用意していること
✓Linux リポジトリ経由で更新する場合は Corretto リポジトリが設定されていること
1
現在のバージョンを確認する
Bashバージョン確認
java -version

現在インストールされている Java ランタイムのバージョンを表示し、更新が必要かどうかを確認します。

2
パッケージマネージャーで更新する
Bashパッケージ更新
# Amazon Linux / RHEL 系 Yum の例
sudo yum update java-21-amazon-corretto

# Debian / Ubuntu 系 Apt の例
sudo apt-get update
sudo apt-get upgrade java-21-amazon-corretto-jdk

設定済みの Corretto リポジトリから最新の CSPU 適用版パッケージを取得してインストールします。

3
更新後のバージョンを確認する
Bash更新確認
java -version

更新後のバージョン番号が CSPU 適用版 (例: 21.0.13.1.2) になっていることを確認し、アプリケーションの動作テストを実施してください。

💡 メリット

💼 ビジネス面

✓セキュリティリスクの低減: 既知の脆弱性が修正されたランタイムへ更新し、本番環境のリスクを低減
✓コスト不要: 商用 JDK のようなライセンス費用なしでセキュリティ更新を継続
✓コンプライアンス対応: 定期的なパッチ適用でセキュリティポリシーや監査要件への対応が容易

🔬 技術面

✓幅広いバージョンカバレッジ: Java 8 〜 27 の全サポート系統に修正版を提供、レガシーも保護
✓簡単な更新手段: Apt / Yum / Apk 経由で更新でき、運用を自動化しやすい
✓マルチプラットフォーム対応: Linux、Windows、macOS で同一系統の更新版を利用可能

⚠️ デメリット・制約事項

🚧 制限事項

⚠パッチ適用には JVM の再起動が必要。稼働中アプリケーションへの適用にはメンテナンス計画が必要
⚠修正される脆弱性の詳細は GitHub の corretto リポジトリの変更履歴で別途確認が必要

🤔 考慮すべき点

⚠本番環境への適用前にステージング環境での動作確認を推奨
⚠コンテナイメージに JDK を同梱している場合はベースイメージの再ビルドと再デプロイが必要
⚠AMI やゴールデンイメージを使用している場合はイメージ更新パイプラインへの反映が必要

🎯 ユースケース

1. EC2 上の Java アプリケーションの定期パッチ運用

シナリオ: Amazon EC2 上で Corretto 21 を使用した Java アプリケーションを運用しており、四半期ごとのセキュリティ更新を適用したい。

BashSystems Manager Run Command で一括適用
aws ssm send-command \
  --document-name "AWS-RunShellScript" \
  --targets "Key=tag:Role,Values=java-app" \
  --parameters 'commands=["sudo yum update -y java-21-amazon-corretto"]'
✅ 効果: 多数のインスタンスに CSPU を一括適用でき、パッチ運用の工数を削減できる。
2. コンテナイメージのセキュリティ更新

シナリオ: Amazon ECS / EKS で稼働するコンテナ化された Java アプリケーションのベースイメージを最新の Corretto に更新したい。

DockerfileCSPU 適用版をベースイメージに使用
FROM amazoncorretto:21
COPY app.jar /app/app.jar
CMD ["java", "-jar", "/app/app.jar"]
✅ 効果: イメージの再ビルドと再デプロイにより、コンテナ環境全体へ速やかにセキュリティ修正を展開できる。
3. レガシー Java 8 アプリケーションの保護

シナリオ: 移行が完了していない Java 8 ベースのレガシーアプリケーションを、セキュリティを維持しながら運用し続けたい。

BashCorretto 8 の最新版 8u514 へ更新
sudo yum update -y java-1.8.0-amazon-corretto
✅ 効果: 商用 JDK のサポート費用をかけずに、レガシーアプリケーションにもセキュリティ修正を適用し続けられる。

💰 料金

Amazon Corretto は無償で提供されており、ダウンロード、利用、セキュリティパッチの適用に費用は発生しません。EC2 や ECS など、Corretto を実行する AWS リソースの料金は別途発生します。

🌍 利用可能リージョン

Amazon Corretto はリージョンに依存しないソフトウェアディストリビューションであり、グローバルにダウンロード可能です。AWS GovCloud (US) を含む各環境で利用できます。

🔗 関連サービス・機能

🛠️ AWS Systems Manager

Run Command や Patch Manager を使用して、EC2 フリート全体への Corretto 更新を自動化できる。

📦 Amazon ECS / Amazon EKS

Corretto ベースイメージを利用したコンテナワークロードの実行基盤。イメージ更新により CSPU を展開できる。

⚡ AWS Lambda

Java ランタイムは Corretto をベースにしており、マネージドランタイムでは AWS がパッチ適用を管理する。

📝 まとめ

今回の CSPU は、Corretto 8 から 27 までの全サポートバージョンに対する重要なセキュリティ更新です。Java アプリケーションを運用しているすべての環境で、ステージングでの動作確認を経て速やかにパッチを適用することを推奨します。コンテナやゴールデンイメージを使用している場合は、イメージ更新パイプラインへの反映も忘れずに実施してください。
