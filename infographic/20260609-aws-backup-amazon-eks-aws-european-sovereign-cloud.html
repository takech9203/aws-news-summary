AWS Backup Amazon EKS 🇩🇪 European Sovereign Cloud

🛡️ AWS Backup の Amazon EKS サポートが
European Sovereign Cloud (Germany) で利用可能に

📅 2026-06-09

📌 概要

Amazon EKS に対する AWS Backup サポートが、AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。 このリージョンの EKS クラスターに対し、フルマネージドかつポリシーベースのデータ保護とリカバリを提供します。

中央集約型・エージェントレスのソリューションで、EKS クラスター全体・名前空間・個々の永続ボリュームを保護でき、 独自のカスタムスクリプトやサードパーティツールを置き換えます。データ主権要件が厳格な規制対象業界にとって特に重要なアップデートです。

⚠️ アップデート前の課題
  • 当リージョンでは EKS のバックアップに AWS Backup を利用できなかった
  • Kubernetes アプリの保護にカスタムスクリプトやサードパーティツールが必要で管理負荷が高い
  • クラスター構成とステートフルデータを、他の AWS サービスと統一ポリシーで一元管理できなかった
✅ アップデート後の改善
  • 当リージョンで EKS に対するフルマネージドな AWS Backup が利用可能に
  • エージェントレスでクラスター全体・名前空間・永続ボリュームを保護、独自ツールが不要に
  • 自動スケジューリング、保持期間管理、イミュータブルボールト、クロスリージョン / クロスアカウントコピーを活用可能

エージェントレスの AWS Backup が EKS クラスター構成・名前空間・永続ボリュームを一元保護し、イミュータブルボールトへ保存。クロスリージョン / クロスアカウントコピーで別リージョン・別アカウントへ複製します。

⚡ 主要機能

🎯 保護対象の柔軟な指定
  • EKS クラスター全体 (デプロイメントやリソース構成を含む)
  • 特定の名前空間単位での保護
  • EBS / EFS / S3 に保存された永続ボリューム (ステートフルデータ)
📋 ポリシーベースの自動保護
  • 自動スケジューリングによる定期バックアップ
  • 保持期間管理によるライフサイクル自動化
  • 他の AWS サービスと統一された中央集約ポリシー
🔒 イミュータブルボールトとコピー
  • 悪意ある変更や誤操作からバックアップを保護
  • クロスリージョンコピーで地理的冗長性を確保
  • クロスアカウントコピーで誤削除リスクを低減
♻️ エージェントレスのリストア
  • フルクラスターを既存または新規クラスターへリストア
  • 過去の構成設定から新規クラスターをプロビジョニング
  • 非破壊的リストア (既存への反映は差分のみ)

🔧 技術仕様

保護対象とリストア先

保護対象保存先ストレージリストア先
EKS クラスター全体クラスター構成 + 永続ボリューム既存クラスター または 新規クラスター
名前空間名前空間内のリソースとデータ既存クラスターのみ
永続ボリュームAmazon EBS / EFS / S3既存クラスター

IAM 権限

Note バックアップ / リストアに必要な権限 
バックアップ / リストアには必要な権限を持つ IAM ロールを指定する。
永続ボリュームとして Amazon S3 を含める場合は、以下のポリシーを IAM ロールに追加する。
  - AWSBackupServiceRolePolicyForS3Backup

🛠️ 設定方法

前提条件

✓当リージョンで Amazon EKS クラスターが稼働していること
✓AWS Backup および Amazon EKS の利用に必要な IAM ロールが用意されていること
✓AWS Backup 設定で Amazon EKS 保護のオプトインが完了していること

手順

1
Amazon EKS 保護のオプトイン

AWS Backup コンソールの [設定] → [リソースを設定] で Amazon EKS の保護を有効化します。これにより EKS リソースが保護対象になります。

2
オンデマンドバックアップの作成

[保護されたリソース] → [オンデマンドバックアップを作成] を選択。リソースタイプに EKS を選び、対象クラスターと IAM ロールを指定します。S3 を含める場合は AWSBackupServiceRolePolicyForS3Backup を追加。定期実行が必要ならバックアッププランでスケジュールと保持期間を定義します。

3
リストアの実行

対象の複合リカバリポイントを選び [フル EKS クラスターをリストア] を選択。既存 / 新規クラスターのいずれかを選び、永続ストレージを構成して IAM ロールを指定し実行します。新規選択時は過去構成からクラスターをプロビジョニングします。

✓運用負荷の削減: 独自スクリプト・サードパーティツールが不要に

✓柔軟な保護粒度: クラスター / 名前空間 / 永続ボリューム単位
✓回復力の向上: クロスリージョン / クロスアカウントコピーで保全

⚠️ デメリット・制約事項

🚧 制限事項

✗永続ストレージの対象は EBS / EFS / S3 に限定
✗名前空間のリストア先は既存クラスターのみ (新規不可)
✗リストアは非破壊的で、既存への反映は差分のみ (バージョン上書きなし)
✗一部失敗時はフルリストア不可 (成功コンポーネントは個別リストア可)

🔎 考慮すべき点

!AWS Backup と Amazon EKS の両サービスが利用可能なリージョンでのみ利用可
!永続ストレージが上記 3 サービス以外の場合は保護対象外となる点を事前確認

🎯 ユースケース

1️⃣ ディザスタリカバリ

シナリオ: 当リージョンで本番 EKS クラスターを運用し、障害時に迅速な復旧が求められる。

実装例
- バックアッププランで日次スケジュールと保持期間を設定
- イミュータブルボールトへ保存
- クロスリージョンコピーで別リージョンへ複製
- 障害時は新規クラスターとしてフルリストア

効果: クラスター構成と永続データを一括復旧でき、RTO を短縮。

2️⃣ コンプライアンス対応

シナリオ: 規制対象業界で、改ざん不可能なバックアップの長期保持が監査要件。

実装例
- イミュータブルボールトを使用してバックアップを保護
- 保持期間管理で規定の保管期間を自動適用
- クロスアカウントコピーで分離された監査用アカウントへ保管

効果: 悪意ある変更や誤削除から保護し、監査要件を満たす。

3️⃣ クラスターアップグレード前の保護

シナリオ: Kubernetes バージョンのアップグレード前に安全なロールバックポイントを確保したい。

実装例
- アップグレード直前にオンデマンドバックアップを作成
- 問題発生時は新規クラスターとして過去構成からリストア

効果: アップグレード失敗時に既知の正常状態へ復元でき、リスクを低減。

💰 料金・利用可能リージョン

料金

AWS Backup の料金は、バックアップストレージの使用量、リストアしたデータ量、クロスリージョン / クロスアカウントのデータ転送量などに基づきます。EKS バックアップの具体的な料金は AWS Backup 料金ページを参照してください。

利用可能リージョン

今回のアップデートで AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。AWS Backup for Amazon EKS は、両サービスが利用可能なすべての商用リージョン (中国を除く) および AWS GovCloud (US) でも提供されています。

📝 まとめ

データ主権要件の厳しい AWS European Sovereign Cloud (Germany) リージョンでも、Amazon EKS クラスターを フルマネージドかつエージェントレスで保護できるようになりました。 ディザスタリカバリ、コンプライアンス対応、クラスターアップグレード前の保護など幅広い用途に活用できます。 当リージョンで EKS を運用する組織は、既存のカスタムスクリプトやサードパーティツールを AWS Backup へ移行し、 バックアップ運用の一元化と回復力の向上を検討することを推奨します。
