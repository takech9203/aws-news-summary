Amazon Bedrock AgentCore

🧠 AgentCore Memory がフルセッションサマリーを提供開始

セッション全体の振り返りを 1 レコードで取得 — 追加設定不要で自動生成
📅 リリース日: 2026 年 11 月 17 日

📌 概要

Amazon Bedrock AgentCore Memory が、すべてのセッションに対してフルセッションサマリー (Full Session Summary) を保持するようになりました。従来のサマリーチャンクが会話の一部分を詳細にカバーするのに対し、フルセッションサマリーはセッション全体の現在の状況を 1 つのレコードで把握できます。

新しいイベントが到着するたびに自動更新されるため、レコードは常に「セッションのこれまで」を反映します。会話の逐一の記録ではなく、手早い全体の振り返り (recap) が欲しい開発者に適した機能です。

❌ アップデート前の課題
  • セッション全体の 1 つの要約を得るには、複数のサマリーチャンクを取得して自前で組み立てる必要があった
  • 同じトピックに戻ると後続チャンクに新しい <topic> エントリが追加され、トピック横断の全体像を把握しにくかった
  • エージェントにセッションの完全なコンテキストを 1 レコードで渡す標準的な手段がなかった
✅ アップデート後の改善
  • セッション全体を 1 レコードで振り返れるフルセッションサマリーが自動的に生成・更新される
  • 追加設定なしで、サマリー戦略を持つすべてのメモリ (既存セッションを含む) で利用可能
  • x-amz-agentcore-memory-recordType メタデータでフィルタリングし、フルセッションサマリーだけを取得可能

サマリー戦略は、会話の進行に合わせてサマリーチャンクを追加しつつ、新しいチャンクの内容をフルセッションサマリーに折り込んで常に最新の状態に更新します。両者は同じ名前空間に保存され、レコードタイプで区別できます。

⚙️ 主要機能

📋 1. セッション全体を 1 レコードで保持
  • セッション全体の振り返りを単一の実行中レコード (running record) として保持
  • 新しいイベントが到着するたびに、新しいサマリーチャンクを既存の振り返りに折り込んで更新
  • 内容はセッションの進行とともに変化するため、最新の振り返りを得るにはイベント追加後にレコードを再読み込み
🔄 2. 追加設定不要の自動生成
  • サマリー戦略に付属し、個別の設定項目は存在しない
  • サマリー戦略を持つすべてのメモリで自動的に生成される
  • 機能提供前に要約された既存セッションに対しても作成される
🔍 3. 既存 API での取得とレコードタイプでのフィルタリング
  • memoryRecordType: FULL_SESSION の長期メモリレコードとして、サマリーチャンクと同じ名前空間に保存
  • GetMemoryRecord / ListMemoryRecords / RetrieveMemoryRecords で取得でき、新しい API は不要
  • システム生成メタデータキー x-amz-agentcore-memory-recordType でフィルタ可能 (インデックスキー宣言は不要)
  • 他のレコードと同様に埋め込み (embedding) されるため、セマンティック検索結果にも含まれる

🛠️ 設定方法

✅ 前提条件

✓Amazon Bedrock AgentCore Memory が利用可能なリージョンであること
✓メモリリソースにサマリー戦略 (summary strategy) が設定されていること
✓bedrock-agentcore:GetMemoryRecord、bedrock-agentcore:ListMemoryRecords、または bedrock-agentcore:RetrieveMemoryRecords を実行できる IAM 権限があること
1
サマリー戦略付きのメモリを確認する
Bashメモリの戦略一覧を確認
aws bedrock-agentcore-control get-memory \
  --memory-id <memory-id> \
  --query "memory.strategies"

サマリー戦略が含まれていれば、フルセッションサマリーは追加設定なしで自動的に生成されます。

2
フルセッションサマリーのみを取得する
BashrecordType でフィルタして一覧
aws bedrock-agentcore list-memory-records \
  --memory-id "<memory-id>" \
  --namespace "/strategy/<memory-strategy-id>/actor/<actor-id>/session/<session-id>/" \
  --metadata-filters '[
    {
      "left":     {"metadataKey": "x-amz-agentcore-memory-recordType"},
      "operator": "EQUALS_TO",
      "right":    {"metadataValue": {"stringValue": "FULL_SESSION"}}
    }
  ]'

セッションの名前空間を指定し、サマリーチャンクを除いたフルセッションサマリーだけを取得できます。

3
セマンティック検索をフルセッションサマリーに限定する
PythonRetrieveMemoryRecords + metadataFilters
import boto3

client = boto3.client('bedrock-agentcore')

response = client.retrieve_memory_records(
    memoryId="<memory-id>",
    namespace="/strategy/<memory-strategy-id>/actor/<actor-id>/session/<session-id>/",
    searchCriteria={
        "searchQuery": "セッションの現在の状況",
        "metadataFilters": [
            {
                "left": {"metadataKey": "x-amz-agentcore-memory-recordType"},
                "operator": "EQUALS_TO",
                "right": {"metadataValue": {"stringValue": "FULL_SESSION"}}
            }
        ]
    }
)

searchCriteria 内の metadataFilters に同じフィルタを追加すると、セマンティック検索の対象をフルセッションサマリーに限定できます。

💡 メリット

💼 ビジネス面
✓エージェント品質の向上: セッション全体の文脈を 1 レコードで渡せるため、長い会話でも一貫性のある応答を提供しやすい
✓開発コストの削減: チャンクから全体像を組み立てる独自ロジックの開発・保守が不要
✓既存資産の活用: 機能提供前の既存セッションにも作成されるため、過去のセッションにも遡って活用できる
🔧 技術面
✓追加設定不要: サマリー戦略を持つメモリであれば自動的に有効。移行作業や設定変更が不要
✓既存 API との互換性: 既存の Memory 操作をそのまま利用できる
✓効率的なコンテキスト管理: 振り返りを 1 レコードで取得でき、基盤モデルのコンテキストウィンドウを効率的に利用

⚠️ デメリット・制約事項

🚫 制限事項

✗サマリー戦略が前提であり、サマリー戦略を持たないメモリでは利用できない
✗他のレコードと同じ IAM アクション・リソース ARN を使用するため、フルセッションサマリーのみへのアクセス許可・拒否を IAM で分離できない (アプリケーション側で x-amz-agentcore-memory-recordType によるフィルタリングが必要)
✗生成を個別に無効化する設定はない

🤔 考慮すべき点

⚠モデルが生成・更新するレコードであるため、内容はセッションの進行とともに変化する。最新の振り返りを得るには、イベント追加後にレコードを再読み込みする必要がある
⚠セマンティック検索の結果にも含まれるため、チャンクのみを対象にしたい検索ではレコードタイプによる除外を検討する必要がある
⚠会話の詳細な経緯が必要な場合は、フルセッションサマリーではなくサマリーチャンクや短期メモリの生イベントの参照が適している

🎯 ユースケース

🎧 1. カスタマーサポートエージェントのセッション引き継ぎ

シナリオ: 長時間にわたるサポート対応の途中で別のエージェントやオペレーターに引き継ぐ際、会話全体の状況を素早く把握させたい。

Bash引き継ぎ用のフルセッションサマリー取得
aws bedrock-agentcore list-memory-records \
  --memory-id "<memory-id>" \
  --namespace "/strategy/<strategy-id>/actor/<customer-id>/session/<session-id>/" \
  --metadata-filters '[{"left":{"metadataKey":"x-amz-agentcore-memory-recordType"},"operator":"EQUALS_TO","right":{"metadataValue":{"stringValue":"FULL_SESSION"}}}]'
✅ 効果: 全チャンクを読み込まずに、問い合わせ内容と対応状況の全体像を 1 レコードで引き継げる。
🪟 2. 長い会話におけるコンテキストウィンドウの節約

シナリオ: 多数のターンが続く会話で、基盤モデルに全履歴を渡すとコンテキストウィンドウを圧迫してしまう。

Pythonサマリーをシステムプロンプトに注入
# フルセッションサマリーを取得してシステムプロンプトに注入
records = client.list_memory_records(
    memoryId="<memory-id>",
    namespace=session_namespace,
    metadataFilters=[full_session_filter]
)
session_recap = records["memoryRecords"][0]["content"]
✅ 効果: 会話履歴全体の代わりに常に最新のセッション振り返りをモデルに渡すことで、トークン消費を抑えつつ会話の一貫性を維持できる。
⏯️ 3. セッション再開時のクイックリキャップ

シナリオ: ユーザーが中断したセッションを再開する際、エージェントが「前回までの状況」を踏まえて会話を続けたい。

Python再開時にリキャップを読み込み
# セッション再開時にフルセッションサマリーを読み込み
recap = client.get_memory_record(
    memoryId="<memory-id>",
    memoryRecordId="<full-session-record-id>"
)
✅ 効果: イベント履歴を再処理することなく、セッションの現在地を 1 回の読み取りで復元でき、自然な会話の再開が可能になる。

📝 まとめ

Amazon Bedrock AgentCore Memory のサマリー戦略に、セッション全体を 1 レコードで振り返れるフルセッションサマリーが追加されました。追加設定なしで既存セッションを含むすべての対象メモリに自動適用されるため、サマリー戦略を利用中の場合は x-amz-agentcore-memory-recordType フィルタによる取得を試し、チャンクの組み立てロジックの置き換えやコンテキスト注入への活用を検討することを推奨します。
