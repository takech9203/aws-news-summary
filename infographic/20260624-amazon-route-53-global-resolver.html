Amazon Route 53

Route 53 Global Resolver
AWS アカウント間での DNS ビュー共有

📅 2026 年 6 月 24 日

📌 概要

Amazon Route 53 Global Resolver が、AWS Resource Access Manager (AWS RAM) を使用して他の AWS アカウントと DNS ビューを共有する機能をサポートしました。

コンシューマーアカウント (共有を受ける側) は、自身が所有する Route 53 プライベートホストゾーンを共有された DNS ビューに関連付けることができ、オーナーアカウント (共有元) の Global Resolver を通じて、Global Resolver が稼働するすべてのリージョンでレコードを解決できるようになります。

重要な点は、ホストゾーンや DNS ビューの所有権を移転することなく共有が実現できることです。各チームは引き続き自身のプライベートホストゾーンを所有・管理しながら、一元化された Global Resolver を通じてレコードを解決可能にできます。 アクセス制御は AWS RAM の事前定義マネージドアクセス許可、またはカスタムアクセス許可で柔軟に設定でき、対応リージョンで追加料金なしで利用できます。

⛔ アップデート前の課題
  • 一元化された Global Resolver で解決可能にするには、ホストゾーンや DNS ビューの所有権を集約する必要があった
  • 各チームがホストゾーンを所有・管理しながら、別アカウントの Global Resolver で解決させる仕組みがなかった
  • マルチアカウント環境で DNS 解決を集約する際、アカウント間の権限分離を維持することが難しかった
✅ アップデート後の改善
  • AWS RAM を使用して、所有権を移転せずに DNS ビューを他アカウントと共有可能に
  • コンシューマーが自身のプライベートホストゾーンを共有 DNS ビューに関連付け、オーナーの Global Resolver で解決可能に
  • マネージド/カスタムアクセス許可で、共有時のアクセスレベルをきめ細かく制御可能に

オーナーアカウントが AWS RAM を通じて DNS ビューを共有し、各コンシューマーが自身のプライベートホストゾーンを関連付けることで、オーナーの Global Resolver を通じた名前解決が実現します。

⚡ 主要機能

🔗 AWS RAM による DNS ビュー共有
  • オーナーが所有する DNS ビューを、AWS RAM で他の AWS アカウントと共有できる
  • 共有時にホストゾーンや DNS ビューの所有権は移転されない
  • コンシューマーは自身のプライベートホストゾーンを共有 DNS ビューに関連付け可能
🎯 所有権を維持したままの一元的な名前解決
  • 各チームは引き続き自身のプライベートホストゾーンを所有・管理できる
  • コンシューマー作成の関連付けはコンシューマーに属するが、オーナーからも参照・削除が可能
  • 関連付けレコードは Global Resolver 稼働の全リージョンで解決可能になる
🔒 きめ細かなアクセス制御
  • AWS RAM の事前定義マネージドアクセス許可を選択できる
  • 関連付けのみ / ライフサイクル管理 / フルアクセスの 3 レベルを用意
  • 特定アクションのみを許可するカスタムアクセス許可も作成できる

🛠️ 設定方法

前提条件

✓オーナーアカウントで Route 53 Global Resolver と DNS ビューが構成されていること
✓コンシューマーアカウントで共有対象とするプライベートホストゾーンが存在すること
✓双方のアカウントで AWS RAM が利用可能であること

1オーナーアカウントで DNS ビューを共有する

Bash AWS RAM リソース共有の作成 
aws ram create-resource-share \
  --name "global-resolver-dns-view-share" \
  --resource-arns "arn:aws:route53:::view/<dns-view-id>" \
  --principals "<consumer-account-id>" \
  --permission-arns "<ram-managed-permission-arn>"

対象の DNS ビューをコンシューマーに共有します。--permission-arns で適用するマネージドアクセス許可を指定します。

2コンシューマーアカウントで共有を承諾する

Bash リソース共有招待の承諾 
aws ram accept-resource-share-invitation \
  --resource-share-invitation-arn "<invitation-arn>"

オーナーから送信された招待を承諾します。同一 AWS Organizations 内で共有が有効な場合は、承諾が不要な場合があります。

3プライベートホストゾーンを共有 DNS ビューに関連付ける

コンシューマーアカウントで、自身のプライベートホストゾーンを共有された DNS ビューに関連付けます。関連付け後、ホストゾーン内のレコードがオーナーの Global Resolver を通じて解決可能になります。設定の詳細は公式ドキュメントを参照してください。

⚖️ メリットと制約事項

👍 メリット
✓権限分離の維持: 各チームが所有権を保持したまま DNS 解決を集約でき、ガバナンスとセキュリティ境界を維持
✓運用の集約: 一元化された Global Resolver で複数アカウントのプライベートドメインを解決でき、運用を簡素化
✓追加コストなし: 対応リージョンで追加料金なしで利用可能
✓所有権の非移転: 既存の管理構造を変更せずに共有できる
✓マルチリージョン解決: 全稼働リージョンでレコードを解決可能
⚠️ 制約・考慮点
!DNS ビュー共有は Global Resolver がサポートされるリージョンでのみ利用可能
!コンシューマー作成の関連付けはオーナーからも削除できるため、運用上の取り決めが必要
!最小権限の原則に従い、必要なアクションのみを許可するアクセス許可を選択する
!複数アカウントから同一 DNS ビューに関連付ける場合、ドメイン名の重複・衝突を避ける命名規則を検討する

💡 ユースケース

1. 集約型 DNS アーキテクチャ

シナリオ: 複数の事業部門がそれぞれ独立した AWS アカウントを持ち、各部門がプライベートホストゾーンを管理。組織全体で統一された Global Resolver を通じて名前解決を提供したい。

効果: 各部門がホストゾーンの所有権を保持したまま、中央の Global Resolver でレコードを解決可能にでき、ガバナンスと運用効率を両立。

2. チーム単位の DNS 管理委譲

シナリオ: ネットワークチームが Global Resolver と DNS ビューを所有し、アプリケーションチームが自身のホストゾーンを管理。アプリケーションチームには関連付けのみを許可したい。

効果: デフォルトの関連付けのみのアクセス許可を使用することで、アプリチームはホストゾーンを関連付けられるが DNS ビュー自体の構成は変更できず、適切な権限分離を実現。

3. オンプレミスからのマルチアカウント名前解決

シナリオ: オンプレミス環境から、複数の AWS アカウントに分散したプライベートリソースの名前解決を行いたい。

効果: 各アカウントのプライベートホストゾーンを共有 DNS ビューに関連付けることで、オンプレミスから単一の Global Resolver エンドポイントを通じて、すべてのアカウントのプライベートドメインを解決可能。

🎯 まとめ

Route 53 Global Resolver の DNS ビュー共有機能により、マルチアカウント環境でホストゾーンの所有権を維持したまま DNS 解決を集約できるようになりました。組織のガバナンスとセキュリティ境界を保ちつつ、一元化された名前解決アーキテクチャを構築したい場合に有効です。AWS RAM のアクセス許可を適切に選択し、最小権限の原則に従った共有設定を行うことを推奨します。
