📋 概要

Amazon SageMaker Feature Store が SageMaker Python SDK v3 をサポート。AWS Lake Formation によるアクセス制御と Apache Iceberg テーブルプロパティの設定機能が追加された。

ML モデル向けの特徴量を保存・共有・管理するフルマネージドリポジトリが、モダンなモジュラー SDK v3 インターフェースできめ細かなアクセス制御と最適化されたオフラインストレージを管理できるようになった。

🔄 Before / After 比較

❌ BEFORE
  • アクセス制御は IAM ポリシーのみ、列・行レベルの制御が困難
  • Iceberg プロパティ設定に AWS Glue API を直接操作が必要
  • SDK v2 は冗長でボイラープレートコードが多い
  • アクセス制御とストレージ最適化に別ツールが必要
✅ AFTER
  • Lake Formation で列・行・セルレベルのアクセス制御が可能
  • SDK v3 から Iceberg プロパティを直接設定
  • モジュラー SDK v3 でワークフロー合理化
  • 単一 SDK でガバナンスとパフォーマンス最適化を管理

⚡ 主要機能

🐍 SageMaker Python SDK v3 対応
  • モダンなモジュラーアーキテクチャによる新しい FeatureGroupManager クラス
  • sagemaker.mlops.feature_store モジュールを使用したフィーチャーグループ管理
  • ワークフローの合理化とボイラープレートコードの削減
  • フィーチャーグループの作成・取得・更新を統一的な API で実行
🔐 AWS Lake Formation アクセス制御統合
  • オフラインストアに対する列・行・セルレベルのセキュリティ
  • LakeFormationConfig クラスによる設定のカプセル化
  • ハイブリッドアクセスモード: IAM + Lake Formation 権限の共存
  • Lake Formation 専用モード: 厳格なアクセス制御
  • クロスアカウントアクセスのサポート
  • acknowledge_risk パラメータによる安全確認ゲート
🧊 Apache Iceberg テーブルプロパティ設定
  • IcebergProperties クラスによるバリデーション付きプロパティ設定
  • スナップショット保持、メタデータファイル管理、書き込み動作の制御
  • フィーチャーグループ作成時または既存グループへの更新で設定可能
  • 許可されたプロパティのみ設定可能なバリデーション機能

🔧 技術仕様

Lake Formation 設定パラメータ

パラメータ 型 デフォルト 説明
enabled bool False Lake Formation をアクティブにするか
use_service_linked_role bool True Lake Formation サービスリンクロールを使用するか
registration_role_arn str None カスタム登録ロールの ARN
hybrid_access_mode_enabled bool - IAM と Lake Formation の共存を許可するか
acknowledge_risk bool - リスク確認の安全ゲート

許可された Iceberg テーブルプロパティ

プロパティ デフォルト値 説明
write.metadata.delete-after-commit.enabled false コミット後に古いメタデータファイルを削除するか
write.metadata.previous-versions-max 100 追跡する過去バージョンメタデータファイルの最大数
history.expire.max-snapshot-age-ms 432000000 (5 日) スナップショットの最大保持期間
history.expire.min-snapshots-to-keep 1 保持するスナップショットの最小数
write.target-file-size-bytes 536870912 (512 MB) 生成ファイルのターゲットサイズ
write.delete.mode copy-on-write 削除コマンドのモード
write.update.mode copy-on-write 更新コマンドのモード
write.parquet.row-group-size-bytes 134217728 (128 MB) Parquet 行グループサイズ
read.split.target-size 134217728 (128 MB) データ入力スプリットのターゲットサイズ

🛠️ 設定方法

前提条件

✓ SageMaker Python SDK v3.8.0 以降がインストールされていること
✓ オフラインストアが設定された SageMaker Feature Group (Iceberg テーブル形式)
✓ Lake Formation 使用時: Lake Formation 管理者が設定済みであること
✓ 適切な IAM 権限 (AmazonSageMakerFeatureStoreAccess, AmazonSageMakerFullAccess)

Step 1: SDK のインストール

Bash SDK インストール/アップグレード 
pip install --upgrade sagemaker>=3.8.0

Step 2: Lake Formation を有効化したフィーチャーグループの作成

Python Lake Formation 有効化 
from sagemaker.mlops.feature_store import (
    FeatureGroupManager,
    LakeFormationConfig,
    OfflineStoreConfig,
    S3StorageConfig,
)

fg = FeatureGroupManager.create(
    # ... 他のパラメータ ...
    offline_store_config=OfflineStoreConfig(
        s3_storage_config=S3StorageConfig(s3_uri="s3://my-bucket/features/"),
        table_format="Iceberg",
    ),
    lake_formation_config=LakeFormationConfig(
        enabled=True,
        hybrid_access_mode_enabled=True,
        acknowledge_risk=True,
    ),
)

Step 3: Iceberg プロパティの設定

Python Iceberg プロパティ設定 
from sagemaker.mlops.feature_store import (
    FeatureGroupManager,
    IcebergProperties,
    OfflineStoreConfig,
    S3StorageConfig,
)

fg = FeatureGroupManager.create(
    # ... 他のパラメータ ...
    offline_store_config=OfflineStoreConfig(
        s3_storage_config=S3StorageConfig(s3_uri="s3://my-bucket/features/"),
        table_format="Iceberg",
    ),
    iceberg_properties=IcebergProperties(
        properties={
            "write.target-file-size-bytes": "536870912",
            "history.expire.min-snapshots-to-keep": "3",
        }
    ),
)

Step 4: 既存フィーチャーグループの更新

Python 既存グループの Iceberg プロパティ更新 
fg = FeatureGroupManager.get(feature_group_name="my-feature-group")
fg.update(
    iceberg_properties=IcebergProperties(
        properties={
            "write.target-file-size-bytes": "268435456",
            "write.delete.mode": "merge-on-read",
        }
    ),
)

Step 5: 設定済みプロパティの確認

Python プロパティ確認 
fg = FeatureGroupManager.get(
    feature_group_name="my-feature-group",
    include_iceberg_properties=True,
)
print(fg.iceberg_properties.properties)
# 例: {"write.target-file-size-bytes": "536870912"}

⚠️ デメリット・制約事項

制限事項

!Lake Formation アクセス制御はオフラインストアのみ。オンラインストアは引き続き IAM ポリシーで制御
!許可リスト外の Iceberg プロパティ変更は互換性保証なし、オフラインストアへの書き込み不能の可能性
!Iceberg テーブルのクロスアカウントアクセスではハイブリッドアクセスモードを無効にする必要あり
!hybrid_access_mode_enabled=False 設定で既存ジョブが即座にアクセスを失う可能性

考慮すべき点

!Lake Formation 有効化後、推奨される S3 拒否ポリシーを手動適用が必要
!サードパーティのクエリエンジン使用時はカスタム登録ロールが必要
!SDK v2 から v3 への移行に伴うコード書き換えが発生する場合あり

💡 ユースケース

🏢 ユースケース 1: マルチチームでの特徴量共有とアクセス制御
大規模な ML 組織で、複数のデータサイエンスチームが共通の特徴量ストアを使用しているが、チームごとにアクセスできる特徴量を制限したい。
Python Lake Formation 有効化 + ハイブリッドモード 
# Lake Formation を有効化してフィーチャーグループを作成
fg = FeatureGroupManager.create(
    feature_group_name="customer-features",
    lake_formation_config=LakeFormationConfig(
        enabled=True,
        hybrid_access_mode_enabled=True,
        acknowledge_risk=True,
    ),
)
# Lake Formation コンソールで列レベル権限を設定:
# チーム A: 全列アクセス可
# チーム B: PII 列を除くアクセスのみ
✅ 効果: 個別の IAM ポリシー作成の代わりに、Lake Formation の統一モデルで管理。運用負荷が大幅に軽減。
🚀 ユースケース 2: 大規模特徴量テーブルのパフォーマンス最適化
数億レコードの特徴量データを持つオフラインストアで、クエリレスポンス時間が増加。スナップショットの肥大化とファイルサイズの最適化が必要。
Python パフォーマンスチューニング 
fg = FeatureGroupManager.get(feature_group_name="large-feature-group")
fg.update(
    iceberg_properties=IcebergProperties(
        properties={
            "write.target-file-size-bytes": "268435456",  # 256 MB
            "history.expire.max-snapshot-age-ms": "259200000",  # 3日
            "history.expire.min-snapshots-to-keep": "2",
            "write.metadata.delete-after-commit.enabled": "true",
            "write.metadata.previous-versions-max": "50",
        }
    ),
)
✅ 効果: スナップショット保持期間の短縮とメタデータの自動クリーンアップで、クエリパフォーマンスが改善。
🔒 ユースケース 3: コンプライアンス要件に基づく行レベルセキュリティ
金融機関で地域ごとに異なる規制要件があり、各地域のデータサイエンティストは自地域の顧客データのみにアクセスする必要がある。
Python Lake Formation 専用モード 
# Lake Formation 専用モードで最大限のセキュリティを確保
fg = FeatureGroupManager.create(
    feature_group_name="customer-financial-features",
    lake_formation_config=LakeFormationConfig(
        enabled=True,
        hybrid_access_mode_enabled=False,  # Lake Formation のみ
        acknowledge_risk=True,
    ),
)
# Lake Formation で行フィルタリングを設定:
# 地域 A チーム: region='asia' のレコードのみ
# 地域 B チーム: region='europe' のレコードのみ
✅ 効果: Lake Formation の行レベルフィルタリングで IAM ポリシーでは実現困難だった行レベルのデータアクセス制御を実現。
