AWS Glue Data Catalog🌎 us-west-1 対応

⚙️ Apache Iceberg テーブル最適化が
米国西部 (北カリフォルニア) で利用可能に

📅 リリース日: 2026 年 10 月 30 日 | コンパクション / スナップショット保持 / 孤立ファイル削除のリージョン拡大

📝 概要

AWS Glue Data Catalog の Apache Iceberg テーブル自動最適化機能が、米国西部 (北カリフォルニア) リージョン (us-west-1) で利用可能になりました。Iceberg テーブルに蓄積する小さなファイル、古いスナップショット、孤立ファイルをバックグラウンドで自動的に整理し、クエリパフォーマンスとストレージ効率を維持します。

テーブル単位の有効化に加え、カタログレベルで全 Iceberg テーブルに一括適用でき、実行状況は AWS Glue コンソールと Amazon CloudWatch で監視できます。

❌ アップデート前の課題
  • us-west-1 ではテーブル最適化が使えず、Spark の rewrite_data_files などで独自メンテナンスジョブを構築・運用する必要があった
  • 古いスナップショットや孤立ファイルの削除も手動またはスケジュールジョブで実施し、運用負荷とストレージコストが増大
  • データ所在地要件で us-west-1 を使うワークロードは、他リージョンと同等の自動最適化の恩恵を受けられなかった
✅ アップデート後の改善
  • us-west-1 でも 3 種類の最適化を自動実行できるようになった
  • テーブル単位に加え、カタログレベルで一括適用が可能に
  • 実行結果を AWS Glue コンソール、CloudWatch メトリクス、ログで一元的に監視できる

Glue Data Catalog のテーブル最適化が Iceberg テーブルを継続的に監視し、3 種類の最適化をバックグラウンドで自動実行する流れ。実行状況は CloudWatch で監視できます。

🔧 主要機能

🗜️ コンパクション (Compaction)

小さなデータファイルを統合・再書き込みし、ストレージ使用量を削減してクエリの読み取りパフォーマンスを向上。デフォルトの binpack に加え、sort および Z-order 戦略をサポートし、スキャンするデータ量を削減してクエリ処理コストを低減します。

🕐 スナップショット保持 (Snapshot Retention)

スナップショットは Iceberg テーブルのタイムスタンプ付きバージョン。保持期間と保持数を設定でき、設定より古いスナップショットと関連する基盤ファイルを自動削除してストレージのオーバーヘッドを抑制します。

🧹 孤立ファイル削除 (Orphan File Deletion)

テーブル削除や ETL ジョブの失敗などで蓄積した、メタデータから参照されないファイルを定期的に特定・削除し、ストレージコストを削減します。

📚 カタログレベルとテーブルレベルの設定

カタログレベルは Lake Formation コンソールまたは AWS Glue の UpdateCatalog API で構成。テーブル単位の有効化・無効化は AWS Glue コンソール、AWS CLI、AWS Glue API で操作できます。

🛠️ 設定方法

前提条件

✓Apache Iceberg 形式のテーブルが AWS Glue Data Catalog に登録されていること
✓最適化ジョブが Amazon S3 のデータの読み書きと Glue Data Catalog へのアクセスを行うための IAM ロールを用意していること
✓米国西部 (北カリフォルニア) リージョンなど、テーブル最適化がサポートされているリージョンを使用していること

ステップ 1: テーブル単位でコンパクションを有効化

Bash コンパクション最適化の作成 
aws glue create-table-optimizer \
  --catalog-id <アカウント ID> \
  --database-name <データベース名> \
  --table-name <テーブル名> \
  --type compaction \
  --table-optimizer-configuration '{
    "roleArn": "arn:aws:iam::<アカウント ID>:role/<最適化用ロール>",
    "enabled": true
  }' \
  --region us-west-1

→ 指定した Iceberg テーブルに対してコンパクション最適化を作成・有効化。roleArn には S3 と Glue へのアクセス権限を持つ IAM ロールを指定します。

ステップ 2: スナップショット保持と孤立ファイル削除を有効化

Bash スナップショット保持最適化の作成 
aws glue create-table-optimizer \
  --catalog-id <アカウント ID> \
  --database-name <データベース名> \
  --table-name <テーブル名> \
  --type retention \
  --table-optimizer-configuration '{
    "roleArn": "arn:aws:iam::<アカウント ID>:role/<最適化用ロール>",
    "enabled": true,
    "retentionConfiguration": {
      "icebergConfiguration": {
        "snapshotRetentionPeriodInDays": 5,
        "numberOfSnapshotsToRetain": 1,
        "cleanExpiredFiles": true
      }
    }
  }' \
  --region us-west-1

→ スナップショットの保持期間と保持数を指定して作成。孤立ファイル削除は --type orphan_file_deletion を指定して同様に作成します。

ステップ 3: 最適化の実行状況を確認

Bash 実行履歴の一覧表示 
aws glue list-table-optimizer-runs \
  --catalog-id <アカウント ID> \
  --database-name <データベース名> \
  --table-name <テーブル名> \
  --type compaction \
  --region us-west-1

→ 最適化の実行履歴を一覧表示。AWS Glue コンソールや Amazon CloudWatch のメトリクスとログでも監視できます。

💡 メリット

💼 ビジネス面

✓運用コストの削減: 独自のメンテナンスジョブの構築・運用が不要になり、データエンジニアの工数を削減
✓ストレージコストの削減: 古いスナップショットや孤立ファイルを自動削除し、S3 のストレージコストを継続的に抑制
✓クエリコストの低減: コンパクションによりスキャンするデータ量が減少し、Athena などのクエリ処理コストを低減

⚙️ 技術面

✓クエリパフォーマンスの維持: 小さなファイルの蓄積によるパフォーマンス劣化を自動的に防止
✓一括設定: カタログレベルの設定により、Data Catalog 内のすべての Iceberg テーブルへ最適化を一括適用
✓可観測性: 実行状況を AWS Glue コンソール、CloudWatch メトリクス、ログで監視可能

⚠️ デメリット・制約事項

制限事項

✗対象は Apache Iceberg テーブルのみであり、他のテーブルフォーマットには適用されない
✗利用可能なリージョンは限定されている (下記の利用可能リージョンを参照)
✗最適化の実行には IAM ロールの設定など事前準備が必要

考慮すべき点

⚠️最適化 (コンパクションなど) の実行には処理量に応じた料金が発生するため、テーブルの書き込み頻度とコストのバランスを考慮する
⚠️スナップショット保持設定により古いスナップショットが削除されると、削除されたスナップショットへのタイムトラベルクエリは実行できなくなる

🎯 ユースケース

📡 ユースケース 1: ストリーミングデータレイクのパフォーマンス維持

シナリオ: us-west-1 のデータレイクに IoT センサーデータを数分間隔で継続的に書き込んでおり、小さなファイルが大量に蓄積して Athena のクエリが徐々に遅くなっている。

実装: 対象テーブルでコンパクション最適化を有効化し、バックグラウンドで小さなファイルを自動統合する。

効果: 手動メンテナンスなしでクエリパフォーマンスを維持し、スキャン量の削減によりクエリコストも低減できる。

💰 ユースケース 2: ストレージコストの自動削減

シナリオ: 日次の ETL ジョブで Iceberg テーブルを更新しており、スナップショットと不要ファイルが蓄積して S3 のストレージコストが増加している。

実装: スナップショット保持最適化で保持期間を 5 日間に設定し、孤立ファイル削除最適化もあわせて有効化する。

効果: 古いスナップショットと参照されないファイルが自動削除され、ストレージコストを継続的に抑制できる。

📚 ユースケース 3: カタログ全体への最適化の一括適用

シナリオ: 多数の Iceberg テーブルを運用しており、テーブルごとに最適化を設定する作業が負担になっている。

実装: Lake Formation コンソールまたは Glue UpdateCatalog API でカタログレベルの最適化設定を構成し、Data Catalog 内のすべての Iceberg テーブルに一括適用する。

効果: 新規作成されるテーブルを含め、カタログ全体で一貫した最適化ポリシーを少ない運用負荷で維持できる。

💲 料金

テーブル最適化の実行は AWS Glue の料金体系に基づいて課金されます。コンパクションなどの最適化処理は、処理に使用されたコンピューティングリソース (DPU 時間) に応じた従量課金です。最新の料金詳細は AWS Glue 料金ページ を確認してください。

✅ まとめ

Glue Data Catalog の Apache Iceberg テーブル自動最適化が米国西部 (北カリフォルニア) リージョンに拡大し、独自のメンテナンスジョブなしでクエリパフォーマンスの維持とストレージコストの削減が可能になりました。us-west-1 で Iceberg ベースのデータレイクを運用している場合は、対象テーブルまたはカタログ全体で最適化を有効化し、CloudWatch で実行状況を監視することを推奨します。
