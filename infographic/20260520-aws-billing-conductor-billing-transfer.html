💰 Billing Transfer Inventory による請求可視性の向上

2026 年 5 月 20 日
US East (N. Virginia)

📋 概要

AWS Billing Conductor コンソールに新しい Billing Transfer Inventory ページが追加されました。請求転送の招待を承認済みだが、ビリンググループが未設定のアカウントを一覧で確認でき、プロフォーマ請求データへのアクセスが欠落しているアカウントを即座に特定できます。

さらに、AWS User Notifications と Amazon EventBridge を通じた日次通知により、設定漏れを自動検知し、複数のチャネルでアラートを配信できます。

❌ Before

  • 招待承認済み・ビリンググループ未設定のアカウントを特定する手段がなかった
  • プロフォーマデータへのアクセス欠落を手動で調査する必要があった
  • 設定漏れに気づかず請求可視性にギャップが生じるリスクがあった

✅ After

  • Inventory ページで設定不完全なアカウントを即座に把握可能
  • 日次通知で設定漏れのあるアカウントを自動検知
  • 複数の通知チャネルで適切な担当者へ迅速にアラート配信

🚀 主要機能

📋 Billing Transfer Inventory ページ

請求転送の招待を承認済みだがビリンググループが未設定のアカウントを一覧表示。プロフォーマ請求データへのアクセスが欠落しているアカウントを特定でき、AWS Billing Conductor コンソール内で直接アクセス可能。

🔔 日次通知機能

AWS User Notifications と Amazon EventBridge を通じた自動通知。ビリンググループが未設定の承認済み請求転送の日次サマリーを配信し、設定完了を促すプロアクティブなアラート機能を提供。

📱 マルチチャネル通知配信

メール、Amazon Q Developer 経由のチャットアプリ (Slack, Microsoft Teams, Amazon Chime)、AWS Console Mobile Application プッシュ通知、Console Notifications Center での表示に対応。

ステップ 2: ビリンググループの作成

Bash AWS CLI - ビリンググループ作成 
aws billingconductor create-billing-group \
  --name "my-billing-transfer-group" \
  --account-grouping '{"LinkedAccountIds": ["123456789012"]}' \
  --computation-preference '{"PricingPlanArn": "arn:aws:billingconductor::123456789012:pricingplan/example-plan"}'

✅ メリットと制約事項

💼 ビジネス面

  • 請求ガバナンスの強化: 設定漏れを自動検出し、可視性ギャップを防止
  • 運用効率の向上: 手動確認が不要になり管理者の作業負担を削減
  • コンプライアンス対応: 全アカウントの請求データアクセス状況を一元的に把握

🔧 技術面

  • プロアクティブな検知: 日次通知で設定漏れを早期発見
  • マルチチャネル対応: 既存ツールと連携しアラート配信
  • EventBridge 連携: イベント駆動型ワークフローと自動化が可能

⚠️ 制限事項

✗US East (N. Virginia) リージョンでのみ利用可能
✗請求転送 (Billing Transfer) を使用している組織のみが対象
✗通知はビリンググループ未設定の検出に限定。自動修復機能は含まれない
✗ビリンググループの設定自体は手動で行う必要がある
✗大規模組織では通知量が多くなる可能性があり、適切なフィルタリングが推奨

🎯 ユースケース

🏢 マルチ組織の請求一元管理

シナリオ: ISV やチャネルパートナーが複数の顧客組織の請求を一元管理し、新規顧客オンボーディング時に請求転送の設定を段階的に進めている。

効果: 新規顧客のオンボーディング漏れを防止し、全顧客に対して一貫したプロフォーマコストデータの提供を保証。

🌐 大規模企業の子会社管理

シナリオ: グローバル企業が各子会社の AWS アカウントを請求転送で統合管理しているが、子会社の追加や変更が頻繁に発生する。

効果: 子会社追加時の設定漏れを即座に検知でき、プロフォーマコストデータの可視性を常に維持。

📑 コンプライアンス監査の自動化

シナリオ: 内部監査チームが全アカウントの請求データアクセス状況を定期的に確認する必要がある。

効果: 手動での監査作業を自動化し、請求ガバナンスのコンプライアンス状況をリアルタイムで把握。
