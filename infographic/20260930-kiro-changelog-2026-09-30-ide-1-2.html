Kiro

🚀 Kiro IDE 1.2 リリース
Workflows・安全強化・エンタープライズサインイン制御

📅 リリース日: 2026 年 9 月 30 日 | AI 搭載 IDE「Kiro」のアップデート

📋 概要

AWS が提供する AI 搭載 IDE である Kiro の IDE 1.2 がリリースされました。再利用可能なマルチエージェント Workflows のバックグラウンド実行、Kiro 設定ファイルと Workflow レシピの保護強化、エンタープライズ向けのサインイン方法の管理機能が導入されました。あわせて Agent Focus Mode のセッション詳細の刷新、エンタープライズプロファイルのリージョン内でのテレメトリ / アクティビティデータ処理、認証・デバッグ・信頼性に関する複数の修正も含まれます。

特に注目すべきは untrusted workspace の安全性強化です。エージェント、Hook、Power の各ファイルや .kiro/workflows/ 内のレシピをエージェントが変更しようとすると、広範なファイル書き込み権限が許可されている場合でも、Kiro は必ずユーザーに確認を求めます。

❌ アップデート前の課題

✗広範な書き込み権限下では、エージェントが Kiro 設定ファイル (エージェント定義 / Hook / Power) を確認なしで変更でき、動作が意図せず書き換えられるリスク
✗untrusted workspace でも一度許可したコマンドは再確認なしで実行され、信頼できないリポジトリへの防御が不十分
✗管理者が組織で許可するサインイン方法を制限・事前設定する手段がない
✗テレメトリ / アクティビティデータの送信先リージョンをプロファイルに合わせて制御できない

✅ アップデート後の改善

✓エージェント / Hook / Power ファイルと Workflow レシピの変更時に、権限設定にかかわらず必ず確認を要求し、改ざんリスクを低減
✓untrusted workspace ではすべての設定変更・コマンド実行の前に毎回確認。レシピは信頼するまで読み込まれない
✓サインイン方法の制限、組織情報の事前入力、ヘルプリンクの追加が可能に
✓テレメトリとアクティビティデータを選択したエンタープライズプロファイルの AWS リージョンに送信

⭐ 主要機能

1️⃣ マルチエージェント Workflows のバックグラウンド実行
  • 再利用可能なマルチステップのプランを依頼し、親チャットで作業を継続しながらバックグラウンドで実行
  • 各ステップは独立したエージェントセッションで実行
  • チャット上部の Workflows エリアから進捗確認、ステップ表示、一時停止 / 再開 / 停止が可能
  • デフォルトでは無効。Agent Focus の Workspace Configuration、または Settings の kiroAgent.workflows.enabled で有効化し、新しいチャットセッションを開始
2️⃣ Kiro 設定と Workflow レシピの保護
  • エージェント定義、Hook、Power の各ファイル、.kiro/workflows/ のレシピ変更前に必ず確認
  • より広範なファイル書き込み権限が許可されている場合でも確認を実施
  • untrusted workspace では、その他の設定変更・各コマンド実行の前にも毎回確認 (許可済みでも再確認)
  • untrusted workspace の Workflow レシピは、ワークスペースを信頼するまで読み込まれない
3️⃣ エンタープライズサインイン制御
  • 管理者が許可するサインイン方法を制限できる
  • 組織のサインイン情報をサインイン画面に事前入力できる
  • サインイン画面にヘルプリンクを追加できる
  • 許可されていない方法を選択した場合、許可されている選択肢を表示
4️⃣ Agent Focus Mode のセッション詳細の刷新
  • Workflows と Artifacts に専用ビューを追加
  • ステップごとのアクティビティ表示、アーティファクトのプレビューが可能
  • すべてのアーティファクトに「Open in IDE」を用意
5️⃣ リージョン内データ処理
  • テレメトリとアクティビティデータが、選択したエンタープライズプロファイルの AWS リージョンに送信される

🛠️ 設定方法

📌 前提条件

  • Kiro IDE 1.2 以降にアップデートしていること
  • エンタープライズサインイン制御を使用する場合は、組織の管理者権限があること
  • Workflows を使用する場合は、機能を明示的に有効化すること (デフォルトで無効)

📌 手順

1
Kiro IDE のアップデート

最新バージョンにアップデートします。untrusted workspace の安全強化と設定ファイル保護は自動的に適用され、追加の設定は不要です。

2
Workflows の有効化 (任意)

Agent Focus の Workspace Configuration で Workflows をオンにするか、Settings で以下を設定します。設定後、新しいチャットセッションを開始すると利用可能になります。

JSON Settings 
{
  "kiroAgent.workflows.enabled": true
}
3
ワークスペースの信頼設定の確認

信頼できないリポジトリは untrusted として扱われ、設定変更やコマンド実行のたびに確認が求められます。内容を確認して問題なければワークスペースを信頼することで、Workflow レシピの読み込みを含む通常の動作に戻ります。

4
エンタープライズサインイン制御の設定 (管理者)

許可するサインイン方法の制限、サインイン情報の事前入力、ヘルプリンクの追加を設定できます。詳細は エンタープライズサインインガバナンスのドキュメント を参照してください。

💡 メリットと制約事項

✅ メリット

✓ガバナンスの強化: サインイン方法を制御でき、組織のアイデンティティポリシーに沿った利用を強制。個人アカウントでの意図しない利用を防止
✓データレジデンシー対応: テレメトリ / アクティビティデータがプロファイルのリージョン内で処理され、データ所在地のコンプライアンス要件を満たしやすい
✓サプライチェーンリスク低減: 信頼できないリポジトリでの多層的な確認により、悪意ある設定やコマンドの自動実行リスクを低減
✓設定改ざんへの防御: エージェント / Hook / Power / レシピの変更は常に確認が必要となり、エージェント自身の動作の無断書き換えを防止
✓並行作業と可視性: Workflows によるバックグラウンド作業と、Agent Focus Mode の専用ビューによる確認性の向上

⚠️ 制約事項・考慮点

!Workflows はデフォルトで無効。有効化後に新しいチャットセッションの開始が必要
!untrusted workspace では Workflow レシピが読み込まれず、信頼するまで Workflows を利用できない
!untrusted workspace では許可済みコマンドでも毎回確認が必要となり、確認操作の頻度が増える
!設定ファイルやレシピの変更をエージェントに依頼するユースケースでは、確認プロンプトが増える
!サインイン制御の導入時は、既存ユーザーのサインイン方法が制限対象に含まれないか事前確認
!CVE-2026-87491 への修正を含むため、セキュリティ観点から早期アップデートを推奨

🎯 ユースケース

🔍 ユースケース 1: 外部リポジトリの安全な調査

シナリオ: オープンソースプロジェクトや外部から受領したリポジトリを Kiro で開いて調査する。悪意ある Hook や Workflow レシピが含まれている可能性がある。

→ untrusted のまま調査を開始すると、Workflow レシピは読み込まれず、コマンド実行は毎回確認される。内容を確認して問題がなければワークスペースを信頼する。

💪 効果: 悪意ある設定やコマンドの自動実行を防ぎながら、未知のコードベースを安全に調査できる。

🏢 ユースケース 2: 組織全体でのサインイン方法の統制

シナリオ: 企業の IT 管理者として、開発者が必ず組織の ID プロバイダー経由で Kiro にサインインするよう統制したい。

→ 許可するサインイン方法を組織の SSO のみに制限し、組織のサインイン詳細を事前入力として設定、社内ヘルプデスクへのリンクを追加する。

💪 効果: 許可されていない方法を選択しても許可された選択肢が提示され、組織のアイデンティティポリシーに沿った利用を徹底できる。

🤝 ユースケース 3: 設定ファイルを含むリファクタリングの安全な委任

シナリオ: エージェントに広範なリファクタリングを委任し、広いファイル書き込み権限を許可しているが、Kiro の動作を定義する設定ファイルは勝手に変更されたくない。

→ 通常のソースコードは既存の権限設定に従い自動編集され、エージェント / Hook / Power ファイルや .kiro/workflows/ のレシピへの変更要求時のみ確認プロンプトが表示される。

💪 効果: 広い権限で作業効率を保ちながら、エージェントの動作定義に関わる重要ファイルだけは人間の確認を必須にできる。

📝 まとめ

Kiro IDE 1.2 は、Workflows の導入に加えて、untrusted workspace と Kiro 設定ファイルに対する多層的な保護、エンタープライズ向けのサインイン制御とリージョン内データ処理を提供する、セキュリティとガバナンスを重視したリリースです。

CVE-2026-87491 に対処する Electron の更新も含まれるため、Kiro ユーザーは早期のアップデートを推奨します。エンタープライズ管理者は、新しいサインイン制御を活用して組織のアイデンティティポリシーの徹底を検討してください。
