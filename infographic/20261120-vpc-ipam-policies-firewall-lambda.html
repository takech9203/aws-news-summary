Amazon VPC IP Address Manager (IPAM)

☁️ IPAM ポリシーが自動インターネットファイアウォールと Lambda Web Functions / MicroVMs に対応

📅 リリース日: 2026 年 11 月 20 日 | 🛡️ パブリック IPv4 割り当ての一元統制がさらに拡大

📝 概要

Amazon VPC IPAM のポリシー機能が拡張され、AWS Network Firewall の自動インターネットファイアウォールと、AWS Lambda の Web Functions / MicroVMs をサポートしました。アカウントとリージョンをまたぐ一元的な IPAM ポリシーにより、指定した IPAM プール (BYOIP または Amazon 提供の連続 IPv4 ブロック) からパブリック IPv4 アドレスを割り当てられます。

セキュリティチームが割り当てルールを一元的に定義することで、リソースが承認済みレンジを使用する前提で IP ベースのフィルタリングを適用できます。Lambda Web Functions / MicroVMs では Lambda Network Connector 経由のアウトバウンド通信に使用されるパブリック IPv4 アドレスが対象です。

❌ Before - アップデート前の課題
  • 割り当てルールの対象は Elastic IP、ALB、RDS、NAT ゲートウェイなどに限られ、自動インターネットファイアウォールや Lambda Web Functions / MicroVMs は一元管理できなかった
  • 承認済み IP 範囲の使用は各アプリケーションチームの個別対応に依存
  • 外部パートナーやオンプレミスの許可リスト維持で、リソースごとの IP 収集・更新の運用負荷が発生
✅ After - アップデート後の改善
  • 自動インターネットファイアウォールと Lambda Web Functions / MicroVMs に指定 IPAM プールからパブリック IPv4 を自動割り当て
  • BYOIP や Amazon 提供の連続 IPv4 ブロックで予測可能なアドレス運用とコスト削減が可能
  • AWS プレフィックスリストとの統合で、割り当てレンジをパートナーと共有し許可リスト維持が容易に

🎯 対象ユーザー: マルチアカウント環境で IP アドレス管理を一元化したいネットワーク管理者・セキュリティチーム、BYOIP によるパブリック IPv4 コスト削減を検討する組織

IPAM ポリシーの割り当てルールに基づき、自動インターネットファイアウォールと Lambda Web Functions / MicroVMs に指定プールからパブリック IPv4 アドレスが割り当てられる流れを示しています。プールが枯渇した場合は Amazon 提供アドレスにフォールバックします。

⚡ 主要機能

🧱 1. 自動インターネットファイアウォールへのパブリック IPv4 割り当て
  • AWS Network Firewall の自動インターネットファイアウォールが割り当てルールの対象リソースタイプに追加
  • 指定した IPAM プール (BYOIP または Amazon 提供の連続 IPv4 ブロック) からアドレスを割り当て
  • 承認済みアドレス範囲での運用により、IP ベースのフィルタリングを前提としたセキュリティ態勢を強化
⚡ 2. Lambda Web Functions / MicroVMs へのパブリック IPv4 割り当て
  • Lambda Network Connector 経由のアウトバウンド通信に使用されるパブリック IPv4 アドレスが対象
  • 外部サービス側で Lambda からの通信元 IP を許可リストに登録する運用が容易に
🌍 3. アカウント / リージョン横断の一元管理とフォールバック
  • 1 つのポリシーに複数の割り当てルールを定義し、複数のリージョンに適用可能
  • プール枯渇時は Amazon 提供アドレスに自動フォールバックし、リソース作成が失敗しない
  • 割り当てレンジは AWS プレフィックスリストとの統合によりパートナーと共有可能

🔧 技術仕様: IPAM ポリシーの割り当てルール

項目詳細
対象リソースタイプElastic IP アドレス、Application Load Balancer、Amazon RDS、NAT ゲートウェイ (リージョン可用性モード)、Lambda Network Connector、自動インターネットファイアウォール
使用できるプールBYOIP アドレス、Amazon 提供の連続 IPv4 ブロックを含むパブリック IPAM プール
適用範囲AWS Organizations の組織、OU、またはメンバーアカウント単位で有効化。複数リージョンに適用可能
ルールの動作ルールを順に評価し、リソースタイプが一致すれば指定プールから割り当て。プール枯渇時は Amazon 提供アドレスにフォールバック
上書き条件リソース作成時に特定の IPAM プールや Elastic IP 割り当て ID を明示指定した場合はポリシーより優先
対応ティアIPAM の Free Tier および Advanced Tier の両方

💻 設定例 (AWS CLI)

Bash 自動インターネットファイアウォール向け割り当てルールの設定 
aws ec2 modify-ipam-policy-allocation-rules \
  --ipam-policy-id ipam-policy-0123456789abcdef0 \
  --locale ap-northeast-1 \
  --resource-type automated-internet-firewall \
  --allocation-rules '[{"IpamPoolId": "ipam-pool-0123456789abcdef0"}]'

指定リージョンの自動インターネットファイアウォールに対して、指定した IPAM プールからパブリック IPv4 アドレスを割り当てるルールを設定する例です (パラメータは環境に応じて読み替えてください)。

🛠️ 設定方法

📋 前提条件

✓IPAM ポリシーが作成済みであること

✓プール所有者以外のアカウントでポリシーを有効化する場合、AWS RAM でプールを対象アカウントと共有していること

ステップ 1: 割り当てルールの追加
コンソールで IPAM の [Policies] から対象ポリシーを選択し、[Allocation rules] タブで [Create allocation rules] を選択。Locale (リージョンまたは Local Zone) とリソースタイプ (自動インターネットファイアウォール、Lambda Network Connector など) を選択し、IP アドレスを提供する IPAM プールを指定します。
ステップ 2: プールの共有
Bash AWS RAM による IPAM プールの共有 
aws ram create-resource-share \
  --name ipam-pool-share \
  --resource-arns arn:aws:ec2::123456789012:ipam-pool/ipam-pool-0123456789abcdef0 \
  --principals arn:aws:organizations::123456789012:organization/o-example
共有が有効になるまで数分かかる場合があり、その間に作成されたリソースには Amazon 提供アドレスが割り当てられる可能性があります。
ステップ 3: ポリシーの有効化とテスト
ポリシーを使用するアカウント (組織、OU、またはメンバーアカウント) を指定して有効化。対象アカウントで設定したリソースタイプのリソースを新規作成し、IPAM プールのアドレスが割り当てられることを確認します。IPAM プールのコンソールで割り当て状況をモニタリングできます。

💡 メリット

💼 ビジネス面
✓パブリック IPv4 コストの削減: BYOIP 使用で Amazon 提供パブリック IPv4 の課金を削減
✓パートナー連携の簡素化: 承認済みレンジをプレフィックスリストで共有し、外部の許可リスト運用を容易に
✓ガバナンスの強化: IP アドレス管理を組織全体で一貫したポリシーとして適用
⚙️ 技術面
✓一元的な IP 割り当て制御: アカウント・リージョン横断の一つのポリシーで制御
✓可用性を損なわないフォールバック: プール枯渇時も Amazon 提供アドレスでリソース作成が失敗しない
✓セキュリティ態勢の向上: 承認済みレンジ前提で IP ベースのフィルタリングを安心して適用

⚠️ デメリット・制約事項

🚫 制限事項
✗リソース作成時に特定の IPAM プールや Elastic IP 割り当て ID を明示指定した場合、IPAM ポリシーより優先される
✗対象アカウントがプールにアクセスできない場合、リソース作成は成功するが Amazon 提供アドレスが割り当てられる
✗プール共有の反映には数分かかる場合があり、その間は Amazon 提供アドレスが割り当てられる可能性がある
🤔 考慮すべき点
⚠フォールバック時は承認済みレンジ外のアドレスとなるため、プールのアドレス残量モニタリングが重要
⚠複数の有効なポリシーのスコープに含まれる場合、適用されるポリシーの優先順位の理解が必要
⚠Lambda Web Functions / MicroVMs で対象となるのは Lambda Network Connector 経由のアウトバウンド通信のパブリック IPv4 である点に注意

🎯 ユースケース

1️⃣ 外部 SaaS への接続元 IP 固定

シナリオ: Lambda Web Functions / MicroVMs から外部の SaaS や金融系 API に接続する際、接続元 IP アドレスを事前に申請・許可リスト登録する必要がある。

  1. BYOIP アドレスをパブリック IPAM プールに登録
  2. Lambda Network Connector を対象とする割り当てルールを作成
  3. ポリシーをワークロードアカウントに対して有効化
  4. 承認済みレンジを SaaS 側の許可リストに登録
✅ 効果: アウトバウンド通信が常に承認済みレンジから行われるため、外部サービス側の許可リスト運用が安定し、申請の再実施が不要になる。
2️⃣ 自動インターネットファイアウォールのアドレス統制

シナリオ: マルチアカウント環境で Network Firewall の自動インターネットファイアウォールを展開し、オンプレミスや取引先のファイアウォールで AWS 側のアドレスを許可リスト管理している。

  1. Amazon 提供の連続 IPv4 ブロックを IPAM プールとして確保
  2. 自動インターネットファイアウォールを対象とする割り当てルールを組織単位で有効化
  3. 割り当てレンジをプレフィックスリストとして取引先と共有
✅ 効果: 連続したアドレスブロックで運用でき許可リストのエントリ数が削減され、アカウント追加時もルール変更なしで統制を維持できる。
3️⃣ BYOIP によるパブリック IPv4 コスト最適化

シナリオ: 多数のアカウントでパブリック IPv4 アドレスを消費しており、Amazon 提供アドレスの課金を削減したい。

  1. 自社保有の IP レンジを BYOIP として IPAM に登録
  2. Elastic IP、NAT ゲートウェイに加え、自動インターネットファイアウォールと Lambda Network Connector も対象とする割り当てルールを定義
  3. 組織全体でポリシーを有効化し、プール使用率をモニタリング
✅ 効果: 対象リソースタイプの拡大により BYOIP を適用できる範囲が広がり、パブリック IPv4 コストをさらに削減できる。

💰 料金

IPAM ポリシー自体の利用は、IPAM の Free Tier と Advanced Tier の両方で可能です。IPAM の料金詳細は、Amazon VPC 料金ページの IPAM タブを参照してください。BYOIP アドレスを使用する場合、Amazon 提供のパブリック IPv4 アドレスにかかる料金を削減できます。

🌍 すべての AWS 商用リージョンで利用可能です。

🔗 関連サービス・機能

  • 🧱 AWS Network Firewall: 自動インターネットファイアウォールのパブリック IPv4 アドレスが IPAM ポリシーの割り当て対象に
  • ⚡ AWS Lambda Web Functions / MicroVMs: Lambda Network Connector 経由のアウトバウンド通信に使用されるパブリック IPv4 アドレスが割り当て対象に
  • 🤝 AWS Resource Access Manager (AWS RAM): IPAM プールを組織内の他アカウントと共有するために使用
  • 📋 AWS マネージドプレフィックスリスト: 割り当てたアドレス範囲をパートナーと共有し、許可リスト運用を簡素化

📌 まとめ

IPAM ポリシーの対象リソースが自動インターネットファイアウォールとLambda Web Functions / MicroVMs に拡大し、パブリック IPv4 アドレスの組織的な統制をより広い範囲に適用できるようになりました。外部サービスの許可リスト運用や BYOIP によるコスト削減に取り組んでいる場合は、既存の IPAM ポリシーへの割り当てルール追加を検討することを推奨します。
