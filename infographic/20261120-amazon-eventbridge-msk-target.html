Amazon EventBridge

🚌 Custom イベントバスが Amazon MSK ターゲットをサポート

📅 リリース日: 2026 年 11 月 20 日 | 機能: Custom イベントバスにおける Amazon MSK ターゲットのサポート

📋 概要

Amazon EventBridge の拡張された Custom イベントバスが、Amazon MSK (Managed Streaming for Apache Kafka) をターゲットとしてサポートするようになりました。独自の Kafka プロデューサーを実装・運用することなく、Custom イベントバス上のイベントを Kafka トピックへ直接配信できます。

💡 Subscriber にクラスターの ARN とトピックを指定するだけで、EventBridge が配信されたイベントごとに 1 つの Kafka レコードを生成してトピックへ書き込みます。プロビジョンドクラスターと MSK Serverless の両方、パブリック接続とプライベート接続の両方に対応します。
❌ Before: アップデート前の課題
✗Lambda 関数などで独自の Kafka プロデューサーを実装・運用する必要があった
✗プライベートクラスター接続には VPC 内のコンピューティングリソースやネットワーク設定を自前で管理
✗パーティションキーの制御や順序保証を自前のコードで実装し、運用負荷が高かった
✅ After: アップデート後の改善
✓クラスター ARN とトピック名を指定するだけで、コードを書かずに Kafka トピックへ配信
✓プライベートクラスターへは AWS PrivateLink による接続を EventBridge が自動的に確立
✓パーティションキー、Acks、圧縮、レコードヘッダーを宣言的に構成可能
✓FIFO Subscriber との組み合わせでイベントグループ単位の順序を保ったまま同一パーティションへ配信

アプリケーションが Custom イベントバスに発行したイベントを、Subscriber がフィルタリングし、Kafka レコードとして MSK クラスターのトピックへ配信する流れ

⚡ 主要機能

🎯 1. MSK クラスターへのダイレクト配信
→Subscriber の TargetArn に MSK クラスターの ARN を設定し、MskParameters で配信先トピックを指定
→イベントごとに 1 つの Kafka レコードを生成し、イベント本文をレコード値として書き込み
→トピック名には固定値のほか、イベントごとに評価される JSONata 式も使用可能
⚙️ 2. Kafka プロデューサー設定の構成
→PartitionKey: 固定値または JSONata 式でパーティションを制御。FIFO Subscriber で省略時はイベントグループ ID がレコードキーとなり、同一グループが同一パーティションへ
→Acks: ALL (デフォルト、全 ISR の確認を待機) または LEADER
→Compression: NONE / GZIP / SNAPPY / LZ4 / ZSTD
→Headers: 最大 100 個のレコードヘッダー、ClientId: client.id の設定
🔒 3. パブリック・プライベート両接続のサポート
→Connectivity に PUBLIC または PRIVATE を指定
→PRIVATE では EventBridge が AWS PrivateLink の VPC エンドポイントを自動作成。ネットワークリソースの管理が不要
→同一クラスターをターゲットとする複数 Subscriber は 1 つのエンドポイントを共有
→MSK Serverless クラスターは PRIVATE のみサポート
🔄 4. 接続ライフサイクルの管理
→接続状態は SubscriberDetails.MskDetails.ConnectivityState で確認 (PROVISIONING / ACTIVE / PROVISION_FAILED)
→接続障害時もイベントのマッチングは継続、リトライポリシー超過分はデッドレターキューへ
→PROVISION_FAILED 時はクラスター修復後に UpdateSubscriber で接続を再確立し、保持イベントの配信を再開

🔧 技術仕様

📝 MskParameters の設定項目

項目詳細
TopicName必須。配信先の Kafka トピック。固定値または JSONata 式
Connectivity必須。PUBLIC または PRIVATE。MSK Serverless は PRIVATE のみ
PartitionKeyKafka レコードキー。固定値または JSONata 式
CompressionNONE (デフォルト)、GZIP、SNAPPY、LZ4、ZSTD
AcksALL (デフォルト) または LEADER
Headersレコードヘッダー。最大 100 個
ClientIdプロデューサーの client.id

🏢 前提となるクラスター設定

接続方式必要な設定
PUBLICプロビジョンドクラスターのパブリックアクセスを有効化 (IAM アクセスコントロール必須)
PRIVATE (プロビジョンド)マルチ VPC プライベート接続を IAM で有効化し、EventBridge の接続を許可するクラスターポリシーを追加
PRIVATE (Serverless)EventBridge の接続を許可するクラスターポリシーを追加 (マルチ VPC 設定は不要)

🔐 プライベート接続用クラスターポリシーの例

PRIVATE 接続では、EventBridge がプライベート接続をセットアップできるように以下のようなクラスターポリシーを添付します。aws:SourceAccount と aws:SourceArn 条件でアクセス元を Subscriber に限定します。

JSON MSK クラスターポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowEventBridgePrivateConnectivity",
            "Effect": "Allow",
            "Principal": {
                "Service": "events.amazonaws.com"
            },
            "Action": [
                "kafka:CreateVpcConnection",
                "kafka:GetBootstrapBrokers",
                "kafka:DescribeClusterV2"
            ],
            "Resource": "arn:aws:kafka:us-east-1:111122223333:cluster/MyCluster/abcd1234-0abc-def0-1234-abcd1234abcd-25",
            "Condition": {
                "StringEquals": {
                    "aws:SourceAccount": "111122223333"
                },
                "ArnLike": {
                    "aws:SourceArn": "arn:aws:events:us-east-1:111122223333:subscriber/my-subscriber/*"
                }
            }
        }
    ]
}

🛠️ 設定方法

✅ 前提条件

  • 拡張された Custom イベントバスが作成済みであること
  • MSK クラスター (プロビジョンドまたは Serverless) で IAM アクセスコントロールが有効化されていること
  • 使用する接続方式 (パブリックアクセスまたはプライベート接続) がクラスター側で有効化されていること
  • EventBridge が引き受ける配信ロール (IAM ロール) が準備されていること
1
配信ロールに MSK への書き込み権限を付与

ブートストラップブローカーの取得、クラスターへの接続、対象トピックへの書き込みを許可するポリシーを設定します。ロールの信頼ポリシーで EventBridge からの AssumeRole を許可しておく必要があります。

JSON 配信ロールの IAM ポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "LookupBrokers",
            "Effect": "Allow",
            "Action": "kafka:GetBootstrapBrokers",
            "Resource": "arn:aws:kafka:us-east-1:111122223333:cluster/MyCluster/abcd1234-0abc-def0-1234-abcd1234abcd-25"
        },
        {
            "Sid": "Connect",
            "Effect": "Allow",
            "Action": "kafka-cluster:Connect",
            "Resource": "arn:aws:kafka:us-east-1:111122223333:cluster/MyCluster/abcd1234-0abc-def0-1234-abcd1234abcd-25"
        },
        {
            "Sid": "Produce",
            "Effect": "Allow",
            "Action": [
                "kafka-cluster:DescribeTopic",
                "kafka-cluster:WriteData"
            ],
            "Resource": "arn:aws:kafka:us-east-1:111122223333:topic/MyCluster/abcd1234-0abc-def0-1234-abcd1234abcd-25/my-topic"
        }
    ]
}
2
クラスターポリシーの追加 (PRIVATE 接続の場合)

前述のクラスターポリシー例を参考に、EventBridge がプライベート接続を確立できるようにクラスターポリシーを追加します。aws:SourceArn の条件は、Subscriber の ARN に生成 ID が含まれるため、subscriber/* のように末尾ワイルドカードを使用した ArnLike で指定します。

3
Subscriber の作成

TargetArn にクラスター ARN、MskParameters に配信先トピックと接続方式を指定します。FIFO タイプを指定すると、イベントグループ単位の順序を保って配信されます。

Bash AWS CLI で Subscriber を作成 
aws events create-subscriber \
  --name my-msk-subscriber \
  --event-bus-arn arn:aws:events:us-east-1:111122223333:event-bus/my-custom-bus \
  --invoke-configuration '{
    "RoleArn": "arn:aws:iam::111122223333:role/my-delivery-role",
    "TargetArn": "arn:aws:kafka:us-east-1:111122223333:cluster/MyCluster/abcd1234-0abc-def0-1234-abcd1234abcd-25",
    "MskParameters": {
      "TopicName": "my-topic",
      "Connectivity": "PRIVATE",
      "Acks": "ALL",
      "Compression": "NONE"
    }
  }' \
  --type FIFO \
  --starting-position LATEST
4
接続状態の確認

PRIVATE 接続の場合、作成直後は ConnectivityState が PROVISIONING となり、ACTIVE になるとイベントのマッチングと配信が開始されます。PROVISION_FAILED の場合は StateReason に失敗理由が表示されます。

Bash 接続状態の確認コマンド 
aws events describe-subscriber \
  --subscriber-arn <Subscriber の ARN> \
  --query "SubscriberDetails.MskDetails"

💪 メリット

💼 ビジネス面
✓開発・運用コストの削減: 独自の Kafka プロデューサー実装と運用が不要になり、イベント連携の構築工数を大幅に削減
✓チーム間連携の促進: 共有の Custom イベントバスのイベントを、他チームの Kafka トピックへそのまま届けられる
✓運用の信頼性向上: リトライポリシー、デッドレターキュー、接続状態管理がマネージド機能として提供
⚙️ 技術面
✓ネットワーク管理の自動化: PrivateLink の VPC エンドポイントを EventBridge が自動作成・管理
✓順序保証とパーティション制御: FIFO Subscriber とパーティションキーで関連イベントを同一パーティションへ順序通りに配信
✓柔軟なプロデューサー設定: Acks、圧縮、ヘッダー、client.id を宣言的に構成。JSONata 式による動的なトピック名・キーの指定も可能

⚠️ デメリット・制約事項

🚧 制限事項
✗拡張された Custom イベントバス (Subscriber モデル) 専用で、従来のルールベースのターゲットとしては利用不可
✗MSK クラスター側で IAM アクセスコントロールの有効化が必須 (SASL/SCRAM や mTLS のみのクラスターでは利用不可)
✗MSK Serverless は PRIVATE 接続のみで、MSK Serverless が利用可能なリージョンに限定
✗レコードヘッダーは最大 100 個まで
🤔 考慮すべき点
⚠PrivateLink VPC エンドポイントの料金は、クラスターを所有する AWS アカウントに課金
⚠同一クラスターへのプライベート Subscriber は接続を共有するため、接続障害は全 Subscriber に影響
⚠PRIVATE Subscriber は初回の接続確立 (PROVISIONING) 完了までイベントのマッチング・配信を行わない
⚠リトライポリシー超過イベントは、デッドレターキュー未設定の場合は破棄される

🎯 ユースケース

🤝 1. 部門横断のイベント連携

シナリオ: 注文管理チームが共有の Custom イベントバスに購買イベントを発行し、決済チームは既存の Kafka コンシューマー群で MSK トピックからデータを処理。

  • 決済チームの MSK クラスターに EventBridge 用のクラスターポリシーを追加
  • 購買イベントのフィルターを設定した Subscriber を作成し、決済用トピックを指定
  • PartitionKey に注文 ID の JSONata 式を設定し、同一注文のイベントを同一パーティションへ集約
✨ 効果: 決済チームは既存のコンシューマーを変更することなく購買イベントを受信でき、チーム間のインテグレーションコードが不要になる。
📊 2. イベントのストリーミング分析基盤への取り込み

シナリオ: アプリケーションのビジネスイベントを、Apache Flink や Kafka Streams を利用したリアルタイム分析パイプラインへ取り込みたい。

  • 分析対象イベントのフィルターを設定した Subscriber を作成
  • Compression に ZSTD を指定してネットワーク転送量を削減
  • Transformer (JSONata) で分析に必要な属性のみに変換してから配信
✨ 効果: Lambda などの中間コンポーネントなしでイベントがストリーミング基盤へ届き、レイテンシーと運用対象が削減される。
🔒 3. MSK Serverless へのセキュアなプライベート配信

シナリオ: パブリックアクセスを持たない MSK Serverless クラスターに対し、VPC リソースを管理せずにイベントを配信したい。

  • MSK Serverless クラスターに EventBridge の接続を許可するクラスターポリシーを追加
  • Connectivity に PRIVATE を指定した Subscriber を作成
  • DescribeSubscriber で ConnectivityState が ACTIVE になったことを確認
✨ 効果: EventBridge が PrivateLink 接続を自動構築するため、インターネットを経由しないセキュアな配信を最小限の設定で実現できる。

💰 料金と利用可能リージョン

💵 料金
→MSK ターゲットへの配信は、Custom イベントバスの標準のイベント送信 (egress) として課金
→配信前の圧縮を有効にした場合、圧縮処理はイベント評価 (Event Evaluation) として課金
→プライベート接続の PrivateLink VPC エンドポイント料金は、MSK クラスターを所有する AWS アカウントに課金 (Subscriber 間でエンドポイントは共有)

詳細は Amazon EventBridge 料金ページ を参照

🌍 利用可能リージョン
→拡張された Custom イベントバスが利用可能なすべての AWS リージョンで利用可能
⚠MSK Serverless クラスターへのプライベート配信は、Amazon MSK Serverless が利用可能なリージョンに限定

🔗 関連サービス・機能

→Amazon MSK / MSK Serverless: 配信先となるマネージド Apache Kafka サービス。IAM アクセスコントロールとの組み合わせで利用
→AWS PrivateLink: プライベート接続時に EventBridge が自動的に作成する VPC エンドポイントの基盤技術
→AWS Lambda / Amazon SQS / Amazon SNS / Amazon Kinesis: Custom イベントバスの Subscriber がサポートする他のターゲット。ユースケースに応じて使い分け
→Amazon EventBridge Pipes: 逆方向 (Kafka からのイベント取り込み) を含むポイントツーポイント連携を提供する関連機能

📝 まとめ

EventBridge の Custom イベントバスから Amazon MSK へ、プロデューサーコードやネットワーク管理なしでイベントを直接配信できるようになりました。イベント駆動アーキテクチャと Kafka ストリーミング基盤を併用している場合は、Lambda などの中間実装を本機能に置き換えることで、運用負荷とレイテンシーの削減を検討することを推奨します。導入時は IAM アクセスコントロールの有効化、クラスターポリシー、デッドレターキューの設定を忘れずに行ってください。
