AWS Billing and Cost Management

💰 EC2 Capacity Blocks for ML の
償却コスト (Amortization) サポート

📅 リリース日: 2026 年 11 月 6 日 | 対象: AWS Data Exports (CUR 2.0) / AWS Cost Explorer

📝 概要

CUR 2.0 と Cost Explorer が、EC2 Capacity Blocks for ML の前払い料金を予約期間全体に按分 (償却) して表示できるようになりました。 Capacity Block 内で起動した各インスタンスの償却コストと未使用キャパシティの償却コストを確認でき、 GPU 支出をチーム、プロジェクト、アプリケーション単位で正確に配賦できます。GPU キャパシティを複数チームで共有する組織や FinOps チームにとって重要なアップデートです。

❌ Before (アップデート前の課題)
  • 前払い料金が購入日に単一の請求として計上され、利用実態との対応が把握しにくい
  • 前払い料金をインスタンス利用に紐づけられず、チャージバック / ショーバックが困難
  • 未使用 (アイドル) キャパシティのコストを可視化する手段がない
✅ After (アップデート後の改善)
  • 前払い料金が予約期間にわたって按分され、インスタンス使用状況と並べて確認可能
  • インスタンス単位の償却コストで、GPU 支出をチーム / プロジェクトに正確に配賦
  • 未使用キャパシティのコストを特定し、将来の購入計画を最適化

Capacity Block の前払い料金が予約期間全体に按分され、起動済みインスタンスと未使用キャパシティそれぞれの償却コストとして CUR 2.0 と Cost Explorer に表示される流れ。

⚙️ 主要機能

1️⃣ 前払い料金の予約期間按分 (償却)
  • 前払い料金を各予約の期間にわたって均等に按分して表示
  • 購入日の一括計上から、利用期間に対応したコスト表示へ改善
  • 発生主義ベースのコスト把握が可能になり、月をまたぐ予約でも各月のコストを正確に把握
2️⃣ インスタンス単位の償却コスト表示
  • Capacity Block 内で起動した各インスタンスの償却コストを確認可能
  • 償却コストがインスタンス使用状況と並べて表示され、実際にキャパシティを消費したワークロードに帰属
  • コスト配分タグやコストカテゴリと組み合わせて、チーム / プロジェクト / アプリ単位の GPU 支出配賦が可能
3️⃣ 未使用キャパシティのコスト可視化
  • 予約したが使用されなかったキャパシティの償却コストを特定可能
  • アイドルキャパシティのコストを定量化し、予約サイズや期間の見直しなど将来の購入判断に活用

🛠️ 設定方法

✅ 前提条件

✓EC2 Capacity Blocks for ML を購入済み、または購入予定であること
✓CUR 2.0 で分析する場合は、AWS Data Exports で CUR 2.0 のエクスポートを作成済みであること
✓Cost Explorer を有効化済みであること
1Cost Explorer で償却コストビューを確認
Console Cost Explorer の設定 
1. AWS Billing and Cost Management コンソールで Cost Explorer を開く
2. 右側の設定パネルで「コストの集計方法」を「償却コスト」に変更
3. サービスで「EC2」をフィルターし、必要に応じてタグやアカウントでグループ化

償却コストビューに切り替えることで、前払い料金が購入日の一括計上ではなく、予約期間に按分された形で表示されます。

2CUR 2.0 エクスポートで償却列を含める
Bash CUR 2.0 エクスポートの作成例 (抜粋) 
aws bcm-data-exports create-export \
  --export '{
    "Name": "cur2-capacity-blocks",
    "DataQuery": {
      "QueryStatement": "SELECT line_item_resource_id, line_item_usage_start_date, reservation_amortized_upfront_fee_for_billing_period, reservation_effective_cost, reservation_net_effective_cost FROM COST_AND_USAGE_REPORT",
      "TableConfigurations": {"COST_AND_USAGE_REPORT": {"TIME_GRANULARITY": "DAILY"}}
    },
    "DestinationConfigurations": {"S3Destination": {"S3Bucket": "my-cur-bucket", "S3Prefix": "cur2", "S3Region": "us-east-1", "S3OutputConfigurations": {"OutputType": "CUSTOM", "Format": "PARQUET", "Compression": "PARQUET", "Overwrite": "OVERWRITE_REPORT"}}}
  }'

AWS Data Exports で CUR 2.0 エクスポートを作成し、償却関連の列を選択して S3 に出力します。

3償却コストを分析してチームに配賦
SQL Athena での分析例: リソース別の実効コスト集計 
SELECT
  line_item_resource_id,
  SUM(reservation_effective_cost) AS effective_cost
FROM cur2_table
WHERE line_item_usage_start_date >= DATE '2026-11-01'
GROUP BY line_item_resource_id
ORDER BY effective_cost DESC;

CUR 2.0 データを Athena などで分析し、インスタンス単位の償却コストを集計します。コスト配分タグと組み合わせて、チームやプロジェクト単位の配賦レポートを作成できます。

👍 メリット

💼 ビジネス面

✓正確なコスト配賦: GPU 支出をチーム、プロジェクト、アプリケーション単位に配賦でき、チャージバック / ショーバック運用が可能
✓購入計画の最適化: 未使用キャパシティのコストを定量化でき、次回購入時に予約サイズや期間を適正化
✓財務報告の精度向上: 前払い料金が利用期間に按分され、発生主義ベースの月次コスト報告が容易に

🔧 技術面

✓既存ツールとの統合: CUR 2.0 の標準列として提供されるため、Athena、QuickSight など既存のコスト分析パイプラインにそのまま組み込める
✓他の予約型割引との一貫性: リザーブドインスタンスや Savings Plans と同様の償却列 (reservation_effective_cost など) で扱え、分析クエリを統一できる
✓追加設定が不要: Cost Explorer では償却コストビューを選択するだけで利用でき、追加料金も発生しない

⚠️ デメリット・制約事項

🚫 制限事項

✗AWS GovCloud (US) リージョンと中国リージョンでは利用できない
✗対象は前払い料金の償却表示であり、Capacity Blocks 自体の料金体系 (前払い、キャンセル不可) は変わらない

💡 考慮すべき点

⚠CUR 2.0 を利用していない場合 (レガシー CUR のみの場合) は、CUR 2.0 エクスポートへの移行を検討する必要がある
⚠既存のコスト分析クエリやダッシュボードが非償却 (unblended) コストを前提としている場合、集計ロジックの見直しが必要になる可能性がある

🎯 ユースケース

1. 複数チームで共有する GPU クラスターのチャージバック

シナリオ: ML プラットフォームチームが Capacity Block をまとめて購入し、複数の研究開発チームがインスタンスを起動して利用。各チームの実際の利用量に応じて GPU コストを配賦したい。

SQL チーム別コスト集計 
SELECT
  resource_tags['user_team'] AS team,
  SUM(reservation_effective_cost) AS team_cost
FROM cur2_table
WHERE product_servicecode = 'AmazonEC2'
GROUP BY resource_tags['user_team'];
✅ 効果: インスタンス単位の償却コストとコスト配分タグを組み合わせて、前払い料金を利用実態に即してチームごとに配賦できる。
2. 未使用キャパシティの特定と購入計画の見直し

シナリオ: 14 日間の Capacity Block を購入したが、トレーニングジョブが早く終了し、後半はインスタンスをほとんど起動しなかった。次回購入の参考にアイドルコストを把握したい。

3. 月次財務報告での発生主義ベースのコスト計上

シナリオ: 月末近くに大規模な Capacity Block を購入したため、購入月のコストが突出して見え、経営層への月次レポートで実態と乖離が生じていた。

実装: Cost Explorer で「償却コスト」ビューを選択し、月次粒度で EC2 コストの推移を表示。前払い料金が予約期間の各月に按分されたレポートを作成。

✅ 効果: 購入タイミングによるコストの偏りがなくなり、利用実態に即した月次コストレポートを作成できる。

💵 料金と利用可能リージョン

💰 料金
  • 本機能は追加料金なしで利用可能
  • CUR 2.0 (AWS Data Exports) および Cost Explorer の利用自体も無料 (CUR の出力先 S3 のストレージ料金、Athena などの分析サービスの利用料金は別途発生)
  • EC2 Capacity Blocks for ML 自体は、予約時点の需給に基づく動的な前払い料金制で、購入時に全額が請求される
🌍 利用可能リージョン
  • AWS GovCloud (US) リージョンと中国リージョンを除く、すべての AWS リージョンで利用可能

🔗 関連サービス・機能

→EC2 Capacity Blocks for ML: GPU インスタンスを将来の日付で予約できる仕組み。今回のアップデートの対象となる前払い料金が発生
→AWS Data Exports (CUR 2.0): コストと使用状況の詳細データを S3 にエクスポート。償却関連の列で Capacity Blocks のコストを分析
→AWS Cost Explorer: コストの可視化・分析ツール。償却コストビューで按分コストを確認
→コスト配分タグ / AWS Cost Categories: 償却コストと組み合わせて、チームやプロジェクト単位の配賦が可能

📌 まとめ

EC2 Capacity Blocks for ML の前払い料金が CUR 2.0 と Cost Explorer で予約期間に按分して表示されるようになり、 GPU 支出のチーム別配賦と未使用キャパシティの可視化が可能になりました。 Capacity Blocks を利用している組織は、Cost Explorer の償却コストビューの確認と、CUR 2.0 の償却関連列 (reservation_effective_cost など) を使った分析パイプラインへの組み込みを検討することを推奨します。
