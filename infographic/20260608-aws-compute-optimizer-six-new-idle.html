AWS Compute Optimizer

📊 概要

AWS Compute Optimizer が、新たに 6 つのリソースタイプ に対してアイドルリソースの推奨機能をサポート。AWS 環境全体でより多くの未使用リソースを検出し、潜在的なコスト削減機会を特定できるようになった。

+6
新規対象リソースタイプ
16+
評価メトリクス数
4
更新された API

Before

  • EC2、Auto Scaling、EBS、ECS、RDS、NAT ゲートウェイなど限られたリソースのみ対象
  • DynamoDB、ElastiCache 等のアイドル検出は手動で実施
  • 個別サービスごとにメトリクスを確認する手間

After

  • 6 つの新リソースタイプを自動でアイドル検出
  • サービス固有のシグナルで正確なアイドル判定
  • Cost Optimization Hub で組織横断の一元管理

🔧 主要機能

📋 サービス固有の評価メトリクス
各リソースタイプに最適化されたメトリクスを使用してアイドル判定を実施。消費キャパシティ、キャッシュヒット、アクティブ接続、CPU 使用率など、サービスごとに異なるシグナルを評価し、誤検知を低減。
⏱️ カスタマイズ可能なルックバック期間
ワークロードの特性に応じてルックバック期間を設定可能。季節性のあるワークロードやバッチ処理など、利用パターンに合わせた適切な判定が実現。
💰 Cost Optimization Hub との統合
組織内の全 AWS アカウントのアイドルリソース推奨を横断的に確認。同一リソースに対する他の推奨との重複排除により、正確な推定削減額を提供。
🔌 API による自動化
CLI/SDK を通じてプログラマティックにアイドルリソースを検出・エクスポートでき、既存の運用ワークフローに統合可能。

📏 リソースタイプ別の評価メトリクス

リソースタイプ 主な評価メトリクス
DynamoDB プロビジョンドテーブル ConsumedReadCapacityUnits, ConsumedWriteCapacityUnits, ConsumedChangeDataCaptureUnits
ElastiCache (Redis/Valkey) CacheHits, CacheMisses, GetTypeCmds, SetTypeCmds, CurrConnections, ElastiCacheProcessingUnits
MemoryDB KeyspaceHits, KeyspaceMisses, NewConnections, EngineCPUUtilization
DocumentDB DatabaseConnections, EngineCPUUtilization
WorkSpaces UserConnected, IsIdle
SageMaker エンドポイント Invocations

🔄 更新された API メソッド

4 つの API メソッドが更新され、新しいリソースタイプとメトリクスをサポート。

ExportIdleRecommendations
fieldsToExport に新しいメトリクスフィールドを追加 (CacheHitsSum, ConsumedReadCapacityUnitsSum, DatabaseConnectionsSum, InvocationsSum など 16 種類)
GetIdleRecommendations
resourceType フィルタに DynamoDBTable, ElastiCacheCluster, MemoryDBCluster, DocumentDBCluster, WorkSpaces, SageMakerEndpoint を追加
GetEC2InstanceRecommendations
recommendationSourceType に新しいリソースタイプを追加
GetRecommendationSummaries
recommendationResourceType に新しいリソースタイプを追加

⚙️ 設定方法

前提条件

  • Compute Optimizer のオプトインが完了していること
  • 対象リソースが十分な期間稼働し、メトリクスが蓄積されていること
  • 適切な IAM 権限が付与されていること

必要な IAM ポリシー

JSON IAM ポリシー例 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "compute-optimizer:GetIdleRecommendations",
        "compute-optimizer:ExportIdleRecommendations",
        "compute-optimizer:GetRecommendationSummaries"
      ],
      "Resource": "*"
    }
  ]
}

アイドルリソース推奨のエクスポート

Bash AWS CLI - アイドルリソース推奨を S3 にエクスポート 
# アイドルリソース推奨を S3 にエクスポート
aws compute-optimizer export-idle-recommendations \
  --s3-destination-config bucket=my-bucket,keyPrefix=idle-recommendations/ \
  --filters "name=ResourceType,values=DynamoDBTable,ElastiCacheCluster,MemoryDBCluster,DocumentDBCluster,WorkSpaces,SageMakerEndpoint" \
  --file-format Csv \
  --include-member-accounts

ルックバック期間の確認

Bash AWS CLI - 推奨設定の確認 
# ルックバック期間の推奨設定を確認
aws compute-optimizer get-recommendation-preferences \
  --resource-type DynamoDBTable

🎯 ユースケース

🧹 開発/テスト環境のクリーンアップ
プロジェクト完了後にクリーンアップし忘れた DynamoDB テーブル、ElastiCache クラスター、SageMaker エンドポイントを自動検出。
Bash 開発アカウントのアイドルリソース確認 
aws compute-optimizer get-idle-recommendations \
  --filters "name=ResourceType,values=DynamoDBTable,ElastiCacheCluster,SageMakerEndpoint" \
  --account-ids "123456789012"
効果: 特にコストの高い SageMaker エンドポイントの放置防止に有効
📊 組織全体のコスト最適化レビュー
FinOps チームが四半期ごとのコスト最適化レビューで、全アカウントのアイドルリソースを一括把握。
Bash 組織全体のアイドルリソース推奨をエクスポート 
aws compute-optimizer export-idle-recommendations \
  --s3-destination-config bucket=finops-reports,keyPrefix=quarterly-review/ \
  --include-member-accounts \
  --file-format Csv
効果: Cost Optimization Hub と合わせて組織全体の未使用リソースを可視化し、クラウドコストを最適化
🖥️ WorkSpaces のライセンスコスト管理
退職者や異動者の WorkSpaces が放置され、月額ライセンス費用が発生し続けている状況を検出。
Bash アイドル状態の WorkSpaces を特定 
aws compute-optimizer get-idle-recommendations \
  --filters "name=ResourceType,values=WorkSpaces" \
  --order-by "dimension=SavingsValue,order=Desc"
効果: UserConnected メトリクスに基づき長期間未使用の WorkSpaces を特定し、不要なライセンスコストを削減

✅ メリット・デメリット

ビジネス面のメリット

  • データベース、キャッシュ、仮想デスクトップ、ML エンドポイントなど、より広い範囲で未使用リソースを特定しコスト削減
  • Cost Optimization Hub を通じて組織全体のアイドルリソースを一元管理し、FinOps の取り組みを加速
  • 重複排除された推定削減額により、実際の削減効果をより正確に見積もり

技術面のメリット

  • 各リソースタイプに最適化されたメトリクスによりアイドル判定の誤検知を低減
  • ルックバック期間を調整しワークロードパターンに応じた適切な判定が可能
  • CLI/SDK で既存の運用ワークフローに統合可能

制限事項・考慮点

  • DynamoDB はプロビジョンドテーブルのみ対象 (オンデマンドキャパシティモードは含まれない)
  • 十分なメトリクスが蓄積されるまで推奨は生成されない (新規リソースには非適用)
  • 災害復旧用スタンバイリソースなど意図的に低利用率を維持しているリソースも検出される可能性あり
  • 季節性や定期バッチなどのワークロード特性を考慮し、即座の削除は避けること
  • 推定削減額は概算であり、RI/Savings Plans の適用状況で実際の削減額は変動

💰 料金情報

🆓
追加料金なし - Compute Optimizer のアイドルリソース推奨は無料で利用可能。Enhanced Infrastructure Metrics を有効にする場合のみ追加料金が発生。
機能 月額料金
Compute Optimizer (標準) 無料
Enhanced Infrastructure Metrics リソースあたり月額料金が発生

🌍 利用可能リージョン

Compute Optimizer が利用可能な全リージョンで本機能を使用可能。詳細は AWS リージョン表を参照。

🔗 関連サービス

AWS Cost Optimization Hub
組織全体のコスト最適化推奨を集約・重複排除して表示するサービス
AWS Cost Explorer
コスト分析と予測に使用。Compute Optimizer の推奨と併用してコスト最適化の効果を追跡可能
Amazon CloudWatch
Compute Optimizer がアイドル判定に使用するメトリクスのソース。カスタムアラームとの組み合わせも可能
AWS Trusted Advisor
コスト最適化を含む多角的な推奨を提供。Compute Optimizer とは異なるアプローチで未使用リソースを検出
