🛡️ AWS Resilience Hub

AWS DevOps Agent 連携による
検出結果とテスト結果のレビュー

📅 リリース日: 2026 年 10 月 15 日 | 障害モード評価の検出結果レビューとレジリエンステスト結果の調査を AI エージェントで実現

📌 概要

次世代の AWS Resilience Hub が AWS DevOps Agent と統合され、 障害モード評価 (FMA: Failure Mode Assessment) の検出結果のレビュー、緩和策の実装、 レジリエンステスト結果のレビューを AI エージェントで行えるようになりました。

本アップデートでは 2 つの連携機能が提供されます。

🧪 レジリエンステストの調査 (自動起動)
テストを実行すると DevOps Agent の調査が自動的に起動し、症状・根本原因・影響に加えて、 ARC リージョン切り替えなどの観測された復旧アクションを構造化された分析結果として返します。
💬 検出結果からの対話型エージェント分析 (オンデマンド)
Resilience Hub コンソールの検出結果から、コンテキストが設定済みの状態で DevOps Agent の オンデマンドタスクを直接開始し、質問や調査を通じて緩和計画を作成できます。

対象ユーザーはプラットフォームエンジニアリングチームと SRE チームで、 レジリエンス上の課題の調査と対処を AI エージェントとの対話で効率化できます。

❌ Before: アップデート前の課題
  • 検出された問題の根本原因調査や緩和策の検討をエンジニアが手動で実施
  • テスト結果の症状・根本原因・影響・復旧アクションの把握にはログやメトリクスの個別分析が必要
  • 検出結果と DevOps Agent の調査が分離し、コンテキストを引き継ぐ仕組みがなかった
✅ After: アップデート後の改善
  • テスト実行と同時に調査が自動開始され、判定 (verdict)・確信度・分析サマリーを確認可能
  • すべての検出結果から「Chat with DevOps Agent」でコンテキスト引き継ぎ済みの対話型セッションを開始
  • テストレポートに DevOps Agent の調査セクションが含まれ、共有と報告が容易に

Resilience Hub はサービスレベルで設定済みのインボーカーロールを引き受けて AWS DevOps Agent の Agent Space に接続し、検出結果からの対話型調査とレジリエンステストの自動調査を実行します。

⚡ 主要機能

1️⃣ レジリエンステストの調査 (自動起動)
  • テスト実行と同時に DevOps Agent の調査が自動的に開始
  • テスト完了後まもなく、分析サマリーがテスト実行結果とテストレポートに表示
  • 症状、根本原因、影響、ARC リージョン切り替えなどの観測された復旧アクションを把握
  • 判定 (verdict)、確信度 (confidence)、分析サマリーを含み、リンクからフルセッションを開ける
  • DevOps Agent の判定は参考情報 (advisory) であり、テスト実行自体の結果が正式な判定
2️⃣ 障害モード評価の検出結果からの対話型エージェント分析 (オンデマンド)
  • すべての障害モード評価の検出結果で「Chat with DevOps Agent」を選択可能
  • 検出結果のコンテキストがあらかじめ設定された対話型セッションが開く
  • 質問や調査を通じて検出結果を深掘りし、緩和計画を作成
  • API 使用時は各検出結果が同じセッションへの investigationDeepLink を返す
3️⃣ テストレポートへの調査結果の統合
  • 接続済みサービスのテストレポートに DevOps Agent の調査セクションとサマリーを含む
  • テストレポートの生成は DevOps Agent の調査完了時に完了

🔧 技術仕様

連携の仕組み

項目詳細
接続単位Resilience Hub のサービスごとに DevOps Agent の Agent Space を接続
Agent Space ARN 形式arn:aws:aidevops:{region}:{account-id}:agentspace/{agent-space-id}
認証方式サービスレベルで設定済みの既存インボーカーロール (リソース検出と同じクロスアカウントロール) を Resilience Hub が引き受ける
調査対象リージョンAgent Space は DevOps Agent がサポートするリージョンに作成。作成リージョンに関係なく、任意のリージョンのリソースを調査可能
接続設定サービスの作成時または更新時に devOpsAgentConfiguration へ Agent Space ARN を指定
接続解除空の DevOps Agent 設定 ('{}') でサービスを更新 (Agent Space 自体には影響なし)

API 変更履歴

日付サービス変更内容

インボーカーロールに追加する IAM 権限

以下の最小権限ポリシーをインラインポリシーとして追加します。新しいロールの作成や信頼ポリシーの変更は不要です。

JSON 最小権限 IAM ポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ResilienceHubV2DevOpsAgentInvestigation",
      "Effect": "Allow",
      "Action": [
        "aidevops:CreateBacklogTask",
        "aidevops:GetBacklogTask",
        "aidevops:ListExecutions",
        "aidevops:ListJournalRecords",
        "aidevops:UpdateBacklogTask"
      ],
      "Resource": "arn:aws:aidevops:*:*:agentspace/*"
    },
    {
      "Sid": "ResilienceHubV2DevOpsAgentValidation",
      "Effect": "Allow",
      "Action": [
        "aidevops:GetAgentSpace",
        "aidevops:GetOperatorApp",
        "aidevops:ListAssociations"
      ],
      "Resource": "arn:aws:aidevops:*:*:agentspace/*"
    }
  ]
}
✓Investigation: 調査を構成するバックログタスクの開始・ポーリング・更新・キャンセルと、ジャーナルレコードの読み取りを許可
✓Validation: Agent Space 接続の検証に使用する読み取り専用アクセスを許可
⚠️ 重要
AWS マネージドポリシーの AIDevOpsAgentFullAccess や AIDevOpsOperatorAppAccessPolicy は、 Resilience Hub が呼び出すべきではない Agent Space の変更系アクションを許可するため、アタッチしないでください。 上記のインラインポリシーが連携に必要な唯一の権限付与です。

🛠️ 設定方法

前提条件

✓DevOps Agent の Agent Space が作成済みであること (DevOps Agent コンソールで作成し ARN を控える)
✓リソース検出が設定済みの次世代 Resilience Hub サービスとクロスアカウントインボーカーロールが存在すること
✓Agent Space が DevOps Agent のサポート対象リージョンにあること
1
インボーカーロールに DevOps Agent 権限を追加
Bashインラインポリシーの追加
aws iam put-role-policy \
  --role-name my-invoker-role \
  --policy-name ResilienceHubDevOpsAgentAccess \
  --policy-document file://resiliencehub-devops-agent-policy.json

権限が不足している場合、接続はアクセス拒否エラーで失敗し、サービスの DevOps Agent ステータスが FAILED になります。

2
サービスを Agent Space に接続
BashUpdateService で接続
aws resiliencehubv2 update-service \
  --service-arn <service-arn> \
  --dev-ops-agent-configuration '{"agentSpaceArn": "<agent-space-arn>"}'

サービスの新規作成時に指定することも可能です。コンソールの場合は、サービス設定で DevOps Agent を構成します。

3
接続ステータスを確認
BashGetService でステータス確認
aws resiliencehubv2 get-service \
  --service-arn <service-arn> \
  --query 'service.devOpsAgentConfiguration.status'
4
検出結果またはテストから DevOps Agent を起動

検出結果で「Chat with DevOps Agent」を選択して対話型調査を開始。レジリエンステストでは調査が自動開始されるため、 テスト完了後にテスト実行結果で判定・確信度・分析サマリーを確認します。API の場合はテスト実行結果の devOpsAgentInvestigation ブロックを参照します。

💡 メリット

ビジネス面

✓調査時間の短縮: AI エージェントが分析を実施するため、エンジニアの分析工数を削減し、緩和策の実装に時間を使える
✓レジリエンス改善サイクルの加速: 検出から調査、緩和計画の作成までが一連の流れでつながる
✓レポートの充実: AI による調査サマリーが含まれ、ステークホルダーへの報告品質が向上

技術面

✓コンテキスト引き継ぎ: 状況説明の手間なく調査に着手できる
✓構造化された分析: 症状、根本原因、影響、観測された復旧アクション (ARC リージョン切り替えなど) を構造化して提供
✓最小権限設計: 必要な権限は 8 つの aidevops アクションに限定され、Agent Space やリソースを変更する権限は含まれない

⚠️ デメリット・制約事項

制限事項

✗次世代 (next generation) の Resilience Hub サービスが対象で、リソース検出とインボーカーロールの設定が前提
✗Agent Space を事前に作成する必要があり、DevOps Agent のサポート対象リージョンに作成が必要
✗インボーカーロールに必要な aidevops 権限がない場合、接続は失敗しステータスが FAILED になる

考慮すべき点

⚠DevOps Agent の判定 (verdict) は参考情報であり、テスト実行自体の結果が正式な判定として扱われる
⚠接続済みサービスでは、テストレポートの生成が調査完了まで待機するため、完了タイミングに影響する
⚠AIDevOpsAgentFullAccess などの広範なマネージドポリシーをアタッチしないよう注意が必要

🎯 ユースケース

1. レジリエンステスト結果の自動分析

シナリオ: SRE チームがマルチリージョン構成のワークロードに対してリージョン切り替えの レジリエンステストを実行し、復旧動作が期待どおりであったかを検証したい。

Bash調査結果の確認
# テスト完了後、テスト実行結果から DevOps Agent の調査結果を確認
aws resiliencehubv2 get-service \
  --service-arn <service-arn> \
  --query 'service.devOpsAgentConfiguration'
# コンソールでテスト実行を開き devOpsAgentInvestigation の
# 判定・確信度・分析サマリーを確認
✅ 効果: 症状、根本原因、影響、ARC リージョン切り替えなどの復旧アクションが構造化された分析として自動的に得られ、手動のログ分析が不要になる。
2. 障害モード評価の検出結果に対する緩和計画の作成

シナリオ: プラットフォームエンジニアリングチームが検出された単一障害点について、 原因の深掘りと具体的な緩和策を検討したい。

1.Resilience Hub コンソールで障害モード評価の検出結果を開く
2.[Chat with DevOps Agent] を選択
3.コンテキスト引き継ぎ済みのセッションで「この検出結果の影響範囲は?」「推奨される緩和策は?」と質問
4.対話を通じて緩和計画を作成
✅ 効果: 検出結果の背景情報を手動で収集・説明することなく、対話形式で調査と緩和計画の作成を進められる。
3. 組織的なレジリエンスレポートの品質向上

シナリオ: 定期的なレジリエンステストの結果を経営層や監査向けのレポートとして共有しており、 テスト結果の分析内容もレポートに含めたい。

1.サービスを Agent Space に接続した状態でレジリエンステストを実行
2.テストレポートを生成
3.レポート内の DevOps Agent 調査セクションのサマリーを確認・共有
✅ 効果: AI による調査サマリーが自動的に含まれるため、レポート作成の工数を削減しつつ、分析の深さと一貫性を確保できる。

🔗 関連サービス・機能

🤖 AWS DevOps Agent
本連携の調査を実行する AI エージェント。Agent Space 内でバックログタスクとして調査を実行し、ジャーナルレコードとして分析結果を記録。
🔄 Amazon Application Recovery Controller
レジリエンステスト中のリージョン切り替えなどの復旧アクションとして、DevOps Agent の調査で観測対象となる。
💥 AWS Fault Injection Service
レジリエンステストの基盤となる障害注入の仕組みと関連し、テストシナリオの実行に関係する。
🔐 AWS IAM
インボーカーロールへの最小権限ポリシーの追加により、Resilience Hub が DevOps Agent を安全に呼び出すためのアクセス制御を提供。

📝 まとめ

次世代の AWS Resilience Hub と AWS DevOps Agent の統合により、 レジリエンステスト結果の自動分析と、 障害モード評価の検出結果に対する対話型調査が可能になりました。 レジリエンスの検出から調査、緩和計画の作成までが一連の流れでつながるため、 SRE やプラットフォームエンジニアリングチームの運用効率が大きく向上します。 次世代 Resilience Hub を利用している場合は、インボーカーロールへの最小権限ポリシーの追加と Agent Space の接続から始めることを推奨します。
