Amazon Connect Customer

📧 メッセージテンプレートでのケースフィールド・計算属性サポート

リリース日: 2026 年 11 月 17 日 | 1 つのテンプレートで顧客ごと・ケースごとにパーソナライズ

📌 概要

Amazon Connect Customer のメッセージテンプレートが、Cases のケースフィールドと Customer Profiles の計算属性 (例: 顧客が最も頻繁に利用するコンタクトチャネル) を メッセージ変数としてサポートしました。保険金請求、注文、申請などの更新通知で、各メッセージに顧客自身のレコードを自動反映できます。

テンプレート作成者は管理者定義のカスタムフィールドを含むケースフィールドを挿入でき、送信のたびに受信者ごとの最新値が自動で埋め込まれます。 開発者は RenderMessageTemplate API でレンダリング時に値を渡せます。

❌ アップデート前の課題
✗テンプレート変数はシステム属性、エージェント属性、顧客プロファイルの標準属性などに限定され、ケースの参照番号やステータスを埋め込めなかった
✗過去 1 年間の注文回数のような、顧客プロファイルから導出される計算属性を参照できなかった
✗ケースごとの情報を送るには、顧客ごとにカスタマイズした複数メッセージを個別に作成・管理する必要があった
✅ アップデート後の改善
✓ケースのシステムフィールド (タイトル、ステータス、参照番号など) と管理者定義のカスタムフィールドを変数として挿入可能に
✓Customer Profiles のデフォルト計算属性 (最頻チャネルなど) とカスタム計算属性を参照可能に
✓送信のたびに受信者ごとの最新値が自動で埋め込まれ、テンプレート 1 つで全受信者に正確な情報を配信

テンプレートに挿入したケースフィールド変数と計算属性変数は、メッセージ送信時に Cases および Customer Profiles の最新値で自動的に置き換えられます。

⚙️ 主要機能

📋 ケースフィールドのテンプレート変数サポート
  • Cases のフィールド値をメッセージテンプレート内で参照可能
  • システムフィールドは読みやすいスラグで参照する (例: {{Attributes.Case.title}}、{{Attributes.Case.status}}、{{Attributes.Case.reference_number}})
  • 管理者が定義したカスタムフィールドは UUID 識別子で参照する (例: {{Attributes.Case.12345678-aaaa-bbbb-cccc-123456789012}})
🧮 計算属性のテンプレート変数サポート
  • Customer Profiles で定義された計算属性 (顧客プロファイルデータから導出される値) を参照可能
  • デフォルト計算属性はアンダースコア接頭辞付きの名前で参照する (例: {{Attributes.Customer.CalculatedAttributes._most_frequent_channel}})
  • カスタム計算属性は定義した名前で参照し、名前にスペースを含む場合はブラケット形式を使用する (例: {{Attributes.Customer.CalculatedAttributes.[Average Ticket Size]}})
🔄 送信時の自動値解決
  • テンプレートを使用したメッセージを送信するたびに、受信者ごとの現在の値で変数を置き換え
  • 複数のカスタマイズ版メッセージを作成することなく、常に最新の情報を各受信者に配信
  • コンソールの Attribute finder から属性を選択してテンプレートに挿入可能

🛠️ 設定方法

前提条件

  • Amazon Connect インスタンスでメッセージテンプレート機能を利用できること
  • ケースフィールドを使用する場合は Cases が有効化されており、参照するフィールドが定義されていること
  • 計算属性を使用する場合は Customer Profiles が有効化されており、参照する計算属性が定義されていること

手順

  1. テンプレートの作成または編集
    ナビゲーションペインで [メッセージテンプレート] を選択。新規作成は [テンプレートを作成] でテンプレート名と説明を入力。既存テンプレートへの追加は対象を選択して [編集] し、ベースとするバージョンを選択する。
  2. メッセージ変数の挿入
    メッセージ詳細セクションで変数を追加する位置にカーソルを置く (E メールは件名と本文、SMS は本文に追加可能)。Attribute finder を開き、ケースフィールドまたは計算属性を選択すると、変数が二重中括弧で囲まれた形式で自動挿入される。
  3. 保存とレンダリング確認
    テンプレートを [保存] または [新しいバージョンとして保存] する。開発者は RenderMessageTemplate API でレンダリング結果を確認できる。
Bash テンプレートのレンダリング確認 
# メッセージテンプレートをレンダリングして変数の解決結果を確認する
aws qconnect render-message-template \
  --knowledge-base-id <knowledge-base-id> \
  --message-template-id <message-template-id> \
  --attributes '{"caseAttributes": {"caseId": "<case-id>"}}'

このコマンドは、指定したテンプレートに属性値を渡してレンダリングし、変数が実際の値に置き換えられたメッセージ本文を返します (パラメータの詳細は API リファレンスを参照)。

📈 ビジネス面

⚠️ デメリット・制約事項

🚧 制限事項
⚠利用可能なリージョンは 10 リージョンに限定されている
⚠カスタムケースフィールドは UUID 識別子で参照する必要があり、読みやすいスラグは使用できない
⚠計算属性の名前にスペースを含む場合はブラケット形式での記述が必要
🤔 考慮すべき点
⚠既存テンプレートへの変数追加時、未送信メッセージへの反映はテンプレートのバージョンとメッセージの設定方法に依存する
⚠値が存在しない受信者への送信時の表示を考慮し、テンプレート設計時にデータの充足状況を確認しておく必要がある

1. 保険会社の保険金請求ステータス通知

シナリオ: 保険会社の請求管理者が、各契約者に自身の請求に関する最新状況をメールで通知したい。

効果: 1 つのメールテンプレートで、各契約者がそれぞれ自身の請求の参照番号とステータスを受け取れるようになり、個別メッセージ作成の手間を削減できる。

2. 小売業者のロイヤルティメール

シナリオ: 小売業者が、顧客ごとの年間注文回数を記載したロイヤルティメールを送信したい。

効果: カスタム計算属性を定義するだけで、全顧客にそれぞれ自身の実績値が記載されたメールを届けられ、エンゲージメントを向上できる。

3. チャネル嗜好に合わせたフォローアップ

シナリオ: コンタクトセンターが、顧客が最も頻繁に利用するチャネルを案内文に含めたフォローアップメッセージを送信したい。

Template実装例

{{Attributes.Customer.CalculatedAttributes._most_frequent_channel}} からも承ります。

効果: デフォルト計算属性をそのまま利用でき、顧客の行動データに基づいたパーソナライズを追加開発なしで実現できる。

🔗 関連サービス・機能

📋 Amazon Connect Cases

ケースの参照番号、ステータス、カスタムフィールドなど、テンプレート変数として参照するケースデータを管理する。

👤 Amazon Connect Customer Profiles

計算属性 (デフォルト・カスタム) を定義し、顧客プロファイルデータから導出された値を提供する。

🤖 Amazon Q in Connect

メッセージテンプレートのレンダリングを担う RenderMessageTemplate API を提供する。

📝 まとめ

Amazon Connect Customer のメッセージテンプレートがケースフィールドと計算属性をサポートしたことで、 1 つのテンプレートから顧客ごと・ケースごとに正確でパーソナライズされた通知を送信できるようになりました。 Cases や Customer Profiles をすでに利用している場合は、Attribute finder から新しい変数を既存テンプレートに追加し、 顧客通知のパーソナライズ強化を検討することを推奨します。
