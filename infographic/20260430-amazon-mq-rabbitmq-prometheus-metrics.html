Amazon MQ for RabbitMQ

Prometheus メトリクスサポート

ネイティブ Prometheus 互換メトリクスエンドポイントで監視基盤を統合
2026 年 4 月 30 日

📋 概要

Amazon MQ for RabbitMQ が RabbitMQ 4.2 ブローカー上で Prometheus プラグインをサポートし、ネイティブの Prometheus 互換メトリクスエンドポイントを提供するようになりました。ブローカー、キュー、コネクションのメトリクスを Prometheus 互換の監視ツールから直接スクレイプでき、既存の Prometheus ベース監視スタックへのシームレスな統合が可能です。

Before (アップデート前)

  • メトリクスは CloudWatch 経由でのみ取得可能
  • Prometheus 互換ツールとの直接統合が不可
  • 別途エクスポーターの設定や変換処理が必要
  • キュー単位の細粒度メトリクス取得手段が限定的

After (アップデート後)

  • Prometheus テキスト形式のネイティブエンドポイントから直接スクレイプ可能
  • 既存 Prometheus 監視スタックとシームレスに統合
  • /metrics/detailed で詳細メトリクス利用可能
  • /metrics/memory-breakdown でメモリ内訳を可視化

⚡ 主要機能

📊 ネイティブ Prometheus メトリクスエンドポイント

  • /metrics: ブローカー全体のサマリーメトリクスを Prometheus テキスト形式で公開
  • /metrics/detailed: キュー、コネクション、チャネルなどの詳細メトリクスを提供
  • /metrics/memory-breakdown: メモリ使用量の内訳メトリクスを公開
  • Prometheus 互換の監視ツールから直接スクレイプ可能

☁️ CloudWatch メトリクス連携

  • Prometheus メトリクスの厳選サブセットを CloudWatch に自動発行
  • AWS ネイティブの監視・アラート機能との併用が可能
  • 追加設定不要で CloudWatch メトリクスが利用可能

🔗 既存監視スタックとの統合

  • Grafana ダッシュボードとの連携
  • Amazon Managed Service for Prometheus への統合
  • セルフホスト型 Prometheus サーバーへの統合
  • 既存のアラートルールやダッシュボードをそのまま活用可能

🛠️ 設定方法

前提条件: RabbitMQ 4.2 ブローカーが稼働中、Prometheus 互換の監視ツールがセットアップ済み、ブローカーエンドポイントへのネットワークアクセスが確保されていること。

Step 1: ブローカーエンドポイントの確認

Bash AWS CLI でブローカー情報を取得 
# AWS CLI でブローカー情報を取得
aws mq describe-broker --broker-id <broker-id> --query 'BrokerInstances[].Endpoints'

Step 2: Prometheus スクレイプ設定の追加

YAML prometheus.yml - 基本設定 
# prometheus.yml
scrape_configs:
  - job_name: 'amazon-mq-rabbitmq'
    scheme: https
    basic_auth:
      username: '<rabbitmq-username>'
      password: '<rabbitmq-password>'
    static_configs:
      - targets: ['<broker-endpoint>:443']
    metrics_path: '/metrics'

Step 3: 詳細メトリクスの取得

YAML 詳細メトリクス用の追加設定 
# 詳細メトリクス用の追加設定
scrape_configs:
  - job_name: 'amazon-mq-rabbitmq-detailed'
    scheme: https
    basic_auth:
      username: '<rabbitmq-username>'
      password: '<rabbitmq-password>'
    static_configs:
      - targets: ['<broker-endpoint>:443']
    metrics_path: '/metrics/detailed'

⚠️ 制約事項・注意点

! RabbitMQ 4.2 以上が必要であり、それ以前のバージョンでは利用不可
! メトリクスエンドポイントへのアクセスにはブローカーの認証情報が必要
! CloudWatch に発行されるメトリクスは Prometheus メトリクスの一部サブセットのみ
! 高頻度のスクレイプはブローカーのパフォーマンスに影響を与える可能性がある (スクレイプ間隔の調整を推奨)
! /metrics/detailed エンドポイントは多数のキュー/コネクションがある場合にレスポンスサイズが大きくなる可能性あり

💡 ユースケース

1. 既存 Prometheus 監視基盤への統合

組織で既に Prometheus + Grafana による監視基盤を運用しており、Amazon MQ for RabbitMQ のメトリクスも同じダッシュボードで監視したい場合。

YAML 既存設定への追加例 
scrape_configs:
  - job_name: 'amazon-mq-rabbitmq'
    scheme: https
    basic_auth:
      username: 'monitoring-user'
      password: '${RABBITMQ_PASSWORD}'
    static_configs:
      - targets: ['b-xxxx.mq.us-east-1.amazonaws.com:443']
    metrics_path: '/metrics'
    scrape_interval: 30s
既存の Grafana ダッシュボードにメッセージングメトリクスを追加し、アプリケーション全体の健全性を一画面で確認可能

2. Amazon Managed Service for Prometheus との連携

AWS 環境でスケーラブルなマネージド Prometheus を利用し、長期保存とクロスアカウント監視を実現したい場合。

YAML EKS 上の Prometheus Agent 設定 
remote_write:
  - url: https://aps-workspaces.us-east-1.amazonaws.com/workspaces/ws-xxxx/api/v1/remote_write
    sigv4:
      region: us-east-1
scrape_configs:
  - job_name: 'amazon-mq-rabbitmq'
    scheme: https
    basic_auth:
      username: 'monitoring-user'
      password: '${RABBITMQ_PASSWORD}'
    static_configs:
      - targets: ['b-xxxx.mq.us-east-1.amazonaws.com:443']
    metrics_path: '/metrics'
メトリクスの長期保存、クロスアカウント集約、Amazon Managed Grafana での統合ダッシュボード構築が可能

3. キュー単位の詳細監視とアラート

特定のキューのメッセージ滞留やコンシューマーの健全性を細かく監視し、異常時に即座にアラートを発報したい場合。

YAML Prometheus アラートルール 
groups:
  - name: rabbitmq-alerts
    rules:
      - alert: RabbitMQQueueMessagesHigh
        expr: rabbitmq_queue_messages > 10000
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "キュー {{ $labels.queue }} のメッセージ数が閾値超過"
      - alert: RabbitMQConsumerDown
        expr: rabbitmq_queue_consumers == 0
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "キュー {{ $labels.queue }} のコンシューマーが 0"
キュー単位の異常を早期検知し、メッセージ処理の遅延やサービス停止を未然に防止
