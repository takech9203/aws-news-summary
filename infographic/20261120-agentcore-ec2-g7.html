Amazon Bedrock AgentCore

🤖 ランタイムインスタンスが EC2 G7 インスタンスをサポート

📅 リリース日: 2026 年 11 月 20 日 | 🎮 NVIDIA RTX PRO 4500 Blackwell Server Edition GPU

📋 概要

Amazon Bedrock AgentCore のランタイムインスタンスが、NVIDIA RTX PRO 4500 Blackwell Server Edition GPU を搭載した Amazon EC2 G7 インスタンスをサポートしました。 ランタイムインスタンスは、AI エージェントを EC2 上で実行しながら、プロビジョニング、パッチ適用、スケーリング、ライフサイクル管理を AgentCore に任せられる機能です。

既存の G6e や G7e に加えて G7 が選択肢に加わり、3D レンダリングやモデル推論を実行するエージェントが最新世代の Blackwell アーキテクチャ GPU を専有して利用できます。 キャパシティプロバイダーの許可インスタンスタイプに g7.2xlarge ～ g7.48xlarge を追加するだけで利用を開始できます。

❌ アップデート前の課題

✗利用できる GPU ファミリーは G6e や G7e などに限られ、Blackwell 世代の RTX PRO GPU を搭載した G7 は選択できなかった
✗GPU を自前運用する場合、NVIDIA ドライバーのインストールや更新をコンテナイメージや AMI で管理する必要があった
✗長時間の GPU 処理のために、インスタンスのライフサイクル管理を独自に構築する必要があった

✅ アップデート後の改善

✓許可インスタンスタイプに G7 を追加するだけで、Blackwell 世代 GPU 上でエージェントを実行可能に
✓NVIDIA ドライバーは AgentCore が管理し、標準のコンテナイメージにドライバーを同梱せずに GPU ワークロードを実行可能に
✓最長 14 日間のセッションで、3D レンダリングやビジョンモデル推論など長時間の GPU 処理を専用 GPU 上で継続可能に

AgentCore がキャパシティプロバイダーの設定に基づいて EC2 G7 インスタンスをプロビジョニングし、NVIDIA ドライバーの管理を含む運用を代行する構成

⚡ 主要機能

🖥️ EC2 G7 インスタンスのサポート

→NVIDIA RTX PRO 4500 Blackwell Server Edition GPU を搭載した G7 インスタンスをランタイムインスタンスとして利用可能
→g7.2xlarge から g7.48xlarge までのインスタンスサイズに対応
→既存の G6e や G7e などの GPU ファミリーに加わる新たな選択肢

🔧 マネージドな GPU 環境

→NVIDIA ドライバーのインストールを AgentCore が管理
→標準のコンテナイメージにドライバーを同梱することなく GPU ワークロードを実行可能
→プロビジョニング、パッチ適用、スケーリング、ライフサイクル管理も AgentCore が代行

⏱️ 長時間セッションのサポート

→最長 14 日間のセッションをサポート
→3D シーンのレンダリングやビジョンモデルの実行など、長時間の GPU 処理を専用 GPU 上で継続可能

🛠️ 設定方法

📌 前提条件

  • Amazon Bedrock AgentCore Runtime が利用可能なリージョンであること
  • ランタイムインスタンス用のキャパシティプロバイダーが作成済み、または作成可能であること
  • 対象リージョンで EC2 G7 インスタンスが利用可能であること
1

キャパシティプロバイダーに G7 インスタンスタイプを追加

Bash AWS CLI 
aws bedrock-agentcore-control update-capacity-provider \
  --capacity-provider-id <capacity-provider-id> \
  --instance-configuration '{"allowedInstanceTypes": ["g7.2xlarge", "g7.4xlarge"]}'

許可インスタンスタイプに G7 を追加します。ワークロードの要件に応じて g7.2xlarge から g7.48xlarge までのサイズを指定できます。

2

エージェントをデプロイして GPU を利用

Bash AWS CLI 
aws bedrock-agentcore-control create-agent-runtime \
  --agent-runtime-name my-gpu-agent \
  --agent-runtime-artifact '{"containerConfiguration": {"containerUri": "<ECR イメージ URI>"}}' \
  --role-arn <IAM ロール ARN>

標準のコンテナイメージをそのままデプロイします。NVIDIA ドライバーは AgentCore が管理するため、イメージにドライバーを同梱する必要はありません。

3

セッションを実行して動作を確認

エージェントのセッションを開始し、GPU を利用する処理 (3D レンダリングやモデル推論など) が正常に動作することを確認します。セッションは最長 14 日間継続できます。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓最新 GPU への迅速なアクセス: Blackwell 世代の RTX PRO GPU をインフラ構築なしで利用可能
✓運用コストの削減: プロビジョニング、パッチ適用、スケーリングを AgentCore に任せて運用負荷を軽減
✓従量課金: 管理料金と EC2 料金の組み合わせで、必要な分だけ支払う

🔧 技術面のメリット

✓ドライバー管理の不要化: 標準のコンテナイメージをそのまま利用可能
✓幅広いサイズ選択: g7.2xlarge ～ g7.48xlarge から規模に応じて選択
✓長時間処理への対応: 最長 14 日間のセッションで中断なく実行

⚠️ 制限事項

⚠利用可能なリージョンは 8 リージョンに限定される
⚠セッションの最長時間は 14 日間
⚠G7 インスタンスの在庫状況はリージョンやアベイラビリティーゾーンによって異なる可能性がある

💡 考慮すべき点

⚠AgentCore の管理料金に加えて EC2 の料金が発生するため、GPU インスタンスの稼働コストを事前に見積もる必要がある
⚠最新の Blackwell GPU が必要かどうかを評価し、既存の G6e や G7e との費用対効果を比較することが望ましい

🎯 ユースケース

🎨 ユースケース 1: 3D シーンレンダリングエージェント

シナリオ: 設計データから 3D シーンを生成しレンダリングするエージェントを、長時間にわたり安定して実行したい。

実装例: キャパシティプロバイダーに g7.8xlarge を追加し、レンダリングエージェントのコンテナをデプロイ。セッションを継続してレンダリングジョブを順次処理。

効果: Blackwell GPU によるレンダリング性能を活用しつつ、インスタンス運用を AgentCore に任せられる。

👁️ ユースケース 2: ビジョンモデルによる画像・映像解析

シナリオ: エージェントがビジョンモデルを専用 GPU 上でホストし、大量の画像や映像を解析する。

実装例: g7.4xlarge を許可インスタンスタイプに設定し、ビジョンモデルを含むコンテナイメージをデプロイ。最長 14 日間のセッションで解析パイプラインを実行。

効果: モデルのロード済み状態を維持したまま長時間の解析を継続でき、推論レイテンシーを安定させられる。

🔄 ユースケース 3: GPU 推論を伴うエージェントワークフロー

シナリオ: 自律型エージェントがローカル推論と外部 API 呼び出しを組み合わせた長時間ワークフローを実行する。

実装例: 標準のコンテナイメージ (ドライバー同梱不要) を用意し、AgentCore Runtime にデプロイ。推論処理は G7 の GPU、オーケストレーションはエージェントが担当。

効果: ドライバー管理なしで GPU 推論を組み込め、エージェント開発に集中できる。

💰 料金

プロビジョニングされたコンピュートの管理に対する AgentCore の料金に加えて、Amazon EC2 の料金が発生します。 詳細は AgentCore の料金ページを参照してください。
