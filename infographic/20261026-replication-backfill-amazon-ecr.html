Amazon ECR

📦 既存コンテナイメージのレプリケーションバックフィルサポート

リリース日: 2026 年 10 月 26 日 | 機能: レプリケーションバックフィル (Replication Backfill)

📝 概要

Amazon ECR が、プライベートレジストリ内の既存コンテナイメージを設定済みのレプリケーション先へ複製する「レプリケーションバックフィル」をサポート。従来は設定適用後にプッシュされたイメージのみが対象でしたが、単一の API コールで設定前にプッシュされた既存イメージも複製できるようになりました。

各バックフィルは一意の replicationBackfillId で識別され、新しい API を通じて進捗の監視、イメージごとの結果確認、任意のタイミングでの停止が可能です。停止しても、すでに複製されたイメージは宛先レジストリから削除されません。

❌ Before: アップデート前の課題

  • レプリケーション設定の有効化前にプッシュされた既存イメージは自動複製の対象外
  • 既存イメージを複製するには、イメージを手動で再タグ付けしてレプリケーションをトリガーする必要があった
  • 大量の既存イメージを持つレジストリでは、新リージョン展開や DR 構成時のカタログ同期に多大な手作業が必要

✅ After: アップデート後の改善

  • 単一の API コール (StartReplicationBackfill) で既存イメージカタログ全体を新規または既存のレプリケーション先へ複製
  • 最大 10 個のバックフィルを同時実行でき、複数の宛先への複製を並行して進められる
  • 新しい API で進捗とイメージごとの複製結果を監視でき、必要に応じて安全に停止可能

管理者がバックフィルを開始すると、ECR は現在のレプリケーション設定を評価して対象イメージを特定し、指定された 1 つの宛先へ既存イメージを複製します。複数の宛先へ複製する場合は、宛先ごとにバックフィルを開始します。

⚡ 主要機能

🔁 既存イメージの一括レプリケーション
  • StartReplicationBackfill API の単一コールで、既存イメージカタログをレプリケーション先へ複製
  • 現在のレプリケーション設定を評価し、指定した宛先に対するルールに一致するイメージのみを対象として特定
  • 各バックフィルは単一の宛先 (リージョン + レジストリ ID) を対象。複数の宛先へは宛先ごとに個別のバックフィルを開始
🧵 同時実行とジョブ管理
  • レジストリあたり最大 10 個を同時実行可能 (超過時は LimitExceededException)
  • 同一宛先リージョンに対するアクティブなバックフィルは 1 つのみ (重複時は ReplicationBackfillInProgressException)
  • PREPARING / IN_PROGRESS 状態は StopReplicationBackfill で停止可能
  • 停止しても複製済みイメージはロールバックされず、宛先レジストリに残る
📊 進捗監視とイメージごとの結果確認
  • DescribeReplicationBackfillResults で進捗カウント (総数・完了数・失敗数) とイメージごとの結果を確認
  • 実行中は進捗カウントのみ。イメージごとの結果とページネーションは完了後に利用可能
  • ListReplicationBackfills でレジストリ内のすべてのバックフィルのサマリーを一覧表示
  • 終端状態のバックフィルは完了後 90 日間保持。終端状態に達すると Amazon EventBridge イベントを送信
🖥️ コンソールからの操作
  • ECR コンソールのプライベートレジストリ設定にある「Backfill jobs」タブから、最大 10 個の宛先を選択してバックフィルを開始可能
  • 同じタブから進捗の監視、結果の確認、ジョブの停止が可能

ステータス説明
PREPARINGECR がレジストリ内の対象イメージを特定中
IN_PROGRESS宛先へのイメージ複製を実行中
COMPLETE対象イメージすべての複製が正常に完了
FAILED複製の 50% 以上が失敗すると自動的に失敗 (100 件以上処理された時点で評価)
STOPPING停止がリクエストされ、実行中の複製の完了を待機中
STOPPED停止が完了し、実行中の複製がすべて終了

API用途

🛠️ 設定方法

前提条件

✓ECR プライベートレジストリでレプリケーション設定が構成済みであること
✓バックフィル先の宛先 (リージョン + レジストリ ID) がレプリケーション設定のルールに含まれていること (含まれていない場合は先にルールへ宛先を追加)
✓レプリケーション用のサービスリンクロールが存在すること (レプリケーション初回設定時に自動作成)

ステップ 1: バックフィルを開始する

BashStartReplicationBackfill
aws ecr start-replication-backfill \
    --region us-west-2 \
    --registry-id 111122223333 \
    --destination region=ap-northeast-1,registryId=111122223333

レスポンスに含まれる replicationBackfillId を以降の監視・停止操作で使用します。クロスアカウントレプリケーションの場合は registryId に宛先アカウント ID を指定します。

ステップ 2: 進捗と結果を監視する

Bash監視 API
# すべてのバックフィルのサマリーを一覧表示
aws ecr list-replication-backfills \
    --region us-west-2 \
    --registry-id 111122223333 \
    --max-results 50

# 特定のバックフィルの進捗とイメージごとの結果を確認
aws ecr describe-replication-backfill-results \
    --region us-west-2 \
    --registry-id 111122223333 \
    --replication-backfill-id a1b2c3d4-5678-90ab-cdef-EXAMPLE11111 \
    --max-results 1000 \
    --result-status-filter FAILED

--result-status-filter で COMPLETE または FAILED のイメージに絞って結果を取得できます。実行中は進捗カウントのみが返され、イメージごとの結果は完了後に確認できます。

ステップ 3: 必要に応じてバックフィルを停止する

BashStopReplicationBackfill
aws ecr stop-replication-backfill \
    --region us-west-2 \
    --registry-id 111122223333 \
    --replication-backfill-id a1b2c3d4-5678-90ab-cdef-EXAMPLE11111

停止時点で実行中の複製は完了を待ってから STOPPED に遷移し、すでに複製されたイメージは宛先レジストリに保持されます。

💡 メリット

ビジネス面

✓新リージョン展開の高速化: 既存イメージカタログ全体を単一の API コールで同期でき、展開リードタイムを短縮
✓DR 準備とコンプライアンス対応: DR リージョンのカタログがソースと一致していることを確実にし、リージョン間のカタログ整合性要件に対応しやすくなる
✓運用コストの削減: 既存イメージの手動再タグ付けという反復作業が不要になり、人為的ミスのリスクも排除

技術面

✓レプリケーション設定との一貫性: 通常のレプリケーションと同じフィルタ条件で既存イメージを複製
✓可観測性: 進捗カウント、イメージごとの結果、失敗コード、EventBridge イベントで大規模バックフィルも正確に把握
✓安全な停止: 任意のタイミングで停止でき、複製済みイメージはロールバックされないため、段階的な実行や中断・再開の判断がしやすい

⚠️ デメリット・制約事項

制限事項

✗対象は現在のレプリケーション設定のルールに一致するイメージのみ。設定にない宛先へは、先にレプリケーションルールへ宛先を追加する必要がある
✗レジストリあたりの同時実行は最大 10 個まで (超過時は LimitExceededException)
✗同一宛先リージョンに対するアクティブなバックフィルは 1 つのみ (ReplicationBackfillInProgressException)
✗複製の 50% 以上が失敗すると自動的に FAILED となる (100 件以上処理された時点で評価)
✗ソースリポジトリが削除されたイメージはスキップされ、結果に FAILED として記録

考慮すべき点

⚠大量のデータを含むレジストリでは、完了までに数時間から数日かかる場合がある
⚠停止しても複製済みイメージは宛先に残るため、不要なイメージは宛先側で個別に削除する必要がある
⚠ジョブ履歴は終端状態から 90 日間のみ保持。長期の監査記録が必要な場合は EventBridge イベントや結果のエクスポートを検討
⚠クロスリージョン複製にはデータ転送と宛先リージョンでのストレージが伴うため、大規模なバックフィル実行前にコストを見積もることが望ましい

🎯 ユースケース

1️⃣ 新リージョン展開時のイメージカタログ同期

シナリオ: 東京リージョンで稼働中のサービスを大阪リージョンにも展開することになり、ECR の既存イメージをすべて大阪リージョンでも利用できるようにしたい。

Bash実装例
# 1. レプリケーションルールに大阪リージョンを追加 (未追加の場合)
aws ecr put-replication-configuration \
    --region ap-northeast-1 \
    --replication-configuration \
    'rules=[{destinations=[{region=ap-northeast-3,registryId=111122223333}]}]'

# 2. 既存イメージのバックフィルを開始
aws ecr start-replication-backfill \
    --region ap-northeast-1 \
    --registry-id 111122223333 \
    --destination region=ap-northeast-3,registryId=111122223333
💡 効果: 新規プッシュは自動複製、既存イメージはバックフィルで一括複製されるため、再タグ付けスクリプトを作成・実行することなく大阪リージョンのカタログを完全な状態にできる。
2️⃣ DR 準備の検証とカタログ整合性の確保

シナリオ: DR リージョンへのレプリケーションを以前から構成しているが、構成前にプッシュされた古いイメージが複製されておらず、フェイルオーバー時に一部のサービスがイメージを取得できないリスクがある。

Bash実装例
# バックフィルを実行して欠落イメージを補完
aws ecr start-replication-backfill \
    --region us-east-1 \
    --registry-id 111122223333 \
    --destination region=us-west-2,registryId=111122223333

# 完了後、失敗したイメージがないか確認
aws ecr describe-replication-backfill-results \
    --region us-east-1 \
    --registry-id 111122223333 \
    --replication-backfill-id <backfill-id> \
    --result-status-filter FAILED
💡 効果: DR リージョンのカタログがソースと整合していることをイメージ単位の結果で検証でき、フェイルオーバー演習前の準備としてカタログの欠落を確実に解消できる。
3️⃣ レプリケーションルール更新後の対象イメージ補完

シナリオ: レプリケーションルールのリポジトリフィルタを拡大し、これまで対象外だったリポジトリ群も複製対象に加えた。ルール更新後の新規プッシュは複製されるが、それらのリポジトリの既存イメージは宛先に存在しない。

Bash実装例
# ルール更新後、対象宛先へのバックフィルを開始
aws ecr start-replication-backfill \
    --region eu-west-1 \
    --registry-id 111122223333 \
    --destination region=eu-central-1,registryId=111122223333

# EventBridge ルールで完了イベントを検知して通知
# detail-type: ECR Replication Backfill の終端状態イベントを利用
💡 効果: 更新後のレプリケーション設定に基づいて対象イメージが自動的に特定されるため、フィルタ拡大で新たに対象となったリポジトリの既存イメージのみが過不足なく複製される。

💰 料金

公式発表にバックフィル固有の追加料金の記載はありません。レプリケーションによって複製されたイメージは宛先リージョンでストレージ料金の対象となり、クロスリージョンレプリケーションではデータ転送料金が適用されます。大規模なレジストリをバックフィルする場合は、事前に Amazon ECR の料金ページでストレージとデータ転送のコストを確認することを推奨します。

🌏 利用可能リージョン

Amazon ECR が利用可能なすべての AWS リージョンで利用できます。

🔗 関連サービス・機能

🔁 ECR クロスリージョン / クロスアカウントレプリケーション

バックフィルの前提となる機能。バックフィル対象はこのレプリケーション設定のルールに基づいて決定される。

📡 Amazon EventBridge

バックフィルが終端状態に達した際のイベント通知を受け取り、後続の検証や通知を自動化できる。

📥 ECR プルスルーキャッシュ

外部レジストリのイメージをオンデマンドでキャッシュする機能。リージョン間のイメージ配置戦略においてレプリケーションと使い分けが可能。

🔑 IAM サービスリンクロール

バックフィルはレプリケーション初回設定時に作成されるサービスリンクロールを使用するため、追加のロール作成は不要。

📌 まとめ

Amazon ECR のレプリケーションバックフィルにより、これまで手動の再タグ付けでしか複製できなかった既存イメージを、単一の API コールでレプリケーション先へ一括複製できるようになりました。新リージョン展開や DR 構成を予定している場合、またはレプリケーション構成前の古いイメージが宛先に欠落している可能性がある場合は、ListReplicationBackfills や DescribeReplicationBackfillResults による監視と組み合わせてバックフィルの実行を検討することを推奨します。大規模なレジストリでは実行時間とデータ転送コストを事前に見積もったうえで、計画的に実施してください。
