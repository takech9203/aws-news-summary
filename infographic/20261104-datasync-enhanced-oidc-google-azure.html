AWS DataSync

🔄 DataSync Enhanced モードが Google Cloud と Microsoft Azure 向けに OIDC をサポート

IAM ロールによる短期クレデンシャルでクロスクラウド転送を実現 — HMAC キーや SAS トークンはもう不要
📅 リリース日: 2026 年 11 月 4 日

📋 概要

AWS DataSync の Enhanced モードが、Google Cloud Storage および Microsoft Azure Blob Storage ロケーションへの接続時に OpenID Connect (OIDC) 認証をサポートしました。 DataSync は AWS IAM ロールを使用して Google Cloud または Microsoft Entra ID から短期クレデンシャルを取得し、 転送中はクレデンシャルが自動的に更新されるため、転送が中断することなく継続されます。

長期クレデンシャルの利用を禁止するセキュリティポリシーを持つ組織でも、ポリシーに準拠したままクロスクラウドのデータ移動が可能になります。 利用を開始するには、AWS CLI、API、または AWS CloudFormation で DataSync ロケーションに IAM ロールをアタッチします。

❌ Before: 長期クレデンシャルが必要
  • Google Cloud Storage には HMAC キー、Azure Blob Storage には SAS トークンの発行・設定が必要だった
  • SAS トークンが転送中に期限切れになるとアクセス不能になり、ロケーション更新とタスク再実行が必要だった
  • 長期クレデンシャルを禁止する組織では、ポリシー準拠のクロスクラウド転送が困難だった
✅ After: IAM ロールベースの OIDC 認証
  • IAM ロールで Google Cloud / Microsoft Entra ID から短期クレデンシャルを取得。HMAC キー・SAS トークンの管理が不要に
  • クレデンシャルは自動更新され、転送中の期限切れによる中断を心配する必要なし
  • 長期クレデンシャル禁止ポリシーに準拠したままクロスクラウドのデータ移動を実現

🏗️ アーキテクチャ図

sequenceDiagram
    participant DS as 🔄 AWS DataSync Enhanced モード
    participant IAM as 🔐 AWS IAM ロール
    participant IdP as 🪪 Google Cloud または Microsoft Entra ID
    participant Ext as 🗄️ Google Cloud Storage または Azure Blob Storage
    participant S3 as 🪣 AWS ストレージ

    DS->>IAM: ロケーションにアタッチされた IAM ロールを使用
    IAM-->>DS: OIDC フェデレーション用の ID を提供
    DS->>IdP: OIDC 認証を実行
    IdP-->>DS: 短期クレデンシャルを発行
    DS->>Ext: 短期クレデンシャルでストレージにアクセス
    Ext-->>DS: オブジェクトデータを転送
    DS->>S3: データを書き込み
    Note over DS,IdP: クレデンシャルは自動更新され転送は中断しない

DataSync Enhanced モードが IAM ロールを起点に OIDC 認証で短期クレデンシャルを取得し、他社クラウドストレージへアクセスする流れです。長期クレデンシャルは一切登場しません。

⚡ 主要機能

🔑 OIDC 認証によるクロスクラウド接続
  • Google Cloud Storage および Microsoft Azure Blob Storage ロケーションへの接続時に OIDC 認証を選択可能
  • DataSync が IAM ロールを使用して Google Cloud または Microsoft Entra ID から短期クレデンシャルを取得
  • HMAC キーや SAS トークンといった長期クレデンシャルの発行・保管・ローテーションが不要
🔄 クレデンシャルの自動更新
  • 転送中に短期クレデンシャルが自動的に更新される
  • 大規模データセットの長時間転送でも、有効期限切れによる転送中断が発生しない
🛠️ IAM ロールによるシンプルなセットアップ
  • AWS CLI、API、AWS CloudFormation で DataSync ロケーションに IAM ロールをアタッチするだけで利用開始
  • アクセス制御を AWS 側の IAM と外部クラウド側の ID 基盤のフェデレーション設定で一元的に管理

1
IAM ロールの準備

DataSync が短期クレデンシャルの取得に使用する IAM ロールを作成します。Google Cloud または Microsoft Entra ID 側では、この IAM ロールを信頼するフェデレーション設定 (Google Cloud の Workload Identity 連携、Microsoft Entra ID のワークロード ID フェデレーションなど) を構成します。

2
DataSync ロケーションへの IAM ロールのアタッチ
Bash Azure Blob Storage ロケーションの更新例 
# AWS CLI、API、または AWS CloudFormation を使用して
# DataSync ロケーションに IAM ロールをアタッチする
aws datasync update-location-azure-blob \
  --location-arn "arn:aws:datasync:us-east-1:123456789012:location/loc-xxxxxxxxxxxxxxxxx" \
  --cli-input-json file://oidc-config.json

具体的なパラメータは AWS DataSync User Guide の最新の手順を確認してください。

3
Enhanced モードタスクの作成と実行
Bash Enhanced モードでタスクを作成 
aws datasync create-task \
  --source-location-arn "arn:aws:datasync:us-east-1:123456789012:location/loc-source" \
  --destination-location-arn "arn:aws:datasync:us-east-1:123456789012:location/loc-dest" \
  --task-mode "ENHANCED"

OIDC 認証を設定したロケーションをソースまたはデスティネーションとして指定し、タスクモードに ENHANCED を指定します。

💡 メリット

💼 ビジネス面

✓セキュリティポリシーへの準拠: 長期クレデンシャル禁止ポリシーの組織でも、準拠したままクロスクラウド転送が可能
✓運用負荷の削減: HMAC キーや SAS トークンの発行・保管・ローテーション・失効管理が不要に
✓マルチクラウド戦略の推進: 他社クラウドから AWS への移行やデータ統合をより安全に実現

🔧 技術面

✓短期クレデンシャルによるリスク低減: 短期間で失効するため、漏えい時の影響範囲を最小化
✓自動更新による転送の安定性: 長時間転送でも有効期限切れによる失敗が発生しない
✓IAM による一元的なアクセス管理: アクセス制御を IAM ロールに集約し、監査・ガバナンスが容易に

⚠️ デメリット・制約事項

制限事項

✗OIDC 認証は Enhanced モードのみサポート (Basic モードのタスクでは従来どおり長期クレデンシャルが必要)
✗対象は Google Cloud Storage と Microsoft Azure Blob Storage のロケーションに限られる
✗設定は AWS CLI、API、AWS CloudFormation で行う (発表時点でコンソールからの設定は案内されていない)

考慮すべき点

⚠Google Cloud または Microsoft Entra ID 側で、AWS からの OIDC フェデレーションを受け入れる設定が別途必要
⚠既存の HMAC キーや SAS トークンを使用したロケーションから移行する場合は、ロケーション設定の更新とタスクの動作確認を計画的に実施
⚠タスクモードは作成後に変更できないため、既存の Basic モードタスクで OIDC を利用するには Enhanced モードでタスクを作り直す必要がある

🎯 ユースケース

1️⃣ Azure Blob Storage から Amazon S3 への大規模移行

シナリオ: 長期クレデンシャルの発行が社内セキュリティポリシーで禁止されている企業が、Azure Blob Storage 上の大量のオブジェクトを Amazon S3 へ移行したい。

実装: Microsoft Entra ID 側でワークロード ID フェデレーションを構成 → Azure Blob Storage ロケーションに IAM ロールをアタッチ → Enhanced モードタスクで S3 へ転送 (エージェント不要・実質無制限のオブジェクト数)

✅ 効果: SAS トークンを一切発行せずにポリシー準拠の移行を実現。クレデンシャルの自動更新により、長時間の大規模転送も中断なく完了。

2️⃣ Google Cloud Storage のデータを AWS の分析基盤へ定期転送

シナリオ: Google Cloud 上のアプリケーションが生成するデータを、Amazon S3 ベースのデータレイクへ定期的に取り込み、Amazon Athena や Amazon Redshift で分析したい。

実装: Google Cloud の Workload Identity 連携で AWS の IAM ロールを信頼するよう構成 → Google Cloud Storage ロケーションに IAM ロールをアタッチ → Enhanced モードタスクをスケジュール実行して S3 へ継続的に転送

✅ 効果: HMAC キーのローテーション運用が不要になり、定期転送パイプラインの運用負荷とセキュリティリスクを同時に低減。

3️⃣ クレデンシャル期限切れによる転送失敗の解消

シナリオ: 従来 SAS トークンで Azure Blob Storage から転送していたが、トークンの有効期限切れにより長時間タスクが失敗することがあり、再設定と再実行の運用負荷が課題だった。

実装: 既存の Azure Blob Storage ロケーションの認証を SAS トークンから OIDC へ変更 → IAM ロールをロケーションにアタッチし、Enhanced モードタスクで転送

✅ 効果: クレデンシャルが自動更新されるため、有効期限切れによるタスク失敗と手動復旧作業が不要に。

💰 料金・利用可能リージョン

💵 料金

OIDC 認証の利用自体に関する追加料金は発表されていません。DataSync の料金は転送したデータ量に基づく従量課金で、Enhanced モードと Basic モードで料金体系が異なります。 また、Google Cloud や Azure 側のデータ転送 (エグレス) 料金やリクエスト料金が別途発生する点に注意が必要です。 詳細は AWS DataSync 料金ページ を参照してください。

🌍 利用可能リージョン

DataSync Enhanced モードが利用可能なすべての AWS リージョンで利用できます。

🔗 関連サービス・機能

→Amazon S3: クロスクラウド転送の主要な転送先。Azure Blob と S3 間の Enhanced モード転送はエージェント不要で実行できる
→AWS IAM: OIDC 認証の起点となる IAM ロールを管理し、短期クレデンシャル取得のアクセス制御を担う
→AWS CloudFormation: DataSync ロケーションへの IAM ロールのアタッチを含む構成を IaC として管理できる
→AWS Secrets Manager: 従来の SAS トークンなどのクレデンシャルを安全に保管する選択肢 (OIDC 利用時はクレデンシャル保管自体が不要になる)

📝 まとめ

AWS DataSync Enhanced モードの OIDC サポートにより、HMAC キーや SAS トークンといった長期クレデンシャルを使わずに、 Google Cloud Storage や Azure Blob Storage とのクロスクラウド転送を実現できるようになりました。 長期クレデンシャルを禁止するセキュリティポリシーを持つ組織や、クレデンシャルの期限切れによる転送失敗に悩まされていたお客様は、 IAM ロールをロケーションにアタッチして OIDC 認証への移行を検討することをおすすめします。
