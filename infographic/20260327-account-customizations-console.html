サービスとリージョンの表示制御設定

AWS Management Console UXC API GA
📅 2026 年 3 月 27 日
Visible Services & Visible Regions

📋 概要

AWS Management Console において、アカウントレベルで表示するサービスとリージョンをカスタマイズできる Visible Services および Visible Regions 設定が一般提供 (GA) されました。AWS User Experience Customization (UXC) API を通じてプログラム的にも設定可能です。

大規模な組織やマルチアカウント環境において、コンソールのナビゲーションを簡素化し、ユーザーの生産性向上に貢献します。

❌ BEFORE - アップデート前の課題
😵200 以上のサービスと 30 以上のリージョンが全て表示され、必要なサービスを見つけにくい
😕利用が許可されていないサービスやリージョンも表示され混乱の原因に
🚫コンソール表示をアカウントレベルでカスタマイズするネイティブ手段が不在
✅ AFTER - アップデート後の改善
🎯コンソールに表示するサービスとリージョンをアカウントレベルで制御可能に
🖱️Unified Settings から GUI で簡単に設定可能
⚙️UXC API で CLI / SDK / CDK / CloudFormation からプログラム的に管理可能

🔑 主要機能

🟢 Visible Services 設定
コンソールに表示するサービスをアカウントレベルで制限。最大 500 サービスまで指定可能。
null に設定するとデフォルト動作に戻り、全サービスが表示される。ListServices API で指定可能なサービス識別子の一覧を取得可能。
🌍 Visible Regions 設定
コンソールに表示するリージョンをアカウントレベルで制限。最大 100 リージョンまで指定可能。
null に設定するとデフォルト動作に戻る。リージョンコードパターン: [a-z]{2}(-[a-z]{1,10}){1,2}-[1-9]
🎨 Account Color 設定
アカウントの識別を容易にするカラー設定。none でデフォルトに戻る。
選択肢: pink, purple, darkBlue, lightBlue, teal, green, yellow, orange, red
⚙️ プログラム的な設定管理
UXC API で AWS CLI / SDK / CDK / CloudFormation から設定を管理。
UpdateAccountCustomizations API はべき等であり、リクエストに含まれた設定のみ変更。IaC での一括管理が可能。

🔧 技術仕様

UXC API の概要

項目詳細
サービス名AWS User Experience Customization (UXC)
API エンドポイントaws uxc
visibleServices 上限最大 500 サービス
visibleRegions 上限最大 100 リージョン
サービス識別子パターン[a-z0-9]+(-[a-z0-9]+)* (1-64 文字)
リージョンコードパターン[a-z]{2}(-[a-z]{1,10}){1,2}-[1-9]
べき等性あり

UXC API オペレーション

API オペレーション説明
GetAccountCustomizations現在のアカウントカスタマイズ設定を取得
UpdateAccountCustomizationsアカウントカスタマイズ設定を更新
ListServicesvisibleServices で使用可能なサービス識別子の一覧を取得

IAM ポリシー例

JSON UXC API 用 IAM ポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "uxc:GetAccountCustomizations",
                "uxc:UpdateAccountCustomizations",
                "uxc:ListServices"
            ],
            "Resource": "*"
        }
    ]
}

🛠️ 設定方法

前提条件: AWS アカウントと適切な IAM 権限、AWS CLI v2 がインストール済みであること。

ステップ 1: 現在の設定を確認

Bash 現在のカスタマイズ設定を取得 
aws uxc get-account-customizations

ステップ 2: 利用可能なサービス識別子を確認

Bash 指定可能なサービス識別子の一覧を取得 
aws uxc list-services

ステップ 3: 表示するサービスとリージョンを設定

Bash サービス / リージョン / カラーを設定 
aws uxc update-account-customizations \
    --visible-services "ec2" "s3" "lambda" "dynamodb" "cloudformation" \
    --visible-regions "us-east-1" "us-west-2" "ap-northeast-1" \
    --account-color "teal"

ステップ 4: 設定をリセット

Bash デフォルト動作に戻す 
aws uxc update-account-customizations \
    --visible-services \
    --visible-regions \
    --account-color "none"

💡 ユースケース

🏢 ユースケース 1: マルチアカウント環境での開発者向けコンソール簡素化
AWS Organizations で複数のアカウントを管理しており、開発チーム用アカウントでは使用するサービスが限定されている。開発者がコンソールで必要なサービスを素早く見つけられるよう、表示を制限したい。
Bash 開発アカウント用設定 
aws uxc update-account-customizations \
    --visible-services "ec2" "s3" "lambda" "dynamodb" "cloudwatch" \
        "cloudformation" "iam" "codepipeline" "codecommit" "codebuild" \
    --visible-regions "ap-northeast-1" "us-east-1"
✅ 使用する 10 サービスと 2 リージョンのみ表示され、ナビゲーションが大幅に簡素化
🔒 ユースケース 2: コンプライアンス要件に基づくリージョン制限
データレジデンシー要件により、特定のリージョンのみでリソースを管理する必要がある。コンソール上でも対象リージョンのみを表示し、運用ミスを防止したい。
Bash EU リージョン限定設定 
aws uxc update-account-customizations \
    --visible-regions "eu-west-1" "eu-central-1" "eu-west-2" \
    --account-color "purple"
✅ EU リージョンのみ表示。アカウントカラーで本番環境を視覚的に識別可能
📋 ユースケース 3: CloudFormation を使用した組織全体の一括設定
AWS Organizations 配下の複数アカウントに対して、CloudFormation StackSets を使用して表示設定を一括適用したい。
YAML CloudFormation テンプレート 
AWSTemplateFormatVersion: '2010-09-09'
Resources:
  AccountCustomizations:
    Type: AWS::UXC::AccountCustomizations
    Properties:
      VisibleServices:
        - ec2
        - s3
        - lambda
        - rds
        - cloudwatch
      VisibleRegions:
        - ap-northeast-1
        - us-east-1
        - eu-west-1
      AccountColor: teal
✅ 組織全体で統一されたコンソール表示設定を維持し、ガバナンスの一貫性を確保

⚠️ デメリット / 制約事項

制限事項
!コンソール表示制御のみ。CLI / SDK / API からのアクセスは制限されない
!アクセス制御ではないため、IAM ポリシーによる権限管理は引き続き必要
考慮すべき点
!アカウントレベルの設定。ユーザー/グループごとの個別設定は不可
!新サービスリリース時は visibleServices に手動追加が必要
!IAM アクセス制御との混同を避ける運用ルールの明確化が必要
