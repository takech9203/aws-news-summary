AWS IoT Core

Direct Messaging

Point-to-Point 通信 - トピックサブスクリプション不要のダイレクト配信
2026-05-28

📋 概要

AWS IoT Core がダイレクトメッセージング機能をサポート。MQTT クライアント ID を指定して特定デバイスに直接メッセージを送信できるようになった。従来の Pub/Sub モデルに依存せず、サブスクリプション不要の配信と配信確認を実現。

Before

  • デバイスが事前にトピックを Subscribe している必要があった
  • メッセージ到達確認の組み込み仕組みがなかった
  • Pub/Sub で Publish-In + Publish-Out の 2 メッセージ課金

After

  • MQTT クライアント ID 指定で直接配信可能
  • PUBACK ベースのエンドツーエンド配信確認
  • 1 メッセージ課金でコスト削減
  • CloudWatch Logs で配信状況を可視化

📊 数字で見るアップデート効果

50% メッセージ課金削減 (確認なし)
67% メッセージ課金削減 (確認あり)
5 KB ペイロード計測単位
128 クライアント ID 最大文字数

🏗 アーキテクチャ図

SendDirectMessage API のフロー: 送信者が HTTP POST で API を呼び出し、AWS IoT Core が受信デバイスへ直接メッセージを配信。confirmation=true の場合、PUBACK を待機してから成功レスポンスを返す。

⚡ 主要機能

📨 ダイレクトメッセージ配信

  • MQTT クライアント ID を指定して特定デバイスに直接メッセージ送信
  • 受信デバイスがトピックを Subscribe していなくても配信可能
  • HTTP POST リクエストで API 呼び出し (AWS CLI / curl / SDK 対応)

✅ 配信確認 (Delivery Confirmation)

  • confirmation=true: QoS 1 で配信し PUBACK を待機
  • confirmation=false: QoS 0 で即座に配信
  • timeout パラメータで待機秒数を指定可能

📊 詳細なレスポンスコードとログ

  • HTTP ステータスコードで配信結果を即座に把握
  • CloudWatch Logs で配信状況と失敗理由を詳細記録
  • traceId によるリクエストトレーサビリティ

🛠 設定方法とコードサンプル

Step 1: IoT データエンドポイントの確認

Bash エンドポイント取得 
aws iot describe-endpoint --endpoint-type iot:Data-ATS --region us-west-2

Step 2: ダイレクトメッセージ送信 (AWS CLI)

Bash SendDirectMessage - AWS CLI 
aws iot-data send-direct-message \
    --client-id myDevice \
    --topic commands/reboot \
    --confirmation \
    --timeout 10 \
    --payload '{"action": "reboot"}' \
    --region us-west-2 \
    --endpoint-url https://{IoT_data_endpoint}

Step 3: X.509 証明書認証 (curl)

Bash SendDirectMessage - curl / X.509 
curl --tlsv1.2 \
    --cacert Amazon-root-CA-1.pem \
    --cert device.pem.crt \
    --key private.pem.key \
    --request POST \
    --data '{"action": "reboot"}' \
    "https://{IoT_data_endpoint}:8443/connections/myDevice/messages?topic=commands%2Freboot&confirmation=true&timeout=10"

IAM ポリシー設定

JSON IoT ポリシー例 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "iot:SendDirectMessage",
      "Resource": "arn:aws:iot:us-west-2:123456789012:client/targetDeviceId",
      "Condition": {
        "StringEquals": {
          "iot:Topic": "commands/reboot"
        }
      }
    }
  ]
}

受信側デバイスには iot:Receive 権限がターゲットトピックに対して必要。iot:Subscribe 権限は不要。

🐍 Python SDK サンプル

Python boto3 による SendDirectMessage 
import boto3

client = boto3.client('iot-data')

response = client.send_direct_message(
    clientId='vehicle-VIN-12345',
    topic='config/navigation',
    confirmation=True,
    timeout=10,
    payload=b'{"mapVersion": "2026.05", "region": "JP"}'
)

print(f"配信結果: {response['message']}")

🎯 ユースケース

🏭 ユースケース 1: デバイスへのコマンド送信と確認

工場の制御システムから特定の IoT デバイスにリブートコマンドを送信し、コマンドが確実に受信されたことを確認。

効果: 配信確認により未配信の場合はリトライや代替アクションを即座に実行可能

コネクテッドカーの車両管理システムから特定車両にナビゲーション設定やソフトウェア設定を個別配信。

効果: 各車両のサブスクリプション管理不要でフリート管理の複雑さを軽減

🏠 ユースケース 3: スマートホームデバイスへの即座の制御

スマートホームアプリからスマートロックに解錠コマンドを送信し、受理されたことを即座に確認。

効果: 配信確認でユーザーに即座にフィードバック、タイムアウト時は再試行を促進

⚠️ 制限事項と注意点

! AWS IoT Rules による処理対象外 (ルールエンジンでの処理不可)
! オフラインデバイスへのメッセージキューイングは非対応 (デバイスが接続中である必要あり)
! Retained メッセージはサポートされない
! クライアント ID は 128 文字以内、ドル記号 ($) で開始不可
! AWS IoT Core の予約トピックは使用不可
! 一部 MQTT クライアントはサブスクライブしていないトピックのメッセージを破棄する可能性あり
! confirmation=true 使用時は HTTP クライアントのタイムアウトを timeout パラメータより大きく設定する必要あり
