AWS Cost Management

💰 Amazon Bedrock 製品属性によるコスト分析サポート

Cost Explorer / Budgets / Dashboards で Bedrock コストをモデル別・プロバイダー別に分解
リリース日: 2026 年 10 月 8 日
サービス: Cost Explorer / Budgets / Dashboards
追加料金: なし

📝 概要

AWS Cost Explorer、AWS Budgets、AWS Cost Management Dashboards で、Amazon Bedrock のコストを製品属性 (Product Attributes) という新しいディメンションで分析できるようになりました。モデル、モデルプロバイダー、推論タイプ、機能の 4 つの属性で Bedrock のコストを分解できます。

さらに、アプリケーション推論プロファイルのコスト配分タグや IAM プリンシパルタグと組み合わせることで、どのアプリケーション・プロジェクト・ユーザーが支出を牽引しているかまで可視化できます。

❌ アップデート前の課題

✗Cost Explorer ではサービス単位や使用タイプ単位でしか分解できず、モデル別の内訳を直感的に把握できない
✗モデル別分析には CUR を Athena や QuickSight で加工する独自パイプラインの構築が必要
✗特定モデルの支出に AWS Budgets でアラート予算を直接設定することが困難

✅ アップデート後の改善

✓Cost Explorer と Dashboards でモデル / プロバイダー / 推論タイプ / 機能によるグループ化とフィルタリングが可能
✓Budgets で製品属性フィルタリングにより特定モデルのアラート予算を設定可能
✓コスト配分タグや IAM プリンシパルタグと組み合わせた多軸でのコスト分析が可能

Amazon Bedrock の各モデルの利用コストが製品属性付きで請求データに反映され、Cost Explorer、Budgets、Dashboards の各ツールで属性単位の分析・予算管理・可視化ができる流れ

⚡ 主要機能

1️⃣ 製品属性によるコスト分解

Bedrock のコストを「モデル」「モデルプロバイダー」「推論タイプ」「機能」の 4 つの新しいディメンションで分解。高コストのモデルやトークン種別の内訳を直接把握できます。

2️⃣ Cost Explorer / Dashboards でのグループ化とフィルタリング

月間 Bedrock 支出をモデル別にグループ化して高コストモデルを特定。プロバイダー別のコスト推移を追跡するダッシュボードウィジェットの作成や、入力 / 出力トークンのコスト比率の把握も可能です。

3️⃣ Budgets での属性フィルタリング

特定モデルの支出に対するアラート予算を設定可能。モデルやプロバイダー単位で予算の閾値超過を検知し、通知を受け取れます。

4️⃣ タグとの組み合わせによる多軸分析

アプリケーション推論プロファイルのコスト配分タグや IAM プリンシパルタグと組み合わせて、アプリケーション別・ユーザー別・モデル別の多軸でコストを分析できます。

🛠️ 設定方法

前提条件

✓AWS Cost Explorer が有効化されていること
✓Cost Explorer、Budgets、Dashboards へのアクセス権限 (ce:*、budgets:* など) を持つ IAM プリンシパルで操作すること
✓アプリケーション別・ユーザー別の分析には、コスト配分タグや IAM プリンシパルタグの有効化が必要

手順

1
📈 Cost Explorer でモデル別にグループ化

フィルターで「サービス」に Amazon Bedrock を指定し、「グループ化の条件」で新しい製品属性ディメンション (モデルなど) を選択。月間の Bedrock 支出がモデル別に分解されて表示されます。

2
🖥️ Dashboards でウィジェットを作成

Cost Management Dashboards で新しいウィジェットを作成し、モデルプロバイダー属性でグループ化。プロバイダー別のコスト推移を継続的に追跡するダッシュボードを構築できます。

3
🔔 Budgets で特定モデルの予算を設定

AWS Budgets で新しいコスト予算を作成し、フィルターに製品属性 (特定のモデルなど) を指定。閾値超過時に通知を受け取り、特定モデルの支出増加を早期に検知できます。

💡 メリット

💼 ビジネス面

  • ✓コストの透明性向上: どのモデルやプロバイダーが支出を押し上げているかを財務チームが直接把握でき、生成 AI 投資の説明責任を果たしやすくなる
  • ✓チャージバックの精緻化: タグとの組み合わせにより、アプリケーションやチーム単位でのコスト配賦が容易になる
  • ✓予算ガバナンスの強化: 特定モデルに対するアラート予算により、想定外のコスト増加を早期に検知できる

⚙️ 技術面

  • ✓追加パイプライン不要: CUR + Athena + QuickSight のような独自分析基盤を構築せずに、標準ツールだけでモデル別分析が可能
  • ✓既存ワークフローとの統合: 使い慣れたツールにそのまま組み込めるため、学習コストが低い
  • ✓多軸分析: 製品属性、コスト配分タグ、IAM プリンシパルタグを組み合わせた柔軟な分析が可能

⚠️ デメリット・制約事項

制限事項

⚠️AWS GovCloud (US) および中国 (北京、寧夏) リージョンでは利用不可
⚠️対象は Amazon Bedrock のコストに限定され、他サービスへの製品属性の適用については言及されていない
⚠️Budgets ではフィルタリングのみ対応しており、グループ化には対応していない

考慮すべき点

💭ユーザー別・アプリケーション別の分析には、IAM プリンシパルタグやアプリケーション推論プロファイルのコスト配分タグの事前整備が必要
💭過去データへの属性の遡及適用範囲は公式発表に明記されていないため、利用開始時に実際のデータで確認が必要

🎯 ユースケース

1. 高コストモデルの特定と最適化

シナリオ: 複数の Bedrock モデルを利用している組織で、月間支出が増加傾向にあり、どのモデルが原因かを特定したい。

Cost Explorer設定例
Cost Explorer:
  フィルター: サービス = Amazon Bedrock
  グループ化: モデル
  期間: 過去 6 か月 (月次)

効果: 高コストのモデルを特定し、より低コストなモデル (例: Claude Haiku 4.5) への切り替えやプロンプト最適化の判断材料にできる。

2. アプリケーション別のモデル支出のチャージバック

シナリオ: 社内の複数アプリケーションが共通の Bedrock 環境を利用しており、アプリケーションごとにモデル支出を配賦したい。

Cost Explorer設定例
Cost Explorer:
  フィルター: サービス = Amazon Bedrock
  グループ化: モデル
  追加フィルター: コスト配分タグ (アプリケーション推論プロファイル)

効果: どのアプリケーションがどのモデルの支出を牽引しているかを可視化し、部門別のチャージバックを正確に実施できる。

3. 特定モデルの予算アラート

シナリオ: 高価格帯モデルの利用を一定額以内に抑えたい。閾値を超えた場合にすぐに通知を受けたい。

AWS Budgets設定例
AWS Budgets:
  予算タイプ: コスト予算
  フィルター: モデル = Claude Sonnet 5
  閾値: 月額予算の 80% で通知

効果: 特定モデルの支出が予算に近づいた時点でアラートを受け取り、利用制御やコスト見直しを迅速に実施できる。

💵 料金・利用可能リージョン

💰 この機能は追加料金なしで利用できます。Cost Explorer のコンソール利用は無料です (API 利用はリクエストごとに課金)。
🌍 AWS GovCloud (US) および中国 (北京、寧夏) リージョンを除く、すべての AWS リージョンで利用可能です。

🤖 Amazon Bedrock

分析対象となる生成 AI サービス。アプリケーション推論プロファイルによるタグ付けと組み合わせることで分析の粒度が向上する。

支出の異常を機械学習で検知する機能。製品属性による分析と組み合わせて原因特定を迅速化できる。

生成 AI の利用拡大に伴い課題となっていた Bedrock コストの可視化が、Cost Explorer、Budgets、Dashboards の標準機能だけで実現できるようになりました。独自の分析パイプラインを構築せずにモデル別・プロバイダー別のコスト分析や予算アラートが可能になります。
