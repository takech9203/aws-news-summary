AWS Glue

⚙️ Apache Spark ジョブの自動バージョンアップグレード

📅 2026 年 11 月 12 日 ｜ GlueVersion: auto の設定だけで、Spark ジョブを常に最新の安定版ランタイムに

📌 概要

AWS Glue が Apache Spark ジョブの自動バージョンアップグレード (auto upgrade) を発表。 ジョブの GlueVersion を auto に設定するだけで、手動の移行プロジェクトなしに 最新の安定版ランタイムへ追従し、セキュリティパッチ、パフォーマンス改善、Apache Iceberg などの新テーブルフォーマット対応を継続的に利用できます。

互換性チェック、ユーザー承認の必須化、出力ベースラインとの比較検証、失敗時の 自動ロールバックという多層のガードレールで安全性を確保。コード変更が必要なジョブは現行バージョンのまま維持され、 修正提案付きの分析結果が提供されます。

❌ Before: アップデート前の課題

  • Glue バージョンアップはジョブごとに手動での互換性評価・テスト・切り替えが必要な移行プロジェクトだった
  • 古いランタイムに留まるジョブは、セキュリティパッチや性能改善、新テーブルフォーマット対応の恩恵を受けられなかった
  • 多数のジョブを抱える環境では作業負荷が大きく、アップグレードが後回しになりがちだった

✅ After: アップデート後の改善

  • GlueVersion を auto に設定するだけで、互換性評価からアップグレード検証まで AWS Glue が自動実施
  • アップグレード後の実行が失敗した場合は、以前のバージョンで自動的に再実行し元へ戻すセーフティネットを提供
  • コード変更が必要なジョブには修正提案付きの分析結果が提供され、計画的な対応が可能に

既存ジョブの自動アップグレードは 4 つのフェーズで進行し、互換性チェック、ユーザー承認、出力ベースラインとの比較検証、失敗時の自動ロールバックという多層のガードレールで安全性を確保します。

🔧 主要機能

1️⃣ GlueVersion パラメータの auto 設定

AWS Glue Studio、CLI、API、SDK からジョブの作成・更新時に設定可能。既存ジョブは 4 フェーズの評価プロセスを経て最新安定版へ移行。新規作成ジョブは評価フェーズをスキップし、最初から最新安定版で実行されます。

2️⃣ 互換性評価とユーザー承認

ジョブスクリプト、設定、依存関係を分析し、既知の破壊的変更の有無をチェック。問題がなければ適格性サマリーが送付され、7 日以内に承認または却下を選択。ユーザーの同意なしにアップグレードされることはありません。

3️⃣ 出力プロファイルによる検証と自動ロールバック

アップグレード後の実行を、スキーマ、データ量、レイテンシー、フォーマットのベースラインと比較。実行が失敗した場合は以前のバージョンでリトライし、ジョブを元のバージョンへ自動復帰。AWS Glue はスクリプトやジョブ設定を変更しません。

4️⃣ コード変更が必要なジョブへの対応

互換性のないジョブはアップグレードされず、現行バージョンのまま安全に稼働を継続。評価サマリーに必要な変更点と修正提案が記載され、手動または Apache Spark upgrade agent で適用できます。

5️⃣ AI エージェントによる一括管理

GitHub の aws-samples/aws-glue-samples で公開されている managing-glue-jobs スキルを利用し、自然言語プロンプトで複数ジョブの評価、auto upgrade の有効化、メール通知設定、承認操作が可能です。

📐 技術仕様

🔄 自動アップグレードの 4 フェーズ

フェーズAWS Glue の動作ユーザーの操作
1. 観測現行バージョンでジョブを実行し、ベースラインを記録不要
2. 互換性チェックと承認既知の破壊的変更をチェックし、問題なければ適格性サマリーを送付サマリーを確認し、7 日以内に承認または却下
3. アップグレード検証次回以降の実行を最新安定版で行い、各実行をベースラインと比較アップグレード後の実行をモニタリング
4. 完了最新安定版で稼働継続。実行失敗時は以前のバージョンへ復帰評価サマリーを確認

✅ 対象ジョブの要件

項目詳細
ジョブタイプSpark ETL ジョブ (glueetl)。Streaming、Python shell、Ray ジョブは非対応
Glue バージョンAWS Glue 2.0 以降のジョブが対象
MaxRetries1 以上に設定 (失敗時に以前のバージョンでリトライするために使用)
ジョブ実行キューイング無効化が必要
リトライ安全性途中失敗からのリトライで出力の重複や破損が発生しない設計であること (例: リトライ時に出力を上書きする)

📝 設定例

JSON ジョブ定義 
{
  "Name": "my-etl-job",
  "GlueVersion": "auto",
  "MaxRetries": 1,
  "Command": {
    "Name": "glueetl",
    "ScriptLocation": "s3://my-bucket/scripts/my-etl-job.py"
  }
}

🛠️ 設定方法

📋 前提条件

✓対象ジョブが AWS Glue 2.0 以降の Spark ETL ジョブ (glueetl) であること
✓MaxRetries が 1 以上に設定され、ジョブ実行キューイングが無効であること
✓ジョブがリトライ安全であること (リトライによる出力の重複・破損が発生しない、または部分出力をクリーンアップできる)
✓auto upgrade に必要な IAM 権限が付与されていること

🚀 手順

1
ジョブのリトライ安全性を確認する

途中失敗からのリトライで出力が重複・破損しないことを確認します。リトライ時に出力を上書きする設計であれば安全です。

2
GlueVersion を auto に設定する
Bash AWS CLI での設定 
aws glue update-job \
  --job-name my-etl-job \
  --job-update '{"GlueVersion": "auto", "MaxRetries": 1, "Role": "arn:aws:iam::123456789012:role/GlueJobRole", "Command": {"Name": "glueetl", "ScriptLocation": "s3://my-bucket/scripts/my-etl-job.py"}}'

AWS Glue Studio のコンソールからも同様に設定できます。設定後は通常どおりジョブを実行し続けます。

3
適格性サマリーを確認して承認する

観測と互換性チェックの完了後に届く適格性サマリーを確認し、7 日以内に承認します。承認後の実行から最新安定版が使用されます。

4
アップグレード後の実行をモニタリングする

検証フェーズの実行結果をモニタリングし、評価完了後に auto upgrade 評価サマリーを確認します。実行が失敗した場合は AWS Glue が自動的に以前のバージョンへ戻します。

5
(オプション) AI エージェントで複数ジョブを一括管理する

aws-samples/aws-glue-samples の managing-glue-jobs スキルをインストールし、自然言語プロンプトで複数ジョブを評価・設定できます。

Text AI エージェントへのプロンプト例 
Assess my Glue jobs in us-west-2 for auto upgrade. Use AWS profile my-profile.
Proceed with the eligible jobs, and set up auto upgrade email notifications to data-team@example.com.

1 つ目のプロンプトは読み取り専用の評価を実行し、2 つ目は適格なジョブの GlueVersion を auto に設定してメール通知リソースを作成します。エージェントは変更前に必ず確認を求めます。

✓セキュリティ体制の強化: 最新ランタイムのセキュリティパッチを継続適用し、古いバージョンに起因するリスクを低減
✓追加コストなし: auto upgrade 自体に追加料金はなく、ジョブ実行は通常のレートで課金

⚙️ 技術面

✓スクリプト非変更: AWS Glue はスクリプトやジョブ設定を変更しないため、意図しない動作変更のリスクがない
✓最新機能の活用: パフォーマンス改善や Apache Iceberg などの新テーブルフォーマット対応を自動的に利用できる

⚠️ デメリット・制約事項

🚫 制限事項

✗Spark ETL ジョブ (glueetl) のみ対応。Streaming、Python shell、Ray ジョブは非対応
✗AWS Glue 2.0 以降のジョブが対象
✗MaxRetries を 1 以上に設定し、ジョブ実行キューイングを無効にする必要がある
✗1 つのジョブで同時に実行できる評価は 1 つのみ。Upgrade with AI を実行中のジョブは auto upgrade を利用できない
✗商用リージョンで利用可能 (GovCloud、中国リージョンは記載なし)

🤔 考慮すべき点

⚠リトライ安全が前提のため、冪等性のない出力処理を持つジョブは事前に設計の見直しが必要
⚠実行頻度の低いジョブは、評価にジョブ自身の実行を使用するため、アップグレード完了までに時間がかかる
⚠評価期間中にスクリプトや出力を変更すると、ベースラインが古くなり評価が失敗する可能性がある
⚠適格性サマリーへの承認期限は 7 日間。期限内の確認・承認フローを運用に組み込む必要がある

🎯 ユースケース

📊 ユースケース 1: 多数の ETL ジョブを抱えるデータ基盤のランタイム統一

シナリオ: 数百の Glue 2.0 / 3.0 / 4.0 ジョブが混在するデータ基盤で、最新バージョンへの統一を進めたいが、手動での移行工数を確保できない。

実装: managing-glue-jobs スキル (AI エージェント) で全ジョブを一括評価し、適格なジョブの GlueVersion を auto に一括設定。メール通知を構成し、適格性サマリーを順次承認。

効果: 移行プロジェクトを立ち上げることなく、多数のジョブを段階的かつ安全に最新ランタイムへ統一できる。

🌙 ユースケース 2: 夜間バッチ ETL ジョブの安全な自動アップグレード

シナリオ: S3 上のデータを変換して出力を上書きする夜間バッチジョブを運用。リトライ安全な設計のため、自動アップグレードに適している。

実装: aws glue update-job --job-name nightly-batch-etl --job-update '{"GlueVersion": "auto", "MaxRetries": 1, ...}'

効果: 夜間バッチは通常どおり実行を継続しながら裏側で互換性評価が進み、承認後に最新安定版へ移行。失敗時は自動で元のバージョンへ戻るため、業務影響を最小化できる。

🆕 ユースケース 3: 新規ジョブを常に最新ランタイムで運用

シナリオ: 新しいデータパイプラインを構築するにあたり、将来のバージョンアップ対応を最初から不要にしたい。

実装: aws glue create-job --name new-pipeline-job --glue-version auto --max-retries 1 ... で新規作成時に auto を指定。

効果: 新規作成時に auto を指定したジョブは評価フェーズをスキップし、最初から最新安定版で実行。以降のバージョンアップも自動で追従する。

💰 料金と利用可能リージョン

💵 料金

auto upgrade 自体に追加料金はありません。評価のための追加のジョブ実行も発生せず、各ジョブ実行は通常の AWS Glue の料金 (DPU 時間ベース) で課金されます。

🌏 利用可能リージョン

すべての AWS 商用リージョンで利用可能です。ドキュメントには以下を含む 33 リージョンが記載されています。

✓アジアパシフィック (東京)、アジアパシフィック (大阪)、ソウル、シンガポール など
✓米国東部 (バージニア北部、オハイオ)、米国西部 (北カリフォルニア、オレゴン)
✓欧州 (フランクフルト、アイルランド、ロンドン、パリ) など

📝 まとめ

AWS Glue の自動バージョンアップグレードにより、Spark ジョブを追加料金なしで常に最新の安定版ランタイムに保てるようになり、バージョンアップの移行プロジェクトが不要になります。 互換性チェック、ユーザー承認、出力ベースライン検証、自動ロールバックという多層のガードレールが安全性を担保します。

まずはリトライ安全な Spark ETL ジョブを対象に GlueVersion を auto に設定し、適格性サマリーを確認するところから始めることを推奨します。
