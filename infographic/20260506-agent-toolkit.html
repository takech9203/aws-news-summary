🧰 Agent Toolkit for AWS

AI コーディングエージェント向け開発支援ツールキット

📅 2026-05-06

📋 概要

AWS は Agent Toolkit for AWS を発表。AI コーディングエージェントが AWS 上で効果的にアプリケーションを構築するための、本番環境対応のツールスイートおよびガイダンス。エラーの削減、トークンコストの低減、エンタープライズグレードのセキュリティ制御を提供する。

AWS Labs で提供されていた MCP サーバー、プラグイン、スキルの後継として位置付けられている。

40+ 検証済みスキル
3 Agent Plugins
0円 追加料金

🔄 Before / After

❌ Before (課題)

  • 複雑なマルチサービスワークフローで正確に動作できない
  • AWS サービスの古い知識に依存して動作
  • エージェントのアクションに対するガバナンスが困難
  • トークンの浪費や開発時間のロスが発生

✅ After (改善)

  • 40+ スキルにより検証済みベストプラクティスに従って動作
  • フルマネージド MCP サーバーで IAM ガードレールとオブザーバビリティを提供
  • プラグインにより単一インストールで導入可能
  • AWS リソース使用料のみで追加料金なし

開発者の AI コーディングエージェントがプラグインを通じてフルマネージド MCP サーバーに接続し、スキルと AWS サービスを活用しながら、IAM ガードレールや CloudWatch / CloudTrail によるガバナンスの下で安全に動作する。

⚡ 主要機能

📋 Agent Skills

AWS のベストプラクティスに基づく検証済みの手順をエージェントに提供

  • CloudFormation テンプレート作成、データパイプライン設定、サーバーレスアプリケーション構築に対応
  • Infrastructure-as-Code、ストレージ、分析、サーバーレス、コンテナ、AI サービスをカバー
  • 各スキルはタスク完了の正確性と信頼性を確保するため厳密に評価済み
  • 今後データベース、ネットワーキング、IAM 向けスキルを追加予定

🔌 AWS MCP Server (一般提供開始)

コーディングエージェントが任意の AWS サービスと対話できるフルマネージド MCP サーバー

  • IAM ベースのガードレールによりエージェントが実行可能なアクションを制御
  • Amazon CloudWatch および AWS CloudTrail によるオブザーバビリティ
  • マルチステップ操作のためのサンドボックス化されたコード実行環境
  • 最新のドキュメントを効率的に検索・取得するツールを提供

📦 Agent Plugins

AWS MCP Server とキュレーションされたスキルセットを単一のインストールにバンドル

🏗️ AWS Core

アプリケーション開発者がフルスタックアプリケーションを構築・管理するためのプラグイン

📊 AWS Data Analytics

データアナリストや BI エンジニアがデータパイプラインの作成やデータのロード・クエリを行うためのプラグイン

🤖 AWS Agents

AI エンジニアが Amazon Bedrock AgentCore を使用して本番環境対応のエージェントを構築するためのプラグイン

🔒 セキュリティとガバナンス

IAM ポリシーによりエージェントが実行可能なアクションを明示的に制御できる。以下は特定リージョンでの操作のみを許可する IAM ポリシーの例。

JSON IAM ポリシー例 - リージョン制限 
{
  "Effect": "Allow",
  "Action": [
    "bedrock:InvokeModel",
    "cloudformation:CreateStack",
    "s3:PutObject"
  ],
  "Resource": "*",
  "Condition": {
    "StringEquals": {
      "aws:RequestedRegion": "us-east-1"
    }
  }
}

⚙️ 設定方法

前提条件

  • AWS アカウントが有効であること
  • AI コーディングエージェント (Claude Code、Amazon Q Developer、Cursor 等) が利用可能であること
  • IAM ユーザーまたはロールに適切な権限が設定されていること

Step 1: MCP Server 接続設定

JSON IDE 設定ファイル 
{
  "mcpServers": {
    "aws": {
      "command": "aws-mcp-server",
      "args": ["--region", "us-east-1"],
      "env": {
        "AWS_PROFILE": "default"
      }
    }
  }
}

Step 2: IAM ガードレールの設定

Bash IAM ロールにポリシーをアタッチ 
# エージェントが使用する IAM ロールに適切なポリシーをアタッチ
aws iam attach-role-policy \
  --role-name AgentToolkitRole \
  --policy-arn arn:aws:iam::aws:policy/AgentToolkitBasicAccess

シナリオ: API Gateway + Lambda + DynamoDB のサーバーレスアプリケーションを構築

Prompt エージェントへの指示例 
「ユーザー認証付きの REST API を構築してください。
API Gateway、Lambda、DynamoDB を使用し、
CloudFormation テンプレートで Infrastructure-as-Code として管理してください。」

→ Agent Skills のサーバーレススキルと IaC スキルを活用し、ベストプラクティスに従った CloudFormation テンプレートを自動生成

📊 データパイプラインの設定

シナリオ: S3 から Redshift へのデータパイプラインを構築

Prompt AWS Data Analytics プラグイン使用例 
「S3 バケットの CSV データを Glue で変換し、
Redshift にロードするパイプラインを作成してください。
スケジュール実行も設定してください。」

→ AWS Data Analytics プラグインにより、Glue ジョブ設定から Redshift テーブル定義まで一貫してベストプラクティスに従った設定

🤖 本番環境対応の AI エージェント構築

シナリオ: Amazon Bedrock AgentCore でカスタマーサポート用 AI エージェントを構築

Prompt AWS Agents プラグイン使用例 
「Bedrock AgentCore を使用して、FAQ 応答と
注文状況確認ができるカスタマーサポートエージェントを構築してください。
IAM ロールの設定と CloudWatch アラームも含めてください。」

→ AWS Agents プラグインにより、セットアップからデプロイまで全工程でガイダンスが提供され、セキュリティ設定やモニタリングも含めた本番環境対応エージェントを効率的に構築
