🔐 AWS Workload Credentials Provider

証明書とシークレットの自動配布を 1 つの軽量プロバイダーで実現
AWS Certificate Manager AWS Secrets Manager
📅 リリース: 2026 年 6 月 11 日

📌 概要

AWS は AWS Workload Credentials Provider を発表しました。 これは軽量なクライアントサイドのプロバイダーで、ACM からエクスポートした証明書のデプロイと、 Secrets Manager のシークレットのローカルキャッシュを、AWS および非 AWS のワークロード全体で自動化します。

  • 証明書 ARN を指定し、ファイルパスやリロード動作を設定するだけで、エクスポートとデプロイを自動処理
  • Windows / Linux 上でシステムサービスとして動作し、Apache・NGINX に対応
  • 既存の AWS Secrets Manager Agent と完全な後方互換性を維持 (Agent の後継)
  • オープンソースで GitHub 公開、すべての AWS リージョンで利用可能

Before / After

❌ アップデート前の課題

  • ACM からの証明書エクスポートに、EventBridge で更新を検知するカスタム自動化を独自構築する必要があった
  • 公開証明書の有効期間短縮 (CA/B 規定) で、カスタム自動化は大規模環境で保守が困難
  • 証明書とシークレットの配布が個別に存在し運用が分散

✅ アップデート後の改善

  • 証明書 ARN・パス・リロードコマンドを設定するだけで自動化、カスタム自動化が不要
  • 証明書とシークレットを単一プロバイダーで配布・自動化
  • 24 時間ごとのリフレッシュで短命な証明書の更新運用を大規模環境でも継続

ワークロードホスト上のプロバイダーが IAM ロールを引き受けて ACM から証明書をエクスポートし、ローカルにファイルとして書き込んだうえで Web サーバーをリロードします。 同時に、アプリケーションは localhost 経由で Secrets Manager のシークレットをキャッシュ付きで取得できます。

⚙️ 主要機能

1. 証明書の自動エクスポートとデプロイ (ACM capability)

  • スケジューラーが各証明書を 24 時間ごとにリフレッシュし、ACM から証明書と秘密鍵をエクスポート
  • ディスク上の内容と比較し、変更があった場合のみ新しいファイルを書き込み
  • ファイル更新時のみ refresh_command を実行し、不要なリロードを回避
  • 起動時に初回リフレッシュ、フリート同時起動時の API 集中を避けるためランダムなジッターを付与

2. シークレットのローカルキャッシュ (Secrets Manager capability)

  • localhost の HTTP インターフェイス (デフォルトポート 2773) を提供し、ローカルからシークレットを取得
  • メモリ内キャッシュ (デフォルト TTL 300 秒、キャッシュサイズ 1000)
  • 既存の Secrets Manager Agent と完全な後方互換性を維持 (従来のフラットな設定キーも利用可)
  • SSRF 保護のためのトークン検証を備える

3. 動的な設定リロードと安全な実行環境

  • acm reload コマンドで、再インストールなしに証明書の追加・削除・変更が可能
  • 各証明書は独立タスクとして実行され、1 つの失敗が他に影響しない
  • 専用の低権限ユーザーで動作、証明書ファイルは制限権限 (デフォルト 0600) で書き込み

設定ファイル例 (NGINX, Linux)

TOMLconfig.toml
[logging]
log_level = "info"
log_to_file = true

[capabilities.acm]
enabled = true

[[capabilities.acm.certificates]]
certificate_arn = "arn:aws:acm:us-west-2:123456789012:certificate/abcd1234-5678-90ab-cdef-EXAMPLE11111"
role_arn = "arn:aws:iam::123456789012:role/ACMExportRole"
certificate_path = "/etc/pki/tls/certs/example.com.crt"
private_key_path = "/etc/pki/tls/private/example.com.key"
chain_path = "/etc/pki/tls/certs/example.com-chain.pem"
refresh_command = "/usr/sbin/nginx -s reload"
💡 chain_path を省略した場合、証明書チェーンは certificate_path のファイルに追記され、単一ファイルにフルチェーンを期待する Web サーバーと互換性のある形式になります。

設定リファレンス (主な項目)

フィールド必須デフォルト説明
capabilities.acm.enabledいいえfalseACM capability の有効化
certificates[].certificate_arnはい—エクスポートする ACM 証明書の ARN
certificates[].role_arnはい—ExportCertificate 呼び出しで引き受ける IAM ロール ARN
certificates[].certificate_pathはい—証明書ファイルを書き込む絶対パス
certificates[].private_key_pathはい—秘密鍵ファイルを書き込む絶対パス
certificates[].chain_pathいいえ—チェーンを書き込む絶対パス。省略時は certificate_path に追記
certificates[].refresh_commandいいえ—証明書更新後に実行するコマンド (絶対パス)
certificates[].key_permissionいいえ0600秘密鍵ファイルの権限

必要な権限

プロバイダーのベース認証情報には、各証明書の role_arn を引き受ける権限が必要です。

JSONベース認証情報のポリシー
{
    "Effect": "Allow",
    "Action": "sts:AssumeRole",
    "Resource": "arn:aws:iam::123456789012:role/ACMExportRole"
}

引き受ける側のロールには、証明書をエクスポートする権限が必要です。

JSON引き受け先ロールのポリシー
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "acm:ExportCertificate",
            "Resource": "arn:aws:acm:us-west-2:123456789012:certificate/*"
        }
    ]
}

🚀 設定方法

前提条件

  • systemd を備えた Linux インスタンス、または Windows Server 2016 以降のインスタンス
  • ACM のエクスポート可能な証明書 (公開またはプライベート)
  • ACM のエクスポート権限を持つ IAM ロールと、インスタンス上で利用可能な AWS 認証情報

ステップ 1: プロバイダーのビルド

Bash
cargo build --release

Rust ツールチェーンでソースからバイナリをビルドします。実行ファイルは target/release/aws-workload-credentials-provider に配置されます。事前ビルド済みのバイナリも利用できます。

ステップ 2: 設定ファイルの作成とインストール

Bash
cd aws_workload_credentials_provider_common/configuration
sudo ./install --config /path/to/your/config.toml

TOML 設定ファイルを作成し、インストールスクリプトを root で実行します。--config を指定すると設定が /etc/aws-workload-credentials-provider/config.toml に自動コピーされます。

ステップ 3: 動作確認と動的リロード

Bash
sudo systemctl status aws-workload-credentials-provider-acm
aws-workload-credentials-provider acm reload --config /path/to/new-config.toml

サービスの稼働状態を確認します。acm reload で新しい設定の検証・権限更新・サービス再起動が行われ、再インストールは不要です。

✅ メリット

💼 ビジネス面

✓運用負荷の削減: EventBridge のカスタム自動化の構築・保守が不要になり、運用コストを削減
✓コンプライアンス対応: CA/B の証明書有効期間短縮に追従し、大規模環境でも継続的更新を維持
✓AWS 内外での統一運用: AWS と非 AWS のワークロードを単一プロバイダーで標準化

🛠️ 技術面

✓自動化された証明書ライフサイクル: 24 時間ごとのリフレッシュ + 内容変更時のみのリロードで無駄のない更新
✓セキュアな実行: 低権限ユーザー、制限ファイル権限、SSRF 保護を備える
✓後方互換性: 既存の Secrets Manager Agent から容易に移行、従来設定をそのまま利用

⚠️ デメリット・制約事項

制限事項

✗証明書機能は ACM のエクスポート可能な証明書のみが対象
✗証明書機能はコンテナや Lambda 非対応 (EC2・オンプレミスが対象)
✗管理できる証明書は最大 50 個まで
✗シークレットキャッシュはメモリ内のため再起動でリセット。TTL 内のローテーションで古い値が返る可能性 (refreshNow=true で回避)

考慮すべき点

⚠️Linux では refresh_command が sudo 経由で実行されるため、sudoers エントリと include 設定の確認が必要
⚠️バイナリのビルドには Rust ツールチェーンが必要 (事前ビルド済みバイナリも利用可)
⚠️ExportCertificate の呼び出しは CloudTrail に記録され、ユーザーエージェントに aws-workload-credentials-provider が含まれる

💡 ユースケース

ユースケース 1: 短命な公開証明書の自動更新

シナリオ: CA/B 規定で有効期間が短縮された公開 TLS 証明書を、複数 EC2 上の NGINX に継続配布したい。

TOML
[[capabilities.acm.certificates]]
certificate_arn = "arn:aws:acm:us-west-2:123456789012:certificate/EXAMPLE"
role_arn = "arn:aws:iam::123456789012:role/ACMExportRole"
certificate_path = "/etc/pki/tls/certs/example.com.crt"
private_key_path = "/etc/pki/tls/private/example.com.key"
refresh_command = "/usr/sbin/nginx -s reload"

▶ 効果: EventBridge ベースのカスタム自動化なしで、更新検知から配布、NGINX リロードまで自動化。

ユースケース 2: オンプレミスサーバーへの証明書配布

シナリオ: AWS 認証情報を持つオンプレミスの Apache サーバーで、ACM のプライベート証明書を利用したい。

TOML
[[capabilities.acm.certificates]]
certificate_arn = "arn:aws:acm:us-west-2:123456789012:certificate/EXAMPLE"
role_arn = "arn:aws:iam::123456789012:role/ACMExportRole"
certificate_path = "/etc/ssl/certs/example.com.crt"
private_key_path = "/etc/ssl/private/example.com.key"
refresh_command = "/bin/systemctl reload httpd"

▶ 効果: AWS 外のワークロードでも ACM 管理の証明書を自動取得・配布。

ユースケース 3: シークレット取得の集約

シナリオ: EC2 上のアプリが Secrets Manager のシークレットを頻繁に取得しており、API 呼び出しとレイテンシを抑えたい。

Bash
curl -H "X-Aws-Parameters-Secrets-Token: $(</var/run/awssmatoken)" \
  'http://localhost:2773/secretsmanager/get?secretId=<YOUR_SECRET_ID>'

▶ 効果: localhost キャッシュ経由でシークレットを取得し、直接呼び出しを削減、レイテンシを低減。

💰 料金 & 🌍 利用可能リージョン

料金: AWS Workload Credentials Provider 自体はオープンソースで提供され、追加料金は発生しません。 証明書のエクスポートやシークレット取得に伴う ACM および AWS Secrets Manager の標準料金が適用されます。

🔗 関連サービス・機能

サービス役割
AWS Certificate Manager (ACM)証明書のエクスポート元。エクスポート可能な公開・プライベート証明書に対応
AWS Secrets Managerシークレットの取得元。本プロバイダーは Secrets Manager Agent の後継として後方互換を維持
Amazon EventBridge従来は証明書更新の検知に利用していたが、本プロバイダーにより不要に
AWS IAM / AWS STS証明書エクスポートのための IAM ロール引き受けに利用

📝 まとめ

AWS Workload Credentials Provider は、ACM 証明書のエクスポートとデプロイ、および Secrets Manager のシークレットキャッシュを単一の軽量プロバイダーで自動化します。 CA/B 規定により証明書の有効期間が短縮されるなか、EventBridge ベースのカスタム自動化を置き換える運用負荷の低い選択肢となります。 証明書のローテーション運用を抱える AWS 内外のワークロードでは、まず開発環境で TOML 設定と refresh_command の動作を検証することを推奨します。
