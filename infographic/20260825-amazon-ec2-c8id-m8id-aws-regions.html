📌 概要

カスタム Intel Xeon 6 プロセッサを搭載した Amazon EC2 C8id および M8id インスタンスが追加リージョンで利用可能になりました。C8id はアジアパシフィック (シドニー) とカナダ (中部)、M8id はアジアパシフィック (ムンバイ) とカナダ (中部) で新たに利用できます。

❌ アップデート前の課題

✗オーストラリア、インド、カナダのユーザーは、ローカル NVMe ストレージ付きの第 8 世代 Intel インスタンスを自国に近いリージョンで利用できなかった
✗データレジデンシー要件がある場合、これらの地域では前世代の C6id/M6id インスタンスなどを選択する必要があった
✗最新世代の性能を活用するには、リージョン間通信によるレイテンシー増加を許容する必要があった

✅ アップデート後の改善

✓C8id がシドニーとカナダ中部で利用可能になり、コンピュート集約型ワークロードを低レイテンシーで実行可能に
✓M8id がムンバイとカナダ中部で利用可能になり、汎用ワークロードで最新世代の性能を活用可能に
✓最大 43% の性能向上と 3.3 倍のメモリ帯域幅を、データレジデンシー要件を満たしながら利用可能に

🔧 主要機能

🌍 リージョン拡大の詳細

C8id: アジアパシフィック (シドニー)、カナダ (中部) リージョンに追加。M8id: アジアパシフィック (ムンバイ)、カナダ (中部) リージョンに追加。

⚡ 高性能プロセッサ

AWS でのみ利用可能なカスタム Intel Xeon 6 プロセッサを搭載。持続的な全コアターボ周波数 3.9 GHz、前世代の C6id/M6id と比較して最大 43% のコンピューティング性能向上と 3.3 倍のメモリ帯域幅を実現。

💾 大容量ローカルストレージ

最大 22.8 TB のローカル NVMe SSD ブロックストレージ。vCPU、メモリ、ローカルストレージがいずれも前世代の 3 倍。I/O 集約型データベースワークロードで最大 46% の性能向上、リアルタイムデータ分析で最大 30% 高速なクエリ結果。

🔀 柔軟な帯域幅設定

EC2 インスタンス帯域幅重み付け設定により、ネットワーク帯域幅と EBS 帯域幅を 25% の範囲で柔軟に調整可能。

🌐 EFA ネットワーキング

24xlarge、48xlarge、metal-24xl、metal-48xl サイズで Elastic Fabric Adapter を利用可能。

⚙️ 設定方法

前提条件

  • AWS アカウントと EC2 起動権限
  • 対象リージョン (シドニー、ムンバイ、カナダ中部) へのアクセス
  • 適切なサービスクォータの確認

ステップ 1: 利用可能なインスタンスタイプの確認

Bash シドニーリージョンで C8id インスタンスタイプを確認 
aws ec2 describe-instance-types \
  --filters "Name=instance-type,Values=c8id*" \
  --region ap-southeast-2 \
  --query "InstanceTypes[].{Type:InstanceType,vCPU:VCpuInfo.DefaultVCpus,Memory:MemoryInfo.SizeInMiB}" \
  --output table

ステップ 2: インスタンスの起動

Bash ムンバイリージョンで M8id インスタンスを起動 
aws ec2 run-instances \
  --instance-type m8id.4xlarge \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --subnet-id subnet-xxxxxxxxxxxxxxxxx \
  --security-group-ids sg-xxxxxxxxxxxxxxxxx \
  --key-name my-key-pair \
  --region ap-south-1

ステップ 3: 帯域幅重み付け設定の確認

Bash 帯域幅の重み付け調整のサポート状況を確認 
aws ec2 describe-instance-types \
  --instance-types c8id.24xlarge \
  --query 'InstanceTypes[0].NetworkInfo.BandwidthWeightingSupport' \
  --region ca-central-1

ネットワークまたは EBS の帯域幅を 25% の範囲で優先配分できます。

⚖️ メリットと制約事項

✅ メリット

✓低レイテンシーでの提供: オーストラリア、インド、カナダの国内ユーザー向けワークロードを地理的に近いリージョンで実行可能
✓データレジデンシー対応: 各国のデータ所在地要件を満たしながら最新世代を利用可能
✓コスト効率の向上: 最大 43% の性能向上により、少ないインスタンス数で同等以上のパフォーマンスを実現可能
✓高い I/O 性能: 最大 22.8 TB のローカル NVMe SSD による低レイテンシーなブロックレベルアクセス
✓帯域幅の柔軟な配分: ネットワークと EBS の帯域幅を 25% の範囲でワークロードに合わせて調整可能
✓EFA 対応: 24xlarge 以上の対象サイズでノード間通信が多い分散ワークロードにも対応

⚠️ 制約・考慮事項

•発表対象は C8id と M8id のみで、追加リージョンはファミリーごとに異なる (シドニーは C8id のみ、ムンバイは M8id のみ)
•EFA は 24xlarge、48xlarge、metal-24xl、metal-48xl の各サイズに限定
•前世代からの移行には AMI やドライバの互換性確認が必要
•ローカル NVMe SSD はエフェメラルストレージのため、インスタンス停止時にデータが失われる。永続保存には Amazon EBS との併用が必要
•ワークロード特性に応じて C8id と M8id を適切に選択する必要がある
•スポットインスタンス利用時は中断リスクを考慮した設計が必要

C8id がシドニーとカナダ中部で、M8id がムンバイとカナダ中部で利用可能になりました。カスタム Intel Xeon 6 プロセッサによる前世代比最大 43% の性能向上、3.3 倍のメモリ帯域幅、最大 22.8 TB のローカル NVMe SSD を、これらの地域のデータレジデンシー要件を満たしながら活用できます。対象リージョンで C6id/M6id などの前世代インスタンスや I/O 集約型ワークロードを運用している場合は、最新世代への移行を検討してください。
