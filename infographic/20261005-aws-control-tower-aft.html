AWS Control Tower - Account Factory for Terraform

🏗️ AFT の plan-only カスタマイズ実行サポート

変更を適用する前に terraform plan で安全にプレビュー — AFT 1.22.0 で導入
📅 リリース日: 2026 年 10 月 5 日
🔧 導入バージョン: AFT 1.22.0
🌏 リージョン: AFT 対応の全リージョン (東京含む)

📰 概要

AWS Control Tower Account Factory for Terraform (AFT) が、 plan-only カスタマイズ実行をサポートしました。 aft-invoke-customizations Step Functions ステートマシンの入力に "plan_only": true を指定するだけで、変更を適用せずに terraform plan のみを実行し、管理対象アカウントへの変更内容を事前にプレビューできます。

ロールアウト前の安全な検証、構成ドリフトの検出、CI/CD レビューワークフローへの統合が可能になり、 多数のアカウントを AFT で管理するエンタープライズ環境のガバナンスと運用の安全性が大きく向上します。

❌ Before: アップデート前の課題
  • カスタマイズ起動で常に完全な terraform apply が実行され、事前プレビュー不可
  • 多数アカウントへのロールアウト前に影響範囲を検証する安全な手段がない
  • 構成ドリフトを変更適用なしで検出することが困難
  • 「plan レビュー → 承認 → 適用」の Terraform ワークフローを CI/CD に組み込めない
✅ After: アップデート後の改善
  • "plan_only": true の追加だけで terraform plan を変更適用なしで実行
  • plan 結果を確認してから通常実行で適用する段階的で安全なロールアウト
  • 定期的な plan-only 実行で構成ドリフトを非破壊的に検出
  • plan の JSON 出力を専用 S3 バケットにエクスポートし CI/CD レビューや自動解析に活用

💡 plan_only パラメータの指定有無によって、AFT カスタマイズパイプラインの動作が terraform plan のみの実行と通常の terraform apply 実行に分岐します。plan 結果は S3 バケットまたは HCP Terraform の実行 UI でレビューでき、問題がなければ通常実行で変更を適用します。

⚡ 主要機能

📝 plan-only カスタマイズ実行

Step Functions 入力に "plan_only": true を指定すると、 apply の代わりに terraform plan のみを実行。 グローバルカスタマイズとアカウントカスタマイズの両方に適用され、既存の include / exclude フィルタ (全アカウント、OU、タグ、アカウント ID) と組み合わせて対象を柔軟に指定可能。 レビュー後に plan_only なしで再実行して変更を適用。

🪣 plan 出力の S3 エクスポート

AFT デプロイ時に AFT 管理アカウント内へ専用の plan-output S3 バケットを作成 (ディストリビューションを問わず常に作成)。KMS 暗号化、バージョニング有効、 パブリックアクセスブロック、書き込みは AFT カスタマイズビルドロールに限定。 Community Edition では plan JSON をデフォルトでエクスポート。TFC / TFE では aft_plan_output_export_enabled = true で有効化。 保持期間はデフォルト 30 日 (aft_plan_output_retention_days で変更可能)。

🌐 全 Terraform ディストリビューション対応

Terraform Community Edition (オープンソース)、HCP Terraform (Terraform Cloud)、 Terraform Enterprise のすべての AFT サポート対象ディストリビューションで動作。

🔧 AFT 1.22.0 のその他の改善 (バグ修正)

→ plan と apply が別々のファイルシステムで実行されるパイプラインで、Lambda デプロイアーカイブが apply 時に見つからずプロビジョニングが失敗する問題を修正
→ 新規 AFT デプロイで、ステートバケットのバージョニング有効化前にレプリケーションが設定され失敗する問題を修正

⌨️ Step Functions 入力例

JSON 特定アカウントを対象にした plan-only 実行 
{
  "include": [
    {
      "type": "accounts",
      "target_value": ["123456789012"]
    }
  ],
  "plan_only": true
}

123456789012 は対象の AWS アカウント ID に置き換えます。 OU やタグによる指定、exclude による除外も従来どおり併用できます。

🛠️ AFT デプロイ入力の設定変数 (TFC / TFE で S3 エクスポートを有効化)

HCL AFT デプロイ入力設定 
module "aft" {
  source = "github.com/aws-ia/terraform-aws-control_tower_account_factory"

  # ... 既存の設定 ...

  # plan 出力の S3 エクスポート (TFC / TFE のみ有効、CE ではデフォルトでエクスポート)
  aft_plan_output_export_enabled = true

  # エクスポートした plan 出力の保持日数 (デフォルト: 30)
  aft_plan_output_retention_days = 30
}

module "aft" {

AFT 管理アカウントで terraform apply を実行して AFT 自体を更新します。plan-output S3 バケットはこの更新時に自動的に作成されます。

2
カスタマイズの変更を Git リポジトリにプッシュ
Bash変更のプッシュ
git add .
git commit -m "Update account customizations"
git push origin main

この時点ではパイプラインは起動せず、次のステップで Step Functions から起動します。

3
plan-only 実行を開始
BashAWS CLI で Step Functions を起動
aws stepfunctions start-execution \
  --state-machine-arn arn:aws:states:ap-northeast-1:111122223333:stateMachine:aft-invoke-customizations \
  --input '{
    "include": [
      {"type": "accounts", "target_value": ["123456789012"]}
    ],
    "plan_only": true
  }'

対象アカウントのカスタマイズパイプラインは terraform plan のみを実行し、変更は適用されません。ARN のリージョン、アカウント ID、対象アカウント ID はご自身の環境の値に置き換えてください。

4
plan 結果をレビュー
Bashplan 出力の確認
# plan-output バケット名を確認してオブジェクトを一覧表示
aws s3 ls s3://<plan-output-bucket-name>/ --recursive

Community Edition では plan-output S3 バケットから JSON を取得してレビュー。HCP Terraform / Terraform Enterprise では実行 UI で確認できます。AWS CodePipeline のコンソールでパイプラインの実行状況も監視可能です。

5
問題がなければ通常実行で変更を適用
Bashplan_only なしで再実行
aws stepfunctions start-execution \
  --state-machine-arn arn:aws:states:ap-northeast-1:111122223333:stateMachine:aft-invoke-customizations \
  --input '{
    "include": [
      {"type": "accounts", "target_value": ["123456789012"]}
    ]
  }'

plan_only パラメータを含めずに再度ステートマシンを起動し、通常のカスタマイズ実行 (terraform apply) で変更をアカウントに適用します。

💡 メリット

💼 ビジネス面

✓変更リスクの低減: 多数のアカウントに影響する変更を適用前にプレビューでき、意図しない変更による障害リスクを大幅に低減
✓ガバナンスと監査性の向上: plan の JSON 出力が暗号化・バージョニングされた S3 に保存され、変更前レビューの証跡として監査に活用可能
✓運用の信頼性向上: 「plan → レビュー → 承認 → apply」の業界標準ワークフローをマルチアカウント管理に適用し、変更管理を標準化

⚙️ 技術面

✓ドリフト検出: 定期的な plan-only 実行で、実際の構成と Terraform コードの差異を非破壊的に検出
✓CI/CD 統合: plan JSON を S3 から取得して自動解析やレビュー自動化に組み込み可能
✓全ディストリビューション対応: CE、HCP Terraform、Terraform Enterprise で同じ方法で利用でき、運用手順の差異が少ない
✓簡単な導入: 入力に "plan_only": true を 1 行追加するだけ。既存の include / exclude フィルタもそのまま利用可能

⚠️ デメリット・制約事項

🚧 制限事項

⚠plan-only 実行は変更を適用しないため、適用には plan_only なしでの再実行が必要 (パイプラインが 2 回実行される)
⚠AFT が一度に起動できるカスタマイズは最大 5 件。多数のアカウント対象時は Step Functions が完了まで待機・ループ
⚠aft_plan_output_export_enabled は TFC / TFE のみに作用。Community Edition では plan JSON が常にエクスポートされる (無効化不可)
⚠利用には AFT 1.22.0 以降への更新が必要

🤔 考慮すべき点

⚠plan から apply までの間に対象アカウントの構成が変化した場合、plan 結果と実際の適用内容が異なる可能性
⚠plan 出力の保持期間はデフォルト 30 日。長期保存が必要な場合は aft_plan_output_retention_days の調整や別ストレージへの退避を検討
⚠plan JSON にはリソース構成の詳細が含まれるため、plan-output バケットへのアクセス権限は最小権限で管理

🎯 ユースケース

1️⃣ 大規模ロールアウト前の事前検証

シナリオ: 全 AFT 管理アカウントに適用するグローバルカスタマイズ (IAM ロールの追加など) を変更し、本番適用前に影響範囲を確認したい。

JSON全アカウント対象の plan-only 実行
{
  "include": [
    {"type": "all"}
  ],
  "plan_only": true
}

効果: 全アカウントの plan 結果を適用前にレビューでき、想定外のリソース変更や削除を事前に検出して、安全に段階的なロールアウトを計画できる。

2️⃣ 定期的な構成ドリフト検出

シナリオ: AFT 管理アカウントで、手動変更などにより Terraform コードと実際の構成に差異が生じていないかを定期的に確認したい。

JSONProduction OU 対象の plan-only 実行
{
  "include": [
    {"type": "ous", "target_value": ["Production"]}
  ],
  "plan_only": true
}

Amazon EventBridge Scheduler などで上記入力の Step Functions 実行を週次でスケジュールし、S3 にエクスポートされた plan JSON を Lambda で解析して差分があれば通知する。

効果: 変更を適用することなくドリフトを継続的に監視でき、ガバナンス違反や手動変更を早期に発見できる。

3️⃣ CI/CD レビューワークフローへの統合

シナリオ: カスタマイズリポジトリへのプルリクエストに対して、plan 結果をレビュー担当者が確認してから本番適用する承認フローを構築したい。

JSONタグ指定による plan-only 実行
{
  "include": [
    {"type": "tags", "target_value": [{"environment": "staging"}]}
  ],
  "plan_only": true
}

CI パイプラインからステージング相当のアカウント群に plan-only 実行を行い、S3 の plan JSON をプルリクエストにコメントとして添付。承認後に plan_only なしの実行で適用する。

効果: 業界標準の「plan レビュー → 承認 → apply」フローをマルチアカウントのアカウントカスタマイズに適用でき、変更管理の品質が向上する。

💰 料金・利用可能リージョン

💵 料金

AFT 自体の利用に追加料金はありません。AFT がデプロイ・利用する基盤サービス (AWS CodePipeline、AWS CodeBuild、AWS Step Functions、AWS Lambda、Amazon S3、Amazon DynamoDB、AWS KMS など) の使用量に応じた料金が発生します。

plan-only 実行に関連するコストは、plan-output S3 バケットのストレージ料金 (デフォルト 30 日保持)、 plan 実行ごとの CodeBuild / Step Functions / Lambda の実行料金です。plan と apply を分けて実行する運用では、 パイプライン実行回数が増える点に留意してください。

🌏 利用可能リージョン

AFT がサポートされているすべての AWS リージョンで利用可能です (東京リージョンを含む)。

🔗 関連サービス・機能

  • AWS Control Tower: マルチアカウント環境のセットアップとガバナンスを提供。AFT は Control Tower のアカウントファクトリーを Terraform で拡張
  • AWS Step Functions: aft-invoke-customizations ステートマシンとして plan-only 実行の起動ポイントを提供
  • AWS CodePipeline / AWS CodeBuild: AFT のカスタマイズパイプラインの実行基盤。plan-only 実行時は plan のみを実行
  • Amazon S3 / AWS KMS: plan の JSON 出力を保存する暗号化された plan-output バケットを提供
  • HCP Terraform (Terraform Cloud) / Terraform Enterprise: AFT がサポートする Terraform ディストリビューション。plan 結果を実行 UI で確認可能

📝 まとめ

AFT 1.22.0 で導入された plan-only カスタマイズ実行により、 マルチアカウント環境への Terraform 変更を適用前に安全にプレビューできるようになり、 事前検証、ドリフト検出、CI/CD レビューワークフローへの統合が可能になりました。

AFT を利用している環境では、モジュールを 1.22.0 以降に更新し、大規模な変更の前に "plan_only": true による事前検証を変更管理プロセスへ組み込むことを推奨します。
