Amazon GuardDuty

🛡️ 機密ファイル変更の脅威検出

Runtime Monitoring における Sensitive File Modification 検出
📅 リリース日
2026 年 7 月 1 日

📌 概要

Amazon GuardDuty の Runtime Monitoring に、機密ファイルが変更された際にセキュリティチームへ通知する 3 つの新しい脅威検出が追加されました。Amazon EC2、および EKS / ECS 上のコンテナワークロードを対象に、設定ファイル、認証設定、システムログといった重要なシステムファイルを監視します。

この検出は、システム侵害後の攻撃者活動 (post-compromise activity) を特定することを目的としています。攻撃者が永続的なアクセスを確立したり、権限を昇格させたり、検出を回避しようとする試みを識別します。

→5 つのファイル操作を直接監視することで、コマンドライン監視を回避する難読化された手法にも対応します。
→相関ベースの分析により正当な管理操作と区別し、誤検知を削減。MITRE ATT&CK の戦術マッピングと修復推奨を提供します。

❌ アップデート前の課題

  • 侵害後の機密システムファイル改ざんを専用検出で捉えることが難しかった
  • コマンドライン監視に依存する検出は難読化手法で回避される可能性があった
  • 正当な操作と悪意ある操作の区別が難しく誤検知が発生しやすかった

✅ アップデート後の改善

  • 永続化・権限昇格・防御回避の 3 戦術に対応した専用検出が利用可能に
  • ファイル操作を直接監視し難読化された手法も検出可能に
  • 相関ベースの分析で正当な操作と区別し誤検知を削減

⚡ 主要機能 - 3 つの検出タイプ

🔐 Persistence:Runtime/SensitiveFileModified 永続化

攻撃者がシステム上で永続的な実行権限を維持できる可能性のある機密ファイルの変更を検出します。

  • 新しい SSH キーファイルのインストール、ユーザー設定ファイルの変更
  • パスワードや shadow ファイルの変更
  • スケジュールされたタスクの作成、システム起動スクリプトの改ざん

デフォルト重要度: Medium

⬆️ PrivilegeEscalation:Runtime/SensitiveFileModified 権限昇格

攻撃者がシステム上で権限を昇格できる可能性のある機密ファイルの変更を検出します。

  • sudoers 設定、PAM 設定、システム認証ファイルの変更
  • 不正な root アクセス、認証メカニズムの弱体化につながる可能性
  • セキュリティ制御の侵害を検出

デフォルト重要度: Medium

🥷 DefenseEvasion:Runtime/SensitiveFileModified 防御回避

攻撃者がシステム上で検出を回避できる可能性のある機密ファイルの変更を検出します。

  • システムログファイル、監査設定、コマンド履歴ファイルの変更
  • 不正活動の隠蔽、セキュリティ監視の妨害
  • システム活動の証拠削除を検出

デフォルト重要度: Medium

🔧 技術仕様

監視対象の 5 つのファイル操作

ファイル操作を直接監視することで、コマンドライン監視を回避する難読化された手法にも対応します。

検出詳細の確認

→service.runtimeDetails.context フィールドに、変更されたファイルパスや操作タイプを含む詳細情報が格納されます。
→侵害された可能性のあるリソースは、GuardDuty コンソールの検出パネルの Resource type で確認できます。
→検出には MITRE ATT&CK の戦術マッピングと修復推奨が含まれます。

⚙️ 設定方法

前提条件

✓対象アカウントで Amazon GuardDuty が有効化されていること
✓EC2 / EKS / ECS のワークロードで GuardDuty Runtime Monitoring が有効化されていること
✓GuardDuty ランタイムエージェントが対象リソースにデプロイされていること

ステップ 1: Runtime Monitoring の有効化

機密ファイル変更の検出は Runtime Monitoring を有効化しているすべてのお客様に自動的に提供されます (追加設定不要)。

BashRuntime Monitoring 有効化
aws guardduty update-detector \
  --detector-id <detector-id> \
  --features '[{"Name":"RUNTIME_MONITORING","Status":"ENABLED"}]'

ステップ 2: 検出の確認

Bash検出結果の一覧表示
aws guardduty list-findings \
  --detector-id <detector-id> \
  --finding-criteria '{"Criterion":{"type":{"Eq":["Persistence:Runtime/SensitiveFileModified"]}}}'

ステップ 3: 通知の設定

→Amazon GuardDuty SNS トピックをサブスクライブすることで、新しい検出タイプが追加された際に自動的に通知を受け取れます。

🎯 ユースケース

1. SSH キーの不正追加による永続化の検出

シナリオ: 攻撃者が Web アプリの脆弱性を悪用して EC2 に侵入し、authorized_keys に自身の SSH 公開鍵を追加して永続的アクセスを確立しようとします。

🔍 Persistence:Runtime/SensitiveFileModified 📄 ~/.ssh/authorized_keys ⚙️ open-for-write

✅ 永続化の試みを早期に検出し、攻撃者がアクセスを維持する前に対応できます。

2. sudoers 変更による権限昇格の検出

シナリオ: 侵害されたコンテナ内で攻撃者が /etc/sudoers を変更し、低権限ユーザーに root 権限を付与しようとします。

🔍 PrivilegeEscalation:Runtime/SensitiveFileModified 📄 /etc/sudoers ⚙️ open-for-write

✅ 認証メカニズムの弱体化につながる操作を検出し、権限昇格を阻止できます。

3. ログ削除による防御回避の検出

シナリオ: 攻撃者が痕跡を隠すためにシステムログや監査設定を改ざん・削除し、セキュリティ監視を妨害しようとします。

🔍 DefenseEvasion:Runtime/SensitiveFileModified 📄 /var/log/ 配下 ⚙️ unlink

✅ 証拠隠滅の試みを検出し、インシデント調査に必要な情報を保全できます。

💡 メリット

📈 ビジネス面

  • インシデント対応の迅速化: 侵害後の攻撃者活動を早期に特定し被害拡大前に対応
  • コンプライアンス対応の強化: 重要ファイルの継続監視で監査要件への対応を支援
  • 運用負荷の削減: 誤検知削減により対応すべき検出に集中できる

🔧 技術面

  • 難読化への耐性: ファイル操作を直接監視するため難読化手法も検出
  • 包括的なカバレッジ: EC2 / EKS / ECS を単一サービスで一貫して監視
  • 実用的なインテリジェンス: MITRE ATT&CK マッピングと修復推奨で対応判断が容易

⚠️ デメリット・制約事項

制限事項

!検出には Runtime Monitoring の有効化とランタイムエージェントのデプロイが必要です
!デフォルト重要度は Medium。環境によっては重要度のカスタマイズを検討する必要があります
!運用の実態に応じた抑制ルールの検討が必要な場合があります

考慮すべき点

!Runtime Monitoring の利用には追加料金が発生します (新規ユーザー向けに 30 日間の無料トライアルあり)
!検出フィールドには攻撃者が制御し得る値 (ファイルパスなど) が含まれるため、コンソール外で処理する際は HTML エンコードなどのサニタイズが必要です

📝 まとめ

今回のアップデートは、侵害後の攻撃者活動を捉える 3 つの専用検出を GuardDuty Runtime Monitoring に追加し、永続化・権限昇格・防御回避という重要な攻撃戦術への可視性を高めます。ファイル操作を直接監視することで難読化された手法にも対応し、相関ベースの分析で誤検知を抑えます。

Runtime Monitoring を利用中の環境では追加設定なしで有効になるため、検出タイプの確認と通知設定を見直し、インシデント対応ワークフローへの組み込みを検討することを推奨します。
