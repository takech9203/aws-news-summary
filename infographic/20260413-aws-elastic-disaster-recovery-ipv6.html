AWS Elastic Disaster Recovery - IPv6 サポート

データレプリケーションおよびコントロールプレーン接続における IPv6 サポート
2026 年 4 月 13 日
AWS Elastic Disaster Recovery

📝 概要

AWS Elastic Disaster Recovery (AWS DRS) が、データレプリケーションおよびコントロールプレーン接続の両方で IPv6 をサポート。IPv6 のみ、またはデュアルスタックのネットワーク環境を運用しているユーザーは、レプリケーション設定で IPv6 を使用するよう構成でき、IPv4 アドレスの必要性を排除できます。

Before
  • すべてのレプリケーション/サービス通信で IPv4 が必須
  • IPv6 のみの環境では DR を構成不可
  • IPv4 アドレス枯渇への対応が困難
  • OMB M-21-07 等 IPv6 コンプライアンス要件を満たせない
  • IPv6 移行を進める組織で AWS DRS が障壁に
→
After
  • レプリケーション設定で IPv6 に変更するだけで有効化
  • IPv6 のみの環境でも DR 構成が可能
  • デュアルスタックエンドポイント経由で通信
  • 既存設定に影響なし、段階的移行が可能
  • IPv4 アドレス不要でコスト最適化

⭐ 主要機能

1. IPv6 対応のデータレプリケーション
📡ソースサーバーから AWS ステージングエリアへの通信で IPv6 使用可能
⚙️internetProtocol を IPV6 に設定で有効化
🌐デュアルスタックエンドポイント経由の通信
2. IPv6 対応のコントロールプレーン接続
🔌Replication Agent - DRS 間で IPv6 通信可能
📨サービス API の呼び出しも IPv6 経由
3. 既存環境との互換性
✅デフォルトは IPv4 が継続使用
✅個別/テンプレート単位で IPv6 に切替可能
⚠️IP 変更時は短い一時停止が発生

🔧 設定方法

📌 前提条件
✅AWS DRS 初期化済みリージョン
✅AWS Replication Agent インストール済み
✅サブネットが IPv6 をサポート
✅EC2 が IPv6 対応のリージョン
✅VPC/サブネットに IPv6 CIDR 関連付け済み
🖥️ 方法 1: コンソールから設定
  1. DRS コンソールにサインイン
  2. 「Source Servers」を選択
  3. 対象サーバーを選択 → 「Replication」
  4. 「Edit replication settings」を選択
  5. 「IP Version」で IPv6 を選択
  6. 「Save replication settings」で保存
📟 方法 2: CLI で個別サーバーを変更
Bash IPv6 に変更 
# 現在の設定を確認
aws drs get-replication-configuration \
  --source-server-id s-123456789abcdefgh

# IPv6 に変更
aws drs update-replication-configuration \
  --source-server-id s-123456789abcdefgh \
  --internet-protocol IPV6 \
  --staging-area-subnet-id subnet-123456789abcd
📄 方法 3: デフォルトテンプレートを変更
Bash テンプレート更新 
# デフォルトテンプレートを IPv6 に更新
aws drs update-replication-configuration-template \
  --replication-configuration-template-id \
    rct-123456789abcdefgh \
  --internet-protocol IPV6
⚠️ テンプレート変更は新規追加サーバーにのみ適用。既存サーバーには個別変更が必要。

✨ メリット

💼 ビジネス面
🏛️コンプライアンス対応: OMB M-21-07 等の IPv6 規制要件への準拠が容易に
🚀ネットワークモダナイゼーション: DR 環境が IPv6 移行の障壁にならない
💰コスト最適化: IPv4 パブリックアドレス課金 ($0.005/時間) を回避可能
⚙️運用の簡素化: IPv6 環境で DR を一元管理、構成の複雑さ軽減
🛠️ 技術面
🌐IPv6 ネイティブ: IPv6 のみの環境でも DR 構成可能
🔄デュアルスタック: 柔軟なネットワーク構成
⚡非破壊的変更: 短い一時停止のみ、フルシンク不要
📈段階的移行: サーバー単位で切替可能
🔒既存互換性: デフォルト IPv4 動作を維持

⚠️ デメリット・制約事項

🚫デュアルスタック対応サブネットが必須 - IPv4 のみのサブネットでは利用不可
🚫純粋な IPv6 のみは非対応 - デュアルスタックエンドポイントが使用される
🚫既存設定の自動更新なし - 個別に設定変更が必要
🚫リージョン制約 - EC2 が IPv6 対応のリージョンのみ
⚠️一時停止の発生 - IP 変更時にレプリケーション一時停止
⚠️フェイルバック考慮 - フェイルバック先も IPv6 サポート必要

💡 ユースケース

🏢 UC1: IPv6 のみの DC からの DR

IPv4 を廃止した DC から AWS への DR 構成。VPC に IPv6 CIDR を関連付け、デュアルスタックサブネットを作成して DRS の IPv6 レプリケーションを有効化。

📊 UC2: 大規模環境の段階的移行

数百台規模の環境で段階的に IPv6 移行。デフォルトテンプレートを IPv6 に変更し、新規サーバーは自動的に IPv6 を使用。既存サーバーはスクリプトで順次移行。

🌍 UC3: マルチリージョン DR の IPv6 統一

複数リージョンにまたがる DR 環境で、全リージョンのレプリケーション設定を IPv6 に統一。Python スクリプトで全リージョンのテンプレートとサーバーを一括更新。

📝 まとめ

AWS DRS が IPv6 をサポートしたことで、IPv6 のみまたはデュアルスタック環境でも DR を構成可能に。internetProtocol を IPV6 に設定するだけで有効化でき、既存設定には影響なし。IPv4 アドレス枯渇対策、コンプライアンス対応、ネットワークモダナイゼーションに有用。追加料金なしで全対応リージョンで即座に利用開始可能。
