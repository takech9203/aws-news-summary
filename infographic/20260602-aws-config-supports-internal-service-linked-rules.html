🔗 内部サービスリンクルール

Internal Service Linked Rules - AWS サービスが独立してリソース構成を評価する新機能

📅 2026-06-02

📋 概要

AWS Config が内部サービスリンクルールをサポート。AWS サービスが顧客の Config 設定に依存せず、独立してリソース構成を評価できるようになった。既存のサービスリンクレコーダー機能を拡張し、AWS Security Hub CSPM などの AWS サービスが、ルール評価を独自にデプロイ・管理できる基盤を提供する。

評価結果はルールをデプロイした AWS サービスに直接配信され、顧客への追加料金は発生しない。

🔄 Before / After 比較

❌ Before

  • AWS サービスが顧客の Config レコーダーに依存
  • 顧客管理ルールとサービス管理ルールが同一パイプラインで動作
  • 顧客が Config を有効化・設定していることが前提
  • サービスリンクルールの評価コストが顧客に課金

✅ After

  • AWS サービスが独立してリソース構成を評価可能
  • 顧客管理のレコーダー・ルールとは完全に独立して動作
  • 顧客の Config 設定不要で評価を実行
  • AWS Config から顧客への課金なし

⚡ 主要機能

🔗 内部サービスリンクルール

AWS サービスが AWS Config マネージドルールを使用してリソース構成を評価する仕組み。既存のサービスリンクレコーダー機能を拡張し、統合セキュリティ・コンプライアンス機能の基盤を提供する。

🔒 独立した動作

顧客管理の AWS Config レコーダーおよびルールとは完全に独立して動作。顧客の既存設定に影響を与えず、AWS サービスがサービス固有の評価を独自に管理する。

📤 評価結果の直接配信

ルールをデプロイした AWS サービスに評価結果を直接配信。AWS Config から顧客への追加課金なしで、サービス側が評価結果を活用したセキュリティ機能を提供する。

🛠️ 設定方法

内部サービスリンクルールは自動的にデプロイされるため、顧客側での追加設定は不要。以下は Security Hub CSPM を利用する場合の手順。

ステップ 1: Security Hub の有効化

Bash Security Hub を有効化 
aws securityhub enable-security-hub --enable-default-standards

ステップ 2: 内部サービスリンクルールの確認

Bash デプロイされたルールを確認 
aws configservice describe-config-rules \
  --filters '{"FilterName": "configRuleName", "FilterValue": "securityhub-"}'

ステップ 3: 評価結果の確認

Bash Security Hub ファインディングで結果確認 
aws securityhub get-findings \
  --filters '{"GeneratorId": [{"Value": "aws-config", "Comparison": "PREFIX"}]}'

🔐 権限モデル

内部サービスリンクルールは AWS サービスが所有し、顧客は読み取り専用でアクセスする。以下の API は権限不足エラーを返す。

JSON サービスリンクルールの保護ポリシー例 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Action": [
        "config:PutConfigRule",
        "config:DeleteConfigRule",
        "config:DeleteEvaluationResults"
      ],
      "Resource": "arn:aws:config:*:*:config-rule/aws-service-rule/*",
      "Condition": {
        "StringNotEquals": {
          "aws:PrincipalServiceName": "securityhub.amazonaws.com"
        }
      }
    }
  ]
}

✅ メリット

ビジネス面

✓ コスト削減: 内部サービスリンクルールの評価は顧客に課金されないため、セキュリティ評価のコストが軽減
✓ 運用負荷の軽減: AWS サービスが独自にルールを管理するため、顧客側での設定・メンテナンスが不要
✓ 統合セキュリティ: AWS サービスがネイティブにセキュリティ評価を実行し、包括的なコンプライアンス管理を実現

技術面

✓ 独立性: 顧客管理ルールと干渉しないため、安定した運用が可能
✓ スケーラビリティ: AWS サービスが必要に応じてルールを追加・更新可能
✓ 即時利用可能: AWS サービスを有効化するだけで、事前の Config 設定なしにリソース評価が開始

⚠️ デメリット・制約事項

制限事項

✗ 内部サービスリンクルールは読み取り専用であり、顧客が編集・削除できない
✗ ルールの評価対象やトリガー条件を顧客が個別にカスタマイズすることはできない
✗ 評価結果は AWS Config コンソールではなく、ルールをデプロイした AWS サービスのコンソールで確認が必要

考慮すべき点

⚠ アカウントあたりの Config ルール上限数にカウントされる可能性があるため、大規模環境では上限に注意
⚠ 顧客管理ルールと内部サービスリンクルールで同一リソースを評価する場合、結果の確認先が異なる

💡 ユースケース

🔒 Security Hub CSPM によるセキュリティ態勢管理

シナリオ: Config を明示的に設定していない環境でも、Security Hub CSPM を有効化するだけでセキュリティ評価を自動実行

効果: Config の事前設定なしに、Security Hub がリソース構成を評価し、セキュリティリスクを検出

🔄 既存の Config 運用との共存

シナリオ: カスタム Config ルールで独自のコンプライアンス基準を運用しつつ、AWS サービスによるセキュリティ評価も並行利用

効果: 既存の Config 運用を変更せずに、追加のセキュリティ評価を受けられる。相互に干渉しないため安定運用を維持

🏢 マルチアカウント環境でのセキュリティ統合

シナリオ: AWS Organizations で管理する複数アカウントにおいて、各アカウントの Config 設定状況に依存せず統一的なセキュリティ評価を実施

効果: Config 未設定のアカウントでもセキュリティカバレッジを確保。メンバーアカウント全体で統一的な評価を実行
