AWS Sign-in

🔐 コンソールサインインに
ネットワーク境界の制御を

リソースベースポリシーとリソースコントロールポリシー (RCP) のサポート
📅 2026 年 6 月 16 日

📌 概要

AWS Sign-in が、AWS マネジメントコンソールへのサインインに対して リソースベースポリシーおよび リソースコントロールポリシー (RCP) を適用できるようになりました。特定の VPC、VPC エンドポイント、IP アドレスからのサインインのみを許可するなど、想定したネットワークからのアクセスに制限できます。

リソースベースポリシーは個々のアカウント単位で、RCP は AWS Organizations を通じて組織全体に一括適用できます。これらはサインイン時だけでなく認証情報の更新時にも評価されるため、セッション途中の想定外アクセスも継続的に防止できます。

😣 アップデート前の課題

  • SCP / IAM 条件キー / VPC エンドポイントポリシーを組み合わせて間接的に実現する必要があった
  • アカウント / ネットワーク単位でサインイン経路を直接制限する統一的な仕組みがなかった
  • 組織全体にサインインのネットワーク境界を一括強制することが難しかった

🎉 アップデート後の改善

  • アカウント単位で許可ネットワークを宣言的に定義できる
  • RCP で組織全体に境界を一括強制できる
  • 認証情報の更新時にも評価され、セッション継続中のアクセスも防止できる

💡 ユーザーのサインインはネットワーク境界の条件でリソースベースポリシーまたは RCP で評価され、許可された場合のみコンソールアクセスが成立します。認証情報の更新時にも同じ評価が再度行われます。

⚙️ 主要機能

📄 リソースベースポリシーによるアカウント単位の制御

  • 個々の AWS アカウントごとに許可するネットワーク境界を定義
  • VPC ID、VPC エンドポイント、IP アドレスに基づき想定したサインインのみ許可
  • アカウントごとに異なるネットワーク要件を柔軟に表現できる

🏢 RCP による組織全体の制御

  • AWS Organizations を通じて全アカウントに境界を一括適用
  • 個々のアカウント管理者が緩和できない組織レベルのガードレール
  • 大規模マルチアカウント環境で一貫したサインイン境界を強制

🔄 サインイン時と認証情報更新時の継続的な評価

  • サインインの瞬間だけでなく、新しい認証情報の要求時にも評価
  • セッション継続中に条件を満たさなくなったアクセスも防止
  • Console Private Access と組み合わせ、ネットワーク境界とアカウント境界の双方を管理

🛠️ 設定方法

前提条件: 対象アカウント (RCP 利用時は AWS Organizations) が有効化され、ポリシー作成の管理者権限を保持し、許可するネットワーク境界が事前に整理されていること。

1

許可するネットワーク境界の整理

社内 IP アドレス範囲、Private Access の VPC エンドポイント、対象 VPC を洗い出し、許可する範囲を定義します。

2

リソースベースポリシーまたは RCP の作成

単一アカウントはリソースベースポリシー、組織全体は RCP を作成。整理した境界を条件として許可範囲を記述します。

3

ポリシーの適用と検証

対象アカウント / 組織に適用し、許可ネットワークからのサインイン成功と非許可ネットワークからの拒否、認証情報更新時の評価を検証します。

✨ メリット

💼 ビジネス面

  • コンプライアンス強化: 承認済み経路からのアクセスのみ許可しやすい
  • 追加コストなし: 全 AWS 商用リージョンで追加料金なし
  • 組織全体のガバナンス: RCP で一貫したサインイン境界を一元化

🔩 技術面

  • 宣言的な境界定義: VPC / エンドポイント / IP で経路を明示的に制御
  • 継続的な評価: 更新時にも評価され経路変更に対応
  • 既存機能との統合: Private Access と組み合わせて統合管理

⚠️ デメリット・制約事項

制限事項・考慮すべき点
  • 全 AWS 商用リージョンで利用可能だが、GovCloud (US) や中国リージョンの提供状況は別途確認が必要
  • 条件設定を誤ると正規ユーザーがサインインできなくなるおそれがある
  • 厳格な設定の前に緊急時のアクセス経路 (ブレークグラス手順) を確保することが望ましい
  • RCP は組織全体に影響するため、本番適用前にステージングや限定スコープで十分に検証する
  • VPC エンドポイントを条件とする場合は Private Access の構成と整合させる必要がある

企業がコンソールアクセスを社内オフィスや VPN 経由の既知の IP アドレス範囲のみに限定したい。

🔗 関連サービス・機能

  • AWS マネジメントコンソール Private Access: アクセス可能なアカウントを制御。本機能のネットワーク境界制御と組み合わせて利用
  • AWS Organizations: RCP を組織全体のアカウントに適用するための基盤
  • AWS IAM: サインインの認証・認可を担う。本機能がネットワーク境界の観点から補完

📝 まとめ

コンソールサインインをアカウント単位 (リソースベースポリシー) または組織全体 (RCP) でネットワーク境界に基づいて制御できるようになりました。追加料金なしで利用でき、認証情報の更新時にも継続的に評価されるため、漏洩時のリスク低減や境界の強制に有効です。Private Access と組み合わせ、ネットワーク境界とアカウント境界の双方を満たすアクセス制御の導入を検討してください。
