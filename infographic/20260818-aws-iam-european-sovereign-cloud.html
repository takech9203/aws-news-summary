AWS IAM / AWS STS

🔐 アウトバウンド ID フェデレーションが
AWS European Sovereign Cloud で利用可能に

📅 リリース日: 2026 年 8 月 18 日 | 🇪🇺 AWS European Sovereign Cloud (ドイツ) リージョン

📌 概要

AWS IAM のアウトバウンド ID フェデレーション機能が、AWS European Sovereign Cloud (ドイツ) リージョンで利用可能になりました。 ワークロードは IAM 認証情報を暗号学的に署名された短期間有効な JWT と交換し、サードパーティクラウド、SaaS プラットフォーム、セルフホスト型アプリケーションへ安全に認証できます。

AWS European Sovereign Cloud は、完全に EU 域内に配置された欧州のための独立したクラウドです。今回のアップデートにより、ソブリンティ (主権) 要件を持つ組織でも、長期認証情報や複雑な回避策なしに外部サービスと安全に連携できるようになりました。

❌ アップデート前の課題
  • 外部サービス認証に API キーやパスワードなどの長期認証情報をコードや環境変数に保存する必要があった
  • 漏洩リスクとローテーション運用の負担が大きく、セキュリティポスチャの低下要因に
  • ソブリンティ要件を満たしながらのマルチクラウド / ハイブリッド認証には複雑な回避策が必要だった
✅ アップデート後の改善
  • STS の GetWebIdentityToken API で短期間有効な JWT を取得し、外部サービスへ安全に認証
  • 長期認証情報の保存が不要になり、漏洩リスクとローテーション負担を軽減
  • IAM ポリシーによる統制と CloudTrail による監査証跡でコンプライアンス報告に活用可能

🏗️ アーキテクチャ図

sequenceDiagram
    participant W as ⚡ AWS ワークロード
    participant S as 🔐 AWS STS
    participant E as 🌐 外部サービス
    participant O as 🔑 OIDC ディスカバリエンドポイント

    W->>S: GetWebIdentityToken を呼び出し
    S->>S: リクエストを検証
    S-->>W: 署名付き JWT を返却
    W->>E: JWT を送信
    E->>O: 発行者 URL から検証キーを取得
    O-->>E: JWKS とメタデータを返却
    E->>E: 署名・有効期限・sub・aud を検証
    E-->>W: アクセスを許可

AWS European Sovereign Cloud 上のワークロードが STS から JWT を取得し、外部サービスがアカウント固有の OIDC ディスカバリエンドポイントで公開される検証キーを用いてトークンを検証する流れです。

⚙️ 主要機能

🎫 短期間有効な JWT による外部サービス認証
✓GetWebIdentityToken API を呼び出し、暗号学的に署名された JWT を取得
✓トークンは公開検証可能。外部サービスは well-known エンドポイントの AWS 検証キーで真正性を確認
✓サードパーティクラウド、SaaS、セルフホスト型アプリなど幅広い外部サービスで利用可能
🏷️ 豊富なコンテキスト情報を含むトークンクレーム
✓sub (ロール ARN など)、aud、iss、exp、iat、jti などの標準 OIDC クレームを含む
✓アカウント ID、ソースリージョン、プリンシパル ID などの AWS 固有メタデータも付与
✓タグをカスタムクレームとして追加し、外部サービス側で属性ベースのアクセス制御を実装可能
🛡️ IAM ポリシーによる統制と監査
✓アイデンティティポリシー、SCP、RCP、VPC エンドポイントポリシーでトークン生成を制御
✓条件キー sts:SigningAlgorithm / sts:IdentityTokenAudience / sts:DurationSeconds で署名アルゴリズム、オーディエンス、有効期間を強制可能
✓すべてのトークンリクエストを CloudTrail に記録し、完全な監査証跡を提供

GetWebIdentityToken API の主要パラメータ

項目詳細
APIsts:GetWebIdentityToken
AudienceJWT の aud クレームに設定される値
DurationSeconds60〜3,600 秒 (デフォルト 300 秒)
SigningAlgorithmES384 または RS256
Tagsカスタムクレームとして JWT に追加されるキーと値のペア (オプション)
発行者 URLアカウントごとに一意。/.well-known/openid-configuration と /.well-known/jwks.json を公開

IAM ポリシー例 (条件キーによる統制)

JSON オーディエンスと有効期間を制限する IAM ポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "sts:GetWebIdentityToken",
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "sts:IdentityTokenAudience": "my-external-service"
        },
        "NumericLessThanEquals": {
          "sts:DurationSeconds": "300"
        }
      }
    }
  ]
}

🛠️ 設定方法

前提条件

✓AWS European Sovereign Cloud リージョンのアカウントを利用していること
✓トークンを取得するワークロードに IAM ロールなどの AWS 認証情報が設定されていること
✓連携先の外部サービスが OIDC 準拠の JWT 検証 (発行者 URL の登録とクレーム検証) をサポートしていること

設定手順

1
アウトバウンド ID フェデレーションの有効化
IAM コンソールの [アカウント設定] から有効化します。AWS がアカウント固有の発行者 URL を生成し、OIDC ディスカバリエンドポイントを公開します。
2
IAM ポリシーで権限を付与
ワークロードのプリンシパル (実行ロールなど) に sts:GetWebIdentityToken の許可を付与し、必要に応じて条件キーでオーディエンスや有効期間を制限します。
JSON トークン取得の許可ポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "sts:GetWebIdentityToken",
      "Resource": "*"
    }
  ]
}
3
外部サービスに発行者 URL を登録
外部サービス側でアカウント固有の発行者 URL を信頼できる発行者として登録し、sub や aud などのクレーム検証ルールと権限マッピングを設定します。
4
ワークロードから JWT を取得
既存の AWS 認証情報で GetWebIdentityToken を呼び出し、取得した JWT を外部サービスへの認証に使用します。
Python boto3 による JWT 取得例 
import boto3

sts_client = boto3.client('sts')
response = sts_client.get_web_identity_token(
    Audience=['my-external-service'],
    SigningAlgorithm='ES384',
    DurationSeconds=300
)
jwt_token = response['WebIdentityToken']

💡 メリット

💼 ビジネス面

✓ソブリンティ要件との両立: EU 域内に完全に配置されたクラウドを利用しながら、外部サービスとの安全な連携が可能
✓コンプライアンス対応の強化: CloudTrail の完全な監査証跡と IAM ポリシーによる統制で、規制の厳しい業界の要件に対応
✓運用コストの削減: API キーの発行、保管、ローテーションといった長期認証情報の管理業務が不要に

🔧 技術面

✓セキュリティポスチャの向上: 有効期限の短い署名付きトークンで、認証情報漏洩時の影響範囲を最小化
✓きめ細かなアクセス制御: 豊富なクレームとカスタムタグで、外部サービス側の属性ベースアクセス制御を実現
✓標準技術による相互運用性: OIDC 準拠の JWT と JWKS エンドポイントで、幅広い外部サービスと標準的に連携

⚠️ デメリット・制約事項

制限事項

✗トークンの有効期間は 60〜3,600 秒の範囲に制限される
✗署名アルゴリズムは ES384 と RS256 のみサポートされる
✗連携先の外部サービスが OIDC 準拠の JWT 検証 (外部発行者の登録とクレーム検証) に対応している必要がある

考慮すべき点

⚠発行者 URL はアカウントごとに一意のため、複数アカウント構成では外部サービス側に各アカウントの発行者を登録する必要がある
⚠外部サービス側のクレーム検証設定 (特に aud と sub の検証) が不十分だと、意図しないワークロードにアクセスを許可するリスクがある
⚠トークン生成を許可するプリンシパルの範囲は、SCP や条件キーで最小権限に統制することを推奨

🎯 ユースケース

1️⃣ 外部クラウドプロバイダーのリソースへのアクセス

シナリオ: AWS European Sovereign Cloud 上の Lambda 関数がデータを処理し、結果を外部クラウドプロバイダーのストレージサービスに書き込む。

Python 外部クラウドストレージ向けトークン取得 
response = sts_client.get_web_identity_token(
    Audience=['external-cloud-storage'],
    SigningAlgorithm='ES384',
    DurationSeconds=300
)
# 取得した JWT を外部クラウドの認証エンドポイントに送信し、
# 外部クラウドの一時認証情報と交換してストレージに書き込む
✅ 効果: 外部クラウドの API キーを保存することなく、マルチクラウド構成のデータ連携を安全に実現できる。
2️⃣ SaaS 型オブザーバビリティプラットフォームとの統合

シナリオ: ソブリンティ要件を持つ企業が、AWS European Sovereign Cloud 上のワークロードのメトリクスを外部のオブザーバビリティ SaaS に送信する。

Python カスタムタグ付きトークン取得 
response = sts_client.get_web_identity_token(
    Audience=['observability-saas'],
    Tags=[{'Key': 'environment', 'Value': 'production'}],
    SigningAlgorithm='RS256',
    DurationSeconds=600
)
# JWT を SaaS の API に提示してメトリクスを送信する
✅ 効果: カスタムクレームにより SaaS 側で環境ごとのアクセス制御が可能になり、監視基盤との連携を安全に自動化できる。
3️⃣ オンプレミス Kubernetes クラスターとのハイブリッド連携

シナリオ: AWS European Sovereign Cloud 上のワークロードが、オンプレミスデータセンターの Kubernetes クラスターで稼働するコンテナアプリケーションと通信する。

💰 料金と利用可能リージョン

💵 料金

アウトバウンド ID フェデレーション機能は無料で利用できます。IAM および STS の利用自体に追加料金は発生しません。

🌍 利用可能リージョン

今回のアップデートにより、AWS European Sovereign Cloud (ドイツ) リージョンで利用可能になりました。

本機能は 2025 年 11 月の発表時点で、すべての AWS 商用リージョン、AWS GovCloud (US) リージョン、中国リージョンで利用可能となっており、今回 AWS European Sovereign Cloud にも拡大されました。

📝 まとめ

AWS European Sovereign Cloud 上のワークロードから外部サービスへの認証が、長期認証情報なしで実現できるようになりました。 EU のソブリンティ要件とマルチクラウド・ハイブリッド連携のセキュリティを両立できる重要なアップデートです。 AWS European Sovereign Cloud の利用を検討している組織は、外部サービス連携の認証方式としてアウトバウンド ID フェデレーションの採用を検討することを推奨します。
