🚀 M9g インスタンスが追加の 4 リージョンで利用可能に

📅 リリース日: 2026 年 11 月 25 日 | 北カリフォルニア・カナダ中部・サンパウロ・ソウルに拡大

📝 概要

AWS Graviton5 プロセッサを搭載した汎用インスタンス Amazon EC2 M9g が、新たに 米国西部 (北カリフォルニア)、カナダ (中部)、 南米 (サンパウロ)、アジアパシフィック (ソウル) の 4 リージョンで利用可能になりました。Graviton4 ベースの M8g と比較して最大 25% 高い性能を発揮し、データベースでは最大 30% の高速化を実現します。

M9g は第 6 世代の AWS Nitro System 上に構築され、形式検証によりワークロード分離を数学的に保証する Nitro Isolation Engine を初めて搭載したインスタンスファミリーです。 オープンソースデータベース、インメモリキャッシュ、ビッグデータ分析、アプリケーションサーバー、マイクロサービス、コンテナなど幅広いワークロードに適しています。

⚡ 主要機能

🧠 AWS Graviton5 プロセッサ

AWS が独自設計した第 5 世代カスタム CPU。M8g (Graviton4 ベース) 比でコンピューティング性能が最大 25% 向上し、データベースで最大 30% 高速化。常時有効なメモリ暗号化、vCPU ごとの専用キャッシュ、ポインタ認証をサポート。

🔒 第 6 世代 AWS Nitro System と Nitro Isolation Engine

第 6 世代の AWS Nitro System 上に構築。形式検証 (formal verification) を用いて、顧客ワークロードが他の顧客および AWS オペレーターから分離されていることを数学的に保証する Nitro Isolation Engine を初めて搭載。

🌐 4 リージョンへの提供拡大

米国西部 (北カリフォルニア)、カナダ (中部)、南米 (サンパウロ)、アジアパシフィック (ソウル) を追加。既存リージョンと合わせて、より多くの地域で Graviton5 ベースの汎用インスタンスを選択可能に。

ステップ 1: 対象リージョンでの利用可能状況を確認

Bash 提供サイズ一覧の確認 (例: ソウル) 
aws ec2 describe-instance-type-offerings \
  --region ap-northeast-2 \
  --filters "Name=instance-type,Values=m9g.*" \
  --query "InstanceTypeOfferings[].InstanceType" \
  --output table

リージョンごとに提供サイズが異なる場合があるため、利用前に確認してください。

ステップ 2: M9g インスタンスを起動

Bash m9g.xlarge の起動 
aws ec2 run-instances \
  --region ap-northeast-2 \
  --instance-type m9g.xlarge \
  --image-id <Arm 対応 AMI の ID> \
  --key-name <キーペア名> \
  --subnet-id <サブネット ID>

AMI は Arm アーキテクチャ対応のものを指定する必要があります。

ステップ 3: アプリケーションの動作確認と性能比較

Bash アーキテクチャの確認 
# アーキテクチャの確認
uname -m
# 出力例: aarch64

既存の M8g や x86 インスタンスと性能・コストを比較します。性能向上率はワークロードにより異なるため、実際のワークロードでの検証を推奨します。

💡 メリット

💼 ビジネス面

✓価格性能比の向上: M8g 比で最大 25% の性能向上により、より少ないインスタンス数・コストで処理できる可能性
✓データ所在地・低レイテンシー要件への対応: リージョンを変えずに最新世代へ移行可能
✓柔軟な購入オプション: Savings Plans、オンデマンド、スポット、Dedicated Instances / Hosts から選択可能

⚙️ 技術面

✓Graviton5 の性能向上: 汎用ワークロードで最大 25%、データベースで最大 30% の高速化
✓Nitro Isolation Engine: 形式検証に基づくワークロード分離の数学的保証
✓マルチリージョン構成の統一: 複数リージョンで同一インスタンスファミリーを採用しやすい

⚠️ デメリット・制約事項

🚧 制限事項

✗Arm (aarch64) アーキテクチャのため、x86 向けバイナリやコンテナイメージはそのままでは動作せず、再ビルドまたはマルチアーキテクチャ対応が必要
✗公式発表には各リージョンの提供インスタンスサイズの明記がないため、利用前に対象サイズの確認が必要
✗M9g は EBS のみのストレージ構成。ローカル NVMe SSD が必要な場合は M9gd を選択

🤔 考慮すべき点

⚠性能向上率 (最大 25% など) はワークロードにより異なるため、本番移行前に実際のワークロードでベンチマークを実施することを推奨
⚠商用ソフトウェアや監視エージェントを利用している場合は、Arm 対応状況を事前に確認
⚠スポットインスタンスは、新規追加リージョンでは当初キャパシティが限られる可能性

🔗 関連サービス・機能

🧩 AWS Graviton

M9g を支える Arm ベースのカスタムプロセッサファミリー。第 5 世代が Graviton5 です。

🛡️ AWS Nitro System

インスタンスの基盤となるハードウェアおよびソフトウェアのプラットフォーム。第 6 世代で Nitro Isolation Engine を搭載しています。

💾 Amazon EC2 M9gd インスタンス

M9g と同一スペックにローカル NVMe SSD を追加した兄弟ファミリー。低レイテンシーなローカルストレージが必要な場合の選択肢です。

🔙 Amazon EC2 M8g インスタンス

Graviton4 ベースの前世代インスタンス。移行時の性能比較の基準になります。

📌 まとめ

AWS Graviton5 搭載の M9g インスタンスが米国西部 (北カリフォルニア)、カナダ (中部)、南米 (サンパウロ)、アジアパシフィック (ソウル) の 4 リージョンに拡大し、これらの地域のワークロードでも M8g 比最大 25% (データベースでは最大 30%) の性能向上を活用できるようになりました。 対象リージョンで Graviton ベースの汎用インスタンスを運用しているお客様は、M9g への移行による性能とコストパフォーマンスの改善効果を検証することをお勧めします。
