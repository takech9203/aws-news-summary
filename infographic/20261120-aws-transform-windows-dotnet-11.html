🚀 AWS Transform for .NET
.NET 11 サポートと対応プロジェクトタイプの拡大

📅 リリース日: 2026 年 11 月 20 日 | VB.NET・デスクトップ・モバイル対応が一般提供に

📌 概要

AWS Transform for .NET が、モダナイゼーションのターゲットとして .NET 11 をサポートしました。あわせて、プレビュー提供だった VB.NET、デスクトップ、モバイルプロジェクトの対応が一般提供 (GA) となりました。

エージェント型 AI を活用して Windows 上のレガシー .NET アプリケーションをクロスプラットフォームの最新 .NET へ変換します。.NET Framework 3.5 以降と .NET 5 から 10 の両方を、C# と VB.NET のいずれのコードベースからでも .NET 11 へ移行できます。

❌ アップデート前の課題

✗変換ターゲットが従来の .NET バージョンに限られ、.NET 11 の性能や言語機能を変換と同時に活用できなかった
✗VB.NET プロジェクトの変換はプレビュー段階で、本番用途での採用判断が難しかった
✗WinForms、WPF などのデスクトップや Xamarin ベースのモバイルの変換もプレビュー段階だった

✅ アップデート後の改善

✓変換ターゲットとして .NET 11 を選択でき、最新ランタイムへの移行を一度のモダナイゼーションで完了
✓VB.NET の変換が GA となり、C# と VB.NET の両方を本番前提で移行可能に
✓デスクトップ (WinForms、WPF) とモバイル (Xamarin) の変換が GA となり、対応範囲が大幅に拡大

レガシー .NET Framework と .NET 5 から 10 のアプリケーションを AWS Transform for .NET が .NET 11 へ変換するフローです。デスクトップとモバイルを除く変換後のアプリケーションは Linux 上で実行でき、コスト削減につながります。

⚡ 主要機能

🎯 .NET 11 への変換サポート

→ モダナイゼーションのターゲットバージョンとして .NET 11 を選択可能

→ パフォーマンス改善、新しい C# 言語機能、強化された診断機能を変換後すぐに活用可能

→ .NET Framework 3.5 以降のレガシーと .NET 5 から 10 のモダンアプリの両方が変換元の対象

📘 VB.NET サポートの一般提供

→ プレビュー提供だった VB.NET コードベースの変換が GA に移行

→ C# と VB.NET の両言語で記述されたアプリケーションをモダナイズ可能

🖥️ デスクトップ・モバイルプロジェクトの一般提供

→ WinForms および WPF によるデスクトップアプリケーションの変換が GA に移行

→ Xamarin によるモバイルアプリケーションの変換が GA に移行

🧩 幅広いプロジェクトタイプへの対応

→ クラスライブラリ、コンソールアプリケーション、Windows サービス

→ ASP.NET Web プロジェクト (MVC、Web API、Web Forms)、Web サービス (ASMX、WCF)

→ 単体テスト (MSTest、NUnit、xUnit)

💡 メリット

💼 ビジネス面

✓運用コストの削減: Linux で実行することで、Windows ライセンス費用を含む運用コストを最大 40% 削減できる可能性
✓モダナイゼーションの加速: エージェント型 AI による自動変換で、手作業と比較してプロジェクト期間を短縮
✓追加費用なし: AWS Transform の .NET 変換機能は追加費用なしで利用可能

⚙️ 技術面

✓最新ランタイムの活用: .NET 11 のパフォーマンス改善、新しい C# 言語機能、強化された診断機能を利用可能
✓対応範囲の拡大: VB.NET、デスクトップ、モバイルを含む幅広いプロジェクトタイプが GA となり、多様な資産を一貫したワークフローで移行可能
✓レガシーとモダンの両対応: .NET Framework 3.5 以降に加え、.NET 5 から 10 のバージョンアップにも利用可能

⚠️ デメリット・制約事項

🚧 制限事項

⚠デスクトップ (WinForms、WPF) およびモバイル (Xamarin) アプリケーションは、変換後も Linux 上では実行できない
⚠AWS Transform が利用可能なリージョンは 8 リージョンに限られる (東京リージョンは利用可能)

🤔 考慮すべき点

⚠自動変換後もビルド確認やテストによる動作検証は必要であり、検証工程を移行計画に含める必要がある
⚠サードパーティ製ライブラリへの依存など、構成によっては追加の手動対応が発生する可能性がある

🎯 ユースケース

🌐 1. レガシー ASP.NET アプリケーションの Linux 移行

シナリオ: .NET Framework 4.x の ASP.NET MVC / Web Forms を Windows Server 上で運用し、ライセンスコストと EOL 対応が課題

実装例: .NET 11 へ変換し、Amazon ECS や AWS Fargate 上の Linux コンテナとしてデプロイ

効果: 運用コストを最大 40% 削減しつつ、最新ランタイムでパフォーマンスと保守性を向上

📘 2. VB.NET 資産のモダナイゼーション

シナリオ: 長年運用してきた VB.NET の業務アプリケーションの開発者確保や保守が年々困難に

実装例: GA となった VB.NET サポートでコードベースを最新の .NET 11 へ変換

効果: レガシー資産を本番前提のワークフローでモダナイズし、技術的負債と属人化リスクを低減

🔄 3. .NET 5 から 10 アプリケーションのバージョンアップ

シナリオ: .NET 6 や .NET 8 で稼働中のアプリをサポートライフサイクルに合わせて継続的に更新したい

実装例: 変換ジョブで .NET 11 をターゲットに指定し、依存関係の更新を含むバージョンアップを自動化

効果: 手作業によるアップグレード工数を削減し、最新の言語機能と診断機能を迅速に取り込み

📝 まとめ

AWS Transform for .NET が .NET 11 への変換に対応し、VB.NET・デスクトップ・モバイルのプロジェクトタイプも GA となったことで、Windows .NET 資産のモダナイゼーション対象が大きく広がりました。追加費用なしで利用でき、Linux 移行により最大 40% のコスト削減が見込めるため、レガシー .NET ワークロードを持つお客様はまず対象アプリケーションの棚卸しと変換の試行から着手することを推奨します。
