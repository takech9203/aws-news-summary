📌 概要

アイデアから動作するエージェントまでを数分で実現する、本番環境向けのマネージド実行基盤。エージェント構築が「コーディング」から「設定 (configuration)」へと変わります。

🧠 モデル
頭脳
何を考えるかを担う部分
⚙️ ハーネス
身体
オーケストレーションループの実行、ツール呼び出し、コンテキスト管理、状態の永続化、障害回復、セッション分離を担う

お客様はエージェントの動作 (モデル / ツール / スキル / 指示) を宣言するだけで、AgentCore が環境・コンピューティング・メモリ・ID・ネットワーク・可観測性を引き受け、設定を稼働中のエージェントへ組み立てます。基盤は AWS のオープンソースエージェントフレームワーク Strands Agents。

😓 アップデート前の課題

  • 本番環境では同時実行・セッション分離・ID・状態管理・スケーリングを各チームが自前で実装する必要があった
  • オーケストレーションループ (モデル呼び出し、ツール選択、結果の受け渡し、コンテキスト管理、障害処理) を手作業でコーディング
  • モデル変更やツール追加のたびにコードの書き換えが発生。可観測性や ID 管理も個別に組み込みが必要

🎉 アップデート後の改善

  • 本番品質のエージェントを、セッションごとに分離された安全な環境で数分以内に実行可能
  • 定義が「設定」に置き換わり、モデル切り替えやツール追加が設定変更だけで完結
  • ID・メモリ・可観測性が組み込み済み。すべての動作が最初の呼び出しからガバナンスとトレースの対象に

ユーザーやアプリケーションからの呼び出しを受けたハーネスが、設定に基づきオーケストレーションループを実行し、分離された microVM 上でモデルとツールを連携させながらエージェントを稼働させます。

✨ 主要機能

📝 設定によるエージェント定義

  • 動作 (モデル / ツール / スキル / 指示) を宣言するだけで、環境・コンピューティング・メモリ・ID・ネットワーク・可観測性を自動構成
  • 別モデルの試行や新ツールの追加が、コードの書き換えではなく設定変更で完結
  • オーケストレーションループ自体は AgentCore が実行するため、ループの実装が不要

🧱 セッションごとに分離された実行環境

  • すべてのセッションはデフォルトでステートフル。安全な分離 microVM 上で実行 (AgentCore runtime が基盤)
  • エージェントは独自のファイルシステムとシェルを持ち、コードの記述と実行が可能
  • 短期 / 長期メモリとファイルを、microVM セッションの期限切れ後もセッションをまたいで永続化

🤖 モデルの柔軟性とプロバイダーの動的切り替え

  • Amazon Bedrock、OpenAI、Google Gemini、LiteLLM 互換の任意プロバイダーを利用可能
  • コンテキストを失わずにセッション中にプロバイダーを切り替え可能 (計画は高性能モデル、実行は別モデルなど)
  • モデル未指定時のデフォルトは Anthropic Claude Sonnet 4.6 (Amazon Bedrock 上)

🔌 ツール連携とスキル

  • AgentCore Gateway、MCP サーバー、組み込みのブラウザ / コードインタープリター / Web 検索に接続
  • Git・S3・AWS 厳選のスキルカタログから AWS スキルを単一トグルでアタッチ
  • カスタム環境には独自コンテナ (BYOC) を持ち込み可能。S3 Files や EFS のマウントでデータ共有

🔍 可観測性、評価、安全なロールアウト

  • すべての動作が AgentCore observability で自動トレースされ、1 か所で統合確認
  • AgentCore evaluations と optimization により、スコアリング・プロンプト推奨・統計的有意性を伴う A/B テスト
  • イミュータブルなバージョンと名前付きエンドポイントで安全にロールアウト、即時ロールバックも可能

🔗 パイプライン統合とコードへのエクスポート

  • AWS Step Functions の AgentCore InvokeHarness ステートで、より大きなパイプラインに組み込み
  • 設定だけで不十分な場合、単一 CLI コマンドで Strands ベースのコードにエクスポート (Claude Agent SDK は近日対応予定)

🚀 設定方法 (クイックスタート)

前提条件

✓サポート対象リージョンで AWS 認証情報が構成されていること
✓CLI 利用時は Node.js 20 以上、SDK / boto3 利用時は Python 3.10 以上と boto3
✓ハーネスが引き受けられる IAM 実行ロール (最小権限はドキュメント参照)
📦 インストール
→
🛠️ create
→
☁️ deploy
→
▶️ invoke
Bashステップ 1: AgentCore CLI のインストール
npm install -g @aws/agentcore@preview
Bashステップ 2: ハーネスプロジェクトの作成
agentcore create --name myresearchagent --model-provider bedrock
Bashステップ 3: デプロイと呼び出し
agentcore deploy
agentcore invoke --harness myresearchagent \
  --session-id "$(uuidgen)" \
  "Research three tropical vacation options under $3k, within five hours of NYC."
Bash参考: AWS CLI でのハーネス作成
# 実行ロールを指定してハーネスを作成
aws bedrock-agentcore-control create-harness \
  --harness-name "MyHarness" \
  --execution-role-arn "arn:aws:iam::123456789012:role/MyHarnessRole"
💡 同じ --session-id を再利用すると同一環境内で会話を継続できます。なお runtimeSessionId は 33 文字以上である必要があります。get-harness をポーリングして "status": "READY" を待機します。

💡 メリット

📈 ビジネス面

✓市場投入までの時間短縮: 本番品質のエージェントを数分で実行
✓インフラ運用コスト削減: 同時実行・分離・スケーリングの自前構築が不要
✓ベンダーロックイン回避: 複数プロバイダーを横断し、価格性能比較を会話の再構築なしに実施

⚙️ 技術面

✓設定主導の開発: モデルやツールの変更が設定変更で完結、ループ再実装が不要
✓組み込みのガバナンスとトレース: ID・メモリ・可観測性が標準装備
✓安全なリリース運用: イミュータブルなバージョンと名前付きエンドポイントで段階ロールアウトと即時ロールバック

⚠️ デメリット・制約事項

制限事項

!コードエクスポート先は現時点で Strands ベースのコードのみ (Claude Agent SDK は近日対応予定)
!CLI には Node.js 20 以上、SDK には Python 3.10 以上が必要
!runtimeSessionId は 33 文字以上が必須

考慮すべき点

!microVM セッションには有効期限あり。保持したい状態はメモリやマウントストレージ (S3 Files / EFS) で永続化
!LiteLLM 互換を含む外部プロバイダー利用時は、各プロバイダーの認証情報や利用条件の管理を考慮

🎯 ユースケース

Use Case 1

本番運用するリサーチエージェントの迅速な構築

シナリオ: 複数ユーザーが同時利用するリサーチアシスタントを、インフラ構築の負担なく本番運用したい。

Bash
agentcore create --name researchagent --model-provider bedrock
agentcore deploy
agentcore invoke --harness researchagent --session-id "$(uuidgen)" \
  "条件に合う候補を 3 つ調査して比較してください。"

セッション分離・状態永続化・スケーリングをマネージド基盤に任せ、本番品質のエージェントを短時間で立ち上げ。

Use Case 2

モデルの価格性能テスト

シナリオ: 計画フェーズと実行フェーズで異なるモデルを使い分け、コストと品質のバランスを検証したい。

セッション内で、計画には高性能モデル、実行には低コストモデルへと、コンテキストを保持したままプロバイダーを切り替え。

会話を再構築せずプロバイダーを切り替えられ、価格性能の A/B テストを統計的有意性とともに評価。

Use Case 3

大規模ワークフローへのエージェント組み込み

シナリオ: 既存の業務パイプラインの一部として、エージェントによる処理を組み込みたい。

AWS Step Functions のステートマシンに AgentCore InvokeHarness ステートを配置し、前後のステップと連携。

エージェントをワークフローのステップとして扱え、可観測性とガバナンスを維持したまま既存の自動化に統合。

💰 料金・利用可能リージョン

料金

ハーネス自体に対する個別の料金は発生しません。利用した基盤となる AgentCore の各機能 (コンピューティング、メモリ、ツールなど) に対してのみ課金されます。

利用可能リージョン

AgentCore harness は、AgentCore が利用可能なすべての AWS 商用リージョンで一般提供されています。最新情報は AgentCore のリージョンドキュメントを参照してください。

🧩 関連サービス・機能

AgentCore Gateway AgentCore Runtime AgentCore Observability Strands Agents AWS Step Functions
  • AgentCore Gateway: セキュリティポリシーを適用したうえでツールにアクセスするゲートウェイ機能
  • AgentCore Runtime: セッションごとの分離 microVM を提供する実行基盤
  • AgentCore Observability: すべての動作を自動トレースし統合ビューで可視化
  • Strands Agents: ハーネスの基盤となる AWS のオープンソースエージェントフレームワーク
  • AWS Step Functions: InvokeHarness ステートでワークフローに組み込み

📝 まとめ

AgentCore harness の GA により、本番品質の AI エージェント構築が「インフラのコーディング」から「設定の宣言」へと大きく変わります。

モデルの柔軟な切り替え、組み込みのメモリ / ID / 可観測性、安全なバージョン管理が標準で提供されるため、運用負荷を抑えつつ迅速にエージェントを本番投入できます。まず AgentCore CLI でリサーチエージェントなどの小さなハーネスを作成し、デフォルトの Claude Sonnet 4.6 で挙動を確認したうえで、必要に応じてモデルやツール、スキルを設定で拡張していくことを推奨します。
