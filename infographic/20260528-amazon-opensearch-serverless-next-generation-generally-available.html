📋 概要

AWS は Amazon OpenSearch Serverless の次世代アーキテクチャ (NEXTGEN) の一般提供を発表した。AI エージェントを構築する顧客向けに設計されたフルマネージドの検索およびベクトルエンジンであり、コンピュートとストレージの完全な分離を新しい共有ストレージレイヤーによって実現する。

リソースベースエンドポイント (コレクションレベル / リージョナル) により、標準的な VPC API を使用したマルチ VPC やオンプレミスからの接続が容易になった。

🔄 Before / After 比較

❌ Before

  • オートスケーリングが遅く、予測不可能なワークロードに対応困難
  • コンピュートとストレージが密結合で固定コストが発生
  • VPC エンドポイント構成が複雑
  • AI 開発プラットフォームとのネイティブ統合なし
  • Scale-to-zero 不可でアイドル時もコスト発生

✅ After

  • 20 倍高速なオートスケーリング、数秒でプロビジョニング
  • Scale-to-zero で未使用時コストゼロ
  • コンピュート/ストレージ完全分離で独立スケーリング
  • リソースベースエンドポイントでネットワーク簡素化
  • Vercel / Kiro / OpenSearch Agent Skills とのネイティブ統合

🚀 主要機能

⚡ 20 倍高速なオートスケーリングと Scale-to-zero
  • 従来版比 20 倍高速なオートスケーリングを実現
  • 数秒でリソースプロビジョニング、予測不可能なワークロードに対応
  • Scale-to-zero でリクエストがない場合はコンピュートゼロに縮小
  • 使用量ベース課金 (pay-per-usage) で最大 60% コスト削減
🔀 コンピュートとストレージの完全分離
  • 新しい共有ストレージレイヤーによる完全なデカップリング
  • コンピュートの独立したスケールアップ/ダウンが可能
  • 低トラフィック時はコンピュート縮小、スパイクには即時対応
  • コレクショングループごとにオートスケーリング状態を可視化
🌐 リソースベースエンドポイント
  • コレクションレベルエンドポイント: 個別コレクションへの直接アクセス
  • リージョナルエンドポイント: リージョン内全コレクションへの一元アクセス
  • 標準 VPC API でマルチ VPC / オンプレミス接続を簡素化
  • 従来の VPC エンドポイント設定の複雑さを解消
🤖 AI 開発プラットフォーム統合
  • Vercel: Marketplace から直接 OpenSearch Serverless をプロビジョニング
  • Kiro: 自然言語コマンドで検索インフラを構築
  • OpenSearch Agent Skills: Claude Code / Cursor / Codex から OpenSearch 機能を利用
🛡️ 削除保護 (Deletion Protection)
  • コレクション単位で削除保護を有効化/無効化可能
  • 誤操作によるコレクション削除を防止

キャパシティ設定

JSON Scale-to-zero 対応キャパシティ設定 
{
  "capacityLimits": {
    "maxIndexingCapacityInOCU": 10,
    "maxSearchCapacityInOCU": 10,
    "minIndexingCapacityInOCU": 0,
    "minSearchCapacityInOCU": 0
  },
  "generation": "NEXTGEN"
}

最小キャパシティを 0 OCU に設定することで Scale-to-zero を実現する。

⚙️ 設定方法

前提条件

✓AWS アカウントと適切な IAM 権限
✓OpenSearch Serverless へのアクセス権限 (aoss:* ポリシー)
✓暗号化ポリシーとネットワークポリシーの設定

Step 1: NEXTGEN コレクショングループの作成

Bash NEXTGEN グループ作成 
aws opensearchserverless create-collection-group \
  --name "my-nextgen-group" \
  --generation "NEXTGEN" \
  --capacity-limits '{
    "maxIndexingCapacityInOCU": 10,
    "maxSearchCapacityInOCU": 10,
    "minIndexingCapacityInOCU": 0,
    "minSearchCapacityInOCU": 0
  }' \
  --description "Next generation collection group for AI agents"

Step 2: コレクションの作成

Bash ベクトルコレクション作成 
aws opensearchserverless create-collection \
  --name "my-vector-collection" \
  --type "VECTORSEARCH" \
  --collection-group-name "my-nextgen-group" \
  --deletion-protection "ENABLED" \
  --description "Vector search collection for RAG"

Step 3: オートスケーリング状態の確認

Bash 状態確認 
aws opensearchserverless batch-get-collection-group \
  --names "my-nextgen-group"

currentCapacity フィールドでオートスケーリング状態を確認。autoscalingStatus が ACTION_SCALING_UP、ACTION_SCALING_DOWN、または NO_ACTION で現在の状態を示す。

⚠️ 制約事項・注意点

制限事項

⚠GA 時点で利用可能なコレクションタイプは SEARCH と VECTORSEARCH の 2 種類のみ (TIMESERIES は未提供)
⚠CLASSIC から NEXTGEN へのインプレースマイグレーションは非対応の可能性あり (新規コレクショングループの作成が必要)
⚠Scale-to-zero からのコールドスタート時に数秒のレイテンシが発生する可能性

考慮すべき点

!既存の CLASSIC コレクショングループからの移行計画が必要
!Scale-to-zero 後の初回リクエストのレイテンシ要件を確認すべき
!リソースベースエンドポイントへの切り替え時の互換性確認

💡 ユースケース

🤖 AI エージェントの RAG バックエンド

予測不可能なトラフィックパターンを持つ AI エージェントのナレッジベースとしてベクトル検索を使用。夜間は自動的に Scale-to-zero し、ピーク時には 20 倍高速なオートスケーリングで即座に対応。従来比最大 60% のコスト削減を実現。

Bash RAG バックエンド構築例 
aws opensearchserverless create-collection-group \
  --name "agent-rag-group" \
  --generation "NEXTGEN" \
  --capacity-limits '{
    "maxIndexingCapacityInOCU": 20,
    "maxSearchCapacityInOCU": 20,
    "minIndexingCapacityInOCU": 0,
    "minSearchCapacityInOCU": 0
  }'

aws opensearchserverless create-collection \
  --name "agent-knowledge-base" \
  --type "VECTORSEARCH" \
  --collection-group-name "agent-rag-group" \
  --deletion-protection "ENABLED"

🌐 マルチ VPC 環境でのログ分析基盤

複数の VPC にまたがるマイクロサービス環境で、各サービスのログを一元的に検索・分析。リージョナルエンドポイントにより、VPC ごとの個別エンドポイント設定が不要に。標準 VPC API で既存ネットワーク設計に自然に統合。

Bash ログ分析基盤構築例 
aws opensearchserverless create-collection-group \
  --name "log-analytics-group" \
  --generation "NEXTGEN" \
  --capacity-limits '{
    "maxIndexingCapacityInOCU": 50,
    "maxSearchCapacityInOCU": 20,
    "minIndexingCapacityInOCU": 2,
    "minSearchCapacityInOCU": 1
  }'

aws opensearchserverless create-collection \
  --name "app-logs" \
  --type "SEARCH" \
  --collection-group-name "log-analytics-group"

💰 料金情報

次世代 OpenSearch Serverless は使用量ベースの課金モデルを採用。Scale-to-zero により未使用時のコストは発生しない。

使用パターン月額料金 (概算)
低トラフィック (Scale-to-zero 多用)従来比最大 60% 削減
中程度のトラフィックOCU 使用量に応じた従量課金
ピーク負荷時自動スケーリング分のみ課金
📌 ポイント: 従来のピーク負荷に合わせたプロビジョニング型と比較して最大 60% のコスト削減が可能。詳細は Amazon OpenSearch Service 料金ページ を参照。
