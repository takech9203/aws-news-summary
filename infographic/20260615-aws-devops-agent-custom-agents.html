AWS DevOps Agent

🤖 カスタム SRE エージェントと
MCP / A2A プロトコル対応

リリース日
2026 年 6 月 15 日

📌 概要

AWS DevOps Agent が大幅に機能拡張され、カスタム SRE エージェント、独自サブエージェントの持ち込み、そして MCP / A2A プロトコルによるヘッドレスアクセスに対応しました。チームは繰り返し発生する SRE ワークフローを自動化し、DevOps Agent を他のエージェントと連携させ、Kiro や Claude などの既存のコーディングアシスタントから機能を利用できます。

カスタム SRE エージェントは Agent Spaces 内で作成し、一定の周期で実行するようスケジュール設定できます。たとえば日次のデータベースヘルスレポートの生成や、過去 24 時間のログから異常を検出するエージェントを構築できます。さらにチャット機能の強化、インシデントスキップのサポート、メモリと Git 管理スキルによるナレッジ強化、品質追跡ダッシュボード、5 つの新リージョンも導入されました。

❌ アップデート前の課題
  • 機能はマネジメントコンソールの Agent Spaces 内でしか使えず、IDE や他ツールから呼び出せなかった
  • 日次ヘルスチェックなど定型的な SRE 作業を定期実行させる仕組みがなかった
  • 独自エージェントや外部フレームワークと連携する標準的な方法がなかった
✅ アップデート後の改善
  • MCP / A2A 経由で Kiro、Claude などからヘッドレスで呼び出せる
  • Agent Spaces 内でカスタム SRE エージェントをスケジュール実行し自動化できる
  • Amazon Bedrock や 3rd party 製の独自サブエージェントを A2A で接続できる

🏗️ アーキテクチャ図

開発者ツールは MCP/A2A 経由で DevOps Agent コアを呼び出し、DevOps Agent はカスタム SRE エージェントや独自サブエージェントと連携して SRE ワークフローを自動化します。

⚡ 主要機能

⏰ 1. カスタム SRE エージェント
  • Agent Spaces 内でエージェントを作成し、一定のカデンス (周期) で実行するようスケジュール設定
  • スロークエリやチューニング対象パラメータをチェックする日次データベースヘルスレポートを自動生成
  • 過去 24 時間のログをレビューして異常を検出するエージェントを構築
🔌 2. ヘッドレスアクセス (MCP / A2A)
  • A2A または MCP プロトコル経由で、すでに利用中のツールやエージェントから DevOps Agent を呼び出せる
  • Kiro power for AWS DevOps Agent により、IDE を離れずに本番ヘルス確認や問題調査を実行
  • Claude などのコーディングアシスタントからも機能を利用可能
🧩 3. 独自サブエージェント連携 (Bring-your-own)
  • Amazon Bedrock やサードパーティフレームワークで構築したサブエージェントを A2A 経由で接続
  • DevOps Agent を起点に、組織固有のエージェントを組み合わせた拡張ワークフローを構築
✨ 4. その他の機能強化
  • チャット機能の強化 / 顧客定義ルールに基づくインシデントスキップ
  • メモリ (memories) と Git 管理スキルによるナレッジの強化
  • 人手によるラベリングと顧客作成ダッシュボードでタスク品質を追跡
  • 5 つの新しいリージョンでの提供開始

🔧 技術仕様 - 連携プロトコル

MCP
Model Context Protocol。コーディングアシスタント等から DevOps Agent をツールとして呼び出すためのプロトコル。
A2A
Agent-to-Agent。独自サブエージェントや外部エージェントと DevOps Agent を相互接続するプロトコル。
項目詳細
カスタム SRE エージェント実行場所Agent Spaces 内
サブエージェント構築フレームワークAmazon Bedrock、サードパーティフレームワーク
サービスエンドポイント形式aidevops.{region}.amazonaws.com

※ 今回のアップデートに対応する awsapichanges.com 上の公開 API 変更情報は確認できませんでした。

🛠️ 設定方法

前提条件

→サポートされているリージョンで Agent Space を作成済みであること
→監視・調査対象の AWS アカウントが Agent Space に関連付けられていること
→ヘッドレス利用時は Kiro や Claude など MCP/A2A 対応クライアントを準備すること

導入ステップ

STEP 1 - カスタム SRE エージェントの作成とスケジュール設定

Agent Spaces のコンソールでエージェントを作成し、実行カデンス (例: 日次) を指定。データベースのスロークエリとチューニング対象パラメータを点検する日次ヘルスレポートを定義します。

STEP 2 - ヘッドレスアクセスの構成

利用中の IDE やコーディングアシスタントから MCP または A2A 経由で接続。Kiro の場合は Kiro power for AWS DevOps Agent を有効化し、IDE 内から本番ヘルス確認や問題調査を実行します。

STEP 3 - 独自サブエージェントの接続

Amazon Bedrock やサードパーティフレームワークで構築したサブエージェントを A2A 経由で接続し、組織固有の調査・自動化ワークフローを拡張します。

💡 補足: サードパーティ連携 (GitHub、GitLab などの CI/CD、Dynatrace、Datadog、New Relic、Splunk などの可観測性ツール、MCP サーバー) は Agent Space 単位で構成し、リージョンに依存しません。

📈 メリット

💼 ビジネス面

  • 運用工数の削減: 繰り返しの SRE 業務を自動化し、付加価値の高い作業へ集中
  • ツールチェーンの統合: 既存の IDE から利用でき、コンテキストスイッチを削減
  • 品質の可視化: ラベリングとダッシュボードでタスク品質を継続的に追跡

⚙️ 技術面

  • 標準プロトコル採用: MCP と A2A で幅広いツール・エージェントと相互運用
  • 拡張性: Bedrock やサードパーティの独自サブエージェントで柔軟に拡張
  • クロスリージョン監視: 作成リージョンに関わらず関連アカウント内の全リージョンを監視

⚠️ デメリット・制約事項

制限事項
  • 現時点でサポートされるリージョンは 11 リージョンに限られる
  • Agent Space とそのデータ (調査、トポロジー、推奨事項) は作成リージョンに保存されるため、データレジデンシー要件を考慮してリージョンを選択する必要がある
  • 公式発表ページに料金の詳細は明記されていない
考慮すべき点
  • カスタム SRE エージェントのスケジュール実行は、対象リソースや実行頻度に応じてコストや負荷に影響する可能性があるため設計時に考慮が必要
  • 独自サブエージェントを A2A で接続する場合、サブエージェント側の権限管理やセキュリティ設計を適切に行う必要がある

📝 まとめ

AWS DevOps Agent はカスタム SRE エージェントのスケジュール実行、MCP/A2A によるヘッドレスアクセス、独自サブエージェント連携を獲得し、定型的な SRE 業務の自動化と既存ツールチェーンへの統合が大きく前進しました。まずは日次ヘルスチェックなどのカスタムエージェントを試作し、Kiro や Claude からのヘッドレス利用を検証することを推奨します。東京を含む 11 リージョンで利用でき、データレジデンシー要件に合わせたリージョン選択も検討してください。
