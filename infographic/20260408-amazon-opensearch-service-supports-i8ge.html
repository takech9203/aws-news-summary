📋 概要

Amazon OpenSearch Service が Graviton4 プロセッサーを搭載した最新世代のストレージ最適化インスタンス i8ge をサポート。前世代の Graviton2 ベース Im4gn インスタンスと比較して、コンピューティング・ストレージ・ネットワークの全方位でパフォーマンスが大幅に向上しています。

最大 18xlarge サイズで 45 TB のインスタンスストレージと 112.5 Gbps のネットワーク帯域幅を提供し、ストレージ最適化インスタンスの中で最も高い値です。

Before / After

Before (Im4gn / Graviton2)

  • コンピューティング性能に限界
  • ストレージ I/O のレイテンシーとばらつきが大きい
  • 最大 30 TB / 100 Gbps に制限

After (i8ge / Graviton4)

  • コンピューティング性能が最大 60% 向上
  • I/O レイテンシー 60% 低減、ばらつき 75% 低減
  • 最大 45 TB / 112.5 Gbps に拡大

⚡ 主要機能

🚀 Graviton4 プロセッサーによる高性能コンピューティング

  • 前世代 Graviton2 ベース Im4gn と比較して最大 60% 優れたコンピューティングパフォーマンス
  • 検索クエリの処理速度やインデックス作成速度の向上
  • エネルギー効率の改善により、同等の処理能力をより低い消費電力で実現

💾 第 3 世代 AWS Nitro SSD による高速ストレージ

  • TB あたりのリアルタイムストレージパフォーマンスが最大 55% 向上
  • ストレージ I/O レイテンシーが最大 60% 低減
  • ストレージ I/O レイテンシーのばらつきが最大 75% 低減
  • より予測可能で安定したストレージパフォーマンスを提供

📦 大容量ストレージとネットワーク帯域幅

  • 最大 18xlarge サイズで 45 TB のインスタンスストレージ
  • 112.5 Gbps のネットワーク帯域幅 (ストレージ最適化インスタンスの中で最大)
  • 大規模データセットに対するリアルタイム検索と分析に最適

🔄 幅広い互換性

  • すべての OpenSearch バージョンをサポート
  • Elasticsearch 7.9 および 7.10 をサポート
  • 既存の OpenSearch ドメインで利用可能

⚙ 設定方法

ステップ 1: 新規ドメインで i8ge インスタンスを使用

Bash 新規ドメイン作成 
aws opensearch create-domain \
  --domain-name my-opensearch-domain \
  --engine-version OpenSearch_2.17 \
  --cluster-config \
    InstanceType=i8ge.2xlarge.search,InstanceCount=3 \
  --ebs-options EBSEnabled=false \
  --region us-east-1

i8ge.2xlarge インスタンスを 3 ノード構成で新しい OpenSearch ドメインを作成します。i8ge インスタンスはインスタンスストレージを使用するため、EBS は無効に設定しています。

ステップ 2: 既存ドメインのインスタンスタイプを変更

Bash インスタンスタイプ変更 
aws opensearch update-domain-config \
  --domain-name my-existing-domain \
  --cluster-config \
    InstanceType=i8ge.4xlarge.search,InstanceCount=3 \
  --region us-east-1

既存のドメインのインスタンスタイプを i8ge.4xlarge に変更します。Blue/Green デプロイメントにより、ダウンタイムなしで変更が行われます。

ステップ 3: ドメインの状態を確認

Bash ステータス確認 
aws opensearch describe-domain \
  --domain-name my-opensearch-domain \
  --query "DomainStatus.{Status:Processing,InstanceType:ClusterConfig.InstanceType,InstanceCount:ClusterConfig.InstanceCount}" \
  --region us-east-1

Processing が false になれば変更が完了しています。

✅ メリット

ビジネス面

  • コストパフォーマンスの向上: Graviton4 による高いコンピューティング効率とエネルギー効率で、同等の性能をより低コストで実現
  • 大規模データ対応: 最大 45 TB のインスタンスストレージにより、大規模ログデータや検索インデックスを効率的に格納・検索可能
  • 予測可能なパフォーマンス: I/O レイテンシーのばらつきが最大 75% 低減されることで、SLA 達成が容易に

技術面

  • 高速なクエリ処理: コンピューティング 60% 向上により、複雑な検索クエリやアグリゲーションの応答時間が改善
  • 安定したストレージ性能: 第 3 世代 Nitro SSD によるレイテンシーの低減とばらつき削減で一貫したパフォーマンスを実現
  • 高帯域幅ネットワーク: 112.5 Gbps でノード間のデータレプリケーションやリカバリが高速化
  • シームレスな移行: 既存 OpenSearch バージョンとの互換性により、アプリケーション変更なしにインスタンスタイプ変更が可能

⚠ デメリット・制約事項

制限事項

  • 利用可能なリージョンが 10 リージョンに限定。東京リージョンは対象外
  • EBS ボリュームは使用できず、インスタンスストレージのみ。ストレージ容量はインスタンスサイズに依存
  • インスタンスストレージはエフェメラルであるため、レプリケーション設定が重要

考慮すべき点

  • Im4gn からの移行時、データ量によっては Blue/Green デプロイメントに時間がかかる場合がある
  • 大容量ストレージに最適化されているため、小規模ドメインではコスト効率が最適ではない可能性がある
  • Graviton4 (Arm ベース) を使用するため、カスタムプラグインの Arm アーキテクチャ対応を確認する必要がある

🎯 ユースケース

📝 大規模ログ分析基盤

大規模 Web サービスを運営する企業が、数十 TB のアクセスログとアプリケーションログをリアルタイムで検索・分析

Bash i8ge.12xlarge x 6 ノード構成 
aws opensearch create-domain \
  --domain-name log-analytics \
  --engine-version OpenSearch_2.17 \
  --cluster-config \
    InstanceType=i8ge.12xlarge.search,InstanceCount=6,DedicatedMasterEnabled=true,DedicatedMasterType=r7g.2xlarge.search,DedicatedMasterCount=3 \
  --ebs-options EBSEnabled=false \
  --region us-east-1

-> 45 TB のストレージと I/O レイテンシー 60% 低減により、大量ログのリアルタイム検索の応答速度が大幅に向上

📈 オブザーバビリティプラットフォーム

マイクロサービスアーキテクチャ環境で、メトリクス・トレース・ログを OpenSearch で統合管理

Bash i8ge.4xlarge x 9 ノード / 3 AZ 構成 
aws opensearch create-domain \
  --domain-name observability-platform \
  --engine-version OpenSearch_2.17 \
  --cluster-config \
    InstanceType=i8ge.4xlarge.search,InstanceCount=9,ZoneAwarenessEnabled=true,ZoneAwarenessConfig="{AvailabilityZoneCount=3}" \
  --ebs-options EBSEnabled=false \
  --region eu-central-1

-> 安定したストレージパフォーマンスにより、リアルタイムダッシュボードとアラート検出のレイテンシーが改善

🔎 E コマース検索エンジン

数百万の商品カタログに対するリアルタイム検索を高速化し、ユーザー体験を向上

Bash i8ge.2xlarge x 6 ノード / 3 AZ 構成 
aws opensearch create-domain \
  --domain-name product-search \
  --engine-version OpenSearch_2.17 \
  --cluster-config \
    InstanceType=i8ge.2xlarge.search,InstanceCount=6,ZoneAwarenessEnabled=true,ZoneAwarenessConfig="{AvailabilityZoneCount=3}" \
  --ebs-options EBSEnabled=false \
  --region us-west-2

-> コンピューティング 60% 向上と I/O 最適化により、検索レスポンスタイムが短縮しコンバージョン率向上に寄与

💰 料金

i8ge インスタンスの料金はインスタンスサイズとリージョンによって異なります。ストレージ最適化インスタンスであるため、インスタンスストレージが含まれており、追加の EBS ボリューム料金は発生しません。

インスタンスタイプ 用途 月額料金 (概算)
i8ge.2xlarge.search 中規模ドメイン リージョンにより異なる
i8ge.4xlarge.search 大規模ログ分析 リージョンにより異なる
i8ge.18xlarge.search 超大規模データセット リージョンにより異なる

Graviton ベースのインスタンスは、同等の x86 ベースインスタンスと比較して一般的にコスト効率が高い傾向にあります。最新の料金は 公式料金ページ をご確認ください。
