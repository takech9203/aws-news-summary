☁️ AWS MCP Server (Agent Toolkit for AWS)

🌏 AWS MCP Server が 6 つの追加リージョンで利用可能に

リリース日: 2026 年 10 月 2 日 | 機能: リージョン拡大 (東京を含む 6 リージョン追加)

📝 概要

AWS MCP Server が新たに 6 つの AWS リージョンで利用可能になりました。追加されたのは、アジアパシフィック (シンガポール、シドニー、東京)、欧州 (アイルランド、ロンドン)、米国西部 (オレゴン) で、既存の 2 リージョンと合わせて合計 8 リージョンでの提供となります。

AWS MCP Server は、Agent Toolkit for AWS の一部として提供されるマネージド型の Model Context Protocol (MCP) サーバーです。AWS API への単一のインターフェイスを提供し、AI コーディングエージェントがサービスごとの個別インテグレーションを構築することなく、AWS サービスを発見して呼び出すことができます。

❌ Before: アップデート前の課題
  • バージニア北部とフランクフルトの 2 リージョンのみで提供
  • アジアパシフィックのユーザーは遠隔エンドポイント利用でレイテンシーが大きい
  • リクエストデータが国外で処理されるため、データレジデンシー要件を持つ組織では利用が困難
✅ After: アップデート後の改善
  • 東京を含む 6 リージョン追加でレイテンシーが低減
  • リクエストデータをリージョン内に保持でき、データレジデンシー要件への対応が容易
  • 8 リージョン稼働ながらすべての商用 AWS リージョンのサービスにアクセス可能

⚡ 主要機能

🌏 6 リージョンの追加

アジアパシフィック (シンガポール、シドニー、東京)、欧州 (アイルランド、ロンドン)、米国西部 (オレゴン) が追加。既存のバージニア北部、フランクフルトと合わせて合計 8 リージョンで利用可能。各リージョンに専用の HTTPS エンドポイントを提供。

🔌 AWS API への単一インターフェイス

AI エージェントが AWS サービスを発見し、API を呼び出すための統一されたインターフェイスを提供。サービスごとの個別インテグレーション構築が不要。インフラのプロビジョニング、ワークロードの検査、障害のデバッグに活用可能。

☁️ 全商用リージョンへのアクセス

MCP サーバーのエンドポイントは 8 リージョンで稼働。接続先のエンドポイントがどのリージョンであっても、すべての商用 AWS リージョンのサービスを操作可能。

🗺️ 利用可能リージョン (全 8 リージョン)

NEW 🗼 アジアパシフィック (東京) ap-northeast-1
NEW 🌏 アジアパシフィック (シンガポール) ap-southeast-1
NEW 🦘 アジアパシフィック (シドニー) ap-southeast-2
NEW ☘️ 欧州 (アイルランド) eu-west-1
NEW 🎡 欧州 (ロンドン) eu-west-2
NEW 🌲 米国西部 (オレゴン) us-west-2
既存 🏛️ 米国東部 (バージニア北部) us-east-1
既存 🏰 欧州 (フランクフルト) eu-central-1

💡 どのエンドポイントからでも、すべての商用 AWS リージョンのサービスにアクセスできます。

💡 メリット

💼 ビジネス面

✓データレジデンシー要件への対応: リクエストデータをリージョン内に保持できるため、国内でのデータ処理が求められる業界や組織でも AI エージェントの活用を進めやすい
✓開発者体験の向上: レイテンシーの低減により、エージェントを使った開発ワークフローの応答性が向上
✓グローバル展開の容易化: 米国、欧州、アジアパシフィックの主要リージョンをカバーし、分散した開発チームでも最寄りのエンドポイントを利用可能

⚙️ 技術面

✓低レイテンシー: 東京リージョンのエンドポイント利用で、日本国内からのアクセスのレイテンシーが大幅に低減
✓統一インターフェイス: サービスごとの MCP サーバーやカスタムインテグレーションを構築せずに、単一エンドポイントから AWS API 全般にアクセス可能
✓広範なサービスカバレッジ: どのエンドポイントに接続しても、すべての商用 AWS リージョンのサービスを操作可能

⚠️ デメリット・制約事項

🚧 制限事項

⚠サーバーが稼働するリージョンは 8 リージョンに限定される (他リージョンのサービス操作は可能)
⚠サービスクォータ (レート制限など) が設定されているため、大量のリクエストを行う場合はクォータドキュメントの確認が必要

🤔 考慮すべき点

⚠エージェントに付与する IAM 権限は最小権限の原則に従って設計する必要がある
⚠データレジデンシー要件がある場合は、利用するエンドポイントのリージョンを明示的に指定する運用ルールの整備が推奨される

🎯 ユースケース

🗼 ユースケース 1: 日本国内からの低レイテンシーなエージェント開発

シナリオ: 日本の開発チームが AI コーディングエージェントから AWS リソースの操作やデバッグを行う。

JSON MCP 設定例 (東京リージョン) 
{
  "mcpServers": {
    "aws-mcp": {
      "url": "https://aws-mcp.ap-northeast-1.api.aws/mcp"
    }
  }
}
✅ 効果: 東京リージョンのエンドポイント利用により、従来の米国・欧州エンドポイント利用時と比べてレイテンシーが低減され、エージェントの応答性が向上。
🏦 ユースケース 2: データレジデンシー要件のある環境での AI エージェント活用

シナリオ: 金融機関や公共機関など、リクエストデータの国内処理が求められる組織で AI エージェントを導入する。

実装例: エージェントの MCP 設定で東京リージョンのエンドポイント (aws-mcp.ap-northeast-1.api.aws/mcp) のみを許可し、リクエストデータをリージョン内に保持する。

✅ 効果: リクエストデータがリージョン内で処理されるため、データレジデンシー要件を満たしながら AI エージェントによる運用自動化を実現。
🌐 ユースケース 3: グローバル分散チームでの統一されたエージェント運用

シナリオ: 米国、欧州、アジアに開発拠点を持つ企業が、各拠点から AWS MCP Server を利用する。

実装例: 各拠点の最寄りエンドポイントを利用。

  • 🇺🇸 米国拠点: us-east-1 または us-west-2
  • 🇪🇺 欧州拠点: eu-central-1、eu-west-1、eu-west-2
  • 🌏 アジア拠点: ap-northeast-1、ap-southeast-1、ap-southeast-2
✅ 効果: 全拠点で同一のインターフェイスを利用しつつ、各拠点で低レイテンシーなアクセスを実現。

🔗 関連サービス・機能

🧰 Agent Toolkit for AWS

AWS MCP Server を含む、AI エージェント開発を支援するツール群。

🔌 Model Context Protocol (MCP)

AI エージェントと外部ツール・データソースを接続するためのオープンプロトコル。AWS MCP Server はこのプロトコルのマネージド実装。

🔐 AWS IAM

エージェントが AWS API を呼び出す際の認証・認可を担い、最小権限での運用に不可欠。

📌 まとめ

AWS MCP Server が東京を含む 6 リージョンに拡大され、日本のユーザーも低レイテンシーかつデータレジデンシー要件を満たした形で AI エージェントから AWS を操作できるようになりました。AI エージェントを活用した開発・運用を検討している場合は、東京リージョンのエンドポイント (aws-mcp.ap-northeast-1.api.aws/mcp) への切り替えを推奨します。
