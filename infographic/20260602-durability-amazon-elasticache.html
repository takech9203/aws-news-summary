同期書き込みでは Multi-AZ トランザクションログへの永続化確認後に応答、非同期書き込みでは即時応答後にバックグラウンドで永続化

📝 概要

Amazon ElastiCache for Valkey にデータ耐久性 (Durability) サポートが追加。マイクロ秒レベルの読み取りレイテンシーを維持しながら、データ損失を許容できないワークロードにも対応可能に。

Multi-AZ トランザクションログを活用し、複数の AZ にまたがるデータ永続化を実現。

🔄 Before / After

❌ Before
  • ノード障害時にデータ消失の可能性
  • 別途データベース併用が必須
  • 障害復旧時間が長い
  • 複雑なデータ同期機構が必要
✅ After
  • データ損失ゼロ or 最大 10 秒
  • ElastiCache 単独で利用可能
  • 高速フェイルオーバー復旧
  • 追加コストなしで非同期耐久性

🔒 同期書き込み

Sync

  • 応答前に 2 つの AZ にデータ永続化
  • ゼロデータロスを保証
  • 書き込みレイテンシー: 約 2.15ms (P50 @ 50K TPS)
  • 読み取りはマイクロ秒レベル維持

⚡ 非同期書き込み

Async

  • 即時応答後にバックグラウンドで永続化
  • 追加コストなし
  • マイクロ秒レベル書き込みレイテンシー維持
  • 障害時: 最大 10 秒分のデータ損失の可能性
  • DurabilityLag メトリクスで遅延監視

🔧 Multi-AZ トランザクションログ

  • 複数 AZ にまたがるログによるデータ永続化
  • プライマリ障害、レプリカ障害、シャード全体障害の全シナリオで復旧可能
  • 高速フェイルオーバー対応
  • データベースリカバリとノード再起動サポート

📊 パフォーマンスベンチマーク

テスト条件: r7g.4xlarge / Primary 1 + Replica 1 / 300 万キー / R/W 80/20

🛠️ API 変更

NEW Durability パラメータの追加 (19 メソッド)

リクエストパラメータ:

CreateReplicationGroup
ModifyReplicationGroup
Durability: 'default' | 'async' | 'sync' | 'disabled'

レスポンスに追加:

Durability - 設定された耐久性オプション
EffectiveDurability - 実際に適用中の耐久性

影響メソッド: CompleteMigration, DecreaseReplicaCount, DeleteReplicationGroup, DescribeReplicationGroups, IncreaseReplicaCount, ModifyReplicationGroupShardConfiguration, StartMigration, TestFailover, TestMigration, CopySnapshot, CreateSnapshot, DeleteSnapshot, DescribeSnapshots, CreateServerlessCache, DeleteServerlessCache, DescribeServerlessCaches, ModifyServerlessCache

⚙️ 設定方法

前提条件:

  • Valkey 9.0 以降
  • Multi-AZ 有効化
  • IAM 権限: CreateReplicationGroup, ModifyReplicationGroup
Bash 新規クラスター作成 (同期) 
aws elasticache create-replication-group \
  --replication-group-id my-durable-cluster \
  --engine valkey \
  --engine-version 9.0 \
  --cache-node-type cache.r7g.large \
  --num-cache-clusters 2 \
  --multi-az-enabled \
  --automatic-failover-enabled \
  --durability sync
Bash 既存クラスターの耐久性変更 
aws elasticache modify-replication-group \
  --replication-group-id my-existing-cluster \
  --durability async \
  --apply-immediately
Bash 耐久性ステータス確認 
aws elasticache describe-replication-groups \
  --replication-group-id my-durable-cluster \
  --query "ReplicationGroups[0].{Durability:Durability,EffectiveDurability:EffectiveDurability}"

✅ メリット

ビジネス面:

  • ユースケース拡大: AI, 決済, 在庫管理等に対応
  • アーキテクチャ簡素化: 別途 DB 不要に
  • ゼロデータロス保証: コンプライアンス対応

技術面:

  • 読み取りレイテンシーへの影響最小限
  • 同期/非同期を柔軟に切り替え可能
  • 全障害シナリオで自動復旧

⚠️ デメリット・制約事項

制限事項:

  • 同期: 書き込みレイテンシーが us → 約 2-3ms に増加
  • 非同期: 障害時に最大 10 秒のデータ損失の可能性
  • レプリカは結果整合性
  • Valkey 9.0 以降が必須 (Redis 不可)

考慮点:

  • 同期 100K TPS 時: 読み取り 260us → 879us に上昇
  • DurabilityLag > 10s で書き込み一時拒否
  • クロス AZ ネットワーク RTT が毎回発生 (同期)
  • Valkey GLIDE + リトライ実装を推奨

📌 まとめ

Amazon ElastiCache for Valkey への耐久性サポートは、インメモリデータストアの適用範囲を大幅に拡大する重要なアップデート。同期書き込みによるゼロデータロスと非同期書き込みによるコスト最適化の 2 つのオプションにより、AI エージェント、決済システム、在庫管理などのミッションクリティカルなワークロードに ElastiCache を直接適用可能に。既存の Multi-AZ クラスターへの適用も API 一つで切り替え可能であり、早期の検証と導入が推奨される。
