Kiro CLI 2.22.0 — Fullscreen Chat and Streamlined Sessions

📝 概要

AWS が提供する AI 搭載 IDE「Kiro」の CLI バージョン 2.22.0 がリリースされました。 チャットを専用のターミナル画面に拡大できるフルスクリーンチャット、 コントロールとセッション一覧を分離したV3 セッションダッシュボード、 そして長時間実行作業の信頼性向上という 3 つの主要な改善が導入されています。

🖼️
フルスクリーンチャット
/fullscreen で会話を専用のターミナル画面へ。TUI / Lite、V2 / V3 の両方に対応
📋
セッションダッシュボード V3
検索・フィルター・ソート・グルーピングを一覧から分離。ソート条件を記憶
🛡️
長時間実行の信頼性
コンパクション中の表示継続、大きなツール結果のコンテキスト節約、メモリ削減
❌ アップデート前の課題
  • チャット表示がシェル履歴と同じインライン画面に限定され、長い会話がシェルの他の出力と混在
  • /sessions はコントロールと一覧が一体化し、ソート条件の選択肢や記憶が限定的
  • 自動コンパクション中は進行中の応答や Thinking インジケーターの表示が中断される場合があった
  • V3 で大きなツール結果がそのままコンテキストを消費し、長時間セッションを圧迫
  • 重いサブエージェント活動中に TUI のメモリ使用量が増大
✅ アップデート後の改善
  • /fullscreen でシェル履歴から独立したスクロール可能な専用ビューを利用可能に
  • V3 の /sessions が最終利用日時・セッション名・メッセージ数によるソートと選択の記憶に対応
  • コンパクション中も応答と Thinking が表示され続け、キューのプロンプトも継続
  • 大きなツール結果はセッションと共に保存し、モデルには短いプレビューのみを提供
  • 重いサブエージェント活動中の TUI メモリ使用量を削減

/fullscreen コマンドによるインライン表示とフルスクリーン表示の相互切り替えと、/settings による既定動作の設定を示しています。フルスクリーンチャットはインタラクティブな TUI セッションと Lite セッションの両方で、V2 と V3 の両ハーネスに対応しています。

⚡ 主要機能

🖼️ フルスクリーンチャット
  • /fullscreen と入力すると、現在の会話がシェル履歴から独立した専用のターミナル画面へ移動し、独自のスクロール可能なビューで表示される
  • もう一度 /fullscreen と入力するとインライン表示に戻る
  • インタラクティブな TUI セッションと Lite セッションの両方で利用でき、V2 と V3 の両方に対応
  • マウス、タッチパッド、キーボードでスクロールでき、クリックしてドラッグすることで選択したテキストをコピーできる
  • 今後の TUI セッションをフルスクリーンで開始するには /settings → Display → Start fullscreen をオンにする
📋 合理化されたセッションダッシュボード V3
  • /sessions が検索、フィルター、ソート、グルーピングの各コントロールをセッション一覧から分離
  • 最終利用日時順のフラットな一覧として開く
  • 最終利用日時、セッション名、メッセージ数によるソートに対応し、選択したソート条件を記憶する
  • Tab キーでコントロールと結果の間を移動できる
🛡️ 長時間実行作業の信頼性向上
  • コンパクションの継続性: 自動コンパクション中もアクティブな応答と Thinking インジケーターが表示され続け、キューに入れたプロンプトはコンパクション後も継続される
  • 大きなツール結果 V3: 大きな結果をセッションと共に保存し、モデルには短いプレビューを渡すことで、完全な出力を失わずにコンテキスト使用量を削減
  • 固定パスインストール: ストレージ制約のある環境向けに KIRO_SKIP_BINARY_PINNING=1 を設定可能。インストーラーがセッション中にバイナリを置換・削除しうる場合は使用しない
  • 長時間セッション: 重いサブエージェント活動中の TUI のメモリ使用量を削減

🔧 修正 (Fixes)

✓--require-mcp-startup が非インタラクティブな V3 実行の開始前に MCP サーバーの起動を待機し、失敗時は終了コード 3 で終了
✓応答停止直前に完全なツール呼び出しが到着した場合でも V3 がターンを継続
✓プロキシが認証情報を要求する場合、V3 がプロキシ認証の失敗を直接報告
✓Configuration Sync カードは同期が有効な場合のみ表示、セッション再開時に前のターンと分離して表示
✓シンボリックリンクされた V3 エージェント設定が、相対パスの file:// プロンプトを設定ファイルの場所から解決
✓V3 の /context がフロントマターのないグローバル / ワークスペースの Steering ファイルを含める
✓V3 のカスタムエージェントが Git ワーキングツリー内のコマンドで正しい作業ディレクトリを使用
✓/settings 画面から戻ると前の行が復元され、Status line から Esc で Display に戻る
✓リプレイ / 再開トランスクリプトで余分な空行なしにターンの区切り線を配置
✓Thinking の後にツール呼び出しが続く場合、空のアシスタント応答マーカーなしで描画
✓長いシェルコマンドで Ctrl+O のヒントが 1 つだけ表示
✓拡張子が正しくない場合でも、画像添付ファイルは検出されたフォーマットで扱われる

🛠️ 設定方法

前提条件: Kiro CLI がインストール済みで、2.22.0 以降にアップデートされていること。セッションダッシュボードの改善は V3 が対象です。

1
フルスクリーンチャットに切り替える
Kiro CLIチャット内で入力
# Kiro CLI のチャット内でフルスクリーン表示に切り替える
/fullscreen

会話が専用のターミナル画面へ移動し、シェル履歴から独立したスクロール可能なビューで表示されます。もう一度入力するとインライン表示に戻ります。

2
TUI セッションを常にフルスクリーンで開始する
Kiro CLI設定メニュー
# 設定メニューを開く
/settings

「Display」を選択して「Start fullscreen」をオンにすると、以降のインタラクティブ TUI セッションはフルスクリーンで開始されます。

3
合理化されたセッションダッシュボードを使う
Kiro CLIセッションダッシュボード
# セッションダッシュボードを開く
/sessions

最終利用日時順のフラットな一覧が表示されます。Tab キーでコントロールと結果の間を移動し、最終利用日時・セッション名・メッセージ数でソートできます。選択したソート条件は記憶されます。

4
非インタラクティブ実行で MCP サーバーの起動を保証する
BashV3 非インタラクティブ実行
# MCP サーバーの起動を待ってから V3 の非インタラクティブ実行を開始する
kiro-cli chat --require-mcp-startup "プロンプト"

設定済みの MCP サーバーが起動するまで実行の開始を待機し、起動に失敗した場合は終了コード 3 で終了します。CI/CD などの自動化環境で MCP ツールへの依存を確実にできます。

💡 メリットと制約事項

📈 ビジネス面のメリット
  • 長い会話のレビュー効率向上: 長い応答やコードレビューをシェル出力と混在させずに閲覧でき、確認時間を短縮
  • 過去セッションへのアクセス改善: ソート条件の選択と記憶により、目的のセッションを素早く再開
  • 自動化パイプラインの信頼性向上: 終了コード 3 で MCP サーバー起動失敗を CI/CD で確実に検知
⚙️ 技術面のメリット
  • コンテキスト効率の向上: 大きなツール結果はセッション側に保存し、モデルには短いプレビューのみを提供
  • コンパクション中の作業継続: 応答と Thinking が見え続け、キューのプロンプトも継続されるため流れが途切れない
  • リソース使用量の削減: 重いサブエージェント活動中の TUI メモリ使用量が削減され、安定性が向上
⚠️ 制限事項
  • 合理化されたセッションダッシュボードは V3 が対象
  • 大きなツール結果の保存とプレビュー化は V3 のみの動作
  • KIRO_SKIP_BINARY_PINNING=1 は、セッション中にインストーラーがバイナリを置換・削除しうる環境では使用できない
🤔 考慮すべき点
  • フルスクリーンチャットは専用画面に移動するため、シェルの他の出力と並べて参照したい場合はインライン表示との使い分けが必要
  • --require-mcp-startup 使用時は、起動失敗が終了コード 3 として返るため、既存の自動化スクリプトの終了コード処理を確認する必要がある

🎯 ユースケース

1️⃣ 長いコードレビューをフルスクリーンで確認する

シナリオ: エージェントに大規模なリファクタリングを依頼し、複数ファイルにわたる長い差分の説明が返ってきた。シェル履歴と混ざった画面ではスクロールしながらの確認が難しい。

実装: /fullscreen で専用画面に切り替え、マウスやキーボードでスクロールしながら確認し、必要な箇所をドラッグしてコピー。確認後、/fullscreen でインライン表示に戻る。

効果: シェル履歴から独立したスクロール可能なビューで長い応答を落ち着いて確認でき、必要なテキストのコピーも容易になる。

2️⃣ 多数のセッションから目的の作業を素早く再開する

シナリオ: 複数のプロジェクトで多数のセッションを並行して使っており、メッセージ数の多い主要セッションや直近使ったセッションを素早く見つけたい。

実装: /sessions でダッシュボードを開き、Tab でソートコントロールに移動してメッセージ数または最終利用日時でソート。選択したソート条件は次回以降も記憶される。

効果: フラットな一覧と記憶されるソート条件により、目的のセッションを探す手間が減り、作業の再開が速くなる。

3️⃣ MCP ツールに依存する自動化ジョブを確実に実行する

シナリオ: CI/CD パイプラインで Kiro CLI の非インタラクティブ実行 (V3) を使っており、MCP サーバー経由のツールが利用できない状態でジョブが進行してしまうことを防ぎたい。

BashCI/CD での実行例
kiro-cli chat --require-mcp-startup "テスト結果を分析してレポートを作成して"
# 終了コード 3 の場合は MCP サーバーの起動失敗としてジョブを失敗させる

効果: MCP サーバーの起動完了を待ってから実行が開始され、起動失敗は終了コード 3 で検知できるため、不完全な状態での自動実行を防止できる。

📌 まとめ

Kiro CLI 2.22.0 は、/fullscreen による専用画面での会話閲覧、 コントロールと一覧を分離した V3 セッションダッシュボード、 そしてコンパクション継続性や大きなツール結果のプレビュー化といった長時間実行の信頼性向上を組み合わせた、日々の CLI 利用体験を高めるアップデートです。

長い応答を扱う機会が多いユーザーは、まず /fullscreen を試し、常用する場合は /settings の Display で「Start fullscreen」を有効化することを推奨します。
