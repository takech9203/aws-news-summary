機能: Intelligent-Tiering

📌 概要

AWS は、Amazon FSx for Lustre の Intelligent-Tiering ストレージクラス を新たに 13 の AWS リージョン で利用可能にしました。クラウドで最も低コストかつ唯一の 完全エラスティック (弾力的) な Lustre ファイルストレージを、より多くの地域で利用できます。

ホットデータとコールドデータが混在し、常に SSD レベルの速度を必要としないワークロードを対象とし、 アクセスパターンに基づき 3 つのティア へ自動的にデータを移動させて、コストとパフォーマンスを両立します。

⛔ アップデート前の課題
  • 一部リージョンで Intelligent-Tiering が使えず、SSD ベースのストレージクラスを選ぶしかなかった
  • データレジデンシー要件がある場合、特定リージョンで完全エラスティックな Lustre を使えなかった
  • 低頻度アクセスのデータも SSD に保持する必要があり、コスト最適化が難しかった
➡
✅ アップデート後の改善
  • 13 の追加リージョンでコスト最適化されたストレージを選択可能に
  • 事前プロビジョニング不要、保存データ量のみ課金のエラスティックモデルを広範に利用可能
  • 自動ティアリングで対象リージョンでもコールドデータのコストを大幅削減

⚙️ 主要機能

🔄 自動ティアリング

アクセスパターンに基づき Frequent Access / Infrequent Access / Archive の 3 ティア間でデータを自動移動。アクセス頻度の高いデータは高速ティアへ、低いデータは低コストティアへ配置し、手動操作は不要です。

⚡ オプションの SSD 読み取りキャッシュ

アクティブなデータを SSD 読み取りキャッシュに保持して高速アクセスを実現。HPC や AI/ML ワークロードに高パフォーマンスを提供しつつ、めったに使われないデータは低コストで保管します。

📦 完全エラスティックなストレージ

事前のキャパシティプロビジョニングが不要で、保存したデータ量に対してのみ課金。ストレージ容量の管理オーバーヘッドを削減します。

🎯 ユースケース

1️⃣ HPC ワークロードのデータ管理

高性能計算 (HPC) のジョブで生成される大量の中間データと結果データを扱う。アクティブな処理データは高速アクセスが必要だが、過去のジョブ結果はアクセス頻度が低い。

効果: アクティブなデータは SSD 読み取りキャッシュで高速アクセス、過去データは Archive ティアへ自動移動してコスト削減。
2️⃣ AI/ML トレーニングデータセットの保管

機械学習トレーニング用の大規模データセットを保管。一部は頻繁に再利用されるが、多くは一度使った後アクセス頻度が下がる。

効果: 頻繁に使うデータセットは高速ティアで、低頻度のものは低コストティアへ移動し、全体のストレージコストを最適化。
3️⃣ 地理的要件を持つワークロードの展開

データレジデンシー要件で特定地域 (例: ヨーロッパ、アジアパシフィック) にデータを保管する必要がある組織が、コスト効率の高い Lustre ストレージを必要とする。

効果: 追加リージョンで Intelligent-Tiering を利用し、要件を満たしつつコスト最適化されたファイルストレージを実現。

💰 料金

Intelligent-Tiering は事前のキャパシティプロビジョニングが不要で、保存したデータ量に対してのみ課金されます。 オンプレミスの HDD ファイルストレージと比較して最大 34% の価格性能比向上を実現し、 めったにアクセスされないデータについては他のフルマネージドクラウドファイルストレージと比較して最大 96% のコスト削減が可能とされています。

正確な料金はリージョンやアクセスパターンによって異なるため、Amazon FSx の料金ページで確認してください。
