🔍 Web Search にドメインフィルタリングと
ユーザーロケーションコントロールが追加

📅 リリース日: 2026 年 10 月 23 日 | 機能: Web Search domain filtering / user location controls

📝 概要

Amazon Bedrock の Web Search が、モデル応答のグラウンディングに使用する検索結果を制御する 2 つの新しいコントロールをサポートしました。既存の OpenAI Responses API リクエスト内の web_search ツールに直接設定でき、アプリケーションコードの大きな変更は不要です。

🧹 filters
allowed_domains / blocked_domains
各最大 100 件のドメイン制御
📍 user_location
国・地域・都市・タイムゾーンで
地域に即した検索結果を取得
⚡ コード変更 最小
既存の Responses API リクエストに
パラメータを追加するだけ
❌ Before (アップデート前の課題)
  • 検索対象ドメインを制御できず、信頼性の低いソースがグラウンディングに使われる可能性があった
  • 社内ポリシー上参照してはならないサイトを検索結果から除外する手段がなかった
  • 位置情報を指定できず、検索結果は米国前提になりがちで地域固有の質問への回答精度に限界があった
✅ After (アップデート後の改善)
  • allowed_domains (最大 100 件) で検索結果を信頼できるドメインのみに限定
  • blocked_domains (最大 100 件) で特定ドメインを検索結果から除外
  • user_location で国・地域・都市・タイムゾーンを指定し、地域に即した検索結果を取得

💡 web_search ツールに設定した filters と user_location が検索結果の取得に反映され、モデルはフィルタ済み・地域最適化された結果に基づいて引用付きの回答を生成します。

🚀 主要機能

1️⃣ ドメインフィルタリング (filters パラメータ)
  • allowed_domains と blocked_domains をそれぞれ最大 100 件まで指定可能
  • allowed_domains 指定時は検索結果が指定ドメインのみに限定される
  • blocked_domains 指定時は指定ドメインが検索結果から除外される
  • ドメイン指定時は http:// や https:// のプレフィックスを省略する
  • 各エントリはサブドメインにもマッチ (例: aws.amazon.com は docs.aws.amazon.com もカバー)
2️⃣ ユーザーロケーション (user_location パラメータ)
  • 位置情報を Web Search ツールに共有するためのオプションパラメータ
  • モデルや検索サービスが位置情報を利用して応答をローカライズ
  • 未設定または空の場合、ロケーションは米国 (United States) がデフォルト
  • country は ISO 3166-1 alpha-2 コードで検証。大文字小文字は区別されず、UK や XK のような未割り当て・ユーザー割り当てコードは拒否される
  • region と city は自由形式の文字列、timezone は IANA タイムゾーン識別子
3️⃣ 既存リクエストへのシームレスな追加
  • 既存の OpenAI Responses API リクエスト内の web_search ツール定義に直接追加するだけで利用可能
  • external_web_access や search_context_size などの既存パラメータと組み合わせて使用できる

JSON ドメインフィルタリング 
{
  "type": "web_search",
  "external_web_access": false,
  "filters": {
    "allowed_domains": [
      "aws.amazon.com",

    ]
  }
}

{
  "type": "web_search",

  }
}

🎚️ search_context_size との組み合わせ

値観測結果の上限用途
low最大 5 件シンプルな質問向け。入力トークン使用量を抑制
medium最大 11 件デフォルト。カバレッジとトークン使用量のバランス
high最大 25 件複雑・マルチホップな質問向け。入力トークン使用量は増加

🛠️ 設定方法

✅ 前提条件

✓IAM アイデンティティに bedrock-websearch:InvokeSearch、bedrock-websearch:InvokeFetch が許可されていること
✓bedrock-mantle エンドポイント経由で OpenAI Responses API を呼び出せること (Amazon Bedrock API キーの発行)
✓対応モデル (OpenAI GPT-5.4 以降) へのアクセスが有効であること
1
環境変数の設定
Bash API キーとベース URL の設定 
export OPENAI_API_KEY="your-amazon-bedrock-api-key"
export OPENAI_BASE_URL="https://bedrock-mantle.us-west-2.api.aws/openai/v1"

OpenAI SDK から Amazon Bedrock の bedrock-mantle エンドポイントに接続するため、API キーとベース URL を環境変数に設定します。

2
ドメインフィルタリング付きリクエストの送信
Bash allowed_domains で AWS 公式ドメインに限定 
curl "https://bedrock-mantle.us-west-2.api.aws/openai/v1/responses" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai.gpt-5.6-terra",
    "input": "AWS Lambda のコールドスタートに関する最新のガイダンスをまとめてください。",
    "tools": [{
      "type": "web_search",
      "external_web_access": false,
      "filters": {
        "allowed_domains": ["aws.amazon.com", "docs.aws.amazon.com"]
      }
    }]
  }'

モデルは指定ドメイン (サブドメイン含む) の検索結果のみを使用して回答をグラウンディングします。

3
ユーザーロケーション付きリクエストの送信
Python user_location で地域に即した回答を取得 
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="openai.gpt-5.6-terra",
    input="What are the best restaurants near me?",
    tools=[{
        "type": "web_search",
        "external_web_access": False,
        "user_location": {
            "type": "approximate",
            "country": "US",
        },
    }],
)

print(response.output_text)

モデルと検索サービスが位置情報を利用し、地域に即した検索結果に基づく回答を返します。

💡 メリット

💼 ビジネス面
✓情報源の信頼性向上: 公式サイトや承認済みドメインに限定でき、回答品質とブランドリスク管理が向上
✓コンプライアンス対応: blocked_domains で参照すべきでないサイトを除外し、規制や社内ポリシーに沿った情報利用を実現
✓地域ユーザー体験の向上: 所在地に応じたローカルな検索結果で、地域性の高いサービスでの回答精度が向上
🔧 技術面
✓既存コードへの影響が最小: web_search ツール定義へのパラメータ追加のみで、移行コストが低い
✓サブドメインの自動カバー: 少ないエントリ数で広い範囲を制御できる
✓他のコントロールとの併用: external_web_access や search_context_size と組み合わせ、きめ細かな検索動作を設計可能

⚠️ デメリット・制約事項

🚫 制限事項

✗allowed_domains と blocked_domains はそれぞれ最大 100 件まで
✗Web Search の利用可能リージョンは米国の 3 商用リージョンと AWS GovCloud (US-West) に限定
✗サーバーサイドツールのため bedrock-runtime エンドポイントでは利用できず、bedrock-mantle エンドポイントが必要
✗対応モデルは OpenAI GPT-5.4 以降に限定 (GovCloud では openai.gpt-5.6-terra、openai.gpt-5.6-luna、openai.gpt-5.4)
✗country に指定できるのは ISO 3166-1 alpha-2 の割り当て済みコードのみ (UK や XK などは拒否)

🤔 考慮すべき点

⚠️user_location 未指定時は米国がデフォルトのため、米国以外のユーザー向けアプリケーションでは明示的な指定を検討する
⚠️allowed_domains を狭く設定しすぎると、必要な情報が得られずモデルが「回答できない」と返すケースが増える可能性がある
⚠️external_web_access はデフォルトで true のため、機密データを扱う場合は false を明示し、データを AWS 境界内に保つことを推奨
⚠️検索結果の引用 (出典) はエンドユーザーへの表示時に保持する必要がある (Acceptable Use)

🎯 ユースケース

📚 1. 公式ドキュメント限定の社内テクニカルアシスタント

社内エンジニア向けのアシスタントで、AWS 公式情報のみを根拠とした回答を提供。非公式ブログやフォーラムの誤情報を排除する。

JSON実装例
{
  "type": "web_search",
  "external_web_access": false,
  "filters": {
    "allowed_domains": ["aws.amazon.com", "docs.aws.amazon.com", "repost.aws"]
  }
}

✅ 効果: 回答のグラウンディングが公式ドメインに限定され、引用付きで信頼性の高い回答を提供できる。

🛡️ 2. ブランドセーフティのためのドメイン除外

カスタマー向けチャットボットで、競合他社サイトや信頼性の低い情報源が回答の根拠として引用されることを防止。

JSON実装例
{
  "type": "web_search",
  "filters": {
    "blocked_domains": ["example-competitor.com", "unreliable-source.example"]
  }
}

✅ 効果: 不適切な情報源が検索結果から除外され、ブランドポリシーに沿った回答を維持できる。

📍 3. 地域密着型サービスのローカライズ回答

店舗検索や地域のサービス提供状況を案内するアプリケーションで、ユーザーの所在地に応じた検索結果を利用。

JSON実装例
{
  "type": "web_search",
  "user_location": {
    "type": "approximate",
    "country": "US",
    "region": "Washington",
    "city": "Seattle",
    "timezone": "America/Los_Angeles"
  }
}

✅ 効果: 位置情報に基づいてローカライズされた検索結果が使用され、「近くのレストラン」のような地域性の高い質問への回答精度が向上する。

ドメインフィルタリングとユーザーロケーションの指定自体に追加料金の記載はありません。Web Search の利用料金およびモデル推論料金が適用されます。

⚠️search_context_size を大きくすると入力トークンが増加し、推論コストが増える可能性があります。

最新の料金は Amazon Bedrock 料金ページ を参照してください。

🔗 関連サービス・機能

🔌 OpenAI Responses API on Amazon Bedrock

Web Search は bedrock-mantle エンドポイントの Responses API 経由で利用するサーバーサイドツール。今回の新パラメータもこの API 上で設定します。

🔐 AWS IAM

bedrock-websearch プレフィックスのアクション (InvokeSearch、InvokeFetch、ExternalWebAccess) で Web Search の利用と外部 Web アクセスを制御します。

📜 AWS CloudTrail

Web Search の API アクティビティをデータイベントとして記録でき、fetchedSources フィールドでフェッチ結果の監査が可能です。

📌 まとめ

Amazon Bedrock の Web Search にドメインフィルタリングとユーザーロケーションの 2 つのコントロールが追加され、モデル応答のグラウンディングに使用する検索結果の信頼性と地域適合性を制御できるようになりました。
