📊 Amazon Quick - S3 Tables Direct Query

データレイクから直接 BI 分析 - 中間レイヤー不要の新時代

2026 年 5 月 4 日
Amazon Quick

📋 概要

Amazon Quick が Amazon S3 テーブルバケット をデータソースとして直接サポート。S3 テーブルバケットに格納された Apache Iceberg テーブルに対して、中間のデータウェアハウスや OLAP レイヤーを介さずにダッシュボード構築、会話型分析、データ探索が可能に。

Zero-ETL を活用して Salesforce、SAP、Amazon Kinesis Data Firehose からのデータを S3 テーブルバケットに直接取り込み、ニアリアルタイムのインサイトを最小限のパイプラインで実現。

❌ Before

  • データウェアハウスや OLAP への移動が必須
  • Athena 等の中間クエリエンジンが必要
  • 複雑な ETL パイプラインの構築・維持
  • Single Source of Truth の維持が困難

✅ After

  • S3 テーブルバケットへ直接クエリ
  • 中間レイヤーが完全に不要
  • ニアリアルタイムでダッシュボード更新
  • データレイクが唯一の真実のソース

⚡ 主要機能

🔍 S3 Tables Direct Query モード
S3 テーブルバケット内の Apache Iceberg テーブルに対して直接クエリを実行。中間のデータウェアハウスや OLAP レイヤーが不要。ストリーミングデータを含む最新データにニアリアルタイムでアクセス可能で、手動のデータセット更新なしで最新データが反映される。
💾 SPICE モードのサポート
S3 Tables データソースに対して SPICE (Super-fast, Parallel, In-memory Calculation Engine) モードも選択可能。スケジュールベースのデータ更新が適切なユースケースや、高速な繰り返しクエリが必要な場合に最適。
💬 自然言語による対話的分析
Dataset Q&A を通じて S3 テーブルバケットのデータに自然言語で質問可能。My Assistant チャットエージェントによるインタラクティブな分析。データレイクを信頼のソースとして、AI が根拠のある回答を生成。
🔗 Zero-ETL 連携
Salesforce、SAP、Amazon Kinesis Data Firehose から S3 テーブルバケットへの Zero-ETL。パイプライン依存を最小限に抑えたデータ連携で、ニアリアルタイムのデータ取り込みと分析を統合。

🔐 権限設定

S3 テーブルバケットへのアクセスに必要な IAM ポリシー。

JSON IAM ポリシー例 
{
  "Effect": "Allow",
  "Action": [
    "s3tables:GetTable",
    "s3tables:GetTableData",
    "s3tables:ListTables",
    "s3tables:ListNamespaces"
  ],
  "Resource": "arn:aws:s3tables:<region>:<account-id>:bucket/<table-bucket-name>/*"
}

⚠️ デメリット・制約事項

制限事項

✗Direct Query モードは「ニアリアルタイム」であり、データ取り込みからクエリ可能になるまでに若干の遅延あり
✗Amazon Quick Enterprise サブスクリプションが必要 (Standard では利用不可)
✗S3 テーブルバケットの Apache Iceberg 形式のみサポート (他のテーブル形式は非対応)

考慮すべき点

⚡Direct Query は SPICE と比較してクエリレイテンシが高くなる可能性がある (大規模データセット)
🔄頻繁に繰り返し実行される同一クエリは SPICE モードの方がパフォーマンス面で有利
🔐S3 テーブルバケットへのアクセス権限設定を適切に管理する必要あり
📡ストリーミングパイプラインの構成は別途必要
