☁️ AWS License Manager

🛡️ AWS Marketplace 版 Ubuntu Pro への
ライセンスタイプ変換をサポート

📅 リリース日: 2026 年 10 月 14 日 ｜ 機能: AWS Marketplace で購入した Canonical Ubuntu Pro へのインプレースアップグレード

📝 概要

AWS License Manager が、EC2 上の Ubuntu LTS インスタンスを、AWS Marketplace で提供される Canonical の Ubuntu Pro へインプレースでアップグレードする機能をサポートしました。インスタンスや AMI を再構築したり、ワークロードを移行したりすることなく、既存のインスタンスのままセキュリティ体制を強化し、コンプライアンス要件を満たすことができます。

Ubuntu Pro により最大 10 年間 (Legacy アドオンで最大 15 年間) のセキュリティパッチを受け取れます。対象はベース OS にとどまらず、NGINX、PostgreSQL、MongoDB、Redis などを含む数千の追加パッケージに及び、Kernel Livepatch により再起動なしでカーネルの重要なセキュリティ修正を適用できます。

❌ アップデート前の課題

  • ライセンスタイプ変換の変換先は AWS 提供の Ubuntu Pro (AWS 課金) のみで、AWS Marketplace で Canonical から購入した Ubuntu Pro を利用できなかった
  • Marketplace 経由の Ubuntu Pro を適用するには、Ubuntu Pro の AMI からの再構築や新インスタンスへの移行が必要だった
  • Canonical との既存の商流 (プライベートオファーなど) を活かして稼働中フリートを Ubuntu Pro 化する手段が限られていた

✅ アップデート後の改善

  • 既存の Ubuntu LTS インスタンスを、AWS Marketplace で購入した Canonical Ubuntu Pro へインプレースで変換可能に
  • 変換ワークフローの中で、License Manager コンソールから Canonical Ubuntu Pro の汎用リスティングに直接サブスクライブ可能に
  • 再構築や AMI 差し替えなしに、最大 10 年 (Legacy アドオンで最大 15 年) のセキュリティパッチと Kernel Livepatch を利用可能に

License Manager の変換ワークフローが AWS Marketplace の Canonical Ubuntu Pro サブスクリプションと連携し、停止中の Ubuntu LTS インスタンスをインプレースで Ubuntu Pro に変換する流れ

⚙️ 主要機能

1️⃣ AWS Marketplace 版 Ubuntu Pro へのインプレース変換
  • EC2 上の Ubuntu LTS インスタンスを、Canonical が AWS Marketplace で販売する Ubuntu Pro へ変換可能
  • 変換は Marketplace 製品コードをインスタンスにアタッチする方式で、使用操作値 (UsageOperation) は RunInstances のまま変わらない
  • 課金は AWS Marketplace のサブスクリプションを通じて Canonical から行われる
2️⃣ コンソールからのサブスクリプション購入
  • サブスクリプション未保有でも、変換ワークフロー内から汎用リスティングにサブスクライブ可能
  • 汎用リスティングはアーキテクチャ別 (x86_64 向けと Arm 向け) に提供され、コンソールは選択したインスタンスに合ったリスティングを提示
3️⃣ 長期セキュリティカバレッジ
  • 最大 10 年間のセキュリティパッチ。Legacy アドオンで最大 15 年間に延長可能
  • ベース OS に加え、NGINX、PostgreSQL、MongoDB、Redis などを含む数千の追加パッケージが対象
  • Kernel Livepatch により再起動なしでカーネルの重要なセキュリティ修正を適用可能
4️⃣ 既存の AWS 提供 Ubuntu Pro への変換との使い分け
  • 従来の「AWS 提供の Ubuntu Pro」への変換 (RunInstances:0g00、AWS 課金) も引き続き利用可能
  • Canonical との Marketplace 契約 (プライベートオファーなど) を利用するお客様にも選択肢が拡大

📋 変換の前提条件と動作

項目詳細
インスタンス状態変換タスク作成時に停止状態である必要がある。変換中は開始・終了操作を行わない
インベントリコンソールでは AWS Systems Manager Inventory に関連付けられたインスタンスのみ表示される
ネットワークCanonical サーバーからライセンストークンを取得し Ubuntu Pro Client をインストールするため、アウトバウンドのインターネットアクセスが必要
変換結果の確認list-license-conversion-tasks と get-license-conversion-task CLI コマンドでステータスを確認可能 (IN_PROGRESS → SUCCEEDED / FAILED)
フレーバー固有パッケージ変換は課金とエンタイトルメントのための製品コードのアタッチのみ。FIPS、CIS ハードニング、Real-time Kernel などは変換後に Ubuntu Pro Client (pro) で自身でインストール・設定が必要
逆方向の変換Ubuntu Pro から Ubuntu LTS への変換はライセンスタイプ変換では不可。AWS Support への申請が必要

🛠️ 設定方法

✅ 前提条件

✓変換対象の EC2 インスタンスが Ubuntu LTS であり、停止状態であること
✓インスタンスが AWS Systems Manager Inventory に関連付けられていること (コンソール利用時)
✓アウトバウンドのインターネットアクセスが設定されていること (ライセンストークン取得と Ubuntu Pro Client のインストールに必要)
✓CLI 利用時は license-manager:CreateLicenseConversionTaskForResource を実行できる IAM 権限があること
✓CLI で Marketplace 版へ変換する場合、事前に有効な Canonical Ubuntu Pro サブスクリプションを保有していること (CLI では自動サブスクライブは行われない)
1
現在のライセンスタイプを確認
BashUsageOperation の確認
aws ec2 describe-instances \
    --instance-ids <instance-id> \
    --query "Reservations[*].Instances[*].{InstanceId: InstanceId, PlatformDetails: PlatformDetails, UsageOperation: UsageOperation}"

使用操作値 (UsageOperation) を確認します。RunInstances は AWS 提供のライセンスを使用していることを示します。

2
コンソールから変換を実行
  1. AWS License Manager コンソールを開く
  2. [License type conversion] → [Create license type conversion] を選択
  3. ソースのオペレーティングシステムとして [Ubuntu LTS] を選択
  4. 変換対象のインスタンスを選択して [Next] を選択
  5. 変換先として Canonical Ubuntu Pro を選択 (サブスクリプションがない場合はワークフロー内でサブスクライブ可能)
  6. 設定内容を確認して [Start conversion] を選択

変換ステータスは Conversion status 列で In progress、Completed、Failed として確認できます。

3
CLI から変換を実行する場合
Bash変換タスクの作成
aws license-manager create-license-conversion-task-for-resource \
    --resource-arn <instance_arn> \
    --source-license-context "UsageOperation=RunInstances" \
    --destination-license-context "UsageOperation=RunInstances,ProductCodes=[{ProductCodeType=marketplace,ProductCodeId=<product_code_id>}]"

インスタンスの ARN と、サブスクライブしている Canonical Ubuntu Pro の Marketplace 製品コードを指定します。使用操作値は RunInstances のまま、製品コードがアタッチされます。

4
変換結果を確認
Bashステータス確認
# 変換タスクのステータスを確認
aws license-manager list-license-conversion-tasks

# インスタンス内で Ubuntu Pro のサブスクリプション状態を確認
pro status

ステータスが SUCCEEDED になった後にインスタンスを起動し、pro status で有効な Ubuntu Pro サブスクリプションが適用されていることを確認します。

💡 メリット

💼 ビジネス面

✓フリート再構築コストの削減: 再構築・移行なしで Ubuntu Pro へ移行でき、プロジェクトの工数とリスクを大幅に削減
✓既存契約の活用: Marketplace で締結済みのサブスクリプション (プライベートオファーなど) をそのまま適用でき、調達の柔軟性が向上
✓コンプライアンス対応の迅速化: 最大 10 年 (Legacy アドオンで最大 15 年) のパッチ提供により、規制業界の長期サポート要件に対応

🔧 技術面

✓インプレース変換: IP アドレス、EBS ボリューム、インスタンス設定を維持したままライセンスタイプのみを変更
✓広範なパッケージカバレッジ: ベース OS に加え、数千のオープンソースパッケージがパッチ対象に
✓Kernel Livepatch: 再起動なしでカーネルの重要な修正を適用し、計画メンテナンスの頻度を削減

⚠️ デメリット・制約事項

🚧 制限事項

✗変換タスク作成時はインスタンスの停止が必要で、変換中は開始・停止操作を行えない (短時間のダウンタイムが発生)
✗Ubuntu Pro から Ubuntu LTS への逆方向の変換は非サポート。AWS Support への申請が必要
✗CLI で変換する場合は事前に有効な Marketplace サブスクリプションが必要 (自動サブスクライブされない)
✗Canonical サーバーと通信するためのアウトバウンドインターネットアクセスが必要

🤔 考慮すべき点

⚠️FIPS や CIS ハードニングなどフレーバー固有のリスティングでも、変換は課金用製品コードのアタッチのみ。フレーバー固有パッケージは別途 pro コマンドでインストールが必要
⚠️AMI の課金情報は変換後も変わらないため、課金情報を参照する既存ワークフローは EC2 の DescribeInstances API を使用するよう更新が必要
⚠️AWS 提供版 (AWS 課金) と Marketplace 版 (Canonical 課金) のどちらが自社の調達・コスト要件に適しているか事前比較を推奨

🎯 ユースケース

1. EOL が近い Ubuntu LTS フリートの延命

シナリオ: 標準サポート終了が近づく Ubuntu LTS で稼働する多数の本番 EC2 インスタンスがあり、アプリケーション互換性の都合で OS のメジャーアップグレードをすぐに実施できない。

実装: コンソールで対象インスタンスを一覧表示 → メンテナンスウィンドウで停止し変換 → 起動後に pro status で ESM (Expanded Security Maintenance) の有効化を確認。

✅ 効果: OS 再構築なしで最大 10 年 (Legacy アドオンで最大 15 年) のセキュリティパッチを確保し、アップグレード計画を安全に先送りできる。
2. Canonical とのプライベートオファーを既存フリートへ適用

シナリオ: AWS Marketplace のプライベートオファーで Ubuntu Pro サブスクリプションを一括購入済みだが、既存インスタンスへの適用には再構築が必要だと考えていた。

Bash契約済み製品コードで変換
aws license-manager create-license-conversion-task-for-resource \
    --resource-arn arn:aws:ec2:ap-northeast-1:123456789012:instance/i-0123456789abcdef0 \
    --source-license-context "UsageOperation=RunInstances" \
    --destination-license-context "UsageOperation=RunInstances,ProductCodes=[{ProductCodeType=marketplace,ProductCodeId=<契約済み製品コード>}]"
✅ 効果: 購入済みサブスクリプションを既存インスタンスにインプレースで適用し、契約を無駄なく活用できる。
3. コンプライアンス監査に向けた OSS ミドルウェアのパッチ体制強化

シナリオ: PostgreSQL や NGINX などの OSS ミドルウェアを Ubuntu LTS 上で運用しており、監査でベース OS 以外のパッケージの脆弱性管理体制を問われている。

実装: コンソールから Ubuntu Pro に変換 (未保有なら汎用リスティングにサブスクライブ) → pro status で esm-apps サービスの有効化を確認 → Kernel Livepatch を有効化し再起動なしのパッチ適用体制を構築。

✅ 効果: ベース OS に加えて数千の追加パッケージがパッチ対象となり、監査要件への対応と運用負荷の低減を両立できる。

💰 料金と利用可能リージョン

💵 料金
  • AWS License Manager 自体は追加料金なしで利用可能
  • Marketplace 版へ変換した場合、Ubuntu Pro の料金は AWS Marketplace のサブスクリプションを通じて Canonical から請求
  • 料金はリスティングや契約形態 (パブリックオファー、プライベートオファー) により異なるため、各リスティングで確認
  • 従来の AWS 提供 Ubuntu Pro へ変換した場合は、AWS から利用料金が請求される
🌍 利用可能リージョン

AWS License Manager が利用可能なすべての商用リージョンで利用できます。

📌 まとめ

AWS License Manager のライセンスタイプ変換が AWS Marketplace 版の Canonical Ubuntu Pro に対応したことで、フリートの再構築やワークロード移行なしに、既存の Ubuntu LTS インスタンスを長期セキュリティサポート付きの Ubuntu Pro へアップグレードできるようになりました。標準サポート終了が近い Ubuntu LTS を運用している場合や、Canonical との Marketplace 契約を保有している場合は、License Manager コンソールから変換ワークフローを試すことを推奨します。
