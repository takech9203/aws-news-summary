🧱 自動インターネットファイアウォール

📅 リリース日: 2026 年 11 月 20 日 | Automated Internet Firewall (パブリックプレビュー)

📝 概要

VPC のインターネットゲートウェイに NAT 機能内蔵のファイアウォールを自動配置する新機能。 AWS Network Security Manager (NSM) でセキュリティルールを一元定義するだけで、スコープ内のすべての VPC のインターネットゲートウェイを通過する インバウンド / アウトバウンドトラフィックに AWS がファイアウォールを直接適用します。

  • ルート操作によるファイアウォール迂回のリスクを監視
  • アウトバウンド用に NAT ゲートウェイを別途構成・管理
  • 新規 VPC ごとに同じ構成を手動で展開

  • モニターモードで影響確認後にエンフォースモードへ安全に移行

Network Security Manager で一元定義したポリシーが、スコープ内の各 VPC のインターネットゲートウェイに自動配置されたファイアウォールで適用される構成です。 VPC 内のルーティング変更は不要で、新規 VPC にも保護が自動拡張されます。

⚡ 主要機能

🚪 インターネットゲートウェイでのインライン検査

スコープ内 VPC のすべてのインターネット通信が、宛先に届く前にファイアウォールを通過。ルートテーブル経由のホップではなくインターネットゲートウェイ自体で検査されるため、ルート変更による迂回が不可能。専用サブネットの作成やルートテーブルの更新も不要。

🔄 ネイティブ NAT 機能

outbound-only / flexible 接続タイプのサブネットに対し、検査後に IPv4 の NAT を実行。NAT 用パブリック IPv4 は AWS が自動割り当てし、BYOIP や連続 IP ブロック、IPAM ポリシー (リソースタイプ igw-firewall) による制御も可能。NAT 用 Elastic IP は各 AZ で 1 個から開始し、ポート使用量に応じて最大 8 個まで自動追加。

🎯 柔軟なスコープ設定と自動拡張

組織全体、OU、アカウント、特定の VPC を宣言的にスコープ定義。スコープに一致する新規 VPC / サブネットへ保護を自動拡張。AWS Organizations を使わないシングルアカウントモードでも利用可能。

🛡️ デフォルトポリシーとマネージドルールグループ

AWS マネージドテンプレート AWSManagedTemplateIGWFirewallBaseline が既知の攻撃インフラ、マルウェア配布ドメイン、ボットネット C2 ドメインをブロック (その他は ACCEPT)。AWS の脅威インテリジェンスを活用した active threat defense を含む Amazon マネージドルールグループのほか、カスタムルールや AWS Marketplace ルールグループも追加可能。

👀 モニターモードによる安全なロールアウト

モニターモードでは一致トラフィックをブロックせずログに記録し、既存ワークロードへの影響を事前評価。確認後にエンフォースモード (ブロック) へ切り替え可能。

🔧 技術仕様

📦 Network Security Manager のリソース階層

リソース説明
NSM ルール設定の最小単位。トラフィック検査ルール (Network Firewall ルールグループを参照) とファイアウォール設定ルール (モード、デフォルトアクション、ログ設定など) の 2 種類
NSM テンプレート複数の NSM ポリシー間で共有できる再利用可能なルールのグループ (オプション)
NSM ポリシーテンプレートとルールの組み合わせ。デフォルトのサブネット接続タイプも設定。1 ポリシーに最大 100 アイテム (テンプレートは最大 2 個、各テンプレートに最大 50 ルール)
スコープ保護対象 VPC の宣言的な選択。組織全体、OU、アカウント、特定 VPC (タグまたは ARN 指定、最大 100 ARN)
デプロイメントNSM ポリシーとスコープの結合。VPC ごとのファイアウォールを作成・維持し、新規 VPC へ自動拡張

🔌 サブネット接続タイプ

接続タイプ説明
bidirectionalパブリック IP を持つリソースはフィルタリングされた双方向通信が可能。パブリック IP のないリソースはインターネットに到達できない
outbound-onlyアウトバウンド専用。未承諾のインバウンドはドロップ。IPv4 は検査後に NAT を実行 (IPv6 は NAT なし)
flexible (推奨)リソースごとに IP 割り当てとルーティングに基づき自動判定。パブリック IP + IGW ルートありは bidirectional、それ以外はネイティブ NAT 経由の outbound-only
exclude検査対象外。特定のサブネットを保護から除外する場合に使用
az-unsupported自動割り当て。未対応のアベイラビリティーゾーン (Local Zones など) のサブネットに付与

🗂️ ファイアウォールリソースの管理モデル

自動インターネットファイアウォールは NSM のみが作成・変更・削除可能。各 VPC には arn:aws:network-firewall:<region>:<account-id>:igw-firewall/<vpc-id> という igw-firewall が作成され、Network Firewall コンソールの [Internet firewalls] タブと API から読み取り専用で参照できます。Network Firewall API から直接変更しようとするとリクエストは失敗します。

🛠️ 設定方法

✅ 前提条件

✓インターネットゲートウェイがアタッチされた VPC (AZ に稼働中の ENI が 1 つ以上あるとプロビジョニングされ、ない場合は Standby 状態)
✓NSM のセットアップ。シングルアカウントモードは NSM 権限を持つ IAM アイデンティティのみで利用可能。マルチアカウントモードは Organizations の全機能有効化、信頼されたアクセス、NSM 管理者アカウントの登録が必要
✓デプロイメントには課金が発生するため、事前に料金ページの確認を推奨

STEP 1: Quick create and deploy でポリシーを作成・デプロイ
  • Define protections: [Firewall type] で [Automated Internet Firewall] を選択し、テンプレート (例: AWSManagedTemplateIGWFirewallBaseline) またはルールを追加。既存ワークロードがある場合は [Monitor] (デフォルト) を推奨。ログ出力先は S3 / CloudWatch Logs / Kinesis Data Firehose
  • Policy details: ポリシー名を入力 (Remediation は必須のため変更不可)
  • Set the scope: 組織全体 / OU / アカウントを選択し、VPC スコープを「すべての既存・将来の VPC」「特定の VPC のみ」「特定の VPC を除外」から設定
  • Subnet connectivity: 接続タイプ (flexible 推奨) を選択し、サブネット単位のオーバーライド (exclude 含む) をタグまたは ARN で指定
  • [Create and deploy] を選択。VPC コンソールの [Actions] > [Security] > [Create Automated Internet Firewall] からも開始可能
STEP 2: デプロイメントの同期状態を確認

[Synchronization] タブで同期状態 (In sync / Out of sync / Not applicable) を確認。Out of sync のリソースは NSM が自動修復。ポリシーの [Coverage] タブで各 VPC のカバレッジ状態 (In effect / Superseded) を確認。

STEP 3: ファイアウォールの確認とエンフォースモードへの移行

Network Firewall コンソールの [Internet firewalls] タブでステータス (Provisioning / Ready / Standby)、NAT IP、モニタリング情報を確認。モニターモードでログを評価した後、NSM のポリシー編集でエンフォースモードに切り替え。

💡 メリット

💼 ビジネス面

✓運用負荷の大幅な削減: 専用サブネット設計、ルートテーブル管理、NAT ゲートウェイ構成が不要になり、導入・運用コストを削減
✓ガバナンスの強化: 組織全体に一貫したポリシーを一元適用。新規 VPC にも自動で保護が及び、カバレッジの抜け漏れリスクを低減
✓導入障壁の低減: AWS マネージドルールグループのデフォルトポリシーにより、カスタム設定なしで保護を開始可能

⚙️ 技術面

✓迂回不可能な適用ポイント: ルート変更ではファイアウォールを迂回できず、侵害されたワークロードによるポリシー回避を防止
✓アーキテクチャ変更ゼロ: flexible 接続タイプでは既存の NAT ゲートウェイ経由のトラフィックもそのまま動作 (段階的にネイティブ NAT へ移行可能)
✓安全なロールアウト: モニターモードで検証してからエンフォースモードに移行でき、本番への影響リスクを抑制
✓一元管理と分散実装の両立: ポリシー管理は NSM で一元化しつつ、ファイアウォールは VPC ごとに分散実装されスケーラビリティと可用性が向上

⚠️ デメリット・制約事項

🚧 制限事項

✗パブリックプレビュー段階の機能であり、仕様が変更される可能性がある
✗プレビュー期間中は Regional NAT、noNAT イングレスルーティング、ingress-only VPC Block Public Access と併用不可
✗プレビュー期間中は NAT64 を実行しない (必要な場合は NAT ゲートウェイを別途使用)
✗EC2 Mac インスタンス、および p4d、p4de、p6-b200、p6-b300、p6e-gb200、trn2、trn2u、g7e の機械学習系インスタンスタイプは未サポート
✗Local Zones では未サポート。未対応 AZ のサブネットは az-unsupported となり検査対象外
✗作成・変更・削除は NSM 経由のみ。Network Firewall API からの直接変更は不可

🤔 考慮すべき点

⚠VPC ごと・AZ ごとの時間課金 + 検査トラフィックの GB 単位課金が適用されるため、組織全体への展開時は事前のコスト試算が重要
⚠VPC ゲートウェイエンドポイント経由のトラフィックはインターネットゲートウェイを通過しないため検査対象外
⚠NAT IP は VPC ごとに個別構成。宛先側で IP 許可リストを運用している場合は IPAM ポリシーによるアドレス範囲の固定を検討
⚠既存のネットワークファイアウォール構成 (集中型検査 VPC など) と併用する場合は、ポリシーの優先順位とスコープの重複に注意

🎯 ユースケース

1️⃣ 組織全体へのベースラインセキュリティの一括適用

シナリオ: 多数のアカウントと VPC を運用する企業で、各チームが個別に VPC を作成しており、インターネット境界のセキュリティ統制が追いついていない。

Steps実装例
1. NSM のマルチアカウントモードをセットアップし、管理者アカウントを登録
2. AWSManagedTemplateIGWFirewallBaseline を含むポリシーを作成
3. スコープを「組織全体 + すべての既存・将来の VPC」に設定してデプロイ
4. モニターモードでログを確認後、エンフォースモードへ移行

効果: 既知の攻撃インフラ、マルウェア配布ドメイン、ボットネット C2 への通信を組織全体で一括ブロック。新規 VPC にも保護が自動拡張され、統制の抜け漏れがなくなる。

2️⃣ NAT ゲートウェイ構成の簡素化とアウトバウンド通信の検査

シナリオ: プライベートサブネットのワークロードが NAT ゲートウェイを使用しているが、アウトバウンドのフィルタリングとログ記録も必要になった。

Steps実装例
1. 接続タイプ flexible でポリシーをデプロイ (既存の NAT ゲートウェイ経由の
   トラフィックはそのまま動作するため、初日から破壊的変更なし)
2. フローログ / アラートログを S3 または CloudWatch Logs に出力
3. 準備ができたタイミングでルートから NAT ゲートウェイを外し、
   ファイアウォールのネイティブ NAT へ段階的に移行

効果: アウトバウンド通信の検査・ログ記録を実現しつつ、NAT ゲートウェイの運用を段階的に廃止してアーキテクチャを簡素化できる。

3️⃣ 宛先 IP 許可リスト環境でのアウトバウンド IP 管理

シナリオ: 接続先の外部パートナーシステムが送信元 IP の許可リストを運用しており、アウトバウンドの送信元 IP を特定の範囲に固定する必要がある。

Steps実装例
1. Amazon VPC IPAM で IPAM プールを作成し、BYOIP または AWS からの
   連続 IP ブロックを登録
2. IPAM ポリシーにリソースタイプ igw-firewall の割り当てルールを追加
3. 自動インターネットファイアウォールをデプロイすると、NAT 用の
   Elastic IP が指定プールの範囲から割り当てられる

効果: アウトバウンドの送信元 IP を単一の連続 CIDR ブロックに集約でき、パートナー側の許可リスト運用が容易になる。

📌 まとめ

自動インターネットファイアウォールは、VPC のアーキテクチャ変更なしにインターネットゲートウェイでのインライン検査とネイティブ NAT を実現する、 インターネット境界セキュリティのデプロイモデルを大きく変えるアップデートです。 ルート操作による迂回を構造的に防止しつつ、組織全体への一元適用と新規 VPC への自動拡張によりガバナンスを強化できます。

パブリックプレビュー段階のため制約事項 (NAT64 非対応、一部インスタンスタイプ未サポートなど) を確認のうえ、 まずはモニターモードで非本番環境から評価を開始することを推奨します。
