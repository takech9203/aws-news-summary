Amazon Aurora DSQL

🏛️ FedRAMP Moderate 対応

📅 2026 年 7 月 16 日

📌 概要

Amazon Aurora DSQL が、米国東部 (オハイオ)、米国東部 (バージニア北部)、米国西部 (オレゴン) の 3 リージョンで FedRAMP Moderate の対象範囲に含まれました。 これにより、FedRAMP Moderate のコンプライアンス要件が適用されるアプリケーションの構築やワークロード実行に Aurora DSQL を利用できます。

FedRAMP (Federal Risk and Authorization Management Program) は、クラウド製品・サービスのセキュリティ評価、認可、継続的なモニタリングに対する標準的なアプローチを提供する米国政府全体のプログラムです。 今回の対応により、米国政府機関や規制業界のお客様が、Aurora DSQL の高い可用性とスケーラビリティを享受しながら規制要件を満たせるようになります。

Aurora DSQL は、アクティブ - アクティブの高可用性とマルチリージョンでの強整合性を備えた、最速のサーバーレス分散 SQL データベースです。インフラ管理を必要とせず、事実上無制限のスケールで常時利用可能なアプリケーションを構築できます。

⚠️ アップデート前の課題

  • FedRAMP Moderate の対象範囲外で、準拠が求められるワークロードに採用できなかった
  • 要件を満たすため他のデータベースサービスを選択、または独自対策の追加が必要だった
  • 規制対象ワークロードで、サーバーレス分散型アーキテクチャの利点を活用できなかった
➡️

✅ アップデート後の改善

  • FedRAMP Moderate 準拠アプリを Aurora DSQL 上で構築できるようになった
  • 対象 3 リージョンで、要件を満たしながらアクティブ - アクティブの高可用性を利用可能
  • サードパーティによる継続的モニタリングと認可のもとで規制対象ワークロードを運用できる

FedRAMP Moderate 準拠が求められるアプリから対象 3 リージョンの Aurora DSQL を利用する構成。各リージョン間では強整合性を保ったレプリケーションが行われます。

⚙️ 主要機能

🛡️ FedRAMP Moderate コンプライアンス対応

  • Aurora DSQL が FedRAMP Moderate の対象範囲に追加
  • 米国東部 (オハイオ)、米国東部 (バージニア北部)、米国西部 (オレゴン) の 3 リージョンで利用可能
  • FedRAMP のセキュリティ評価、認可、継続的モニタリングの標準アプローチに準拠

⚡ アクティブ - アクティブの高可用性

  • 単一リージョンで 99.99%、マルチリージョンで 99.999% の可用性を提供
  • インフラコンポーネント障害時に、自動的に正常なインフラへリクエストをルーティング
  • 従来のデータベースフェイルオーバーを意識する必要がない

🔗 マルチリージョンでの強整合性

  • ピアリングされたマルチリージョンクラスターが 2 つのリージョナルエンドポイントを提供
  • 両エンドポイントが単一の論理データベースとして動作し、同時読み書きに対応
  • リーダーは常に同一のデータを参照できる

🛠️ 設定方法

前提条件

  • 対象リージョン (us-east-1、us-east-2、us-west-2 のいずれか) を利用可能な AWS アカウント
  • Aurora DSQL クラスターの作成・管理に必要な IAM 権限
  • PostgreSQL 互換のクライアントまたはドライバー (例: psql)

ステップ 1: Aurora DSQL クラスターの作成

Bash クラスター作成 
aws dsql create-cluster \
  --region us-east-1

対象リージョンで Aurora DSQL クラスターを作成します。FedRAMP Moderate 準拠が必要な場合は、対象 3 リージョンのいずれかを選択します。

ステップ 2: FIPS エンドポイントへの接続

Bash FIPS エンドポイント接続 
psql "host=<cluster-id>.dsql-fips.us-east-1.api.aws \
  dbname=postgres user=admin sslmode=require"

FIPS 準拠が求められる環境では、標準エンドポイントの代わりに FIPS エンドポイントを使用して接続します。SSL による接続を必須とします。

ステップ 3: コンプライアンス範囲の確認

AWS のコンプライアンス対応状況は、AWS Artifact や「AWS services in scope by compliance program」ページで最新の対象範囲を確認します。監査対応時には、これらの情報をエビデンスとして活用します。

💡 メリット

🏢 ビジネス面

✓規制対応の拡大: 政府機関や規制業界のワークロードで Aurora DSQL を採用できる
✓コンプライアンスコストの削減: AWS による第三者評価と継続的モニタリングを活用でき、独自対策の負担を軽減
✓調達の簡素化: FedRAMP 認可済みサービスとして政府調達要件への適合が容易

⚙️ 技術面

✓高可用性の維持: 要件を満たしながらアクティブ - アクティブ構成の高可用性を利用
✓運用負荷の低減: サーバーレスにより、プロビジョニングやパッチ適用が不要
✓既存資産の活用: PostgreSQL 互換のため既存のドライバーや ORM、SQL 知識をそのまま利用

⚠️ デメリット・制約事項

制限事項

✗FedRAMP Moderate の対象は現時点で 3 リージョンに限定
✗マルチリージョンクラスターは同一の Region set 内でのみ作成可能。大陸をまたぐ構成は非対応
✗一部の PostgreSQL 機能は Aurora DSQL で未対応の場合がある

考慮すべき点

🔎最新のコンプライアンス対象範囲は AWS 公式ページで随時確認する必要がある
🔎FedRAMP Moderate 準拠には Aurora DSQL 単体でなく、関連アーキテクチャ全体での対応が必要
🔎FIPS 要件がある場合は、FIPS エンドポイントの利用を明示的に構成する必要がある

🎯 ユースケース

1. 政府機関向けの常時稼働アプリケーション

シナリオ: 米国政府機関のシステムで、FedRAMP Moderate 準拠が必須かつ高い可用性が求められるトランザクションアプリを構築する。

効果: アクティブ - アクティブ構成により、要件を満たしながら 99.999% (マルチリージョン) の可用性を実現できる。

2. 規制業界のマイクロサービス基盤

シナリオ: 金融やヘルスケアなど、FedRAMP Moderate に準拠する必要がある規制業界で、サーバーレスのマイクロサービスアーキテクチャを採用する。

効果: インフラ管理不要でスケールする分散 SQL データベースを、規制要件を満たしながら利用でき、運用負荷を抑えられる。

3. クロスリージョンディザスタリカバリ

シナリオ: 対象 3 リージョンを活用し、コンプライアンス準拠のワークロードでリージョン障害に備えた冗長構成を構築する。

効果: マルチリージョンの強整合性により、フェイルオーバー時のデータ欠損や結果整合性を意識することなく事業継続性を確保できる。

💰 料金と利用可能リージョン

💵 FedRAMP Moderate 対応に伴う追加料金はありません。Aurora DSQL の通常の料金体系が適用され、使用したリソース (コンピュート、I/O、ストレージ) に基づく従量課金です。

FedRAMP Moderate 対象の 3 リージョン

  • 🌎 米国東部 (オハイオ) us-east-2
  • 🌎 米国東部 (バージニア北部) us-east-1
  • 🌎 米国西部 (オレゴン) us-west-2

なお、Aurora DSQL サービス自体は、これら以外にもアジアパシフィック (東京) やヨーロッパ (フランクフルト) など複数のリージョンで利用可能です。

🧩 関連サービス・機能

🗂️ AWS Artifact: FedRAMP を含むコンプライアンスレポートや認証情報をオンデマンドで取得できるサービス
🛢️ Amazon Aurora: PostgreSQL / MySQL 互換のリレーショナルデータベース。プロビジョンド型のワークロードで選択肢となる
🔐 AWS Identity and Access Management (IAM): Aurora DSQL クラスターへのアクセス制御と認証に利用

📝 まとめ

Amazon Aurora DSQL が対象 3 リージョンで FedRAMP Moderate の対象範囲に加わったことで、米国政府機関や規制業界のお客様が、サーバーレス分散 SQL データベースの高可用性とスケーラビリティをコンプライアンス要件を満たしながら活用できるようになりました。 FedRAMP Moderate 準拠のワークロードを検討している場合は、AWS の最新のコンプライアンス対象範囲を確認したうえで、Aurora DSQL の採用を評価することをお勧めします。
