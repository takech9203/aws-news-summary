AWS Security Agent / AWS Continuum

🛡️ Kiro Power・Claude Code でセキュリティを開発フローへ

シミュレート検証と新規ソースコントロール統合を追加
リリース日
2026/06/17

📌 概要

AWS は AWS Security Agent に開発者向けの大幅な機能拡張を発表しました。AI 搭載 IDE である Kiro および Claude Code をサポートし、開発者は普段の開発環境からセキュリティスキャンを直接起動できます。あわせて、検出結果の信頼性を高める「シミュレート検証」と、複数のソースコントロール / ドキュメントプラットフォームとの新規統合が追加されました。

AWS Security Agent は、アプリケーションを開発ライフサイクル全体で能動的に保護するフロンティアエージェントです。今回の拡張は、機能を開発者の作業環境に直接届け、コンテキストの切り替えを排除することを目的としています。

❌ アップデート前の課題

  • 専用コンソールへの移動が必要で、開発フローからのコンテキスト切り替え負担があった
  • 検出結果が悪用可能か開発者が手動でトリアージする必要があり、誤検知の切り分けに時間がかかった
  • 連携できるソースコントロール / ドキュメントが限られていた

✅ アップデート後の改善

  • Kiro、Claude Code、MCP 対応 AI IDE から直接スキャンを起動できる
  • シミュレート検証で悪用の証拠を提示し、誤検知を最小化して優先度付け可能に
  • GitLab、GitHub Enterprise、Bitbucket、Confluence との統合を追加

開発者は AI IDE から MCP 経由で AWS Security Agent を起動し、接続されたソースコントロールやドキュメントに対してスキャンを実行します。検出結果はサンドボックスでシミュレート検証され、悪用の証拠とともに IDE 内にインラインで返却されます。

⚡ 主要機能

🟣 Kiro Power と Claude Code プラグイン

  • オープンソースの Kiro Power と Claude Code プラグインで、普段の IDE からセキュリティスキャンを直接起動
  • オープンな MCP 統合により、AWS Security Agent MCP サーバーを介して任意の AI IDE と連携
  • スレットモデル構築、コードスキャン、検証された修正対応を IDE 内で完結

🧪 シミュレート検証 (Simulated Validations)

  • 検出結果を隔離サンドボックス内で再現し、悪用の証拠 (proof of exploit) を提示
  • 単なる検出を超えて、脆弱性が実際にどう悪用され得るかの証拠を返し信頼性を向上
  • 未検証アラートのトリアージ時間を削減し、誤検知を最小化して優先度付けを支援

🔗 新規統合のサポート

  • GitLab.com、GitLab Self Managed、GitHub Enterprise、Bitbucket に対応
  • ドキュメントプラットフォームとして Confluence をサポート
  • SaaS 型および自己ホスト型の両方の環境に対応

🛠️ 設定方法

IDE 上で自然言語のプロンプトを送るだけで、セットアップからスキャン、修正対応までを実行できます。

ステップ 1: AWS Security Agent のセットアップ

PromptIDE 上での依頼
Set up AWS Security Agent

Kiro が Agent Space の有無を確認し、既存の利用か新規作成かを選択できます。

ステップ 2: フルセキュリティスキャンの実行

Promptスキャン実行
Run a full security scan on this repo

Kiro のターン完了後、Agent フックが差分スキャンを開始すべきか評価します。

ステップ 3: 修正対応とスレットモデリング

Prompt修正 / スレットモデル
help me remediate my findings
Build a threat model for this application

検出結果がローカルにダウンロードされ、重大なものから優先するバグ修正セッションが提供されます。スレットモデルは .security-agent/threat_model.md に保存されます。

💡 メリット

📈 ビジネス面

  • セキュリティ対応の前倒し: 早期にセキュリティを組み込み手戻りを削減
  • 誤検知コストの削減: 悪用の証拠で検証工数を削減
  • 既存ツールへの統合: GitLab / GitHub / Bitbucket / Confluence を活用

⚙️ 技術面

  • コンテキストスイッチの排除: 普段の IDE で完結
  • オープンな連携基盤: MCP で任意の AI IDE と連携
  • 再現性のある検証: 隔離サンドボックスで脆弱性を再現

⚠️ デメリット・制約事項

🚧 制限事項

  • スレットモデリングおよびコードレビューはプレビュー段階。本番利用前に動作確認が必要
  • 利用可能リージョンは AWS Security Agent がサポートする AWS 商用リージョンに限定
  • Claude Code プラグインの提供状況は提供元情報の確認が必要

🔍 考慮すべき点

  • 自己ホスト型のソースコントロール接続時は、ネットワークやアクセス権限の構成を確認する
  • シミュレート検証はサンドボックス内実行のため、脆弱性の種類によって結果が異なる可能性がある

🎯 ユースケース

1. IDE 内でのプルリクエストセキュリティレビュー

シナリオ: 開発者が PR 作成時に、IDE を離れることなくセキュリティレビューを実施したい。
Prompt
Run a full security scan on this repo
効果: 推論ベースの分析で複雑な脆弱性を検出し、修正コミットと是正ガイダンスを開発フロー内で受け取れる。

2. 誤検知の削減と優先度付け

シナリオ: セキュリティチームが大量の検出結果のトリアージに追われ、悪用可能なものを優先したい。
Prompt
help me remediate my findings
効果: シミュレート検証で悪用の証拠が提示され、最も重大な脆弱性から優先的に修正対応できる。

3. 設計段階でのスレットモデリング

シナリオ: 設計段階でアーキテクチャ上の脅威を体系的に洗い出したい。
Prompt
Build a threat model for this application
効果: STRIDE フレームワークに基づき脅威アクター・攻撃ベクトル・弱点を特定し、.security-agent/threat_model.md に保存。

🔌 関連サービス・機能

  • Kiro: AWS が提供する AI 搭載 IDE。Kiro Power により AWS Security Agent と連携
  • Claude Code: Anthropic の Claude Code。プラグインでスキャンを起動
  • AWS Continuum: AWS Security Agent が属する、開発ライフサイクル全体を保護するエージェント基盤
  • Model Context Protocol (MCP): AI IDE と AWS Security Agent を連携させるオープンな統合プロトコル
