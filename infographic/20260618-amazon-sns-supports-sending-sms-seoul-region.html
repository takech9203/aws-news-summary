Amazon SNS

📱 ソウルリージョンで
SMS 送信がサポート

アジアパシフィック (ソウル) リージョン ap-northeast-2 から直接 SMS 送信が可能に
📅 2026 年 6 月 18 日

📝 概要

Amazon SNS がアジアパシフィック (ソウル) リージョンで SMS の送信に対応しました。 ソウルリージョンのお客様は 200 以上の国と地域のサブスクライバーへ テキストメッセージを送信できるようになります。

SNS トピックに電話番号をサブスクライブし、AWS End User Messaging を通じて SMS をブロードキャストできます。韓国国内ワークロードのデータレジデンシーやレイテンシーの観点で重要な意味を持ち、 OTP 配信、トランザクション通知、プロモーションメッセージなど幅広いユースケースに対応します。

😟 アップデート前の課題

  • ソウルリージョンから直接 SMS を送信できず、別リージョン経由が必要だった
  • リージョンをまたぐ構成でアーキテクチャが複雑化し、レイテンシーが増加する可能性
  • 韓国国内でワークロードを完結させるデータレジデンシー要件への対応が困難

😀 アップデート後の改善

  • ソウルリージョン内で直接 SMS を送信できるようになった
  • リージョンをまたぐ構成が不要になり、アーキテクチャがシンプルに
  • ソウルリージョンから 200 以上の国と地域へ SMS を配信可能

⚡ 主要機能

🌏 ソウルリージョンからの SMS 送信
  • ap-northeast-2 の Amazon SNS から直接 SMS を送信可能
  • 200 以上の国と地域のサブスクライバーへ配信可能
  • リージョンをまたぐ構成が不要
📢 トピックへの電話番号サブスクライブ
  • SNS トピックに電話番号をサブスクライブし、SMS をブロードキャスト送信
  • 複数の受信者へ一斉にメッセージを配信
  • pub/sub モデルによる効率的なメッセージ配信
📨 AWS End User Messaging との連携
  • SMS の配信は AWS End User Messaging を通じて行われる
  • ダイレクト送信 (特定の電話番号への直接送信) にも対応

🔧 技術仕様

SMS 送信方式

項目詳細
ダイレクト送信トピックを使用せず、特定の電話番号へ直接 SMS を送信
トピック経由送信SNS トピックにサブスクライブした複数の電話番号へブロードキャスト
配信基盤AWS End User Messaging
対応範囲200 以上の国と地域

SMS メッセージタイプ

タイプ用途
TransactionalOTP やトランザクション通知など、高い配信信頼性が求められるメッセージ
Promotionalプロモーションやマーケティングなど、コスト最適化を重視するメッセージ

🛠️ 設定方法

前提条件

  • ソウルリージョンで Amazon SNS を利用できる AWS アカウント
  • SMS 送信に必要な IAM 権限 (sns:Publish など)
  • 送信先によっては送信者 ID (Sender ID) や専用番号の事前登録が必要

ステップ 1: ダイレクト SMS 送信

Bash特定の電話番号へ直接送信 (E.164 形式)
aws sns publish \
  --region ap-northeast-2 \
  --phone-number "+821012345678" \
  --message "お客様のワンタイムパスワードは 123456 です。"

ステップ 2: トピック経由のブロードキャスト送信

Bash電話番号をサブスクライブ → トピックへ発行
# トピックに電話番号をサブスクライブ
aws sns subscribe \
  --region ap-northeast-2 \
  --topic-arn arn:aws:sns:ap-northeast-2:123456789012:MyTopic \
  --protocol sms \
  --notification-endpoint "+821012345678"

# トピックへメッセージを発行
aws sns publish \
  --region ap-northeast-2 \
  --topic-arn arn:aws:sns:ap-northeast-2:123456789012:MyTopic \
  --message "システムメンテナンスのお知らせです。"

✅ メリット

💼 ビジネス面

  • データレジデンシー対応: ソウルリージョン内で SMS 送信を完結
  • グローバルリーチ: 200 以上の国と地域への配信
  • 顧客体験の向上: OTP やトランザクション通知を迅速に配信

🔧 技術面

  • アーキテクチャの簡素化: リージョンをまたぐ構成が不要
  • レイテンシーの低減: リージョン間通信のオーバーヘッドを削減
  • 既存サービスとの統合: pub/sub モデルを活用し容易に統合

⚠️ デメリット・制約事項

制限事項

  • 送信先によっては送信者 ID や専用番号の登録、規制対応が必要
  • SMS にはサイズ制限があり、長いメッセージは複数に分割される
  • 一部の国ではプロモーション SMS の送信に制限がある

考慮すべき点

  • アカウントの送信制限 (スペンドリミット) が適用される場合があり、必要に応じて引き上げ申請する
  • 配信信頼性が重要なメッセージには Transactional タイプを使用する
  • 各国の通信規制やオプトイン / オプトアウト要件への準拠が必要

🎯 ユースケース

1. ワンタイムパスワード (OTP) の配信
シナリオ: 韓国国内ユーザー向け認証システムで、ログイン時の二要素認証用 OTP を SMS 配信する。
BashTransactional タイプで OTP 送信
aws sns publish \
  --region ap-northeast-2 \
  --phone-number "+821098765432" \
  --message "認証コード: 654321 (5 分間有効)" \
  --message-attributes '{"AWS.SNS.SMS.SMSType":{"DataType":"String","StringValue":"Transactional"}}'
→ ソウルリージョン内で完結する低レイテンシーかつ高信頼な OTP 配信を実現
2. トランザクション通知のブロードキャスト
シナリオ: E コマースサイトで注文確定や配送状況の更新を複数ユーザーへ一斉に SMS 通知する。
Bashトピックへ発行してブロードキャスト
aws sns publish \
  --region ap-northeast-2 \
  --topic-arn arn:aws:sns:ap-northeast-2:123456789012:OrderUpdates \
  --message "ご注文の商品が発送されました。追跡番号: 1234567890"
→ サブスクライブされた多数の顧客へ効率的にトランザクション通知を配信
3. システムアラート通知
シナリオ: 運用チームへのシステム障害アラートを SMS で即時通知する。
Bash運用アラートを SMS で即時通知
aws sns publish \
  --region ap-northeast-2 \
  --topic-arn arn:aws:sns:ap-northeast-2:123456789012:OpsAlerts \
  --message "[ALERT] 本番環境で CPU 使用率が閾値を超過しました。"
→ E メールに依存しない即時性の高いアラートで、インシデント対応の初動を早める

💰 料金 & 利用可能リージョン

SMS 送信は Amazon SNS の SMS 料金体系に従って課金されます。料金は送信先の国や地域、 メッセージタイプ (Transactional / Promotional) によって異なります。 最新の料金は Amazon SNS の料金ページを参照してください。

🌏 アジアパシフィック (ソウル) リージョン — ap-northeast-2

その他のリージョンでの SMS 送信サポートは、ドキュメントの「サポートされている国とリージョン」を参照してください。

🔗 関連サービス・機能

  • 📨 AWS End User Messaging: SMS の配信基盤。SNS の SMS 送信はこのサービスを通じて行われる
  • 📥 Amazon SQS: SNS と連携し、メッセージのキューイングと処理に利用
  • ⚡ AWS Lambda: SNS トピックのサブスクライバーとして、受信時の処理を実行
  • 🔥 Amazon Data Firehose: SNS から配信されたメッセージをデータストアへストリーミング

💡 まとめ

ソウルリージョンの Amazon SNS から直接 SMS を送信できるようになりました。韓国国内ワークロードで データレジデンシー要件に対応しつつ、200 以上の国と地域へのグローバルな SMS 配信が可能になります。ソウルリージョンで SMS を利用しているお客様は、リージョンをまたぐ既存構成の見直しと、 メッセージタイプや送信制限の確認を進めることが推奨されます。
