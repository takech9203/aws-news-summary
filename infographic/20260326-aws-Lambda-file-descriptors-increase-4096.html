📋 概要

AWS Lambda が Lambda Managed Instances (LMI) 上で実行される関数のファイルディスクリプタ上限を 1,024 から 4,096 に引き上げました。LMI はマネージドな Amazon EC2 インスタンス上で Lambda 関数を実行する機能で、ルーティング、ロードバランシング、オートスケーリングが組み込まれています。複数のリクエストを同時に処理するため、各リクエストが開くファイル、ネットワークソケット、内部リソースがそれぞれファイルディスクリプタを消費します。今回の上限引き上げにより、高並行性の Web サービスやファイル集約型のデータ処理パイプラインなどのワークロードを、制限に悩まされることなく実行できるようになりました。

🔄 Before / After

❌ Before
•FD 上限が 1,024 に制限
•高並行性 Web サービスで同時接続数が不足する可能性
•ファイル集約型データ処理で "Too many open files" エラーのリスク
→
✅ After
•FD 上限が 4,096 に引き上げ (4 倍)
•FD 制限を気にせず高並行性 Web サービスを実行可能
•より多くのファイルやソケットを同時に扱える

🔧 主要機能

📈 ファイルディスクリプタ上限の 4 倍引き上げ
LMI 上の Lambda 関数で利用可能なファイルディスクリプタ上限が 1,024 から 4,096 に増加。追加設定は不要で自動的に新しい上限が適用されます。開いたファイル、ネットワークソケット、内部リソースの全てに適用されます。
⚡ 高並行性ワークロードのサポート強化
LMI は複数のリクエストを 1 つのインスタンス上で同時処理するため、従来よりも多くの並行接続を維持可能に。Web サービスでの同時接続数の実質的な上限が大幅に拡大しました。
💾 I/O 集約型パイプラインへの対応
ファイル集約型のデータ処理パイプラインで同時に開くことができるファイル数が増加。データ変換やバッチ処理などの ETL ワークロードでの柔軟性が向上しました。

⚙️ 設定方法

前提条件: AWS アカウント、LMI を使用する Lambda 関数、AWS CLI v2 がインストールされていること。

Step 1: 現在のファイルディスクリプタ上限を確認

Python FD 上限確認 
import resource
import os

def lambda_handler(event, context):
    soft, hard = resource.getrlimit(resource.RLIMIT_NOFILE)
    return {
        'soft_limit': soft,
        'hard_limit': hard,
        'current_open_fds': len(os.listdir('/proc/self/fd'))
    }

LMI 上で実行されている場合、上限が 4,096 と表示されます。

Step 2: Lambda Managed Instances で関数を設定

Bash LMI 設定 
# Lambda 関数を LMI で実行するよう設定
aws lambda update-function-configuration \
  --function-name my-function \
  --compute-platform ManagedInstances

設定後、ファイルディスクリプタの上限は自動的に 4,096 に引き上げられます。

Step 3: ファイルディスクリプタの使用状況をモニタリング

Python FD モニタリング 
import os

def lambda_handler(event, context):
    open_fds = len(os.listdir('/proc/self/fd'))
    print(f"Currently open file descriptors: {open_fds}/4096")

    # ファイルディスクリプタの使用率をチェック
    usage_percent = (open_fds / 4096) * 100
    if usage_percent > 80:
        print(f"WARNING: FD usage is at {usage_percent:.1f}%")

    return {'fd_usage': open_fds}

本番環境では FD 使用状況のモニタリングを推奨します。使用率が高い場合はアラートを設定し、リソースリークを早期に検出できるようにします。

⚠️ 制限事項・注意点

✗LMI 上の関数のみが対象。標準 Lambda 実行環境には適用されない
✗上限は 4,096。超える場合は別アーキテクチャの検討が必要
✗LMI は通常の Lambda と異なる料金体系
考慮すべき点
▶FD リークがある場合、上限引き上げは根本的な解決にならない
▶高並行処理では FD 以外のリソース (メモリ、CPU) も考慮が必要

💡 ユースケース

🌐 ユースケース 1: 高並行性 Web サービス
REST API を提供する Lambda 関数が LMI 上で多数のクライアントからの同時リクエストを処理。各リクエストがデータベース接続やキャッシュへの接続でファイルディスクリプタを消費するシナリオ。
Python 高並行性 Web サービス例 
import urllib3

http = urllib3.PoolManager(maxsize=50)

def lambda_handler(event, context):
    # 複数のバックエンドサービスに同時接続
    responses = []
    for endpoint in event['endpoints']:
        resp = http.request('GET', endpoint)
        responses.append(resp.data)
    return {'results': len(responses)}
→ 従来の 1,024 では制約されていた同時接続数が、4,096 への引き上げで大幅に安定して維持可能に
📂 ユースケース 2: ファイル集約型データ処理パイプライン
大量の CSV / JSON ファイルを同時に読み込み、変換して S3 にアップロードする ETL パイプライン。
Python ETL パイプライン例 
import boto3
import concurrent.futures

s3 = boto3.client('s3')

def lambda_handler(event, context):
    files = event['files']
    results = []

    # 同時に多数のファイルを処理
    with concurrent.futures.ThreadPoolExecutor(max_workers=100) as executor:
        futures = {
            executor.submit(process_file, f): f for f in files
        }
        for future in concurrent.futures.as_completed(futures):
            results.append(future.result())

    return {'processed': len(results)}
→ 同時に開くファイル数の上限が 4 倍に増加し、バッチサイズを大きくできスループットが向上
🔗 ユースケース 3: マイクロサービス間通信の集約 (BFF パターン)
API Gateway の背後で動作する Lambda 関数が複数のマイクロサービスに対して同時にリクエストを送信し、結果を集約する Backend for Frontend パターン。
Python BFF パターン例 
import asyncio
import aiohttp

async def fetch_all(endpoints):
    async with aiohttp.ClientSession() as session:
        tasks = [session.get(url) for url in endpoints]
        return await asyncio.gather(*tasks)

def lambda_handler(event, context):
    endpoints = [
        'https://service-a.internal/api/data',
        'https://service-b.internal/api/data',
        'https://service-c.internal/api/data',
        # ... 多数のサービスエンドポイント
    ]
    results = asyncio.run(fetch_all(endpoints))
    return {'aggregated': len(results)}
→ 多数のマイクロサービスへの同時接続が可能になり、レスポンス集約のレイテンシが改善

💰 料金情報

今回のファイルディスクリプタ上限の引き上げに伴う追加料金は発生しません。料金は Lambda Managed Instances の通常の利用料金に従います。LMI の料金は使用する EC2 インスタンスタイプと実行時間に基づいて課金されます。
