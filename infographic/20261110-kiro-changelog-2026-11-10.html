📋 概要

エンタープライズ向けガバナンス機能 Enterprise Management のプレビュー提供、xAI の最新モデル Grok 4.7 の実験的サポート、Kiro CLI 3.2 のリリース、Kiro Crew 0.12 における Bots の全ユーザー開放とブラウザテイクオーバー機能という、4 つの大きなアップデートが発表された。

😣 アップデート前の課題

  • 利用ポリシーをクライアント (IDE、CLI、Web、Crew) ごとに個別管理。組織全体の一貫した統制手段がなかった
  • Grok 系の最新モデルを Kiro から利用できなかった
  • ターミナル幅を超える Mermaid 図は CLI で読みづらく、動的クライアント登録のない MCP サーバーには OAuth 設定の手動記述が必要だった
  • Crew の Mates はプレビュー扱いで、エージェントのブラウザ操作中にユーザーが介入する手段がなかった

😊 アップデート後の改善

  • AWS コンソールの 1 つのポリシーが、全開発者の Kiro IDE、CLI、Web、Crew LTS に自動適用
  • Grok 4.7 (500K トークン) を Pro、Pro+、Pro Max、Power プランで利用可能に
  • ワイドな Mermaid 図を専用画面で全幅表示。Client ID Metadata Documents 対応 MCP サーバーへ OAuth 設定なしでサインイン
  • Bots が全インストールで有効化。Bot ごとに Git ワーキングツリーで作業分離、ブラウザ操作をワンクリックで引き継ぎ可能に

Enterprise Management の構成。管理者が AWS コンソールの Controls ページで記述した 1 つのポリシーが、プロファイルに属するすべての開発者の Kiro クライアント (IDE、CLI、Web、Crew LTS) に配布・適用される。

🚀 主要機能

🏢 1. Enterprise Management プレビュー: すべての Kiro クライアントに 1 つのポリシー
  • 米国東部 (バージニア北部) us-east-1 で新規作成した Kiro プロファイルで利用可能。作成すると Controls ページが追加設定なしでコンソールに表示 (既存・欧州プロファイルは後日対応)
  • ポリシーは 3 要素で構成: ルール (モデル利用、シェルコマンド、ファイル読み書き、Web 検索、MCP ツール呼び出しを allow / deny / ask で制御)、設定 (デフォルトモデル、プロンプトログ、使用状況レポート)、配布物 (ステアリングファイル、Skills、Powers)
  • ルールはプロファイル全体、特定グループ、特定ユーザーを対象に適用可能
  • ID ソースとして IAM Identity Center、Okta、Microsoft Entra ID と連携
  • デフォルト動作: モデル、API キー、Crew のメッセージング・ネットワークアクセスは許可されるまで拒否。ファイル、シェル、Web、MCP、スケジュールジョブは Kiro 自身のデフォルトを維持
  • Kiro Crew LTS: 統制された組織向け Crew エディション。Crew 固有の第 2 層ルール (メッセージングチャネル、承認モード、スケジュールジョブ、fetch 到達可能ホスト、ブラウザ操作、Tailscale 公開、サードパーティテーマ) を適用。通常の Crew と並行インストールされ、lts チャネルからのみ更新
🤖 2. Grok 4.7 が Kiro で利用可能に
  • Kiro IDE、CLI、Crew、Web の全クライアントで実験的サポートとして提供
  • 対象プランは Pro、Pro+、Pro Max、Power
  • xAI のコーディング・ナレッジワーク向け最上位モデル。数時間に及ぶ困難なタスクでも集中を維持し、次に進む前に自己検証を行う設計
  • コンテキストウィンドウは 500K トークン
  • モデルリスト更新には IDE / CLI の再起動、Crew では kirocrew restart、Web ではブラウザ更新が必要
⌨️ 3. Kiro CLI 3.2.0 リリース (最新パッチ: 3.2.1)
  • フルスクリーン図ビューア: ターミナル幅を超える Mermaid 図を Ctrl+] または /diagram で専用画面に全幅表示。矢印キー・マウスホイールで移動、Tab で過去の図へ切り替え、Esc でドラフトを保持したままチャットへ復帰。キーは chat.keybindings.viewDiagram で変更可能
  • MCP サインイン改善: Client ID Metadata Documents 対応かつ動的クライアント登録のないサーバー (例: Tableau のホステッド MCP) に、Kiro のホステッドクライアントメタデータドキュメントでサインイン可能。oauth ブロックの記述が不要。設定済みの clientId / clientMetadataUrl は従来どおり優先
  • ワークフローループの追加実行・完了、自律モードでのワークフロー利用不可通知、V2 シェルコマンドの環境変数設定前確認、ファイル検索・カスタムエージェント・スペック・Hook などの修正
  • パッチ 3.2.1 (11 月 11 日): ツール呼び出し出力詳細度の /settings 選択を全ユーザーに展開、Linux ホストのサインイン問題などを修正
🤝 4. Kiro Crew 0.12: Bots for Everyone とブラウザテイクオーバー
  • Mates は Bots に改称: 全画面・プロンプト・コマンドバーで名称を統一し、プレビュースイッチなしで全インストールで有効化。旧 .crewjam / .crewmate ファイルのインポートも引き続き可能
  • Bot ごとの分離: 各 Bot は自身のサイドバーフォルダにチャットを保持し、リポジトリごとに専用の Git ワーキングツリーで作業。.kirobot ファイルでエクスポート / インポート可能。委譲された作業はワークレジャーで追跡
  • ブラウザのライブ表示とテイクオーバー: エージェントのブラウザ操作をチャットにライブ配信。画像クリックで操作を引き継ぎ、手動ステップ後にエージェントへ返却。サインインはシートがシークレットを代理入力し、エージェントは内容を見ず保存もされない
  • エージェントハーネス追加: Strands CLI と GitHub Copilot CLI をハーネスとして選択可能に
  • Connections とナレッジ: Gmail、Google Drive、Calendar、Sheets、Docs、Slides を追加 (読み取り専用スコープ)。Amazon Bedrock Knowledge Base をナレッジ検索にライブ統合
  • 通知の強化: アプリを閉じた後もインストール済み Web アプリ (iOS ホーム画面追加を含む) にプッシュ通知。カテゴリごとのカスタムサウンド (MP3、WAV、OGG) に対応
  • そのほか: Developer Mode 廃止 (Settings → Developer が常時表示)、Crew Mode は Ultra Mode に改称。Feature Previews に Ultra Mode、Explore、Bot ごとのハーネス、Shared Crew、Remote dispatch

⚙️ 設定方法

✅ 前提条件

✓Enterprise Management を利用する場合、us-east-1 で新規に Kiro プロファイルを作成できる AWS アカウントがあること
✓Kiro IDE 1.4.154 以降、Kiro CLI 3.1.0 以降にアップデートしていること
✓Grok 4.7 を利用する場合、Pro、Pro+、Pro Max、Power のいずれかのプランに加入していること
1
Enterprise Management の開始
AWS コンソールで米国東部 (バージニア北部) リージョンを選択し、新規 Kiro プロファイルを作成する。Controls ページが追加のセットアップなしで表示されるので、allow / deny / ask のルール、デフォルトモデルなどの設定、配布するステアリングファイル・Skills・Powers を定義する。
2
Kiro Crew LTS のインストール
Bash Kiro Crew LTS のセットアップ 
# 組織の SSO 経由で Kiro CLI からサインイン
kiro-cli login

# 各プラットフォーム向けインストーラをダウンロード
# macOS: KiroCrew-LTS.dmg / KiroCrew-LTS-arm64.dmg
# Linux: KiroCrew-LTS-x86_64.AppImage
# Windows: KiroCrew-LTS-Setup.exe
Kiro Crew LTS には専用のサインインダイアログがないため、事前に Kiro CLI から組織の SSO (IAM Identity Center または外部 ID プロバイダー) でサインインしておく。未サインインの場合はゲートウェイエラーが表示されるので、サインイン後に Retry を選択する。
3
Grok 4.7 の利用開始
Bash モデルリストの更新 
# Kiro Crew の場合はプロセスを再起動してモデルリストを更新
kirocrew restart
IDE または CLI は再起動、Kiro Web はブラウザの更新で最新のモデルリストが読み込まれ、モデルピッカーから Grok 4.7 を選択できる。
4
CLI のフルスクリーン図ビューアの利用
Bash Kiro CLI チャット内 
# ワイドな Mermaid 図を専用画面で開く
/diagram
Mermaid 図がターミナル幅を超える場合、Ctrl+] または /diagram で専用画面を開き、矢印キーで移動、Tab で過去の図に切り替え、Esc でチャットに戻る。

💼 ビジネス面

✓組織統制の一元化: 単一ポリシーで全 Kiro クライアントを統制し、設定漏れによるガバナンスリスクを低減
✓既存 ID 基盤の活用: IAM Identity Center、Okta、Microsoft Entra ID と連携し、既存の ID 管理プロセスをそのまま利用可能
✓セキュアバイデフォルト: モデル、API キー、Crew のメッセージング・ネットワークアクセスは明示的に許可するまで拒否

✓Bot 単位の作業分離: Bot ごとの独立 Git ワーキングツリーで、複数の自律エージェントを安全に並行稼働
✓ブラウザ操作の透明性: ライブ表示で必要な時点で人間が介入。シークレットはエージェントから隔離されたまま代理入力
✓MCP 接続の簡素化: 動的クライアント登録のないサーバーにも OAuth 設定なしで接続可能

⚠️ デメリット・制約事項

🚧 制限事項

✗Enterprise Management はプレビューで、us-east-1 で新規作成したプロファイルのみが対象。既存・欧州プロファイルは後日対応予定
✗Grok 4.7 は実験的サポートで、クレジット倍率が 2.7 倍 (200K トークン超は 5.4 倍) と高めに設定
✗Kiro Crew LTS では Feature Previews と Debug tools が無効化され、auto-approve はルールで許可されない限りオフ
✗Enterprise Management の利用には Kiro IDE 1.4.154 以降、Kiro CLI 3.1.0 以降が必要

🤔 考慮すべき点

⚠Mates → Bots の改称、Developer Mode の廃止、MCP Management の Connections ページへの移動など UI 構成が変更されており、運用手順書の更新が必要
⚠Bedrock Knowledge Base の登録は検索ごとにライブクエリが発生。初回確認カードの AWS アカウント・リージョン・コストを確認してから有効化する
⚠Grok 4.7 の利用可否は Enterprise Management のモデルルールの影響を受ける (許可されるまでモデルは拒否)

🎯 ユースケース

🏢 ユースケース 1: 全社での Kiro 利用ポリシーの統一

シナリオ: 数百名の開発者が IDE、CLI、Web と異なる Kiro クライアントを使っており、セキュリティ部門が利用可能モデルと実行可能コマンドを一元統制したい。

実装: us-east-1 で Kiro プロファイルを新規作成し IAM Identity Center と連携 → Controls ページで承認済みモデルのみ allow、破壊的シェルコマンドは ask、共通のステアリングファイルと Skills を配布物に登録 → グループ単位のルールでチームごとの例外を設定。

効果: 1 つのポリシーが IDE、CLI、Web、Crew LTS のすべてに適用され、クライアントごとの設定作業と監査負荷を削減できる。

🧠 ユースケース 2: 大規模コードベースのリファクタリングに Grok 4.7 を活用

シナリオ: モノレポ全体にまたがる長時間のリファクタリングタスクで、広いコンテキストを維持できるモデルを使いたい。

実装: IDE / CLI を再起動してモデルリストを更新 → モデルピッカーで Grok 4.7 を選択 → リクエストを 200K トークン以下に収めてクレジット倍率 2.7 倍で運用。

効果: 500K トークンのコンテキストウィンドウと自己検証型の動作により、数時間に及ぶマルチステップタスクでも一貫した作業を期待できる。

🌐 ユースケース 3: ブラウザテイクオーバーによる安全な Web 操作の委任

シナリオ: エージェントに Web ベースの管理画面の操作を任せたいが、サインインや重要な確認ステップは人間が実施したい。

実装: Kiro Crew 0.12 の Settings → Browser でライブビューを有効化 → ブラウザ操作タスクを依頼しライブ表示を監視 → サインインや確認ダイアログで画像をクリックして操作を引き継ぎ、完了後にエージェントへ返却。

効果: 認証情報をエージェントに渡すことなく Web 操作を自動化でき、重要な操作のみ人間が確実に関与するワークフローを実現できる。

💰 料金

Kiro の既存サブスクリプションプラン (Pro、Pro+、Pro Max、Power など) の枠内で提供される。Grok 4.7 の利用は、200K トークン以下のリクエストで 2.7 倍、200K トークンを超えるリクエストで 5.4 倍 のクレジット倍率が適用される。Enterprise Management プレビューおよび Kiro Crew 0.12 の新機能自体に追加料金の記載はない。Bedrock Knowledge Base をナレッジソースとして利用する場合は、接続先 AWS アカウント側でクエリコストが発生する。
