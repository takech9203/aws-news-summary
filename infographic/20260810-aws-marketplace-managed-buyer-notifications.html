📌 概要

AWS Marketplace の購入者向け通知が AWS User Notifications (マネージド通知) に統合されました。 通知を 4 つのカテゴリに分類して管理し、メール、AWS Console Mobile Application、 Slack や Microsoft Teams のチームチャネルなど複数のチャネルで受信できます。

これまで通知はルートユーザーのメールアドレスにのみ送信されていましたが、調達チーム、契約更新チーム、 コスト管理チームなど、役割の異なる担当者がそれぞれ関連するカテゴリの通知だけを適切なチャネルで受け取れるようになります。

❌ アップデート前の課題
  • 通知はルートユーザーのメールにのみ送信され、各チームはアラートを見逃したりメール転送に依存
  • 通知種別ごとに受信者を分けられない
  • チャットツールやモバイルアプリなどメール以外のチャネルがない
✅ アップデート後の改善
  • 4 つのカテゴリに分類して通知を管理
  • 追加メールアドレス、配布リスト、モバイルアプリ、Slack / Microsoft Teams へ配信可能
  • 受信者ごとに役割に関連するカテゴリのみを受信するよう調整可能
⚠️
2027 年 1 月に自動有効化: すべての顧客に対してカテゴリ管理と配信管理が自動的に有効化される予定です。既存の通知は変更なく継続されますが、 今すぐオプトインすることで早期にカスタマイズを開始できます。

🛠️ 設定方法

✅ 前提条件

✓AWS アカウントを保有し、AWS Marketplace で製品を購入またはサブスクライブしていること
✓AWS User Notifications コンソールへのアクセス権限があること
✓Slack や Microsoft Teams へ配信する場合は、Amazon Q Developer in chat applications の設定が必要

📝 手順

1
AWS User Notifications コンソールでマネージド通知を確認
マネージド通知セクションにアクセスし、AWS Marketplace のマネージド通知にオプトインします。
URLマネージド通知コンソール
https://us-east-1.console.aws.amazon.com/notifications/home#/managed-notifications
2
カテゴリごとのサブスクリプションを設定
4 つのカテゴリごとに通知の有効・無効と受信者を設定します。デフォルトではすべてのカテゴリが有効で、ルートアカウントのメールアドレスに送信されます。
3
配信チャネルを追加
各カテゴリに対して、追加のメールアドレス、配布リスト、AWS Console Mobile Application、Slack や Microsoft Teams のチームチャネルを配信先として追加します。
4
メールフィルタの更新
メールフィルタやルールを使用している場合は、新しい送信元アドレス marketplace@aws.com を許可するように更新します。

💡 メリット

💼 ビジネス面

✓通知の見逃し防止: 各チームが必要な通知を直接受け取れるため、重要なイベントの見逃しやメール転送への依存を解消
✓役割ベースの情報配信: 受信者ごとに関連カテゴリのみを配信し、各チームがノイズなく必要な情報に集中
✓コスト管理の強化: 価格引き上げを早期に把握し、予算計画に反映可能

⚙️ 技術面

✓マルチチャネル対応: モバイルアプリやチームチャネルで受信でき、既存ワークフローに統合しやすい
✓一元管理: AWS User Notifications のコンソール通知センターで通知を一元的に確認・管理
✓追加実装が不要: EventBridge ルールや SNS トピックを個別に構築することなく、コンソール設定のみで利用可能

⚠️ デメリット・制約事項

🚧 制限事項

✗2027 年 1 月にすべての顧客へ自動的に有効化されるため、それまでに通知運用の見直しが推奨される
✗通知カテゴリは 4 種類に固定されており、独自のカテゴリを定義することはできない
✗Slack や Microsoft Teams への配信には Amazon Q Developer in chat applications の設定が別途必要

🤔 考慮すべき点

⚠送信元メールアドレスが no-reply@marketplace.aws から marketplace@aws.com に変わるため、メールフィルタ使用時は事前の更新が必要
⚠ルートユーザーメールのみの運用から移行する場合は、通知の受信者と配信チャネルの設計を社内で整理しておく必要がある
⚠EventBridge や Amazon SNS ベースの既存の通知連携がある場合は、マネージド通知との使い分けを検討する必要がある

🎯 ユースケース

1️⃣ 調達チームへのプライベートオファー通知の直接配信

シナリオ: 調達チームがプライベートオファーを管理しているが、通知がルートユーザーのメールにのみ届くため、オファー受領の確認が遅れていた。

設定例
1. AWS User Notifications コンソールでマネージド通知にオプトイン
2. プライベートオファーカテゴリの配信先に調達チームの
   Slack チャネルと配布リストを追加
3. 他のカテゴリは調達チームには配信しないよう設定
✅ 効果: 新規プライベートオファーと承諾確認をリアルタイムで把握でき、オファーへの対応時間を短縮。
2️⃣ コスト管理チームによる価格変更の監視

シナリオ: FinOps チームがサブスクライブ中の Marketplace 製品の価格変更を監視し、予算への影響を早期に評価したい。

設定例
1. 価格変更カテゴリの配信先に FinOps チームの
   メール配布リストを追加
2. AWS Console Mobile Application でも受信するよう設定し、
   外出先でも価格引き上げを確認可能にする
✅ 効果: 価格引き上げを早期に検知し、コスト予測の修正や代替製品の検討を迅速に開始。
3️⃣ 契約更新・支払い失敗の運用チームへの通知

シナリオ: サブスクリプションの更新漏れや支払い失敗によるサービス停止リスクを回避するため、契約ライフサイクルイベントを運用チームで監視したい。

設定例
1. 契約とサブスクリプションカテゴリの配信先に
   運用チームの Microsoft Teams チャネルを追加
2. 支払い失敗や更新の通知をチーム全体で共有し、
   対応漏れを防止する体制を構築
✅ 効果: 契約の開始、キャンセル、更新、支払い失敗をチーム全体で即座に把握し、サービス継続性リスクを低減。
