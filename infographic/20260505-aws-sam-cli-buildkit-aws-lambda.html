AWS SAM CLI

BuildKit サポートによる
コンテナイメージビルドの強化

2026-05-05

📋 概要

AWS SAM CLI が BuildKit をサポートし、Lambda 関数をコンテナイメージとしてパッケージングする際のビルドが大幅に強化された。SAM CLI バージョン 1.159.0 以降で --use-buildkit フラグを使用することで、マルチステージビルド、並列化、キャッシング強化、クロスアーキテクチャビルド、Docker シークレットなどの高度な機能を Docker および Finch の両方で活用できる。

Before

  • BuildKit 非対応でビルド最適化手段が限定的
  • マルチステージビルドによる本番イメージ軽量化が不可
  • クロスアーキテクチャビルドが困難
  • シークレット情報の安全な取り扱い手段が限られていた

After

  • マルチステージビルドで軽量な本番イメージを作成
  • キャッシング強化でリビルド時間を短縮
  • 同一マシンから x86_64 / arm64 の両方をビルド
  • Docker シークレットで機密データをイメージから除外

🏗️ アーキテクチャ図

🚀 主要機能

📦 マルチステージビルド

ビルドステージと実行ステージを分離し、開発ツールやビルド依存関係を最終イメージから除外。本番イメージのサイズを大幅に削減し、Lambda のコールドスタート時間短縮に貢献する。

💾 改善されたキャッシング

BuildKit のインテリジェントなレイヤーキャッシュにより、変更のないステップの再実行を回避。差分ビルドの高速化により開発サイクルが改善され、CI/CD パイプラインでのビルド時間も短縮される。

⚙️ ビルドステップの並列化

依存関係のないビルドステップを同時に実行。ビルドグラフの最適化により全体的なビルド時間を短縮する。

🦾 クロスアーキテクチャビルド

同一開発マシンから x86_64 と arm64 の両アーキテクチャ向けイメージをビルド可能。Intel ベースの開発マシンから AWS Graviton2 向け Lambda 関数を直接ビルドでき、アーキテクチャ固有のテスト環境が不要になる。

🔒 Docker シークレット

ビルド時に必要な認証情報や API キーを安全に注入。シークレットは最終イメージレイヤーに残らないため、セキュリティリスクを低減。プライベートリポジトリからの依存関係取得に活用可能。

⚡ 設定方法

Step 1: SAM CLI のアップデート

Bash SAM CLI アップデート 
# pip を使用してアップデート
pip install --upgrade aws-sam-cli

# バージョン確認
sam --version

Step 2: BuildKit を有効にしてビルド

Bash BuildKit ビルド実行 
# BuildKit フラグを指定してビルド
sam build --use-buildkit

Step 3: マルチステージビルドの Dockerfile

Dockerfile マルチステージビルド例 
# ビルドステージ
FROM public.ecr.aws/lambda/python:3.12 AS builder
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt -t /opt/python

# 本番ステージ
FROM public.ecr.aws/lambda/python:3.12
COPY --from=builder /opt/python /opt/python
COPY app.py ${LAMBDA_TASK_ROOT}
CMD ["app.handler"]

Step 4: クロスアーキテクチャビルド

Bash arm64 向けビルド 
# arm64 向けビルド (Intel マシンから)
sam build --use-buildkit --parameter-overrides Architecture=arm64

Step 5: Docker シークレットの使用

Dockerfile シークレットマウント 
# Dockerfile 内でシークレットを使用
RUN --mount=type=secret,id=my_secret \
    pip install -r requirements.txt --extra-index-url $(cat /run/secrets/my_secret)

📄 SAM テンプレート設定例

YAML template.yaml 
# template.yaml (SAM テンプレート)
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31

Resources:
  MyFunction:
    Type: AWS::Serverless::Function
    Properties:
      PackageType: Image
      Architectures:
        - arm64
    Metadata:
      DockerTag: latest
      DockerContext: ./app
      Dockerfile: Dockerfile

🎯 ユースケース

🤖 UC1: ML 推論用 Lambda 関数の軽量化

機械学習モデルを含む Lambda 関数で、ビルド時に大量のコンパイルツール (gcc, cmake 等) が必要だが、実行時には不要なケース。マルチステージビルドでビルドツールを最終イメージから除外する。

Dockerfile ML 推論用マルチステージビルド 
# syntax=docker/dockerfile:1
FROM public.ecr.aws/lambda/python:3.12 AS builder
RUN yum install -y gcc gcc-c++ cmake
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt -t /opt/python

FROM public.ecr.aws/lambda/python:3.12
COPY --from=builder /opt/python /opt/python
COPY model/ ${LAMBDA_TASK_ROOT}/model/
COPY handler.py ${LAMBDA_TASK_ROOT}
CMD ["handler.lambda_handler"]
イメージサイズを 50% 以上削減し、コールドスタート時間を短縮

💰 UC2: Graviton2 向けクロスビルドによるコスト最適化

開発チームが Intel Mac を使用しているが、Lambda 関数を Graviton2 (arm64) で実行してコストを削減したいケース。クロスアーキテクチャビルドで同一マシンから arm64 イメージを生成する。

Bash ビルド、テスト、デプロイ 
# SAM テンプレートで arm64 を指定
sam build --use-buildkit

# ローカルテスト
sam local invoke MyFunction

# デプロイ
sam deploy
arm64 Lambda は x86_64 と比較して最大 20% のコスト削減と優れたパフォーマンスを実現

🔐 UC3: プライベートリポジトリからの安全な依存関係取得

社内のプライベート PyPI リポジトリから認証付きでパッケージを取得する必要があるが、認証情報をイメージに残したくないケース。Docker シークレットで認証トークンを安全に扱う。

Dockerfile シークレットマウントによる認証 
# syntax=docker/dockerfile:1
FROM public.ecr.aws/lambda/python:3.12
RUN --mount=type=secret,id=pip_token \
    pip install --no-cache-dir \
    --extra-index-url https://$(cat /run/secrets/pip_token)@private.pypi.example.com/simple/ \
    -r requirements.txt -t ${LAMBDA_TASK_ROOT}
COPY app.py ${LAMBDA_TASK_ROOT}
CMD ["app.handler"]
認証トークンが最終イメージに残らず、イメージ漏洩時もプライベートリポジトリへのアクセスが保護される

⚠️ 制約事項・注意点

!--use-buildkit フラグの明示的な指定が必要 (デフォルトでは無効)
!ZIP パッケージング形式の Lambda 関数には適用されない (コンテナイメージのみ)
!BuildKit 特有の Dockerfile 構文を使用する場合、非対応環境との互換性に注意
考慮すべき点:
  • 既存の Dockerfile を BuildKit 向けに最適化する作業が必要な場合がある
  • クロスアーキテクチャビルドでは QEMU エミュレーションのため、ネイティブビルドより時間がかかる可能性がある
  • CI/CD 環境でのキャッシュ活用には、キャッシュストレージの適切な設定が必要

💰 料金

SAM CLI は無料で使用できるオープンソースツールであり、BuildKit サポートの追加に伴う追加料金は発生しない。Lambda 関数の実行やコンテナイメージの保存 (Amazon ECR) に関する料金は通常の AWS サービス料金に従う。

🌍 利用可能リージョン

SAM CLI はローカル開発ツールであるため、リージョンに依存しない。ビルドしたコンテナイメージは、Lambda のコンテナイメージデプロイをサポートする全ての AWS リージョンにデプロイ可能。
