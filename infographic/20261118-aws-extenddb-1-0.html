🗄️ ExtendDB 1.0 リリース

DynamoDB 互換のオープンソースアダプター、初のプロダクション対応リリース
📅 リリース日: 2026 年 11 月 18 日

📝 概要

AWS は、Amazon DynamoDB 互換のオープンソースアダプター ExtendDB 1.0 を発表しました。 DynamoDB API と完全な互換性を持つため、アプリケーションコードを変更することなく、 DynamoDB スタイルのワークロードをオンプレミス、プライベートクラウド、パブリッククラウド、エッジ環境など、 任意のインフラストラクチャ上で実行できます。

ストレージバックエンドとして PostgreSQL、SQLite、Cassandra、MongoDB の 4 種類をサポート。 ローカル開発や CI 向けには、extenddb-dev コンテナイメージと @extenddb/dev npm パッケージが提供されます。 AWS がメンテナンスし、Apache 2.0 ライセンスで GitHub 上にてオープンに開発されています。

❌ Before: アップデート前の課題
  • DynamoDB API 利用アプリは AWS クラウド上の DynamoDB に依存し、オンプレミスやエッジで同じコードを実行することが困難
  • ローカル開発や CI で DynamoDB 相当の動作を再現するには、追加セットアップやエミュレーターの管理が必要
  • 規制やデータ主権の要件で AWS 外でのデータ保持が必要な場合、アプリケーションの移植にコード変更が必要
✅ After: アップデート後の改善
  • DynamoDB API と完全互換のため、コード変更なしで任意のインフラ上で DynamoDB スタイルのワークロードを実行可能
  • PostgreSQL、SQLite、Cassandra、MongoDB の 4 種類から要件に応じてバックエンドを選択可能
  • extenddb-dev コンテナと npm パッケージで、外部データベース不要のローカル開発・CI 環境を即座に構築可能

アプリケーションは既存の DynamoDB API 呼び出しをそのまま ExtendDB アダプターに向けるだけで、 4 種類のストレージバックエンドのいずれかを利用した DynamoDB 互換の動作を任意の環境で実現できます。

⚡ 主要機能

🔄 1. DynamoDB API との完全互換
  • DynamoDB API と完全互換のアダプターとして動作
  • アプリケーションコードの変更なしで、DynamoDB 向けに開発されたワークロードをそのまま実行可能
  • オンプレミス、プライベートクラウド、パブリッククラウド、エッジ環境など、任意のインフラにデプロイ可能
🗄️ 2. 4 種類のストレージバックエンド
  • PostgreSQL、SQLite、Cassandra、MongoDB をストレージバックエンドとしてサポート
  • 既存のデータベース運用スキルやインフラ資産を活用して DynamoDB 互換レイヤーを構築可能
🧪 3. ローカル開発・CI 向けツール
  • extenddb-dev コンテナイメージと @extenddb/dev npm パッケージを提供
  • SQLite をバックエンドとした DynamoDB 互換エンドポイントを起動でき、外部データベースのセットアップが不要
🌐 4. オープンソースガバナンス
  • AWS がメンテナンスを担当
  • Apache 2.0 ライセンスで公開
  • GitHub 上でオープンに開発

🛠️ 設定方法

📋 前提条件

✓コンテナランタイム (Docker など) または Node.js 環境
✓プロダクション利用の場合は、バックエンドとして使用する PostgreSQL、Cassandra、MongoDB などのデータベース
✓DynamoDB API を利用する既存または新規のアプリケーション

ステップ 1: 開発用エンドポイントの起動

Bash extenddb-dev コンテナイメージを起動する例 
docker run -p 8000:8000 extenddb/extenddb-dev

SQLite をバックエンドとした DynamoDB 互換エンドポイントをローカルで提供します。外部データベースのセットアップは不要です。

ステップ 2: アプリケーションのエンドポイント切り替え

Bash AWS CLI から ExtendDB エンドポイントに接続する例 
aws dynamodb list-tables --endpoint-url http://localhost:8000

DynamoDB クライアントのエンドポイント URL を ExtendDB に向けることで、アプリケーションコードを変更せずに DynamoDB 互換の動作を確認できます。

ステップ 3: プロダクションバックエンドの選択

プロダクション環境では、PostgreSQL、Cassandra、MongoDB などの要件に適したバックエンドを選択して ExtendDB を構成します。 詳細な構成方法はプロジェクトページおよび GitHub リポジトリのドキュメントを参照してください。

⚖️ メリット・デメリット

💼 ビジネス面のメリット

✓ベンダーロックインの緩和: DynamoDB 向けのアプリ資産を AWS 外の環境でも活用可能
✓データ主権・規制対応: オンプレミスやプライベートクラウドでのデータ保持要件に対応
✓ライセンスコスト不要: Apache 2.0 ライセンスの OSS として無償で利用可能

🔧 技術面のメリット

✓コード変更不要: 完全互換のため既存アプリをそのまま移行・併用可能
✓バックエンドの選択肢: 4 種類から運用要件に合わせて選択可能
✓開発体験の向上: extenddb-dev で外部 DB なしのローカル開発・CI 環境を即座に構築

⚠️ 制限事項

✗マネージドサービスではないため、インフラの構築、運用、スケーリング、バックアップはユーザー自身で実施
✗DynamoDB のマネージド機能 (自動スケーリング、グローバルテーブル、ポイントインタイムリカバリなど) がどこまで利用できるかは公式ドキュメントでの確認が必要

🤔 考慮すべき点

⚠選択するストレージバックエンドによって性能特性や運用方法が異なる
⚠プロダクション利用には、バックエンドデータベース自体の高可用性設計が別途必要
⚠フルマネージドな DynamoDB と自己管理の ExtendDB のどちらが適切か、運用コストを含めた比較検討を推奨

🎯 ユースケース

🧪 1. ローカル開発・CI 環境での DynamoDB 互換テスト

シナリオ: DynamoDB を利用するアプリケーションの開発チームが、AWS への接続なしでユニットテストや統合テストを実行したい。

Bash CI パイプラインで extenddb-dev を起動し、テストを実行 
docker run -d -p 8000:8000 extenddb/extenddb-dev
npm test
✅ 効果: 外部データベースのセットアップや AWS アカウントへの接続なしで、SQLite ベースの DynamoDB 互換エンドポイントを使った高速なテストが可能になります。
🏢 2. オンプレミス環境での DynamoDB ワークロード実行

シナリオ: 規制要件によりデータをオンプレミスに保持する必要がある企業が、DynamoDB 向けに開発した既存アプリケーションを社内データセンターで稼働させたい。

実装例: オンプレミスの PostgreSQL をバックエンドとして ExtendDB を構成し、アプリケーションのエンドポイント URL を ExtendDB に変更する。

✅ 効果: アプリケーションコードを変更することなく、データ主権要件を満たしながら DynamoDB スタイルのワークロードを実行できます。
📡 3. エッジ環境でのデータ処理

シナリオ: ネットワーク接続が限定されるエッジ拠点で、クラウドと同じ DynamoDB API を使ったアプリケーションを動作させたい。

実装例: エッジデバイス上で SQLite バックエンドの ExtendDB を稼働させ、クラウドとエッジで同一のアプリケーションコードを使用する。

✅ 効果: クラウドとエッジで共通のコードベースを維持しながら、エッジ環境でもローカルにデータを処理できます。

💰 料金・利用可能リージョン

💵 料金

Apache 2.0 ライセンスのオープンソースソフトウェアであり、ソフトウェア自体の利用は無償です。 AWS からの料金は発生しません。ただし、ExtendDB を稼働させるインフラストラクチャおよびバックエンドデータベースの運用コストはユーザー負担となります。

🌍 利用可能リージョン

セルフホスト型のオープンソースソフトウェアであるため、特定の AWS リージョンに依存しません。 オンプレミス、プライベートクラウド、パブリッククラウド、エッジ環境など、任意のインフラストラクチャで利用できます。

🔗 関連サービス・機能

🗄️ Amazon DynamoDB

ExtendDB が互換性を提供するフルマネージド NoSQL データベースサービス。クラウドでのフルマネージド運用には引き続き DynamoDB が適します。

💻 DynamoDB Local

従来から提供されているローカル開発向けの DynamoDB エミュレーター。ExtendDB はプロダクション利用と複数バックエンドへの対応という点で異なります。

🐘 PostgreSQL / 📦 SQLite / 📋 Cassandra / 🍃 MongoDB

💡 まとめ

ExtendDB 1.0 は、DynamoDB API 互換のワークロードを任意のインフラストラクチャで実行可能にする、AWS メンテナンスのオープンソースアダプターです。 データ主権要件への対応やローカル開発・CI 環境の効率化に有効であり、DynamoDB を利用する開発チームは extenddb-dev によるローカル検証から試すことを推奨します。
