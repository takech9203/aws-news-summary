🚀 M9g / M9gd 汎用インスタンス
AWS Graviton5 プロセッサ搭載

📅 リリース日
2026年6月10日

📌 概要

AWS は、独自設計プロセッサ第 5 世代となる AWS Graviton5 を搭載した Amazon EC2 M9g / M9gd 汎用インスタンスの一般提供を開始しました。汎用ワークロードにおいて最高のコストパフォーマンスを提供します。

M9g はアプリケーションサーバー、マイクロサービス、ゲーム、キャッシング、コンテナに加え、リアルタイム推論・コード生成・マルチステップオーケストレーションといったエージェント型 AI に適しています。M9gd はこれらに加えてローカル NVMe SSD ストレージを備え、メディア処理やバッチ/ログ処理に対応します。

これらは第 6 世代 AWS Nitro System 上に構築され、形式検証 (formal verification) を用いた Nitro Isolation Engine を初めて搭載。ワークロード分離を数学的に保証します。

⚠️ アップデート前の課題

  • Graviton4 (M8g/M8gd) ではエージェント型 AI 向けの演算性能が不足
  • メモリ帯域幅やコア間レイテンシがボトルネックに
  • 分離保証は運用管理に依存し、数学的な証明がなかった

✅ アップデート後の改善

  • M8g/M8gd 比で最大 25% 高い演算性能
  • DDR5-8800 + 大容量 L3 キャッシュで大幅高速化
  • Nitro Isolation Engine で分離を数学的に証明

M9g / M9gd は第 6 世代 Nitro System 上の Graviton5 プロセッサで動作し、M9gd ではローカル NVMe SSD ストレージが追加される構成です。

⚡ 主要機能

🧠 AWS Graviton5 プロセッサ

  • AWS 独自設計プロセッサの第 5 世代
  • 最大 192 コア、DDR5-8800 メモリ (クラウド最速)
  • 前世代比 5 倍の L3 キャッシュ、最大 33% 低いコア間レイテンシ
  • AWS の CPU として初めて PCIe Gen6 をサポート

🖥️ M9g 汎用インスタンス

  • アプリサーバー、マイクロサービス、ゲーム、キャッシング、コンテナ向け
  • リアルタイム推論・コード生成・オーケストレーションなどエージェント型 AI に対応
  • vCPU 1 つあたり 4 GiB のメモリ比率を維持

💾 M9gd 汎用インスタンス

  • M9g の特性に加え、ローカル NVMe SSD ブロックストレージを搭載
  • 最大 11.4 TB の NVMe SSD、M8gd 比 30% 高い IOPS
  • メディア処理、バッチ/ログ処理、キャッシュ/スクラッチファイル向け

🔒 第 6 世代 Nitro System + Nitro Isolation Engine

  • 第 6 世代 AWS Nitro System 上に構築
  • 形式検証を用いた Nitro Isolation Engine を初搭載し、分離を数学的に保証

🛠️ 設定方法

前提条件

✓AWS アカウントと EC2 起動権限を持つ IAM 権限を保有
✓対応リージョン (バージニア北部、オハイオ、オレゴン、フランクフルト) を利用
✓ワークロードが Arm ベース (AArch64) に対応

ステップ1: 対応 AMI の確認

BashArm64 対応の最新 AMI 取得
# Arm64 アーキテクチャに対応した最新の Amazon Linux 2023 AMI を取得
aws ec2 describe-images \
  --owners amazon \
  --filters "Name=architecture,Values=arm64" "Name=name,Values=al2023-ami-*" \
  --query 'Images | sort_by(@, &CreationDate)[-1].ImageId' \
  --region us-east-1

ステップ2: M9g インスタンスの起動

Bashm9g.xlarge を起動
# M9g インスタンスを起動
aws ec2 run-instances \
  --image-id <arm64-ami-id> \
  --instance-type m9g.xlarge \
  --key-name <your-key-pair> \
  --region us-east-1

インスタンスタイプを m9gd.xlarge に変更すると、ローカル NVMe SSD 付きインスタンスを起動できます。

ステップ3: ローカル NVMe ストレージの確認 (M9gd)

BashNVMe デバイスの確認
# インスタンスにログイン後、ローカル NVMe デバイスを確認
lsblk

⚠ ローカルストレージはインスタンスの停止/終了でデータが失われるため、永続化が必要なデータは保存しないでください。利用前にファイルシステムの作成とマウントが必要です。

💡 メリット

📈 ビジネス面

  • コストパフォーマンス向上: 同等性能をより低コストで実現
  • エージェント型 AI 対応: 推論やコード生成を効率実行
  • エネルギー効率: サステナビリティ目標に貢献

🔩 技術面

  • 高いメモリ性能: DDR5-8800 でスループット向上
  • 強化された分離: 形式検証による分離保証
  • 柔軟な構成: medium〜48xlarge / bare metal、IBC 対応

⚠️ デメリット・制約事項

制限事項

✗利用可能リージョンは米国東部 (バージニア北部、オハイオ)、米国西部 (オレゴン)、欧州 (フランクフルト) に限定 (東京リージョンは未対応)
✗Graviton (Arm64) 対応のソフトウェアと AMI が必要
✗M9gd のローカル NVMe は一時ストレージで、停止/終了でデータ消失

考慮すべき点

⚠x86 ワークロードの移行時は Arm64 への再コンパイルや互換性検証が必要な場合あり
⚠ローカルストレージを永続データに使わないようデータ配置を設計

🎯 ユースケース

① エージェント型 AI ワークロードの実行

シナリオ: リアルタイム推論・コード生成・マルチステップオーケストレーションを高コスパで実行。

実装例: m9g.4xlarge (16 vCPU / 64 GiB) でオーケストレーション層を実行。

→ コア間レイテンシ改善とメモリ性能により低レイテンシでマルチステップ処理を実行。

② 高性能 Web アプリケーションサーバー

シナリオ: トラフィックの多い Web アプリを効率的にスケール。

実装例: m9g.2xlarge をオートスケーリンググループで水平スケール。

→ M8g 比で最大 35% 高速、同コストでより多くのリクエストを処理。

③ メディア処理とログ処理

シナリオ: メディアのトランスコードやログのバッチ処理で高速ローカルストレージが必要。

実装例: m9gd.16xlarge (NVMe 3800 GB) で一時ファイルを処理し結果を Amazon S3 に保存。

→ ローカル NVMe SSD で低レイテンシ、M8gd 比 30% 高い IOPS でスループット向上。

✅ まとめ

Amazon EC2 M9g / M9gd は、AWS Graviton5 プロセッサと第 6 世代 Nitro System により、汎用ワークロードとエージェント型 AI に対して最高のコストパフォーマンスと数学的に証明されたワークロード分離を提供します。Arm64 対応ワークロードを運用しているお客様は、対応リージョンで M8g / M9g の性能とコストを比較検証し、移行による効果を評価することをお勧めします。
