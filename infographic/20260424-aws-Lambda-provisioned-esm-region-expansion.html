リージョン拡大

Kafka イベントソースマッピング向け Provisioned Mode が 3 つの新リージョンで利用可能に
2026-04-24

📋 概要

AWS Lambda の Kafka イベントソースマッピング (ESM) 向け Provisioned Mode が、 Asia Pacific (Taipei)、AWS GovCloud (US-East)、AWS GovCloud (US-West) の 3 リージョンで新たに利用可能になりました。

Provisioned Mode は、Apache Kafka イベントソースに対する ESM のイベントポーリングリソースを事前にプロビジョニングしておくことで、突発的なトラフィックスパイクに即座に対応できる機能です。通常のオンデマンドモードではスケールアップに時間がかかる場合がありますが、Provisioned Mode を使用すると常に十分なポーリングリソースが準備された状態を維持できます。

+3 新規対応リージョン
2 GovCloud リージョン対応
18+ 合計利用可能リージョン

🔄 Before / After

❌ Before
  • Taipei / GovCloud リージョンで Provisioned Mode を利用不可
  • トラフィックスパイク時のポーリングリソーススケールアップに遅延が発生
  • GovCloud 環境での Kafka スループット最適化の選択肢が限定的
✅ After
  • Taipei、GovCloud US-East / US-West で Provisioned Mode が利用可能
  • 事前プロビジョニングにより突発的なスパイクに即座に対応
  • GovCloud 環境でも高パフォーマンスな Kafka イベント処理アーキテクチャ構築が可能

⚡ 主要機能

🚀 Provisioned Mode によるスループット最適化

Kafka ESM のイベントポーリングリソースを事前にプロビジョニングし、一定のスループット容量を確保します。

  • 突発的なトラフィックスパイクに対してスケールアップを待つことなく即座に対応
  • MinimumPollers パラメータで常時稼働ポーラーの最小数を指定可能
📡 Apache Kafka イベントソースとの統合

Amazon MSK および自己管理型 Kafka クラスターの両方に対応しています。

  • Kafka トピックのパーティションからイベントをポーリングし Lambda にバッチ配信
  • VPC 内の Kafka クラスターへの接続もサポート
🏛️ GovCloud リージョンへの対応

AWS GovCloud (US-East) および (US-West) で利用可能になりました。

  • 政府機関や規制産業のワークロードで高パフォーマンスな Kafka イベント処理を実現
  • FedRAMP High 認定環境での利用が可能

Provisioned Mode の設定パラメータ

📝 設定方法

前提条件

  • 対象リージョン (ap-east-2, us-gov-east-1, us-gov-west-1) が有効化されていること
  • Apache Kafka クラスター (Amazon MSK or 自己管理型) が稼働していること
  • Lambda 関数が作成済みであること
  • AWS CLI v2 がインストールされていること

Step 1: Lambda 関数の作成

Bash Kafka イベント処理用 Lambda 関数を作成 
# Kafka イベントを処理する Lambda 関数を作成
aws lambda create-function \
  --function-name kafka-event-processor \
  --runtime python3.13 \
  --role arn:aws:iam::123456789012:role/lambda-kafka-role \
  --handler lambda_function.handler \
  --zip-file fileb://function.zip \
  --region ap-east-2

Step 2: Provisioned Mode で ESM を作成

Bash Provisioned Mode を有効にした ESM を作成 
# Provisioned Mode を有効にした ESM を作成
aws lambda create-event-source-mapping \
  --function-name kafka-event-processor \
  --event-source-arn "arn:aws:kafka:ap-east-2:123456789012:cluster/my-cluster/abc123" \
  --topics "my-topic" \
  --starting-position LATEST \
  --provisioned-poller-config '{"MinimumPollers": 2, "MaximumPollers": 10}' \
  --region ap-east-2

Step 3: ESM の状態確認

Bash イベントソースマッピングの状態を確認 
# イベントソースマッピングの状態を確認
aws lambda list-event-source-mappings \
  --function-name kafka-event-processor \
  --region ap-east-2

ESM の State が Enabled になっていることを確認してください。

⚖️ メリットとデメリット

✅ メリット

ビジネス面

  • プロビジョニング済みポーラーにより SLA 要件を満たしやすくなる
  • GovCloud で高パフォーマンスな Kafka イベント処理を実現
  • Taipei リージョン利用で台湾周辺地域への低レイテンシーを提供

技術面

  • イベント取得から Lambda 呼び出しまでのレイテンシーが安定
  • MinimumPollers / MaximumPollers で柔軟なスケーリング
  • マネージドサービスとしてポーリングインフラ管理が不要

⚠️ デメリット / 制約

制限事項

  • Kafka イベントソースにのみ対応 (SQS, DynamoDB Streams 等は不可)
  • プロビジョニング済みポーラーは常時稼働のためコストが発生
  • すべての AWS リージョンで利用できるわけではない

考慮すべき点

  • MinimumPollers を高く設定しすぎると不要なコスト発生の可能性
  • 自己管理型 Kafka 使用時は VPC / SG の別途設定が必要
  • モード切替時に一時的な処理遅延の可能性あり

🎯 ユースケース

🏦 金融取引のリアルタイム処理
金融機関が Kafka で取引イベントをストリーミングし、Lambda でリアルタイムに不正検知や取引処理を行うシナリオ。
Python 不正検知 Lambda ハンドラー 
import json

def handler(event, context):
    for record in event['records'].values():
        for item in record:
            payload = json.loads(
                __import__('base64').b64decode(item['value']).decode('utf-8')
            )
            if detect_fraud(payload):
                alert_security_team(payload)
            process_transaction(payload)
-> 市場の急変動時にも安定したスループットで取引イベントを処理し、不正検知の遅延を最小限に抑制
🏛️ GovCloud での IoT データパイプライン
政府機関が GovCloud 環境で IoT デバイスからの Kafka ストリームを処理し、リアルタイム分析を行うシナリオ。
Python IoT センサーデータ処理 
import json

def handler(event, context):
    for record in event['records'].values():
        for item in record:
            sensor_data = json.loads(
                __import__('base64').b64decode(item['value']).decode('utf-8')
            )
            if sensor_data['temperature'] > THRESHOLD:
                trigger_alert(sensor_data)
            send_to_analytics(sensor_data)
-> FedRAMP 準拠のセキュアな環境で高スループットの IoT データ処理が可能
🛒 E コマースのイベント駆動型アーキテクチャ
E コマースプラットフォームが Kafka で注文イベントを処理し、在庫管理や通知を自動化するシナリオ。
Python 注文イベント処理 
import json

def handler(event, context):
    for record in event['records'].values():
        for item in record:
            order_event = json.loads(
                __import__('base64').b64decode(item['value']).decode('utf-8')
            )
            if order_event['type'] == 'ORDER_PLACED':
                update_inventory(order_event)
                send_confirmation(order_event)
            elif order_event['type'] == 'ORDER_CANCELLED':
                restore_inventory(order_event)
                send_cancellation_notice(order_event)
-> セール期間中のトラフィックスパイクに対して Provisioned Mode のポーラーが即座に対応し、注文処理の遅延を防止

💰 料金情報

Provisioned Mode を使用する場合、プロビジョニング済みポーラーの稼働時間に基づいて料金が発生します。通常の Lambda 実行料金に加えて、ESM のポーラー料金が課金されます。

使用量月額料金 (概算)
Provisioned Pollers 2 台、24 時間 365 日稼働ESM ポーラー料金 + Lambda 実行料金
Provisioned Pollers 5 台、ピーク時間のみ (12 時間/日)ESM ポーラー料金 + Lambda 実行料金

* 具体的な料金は AWS Lambda 料金ページ をご確認ください。

* GovCloud リージョンでは、商用リージョンと異なる料金が適用される場合があります。

📌 まとめ

AWS Lambda の Kafka ESM 向け Provisioned Mode が Asia Pacific (Taipei)、GovCloud (US-East)、GovCloud (US-West) に拡大されました。特に GovCloud 環境での対応は、政府機関や規制産業のお客様にとって重要なアップデートです。

Kafka ベースのイベント駆動型アプリケーションで突発的なトラフィックスパイクへの対応が求められる場合は、Provisioned Mode の導入を検討することをお勧めします。
