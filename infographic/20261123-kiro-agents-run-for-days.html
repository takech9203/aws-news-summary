⚡ Kiro CLI の長時間セッション向け
パフォーマンス改善

Kiro CLI 📅 リリース日: 2026 年 11 月 23 日
数日〜数週間続くエージェントセッションに対応するため、メモリ管理・入力応答性・起動時間・ダウンロードサイズを大幅改善

📝 概要

モデルの長時間タスク処理能力の向上や /goal のような機能により、エージェントセッションは 数日から数週間開き続けられるようになりました。Kiro は CLI 自体の性能がボトルネックにならないよう、 4 つの領域にわたる大規模なパフォーマンス改善を発表しました。

対象は、複数の長時間エージェントセッションを並行実行する開発者や、CI/CD・プルリクエストレビューなどの自動化環境で Kiro を利用するチームです。

❌ アップデート前の課題

  • メモリが増加し続け、Bun プロセスが約 3 GB に達する事例 (最後の 1 週間で 1 日約 10 MB 増加)
  • macOS 署名プロセスで JIT エンタイトルメントが除去され、長い応答の後にタイピングが遅延
  • macOS のダウンロード約 960 MB、インストール後約 1.8 GB で CI/CD に待ち時間
  • 起動時に約 1.55 GB の実行ファイル 2 つをハッシュ計算し、それだけで 5.77 秒 (ウォームスタート中央値 6.785 秒)
  • メモリ確保のために有用なセッションを閉じる「セッションのやりくり」が必要

✅ アップデート後の改善

  • 直近のターンのみメモリ保持、古いターンはディスクへ。21 日間で 193.5 MB で安定 (CLI 2.22.0 以降)
  • JIT 復元で p95 再描画が約 7.8 倍高速化 (2.16.1)。1,118 行表示中もキー入力が p95 で 2.32 ミリ秒 (2.25.0)
  • macOS: ダウンロード 358.2 MB (約 63% 減)、インストール 654.6 MB (約 64% 減)。Linux ARM64 は約 75〜77% 減
  • ウォームスタート中央値 0.414 秒、0.5 秒未満の p95 目標を達成
  • 24 GB の MacBook Pro で 15 個の長時間セッションを再起動なしで同時維持

💡 メリット

💼 ビジネス面

✓開発者の生産性向上: 「セッションのやりくり」が不要になり、エージェントによる長時間タスクを中断せずに継続できる
✓CI/CD の高速化: ダウンロードサイズが約 63〜77% 削減され、自動化環境でのセットアップ時間が短縮される
✓ハードウェアコストの抑制: 24 GB のラップトップで 15 の長時間セッションを同時維持でき、追加リソースなしで並行作業を拡大できる

⚙️ 技術面

✓メモリ増加の根本的解決: 時間経過による増加自体を停止させるアーカイブ型のメモリ管理を採用
✓会話履歴の完全保持: 古いターンはディスクに退避されるだけで、/transcript や /rewind から全履歴にアクセス可能
✓即応性のある入力体験: 長い応答の表示後でもキー入力が p95 で 2.32 ミリ秒で反映され、体感的な遅延がない
✓高速な起動: ウォームスタートが 0.414 秒となり、バックグラウンド読み込み中でも入力を開始できる

⚠️ デメリット・制約事項

🚧 制限事項

✗メモリ管理の改善は 2.22.0 以降、タイピング応答性の最新数値は 2.25.0 以降が対象で、古いバージョンでは恩恵を受けられない
✗記事中の「3 GB のセッション」は一例であり、すべてのセッションで同じ削減率が得られるわけではない
✗旧ビルドの正確なサイズ記録が残っていないため、サイズ削減率は概数に基づく

🤔 考慮すべき点

→セッションあたりの計画メモリの目安は 500 MB (CLI 300 MB + エージェントサーバー 200 MB)。同時セッション数の設計時はこの値を基準にするとよい
→数十のセッションを同時に実行したい場合は、ローカルではなくクラウドセッションの利用が推奨されている
→測定値はビルドやワークロードにより異なるため、起動時間の改善幅は「時間経過による進歩」として解釈する必要がある

🎯 ユースケース

1. 複数の長時間エージェントセッションの並行実行

シナリオ: 複数のリポジトリやタスクに対して、専用の Kiro CLI セッションを数日間開いたままにして、エージェントに長時間タスクを任せたい。

Bash実装例
# 各ワークスペースでセッションを起動し、開いたまま維持
cd ~/projects/service-a && kiro-cli
cd ~/projects/service-b && kiro-cli
# /goal でエージェントに目標を与え、長時間の反復作業を実行

効果セッションあたり 500 MB の計画値で 15 セッションが 7.5 GB に収まり、24 GB のラップトップでもエディタやブラウザと併用しながら複数セッションを維持できる。

2. CI/CD やプルリクエストレビューの自動化

シナリオ: CI/CD パイプラインやプルリクエストレビューの自動化で Kiro CLI を毎回ダウンロード・インストールしており、セットアップ時間を短縮したい。

Bash実装例
# CI ジョブ内で Kiro CLI を取得 (Linux ARM64 の例)
# ダウンロードサイズ: 約 674 MB → 154.5 MB
# インストールサイズ: 約 1.1 GB → 272.1 MB

効果ダウンロードが約 77% 小さくなり、ジョブごとのセットアップ待ち時間が大幅に短縮される。起動も 0.414 秒 (中央値) と高速なため、自動化タスクがすぐに開始できる。

3. 長い応答を扱うインタラクティブな開発

シナリオ: エージェントが 1,000 行を超える長い応答を生成した後も、続けてコマンドや指示を快適に入力したい。

Bash実装例
# 長い応答の後もそのまま入力を継続
# 過去の内容が必要になったらアーカイブから参照
/transcript
/rewind

効果1,118 行の履歴を表示した状態でもキー入力が p95 で 2.32 ミリ秒で反映され、入力遅延なく作業を継続できる。

✨ まとめ

Kiro CLI は、メモリ管理・タイピング応答性・ダウンロードサイズ・起動時間の 4 領域で大幅なパフォーマンス改善を実現し、 数日から数週間にわたる長時間エージェントセッションを安心して開き続けられるようになりました。 メモリ増加の停止 (2.22.0 以降) と 0.5 秒未満の起動により、1 台のラップトップで 15 の並行セッションも現実的になっています。

👉 Kiro CLI を利用中の場合は、最新バージョン (2.25.0 以降) へのアップデートを推奨します。
