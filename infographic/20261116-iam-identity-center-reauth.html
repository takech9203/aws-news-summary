🔐 IAM Identity Center
SAML リクエストでの ForceAuthn サポート

AWS IAM Identity Center 📅 2026 年 11 月 16 日

セッション期限切れ時に外部 IdP でのユーザー再認証を必須化できるようになりました。SAML 2.0 標準の ForceAuthn 属性を利用し、厳格なセキュリティ・コンプライアンス要件に標準機能で対応できます。

📋 概要

AWS IAM Identity Center が SAML 2.0 の ForceAuthn 属性をサポートしました。ユーザー再認証を「Required」に設定すると、IAM Identity Center セッションの期限切れ時に IdP へ送信される SAML リクエストに ForceAuthn 属性が付与され、既存の IdP セッションの有無にかかわらず、ユーザーは IdP で再度認証 (認証情報の入力と、IdP が要求する場合は MFA) を行う必要があります。外部 IdP を ID ソースとするすべてのインスタンス (組織インスタンスおよびアカウントインスタンス) で設定できます。

❌ Before: アップデート前の課題
  • セッション期限切れ時に既存の IdP セッションで自動更新され、明示的な再認証を強制できなかった
  • セッション開始のたびに本人確認を求める要件を IAM Identity Center 単体では満たせなかった
  • 認証情報と MFA の再入力の強制は IdP 側のセッション管理のみに依存していた
✅ After: アップデート後の改善
  • セッション期限切れ時に外部 IdP での再認証 (認証情報 + MFA) を必須にできる
  • SAML 2.0 標準の ForceAuthn 属性を利用するため、標準準拠の IdP なら追加開発が不要
  • 設定変更が AWS CloudTrail に記録され、有効化・無効化の監査が可能

AWS アクセスポータルからのサインイン (SP-initiated) 時に、再認証設定が「Required」の場合は SAML リクエストに ForceAuthn 属性が付与され、既存の IdP セッションの有無にかかわらずユーザーは IdP で再認証を求められます。

⚡ 主要機能

1️⃣ ユーザー再認証の必須化設定
  • 外部 IdP 設定に「User re-authentication」設定が追加され、「Require」または「Do not require」を選択可能
  • デフォルトは「Not required」(従来どおり既存の IdP セッションによる自動更新)
  • 「Required」に設定すると、ユーザーインタラクティブセッションの期限切れ時に IdP での再認証を要求
2️⃣ SAML 2.0 ForceAuthn 属性による標準準拠の実装
  • IdP へ送信する SAML リクエストに ForceAuthn 属性を追加することで再認証を要求
  • IdP が属性を尊重する場合、既存の IdP セッションがあってもサインイン画面が表示される
  • 組織インスタンス・アカウントインスタンスのどちらでも、外部 IdP を ID ソースとする場合に設定可能
3️⃣ CloudTrail による設定変更の監査
  • 設定変更は CloudTrail イベント UpdateExternalIdPConfigurationForDirectory (イベントソース: sso-directory.amazonaws.com) として記録
  • requestParameters.idpSAMLConfig.forceAuthn の値 (ENABLED など) で設定内容を確認可能
  • いつ・誰が再認証設定を有効化・無効化したかを追跡できる

項目詳細

設定値Required / Not required (デフォルト: Not required)

📝 CloudTrail イベントの例

管理者がユーザー再認証を「Required」に設定した際の CloudTrail イベントの関連フィールドです。

JSON CloudTrail イベント (抜粋) 
{
  "eventName": "UpdateExternalIdPConfigurationForDirectory",
  "eventSource": "sso-directory.amazonaws.com",
  "requestParameters": {
    "idpSAMLConfig": {
      "forceAuthn": "ENABLED"
    }
  }
}

🛠️ 設定方法

前提条件

✓IAM Identity Center のインスタンス (組織インスタンスまたはアカウントインスタンス) が有効化されていること
✓ID ソースとして外部 IdP (SAML 2.0 対応) が接続されていること
✓使用する IdP が SAML リクエストの ForceAuthn 属性を尊重すること (IdP のドキュメントで要確認)

手順

1
認証設定画面を開く
  1. IAM Identity Center コンソールを開き、[Settings] を選択
  2. [Identity source] タブの [Sign-in] セクションで [Manage authentication] を選択
2
ユーザー再認証を必須に設定する
  1. [User sign-in configurations] カードの [Require user re-authentication] の横にある [Edit] を選択
  2. [User re-authentication] で [Require] (セッション期限切れごとに IdP での認証を必須化) または [Do not require] (デフォルト) を選択
  3. [Save changes] を選択。変更は新規の SP-initiated サインインに適用され、保存時にアクティブなセッションは中断されない
3
動作をテストする
  1. AWS アクセスポータル URL (例: https://d-xxxxxxxxxx.awsapps.com/start) を開き、外部 IdP でサインイン
  2. ナビゲーションバーで [Sign out] を選択し、同じページで [Sign in] を選択
  3. アクティブな IdP セッションがあるにもかかわらずサインイン画面が表示されれば、設定は正常に動作している

⚖️ メリットと制約事項

👍 メリット

✓コンプライアンス対応: セッション開始のたびに本人確認を求める規制・社内ポリシーに追加コストなしで対応
✓セキュリティ向上: 共有端末や離席時のリスクを低減し、アクセス時点での本人性を担保
✓監査対応の容易化: CloudTrail の記録で統制状況を監査人に提示しやすい
✓標準準拠: SAML 2.0 標準のため、標準準拠の IdP なら追加開発不要
✓簡単な設定: コンソールの設定変更のみで有効化、アプリ側の変更不要
✓業務影響なし: 設定変更時にアクティブなセッションは中断されず、段階的に導入可能

⚠️ 制約・考慮点

✗SP-initiated のみ: IdP のポータルから開始する IdP-initiated サインインでは SAML リクエストが送信されないため効果がない
✗IdP 依存: IdP が ForceAuthn を尊重する場合のみ機能。Okta や Google Workspace など IdP 固有の既知の問題はトラブルシューティングドキュメントで要確認
✗外部 IdP のみ: Identity Center ディレクトリや AWS Managed Microsoft AD を ID ソースとする場合は対象外
⚠サインイン頻度の増加: セッション期限切れのたびに認証情報 (+ MFA) の入力が必要。セッション継続時間の見直しを推奨
⚠既存セッションには非適用: 即時終了したい場合はアクティブセッションの表示・終了機能を併用

💡 ユースケース

🏦 ユースケース 1: 金融機関における定期的な本人確認の強制

シナリオ: セキュリティポリシーで、AWS 環境へのアクセスセッション開始時に必ず MFA を含む本人確認を行うことが義務付けられている。

実装: ユーザー再認証を「Required」に設定し、セッション継続時間を 8 時間などポリシーに沿った値に設定。IdP 側で MFA を必須化。

効果: セッション期限切れごとに IdP での認証と MFA が強制され、既存 IdP セッションによる自動更新を防止できる。

📑 ユースケース 2: 設定変更の監査体制の整備

シナリオ: 監査要件により、認証強度に関わる設定の変更履歴を追跡・報告する必要がある。

実装: CloudTrail で eventName: UpdateExternalIdPConfigurationForDirectory、eventSource: sso-directory.amazonaws.com のイベントをフィルタリングし、forceAuthn の値を確認。

効果: 再認証設定の有効化・無効化の履歴を CloudTrail から抽出し、監査証跡として提示できる。

🖥️ ユースケース 3: 共有端末環境でのセッション乗っ取りリスクの低減

シナリオ: コールセンターや工場など、複数のユーザーが端末を共有する環境で AWS アクセスポータルを利用している。

実装: ユーザー再認証を「Required」に設定し、セッション継続時間を短め (例: 1〜4 時間) に設定。ユーザーには SP-initiated サインインを周知。

効果: 前のユーザーの IdP セッションが残っていても、セッション期限切れ後は必ず再認証が要求され、なりすましアクセスのリスクを低減できる。

🔗 関連サービス・機能

📊 AWS CloudTrail

再認証設定の変更イベント (UpdateExternalIdPConfigurationForDirectory) を記録し、監査を可能にする。

⏱️ IAM Identity Center セッション管理

セッション継続時間の設定とアクティブセッションの表示・終了機能。再認証の頻度はセッション継続時間に依存するため、併せて設計する。

🏢 外部 ID プロバイダー連携 (SAML 2.0)

Okta、Microsoft Entra ID、Google Workspace などの外部 IdP を ID ソースとして利用する機能。本機能の前提となる。

🎯 まとめ

IAM Identity Center が SAML 2.0 の ForceAuthn 属性をサポートしたことで、セッション期限切れ時に外部 IdP での再認証を必須化でき、厳格なセキュリティ・コンプライアンス要件に標準機能で対応できるようになりました。外部 IdP を利用している組織は、IdP の ForceAuthn 対応状況とセッション継続時間の設定を確認したうえで、要件に応じた有効化を検討することを推奨します。
