🎙️ Amazon Transcribe Turbo

次世代音声認識モデルと音声エージェント向け新機能 | リリース日: 2026 年 11 月 25 日

📌 概要

AWS は次世代音声認識モデル Amazon Transcribe Turbo のパブリックプレビューを発表。バッチとストリーミングの両方で認識精度が大幅に向上し、音声エージェント向けにセマンティックターンテイキングとランタイム ASR ヒントの 2 つの新機能が追加されました。ベースモデルの利用に API、コード、SDK の変更は不要です。

❌ アップデート前の課題

  • ストリーミング認識の単語誤り率やエンティティのフォーマット精度に改善の余地があった
  • 発話終了の判定が無音時間に依存し、「はい」「いいえ」などの短い応答でも無音を待つ必要があり会話が不自然だった
  • 話者が考えながら話している途中でエージェントが割り込んでしまうケースがあった
  • カスタム語彙はセッション単位の静的な設定で、会話の文脈に応じてターンごとに認識精度を調整できなかった

✅ アップデート後の改善

  • ストリーミングで約 14% (英語)、バッチで約 16% の WER 相対改善により、より正確な文字起こしが可能に
  • セマンティックターンテイキングで意味と韻律に基づく自然な発話終了判定。約 615 ミリ秒の応答時間と 5% の割り込み率を実現
  • ランタイム ASR ヒントでターンごとに文脈情報を送信可能。メニュールーティング精度が 87% から 97% に向上
  • ベースモデルは API、コード、SDK の変更なしで利用でき、既存ワークロードをそのまま検証可能

sequenceDiagram
    participant U as 👤 発話者
    participant T as 🎙️ Transcribe Turbo
    participant A as 🤖 音声エージェント

    A->>T: ConfigureEvent 送信
KeywordPhrases や EntityTypes
    T-->>A: ConfigureAppliedEvent
    U->>T: 音声ストリーミング
    T-->>A: 文字起こし結果
    alt 発話終了の兆候を検出

        A->>A: 応答を事前生成

            A->>A: 事前生成した応答を破棄

            T-->>A: EndOfTurnEvent
            A->>U: 音声で応答
        end
    end

セマンティックターンテイキングとランタイム ASR ヒントを利用した音声エージェントの処理フロー。エージェントはターンごとにヒントを送信し、EagerEndOfTurnEvent で応答を事前生成することで低レイテンシーな会話を実現します。

⚡ 主要機能

🚀 1. 次世代音声認識モデル Transcribe Turbo

  • ストリーミングで英語約 14%、その他の対応言語で約 11% の単語誤り率の相対的な改善
  • バッチで約 16% の単語誤り率の改善 (中国語、日本語、韓国語は約 6% の文字誤り率の改善)
  • 数値、日付、通貨、電話番号、住所などのフォーマット精度が 20 ポイント以上向上 (正確なフォーマット率は約 53% → 約 78%)
  • カスタム語彙に対応し、英語では約 40% の単語誤り率の改善
  • ベースモデルの利用に API、コード、SDK の変更は不要

🗣️ 2. セマンティックターンテイキング (EndOfTurnDetection)

  • 無音時間だけでなく、発話の意味と韻律に基づいて発話終了を判定
  • 文の途中での割り込みを回避しつつ、「はい」「いいえ」などの短い応答では即座に応答可能
  • 約 615 ミリ秒の応答時間と 5% の割り込み率を実現。しきい値はチューニング可能
  • EagerEndOfTurnEvent により発話終了の兆候を早期通知し、応答を事前生成可能

💡 3. ランタイム ASR ヒント (ConfigureEvent)

  • セッション単位の静的なカスタム語彙とは異なり、会話のターンごとに文脈情報を送信可能
  • 直前に提示したメニュー選択肢、期待される名前、期待されるエンティティタイプをヒントとして指定
  • 英語のカスタマーサービスデータでメニュールーティング精度が 87% から 97% に向上
  • 音声エージェント向け機能はローンチ時点で英語に対応。その他の言語は 2026 年 12 月末までに対応予定

⚙️ セマンティックターンテイキングのパラメータ

パラメータ用途デフォルト
EndOfTurnThreshold発話終了と判定する信頼度のしきい値。上げると割り込みが減少0.60
EagerEndOfTurnThreshold発話終了の兆候を早期通知するしきい値。応答の事前生成に利用無効
EndOfTurnTimeoutこの秒数の無音が続いた場合に発話終了と判定5 秒

📝 ランタイム ASR ヒントの種類

ヒントタイプ用途上限
KeywordPhrases直前に提示した選択肢などの短いフレーズ10 フレーズ
EntityTypes期待される回答のエンティティタイプ (SERIAL、CURRENCY など 10 種類)1 ターンあたり 1 つ
VocabularyPhrases製品名や人名などの珍しい語彙 (インラインカスタム語彙)200 フレーズ

📤 ConfigureEvent の送信例

JSON メニュー選択肢をヒントとして送信 
{ "KeywordPhrases": [ { "Text": "checking" }, { "Text": "savings" }, { "Text": "HELOC" } ] }
JSON エンティティタイプの指定 (以前の KeywordPhrases をクリア) 
{ "KeywordPhrases": [], "EntityTypes": ["SERIAL"] }

空のリストを送信すると以前の設定がクリアされ、省略したフィールドは以前の設定が維持されます。Transcribe は ConfigureAppliedEvent で設定の適用を通知します。

🛠️ 設定方法

📋 前提条件

✓AWS アカウントと Amazon Transcribe へのアクセス権限
✓プレビュー機能を利用する場合は米国東部 (オハイオ) リージョンを使用
✓ストリーミング機能を利用する場合は AWS SDK (ストリーミング対応)
1

ベースモデルの検証

既存の Transcribe API 呼び出しをそのまま米国東部 (オハイオ) リージョンに向けます。ベースモデルの利用に API、コード、SDK の変更は不要です。プレビューはテストトラフィック向けであり、本番環境での利用は想定されていません。

2

セマンティックターンテイキングの有効化

ストリーミング開始時に end-of-turn-detection=true を設定します。電話番号や口座番号のように区切りながら話す入力が想定される場合は、しきい値を調整します。

JSON しきい値の調整例 
{ "EndOfTurnThreshold": 0.9, "EagerEndOfTurnThreshold": 0.6 }

EndOfTurnThreshold を高くすることで途中での割り込みを減らし、EagerEndOfTurnThreshold により応答の事前生成を有効化しています。

3

ランタイム ASR ヒントの送信

エージェントが質問を提示するたびに ConfigureEvent を送信します。

JSON 次の発話で金額が話されることをヒントとして送信 
{ "EntityTypes": ["CURRENCY"] }

認識結果に通貨記号が付与されるなど適切なフォーマットが適用されます。イベントフローの実装例は AWS のサンプルリポジトリ (GitHub) を参照してください。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓顧客体験の向上: 自然なターンテイキングにより、音声エージェントとの会話が人間同士の会話に近づく
✓追加コストなし: Turbo モデルと音声エージェント向け機能は標準の Transcribe 料金で利用可能
✓ルーティング精度の向上: 87% → 97% の精度向上で誤転送やリトライによるオペレーションコストを削減

🔬 技術面のメリット

✓移行コストの低さ: API、コード、SDK の変更なしで既存ワークロードを検証可能
✓低レイテンシー: 約 615 ミリ秒の応答時間と応答の事前生成で体感レイテンシーを短縮
✓ターン単位の文脈制御: 会話の文脈に応じた動的な認識精度の調整が可能

⚠️ 制限事項

⚠プレビュー機能は米国東部 (オハイオ) のみ。テストトラフィック向けで本番利用は想定されていない
⚠音声エージェント向け機能はローンチ時点で英語のみ (その他言語は 2026 年 12 月末までに対応予定)
⚠ASR ヒントには上限がある (KeywordPhrases 10 フレーズ、EntityTypes 1 ターン 1 つ、VocabularyPhrases 200 フレーズ)
⚠プレビュー段階では話者識別と自動言語識別は無効 (GA 時に有効化予定)

🤔 考慮すべき点

⚠EndOfTurnThreshold のチューニングはユースケース依存。途中での打ち切りは 2% から 10% の範囲で変動するため実会話データでの検証が必要
⚠EagerEndOfTurnEvent を利用する場合、TurnResumedEvent 受信時に事前生成した応答を破棄する実装が必要
⚠その他言語とストリーミングの GA は 2026 年 12 月予定。本番導入スケジュールに考慮が必要

🎯 ユースケース

📞 1. コンタクトセンターの音声エージェント

シナリオ: 銀行のコンタクトセンターで、口座種別の選択、口座番号の聞き取り、金額の確認を行う自動音声エージェントを構築。

JSON ターンごとの ConfigureEvent 送信例 
{ "KeywordPhrases": [ { "Text": "checking" }, { "Text": "savings" }, { "Text": "HELOC" } ] }
{ "KeywordPhrases": [], "EntityTypes": ["SERIAL"] }
{ "EntityTypes": ["CURRENCY"] }

効果メニュールーティング精度が 87% から 97% に向上し、10 桁の口座番号が電話番号形式ではなく 4417209381 のような連続した数字として正しくフォーマットされる。

🗨️ 2. 低レイテンシーな音声アシスタント

シナリオ: 音声アシスタントで、ユーザーの発話終了後すぐに応答を返したいが、途中での割り込みは避けたい。

JSON しきい値設定例 
{ "EndOfTurnThreshold": 0.9, "EagerEndOfTurnThreshold": 0.6 }

効果EagerEndOfTurnEvent で応答を事前生成し、EndOfTurnEvent の受信後すぐに応答を再生することで、約 615 ミリ秒の応答時間と低い割り込み率を両立できる。

🎧 3. 多言語コンテンツのバッチ文字起こし

シナリオ: 会議録画やポッドキャストなどの音声コンテンツを複数言語でバッチ文字起こしし、精度を改善したい。

実装: 既存のバッチ文字起こしジョブを米国東部 (オハイオ) リージョンで実行。英語はすでに GA のため、ほとんどのリージョンで Turbo が適用済み。

効果バッチで約 16% の単語誤り率の改善 (日本語、中国語、韓国語は約 6% の文字誤り率の改善) と、数値や日付などのフォーマット精度の向上が得られる。

💰 料金と利用可能リージョン

追加料金なし: Turbo モデルおよび音声エージェント向け機能 (セマンティックターンテイキング、ランタイム ASR ヒント) は、標準の Amazon Transcribe 料金に対する追加料金なしで利用できます。

✓バッチ (英語): ほとんどの AWS リージョンで GA (すでに Turbo が適用)
✓プレビュー機能 (ストリーミング、英語以外のバッチ、音声エージェント向け機能): 米国東部 (オハイオ) リージョン
✓その他リージョンでの GA は 2026 年 12 月に予定

🔗 関連サービス・機能

📞 Amazon Connect コンタクトセンターサービス。Transcribe のリアルタイム文字起こしと組み合わせて音声エージェントを構築できる。
🤖 Amazon Bedrock 生成 AI 基盤サービス。文字起こし結果を LLM に渡して応答を生成する音声エージェントのバックエンドとして利用できる。
🔊 Amazon Polly テキスト読み上げサービス。音声エージェントの応答音声の生成に利用できる。

📝 まとめ

Amazon Transcribe Turbo は、認識精度の大幅な改善に加え、セマンティックターンテイキングとランタイム ASR ヒントという音声エージェント構築に直結する機能を追加料金なしで提供する重要なアップデートです。

ベースモデルは API 変更なしで利用できるため、まずは米国東部 (オハイオ) リージョンでテストトラフィックを流し、既存ワークロードでの精度改善を検証することを推奨します。音声エージェントを構築している場合は、EndOfTurnDetection と ConfigureEvent の活用により会話品質の大幅な向上が期待できます。
