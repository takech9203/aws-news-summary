脅威モデリングのサポート

AWS Security Agent / Continuum Public Preview
リリース日
2026 年 6 月 17 日

📌 概要

AWS は AWS Continuum の一部である AWS Security Agent に、アプリケーションの脅威モデルを自動構築する AI 駆動の脅威モデリング機能 を追加しました。エージェントが設計ドキュメントやソースコードをレビューし、アーキテクチャコンテキストを把握したうえで、STRIDE フレームワーク に基づいて脅威を特定し、推奨される緩和策を提示します。

従来は専門スキルと多大な手作業を要した脅威モデリングを、エージェント型 AI の推論能力で自動化。Kiro や Claude Code などの IDE に組み込むことで、設計フェーズの早い段階で脅威に対処できます。

❌ アップデート前の課題

  • 脅威モデリングには専門的なセキュリティスキルが必要で、実施できる人材が限られていた
  • アーキテクチャ、データフロー、信頼境界の分析に多大な手作業が必要だった
  • 設計フェーズの早い段階で脅威を体系的に洗い出す仕組みが整っていなかった

✅ アップデート後の改善

  • 設計ドキュメントやソースコードを入力するだけで、エージェントが脅威モデルを自動構築
  • STRIDE の 6 カテゴリすべてに沿って脅威と緩和策を網羅的に提示
  • Kiro や Claude Code などの IDE に統合し、設計フェーズ早期にシフトレフトで対処

エージェントが設計ドキュメントやソースコードを入力として受け取り、分析を経て STRIDE に基づく脅威一覧と緩和策を生成する流れ

⭐ 主要機能

📄 1. 設計ドキュメントとソースコードの自動分析

  • アプリケーション全体のアーキテクチャコンテキストを把握
  • アーキテクチャ、データフロー、信頼境界を理解したうえで脅威を特定
  • S3 上のドキュメント・ソースコード、連携済みリポジトリなど複数の入力アセットに対応

🎯 2. STRIDE フレームワークによる脅威の特定

  • STRIDE の 6 カテゴリすべてにわたって脅威を分類
  • 各脅威に重要度 (CRITICAL / HIGH / MEDIUM / LOW / INFO) と推奨緩和策を付与
  • 脅威ごとにステータス (OPEN / RESOLVED / DISMISSED) を管理し対応状況を追跡

🔧 3. IDE への統合とデプロイ前評価

  • Kiro や Claude Code などの IDE に組み込み、仕様から脅威モデルを作成
  • 設計フェーズの早い段階で脅威に対処し、シフトレフトを実現
  • セキュリティチームはデプロイ前評価として活用可能

⚙️ 設定方法

前提条件

  • AWS Security Agent (AWS Continuum) が利用可能なリージョンであること
  • エージェントがアセットにアクセスするための IAM サービスロールが構成されていること
  • 分析対象の設計ドキュメントまたはソースコードが S3 などの参照可能な場所に配置されていること

ステップ 1: 脅威モデルの作成

Bashcreate-threat-model
aws securityagent create-threat-model \
  --title "payment-service-threat-model" \
  --agent-space-id "as-xxxxxxxx" \
  --assets '{"sourceCode":[{"s3Location":"s3://my-bucket/payment-service/"}]}' \
  --service-role "arn:aws:iam::123456789012:role/SecurityAgentThreatModelingRole"

ステップ 2: 脅威モデリングジョブの開始

Bashstart-threat-model-job
aws securityagent start-threat-model-job \
  --agent-space-id "as-xxxxxxxx" \
  --threat-model-id "tm-xxxxxxxx"

エージェントがアーキテクチャ、データフロー、信頼境界を分析します。

ステップ 3: 検出された脅威の確認

Bashlist-threats
aws securityagent list-threats \
  --agent-space-id "as-xxxxxxxx" \
  --threat-job-id "tmj-xxxxxxxx"

STRIDE 分類、重要度、推奨緩和策とともに一覧で確認できます。IDE (Kiro / Claude Code) に統合している場合は、開発ワークフローの中で同様の操作を実行できます。

💡 メリット

📈 ビジネス面

  • 専門スキルへの依存軽減: AI エージェントが補完し、より多くのチームが脅威モデリングを実施
  • シフトレフトによるコスト削減: 設計フェーズ早期の対処で後工程の手戻りを抑制
  • 追加コストなしでの評価: プレビュー期間中は追加料金なしで導入のハードルが低い

🔧 技術面

  • コンテキストに即した分析: 汎用チェックリストより精度の高い結果
  • STRIDE の網羅的カバレッジ: 6 カテゴリすべてで脅威を分類し見落としを削減
  • 開発ワークフローへの統合: 普段の作業の中で脅威モデリングを実施

⚠️ デメリット・制約事項

制限事項

  • パブリックプレビューのため、機能や挙動が変更される可能性がある
  • 利用可能リージョンは AWS Security Agent がサポートするリージョンに限定される
  • AI による生成結果であるため、専門家によるレビューと検証が引き続き推奨される

考慮すべき点

  • 入力するソースコードや設計ドキュメントの品質が、生成される脅威モデルの精度に影響する
  • エージェントがアセットへアクセスするための IAM ロールの権限設計を適切に行う必要がある
  • パブリックプレビュー終了後の料金体系を事前に確認しておく必要がある

🎬 ユースケース

1. 設計フェーズでの早期脅威特定

シナリオ: 新しいマイクロサービスを開発するチームが、設計仕様をもとに早期に脅威を洗い出したい。

実装例: Kiro / Claude Code 内で仕様 (spec) からエージェントを呼び出し → STRIDE に基づく脅威モデルを生成 → 設計フェーズで緩和策を反映

✅ 効果: 実装前に脅威を特定して対処することで、後工程での手戻りを削減

2. デプロイ前のセキュリティ評価

シナリオ: セキュリティチームが本番デプロイ前に、設計ドキュメントとソースコードに対して脅威評価を実施したい。

実装例: CreateThreatModel で設計ドキュメントとソースコードを指定 → StartThreatModelJob で分析 → ListThreats で CRITICAL / HIGH の脅威を抽出してレビュー

✅ 効果: デプロイ前に重大な脅威を体系的に把握し、リスクを低減

3. 既存アプリケーションの脅威棚卸し

シナリオ: 既存アプリケーションのソースコードに対して脅威モデルを構築し、現状のリスクを可視化したい。

実装例: 連携リポジトリ (integratedRepositories) を入力アセットに指定 → 脅威モデリングジョブを実行 → UpdateThreat で対応状況 (RESOLVED / DISMISSED) を管理

✅ 効果: 既存システムのリスクを STRIDE 観点で棚卸しし、継続的に対応状況を追跡

💰 料金・利用可能リージョン

料金: パブリックプレビュー期間中は 追加料金なし で利用可能。プレビュー終了後の料金体系は公式ドキュメントおよび料金ページで最新情報を確認してください。
利用可能リージョン: AWS Security Agent がサポートするすべてのリージョンで利用可能。具体的な対応リージョンは公式ドキュメントを参照してください。

📝 まとめ

AWS Security Agent の脅威モデリング機能は、従来は専門スキルと手作業を要した脅威モデリングを AI エージェントで自動化 し、STRIDE フレームワークに沿った脅威と緩和策を提示します。Kiro や Claude Code への統合により 設計フェーズでのシフトレフト が実現できるため、開発チームとセキュリティチームの双方で活用を検討する価値があります。まずはパブリックプレビュー期間中に、追加料金なしで自社アプリケーションへの適用を試すことを推奨します。
