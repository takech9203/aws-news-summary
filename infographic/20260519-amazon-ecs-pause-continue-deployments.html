⏸️ Amazon ECS - サービスデプロイメントの一時停止・再開コントロール

PAUSE デプロイメントライフサイクルフックと ContinueServiceDeployment API

Amazon ECS
2026-05-19

📋 概要

Amazon ECS がサービスデプロイメントの進行中に一時停止 (Pause) と再開 (Continue) を制御する新機能をリリース。デプロイメントの重要なステージにおいて、手動承認ワークフロー、運用チェック、統合テスト、カスタムオートメーションなどの判断ポイントを導入できるようになる。

❌ Before

  • 手動承認ポイントには外部 CI/CD ツールに依存が必要
  • ECS ネイティブのデプロイ途中で検証を挟む仕組みがなかった
  • カナリア/ブルーグリーンデプロイ中の手動品質確認タイミングを制御不可

✅ After

  • ECS ネイティブに PAUSE フックでデプロイ一時停止ポイントを設定可能
  • EventBridge 連携で自動化ワークフローや承認システムをトリガー
  • 最大 14 日間のタイムアウト設定と自動続行/ロールバックアクション
  • 既存のトラフィックシフト、ベイクタイム、アラーム、サーキットブレーカーと併用可能

🏗️ アーキテクチャ図

Amazon ECS デプロイメントが PAUSE フックに到達した際のイベントフロー。EventBridge 経由で外部システムと連携し、ContinueServiceDeployment API で制御する。

sequenceDiagram
    participant Dev as 👤 開発者/CI
    participant ECS as ⚡ Amazon ECS
    participant EB as 📡 EventBridge
    participant Auto as 🔧 自動化ワークフロー
    participant Approve as ✅ 承認システム

    Dev->>ECS: デプロイメント開始
    ECS->>ECS: タスク配置・トラフィックシフト
    Note over ECS: PAUSE フックに到達
    ECS->>EB: デプロイ一時停止イベント発行
    EB->>Auto: ワークフロートリガー
    Auto->>Auto: 統合テスト実行
    Auto->>Approve: テスト結果通知
    alt 承認
        Approve->>ECS: ContinueServiceDeployment API action: CONTINUE
        ECS->>ECS: デプロイメント続行
        Note over ECS: デプロイ完了
    else 却下
        Approve->>ECS: ContinueServiceDeployment API action: ROLLBACK
        ECS->>ECS: ロールバック実行
    else タイムアウト
        Note over ECS: 設定されたタイムアウトアクション実行
    end

⭐ 主要機能

⏸️
PAUSE デプロイメントライフサイクルフック
デプロイ設定に PAUSE フックを構成可能。Rolling、Blue/Green、Linear、Canary すべてのデプロイ戦略で利用可能。
📡
ContinueServiceDeployment API
一時停止中のデプロイメントを続行またはロールバック。ECS コンソール、AWS CLI、SDK から呼び出し可能。
⚡
EventBridge イベント連携
一時停止状態に移行した際にイベントを発行。Lambda、Step Functions、SNS など任意のターゲットに接続可能。
⏰
タイムアウト制御
最大 14 日間のタイムアウト期間を設定可能。タイムアウト時のアクション (自動続行/自動ロールバック) を構成可能。

⚙️ 設定方法

前提条件

  • Amazon ECS クラスターが作成済みであること
  • ECS サービスがデプロイメント設定を使用していること
  • ContinueServiceDeployment API を呼び出すための IAM 権限が付与されていること
  • EventBridge ルールを設定する場合は、適切な IAM ロールが必要

ステップ 1: PAUSE フック付きデプロイメント設定の作成

Bash PAUSE フック設定 
aws ecs update-service \
  --cluster my-cluster \
  --service my-service \
  --deployment-configuration '{
    "deploymentLifecycleHooks": [
      {
        "hookType": "PAUSE",
        "timeoutDuration": "PT1H",
        "timeoutAction": "ROLLBACK"
      }
    ]
  }'

ステップ 2: EventBridge ルールの設定

Bash EventBridge ルール作成 
aws events put-rule \
  --name "ecs-deployment-pause-rule" \
  --event-pattern '{
    "source": ["aws.ecs"],
    "detail-type": ["ECS Deployment State Change"],
    "detail": {
      "deploymentStatus": ["PAUSE"]
    }
  }'

ステップ 3: デプロイメントの続行またはロールバック

Bash ContinueServiceDeployment API 
# デプロイメントを続行
aws ecs continue-service-deployment \
  --cluster my-cluster \
  --service my-service \
  --deployment-id "ecs-svc/1234567890" \
  --action CONTINUE

# デプロイメントをロールバック
aws ecs continue-service-deployment \
  --cluster my-cluster \
  --service my-service \
  --deployment-id "ecs-svc/1234567890" \
  --action ROLLBACK

IAM ポリシー例

JSON 必要な IAM 権限 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ecs:ContinueServiceDeployment",
        "ecs:DescribeServices",
        "ecs:UpdateService"
      ],
      "Resource": "arn:aws:ecs:*:*:service/*"
    }
  ]
}

⚖️ メリット・デメリット

💼 ビジネス面のメリット

✅ リスク低減: 本番デプロイ前に手動承認ゲートを設けることで、問題のあるリリースを防止
✅ コンプライアンス対応: 規制要件に基づく承認プロセスをデプロイフローに組み込み可能
✅ 運用の可視性向上: デプロイの各段階を明示的に制御・追跡でき、監査証跡を残せる

💻 技術面のメリット

✅ ネイティブ統合: 外部 CI/CD ツールに依存せず、ECS 標準のデプロイ戦略と一体化
✅ 柔軟な自動化: EventBridge 連携により、Lambda、Step Functions、SNS など任意のサービスと接続
✅ 安全なデフォルト: タイムアウトアクションにより、承認待ちのデッドロックを自動回避
✅ 既存機能との共存: トラフィックシフト、ベイクタイム、CloudWatch アラーム、サーキットブレーカーと併用可能

⚠️ 制限事項・考慮点

⚠️ タイムアウト期間は最大 14 日間まで
⚠️ PAUSE フックの数や配置ポイントに制限がある可能性
⚠️ CloudFormation でのデプロイ続行操作は不可 (コンソール、CLI、SDK のみ)
⚠️ タイムアウト設定が短すぎると意図しないロールバックが発生する可能性
⚠️ 複数の PAUSE ポイントを設定する場合、全体のデプロイ時間が大幅に延長される
⚠️ EventBridge ルール設定が適切でない場合、一時停止通知が届かずタイムアウトまで待機してしまう

🎯 ユースケース

🏦 ユースケース 1: 本番環境への手動承認デプロイ
シナリオ: 金融機関のサービスで、本番環境へのデプロイには変更管理委員会の承認が必要。カナリアデプロイでトラフィックの 10% に新バージョンを投入した後、承認を得てから全トラフィックを切り替えたい。
JSON カナリアデプロイ + PAUSE フック設定 
{
  "deploymentStrategy": "CANARY",
  "canaryConfig": {
    "initialTrafficPercentage": 10
  },
  "deploymentLifecycleHooks": [
    {
      "hookType": "PAUSE",
      "timeoutDuration": "P7D",
      "timeoutAction": "ROLLBACK"
    }
  ]
}
✨ 効果: カナリアトラフィック投入後に自動一時停止し、7 日間の承認猶予を確保。承認が得られなければ自動ロールバック。
🤖 ユースケース 2: 統合テスト自動化パイプライン
シナリオ: マイクロサービスアーキテクチャで、新バージョンのデプロイ後に E2E テストスイートを実行し、結果に基づいて自動的にデプロイを続行またはロールバックしたい。
Python Lambda 関数: EventBridge からトリガー 
import boto3

def handler(event, context):
    ecs_client = boto3.client('ecs')
    deployment_id = event['detail']['deploymentId']
    cluster = event['detail']['clusterArn']
    service = event['detail']['serviceArn']

    # 統合テスト実行
    test_result = run_integration_tests()

    # テスト結果に基づいてデプロイを制御
    action = 'CONTINUE' if test_result.passed else 'ROLLBACK'
    ecs_client.continue_service_deployment(
        cluster=cluster,
        service=service,
        deploymentId=deployment_id,
        action=action
    )
✨ 効果: デプロイの品質ゲートを自動化し、テスト失敗時は即座にロールバック。人手介入なしでデプロイの安全性を確保。
🛒 ユースケース 3: ブルー/グリーンデプロイでの運用確認
シナリオ: 大規模な e コマースプラットフォームで、ブルー/グリーンデプロイ時にグリーン環境のメトリクスを一定期間監視してから、本番トラフィックを切り替えたい。
