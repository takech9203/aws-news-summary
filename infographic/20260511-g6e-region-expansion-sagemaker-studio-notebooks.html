🔄 概要: Before / After

Amazon SageMaker Studio ノートブックにおいて、G6e インスタンスが新たに 6 つのリージョンで一般利用可能 (GA) になった。NVIDIA L40s GPU 搭載で、生成 AI ワークロードに最適なインスタンスタイプである。

❌ Before

  • G6e は一部リージョンのみで利用可能
  • 東京・ソウル等のアジアパシフィックリージョンでは使用不可
  • 米国リージョンへのアクセスが必要 (高レイテンシー・転送コスト)
  • G5 では性能不十分なワークロードへの対応が限定的

✅ After

  • 東京、ソウル、フランクフルト、ストックホルム、スペイン、ドバイの 6 リージョン追加
  • 東京リージョンで低レイテンシーな ML 開発が可能
  • G5 比 2.5 倍の性能向上
  • 13B パラメータまでの LLM を効率的に処理

🚀 主要機能

🎮 NVIDIA L40s GPU によるハイパフォーマンスコンピューティング

最大 8 基の NVIDIA L40s Tensor Core GPU を搭載。GPU あたり 48 GB の GDDR6X メモリ。Ada Lovelace アーキテクチャベースで AI/ML 推論とグラフィックスに最適化。FP8、INT8、FP16 などの混合精度演算をサポート。

⚡ G5 インスタンス比 2.5 倍の性能向上

G5 (NVIDIA A10G) から G6e (NVIDIA L40s) への世代交代による大幅な性能改善。推論スループットと学習速度において顕著な性能差。メモリ帯域幅の向上により大規模モデルの処理が高速化。

🤖 生成 AI ワークロード対応

最大 13B パラメータの LLM デプロイ、拡散モデルによる画像・動画・音声生成、インタラクティブなモデルトレーニングとファインチューニング、モデルデプロイのテストをノートブック環境で実行可能。

⚙️ 設定方法

前提条件

  • SageMaker Studio ドメインが対象リージョンに作成済みであること
  • G6e インスタンスタイプに対するサービスクォータが十分であること
  • 適切な IAM ロールが設定されていること

ステップ 1: サービスクォータの確認

Bash G6e インスタンスのクォータ確認 
# G6e インスタンスのクォータを確認 (東京リージョンの例)
aws service-quotas get-service-quota \
  --service-code sagemaker \
  --quota-code L-12345678 \
  --region ap-northeast-1

ステップ 2: SageMaker Studio ノートブックの起動

Bash ノートブックインスタンスの作成 
# SageMaker Studio でノートブックインスタンスを作成
aws sagemaker create-app \
  --domain-id <domain-id> \
  --user-profile-name <user-profile> \
  --app-type JupyterLab \
  --app-name default \
  --resource-spec InstanceType=ml.g6e.xlarge \
  --region ap-northeast-1

ステップ 3: インスタンスタイプの変更 (既存ノートブック)

SageMaker Studio コンソールで既存のノートブックインスタンスのインスタンスタイプを変更する手順。

  1. SageMaker Studio にログイン
  2. 実行中のノートブックを停止
  3. インスタンスタイプのドロップダウンから ml.g6e.* を選択
  4. ノートブックを再起動

🎯 ユースケース

🤖 LLM ファインチューニング

日本語対応の LLM (7B - 13B パラメータ) を社内データでファインチューニング。48 GB の GPU メモリにより 13B パラメータモデルを効率的に処理し、G5 比で学習時間を約 60% 短縮。

🎨 画像生成モデルのプロトタイピング

Stable Diffusion XL などの拡散モデルを使用して画像生成パイプラインのプロトタイプを開発。L40s GPU により SDXL の推論速度が G5 比で大幅に向上。

🧪 モデルデプロイテスト

本番デプロイ前に SageMaker Studio ノートブック上でモデルの推論パフォーマンスとレイテンシーをテスト。リージョン内での特性を事前に把握可能。

コード例: LoRA ファインチューニング

Python G6e の 48GB GPU メモリを活用した 13B モデルのファインチューニング 
# SageMaker Studio ノートブックでの LoRA ファインチューニング例
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import get_peft_model, LoraConfig
import torch

# G6e の 48GB GPU メモリを活用して 13B モデルをロード
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-2-13b-hf",
    torch_dtype=torch.bfloat16,
    device_map="auto"
)

lora_config = LoraConfig(
    r=16, lora_alpha=32, target_modules=["q_proj", "v_proj"]
)
model = get_peft_model(model, lora_config)

✅ メリット

💼 ビジネス面

  • 東京リージョンでの利用により、低レイテンシーで ML 開発が可能
  • G5 比 2.5 倍の性能向上により、GPU コストを削減
  • データレジデンシー要件に対応可能

🔬 技術面

  • GPU メモリ倍増 (24 GB → 48 GB) で大規模モデルに対応
  • ノートブック環境で直接 GPU リソースを活用
  • 最大 8 GPU 構成でマルチ GPU 並列処理に対応

⚠️ 制約事項・考慮点

  • LLM デプロイは最大 13B パラメータまでが推奨範囲 (70B 以上は p5 インスタンスの検討が必要)
  • サービスクォータの引き上げが必要な場合、承認までに時間がかかる可能性あり
  • SageMaker Studio ノートブック環境でのみ利用可能 (EC2 直接利用とは別)
  • G6e は G5 より高い時間単価のため、小規模ワークロードでは G5 の方がコスト効率的な場合あり
  • 新規リージョンではアベイラビリティーゾーンによって利用可能サイズが異なる場合あり
