📊 Amazon CloudWatch

ダッシュボードのタグ付けに対応

タグでダッシュボードを整理・分類し、アクセスを制御できるように
🗓️ 2026 年 6 月 24 日

📌 概要

Amazon CloudWatch が CloudWatch ダッシュボードへのタグ付けに対応しました。タグ (キーと値のペア) を使って、ダッシュボードをチーム・プロジェクト・環境ごとにグループ化できます。

PutDashboard API がオプションの Tags パラメータを受け付け、新規作成時に最大 50 個のタグを割り当て可能に。さらに TagResource / UntagResource / ListTagsForResource がダッシュボードの ARN をサポートし、既存ダッシュボードのタグ操作もできるようになりました。

タグ値による 属性ベースのアクセス制御 (ABAC) や、AWS Resource Explorer でのフィルタリングが可能です。すべての CloudWatch 利用可能リージョンで追加費用なしで利用できます。

Before / アップデート前の課題

  • ダッシュボードにタグを付けられず、チーム・プロジェクト・環境ごとに体系的に分類できなかった
  • タグベースで IAM 権限を絞り込む ABAC を実装できなかった
  • Resource Explorer でタグによる検索・フィルタリングができなかった

After / アップデート後の改善

  • 最大 50 個のタグでダッシュボードをチーム・プロジェクト・環境別にグループ化
  • タグ値をスコープとした IAM 権限による ABAC が可能
  • Resource Explorer でタグによるフィルタリングが可能

ダッシュボードにタグを付与し、そのタグを起点に IAM による ABAC、Resource Explorer での検索、CloudFormation での管理を実現する流れ

⚙️ 主要機能

🔧 作成時のタグ付け (PutDashboard)

  • PutDashboard がオプションの Tags パラメータを受け付ける
  • 新規作成時に最大 50 個のタグを割り当て可能 (キーと値のペア)
  • 既存ダッシュボードの更新時に Tags を指定しても無視される (タグ付けは新規作成時のみ)

🏷️ 既存ダッシュボードのタグ管理

  • TagResource: タグの追加・更新
  • UntagResource: タグの削除
  • ListTagsForResource: 付与済みタグの一覧取得
  • これらの API がダッシュボードの ARN をサポート

📦 AWS CloudFormation によるタグ管理

  • ダッシュボードのタグを CloudFormation テンプレートで宣言的に管理
  • Infrastructure as Code (IaC) でタグ運用の一貫性を確保

🔐 属性ベースのアクセス制御 (ABAC) と検索

  • タグ値をスコープに IAM 権限を限定し、特定のタグを持つダッシュボードのみアクセス許可
  • AWS Resource Explorer でタグによるフィルタリングが可能

ABAC 用 IAM ポリシー例

JSONTeam タグが platform のダッシュボードのみ許可
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "cloudwatch:GetDashboard",
        "cloudwatch:PutDashboard"
      ],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "aws:ResourceTag/Team": "platform"
        }
      }
    }
  ]
}

🛠️ 設定方法

前提条件

  • Amazon CloudWatch を利用している AWS アカウント
  • ダッシュボードのタグ操作 (cloudwatch:TagResource など) を許可する IAM 権限
  • AWS CLI または AWS SDK の利用環境 (CLI で操作する場合)

ステップ 1: タグ付きでダッシュボードを作成する

BashPutDashboard with Tags
aws cloudwatch put-dashboard \
  --dashboard-name "ProdServiceDashboard" \
  --dashboard-body file://dashboard-body.json \
  --tags Key=Team,Value=platform Key=Environment,Value=production

ステップ 2: 既存ダッシュボードにタグを追加する

BashTagResource
aws cloudwatch tag-resource \
  --resource-arn "arn:aws:cloudwatch::123456789012:dashboard/ProdServiceDashboard" \
  --tags Key=Project,Value=checkout

ステップ 3: タグを確認・削除する

BashListTagsForResource / UntagResource
# タグ一覧を取得
aws cloudwatch list-tags-for-resource \
  --resource-arn "arn:aws:cloudwatch::123456789012:dashboard/ProdServiceDashboard"

# タグを削除
aws cloudwatch untag-resource \
  --resource-arn "arn:aws:cloudwatch::123456789012:dashboard/ProdServiceDashboard" \
  --tag-keys Project

⚖️ メリットと制約事項

✅ メリット

  • ガバナンスの向上: チーム・プロジェクト・環境ごとに分類でき、リソース管理が容易に
  • コスト不要: 全対応リージョンで追加費用なし
  • アクセス制御の明確化: タグで担当チームのみに公開でき、運用責任の所在が明確に
  • ABAC の実現: タグ値スコープの IAM 権限でダッシュボード単位の細やかな制御
  • 検索性の向上: Resource Explorer でタグフィルタリング
  • IaC との統合: CloudFormation でタグを宣言的に管理し環境間の一貫性を維持

⚠️ 制約・考慮点

  • 1 ダッシュボードあたりのタグは最大 50 個
  • PutDashboard の Tags は新規作成時のみ有効。更新時のタグ指定は無視される
  • 既存ダッシュボードのタグ操作には TagResource / UntagResource が必要
  • ダッシュボードはアカウント内でグローバル (リージョン固有ではない) 点に留意
  • ABAC 運用ではタグキー・値の命名規則を組織全体で統一する必要がある
  • 導入時は既存 IAM ポリシーへの影響を事前に検証する

💡 ユースケース

1. チーム別のアクセス制御

シナリオ: 複数チームが同一アカウントを共有し、各チームが自チームのダッシュボードのみを編集できるようにしたい。

実装: Team=platform / Team=payments などのタグを付与し、aws:ResourceTag/Team 条件キーで IAM 権限をスコープ。

担当外ダッシュボードへの誤操作を防ぎ、最小権限の原則を実現

2. 環境別のダッシュボード整理

シナリオ: 本番・ステージング・開発の各環境のダッシュボードが混在しており、環境ごとに素早く絞り込みたい。

実装: Environment=production / staging / development タグを付与し、AWS Resource Explorer でフィルタリング。

大量のダッシュボードから目的の環境のものを迅速に特定できる

3. CloudFormation による標準化

シナリオ: 新しいマイクロサービスを追加するたびに、標準タグ付きのダッシュボードを自動作成したい。

YAMLAWS::CloudWatch::Dashboard
Resources:
  ServiceDashboard:
    Type: AWS::CloudWatch::Dashboard
    Properties:
      DashboardName: checkout-service
      DashboardBody: !Sub '${DashboardJson}'
      Tags:
        - Key: Team
          Value: payments
        - Key: Environment
          Value: production

IaC でタグ運用を標準化し、人手によるタグ付け漏れを防止できる

🎯 まとめ

CloudWatch ダッシュボードのタグ付け対応により、ダッシュボードをチーム・プロジェクト・環境別に整理し、ABAC によるアクセス制御や Resource Explorer での検索が可能になりました。追加費用なしで利用できるため、複数チームでアカウントを共有している組織は、タグの命名規則を整備した上で、IAM ポリシーや CloudFormation テンプレートへの組み込みを検討することを推奨します。
