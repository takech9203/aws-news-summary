ExtendDB - DynamoDB 互換オープンソースアダプター

DynamoDB API をプラガブルなストレージバックエンドで実装するオープンソースプロジェクト
2026-05-20

📋 概要

AWS は ExtendDB バージョン 0.1 を発表した。ExtendDB は、Amazon DynamoDB API をプラガブルなストレージバックエンドで実装するオープンソースプロジェクトである。Apache 2.0 ライセンスのもとで公開され、Rust で開発されている。

DynamoDB マネージドサービスが利用できない環境 (開発者のラップトップ、オンプレミスデータセンター、切断されたエッジサイト) で、アプリケーションコードを書き換えることなく DynamoDB プログラミングモデルを使用可能にする。

🔄 Before / After

❌ Before (課題)

  • ローカル開発やテストに高忠実度な環境がなかった
  • オンプレミスや切断環境でのワークロード実行にはコード書き換えが必要
  • CI/CD パイプラインで DynamoDB 依存テストが困難
  • DynamoDB Local は機能限定的でバックエンド選択肢なし

✅ After (改善)

  • endpoint-url の変更のみで DynamoDB と切り替え可能
  • PostgreSQL / Cassandra でオンプレミス運用可能
  • 全 AWS SDK および高レベルライブラリと互換
  • コントロールプレーン + データプレーン + Streams + TTL 対応

⚡ 主要機能

🔌 DynamoDB API 完全互換

コントロールプレーン API (CreateTable, DeleteTable, DescribeTable, ListTables, UpdateTable)、データプレーン API (PutItem, GetItem, DeleteItem, UpdateItem)、Query / Scan、バッチ / トランザクション、Streams、TTL、Import / Export、タグ管理を全てサポート。

🧩 プラガブルストレージアーキテクチャ

Rust トレイトとしてストレージインターフェースを定義。PostgreSQL リファレンスバックエンド (完全テストスイート検証済み) に加え、Apache Cassandra バックエンド (水平スケーリング対応) を提供。コアアダプターを変更せずに新バックエンド追加可能。

🔒 セキュリティ機能

TLS 必須 (初回実行時に自己署名証明書を自動生成)、SigV4 認証 (ローカル認証情報ストア)、IAM ポリシー互換の認可モデル、管理コンソール (https://127.0.0.1:8000/console/) を搭載。

🛠️ SDK 完全互換性

全 AWS SDK (JavaScript, Python, Java, Go 等) で動作。高レベルライブラリ (PynamoDB, Dynamoose, DynamoDB Toolbox, awswrangler) にも対応。エラーコードパリティにより同一のエラーハンドリングコードが動作。

🚀 設定方法

ステップ 1: リポジトリのクローンとビルド

Bash ビルド手順 
git clone https://github.com/ExtendDB/extenddb.git
cd extenddb
cargo build --release

ステップ 2: 初期化とサーバー起動

Bash 初期化とサーバー起動 
./target/release/extenddb init
./target/release/extenddb serve --config extenddb.toml

init コマンドはデータベースとスキーマの作成、管理者認証情報の生成、TLS 証明書のプロビジョニング、設定ファイルの書き込みを実行する。

ステップ 3: ユーザーとアクセスキーの作成

Bash ユーザー管理 
# ユーザー作成
./target/release/extenddb manage --user admin --password '<admin-password>' \
  create-user --account-id <account-id> --user-name myuser

# ポリシー設定
./target/release/extenddb manage --user admin --password '<admin-password>' \
  put-user-policy --account-id <account-id> --user-name myuser \
  --policy-name full-access \
  --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":"dynamodb:*","Resource":"*"}]}'

# アクセスキー作成
./target/release/extenddb manage --user admin --password '<admin-password>' \
  create-access-key --account-id <account-id> --user-name myuser

ステップ 4: 環境変数の設定と利用

Bash AWS CLI での利用例 
export AWS_ACCESS_KEY_ID="AKIA..."
export AWS_SECRET_ACCESS_KEY="extenddb..."
export AWS_CA_BUNDLE=~/.extenddb/tls/cert.pem

# AWS CLI での利用例
aws dynamodb create-table \
  --table-name Orders \
  --attribute-definitions AttributeName=PK,AttributeType=S AttributeName=SK,AttributeType=S \
  --key-schema AttributeName=PK,KeyType=HASH AttributeName=SK,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --endpoint-url https://127.0.0.1:8000 \
  --region us-east-1

--endpoint-url を ExtendDB のアドレスに向けるだけで、通常の AWS CLI コマンドがそのまま動作する。

💡 ユースケース

💻 ローカル開発と CI テスト

DynamoDB を使用するマイクロサービスの開発チームが、ローカル環境と CI パイプラインで高忠実度なテストを実行。式評価、条件式、エラーコードパリティにより、本番環境と同等の動作検証が可能。テストの信頼性が向上し、本番デプロイ後の不具合を削減。

Python ローカル開発での利用例 
import boto3

# ExtendDB をローカルで使用
dynamodb = boto3.resource(
    'dynamodb',
    endpoint_url='https://127.0.0.1:8000',
    region_name='us-east-1'
)

table = dynamodb.Table('Orders')
table.put_item(Item={'PK': 'ORDER#123', 'SK': 'META', 'status': 'pending'})

🏢 オンプレミスデータセンターでの運用

規制要件によりデータをオンプレミスに保持する必要がある金融機関や医療機関が、DynamoDB のプログラミングモデルを活用。PostgreSQL の既存運用ツール (レプリケーション、ポイントインタイムリカバリ) を活用しながら DynamoDB 互換 NoSQL インターフェースで構築。

TOML extenddb.toml 設定例 
[storage]
backend = "postgres"

[storage.postgres]
host = "db-primary.internal.example.com"
port = 5432
database = "extenddb"

📡 切断環境でのエッジ運用

インターネット接続が間欠的または不可能なエッジサイト (工場、船舶、遠隔地) で DynamoDB 互換ワークロードを運用。オフライン環境で API を提供し、接続回復時にデータをクラウドと同期する戦略が可能。

Bash Docker でのエッジデプロイ 
docker run -d --name extenddb \
  -p 8000:8000 \
  -v /data/extenddb:/var/lib/extenddb \
  extenddb/extenddb:latest serve --config /etc/extenddb/extenddb.toml
