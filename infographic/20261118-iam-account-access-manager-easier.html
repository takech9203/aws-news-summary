☁️ AWS Identity and Access Management (IAM)

🔐 IAM account access manager の導入・運用が容易に

📅 リリース日: 2026 年 11 月 18 日 | マネージドポリシー、IaC 対応、サードパーティ連携

📝 概要

IAM account access manager は、IAM Identity Center の組織インスタンスに同期されたユーザーやグループに対して、各 AWS アカウントの既存の IAM ロールを割り当ててアカウントアクセスを管理できる機能です。今回のアップデートで、導入と運用のハードルを下げる 3 つの改善が発表されました。

📜
AWS マネージドポリシー
3 種類の新ポリシーで役割ごとの権限付与が簡単に
⚙️
IaC 対応
Terraform / Pulumi / CloudFormation で構成管理
🔗
サードパーティ連携
Okta や SailPoint などからロール割り当てを直接管理

❌ アップデート前の課題

✗有効化・管理には IAM Identity Center、Organizations、KMS、IAM にまたがるポリシーを手動で組み立てる必要があった
✗役割ごとの最小権限ポリシーを自作・保守する運用負荷があった
✗サードパーティのアイデンティティ管理ツールとのネイティブなロール割り当て統合が限定的だった

✅ アップデート後の改善

✓3 種類の AWS マネージドポリシーだけで有効化・管理・監査に必要な権限を付与できる
✓Terraform、Pulumi、CloudFormation で IaC として管理し、自動化・大規模展開に組み込める
✓Okta、SailPoint などのパートナーソリューションからロール割り当てを直接統合管理できる

管理者はマネージドポリシーまたは IaC ツールで account access manager を有効化・管理し、IAM Identity Center のユーザー・グループを各アカウントの既存 IAM ロールにマッピングします。ユーザーはアカウントアクセスポータルや aws login コマンド経由で割り当てられたアカウントにアクセスします。

⚡ 主要機能

📜 1. AWS マネージドポリシーによる有効化・管理

  • 新たに 3 種類の AWS マネージドポリシーが提供され、役割ごとの権限付与が容易になった
  • 従来必要だった IAM Identity Center、Organizations、KMS、IAM にまたがるポリシーの手動作成が不要に
  • 最小権限の原則に沿った権限分離 (管理者 / エンタイトルメント管理者 / 読み取り専用) を標準で実現

⚙️ 2. Infrastructure as Code 対応

  • Terraform、Pulumi、AWS CloudFormation で account access manager の構成を管理できる
  • 既存の IaC パイプラインに組み込み、有効化からロール割り当てまでをコードとして再現可能に展開
  • 大規模なマルチアカウント環境での一貫したデプロイが可能
Terraform Pulumi AWS CloudFormation

🔗 3. サードパーティソリューションとのロール割り当て統合

  • 既存のアイデンティティガバナンス・エンタイトルメント管理ワークフローから AWS アカウントへのロール割り当てを直接管理
  • Just-in-Time アクセスやアクセスレビューなど、パートナー製品の機能と組み合わせた運用が可能
Okta Ping Identity Cisco Duo Apono BeyondTrust Britive Sonrai Security C1.ai Lumos SailPoint

🔄 account access manager の基本機能 (おさらい)

  • IAM Identity Center の組織インスタンスのユーザー・グループに対し、各アカウントの既存の IAM ロールを割り当ててアクセスを付与
  • IAM Identity Center の許可セット (permission sets) と併用も単独使用も可能
  • タグ・セッションタグによる ABAC、信頼ポリシーによるロール引き受け制限、ロールパスによる論理的なグループ化など、IAM ロールの柔軟性をそのまま活用できる
  • 専用のアカウントアクセスポータルからアクセスでき、サインイン後に aws login コマンドで AWS CLI の認証情報を取得できる
  • IAM API とは独立した account-access という専用の API 名前空間を持つ

🛠️ 設定方法

✅ 前提条件

  • AWS Organizations の組織が構成されており、管理アカウントにアクセスできること
  • IAM Identity Center の組織インスタンスが有効化されており、ユーザー・グループが同期または作成されていること
  • アクセスを割り当てる対象の IAM ロールが各メンバーアカウントに存在すること

STEP 1管理者へのマネージドポリシーのアタッチ

Bash 管理者ロールへのポリシーアタッチ 
aws iam attach-role-policy \
  --role-name AccountAccessAdminRole \
  --policy-arn arn:aws:iam::aws:policy/AWSAccountAccessManagerAdministrator

有効化・管理を担当する管理者のロールに新しいマネージドポリシーをアタッチします。複数サービスにまたがるカスタムポリシーの作成は不要です。

STEP 2account access manager の有効化とロール割り当て

組織の管理アカウントで有効化し、IAM Identity Center のユーザー・グループと各アカウントの IAM ロールをマッピングします。コンソールのほか、account-access API 名前空間を使用した AWS CLI / SDK、または Terraform、Pulumi、CloudFormation などの IaC ツールで構成できます。

STEP 3エンタイトルメント管理者・監査担当者への権限付与

Bash 役割別のポリシーアタッチ 
# エンタイトルメント管理者 (アクセスの割り当て・削除のみ)
aws iam attach-role-policy \
  --role-name EntitlementManagerRole \
  --policy-arn arn:aws:iam::aws:policy/AWSAccountAccessManagerEntitlementManager

# 監査担当者 (読み取り専用)
aws iam attach-role-policy \
  --role-name AuditorRole \
  --policy-arn arn:aws:iam::aws:policy/AWSAccountAccessManagerReadOnlyAccess

日常的なアクセス割り当てを行う担当者と監査担当者に、それぞれ最小権限のマネージドポリシーを付与します。これにより職務分掌を標準ポリシーだけで実現できます。

💡 メリット

💼 ビジネス面

✓導入までの時間短縮: マネージドポリシーにより権限設計の手間が大幅に削減され、迅速に導入を開始できる
✓ガバナンスの強化: 管理者・エンタイトルメント管理者・監査担当者の職務分掌を AWS 標準のポリシーで実現でき、コンプライアンス対応が容易になる
✓既存投資の活用: Okta や SailPoint などの既存のアイデンティティガバナンス製品をそのまま活用し、AWS アカウントアクセスを統合管理できる

⚙️ 技術面

✓IaC による再現性: 構成をコード化でき、マルチアカウント環境への一貫した展開と変更管理が可能になる
✓ポリシー保守の負荷軽減: カスタムポリシーの作成・保守が不要になり、権限の過不足によるリスクを低減できる
✓既存 IAM ロールの柔軟性維持: ABAC 用のセッションタグ、信頼ポリシーの条件、ロールパスなど、IAM ロールの機能をそのまま利用できる

⚠️ デメリット・制約事項

🚧 制限事項

!利用には IAM Identity Center の組織インスタンスが前提となる (AWS Organizations 環境が必要)
!割り当て対象の IAM ロールは自動プロビジョニングされないため、IaC またはコンソールで事前に各アカウントへ作成する必要がある
!サードパーティ統合の具体的な機能範囲は各パートナーソリューションの実装に依存する

🤔 考慮すべき点

!IAM Identity Center の許可セットで統一的なアクセス管理を行っている場合、使い分け (カスタムロールは account access manager、ベースラインは許可セット) の設計が必要
!既存のカスタムポリシーで運用している場合は、新しいマネージドポリシーへの移行を検討するとポリシー保守が簡素化される

🧩 関連サービス・機能

👥 AWS IAM Identity Center

account access manager はその組織インスタンスのユーザー・グループを利用する。許可セットとの併用も可能。

🏢 AWS Organizations

組織の管理アカウントで account access manager を有効化・管理する。

🔑 AWS IAM

割り当て対象となる既存の IAM ロール (タグ、信頼ポリシー、パスなど) を提供する。

⚙️ AWS CloudFormation / Terraform / Pulumi

account access manager の構成を IaC として管理できる。

📌 まとめ

今回のアップデートにより、IAM account access manager はマネージドポリシー、IaC 対応、サードパーティ統合の 3 点で導入・運用のハードルが大きく下がりました。既存の IAM ロールを活用したきめ細かいアカウントアクセス管理を検討している組織は、まず新しいマネージドポリシーを使った小規模な有効化から始め、Terraform や CloudFormation による構成管理へ段階的に拡大することを推奨します。
