📌 概要

Amazon FSx for OpenZFS の Intelligent-Tiering ストレージクラスが、新たに 8 つの AWS リージョンで利用可能になりました。米国、欧州、アジアパシフィック、南米の各地域で Intelligent-Tiering を使った FSx for OpenZFS ファイルシステムを作成できます。

アクセスパターンに基づいて、データを 3 つのストレージ階層 (Frequent Access、Infrequent Access、Archive) 間で自動的に移動。オプションの SSD 読み取りキャッシュにより、アクティブなデータへの高速アクセスを維持します。保存したデータ量に対してのみ課金され、容量管理は不要です。

⛔ アップデート前の課題

  • 一部のリージョンで Intelligent-Tiering が利用できず、コスト効率の高い汎用ファイルストレージを構築できなかった
  • 対象外リージョンでは、高コストな SSD ストレージクラスやオンプレミス HDD NAS に依存する必要があった
  • アクセス頻度に応じた階層化を AWS 上で自動化できないケースがあった

✅ アップデート後の改善

  • 北カリフォルニア、ロンドン、ストックホルム、スペイン、チューリッヒ、ハイデラバード、ソウル、サンパウロで利用可能に
  • 保存データ量に応じた従量課金とアクセスパターンに基づく自動階層化を活用可能
  • リージョンに近い場所でレイテンシとコストの両方を最適化できる

⚙️ 主要機能

🔄 3 階層の自動データ移動

  • アクセスパターンに基づき Frequent / Infrequent / Archive の 3 階層間でデータを自動移動
  • 管理者による手動の階層管理は不要
  • 頻繁にアクセスされなくなったデータは、より低コストな階層へ自動移動

⚡ オプションの SSD 読み取りキャッシュ

  • アクティブなデータをキャッシュし、高速な読み取りパフォーマンスを維持
  • アクティブワークロードには高性能、それ以外には低コストストレージを提供

💰 容量管理不要の従量課金

  • 保存したデータ量に対してのみ課金、事前のキャパシティプロビジョニング不要
  • ファイル共有、アーカイブ、メディアライブラリ、オンプレ HDD からの移行に最適化

制限事項

!すべての AWS リージョンで利用できるわけではなく、利用前に最新の対応状況の確認が必要
!SSD 読み取りキャッシュはオプションで、利用時はプロビジョニング容量に応じた追加料金が発生

考慮すべき点

!アクセスパターンが頻繁に変動するワークロードでは、リクエスト課金や階層間移動を考慮
!低レイテンシが常時求められる高 IOPS ワークロードでは SSD ストレージクラスの方が適する場合がある

💡 ユースケース

1. 大規模ファイル共有

シナリオ: 部門間で共有される大量のファイルのうち、一部のみが頻繁にアクセスされ、大半は時間とともにアクセスされなくなる。

効果: アクティブファイルは SSD キャッシュと Frequent Access で高速提供しつつ、低頻度ファイルは自動的に低コスト階層へ移動しストレージコストを削減。

2. メディアライブラリのアーカイブ

シナリオ: 放送・制作業界で大容量のメディアアセットを保管し、過去のコンテンツは稀にしかアクセスされない。

効果: 過去のメディアアセットを Archive 階層へ自動移動し、保管コストを抑えながら必要時にアクセス可能。

3. オンプレミス HDD NAS からの移行

シナリオ: オンプレミスの HDD ベース NAS で運用していた汎用ファイルワークロードをクラウドへ移行したい。

効果: オンプレ HDD NAS と比較して最大 20% のコスト削減を実現しつつ、容量管理不要の従量課金で運用負荷を軽減。

💴 料金

各階層で消費した平均ストレージ量 (GB - 月単位) に対して課金されます。保存したデータ量に対してのみ課金され、事前のキャパシティプロビジョニングは不要です。具体的な料金はリージョンによって異なります。

🎯 まとめ

今回のアップデートにより、FSx for OpenZFS の Intelligent-Tiering ストレージクラスが 8 つの新規リージョンで利用可能になり、より多くの地域でコスト効率の高い汎用ファイルストレージを構築できるようになりました。ファイル共有やメディアライブラリ、オンプレミス HDD からの移行を検討している場合は、対象リージョンでの導入を検討し、ワークロードのアクセスパターンに基づいたコスト最適化を進めることをおすすめします。
