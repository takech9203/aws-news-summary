Amazon EC2 | Capacity Blocks for ML

🔍 Capacity Blocks for ML が複数インスタンスタイプ・複数リージョンの横断検索に対応

📅 リリース日: 2026 年 11 月 23 日 🖥️ 対象: P6-B300 / P6-B200 / Trn2 などのアクセラレーテッドインスタンス

📝 概要

EC2 Capacity Blocks for ML が、複数のインスタンスタイプと複数の AWS リージョンにまたがるキャパシティ検索をサポート。1 回の検索で複数の組み合わせを横断的に確認でき、ML 向けコンピューティングキャパシティの確保が大幅に簡素化されます。

Capacity Blocks for ML は、P6-B300、P6-B200、Trn2 などのアクセラレーテッドインスタンスを、将来の開始日を指定して最大 6 か月間予約できる機能です。ML モデルのトレーニングやファインチューニングなど、GPU / アクセラレーターを一定期間だけ確実に確保したいワークロードに適しています。API では DescribeCapacityBlockOfferings への 1 回の呼び出しで、単一リージョン内の複数インスタンスタイプを横断照会できます。

❌ アップデート前の課題
  • インスタンスタイプとリージョンの組み合わせごとに個別の検索が必要
  • 複数候補の比較には検索の繰り返しが必要で、キャパシティ確保に時間がかかった
  • 希望タイプが見つからない場合、代替候補を探す作業が煩雑だった
✅ アップデート後の改善
  • コンソールでの 1 回の検索で複数タイプ・複数リージョンの空き状況を確認可能
  • 繰り返し検索なしで必要なキャパシティを迅速に特定・予約
  • API では 1 回の呼び出しで同一リージョン内の複数タイプを照会可能

アップデート前は組み合わせごとに検索を繰り返す必要がありましたが、アップデート後はコンソールでの 1 回の検索で複数インスタンスタイプ・複数リージョンの空き状況を一括確認し、そのまま予約できます。

⚡ 主要機能

1️⃣ 複数インスタンスタイプの横断検索
  • 1 回の検索で複数のインスタンスタイプ (例: P6-B300、P6-B200、Trn2) の空き状況を同時に確認可能
  • 希望タイプに空きがない場合でも、代替候補を同じ検索結果の中から比較できる
  • API (DescribeCapacityBlockOfferings) でも 1 回の呼び出しで複数タイプの照会が可能
2️⃣ 複数 AWS リージョンの横断検索
  • AWS マネジメントコンソールで、複数リージョンにまたがるキャパシティ検索が可能
  • リージョンごとの検索やり直しが不要になり、グローバルにキャパシティを比較できる
  • 複数リージョン検索はコンソールのみ。AWS CLI / SDK / API はリクエスト送信先のリージョンが対象
3️⃣ Capacity Blocks for ML の基本機能 (変更なし)
  • 将来の開始日 (最大 8 週間先) を指定して、最大 6 か月間のキャパシティを予約可能
  • 1 つの Capacity Block あたり最大 64 インスタンス、合計で最大 256 インスタンスまで予約可能
  • 予約インスタンスは EC2 UltraClusters 内に近接配置され、低レイテンシーな大規模ネットワーキングを利用可能

🛠️ 設定方法

前提条件

✓AWS アカウントと、EC2 Capacity Blocks の検索・購入に必要な IAM 権限があること
✓利用したいインスタンスタイプが Capacity Blocks for ML の対象であること
✓対象リージョンで Capacity Blocks for ML が提供されていること (対応リージョンはドキュメントを参照)

手順

1
EC2 コンソールで Capacity Blocks の検索画面を開く

AWS マネジメントコンソールで EC2 を開き、[Capacity Blocks] から Capacity Block 予約の作成画面に進みます。

2
複数のインスタンスタイプとリージョンを指定して検索する

複数のインスタンスタイプと複数の AWS リージョン、必要なインスタンス数、期間、開始日の範囲を指定して検索を実行します。1 回の検索で、指定した組み合わせ全体の空き状況と料金が一覧表示されます。

3
API で複数インスタンスタイプを照会する (オプション)
Bash Capacity Block オファリングの照会例 
# 単一リージョン内で Capacity Block オファリングを照会する例
aws ec2 describe-capacity-block-offerings \
  --instance-count 4 \
  --capacity-duration-hours 336 \
  --region us-east-2

DescribeCapacityBlockOfferings API は、指定した条件に合致するオファリング (開始日、期間、料金など) を返します。今回のアップデートにより、1 回の API 呼び出しで複数インスタンスタイプを対象とした照会が可能になりました。なお、API での検索対象はリクエストを送信したリージョンのみです。

4
検索結果から Capacity Block を購入する

検索結果から条件に合うオファリングを選択し、Capacity Block を購入します。予約開始後は、予約 ID をターゲットに指定してインスタンスを起動します。

✓ML プロジェクトの計画性向上: 複数リージョンの空き状況を俯瞰でき、トレーニングスケジュールの立案が容易になる

🎯 ユースケース

1. 大規模モデルトレーニングのキャパシティ確保

シナリオ: 基盤モデルのトレーニングのために P6-B300 を第一候補としつつ、空きがなければ P6-B200 でも許容できるチームが、最速でキャパシティを確保したい。

実装例: コンソールの検索でインスタンスタイプに P6-B300 と P6-B200 の両方を指定し、候補リージョンを複数選択して検索。最も早く開始できるオファリングを選択して予約する。

💡 効果: 組み合わせごとの繰り返し検索が不要になり、トレーニング開始までのリードタイムを短縮できる。

2. リージョンに柔軟な実験・プロトタイピング

シナリオ: データの所在に強い制約がない ML 実験で、コストと開始時期を優先してリージョンを選びたい。

実装例: コンソールで複数リージョンを対象にキャパシティを横断検索し、開始日と料金を比較して最適なリージョンの Capacity Block を予約する。

💡 効果: 特定リージョンの空き待ちを回避し、実験のイテレーション速度を維持できる。

3. キャパシティ監視の自動化

シナリオ: 希望条件のキャパシティが出るのを定期的にチェックし、空きが出たら通知する仕組みを構築したい。

実装例: スケジュール実行する Lambda 関数から DescribeCapacityBlockOfferings を呼び出し、複数インスタンスタイプのオファリングを 1 回の API 呼び出しで照会。条件に合うオファリングが見つかったら SNS で通知する。

💡 効果: 1 回の API 呼び出しで複数タイプをカバーでき、監視ロジックがシンプルになり API 呼び出し回数も削減できる。

💰 料金と利用可能リージョン

料金: 今回のアップデート (検索機能の強化) に伴う追加料金の記載はありません。Capacity Blocks for ML の料金は従来どおりで、予約時に表示される料金を予約した期間分だけ前払いで支払う方式です。
利用可能リージョン: Capacity Blocks for ML が提供されているすべての AWS リージョンの Instance Capacity Blocks で利用可能です。対応リージョンには米国東部 (バージニア北部、オハイオ)、米国西部 (オレゴン)、アジアパシフィック (東京) などが含まれます。最新の一覧は公式ドキュメントを参照してください。

EC2 Capacity Blocks for ML の検索が複数インスタンスタイプ・複数リージョンに対応したことで、希少な ML 向けアクセラレーテッドキャパシティの確保が大幅に効率化されました。GPU / Trainium インスタンスの予約を検討しているチームは、コンソールの横断検索を活用して候補を一括比較することを推奨します。自動化が必要な場合は、DescribeCapacityBlockOfferings API による複数タイプ照会の活用も検討してください。
