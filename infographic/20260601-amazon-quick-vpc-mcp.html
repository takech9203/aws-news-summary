🔌 Amazon Quick - VPC 経由での MCP サーバー接続サポート

Amazon Quick VPC Connectivity MCP
2026-06-01

📋 概要

Amazon Quick が、プライベートネットワーク上でホストされている Model Context Protocol (MCP) サーバーへの Amazon VPC 経由の接続をサポートしました。企業が社内ネットワークで運用する MCP サーバーを、インターネットに公開することなく Quick の AI ワークフローに統合できるようになります。

Amazon Quick は AWS が提供する AI アシスタントであり、Slack、Microsoft Teams、CRM、データベースなど既存のツールやデータソースと連携して、質問への回答やアクションの実行を自然言語で行えるサービスです。

🔄 Before / After 比較

❌ Before

  • パブリックインターネット経由でアクセス可能なサードパーティサーバーに限定
  • プライベート MCP サーバーを接続するにはインターネットに公開が必要
  • セキュリティポリシーで公開不可の組織は MCP 機能を活用できなかった
  • 社内データソースや内部ツールへの AI アクセスが制限

✅ After

  • VPC 経由でプライベート MCP サーバーに直接接続が可能に
  • MCP サーバーをインターネットに公開せずに Quick と統合可能
  • EC2、Fargate、Agentcore などで稼働する MCP サーバーと安全に接続
  • コネクタ作成時に VPC 接続を選択するだけで簡単セットアップ

⚡ 主要機能

🔒 VPC 経由の MCP サーバー接続

  • プライベートネットワーク上の MCP サーバーに VPC を通じて安全に接続
  • インターネットへの公開が不要
  • MCP コネクタ作成時に VPC 接続を選択し、MCP サーバーの URL を指定するだけで設定完了

🖥️ 対応コンピューティング環境

  • Amazon EC2 インスタンス上で稼働する MCP サーバー
  • AWS Fargate で実行されるコンテナ化された MCP サーバー
  • AWS Agentcore で管理される MCP サーバー
  • その他のプライベートネットワーク内のコンピューティングリソース

💬 自然言語によるインタラクション

  • VPC 経由で接続されたプライベート MCP サーバーに対して自然言語で操作可能
  • 接続後はパブリック MCP サーバーと同様のユーザー体験を提供
  • チームメンバーが技術的な知識なしに社内ツールやデータにアクセス可能

📐 設定方法

前提条件

  • Amazon Quick のアカウントとサブスクリプションが有効であること
  • MCP サーバーが VPC 内のプライベートサブネットで稼働していること
  • VPC のセキュリティグループが Quick からの接続を許可していること
  • MCP サーバーの URL がプライベートネットワーク内で解決可能であること

Step 1: VPC 接続の準備

MCP サーバーが稼働するプライベートサブネットのセキュリティグループで、Amazon Quick からのインバウンドトラフィックを許可。MCP サーバーがリッスンするポートへのアクセスを設定。

Step 2: MCP コネクタの作成

Amazon Quick のコンソールから MCP コネクタを新規作成。コネクタ作成画面で接続タイプとして「VPC 接続」を選択。

Step 3: VPC 接続の設定

対象の VPC を選択し、MCP サーバーの内部 URL を入力。サブネットとセキュリティグループを指定して接続を確立。

Step 4: 接続の確認

設定完了後、Quick のインターフェースから自然言語でプライベート MCP サーバーへのアクセスをテスト。正常に応答が返ることを確認。

✅ メリット

💼 ビジネス面

  • セキュリティコンプライアンスの維持: 社内のセキュリティポリシーを遵守しながら AI ワークフローを活用
  • 社内データ活用の促進: プライベートデータソースや内部ツールを AI アシスタントから利用可能にし業務効率が向上
  • 既存インフラの活用: VPC 内で運用中の MCP サーバーをそのまま Quick に統合、追加インフラ変更不要

🔧 技術面

  • ゼロトラストアーキテクチャとの整合: MCP サーバーをインターネットに公開不要、VPC 内プライベート通信で完結
  • 柔軟なコンピューティング選択: EC2、Fargate、Agentcore など多様な環境に対応
  • 簡易なセットアップ: VPC 接続を選択して URL を指定するだけで設定完了

⚠️ 制限事項・考慮点

🚧 制限事項

  • VPC 内の MCP サーバーへのネットワーク到達性を事前に確保する必要がある
  • セキュリティグループやネットワーク ACL の設定が適切でないと接続に失敗する可能性がある
  • VPC ピアリングやトランジットゲートウェイを使用する場合、追加のネットワーク設定が必要になる場合がある

💡 考慮すべき点

  • VPC 接続に関連するデータ転送料金が発生する可能性がある
  • MCP サーバーの可用性は顧客側の責任で管理する必要がある
  • DNS 解決の設定が適切でない場合、プライベート URL の名前解決に失敗する可能性がある
