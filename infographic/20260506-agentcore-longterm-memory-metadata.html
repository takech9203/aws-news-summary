Amazon Bedrock AgentCore Memory

🧠 長期メモリのメタデータサポート

AI エージェントのメモリ検索精度を大幅に向上させるメタデータフィルタリング機能
2026-05-06

📋 概要

Amazon Bedrock AgentCore Memory に長期メモリレコードへのメタデータ付与機能が追加された。これにより、開発者はメモリエントリに構造化された属性を付加し、セマンティック検索に加えてメタデータベースのフィルタリングや検索を行うことが可能になる。

Before / After

Before
  • セマンティック検索のみに依存
  • 構造化属性での絞り込み不可
  • 関連性の低い結果が混在
  • メモリ分類の標準的仕組みなし
After
  • メタデータで正確なフィルタリング
  • ハイブリッド検索で高精度
  • LLM 自動抽出で手動負荷軽減
  • 構造的なメモリ管理が可能

🏗️ アーキテクチャ図

メモリリソースにメタデータスキーマを定義し、イベント取り込み時に LLM が自動でメタデータを抽出する。検索時はセマンティック検索とメタデータフィルタを組み合わせて精度の高い結果を取得する。

⚡ 主要機能

📋
メタデータスキーマ定義
メモリリソースに最大 10 個のインデックスキーを定義。STRING, NUMBER, STRING_LIST をサポートし、許可値バリデーションも設定可能。
🤖
LLM ベース自動メタデータ抽出
抽出指示を定義すると、会話コンテンツから LLM がメタデータを自動推論・付与。イベント取り込み時に自動処理される。
🔍
メタデータフィルタリング検索
セマンティック検索と併用可能なメタデータフィルタ。複数オペレーターによる柔軟な条件指定と複合条件検索をサポート。
📦
バッチ操作サポート
BatchCreateMemoryRecords でメタデータ付きレコードの一括作成、BatchUpdateMemoryRecords で既存レコードのメタデータ更新に対応。

🔧 技術仕様

メタデータ型と対応オペレーター

データ型 説明 対応オペレーター
STRING 文字列値 EQUALS_TO, EXISTS, NOT_EXISTS, CONTAINS
NUMBER 数値 EQUALS_TO, EXISTS, NOT_EXISTS, GREATER_THAN, GREATER_THAN_OR_EQUALS, LESS_THAN, LESS_THAN_OR_EQUALS
STRING_LIST 文字列リスト EQUALS_TO, EXISTS, NOT_EXISTS, CONTAINS
DATETIME タイムスタンプ ISO 8601 UTC BEFORE, AFTER

メタデータスキーマ構造

項目 詳細
最大インデックスキー数 メモリリソースあたり 10 個
キー定義要素 key, type, extractionConfig
バリデーション stringValidation, stringListValidation, numberValidation
抽出設定 llmExtractionConfig: definition, llmExtractionInstruction, validation

🛠️ 設定方法

前提条件

1. Amazon Bedrock AgentCore Memory が利用可能なリージョンの AWS アカウント
2. AgentCore Memory リソースが作成済みであること
3. 適切な IAM 権限 (bedrock-agentcore:CreateMemory, UpdateMemory, RetrieveMemoryRecords 等)

Step 1: メタデータスキーマ付きメモリリソースの作成

Python メモリリソース作成 
import boto3

client = boto3.client('bedrock-agentcore-control')

response = client.create_memory(
    name='customer-support-memory',
    description='カスタマーサポート用メモリ',
    indexedKeys=[
        {'key': 'ticket_number', 'type': 'STRING'},
        {'key': 'priority', 'type': 'STRING'},
        {'key': 'category', 'type': 'STRING_LIST'},
        {'key': 'score', 'type': 'NUMBER'}
    ],
    memoryStrategies={
        'semanticMemoryStrategy': {
            'memoryRecordSchema': {
                'metadataSchema': [
                    {
                        'key': 'priority',
                        'type': 'STRING',
                        'extractionConfig': {
                            'llmExtractionConfig': {
                                'definition': 'チケットの優先度レベル',
                                'llmExtractionInstruction': '会話から優先度を判断し、high/medium/low のいずれかを設定',
                                'validation': {
                                    'stringValidation': {
                                        'allowedValues': ['high', 'medium', 'low']
                                    }
                                }
                            }
                        }
                    }
                ]
            }
        }
    }
)

Step 2: メタデータ付きメモリレコードの作成

Python メモリレコード作成 
runtime_client = boto3.client('bedrock-agentcore')

response = runtime_client.batch_create_memory_records(
    memoryId='memory-id',
    records=[
        {
            'requestIdentifier': 'record-001',
            'namespaces': ['support', 'billing'],
            'content': {
                'text': 'ユーザーは請求に関する問題を報告。優先度高。'
            },
            'timestamp': '2026-05-06T10:00:00Z',
            'memoryStrategyId': 'strategy-id',
            'metadata': {
                'ticket_number': {'stringValue': 'TICKET-12345'},
                'priority': {'stringValue': 'high'},
                'category': {'stringListValue': ['billing', 'dispute']},
                'score': {'numberValue': 9.5}
            }
        }
    ]
)

Step 3: メタデータフィルタを使用した検索

Python メタデータフィルタリング検索 
response = runtime_client.retrieve_memory_records(
    memoryId='memory-id',
    searchCriteria={
        'searchQuery': '請求に関する問題',
        'memoryStrategyId': 'strategy-id',
        'topK': 5,
        'metadataFilters': [
            {
                'left': {'metadataKey': 'priority'},
                'operator': 'EQUALS_TO',
                'right': {'metadataValue': {'stringValue': 'high'}}
            },
            {
                'left': {'metadataKey': 'category'},
                'operator': 'CONTAINS',
                'right': {'metadataValue': {'stringListValue': ['billing']}}
            }
        ]
    }
)

⚖️ メリット・デメリット

✅ メリット

✓ 応答精度の向上: メタデータフィルタにより無関係なコンテキストを排除
✓ 運用効率の改善: チケット番号や優先度での正確なメモリ検索
✓ スケーラブルなメモリ管理: 大量レコードの構造的な分類・管理
✓ ハイブリッド検索: セマンティック + メタデータフィルタの両立
✓ 自動メタデータ抽出: LLM ベースで手動付与の負荷を大幅削減
✓ 型安全なフィルタリング: 型定義とバリデーションでデータ一貫性保証

⚠️ 制限・考慮事項

! インデックスキーはメモリリソースあたり最大 10 個
! データ型は 3 種類のみ (DATETIME は検索フィルタで対応)
! LLM 自動抽出の精度は抽出指示の品質に依存
! スキーマ変更は既存レコードに影響する可能性あり
! LLM 自動抽出は処理時間とコストが増加する可能性
! 複雑なフィルタ条件が検索パフォーマンスに影響

💡 ユースケース

🎧 カスタマーサポートエージェント
顧客からの問い合わせに対応するエージェントが、過去のチケット履歴をメタデータ (customer_id, priority) で効率的に検索。特定顧客の高優先度チケットのみを正確に取得。
効果: 特定顧客の重要な問い合わせ履歴のみを正確に取得し、コンテキストに基づいた的確な対応が可能に
📊 プロジェクト管理アシスタント
複数プロジェクトを横断して進捗状況や決定事項を管理するエージェントが、プロジェクト名・期間のメタデータフィルタで検索。AFTER オペレーターで直近の決定事項のみを取得。
効果: メタデータフィルタにより他プロジェクトのノイズを排除し、関連する決定事項のみを正確に取得
🎯 パーソナライズドレコメンデーション
ユーザーの過去の行動や好みを記憶し、interest_score (GREATER_THAN_OR_EQUALS) とカテゴリ (CONTAINS) でフィルタ。高スコアの特定カテゴリの好みを検索。
効果: ユーザーの強い関心を示す高スコアレコードを特定カテゴリで絞り込み、精度の高いレコメンデーションを実現
