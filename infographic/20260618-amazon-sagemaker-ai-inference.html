新しいオブザーバビリティ機能

SageMaker AI Insights ダッシュボードで生成 AI 推論を可視化

📅 2026 年 6 月 18 日

📌 概要

Amazon SageMaker AI が、推論エンドポイント向けの新しいオブザーバビリティ機能を発表しました。本番環境で稼働する生成 AI ワークロードのパフォーマンスを可視化し、問題の特定と解決にかかる時間を大幅に短縮します。

中核となるのは、Amazon CloudWatch に組み込まれた事前構築済みの SageMaker AI Insights ダッシュボードです。トークンレイテンシー、GPU 使用率、推論コンポーネントのコピー数、スケーリングイベント、コールドスタートの内訳を 1 つのビューに集約します。メトリクスは OpenTelemetry ネイティブメトリクスとして自動公開されるため、ユーザー側の計装 (インストルメンテーション) は不要です。

🔄 アップデート前後の比較

❌ Before (従来)
  • CloudWatch の複数メトリクスを手動で探し回る必要があった
  • レイテンシー問題とハードウェア状態を手動で相関させ、原因特定に数時間を要した
  • TTFT やトークン間レイテンシーなど生成 AI 特有の指標を統合把握する手段が限られていた
➜
✅ After (改善後)
  • 生成 AI 特有のメトリクスとインフラ健全性を 1 つのダッシュボードで統合把握
  • 計装なしで OpenTelemetry ネイティブメトリクスを自動取得
  • 問題の特定と解決が数時間から数分に短縮

推論エンドポイントが OpenTelemetry ネイティブメトリクスを自動公開し、CloudWatch のダッシュボードまたは PromQL 経由の Grafana で可視化する流れ

⚡ 主要機能

📊 生成 AI 向けパフォーマンスメトリクスのリアルタイム追跡
  • Time to First Token (TTFT) を追跡し、最初のトークンが返るまでの遅延を把握
  • トークン間レイテンシー、キュー深度、1 秒あたりのトークン数を可視化
  • これらの指標をインフラストラクチャの健全性とあわせて表示
📈 SageMaker AI Insights ダッシュボード (CloudWatch)
  • トークンレイテンシー、GPU 使用率、推論コンポーネントのコピー数を 1 つのビューに集約
  • スケーリングイベントとコールドスタートの内訳を確認
  • OpenTelemetry ネイティブメトリクスが自動公開され、計装は不要
📉 Grafana 連携
  • リージョン別の PromQL エンドポイントを使用して Grafana と連携
  • インポート可能な事前構成済みダッシュボードテンプレートを提供
  • CloudWatch 以外の監視ツールを利用するチームにも対応

🔧 技術仕様

追跡される主要メトリクス

項目詳細
Time to First Token (TTFT)リクエストから最初のトークンが返されるまでの時間
トークン間レイテンシートークンとトークンの間の生成遅延
キュー深度処理待ちリクエストの滞留状況
1 秒あたりのトークン数スループットを示すトークン生成速度
GPU 使用率推論コンポーネントの GPU リソース使用状況
推論コンポーネントのコピー数スケーリングの状態
コールドスタートの内訳起動時のレイテンシー要因の分解

API 変更履歴

2026/06/16 api.sagemaker — 21 updated api methods。Endpoint の MetricsConfig に EnableDetailedObservability を追加。GPU、ホスト、フレームワークネイティブの推論メトリクスを、推論コンポーネント別・アベイラビリティーゾーン別・インスタンス別のディメンションで CloudWatch に公開。推論コンポーネントのプロビジョニングライフサイクルとマルチ AZ 配置メトリクスを追加。

設定例

JSON EndpointConfig の MetricsConfig 
{
  "EndpointConfigName": "my-genai-endpoint-config",
  "MetricsConfig": {
    "EnableDetailedObservability": true
  }
}

MetricsConfig の EnableDetailedObservability を有効化することで、詳細なオブザーバビリティメトリクスが CloudWatch に自動公開されます。

⚙️ 設定方法

前提条件

✓SageMaker AI の推論エンドポイントが利用可能なリージョンにあること
✓CloudWatch にアクセスできる IAM 権限があること
✓Grafana 連携を利用する場合は、Amazon Managed Grafana または既存の Grafana 環境があること

ステップ 1: エンドポイント構成でオブザーバビリティを有効化

Bash AWS CLI 
aws sagemaker create-endpoint-config \
  --endpoint-config-name my-genai-endpoint-config \
  --metrics-config EnableDetailedObservability=true \
  --production-variants '[{...}]'

GPU・ホスト・フレームワークネイティブの推論メトリクスを CloudWatch へ自動公開するよう設定します。

ステップ 2: SageMaker AI Insights ダッシュボードを確認

CloudWatch コンソールから事前構築済みの SageMaker AI Insights ダッシュボードを選択。トークンレイテンシー、GPU 使用率、スケーリングイベント、コールドスタートの内訳を 1 つのビューで確認できます。追加の計装は不要です。

ステップ 3: Grafana 連携を構成 (任意)

CloudWatch 以外の監視ツールを利用している場合は、リージョン別の PromQL エンドポイントを Grafana のデータソースとして登録し、事前構成済みダッシュボードテンプレートをインポートして既存の運用ダッシュボードに統合します。

🎯 ユースケース

1. TTFT の悪化要因の特定
シナリオ: 生成 AI チャットアプリで、応答の初動が遅いという報告が増加。
実装: ダッシュボードで TTFT、キュー深度、GPU 使用率を同時に確認。
効果: TTFT 悪化がキュー滞留か GPU リソース不足かを即座に切り分け、適切な対策を打てる。
2. オートスケーリングポリシーの最適化
シナリオ: トラフィック変動が大きい本番エンドポイントで、コールドスタート遅延が断続的に発生。
実装: スケーリングイベントとコールドスタートの内訳、コピー数を分析。
効果: スケーリングのしきい値とウォームプール設定を見直し、コールドスタートの影響を最小化。
3. アベイラビリティーゾーンのコンプライアンス確認
シナリオ: 規制要件により、推論ワークロードが特定の AZ に配置されていることを継続確認する必要がある。
実装: AZ 別ディメンションのメトリクスとマルチ AZ 配置メトリクスを確認。
効果: ワークロードの配置状況を可視化し、AZ 配置に関するコンプライアンスを継続確認。

📝 まとめ

本アップデートは、本番環境の生成 AI 推論ワークロードの運用を大きく改善する重要な機能です。計装不要で TTFT などの生成 AI 特有のメトリクスとインフラ健全性を統合的に可視化でき、問題解決時間を数時間から数分へ短縮します。東京リージョンでも利用できるため、推論エンドポイントを運用しているチームは、まず EnableDetailedObservability を有効化し、SageMaker AI Insights ダッシュボードでの運用を検討することを推奨します。
