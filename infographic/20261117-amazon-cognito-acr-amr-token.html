Amazon Cognito

🔐 認証レベル ACR と認証方式 AMR の
トークンクレームをサポート

📅 リリース日: 2026 年 11 月 17 日 | 認証コンテキストクラス参照 (ACR) / 認証方式参照 (AMR)

📝 概要

Amazon Cognito が発行するアクセストークン、ID トークン、リフレッシュトークンに、 OpenID Connect Core 仕様準拠の acr (認証レベル) と amr (完了した認証方式の一覧) クレームが追加されました。 パスワードのみのレベル 1 から、パスワード + 認証アプリ TOTP のレベル 4 まで、 4 段階の固定された認証レベルを定義します。

アプリケーションは acr を参照して機密操作の前に追加ファクターを要求する ステップアップ認証を実装でき、 amr は監査・コンプライアンスの証跡として活用できます。 ACR レベルの URI 名はユーザープールごとにカスタマイズ可能で、OIDC フェデレーションユーザーの ACR / AMR 値のマッピングにも対応します。

❌ Before: アップデート前の課題
▪トークンに認証強度を示す標準クレームがなく、MFA 完了状況を独自に追跡する仕組みが必要
▪機密操作前のステップアップ認証をカスタム実装で作り込む必要があった
▪「どの認証方式を完了したか」を証明する標準的な手段がなかった
✅ After: アップデート後の改善
✓acr / amr クレームを参照するだけで認証レベルと完了方式を確認可能
✓acr_values / TARGET_ACR_VALUES でステップアップ認証をネイティブに実装
✓OIDC フェデレーションユーザーも IdP の値をマッピングして一貫した認可判断が可能

🏗️ ステップアップ認証のフロー

sequenceDiagram
    participant U as 👤 ユーザー
    participant A as 💻 アプリケーション
    participant C as 🔐 Amazon Cognito

    U->>A: 機密性の高い操作をリクエスト
    A->>A: ID トークンの acr と auth_time を確認
    alt 必要なレベルを満たしている
        A-->>U: 操作を許可
    else ステップアップが必要
        A->>C: acr_values で目標レベルを指定して認可リクエスト
        C->>U: 追加の認証ファクターを要求 例 TOTP
        U->>C: 追加ファクターの認証を完了
        C-->>A: acr と amr を更新した新しいトークンを発行
        A->>A: acr クレームを検証
        A-->>U: 操作を許可
    end

アプリケーションは現在のトークンの acr レベルと auth_time を確認し、不足している場合のみ Amazon Cognito に目標レベルを指定して再認証を要求します。

⚙️ 主要機能

1️⃣ acr クレームによる認証レベルの通知

ユーザーが満たした認証レベルを示す文字列 (例: urn:cognito:loa:3) をトークンに付与。完了したファクターの組み合わせが完全に満たす最高レベルを割り当て、初回サインインを含むすべてのサインインに適用されます。

2️⃣ amr クレームによる完了済み認証方式の記録

完了した認証方式の文字列配列 (例: ["pwd", "otp", "mfa"]) をトークンに付与。2 つ以上の異なるファクターを完了すると mfa 値が追加され、監査・コンプライアンス用途に活用できます。

3️⃣ 目標認証レベルのリクエスト (ステップアップ認証)

マネージドログインでは acr_values、USER_AUTH API フローでは TARGET_ACR_VALUES を使用。オプションの max_age で直近の認証からの経過時間も要求可能。必要なファクター完了後、更新されたクレームを持つ新しいトークン一式を発行します。

4️⃣ ACR レベル URI のカスタマイズ

CreateUserPool / UpdateUserPool の AcrConfiguration で各レベルの URI 名をユーザープールごとにカスタマイズ可能。ファクターの組み合わせ自体は固定で、変更できるのは名前のみです。

5️⃣ OIDC フェデレーションユーザーのマッピング

IdP が返す ACR / AMR 値を AcrMapping で設定済みレベルへマッピング。ACR / AMR 非対応の IdP 経由ではプレースホルダーとして fed 値を付与します。

🔄 トークン更新時の動作

項目詳細
トークンリフレッシュ新しいアクセストークンと ID トークンに同じ acr / amr 値を引き継ぐ (リフレッシュのたびにステップアップを再要求しない)
auth_timeトークンリフレッシュではリセットされない。一定時間後の再認証を強制したい場合は max_age を使用
ステップアップ完了時更新されたクレームと新しい有効期間を持つアクセストークン、ID トークン、リフレッシュトークンを発行
Lambda トリガーacr / amr クレームは事前トークン生成 Lambda トリガーなどで上書き・追加・抑制できない
ホスト UI (クラシック)acr_values / max_age は無視され、ローカルユーザーの acr は MFA 完了時でもレベル 1 になる。正確なレベルにはマネージドログインが必要

🛠️ 設定方法

✅ 前提条件

✓Amazon Cognito ユーザープールが作成済みであること
✓ステップアップ認証を使用する場合、ドメインのブランディングバージョンがマネージドログインに設定されていること (ホスト UI クラシックは非対応)
✓目標レベルのリクエストとカスタム ACR 名の設定には Essentials または Plus 機能プランが必要
1
ACR レベル名のカスタマイズ (オプション)
Bash AWS CLI - UpdateUserPool 
aws cognito-idp update-user-pool \
  --user-pool-id us-east-1_ExAmPlE \
  --user-pool-add-ons AdvancedSecurityMode=ENFORCED \
  --cli-input-json '{
    "AcrConfiguration": {
      "Level2": { "AcrValue": "urn:my-standard:loa:2" },
      "Level3": { "AcrValue": "urn:my-standard:loa:3" }
    }
  }'

AcrConfiguration でカスタマイズしたいレベルの URI 名のみを上書きします。各 AcrValue は 1 ～ 64 文字で、4 レベル全体 (未カスタマイズのデフォルト名を含む) で一意である必要があります。

2
マネージドログインで目標レベルをリクエスト
Text authorize エンドポイント 
https://<ドメイン>.auth.us-east-1.amazoncognito.com/oauth2/authorize?
  client_id=<クライアント ID>&
  response_type=code&
  redirect_uri=<リダイレクト URI>&
  acr_values=urn:cognito:loa:4&
  max_age=300

acr_values で目標認証レベルを指定します。max_age を併用すると、直近 300 秒以内に認証したことも要求できます。レベルが不足している場合、Amazon Cognito は必要なファクターの完了をユーザーに求めます。

3
USER_AUTH API フローで目標レベルをリクエスト
Bash AWS CLI - InitiateAuth 
aws cognito-idp initiate-auth \
  --client-id <クライアント ID> \
  --auth-flow USER_AUTH \
  --auth-parameters USERNAME=<ユーザー名>,TARGET_ACR_VALUES=urn:cognito:loa:4,MAX_AGE=300

SDK / API ベースのサインインでは TARGET_ACR_VALUES と MAX_AGE を指定します。機能プランが不足している場合、InitiateAuth は FeatureUnavailableInTierException を返します (マネージドログインの authorize エンドポイントはエラーを返さず acr_values を無視します)。

4
アプリケーションで acr クレームを検証

トークン発行後、アプリケーションは操作が要求するレベルと acr クレームが一致することを必ず検証します。Amazon Cognito は到達したレベルでトークンを発行するだけであり、操作ごとのレベル要求の強制はアプリケーションの責任です。

💡 メリット

💼 ビジネス面

✓コンプライアンス対応の強化: amr により完了した認証方式を標準形式で記録でき、監査証跡の要件に対応しやすい
✓リスクベースのセキュリティ: 送金や設定変更などの機密操作にのみ強い認証を要求でき、セキュリティと利便性を両立
✓開発コストの削減: ステップアップ認証のカスタム実装が不要になり、標準クレームベースの実装に集約

🔧 技術面

✓OpenID Connect 標準準拠: OIDC Core 仕様のクレームであり、既存の OIDC 対応ライブラリやツールと親和性が高い
✓トークンリフレッシュでの引き継ぎ: リフレッシュ時に同じ値が維持され、不要な再認証を求めない
✓フェデレーションの一貫性: OIDC IdP の値をマッピングでき、ローカル / フェデレーションユーザーで統一した認可ロジックを実装可能

⚠️ デメリット・制約事項

🚧 制限事項

✗各 ACR レベルを満たすファクターの組み合わせは固定であり、変更できるのは URI 名のみ
✗acr / amr は事前トークン生成 Lambda トリガーなどでカスタマイズ・上書き・抑制できない
✗ステップアップ認証はマネージドログインが必要で、ホスト UI (クラシック) では acr_values / max_age が無視される
✗目標レベルのリクエストとカスタム ACR 名の設定には Essentials または Plus 機能プランが必要
✗段階的にロールアウト中であり、ユーザープールによってはまだ利用できない場合がある

🤔 考慮すべき点

⚠acr の検証と操作ごとのレベル強制はアプリケーションの責任であり、Amazon Cognito は到達レベルを報告するのみ
⚠NIST や eIDAS など他の標準への変換が必要な場合は、アプリケーション層でレベルを翻訳する必要がある
⚠ACR レベル名を変更すると、古い名前を持つ既存トークンは「認識されないレベル」として扱われる (エラーにはならず、amr の値に基づいて不足ファクターのみ要求される)
⚠SAML フェデレーションユーザーはホスト UI (クラシック) では acr がレベル 1、amr が ["fed"] になる

🎯 ユースケース

💸 ユースケース 1: 送金操作前のステップアップ認証

シナリオ: 金融アプリケーションで、残高照会はパスワード認証のみで許可するが、送金操作にはパスワード + TOTP (レベル 4) を要求したい。

Text実装例
1. 送金リクエスト時に ID トークンの acr を確認
2. acr が urn:cognito:loa:4 未満の場合、authorize エンドポイントへリダイレクト
   acr_values=urn:cognito:loa:4 を指定
3. ユーザーが TOTP を完了すると新しいトークンが発行される
4. アプリケーションで acr クレームを再検証して送金を実行
✅ 効果: 日常操作の利便性を損なわずに、機密操作にのみ強い認証を強制できる。
📋 ユースケース 2: 監査・コンプライアンスでの認証方式の証明

シナリオ: 規制対象の業務システムで、管理者操作の実行時に MFA が完了していたことを監査ログに記録する必要がある。

Text実装例
1. 操作実行時にアクセストークンの amr クレームを取得
2. ["pwd", "otp", "mfa"] のような完了済み認証方式を監査ログに記録
3. 監査時に「操作時点で TOTP による MFA が完了していた」ことを証明
✅ 効果: 認証方式の証跡を標準クレームとして取得でき、独自の MFA 追跡の仕組みが不要になる。
🌐 ユースケース 3: OIDC フェデレーション環境での統一的な認可

シナリオ: 社内 IdP (OIDC) と Amazon Cognito ローカルユーザーが混在する環境で、両者に同じ認可ポリシーを適用したい。

Text実装例
1. OIDC IdP の設定で AcrMapping を構成し、IdP の ACR 値を
   ユーザープールのレベルにマッピング
2. アプリケーションは acr クレームのみを参照して認可判断
3. ローカルユーザーもフェデレーションユーザーも同一ロジックで処理
✅ 効果: 認証経路の違いを意識せず、トークンクレームベースの一貫した認可を実装できる。

💰 料金・利用可能リージョン

💵 料金

acr / amr クレームの付与自体は、機能プランにかかわらずすべてのユーザープールに追加料金なしで含まれます。

ただし、以下の機能には Essentials または Plus 機能プランが必要です。

  • 目標認証レベルのリクエスト (TARGET_ACR_VALUES / acr_values によるステップアップ認証)
  • AcrConfiguration によるカスタム ACR レベル名の設定

機能プランの料金は月間アクティブユーザー (MAU) 数に基づきます。詳細は 料金ページ を参照してください。

🌍 利用可能リージョン

Amazon Cognito が提供されているすべての AWS リージョンで利用可能です。

⚠ 本機能は段階的にロールアウト中のため、ユーザープールによっては利用可能になるまで時間がかかる場合があります。
