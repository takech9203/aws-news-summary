AWS Security Agent

Full Repository Code Review

AI 駆動のリポジトリ全体コードレビュー機能

2026-05-12

📋 概要

AWS Security Agent に Full Repository Code Review 機能が追加された。コードベース全体に対してコンテキストを考慮したディープセキュリティ分析を実行し、従来のパターンマッチングベースの静的解析ツールでは検出できないシステミックな脆弱性を発見する。

脆弱性検出時には具体的なファイルと行番号に紐付いたコード修正案を自動生成し、セキュリティ脆弱性の特定から修正までを大幅に高速化する。プレビュー期間中は追加料金なしで提供される。

Before

  • 既知の脆弱性パターンとのマッチングに依存
  • アプリケーション固有のアーキテクチャに起因するシステミックな脆弱性を検出できなかった
  • 信頼境界をまたぐデータフローの問題発見が困難
  • 修正案が抽象的で開発者が具体的な修正コードを自分で考える必要があった

After

  • AI 駆動のコンテキスト認識型セキュリティ分析
  • アーキテクチャ、信頼境界、データフローを理解した分析
  • パターンマッチでは不可能だったシステミック脆弱性の検出
  • ファイル名と行番号に紐付いた修正コードを自動生成

⚡ 主要機能

🧠 コンテキスト認識型セキュリティ分析

  • アプリケーションのアーキテクチャ全体を理解した上で分析を実施
  • 信頼境界 (Trust Boundaries) の特定と検証
  • データフローの追跡によるシステミック脆弱性の検出
  • 複数ファイルにまたがる脆弱性パターンの検出

🔧 自動コード修正 (Code Remediation)

  • 脆弱性に対する具体的な修正コードの自動生成
  • ファイル名と行番号を指定した正確な修正箇所の特定
  • 修正戦略の選択: AUTOMATIC または DISABLED
  • StartCodeRemediation API による修正の実行

🔄 多段階分析パイプライン

  • PREFLIGHT: 事前チェックとソースコードの検証
  • STATIC_ANALYSIS: コンテキスト認識型の静的解析
  • PENTEST: 侵入テスト観点でのセキュリティ検証
  • FINALIZING: 結果の集約と修正案の生成

🔗 リポジトリ統合

  • ソースコードリポジトリとの直接連携
  • S3 経由でのソースコード提供
  • 複数リポジトリの一括分析対応

🛠️ 設定方法

前提条件

  • AWS Security Agent が有効化された AWS アカウント
  • Agent Space が作成済みであること
  • ソースコードへのアクセス権限 (S3 またはリポジトリ連携)
  • IAM サービスロールの作成

ステップ 1: IAM サービスロールの作成

Bash サービスロール作成 
aws iam create-role \
  --role-name SecurityAgentCodeReviewRole \
  --assume-role-policy-document '{
    "Version": "2012-10-17",
    "Statement": [
      {
        "Effect": "Allow",
        "Principal": {
          "Service": "security-agent.amazonaws.com"
        },
        "Action": "sts:AssumeRole"
      }
    ]
  }'

ステップ 2: コードレビューの作成

Bash コードレビュー作成 
aws security-agent create-code-review \
  --title "Full Repository Security Review" \
  --agent-space-id "your-agent-space-id" \
  --assets '{
    "sourceCode": [
      {"s3Location": "s3://your-bucket/source-code.zip"}
    ]
  }' \
  --service-role "arn:aws:iam::123456789012:role/SecurityAgentCodeReviewRole" \
  --log-config '{
    "logGroup": "/aws/security-agent/code-review",
    "logStream": "my-review"
  }' \
  --code-remediation-strategy "AUTOMATIC"

ステップ 3: ジョブの実行

Bash レビュージョブ開始 
aws security-agent start-code-review-job \
  --agent-space-id "your-agent-space-id" \
  --code-review-id "your-code-review-id"

ステップ 4: 結果の確認

Bash 検出結果の取得 
aws security-agent list-findings \
  --agent-space-id "your-agent-space-id" \
  --code-review-job-id "your-job-id"

✅ メリット

💼 ビジネス面

  • セキュリティリスクの早期発見: リリース前にシステミックな脆弱性を検出し、インシデントを未然に防止
  • 修正コストの削減: 脆弱性の発見から修正案の生成までが自動化
  • コンプライアンス対応の強化: CloudWatch Logs で実行証跡を管理可能

🔬 技術面

  • コンテキスト認識型分析: アプリケーション全体の構造を理解した分析
  • 26 種類以上のリスクタイプ: SQL インジェクションから SSRF まで幅広く検出
  • API による自動化: CI/CD パイプラインへの組み込みが容易
  • 具体的な修正コード生成: ファイル名と行番号に紐付いた修正案

⚠️ デメリット・制約事項

制限事項

  • プレビュー段階の機能であり、GA までに仕様変更の可能性がある
  • AI 駆動の分析であるため、誤検知 (False Positive) が発生する可能性がある
  • 大規模リポジトリの場合、分析に時間がかかる可能性がある
  • 自動生成された修正コードは必ず人間のレビューが必要

考慮すべき点

  • ソースコードを AWS に送信するため、機密コードの取り扱いポリシーとの整合性確認が必要
  • 既存のセキュリティツール (SAST/DAST) との役割分担と使い分けの整理が必要
  • 修正コードの自動適用 (AUTOMATIC) を有効にする場合のガバナンス体制の検討

🎯 ユースケース

1. リリース前セキュリティゲート

マイクロサービスアーキテクチャのアプリケーションで、リリース前に全リポジトリのセキュリティレビューを自動実行。CI/CD パイプラインに組み込み、デプロイ前にシステミックな脆弱性を自動検出し、修正案とともにチームに通知する。

2. レガシーコードのセキュリティ監査

長期運用されているモノリシックアプリケーションのセキュリティ状態を把握。データフローと信頼境界の分析により、長年見過ごされてきたシステミックな脆弱性を発見し、修正の優先順位付けに活用する。

3. サードパーティコードの受入検査

外部ベンダーから納品されたコードのセキュリティ品質を検証。納品コードに含まれる脆弱性を客観的に評価し、ベンダーへの修正依頼を具体的な根拠とともに行える。
