パブリック DNS フォールバック対応

Advanced Hosted Zones の新機能で、スプリットホライズン DNS の運用がシンプルに

📅 リリース日: 2026 年 11 月 20 日
機能: パブリック DNS フォールバック
Advanced Hosted Zones

📋 概要

Amazon Route 53 のプライベートホストゾーンが、パブリック DNS へのフォールバックをサポートしました。 これまでプライベートホストゾーンはドメイン全体に対して完全に権威を持ち、ゾーン内に一致するレコードがない問い合わせには NXDOMAIN が返されていました。本アップデートにより、一致するレコードがない場合に パブリック DNS からの回答を返すことが可能になります。

本機能は同時期に発表された Advanced Hosted Zones の一機能として提供されます。 一部の名前だけをプライベートに解決したい場合に、パブリックゾーンのレコード全体を複製して同期を維持する必要がなくなり、 ハイブリッド構成やスプリットホライズン DNS (内部と外部で異なる回答を返す構成) の運用負荷が大幅に軽減されます。

❌ Before: アップデート前の課題
✗ゾーン内に存在しない名前は NXDOMAIN となり、パブリック DNS のレコードを解決できない
✗一部の名前だけ上書きしたくても、パブリックゾーンの全レコードをプライベートゾーンに複製する必要があった
✗複製レコードの継続的な同期が必要で、運用負荷と設定ミスのリスクが発生
✅ After: アップデート後の改善
✓一致するレコードがない場合、NXDOMAIN ではなくパブリック DNS からの回答を返せる
✓プライベートに解決したい名前だけを登録すればよく、それ以外はパブリック DNS で解決
✓レコードの複製・同期作業が不要になり、DNS 構成の管理がシンプルに

VPC 内のクライアントからの DNS 問い合わせに対し、プライベートホストゾーンに一致するレコードがない場合の解決フローです。 フォールバックが有効な場合はパブリック DNS からの回答が返され、無効な場合は従来どおり NXDOMAIN が返されます。

⚡ 主要機能

1️⃣ パブリック DNS フォールバック

プライベートホストゾーンのドメイン配下の名前への問い合わせで、一致するレコードがゾーン内に存在しない場合、パブリック DNS からの回答を返します。 例: example.com をプライベートエンドポイントに向けつつ、パブリック DNS にのみ存在する partner.example.com も解決できます。

2️⃣ Advanced Hosted Zones の一機能として提供

新規にプライベートの Advanced Hosted Zone を作成するか、既存のプライベートホストゾーンをアップグレードした上でフォールバックを有効化します。

3️⃣ 多様な設定インターフェイス

Route 53 コンソール、API、AWS CLI、AWS SDK、AWS CloudFormation から設定可能。 API では UpdateHostedZoneFeatures の EnablePublicDNSFallback パラメータなどで制御します。

🔧 技術仕様

📊 解決動作の比較

問い合わせ対象 従来の動作 フォールバック有効時の動作
プライベートホストゾーンにレコードあり プライベートレコードで回答 プライベートレコードで回答 (変更なし)
ゾーン内にレコードなし、パブリック DNS にあり NXDOMAIN パブリック DNS の回答を返す
ゾーン内にもパブリック DNS にもレコードなし NXDOMAIN NXDOMAIN

🔄 API 変更履歴 (2026/11/20)

Amazon Route 53 に 4 new 8 updated api methods - Advanced Hosted Zones のサポート。 パブリック DNS フォールバック、変更ガードレール、変更履歴などを含みます。

  • CreateHostedZone: HostedZoneConfig に HostedZoneTier (STANDARD | ADVANCED) と EnablePublicDNSFallback パラメータが追加
  • UpdateHostedZoneFeatures: EnablePublicDNSFallback と DryRun パラメータによるフォールバックの有効化・無効化
  • UpdateHostedZoneTier: 既存ホストゾーンの Advanced Hosted Zone へのアップグレード
  • GetHostedZone / ListHostedZones: ホストゾーンのティアやフォールバック設定の参照

🐍 設定例 (boto3)

Python 既存のプライベートホストゾーンでパブリック DNS フォールバックを有効化 
# 既存のプライベートホストゾーンでパブリック DNS フォールバックを有効化
client.update_hosted_zone_features(
    HostedZoneId='Z1234567890ABC',
    EnablePublicDNSFallback=True
)

🛠️ 設定方法

✅ 前提条件

  • Route 53 のプライベートホストゾーンが作成済み、または新規作成すること
  • 対象ホストゾーンが Advanced Hosted Zone であること (既存ゾーンはアップグレードが必要)
  • ホストゾーンの設定変更に必要な IAM 権限を持っていること
1
プライベートの Advanced Hosted Zone を用意する
BashAWS CLI
# 既存のプライベートホストゾーンを Advanced Hosted Zone にアップグレード
aws route53 update-hosted-zone-tier \
  --hosted-zone-id Z1234567890ABC \
  --hosted-zone-tier ADVANCED

新規作成の場合は、ホストゾーン作成時にティアとして ADVANCED を指定します。

2
パブリック DNS フォールバックを有効化する
BashAWS CLI
# パブリック DNS フォールバックを有効化
aws route53 update-hosted-zone-features \
  --hosted-zone-id Z1234567890ABC \
  --enable-public-dns-fallback

Route 53 コンソールや CloudFormation からも設定できます。

3
名前解決の動作を確認する
BashVPC 内のインスタンスから確認
# VPC 内のインスタンスからプライベートに存在しない名前を問い合わせ
dig partner.example.com

プライベートホストゾーンに存在せずパブリック DNS にのみ存在する名前が、NXDOMAIN ではなくパブリック DNS の回答で返ることを確認します。

💡 メリット

💼 ビジネス面
✓運用コストの削減: レコードの複製・同期作業が不要になり、DNS 運用の工数を削減
✓障害リスクの低減: 同期漏れによる名前解決の失敗や設定ミスのリスクを排除
✓導入の迅速化: 一部の名前だけをプライベート化したい要件に最小限の設定変更で対応
⚙️ 技術面
✓スプリットホライズン DNS の簡素化: 上書きしたい名前だけを登録すればよく、構成がシンプルに
✓パブリック DNS との一貫性: パブリック側の変更が自動反映され、常に最新の情報と一致
✓柔軟な制御: ゾーン単位で有効・無効を切り替え可能。API の DryRun による事前確認も可能

⚠️ デメリット・制約事項

🚧 制限事項

  • Advanced Hosted Zones の機能として提供されるため、Standard のプライベートホストゾーンでは利用できない (アップグレードが必要)
  • プライベートホストゾーンが利用可能な AWS 商用リージョンでの提供であり、それ以外のリージョンでは利用できない

🤔 考慮すべき点

!有効化すると、これまで NXDOMAIN となっていた名前がパブリック DNS で解決されるようになるため、意図しない名前解決が発生しないか事前に影響範囲を確認する必要がある
!内部からの解決を明示的に遮断したい名前がある場合は、プライベートホストゾーンにレコードを登録して制御する設計が必要
!Advanced Hosted Zones の料金体系が適用されるため、コストへの影響を事前に確認することを推奨

🎯 ユースケース

1. ハイブリッド環境でのスプリットホライズン DNS

シナリオ: example.com のうち、社内システムのエンドポイントだけを VPC 内でプライベート IP に解決し、その他のサブドメインはパブリック DNS の回答をそのまま利用したい。

実装例: example.com のプライベート Advanced Hosted Zone を作成し VPC に関連付け → internal.example.com など内部向けレコードのみ登録 → パブリック DNS フォールバックを有効化

効果: 内部向けの名前はプライベートに解決しつつ、www.example.com などパブリックのみに存在する名前も VPC 内から問題なく解決できる。

2. SaaS やパートナーサービスとの連携

シナリオ: 自社ドメイン配下の partner.example.com がパートナー企業によりパブリック DNS で管理されており、VPC 内のアプリケーションからもアクセスする必要がある。

実装例: example.com のプライベートホストゾーンでフォールバックを有効化 → partner.example.com はプライベートホストゾーンに登録しない → VPC 内からの問い合わせはパブリック DNS の回答で解決

効果: パートナー側のレコード変更を複製・追従する必要がなく、常に最新のパブリック DNS の回答が利用される。

3. 既存プライベートホストゾーンの運用簡素化

シナリオ: パブリックゾーンのレコードをプライベートゾーンへ複製して同期するバッチ処理を運用しており、同期漏れによる障害が課題になっている。

実装例: 既存ゾーンを Advanced Hosted Zone にアップグレード → フォールバックを有効化 → プライベートに上書きが必要なレコード以外を削除 → 同期バッチ処理を廃止

効果: 同期の仕組み自体が不要になり、運用負荷と障害リスクを大幅に削減できる。

📝 まとめ

Route 53 プライベートホストゾーンのパブリック DNS フォールバック対応により、一部の名前だけをプライベートに解決する スプリットホライズン構成が、レコードの複製や同期なしで実現できるようになりました。

✓パブリックゾーンのレコードを複製・同期する運用を行っている場合は、Advanced Hosted Zone へのアップグレードと本機能の有効化を検討することを推奨
!有効化の際は、これまで NXDOMAIN となっていた名前の解決動作が変わるため、影響範囲の事前確認を忘れずに実施
