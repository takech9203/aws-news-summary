AWS Lambda Managed Instances
マネージドリソースへのタグ伝播 🏷️

リリース日
2026 年 6 月 15 日

📌 概要

AWS Lambda Managed Instances (LMI) が タグ伝播 (Tag Propagation) に対応しました。 LMI がプロビジョニングするマネージドリソース (Amazon EC2 インスタンス、Amazon EBS ボリューム、Amazon ENI) に対して、 キャパシティプロバイダーで指定したタグを自動的に適用できるようになりました。

LMI は、マネージド型の EC2 インスタンス上で Lambda 関数を実行できる機能です。組み込みのルーティング、ロードバランシング、 オートスケーリングを備え、運用負荷なしで特化型コンピューティング構成を利用できます。 これまで裏側で作成されるリソースにはタグを伝播する手段がなく、コスト配分やガバナンスの観点で課題がありました。

❌ アップデート前の課題
  • マネージドリソース (EC2 / EBS / ENI) にタグを伝播する手段がなかった
  • タグ依存のコスト配分・可視化がマネージドリソースで機能しなかった
  • タグ条件を用いた SCP やコンプライアンス制御を一貫適用できなかった
✅ アップデート後の改善
  • 指定したタグが作成される全マネージドリソースに自動適用
  • コスト配分・SCP・コンプライアンス要件を一貫適用できる
  • 手動タグ付けが不要になり運用負荷を低減

✨ 主要機能

🏷️ マネージドリソースへのタグ自動伝播
  • キャパシティプロバイダー設定で指定したタグを、LMI が作成する全リソースに自動適用
  • 対象は Amazon EC2 インスタンス、Amazon EBS ボリューム、Amazon ENI
  • タグ付けの手動作業が不要
⚙️ PropagateTags 設定による制御
  • PropagateTags の Mode を Explicit に設定し、伝播するタグをキーバリューペアで明示指定
  • Mode は None (伝播しない) と Explicit (明示指定したタグを伝播) を選択可能
🛡️ ガバナンスとコスト管理の強化
  • コスト配分タグの強制によりコスト可視化と配賦の精度が向上
  • タグ条件を用いた SCP の適用やコンプライアンス遵守を一貫適用

🔧 技術仕様

PropagateTags の構成要素

項目詳細
ModeNone または Explicit。Explicit で明示指定したタグを伝播
ExplicitTags伝播するタグをキーバリューペア {'string': 'string'} で指定
対象リソースAmazon EC2 インスタンス、Amazon EBS ボリューム、Amazon ENI
設定対象 APICreateCapacityProvider、UpdateCapacityProvider

PropagateTags の設定例

JSONPropagateTags 設定
{
  "PropagateTags": {
    "Mode": "Explicit",
    "ExplicitTags": {
      "CostCenter": "1234",
      "Environment": "Production",
      "Team": "Platform"
    }
  }
}

ステップ 1: 新規作成時にタグ伝播を設定

Bashcreate-capacity-provider
aws lambda create-capacity-provider \
    --capacity-provider-name my-capacity-provider \
    --propagate-tags '{"Mode":"Explicit","ExplicitTags":{"CostCenter":"1234","Environment":"Production"}}'

ステップ 2: 既存キャパシティプロバイダーに追加

Bashupdate-capacity-provider
aws lambda update-capacity-provider \
    --capacity-provider-name my-capacity-provider \
    --propagate-tags '{"Mode":"Explicit","ExplicitTags":{"CostCenter":"1234","Team":"Platform"}}'

ステップ 3: 設定内容を確認

Bashget-capacity-provider
aws lambda get-capacity-provider \
    --capacity-provider-name my-capacity-provider
💡 AWS Management Console、AWS CloudFormation、AWS CDK、AWS SAM からも同様に設定できます。

🎯 メリット

💼 ビジネス面
  • コスト配分の精度向上: チーム・プロジェクト単位のコスト可視化と配賦
  • ガバナンス強化: SCP やコンプライアンス制御を一貫適用
  • 運用負荷の低減: タグ付けの自動化で付け漏れリスクを削減
⚙️ 技術面
  • 一貫したタグ付け: EC2 / EBS / ENI に統一タグを自動付与
  • IaC との統合: CloudFormation / CDK / SAM で宣言的に管理
  • API 経由の柔軟な制御: Explicit モードと任意タグを指定可能

⚠️ デメリット・制約事項

制限事項

!タグ伝播は設定適用後に新規プロビジョニングされるリソースに適用。既存リソースへ遡及適用はされない
!現時点のモードは None と Explicit の 2 種類
!対象は LMI が一般提供されている AWS 商用リージョンに限られる

考慮すべき点

→既存リソースにタグを反映するには、リソースの再プロビジョニングが必要になる可能性がある
→SCP やコスト配分タグの運用ポリシーと整合するタグ設計をあらかじめ検討する必要がある

💡 ユースケース

① コスト配分タグの強制
シナリオ: 複数チームが LMI を利用しており、チーム単位でコストを按分したい
JSON
{ "PropagateTags": { "Mode": "Explicit",
    "ExplicitTags": { "CostCenter": "marketing-001", "Team": "marketing" } } }
効果: Cost Explorer や請求レポートでチーム単位のコストを正確に把握できる
② SCP によるガバナンス適用
シナリオ: 特定のタグを持つリソースのみ操作を許可する SCP を組織で運用している
JSON
{ "PropagateTags": { "Mode": "Explicit",
    "ExplicitTags": { "Compliance": "pci-dss", "DataClassification": "confidential" } } }
効果: コンプライアンスタグが伝播され、タグ条件の SCP やポリシー制御が一貫機能する
③ 環境別のリソース管理
シナリオ: 本番環境と検証環境のリソースをタグで区別して管理したい
JSON
{ "PropagateTags": { "Mode": "Explicit",
    "ExplicitTags": { "Environment": "Production", "Application": "order-service" } } }
効果: 環境・アプリ単位でリソースを識別でき、運用やモニタリングの効率が向上する

🚀 まとめ

AWS Lambda Managed Instances のタグ伝播機能により、LMI が作成する EC2 インスタンス・EBS ボリューム・ENI へタグを自動適用でき、 コスト配分・SCP・コンプライアンス要件をマネージドリソース全体に一貫して適用できるようになりました。 LMI を利用している組織は、PropagateTags を Explicit モードで設定し、 ガバナンスとコスト管理の自動化を検討することを推奨します。
