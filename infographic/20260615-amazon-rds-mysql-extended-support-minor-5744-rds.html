Amazon RDS for MySQL

🛡️ Extended Support 新マイナーバージョン提供開始

5.7.44-RDS.20260521
リリース日
2026 年 6 月 15 日

📌 概要

Amazon RDS for MySQL は、新しい Extended Support マイナーバージョン 5.7.44-RDS.20260521 のサポートを開始しました。 このバージョンは、以前の MySQL に存在する既知のセキュリティ脆弱性とバグを修正するもので、AWS はアップグレードを推奨しています。

Amazon RDS Extended Support は、メジャーバージョンがコミュニティの標準サポート終了を迎えた後も、最大 3 年間にわたり新メジャーバージョンへのアップグレード猶予を提供する仕組みです。期間中、AWS は Aurora および RDS 上の MySQL に重要なセキュリティ修正とバグ修正を継続的に提供します。今回のバージョンは MySQL 5.7 系を Extended Support で運用しているお客様が対象です。

⛔ アップデート前の課題

  • 以前のマイナーバージョンに既知のセキュリティ脆弱性やバグが残存
  • 標準サポート終了後のバージョンでは修正が適用されないリスク
  • セキュリティ修正には新しいマイナーバージョンの提供を待つ必要

✅ アップデート後の改善

  • 5.7.44-RDS.20260521 へのアップグレードで脆弱性とバグを修正
  • 標準サポート終了後の MySQL 5.7 でも重要な修正を受けられる
  • 最大 3 年間の猶予でメジャー移行を計画的に進められる

コミュニティサポート終了後の MySQL メジャーバージョンに対して、Extended Support が最大 3 年間のセキュリティ修正とバグ修正を提供し、新マイナーバージョン 5.7.44-RDS.20260521 がその一環として配信される流れを示しています。

⚙️ 主要機能

📦 1. 新しい Extended Support マイナーバージョンの提供
  • マイナーバージョン 5.7.44-RDS.20260521 が利用可能に
  • 以前の MySQL に存在する既知のセキュリティ脆弱性とバグを修正
  • Amazon RDS for MySQL のお客様にアップグレードを推奨
🛡️ 2. Extended Support によるサポート期間の延長
  • メジャーバージョン標準サポート終了後も最大 3 年間サポートを継続
  • Aurora および RDS の MySQL データベースが対象
  • 重要なセキュリティ修正とバグ修正を継続的に提供
🗓️ 3. 計画的なメジャーバージョン移行の支援
  • 標準サポート終了日を超えても運用を継続しながら移行を準備
  • ビジネス要件に合わせたアップグレード計画の立案が可能

Extended Support のマイナーバージョンを指定してアップグレードする場合、AWS CLI では modify-db-instance の --engine-version パラメータに対象バージョンを指定します。

Bashバージョン指定アップグレード
aws rds modify-db-instance \
    --db-instance-identifier my-mysql-instance \
    --engine-version 5.7.44-RDS.20260521 \
    --apply-immediately

🚀 設定方法 (アップグレード手順)

前提条件

✓Amazon RDS for MySQL のデータベースインスタンスを運用していること
✓アップグレード対象が MySQL 5.7 系の Extended Support バージョンであること
✓アップグレード前にスナップショットを取得し、メンテナンスウィンドウを確認していること

ステップ1: 現在のエンジンバージョンを確認

Bash
aws rds describe-db-instances \
    --db-instance-identifier my-mysql-instance \
    --query "DBInstances[0].EngineVersion"

ステップ2: スナップショットを取得

Bash
aws rds create-db-snapshot \
    --db-instance-identifier my-mysql-instance \
    --db-snapshot-identifier my-mysql-instance-before-5744-rds

ステップ3: マイナーバージョンへアップグレード

Bash
aws rds modify-db-instance \
    --db-instance-identifier my-mysql-instance \
    --engine-version 5.7.44-RDS.20260521 \
    --apply-immediately
💡 --apply-immediately を指定すると即時適用され、省略時は次回メンテナンスウィンドウで適用されます。本番環境ではメンテナンスウィンドウでの適用を検討してください。Amazon RDS マネジメントコンソールからも同様の操作が可能です。

⚖️ メリット・制約事項

👍 メリット

✓移行猶予の確保: 最大 3 年間の猶予でビジネス要件に合わせた移行計画
✓ダウンタイムリスク低減: 急いだ移行を避け十分なテスト期間を確保
✓コンプライアンス維持: セキュリティ修正の継続適用で基準を満たしやすい
✓脆弱性の修正: 既知のセキュリティ脆弱性が修正され安全性が向上
✓マネージドな提供: AWS が修正版を提供し独自パッチ管理が不要

⚠️ 制約・考慮点

!Extended Support は標準サポートに加えて追加料金が発生
!期間は標準サポート終了後最大 3 年間に限られる
!マイナーアップグレードでも適用時に短時間のダウンタイムの可能性
!コスト継続負担より計画的なメジャー移行が望ましい
!検証環境での動作確認とアプリ互換性確認を事前に実施

💡 ユースケース

🔐 1. セキュリティ脆弱性への対応

シナリオ: MySQL 5.7 を Extended Support で運用しており、既知のセキュリティ脆弱性に早期対応する必要がある。

Bash
aws rds modify-db-instance \
    --db-instance-identifier prod-mysql \
    --engine-version 5.7.44-RDS.20260521 \
    --apply-immediately

効果: 既知のセキュリティ脆弱性が修正され、セキュリティリスクを低減できます。

🗓️ 2. メジャーバージョン移行までの安定運用

シナリオ: MySQL 8.0 などへの移行を計画しているが、アプリ改修に時間が必要で、その間も安定運用を維持したい。

手順
1. 最新の Extended Support マイナーバージョンを適用してセキュリティと安定性を維持
2. 検証環境で MySQL 8.0 への移行テストを並行して実施
3. 移行準備が整い次第、メジャーバージョンアップグレードを実施

効果: 最大 3 年間の猶予を活用しつつ、安全な状態で計画的な移行を進められます。

📋 3. コンプライアンス要件への準拠

シナリオ: 規制業界において、データベースに最新のセキュリティ修正が適用されていることを求められている。

手順
1. 提供された最新の Extended Support マイナーバージョンを定期的に適用
2. アップグレード履歴を監査ログとして記録
3. パッチ適用状況をコンプライアンスレポートに反映

効果: 継続的なセキュリティ修正の適用により、コンプライアンス要件を満たしやすくなります。

💰 料金・利用可能リージョン

💵 料金

Extended Support は標準サポートに加えて追加料金が発生します。料金は vCPU あたりの時間単位で課金され、年数に応じて段階的に設定されています。

最新の Extended Support マイナーバージョンへのアップグレード自体に追加料金は発生しません。利用料金はメジャーバージョン標準サポート終了後に適用されます。

🌍 利用可能リージョン

今回の発表では特定のリージョンは明記されていません。対象リージョンおよびマイナーバージョンの提供状況は、Amazon RDS for MySQL の料金ページおよびドキュメントを参照してください。

  • Amazon RDS Blue/Green Deployments
    メジャーバージョンアップグレードや大規模な変更を、ダウンタイムを最小化しながら安全に実施できる
  • Amazon RDS マネジメントコンソール
    マイナーバージョンアップグレードをコンソールから簡単に実施できる

📝 まとめ

新しい Extended Support マイナーバージョン 5.7.44-RDS.20260521 は、既知のセキュリティ脆弱性とバグを修正する重要なアップデートです。MySQL 5.7 を Extended Support で運用しているお客様は、検証環境での動作確認とスナップショット取得を行ったうえで、本バージョンへのアップグレードを検討してください。あわせて、最大 3 年間の猶予期間を活用し、新メジャーバージョンへの計画的な移行を進めることが推奨されます。
