Amazon RDS for Oracle

🗄️ 2026 年 9 月 Monthly Recommended Patch (MRP) サポート

📅 リリース日: 2026 年 10 月 28 日 | 対象: Oracle Database 19c / 26ai

📌 概要

Amazon RDS for Oracle が、Oracle Database 19c および 26ai 向けの September 2026 MRP をサポートしました。MRP は四半期ごとの Release Update (RU) の上に構築されるマイナーエンジンバージョンで、Oracle の Critical Security Patch Update (CSPU) とその他の推奨修正をまとめたパッチです。

今回の MRP は 2026 年 7 月の RU の上に適用され、2026 年 9 月 CSPU を含みます。さらにタイムゾーンファイル DST バージョン 46 を収録し、2026 年施行の新しい夏時間ルールに対応します。AWS は最新のセキュリティアップデートを含むため、このパッチへのアップグレードを推奨しています。

✗カナダ (BC 州・アルバータ州) やモロッコ・西サハラの新夏時間ルールに対応できず、タイムゾーン付きタイムスタンプの計算に不整合が生じるリスク

✓コンソール、AWS SDK、CLI から新規作成・既存インスタンスのアップグレードが可能

September 2026 MRP は、July 2026 RU の上にセキュリティ修正と推奨修正を積み重ねたマイナーエンジンバージョンとして提供され、19c と 26ai の両方に適用できます。

⚙️ 主要機能

1️⃣ September 2026 MRP のサポート
→Oracle Database 19c および 26ai 向けのマイナーエンジンバージョンとして提供
→2026 年 7 月の Release Update (RU) の上に適用される
→Oracle の 2026 年 9 月 Critical Security Patch Update (CSPU) を含む
→その他の Oracle 推奨修正もバンドル
2️⃣ タイムゾーンファイル DST バージョン 46 の収録
→カナダのブリティッシュコロンビア州・アルバータ州の新夏時間ルール (2026 年 11 月 1 日施行) に対応
→モロッコ・西サハラの新ルール (2026 年 9 月 20 日施行) に対応し、恒久的な UTC オフセットへの移行を反映
→タイムゾーン付きタイムスタンプデータを新ルールと整合した状態に維持
3️⃣ 複数の適用方法
→新規 DB インスタンス作成時に MRP バージョンを指定可能
→既存インスタンスをマイナーバージョンアップグレードで移行可能
→RDS マネジメントコンソール、AWS SDK、AWS CLI のいずれからも操作可能

🔄 MRP と RU の関係

パッチ種別提供頻度内容
Release Update (RU)四半期ごと機能修正・セキュリティ修正を含む包括的な更新
Monthly Recommended Patch (MRP)月次直近の RU の上に CSPU と推奨修正をバンドルしたマイナーバージョン

🛠️ 設定方法

✅ 前提条件

  • Amazon RDS for Oracle の DB インスタンス (Oracle Database 19c または 26ai) を利用していること
  • 対象インスタンスが July 2026 RU 系のバージョンへアップグレード可能であること
  • アップグレード操作に必要な IAM 権限 (rds:ModifyDBInstance など) を保有していること

ステップ 1: 利用可能なエンジンバージョンの確認

BashSeptember 2026 MRP を含むバージョンの検索
aws rds describe-db-engine-versions \
    --engine oracle-ee \
    --query "DBEngineVersions[?contains(EngineVersion, 'mrp-2026-09')].EngineVersion"

ステップ 2: 既存インスタンスのアップグレード

Bashエンジンバージョンの変更 (即時適用)
aws rds modify-db-instance \
    --db-instance-identifier my-oracle-instance \
    --engine-version 19.0.0.0.ru-2026-07.mrp-2026-09.r2 \
    --apply-immediately

--apply-immediately を指定すると即時適用され、指定しない場合は次のメンテナンスウィンドウで適用されます。

ステップ 3: アップグレード状態の確認

Bashステータスとエンジンバージョンの確認
aws rds describe-db-instances \
    --db-instance-identifier my-oracle-instance \
    --query "DBInstances[0].[DBInstanceStatus,EngineVersion]"

💡 メリット

💼 ビジネス面

✓セキュリティコンプライアンスの維持: 最新の CSPU を適用し、四半期 RU を待たずにセキュリティ基準や監査要件への準拠を維持
✓業務データの正確性確保: 新しい夏時間ルールに対応したタイムゾーンデータで、グローバル業務システムの時刻計算の正確性を確保
✓運用負荷の軽減: マネージドサービスとしてパッチが提供され、パッチ適用作業の計画・検証負担を軽減

🔬 技術面

✓月次のセキュリティ更新サイクル: MRP により四半期 RU の間でも最新のセキュリティ修正を取り込み可能
✓19c と 26ai の両方に対応: 長期サポート版と最新版のどちらでも同じタイミングでパッチを適用可能
✓柔軟な適用方法: コンソール、SDK、CLI のいずれからも適用でき、既存の運用自動化に組み込みやすい

⚠️ デメリット・制約事項

🚧 制限事項

!MRP は July 2026 RU がベースのため、より古い RU 系バージョンからは段階的なアップグレード計画が必要になる場合がある
!マイナーバージョンアップグレードの適用時にはダウンタイムが発生する (Multi-AZ 構成ではフェイルオーバーにより短縮可能)

🤔 考慮すべき点

→本番環境への適用前に、ステージング環境でアプリケーションの動作検証を実施することを推奨
→自動マイナーバージョンアップグレード有効時は、メンテナンスウィンドウでの適用タイミングを確認
→タイムゾーン付きタイムスタンプを多用するシステムでは、DST v46 更新による影響範囲を事前に確認

🎯 ユースケース

🏦 ユースケース 1: セキュリティ要件の厳しい金融システム

シナリオ: 金融機関の勘定系データベースで、既知の脆弱性に対するパッチを可能な限り早期に適用するポリシーを運用。

Bash本番 DB のアップグレード
aws rds modify-db-instance \
    --db-instance-identifier prod-banking-db \
    --engine-version 19.0.0.0.ru-2026-07.mrp-2026-09.r2
✅ 効果: 四半期 RU を待たずに September 2026 CSPU を適用し、脆弱性対応の SLA を満たせる。
🌍 ユースケース 2: グローバル展開するスケジュール管理システム

シナリオ: カナダやモロッコにユーザーを持つ予約・スケジュール管理システムで、タイムゾーン付きタイムスタンプを使用。2026 年施行の新しい夏時間ルールへの対応が必要。

Bashメンテナンスウィンドウでの適用を予約
# メンテナンスウィンドウでの適用を予約
aws rds modify-db-instance \
    --db-instance-identifier global-scheduler-db \
    --engine-version 26.0.0.0.ru-2026-07.mrp-2026-09.r2 \
    --no-apply-immediately
✅ 効果: DST v46 により、新ルール施行後も予約時刻の計算が正確に保たれる。
🧪 ユースケース 3: 26ai への移行後も最新パッチを維持する開発基盤

シナリオ: Oracle Database 26ai へ移行済みの開発・検証環境で、本番と同等のパッチレベルを維持したい。

Bash最新 MRP での新規インスタンス作成
aws rds create-db-instance \
    --db-instance-identifier dev-oracle-26ai \
    --engine oracle-ee \
    --engine-version 26.0.0.0.ru-2026-07.mrp-2026-09.r2 \
    --db-instance-class db.m8i.large \
    --allocated-storage 100 \
    --master-username admin \
    --manage-master-user-password
✅ 効果: 新規インスタンスを最初から最新の MRP で作成し、本番とのパッチレベル差異をなくして検証精度を向上。

💰 料金

MRP の適用自体に追加料金はかかりません。Amazon RDS for Oracle の通常料金 (インスタンス料金、ストレージ料金、ライセンス形態に応じた料金) が引き続き適用されます。

🌐 利用可能リージョン

公式発表にはリージョンの明記はありませんが、Amazon RDS マネジメントコンソール、AWS SDK、AWS CLI を通じて利用できます。利用予定のリージョンで対象エンジンバージョンが提供されているかは、describe-db-engine-versions で確認してください。

🔗 関連サービス・機能

→Amazon RDS for Oracle Release Update (RU): MRP のベースとなる四半期ごとの包括的なパッチ。2026 年 8 月に July 2026 RU のサポートが発表済み
→RDS 自動マイナーバージョンアップグレード: 有効にすると、メンテナンスウィンドウで推奨マイナーバージョンへ自動的にアップグレード
→RDS マイナーバージョンアップグレード事前チェック: 2026 年 10 月発表の機能で、アップグレード前の事前検証と新しい RDS イベントによる通知が可能

📝 まとめ

Amazon RDS for Oracle の September 2026 MRP は、最新のセキュリティ修正 (September 2026 CSPU) と DST バージョン 46 のタイムゾーン更新を含む重要なパッチです。特にセキュリティ要件の厳しいシステムや、カナダ・モロッコなどの新しい夏時間ルールの影響を受けるシステムでは、早期の適用を推奨します。まずは検証環境でアップグレードを実施し、動作確認のうえ本番環境のメンテナンスウィンドウで適用する計画を立てましょう。
