🔍 Amazon CloudWatch Logs Insights
23 個の新しいクエリコマンドと関数

Amazon CloudWatch Logs
📅 リリース日: 2026 年 6 月 8 日

📝 概要

Amazon CloudWatch Logs Insights のクエリ言語に、ログのクエリ・パース・変換・分析を行うための 23 個の新しいコマンドと関数が追加されました。条件処理、文字列変換、IP アドレス処理、各種ファイル形式のパース、複雑な集計処理を、より柔軟に実行できます。

さらに、最初の N 件を取得する limit any N がサポートされ、1 つのクエリ内で最大 10 個の stats コマンドを使用できるようになりました。これらの機能はすべての商用 AWS リージョンで本日から利用可能です。

⛔ アップデート前の課題
  • 条件分岐や型変換の関数が限られ、複雑な前処理を SQL ライクな構文で完結しにくい
  • IP アドレスの判定や CSV / XML などの構造化ログのパースが標準機能だけでは困難
  • 1 クエリで使える stats コマンド数や時系列分析向け集計関数が不足
✅ アップデート後の改善
  • if / toNumber / md5 でクエリ内に条件処理・型変換・ハッシュ化を直接記述
  • IP 種別判定や CSV / XML / 複数パターンのパースを標準関数で実行
  • rate / count_over_time など時系列分析関数と最大 10 個の stats、limit any N で高度な集計が可能

ロググループから取得したログを、新しいパース関数で構造化し、変換関数で整形した後、分析関数で集計するという一連の流れをクエリ内で完結できます。

⚙️ 主要機能

🔐 ハッシュ関数
md5 / sha256

フィールド値をハッシュ化し、機密情報のマスキングや一意性チェックに活用できます。

🔤 文字列関数
strcontains / split

大文字小文字を区別しない包含判定や、区切り文字での分割 (配列化) ができます。

🔀 条件ロジック
if

クエリ内で条件分岐を行い、値の振り分けやカテゴリ分類が可能になります。

🔢 変換関数
toNumber / toInt / toLong / toDouble

文字列として取り込まれた値を数値型に変換し、計算や比較に利用できます。

🌐 IP 関数
ipv4ToNumber / isPrivateIP / isPublicIP / isReservedIP

IPv4 を数値に変換し、プライベート / パブリックなど IP の種別を判定します。

📊 分析関数
rate / count_over_time / sum_over_time / offset / histogram

時系列での増減や集計、値のオフセット取得、分布のヒストグラム集計ができます。

📥 パース関数
parse CSV / parse XML / parse multi / values / addtotals

構造化ログの解析、複数パターンのパース、値の集合取得、合計行の追加ができます。

🧩 クエリ構文の拡張
limit any N / 最大 10 stats

最初の N 件を取得する limit any N と、最大 10 個の stats コマンドに対応。

クエリ例

SQL ライク Logs Insights クエリ 
fields @timestamp, @message
| parse @message "client_ip=*, status=*, bytes=*" as ip, status, bytes
| filter isPublicIP(ip)
| stats sum(toNumber(bytes)) as total_bytes by if(status >= 500, "error", "ok") as result
| sort total_bytes desc
| limit any 20

ログメッセージから IP アドレス・ステータス・バイト数を抽出し、パブリック IP のみを対象に、ステータスコードに応じて「error」「ok」へ分類して転送バイト数を集計します。

💼 ビジネス面

✓分析の内製化: 外部 ETL や追加ツールなしで前処理から分析までを CloudWatch 内で完結し、運用コストを抑制
✓意思決定の迅速化: 時系列分析関数でエラー率やトラフィックの傾向を素早く把握
✓追加費用なし: 既存クエリ機能の延長として利用でき、新製品導入を伴わない

🔧 技術面

✓クエリ表現力の向上: 条件分岐・型変換・ハッシュ化を 1 クエリで記述できる
✓構造化ログ対応: CSV / XML を標準関数でパースでき、前処理の手間を削減
✓セキュリティ分析の強化: IP 種別判定で不正アクセスやトラフィック分析が容易に

⚠️ デメリット・制約事項

制限事項

▸stats コマンドは 1 つのクエリで最大 10 個まで
▸これらは CloudWatch Logs Insights のクエリ言語で利用可能。他のクエリ言語 (OpenSearch PPL / SQL) との構文差異に注意
▸AWS GovCloud (US) や中国リージョンでの提供有無は別途確認が必要 (発表時点では商用リージョン対象)

考慮すべき点

▸複雑なクエリはスキャン対象データ量が増え、クエリ料金やパフォーマンスに影響する可能性
▸既存のクエリ言語バージョンや構文との互換性を確認したうえで利用する

🎯 ユースケース

🛡️ ユースケース 1: アクセスログのセキュリティ分析
シナリオ: Web アプリのアクセスログから、パブリック IP からのエラーアクセスを特定したい。
SQL ライク
fields @timestamp, @message
| parse @message "ip=*, status=*" as ip, status
| filter isPublicIP(ip) and toInt(status) >= 400
| stats count(*) as error_count by ip
| sort error_count desc
| limit any 10
📈 効果: パブリック IP からのエラーアクセスを集計し、攻撃の兆候や問題のあるクライアントを素早く特定。
📦 ユースケース 2: 構造化ログの集計
シナリオ: CSV 形式で出力されたバッチ処理ログを解析し、項目別に集計したい。
SQL ライク
fields @message
| parse @message as csv_record
| stats sum(toDouble(amount)) as total by category
| addtotals
📈 効果: CSV ログを標準関数でパースし、カテゴリ別の合計と全体合計を 1 クエリで取得。
⏱️ ユースケース 3: エラー率の時系列モニタリング
シナリオ: 一定時間ごとのリクエスト数とエラー発生率の推移を可視化したい。
SQL ライク
fields @timestamp, status
| stats count_over_time(*) as requests, rate(toInt(status) >= 500) as error_rate by bin(5m)
📈 効果: 時間帯ごとのリクエスト数とエラー率を集計し、障害の発生傾向やピーク時間帯を把握。

🚀 まとめ

今回のアップデートにより、CloudWatch Logs Insights はログの前処理から高度な分析までを 1 つのクエリで完結できる強力なツールへと進化しました。条件処理・型変換・IP 判定・構造化ログのパース・時系列分析が標準機能として利用できるため、セキュリティ分析や運用モニタリングの担当者は、既存のクエリを見直して新しい関数の活用を検討することをお勧めします。
