aws-bench
AI エージェント向けベンチマーク

実際の AWS 環境で AI エージェントの精度と効率を測定 (リサーチプレビュー)
リリース日
2026 年 7 月 24 日

📌 概要

AWS は、AI エージェントが実際の AWS タスクをどれだけ正確かつ効率的に完了できるかを測定するオープンソースベンチマーク aws-bench のリサーチプレビューを発表しました。モデルプロバイダーや AI 研究者に、AWS インフラ上でのエージェント性能を 客観的かつ再現可能に測定し、失敗原因を診断する手段を提供します。

従来のベンチマークが固定データセットに対してスコアを算出するのに対し、aws-bench は 使い捨ての実際の AWS 環境に対してエージェントを実行する点が特徴です。テストケースは実際の AWS 利用状況の分析に基づき、調査・トラブルシューティング・インフラストラクチャの作成をカバーします。各テストケースは、自然言語クエリ・定義済みのクラウドリソース状態・正解 (ground-truth) を組み合わせ、一貫性のある検証可能なスコアリングを実現します。

aws-bench は Harbor フレームワークを基盤とし、AWS 固有のプロビジョニングと検証ロジック (verifier) を拡張したものです。GitHub 上で Apache License 2.0 のもと公開され、テスト環境の構築・評価の実行とスコアリング・リソース状態のリセットを行う CLI ツールが同梱されています。

🔄 Before / After

😰 アップデート前の課題
  • AWS 環境での AI エージェント性能を、客観的かつ再現可能に測定する標準手段が存在しなかった
  • 固定データセットのベンチマークでは、実際のクラウドリソースを操作する現実的なタスクの評価が難しかった
  • 失敗原因を体系的に診断し、基盤モデルやエージェントハーネスの改善につなげる仕組みが不足していた
➡
😊 アップデート後の改善
  • 実際の AWS 利用状況に基づくテストケースで、性能を客観的に測定できる
  • 使い捨ての実 AWS 環境にエージェントを実行し、ライブ状態に対して検証できる
  • CLI ツールで、テスト環境の構築・評価の実行とスコアリング・リソース状態のリセットが容易に

⚙️ 主要機能

🌐 実環境ベースのベンチマーク

固定データセットではなく、使い捨ての実 AWS 環境に対してエージェントを実行。テストケースは実際の AWS 利用状況の分析に基づき、調査・トラブルシューティング・インフラ作成をカバーします。

🧩 2 種類のタスクファミリー

  • Introspection: 読み取り専用の診断タスク。LLM が評価
  • Mutation: リソースの作成・変更タスク。ライブ状態にプログラムで検証後、ロールバック

🛠️ CLI ツールによる自動化

環境の初期化・リソースのデプロイ・ドリフトチェック・リセット・削除を CLI で実行。各テストケースは自然言語クエリ・リソース状態・正解を組み合わせて検証可能なスコアリングを実現します。

🏆 reward.json でスコアリング

トライアルごとに reward.json が出力され、1.0 (合格) または 0.0 (不合格) が記録されます。一貫性のある検証可能な評価を提供します。

🧬 2 種類のタスクファミリー

🔍 Introspection (イントロスペクション)

読み取り専用の診断タスク。リソースを変更せず、状態を調査・診断する。結果は LLM によって評価される。

✏️ Mutation (ミューテーション)

リソースの作成・変更タスク。ライブ状態に対してプログラムで検証された後、変更はロールバックされる。

🚀 設定方法

前提条件: macOS または Linux と Python 3.12 以上 / uv と Docker (Compose v2、buildx 0.17.0 以上) / AWS Organization とメンバーアカウントを作成できる権限を持つ AWS アカウント。

ステップ 1: リポジトリのクローンとセットアップ

Bash クローンと依存関係インストール 
git clone https://github.com/aws-bench/aws-bench.git && cd aws-bench
uv sync
uv run aws-bench --help

ステップ 2: テスト環境の構築

Bash プロビジョニングとリソースのデプロイ 
# 環境のプロビジョニングとリソースのデプロイ
uv run aws-bench env init --env-name my-bench
uv run aws-bench env setup --env-name my-bench

env init で使い捨てアカウントをプロビジョニングし、env setup でシナリオのインフラ (CDK スタック) をデプロイします。

ステップ 3: ベンチマークの実行

Bash 単一シナリオデータセットの実行 
# 単一シナリオデータセットの実行
uv run aws-bench run -d ec2-multiregion@latest --env-name my-bench -a claude-code -m <model-id>

指定したデータセットに対してエージェントを実行し、verifier がスコアリング。結果は jobs/<timestamp>/ 配下にトライアルごとの reward.json として出力されます。

⚖️ メリットと制約・考慮点

✅ メリット

  • 客観的な評価基準: AWS 環境での性能を再現可能な方法で比較できる
  • オープンソース: Apache License 2.0 で無償利用・拡張が可能
  • 進捗の追跡: 基盤モデルやハーネスの改善状況を継続的に測定
  • 実環境ベースの検証: 使い捨ての実 AWS 環境で現実的な遂行能力を測定
  • CLI による自動化: 構築・実行・リセット・削除を一連のコマンドで自動化
  • 拡張性: Harbor を基盤に AWS 固有のプロビジョニングと verifier を追加可能

⚠️ 制約・考慮すべき点

  • リサーチプレビューとして提供され、仕様が変更される可能性がある
  • 実行には AWS Organization とメンバーアカウントを作成できる権限が必要
  • 対応 OS は macOS と Linux のみ (Windows は非サポート)
  • 実 AWS 環境をプロビジョニングするため、実行に伴う AWS 利用料金が発生する
  • Docker・uv・Python 3.12 以上など複数の前提ツールのセットアップが必要
  • Mutation タスクはライブ状態を変更するため、専用アカウントでの実行が前提

💡 ユースケース

1️⃣ 基盤モデルの性能改善

モデルプロバイダーが、新しい基盤モデルの AWS タスク遂行能力を評価・改善したい。

Bash
uv run aws-bench run -d aws-bench-basic@latest --env-name eval -a claude-code -m <model-id>

効果: 78 タスク / 4 シナリオの標準データセットで、モデルの精度を客観的に測定し改善につなげられる。

2️⃣ エージェントハーネスの改良

AI 研究者が、エージェントのツール呼び出しやプロンプト戦略 (ハーネス) を改良し、効果を検証したい。

Bash
uv run aws-bench run -d aws-bench-advanced@latest --env-name harness-test -a claude-code -m <model-id>

効果: より難易度の高い 47 タスク / 3 シナリオで、ハーネス変更による遂行能力の変化を verifier のスコアで比較できる。

3️⃣ 失敗原因の診断

エージェントが特定の AWS トラブルシューティングタスクで失敗する原因を特定したい。

Bash
uv run aws-bench run -d aws-bench-quickstart@latest --env-name debug -a claude-code -m <model-id>
uv run aws-bench env show --env-name debug

効果: 少数のタスクで素早く実行し、reward.json とリソース状態を確認して失敗パターンを診断できる。

💰 料金 & 利用可能リージョン

料金: aws-bench 自体は オープンソース (Apache License 2.0) で無償。ただしベンチマーク実行時には実際の AWS 環境 (メンバーアカウント、CDK スタックによるリソース) をプロビジョニングするため、通常の AWS 料金が発生します。料金は作成されるリソースの種類と実行時間に依存します。

📝 まとめ

aws-bench は、AWS 環境における AI エージェントの遂行能力を、実際のクラウド環境に対して客観的かつ再現可能に測定するオープンソースベンチマークです。モデルプロバイダーや AI 研究者は、まず aws-bench-quickstart データセットで動作を確認し、基盤モデルやエージェントハーネスの改善に向けた評価基盤として活用することが推奨されます。
