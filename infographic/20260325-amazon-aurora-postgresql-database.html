📝 概要

Amazon Aurora PostgreSQL に Express Configuration が追加されました。事前設定済みの構成により、クラスターを数秒で作成しクエリを実行できます。

VPC の外部に配置されたクラスターに、インターネットアクセスゲートウェイ経由でセキュアに接続でき、VPN や Direct Connect は不要です。

開発者のツールからインターネットアクセスゲートウェイを経由して、VPC 外に配置された Aurora PostgreSQL Serverless クラスターにセキュアに接続する構成です。IAM 認証によるパスワードレス認証と、マルチ AZ 構成による高可用性が標準で提供されます。

🔑 IAM 認証の仕組み

IAM 認証トークンは一時的な認証情報として機能し、パスワードの管理や定期的なローテーションが不要になります。

Bash IAM 認証トークンの生成と接続 
# IAM 認証トークンの生成
aws rds generate-db-auth-token \
  --hostname <cluster-endpoint> \
  --port 5432 \
  --region <region> \
  --username <admin-user>

# 生成されたトークンを使用して psql で接続
PGPASSWORD=$(aws rds generate-db-auth-token \
  --hostname <cluster-endpoint> \
  --port 5432 \
  --region <region> \
  --username <admin-user>) \
psql "host=<cluster-endpoint> port=5432 \
  dbname=postgres user=<admin-user> \
  sslmode=require"

⚙️ 設定方法

📌前提条件: AWS アカウント (Free/Paid Plan)、適切な IAM 権限、PostgreSQL クライアントツール
Step 1: Express Configuration でクラスター作成

RDS コンソールで「データベースの作成」から Express Configuration を選択。数秒以内に作成されます。

Bash AWS CLI でのクラスター作成 
aws rds create-db-cluster \
  --db-cluster-identifier my-express-cluster \
  --engine aurora-postgresql \
  --engine-mode provisioned \
  --serverless-v2-scaling-configuration \
    MinCapacity=0,MaxCapacity=2 \
  --enable-iam-database-authentication \
  --publicly-accessible
Step 2: IAM ポリシーの確認

rds-db:connect アクションを許可する IAM ポリシーが必要です。

JSON IAM ポリシー例 
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["rds-db:connect"],
    "Resource": [
      "arn:aws:rds-db:<region>:<account-id>:dbuser:<resource-id>/<admin-user>"
    ]
  }]
}
Step 3: データベースへの接続

インターネットアクセスゲートウェイ経由で、ローカル環境から直接接続。VPN や踏み台サーバーは不要です。

Bash エンドポイント取得と接続 
# クラスターのエンドポイントを取得
ENDPOINT=$(aws rds describe-db-clusters \
  --db-cluster-identifier my-express-cluster \
  --query 'DBClusters[0].Endpoint' \
  --output text)

# IAM 認証トークンを生成して接続
PGPASSWORD=$(aws rds generate-db-auth-token \
  --hostname $ENDPOINT \
  --port 5432 \
  --region <region> \
  --username <admin-user>) \
psql "host=$ENDPOINT port=5432 \
  dbname=postgres user=<admin-user> \
  sslmode=require"

⚠️ デメリット・制約事項

🚧 制限事項
  • VPC 外配置のため、VPC 内リソースとのプライベート通信には追加構成が必要な場合がある
  • インターネット経由の接続が前提のため、外部接続が制限されている環境では利用が難しい場合がある
  • IAM 認証がデフォルトのため、従来のパスワードベース認証に依存するレガシーアプリの接続には追加設定が必要
💡 考慮すべき点
  • 本番ワークロードでは、VPC 内配置によるネットワーク分離やセキュリティグループによるアクセス制御が推奨される場合がある
  • Express Configuration は迅速な開発開始を目的としているため、本番環境ではカスタム構成を検討する

💡 ユースケース

🚀 迅速なプロトタイプ開発

Web アプリケーションのプロトタイプ開発時に、数分以内にデータベースを準備してバックエンドの検証を開始。VPC やネットワーク設定を省略し、アプリケーション開発に集中できる。

🏠 リモート開発環境からの接続

リモートワーク中の開発者が、自宅のネットワーク環境から VPN を構築せずに共有データベースにアクセス。IAM 認証でセキュアにインターネット経由で接続し、リモート開発の生産性が向上。

🎓 教育・ハンズオン環境の構築

企業内の技術トレーニングで、参加者ごとに独立した Aurora PostgreSQL データベースを短時間で準備。参加者がネットワーク設定を意識することなく、各自の PC から直接接続してハンズオン演習を開始できる。
