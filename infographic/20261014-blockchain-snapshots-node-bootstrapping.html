Blockchain Snapshots on AWS Amazon S3 / Amazon EC2 📅 2026 年 10 月 14 日

⛓️ Blockchain Snapshots on AWS

Ethereum / Solana 向け事前同期済みチェーンデータスナップショットの提供開始 — ノードブートストラップを数日から数時間へ

📝 概要

AWS は、Ethereum / Solana ノードオペレーター向けに、事前同期済みのパブリックブロックチェーンチェーンデータを Amazon S3 で無料公開する「Blockchain Snapshots on AWS」を発表しました。ピアツーピア同期の代わりにスナップショットからノードをブートストラップでき、Amazon EC2 でのセットアップ時間を大幅に短縮できます。

スナップショットは AWS インフラストラクチャ内でホストされ、複数コアによる並列展開に最適化された形式で再公開されます。更新頻度はアップストリームプロバイダーと同じです。RPC フリートへのキャパシティ追加、障害ノードの復旧、破損データベースの再同期に活用できます。

❌ Before: アップデート前の課題

  • 新規ノードの立ち上げはピアツーピア同期が必要で、チェーンデータの肥大化により数日〜数週間かかる場合があった
  • コミュニティのスナップショットは AWS 外部ホストが多く、インターネット経由のダウンロードに時間がかかっていた
  • 障害やデータベース破損からの復旧に長い再同期時間を要し、RPC フリートのスケールアウトも迅速に行えなかった

✅ After: アップデート後の改善

  • Amazon S3 上のスナップショットから直接ブートストラップでき、ピアツーピア同期を省略してセットアップ時間を大幅短縮
  • AWS 内ホスティングにより、同一リージョンの EC2 から低レイテンシーかつ最適化されたデータ転送でダウンロード
  • 並列展開に最適化された形式で展開も高速化
  • 無料で利用でき、アップストリームと同じ頻度で更新

各ネットワークの公式スナップショットが並列展開に最適化された形式で Amazon S3 に再公開され、同一リージョンの EC2 インスタンスが S3 ゲートウェイ VPC エンドポイント経由でダウンロードしてノードをブートストラップします。

⚡ 主要機能

🪣 事前同期済みスナップショットの S3 ホスティング
  • Ethereum / Solana のチェーンデータを Amazon S3 のリージョン別バケットで公開
  • 各ネットワークの公式 (アップストリーム) スナップショットを再公開し、アップストリームと同じ頻度で更新
  • AWS インフラストラクチャ内でのホスティングにより、低レイテンシーかつ最適化されたデータ転送を実現
🚀 並列展開に最適化されたフォーマット
  • 複数コアでの並列展開に最適化された形式で提供し、セットアップ時間を短縮
  • 配信プロトコル: tar-zstd-seekable-v1 (zstd フレームの並列デコード)、tar-zstd-stream-v1 (ストリーム展開)、archive-set-v1 (Solana / Agave 向けにアーカイブのまま配置)
  • ローカル NVMe では O_DIRECT 書き込み、EBS ではバッファード書き込みなど、ストレージ特性に応じた展開動作
🛠️ snapshot.sh によるシンプルな取得フロー
  • awslabs の GitHub リポジトリで公開されるツール (Apache-2.0 ライセンス) を使用
  • --list でカタログを一覧表示し、--snapshot で対象を指定してダウンロードと展開を実行
  • --json 出力による自動化や、--workers、--region などのオプションに対応

⚙️ 設定方法

📋 前提条件

✓提供リージョン (us-east-1、eu-west-1、ap-northeast-1) のいずれかに Amazon EC2 インスタンスを起動していること
✓VPC に Amazon S3 ゲートウェイ VPC エンドポイントが設定されていること (リージョン内ダウンロードが前提で、ローカル PC などリージョン外からはダウンロード不可)
✓インスタンスプロファイルにリージョン別バケットへの s3:GetObject と s3:ListBucket 権限が付与されていること
✓展開後のデータサイズを格納できるローカル NVMe または EBS ストレージがあること
1

ツールのセットアップ

Bashawslabs リポジトリのクローンとセットアップ
sudo dnf install -y git
cd ~ && git clone https://github.com/awslabs/blockchain-snapshots.git
cd blockchain-snapshots/dist
./snapshot.sh --setup

セットアップでは AWS CLI v2、Python / boto3、zstd、mountpoint-s3 などの依存ツールがインストールされます。Ubuntu の場合は apt-get を使用します。

2

利用可能なスナップショットの確認

Bashカタログの一覧表示
./snapshot.sh --list

現在のリージョンのカタログから、利用可能なスナップショットの一覧 (ネットワーク、クライアント、更新日時など) を表示します。

3

スナップショットのダウンロードと展開

Bashダウンロードと並列展開
./snapshot.sh --snapshot ethereum-mainnet-geth --out /data/ethereum-mainnet-geth

ツールはカタログから最新エントリを解決し、認証情報・空き容量・出力先の安全性を検証したうえで、配信プロトコルに従ってデータを配置します。完了後、展開されたチェーンデータをデータディレクトリとして指定し、ノードクライアントを起動します。

BashJSON 出力による自動化の例
./snapshot.sh --snapshot ethereum-mainnet-reth --json | jq -r .output_dir

--json オプションで実行結果を JSON 形式で出力し、jq で展開先ディレクトリを取得する例です。CI / CD や起動スクリプトへの組み込みに便利です。

💡 メリット

💼 ビジネス面
  • ノード立ち上げ時間の大幅短縮: 数日かかっていたピアツーピア同期をスナップショット復元に置き換え、サービス投入・障害復旧を迅速化
  • コスト削減: スナップショットは無料。同一リージョン内の S3 ゲートウェイ VPC エンドポイント経由のため、インターネット経由のデータ転送コストを回避
  • 運用の安定化: 障害ノード復旧や破損データベース再同期を迅速に行え、RPC サービスの可用性を維持しやすい
🔬 技術面
  • 最適化されたデータ転送: AWS 内ホスティングにより、同一リージョンの EC2 から低レイテンシーでダウンロード
  • 並列展開による高速化: 複数コアを活用する展開最適化フォーマットで、展開時間も短縮
  • 自動化しやすい設計: --list や --json を備えた CLI ツールで、Auto Scaling やフリート管理へ容易に組み込める

⚠️ デメリット・制約事項

制限事項

✗提供リージョンは US East (N. Virginia)、Europe (Ireland)、Asia Pacific (Tokyo) の 3 リージョンのみ
✗対応ネットワークは Ethereum と Solana のみ
✗同一リージョン内の EC2 インスタンスと S3 ゲートウェイ VPC エンドポイントが必須で、リージョン外やオンプレミスからのダウンロードは想定されていない

考慮すべき点

⚠スナップショットは「AS IS」で提供され、可用性や鮮度の保証はなく、SLA を持つ AWS サービスではない
⚠チェーンデータはサードパーティのアップストリームプロバイダー由来のため、ノード起動後はネットワークピアとの検証 (同期の追い付き) が必要
⚠展開後のデータサイズを見込んだ十分なストレージ容量 (ローカル NVMe または EBS) を事前に確保する必要がある
⚠更新頻度はアップストリームプロバイダーに依存するため、取得後に最新ブロックまでの差分同期が発生する

🎯 ユースケース

1️⃣ RPC フリートへのキャパシティ追加

シナリオ: dApp やインデクサー向けに Ethereum RPC ノードのフリートを運用しており、トラフィック増加に応じて迅速にノードを追加したい。

Bash実装例
# 新規 EC2 インスタンスの起動スクリプト内で実行
./snapshot.sh --snapshot ethereum-mainnet-reth --out /data/reth --json
# 展開完了後に Reth をスナップショットのデータディレクトリで起動

✅ 効果: ピアツーピア同期を待たずに新規ノードを数時間以内でフリートへ投入でき、需要変動への追従が容易になる。

2️⃣ 障害ノードの迅速な復旧

シナリオ: Solana バリデータ / RPC ノードがハードウェア障害で停止し、できるだけ早くサービスへ復帰させたい。

Bash実装例
# 代替インスタンスでスナップショットを取得
./snapshot.sh --snapshot solana-mainnet-agave --out /data/solana
# Agave はアーカイブのまま配置されるため --no-snapshot-fetch で起動

✅ 効果: ネットワークからのスナップショット取得を省略し、障害発生から復旧までの時間を短縮できる。

3️⃣ 破損したデータベースの再同期

シナリオ: Geth ノードのデータベースが破損し、ゼロからの再同期では数日を要してしまう。

Bash実装例
# 破損したデータディレクトリを退避し、スナップショットから再構築
./snapshot.sh --snapshot ethereum-mainnet-geth --out /data/geth --force

✅ 効果: フル再同期の代わりに最新スナップショットから復元し、残りの差分のみをネットワークから同期することでダウンタイムを最小化できる。

💰 料金

スナップショット自体は無料で利用できます。ただし、ノードを実行する Amazon EC2 インスタンス、Amazon EBS ボリュームなどの通常の利用料金は別途発生します。Amazon S3 ゲートウェイ VPC エンドポイント経由の同一リージョン内アクセスのため、データ転送は最適化されています。

🔗 関連サービス・機能

🪣 Amazon S3

スナップショットのホスティング基盤。ゲートウェイ VPC エンドポイント経由でリージョン内から高速にアクセスする。

⚙️ Amazon EC2

スナップショットを取得・展開し、ブロックチェーンノードを実行するコンピューティング基盤。

💾 Amazon EBS / インスタンスストア NVMe

展開後のチェーンデータを格納するストレージ。ツールはストレージ特性に応じて書き込み方式を最適化する。

📌 まとめ

Blockchain Snapshots on AWS により、Ethereum および Solana のノードオペレーターは、ピアツーピア同期に数日を費やすことなく、Amazon S3 上の事前同期済みスナップショットからノードを迅速にブートストラップできるようになりました。東京リージョンでも提供されるため、国内でノードを運用するお客様にも有用です。RPC フリートの拡張やノード復旧の時間短縮が課題となっている場合は、ドキュメントのセットアップ手順に従って snapshot.sh を試すことを推奨します。
