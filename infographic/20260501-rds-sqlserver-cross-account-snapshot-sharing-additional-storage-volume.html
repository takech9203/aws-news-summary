Amazon RDS for SQL Server

追加ストレージボリュームの
クロスアカウントスナップショット共有

大容量データベースのバックアップ、災害復旧、コンプライアンス対応を大幅に簡素化

2026-05-01

📋 概要

Amazon RDS for SQL Server で、追加ストレージボリュームを持つデータベースインスタンスのクロスアカウントスナップショット共有がサポートされました。追加ストレージボリュームは、プライマリストレージに加えて最大 3 つのボリューム (各最大 64 TiB) を追加し、データベースストレージを最大 256 TiB までスケールできる機能です。

今回のアップデートにより、追加ストレージボリュームを設定した DB インスタンスのスナップショットを AWS アカウント間で作成、共有、コピーできるようになり、ストレージレイアウトが完全に保持されます。

🔄 Before / After

❌ Before

  • 追加ストレージボリュームを持つスナップショットをアカウント間で共有できなかった
  • 大容量 DB (64 TiB 超) の災害復旧を別アカウントで管理するには手動データ移行が必要
  • 追加ストレージボリューム構成での分離バックアップ環境構築が困難

✅ After

  • 追加ストレージボリュームを含むスナップショットをアカウント間で直接共有可能
  • ストレージレイアウト (追加ストレージボリュームの構成) が完全に保持される
  • ターゲットアカウントでの復元、リージョン間コピー、独立バックアップ作成が可能

⚡ 主要機能

📤 クロスアカウントスナップショット共有

追加ストレージボリュームを持つ DB インスタンスのスナップショットを別の AWS アカウントに共有可能。ストレージレイアウトが完全に保持されます。AWS Management Console、CLI、SDK から利用可能です。

🔄 ターゲットアカウントでの操作

共有スナップショットから別の DB インスタンスへの復元、同一/異なるリージョンへのスナップショットコピー、異なる IAM アクセス権限での独立バックアップの作成が可能です。

💾 追加ストレージボリューム構成の保持

最大 3 つの追加ストレージボリューム (各最大 64 TiB) の構成が保持されます。プライマリストレージボリュームと追加ストレージボリュームの完全なレイアウトが復元時に再現されます。

🛠️ 設定方法

ステップ 1: DB スナップショットの作成

Bash スナップショット作成 
aws rds create-db-snapshot \
  --db-instance-identifier my-sql-server-instance \
  --db-snapshot-identifier my-cross-account-snapshot

追加ストレージボリュームを持つ RDS for SQL Server インスタンスの手動スナップショットを作成します。

ステップ 2: スナップショットの共有

Bash クロスアカウント共有 
aws rds modify-db-snapshot-attribute \
  --db-snapshot-identifier my-cross-account-snapshot \
  --attribute-name restore \
  --values-to-add 123456789012

ターゲットアカウント (123456789012) にスナップショットの復元権限を付与します。追加ストレージボリュームの構成はスナップショットとともに保持されます。

ステップ 3: ターゲットアカウントでスナップショットを復元

Bash スナップショットからの復元 
aws rds restore-db-instance-from-db-snapshot \
  --db-instance-identifier restored-instance \
  --db-snapshot-identifier arn:aws:rds:us-east-1:111122223333:snapshot:my-cross-account-snapshot

ターゲットアカウントで共有スナップショットから DB インスタンスを復元します。ストレージレイアウト (追加ストレージボリュームを含む) が再現されます。

🎯 ユースケース

🏦 コンプライアンス要件に基づく分離バックアップ

金融機関が規制要件に基づき、本番データベースのバックアップを完全に分離されたアカウントに保持する必要がある場合。100 TiB を超える大容量データベースの完全なストレージレイアウトを維持した状態で、分離アカウントにバックアップを保持しコンプライアンス要件を満たせます。

🔍 本番問題の調査用環境構築

本番環境で発生したデータ関連の問題を調査するため、開発チームが別アカウントでデータベースを復元してデバッグを行う場合。本番環境に影響を与えることなく、追加ストレージボリュームの構成も保持されるため本番と同等のストレージレイアウトで再現検証が可能です。

🌍 クロスリージョン災害復旧

災害復旧計画の一環として、プライマリリージョンの大容量データベーススナップショットを別アカウント・別リージョンにコピーし DR 環境を維持する場合。アカウント分離とリージョン分離の両方を実現しながら追加ストレージボリュームを含む DR 環境を構築できます。

✅ メリット

ビジネス面

✓ コンプライアンス強化: 分離されたアカウントにバックアップを保持することで、規制要件への適合を実現
✓ 災害復旧の改善: 大容量データベースのクロスアカウント DR 戦略を簡素化
✓ 運用効率の向上: 手動データ移行の必要性を排除し、スナップショットベースのワークフローで効率化

技術面

✓ ストレージレイアウト保持: 追加ストレージボリュームの構成が共有・復元時に維持される
✓ 大容量対応: 最大 256 TiB のデータベースに対してクロスアカウント操作が可能
✓ マルチリージョン対応: 共有スナップショットを異なるリージョンにコピー可能

⚠️ 制約事項・注意点

制限事項

  • RDS for SQL Server のみが対象 (他の RDS エンジンについては別途確認が必要)
  • スナップショットの暗号化設定によっては、KMS キーポリシーの調整が必要
  • ターゲットアカウントでの復元には十分なストレージクォータが必要

考慮すべき点

  • 暗号化されたスナップショットの共有には、KMS キーへのクロスアカウントアクセス設定が必要
  • 大容量スナップショットのコピーには時間がかかる場合がある
  • スナップショット共有は手動スナップショットのみサポート (自動バックアップは対象外)

💰 料金

スナップショットの共有自体に追加料金は発生しません。ただし、以下の標準料金が適用されます。

項目 料金
スナップショットストレージ リージョンごとの RDS スナップショットストレージ料金
クロスリージョンコピー データ転送料金 + コピー先リージョンのスナップショットストレージ料金
復元した DB インスタンス 通常の RDS for SQL Server インスタンス料金

📝 まとめ

Amazon RDS for SQL Server の追加ストレージボリュームに対するクロスアカウントスナップショット共有のサポートにより、大容量データベース (最大 256 TiB) のバックアップ、災害復旧、およびコンプライアンス対応が大幅に簡素化されました。ストレージレイアウトが完全に保持されるため、追加ストレージボリュームを活用している環境でも安心してクロスアカウント運用を導入できます。

この機能はすべての AWS 商用リージョンで利用可能であり、AWS Management Console、CLI、SDK から即座に利用を開始できます。
