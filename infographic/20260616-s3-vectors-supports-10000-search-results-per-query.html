📌 概要

Amazon S3 Vectors は、ベクトルデータをネイティブにサポートする Amazon S3 のオブジェクトストレージです。 今回、1 回の類似検索クエリで返却できる結果数の上限を、従来の 100 件から最大 10,000 件へ拡張しました。

これにより、1 回のクエリでより広範な候補集合を取得できます。とくにリランキング・集約・重複排除を行う多段階検索パイプライン (multi-stage retrieval pipeline) に有用です。結果はページネーションで返却され、最初のページを処理しながら後続のページを取得できます。

⚡ 主要機能

1. 📊 結果数上限の 100 倍拡張
  • 類似検索結果数が最大 100 件 → 最大 10,000 件へ拡張
  • QueryVectors API の topK パラメータで最大 10,000 を指定可能
  • より広範な候補集合を 1 回のクエリで取得
2. 📄 ページネーション対応
  • レスポンスに nextToken が追加され、結果をページ単位で取得
  • 最初のページを処理しながら後続ページを取得する並行処理が可能
  • 大量結果のメモリ効率とレイテンシ管理に寄与
3. 🔗 多段階検索パイプラインの強化
  • リランキング・集約・重複排除などの後段処理に十分な候補数を供給
  • 候補取得とフィルタリングを分離した検索アーキテクチャを構築しやすい

🧪 QueryVectors API のリクエスト / レスポンス例

PythontopK と nextToken の指定
# QueryVectors リクエスト (topK と nextToken を指定)
response = client.query_vectors(
    vectorBucketName='string',
    indexName='string',
    topK=10000,                # 最大 10,000 件まで指定可能
    queryVector={'float32': [ ... ]},
    returnMetadata=True,
    returnDistance=True,
    nextToken='string'         # 後続ページ取得用 (任意)
)

# レスポンス (nextToken が付与される)
# {
#     'vectors': [
#         {'distance': ..., 'key': 'string', 'metadata': {...}},
#     ],
#     'distanceMetric': 'cosine',
#     'nextToken': 'string'    # 次ページが存在する場合に返却される
# }

QueryVectors API に nextToken が追加され、リクエストでページ継続トークンを指定し、レスポンスで次ページの有無を判定できます。

前提条件

✓ベクトルバケットとベクトルインデックスが作成済みであること
✓最新の AWS SDK を利用していること

Python最大 10,000 件を要求
response = client.query_vectors(

    returnDistance=True
)

ステップ 3: ページネーション処理

PythonnextToken でループ取得
next_token = None
while True:
    kwargs = {
        'vectorBucketName': 'my-vector-bucket',
        'indexName': 'my-index',
        'topK': 10000,
        'queryVector': {'float32': query_embedding},
        'returnMetadata': True,
    }
    if next_token:
        kwargs['nextToken'] = next_token
    response = client.query_vectors(**kwargs)
    # ここで response['vectors'] を処理 (リランキング、重複排除など)
    next_token = response.get('nextToken')
    if not next_token:
        break

レスポンスの nextToken を用いて後続ページを取得し、ページごとに後段処理を行います。次ページが存在しない場合は nextToken が返却されないためループを終了します。

💡 メリットと制約

👍 メリット

✓検索品質の向上: 広範な候補集合を取得し後段処理で精度を高められる
✓開発工数の削減: 複数クエリの結合処理が不要に
✓コスト効率: 返却データの最初の 512 KB が無料、低コストストレージで大規模検索
✓多段階検索の実現: 1 回のクエリベースでパイプラインを構築
✓パフォーマンス管理: ページネーションでメモリとレイテンシを制御
✓シンプルな API: topK と nextToken の指定だけで利用可能

⚠️ 制約・考慮点

!1 クエリあたりの結果数上限は最大 10,000 件
!512 KB を超える返却データには少額のデータ返却料金が発生
!最新の AWS SDK が必要 (古い SDK では新上限を利用できない場合あり)
!topK を大きくすると料金とレイテンシへの影響を考慮する
!nextToken のループ制御を確実に実装する必要がある

🎯 ユースケース

1. RAG におけるリランキング前の候補拡大

シナリオ: 検索拡張生成 (RAG) のパイプラインで、リランキングモデルに渡す候補ドキュメントをより多く取得したい。

Python
# 1 クエリで大量候補を取得し、後段のリランカーへ渡す
candidates = client.query_vectors(
    vectorBucketName='docs-bucket',
    indexName='docs-index',
    topK=2000,
    queryVector={'float32': query_embedding},
    returnMetadata=True
)['vectors']
# reranker.rerank(candidates) で上位を選定
✨ 効果: リランキング対象の候補数が増え、最終的な回答の関連性と網羅性が向上。
2. 重複排除を伴う大規模検索

シナリオ: 類似コンテンツが多いデータセットで、重複を排除した多様な結果集合を提示したい。

Python
results = client.query_vectors(
    vectorBucketName='media-bucket',
    indexName='media-index',
    topK=5000,
    queryVector={'float32': query_embedding},
    returnMetadata=True
)['vectors']
# メタデータを用いて重複排除を実施し、多様な結果を抽出
✨ 効果: 十分な候補数から重複を取り除き、多様性のある検索結果を提示。
3. 集約分析のための広範なベクトル取得

シナリオ: クエリベクトルに近い大量のアイテムを集約し、傾向分析やクラスタリングを行いたい。

Python
# ページネーションで最大 10,000 件まで取得し集約処理を実施
next_token = None
all_vectors = []
while True:
    resp = client.query_vectors(
        vectorBucketName='analytics-bucket',
        indexName='items-index',
        topK=10000,
        queryVector={'float32': query_embedding},
        returnMetadata=True,
        **({'nextToken': next_token} if next_token else {})
    )
    all_vectors.extend(resp['vectors'])
    next_token = resp.get('nextToken')
    if not next_token:
        break
✨ 効果: 広範な近傍アイテムを取得して集約でき、より精緻な分析結果を得られる。

💰 料金

このアップデート自体に追加の基本料金は発生しません。大規模なクエリでは返却される結果の合計サイズに応じた少額のデータ返却料金が適用されます。1 クエリあたり返却データの最初の 512 KB は無料です。

使用量月額料金 (概算)
1 クエリあたり返却データ 512 KB 以内データ返却料金は無料
512 KB を超える返却データ超過分にデータ返却料金が発生 (詳細は料金ページ参照)
