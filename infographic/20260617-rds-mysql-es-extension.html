MySQL 5.7 の Extended Support を
2029 年 6 月まで延長

📅 リリース日
2026 年 6 月 17 日

📌 概要

AWS は、Amazon Aurora MySQL 互換エディションおよび Amazon RDS for MySQL における MySQL 5.7 の RDS Extended Support 終了日を、従来の 2027 年 2 月 28 日 から 2029 年 6 月 30 日 まで延長したことを発表しました。 これにより、サポート対象メジャーバージョンへの移行を計画・完了させる時間を追加で確保できます。

RDS Extended Support は、標準サポート (コミュニティサポート) が終了したバージョンに対して、 重大度の高い CVE へのセキュリティパッチ、運用上の重大な問題へのバグ修正、 標準 SLA の範囲内での AWS サポートを提供する有償オプションです。 今回の延長は Aurora MySQL バージョン 2 (MySQL 5.7 互換) と RDS for MySQL バージョン 5.7 を対象とし、両サービスが利用可能なすべての AWS リージョンに適用されます。

🔄 アップデート前後の比較

❌ Before（更新前の課題）
  • 終了日が 2027 年 2 月 28 日で、移行計画に使える時間が限られていた
  • 大規模・複雑な依存を持つ環境では期日までの移行完了が困難
  • 終了日を過ぎるとセキュリティパッチを受けられないリスク
→
✅ After（更新後の改善）
  • 終了日が 2029 年 6 月 30 日まで延長、約 2 年 4 か月の猶予追加
  • 価格据え置き（Year 3 料金）でパッチ・バグ修正を継続享受
  • 全リージョンで追加対応なしに自動適用

延長された猶予期間中に、Blue/Green Deployments・in-place アップグレード・スナップショットリストアのいずれかの手段で MySQL 8.0 / 8.4 への移行を進めることが推奨されます。

⭐ 主要機能

1. Extended Support 終了日の延長
  • 終了日が 2027 年 2 月 28 日から 2029 年 6 月 30 日 へ延長
  • 対象は Aurora MySQL バージョン 2 と RDS for MySQL バージョン 5.7
  • 追加の申請や設定変更は不要で、対象バージョンに自動適用
2. 価格据え置き（3 年目料金の継続）
  • 今回の延長に伴う価格の引き上げはなし
  • 2029 年 6 月 30 日まで Year 3 の Extended Support 料金を継続
  • vCPU あたりの時間単位課金で、長期利用ほどコスト負担が増す点は不変
3. 継続的なセキュリティとサポートの提供
  • Critical / High の CVE に対するセキュリティパッチを提供
  • 運用上の重大な問題に対するバグ修正を提供
  • 標準 SLA の範囲内で AWS サポートへアクセス可能

🛠️ 設定方法（推奨アップグレード手順）

延長自体は対象バージョンに自動適用されるため追加操作は不要です。一方で AWS は MySQL 8.0 / 8.4 互換バージョンへの移行を推奨しています。

前提条件

  • ✓ 対象が Aurora MySQL v2 または RDS for MySQL 5.7 であることを確認
  • ✓ アプリケーションが MySQL 8.0 / 8.4 と互換性があるか事前検証
  • ✓ アップグレード前にスナップショットを取得しロールバック手段を確保

ステップ 1: 現在の対象 DB を確認する

BashMySQL 5.7 系インスタンスの一覧
aws rds describe-db-instances \
  --query "DBInstances[?starts_with(EngineVersion, '5.7')].[DBInstanceIdentifier,EngineVersion]" \
  --output table

エンジンバージョンが 5.7 で始まるインスタンスを抽出し、移行対象の棚卸しに利用します。

ステップ 2: Blue/Green Deployments で移行する

BashBlue/Green デプロイメントの作成
aws rds create-blue-green-deployment \
  --blue-green-deployment-name mysql57-to-80 \
  --source <既存DBインスタンスのARN> \
  --target-engine-version 8.0.<マイナーバージョン>

本番 (Blue) のクローンとなる Green を作成して 8.0 へアップグレードし、検証後に切り替えることでダウンタイムを最小化します。

ステップ 3: in-place / スナップショットリストアを選択する

  • in-place アップグレード: modify-db-instance でバージョン指定。手順はシンプルだがアップグレード中はダウンタイムが発生
  • スナップショットリストア: 既存スナップショットから新バージョンで復元。元環境を残したまま移行先を構築

✅ メリット

ビジネス面

  • ✓移行猶予の確保: 約 2 年 4 か月延長され、大規模・複雑な環境でも余裕を持った計画が可能
  • ✓追加コストの回避: 価格引き上げがなく、想定外のコスト増を避けられる
  • ✓コンプライアンス維持: 延長期間中もパッチを受けられ、要件を満たし続けられる

技術面

  • ✓継続的なセキュリティ対応: Critical / High CVE パッチで既知の脆弱性リスクを低減
  • ✓運用の安定性: 運用上の重大な問題へのバグ修正が継続提供
  • ✓全リージョン対応: 対象バージョンに自動適用され、地域ごとの個別対応が不要

⚠️ デメリット・制約事項

制限事項

  • ✗延長対象は MySQL 5.7 互換バージョン（Aurora MySQL v2、RDS for MySQL 5.7）のみ
  • ✗有償オプションのため、延長期間中も 3 年目料金の課金が継続
  • ✗提供は CVE パッチと重大問題のバグ修正に限られ、新機能の追加は含まれない

考慮すべき点

  • →あくまで移行までの猶予であり、最終的に MySQL 8.0 / 8.4 への移行が必要
  • →料金は通常の DB 利用料金に上乗せされ、長期利用ほど負担が大きい
  • →新機能・性能改善は 8.0 / 8.4 のみ。移行を先送りするほど機会損失が生じる

💡 ユースケース

1. 大規模本番環境の段階的移行

シナリオ: 多数のアプリが依存する大規模な MySQL 5.7 本番 DB を運用しており、2027 年 2 月までの移行完了が困難だった。

① 延長で 2029 年 6 月まで猶予確保 → ② 開発・ステージングから順次 8.0 へ移行・検証 → ③ Blue/Green で本番を低ダウンタイム切り替え

効果: 互換性を十分に検証しながら、リスクを抑えた段階的移行が可能。
2. コンプライアンス要件下でのセキュリティ維持

シナリオ: 要件により、サポート外バージョンの運用が許されない。

① Extended Support を継続し CVE パッチ適用 → ② 延長期間中に移行計画を策定・実行 → ③ 移行完了後に Extended Support を終了

効果: 移行作業中もパッチ適用を継続でき、コンプライアンス要件を満たし続けられる。
3. コストを意識した移行タイミングの最適化

シナリオ: 料金負担を抑えつつ、移行リソースと予算を計画的に配分したい。

① 価格据え置きを前提に予算を再計画 → ② 優先度の高いワークロードから 8.0 / 8.4 へ移行 → ③ 課金期間をできる限り短縮

効果: 価格引き上げのない延長を活用し、リソースと予算を無理なく配分できる。

💰 料金

今回の延長に伴う価格引き上げはありません。2029 年 6 月 30 日まで、引き続き 3 年目 (Year 3) の RDS Extended Support 料金を支払います。 Extended Support は DB インスタンスの vCPU 数に基づく時間単位の追加料金として課金され、 延長期間中は最も高い 3 年目料金が適用される点に注意が必要です。

使用量月額料金（概算）
MySQL 5.7 (Extended Support 適用)vCPU 単価 × vCPU 数 × 稼働時間が通常料金に上乗せ
MySQL 8.0 / 8.4 へ移行後✓ Extended Support 料金は発生しない

正確な単価はリージョンやエンジンによって異なるため、最新の料金は公式の料金ページで確認してください。

🌐 利用可能リージョン・関連サービス

Aurora MySQL および RDS for MySQL が利用可能なすべての AWS リージョンで、今回の延長が適用されます。

関連サービス・機能

  • Amazon RDS Blue/Green Deployments: 本番影響を最小限に抑えて 8.0 / 8.4 へアップグレードする推奨手段
  • Amazon RDS for MySQL: バージョン 5.7 が延長対象。8.0 / 8.4 が移行先
  • Amazon Aurora MySQL: バージョン 2 (5.7 互換) が延長対象。バージョン 3 (8.0 互換) が移行先

🎯 まとめ

MySQL 5.7 の RDS Extended Support 終了日が 2029 年 6 月 30 日まで価格据え置きで延長 されたことで、 より余裕を持って MySQL 8.0 / 8.4 への移行を計画・実行できるようになりました。 Extended Support はあくまで移行までの猶予を提供するものであるため、延長期間に頼り切るのではなく、 Blue/Green Deployments などを用いた計画的な移行を早期に進めることを推奨します。
