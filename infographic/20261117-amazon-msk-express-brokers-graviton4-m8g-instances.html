⚡ Express Brokers が Graviton4 ベースの M8g インスタンスをサポート

📅 リリース日: 2026 年 11 月 17 日 | Amazon Managed Streaming for Apache Kafka

📝 概要

Amazon MSK の Express Brokers で、AWS Graviton4 ベースの M8g インスタンスが一般提供されました。M7g ベースと比較して、 コンピュートコストと produce レイテンシーが改善し、クロス AZ データ転送のブローカー側料金が不要になります。 データ転送料金とブローカー時間料金の低減を合わせると、最大 30% のコスト削減を実現します。

❌ アップデート前の課題

  • Express Brokers は M7g のみで、最新世代 Graviton4 の性能向上を活用できなかった
  • クロス AZ データ転送でクライアント側とブローカー側の両方に料金が発生し、マルチ AZ 構成でコストが大きな割合を占めていた
  • 遅延したコンシューマーのキャッチアップ速度に制約があり、障害復旧やリプレイに時間がかかる場合があった

✅ アップデート後の改善

  • M7g 比でコンピュートコスト 15% 低減、P99 produce レイテンシー最大 45% 低減
  • ブローカー側のクロス AZ 転送料金が不要になり、総転送コストが 50% 削減
  • 遅延コンシューマーのキャッチアップが 2 倍高速になり、復旧・リプレイが迅速に
  • 既存 M7g クラスターからクライアント無停止でインプレース移行が可能

M8g 上の Express Brokers への 2 つの移行パス (既存 M7g クラスターからのインプレース移行、MSK Replicator による外部クラスターからの移行) と、性能・コスト面の主要な改善点を示しています。

🚀 主要機能

🧠 Graviton4 ベース M8g インスタンスによる性能向上

  • M7g 上の Express Brokers と比較してコンピュートコストが 15% 低減
  • P99 の produce レイテンシーが最大 45% 低減し、テールレイテンシーが改善
  • 遅延したコンシューマーのキャッチアップ (過去データの読み取り) が 2 倍高速化

💰 クロス AZ データ転送コストの削減

  • クライアントとブローカー間で AZ をまたぐ転送のブローカー側料金が不要に
  • クロス AZ データ転送の総コストが 50% 削減
  • データ転送料金とブローカー時間料金の低減を合わせ、M7g 比で最大 30% のコスト削減

⚡ Express Brokers の既存の優位性を継承

  • Standard Brokers と比較してブローカーあたり最大 3 倍のスループット
  • 最大 20 倍高速なスケーリング、復旧時間を 90% 短縮
  • ストレージ管理が不要なアーキテクチャなど、既存の Express 機能をそのまま利用可能

🔀 柔軟な移行オプション

  • 既存の M7g クラスターからは、クライアントが produce / consume を継続したままインプレース移行が可能
  • オンプレミス、セルフマネージド、他クラウドの外部 Kafka クラスターからは、Amazon MSK Replicator でシームレスに移行可能

⚙️ 設定方法

📋 前提条件

✓MSK Express Brokers と M8g インスタンスの両方が利用可能なリージョンを使用していること
✓Amazon MSK クラスターの作成・更新を行う IAM 権限があること
✓外部クラスターから移行する場合は、MSK Replicator を構成するためのネットワーク接続と権限があること

ステップ 1: M8g の Express Brokers で新規クラスターを作成

Bash 新規クラスター作成 
aws kafka create-cluster-v2 \
  --cluster-name my-express-m8g-cluster \
  --provisioned '{
    "BrokerNodeGroupInfo": {
      "InstanceType": "express.m8g.large",
      "ClientSubnets": ["subnet-xxxxxxxx", "subnet-yyyyyyyy", "subnet-zzzzzzzz"],
      "SecurityGroups": ["sg-xxxxxxxx"]
    },
    "KafkaVersion": "3.6.0",
    "NumberOfBrokerNodes": 3
  }'

M8g ベースの Express Brokers を指定して新しい MSK クラスターを作成します。インスタンスタイプやブローカー数はワークロードに応じて選択してください。AWS Management Console からも作成できます。

ステップ 2: 既存の M7g クラスターをインプレース移行 (既存ユーザーの場合)

Bash ブローカータイプの更新 
aws kafka update-broker-type \
  --cluster-arn arn:aws:kafka:ap-northeast-1:123456789012:cluster/my-cluster/xxxx \
  --current-version K3AEGXETSR30VB \
  --target-instance-type express.m8g.large

既存の M7g クラスターのブローカータイプを M8g に更新します。移行中もクライアントアプリケーションは中断なく produce / consume を継続できます。

ステップ 3: 外部 Kafka クラスターから MSK Replicator で移行 (外部クラスターの場合)

Bash MSK Replicator の作成 
aws kafka create-replicator \
  --replicator-name migrate-to-express-m8g \
  --kafka-clusters '[{"AmazonMskCluster": {"MskClusterArn": "arn:aws:kafka:...:cluster/source/..."}, "VpcConfig": {...}}, {"AmazonMskCluster": {"MskClusterArn": "arn:aws:kafka:...:cluster/target-m8g/..."}, "VpcConfig": {...}}]' \
  --replication-info-list '[{"SourceKafkaClusterArn": "...", "TargetKafkaClusterArn": "...", "TargetCompressionType": "NONE", "TopicReplication": {"TopicsToReplicate": [".*"]}, "ConsumerGroupReplication": {"ConsumerGroupsToReplicate": [".*"]}}]' \
  --service-execution-role-arn arn:aws:iam::123456789012:role/msk-replicator-role

MSK Replicator で移行元クラスターからトピックとコンシューマーグループをレプリケーションし、完了後にクライアントを新クラスターへ切り替えることでシームレスに移行できます。

💡 メリット

💼 ビジネス面

✓最大 30% のコスト削減: ブローカー時間料金の低減とクロス AZ データ転送料金の削減により、M7g 比でトータルコストを最大 30% 削減
✓移行リスクの低減: クライアント無停止のインプレース移行により、ビジネスへの影響を最小限に抑えながら新世代インスタンスの恩恵を受けられる
✓外部クラスターからの移行促進: MSK Replicator により、オンプレミスや他クラウドの Kafka からの移行が容易になり、運用負荷の削減とコスト最適化を同時に実現

🔧 技術面

✓低レイテンシー: P99 produce レイテンシーが最大 45% 低減し、リアルタイム性が求められるストリーミングアプリケーションの応答性が向上
✓高速なキャッチアップ: 遅延したコンシューマーの読み取りが 2 倍高速になり、障害復旧やデータリプレイの所要時間が短縮
✓Express アーキテクチャの継承: 最大 3 倍のスループット、最大 20 倍高速なスケーリング、90% 短い復旧時間をそのまま活用可能

⚠️ デメリット・制約事項

制限事項

✗M8g の Express Brokers は、MSK Express Brokers と M8g インスタンスの両方が利用可能なリージョンに限定される
✗Express Brokers 自体の機能特性 (Standard Brokers との構成上の違い) は従来どおりで、Standard Brokers からの移行には構成の見直しが必要になる場合がある

考慮すべき点

⚠利用予定のリージョンで M8g の Express Brokers が提供されているかを事前に確認する
⚠インプレース移行はクライアント無停止だが、本番環境での実施前に検証環境での動作確認を推奨
⚠クロス AZ 転送コストの削減効果は AZ 配置やトラフィックパターンによって異なるため、自環境での削減額の試算が望ましい

🎯 ユースケース

1️⃣ 既存 M7g クラスターのコスト最適化

シナリオ: M7g 上の Express Brokers で大規模なストリーミング基盤を運用しており、クラスターの停止を伴わずにコストを削減したい。

実装: UpdateBrokerType API または AWS Management Console から既存クラスターのブローカータイプを express.m8g 系へ変更し、クライアントを稼働させたままインプレース移行する。

✅ 効果: produce / consume を中断することなく、ブローカー時間料金とクロス AZ 転送料金を合わせて最大 30% のコスト削減を実現。

2️⃣ マルチ AZ 構成でのデータ転送コスト削減

シナリオ: 高可用性のためにプロデューサー・コンシューマーを複数 AZ に分散配置しており、クロス AZ データ転送コストが課題になっている。

実装: M8g 上の Express Brokers クラスターへ移行し、クロス AZ 転送のブローカー側料金が不要になった構成でマルチ AZ の高可用性アーキテクチャを維持する。

✅ 効果: 可用性を犠牲にすることなく、クロス AZ データ転送の総コストを 50% 削減。

3️⃣ 外部 Kafka クラスターからの移行

シナリオ: オンプレミスや他クラウドでセルフマネージドの Apache Kafka を運用しており、運用負荷の削減と価格性能の改善のためにマネージドサービスへ移行したい。

実装: M8g 上の Express Brokers で新規クラスターを作成し、Amazon MSK Replicator でトピックとコンシューマーグループをレプリケーション後、クライアントを切り替える。

✅ 効果: ストレージ管理不要の Express アーキテクチャと M8g の価格性能を即座に活用でき、運用負荷とコストの両方を削減。

💰 料金・利用可能リージョン

M8g 上の Express Brokers は、ブローカー時間とストレージなどに基づく MSK の料金体系に従います。 M7g と比較してコンピュートコストが 15% 低く、クライアントとブローカー間のクロス AZ データ転送におけるブローカー側の料金が不要になります。

🌍 利用可能リージョン: MSK Express Brokers と M8g インスタンスの両方が利用可能なすべての AWS リージョンで利用できます。 最新の対応状況は AWS リージョン別サービス一覧 を参照してください。

詳細な料金は Amazon MSK 料金ページ を参照してください。

📌 まとめ

Amazon MSK Express Brokers が Graviton4 ベースの M8g インスタンスに対応し、M7g 比で コンピュートコスト 15% 削減、P99 produce レイテンシー最大 45% 低減、 クロス AZ データ転送コスト 50% 削減により、トータルで最大 30% のコスト削減を実現できるようになりました。

既存の M7g クラスターを運用している場合はクライアント無停止のインプレース移行を、外部 Kafka クラスターを運用している場合は MSK Replicator による移行を検討し、価格性能の改善を早期に取り込むことを推奨します。
