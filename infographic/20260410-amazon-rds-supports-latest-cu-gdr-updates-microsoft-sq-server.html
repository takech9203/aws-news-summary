📋 概要

Amazon RDS for SQL Server が、Microsoft SQL Server の最新の累積更新プログラム (CU) および一般配布リリース (GDR) のサポートを開始しました。SQL Server 2016、2017、2019、2022 の 4 バージョンに対するアップデートが提供されています。GDR アップデートにはセキュリティ脆弱性に対処する修正が含まれており、AWS Management Console、SDK、または CLI から簡単にアップグレードできます。

Before / After

❌ Before
  • CVE-2026-21262 / CVE-2026-26115 の脆弱性が存在し、攻撃リスクあり
  • 最新の CU 未適用でバグ修正やパフォーマンス改善を利用不可
  • セキュリティコンプライアンスのためパッチ適用状況を手動追跡
✅ After
  • 2 件の CVE 脆弱性が修正され、インスタンスのセキュリティが向上
  • 最新 CU でバグ修正、パフォーマンス改善、機能強化を利用可能
  • Console / SDK / CLI から簡単にアップグレードし運用負荷を削減

⚡ 主要機能

🔒
CVE-2026-21262 / CVE-2026-26115 の修正
GDR アップデートにより 2 件のセキュリティ脆弱性に対処。SQL Server 2016 SP3、2017、2019 の GDR に含まれる Microsoft セキュリティ勧告に基づいた緊急パッチです。
📦
SQL Server 2022 CU24 サポート
KB5080999 (ビルド 16.00.4245.2.v1) を RDS で利用可能。バグ修正、パフォーマンス改善、機能強化を含む最新の累積更新プログラムです。
📊
4 バージョンの包括的アップデート
SQL Server 2016 SP3+GDR、2017 CU31+GDR、2019 CU32+GDR、2022 CU24。レガシーバージョンを含む幅広いサポートを提供します。
🚀
簡単なアップグレードプロセス
AWS Management Console から数クリックで、または CLI/SDK で自動化可能。メンテナンスウィンドウ中の自動アップグレード設定にも対応します。

前提条件

  1. Amazon RDS for SQL Server のインスタンスが稼働している
  2. AWS Management Console へのアクセス権限、または AWS CLI/SDK の設定が完了している
  3. アップグレード前のバックアップが取得済み (推奨)

ステップ 1: バックアップの作成

Bash 手動スナップショットを作成 
# 手動スナップショットを作成
aws rds create-db-snapshot \
  --db-instance-identifier mydbinstance \
  --db-snapshot-identifier mydbinstance-pre-cu-gdr-snapshot

ステップ 2: Console からアップグレード

  1. AWS Management Console を開き、Amazon RDS サービスに移動
  2. ナビゲーションペインで「データベース」を選択
  3. アップグレードするデータベースインスタンスを選択
  4. 「変更」ボタンをクリック
  5. 「DB エンジンのバージョン」で新しいバージョンを選択
  6. 「すぐに適用」または「次のメンテナンスウィンドウ中に適用」を選択
  7. 「データベースの変更」をクリック

ステップ 2 (代替): CLI からアップグレード

Bash AWS CLI を使用した RDS インスタンスのアップグレード 
# SQL Server 2022 CU24 にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier mydbinstance \
  --engine-version 16.00.4245.2.v1 \
  --apply-immediately

# SQL Server 2019 CU32+GDR にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier mydbinstance \
  --engine-version 15.00.4460.4.v1 \
  --apply-immediately

ステップ 3: アップグレードの確認

Bash 進行状況の確認 
# アップグレードの進行状況を確認
aws rds describe-db-instances \
  --db-instance-identifier mydbinstance \
  --query 'DBInstances[0].[EngineVersion,DBInstanceStatus]'

ステップ 4: アプリケーションのテスト

SQL アプリケーションの動作確認 
-- アプリケーションの主要な機能をテスト
SELECT TOP 10 * FROM YourTable;

-- エラーログを確認
EXEC sp_readerrorlog;

-- パフォーマンスへの影響を確認
SELECT TOP 20
    qs.total_elapsed_time / qs.execution_count AS avg_elapsed_time,
    qs.execution_count,
    SUBSTRING(qt.text, 1, 100) AS query_text
FROM sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) qt
ORDER BY avg_elapsed_time DESC;

⚖️ メリット / 制約事項

✅ メリット

ビジネス面

  • CVE-2026-21262 / CVE-2026-26115 修正でデータ侵害リスクを削減
  • PCI DSS、SOC 2、HIPAA 等のコンプライアンス要件を維持
  • 安定バージョンで予期しないダウンタイムを防止

技術面

  • 2 件の CVE を 1 回のアップグレードで同時修正
  • CU に含まれるパフォーマンス最適化を利用可能
  • 既知のバグが修正されシステム安定性が向上
  • Console / CLI から簡単にアップグレード可能

⚠️ 制約事項

制限事項

  • アップグレード中はインスタンスが一時的に利用不可 (数分~数十分)
  • ダウングレードは直接サポートされない (スナップショット復元が必要)
  • Multi-AZ でもフェイルオーバーが発生し短時間のダウンタイムあり

考慮すべき点

  • テスト環境で事前に互換性を確認することを強く推奨
  • ビジネスに影響の少ない時間帯にアップグレードを計画
  • クエリプラン変更の可能性があるためパフォーマンスを監視
  • セキュリティパッチの緊急性を考慮し適用タイミングを判断

💡 ユースケース

🏢 ユースケース 1: 本番環境のセキュリティパッチ適用
本番環境で Amazon RDS for SQL Server 2019 を使用しており、CVE-2026-21262 および CVE-2026-26115 のセキュリティ脆弱性に対処する必要がある。
Bash メンテナンスウィンドウ中にアップグレード 
# 1. 手動スナップショットを作成
aws rds create-db-snapshot \
  --db-instance-identifier prod-sqlserver-2019 \
  --db-snapshot-identifier prod-sqlserver-2019-pre-gdr

# 2. メンテナンスウィンドウ中にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier prod-sqlserver-2019 \
  --engine-version 15.00.4460.4.v1 \
  --no-apply-immediately
→ メンテナンスウィンドウ中にセキュリティパッチが自動適用され、ビジネスへの影響を最小限に抑えながら 2 件の CVE リスクを軽減
🚀 ユースケース 2: SQL Server 2022 の最新 CU への更新
SQL Server 2022 を使用しており、最新の CU24 に含まれるバグ修正とパフォーマンス改善を適用したい。
Bash 即時アップグレード 
# SQL Server 2022 を CU24 にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier prod-sqlserver-2022 \
  --engine-version 16.00.4245.2.v1 \
  --apply-immediately
→ CU24 のバグ修正とパフォーマンス改善により、システムの安定性と処理効率が向上
🧪 ユースケース 3: 開発環境での事前検証
GDR アップデートを本番環境に適用する前に、開発環境で互換性を検証したい。
Bash 開発環境で検証 
# 開発環境を即座にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier dev-sqlserver \
  --engine-version 15.00.4460.4.v1 \
  --apply-immediately

# アプリケーションのテストスイートを実行して互換性を確認
→ 開発環境で事前検証を行い、互換性やパフォーマンスへの影響を本番適用前に確認。問題発見時は本番ロールアウトを延期し修正可能
