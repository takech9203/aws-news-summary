AWS Service Catalog

☁️ Asia Pacific (ニュージーランド) & Canada West (カルガリー) リージョン対応

2026-05-08
リージョン拡大

📋 概要

AWS Service Catalog が Asia Pacific (New Zealand) - ap-southeast-5 および Canada West (Calgary) - ca-west-1 で利用可能に。ニュージーランドおよびカナダ西部のユーザーは、より低レイテンシーで承認済み IaC 製品のカタログを作成・管理・配布できるようになった。

❌ Before

  • 地理的に離れたリージョンでの利用が必要でレイテンシーが高かった
  • データレジデンシー要件により近隣リージョンに配置できないケースがあった
  • マルチリージョン展開で IaC ガバナンスの一元管理が困難

✅ After

  • 低レイテンシーで Service Catalog にアクセス可能
  • データレジデンシー要件を満たしながら IaC ガバナンス管理が可能
  • AWS Organizations と連携したグローバルなポートフォリオ共有を実現

⚡ 主要機能

📋
IaC 製品カタログの管理
CloudFormation / Terraform で製品を定義。単一インスタンスからマルチティアアプリまで対応。バージョン管理でライフサイクルを管理。
🔒
ガバナンスとアクセス制御
ポートフォリオ単位のアクセス権限管理。制約設定によるデプロイ条件制御。IAM ロール連携の最小権限プロビジョニング。
🌐
クロスアカウント共有
AWS Organizations を通じたポートフォリオ共有。OU レベル一括配布。数千アカウントへスケーラブルに展開。

🔧 技術仕様

対応リージョン

リージョン名 リージョンコード 所在地
Asia Pacific (New Zealand) ap-southeast-5 ニュージーランド
Canada West (Calgary) ca-west-1 カナダ・カルガリー

サポートされる IaC ツール

ツール 説明
AWS CloudFormation AWS ネイティブの IaC サービス
HashiCorp Terraform Open Source オープンソースの IaC ツール
Terraform Cloud Terraform のマネージドサービス

🛠️ 設定方法

前提条件

✓AWS アカウントが有効であること
✓該当リージョンへのアクセスが有効化されていること
✓AWSServiceCatalogAdminFullAccess 権限を持つ IAM ユーザー/ロール

ステップ 1: リージョンの選択

Bash リージョン指定 
# AWS CLI でリージョンを指定
export AWS_DEFAULT_REGION=ap-southeast-5
# または
export AWS_DEFAULT_REGION=ca-west-1

ステップ 2: ポートフォリオの作成

Bash ポートフォリオ作成 
aws servicecatalog create-portfolio \
  --display-name "My Portfolio" \
  --provider-name "IT Department" \
  --description "Approved IaC products for deployment"

ステップ 3: 製品の作成と登録

Bash 製品作成 
aws servicecatalog create-product \
  --name "Web Application Stack" \
  --owner "IT Department" \
  --product-type CLOUD_FORMATION_TEMPLATE \
  --provisioning-artifact-parameters \
    Name="v1.0",Info={LoadTemplateFromURL=https://s3.amazonaws.com/mybucket/template.yaml},Type=CLOUD_FORMATION_TEMPLATE

✅ メリット

💼 ビジネス面

✓データレジデンシーの遵守: ニュージーランド/カナダの規制要件に準拠
✓レイテンシーの削減: 地理的に近いリージョンでレスポンス向上
✓グローバル展開の加速: マルチリージョン戦略の対象拡大

⚙️ 技術面

✓一貫したガバナンス: 全リージョンで統一 IaC 製品管理
✓AWS Organizations 連携: 新リージョンでもクロスアカウント共有
✓Terraform サポート: CloudFormation に加え Terraform も管理可能

⚠️ 制約事項・考慮点

制限事項
!既存リージョンのポートフォリオは自動的に複製されない
!リージョン間でのポートフォリオ共有には追加設定が必要
!一部 AWS サービスが新リージョンで未対応の場合、テンプレート内で使用不可のリソースがある可能性
考慮すべき点
!既存のマルチリージョン展開パイプラインに追加する際はテンプレート互換性を確認
!新リージョンでの依存サービスの対応状況を事前確認すること

🎯 ユースケース

🇳🇿 NZ データレジデンシー対応
ニュージーランドの金融機関が規制要件により国内にデータを保持。ap-southeast-5 でポートフォリオを作成し、データレジデンシー要件を満たしながらセルフサービスデプロイを実現。
🇨🇦 カナダ西部 DR 構成
カナダ東部 ca-central-1 をプライマリ、カナダ西部 ca-west-1 を DR サイトとして構成。カナダ国内でのリージョン間 DR を Service Catalog で一元管理。
🌐 グローバルポートフォリオ共有
グローバル企業が AWS Organizations を使用し、新リージョンを含む全拠点に標準化された製品を配布。開発チームが即座に承認テンプレートを利用可能。

ユースケース実装例

Bash NZ コンプライアント製品ポートフォリオ 
# ニュージーランドリージョンでのポートフォリオ作成
aws servicecatalog create-portfolio \
  --display-name "NZ Compliant Products" \
  --provider-name "Cloud Team" \
  --region ap-southeast-5
Bash Organizations を通じたポートフォリオ共有 
# Organizations を通じたポートフォリオ共有
aws servicecatalog create-portfolio-share \
  --portfolio-id port-xxxxxxxxx \
  --organization-node Type=ORGANIZATION,Value=o-xxxxxxxxxx

💰 料金

AWS Service Catalog 自体の利用に追加料金は発生しない。プロビジョニングされた AWS リソースの使用量に基づいて課金。

項目 料金
Service Catalog の利用 無料
プロビジョニングされたリソース 各サービスの標準料金
