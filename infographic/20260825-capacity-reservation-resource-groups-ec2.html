Capacity Reservation Resource Groups が
Capacity Blocks と中断可能な予約をサポート

📅 リリース日: 2026 年 8 月 25 日 ｜ すべてのキャパシティ予約タイプを 1 つのグループで一元管理

📌 概要

Amazon EC2 の Capacity Reservation Resource Groups が、 EC2 Capacity Blocks for ML と 中断可能なキャパシティ予約 をサポートしました。 これまでオンデマンドキャパシティ予約 (ODCR) のみをグループ化できましたが、 今回のアップデートですべての予約タイプを任意の組み合わせで 1 つのグループに含められます。

単一のグループ ARN を指定するだけで、予約済みキャパシティのポートフォリオ全体を対象にインスタンスを起動可能。 EC2 Fleet / Auto Scaling グループでは、予約タイプ間の優先順位付けと、 枯渇時のオンデマンドへの自動フォールバックも設定できます。

🟦 ODCRオンデマンドキャパシティ予約 (従来から対応)
🟩 Capacity Blocks for ML今回新たにサポート
🟨 中断可能な予約今回新たにサポート
❌ Before: アップデート前の課題
  • グループ化できるのは ODCR のみで、Capacity Blocks や中断可能な予約は対象外
  • 予約タイプごとに起動ターゲットを個別指定する必要があり、運用が複雑
  • Capacity Blocks と ODCR の併用時に、キャパシティ消費順序を制御する統一的な仕組みがなかった
✅ After: アップデート後の改善
  • ODCR、Capacity Blocks for ML、中断可能な予約を任意の組み合わせで 1 グループに追加可能
  • 単一のグループ ARN 指定でポートフォリオ全体からインスタンスを起動
  • EC2 Fleet / Auto Scaling で優先順位付けとオンデマンドへの自動フォールバックを設定可能

複数タイプのキャパシティ予約を 1 つのリソースグループにまとめ、単一の ARN をターゲットとしてインスタンスを起動するフローです。 EC2 Fleet や Auto Scaling グループでは、優先順位付けとオンデマンドへの自動フォールバックを設定できます。

⚙️ 主要機能

1️⃣ 全予約タイプのグループ化
  • ODCR に加えて、EC2 Capacity Blocks for ML と中断可能なキャパシティ予約をグループに追加可能
  • 任意の組み合わせで複数の予約タイプを 1 つのグループに混在可能
  • 自アカウント所有の予約と、他アカウントから共有された予約を同一グループに含めることも可能
2️⃣ 単一 ARN によるポートフォリオ全体への起動
  • グループ ARN の指定だけで、属性が一致し空きキャパシティのある予約に自動マッチング
  • インスタンスタイプ、プラットフォーム、AZ、テナンシー、プレイスメントグループが異なる予約も同一グループに追加可能
3️⃣ EC2 Fleet / Auto Scaling での優先順位付けとフォールバック
  • ReservedCapacityOptions により割り当て戦略 (prioritized) を設定可能
  • 予約タイプとして capacity-block と on-demand-capacity-reservation を指定可能
  • 予約枯渇時のオンデマンド自動フォールバック (ReservedCapacityFallbackOptions) を設定可能

🛠️ 設定方法

前提条件

✓利用するリージョンで Capacity Blocks for ML および中断可能な ODCR がサポートされていること
✓AWS Resource Groups でグループを作成・管理する IAM 権限があること
✓グループに追加するキャパシティ予約 (ODCR、Capacity Blocks、中断可能な予約) が作成済みであること

手順

1
Capacity Reservation Resource Group を作成する
BashAWS CLI
aws resource-groups create-group \
  --name my-cr-group \
  --configuration '[{"Type":"AWS::EC2::CapacityReservationPool"}]'

AWS::EC2::CapacityReservationPool タイプの設定により、キャパシティ予約専用のグループとして構成されます。

2
キャパシティ予約をグループに追加する
BashAWS CLI
aws resource-groups group-resources \
  --group my-cr-group \
  --resource-arns \
    "arn:aws:ec2:us-east-1:123456789012:capacity-reservation/cr-1234567890abcdef0" \
    "arn:aws:ec2:us-east-1:123456789012:capacity-reservation/cr-0987654321fedcba0"

ODCR、Capacity Blocks、中断可能なキャパシティ予約の ARN を指定して、任意の組み合わせでグループに追加します。

3
グループをターゲットにインスタンスを起動する
BashAWS CLI
aws ec2 run-instances \
  --image-id ami-0123456789abcdef0 \
  --instance-type p5.48xlarge \
  --count 1 \
  --capacity-reservation-specification \
    'CapacityReservationTarget={CapacityReservationResourceGroupArn=arn:aws:resource-groups:us-east-1:123456789012:group/my-cr-group}'

グループ内で属性が一致し空きキャパシティのある予約にインスタンスがマッチングされます。EC2 Fleet や Auto Scaling グループでは ReservedCapacityOptions で優先順位付けとフォールバックを設定できます。

✓追加コストなし: この機能の利用に追加料金は不要
✓ML ワークロードの計画的な実行: Capacity Blocks と ODCR を組み合わせ、優先順位に基づいてコスト効率よく消費

✓柔軟なキャパシティ戦略: EC2 Fleet / Auto Scaling の優先順位付けで予約タイプ間の消費順序を制御
✓可用性の向上: 予約枯渇時のオンデマンド自動フォールバックで起動失敗を回避

⚠️ デメリット・制約事項

🚫 制限事項
✗AWS GovCloud (US) および中国リージョンでは利用不可
✗Capacity Blocks for ML と中断可能な ODCR をサポートするリージョンでのみ利用可能
✗優先順位付けとオンデマンドフォールバックは EC2 Fleet / EC2 Auto Scaling グループ使用時に設定可能
🤔 考慮すべき点
⚠中断可能な予約で起動したインスタンスは中断される可能性があり、耐障害性を考慮した設計が必要
⚠Capacity Blocks は予約期間が決まっているため、期間終了時のインスタンスの扱いを運用として計画する必要がある
⚠オンデマンドフォールバック有効時、予約枠を超えた分は通常のオンデマンド料金が発生

🎯 ユースケース

1. ML トレーニングにおける Capacity Blocks と ODCR の併用

シナリオ: ML トレーニング用に GPU インスタンスの Capacity Blocks を予約しつつ、常時稼働分は ODCR で確保。両方の予約を一元的に利用したい。

実装例
  1. Capacity Blocks と ODCR を 1 つのリソースグループに追加
  2. EC2 Fleet の ReservedCapacityOptions で AllocationStrategy=prioritized を設定
  3. ReservationTypes に capacity-block と on-demand-capacity-reservation を指定
✅ 効果: 予約タイプを意識せずに単一ターゲットでトレーニングジョブを起動でき、予約済みキャパシティの利用率が向上。
2. 予約キャパシティ枯渇時のオンデマンドフォールバック

シナリオ: Auto Scaling グループでスケールアウトする際、まず予約済みキャパシティを消費し、不足分はオンデマンドで補いたい。

実装例
  1. Auto Scaling グループの起動設定でグループ ARN をターゲットに指定
  2. ReservedCapacityFallbackOptions で MarketTypes=on-demand を設定
✅ 効果: 予約分を優先的に使い切った上で、キャパシティ不足による起動失敗を防ぎ、スケールアウトの信頼性を確保。
3. マルチアカウント環境での共有予約の一元管理

シナリオ: 組織内の複数アカウントで共有されたキャパシティ予約と自アカウントの予約を組み合わせて利用したい。

実装例
  1. 自アカウント所有の予約と、他アカウントから共有された予約を同一グループに追加
  2. 属性 (インスタンスタイプ、AZ など) が異なる予約も同一グループで管理
  3. アプリケーションは単一のグループ ARN のみを参照して起動
✅ 効果: 組織全体の予約済みキャパシティを論理的に集約し、アカウントをまたいだキャパシティの有効活用が可能。

💰 料金

この機能の利用に追加料金は発生しません。 各キャパシティ予約 (ODCR、Capacity Blocks for ML、中断可能なキャパシティ予約) 自体の料金は、それぞれの料金体系に従って課金されます。 オンデマンドフォールバックで起動したインスタンスには通常のオンデマンド料金が適用されます。

🌍 利用可能リージョン

Capacity Blocks for ML および中断可能な ODCR をサポートするすべての AWS リージョンで利用可能です。 ただし、AWS GovCloud (US) および中国リージョンは除きます。

📝 まとめ

Capacity Reservation Resource Groups がすべての予約タイプに対応したことで、 ODCR、Capacity Blocks for ML、中断可能なキャパシティ予約を単一のグループ ARN で一元管理し、 ポートフォリオ全体からインスタンスを起動できるようになりました。 特に ML ワークロードで複数の予約タイプを併用している場合は、 EC2 Fleet や Auto Scaling グループの優先順位付けとオンデマンドフォールバックの設定を検討し、 予約済みキャパシティの利用率向上と起動の信頼性確保につなげることを推奨します。
