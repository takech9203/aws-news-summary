Agent Toolkit for AWS

☁️ AWS MCP Server - 一般提供開始

AI コーディングエージェントに AWS サービスへのセキュアかつ監査可能なアクセスを提供するマネージドサーバー

2026-05-06

📋 概要

AWS MCP Server は、Model Context Protocol (MCP) を通じて AI コーディングエージェントに AWS サービスへのセキュアかつ監査可能なアクセスを提供するマネージドサーバー。re:Invent 2025 でのプレビュー開始を経て、GA (一般提供) リリースとなった。

Agent Toolkit for AWS の中核コンポーネントとして、Claude Code、Cursor、Kiro、Codex などのコーディングエージェントが AWS 上でアプリケーションを構築・デプロイ・管理する際の基盤を提供する。

300+ 対応 AWS サービス
15,000+ API アクション
無料 MCP Server 利用料

🔄 Before / After

❌ Before (アップデート前)

  • エージェントと人間のアクションを区別できず監査困難
  • AWS 知識がトレーニングデータ時点で古い
  • 正しい API を呼ぶまで試行錯誤でトークン浪費
  • 組織全体でのガードレール適用手段がない

✅ After (アップデート後)

  • IAM + CloudTrail でエージェントアクションを監査・制御
  • リアルタイムのドキュメント検索で最新情報にアクセス
  • Agent Skills で初回から正しい手順でタスク完了
  • サンドボックス環境で安全にマルチステップ操作を実行
  • ドキュメント検索は認証不要で導入障壁が低下

⚡ 主要機能

🔌 フル AWS API カバレッジ

300 以上の AWS サービス、15,000 以上の API アクションに単一ツールからアクセス可能。ローカルに AWS CLI のインストール不要。ファイルアップロードや長時間実行を必要とする操作にも対応。

🐍 サンドボックス化されたスクリプト実行

隔離された環境で Python スクリプトを実行可能。マルチステップ操作、データ処理、複雑なワークフローのオーケストレーションに対応。ローカルファイルシステムやネットワークへのアクセスは不可。

📚 リアルタイムドキュメントアクセス

最新の AWS ドキュメント、ユーザーガイド、API リファレンスを検索・取得可能。モデルのトレーニングカットオフ後にリリースされたサービスにも対応。AWS 認証情報なしで利用可能。

📋 Agent Skills

キュレートされたタスク実行手順をオンデマンドで検出・ロード。サービス選定ガイド、ステップバイステップ手順、トラブルシューティングガイドを含む。コンテキストウィンドウの使用量を最小限に抑制。

🔒 エンタープライズ制御

CloudWatch メトリクスによるエージェントアクティビティの監視。IAM コンテキストキー (aws:CalledViaAWSMCP) によるエージェント固有のポリシー適用。CloudTrail による全リクエストの監査ログ。

🚀 設定方法

前提条件

✓uv がシステムにインストールされていること (MCP プロキシに必要)
✓AWS アカウントと IAM 認証情報がローカルマシンに設定されていること
✓MCP 対応の AI コーディングエージェント (Claude Code、Cursor、Kiro、Codex など)

Claude Code の場合

Bash プラグインのインストール 
/plugin marketplace add aws/agent-toolkit-for-aws
/plugin install aws-core@agent-toolkit-for-aws
/reload-plugins

その他の MCP 対応エージェントの場合

JSON MCP サーバー設定 
{
  "mcpServers": {
    "aws": {
      "command": "uvx",
      "args": ["mcp-proxy-for-aws@latest", "https://mcp.us-east-1.amazonaws.com"]
    }
  }
}

接続の確認

エージェントに「What AWS Regions are available?」と質問する。AWS リージョンのリストが返される場合、接続は正常に動作している。

💡 ユースケース

🏗️ AWS 上でのアプリケーション構築・デプロイ

AI コーディングエージェントを使用して、サーバーレスアプリケーションを AWS 上にデプロイ。エージェントが Agent Skills を使用して適切なサービスを選択し、Well-Architected ベストプラクティスに基づいたインフラを自動構成する。

Text エージェントへの指示例 
API Gateway + Lambda + DynamoDB を使用したサーバーレス REST API を
構築してください。認証には Cognito を使用し、CloudWatch で
モニタリングを設定してください。
🤖 カスタム AI エージェントへの AWS アクセス付与

Strands、LangChain、Bedrock AgentCore などのフレームワークで構築された自律エージェントに、MCP プロトコルを通じた標準化されたインターフェースで安全に AWS API を呼び出す機能を提供。

🔍 運用トラブルシューティング

デプロイの失敗、エラー率の急上昇、予期しないコスト増加の原因調査をエージェントに依頼。CloudWatch ログ・メトリクス、CloudFormation スタックステータスを確認し、トラブルシューティング Skills を活用して問題を診断する。

⚠️ 制限事項・注意点

制限事項

✗利用可能リージョンが US East (N. Virginia) と Europe (Frankfurt) の 2 リージョンに限定
✗サンドボックス実行環境ではローカルファイルシステムやネットワークにアクセスできない
✗AWS API 実行にはローカルマシンに IAM 認証情報の設定が必要
✗MCP プロキシの実行に uv のインストールが必要

考慮すべき点

⚠エージェントが実行する AWS API 呼び出しに対して通常の AWS 利用料金が発生する
⚠IAM ポリシーの適切な設計が必要 (エージェントに過剰な権限を付与しないよう注意)
⚠AWS Labs MCP サーバーからの移行計画を検討する必要がある (今後 Agent Toolkit for AWS に統合予定)
