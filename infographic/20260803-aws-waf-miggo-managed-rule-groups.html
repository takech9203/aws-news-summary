AWS WAF🤖 AI/ML アプリ保護

🛡️ AWS WAF が Miggo Security
マネージドルールグループをサポート

新興脅威対策と AI/ML アプリケーション保護の 2 つのルールグループを AWS Marketplace 経由で提供
📅 リリース日: 2026 年 8 月 3 日

📌 概要

AWS WAF が、Miggo Security の 2 つの新しいパートナーマネージドルールグループを AWS Marketplace 経由でサポートするようになりました。 実際に悪用されている脆弱性、公開された概念実証 (PoC) コードが存在する脆弱性、CISA KEV カタログ掲載の脆弱性に対して、継続的に更新される保護を提供します。

特に AI/ML Application Protection は、AI エージェントフレームワーク、LLM ゲートウェイ、モデルサービングインフラストラクチャといった生成 AI アプリケーションスタックの保護に焦点を当てており、生成 AI アプリケーションを運用する組織にとって注目すべきアップデートです。

❌ Before: アップデート前の課題
  • 新たに悪用が確認された脆弱性 (CISA KEV 掲載など) への対応には、カスタムルールの作成・更新を続ける必要があった
  • AI エージェントフレームワークや LLM ゲートウェイなど、生成 AI スタック特有の攻撃ベクトルに特化したマネージドルールの選択肢が限られていた
  • 新興脅威への対応は情報収集からルール反映までのリードタイムが長く、運用負荷が高かった
✅ After: アップデート後の改善
  • Miggo Security が継続更新するルールグループを購読するだけで、悪用中の脆弱性への保護を自動的に取り込める
  • 生成 AI アプリケーションスタックに特化した保護を、追加設定なしで Web ACL に追加できる
  • 両ルールグループはバージョニングをサポートし、ルール更新の管理を計画的に行える

Miggo Security が継続的に更新するルールグループを AWS Marketplace 経由で購読し、Web ACL に追加することで、新興脅威や生成 AI スタックへの攻撃からアプリケーションを保護する構成

⚡ 主要機能

⚠️ Miggo Rules for AWS WAF – High Emerging Application Threats
→実際に悪用が進行中の脆弱性への保護に焦点を当てたルールグループ
→公開された概念実証 (PoC) コードが存在する脆弱性や、CISA KEV カタログ掲載の脆弱性を対象
→Miggo Security により継続的に更新されるため、ユーザーによるルールの作成・維持が不要
🤖 Miggo Rules for AWS WAF – AI/ML Application Protection
→生成 AI アプリケーションスタックの保護に特化したルールグループ
→AI エージェントフレームワーク、LLM ゲートウェイ、モデルサービングインフラストラクチャなどを保護対象とする
🚀 簡単な導入とバージョニング
→AWS Marketplace でサブスクリプションを購入し、AWS WAF コンソールから直接 Web ACL に追加可能
→追加の設定は不要
→両ルールグループともバージョニングをサポートし、ルール更新のタイミングを制御可能

✅ 前提条件

✓AWS アカウントを保有していること
✓AWS WAF の Web ACL を作成済み、または作成する権限があること
✓AWS Marketplace でサブスクリプションを購入できること

📊 動作確認と

1
AWS Marketplace でルールグループを購読

以下のいずれか (または両方) のルールグループを購読します。料金は Miggo により AWS Marketplace を通じて設定されています。

• High Emerging Application Threats (Marketplace)
• AI/ML Application Protection (Marketplace)

2
Web ACL にルールグループを追加

AWS WAF コンソールで対象の Web ACL を開き、「Rules」からマネージドルールグループとして Miggo のルールグループを追加します。追加の設定は不要です。

Bash Web ACL の現在の設定を確認する例 
# CLI で Web ACL の現在の設定を確認する例
aws wafv2 get-web-acl \
  --name my-web-acl \
  --scope REGIONAL \
  --id <web-acl-id>

このコマンドは指定した Web ACL の現在のルール構成を取得します。ルールグループ追加前後の構成確認に使用できます。

3
動作確認とモニタリング

Amazon CloudWatch メトリクスや AWS WAF のサンプルリクエスト、ログで動作を確認します。最初はカウントモードで動作を検証してからブロックモードへ移行することを検討してください。

💼 ビジネス面
✓運用負荷の削減: 新興脆弱性への対応ルールを自作・維持する必要がなくなり、セキュリティチームの負荷を軽減
✓対応速度の向上: 悪用が確認された脆弱性への保護が継続的に提供され、脅威発生から防御までの時間を短縮
✓生成 AI 活用の安全性向上: 生成 AI アプリの本番運用時のセキュリティ懸念に、専用マネージドルールで対処
⚙️ 技術面
✓CISA KEV カタログ連動: 実際に悪用されている脆弱性 (KEV) に基づく保護を利用可能
✓AI/ML スタック特化の保護: 従来の WAF ルールではカバーしにくい AI エージェント、LLM ゲートウェイ、モデルサービング基盤に対応
✓バージョニング対応: バージョンの固定または追従により、変更管理を計画的に実施可能

⚠️ デメリット・制約事項

🚫 制限事項
✗利用には AWS Marketplace でのサブスクリプション購入が必要
✗料金は Miggo が設定するため、AWS WAF の基本料金とは別にサブスクリプション費用が発生
✗ルールの内容は Miggo が管理するため、個々のルールの詳細なカスタマイズには制約がある
🤔 考慮すべき点
⚠導入前にカウントモードでの検証を行い、正常なトラフィックへの誤検知 (フォールスポジティブ) がないか確認を推奨
⚠既存の AWS Managed Rules との重複や、Web ACL の WCU (Web ACL Capacity Unit) 上限への影響を確認する必要がある
⚠利用可能なリージョンは AWS Regional Services ページでの確認が必要

🎯 ユースケース

1️⃣ 新興脆弱性への迅速な防御

シナリオ: 公開 Web アプリケーションを運用しており、新たに公表された脆弱性の悪用 (PoC 公開直後の攻撃など) に迅速に対応したいが、専任セキュリティチームのリソースが限られている。

実装例: ① Marketplace で「High Emerging Application Threats」を購読 → ② 公開アプリの Web ACL にルールグループを追加 → ③ CloudWatch メトリクスで検知状況をモニタリング

✅ 効果: CISA KEV 掲載や悪用中の脆弱性への保護が自動更新され、パッチ適用までの間の防御層 (仮想パッチ) として機能する。
2️⃣ 生成 AI アプリケーションの保護

シナリオ: LLM ゲートウェイや AI エージェントフレームワークを利用した生成 AI アプリケーションを公開しており、AI スタック特有の攻撃ベクトルへの防御を強化したい。

実装例: ① Marketplace で「AI/ML Application Protection」を購読 → ② 生成 AI アプリのフロントの Web ACL にルールグループを追加 → ③ カウントモードで一定期間検証後、ブロックモードへ移行

✅ 効果: AI エージェントフレームワーク、LLM ゲートウェイ、モデルサービング基盤を狙う攻撃への専用保護を、カスタムルール開発なしで導入できる。
3️⃣ 多層防御の強化

シナリオ: AWS Managed Rules をすでに利用しているが、新興脅威への対応をさらに強化し、多層防御を実現したい。

実装例: ① 既存 Web ACL の構成と WCU 使用量を確認 → ② Miggo のルールグループを追加し、既存ルールとの評価順序を調整 → ③ WAF ログを分析し、各ルールグループの検知傾向を把握

✅ 効果: AWS Managed Rules による汎用的な保護に加えて、悪用中の脆弱性に特化した保護レイヤーを追加でき、防御の網羅性が向上する。

📝 まとめ

AWS WAF に Miggo Security の 2 つのマネージドルールグループが追加され、活発に悪用されている脆弱性や CISA KEV カタログ掲載の脆弱性、そして生成 AI アプリケーションスタックへの攻撃に対する保護を、カスタムルールの開発なしで導入できるようになりました。

特に LLM ゲートウェイや AI エージェントを本番運用している組織は、AI/ML Application Protection ルールグループの評価を検討する価値があります。まずは AWS Marketplace で製品ページを確認し、カウントモードでの検証から始めることを推奨します。
