📡 Amazon IVS Real-Time Streaming
冗長インジェスト

Amazon Interactive Video Service Redundant Ingest
2026-04-08

📋 概要

Amazon IVS Real-Time Streaming に冗長インジェスト機能が追加されました。2 台のエンコーダーから同時にストリーミングを送信し、単一のステージに対して自動フェイルオーバーを実現。ソースエンコーダーの障害やファーストマイルネットワークの問題が発生しても、視聴者への配信を中断なく継続できます。

2 台 同時エンコーダー
自動 フェイルオーバー
0 秒 視聴者への中断

❌ Before

  • エンコーダー障害やネットワーク問題でライブストリームが中断
  • 単一エンコーダーに依存し、単一障害点 (SPOF) が存在
  • ファーストマイルネットワーク障害に対する耐性なし
  • 24/365 配信でエンコーダー障害時に手動切り替えが必要

✅ After

  • 2 台のエンコーダーから同時送信、自動フェイルオーバーで継続性を確保
  • ソース障害時にもう一方へ自動切り替え、視聴者への影響を最小化
  • ファーストマイルネットワーク障害への冗長性を確保
  • API を通じた冗長インジェストの設定・管理でプログラマティックな制御を実現

⚡ 主要機能

📡

冗長インジェスト

  • 2 台のエンコーダーから単一ステージに同時ストリーミング
  • redundantIngest を True に設定で有効化
  • 2 つの participantId と streamKey のペアが生成
🔄

自動フェイルオーバー

  • プライマリエンコーダー障害を自動検知
  • セカンダリエンコーダーのストリームに自動切り替え
  • ファーストマイルネットワーク問題にも対応
🔧

API による管理

  • CreateIngestConfiguration で設定作成
  • UpdateIngestConfiguration で設定更新
  • GetParticipant / ListParticipants で状態参照

📐 技術仕様

項目 詳細
対応プロトコル RTMP / RTMPS
エンコーダー数 最大 2 台の同時ストリーミング
フェイルオーバー方式 自動
認証情報 2 セットの participantId + streamKey
設定方法 API: CreateIngestConfiguration / UpdateIngestConfiguration
対象 Amazon IVS Real-Time Streaming ステージ

🔌 更新された API メソッド

メソッド 変更内容
CreateIngestConfiguration リクエストに redundantIngest 追加、レスポンスに redundantIngestCredentials 追加
UpdateIngestConfiguration リクエストに redundantIngest 追加、レスポンスに redundantIngestCredentials 追加
GetIngestConfiguration レスポンスに redundantIngest と redundantIngestCredentials 追加
ListIngestConfigurations レスポンスに redundantIngest 追加
GetParticipant レスポンスに redundantIngest と ingestConfigurationArn 追加
ListParticipants レスポンスに redundantIngest と ingestConfigurationArn 追加

💻 設定例

冗長インジェストを有効にしたインジェスト設定の作成と認証情報の取得。

Python 冗長インジェスト設定の作成 
import boto3

client = boto3.client('ivs-realtime')

# 冗長インジェストを有効にしたインジェスト設定の作成
response = client.create_ingest_configuration(
    name='my-redundant-ingest',
    stageArn='arn:aws:ivs:us-east-1:123456789012:stage/abcdefgh',
    userId='broadcaster-1',
    ingestProtocol='RTMPS',
    insecureIngest=False,
    redundantIngest=True,
    tags={
        'Environment': 'production'
    }
)

# レスポンスから 2 つの認証情報を取得
ingest_config = response['ingestConfiguration']
print(f"冗長インジェスト有効: {ingest_config['redundantIngest']}")

for i, cred in enumerate(ingest_config['redundantIngestCredentials']):
    print(f"エンコーダー {i+1}:")
    print(f"  participantId: {cred['participantId']}")
    print(f"  streamKey: {cred['streamKey']}")
Bash AWS CLI による設定手順 
# ステップ 1: 冗長インジェスト設定の作成
aws ivs-realtime create-ingest-configuration \
  --name "my-redundant-stream" \
  --stage-arn "arn:aws:ivs:us-east-1:123456789012:stage/abcdefgh" \
  --ingest-protocol RTMPS \
  --redundant-ingest

# ステップ 2: エンコーダー設定情報の確認
aws ivs-realtime get-ingest-configuration \
  --arn "arn:aws:ivs:us-east-1:123456789012:ingest-configuration/abcdefgh"

# ステップ 3: ストリーミング状態の確認
aws ivs-realtime list-participants \
  --stage-arn "arn:aws:ivs:us-east-1:123456789012:stage/abcdefgh" \
  --session-id "session-id"

# ステップ 4: 既存設定への冗長インジェスト追加
aws ivs-realtime update-ingest-configuration \
  --arn "arn:aws:ivs:us-east-1:123456789012:ingest-configuration/abcdefgh" \
  --redundant-ingest

🎯 ユースケース

🏟️

大規模ライブイベント

スポーツ中継や音楽ライブなど、数万人規模の視聴者に途切れない配信を提供

✓ プライマリ障害時もセカンダリへ自動切り替え、視聴者は中断を意識せず継続視聴
📺

24/365 ニュースチャンネル

24 時間 365 日のライブストリームを運用し、エンコーダーメンテナンス時にもストリームを維持

✓ 計画メンテナンス時もセカンダリで配信継続、視聴者に影響のないメンテナンスが可能
🛒

EC サイトのライブコマース

ライブコマースイベントで配信中断が売上損失に直結するシナリオ

✓ ストリーム中断を防止し、視聴者の離脱と売上損失リスクを最小化

📊 メリット

💼 ビジネス面

  • 視聴者エンゲージメントの維持: ストリーム中断による視聴者の離脱を防止し、広告収入やイベント視聴率を保護
  • サービス品質の向上: 24/365 の連続配信でもダウンタイムリスクを大幅に低減し、SLA 改善に貢献
  • ブランド信頼性の強化: ライブイベントでの配信障害を防止し、プロフェッショナルな配信体験を提供

🔧 技術面

  • 単一障害点の排除: エンコーダーとファーストマイルネットワークの冗長化により SPOF を解消
  • 自動フェイルオーバー: 障害検知と切り替えが自動化されており、運用者の手動介入が不要
  • API による統合管理: プログラマティックに設定・監視が可能で既存ワークフローに組み込みやすい

⚠️ デメリット・制約事項

🚫 制限事項

  • エンコーダー数は最大 2 台まで、3 台以上の冗長化は非対応
  • RTMP / RTMPS プロトコルのみ対応、WHIP など他プロトコルは利用不可
  • 2 台のエンコーダーが同一コンテンツを送信する必要があり、同期設定が必要

💡 考慮すべき点

  • 2 つのストリーム送信により帯域幅使用量が増加
  • 2 台のエンコーダーの設置・管理コストが追加で発生
  • 冗長インジェスト用の 2 つの認証情報の安全な管理が必要
