Amazon EC2

⚡ EC2 T9g インスタンス一般提供開始

Graviton5 搭載の低コストバースト可能汎用インスタンス | リリース日: 2026 年 11 月 20 日

📌 概要

AWS Graviton5 プロセッサを搭載した低コストのバースト可能 (burstable) 汎用インスタンス Amazon EC2 T9g が一般提供開始。第 6 世代 AWS Nitro カード上に構築され、 AWS は「汎用 EC2 インスタンスの中で最高のプライスパフォーマンス」を提供するとしています。 CPU クレジットの仕組みは T4g と同じため、既存の T 系ユーザーは運用モデルを変えずにアップグレードし、TCO を削減できます。

❌ Before: アップデート前の課題
  • バースト可能な Graviton インスタンスは Graviton2 ベースの T4g が最新で、最新世代の性能向上を利用できなかった
  • 小規模ワークロードで高いネットワーク / EBS 帯域幅が必要な場合、より大きな固定性能インスタンスへの移行が必要だった
  • 低コスト帯で最新のセキュリティ分離機構を利用する選択肢が限られていた
✅ After: アップデート後の改善
  • Graviton5 の性能をバースト可能インスタンスで利用でき、T4g 比で最大 2.3 倍の性能と最大 45% 優れたプライスパフォーマンスを実現
  • T4g と同じ CPU クレジットモデル (Standard / Unlimited) のため、既存の T 系ワークロードをそのまま移行可能
  • 形式検証を活用した Nitro Isolation Engine により、数学的に証明されたレベルの分離を提供

T9g インスタンスは Graviton5 プロセッサと第 6 世代 Nitro カードで構成され、T4g と同じ CPU クレジットモデルで低〜中 CPU 使用率のワークロードに低コストのバースト性能を提供します。

🔧 設定方法

📋 前提条件

  • AWS アカウントを保有していること
  • 利用するリージョンが T9g の提供リージョンであること
  • ワークロードが Arm アーキテクチャ (aarch64) に対応していること

ステップ 1: 利用可能なインスタンスタイプの確認

Bash インスタンスタイプの提供状況を確認 
aws ec2 describe-instance-type-offerings \
  --location-type region \
  --filters "Name=instance-type,Values=t9g.*" \
  --region ap-northeast-1

対象リージョン (例: 東京リージョン) で T9g インスタンスタイプが提供されているかを確認します。

ステップ 2: T9g インスタンスの起動

Bash t9g.micro を Unlimited モードで起動 
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type t9g.micro \
  --key-name my-key-pair \
  --subnet-id subnet-xxxxxxxx \
  --credit-specification CpuCredits=unlimited

Arm64 対応の AMI を指定して起動します。--credit-specification で CPU クレジットモードを unlimited または standard に設定できます。

ステップ 3: CPU クレジットの監視

Bash CloudWatch で CPUCreditBalance を取得 
aws cloudwatch get-metric-statistics \
  --namespace AWS/EC2 \
  --metric-name CPUCreditBalance \
  --dimensions Name=InstanceId,Value=i-xxxxxxxxxxxxxxxxx \
  --start-time 2026-11-20T00:00:00Z \
  --end-time 2026-11-21T00:00:00Z \
  --period 3600 \
  --statistics Average

CloudWatch の CPUCreditBalance メトリクスで CPU クレジットの残高を監視し、バーストの発生状況やクレジット枯渇のリスクを把握します。

💡 メリット

💼 ビジネス面

✓コスト削減: T4g 比で最大 45% 優れたプライスパフォーマンスにより、小規模ワークロードの TCO を削減
✓無料利用枠: micro と small サイズが対象であり、検証や学習、新規導入のハードルが低い
✓移行の容易さ: T4g と同じクレジットモデルのため、既存 T 系ユーザーは運用変更なしでアップグレード可能

🔬 技術面

✓性能向上: 最大 2.3 倍のコンピューティング性能、1.5 倍のネットワーク帯域幅、2.8 倍の EBS 帯域幅
✓セキュリティ強化: 形式検証を活用した Nitro Isolation Engine による数学的に証明された分離
✓柔軟な購入オプション: オンデマンド、Savings Plans、スポットインスタンスに対応

⚠️ デメリット・制約事項

🚧 制限事項

✗インスタンスサイズは nano、micro、small、medium の 4 サイズのみで、large 以上は発表時点で提供されていない
✗Arm アーキテクチャのため、x86 専用のソフトウェアやバイナリは再ビルドまたは代替が必要
✗提供リージョンは発表時点で 12 リージョンに限定されている

🤔 考慮すべき点

⚠持続的に高い CPU 使用率が必要なワークロードには M 系や C 系などの固定性能インスタンスが適している
⚠Standard モードではクレジット枯渇時にベースライン性能に制限されるため、ワークロード特性に応じて Unlimited モードを検討する
⚠Unlimited モードではベースラインを超える持続的な使用に追加料金が発生する可能性がある

🎯 ユースケース

1️⃣ 低トラフィックの Web サイト・マイクロサービス

アクセスが断続的で、通常時は CPU 使用率が低い Web サイトや小規模なマイクロサービスを低コストで運用。

BashStandard モードで起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type t9g.small \
  --credit-specification CpuCredits=standard

効果: 通常時にクレジットを蓄積し、アクセス増加時にバーストすることで、低コストと応答性を両立。

2️⃣ 開発・ステージング環境

本番環境と同じ Arm アーキテクチャで開発・ステージング環境を構築し、環境コストを最小化。

Bashステージング用タグを付与して起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type t9g.micro \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Env,Value=staging}]'

効果: 無料利用枠対象の micro サイズを活用し、開発・検証コストを大幅に抑制。

3️⃣ バッチ処理・CI/CD パイプライン

短時間で完了するバッチ処理や CI/CD のビルドジョブを、必要なときだけ高い性能で実行。

BashUnlimited モード + スポットで起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type t9g.medium \
  --credit-specification CpuCredits=unlimited \
  --instance-market-options 'MarketType=spot'

効果: Unlimited モードとスポットインスタンスの組み合わせで、短時間のジョブを低コストかつ高速に処理。

💰 料金

T9g インスタンスは、オンデマンド、Savings Plans、スポットインスタンスの購入オプションで利用できます。 micro および small サイズは AWS 無料利用枠の対象です。

⚠Unlimited モードでは、ベースラインを超える CPU 使用が持続した場合に追加の vCPU 料金が発生する可能性があります。

最新の料金は Amazon EC2 料金ページ および T9g インスタンスページ を参照してください。

EC2 の基盤となる仮想化インフラストラクチャ。T9g は第 6 世代 Nitro カードと Nitro Isolation Engine を採用。

📝 まとめ

T9g インスタンスは、Graviton5 の性能と第 6 世代 Nitro のセキュリティを低コストのバースト可能インスタンスで利用できるアップデートであり、 東京リージョンでも初日から利用可能です。T4g と同じ CPU クレジットモデルを採用しているため、既存の T 系インスタンスを利用中のユーザーはまず開発・検証環境で T9g への移行を試し、 プライスパフォーマンスの改善を確認することを推奨します。
