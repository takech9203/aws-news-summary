🤖 WorkSpaces Advisor プロアクティブトラブルシューティング

📅 リリース日: 2026 年 11 月 17 日 | 問題を「待つ」運用から「先回りして防ぐ」運用へ

📌 概要

AI エージェント WorkSpaces Advisor が、管理者の調査開始やユーザーの問題報告を待つことなく、環境全体を継続的に監視。問題の検出、根本原因の推定、修復アクションの推奨までを自動的に実行します。対象は WorkSpaces Personal を運用する IT 管理者とエンドユーザーで、プレビュー期間中は追加料金なしで利用できます。

🖥️ フリート向けプロアクティブトラブルシューティング

複数の WorkSpaces に影響する問題を単一の課題として検出し、WorkSpaces コンソールに表示。根本原因と推奨修復アクションを提示します。

👤 ユーザー向けプロアクティブトラブルシューティング

End User Advisor が WorkSpaces クライアント上で、問題の原因 (デバイス / ネットワーク / WorkSpace) と対処方法をユーザー自身に提示します。

❌ Before: アップデート前の課題

  • 問題の認識はユーザーからのチケット発生後で、対応が後手に回っていた
  • 同一の根本原因 (証明書期限切れ、サブネット障害など) でも WorkSpace ごとに個別調査が必要
  • CloudWatch メトリクス、ログ、設定情報など複数ツールを横断する調査に時間がかかる
  • 「WorkSpace が遅い」という症状ベースの報告から、原因の切り分けを始める必要があった
  • CloudWatch アラームのしきい値設定など事前の監視設定が必要だった

✅ After: アップデート後の改善

  • フリート全体を自動監視。調査開始、報告、しきい値設定なしで問題を検出
  • 共有構成 (ディレクトリ、サブネット、バンドルなど) でグループ化し、単一の課題として根本原因と推奨アクションを提示
  • CPU、メモリ、ディスク容量の枯渇を予測し、影響が出る前に対処可能
  • サインインに必要な証明書の期限切れを事前通知
  • ユーザーはクライアント上で原因を確認し、許可された修復アクション (再起動など) を自分で実行可能
  • エスカレーション時も診断情報付きで、管理者は症状ではなく診断から対応を開始

WorkSpaces Advisor がフリート全体とユーザーセッションを継続的に監視し、管理者には WorkSpaces コンソールで、ユーザーには WorkSpaces クライアントで、問題の原因と推奨アクションを提示する構成です。

⚙️ 主要機能

1️⃣ フリート向けプロアクティブトラブルシューティング

  • フリートの通常状態 (ベースライン) を学習し、固定しきい値ではなく「普段との差異」として問題を検出
  • 影響を受けた WorkSpaces を共有構成 (ディレクトリ、サブネット、バンドル、コンピュートタイプなど) でグループ化し、単一の課題として報告
  • 各課題には影響を受ける WorkSpaces、判断根拠 (エビデンス)、推奨アクションを表示
  • AWS のメンテナンスなど既知の想定イベントは課題として報告されない
  • 新規ディレクトリは参照ベースラインから開始し、履歴の蓄積後に自身のベースラインへ切り替え

2️⃣ 検出される課題カテゴリ

  • 構成を共有する WorkSpaces の異常: 同一ディレクトリ・サブネットの WorkSpaces が同時に応答しなくなった場合などを検出
  • リソース枯渇: CPU、メモリ、ルート / ユーザーボリュームの危険水準到達や予測を、想定時期と上位プロセスとともに報告
  • 信頼済みデバイス証明書の期限切れ: アクセス制限用証明書の期限が近いことを通知
  • 証明書ベース認証の CA の問題: AWS Private CA の期限切れや利用不可を、影響を受けるディレクトリとともに報告

3️⃣ ユーザー向けプロアクティブトラブルシューティング End User Advisor

  • WorkSpaces クライアント上で接続前・セッション中・切断後の各フェーズでセッションを監視
  • 「何が起きているか」「何をすべきか」「原因はデバイス / ネットワーク / WorkSpace のどれか」を平易な言葉で表示
  • 接続前: 無効な登録コード、サインインの問題、メンテナンス中、起動遅延、ネットワーク遮断などを説明
  • セッション中: 遅延・フリーズの原因を切り分け、不要アプリの終了、再起動、コンピュートタイプ変更などを提案
  • 切断後: 無操作切断、別デバイスからのセッション開始、ネットワーク切断などの理由と再接続方法を提示
  • IT の対応が必要な場合は、管理者への連絡時に診断情報を伝えられるよう問題と推定原因を提示

4️⃣ 管理者によるコントロール

  • End User Advisor はディレクトリ単位のセルフサービス権限として制御可能 (デフォルトで有効)
  • ユーザーが実行できる修復アクションは、管理者が有効化したセルフサービス権限 (再起動、コンピュートタイプ変更、ボリュームサイズ拡張など) の範囲内に限定
  • 設定変更はユーザーの次回接続時に反映され、進行中のセッションには影響しない

🛠️ 設定方法

📝 前提条件

✓WorkSpaces Personal 環境が利用可能なリージョンで稼働していること
✓ユーザー向け機能を利用する場合、WorkSpaces Windows クライアント バージョン 5.37 以降で新しいクライアント体験が有効になっていること
✓ユーザーにセルフサービスアクションを許可する場合、ディレクトリのセルフサービス権限が設定されていること

1フリートの検出済み課題を確認する

  1. Amazon WorkSpaces コンソールを開く
  2. ナビゲーションペインで [WorkSpaces Advisor] を選択
  3. 検出された課題の一覧を確認 (影響を受ける WorkSpaces、発生時刻、ステータス)
  4. 課題を選択して詳細 (エビデンスと推奨アクション) を表示
  5. 推奨アクションのリスクと影響を確認し、コンソールまたは自組織の変更プロセスで実行

💡 フリート監視は自動で行われるため、有効化の操作は不要です。

2End User Advisor の有効/無効をコンソールで設定する

  1. Amazon WorkSpaces コンソールを開く
  2. ナビゲーションペインで [ディレクトリ] を選択
  3. 対象のディレクトリを選択
  4. [セルフサービス権限] セクションで [編集] を選択
  5. [End User Advisor] を選択または解除
  6. [保存] を選択

💡 End User Advisor はデフォルトで有効です。設定はディレクトリに登録されたすべての WorkSpaces とユーザーに適用されます。

3End User Advisor を CLI で設定する

Bash AWS CLI での設定と確認 
# End User Advisor を無効化する
aws workspaces modify-selfservice-permissions \
    --resource-id d-1234567890 \
    --selfservice-permissions EnableEndUserAdvisor=DISABLED

# 設定を確認する
aws workspaces describe-workspace-directories \
    --directory-ids d-1234567890 \
    --query "Directories[0].SelfservicePermissions"

💡 再度有効化する場合は EnableEndUserAdvisor=ENABLED を指定します。

💡 メリット

💼 ビジネス面

✓ヘルプデスク負荷の削減: ユーザーが自己解決できる問題はチケット化されず、エスカレーションされるチケットにも診断情報が付与されるため、サポートコストを削減できる
✓ダウンタイムの予防: リソース枯渇の予測や証明書期限切れの事前通知により、小さな問題が障害や大量のチケットに発展する前に対処できる
✓運用チームの生産性向上: 個別の問題を 1 件ずつ追いかける時間を減らし、ビジネス価値の高いプロジェクトに時間を振り向けられる
✓追加コストなし: プレビュー期間中は追加料金なしで利用できる

⚙️ 技術面

✓根本原因への一括対応: 同じ問題が多数の WorkSpaces に影響する場合も単一の課題として提示され、症状を WorkSpace ごとに追いかける必要がない
✓ベースライン学習による検出: 固定しきい値ではなくフリート固有の通常状態との差異で検出するため、アラームしきい値の設計・調整が不要
✓原因の自動切り分け: セッションの問題がデバイス、ネットワーク、WorkSpace のどこにあるかを自動で切り分け、調査の起点を提供
✓管理者によるガバナンス維持: Advisor は推奨のみを行い、変更は管理者またはユーザーが承認済みアクションを選択した場合にのみ実行される

⚠️ デメリット・制約事項

🚫 制限事項

✗プレビュー段階の機能であり、仕様は変更される可能性がある
✗対象は WorkSpaces Personal のみ (WorkSpaces Pools は対象外)
✗検出された課題は WorkSpaces コンソールにのみ表示され、プレビュー期間中は他のサービスへの通知 (SNS、EventBridge など) は行われない
✗検出しきい値はカスタマイズできない
✗End User Advisor の設定はディレクトリ全体に適用され、ユーザー、WorkSpace、バンドル単位での切り替えや実行するチェックの選択はできない
✗ユーザーが推奨を確認したことを管理者に通知する仕組みはない

🤔 考慮すべき点

⚠️ユーザー向け機能は WorkSpaces Windows クライアント バージョン 5.37 以降 (新しいクライアント体験) が必要なため、クライアントの更新計画が必要
⚠️End User Advisor はデフォルトで有効のため、組織のポリシー上不要な場合はディレクトリ単位で明示的に無効化する必要がある
⚠️ユーザーが実行できる修復アクションはセルフサービス権限に依存するため、どのアクションを許可するか事前に設計する必要がある
⚠️GA 時に料金体系が変更される可能性があるため、プレビュー終了後の発表を確認する必要がある

🎯 ユースケース

1️⃣ 構成起因の同時障害への先回り対応

シナリオ: 特定のサブネットに属する複数の WorkSpaces が同時に応答しなくなった。従来はユーザーからのチケットが複数届いてから、WorkSpace ごとに調査を開始していた。

対応の流れ: コンソールの [WorkSpaces Advisor] に該当サブネットを共有する WorkSpaces 群が 1 件の課題として表示 → 影響範囲、発生時刻、エビデンス、推定原因を確認 → 推奨アクションに従い根本原因 (ネットワーク設定など) を 1 回の対応で修復

✅ 効果: 同一原因の問題を WorkSpace ごとに追いかける必要がなくなり、ユーザーからの報告を待たずに根本原因へ一括対応できる。

2️⃣ 証明書期限切れによるサインイン障害の予防

シナリオ: 証明書ベース認証に使用している AWS Private CA の証明書期限が近づいている。期限切れになると、該当ディレクトリのユーザー全員がサインインできなくなる。

対応の流れ: Advisor が期限切れの近い CA 証明書と影響を受けるディレクトリを課題として検出 → コンソールで課題を確認し、推奨アクションに従って証明書を更新 → 期限切れ前に対応完了

✅ 効果: アラームを事前に設定していなくても証明書の期限切れを検出でき、全社的なサインイン障害という重大インシデントを未然に防げる。

3️⃣ エンドユーザーによるセッション問題の自己解決

シナリオ: 在宅勤務中のユーザーのセッションが遅くなった。従来は「WorkSpace が遅い」というチケットが起票され、管理者が切り分けから始めていた。

対応の流れ: クライアント (Windows 5.37 以降) 上で Advisor が原因を自動切り分け → ネットワーク起因なら「ルーターに近づく」「有線接続を使う」を提示 → WorkSpace のリソース不足ならリソースを消費しているアプリを提示し、許可されていれば再起動をクライアントから実行 → IT の対応が必要な場合は診断情報を含めて報告

✅ 効果: ヘルプデスクに届くチケット数が減り、届いたチケットも診断情報付きになるため、管理者は切り分け作業を省略して対応を開始できる。

🌏 利用可能リージョン

🔗 関連サービス・機能

  • Amazon WorkSpaces Personal: 本機能の対象となる仮想デスクトップサービス。WorkSpaces Pools はプレビューの対象外
  • WorkSpaces Advisor (Investigate): 2026 年 4 月発表の、管理者が個別の WorkSpace をコンソールから調査できる一般提供済みの機能。今回のプレビューはこれをフリート全体とエンドユーザーに拡張するもの
  • セルフサービス権限: End User Advisor の有効/無効や、ユーザーが実行できる修復アクション (再起動、コンピュートタイプ変更、ボリュームサイズ拡張など) を制御する仕組み
  • AWS Private CA: 証明書ベース認証に使用する CA。Advisor が証明書の期限切れや利用不可を検出
  • Amazon CloudWatch: 従来のトラブルシューティングで管理者が参照していたメトリクス・ログの基盤。Advisor はこうした情報の横断調査を自動化

📝 まとめ

WorkSpaces Advisor のプロアクティブトラブルシューティングにより、WorkSpaces 運用は「チケットに反応する」モデルから「問題を先回りして防ぐ」モデルへと進化します。追加設定もしきい値設計も不要で、プレビュー期間中は追加料金なしで利用できます。
