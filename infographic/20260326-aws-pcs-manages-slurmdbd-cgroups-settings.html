AWS Parallel Computing Service

⚙️ slurmdbd / cgroups 設定のネイティブサポート

HPC 環境のアカウンティング管理とリソース分離をマネージドサービス上で直接制御
📅 リリース日: 2026 年 3 月 26 日

📊 概要

AWS Parallel Computing Service (AWS PCS) が Slurm の slurmdbd および cgroups に関する追加設定をサポートしました。AWS PCS コンソール、CLI、SDK を通じて、アカウンティング動作やリソース分離を直接設定できるようになり、本番環境向け HPC 環境の構築が大幅に簡素化されます。

⚠️ アップデート前

  • slurmdbd の設定をコンソールや CLI から直接管理できず、アカウンティングの細かな制御が困難
  • cgroups の設定を AWS PCS 上で直接行う手段がなく、カスタム構成が必要
  • CPU コアバインディングやメモリ制限などのリソース管理に追加の手順が必要

✨ アップデート後

  • コンソール、CLI、SDK から slurmdbd 設定を直接構成でき、アカウンティング動作の柔軟な制御が可能
  • cgroups 設定で CPU コアバインディング、メモリ制限、デバイスアクセス制御をネイティブにサポート
  • 新規 / 既存クラスターの両方に設定を適用でき、本番環境向けの HPC 構成が容易

🎯 主要機能

🗄️ slurmdbd 設定管理

Slurm アカウンティングデーモンの動作をコンソール、CLI、SDK から直接設定できます。

  • プライバシー制御: ユーザーやジョブのアカウンティング情報の可視性を管理
  • データ保持ポリシー: アカウンティングデータの保存期間を制御
  • ワークロード追跡: ジョブの実行状況を詳細に記録

📦 cgroups リソース分離

Linux cgroups を活用したリソース分離を AWS PCS 上でネイティブに設定できます。

  • CPU コアバインディング: ジョブが指定された CPU コアのみを使用するよう制限
  • メモリ制限の強制: ノードの安定性を維持しオーバーサブスクリプションを防止
  • デバイスアクセス制御: GPU 等のデバイスへのアクセスを定義された境界内に制限

🔄 柔軟な適用タイミング

新規クラスター作成時および既存クラスターの変更時に設定を適用でき、コンソール、CLI、SDK のいずれからでも実行可能です。

📝 設定方法

AWS PCS クラスターの slurmdbd / cgroups 設定は、AWS CLI から以下のように適用します。

Bash ステップ 1: クラスターの確認 
# AWS PCS クラスターの一覧を取得
aws pcs list-clusters
Bash ステップ 2: slurmdbd 設定の適用 
# クラスターの slurmdbd 設定を更新
aws pcs update-cluster \
  --cluster-identifier <cluster-id> \
  --slurm-configuration '{
    "slurmdbdSettings": {
      "privacySettings": {
        "jobPrivacy": "enabled"
      },
      "dataRetention": {
        "purgeAfterDays": 90
      }
    }
  }'
Bash ステップ 3: cgroups 設定の適用 
# クラスターの cgroups 設定を更新
aws pcs update-cluster \
  --cluster-identifier <cluster-id> \
  --slurm-configuration '{
    "cgroupsSettings": {
      "constrainCores": true,
      "constrainRAMSpace": true,
      "constrainDevices": true
    }
  }'
💡 具体的なパラメータ名は公式ドキュメントを参照してください。設定変更の反映にはクラスターの状態によって時間がかかる場合があります。

✔️ メリット

💼 ビジネス面

運用コストの削減

マネージドサービス上で直接設定を管理できるため、カスタム構成スクリプトの開発・保守が不要に

本番環境品質の向上

プライバシー制御やデータ保持ポリシーにより、コンプライアンス要件に対応した HPC 環境を構築可能

リソース効率の最適化

cgroups によるリソース分離でノードの使用効率が向上し、コスト最適化が可能

⚙️ 技術面

オーバーサブスクリプション防止

cgroups による CPU コアバインディングとメモリ制限で、ワークロード間のリソース競合を解消

ノード安定性の向上

メモリ制限の強制により、OOM によるノード障害のリスクが低減

統一的な設定管理

コンソール、CLI、SDK のいずれからでも設定を管理でき、Infrastructure as Code との統合が容易

⚠️ 制限事項・注意点

設定可能なパラメータの範囲

AWS PCS がサポートする範囲に限定されており、Slurm のすべての slurmdbd/cgroups パラメータが設定できるわけではない可能性があります。

設定反映の所要時間

設定変更の反映にはクラスターの状態によって時間がかかる場合があります。

cgroups 制限の影響

制限設定が厳しすぎると、正常なジョブが制限に抵触して失敗する可能性があります。既存ワークロードへの影響を事前にテストすることを推奨します。

プライバシー設定変更の影響

slurmdbd のプライバシー設定を変更すると、ユーザーが参照できるアカウンティング情報の範囲が変わるため、チーム内での合意が必要です。

💡 ユースケース

🏭 マルチテナント HPC 環境のリソース分離

複数の研究チームが共有する HPC クラスターで、各チームのジョブが他チームのリソースに影響を与えないようにしたい。CPU コアバインディングとメモリ制限を有効化して、リソースのオーバーサブスクリプションを防止します。

✔ 効果: 各ジョブが割り当てられたリソースのみを使用し、ノイジーネイバー問題を防止

📋 コンプライアンス要件に対応したアカウンティング管理

規制業界で HPC を利用しており、ジョブの実行履歴やリソース使用量のデータ保持期間を規制要件に合わせて管理する必要がある。slurmdbd のプライバシー制御とデータ保持ポリシーを設定します。

✔ 効果: 機密ジョブ情報へのアクセスを制限し、規制要件に準拠したデータライフサイクル管理を実現

🤖 GPU ワークロードのデバイスアクセス制御

機械学習トレーニングジョブを実行するクラスターで、各ジョブが割り当てられた GPU のみにアクセスするよう制限したい。デバイスアクセス制御と CPU コアバインディングを組み合わせます。

✔ 効果: GPU リソースの競合を防止し、一貫したパフォーマンスを確保

💰 料金

AWS PCS 自体には追加料金はなく、使用する基盤の EC2 インスタンスやその他の AWS リソースに対してのみ課金されます。slurmdbd / cgroups 設定機能の利用に追加料金は発生しません。

構成月額料金 (概算)
c5.xlarge x 10 ノード (オンデマンド、us-east-1)約 $1,224
c5.xlarge x 10 ノード (Spot、us-east-1)約 $367 - $490 (最大 70% 割引)
🛈 料金は EC2 インスタンスの使用料のみです。実際の料金はリージョンや使用状況により異なります。

AWS PCS が利用可能なすべての AWS リージョンで利用可能です。対応リージョンについては AWS リージョン別サービス一覧 を参照してください。
