📝 概要

Oracle Database@AWS が新たに 5 つの AWS リージョンで一般提供を開始し、合計 12 リージョンで利用可能になりました。

AWS データセンター内で OCI が管理する Oracle Exadata システムへのアクセスを提供するサービスで、ヨーロッパおよびアジア太平洋地域でデータレジデンシー要件を持つお客様が Oracle Exadata/RAC アプリケーションを AWS に移行できるようになりました。

🔄 Before / After

😥 Before

  • ロンドン、ムンバイ、ハイデラバード、ソウルでは利用不可
  • 欧州西部/アジア太平洋でデータレジデンシー要件を満たせず
  • カナダ中部/シドニーは 1 AZ のみで HA 構成に制限
→

😊 After

  • 合計 12 リージョンにグローバル拡大
  • 英国/インド/韓国でデータレジデンシー対応
  • カナダ/シドニーが 2 AZ でマルチ AZ HA 実現

⚙️ 主要機能

🌍 5 つの新規リージョン

  • EU-West-1 ダブリン: 2 AZ
  • EU-West-2 ロンドン: 1 AZ
  • AP-South-1 ムンバイ: 2 AZ
  • AP-South-2 ハイデラバード: 2 AZ
  • AP-Northeast-2 ソウル: 1 AZ

📈 既存リージョンの AZ 拡張

  • CA-Central-1 カナダ中部: 1 AZ → 2 AZ
  • AP-Southeast-2 シドニー: 1 AZ → 2 AZ
  • 2 AZ 構成により高可用性が強化

🔧 OCI 管理の Oracle Exadata

  • AWS データセンター内で Oracle Exadata を実行
  • Oracle RAC アプリケーションの移行をサポート
  • AWS KMS、CloudWatch、IAM との統合

💡 ユースケース

1

英国金融機関の Oracle 移行

FCA 規制によりデータを英国内に保持する必要がある金融機関が、EU-West-2 でオンプレミス Exadata を Oracle Database@AWS に移行。AWS サービスとの統合でモニタリング/暗号化/ガバナンスを強化。

2

インド企業のマルチリージョン DR

RBI データローカライゼーション対応のため、ムンバイをプライマリ、ハイデラバードを DR として構成。インド国内 2 リージョン間のレプリケーションで高可用性と災害復旧を確保。

3

韓国製造業の Oracle RAC 移行

ソウルリージョンで Oracle RAC をクラウド移行。データは韓国国内に保持しつつ、CloudWatch でパフォーマンスモニタリング。インフラ管理は OCI に委任し運用効率を向上。

✅ メリット

📊 ビジネス面

🌍グローバルカバレッジ拡大: 12 リージョンでヨーロッパ/アジア太平洋のデータレジデンシーに対応
🇮🇳インド市場対応: ムンバイ+ハイデラバードの 2 リージョンでデータローカライゼーション要件に対応
🚀移行の加速: 英国/韓国のお客様が最小限の変更で AWS に移行可能

🔧 技術面

🛡️高可用性強化: カナダ/シドニーの 2 AZ 拡張、ダブリン/ムンバイ/ハイデラバードの 2 AZ 提供
⚡低レイテンシ: AWS データセンター内配置で AWS アプリとの高速通信
🔗AWS サービス統合: KMS、CloudWatch、IAM、CloudTrail、EventBridge とネイティブ統合

⚠️ デメリット・制約事項

ロンドンとソウルは 1 AZ のみ。マルチ AZ 構成は利用不可
AWS Marketplace 経由の Oracle プライベートオファーが必要。即時利用は不可
Oracle ライセンスと料金が別途適用
一部管理操作は OCI コンソールの使用が必要
ODB ピアリング接続のネットワーク事前設計が重要
1 AZ → 2 AZ 拡張タイムラインは未発表。HA 要件が厳しい場合は 2 AZ リージョンを選択
