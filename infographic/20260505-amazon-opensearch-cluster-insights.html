📋 概要

Cluster Insights が OpenSearch 1.0 以降 および Elasticsearch 6.8 以降 の全バージョンに対応拡大。さらに、新しい Unused Index インサイト により、過去 30 日間アクティビティのないインデックスを自動検出し、コスト最適化を推奨します。

❌ Before

  • OpenSearch 2.17 以降のみ対応
  • 未使用インデックスの特定に手動調査が必要
  • Warm/Cold ストレージへの移行判断に体系的な手段なし

✅ After

  • OpenSearch 1.0+ / Elasticsearch 6.8+ で利用可能
  • 30 日間未使用インデックスを自動検出
  • Warm/Cold 移行や削除の具体的アクションを推奨

⚡ 主要機能

🔄 Cluster Insights バージョン拡大

OpenSearch 1.0 以降、Elasticsearch 6.8 以降の全バージョンに対応。以前は OpenSearch 2.17 以降に限定されていたプロアクティブ監視が、追加コストなしで全ユーザーに開放されました。

🗂️ Unused Index インサイト

過去 30 日間に検索・インデクシングのアクティビティがゼロのインデックスを自動検出。Warm/Cold ストレージへの移行または削除を推奨し、コスト最適化を支援します。

📢 マルチチャネル配信

AWS マネジメントコンソール、OpenSearch Service Notifications、OpenSearch UI、Amazon EventBridge の 4 つのチャネルでインサイトを確認可能です。

🛠️ 設定方法

前提条件

✓ OpenSearch 1.0 以降または Elasticsearch 6.8 以降で稼働するドメイン
✓ AWS マネジメントコンソールへのアクセス権限
✓ OpenSearch UI から詳細確認する場合は管理者ロールが必要

Step 1: ドメイン情報の確認

Bash AWS CLI でドメイン情報を確認 
# AWS CLI でドメインの情報を確認
aws opensearch describe-domain --domain-name your-domain-name

AWS マネジメントコンソールで OpenSearch Service に移動し、対象ドメインの「Cluster health」タブを選択すると、Cluster Insights が表示されます。

Step 2: Unused Index インサイトの確認

Cluster Insights 一覧から「Unused Index」インサイトを選択すると、過去 30 日間にアクティビティのないインデックスのリストと推奨アクションが表示されます。

Step 3: 推奨アクションの実行

Bash Warm/Cold ストレージへの移行・削除 
# Warm ストレージに移行する例
POST _ultrawarm/migration/your-unused-index/_warm

# Cold ストレージに移行する例
POST _cold/migration/your-unused-index/_cold

# 不要なインデックスを削除する例
DELETE /your-unused-index

✅ メリット

ビジネス面

✓ コスト最適化: 未使用インデックスを低コストのストレージ層に移行でき、ストレージコストを削減
✓ 運用効率向上: プロアクティブ監視により問題発生前に対処可能、ダウンタイムを最小化
✓ 幅広いカバレッジ: レガシーバージョンのユーザーも Cluster Insights の恩恵を享受可能

技術面

✓ プロアクティブなリスク検出: パフォーマンスや安定性に影響するリスクを事前に特定
✓ 自動化対応: EventBridge 連携でインサイトに基づく自動修復ワークフロー構築可能
✓ 統合監視: 複数チャネルで一貫した情報を取得可能

⚠️ 制約事項・注意点

制限事項

✗ OpenSearch UI からの詳細メトリクス表示は OpenSearch 2.17 以降が必要
✗ Query View 機能は OpenSearch 2.19 以降でのみ利用可能
✗ Unused Index の検出期間は 30 日間で固定、カスタマイズ不可

考慮すべき点

⚠ 季節性のあるワークロードや定期バッチ処理で使用されるインデックスが検出される可能性あり
⚠ ストレージ層の移行には時間がかかる場合あり、再度アクティブに必要となった場合の復元時間を考慮

💡 ユースケース

🗂️ ログ分析基盤のコスト最適化

大量のログデータを OpenSearch に取り込んでいる組織で、古いインデックスが Hot ストレージに残り続けている場合。Unused Index インサイトで検出し、30 日以上アクセスのないログインデックスを Warm ストレージに移行してコスト削減を実現。

Bash Warm ストレージへの移行例 
# 30 日以上アクセスのないログインデックスを移行
POST _ultrawarm/migration/logs-2026-01/_warm
POST _ultrawarm/migration/logs-2026-02/_warm

📦 レガシーバージョンでのプロアクティブ監視

Elasticsearch 7.x から OpenSearch への移行を計画中の組織が、移行前のクラスターでもヘルス監視を実施。移行前の段階からクラスターの安定性リスクを検出し、計画的な対応が可能に。

⚡ EventBridge を活用した自動コスト管理

Unused Index インサイトのイベントを EventBridge で受信し、自動的に Lambda で Cold ストレージへの移行を実行するパイプラインを構築。運用チームの介入なしに最適化を自動化。

JSON EventBridge ルールパターン 
{
  "source": ["aws.opensearch"],
  "detail-type": ["OpenSearch Service Cluster Insight"],
  "detail": {
    "insightType": ["UNUSED_INDEX"]
  }
}

💰 料金情報

Cluster Insights は 追加コストなし で利用可能。Amazon OpenSearch Service が利用可能なすべてのリージョンで自動的に提供されます。

ただし、推奨アクションとして実施する Warm/Cold ストレージへの移行には、それぞれのストレージ層の料金が適用されます。

ストレージ層の比較

高パフォーマンス

🌏 利用可能リージョン

Amazon OpenSearch Service が利用可能な すべてのリージョン で Cluster Insights を利用できます。東京リージョン (ap-northeast-1) を含むすべての商用リージョンが対象です。
