📋 概要

Amazon Bedrock AgentCore が、本番環境で稼働する AI エージェントのパフォーマンスを最適化するための 3 つの新機能 をプレビューとしてリリース。「観測 (Observe) - 評価 (Evaluate) - 改善 (Improve)」 のフルサイクルが完成します。

🔍 観測
本番トレース収集
→
📏 評価
AI 分析・推奨生成
→
✅ 検証
バッチ評価・A/B テスト
→
🚀 改善
承認・デプロイ

❌ Before

  • プロンプト最適化は開発者の手動作業に依存
  • 変更の影響を統計的に検証する仕組みがなかった
  • 本番トレースから改善点を体系的に抽出するワークフローが存在しなかった

✅ After

  • AI が本番トレースを分析し、最適化を自動で推奨
  • バッチ評価と A/B テストで統計的に有意な検証が可能に
  • 承認フローを含む安全な改善サイクルで継続的に品質向上

⚡ 主要機能

💡 Recommendations (推奨)
本番環境のトレースと評価出力を AI が分析し、最適化提案を自動生成
  • 最適化されたシステムプロンプトを自動生成 (SYSTEM_PROMPT_RECOMMENDATION)
  • 最適化されたツール説明文を自動生成 (TOOL_DESCRIPTION_RECOMMENDATION)
  • CloudWatch Logs からのトレースデータを入力として使用
  • Configuration Bundle との統合によるバージョン管理された設定変更提案
📋 Batch Evaluations (バッチ評価)
複数のエージェントセッションに対して評価器を一括実行し、推奨内容を検証
  • サーバーサイドオーケストレーションによる効率的な処理
  • 事前定義されたテストケース (Ground Truth) に対する検証
  • アサーション、期待されるツール呼び出し軌跡、ターンごとの期待応答をサポート
  • 評価結果のサマリー統計 (平均スコア、完了/失敗セッション数)
⚖️ A/B Tests (A/B テスト)
Gateway を通じた制御されたトラフィック分割による本番検証
  • 重み付きバリアント設定によるトラフィック配分
  • リアルタイムの統計的有意性レポート (p 値、信頼区間)
  • 事前定義テストセットまたはライブ本番トラフィックでの検証
  • 実行ステータス管理 (PAUSED / RUNNING / STOPPED)

🛠️ 設定手順

前提条件

1. Amazon Bedrock AgentCore が利用可能なリージョンの AWS アカウント
2. AgentCore Evaluations が設定済みであること
3. 本番環境のエージェントが CloudWatch Logs にトレースを出力していること
4. 適切な IAM 権限 (AgentCore API へのアクセス)

Step 1: 評価器の作成

Bash LLM-as-a-Judge 評価器の作成 
aws bedrock-agentcore-control create-evaluator \
  --evaluator-name "quality-evaluator" \
  --evaluator-config '{
    "llmAsAJudge": {
      "instructions": "Evaluate the agent response quality...",
      "ratingScale": {
        "numerical": [
          {"definition": "Poor", "value": 1.0, "label": "Poor"},
          {"definition": "Good", "value": 3.0, "label": "Good"},
          {"definition": "Excellent", "value": 5.0, "label": "Excellent"}
        ]
      },
      "modelConfig": {
        "bedrockEvaluatorModelConfig": {
          "modelId": "anthropic.claude-sonnet-4-20250514"
        }
      }
    }
  }' \
  --level SESSION

Step 2: 推奨の生成

Bash 本番トレースからの推奨生成 
aws bedrock-agentcore start-recommendation \
  --name "system-prompt-optimization" \
  --type SYSTEM_PROMPT_RECOMMENDATION \
  --recommendation-config '{
    "systemPromptRecommendationConfig": {
      "systemPrompt": {
        "text": "You are a helpful assistant..."
      },
      "agentTraces": {
        "cloudwatchLogs": {
          "serviceNames": ["my-agent"],
          "startTime": "2026-04-01T00:00:00Z",
          "endTime": "2026-04-30T00:00:00Z"
        }
      }
    }
  }'

Step 3: バッチ評価による検証

Bash 推奨内容のバッチ評価

🎯 ユースケース

🎧 カスタマーサポートエージェントのプロンプト最適化

カスタマーサポート用 AI エージェントの解決率が低下しているが、プロンプトのどの部分を改善すべきか特定が困難な状況

低スコアのセッションを重点的にフィルタリングし、AI が問題パターンを分析。改善すべきプロンプト要素を特定し、バッチ評価で検証後、A/B テストで本番適用前に効果を確認。

→ データドリブンなプロンプト改善で解決率を向上

🔧 ツール選択精度の向上

マルチツールエージェントで、ツールの選択ミスが頻発しており、ツール説明文の改善が必要な状況

AI がトレースからツール選択エラーのパターンを分析し、各ツールの説明文をより明確で区別しやすい形に最適化。TOOL_DESCRIPTION_RECOMMENDATION により具体的な改善案を生成。

→ ツール選択の正確性向上でエージェント全体の品質改善

🚀 段階的ロールアウトによる安全なデプロイ

推奨されたプロンプト変更を本番環境に安全に適用したい。段階的にトラフィックを移行しながら効果を検証する

最初は 10% のトラフィックで A/B テストを開始し、統計的有意性が確認された段階でトラフィック比率を徐々に増加。p 値と信頼区間によりリスクを定量評価。

→ リスク最小化しながら本番デプロイを安全に実行

✅ メリット

📈 継続的な品質向上

本番データに基づく自動最適化により、エージェントの応答品質が継続的に改善される

🛡️ リスク軽減

承認フローと段階的検証により、本番障害のリスクを最小化しながら改善を実施

💰 運用コスト削減

プロンプトエンジニアリングの手動作業を AI が代替し、開発者の工数を削減

📊 データドリブン最適化

本番トレースに基づく客観的な分析により、直感ではなくデータに基づいた改善が可能

🧪 統計的検証

A/B テストによる p 値と信頼区間の算出により、改善効果の統計的有意性を確認

🗂️ バージョン管理統合

Configuration Bundle によるプロンプト・ツール設定の版管理とブランチ管理を実現

⚠️ 制限事項・考慮点

制限事項

  • プレビュー段階であり、一般提供 (GA) までに仕様変更の可能性がある
  • AgentCore Evaluations が利用可能なリージョンでのみ利用可能
  • 推奨の生成には十分な本番トレースデータが必要であり、トラフィックが少ないエージェントでは効果が限定的

考慮すべき点

  • A/B テストのトラフィック分割は Gateway を経由するため、Gateway の設定が前提
  • 統計的有意性を得るためには一定量のトラフィックと期間が必要
  • 推奨が必ずしも改善につながるとは限らないため、バッチ評価での検証を省略しないことが重要
