🔎 Amazon OpenSearch intelligent ingestion

S3 のログとドキュメントを、パイプラインコードなしで検索可能なインデックスに変換するフルマネージド機能

📋 概要

Amazon OpenSearch Serverless に intelligent ingestion が登場。Amazon S3 に保存されたログやドキュメントを、インジェスト基盤を管理することなく OpenSearch Serverless (NextGen) コレクションの検索可能なコンテンツに変換します。コンソールで数クリック、または単一の API 呼び出しでセットアップでき、サービスがデータタイプの自動検出、パース、画像のテキスト化、チャンク分割、埋め込み生成、インデックス登録までを自動実行します。

❌ アップデート前の課題

  • S3 のデータ検索には OpenSearch Ingestion パイプライン (Data Prepper) や独自基盤の構築・管理が必要
  • PDF / Word の検索可能化には、パース・チャンク分割・埋め込み生成を外部サービスや自前コードで組み合わせる必要
  • 図やスクリーンショットなどの視覚情報は、別途画像理解の仕組みがない限り検索対象にできない
  • インジェスト用キャパシティ管理 (最小 / 最大 OCU) をユーザー自身が実施

✅ アップデート後の改善

  • コレクションの「Ingestion」タブから数クリック、または単一 API でインジェスト開始
  • パース、画像理解、チャンク分割、埋め込み生成がマネージドで提供され、パイプラインコード不要
  • 一回限りのジョブと継続ストリームを選択でき、バックフィル後にストリーミングへ移行するパターンにも対応
  • ワークロードに応じて自動スケールし、ジョブ完了後は課金が停止

S3 のオブジェクトは、一回限りのジョブ (実線) では直接スキャンされ、継続的なストリーム (点線) では S3 イベント通知を受け取る SQS キュー経由で処理されます。構造化データ (JSON / NDJSON / JSON 配列) の場合はパースと画像理解をスキップし、変換と埋め込み生成 (オプション) が適用されます。

⚡ 主要機能

🛠️ インジェスト基盤の管理が不要なフルマネージドインジェスト

  • NextGen コレクションから直接インジェストを作成・管理。パイプラインリソースや文書処理インフラのプロビジョニング不要
  • コンソールの「Ingestion」タブから数クリック、または単一の API 呼び出しでセットアップ
  • 処理キャパシティはコレクションの最大 OCU 上限まで自動スケール

📊 構造化データ (ログ) の処理

  • JSON、NDJSON (改行区切り JSON)、JSON 配列形式のオブジェクトからレコードを読み取り
  • フィールド / ドキュメント変換を適用し、パイプラインコードなしでインデックス登録
  • 設定したテキストフィールドへのベクトル埋め込み生成をオプションで実行可能

📄 非構造化ドキュメントのインテリジェントな処理

  • PDF、Word、プレーンテキスト、Markdown からテキストを抽出
  • 見出し、読み順、表などの文書構造を保持したままパースし、セマンティック検索・ハイブリッド検索に対応
  • 検索に適したサイズのチャンクに分割し、スパース埋め込みを生成
  • 元の S3 オブジェクトを特定できるソースメタデータ (s3_uri、s3_bucket) を保持

🖼️ 視覚コンテンツの検索可能化

  • チャート、図、スクリーンショット、写真に対して視覚言語モデルがテキスト説明を生成
  • 説明文は周囲の文書コンテンツとともにインデックスされ、画像にしか含まれない情報も検索・取得可能

🔄 2 つのインジェストパターン

  • インジェストジョブ (一回限り): 既存データセットのロード・再ロードに使用。移行、バックフィル、PoC に適し、繰り返し実行のスケジュールも可能
  • インジェストストリーム (継続): S3 イベント通知 (SQS 経由) で新規オブジェクトを継続処理。「Continuous streaming」と「Backfill then stream」を選択可能

🏢 クロスアカウントソース対応

  • ソースの S3 バケットは同一アカウントでも別アカウントでも指定可能
  • クロスアカウントの場合は IAM ロールとリソースポリシーによるアクセス許可の設定が必要

非構造化ドキュメントはチャンクごとに個別のドキュメントとしてインデックスされます。同一ソースオブジェクト由来のチャンクが近くに格納されるよう、ソースバケットとオブジェクトキーに基づいてルーティング値 (_routing) が設定されます。

📝 設定方法

前提条件

✓OpenSearch Serverless NextGen コレクションが作成済みであること
✓インジェスト対象のデータまたはドキュメントを含む S3 バケットが準備されていること
✓インジェスト API の呼び出しとソース / ターゲットへのアクセスを許可する IAM 権限およびデータアクセスポリシーが設定されていること
✓(継続ストリームの場合) S3 イベント通知を SQS キューへ送信する設定と、サービスが引き受けるインジェストロールが構成されていること

ステップ 1: ドキュメント抽出用インデックスの事前作成 (ドキュメントの場合)

Bash semantic enrichment を有効化したインデックス作成 
aws opensearchserverless create-index \
    --id <コレクション ID> \
    --index-name <インデックス名> \
    --index-schema '{
      "mappings": {
        "properties": {
          "text": {
            "type": "text",
            "semantic_enrichment": {
              "status": "ENABLED",
              "language_options": "english"
            }
          }
        }
      }
    }' \
    --region <リージョン>

text フィールドに automatic semantic enrichment を有効化したインデックスを作成します。ドキュメント抽出のスパース埋め込み生成には、このフィールド設定が必須です。インジェスト開始時にインデックスが存在しない場合、semantic enrichment なしでインデックスが自動作成され、スパース埋め込みは生成されません。日本語などの英語以外のコンテンツでは language_options に multi-lingual を指定します。

ステップ 2: インジェストジョブの作成

Bash 一回限りのインジェストジョブ作成 
aws opensearchserverless create-ingestion-job \
    --collection-id <コレクション ID> \
    --ingestion-job-name <ジョブ名> \
    --index-name <インデックス名> \
    --source '{"s3":{"bucket":"arn:aws:s3:::<ソースバケット名>","bucketOwnerAccountId":"<バケット所有者アカウント ID>","keyPrefix":"<キープレフィックス>"}}' \
    --region <リージョン>

ソースの S3 バケット (ARN 指定)、スキャン対象を絞るキープレフィックス (オプション)、ターゲットインデックスを指定します。ジョブは即座に開始され、対象オブジェクトの処理が完了すると終了します。コンソールの場合は、コレクションの「Ingestion」タブから「Create ingestion job」を選択し、「One-time job」を設定します。

ステップ 3: ジョブの監視と結果の確認

Bash ジョブ進捗の確認 
aws opensearchserverless get-ingestion-job \
    --collection-id <コレクション ID> \
    --ingestion-job-id <ジョブ ID> \
    --region <リージョン>

作成時のレスポンスに含まれる ingestionJobId を指定して進捗を確認します。ステータスが COMPLETED になったら、ターゲットインデックスにクエリを実行して結果を検証します。スキャン済み・インデックス済み・失敗したオブジェクト数はコンソールからも監視できます。

ステップ 4: 継続同期が必要な場合はインジェストストリームを作成

Bash 継続的なインジェストストリーム作成 
aws opensearchserverless create-ingestion-stream \
    --collection-id <コレクション ID> \
    --ingestion-stream-name <ストリーム名> \
    --index-name <インデックス名> \
    --role-arn arn:aws:iam::<アカウント ID>:role/<インジェストロール名> \
    --source '{"s3":{"sqsArn":"arn:aws:sqs:<リージョン>:<アカウント ID>:<キュー名>"}}' \
    --region <リージョン>

S3 イベント通知を受信する SQS キューと、サービスが引き受けるインジェストロールを指定してストリームを作成します。ストリームはアクティブになると、キューに届く新規オブジェクトの通知を継続的に処理します。既存オブジェクトも含めて処理する場合は、コンソールで「Backfill then stream」を選択します。

💡 メリット

💼 ビジネス面

✓構築期間の大幅短縮: パイプラインコードや文書処理インフラの開発なしで、S3 のデータを数クリックで検索可能にでき、ログ分析基盤や RAG ナレッジベースの立ち上げを加速
✓運用コストの削減: インジェスト基盤のプロビジョニング、スケーリング、保守が不要になり、運用チームの負担を軽減
✓従量課金によるコスト効率: アクティブな処理に対してのみ課金され、ジョブ完了後は課金が停止。一時的なロードやバックフィルを低コストで実行可能

⚙️ 技術面

✓文書構造を保持した高品質なパース: 見出し、読み順、表を保持してチャンク分割するため、セマンティック検索や RAG での回答品質向上が期待できる
✓視覚情報の検索可能化: チャートやスクリーンショットにしか存在しない情報も、視覚言語モデルによる説明文生成でテキスト検索の対象に
✓柔軟なインジェストパターン: 一回限りのジョブ、継続ストリーミング、バックフィル後ストリーミングを用途に応じて使い分け可能
✓自動スケーリング: 最大 OCU 上限までワークロードに応じて自動スケールし、キャパシティの事前設計が不要

⚠️ デメリット・制約事項

制限事項

●対象は OpenSearch Serverless NextGen コレクションのみ。Classic コレクションおよびマネージドドメインは宛先として利用不可
●非構造化ドキュメントは PDF、Word、プレーンテキスト、Markdown のみ。構造化データは JSON、NDJSON、JSON 配列のみをサポート
●圧縮されたオブジェクト (gzip など) は非対応
●ベクトル埋め込み生成の対象となる非構造化オブジェクトは 1 件あたり 60 MB、150 ページまで
●アカウントあたりインジェストジョブ 100 件、インジェストストリーム 20 件のソフトリミット (Service Quotas で引き上げ可能)
●利用可能リージョンは一部に限られ、サポートされるコンテンツタイプや処理オプションはリージョンにより異なる場合がある

考慮すべき点

⚠ドキュメント抽出でスパース埋め込みを生成するには、text フィールドに automatic semantic enrichment を有効化したインデックスの事前作成が必要 (存在しない場合は埋め込みなしで自動作成される)
⚠継続ストリームでは S3 イベント通知と SQS キュー、サービスが引き受けるインジェストロールの構成が必要で、ジョブよりセットアップ項目が多い
⚠画像理解にはモデル推論料金が、埋め込み生成には埋め込みモデルの推論料金が別途発生。大量の画像を含むドキュメントではコストの事前見積もりが望ましい
⚠より細かいパイプライン制御 (Data Prepper のプロセッサ構成など) や、ログ・メトリクス・トレースのストリーミング変換が必要な場合は、引き続き Amazon OpenSearch Ingestion の利用が適している

🎯 ユースケース

1️⃣ S3 上のドキュメントから RAG 用ナレッジベースを構築

シナリオ: 社内規程、製品マニュアル、技術レポートなどの PDF / Word ファイルが S3 に蓄積されており、生成 AI アプリケーションの RAG 用に検索可能なベクトルインデックスを構築したい。

  1. NextGen コレクションに semantic enrichment を有効化したインデックスを作成
  2. ドキュメント格納バケットを指定して「Backfill then stream」のストリームを作成
  3. 既存ドキュメントがバックフィルされ、以降の新規アップロードも自動で同期
  4. アプリケーションから text / text_embedding / headings を使ったハイブリッド検索で関連チャンクを取得し、LLM のコンテキストに利用

✅ 効果: パース、チャンク分割、埋め込み生成のコードを一切書かずに、常に最新のドキュメントと同期した RAG ナレッジベースを運用できる。図表やスクリーンショットの情報も検索対象になる。

2️⃣ S3 に出力された観測性ログの検索・分析

シナリオ: アプリケーションや各種サービスのログが NDJSON 形式で S3 に集約されており、障害調査のために OpenSearch で全文検索・分析できるようにしたい。

  1. ログバケットに S3 イベント通知を設定し、SQS キューへ送信
  2. インジェストロールを作成し、SQS / S3 / コレクションへのアクセスを許可
  3. create-ingestion-stream でログ用インデックスへの継続ストリームを作成
  4. 新しいログオブジェクトが到着するたびに自動で変換・インデックス登録

✅ 効果: Data Prepper パイプラインの構築・チューニングなしで、S3 着信からの継続的なログインジェストを実現できる。キャパシティは自動スケールするため、ログ量の変動にも追従できる。

3️⃣ 既存データセットの移行・バックフィル

シナリオ: 過去数年分の JSON データや文書アーカイブが S3 に保存されており、新規に構築した OpenSearch Serverless コレクションへ一括ロードしたい。

  1. create-ingestion-job でバケットとキープレフィックスを指定した一回限りのジョブを作成
  2. get-ingestion-job でステータスが COMPLETED になるまで進捗を監視
  3. 失敗したオブジェクトは <インデックス名>-ingestion-failures インデックスで内容を確認し、必要に応じて再実行

✅ 効果: ジョブは処理完了後にインジェスト課金が停止するため、一時的な大量ロードをコスト効率よく実行できる。定期的な繰り返しロードのスケジュール実行にも対応する。

💰 料金

intelligent ingestion は、ワークロードが消費した処理に対して課金されます。構成とコンテンツに応じて、以下の料金が発生します。

  • 💻 データの読み取り・変換・インデックス登録に使用するインジェストコンピューティング
  • 📄 ドキュメントのパースとチャンク分割に使用する追加の文書処理コンピューティング
  • 🖼️ 画像理解に使用するモデルの入出力トークン
  • 🧮 構成に応じた埋め込みモデルの推論
💡インジェストジョブは完了後にインジェストキャパシティの消費が停止し、インジェストストリームは処理すべきデータがあるときにリソースを消費します。宛先となる NextGen コレクションのインデックス登録・検索・ストレージの料金は、intelligent ingestion の料金とは別に発生します。

詳細は Amazon OpenSearch Service 料金ページ および (モデル料金について) Amazon Bedrock 料金ページ を参照してください。

📌 まとめ

Amazon OpenSearch Serverless の intelligent ingestion により、S3 上のログやドキュメントを、パイプラインコードやインジェスト基盤の管理なしで検索可能なインデックスに変換できるようになりました。文書構造の保持、画像のテキスト化、チャンク分割、埋め込み生成までマネージドで提供されるため、RAG ナレッジベースやログ検索基盤の構築ハードルが大きく下がります。

S3 にデータを蓄積している NextGen コレクション利用者は、まず一回限りのインジェストジョブで小規模なデータセットを試し、semantic enrichment 付きインデックスとの組み合わせによる検索品質を評価することを推奨します。
