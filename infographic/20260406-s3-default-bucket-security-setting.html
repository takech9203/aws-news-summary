🔒 Amazon S3 - デフォルトバケットセキュリティ設定による SSE-C 自動無効化

新規バケットで SSE-C をデフォルト無効化し、セキュリティベストプラクティスを自動適用
Amazon S3
📅 2026 年 04 月 06 日
🌍 37 リージョン展開

📝 概要

Amazon S3 が、すべての新規汎用バケットに対して SSE-C を自動無効化する新しいデフォルトセキュリティ設定を展開開始しました。2025 年 11 月 19 日に発表され、37 の AWS リージョン (中国 / GovCloud 含む) に順次適用されています。

SSE-C はユーザー管理の暗号化キーで S3 オブジェクトを暗号化する方式ですが、キー紛失によるデータ消失リスクやインシデント対応の複雑さが課題でした。今回、AWS がデフォルトで SSE-C の使用を防止します。

🔄 Before / After

😟 Before
  • SSE-C がデフォルトで許可
  • 意図しない SSE-C 使用リスク
  • キー紛失 = データ消失
  • 手動でバケットポリシー設定が必要
  • 組織全体の SSE-C 制御が困難
→
😊 After
  • SSE-C が自動的に無効化
  • ベストプラクティスがデフォルト適用
  • 既存バケットも自動無効化
  • SSE-C 使用中のアカウントは影響なし
  • 追加設定不要

新規バケットは無条件で SSE-C 無効化。既存バケットは SSE-C オブジェクトの有無で判定。

⭐ 主要機能

1. 新規バケットの SSE-C 自動無効化
  • すべての新規汎用バケットで SSE-C が自動的に無効化
  • バケット作成時に追加の設定は不要
  • SSE-S3 / SSE-KMS は引き続き利用可能
2. 既存バケットへの段階的適用
  • SSE-C オブジェクトなしのアカウントが対象
  • 自動的に SSE-C を無効化し、新規書き込みをブロック
  • SSE-C 使用中のアカウントは変更されない
3. グローバル展開
  • 37 の AWS リージョンに展開
  • 中国リージョンおよび GovCloud を含む
  • 全リージョンで同一のベストプラクティス適用
💡 SSE-C を引き続き使用する場合は、バケットの暗号化設定を明示的に変更して再有効化可能。ただし AWS は SSE-S3 / SSE-KMS の使用を推奨。

🛠️ 設定方法

前提: AWS CLI v2 + 適切な IAM 権限

Step 1: 暗号化設定を確認
Bash暗号化設定の確認
aws s3api get-bucket-encryption \
  --bucket my-bucket
Step 2: SSE-C 使用状況を確認
Bashオブジェクトの暗号化を確認
aws s3api head-object \
  --bucket my-bucket \
  --key my-object

SSECustomerAlgorithm が存在する場合、SSE-C で暗号化。

Step 3: SSE-KMS に移行する場合
Bash暗号化方式の移行
aws s3api update-object-encryption \
  --bucket my-bucket \
  --key my-object \
  --server-side-encryption aws:kms \
  --ssekms-key-id arn:aws:kms:region:account-id:key/key-id

大規模移行には S3 Batch Operations を推奨。

🛡️運用リスク軽減: SSE-C キー管理に起因するデータ消失リスクを低減

⚠️ デメリット・制約事項

制限事項
  • SSE-C を意図的に使用する場合、新規バケットで再有効化が必要
  • 自動無効化のタイミングはリージョンごとに異なり、制御不可
  • ディレクトリバケット (S3 Express One Zone) は対象外
考慮すべき点
  • SSE-C 使用のサードパーティツールは新規バケットで動作確認が必要
  • SSE-C 再有効化が必要な場合、自動化スクリプトの更新が必要な場合あり

💡 ユースケース

1セキュリティガバナンスの強化

大規模組織で複数チームがバケットを作成する環境。意図しない SSE-C 使用を防止し、一貫した暗号化ポリシーを維持。

2コンプライアンス要件への対応

金融・医療業界など厳格なデータ暗号化要件がある環境。SSE-KMS / SSE-S3 の使用が促進され、監査証跡とキー管理の一元化を実現。

3既存環境の SSE-C からの移行

キー管理の運用負荷軽減のため SSE-KMS へ移行。S3 Batch Operations で一括移行が可能。

BashS3 Batch Operations で一括移行
aws s3control create-job \
  --account-id 123456789012 \
  --operation '{"S3PutObjectCopy":{
    "TargetResource":"arn:aws:s3:::my-bucket",
    "SSEAwsKmsKeyId":"arn:aws:kms:region:account-id:key/key-id"
  }}' \
  --manifest '{"Spec":{
    "Format":"S3BatchOperations_CSV_20180820",
    "Fields":["Bucket","Key"]},
    "Location":{
      "ObjectArn":"arn:aws:s3:::manifest-bucket/manifest.csv",
      "ETag":"manifest-etag"
  }}' \
  --report '{"Bucket":"arn:aws:s3:::report-bucket",
    "Prefix":"reports/",
    "Format":"Report_CSV_20180820",
    "Enabled":true,
    "ReportScope":"AllTasks"}' \
  --priority 1 \
  --role-arn arn:aws:iam::123456789012:role/S3BatchRole \
  --region us-east-1

📌 まとめ: Amazon S3 が SSE-C の自動無効化をデフォルトで展開開始。新規バケットおよび SSE-C 未使用の既存バケットが対象で、SSE-C 使用中のアカウントには影響なし。SSE-C を使用しているユーザーは、現在のワークロードへの影響を確認し、可能であれば SSE-KMS または SSE-S3 への移行を検討することを推奨します。
