Amazon EC2 Auto Scaling

⚙️ Reservations Then Balanced

キャパシティ予約優先の AZ 分散戦略
📅 リリース日
2026 年 6 月 30 日

📌 概要

Amazon EC2 Auto Scaling に、新しいアベイラビリティゾーン (AZ) 分散戦略 reservations-then-balanced が追加されました。Auto Scaling グループのインスタンス起動時に、まず関連付けられたキャパシティ予約への起動を優先し、予約が満たされた後に残りのキャパシティを各 AZ へ均等に分散します。

これにより、On-Demand Capacity Reservations (ODCR)、Capacity Blocks、Interruptible Capacity Reservations といった事前購入済みキャパシティの利用率を最大化しつつ、Auto Scaling の運用のシンプルさと回復性を維持できます。GPU、HPC、機械学習などコスト重視のワークロードでの活用が想定されています。

Before / After

⚠️ アップデート前の課題
  • AZ 間でインスタンス数を均等に保つことを優先するため、特定 AZ の予約を活用しきれない場合があった
  • 事前購入した予約 (ODCR や Capacity Blocks) を使い切れず、未使用コストが発生するリスク
  • 予約利用率を高めるには AZ ごとにグループを分けるなど運用が煩雑
✅ アップデート後の改善
  • 予約への起動を最優先する分散戦略を Auto Scaling グループに宣言的に指定可能に
  • 予約を使い切った後に残りを各 AZ へ均等分散。利用率最大化と AZ 分散を両立
  • スケールインも最適化され、予約外のインスタンスから優先的に削除される

Auto Scaling はまずキャパシティ予約への起動を優先し、予約を使い切った後に残りのキャパシティを各 AZ へ均等に分散します。

🚀 主要機能

🎟️ 1. キャパシティ予約優先の起動
  • グループに関連付けられた予約への起動を、AZ 間の均等分散よりも優先
  • 事前購入済みの予約キャパシティを最大限活用できる
  • ODCR、Capacity Blocks、Interruptible Capacity Reservations に対応
⚖️ 2. 予約充填後の均等分散
  • すべての予約が満たされた後、残りのキャパシティを有効化された各 AZ へ均等分散
  • 予約利用率の最大化と AZ 分散による回復性の両立を図る
📉 3. 予約利用率を保つスケールイン動作
  • スケールイン時はまず予約に含まれないインスタンスから削除し、予約利用率を維持
  • さらに削減が必要な場合は、予約インスタンス数が最も多い AZ から削除

🔧 技術仕様

AZ 分散戦略の比較

戦略動作主な用途
balanced-best-effort 各 AZ へ均等にインスタンスを維持。起動失敗時は他の正常な AZ で起動を試行 AZ 冗長性が必要で、グループの偏りを許容できるアプリケーション
balanced-only 各 AZ へ均等に維持。起動失敗時も同じ AZ で起動を試行し続ける クォーラムベースのワークロードなど特定要件がある場合
reservations-then-balanced まずキャパシティ予約へ起動し、予約充填後に残りを各 AZ へ均等分散 予約を使う GPU、HPC、機械学習などコスト重視のワークロード

主な構成項目

項目詳細
設定箇所Auto Scaling グループの AvailabilityZoneDistribution 構成
予約の指定方法Capacity Reservation Group ARN、または個別の Capacity Reservation ID
予約の指定場所起動テンプレート (複数の予約を優先する場合は予約ごとに別の起動テンプレート)
対応予約タイプODCR、Capacity Blocks、Interruptible Capacity Reservations
追加料金なし (標準の EC2 料金)

⚙️ 設定方法

前提条件

✓対象のキャパシティ予約 (ODCR、Capacity Blocks、Interruptible Capacity Reservations) が作成済みであること
✓起動テンプレートでキャパシティ予約を指定していること (Group または個別 ID)
✓Auto Scaling グループが該当する AZ で有効化されていること

ステップ 1: マネジメントコンソールでの設定

Auto Scaling グループの作成・更新時の [Network] セクションで、AZ 分散戦略として [Reservations then balanced] を選択します。あわせて優先するキャパシティ予約を Capacity Reservation group または個別の Capacity Reservation ID で指定します。

ステップ 2: AWS CLI での設定

Bash 既存グループへの適用 
aws autoscaling update-auto-scaling-group \
  --auto-scaling-group-name my-asg \
  --availability-zone-distribution CapacityDistributionStrategy=reservations-then-balanced

update-auto-scaling-group で既存グループに戦略を適用します。新規作成時は create-auto-scaling-group で同様に指定できます。

ステップ 3: 起動テンプレートでの予約指定

複数のキャパシティ予約を優先したい場合は、予約ごとに個別の起動テンプレートを用意し、それぞれで対象の Capacity Reservation Group または Capacity Reservation ID を指定します。

💡 メリット

📈 ビジネス面

✓予約コストの最大活用: 未使用予約による無駄なコストを削減
✓運用のシンプルさ維持: 標準的な運用フローの中で宣言的に実現
✓コスト重視ワークロードへの最適化: GPU や機械学習で効果大

🛠️ 技術面

✓予約と AZ 分散の両立: 余剰分は AZ へ均等分散して回復性を確保
✓柔軟な予約指定: Group ARN と個別 ID の両方で指定可能
✓スマートなスケールイン: 予約外インスタンスから優先削除

⚠️ デメリット・制約事項

🚧 制限事項

!予約利用率の最大化が AZ 均等分散より優先されるため、予約が特定 AZ に偏るとインスタンス配置も偏る可能性
!複数の予約を優先する場合、予約ごとに個別の起動テンプレートが必要

🤔 考慮すべき点

!厳密な AZ 冗長性が必須なワークロードでは balanced-best-effort や balanced-only との比較検討が必要
!予約枯渇後にのみ均等分散されるため、予約のキャパシティ計画が配置結果に直接影響

🎯 ユースケース

1. GPU を利用する機械学習トレーニング
シナリオ: 機械学習トレーニング用に GPU インスタンスの Capacity Blocks を事前購入しており、その予約を確実に使い切りたい。
実装例: 戦略 = reservations-then-balanced / 予約指定 = Capacity Reservation Group ARN (GPU 予約をグループ化)
✅ 効果: 高コストな GPU 予約を優先的に充填し、予約利用率を最大化できる。
2. HPC クラスターのコスト最適化
シナリオ: HPC ワークロード向けに ODCR を確保しているが、需要変動に応じて Auto Scaling でスケールしたい。
実装例: 戦略 = reservations-then-balanced / 予約指定 = 個別の Capacity Reservation ID / スケールアウト分 = 予約充填後に各 AZ へ均等分散
✅ 効果: 予約分を優先消費しつつ、超過分は AZ へ分散して回復性を維持できる。
3. Interruptible Capacity Reservations の活用
シナリオ: 中断耐性のあるバッチ処理で Interruptible Capacity Reservations を活用し、コストを抑えたい。
実装例: 戦略 = reservations-then-balanced / 予約指定 = Interruptible Capacity Reservations
✅ 効果: 割安な中断可能予約を優先的に使い切り、処理コストを削減できる。

💰 料金・リージョン・関連サービス

💵 料金

この機能の利用に追加料金はありません。標準の EC2 料金が適用され、キャパシティ予約分の料金に加え、グループが起動するオンデマンドまたはスポットインスタンスの料金を支払います。

🌐 利用可能リージョン

すべての AWS 商用リージョンで利用可能です。

🔗 関連サービス・機能

→ODCR: 特定 AZ でキャパシティを予約。本戦略の優先対象
→Capacity Blocks for ML: 機械学習向けに GPU を期間指定で予約。本戦略で優先充填
→EC2 起動テンプレート: 優先するキャパシティ予約の指定に使用

📝 まとめ

reservations-then-balanced は、キャパシティ予約への起動を最優先しつつ余剰分を AZ へ均等分散する新しい分散戦略です。GPU や HPC、機械学習といったコスト重視のワークロードで、事前購入済みキャパシティの利用率を最大化できます。

追加料金なくすべての商用リージョンで利用可能なため、ODCR や Capacity Blocks を活用している場合は、Auto Scaling グループの AZ 分散戦略として本戦略の適用を検討してください。
