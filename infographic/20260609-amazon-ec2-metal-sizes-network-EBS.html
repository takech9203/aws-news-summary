ネットワーク / EBS 最適化インスタンス向け
metal-48xl・metal-96xl サイズが一般提供

M8in / M8ib / M8idn / M8idb / R8in / R8ib / R8idn / R8idb の 8 ファミリー
📅 2026 年 6 月 9 日

📌 概要

AWS は、第 8 世代のネットワーク最適化・EBS 最適化インスタンスに対して、新しい metal-48xl (192 vCPU) および metal-96xl (384 vCPU) のベアメタルサイズの一般提供を発表しました。 これらは AWS 専用のカスタム第 6 世代 Intel Xeon Scalable プロセッサと第 6 世代 AWS Nitro Cards を搭載し、 前世代 (M6in/M6idn/R6in/R6idn) 比で vCPU あたり最大 43% 優れたコンピューティング性能を提供します。

これにより、ハイパーバイザーを介さない直接的なハードウェアアクセスを必要とするワークロードでも、 ネットワーク系の 600 Gbps 帯域幅、EBS 系の 最大 300 Gbps 帯域幅を活用できるようになりました。

  • ✕ 第 8 世代ネットワーク/EBS 最適化系にベアメタルサイズが無かった
  • ✕ 直接的なハードウェアアクセスが必要なワークロードで利用できなかった
  • ✕ 仮想化を許可しないライセンスや独自ハイパーバイザーで高帯域幅インスタンスを活用しにくかった

✅ アップデート後の改善

  • ✓ metal-48xl (192 vCPU)・metal-96xl (384 vCPU) が利用可能に
  • ✓ ベアメタルで 600 Gbps ネットワーク / 300 Gbps EBS を活用可能
  • ✓ 48xlarge / 96xlarge / metal-48xl / metal-96xl で EFA をサポート
  • ✓ 前世代比 vCPU あたり最大 43% の性能向上

🔧 主要機能

🆕 1. 新しいベアメタルサイズの追加

  • metal-48xl: 192 vCPU / metal-96xl: 384 vCPU
  • ハイパーバイザーを介さず基盤サーバーハードウェアへ直接アクセス
  • 対象は M8in / M8ib / M8idn / M8idb / R8in / R8ib / R8idn / R8idb の 8 ファミリー

🌐 2. 高いネットワーク帯域幅 (M8in/M8idn/R8in/R8idn)

  • 600 Gbps のネットワーク帯域幅 — Enhanced Networking 対応 EC2 で最高
  • リアルタイムビッグデータ分析、分散型インメモリキャッシュ、AI/ML クラスタのキャッシュフリート、Telco 5G UPF に最適

💽 3. 高い EBS 帯域幅 (M8ib/M8idb/R8ib/R8idb)

  • 最大 300 Gbps の EBS 帯域幅 — 非アクセラレーテッドコンピューティング EC2 で最高
  • 高性能ファイルシステム、NoSQL データベース、大規模商用データベース、データレイクに最適

🔗 4. Elastic Fabric Adapter (EFA) のサポート

  • 48xlarge / 96xlarge / metal-48xl / metal-96xl の各サイズで EFA をサポート
  • 密結合された HPC やクラスタワークロードで低レイテンシと高いクラスタ性能を実現

API 変更履歴

今回のアップデートに直接関連する API の変更はありません。新しいインスタンスサイズは既存の EC2 API (RunInstances など) で InstanceType に指定することで利用できます。

⚙️ 設定方法

前提条件

→AWS US East (N. バージニア) リージョンで EC2 を利用できる権限を持つアカウント
→対象インスタンスの起動に必要な vCPU クォータ (事前の引き上げが必要な場合あり)
→ベアメタル使用時は OS / アプリケーションがベアメタル環境に対応していること

ステップ 1: 利用可能なインスタンスタイプの確認

Bashdescribe-instance-types
aws ec2 describe-instance-types \
  --filters "Name=instance-type,Values=m8in.metal-48xl,m8in.metal-96xl" \
  --region us-east-1

ステップ 2: ベアメタルインスタンスの起動

Bashrun-instances
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type m8in.metal-48xl \
  --region us-east-1 \
  --count 1

--instance-type を r8ib.metal-96xl などに変更することで他のファミリーやサイズを起動できます。

ステップ 3: EFA を有効化したクラスタ構成 (任意)

密結合された HPC やキャッシュクラスタを構築する場合は、EFA 対応のネットワークインターフェイスを作成し、 クラスタプレイスメントグループ内でインスタンスを起動します。これにより低レイテンシと高いクラスタ性能を実現できます。

⚖️ メリットと制約事項

✅ メリット

✓移行容易性: 仮想化を許可しないライセンスや独自ハイパーバイザーのアプリを最新世代へ移行可能
✓コスト効率: vCPU あたり最大 43% の性能向上でより少ないリソースで処理できる可能性
✓大規模集約: metal-96xl の 384 vCPU で大規模 DB・分析基盤を単一インスタンスに集約
✓直接ハードウェアアクセス: ハイパーバイザーのオーバーヘッドなしで全リソースを活用
✓最高クラスの帯域幅: 600 Gbps ネットワーク / 最大 300 Gbps EBS をベアメタルで利用

⚠️ 制約・考慮点

!現時点では AWS US East (N. バージニア) リージョンのみ
!600 Gbps はネットワーク系のみ、300 Gbps EBS は EBS 系のみが対象
!大規模サイズのため相応の vCPU クォータと予算が必要
!ベアメタルは仮想化インスタンスより起動に時間がかかる場合がある
!全リソースを使い切れない場合は仮想化 48xlarge/96xlarge の方がコスト効率が良い可能性

💡 ユースケース

1. AI/ML クラスタ向けの大規模インメモリキャッシュ

AI/ML 学習クラスタへ高速にデータを供給する分散型インメモリキャッシュフリート。ネットワーク帯域幅がボトルネック。

構成
インスタンス: R8in.metal-96xl (384 vCPU / 3,072 GiB)
ネットワーク: 600 Gbps + EFA
構成: クラスタプレイスメントグループ内に複数台を配置

⚡ 効果: 600 Gbps + EFA でキャッシュノード間とクラスタへのデータ供給を低レイテンシで実現。

2. 大規模商用データベースのベアメタル運用

仮想化を許可しないライセンス要件を持つ大規模商用 DB を、高い EBS スループットで運用したい。

構成
インスタンス: R8ib.metal-48xl (192 vCPU / 1,536 GiB)
ストレージ: 最大 300 Gbps EBS 帯域幅

⚡ 効果: ベアメタルでライセンス要件を満たしつつ、最大 300 Gbps の EBS 帯域幅で DB I/O 性能を最大化。

3. Telco 5G UPF (User Plane Function)

5G コアネットワークのユーザープレーン機能を、低レイテンシかつ高スループットで処理したい。

構成
インスタンス: M8in.metal-96xl (384 vCPU / 1,536 GiB)
ネットワーク: 600 Gbps

⚡ 効果: ベアメタルの直接アクセスと 600 Gbps で大量のパケット処理を低レイテンシで安定実行。
