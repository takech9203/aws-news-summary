🤖 Reflection 社の Beam モデルが SageMaker JumpStart で利用可能に

📅 リリース日: 2026 年 10 月 21 日 | サービス: Amazon SageMaker AI (SageMaker JumpStart) / AWS Trainium

📌 概要

米国の AI 企業 Reflection 社初のオープンウェイトモデル「Beam」が Amazon SageMaker JumpStart で利用可能になりました。 Beam は同クラスのオープンウェイトモデルにおけるフロンティア性能を主張し、推論 (reasoning)、コーディング、エージェント系ベンチマークで高いパフォーマンスを示すとされています。 Apache 2.0 ライセンスで公開されているため、重みの検査・変更やファインチューニングを含む完全なカスタマイズが可能です。

本モデルは AWS Trainium3 向けに移植・最適化されており、提供初日からコスト効率と高パフォーマンスを両立したデプロイオプションを選択できます。 モデルはお客様自身の AWS アカウント内で実行されるため、データを外部に出すことなく、既存の AWS のセキュリティ・コンプライアンス機能で保護された状態でフロンティアモデルを活用できます。

Reflection 社の共同創業者兼 CEO である Misha Laskin 氏は「開発者が API を通じて借りるのではなく、実際にコントロールできるフロンティア AI を提供する」と述べており、モデルの完全なコントロールを重視する組織が主な対象ユーザーです。

❌ アップデート前の課題

✗フロンティア級モデルの多くはプロプライエタリで API 経由の利用に限定され、重みの検査・変更やファインチューニングができなかった
✗機密性の高いコードやデータを扱う組織では、外部 API へのデータ送信自体が制約となり、フロンティアモデルの採用が困難だった
✗オープンウェイトモデルを自前ホストする場合、推論基盤の構築・最適化や運用管理の負担が大きかった

✅ アップデート後の改善

✓SageMaker JumpStart から数クリックで Beam をフルマネージドエンドポイントとしてデプロイし、すぐに推論を開始できる
✓独自のコードやデータでファインチューニングし、自組織のドメインに特化したモデルを構築できる
✓AWS Trainium3 最適化デプロイにより、コスト効率の高い推論を初日から利用できる
✓お客様の AWS アカウント内で実行されるため、データの完全なコントロールを維持しながら、アクセス制御・監査証跡・モニタリングを活用できる

SageMaker JumpStart から Beam をデプロイし、フルマネージドエンドポイントまたは AWS Trainium3 で推論を実行する構成です。すべての処理がお客様の AWS アカウント内で完結し、ファインチューニングやエージェントワークフローへの組み込みも同一環境内で行えます。

  • SageMaker AI 標準のアクセス制御、監査証跡、モニタリングでスケール可能

  • Apache 2.0 ライセンスで公開され、重みの検査・変更が可能
  • 独自のコードやデータによるファインチューニングでドメイン特化モデルを構築可能
  • BF16、FP8、NVFP4 の 3 種類のチェックポイントバリアントを提供
🚀 3. AWS Trainium3 への最適化
  • Beam は AWS Trainium3 向けに移植・最適化済み
  • 提供初日からコスト効率と高パフォーマンスを両立したデプロイオプションを選択可能

  • ソフトウェアの課題解決、コードの生成・レビュー、運用の自動化、高度な数学・科学推論などのユースケースに対応
  • マルチステップのエージェントワークフローに組み込み可能

📝 設定方法

✅ 前提条件

  • AWS アカウントと Amazon SageMaker AI を利用できる IAM 権限があること
  • Amazon SageMaker Studio のドメインとユーザープロファイルがセットアップ済みであること
  • 利用可能リージョン (米国東部リージョン) でセットアップしていること
1
SageMaker Studio で JumpStart を開く

Amazon SageMaker Studio を起動し、ナビゲーションから SageMaker JumpStart を開きます。検索ボックスに「Beam」と入力してモデルを検索します。

2
モデルをデプロイする

モデルカードから Beam を選択し、デプロイ設定 (インスタンスタイプ、エンドポイント名など) を確認してデプロイを実行します。AWS Trainium3 ベースのインスタンスを選択することで、コスト効率の高い推論構成にできます。デプロイが完了すると、フルマネージドな SageMaker AI エンドポイントが作成されます。

3
推論を実行する
Python Beam エンドポイントの呼び出し例 
import boto3
import json

runtime = boto3.client("sagemaker-runtime")

response = runtime.invoke_endpoint(
    EndpointName="<your-beam-endpoint>",
    ContentType="application/json",
    Body=json.dumps({
        "inputs": "Explain the trade-offs of eventual consistency.",
        "parameters": {"max_new_tokens": 512}
    })
)
print(response["Body"].read().decode())

SageMaker Runtime の invoke_endpoint API でデプロイ済みの Beam エンドポイントを呼び出し、推論結果を取得します。エンドポイント名は実際にデプロイしたものに置き換えてください。

4
必要に応じてファインチューニングする

SageMaker JumpStart のファインチューニング機能、または SageMaker AI のトレーニングジョブを使用して、独自のコードやデータで Beam を特化させることができます。

💡 メリットと制約事項

📈 ビジネス面のメリット

✓データ主権の確保: モデルがお客様の AWS アカウント内で実行されるため、機密データを外部 API に送信せずにフロンティア級モデルを活用可能。政府機関や規制業界での採用ハードルが下がる
✓ベンダーロックインの回避: Apache 2.0 のオープンウェイトモデルであり、API 経由の「借用」ではなくモデル自体をコントロールできる
✓コスト効率: Trainium3 最適化により、推論コストを抑えたデプロイオプションを初日から選択できる

⚙️ 技術面のメリット

✓フルマネージド運用: 推論基盤の構築・最適化を SageMaker AI に任せられ、自前ホスティングの運用負担を軽減
✓柔軟な精度選択: BF16 / FP8 / NVFP4 で精度とコスト・レイテンシのバランスを選択可能
✓エンタープライズ機能の継承: SageMaker AI 標準のアクセス制御、監査証跡、モニタリングをそのまま利用可能

⚠️ 制限事項

✗提供リージョンは現時点で米国東部 (バージニア北部) と米国東部 (オハイオ) の 2 リージョンに限定
✗東京リージョンを含む他リージョンでの提供時期は発表されていない

🤔 考慮すべき点

⚠「同クラスのオープンウェイトモデルのフロンティア性能」はベンダーの主張であり、採用前に自組織のユースケースでのベンチマーク評価が推奨される
⚠Trainium3 での推論を利用する場合、対象リージョンでのインスタンスの利用可否とキャパシティを事前に確認する必要がある
⚠ファインチューニングやエンドポイントの常時稼働にはインスタンス利用料金が発生するため、ワークロードに応じたインスタンス選定とスケーリング設計が必要
