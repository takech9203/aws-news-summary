🔑 AWS Payment Cryptography

リソースベースポリシーによるクロスアカウント鍵共有

AWS Payment Cryptography
2026-05-04

📋 概要

AWS Payment Cryptography がリソースベースポリシー (RBP) を使用したクロスアカウント鍵共有をサポート。複数の AWS アカウント間で暗号鍵を安全に共有できるようになり、社内ワークロード間だけでなく、外部パートナー企業との鍵共有も容易に。

PCI PIN Security および P2PE 準拠のマネージドサービスとして、クラウドホスト型決済アプリケーションにおける暗号処理を簡素化。AWS PCI DSS ガイダンスに従いマルチアカウント運用を行う顧客に最適。

❌ Before

  • 鍵のインポート/エクスポートフローが必要で運用が煩雑
  • アカウントごとに鍵を複製、リネージュが失われやすい
  • アクセス制御が複雑、監査・コンプライアンス負担が大きい

✅ After

  • 鍵の単一コピーを維持しクロスアカウントアクセス実現
  • インポート/エクスポート不要、リソース単位の簡潔なアクセス制御
  • 鍵リネージュが明確、監査性・コンプライアンス対応改善

🏗️ アーキテクチャ図

⚡ 主要機能

🔐 リソースベースポリシーによる鍵共有
  • 暗号鍵リソースに直接ポリシーをアタッチし、他アカウントからのアクセスを許可
  • JSON 形式のポリシードキュメントで、きめ細かなアクセス制御が可能
  • 鍵の単一コピーを維持しながらマルチアカウントアクセスを実現
🌐 クロスアカウントアクセス制御
  • 社内の複数アカウント間での鍵共有
  • 外部パートナー企業のアカウントとの鍵共有
  • リソース単位でのアクセス許可/拒否の設定
👥 Multi-Party Approval (MPA) チーム連携 API
  • ルート公開鍵のインポート操作を保護するための MPA チーム関連付け機能
  • 機密性の高い鍵操作に対する多者承認ワークフロー
  • AssociateMpaTeam / DisassociateMpaTeam / GetMpaTeamAssociation API の追加

🔧 技術仕様

リソースベースポリシー API

⚙️ 設定方法

前提条件

1. 鍵所有者アカウントで AWS Payment Cryptography の鍵が作成済み
2. 対象アカウントの AWS アカウント ID を把握
3. payment-cryptography:PutResourcePolicy 権限を持つ IAM プリンシパルでの操作

ステップ 1: リソースベースポリシーの作成

JSON policy.json 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CrossAccountKeyAccess",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::CONSUMER_ACCOUNT_ID:root"
      },
      "Action": [
        "payment-cryptography:Encrypt",
        "payment-cryptography:Decrypt"
      ],
      "Resource": "*"
    }
  ]
}

ステップ 2: ポリシーを鍵リソースにアタッチ

Bash AWS CLI 
aws payment-cryptography put-resource-policy \
  --resource-arn "arn:aws:payment-cryptography:us-east-1:OWNER_ACCOUNT_ID:key/KEY_ID" \
  --policy file://policy.json

ステップ 3: 消費者アカウントからのアクセス確認

Bash AWS CLI - アクセス確認 
aws payment-cryptography get-key \
  --key-identifier "arn:aws:payment-cryptography:us-east-1:OWNER_ACCOUNT_ID:key/KEY_ID"

💡 メリット

📈 ビジネス面

  • 鍵管理コスト削減: 鍵の複製不要でアカウントごとの管理コストを削減
  • コンプライアンス効率化: 単一コピーで監査証跡が明確、PCI DSS 準拠の証明が容易
  • パートナー連携迅速化: API 一つで鍵共有完了、ビジネス連携リードタイム短縮

🛠️ 技術面

  • 鍵リネージュ維持: 単一コピーで出自追跡・変更管理の一元化
  • 最小権限の原則: リソース単位の細粒度アクセス制御
  • 運用簡素化: インポート/エクスポートフロー排除で運用負荷大幅削減

⚠️ デメリット・制約事項

📌 リソースベースポリシーは鍵リソースにのみアタッチ可能 (エイリアスなど他リソースタイプには適用不可の可能性)
📌 消費者アカウント側の IAM ポリシーとリソースベースポリシーの両方で許可が必要
📌 ポリシーサイズ上限あり、大量アカウント許可時は AWS Organizations 条件キー活用を検討
📌 クロスアカウントアクセスのレイテンシーが同一アカウント内より若干増加する可能性
📌 リソースベースポリシーの変更権限を厳格に管理する必要あり
📌 CloudTrail によるクロスアカウントアクセスの監視体制を事前構築推奨

🎯 ユースケース

💳 ユースケース 1: マルチアカウント決済プラットフォーム

シナリオ: 大規模決済処理企業が、カード発行・加盟店処理・スイッチングを別々のアカウントで運用。従来は各アカウントに同じ鍵をインポート。
JSON マルチアカウント鍵共有ポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowIssuingAccount",
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::111111111111:root"},
      "Action": [
        "payment-cryptography:GeneratePinData",
        "payment-cryptography:VerifyPinData"
      ],
      "Resource": "*"
    },
    {
      "Sid": "AllowSwitchingAccount",
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::222222222222:root"},
      "Action": ["payment-cryptography:TranslatePinData"],
      "Resource": "*"
    }
  ]
}
✅ 鍵の単一コピーを維持しながら、各ワークロードに必要最小限の暗号操作のみを許可。セキュリティとコンプライアンスが向上。

🤝 ユースケース 2: パートナー間の安全な暗号鍵共有

シナリオ: カード発行会社と決済ネットワーク事業者が、トランザクション認証用の暗号鍵を共有。従来は TR-34 プロトコルによる鍵交換を定期的に実施。
Bash パートナーアクセス許可 
aws payment-cryptography put-resource-policy \
  --resource-arn "arn:aws:payment-cryptography:us-east-1:ISSUER_ACCOUNT:key/SHARED_KEY_ID" \
  --policy '{
    "Version": "2012-10-17",
    "Statement": [{
      "Sid": "NetworkPartnerAccess",
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::NETWORK_ACCOUNT:root"},
      "Action": ["payment-cryptography:VerifyMac", "payment-cryptography:GenerateMac"],
      "Resource": "*",
      "Condition": {"StringEquals": {"aws:PrincipalOrgID": "o-partnerorg"}}
    }]
  }'
✅ 鍵交換フロー不要、鍵リネージュ保持、即時アクセス制御変更が可能。

🧪 ユースケース 3: 開発・テスト環境での鍵参照

シナリオ: 本番環境の鍵を開発・ステージング環境から読み取り専用で参照し、鍵メタデータの検証やテストデータの暗号処理を実施。本番鍵の複製はセキュリティポリシーで禁止。
JSON 開発環境向け読み取りアクセス 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "DevAccountReadOnly",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::DEV_ACCOUNT_ID:role/PaymentTestRole"
      },
      "Action": [
        "payment-cryptography:GetKey",
        "payment-cryptography:Encrypt"
      ],
      "Resource": "*",
      "Condition": {
        "IpAddress": {"aws:SourceIp": "10.0.0.0/8"}
      }
    }
  ]
}
✅ 本番鍵の複製を防止しながら、開発チームが必要な暗号操作を実行。セキュリティポリシーとの整合性維持。

💰 料金情報

クロスアカウント鍵共有機能の利用に追加料金なし。従来の料金体系がそのまま適用。

API 呼び出し (2,000 万回超/月) $0.75 / 10,000 回
アクティブ鍵 $1.00 / 鍵 / 月

🔗 関連サービス

AWS KMS
同様に RBP によるクロスアカウント鍵共有をサポートする汎用暗号鍵管理サービス。Payment Cryptography は決済業界固有の暗号操作に特化。
AWS Organizations
aws:PrincipalOrgID 条件キーで組織全体のアクセス制御を効率化。
AWS CloudTrail
クロスアカウントアクセスの監査ログ記録。誰がいつどの鍵にアクセスしたかを追跡。
AWS RAM
他サービスのリソース共有メカニズム。Payment Cryptography は独自の RBP を採用。
