🚪 どの Kiro アプリを選ぶべきか?

IDE / CLI / Web / Mobile / Crew — 5 つの「玄関」と 1 つのエンジン

📅 2026 年 8 月 12 日
Kiro 公式ブログ

📋 概要

Kiro は IDE、CLI、Web、Mobile、Crew という複数のアプリ (フロントドア) を提供していますが、これらはすべて単一の「エージェントハーネス」という共通エンジンの上に構築されています。公式ブログが、この統合アーキテクチャの背景と各アプリの位置付け、タスクに応じた選び方のフレームワークを解説しました。

「どれか 1 つを選ぶ」という問い自体が誤り。
正しい問いは 「このタスクにはどのアプリか?」
ハーネスが能力 (何ができるか) を定義し、アプリは体験 (どう使うか) を定義する

対象読者は開発者だけでなく、PM、アーキテクト、QA リード、運用担当者など、ソフトウェアデリバリーに関わるすべてのロールです。

❌ Before: アプリごとに独立した実装

  • IDE は TypeScript、CLI は Rust、Web は Python と 3 つの別々の「頭脳」が存在
  • セッション保存形式や権限の扱いに互換性がなく、動作が不一致
  • 新機能の追加ごとに 3 回実装が必要で、速度と一貫性に課題
  • アプリ選択がロックインのように感じられ、選び方が不明瞭

✅ After: 単一エージェントハーネスに統合

  • ハーネスへのコア機能追加が全サーフェスに同時反映
  • ラップトップで開始 → クラウドで継続 → スマートフォンで確認と、セッションが一貫
  • Skills、Steering、カスタムエージェント、設定はハーネス側に紐付き、環境の再構築が不要
  • アプリ選択は「壁に囲まれた庭」ではなく「玄関」。タスクごとに使い分け可能

すべてのアプリは横方向 (アプリ同士) ではなく下方向 (共通ハーネス) に収束します。ハーネスはコードの隣でスタンドアロンプロセスとして動作し、各アプリとは ACP (Agent Client Protocol) という明確に定義されたプロトコルで通信します。

🧭 アプリ選定の背後にある 2 つの原則

1️⃣ Kiro はソフトウェアデリバリーライフサイクルに奉仕する
  • 開発者を第一としつつ、PM、プロジェクトマネージャー、アーキテクト、QA リード、UX デザイナー、Ops / DevOps 担当者まで「ソフトウェアを出荷する人々」のためにアプリを構築
  • 判断基準は「この人は開発者か?」ではなく「これはソフトウェアの出荷という行為に役立つか?」
  • 汎用的な「万人向け AI アシスタント」は意図的に構築しない
2️⃣ ビルダーの現在地で出会い、前進を助ける
  • ファイルと関数の中で生きる「コードファースト」層と、エージェントをオーケストレーションしコードを副産物と捉える「エージェントファースト」層の両方に対応
  • 業界の主流は依然コードファーストだが、エージェントファーストが業界の向かう先
  • 両者の間にシンプルで文脈に沿ったオンランプ (移行経路) を用意

🗂️ 各アプリの位置付け

🖥️ Kiro IDE: ホームベース GA
  • Code OSS ベースのエディタ。多くの人が「Kiro」と言うときに指すプライマリサーフェス
  • エンタープライズチームの主流開発者にとってのホームベース
  • 実験的機能の Agent Focus Mode により、Code Focus (従来のコード中心編集) と Agent Focus (複数セッションの並列オーケストレーション) をトグル切り替え可能。エージェントファーストへの「オンランプ」
⌨️ Kiro CLI: ターミナルとパイプライン GA
  • 2 つのオーディエンスに対応: (1) ターミナルを好む開発者 (4〜6 セッション並列実行も一般的)、(2) 人間が介在しない自動化 (シェルスクリプト、GitHub / GitLab の CI/CD パイプライン)
  • 自動化ユースケースは、エンジンと体験の分離が可能にする「UI なしの Kiro」
  • フル TUI の提供後、一部ユーザーには過剰だったため lite モードを追加。「より多くのサーフェスが常に有用とは限らない」という学び
🌐 Kiro on the web: クラウドファーストサーフェス Preview
  • コラボレーション、作業の開始、バックグラウンドエージェントの監視のためのクラウドファーストな場所
  • 実質的な役割は「すべてのクラウドセッションを一箇所で監視・操縦するコントロールプレーン」に進化
  • スペック駆動開発は元々 IDE 専用だったが、ワークフローがハーネスに移動したことで再実装なしに Web でも利用可能に。統合アーキテクチャの配当の具体例
📱 Kiro Mobile: 外出先の Kiro Preview
  • バックグラウンドエージェントの監視、結果のレビュー、アクションの承認、長時間タスクの後押しなど、デスク不要の操作に特化
  • スマートフォンからローカルのラップトップセッションへの到達は今後の課題として明示
👥 Kiro Crew: アウターハーネス オープンソース
  • 永続メモリ、スケジュールジョブ、非同期バックグラウンドエージェントをバンドル。「寝ている間もエージェントのクルー全体を動かし続ける」ための初のオープンソースアプリ
  • チケットキューのトリアージと振り分け、リポジトリ横断のインシデント調査、チェックポイントとリトライを伴うマイグレーションなどを委任可能
  • デスクトップアプリ、Web ダッシュボード、TUI、Slack 連携という独自のアプリ群を持つ「フルシステム拡張」
  • 一部機能はハーネス側と重複 (出荷を加速するための意図的な逸脱)。今後共有アーキテクチャとの整合を計画

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓ロックインのない選択: どのアプリでも同じエンジンの能力を利用でき、導入判断のリスクが低い
✓幅広いロールのカバー: PM、QA、Ops など、デリバリーに関わるロール全体が自分に合ったサーフェスから参加
✓段階的な移行: コードファーストからエージェントファーストへ、チームのペースで移行できるオンランプ

🔧 技術面のメリット

✓機能の即時展開: ハーネスに一度実装された機能 (例: スペック駆動開発) が再実装なしで全サーフェスに展開
✓環境の可搬性: Skills や Steering がハーネス側に保持され、サーフェス移動時の再構築が不要
✓ヘッドレス実行: エンジンと UI の分離により、CI/CD など完全自動化ユースケースに対応

⚠️ 制限事項

•Kiro on the web と Kiro Mobile は Preview 段階であり、今後変更の可能性あり
•Mobile からローカルのラップトップセッションへのアクセスは未対応 (今後の課題)
•設定の可搬性は現時点で特定のアプリ組み合わせのみ。全組み合わせ対応は今後の方向性
•Kiro Crew の一部機能 (常時稼働の自動化、マルチエージェントオーケストレーション、永続メモリ) はハーネスと重複 (将来的に整合予定)

🤔 考慮すべき点

!IDE と Web の Agent Focus 体験は現時点で疎結合。フィードバック募集中
!アプリ間の機能重複は意図的な設計 (「排除すべきバグではなく期待される形」)。単一アプリへの機能集約は方針として想定されていない

💡 ユースケース

1. エンタープライズチームでの日常開発

シナリオ: 使い慣れたエディタ環境で AI 支援を受けながらコードを書きつつ、エージェント活用も試したい。

StepsKiro IDE の活用
1. Kiro IDE (GA) をホームベースとして利用
2. 通常は Code Focus で従来のコード中心編集
3. Agent Focus Mode に切り替え、複数エージェントセッションを
   並列オーケストレーション
4. 慣れない場合はいつでも Code Focus に戻る

効果: 既知の環境の安全圏からエージェントファーストの世界を試すことができ、チームのペースで段階的に移行できる。

2. CI/CD パイプラインへの組み込み

シナリオ: GitHub / GitLab のパイプラインで、人間の介在なしに Kiro をジョブとして実行したい。

StepsKiro CLI の自動化
1. Kiro CLI (GA) をシェルスクリプトでラップ
2. CI/CD パイプラインのステップとして組み込み
3. 会話ではなくジョブとして実行 (UI なしの Kiro)

効果: エンジンと体験の分離を活かし、レビューやテストの自動化など完全自動のワークフローを構築できる。

3. 不在中も動き続けるエージェントクルーへの委任

シナリオ: チケットキューの処理や大規模マイグレーションを、会議中や就寝中もエージェントに進めてほしい。

StepsKiro Crew + Mobile の併用
1. Kiro Crew (オープンソース) にチケットキューを渡し、
   トリアージと振り分けを委任
2. リポジトリ横断のインシデント調査を並行実行
3. マイグレーションをチェックポイントとリトライ付きで実行
4. 進捗はデスクトップアプリ、Web ダッシュボード、TUI、
   Slack のいずれからでも確認
5. 外出先では Kiro Mobile で承認・確認・後押し

効果: 「運転する」から「委任する」への移行により、複数エージェントが常時稼働し、過去の指摘や好みをセッションをまたいで記憶した状態で作業が進む。
