Amazon Connect Customer

📦 Cases の一括アクション
最大 100 件をまとめて処理

📅 リリース日: 2026 年 11 月 12 日 | 機能: Cases のバッチアクション (Bulk Case Actions)

📋 概要

Amazon Connect Customer の Cases で、エージェントとスーパーバイザーが 最大 100 件のケースに対して一括アクションを実行できるようになりました。 担当者の割り当て、コメントの追加、ステータスの更新 (クローズを含む) を、 ケースを 1 件ずつ開くことなく単一の操作で実行できます。

配送遅延やサービス障害のように 1 つの問題が多数の顧客に影響するシナリオで特に有効です。 コンソール操作に加えて、開発者向けのバッチ API も提供され、 プログラムからの自動化も可能です。

❌ アップデート前の課題
✗多数の顧客に影響する問題でも、ケースを 1 件ずつ開いて個別に更新する必要があった
✗大量のケースの担当者変更やクローズに時間がかかり、エージェントの作業負荷が増大
✗関連ケース群へ一括でコメントを追加する手段がなく、情報共有に手間がかかっていた
✅ アップデート後の改善
✓最大 100 件のケースへ担当者割り当て、コメント追加、ステータス更新を単一アクションで実行
✓大規模障害や配送遅延の際に、関連ケースの一括クローズ・一括更新で対応時間を大幅に短縮
✓バッチ API (BatchUpdateCase、BatchCreateRelatedItem) によりプログラムからの自動化も可能

ケースを 1 件ずつ更新していた従来のフローと、検索ビューまたはバッチ API から最大 100 件のケースへ一括アクションを実行する新しいフローの比較

⚡ 主要機能

👥 1. 担当者の一括割り当て
  • Cases 検索ビューの [Actions] ドロップダウンから [Assign cases] を選択
  • 選択した複数のケースをユーザーまたはキューへ一括で割り当て可能
  • 大規模インシデント時の担当チームへの振り分けを効率化
💬 2. コメントの一括追加
  • [Actions] ドロップダウンから [Add comment] を選択し、選択したすべてのケースに同一コメントを追加
  • 障害の進捗状況や対応方針を関連ケース全体へ一度に共有可能
✅ 3. ステータスの一括更新
  • [Actions] ドロップダウンから [Update status] を選択し、選択したケースのステータスを一括変更
  • 問題解決後の関連ケースの一括クローズに活用可能
🔌 4. バッチ API によるプログラム実行
  • BatchUpdateCase: 最大 100 件のケースのフィールド (タイトル、ステータス、顧客 ID、カスタムフィールド) を一括更新
  • BatchCreateRelatedItem: 最大 100 件のケースへコメントタイプの関連アイテムを一括追加
  • いずれも同一ドメイン内のケースが対象で、ケースごとの成功 / 失敗結果が返却される

🔐 必要な権限設定

⚠️ 一括アクションを使用するには、セキュリティプロファイルに Cases - Cases bulk action 権限が必要です。 この権限がない場合、Cases 検索ビューに [Actions] ドロップダウンは表示されません。

🛠️ 設定方法

📌 前提条件

  • Amazon Connect インスタンスで Cases が有効化されていること
  • セキュリティプロファイルに Cases bulk action 権限が付与されていること
  • 対象リージョンでインスタンスが稼働していること

🪜 手順

1
セキュリティプロファイルの権限設定

Amazon Connect 管理コンソールでセキュリティプロファイルを開き、Cases セクションの Cases bulk action 権限を有効化します。この権限により、エージェントワークスペースの Cases 検索ビューに [Actions] ドロップダウンが表示されるようになります。

2
エージェントワークスペースで一括アクションを実行
  • Cases 検索ビューで対象のケースを検索し、一括操作したいケースを選択
  • [Actions] ドロップダウンから [Assign cases]、[Update status]、[Add comment] のいずれかを選択
  • ダイアログで割り当て先、ステータス、コメント内容を指定して実行
3
バッチ API によるプログラム実行 (オプション)
Bash 最大 100 件のケースのステータスを一括更新する例 
# 最大 100 件のケースのステータスを一括更新する例
aws connectcases batch-update-case \
  --domain-id "your-domain-id" \
  --cases '[{"caseId": "case-id-1", "fields": [{"id": "status", "value": {"stringValue": "closed"}}]}]'

batch-update-case は指定したドメイン内の複数ケースのフィールド (ステータスなど) を一括更新します。レスポンスにはケースごとの成功 / 失敗結果が含まれるため、部分的な失敗をハンドリングできます。

💡 メリット

💼 ビジネス面
✓対応時間の短縮: 数十〜100 件のケースを単一アクションで処理でき、顧客対応のリードタイムを大幅に短縮
✓エージェント生産性の向上: 繰り返しの個別更新作業が不要になり、顧客対応そのものに集中可能
✓一貫した顧客コミュニケーション: 同一コメントの一括追加で対応内容のばらつきを防止
⚙️ 技術面
✓API による自動化: BatchUpdateCase と BatchCreateRelatedItem により外部システムやワークフローからの一括更新を自動化可能
✓ケースごとの結果返却: ケース単位の成功 / 失敗を返却するため、エラーハンドリングやリトライ処理を実装しやすい
✓権限による統制: Cases bulk action 権限により、一括操作を実行できるユーザーを制御可能

⚠️ デメリット・制約事項

🚧 制限事項

✗一度に操作できるケース数は最大 100 件まで
✗バッチ API の対象は同一ドメイン内のケースに限定される
✗一括アクションの利用にはセキュリティプロファイルの Cases bulk action 権限が必要

🤔 考慮すべき点

⚠️ 一括更新は影響範囲が大きいため、誤操作時の影響も大きくなる。権限付与の対象者は慎重に選定することが推奨される
⚠️ バッチ API 利用時は、ケースごとの失敗結果を確認し、必要に応じて再実行する仕組みを用意することが望ましい

🎯 ユースケース

🚚 ユースケース 1: 配送遅延に伴う関連ケースの一括更新

シナリオ: 物流障害により特定地域の配送が遅延し、同一の問い合わせケースが大量に発生した。

実装例
  1. Cases 検索ビューで該当地域・該当期間のケースを検索
  2. 関連ケースを選択し [Add comment] で遅延状況と解消見込みを一括追加
  3. 配送再開後、[Update status] で該当ケースを一括クローズ
効果

数十件のケースへの対応を数分で完了でき、顧客への情報提供の遅れを防止できる。

🚨 ユースケース 2: サービス障害発生時の専任チームへの一括割り当て

シナリオ: サービス障害の発生により関連ケースが急増し、障害対応の専任チームに集約したい。

実装例
  1. 障害に関連するケースを検索ビューで抽出
  2. [Assign cases] で障害対応キューまたは専任ユーザーへ一括割り当て
  3. 対応方針をコメントとして一括追加し、チーム内で共有
効果

ケースの振り分け作業が単一アクションで完了し、障害対応の初動を迅速化できる。

🔄 ユースケース 3: 外部システムと連携した一括クローズの自動化

シナリオ: 社内の障害管理システムでインシデントがクローズされた際、関連する Connect のケースを自動でクローズしたい。

実装例
  1. 障害管理システムのクローズイベントをトリガーに Lambda 関数を起動
  2. 関連ケース ID の一覧を取得し、BatchUpdateCase でステータスを一括更新
  3. BatchCreateRelatedItem で解決内容のコメントを一括追加
  4. レスポンスの失敗ケースのみ再実行またはアラート通知
効果

手動運用を排除し、システム間でケース状態の整合性を自動的に維持できる。
