AWS Transform Well-Architected Agent パブリックプレビュー

🧭 Well-Architected Agent による
ターゲットネットワーク設計レビュー

移行の計画段階でベストプラクティスを設計に直接適用し、デプロイ後の手戻りを回避
📅 リリース日: 2026 年 11 月 17 日

📝 概要

AWS Transform for migrations が、インフラストラクチャの AWS への移行・モダナイゼーションの過程で、ターゲットネットワークに対する Well-Architected レビューを組み込むようになりました。レビューはパブリックプレビュー中の AWS Well-Architected Agent が提供し、セキュリティ、信頼性、コスト最適化の 3 つの柱にわたる最新のベストプラクティスに基づく推奨事項を生成します。

推奨事項はターゲットネットワークの設計に直接適用されるため、デプロイ後にインフラストラクチャを修正する手戻りを回避できます。大規模なオンプレミスネットワークを移行する組織にとって、移行プロジェクトの品質とスピードの両面で大きな価値があります。

❌ Before: アップデート前の課題

  • 設計の不備がデプロイ後に発覚し、修正コストが高額に
  • 追加のレビュー・更新サイクルで移行スケジュールが遅延
  • ベストプラクティス適用には専門家による手動レビューが必要

✅ After: アップデート後の改善

  • 計画段階で Well-Architected Agent が改善機会を特定
  • 推奨事項が設計に直接適用され、デプロイ後の修正が不要
  • デプロイ後向け推奨事項はダウンロード可能なアーティファクトとして文書化

AWS Transform が生成するターゲットネットワーク設計を Well-Architected Agent がレビューし、推奨事項を設計に直接適用します。デプロイ後に対応すべき推奨事項は、チャットからダウンロード可能なアーティファクトとして提供されます。

⚡ 主要機能

1️⃣ 計画段階での Well-Architected レビュー

移行・モダナイゼーションの過程で、ターゲットネットワークに対するレビューを自動実施。セキュリティ、信頼性、コスト最適化の 3 つの柱にわたる最新のベストプラクティスを参照し、デプロイ前に設計ギャップを特定することで高コストな手戻りを回避します。

2️⃣ 推奨事項の設計への直接適用

レビュー結果がターゲットネットワーク設計に直接反映されます。例: 非 RFC1918 アドレスを使用したスポーク VPC の再アドレッシングや、CIDR 割り当てのガバナンス強化といった推奨事項を設計に適用。

3️⃣ デプロイ後向け推奨事項のアーティファクト化

ネットワーク稼働後に実施すべき推奨事項は、AWS Transform チャットからダウンロード可能なアーティファクトとして文書化。移行チームは稼働後に自身の AWS アカウントで対応できます。

🤖 AWS Well-Architected Agent について

今回のレビューを提供する AWS Well-Architected Agent は、パブリックプレビュー中の AI 駆動のクラウド最適化サービスです。公式ドキュメントによると、以下の特徴があります。

✓AWS 環境を継続的に分析し、コスト、セキュリティ、パフォーマンス、レジリエンスにわたるパーソナライズされた推奨事項を優先度付きで提供
✓リソース、アプリケーション、アーキテクチャの 3 つのレベルで推奨事項を生成
✓IaC コードの更新など、すぐにデプロイ可能な修正を含む処方的ガイダンスを提供
✓1 つのエージェントプロファイルで最大 1,000 の AWS アカウントを分析可能

🛠️ 設定方法

前提条件

  • AWS アカウントと AWS Transform for migrations へのアクセス
  • AWS Well-Architected Agent の利用資格 — 有料サポートプランに含まれる。公式ドキュメントによると Business+ 以上のサポートプラン: Business+、Enterprise On-Ramp、Enterprise Support、Unified Operations
  • 移行対象のオンプレミスネットワーク情報

手順

1
AWS Transform for migrations を開始
コンソールから migrations のジョブを開始し、ディスカバリとウェーブ計画を実施。既存ネットワークの情報をもとに、ターゲットネットワークの設計が生成されます。
2
Well-Architected レビュー結果の確認
設計の生成過程で Well-Architected Agent によるレビューが実施され、推奨事項が設計に直接適用されます。適用された推奨事項の内容を確認します。
3
デプロイ後向け推奨事項の取得
AWS Transform チャットからアーティファクトをダウンロード。ネットワーク稼働後、自身の AWS アカウントで推奨事項に対応します。

💡 メリット

💼 ビジネス面

✓移行コストの削減: デプロイ後の設計修正に伴う高額な手戻りコストを回避
✓移行スケジュールの短縮: 追加のレビュー・更新サイクルが不要になり、遅延リスクを低減
✓移行品質の向上: ベストプラクティスに準拠した設計を最初から採用

⚙️ 技術面

✓計画段階でのギャップ検出: デプロイ前に 3 つの柱の観点から設計ギャップを特定
✓自動適用による省力化: 手動での設計修正作業が削減される
✓稼働後の改善計画: デプロイ後向け推奨事項を改善活動に活用可能

⚠️ デメリット・制約事項

制限事項

✗Well-Architected Agent は現在パブリックプレビューであり、仕様が変更される可能性がある
✗有料サポートプランに含まれる形で提供される (Business+ 以上のサポートプランが必要)
✗レビュー対象は 3 つの柱のみで、Well-Architected フレームワークの全ての柱を網羅するものではない

考慮すべき点

⚡AI が生成する推奨事項のため、適用前に内容を十分にレビューすることを推奨
⚡デプロイ後向けの推奨事項は自動適用されないため、アーティファクトをもとに計画的に対応する必要がある

🎯 ユースケース

1. 大規模オンプレミスネットワークの AWS 移行

シナリオ: 数百のサブネットを持つ大規模なオンプレミスネットワークを AWS に移行する企業が、移行後の設計修正リスクを最小化したい。

1. AWS Transform for migrations でディスカバリとウェーブ計画を実施 2. ターゲットネットワーク設計時に Well-Architected レビューが自動実施される 3. CIDR 割り当てガバナンスなどの推奨事項が設計に直接適用される
✅ 効果: デプロイ前にベストプラクティス準拠の設計が完成し、稼働後の修正サイクルを回避できる。
2. IP アドレス枯渇への対応を含むネットワーク再設計

シナリオ: RFC1918 アドレス空間が枯渇しつつある企業が、移行を機にアドレス設計を見直したい。

1. AWS Transform がターゲットネットワーク設計を生成 2. Well-Architected Agent が非 RFC1918 アドレスを使用した スポーク VPC の再アドレッシングを推奨 3. 推奨事項が設計に適用された状態でデプロイ
✅ 効果: アドレス枯渇の課題を移行と同時に解消し、将来の拡張性を確保できる。
3. 移行後の継続的な改善計画の策定

シナリオ: 移行チームが、ネットワーク稼働後に実施すべき改善項目を体系的に管理したい。

1. AWS Transform チャットからデプロイ後向け推奨事項の アーティファクトをダウンロード 2. 推奨事項を自社の改善バックログに登録 3. 稼働後に AWS アカウント上で順次対応
✅ 効果: 移行完了後も Well-Architected ベストプラクティスに基づく継続的な改善を計画的に実施できる。

💵 料金・利用可能リージョン

💰 料金

AWS Well-Architected Agent は AWS Support によって提供され、有料サポートプランに含まれます。公式ドキュメントによると、Business+ 以上のサポートプラン (Business+、Enterprise On-Ramp、Enterprise Support、Unified Operations) で利用可能です。AWS Transform の料金は 料金ページを参照してください。

🌍 利用可能リージョン

本機能は商用 AWS リージョンで利用可能です。なお、Well-Architected Agent のプロファイルは米国東部 (バージニア北部)、米国東部 (オハイオ)、米国西部 (オレゴン) でホストされ、そこから全ての商用リージョンのリソースをスキャンします。

🔗 関連サービス・機能

🧰 AWS Well-Architected Tool

Well-Architected フレームワークに基づくワークロードレビューを実施するサービス。Well-Architected Agent は同コンソールから利用可能。

🧑‍⚕️ AWS Trusted Advisor

Well-Architected Agent は Trusted Advisor などの最適化サービスの検出結果を取り込み、パーソナライズと優先度付けを追加する。

🤖 AWS Transform for migrations

ディスカバリ、ウェーブ計画からネットワーク変換、カットオーバーまでの移行ライフサイクルを agentic AI で自動化するサービス。

📌 まとめ

AWS Transform for migrations に Well-Architected Agent によるターゲットネットワークのレビューが組み込まれ、移行の計画段階でセキュリティ、信頼性、コスト最適化のベストプラクティスを設計に直接適用できるようになりました。大規模なネットワーク移行を計画している組織は、デプロイ後の手戻りを削減するために本機能の活用を検討することを推奨します。Well-Architected Agent はパブリックプレビューのため、仕様変更の可能性がある点には留意してください。
