🔐 Iceberg REST カタログフェデレーションで
catalog-vended credentials をサポート

📅 リリース日: 2026 年 11 月 6 日 | AWS Glue Data Catalog / AWS Lake Formation

📝 概要

AWS Glue Data Catalog が、Apache Iceberg REST カタログフェデレーションにおいて、外部カタログが発行する一時認証情報 (catalog-vended credentials) をサポートしました。Snowflake Horizon や Databricks Unity Catalog などの外部カタログ側で付与されたテーブル権限に基づいて、Amazon Athena、Amazon EMR、Amazon Redshift、AWS Glue から外部 Iceberg テーブルを読み取れます。

外部カタログが Iceberg REST API の loadTable レスポンスを通じて、Amazon S3 ストレージプレフィックスにスコープされた一時認証情報を発行し、AWS Lake Formation が行・列・セルレベルのきめ細かなアクセス制御やクロスアカウント共有を重ねて管理します。

❌ Before: アップデート前の課題
✗S3 バケットへのアクセス権を持つ IAM ロール (Registered role 方式) の登録が必須だった
✗外部カタログ側がストレージを所有している場合、フェデレーションの構成が困難だった
✗外部カタログ側のテーブル権限を AWS 側のアクセス制御に直接反映できなかった
✅ After: アップデート後の改善
✓新しい接続方式 SOURCE_VENDED で外部カタログが許可したテーブルのみを読み取り可能に
✓IAM ロールに S3 バケットへのアクセス権限が不要に
✓外部カタログの権限 + Lake Formation のきめ細かな権限による多層的なアクセス制御
✓外部カタログ側の権限取り消しが AWS 側の変更なしに即座に反映

sequenceDiagram

    participant Glue as 📚 AWS Glue Data Catalog
    participant LF as 🛡️ AWS Lake Formation
    participant Remote as 🗂️ 外部 Iceberg REST カタログ
    participant S3 as 🪣 Amazon S3

    Engine->>Glue: フェデレーテッドテーブルへのクエリ
    Glue->>Remote: loadTable リクエスト
    Remote-->>Glue: テーブルメタデータ + S3 プレフィックスにスコープされた一時認証情報
    Glue->>LF: Lake Formation 権限の確認
    Note over LF: 行・列・セルレベルの<br/>きめ細かな権限を適用
    LF-->>Engine: 一時認証情報を引き渡し
    Engine->>S3: Iceberg データファイルを直接読み取り
    S3-->>Engine: クエリ結果を返却

Vended credential 方式では、外部 Iceberg REST カタログが loadTable レスポンスで S3 ストレージプレフィックスにスコープされた一時認証情報を発行し、Lake Formation がきめ細かな権限を適用した上で分析エンジンに引き渡します。IAM ロールによる S3 への直接アクセスは不要です。

⚡ 主要機能

🔑 1. Vended credential 方式 (SOURCE_VENDED) の追加
✓外部カタログが Iceberg REST の loadTable レスポンスを通じて S3 への一時認証情報を発行
✓IAM ロールは Secrets Manager のシークレットへのアクセスのみ必要 (S3 権限不要)
✓接続プロパティ CREDENTIAL_VENDING_MODE で SOURCE_VENDED を指定 (デフォルトは AWS_VENDED)
🛡️ 2. 外部カタログの権限と Lake Formation 権限の多層適用
✓外部カタログ側で権限を取り消すと、AWS 側の変更なしに次回のテーブル読み込み時からクエリが失敗
✓行・列・セルレベル権限および LF-Tag ベースのアクセス制御を重ねて適用可能
✓フェデレーテッドカタログを AWS アカウント間で安全に共有可能
🔄 3. 一時認証情報の自動更新
✓認証情報の有効期間は外部カタログ側が設定
✓長時間実行クエリの実行中に AWS Glue が自動更新し、有効期限切れによるクエリ失敗を防止
🚀 4. 幅広い分析エンジンのサポート
✓Amazon Athena、Amazon Redshift、Amazon EMR、AWS Glue に加え、Apache Spark などのサードパーティエンジンにも対応
✓クエリ時に外部カタログから最新のテーブル情報 (S3 ロケーション、スキーマ、パーティション) を取得

🔬 技術仕様: アクセス委任モードの比較

項目 Registered role (AWS_VENDED) Vended credential (SOURCE_VENDED)
S3 認証情報の発行元 Lake Formation (登録した IAM ロールを引き受けて発行) 外部カタログ (Iceberg REST の loadTable レスポンスで発行)
IAM ロールの S3 アクセス権限 ⚠️ 必要 ✅ 不要
データアクセス範囲の制御 Lake Formation 権限と IAM ロール Lake Formation 権限と外部カタログのグラント
主なユースケース 外部テーブルを格納する S3 バケットを所有、またはアクセス権を付与できる場合 外部カタログサービスがストレージを所有している場合や、AWS ロールに直接読み取りを許可したくない場合
接続プロパティ CREDENTIAL_VENDING_MODE AWS_VENDED (デフォルト) SOURCE_VENDED

接続設定例 (AWS Glue 接続オブジェクト)

JSON Snowflake Iceberg REST カタログへの接続定義 
{
  "Name": "my-connection-to-snowflake",
  "ConnectionType": "SNOWFLAKEICEBERGRESTCATALOG",
  "ConnectionProperties": {
    "INSTANCE_URL": "https://<account>.snowflakecomputing.com",
    "ROLE_ARN": "arn:aws:iam::123456789012:role/GlueConnectionRole",
    "CREDENTIAL_VENDING_MODE": "SOURCE_VENDED",
    "CATALOG_CASING_FILTER": "UPPERCASE_ONLY"
  },
  "AuthenticationConfiguration": {
    "AuthenticationType": "OAUTH2",
    "OAuth2Properties": {
      "OAuth2GrantType": "CLIENT_CREDENTIALS",
      "TokenUrl": "https://<account>.snowflakecomputing.com/polaris/api/catalog/v1/oauth/tokens",
      "TokenUrlParametersMap": {
        "scope": "session:role:<snowflake-role>"
      }
    },
    "SecretArn": "arn:aws:secretsmanager:<region>:123456789012:secret:<secret-name>"
  }
}

CREDENTIAL_VENDING_MODE に SOURCE_VENDED を指定することで、外部カタログ発行の一時認証情報を使用する Vended credential 方式になります。

🛠️ 設定方法

前提条件

  • 外部 Iceberg REST カタログ側で、フェデレーション対象のデータベース・スキーマ・テーブルに対する読み取り権限をサービスプリンシパルに付与しておくこと
  • 外部カタログのアクセストークンを AWS Secrets Manager に USER_MANAGED_CLIENT_APPLICATION_CLIENT_SECRET キーで保存しておくこと
  • 操作する IAM プリンシパルに lakeformation:RegisterResource、glue:CreateConnection、glue:CreateCatalog、secretsmanager:CreateSecret などの権限があること
  • Lake Formation のデータレイク管理者であるか、Data Catalog に対する CREATE_CATALOG 権限を持つこと

手順

1
Secrets Manager シークレットの作成
Bashクライアントシークレットの保存
aws secretsmanager create-secret \
  --name my-remote-catalog-secret \
  --description "Remote Iceberg catalog secret" \
  --secret-string '{"USER_MANAGED_CLIENT_APPLICATION_CLIENT_SECRET": "<client_secret>"}' \
  --region <region>

外部カタログへの認証に使用するクライアントシークレットを保存します。USER_MANAGED_CLIENT_APPLICATION_CLIENT_SECRET は AWS Glue が参照する予約キーワードです。

2
接続用 IAM ロールの作成

Vended credential 方式の場合、IAM ロールにはシークレットへのアクセス権限 (secretsmanager:GetSecretValue、secretsmanager:DescribeSecret、secretsmanager:PutSecretValue) のみが必要です (Amazon VPC 経由で接続する場合は VPC ネットワークインターフェイスの権限も必要)。S3 への読み取り権限は不要です。信頼ポリシーでは glue.amazonaws.com にロールの引き受けを許可します。

3
AWS Glue 接続オブジェクトの作成
Bash外部カタログへの接続作成
aws glue create-connection \
  --connection-input '{
    "Name": "my-connection-to-remote-catalog",
    "ConnectionType": "SNOWFLAKEICEBERGRESTCATALOG",
    "ConnectionProperties": {
      "INSTANCE_URL": "https://<account>.snowflakecomputing.com",
      "ROLE_ARN": "<接続用 IAM ロールの ARN>",
      "CREDENTIAL_VENDING_MODE": "SOURCE_VENDED",
      "CATALOG_CASING_FILTER": "UPPERCASE_ONLY"
    },
    "AuthenticationConfiguration": {
      "AuthenticationType": "OAUTH2",
      "OAuth2Properties": {
        "OAuth2GrantType": "CLIENT_CREDENTIALS",
        "TokenUrl": "https://<account>.snowflakecomputing.com/polaris/api/catalog/v1/oauth/tokens",
        "TokenUrlParametersMap": {"scope": "session:role:<snowflake-role>"}
      },
      "SecretArn": "<シークレットの ARN>"
    }
  }'
4
接続の Lake Formation への登録
BashLake Formation 管理リソースとして登録
aws lakeformation register-resource \
  --resource-arn <Glue 接続の ARN> \
  --role-arn <IAM ロールの ARN> \
  --with-federation \
  --with-privileged-access

⚠️ カタログ作成前に接続を登録しないと create-catalog が失敗するため、順序に注意してください。

5
フェデレーテッドカタログの作成
BashData Catalog にフェデレーテッドカタログを作成
aws glue create-catalog \
  --name my-federated-catalog \
  --catalog-input '{
    "FederatedCatalog": {
      "Identifier": "<外部カタログ名>",
      "ConnectionName": "my-connection-to-remote-catalog"
    },
    "CreateTableDefaultPermissions": [],
    "CreateDatabaseDefaultPermissions": []
  }'
6
Lake Formation 権限の付与とクエリの実行

カタログレベルの権限はフェデレーテッドデータベースやテーブルには継承されないため、クエリを実行する各プリンシパルに対して、データベースへの DESCRIBE、テーブル (ワイルドカード) への SELECT と DESCRIBE を付与します。

SQLAmazon Athena からのクエリ例
SELECT * FROM "<federated-catalog>"."<schema>"."<table>" LIMIT 10;

💡 メリット

💼 ビジネス面

✓マルチカタログ環境のガバナンス統合: 外部カタログのデータをデータ移動なしに AWS の分析エンジンと Lake Formation のガバナンス下で活用
✓アクセス管理の二重化: 外部カタログ側の権限取り消しが即座に反映され、データ所有者側の統制を維持
✓セットアップの簡素化: S3 バケットへの IAM アクセス権限の調整が不要になり、データ共有の調整コストが低減

⚙️ 技術面

✓IAM ロールの権限最小化: S3 アクセス権限が不要になり、最小権限の原則に沿った構成が可能
✓スコープされた一時認証情報: S3 ストレージプレフィックスに限定されたアクセス範囲
✓長時間クエリへの対応: 一時認証情報の自動更新により有効期限切れによる失敗を回避
✓きめ細かな制御の重ね掛け: 外部カタログのグラントの上に行・列・セルレベル権限や LF-Tag を適用可能

⚠️ デメリット・制約事項

制限事項

⚠フェデレーテッド Iceberg カタログでは、REST API 呼び出しあたりのメタデータサイズは最大 5 MB に制限される (超過するテーブルへのリクエストは拒否)
⚠本機能は外部 Iceberg テーブルの読み取りに対応するものであり、外部カタログ側で許可されたテーブルのみが対象
⚠Polaris カタログのネストされた名前空間は非サポート (catalog.database.table の 3 階層表記のみアクセス可能)

考慮すべき点

⚠一時認証情報の有効期間は外部カタログ側の設定に依存するため、外部カタログ側のポリシーの事前確認が必要
⚠外部カタログ側でデータベースやテーブルを削除しても、Lake Formation 側の付与済み権限は自動的に取り消されない (明示的な削除が必要)
⚠CATALOG_CASING_FILTER の設定によっては、大文字または小文字の識別子を持つオブジェクトのみがフェデレーションされる

🎯 ユースケース

❄️ ユースケース 1: Snowflake 管理データの AWS 分析エンジンからの参照

シナリオ: Snowflake Horizon カタログで管理する Iceberg テーブルを Amazon Athena や Amazon Redshift からも分析したいが、Snowflake 側が管理する S3 ストレージへの直接アクセス権を AWS の IAM ロールに付与したくない。

1️⃣ Snowflake 側で
SELECT 権限を付与
→
2️⃣ SOURCE_VENDED で
Glue 接続を作成
→
3️⃣ フェデレーテッド
カタログ作成 + 権限付与
→
4️⃣ Athena から
SELECT 実行
💡 効果: データの複製や ETL なしに、Snowflake 側の権限統制を維持したまま AWS の分析エンジンからクエリ可能になる。
🏢 ユースケース 2: 行・列レベル制御を加えたアカウント間データ共有

シナリオ: 外部カタログで管理する Iceberg テーブルを複数の AWS アカウントのデータ分析チームに共有したいが、チームごとに参照可能な列や行を制限したい。

  • 1. Vended credential 方式でフェデレーテッドカタログを作成
  • 2. Lake Formation で列レベルフィルタや行レベルフィルタを定義
  • 3. Lake Formation のクロスアカウント共有で対象アカウントに権限付与
  • 4. 各アカウントの分析エンジンからフィルタ適用済みのデータを参照
💡 効果: 外部カタログの粗粒度権限に加えて、Lake Formation のきめ細かな権限とアカウント間共有を組み合わせた多層的なガバナンスを実現できる。
⏱️ ユースケース 3: 長時間実行される ETL ジョブからの外部テーブル読み取り

シナリオ: AWS Glue の Spark ETL ジョブで外部カタログの大規模 Iceberg テーブルを読み取るが、処理時間が長く、一時認証情報の有効期限切れが懸念される。

  • 1. Vended credential 方式のフェデレーテッドカタログを構成
  • 2. Glue ジョブからフェデレーテッドテーブルを入力として読み取り
  • 3. AWS Glue が実行中に一時認証情報を自動更新
💡 効果: 認証情報の有効期限を意識することなく、長時間実行ジョブでも安定して外部 Iceberg テーブルを処理できる。

🔗 関連サービス・機能

🛡️AWS Lake Formation: フェデレーテッドカタログへのアクセス制御 (行・列・セルレベル権限、LF-Tag、クロスアカウント共有) を管理
⚙️Amazon Athena / Amazon Redshift / Amazon EMR: フェデレーテッドテーブルへのクエリを実行する分析エンジン。Lake Formation 権限を適用した上で S3 のデータファイルを直接読み取る

📌 まとめ

AWS Glue Data Catalog の Iceberg REST カタログフェデレーションに Vended credential 方式が追加され、IAM ロールに S3 アクセス権限を付与することなく、外部カタログ発行の一時認証情報で外部 Iceberg テーブルを安全に読み取れるようになりました。

Snowflake や Databricks などの外部カタログと AWS 分析エンジンを併用している環境では、最小権限での構成と外部カタログ側の統制維持を両立できるため、接続作成時のアクセス委任モードとして SOURCE_VENDED の採用を検討することを推奨します。
