Amazon ElastiCache

🗄️ データティアリングが R8gd / R7gd ノードで
欧州 (スペイン) とアジアパシフィック (ハイデラバード) に拡大

📅 リリース日: 2026 年 10 月 27 日 | 対象: ElastiCache for Valkey (7.2 以降)

📌 概要

Amazon ElastiCache for Valkey のデータティアリングが、新たに欧州 (スペイン) リージョンで Graviton4 ベースの R8gd と Graviton3 ベースの R7gd に、 アジアパシフィック (ハイデラバード) リージョンで R7gd に対応しました。 メモリと SSD を組み合わせることで、数百テラバイト規模までクラスターをコスト効率よくスケールできます。

メモリが満杯になると、最も長くアクセスされていないアイテム (LRU) を自動的に SSD へ移動し、SSD 上のアイテムが読み取られると自動的にメモリへ戻します。 データセット全体のうち定期的にアクセスするのが最大 20% 程度のワークロードに最適です。

❌ Before: アップデート前の課題
✗欧州 (スペイン) では R8gd / R7gd によるデータティアリングを利用できなかった
✗アジアパシフィック (ハイデラバード) では R7gd によるデータティアリングを利用できなかった
✗大容量データセットをすべてメモリに保持するとノードコストが高額になりやすかった
✅ After: アップデート後の改善
✓スペインで R8gd / R7gd、ハイデラバードで R7gd のデータティアリングが利用可能に
✓R8gd (Graviton4) は Graviton3 比で最大 47% 高いスループットと最大 43% 低い P99 レイテンシー
✓R7gd (Graviton3) は Graviton2 比で最大 28% 高いスループットと 25% 多いネットワーク帯域幅

🛠️ 設定方法

前提条件

✓AWS アカウントを保有していること
✓対象リージョン (欧州 (スペイン) またはアジアパシフィック (ハイデラバード)) を利用すること
✓Valkey 7.2 以降のエンジンバージョンを使用すること

ステップ 1: データティアリング対応クラスターの作成

Bashスペインリージョンに R8gd クラスターを作成
aws elasticache create-replication-group \
    --replication-group-id my-valkey-cluster \
    --replication-group-description "Valkey cluster with data tiering" \
    --engine valkey \
    --engine-version 7.2 \
    --cache-node-type cache.r8gd.xlarge \
    --data-tiering-enabled \
    --num-node-groups 2 \
    --replicas-per-node-group 1 \
    --region eu-south-2

--data-tiering-enabled フラグでデータティアリングを有効化し、--cache-node-type でデータティアリング対応ノードタイプを指定します。

ステップ 2: 既存クラスターのノードタイプ変更

Bashハイデラバードリージョンの既存クラスターを R7gd に変更
aws elasticache modify-replication-group \
    --replication-group-id my-valkey-cluster \
    --cache-node-type cache.r7gd.xlarge \
    --apply-immediately \
    --region ap-south-2

ステップ 3: クラスターの状態確認

Bashステータス・ノードタイプ・データティアリング有効化状態の確認
aws elasticache describe-replication-groups \
    --replication-group-id my-valkey-cluster \
    --query "ReplicationGroups[0].{Status:Status,NodeType:CacheNodeType,DataTiering:DataTiering}"

💡 ユースケース

1️⃣ 大規模セッションストアのコスト最適化

シナリオ: 欧州 (スペイン) で数十テラバイト規模のセッションデータを保持する Web アプリケーション。アクティブユーザーのセッションは全体の 20% 程度。

Bash実装例
aws elasticache create-replication-group \
    --replication-group-id session-store \
    --engine valkey \
    --engine-version 7.2 \
    --cache-node-type cache.r8gd.4xlarge \
    --data-tiering-enabled \
    --num-node-groups 4 \
    --replicas-per-node-group 1 \
    --region eu-south-2

効果: アクティブセッションはメモリ、非アクティブセッションは SSD に移動することで、メモリのみの構成と比較してコストを削減。

2️⃣ ハイデラバードでの大容量キャッシュのレイテンシー要件対応

シナリオ: インド国内のユーザー向けサービスで、データ主権と低レイテンシーの要件から、ハイデラバードリージョン内に大容量キャッシュ層を構築。

Bash実装例
aws elasticache create-replication-group \
    --replication-group-id in-cache \
    --engine valkey \
    --engine-version 7.2 \
    --cache-node-type cache.r7gd.2xlarge \
    --data-tiering-enabled \
    --num-node-groups 3 \
    --replicas-per-node-group 2 \
    --region ap-south-2

効果: データ主権要件を満たしつつ、R7gd ノードのデータティアリングで大容量キャッシュをコスト効率よく運用。

3️⃣ 既存クラスターの最新世代ノードへのアップグレード

シナリオ: 欧州 (スペイン) で旧世代ノードを使用している Valkey クラスターを、性能と価格性能比に優れた R8gd ノードへ移行。

Bash実装例
aws elasticache modify-replication-group \
    --replication-group-id existing-cluster \
    --cache-node-type cache.r8gd.xlarge \
    --apply-immediately \
    --region eu-south-2

効果: Graviton4 ベースの R8gd により、最大 47% 高いスループット、最大 43% 低い P99 レイテンシー、最大 31% 優れた価格性能比を実現。

📝 まとめ

Amazon ElastiCache for Valkey のデータティアリングが、欧州 (スペイン) の R8gd / R7gd ノードと アジアパシフィック (ハイデラバード) の R7gd ノードに拡大されました。 これらのリージョンで大容量キャッシュを運用するユーザーは、最新世代 Graviton プロセッサの性能向上と メモリ + SSD 構成によるコスト削減を両立できます。 データセットの一部のみへ定期的にアクセスする大規模ワークロードを運用している場合は、データティアリング対応ノードへの移行を検討することを推奨します。
