Amazon Managed Service for Prometheus

順序外サンプルの取り込みサポート

out-of-order sample ingestion ＋ ワークスペースレベルのルールクエリオフセット
📅 リリース日
2026 年 6 月 11 日

📌 概要

Amazon Managed Service for Prometheus が 順序外サンプルの取り込み と ワークスペースレベルのルールクエリオフセット をサポートしました。これまで Prometheus は厳密な時系列順での取り込みを前提とし、タイムスタンプが直前より過去になるサンプルは破棄されていました。今回のアップデートで、全ワークスペースにデフォルトで 60 秒 の順序外許容ウィンドウが設定され、時系列順から外れて到着したサンプルも受け入れられます。

順序外サンプルの典型的な原因は、分散コレクター・バッチエクスポート・ネットワークレイテンシーのばらつきです。加えてルール評価前に遅延を挿入するルールクエリオフセットにより、遅れて到着したサンプルが取り込まれる猶予を確保してからルールを実行できます。

⚠️ アップデート前の課題

  • 時系列順から外れたサンプルは破棄され、データ欠損が発生
  • 分散コレクター/バッチエクスポートで取り込みタイミングがばらつき、アラートが誤発報・欠落しやすい
  • 遅延サンプルが未取り込みのまま、不完全なデータでルールが評価される

✅ アップデート後の改善

  • デフォルト 60 秒の順序外許容ウィンドウで順序外サンプルを取り込み可能に
  • ルールクエリオフセットで遅延サンプルの取り込みを待ってから評価可能に
  • 2 つの新 CloudWatch メトリクスで取り込みパターンを可視化

分散コレクターから前後して到着したサンプルを順序外許容ウィンドウで受け入れ、ルールクエリオフセットで遅延サンプルの取り込みを待ってからルールを評価する流れ

⚡ 主要機能

⏱️ 順序外許容ウィンドウ (out-of-order time window)

  • 時系列順から外れて到着したサンプルを受け入れる時間ウィンドウを指定
  • 全ワークスペースにデフォルトで 60 秒のウィンドウを設定
  • 値を 0 にすると機能が無効になり、順序外サンプルは破棄される
  • 範囲: 最小 0 秒 ～ 最大 600 秒 (上限超過はサービスクォータ引き上げを申請)

⚙️ ルールクエリオフセット (rule query offset)

  • ルール評価クエリの実行前にグローバルな遅延を挿入
  • 遅延サンプルの取り込みを待ち、より完全なデータセットで評価できる
  • デフォルト: 新規ワークスペース 60 秒 / 既存ワークスペース 0 秒
  • 範囲: 最小 0 秒 ～ 最大 86,400 秒 (24 時間)
  • ルールグループレベルの設定がワークスペースレベルより優先される

📊 新しい CloudWatch ベンドメトリクス

  • OutOfOrderIngestionRate: 順序外サンプルの取り込みレートを可視化
  • OutOfOrderSampleAge: 順序外サンプルがどれだけ過去のタイムスタンプかを可視化
  • 適切なウィンドウ/オフセット値の判断材料になる

🔧 技術仕様: 設定項目と値の範囲

📐 設定の優先順位

→ルールグループレベルのクエリオフセットは、ワークスペースレベルの設定より優先されます。
→順序外許容ウィンドウを設定している場合は、ルールクエリオフセットをウィンドウ以上の値にすることが推奨されます (順序外サンプルがルール評価に含まれるようにするため)。

🛠️ 設定方法

前提条件

  • Amazon Managed Service for Prometheus のワークスペースが作成済み
  • ワークスペース設定を変更する IAM 権限を保有
  • 必要に応じて CloudWatch でメトリクスを確認できること

ステップ 1: 順序外許容ウィンドウの設定

  1. Amazon Managed Service for Prometheus コンソールを開く
  2. 左上メニューから [All workspaces] を選択
  3. 対象の [Workspace ID] を選択
  4. [Workspace configurations] タブを選択
  5. [Out of order time window] で [Edit] を選択し、ウィンドウを秒単位で指定 (0 で無効化)

ステップ 2: ルールクエリオフセットの設定

  1. 同じ [Workspace configurations] タブを開く
  2. [Rule query offset] で [Edit] を選択し、オフセットを秒単位で指定 (ウィンドウ以上の値を推奨)

ステップ 3: CloudWatch メトリクスの確認

CloudWatch コンソールで OutOfOrderIngestionRate と OutOfOrderSampleAge を確認し、取り込みレートとサンプルの遅延量を把握。これをもとにウィンドウとオフセットを調整します。

💡 メリット

📈 ビジネス面

  • データ欠損の削減: 順序外サンプルを取り込み、監視データの完全性を向上
  • アラート精度の向上: 完全なデータでルールを評価し、誤発報・欠落を抑制
  • 運用の信頼性向上: 分散/バッチ環境でも信頼できる監視を実現

🔩 技術面

  • 既存環境への影響が小さい: デフォルト 60 秒ウィンドウで追加設定なしで効果
  • 柔軟な調整: ウィンドウとオフセットを秒単位で最適化
  • 可視化: 2 つの新 CloudWatch メトリクスでデータに基づき分析

⚠️ デメリット・制約事項

制限事項

!順序外許容ウィンドウの最大値は 600 秒 (超過時はサービスクォータ引き上げ申請が必要)
!ルールクエリオフセットの最大値は 86,400 秒 (24 時間)
!ウィンドウを超えて到着した順序外サンプルは引き続き破棄される

考慮すべき点

⏳ ルールクエリオフセットを設定すると、ルール評価とアラートがオフセット分だけ遅延します。アラートの即時性とデータ完全性のバランスを考慮してください。

🔁 既存ワークスペースのオフセットのデフォルトは 0 秒のため、効果を得るにはコンソールから明示的に値を更新する必要があります。

🎯 ユースケース

1. 分散コレクターからのメトリクス収集

シナリオ: 複数リージョン/エッジロケーションのコレクターから収集し、レイテンシー差でサンプルが時系列順から外れて到着。

Config実装例
順序外許容ウィンドウ: 120 秒
ルールクエリオフセット: 120 秒

✅ 遅延サンプルを取り込み、ルール評価にも含めることでデータ欠損とアラート誤検知を削減。

2. バッチ化されたメトリクスエクスポート

シナリオ: アプリがメトリクスをバッチでエクスポートし、バッチ内のタイムスタンプが直近の取り込み時刻より過去になる。

Config実装例
順序外許容ウィンドウ: 300 秒

✅ 過去タイムスタンプを持つバッチサンプルが破棄されず、メトリクスの完全性が向上。

3. 可変ネットワークレイテンシー環境でのアラート精度向上

シナリオ: レイテンシーが変動し、ルールが不完全なデータで評価されアラートが誤発報。

Config実装例
順序外許容ウィンドウ: 60 秒
ルールクエリオフセット: 90 秒  # ウィンドウ以上の値

✅ 評価をオフセット分だけ遅延させ、遅延サンプル取り込み後に評価することでアラート精度が向上。

💰 料金 ＆ 利用可能リージョン

💵 料金

本機能の利用に追加料金はありません。AMP の標準的な取り込み・ストレージ・クエリ料金が適用されます。CloudWatch ベンドメトリクスには CloudWatch の料金が適用される場合があります。

🌍 リージョン

Amazon Managed Service for Prometheus が一般提供されているすべての AWS リージョンで利用できます。

🔗 関連サービス・機能

  • Amazon CloudWatch: 新ベンドメトリクス (OutOfOrderIngestionRate / OutOfOrderSampleAge) とルール評価メトリクス (RuleGroupLastEvaluationDuration / RuleGroupIterationsMissed) を確認可能
  • Amazon SNS: Alertmanager からのアラート通知の送信先として利用
  • PromQL offset 修飾子: 個別ルール式へのオフセット適用方法。ワークスペースレベルオフセットの代替として利用可能

📝 まとめ

本アップデートは、分散コレクター・バッチエクスポート・可変ネットワークレイテンシー を持つワークロードでのデータ欠損とアラート誤検知を削減する重要な機能強化です。全ワークスペースにデフォルト 60 秒の順序外許容ウィンドウが適用されるため、既存ワークスペースでもルールクエリオフセットの設定を見直し、新しい CloudWatch メトリクスで取り込みパターンを確認したうえで、ワークロードに合わせてウィンドウとオフセットを最適化することを推奨します。
