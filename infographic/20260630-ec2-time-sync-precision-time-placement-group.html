Precision Time Placement Group (PTPG) によるマイクロ秒精度時刻同期
リリース日
2026-06-30

📌 概要

Amazon Time Sync Service が、新たに 26 種類の EC2 インスタンスタイプで、すべての商用リージョンにおいてマイクロ秒精度の時刻同期に対応しました。AWS Nitro System 上に構築され、Nitro 内のリファレンスクロックを直接活用することで、マイクロ秒精度の時刻とナノ秒精度のハードウェアタイムスタンプを提供します。

高精度時刻にアクセスするには、Precision Time Placement Group (PTPG) を作成します。これは Precision Time Protocol ハードウェアクロック (PHC) を有効にしてインスタンスを起動できる新しい配置戦略です。低レイテンシも必要な場合は、PTPG を Cluster Placement Group (CPG) に関連付けることで、両方を同時に実現できます。

Before / After

❌ アップデート前の課題
  • 高精度時刻 (PHC) を使えるインスタンスファミリーとリージョンが限定的
  • 一部のインスタンスでマイクロ秒精度同期やハードウェアタイムスタンプが利用不可
  • 高精度時刻と低レイテンシを両立する標準的な仕組みが未整備
→
✅ アップデート後の改善
  • 追加 26 種類のインスタンスタイプで全商用リージョンでマイクロ秒精度同期が可能
  • precision-time 戦略の PTPG を作るだけで PHC 有効インスタンスを起動
  • PTPG を CPG に関連付け、高精度時刻と低レイテンシを両立

Nitro System 内のリファレンスクロックが拡張 NTP ソースと PHC デバイスの両方に高精度な時刻を供給し、PTPG 内のインスタンスはこれらをローカルに利用して chronyd で時刻同期します。PTPG を CPG に関連付けることで、低レイテンシと高精度時刻を両立できます。

🔬 技術仕様

時刻ソースの種類

項目詳細
拡張 NTP ソースリンクローカルアドレス (IPv4: 169.254.169.123 / IPv6: fd00:ec2::123) 経由でアクセス。すべての OS で利用可能
PHC デバイスLinux インスタンスのみ。/dev/ptp_ena シンボリックリンク経由でアクセス。マイクロ秒精度の同期を実現

うるう秒の扱いNTP ソースはうるう秒スミアリング (leap smearing) ビューを提供。PHC は時刻をスミアリングしない

PHC アクセスの要件

✓ENA ドライバ バージョン 2.10.0 以降がサポート対象 OS にインストールされていること
✓Linux を実行している EC2 インスタンスであること (Windows は NTP 経由でのみアクセス可能)
✓PTPG 内に起動されたインスタンスであること

⚙️ 設定方法

ステップ 1: Precision Time Placement Group を作成する

BashPTPG の作成
aws ec2 create-placement-group \
    --group-name my-precision-time-pg \
    --strategy precision-time

precision-time 戦略を指定して配置グループを作成。配置グループ ARN とグループ名 / グループ ID が返されます。

ステップ 2: PTPG 内にインスタンスを起動する

Bashインスタンス起動
aws ec2 run-instances \
    --image-id ami-0abcdef1234567890 \
    --instance-type r7g.2xlarge \
    --placement GroupId=pg-0aaa1111111111111

作成した PTPG を指定して起動することで拡張 Amazon Time Sync Service にアクセスできます。リンクローカル NTP アドレスは追加設定なしで利用可能です。

ステップ 3: chronyd で PHC デバイスを利用するよう設定する (Linux)

Bashchrony 設定
# /etc/chrony.conf に以下の行を追加
refclock PHC /dev/ptp_ena poll 0 delay 0.000010 prefer

# chrony を再起動
sudo systemctl restart chronyd

# 時刻ソースを確認
chronyc sources

PHC0 が Stratum 0 の優先ソース (先頭に #*) として表示されれば、PHC デバイスを利用した同期が有効です。

出力例chronyc sources

ビジネス面

✓追加コストなし: PTPG は追加料金なしで利用可能

技術面

✓マイクロ秒精度の時刻同期: Nitro のリファレンスクロックを直接活用し、ネットワークジッタの影響を受けにくい同期を実現
✓片方向レイテンシ測定: ナノ秒精度のハードウェアパケットタイムスタンプにより精緻な計測が可能
✓デプロイの簡素化: 単一の配置戦略で配置グループ内の全インスタンスに高精度時刻機能を付与

⚠️ デメリット・制約事項

制限事項

✗PHC デバイスは Linux のみアクセス可能。Windows は NTP 経由でのみ拡張 Time Sync Service を利用可能
✗リンクローカルアドレスを使うサービスには 1 秒あたり 1024 パケット (PPS) の上限。NTP、Route 53 Resolver DNS、IMDS リクエストの合計に適用
✗起動時に提供ハードウェアが不足するとリクエストが失敗。停止後の再起動時も同様に失敗する可能性

考慮すべき点

→NTP はうるう秒スミアリングビューを提供、PHC はスミアリングしない。用途に応じて時刻ソースを選択する
→配置グループ自体のルールおよび制限が適用される
→キャパシティ不足で失敗した場合は時間をおいて再試行するか、別のアベイラビリティーゾーンを試す

🎯 ユースケース

1. 分散データベースのトランザクション順序付け
シナリオ: 複数ノードにまたがる分散データベースで、トランザクションの正確な順序付けが求められる
実装: PTPG を作成しノードを起動 → 各ノードで chronyd を PHC に同期 → マイクロ秒精度のタイムスタンプで順序付け
効果: ノード間のクロック差が縮小し、分散トランザクションの整合性と処理速度が向上
2. 金融取引システムのイベント記録
シナリオ: 取引イベントの発生順序を高精度に記録し、監査やコンプライアンス要件に対応
実装: PTPG を CPG に関連付けて取引アプリを配置 → 低レイテンシと高精度時刻を両立 → ナノ秒精度でイベント記録
効果: イベント順序の正確性が向上し、規制要件への対応が容易に
3. ネットワーク性能の精密計測
シナリオ: 分散システム間の片方向ネットワークレイテンシを正確に測定したい
実装: PTPG 内に起動し ENA で PHC を有効化 → ethtool -T <interface> で確認 → 送受信タイムスタンプから片方向レイテンシを算出
効果: ソフトウェア処理の影響を排した精密なネットワーク計測が可能に

💰 料金 & 🌍 利用可能リージョン

料金: Precision Time Placement Group (PTPG) は追加料金なし。インスタンスには通常の EC2 料金が適用されます。

PTPG はすべての AWS 商用リージョンで利用可能です。今回のアップデートにより、26 種類の追加インスタンスタイプでマイクロ秒精度の時刻同期が全商用リージョンで利用できます。

レガシーアクセス (PTPG なしでアクセス可能)

以下の特定リージョン・ファミリーでは PTPG なしでも拡張 Time Sync Service と PHC にアクセス可能 (最良の体験には PTPG での起動を推奨)。

→対応リージョン: 米国東部 (バージニア北部) / 米国東部 (オハイオ) / アジアパシフィック (マレーシア) / アジアパシフィック (タイ) / アジアパシフィック (東京) / 欧州 (ストックホルム)
→対応 Local Zones: 米国東部 (ニューヨークシティ)
→対応ファミリー: M7a, M7g, M7i, R7a, R7g, R7i, I8g, I8ge
