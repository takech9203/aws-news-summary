AWS IAM Roles Anywhere

🔐 証明書失効の自動チェック機能

CRL 配布ポイント (CDP) による自動失効チェックをサポート
📅 リリース日: 2026 年 11 月 5 日 🌍 すべての商用 AWS リージョン 💰 追加料金なし

📝 概要

AWS IAM Roles Anywhere が、証明書失効リスト (CRL) 配布ポイント (CDP) を利用した自動失効チェックをサポートしました。トラストアンカーで有効化すると、認証に使用される X.509 証明書に埋め込まれた CDP の URL から CRL を自動ダウンロードし、失効済み証明書による認証情報のリクエストを拒否します。

IAM Roles Anywhere は、オンプレミスサーバーやコンテナ、IoT デバイスなど AWS 外部のワークロードが X.509 証明書を使って IAM ロールの一時認証情報を取得できるサービスです。今回のアップデートで、失効チェックを認証局 (CA) と常に同期した状態に保てるようになり、CRL の手動インポートと再インポートという運用負荷が解消されます。AWS Private CA だけでなく、独自の PKI で発行した証明書でも利用できます (パブリックにアクセス可能な CDP の URL が条件)。

❌ Before: 手動 CRL 管理
  • 失効チェックには CA が生成した CRL を ImportCrl API または CLI で手動インポートが必要
  • CA が CRL を更新するたびに再インポートの運用作業が発生
  • インポート済み CRL は nextUpdate 期限後も使用され続け、古い失効情報で判定されるリスク
✅ After: 自動失効チェック
  • トラストアンカーの crlDpRevocationEnabled を有効化するだけで、証明書ごとの追加設定なしに自動化
  • CRL を定期的に自動ダウンロード・更新し、手動インポート・再インポートが不要に
  • CA の最新の失効情報と同期を維持し、失効済み証明書による認証情報の発行を確実に防止
最大 30 分
CA の CRL 公開から失効チェックへの反映時間
設定 1 つ
crlDpRevocationEnabled の有効化のみで自動化
$0
追加料金なしで利用可能

🏗️ アーキテクチャ図

自動失効チェック有効時の CreateSession の流れです。IAM Roles Anywhere が証明書内の CDP の URL から CRL を取得して失効状態を確認し、失効済み証明書によるリクエストを拒否します。

sequenceDiagram
    participant W as 🖥️ 外部ワークロード
    participant RA as 🔐 IAM Roles Anywhere
    participant CDP as 🌐 CRL 配布ポイント
    participant STS as 🎫 AWS STS

    W->>RA: CreateSession 証明書を提示
    RA->>RA: 証明書内の CDP URL を読み取り
    RA->>CDP: CRL をダウンロード
    CDP-->>RA: 最新の CRL
    RA->>RA: 失効状態をチェック
    alt 証明書が有効
        RA->>STS: ロールの引き受け
        STS-->>RA: 一時認証情報
        RA-->>W: 一時認証情報を発行
    else 証明書が失効済み
        RA-->>W: リクエストを拒否
    end

⚙️ 主要機能

🔍 CDP による自動失効チェック
  • 認証に使用される証明書に埋め込まれた CRL 配布ポイントの URL を IAM Roles Anywhere が自動的に読み取る
  • 対応する CRL をダウンロードし、証明書チェーン内の各証明書について失効状態をチェックする
  • 失効済み証明書による CreateSession リクエストを拒否し、認証情報を発行しない
🔄 CRL の自動更新
  • 配布ポイントから取得した CRL を定期的に自動更新する
  • CA が更新した CRL は、公開後最大 30 分以内に失効チェックへ反映される
  • CRL の nextUpdate 期限内であれば、一時的に配布ポイントへ到達できなくても既存の CRL で失効チェックを継続する
🎛️ トラストアンカー単位の有効化
  • トラストアンカーの設定 crlDpRevocationEnabled で制御する (デフォルトは無効)
  • 有効化すると、そのトラストアンカーで認証されるすべてのリクエストに適用される
  • IAM Roles Anywhere コンソール、AWS SDK、AWS CLI から有効化できる
🔗 既存の CRL インポート機能との併用
  • 手動インポートした CRL と自動失効チェックは併用可能
  • 併用時は、どちらか一方のリストに記載されている証明書は失効済みとして扱われる

🔬 技術仕様

CDP の要件と動作

項目詳細
有効化設定トラストアンカーの crlDpRevocationEnabled を true に設定 (デフォルトは false)
対象 URL スキームHTTP または HTTPS のみ (LDAP などは無視される)
チェック対象の URL 数証明書ごとに最大 5 つの CDP URL
URL 長2,048 文字以内
ポートHTTP は 80、HTTPS は 443 のデフォルトポートのみ
アクセス性ホスト名がパブリック IP アドレスに解決され、インターネットから到達可能であること
リダイレクト非対応 (URL が CRL を直接返す必要がある)
CRL サイズ1 MB 以内の単一の CRL
CRL 更新の反映CA による CRL 公開後、最大 30 分で反映
間接 CRL非対応 (証明書を発行した CA 自身が発行・署名した CRL のみ対応)
OCSP非対応 (IAM Roles Anywhere は OCSP による失効チェックをサポートしない)

🚫 フェイルクローズ動作

⚠️ 失効状態を確認できない場合はリクエストを拒否

チェック対象の配布ポイントから有効な CRL を取得できず、過去にダウンロードした有効な CRL も存在しない場合、IAM Roles Anywhere は失効状態を確認できないため CreateSession リクエストを拒否します。失効状態が確認できない状態で認証情報が発行されることはありません。

🛠️ 設定方法

前提条件

✓IAM Roles Anywhere のトラストアンカーが設定済みであること
✓認証に使用する証明書に CDP の URL が含まれていること (AWS Private CA または独自 PKI で発行)
✓CDP の URL がインターネットからパブリックにアクセス可能で、配布ポイントの要件を満たしていること

手順

1
証明書の CDP URL を確認する
Bash CDP URL の確認 
openssl x509 -text -noout -in certificate.pem | grep -A 4 "CRL Distribution Points"

X509v3 CRL Distribution Points 拡張に HTTP または HTTPS の URL が表示されれば、自動失効チェックの対象になります。

2
トラストアンカーで自動失効チェックを有効化する
Bash 自動失効チェックの有効化 
aws rolesanywhere update-trust-anchor \
  --trust-anchor-id <トラストアンカー ID> \
  --crl-dp-revocation-enabled

この設定は、該当トラストアンカーで認証されるすべてのリクエストに適用されます。コンソールの場合は、トラストアンカーの編集画面から有効化できます。

3
動作を確認する
Bash credential helper による動作確認 
./aws_signing_helper credential-process \
  --certificate certificate.pem \
  --private-key private-key.pem \
  --trust-anchor-arn <トラストアンカー ARN> \
  --profile-arn <プロファイル ARN> \
  --role-arn <ロール ARN>

有効な証明書では認証情報が発行され、CA で失効させた証明書ではリクエストが拒否されることを確認します。なお、配布ポイントの URL を初めて処理する際は CreateSession リクエスト中に CRL をダウンロードするため、初回リクエストのレイテンシーが増加する場合があります。

💡 メリット

💼 ビジネス面

✓運用負荷の削減: CRL の手動インポートと CA 更新のたびの再インポートが不要になり、PKI 運用チームの作業負担を軽減できる
✓セキュリティポスチャの向上: 失効チェックが CA と自動的に同期されるため、失効済み証明書による不正アクセスのリスクを低減できる
✓追加コストなし: 追加料金なしで利用でき、セキュリティ強化に伴うコスト増加がない

🔧 技術面

✓CA との自動同期: CA が公開した最新の CRL が最大 30 分で失効チェックに反映され、人手による更新遅延がなくなる
✓フェイルクローズ設計: 失効状態を確認できない場合はリクエストを拒否するため、不確実な状態で認証情報が発行されない
✓PKI の選択肢が広い: AWS Private CA に加えて独自 PKI でも利用でき、既存の証明書基盤をそのまま活用できる

⚠️ デメリット・制約事項

制限事項

✗CDP の URL はインターネットからパブリックにアクセス可能である必要があり、プライベートネットワーク内のみで公開される CRL は利用できない
✗OCSP による失効チェックはサポートされない
✗間接 CRL (証明書を発行した CA と異なる主体が発行する CRL) はサポートされず、CRL 発行者フィールドを含む配布ポイントはスキップされる
✗チェック対象は証明書ごとに最大 5 つの HTTP/HTTPS URL で、CRL は 1 MB 以内である必要がある
✗自動検出された配布ポイントはアカウント内のリソースとして作成されないため、個別に表示・管理できない

考慮すべき点

⚠️配布ポイントが要件を満たさず、有効な CRL が過去のダウンロードにも存在しない場合、CreateSession が拒否される。有効化前に CDP の URL の到達性と応答速度を確認することが重要
⚠️CA は前の CRL の nextUpdate 期限が切れる前に、更新した CRL を各配布ポイントへ公開する必要がある。期限切れの CRL は使用されず、新しい CRL を取得できなければリクエストが拒否される
⚠️AWS Private CA を使用する場合、CRL は Amazon S3 バケットに公開されるため、S3 の CRL 公開先が配布ポイントの要件 (パブリックアクセス可能であることなど) を満たすよう設定する必要がある
⚠️初めて処理される配布ポイントの URL では、初回の CreateSession リクエストにレイテンシーが追加される

🎯 ユースケース

1️⃣ オンプレミスサーバーの証明書失効管理の自動化

シナリオ: オンプレミスのアプリケーションサーバー群が IAM Roles Anywhere で AWS リソースにアクセスしており、社内 PKI が発行する証明書の失効情報を手動で CRL インポートして管理している。

Bash 自動失効チェックへの移行 
# 既存の手動 CRL インポート運用から自動失効チェックへ移行
aws rolesanywhere update-trust-anchor \
  --trust-anchor-id ta-example1234567890 \
  --crl-dp-revocation-enabled

効果: CA が CRL を更新するたびに行っていた再インポート作業が不要になり、退職者や漏えいした証明書の失効が最大 30 分で自動的に反映される。

2️⃣ AWS Private CA と組み合わせたハイブリッド環境のセキュリティ強化

シナリオ: AWS Private CA で発行した証明書を使用して、ハイブリッド環境のワークロードが IAM Roles Anywhere 経由で AWS にアクセスしている。インシデント発生時に、漏えいした証明書からの認証を迅速に遮断したい。

Bash 証明書の失効のみでインシデント対応が完結 
# AWS Private CA で証明書を失効させる
aws acm-pca revoke-certificate \
  --certificate-authority-arn <CA の ARN> \
  --certificate-serial <証明書のシリアル番号> \
  --revocation-reason "KEY_COMPROMISE"

# AWS Private CA が S3 に公開する CRL を IAM Roles Anywhere が自動取得
# 追加の運用作業は不要

効果: 証明書の失効操作のみでインシデント対応が完結し、IAM Roles Anywhere 側での CRL インポート作業なしに失効済み証明書からの認証情報発行を防止できる。

3️⃣ 手動インポート CRL との併用による多層防御

シナリオ: 複数の CA を利用しており、一部の CA の CRL はパブリックな CDP で公開できないため手動インポートを継続しつつ、CDP を公開できる CA は自動失効チェックへ移行したい。

Bash 手動インポートと自動チェックの併用 
# CDP を公開できない CA の CRL は従来どおり手動インポート
aws rolesanywhere import-crl \
  --name internal-ca-crl \
  --crl-data fileb://crl.der \
  --trust-anchor-arn <トラストアンカー ARN>

# トラストアンカーでは自動失効チェックも有効化
aws rolesanywhere update-trust-anchor \
  --trust-anchor-id ta-example1234567890 \
  --crl-dp-revocation-enabled

効果: 手動インポートと自動チェックを併用でき、どちらか一方のリストに記載された証明書は失効済みとして扱われるため、CA ごとの運用形態に合わせた柔軟な失効管理が実現する。
