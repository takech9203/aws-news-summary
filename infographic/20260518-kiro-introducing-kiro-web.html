ブラウザから自律的ソフトウェア開発を実現

2026-05-18
Kiro

📋 概要

Kiro Web は、ブラウザから直接自律的なソフトウェア開発を行える新しいインターフェース。すべての有料サブスクライバー (Pro、Pro+、Power) 向けにプレビューとして提供が開始された。

ユーザーは app.kiro.dev にアクセスし、構築したい内容を伝えるだけで、Kiro がコードを記述し、複数リポジトリにまたがる変更を調整し、プルリクエストを作成する。

re:Invent で発表された自律的ソフトウェア開発のビジョンに基づき、自律性を別製品としてではなく、Kiro のコア体験に統合するアプローチを採用。今後 Kiro IDE および Kiro CLI にも自律ワークフローが追加される予定。

🔄 Before / After

❌ Before

  • IDE を開かないと AI 支援コーディングを開始できない
  • PR レビュー中のバグ修正や Slack での依頼への対応が遅延
  • 複数リポジトリの変更を手動で調整
  • GitHub Issue からの作業割り当てに手動介入が必要

✅ After

  • ブラウザからどこでも自律的ソフトウェア開発を開始可能
  • 複数リポジトリにまたがる変更を 1 セッションで自動調整
  • GitHub Issue へのラベル/コメントで直接タスク割り当て
  • ステアリングファイルでチームの規約を一貫して適用

⚡ 主要機能

💬

チャットベースのインタラクション

リポジトリを選択し作業内容を記述。Kiro がリポジトリ、Web 検索、過去のレビューからコンテキストを活用して応答。チャットで議論しながら PR を作成。

🤖

自律モード

Autonomous トグルを有効化すると、Kiro が明確化の質問を行い計画を構築。専門サブエージェントが計画・コーディング・検証を実行し完成した PR を提供。

🔀

マルチリポジトリサポート

1 つのセッションで複数リポジトリにまたがる作業が可能。共有ライブラリの更新と依存サービスのマイグレーションを同時実行。

🐙

GitHub インテグレーション

Issue に kiro ラベル追加や /kiro コメントでタスク割り当て。PR へのフィードバックに自動対応。/kiro all で全コメントに一括対応。

📐

ステアリングファイル

コーディング規約、アーキテクチャパターン、テスト標準を定義。.kiro/steering/ から自動読み取り。IDE、CLI、Web 間で共通動作。

☁️

クラウドサンドボックス

各タスクが独自の隔離サンドボックスで実行。セッション終了時に破棄。ネットワーク、MCP ツール、ベースイメージを制御可能。

🎯 メリット

💼 ビジネス面
  • 開発速度の向上: ブラウザからすぐにタスク開始、IDE 起動やローカル環境セットアップ不要
  • マルチリポジトリの効率化: 1 セッションで自動調整、手動コーディネーションのオーバーヘッド削減
  • チーム標準の一貫性: ステアリングファイルでコーディング規約を自動適用
⚙️ 技術面
  • セキュアな実行環境: 隔離サンドボックスでセッション間の干渉を排除
  • コンテキストインテリジェンス: リポジトリ + Web 検索 + 過去のレビュー学習を統合
  • GitHub ネイティブ: 既存ワークフローを変更せずに導入可能

⚠️ 制限事項・考慮点

制限事項
  • 現時点ではプレビュー段階であり、本番利用には慎重な検討が必要
  • 有料プラン (Pro 以上) のみ利用可能。Free プランでは利用不可
  • GitHub のみ対応。GitLab や Bitbucket は現時点で未対応
  • クレジットベースの課金制であり、利用量に応じたコスト管理が必要
考慮すべき点
  • 自律モードのコードは必ず PR として提出されるため、レビュープロセスは維持される
  • ステアリングファイルの品質がアウトプットの品質に直接影響
  • AWS Identity Center を使用する組織では管理者による事前の有効化が必要
  • サンドボックスのネットワークアクセスは組織のセキュリティポリシーに合わせた構成が必要

💡 ユースケース

1. マイクロサービス間の API 変更
バックエンドサービスに新しい API エンドポイントを追加し、フロントエンドクライアントコードも同時に更新する必要があるケース。
Plaintext 実装例 
セッション開始 → backend-api と frontend-app リポジトリを選択
指示: "POST /api/v2/notifications エンドポイントを追加し、
フロントエンドの通知サービスクライアントを更新してください"
→ Kiro が両リポジトリに調整された PR を作成
→ 手動で複数リポジトリの変更を調整する時間を削減し、API 契約の整合性を自動的に維持
2. GitHub Issue からのバグ修正自動化
チームメンバーが GitHub Issue でバグを報告し、開発者はミーティング中で対応できないケース。
Plaintext 実装例 
GitHub Issue に kiro ラベルを追加
Issue 内容: "ユーザー登録時にメールバリデーションが
RFC 5322 に準拠していない #1234"
→ Kiro が Issue を取得、修正コードを作成、テストを追加し PR を作成
→ レビューコメントに /kiro fix で対応
→ 開発者が他の作業に集中している間もバグ修正が進行し、リードタイムを短縮
3. 共有ライブラリのアップグレードとマイグレーション
社内共有ライブラリのメジャーバージョンアップデートに伴い、依存する複数サービスをマイグレーションするケース。
Plaintext 実装例 
セッション開始 → shared-lib, service-a, service-b, service-c を選択
Autonomous モード有効化
指示: "shared-lib を v3 にアップデートし、
全依存サービスの import パスと API 呼び出しを
新しいインターフェースに合わせて更新してください"
→ Kiro が計画を作成し、各リポジトリに調整された PR を作成
→ 複数サービスにまたがるマイグレーション作業を自動化し、手動更新時の見落としや不整合を防止
