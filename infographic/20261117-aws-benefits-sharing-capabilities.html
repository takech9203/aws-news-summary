AWS Billing and Cost Management 📅 2026 年 11 月 17 日

💰 クレジット、Savings Plans、RI の
一貫した共有コントロール

コスト削減ベネフィットの配分を Cost Categories ベースで対称的 (symmetric) かつきめ細かく制御

📝 概要

クレジット、リザーブドインスタンス (RI)、Savings Plans が組織内でどのように共有されるかを、 対称的かつきめ細かく制御できる新機能が登場。 すべてのベネフィットに自動適用されるデフォルト共有設定を定義し、 個々のベネフィット単位で上書きできます。助成金による資金調達、規制上の義務、複数エンティティ構造を持つ組織で、 手動のチャージバック (費用配賦) 照合が不要になります。

3 種類 クレジット / RI / Savings Plans を同一の仕組みで制御
1 回 デフォルト設定で全新規クレジットが自動継承
追加料金なし 全 AWS リージョンで利用可能

❌ Before: アップデート前の課題

  • クレジットの共有設定はクレジットごとに手動構成が必要で、新規付与のたびに設定作業が発生
  • RI / Savings Plans の割引共有は組織全体またはアカウント単位の有効化・無効化が中心で、特定チームへの限定配分が困難
  • 助成金や規制要件がある組織は手動のチャージバック照合で対応

✅ After: アップデート後の改善

  • Billing Preferences で Credit Group Sharing を 1 回設定すれば全新規クレジットが自動継承
  • RI / Savings Plans を個々のコミットメント単位 (Level Sharing) で構成可能
  • Cost Categories という同一の仕組みで一貫した共有コントロールを実現
  • SplitCredit / TransferCredit API でクレジットの分割・移転を自動化

管理アカウントがデフォルトの共有設定とコミットメント単位の Level Sharing を定義し、Cost Categories で定義したアカウントグループに従って各ベネフィットがメンバーアカウントへ配分される構成

⚙️ 主要機能

🎫 1. Credit Group Sharing (クレジットのデフォルト共有設定)

  • Billing Preferences ページで単一のデフォルト設定を構成すると、すべての新規クレジットが自動継承
  • Prioritized sharing group または Restricted sharing group を選択し、Benefit group sharing 関連付けを持つ Cost Category でアカウントグループを指定
  • クレジットごとの手動設定サイクルが不要に

📦 2. RI / Savings Plans の Level Sharing (コミットメント単位の共有設定)

  • インベントリページから個々のコミットメントの詳細ページで共有設定を構成
  • リンクアカウント購入・支払いアカウント購入のどちらにも設定可能
  • Level Sharing は組織のグループ共有設定より優先。未設定のコミットメントは組織のグループ共有またはオープン共有に従う

🔀 3. 共有モード

🌐 Organization-wide (オープン)

所有アカウントに適用後、残りの割引を組織内の共有有効化済みアカウント全体で共有。組織全体の割引額が最大になるモード。

⭐ Prioritized sharing

所有アカウント適用後、定義したグループ内へ優先的に共有し、残余分は組織内の他の共有有効化済みアカウントへ。

🔒 Restricted sharing

定義したグループ内のアカウントにのみ共有。未使用キャパシティが残ってもグループ外には共有されない。

🏷️ 4. Cost Categories ベースの一貫したグルーピング

  • グループ共有には Benefit group sharing、Level Sharing には Benefit level sharing の関連付けを持つ Cost Category を使用
  • 1 つの Cost Category を RI、Savings Plans、クレジットで共通利用可能
  • Cost Explorer、AWS Budgets、Cost and Usage Report で使い慣れた同じ構造で共有先を定義

🔌 5. クレジット操作 API の追加

  • SplitCredit: 1 つのクレジットを複数の子クレジットに分割
  • TransferCredit: クレジットを別のアカウントへ移転
  • 両 API とも dryRun パラメータをサポートし、実行前に影響を確認可能

🧩 追加・更新された API

API 種別 内容
SplitCredit 🆕 新規 クレジットを複数の子クレジットに分割。creditId、portions (金額と説明)、clientToken、dryRun を指定
TransferCredit 🆕 新規 クレジットを destinationAccountId で指定したアカウントへ移転。clientToken、dryRun を指定
GetBillingPreferences 🔄 更新 features に BENEFIT_LEVEL_SHARING が追加され、ベネフィットレベル共有設定を取得可能に
UpdateBillingPreferences 🔄 更新 feature に BENEFIT_LEVEL_SHARING が追加され、ベネフィットレベル共有設定を更新可能に

💻 API 呼び出し例

Python boto3 でのクレジット分割と共有設定の取得 
import boto3

client = boto3.client("billing")

# クレジットを 2 つに分割 (dryRun で事前確認)
response = client.split_credit(
    creditId="credit-id",
    portions=[
        {"amount": "6000", "description": "チーム A 向け"},
        {"amount": "4000", "description": "チーム B 向け"},
    ],
    clientToken="unique-token-1",
    dryRun=True,
)

# ベネフィットレベル共有設定の取得
prefs = client.get_billing_preferences(
    features=["BENEFIT_LEVEL_SHARING"],
)

🛠️ 設定方法

✅ 前提条件

✓AWS Organizations の一括請求 (Consolidated Billing) を利用していること
✓組織の管理アカウントでサインインしていること
✓共有グループを定義する Cost Category を Billing and Cost Management コンソールで作成できること (グループ共有には Benefit group sharing、Level Sharing には Benefit level sharing の関連付けが必要)

📋 手順

1

クレジットのグループ共有を設定する

  1. Billing and Cost Management コンソールで [Billing preferences] を選択
  2. [Credit sharing preferences] セクションで [Edit] を選択
  3. [Prioritized sharing group] または [Restricted sharing group] を選択
  4. Benefit group sharing 関連付けを持つ Cost Category を選択 (または新規作成)
  5. 影響に関する警告を確認し、設定を保存

→ 以降に付与されるすべての新規クレジットがこの共有設定を自動継承します。

2

RI / Savings Plans のグループ共有を設定する

  1. [Billing preferences] の [Reserved Instances and Savings Plans discount sharing preference] セクションで [Edit] を選択
  2. [Prioritized sharing group] または [Restricted sharing group] を選択
  3. Benefit group sharing 関連付けを持つ Cost Category を選択して保存

→ 組織全体のデフォルトモードを設定。あわせて [discount sharing preference by account] でアカウントごとの有効化・無効化を管理します。

3

個々のコミットメントに Level Sharing を設定する

  1. [Savings Plans] または [Reservations] 配下の [Inventory] を選択
  2. 対象のコミットメントを選択して詳細ページを開く
  3. [Sharing preferences] セクションで [Manage sharing preference] を選択
  4. [Mode] で [Prioritized] または [Restricted] を選択
  5. Benefit level sharing 関連付けを持つ Cost Category を選択
  6. [Rule] で利用可能アカウントを定義するルールを選択
  7. [Selected rule details] で内容を確認し、[Save] を選択

→ 特定チーム向けコミットメントの割引を定義したアカウント群に限定可能。設定を削除すると組織の共有設定に従う動作に戻ります。

👍 メリット

💼 ビジネス面

✓チャージバック照合の自動化: 助成金、規制上の義務、複数エンティティ構造を持つ組織が手動で行っていたベネフィット配分の照合作業を自動化
✓ガバナンスの強化: 特定の資金源に紐づくクレジットや事業部門向けコミットメントを、意図したアカウント群にのみ配分
✓追加コストなし: 新しい共有コントロールは追加料金なしで利用可能

🔧 技術面

✓設定の一元化と自動継承: Credit Group Sharing のデフォルト設定により、クレジットごとの手動設定が不要
✓一貫したグルーピング構造: Cost Explorer、AWS Budgets、Cost and Usage Report と同じ Cost Categories を利用するため学習コストが低い
✓API による自動化: SplitCredit / TransferCredit や UpdateBillingPreferences により、共有設定やクレジット操作を IaC やスクリプトに組み込める

⚠️ デメリット・制約事項

🚧 制限事項

✗各アカウントは 1 つの共有グループにのみ所属できる
✗組織でグループ共有に関連付けできる Cost Category は同時に 1 つのみ
✗共有用の Cost Category は Billing and Cost Management コンソールで作成・編集する必要があり、ルールで使用できるディメンションは Accounts のみ
✗Level Sharing のルールにはコミットメントを所有するアカウントを含める必要があり、Cost Category は管理アカウントに属している必要がある
✗1 つの Cost Category に Benefit group sharing と Benefit level sharing の両方の関連付けを持たせることはできない

🤔 考慮すべき点

⚠グループ共有や Level Sharing はオープン共有と比較して、割引が定義したアカウント内に留まるため、組織全体の削減額が低下する可能性がある
⚠月の途中で設定を変更すると、その月のこれまでの割引が新しい設定で再適用され、見積もり請求額が変動する。最終的な請求は月末 23:59:59 UTC 時点の設定に基づく
⚠Savings Plans の割引を共有するには、Savings Plans を所有するアカウント側でも共有が有効化されている必要がある
⚠既存の RI / Savings Plans グループ共有に関連付け済みの Cost Category はそのまま動作するが、Benefit group sharing の関連付けへは自動変換されない

🎯 ユースケース

🎓 ユースケース 1: 研究助成金によるクレジットの限定配分

シナリオ: 大学や研究機関が複数の研究プロジェクトを別々の AWS アカウントで運用しており、特定の助成金で付与されたクレジットを、その助成金の対象プロジェクトのアカウントにのみ使用させる必要がある。

実装例:

  1. 助成金対象アカウントを定義する Cost Category を作成 (Benefit group sharing 関連付け)
  2. Billing Preferences で Restricted sharing group を選択し、該当 Cost Category を指定
  3. 複数の助成金がある場合は SplitCredit でクレジットを分割し、助成金ごとに配分
💡 効果: 助成金の使途に関する規制・監査要件を満たしつつ、手動のチャージバック照合なしでクレジット配分を自動化できる。

🏢 ユースケース 2: 事業部門専用の Savings Plans

シナリオ: 持株会社配下の複数の事業会社が同一の AWS Organizations を利用しており、ある事業会社が自社予算で購入した Savings Plans の割引を他社に流出させたくない。

実装例:

  1. 事業会社ごとのアカウント群を定義する Cost Category を作成 (Benefit level sharing 関連付け)
  2. 対象の Savings Plans の詳細ページで Manage sharing preference を選択
  3. Mode に Restricted を選択し、自社アカウント群のルールを指定
💡 効果: コミットメントの購入元である事業会社内にのみ割引を限定でき、会社間の費用負担の公平性を担保できる。

⚖️ ユースケース 3: 優先配分と組織全体の利用率最大化の両立

シナリオ: プラットフォームチームが全社向けに RI を購入しているが、まずは基幹システムのアカウント群に割引を優先適用し、余剰分は他チームにも共有して利用率を最大化したい。

実装例:

  1. 基幹システムのアカウント群を定義する Cost Category を作成
  2. 対象の RI の詳細ページで Level Sharing を設定し、Mode に Prioritized を選択
  3. 余剰割引は組織内の共有有効化済みアカウントへ自動的に共有される
💡 効果: 重要ワークロードへの割引適用を優先しつつ、未使用分を組織全体で活用して全体の削減額を最大化できる。

🔗 関連サービス・機能

  • AWS Cost Categories: 共有グループの定義に使用するグルーピング構造。Cost Explorer、AWS Budgets、Cost and Usage Report と共通
  • AWS Organizations: 一括請求 (Consolidated Billing) の基盤であり、ベネフィット共有の前提となるサービス
  • AWS Billing Conductor: カスタム請求グループを構成するサービス。共有設定の変更は標準の AWS 請求に影響する点に注意
  • Savings Plans / Amazon EC2 リザーブドインスタンス: 本アップデートで Level Sharing の対象となるコミットメント型割引

📌 まとめ

クレジット、RI、Savings Plans の共有を Cost Categories ベースで一貫して制御できるようになり、 これまで手動のチャージバック照合に頼っていたベネフィット配分を自動化できます。 複数の事業部門や助成金を扱う組織は、まず共有グループを表す Cost Category を設計し、 Credit Group Sharing のデフォルト設定と重要なコミットメントの Level Sharing から導入を検討することが推奨されます。
