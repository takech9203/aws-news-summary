🏛️ AWS Control Tower

AFT が OU 間のアカウント移動時にカスタマイズを再適用

📅 2026 年 7 月 16 日

📌 概要

AWS Control Tower Account Factory for Terraform (AFT) は、登録済みアカウントが別の組織単位 (OU) へ移動された際に、そのアカウントのカスタマイズを自動的に再適用できるようになりました。 これにより、OU のメンバーシップに紐づくコンプライアンスやセキュリティのベースラインを、アカウントの移動後も自動的に維持できます。

AFT は AWS Control Tower を Terraform ワークフローで運用するためのフレームワークで、アカウントのプロビジョニングとカスタマイズを Infrastructure as Code (IaC) として管理します。 今回のアップデートは、この AFT に account_move というトリガーを追加し、OU 構造の変更に伴う設定管理を自動化するものです。

⛔ Before：アップデート前の課題
  • 別の OU へ移動した後、カスタマイズの再適用を管理者が手動でトリガーする必要があった
  • 手動作業が運用負荷を増やし、構成ドリフト (configuration drift) のリスクを高めていた
  • OU に紐づくベースラインと実際の設定の整合性を保つ仕組みが不足していた
🎉 After：アップデート後の改善
  • OU 間で移動するとカスタマイズが自動的に再適用される
  • 手動トリガーが不要となり、運用負荷と構成ドリフトのリスクが低減
  • ブートストラップとプロビジョニングをスキップし、より迅速に完了

アカウントを OU 間で移動すると account_move トリガーが検知され、スキップ対象でないアカウントに対して、ブートストラップとプロビジョニングを省略したカスタマイズパイプラインが実行される

⚙️ 主要機能

🔀 アカウント移動トリガーによる自動再適用
  • AFT 設定で aft_customization_triggers = ["account_move"] を指定して有効化する
  • 登録済みアカウントが別の OU へ移動されると、カスタマイズが自動的に再適用される
  • OU に紐づくコンプライアンスやセキュリティのベースラインとの整合性を維持する
⚡ フェーズのスキップによる高速化
  • 再適用時はブートストラップフェーズとプロビジョニングフェーズをスキップする
  • グローバルカスタマイズとアカウントレベルカスタマイズのみを実行する
  • 実行時間を短縮し、必要な処理のみを効率的に完了する
🎛️ アカウント単位のオプトアウト
  • account_skip_customization_triggers = "true" で特定アカウントを再適用対象から除外できる
  • チームが再適用を適用するアカウントを選択できる柔軟性を提供する
🧩 その他の改善点
  • Terraform Cloud および Enterprise のワークスペース命名変数のカスタマイズをサポート
  • AFT ロギングバケットに対するアクセス制御を強化
  • 大規模な AWS Enterprise Support 登録に対するスケーリングを改善

✅ メリット

💼 ビジネス面

  • コンプライアンス維持の自動化：OU に紐づくベースラインを移動後も自動維持
  • 運用負荷の削減：手動での再適用作業が不要となり管理コストを低減
  • ガバナンス強化：組織構造の変更に設定が確実に追従し統制環境の一貫性が向上

🔧 技術面

  • 構成ドリフトの防止：移動後のアカウントが移動先 OU の設定に自動整合
  • 実行効率の向上：不要な Bootstrap / Provisioning をスキップし迅速に完了
  • 柔軟な制御：アカウント単位でオプトアウトでき対象を細かく選択可能

⚠️ デメリット・制約事項

制限事項

  • 再適用時は Bootstrap / Provisioning がスキップされるため、これらのフェーズで定義される処理はトリガーで再実行されない
  • アカウント移動トリガーは設定で明示的に有効化する必要がある (デフォルトでは無効)

考慮すべき点

  • 意図しないカスタマイズが適用されないよう account_skip_customization_triggers を適切に管理する
  • 大規模な OU 移動では複数アカウントで同時にパイプラインが起動する可能性があり、実行への影響を考慮する

🎯 ユースケース

1. セキュリティベースラインの自動整合
シナリオ：開発用アカウントを、より厳格なセキュリティ要件を持つ本番 OU へ昇格させる際に、本番 OU のベースラインを自動適用したい。
効果：アカウントを本番 OU へ移動するだけで本番向けカスタマイズが自動再適用され、手動作業なしでセキュリティ設定が整合する。
2. コンプライアンス OU 間の移設
シナリオ：規制要件の異なるコンプライアンス OU 間でアカウントを移設する際、移設先の要件に沿った設定へ確実に更新したい。
効果：移設と同時にカスタマイズが再適用され、構成ドリフトを防ぎながらコンプライアンス要件を満たせる。
3. 特定アカウントの除外運用
シナリオ：一部の特殊なアカウントは OU 移動時に自動再適用を行わず、手動で管理したい。
効果：account_skip_customization_triggers = "true" で対象を除外し、自動再適用の影響を受けずに個別管理できる。

💰 料金・利用可能リージョン・関連サービス

💰 料金

AFT の機能拡張であり追加料金は発生しません。AFT の実行に使う AWS CodePipeline、AWS Step Functions、AWS Lambda などの基盤サービスの利用料金が発生します。

🌐 利用可能リージョン

AWS Control Tower Account Factory for Terraform が提供されているすべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

  • AWS Control Tower：マルチアカウント環境のセットアップとガバナンスを提供する基盤サービス
  • AWS Organizations：OU の管理とアカウント移動を行う組織管理サービス
  • Terraform (HashiCorp)：AFT が IaC として利用するプロビジョニングツール。Cloud / Enterprise のワークスペース命名にも対応
  • AWS CodePipeline / AWS Step Functions：AFT のカスタマイズパイプラインを実行する基盤サービス

📝 まとめ

今回のアップデートにより、AWS Control Tower Account Factory for Terraform は OU 間のアカウント移動時にカスタマイズを自動再適用できるようになり、コンプライアンスやセキュリティのベースライン維持が大幅に効率化されました。 マルチアカウント環境で OU ベースのガバナンスを運用しているチームは、aft_customization_triggers = ["account_move"] を設定することで、構成ドリフトの防止と運用負荷の削減を実現できます。既存の AFT 環境でこの設定の有効化を検討することを推奨します。
