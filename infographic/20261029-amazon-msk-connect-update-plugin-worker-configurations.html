Amazon MSK Connect

🔌 コネクタプラグインおよびワーカー構成の更新サポート

既存コネクタのカスタムプラグインとワーカー構成をインプレースで更新可能に
📅 リリース日: 2026 年 10 月 29 日 🛠️ 機能: UpdateConnector API によるインプレース更新 💰 追加料金なし

📝 概要

Amazon MSK Connect は、Apache Kafka Connect コネクタのデプロイ、モニタリング、スケーリングを行うフルマネージドサービスです。 今回のアップデートにより、既存コネクタのカスタムプラグイン (コネクタコード) と ワーカー構成を UpdateConnector API で インプレース更新できるようになりました。

コネクタはコミット済みオフセットを保持したまま、更新完了後に停止した位置から処理を再開します。 依存関係を更新した新バージョンのコネクタコードへの入れ替え、キー/バリューコンバーターの切り替え、 プロデューサー/コンシューマープロパティのチューニングを、パイプラインを削除・再作成せずに実施できます。

❌ Before: アップデート前の課題

✗プラグインやワーカー構成の変更には、コネクタの削除と再作成が必要だった
✗削除・再作成は破壊的なオペレーションであり、設定ミスやダウンタイムのリスク、運用負荷が高かった
✗依存ライブラリ更新 (脆弱性対応など) やコンバーター変更のたびに、移行手順の計画と検証が必要だった

✅ After: アップデート後の改善

✓カスタムプラグインを新しいプラグイン/リビジョンへインプレースで更新可能に
✓ワーカー構成 (コンバーター切り替え、プロパティ調整など) を更新可能に
✓コミット済みオフセットを保持し、停止位置から処理を再開。データの再処理や欠損の心配なし
✓更新後のヘルスチェックと、失敗時の自動ロールバックで安全に更新

🏗️ アーキテクチャ図: インプレース更新のフロー

sequenceDiagram
    participant U as 👤 運用者
    participant MC as 🔌 MSK Connect
    participant W as ⚙️ コネクタワーカー
    participant K as 📨 Kafka クラスター

    U->>MC: UpdateConnector 新プラグインとワーカー構成を指定
    MC-->>U: connectorOperationArn を返却
    MC->>W: ワーカー設定を更新 UPDATE_WORKER_SETTING
    MC->>MC: 更新を検証 VALIDATE_UPDATE
    alt 検証成功
        W->>K: コミット済みオフセットから処理を再開
        MC-->>U: UPDATE_COMPLETE
    else 検証失敗
        MC->>W: 元の構成へロールバック
        MC-->>U: ROLLBACK_COMPLETE
    end
    U->>MC: DescribeConnectorOperation で進捗を確認

💡 UpdateConnector API によるインプレース更新のフロー。更新後にヘルスチェックが実行され、失敗時には元の構成へ自動的にロールバックされます。

⚡ 主要機能

1️⃣ カスタムプラグインの更新
→既存コネクタに関連付けられたカスタムプラグイン (ARN とリビジョン) を変更可能
→依存関係を更新した新バージョンのコネクタコードの適用に有効
→コネクタの削除・再作成が不要になり、インプレースで入れ替え可能
2️⃣ ワーカー構成の更新
→ワーカー構成 (ARN とリビジョン) を変更可能
→キーコンバーターやバリューコンバーターの切り替えに対応
→スループットやレイテンシーを最適化するプロデューサー/コンシューマープロパティのチューニングに対応
→useDefaultWorkerConfiguration でデフォルトのワーカー構成への切り替えも指定可能
3️⃣ オフセットを保持した継続処理
→更新中もコネクタはコミット済みオフセットを保持
→更新完了後、タスクは停止した位置から処理を再開
→データの重複処理や欠損のリスクを最小化
4️⃣ ヘルスチェックと自動ロールバック
→更新後に MSK Connect がコネクタとタスクのヘルスを検証
→検証に失敗した場合は元の構成へ自動的にロールバック
→UpdateConnector は操作 ARN を返却し、DescribeConnectorOperation で進捗と各ステップの状態を追跡可能

🔧 技術仕様

📋 更新オペレーションの追跡

項目詳細
更新 APIUpdateConnector (plugins、workerConfiguration、useDefaultWorkerConfiguration パラメータが追加)
追跡 APIDescribeConnectorOperation (originWorkerSetting/targetWorkerSetting にプラグインとワーカー構成が追加)
オペレーションタイプUPDATE_WORKER_SETTING、UPDATE_CONNECTOR_CONFIGURATION など
オペレーション状態PENDING、UPDATE_IN_PROGRESS、UPDATE_COMPLETE、UPDATE_FAILED、ROLLBACK_IN_PROGRESS、ROLLBACK_COMPLETE、ROLLBACK_FAILED など
ステップタイプINITIALIZE_UPDATE、UPDATE_WORKER_SETTING、VALIDATE_UPDATE、FINALIZE_UPDATE など

🛠️ 設定方法

✅ 前提条件

✓Amazon MSK Connect で稼働中のコネクタが存在すること
✓更新先のカスタムプラグイン (新しいリビジョン) またはワーカー構成が作成済みであること
✓kafkaconnect:UpdateConnector および kafkaconnect:DescribeConnectorOperation を実行できる IAM 権限があること
🔍 現在の構成を確認
describe-connector
→
🔄 更新を実行
update-connector
→
📊 進捗を追跡
describe-connector-operation

STEP 1現在のコネクタ情報を確認

BashAWS CLI
aws kafkaconnect describe-connector \
  --connector-arn <コネクタの ARN>

コネクタの現在の構成と currentVersion を確認します。UpdateConnector の呼び出しには currentVersion の指定が必要です。

STEP 2プラグインとワーカー構成を更新

BashAWS CLI
aws kafkaconnect update-connector \
  --connector-arn <コネクタの ARN> \
  --current-version <現在のバージョン> \
  --plugins '[{"customPlugin":{"customPluginArn":"<新しいプラグインの ARN>","revision":2}}]' \
  --worker-configuration '{"workerConfigurationArn":"<ワーカー構成の ARN>","revision":3}'

既存コネクタのカスタムプラグインとワーカー構成をインプレースで更新します。レスポンスに含まれる connectorOperationArn を控えておきます。

STEP 3更新オペレーションの進捗を確認

BashAWS CLI
aws kafkaconnect describe-connector-operation \
  --connector-operation-arn <オペレーションの ARN>

更新オペレーションの状態 (UPDATE_IN_PROGRESS、UPDATE_COMPLETE など) と各ステップの進捗を確認します。検証に失敗した場合は ROLLBACK_IN_PROGRESS を経て元の構成に戻ります。

💡 メリット

💼 ビジネス面
✓運用リスクの低減: 削除・再作成という破壊的オペレーションが不要になり、更新時の障害リスクが低減される
✓運用コストの削減: 移行手順の計画や再作成時の設定再入力が不要になり、運用工数を削減できる
✓追加費用なし: 本機能は追加料金なしで利用可能
⚙️ 技術面
✓処理の継続性: コミット済みオフセットが保持され、停止位置から処理を再開。データの再処理や欠損を回避できる
✓安全な更新: ヘルスチェックと失敗時の自動ロールバックにより、不正な構成変更から保護される
✓可観測性: 操作 ARN により DescribeConnectorOperation でステップ単位の進捗を追跡でき、自動化パイプラインにも組み込みやすい

⚠️ デメリット・制約事項

🚧 制限事項
⚠更新対象として指定するカスタムプラグインやワーカー構成は、事前に MSK Connect 上に作成しておく必要がある
⚠UpdateConnector には currentVersion の指定が必要であり、並行更新時は競合に注意が必要
🤔 考慮すべき点
⚠新しいプラグインのコネクタ設定互換性 (設定キーやコンバーターの互換性) は事前に検証環境で確認することが望ましい
⚠更新中はタスクの一時停止が発生するため、レイテンシー要件が厳しいワークロードでは更新タイミングを計画すべき
⚠skipHealthValidation でヘルス検証をスキップできるが、自動ロールバックの保護が働かなくなるため通常は推奨されない

🎯 ユースケース

1. 🔒 プラグインの脆弱性対応・バージョンアップ

シナリオ: 利用中のサードパーティコネクタ (例: JDBC Sink Connector) の依存ライブラリに脆弱性が見つかり、修正版へ早急に入れ替えたい。

Bash実装例
# 修正版 JAR をアップロードして新しいカスタムプラグインを作成した後
aws kafkaconnect update-connector \
  --connector-arn <コネクタの ARN> \
  --current-version <現在のバージョン> \
  --plugins '[{"customPlugin":{"customPluginArn":"<修正版プラグインの ARN>","revision":1}}]'
✨ 効果: コネクタを削除・再作成せずに修正版プラグインへ入れ替えられ、オフセットを保持したまま処理を継続できるため、セキュリティ対応のリードタイムを短縮できる。
2. 🔄 コンバーターの切り替え

シナリオ: データ基盤の標準化に伴い、バリューコンバーターを JSON から Avro (Schema Registry 連携) へ切り替えたい。

Bash実装例
# Avro コンバーターを設定した新しいワーカー構成を作成した後
aws kafkaconnect update-connector \
  --connector-arn <コネクタの ARN> \
  --current-version <現在のバージョン> \
  --worker-configuration '{"workerConfigurationArn":"<Avro 用ワーカー構成の ARN>","revision":1}'
✨ 効果: パイプラインを再構築することなくシリアライゼーション形式を移行でき、切り替えに失敗した場合も自動ロールバックで元の構成に復帰できる。
3. 📈 スループット・レイテンシーのチューニング

シナリオ: データ量の増加に伴い、プロデューサー/コンシューマープロパティ (バッチサイズ、fetch.min.bytes など) を調整してスループットを改善したい。

Bash実装例
# チューニング済みプロパティを含むワーカー構成を作成した後
aws kafkaconnect update-connector \
  --connector-arn <コネクタの ARN> \
  --current-version <現在のバージョン> \
  --worker-configuration '{"workerConfigurationArn":"<チューニング済み構成の ARN>","revision":2}'

# 更新の進捗を確認
aws kafkaconnect describe-connector-operation \
  --connector-operation-arn <オペレーションの ARN>
✨ 効果: 本番トラフィックを流しながら段階的にパラメータを調整でき、性能改善のイテレーションを高速化できる。

🔗 関連サービス・機能

📨 Amazon MSK

MSK Connect が接続する Apache Kafka 互換のフルマネージドストリーミングサービス。

🔌 Apache Kafka Connect

MSK Connect の基盤となるオープンソースのコネクタフレームワーク。ソース/シンクコネクタによるデータ連携を実現。

⏸️ MSK Connect の一時停止・再開機能

2026 年 10 月に追加された PauseConnector/ResumeConnector API。本機能と同様に操作 ARN で進捗を追跡でき、オフセットを保持したまま再開可能。

📌 まとめ

Amazon MSK Connect の既存コネクタに対して、カスタムプラグインとワーカー構成をインプレースで更新できるようになり、 従来必要だった削除・再作成の運用負荷とリスクが解消されました。 オフセット保持による処理の継続性と、ヘルスチェック・自動ロールバックによる安全性を備えているため、 プラグインのバージョンアップやコンバーター変更を予定している場合は、UpdateConnector API を利用した更新フローへの移行を推奨します。
