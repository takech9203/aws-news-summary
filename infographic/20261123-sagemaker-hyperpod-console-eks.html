🧭 EKS オーケストレーションクラスター作成の
再設計されたコンソールエクスペリエンス

リリース日: 2026 年 11 月 23 日 | ガイド付きウィザードとワークロードプロファイルで ML クラスター構築を効率化

📝 概要

Amazon SageMaker HyperPod が、Amazon EKS をオーケストレーターとするクラスター作成のための再設計されたコンソールエクスペリエンスを発表。 新しいガイド付きワークフローにより、ネットワーク、インスタンスグループ、ストレージ、権限、耐障害性、オブザーバビリティ、ライフサイクルスクリプト、タグを順を追って効率的に設定できます。 必須設定とオプション設定が明確に分離され、最低限の入力でデプロイし、追加機能は後から段階的に有効化できます。

❌ Before: アップデート前の課題
  • 必須設定とオプション設定が混在し、最低限必要な項目を見極めにくい
  • ネットワーク、オペレーター、オブザーバビリティなどを個別に設定する必要があり、繰り返しの設定作業が発生
  • 用途 (トレーニング / 推論) に応じた推奨構成を適用する仕組みがなく、アドオン選定の知識が必要
✅ After: アップデート後の改善
  • 必須設定 (クラスターエッセンシャル) とオプション設定が分離され、必要な項目だけでクラスター作成が可能
  • 4 つのワークロードプロファイルで用途に合わせた推奨設定を一括適用
  • スマートデフォルトで設定作業を削減しつつ、個別設定・高度な設定も引き続き調整可能

「クラスターエッセンシャル」「オプション設定」「確認と作成」の 3 ステップ構成のウィザードでクラスターを設計し、CloudFormation が EKS オーケストレーションの HyperPod クラスターをプロビジョニングします。

⚡ 主要機能

🧭 1. ガイド付きワークフロー
  • 「Configure cluster essentials」「Optional settings」「Review and create」の明確な 3 ステップ構成
  • ネットワーク、インスタンスグループ、ストレージ、権限、耐障害性、オブザーバビリティ、ライフサイクルスクリプト、タグを順を追って設定
  • 検証エラー発見時は該当ステップ・セクションが自動的に開き、修正箇所を迷わない
🔀 2. 必須設定とオプション設定の分離
  • 必要な項目 (名前、ネットワーク、インスタンスグループ、ストレージ) のみ入力すればデプロイ可能
  • オペレーター、オートスケーリング、オブザーバビリティなどは後から段階的に有効化できる
  • 組み込みのクォータ検証により、インスタンス数がクォータを超過する可能性がある場合は警告を表示
🎛️ 3. ワークロードプロファイル
  • 4 プロファイルから選択し、オートスケーラー (Karpenter)、HyperPod オペレーター、オブザーバビリティメトリクス、階層型ストレージ、タスクガバナンスの推奨構成を一括適用
  • プロファイル適用後も、すべての設定を個別に編集可能
📦 All add-ons
すべての推奨アドオンを適用
🏋️ Training
分散トレーニングに最適化
🚀 Inference
推論ワークロードに最適化
🧱 No add-ons
最小構成で開始
⚙️ 4. EKS クラスターのインライン作成
  • EKS コンソールを開かずに、ウィザード内から新しい Amazon EKS クラスターを作成可能
  • Kubernetes バージョンの選択、デフォルト Helm チャートとアドオンのインストール、有効化するオペレーターの選択に対応
📜 5. デプロイ方法の選択
  • コンソールから直接作成する方法に加え、CloudFormation テンプレートパラメータ (JSON) をダウンロードして AWS CLI からデプロイ可能
  • ダウンロードしたパラメータファイルを編集して IaC ワークフローに組み込める

📋 前提条件

✓AWS アカウントと SageMaker AI コンソールへのアクセス権限
✓使用するインスタンスタイプに対する十分な SageMaker HyperPod クォータ
✓既存 VPC を使用する場合は、SageMaker AI からアクセス可能な VPC (EKS 用サブネットはプライベートである必要あり)

ステップ 1: ウィザードの起動
  • SageMaker AI コンソールを開き、[HyperPod Clusters] から [Cluster Management] を選択
  • [Create HyperPod cluster] のドロップダウンで [Orchestrated by Amazon EKS] を選択
  • 2 つの設定ステップと確認ページで構成されるウィザードが開く
ステップ 2: クラスターエッセンシャルの設定
  • クラスター名、ネットワーク (VPC / AZ / セキュリティグループ)、インスタンスグループ、ストレージ (FSx for Lustre) を設定
  • インスタンスグループは最低 1 つ必要で、複数のインスタンスタイプを組み合わせたヘテロジニアスクラスターも構成可能
ステップ 3: オプション設定とデプロイ
  • ワークロードプロファイルを選択して推奨アドオンセットを適用し、必要に応じて各設定を調整
  • [Review and create] で内容を確認し、[Create cluster] を選択するか、CloudFormation テンプレートパラメータをダウンロードして CLI からデプロイ
Bash CloudFormation パラメータをダウンロードした場合のデプロイ例 
# CloudFormation パラメータをダウンロードした場合のデプロイ例
aws cloudformation create-stack \
  --stack-name my-hyperpod-cluster \
  --template-url <テンプレート URL> \
  --parameters file://downloaded-parameters.json \
  --capabilities CAPABILITY_NAMED_IAM

ダウンロードしたパラメータ JSON ファイルを指定して CloudFormation スタックを作成し、クラスターリソースをプロビジョニングします。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓セットアップ時間の短縮: スマートデフォルトとワークロードプロファイルで ML インフラの立ち上げが迅速に
✓専門知識への依存低減: 用途別の推奨構成により、Kubernetes や HyperPod エコシステムの深い知識がなくても適切に構成可能
✓設定ミスの削減: クォータ検証とエラー箇所への自動ナビゲーションでデプロイ失敗の手戻りを防止

🔧 技術面のメリット

✓段階的な機能有効化: 必須項目のみで作成し、後から機能追加できる柔軟な運用
✓EKS インライン作成: オーケストレーター込みのクラスター構築がワンストップで完結
✓IaC との連携: コンソールで設計した構成を CI/CD パイプラインに組み込める

🚫 制限事項

✗クラスター名は作成後に変更できない
✗オブザーバビリティアドオンには、該当リージョンの IAM Identity Center の organization インスタンスが必要
✗Karpenter によるオートスケーリングは、Standard インスタンスグループが 1 つ以上ある場合のみ有効化可能
✗新規 EKS クラスター作成時は、HyperPod 用の VPC サブネットがプライベートである必要がある

⚠️ 考慮すべき点

⚠️本アップデートはコンソールエクスペリエンスの改善であり、API や CLI のクラスター作成フローは対象外
⚠️クラスターインスタンス、FSx for Lustre、EBS ボリュームなど作成されるリソースには料金が発生
⚠️インスタンスタイプごとのクォータと未割り当て IP アドレスを事前に確認する必要がある

🎯 ユースケース

🏋️ ユースケース 1: トレーニング用クラスターの迅速な立ち上げ

シナリオ: 基盤モデルの分散トレーニング環境を新規に構築したいが、Kubernetes アドオンの選定に時間をかけたくない。

  1. ウィザードで [Orchestrated by Amazon EKS] を選択
  2. インスタンスグループに GPU インスタンスを追加
  3. ワークロードプロファイルで [Training] を選択 → HyperPod トレーニングオペレーター、オブザーバビリティなどの推奨構成が一括適用
  4. [Create cluster] でデプロイ
💡 効果: トレーニングに最適化されたアドオン構成が自動適用され、環境構築のリードタイムを大幅に短縮できる。
🧱 ユースケース 2: 最小構成から始める段階的な本番化

シナリオ: まず最小構成で PoC 用クラスターを作成し、本番化の段階でオブザーバビリティやタスクガバナンスを追加したい。

  1. クラスターエッセンシャル (名前 / ネットワーク / インスタンスグループ / ストレージ) のみ設定
  2. ワークロードプロファイルは [No add-ons] を選択してデプロイ
  3. 本番化のタイミングで、オブザーバビリティアドオンやタスクガバナンスを後から有効化
💡 効果: 必要最小限の設定で素早く検証を開始し、要件の確定に合わせて機能を段階的に追加できる。
🔁 ユースケース 3: コンソール設計 + IaC デプロイのハイブリッド運用

シナリオ: プラットフォームチームがコンソールで構成を設計し、デプロイは CI/CD パイプライン経由で統制したい。

  1. ウィザードでクラスター構成を設計
  2. [Review and create] で [Download CloudFormation template parameters] を選択
  3. パラメータ JSON をリポジトリで管理し、パイプラインから aws cloudformation create-stack を実行
💡 効果: コンソールの使いやすさと IaC の再現性・統制を両立し、複数環境への展開を標準化できる。

💰 料金と利用可能リージョン

💵 料金

コンソールエクスペリエンス自体に追加料金はありません。クラスターを構成する SageMaker HyperPod インスタンス、FSx for Lustre ファイルシステム、Amazon EBS ボリュームなどのリソースには通常の利用料金が発生します。詳細は SageMaker AI 料金ページを参照してください。

🌍 利用可能リージョン

Amazon SageMaker HyperPod が利用可能なすべての AWS リージョンで提供されます。

🔗 関連サービス・機能

→Amazon EKS: HyperPod クラスターのオーケストレーターとして機能し、ウィザード内から新規作成も可能
→AWS CloudFormation: クラスターリソースのプロビジョニングに使用され、テンプレートパラメータのダウンロードによる CLI デプロイにも対応
→Amazon FSx for Lustre: クラスターの高性能共有ストレージとして、ウィザードから新規作成または既存ファイルシステムの選択が可能
→Karpenter: ワークロードプロファイルまたは個別設定で有効化できるノードオートスケーリング
→AWS IAM Identity Center: オブザーバビリティアドオンの利用に必要な organization インスタンスを提供

📌 まとめ

Amazon SageMaker HyperPod の EKS オーケストレーションクラスター作成が、必須設定とオプション設定を分離したガイド付きウィザードに刷新され、ワークロードプロファイルによる推奨構成の一括適用が可能になりました。 ML インフラの構築を担当するチームは、設定作業の負荷を抑えつつ、用途に最適化された HyperPod クラスターを迅速にデプロイできます。 まずは検証環境で Training または Inference プロファイルを試し、自チームの標準構成を確立することを推奨します。
