AWS DataSync

🔄 DataSync Enhanced モードが FSx for Windows File Server / FSx for NetApp ONTAP と Red Hat OpenShift Virtualization をサポート

📅 リリース日: 2026 年 10 月 29 日 🏷️ サービス: AWS DataSync

📋 概要

AWS DataSync の Enhanced モードが、Amazon FSx for Windows File Server および Amazon FSx for NetApp ONTAP を転送元または転送先のロケーションとしてサポートしました。オンプレミスのファイルサーバーから FSx for Windows File Server への移行など、Windows 環境間のデータ移行を Enhanced モードの高いパフォーマンスで実行できます。

さらに、Enhanced モードのエージェントを Red Hat OpenShift Virtualization バージョン 4.20 以降にデプロイ可能になりました。これにより Enhanced モードは Basic モードと同等のロケーションオプションを利用できるようになり、大規模なファイル移行やデータ同期を行うストレージ管理者、移行プロジェクト担当者にとって重要なアップデートです。

❌ アップデート前の課題

  • FSx for Windows File Server / FSx for NetApp ONTAP のタスクでは Enhanced モードを選択できず、Basic モードが必要だった
  • Basic モードは準備・転送・検証を順次実行するため、大規模データセットでは転送に時間がかかっていた
  • タスク実行あたりのファイル数・オブジェクト数にクォータ制限があり、大規模移行ではデータセットの分割が必要だった
  • OpenShift Virtualization 利用環境では、エージェント用に別の仮想化基盤を用意する必要があった

✅ アップデート後の改善

  • FSx for Windows File Server / FSx for NetApp ONTAP を対象とした転送でも Enhanced モードを選択可能になった
  • 並列処理により、ほとんどのワークロードで Basic モードより高いパフォーマンスを実現
  • 実質無制限のファイル・オブジェクトを 1 つのタスク実行で転送でき、データセットの分割が不要になった
  • OpenShift Virtualization 4.20 以降に Enhanced モードのエージェントを直接デプロイ可能になった

オンプレミスのファイルサーバーから、Red Hat OpenShift Virtualization などにデプロイした Enhanced モードエージェントを経由して、FSx for Windows File Server や FSx for NetApp ONTAP へ高速にデータを転送できます。

⚡ 主要機能

🗄️ FSx for Windows File Server / FSx for NetApp ONTAP の Enhanced モード対応

✓両ファイルシステムを Enhanced モードタスクの転送元または転送先ロケーションとして指定可能
✓オンプレミスのファイルサーバーから FSx for Windows File Server への移行など、Windows 間のデータ移行に対応
✓Enhanced モードは Basic モードと同等のロケーションオプションを提供 (S3 on Outposts を除く)

🤖 Red Hat OpenShift Virtualization へのエージェントデプロイ対応

✓Enhanced モードのエージェントを OpenShift Virtualization バージョン 4.20 以降にデプロイ可能
✓既存の VMware ESXi、KVM、Microsoft Hyper-V、Amazon EC2 に加わる新しい選択肢
✓OpenShift ベースの仮想化基盤に標準化している企業でも、追加の仮想化環境なしでエージェントを運用可能

🚀 Enhanced モードの特長

✓データの一覧取得・準備・転送・検証を並列実行し、Basic モードより高いパフォーマンスを実現
✓タスク実行あたりのファイル数・オブジェクト数が実質無制限
✓転送元で検出したオブジェクト数など、Basic モードより詳細な転送メトリクスとカウンターを提供
✓JSON 形式の構造化ログを出力

ステップ 1: 転送元ロケーションの作成

Bash オンプレミス SMB ファイルサーバーのロケーションを作成 
aws datasync create-location-smb \
  --server-hostname "fileserver.example.com" \
  --user "transfer-user" \
  --domain "EXAMPLE" \
  --password "password" \
  --subdirectory "/share" \
  --agent-arns "arn:aws:datasync:ap-northeast-1:123456789012:agent/agent-0123456789abcdef0"

エージェント ARN には Enhanced モード対応エージェントを指定します。

ステップ 2: 転送先ロケーションの作成

Bash FSx for Windows File Server のロケーションを作成 
aws datasync create-location-fsx-windows \
  --fsx-filesystem-arn "arn:aws:fsx:ap-northeast-1:123456789012:file-system/fs-0123456789abcdef0" \
  --security-group-arns "arn:aws:ec2:ap-northeast-1:123456789012:security-group/sg-0123456789abcdef0" \
  --user "transfer-user" \
  --domain "EXAMPLE" \
  --password "password"

ファイルシステムへのアクセスを許可するセキュリティグループと認証情報を指定します。

ステップ 3: Enhanced モードでタスクを作成

Bash Enhanced モードタスクの作成 
aws datasync create-task \
  --source-location-arn "arn:aws:datasync:ap-northeast-1:123456789012:location/loc-source" \
  --destination-location-arn "arn:aws:datasync:ap-northeast-1:123456789012:location/loc-dest" \
  --name "windows-migration-task" \
  --task-mode "ENHANCED" \
  --options TransferMode=CHANGED,VerifyMode=ONLY_FILES_TRANSFERRED,LogLevel=TRANSFER

--task-mode "ENHANCED" を指定して Enhanced モードのタスクを作成します。タスク作成後にタスクモードを変更することはできないため、作成時に適切なモードを選択してください。コンソールの場合は、タスク作成画面の [Task mode] で [Enhanced] を選択します。

💡 メリットと制約事項

📈 ビジネス面のメリット

✓移行プロジェクトの短縮: 並列処理により大規模な Windows ファイルサーバー移行の所要時間を短縮
✓既存基盤への投資保護: OpenShift Virtualization を標準基盤とする企業は、エージェント用の別の仮想化環境が不要
✓運用の可視性向上: 詳細な転送メトリクスで移行や同期の進捗を正確に報告可能

⚙️ 技術面のメリット

✓スケーラビリティ: ファイル数が実質無制限となり、タスクの分割設計が不要
✓モード選択の一貫性: ロケーションの種類を理由に Basic モードへフォールバックする必要がほぼ解消
✓監視性の向上: 構造化ログ (JSON 形式) と詳細なカウンターで CloudWatch での監視・分析が容易

🚫 制限事項

✗S3 on Outposts を使用する転送は引き続き Enhanced モードに非対応 (Basic モードが必要)
✗OpenShift Virtualization へのエージェントデプロイはバージョン 4.20 以降が必要
✗タスク作成後にタスクモード (Enhanced / Basic) を変更することはできない

⚠️ 考慮すべき点

⚠️Enhanced モードタスクの作成には iam:CreateServiceLinkedRole 権限が必要
⚠️Enhanced モードはデフォルトで転送されたデータのみを検証するため、検証要件に応じた設定確認が必要
⚠️Enhanced モードと Basic モードでは料金体系が異なる場合があるため、料金ページで事前確認を推奨

🎯 ユースケース

1️⃣ オンプレミス Windows ファイルサーバーから FSx for Windows File Server への移行

シナリオ: 数千万ファイル規模のオンプレミス Windows ファイルサーバーを FSx for Windows File Server へ移行する。Basic モードのファイル数クォータを超えるため、従来はデータセットの分割が必要だった。

  1. オンプレミス環境に Enhanced モード対応エージェントをデプロイ
  2. SMB ロケーション (転送元) と FSx for Windows File Server ロケーション (転送先) を作成
  3. Enhanced モードでタスクを作成し、TransferMode=CHANGED で増分同期を実行
  4. カットオーバー前に最終同期を実行して切り替え
💪 効果: タスク分割なしで大規模移行を実行でき、並列処理により移行時間を大幅に短縮できる。

2️⃣ OpenShift Virtualization 基盤からのデータ転送

シナリオ: 仮想化基盤を Red Hat OpenShift Virtualization に標準化している企業が、オンプレミスの NAS データを AWS へ移行したい。エージェント用に VMware や Hyper-V 環境を別途維持したくない。

  1. OpenShift Virtualization バージョン 4.20 以降に Enhanced モードエージェントをデプロイ
  2. エージェントを DataSync にアクティベート
  3. オンプレミス NFS / SMB ロケーションと AWS 側ロケーションを作成し、Enhanced モードタスクを実行
💪 効果: 既存の OpenShift 基盤のみでエージェントを運用でき、追加の仮想化環境の構築・維持コストが不要になる。

3️⃣ FSx for NetApp ONTAP への大規模データ同期

シナリオ: オンプレミスの NetApp ストレージから FSx for NetApp ONTAP へ継続的にデータを同期し、ハイブリッド構成やディザスタリカバリに活用する。

  1. FSx for NetApp ONTAP ロケーションを転送先として作成
  2. Enhanced モードタスクを作成し、スケジュール実行を設定
  3. 詳細メトリクスと構造化ログを CloudWatch で監視
💪 効果: 並列処理による高速な同期と詳細なメトリクスにより、RPO の短縮と運用の可視化を両立できる。

💰 料金と利用可能リージョン

💵 料金

DataSync の料金は、転送したデータ量に基づく従量課金です。Enhanced モードと Basic モードでは料金体系が異なる場合があるため、最新の料金は DataSync 料金ページを参照してください。

FSx for Windows File Server、FSx for NetApp ONTAP のストレージ料金、およびデータ転送に伴うネットワーク料金は別途発生します。

🌍 利用可能リージョン

本機能は、DataSync Enhanced モードがサポートされているすべての AWS リージョンで利用可能です。

📝 まとめ

今回のアップデートにより、AWS DataSync Enhanced モードは FSx for Windows File Server と FSx for NetApp ONTAP に対応し、Basic モードと同等のロケーションオプションを実現しました。あわせて Red Hat OpenShift Virtualization へのエージェントデプロイも可能になり、オンプレミス環境の選択肢が広がっています。

大規模な Windows ファイルサーバー移行や NetApp ストレージの同期を計画している場合は、ファイル数無制限かつ高性能な Enhanced モードの採用を検討することを推奨します。
