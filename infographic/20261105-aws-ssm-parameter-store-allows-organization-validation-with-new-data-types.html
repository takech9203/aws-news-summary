AWS Systems Manager Parameter Store

🗄️ Parameter Store が組み込みデータ型による
値の検証と整理をサポート

📅 リリース日: 2026 年 11 月 5 日 | 13 種類の組み込みデータ型で保存時にパラメータ値を自動検証

📋 概要

Parameter Store に、パラメータ値を作成時・更新時に自動検証する 13 種類の組み込みデータ型が追加されました。 integer や boolean などの基本型から、ipv4-address、email、aws:account:id のような形式固有の型、json / jsonc の構造化データ型までをサポート。 データ型に一致しない値は PutParameter の時点で拒否されるため、不正な IP アドレスや壊れた JSON がアプリケーションに読み込まれる前に検出でき、独自の検証コードが不要になります。

データ型は String と SecureString で利用でき、一部の型は StringList にも対応してリスト内の各項目を個別に検証します。AllowedPattern との併用や、既存の text パラメータの型変更も可能です。さらに DescribeParameters API とコンソールでデータ型によるフィルタリングができ、パラメータの整理にも活用できます。

❌ Before: アップデート前の課題
  • データ型は text (検証なし)、aws:ec2:image、aws:ssm:integration のみで、一般的な設定値の形式検証ができなかった
  • 不正な IP アドレスや JSON もそのまま保存され、アプリが読み込むまで誤りに気づけなかった
  • AllowedPattern で正規表現を自作するか、アプリ側に独自の検証コードが必要だった
✅ After: アップデート後の改善
  • 13 種類の組み込みデータ型により、PutParameter の時点で値の形式を自動検証し、不正な値は保存前に拒否
  • IP アドレス、メールアドレス、JSON などの一般的な形式で、正規表現や独自検証コードが不要に
  • DescribeParameters API とコンソールでデータ型によるフィルタリングが可能になり、整理・分類が容易に

⚙️ 主要機能

1️⃣ 13 種類の組み込みデータ型の追加

標準・アドバンスドパラメータ共通の 10 種類と、アドバンスドパラメータ専用の 3 種類が追加されました。デフォルトは従来どおり text (検証なし) で、既存パラメータへの影響はありません。

aws:region aws:account:id boolean integer float binary hostname email ipv4-address ipv6-address url json jsonc

🔵 青 = 標準 / アドバンスド共通 (10 種類)、🟣 紫 = アドバンスド専用 (3 種類)

2️⃣ PutParameter 時の同期検証

データ型に一致しない値は PutParameter 操作の時点で拒否されます。String と SecureString の両方で利用可能。一部のデータ型 (aws:account:id、email、ipv4-address、ipv6-address) は StringList にも対応し、リスト内の各項目を個別に検証します (1 項目でも不正なら要求全体が失敗)。

3️⃣ AllowedPattern との併用と既存パラメータの型変更

AllowedPattern 制約と組み合わせると、データ型検証とパターンマッチングの両方を満たす必要があり、より厳密な制約を定義できます。既存の text パラメータのデータ型を integer などに変更することも可能です (aws:ec2:image と aws:ssm:integration への変更・からの変更は不可)。

4️⃣ データ型によるフィルタリング

DescribeParameters API およびコンソールで、データ型を条件にパラメータを検索・一覧化できます。パラメータの整理・分類・棚卸しに活用できます。

🔍 検証の動作仕様

項目詳細
検証タイミングPutParameter 操作時に同期検証 (aws:ec2:image のみ従来どおり非同期)
不一致時の動作要求が失敗し、値は保存されない
StringList の検証リスト内の各項目を個別に検証。1 項目でも不正なら要求全体が失敗
値の取得GetParameter などの取得系 API は、データ型に関係なく常に文字列として値を返す (例: integer の 443 は文字列 "443")
AllowedPattern との併用可能。両方の条件を満たす必要がある
既存パラメータの型変更可能 (例: text → integer)。標準パラメータをアドバンスド専用型に変更する場合はアドバンスドティアへの変更も必要
Intelligent-Tieringアドバンスド専用型を指定した場合、自動的にアドバンスドパラメータとして作成・昇格される

🛠️ 設定方法

✅ 前提条件

✓Parameter Store へのアクセス権限 (ssm:PutParameter、ssm:GetParameter、ssm:DescribeParameters など) があること
✓url、json、jsonc を使用する場合は、アドバンスドパラメータ (または Intelligent-Tiering) を利用できること
✓AWS CLI または AWS マネジメントコンソールが利用できること

ステップ 1: データ型を指定してパラメータを作成

Bash integer 型のパラメータを作成 
aws ssm put-parameter \
    --name "/myapp/config/port" \
    --value "443" \
    --type String \
    --data-type "integer"

--data-type オプションでデータ型を指定して String パラメータを作成します。値 443 は integer の検証を通過して保存されます。--value "abc" のように型に一致しない値を指定すると、コマンドはエラーで失敗します。

ステップ 2: 既存パラメータのデータ型を変更

Bash StringList を ipv4-address 型に変更 
aws ssm put-parameter \
    --name "/myapp/config/allowed-ips" \
    --value "192.0.2.1,192.0.2.2" \
    --type StringList \
    --data-type "ipv4-address" \
    --overwrite

既存のパラメータを --overwrite で更新し、データ型を ipv4-address に変更します。StringList の場合はカンマ区切りの各項目が個別に検証されます。

ステップ 3: データ型でパラメータをフィルタリング

Bash integer 型のパラメータを一覧化 
aws ssm describe-parameters \
    --parameter-filters "Key=DataType,Values=integer"

DescribeParameters API のパラメータフィルターでデータ型を条件に指定し、integer 型のパラメータの一覧を取得します。コンソールでも同様のフィルタリングが可能です。

💡 メリット

💼 ビジネス面

✓設定ミスによる障害の予防: 不正な設定値が保存前に拒否されるため、誤設定がアプリケーションに波及して障害につながるリスクを低減
✓開発・運用コストの削減: 一般的な形式の検証コードを自前で実装・保守する必要がなくなり、本来の開発に集中できる
✓ガバナンスの向上: データ型によるフィルタリングで、組織内のパラメータの分類・棚卸し・監査がしやすくなる

🔧 技術面

✓保存時点での早期検証: PutParameter の同期検証により、CI/CD パイプラインや IaC の適用時点で設定ミスを検出できる
✓AllowedPattern との組み合わせ: データ型検証に加えて正規表現による追加制約を定義でき、柔軟かつ厳密なバリデーションを実現
✓段階的な導入が可能: 既存の text パラメータの型を後から変更できるため、重要なパラメータから順次検証を適用できる

⚠️ デメリット・制約事項

🚧 制限事項

✗url、json、jsonc はアドバンスドパラメータ専用であり、標準パラメータでは利用できない
✗aws:ec2:image と aws:ssm:integration は他のデータ型との相互変更ができない
✗aws:account:id は 12 桁の形式のみを検証し、アカウントが実在するかは確認しない
✗StringList に対応するのは一部のデータ型 (aws:account:id、email、ipv4-address、ipv6-address など) に限られる
✗取得系 API は常に文字列を返すため、アプリケーション側での型変換は引き続き必要

🤔 考慮すべき点

⚠既存パラメータに型を適用する際、現在の値が検証に通らない場合は更新が失敗するため、事前に値の形式を確認する必要がある
⚠integer は先頭ゼロや + 記号を許可しない、ipv4-address は CIDR を許可しないなど、検証ルールが厳密なため既存の値の表記との互換性に注意
⚠jsonc のコメントは記述されたまま保存・返却されるため、読み取り側で JSONC 対応パーサーを使用する必要がある
⚠標準パラメータをアドバンスド専用型に変更する場合、アドバンスドティアへの昇格が必要で料金が発生する

🎯 ユースケース

1. アプリケーション設定値の型安全な管理

シナリオ: マイクロサービスのポート番号、機能フラグ、タイムアウト値などを Parameter Store で管理しており、デプロイ時の設定ミスによる起動失敗を防ぎたい。

Bash integer / boolean / float の適用例 
aws ssm put-parameter --name "/svc/api/port" --value "8080" \
    --type String --data-type "integer"
aws ssm put-parameter --name "/svc/api/feature-x-enabled" --value "true" \
    --type String --data-type "boolean"
aws ssm put-parameter --name "/svc/api/timeout-seconds" --value "30.5" \
    --type String --data-type "float"
✅ 効果: 数値や真偽値の形式が保存時に保証されるため、アプリケーション起動時のパースエラーや予期しない動作を未然に防止できる。
2. ネットワーク設定の検証付き一元管理

シナリオ: 複数環境の許可 IP リスト、接続先ホスト名、エンドポイント URL を Parameter Store で一元管理し、不正な形式の値の混入を防ぎたい。

Bash ipv4-address / url の適用例 
aws ssm put-parameter --name "/network/allow-list" \
    --value "192.0.2.1,198.51.100.7" \
    --type StringList --data-type "ipv4-address"
aws ssm put-parameter --name "/network/api-endpoint" \
    --value "https://api.example.com" \
    --type String --tier Advanced --data-type "url"
✅ 効果: IP アドレスのタイプミスや CIDR 表記の誤混入が保存時に拒否され、ネットワーク設定の信頼性が向上する。StringList ではリスト内の全項目が個別に検証される。
3. JSON 設定ドキュメントの構文保証

シナリオ: アプリケーションの複合的な設定を JSON ドキュメントとして SecureString のアドバンスドパラメータに保存しており、壊れた JSON のデプロイを防ぎたい。コメント付きで管理したい設定もある。

Bash json / jsonc の適用例 
aws ssm put-parameter --name "/myapp/config/settings" \
    --value '{"port": 443, "retries": 3}' \
    --type SecureString --tier Advanced --data-type "json"
aws ssm put-parameter --name "/myapp/config/settings-annotated" \
    --value '{"port": 443 /* HTTPS */}' \
    --type SecureString --tier Advanced --data-type "jsonc"
✅ 効果: 構文エラーのある JSON や重複キーを含む値が保存前に拒否され、アプリケーションが設定の読み込みに失敗するリスクを排除できる。jsonc を使えばコメント付きの設定も管理できる。

💰 料金と利用可能リージョン

💵 料金

データ型の指定自体に追加料金はありません。標準パラメータで利用できる 10 種類のデータ型は、標準パラメータの既存の料金 (無料) の範囲で利用できます。

url、json、jsonc のデータ型を使用するパラメータはアドバンスドパラメータとなり、既存のアドバンスドパラメータ料金が適用されます。詳細は AWS Systems Manager 料金ページを参照してください。

🌍 利用可能リージョン

AWS Systems Manager が提供されているすべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

→AWS Systems Manager Parameter Store: 本アップデートの対象機能。設定データとシークレットを階層的に一元管理するサービス
→Parameter Store アドバンスドパラメータ: url、json、jsonc データ型の利用に必要。8 KB までの値やパラメータポリシーもサポート
→AWS Lambda / Amazon ECS: Parameter Store から設定値を読み込む代表的なコンシューマー。保存時検証により、不正な設定値を読み込むリスクを低減
→AWS CloudFormation / AWS CDK: IaC でパラメータを管理する場合、デプロイ時点でデータ型検証が機能し、設定ミスを早期に検出できる

📝 まとめ

このアップデートにより、Parameter Store は 13 種類の組み込みデータ型でパラメータ値を保存時に自動検証できるようになり、誤った設定値がアプリケーションに到達する前に検出できるようになりました。 独自の検証コードや複雑な AllowedPattern で形式チェックを行っていた場合は、組み込みデータ型への置き換えを検討する価値があります。 まずはポート番号や IP アドレスなど、形式が明確で影響の大きいパラメータから段階的に適用することを推奨します。
