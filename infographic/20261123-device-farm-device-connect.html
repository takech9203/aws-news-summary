☁️ AWS Device Farm

🔌 Device Connect でリモート Android 実機にローカルアクセス

📅 リリース日: 2026 年 11 月 23 日 | 機能: Device Connect for AWS Device Farm

📝 概要

AWS Device Farm は、クラウド上のリモート Android デバイスに対して、ローカルマシンから直接アクセスできる新機能 Device Connect を発表しました。開発者や AI エージェントは、IDE やターミナルなどの使い慣れた開発環境から、 あたかもラップトップに USB 接続されているかのように Device Farm 上の実機デバイスを操作できます。

Device Connect は devicefarm-connect という CLI クライアントとして提供され、ローカルの adb (Android Debug Bridge) サーバーの代わりとなる「ブリッジ」プロセスを起動します。Android Studio、シェルスクリプト、CI ジョブなど、 ローカル adb を前提としたツールやテストフレームワークが 変更なしでそのまま Device Farm の実機に対して動作します。

❌ Before: アップデート前の課題

  • リモートアクセスセッションでの操作は Web ブラウザー経由の手動操作に限定
  • 自動テストは API 経由で実行する必要があり、Android Studio やターミナルから直接操作できなかった
  • adb 前提の既存ツールチェーンをクラウド実機に利用できなかった

✅ After: アップデート後の改善

  • ローカルの adb ベースのワークフローが変更なしでそのまま実機に対して動作
  • Android Studio からのデバッガーアタッチ、プロファイリング、アプリのインストールと実行が可能
  • AI エージェントがローカル開発環境からリモート実機を操作するワークフローを構築可能

Device Connect ブリッジはローカル adb サーバーのデフォルトアドレス 127.0.0.1:5037 で待ち受け、 adb クライアントからのリクエストを暗号化 WebSocket 経由で Device Farm 上のリモート adb サーバーへ中継します。

⚡ 主要機能

🔄 ローカル adb ツールとの透過的な統合

  • ブリッジがポート 5037 で動作するため、adb や Android Studio は設定変更なしでリモートデバイスを認識
  • adb install、adb push、adb pull、adb shell、adb logcat、adb forward など USB 接続デバイスと同様の操作が可能
  • Espresso テストなどの計装テストもローカルから直接実行できる

🔐 セッションの自動維持と資格情報管理

  • 起動したシェルの AWS 認証情報を使用してエンドポイントを取得し、数分ごとに自動更新
  • アイドル接続を 1 本維持し、コマンド間でセッションがタイムアウトしないよう保つ
  • 認証情報を保存せず、テレメトリーも送信せず、管理者権限なしで動作

🩺 診断とトラブルシューティング

  • devicefarm-connect doctor コマンドで接続の問題を診断
  • ライブ映像、デバイスログ、テストログを確認しながら操作可能
  • ブリッジはターミナルを閉じても動作を継続し、devicefarm-connect bridge stop で明示的に停止

動作要件

項目詳細

ステップ 1: Device Connect クライアントのインストール

Bash インストール (macOS / Linux) 
# macOS / Linux の場合
curl -fsSL https://raw.githubusercontent.com/aws/device-connect-devicefarm/main/install.sh | sh

# インストール確認
devicefarm-connect --version

インストールスクリプトが devicefarm-connect バイナリを ~/.local/bin に配置します。sudo や管理者権限は不要です。Windows では PowerShell 用のインストールスクリプトを使用します。

ステップ 2: リモートアクセスセッションの作成

Bash セッション作成 
aws devicefarm create-remote-access-session \
  --project-arn "$PROJECT_ARN" \
  --device-arn "$DEVICE_ARN" \
  --region us-west-2

Android 9 以降のパブリックデバイスを確保し、出力に含まれるセッション ARN を控えておきます。コンソールからの作成も可能です。

ステップ 3: デバイスのアタッチと adb 操作

Bash デバイスアタッチ 
# セッションのデバイスをローカルにアタッチ (ブリッジが自動起動)
devicefarm-connect device add --session-arn "$SESSION_ARN"

# 通常の adb コマンドがそのまま利用可能
adb devices
adb install app-debug.apk
adb shell am instrument -w com.example.test/androidx.test.runner.AndroidJUnitRunner

device add コマンドがブリッジを起動し、リモートデバイスをローカルの adb に認識させます。以降は USB 接続デバイスと同様に操作できます。

ステップ 4: クリーンアップ

Bash クリーンアップ 
# ブリッジの停止
devicefarm-connect bridge stop

# リモートアクセスセッションの停止 (課金の停止)
aws devicefarm stop-remote-access-session --arn "$SESSION_ARN" --region us-west-2

⚠️ ブリッジを停止してもリモートアクセスセッション自体は Device Farm 側で継続し、課金も続くため、必ずセッションの停止も実行します。

⚖️ メリットと制約事項

👍 ビジネス面のメリット

✓実機確保コストの削減: 多様な Android 実機を購入・管理せず、必要なときだけ従量課金で利用
✓開発サイクルの短縮: 普段の開発環境から直接デバッグ・検証でき、問題の特定と修正が高速化
✓既存資産の活用: adb 前提のテストスクリプトや CI ジョブを変更なしで適用

🛠️ 技術面のメリット

✓透過的な adb 互換: Android Studio を含むツール群が無設定で動作
✓セキュアな通信: 暗号化 WebSocket を使用し、エンドポイントは自動更新。認証情報は保存しない
✓AI エージェントとの親和性: ターミナル操作により実機テストの自動化ワークフローに組み込みやすい

⚠️ 制限事項

✗対応リージョンは米国西部 (オレゴン) のみ
✗Android 9 以降のパブリックデバイスのみ、課金方式は従量課金 (metered) に限定
✗セッション最大 150 分、同時アタッチは 1 台のみ
✗adb reboot など破壊的なコマンドはブロック
✗adb reverse はデフォルト無効 (--allow-adb-reverse が必要)
✗ポートフォワード・リバースは TCP ポートのみ対応
✗Android Studio のデバイスミラーリング機能は利用不可

🤔 考慮すべき点

⚠️ブリッジは adb クライアントを認証しないため、ローカルマシン上の任意のプログラムがデバイスを利用可能
⚠️ブリッジ停止後もセッションは終了せず課金が継続するため、明示的な停止が必要
⚠️ローカルとリモートの adb バージョンの一致 (1.0.41) が必要

💡 ユースケース

🐛 ユースケース 1: Android Studio からの実機デバッグ

シナリオ: 特定の実機でのみ発生する不具合を、手元にデバイスがない状態でデバッグしたい。

Bash実装例
devicefarm-connect device add --session-arn "$SESSION_ARN"
# この後 Android Studio を起動すると、リモート実機がデバイスリストに表示される
# ブレークポイントの設定、デバッガーアタッチ、プロファイリングが可能

✅ 効果: 問題が発生する実機モデルに対して、普段のデバッグワークフローをそのまま適用でき、原因特定までの時間を短縮できる。

🔁 ユースケース 2: CI パイプラインからの実機テスト

シナリオ: CI ジョブで、ビルドしたアプリの計装テストをエミュレーターではなく実機で実行したい。

Bash実装例
SESSION_ARN=$(aws devicefarm create-remote-access-session \
  --project-arn "$PROJECT_ARN" --device-arn "$DEVICE_ARN" \
  --region us-west-2 --query 'remoteAccessSession.arn' --output text)
devicefarm-connect device add --session-arn "$SESSION_ARN"
adb install app-debug.apk
adb shell am instrument -w com.example.test/androidx.test.runner.AndroidJUnitRunner
devicefarm-connect bridge stop
aws devicefarm stop-remote-access-session --arn "$SESSION_ARN" --region us-west-2

✅ 効果: 既存の adb ベースのテストスクリプトを変更せずに実機テストへ移行でき、エミュレーターでは検出できない実機固有の問題を早期に発見できる。

🤖 ユースケース 3: AI エージェントによる実機操作の自動化

シナリオ: AI コーディングエージェントに、実装した機能を実機で動作確認させたい。

Bash実装例
# エージェントの実行環境でブリッジを起動しておく
devicefarm-connect device add --session-arn "$SESSION_ARN"
# エージェントは通常の adb コマンドでアプリのインストール・起動・ログ確認を実行
adb install app-debug.apk
adb shell am start -n com.example/.MainActivity
adb logcat -d | grep "com.example"

✅ 効果: エージェントがターミナル経由で実機を操作できるため、コード生成から実機検証までを一貫して自動化できる。

🔗 関連サービス・機能

📡 AWS Device Farm リモートアクセスセッション

Device Connect の基盤となる機能。従来はブラウザー経由の操作のみだったが、本機能でローカル adb からの操作が可能になった。

🧪 AWS Device Farm 自動テスト

API 経由でテストスイートを一括実行する既存機能。Device Connect は対話的な開発・デバッグ用途を補完する。

⌨️ Android Debug Bridge (adb)

Android 開発の標準ツール。Device Connect は adb のクライアント・サーバーモデルにおけるサーバーの役割をブリッジとして代替する。

🎯 まとめ

Device Connect は、クラウド上の Android 実機をローカルの adb ツールチェーンから透過的に扱えるようにする、 Device Farm の大きな機能拡張です。既存の adb ベースのワークフローが変更なしで動作するため、実機デバッグや CI での実機テスト、 AI エージェントによる実機検証の導入障壁が大きく下がります。 Android アプリ開発で実機検証に課題を抱えているチームは、無料トライアル枠を活用して devicefarm-connect クライアントを試すことを推奨します。
