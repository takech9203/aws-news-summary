Amazon EC2

💿 AMI への互換インスタンスタイプ指定のサポート

📅 リリース日: 2026 年 9 月 4 日 | 機能: AMI 許可インスタンスタイプ (InstanceTypeSpecification)

📌 概要

Amazon EC2 が、AMI 所有者による互換インスタンスタイプの定義をサポートしました。 AMI がサポートするインスタンスタイプ (SupportedInstanceTypes)、サポートしないインスタンスタイプ (UnsupportedInstanceTypes)、またはその両方を AMI の属性として指定でき、 許可されていないインスタンスタイプでの起動リクエストは EC2 が起動時に自動的にブロックします。

GPU ドライバーを含む AMI を GPU インスタンスタイプのみに制限するなど、非互換な組み合わせによる起動失敗を未然に防止できます。 組織内で AMI を共有するプラットフォームチームや、AMI を配布する ISV / ソフトウェアベンダーに特に有用です。

起動時に強制
非互換タイプはハードブロックされ即時エラー
オプトイン方式
未設定の AMI は従来どおり全タイプで起動可能

すべての AWS リージョンで利用可能
❌ アップデート前の課題
✗互換インスタンスタイプを技術的に強制する手段がなく、README やドキュメントでの周知に依存
✗非互換タイプの選択 (例: GPU ドライバー前提 AMI を GPU 非搭載で起動) が起動後の障害として顕在化し、原因特定に時間を要した
✗共有 AMI やゴールデン AMI に、想定外のタイプでの利用を防ぐガードレールを持たせられなかった
✅ アップデート後の改善
✓InstanceTypeSpecification 属性で対象/対象外を宣言でき、EC2 が起動時に強制 (ハードブロック)
✓ワイルドカード (t3.*、*.12xlarge) でパターン指定でき、個別列挙が不要
✓不許可タイプは InvalidParameterCombination エラーで即座に失敗し、起動前に不一致を検出
✓CopyImage によるコピー時にも指定が引き継がれ、一貫したガードレールを維持

AMI 所有者が InstanceTypeSpecification を設定すると、EC2 は起動時に指定インスタンスタイプの互換性を評価し、許可されていない組み合わせの起動をブロックします。

⚙️ 主要機能

1️⃣ InstanceTypeSpecification 属性による互換性の宣言

AMI に SupportedInstanceTypes (サポート対象) と UnsupportedInstanceTypes (サポート対象外) の 2 つのリストを設定可能。片方のみ、または両方の組み合わせで柔軟に許可範囲を制御できる。

2️⃣ ワイルドカードによるパターン指定

t3.* のようにファミリー単位、*.12xlarge のようにサイズ単位での指定が可能で、多数のインスタンスタイプを個別に列挙する手間を削減できる。

3️⃣ 起動時の自動エンフォース

RunInstances などによる起動時に EC2 が互換性をチェック。不許可タイプはハードブロックされ InvalidParameterCombination エラーが返る。制限は新規起動にのみ適用され、稼働中インスタンスには影響しない。

4️⃣ デフォルト動作の維持 (オプトイン方式)

未設定の AMI は従来どおりすべてのインスタンスタイプで起動可能。制限を明示的に適用するまで既存ワークフローに影響なし。

5️⃣ AMI コピー時の指定の引き継ぎ

CopyImage で AMI をコピーすると、コピー先の AMI にもインスタンスタイプ指定が保持される。

📐 評価ロジック

InstanceTypeSpecification の設定状態起動可能なインスタンスタイプ
未設定 (デフォルト)すべてのインスタンスタイプ

🛠️ 設定方法

✅ 前提条件

  • ✓対象 AMI の所有者であること (AMI 所有者のみが指定を設定・変更できる)
  • ✓AWS CLI を使用する場合は、本機能に対応した最新バージョンへ更新済みであること
  • ✓共有 AMI に設定する場合、利用者側の起動テンプレートや Auto Scaling グループで使用中のインスタンスタイプを事前に把握していること
1
サポート対象/対象外インスタンスタイプの設定
BashInstanceTypeSpecification の設定
aws ec2 replace-image-instance-type-specification \
    --image-id ami-1234567890abcdef0 \
    --instance-type-specification '{"SupportedInstanceTypes": ["t3.*", "a2.*"], "UnsupportedInstanceTypes": ["t3.micro"]}'

t3 ファミリーと a2 ファミリーの全サイズを許可しつつ、t3.micro のみを除外する例。コンソールでは EC2 コンソールの [AMIs] で対象 AMI を選択し、[Actions] から [Manage instance type specification] を選択して設定します。

2
設定内容の確認
BashDescribeImages で確認
aws ec2 describe-images \
    --image-ids ami-1234567890abcdef0

レスポンスの InstanceTypeSpecification フィールドに設定が反映されていることを確認します。コンソールでは AMI の [Details] タブから確認できます。

3
起動ブロック動作の確認
Bash不許可タイプでの起動テスト
aws ec2 run-instances \
    --image-id ami-1234567890abcdef0 \
    --instance-type t3.micro
Text返されるエラー
An error occurred (InvalidParameterCombination) when calling the RunInstances operation:
This AMI does not support the specified instance type.
Check DescribeImages for InstanceTypeSpecification, and try again.

許可されていないインスタンスタイプ (t3.micro) での起動を試行すると、EC2 はエラーを返して起動をブロックします。

4
指定の解除 (必要な場合)
Bash指定の削除
aws ec2 replace-image-instance-type-specification \
    --image-id ami-1234567890abcdef0

--instance-type-specification を指定せずに実行すると指定が削除され、すべてのインスタンスタイプでの起動を許可するデフォルト動作に戻ります。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓トラブルの未然防止: 非互換な組み合わせが起動前にブロックされ、障害調査やサポート対応の工数を削減
✓AMI 配布者の品質保証: 検証済みインスタンスタイプのみで利用させるガードレールを提供し、サポート範囲を明確化
✓追加コストなし: すべてのリージョンで追加料金なし、既存の AMI 運用にそのまま組み込める

🔧 技術面のメリット

✓起動時の強制力: EC2 コントロールプレーンがハードブロックとして強制し、ヒューマンエラーを確実に防止
✓ワイルドカードによる保守性: パターン指定により、新サイズ追加時の更新負荷を抑制
✓後方互換性: オプトイン方式のため既存ワークフローへ影響なく段階導入が可能
✓コピー時の一貫性: リージョン間コピーでもガードレールが維持される

🚧 制限事項

✗指定を設定・変更できるのは AMI 所有者のみ
✗ReplaceImageInstanceTypeSpecification は指定全体を置き換える操作。個別追加・削除時も更新後の完全な指定が必要
✗制限は新規起動にのみ適用。既存の稼働中インスタンスの停止・起動を強制する機能ではない

⚠️ 考慮すべき点

⚠共有 AMI に設定すると、既存の起動テンプレートや Auto Scaling グループが起動失敗する可能性あり。設定前に利用側の互換性確認を推奨
⚠SupportedInstanceTypes のみで運用すると、将来の新インスタンスタイプはデフォルトでブロックされ、採用時に指定の更新が必要
⚠自動化パイプラインでは InvalidParameterCombination をハンドリングし、DescribeImages で許可タイプを確認するフローの組み込みを推奨

💡 ユースケース

🎮 ユースケース 1: GPU ドライバー入り AMI を GPU インスタンスに限定

シナリオ: 機械学習チームが NVIDIA ドライバーと CUDA をプリインストールした AMI を組織内に共有。GPU 非搭載インスタンスで起動されるとドライバー初期化に失敗し、問い合わせが多発していた。

BashGPU ファミリーのみ許可
aws ec2 replace-image-instance-type-specification \
    --image-id ami-0123456789gpuami0 \
    --instance-type-specification '{"SupportedInstanceTypes": ["p4d.*", "p5.*", "g5.*", "g6.*"]}'

効果: GPU インスタンスファミリー以外での起動が自動的にブロックされ、非互換環境での起動に起因する障害と問い合わせが解消される。

🚫 ユースケース 2: 特定インスタンスファミリーとの非互換の明示

シナリオ: 特定のカーネルモジュールに依存する AMI が一部のインスタンスファミリーで動作しないことが判明。それ以外のタイプは自由に選択させたい。

Bash非互換タイプのみ除外
aws ec2 replace-image-instance-type-specification \
    --image-id ami-0abcdef012345678f \
    --instance-type-specification '{"UnsupportedInstanceTypes": ["t3.micro", "t3.nano"]}'

効果: 非互換と判明しているタイプのみをピンポイントで除外し、その他のタイプでは従来どおり自由に起動できる柔軟な制御を実現。

📦 ユースケース 3: 最小スペック要件を持つソフトウェア製品 AMI の配布

シナリオ: ISV がメモリ要件の大きい製品を AMI として顧客に配布。小さいサイズのインスタンスで起動されるとパフォーマンス問題が発生し、サポートコストが増大していた。

Bash対象ファミリー許可 + 最小サイズ除外
aws ec2 replace-image-instance-type-specification \
    --image-id ami-0fedcba9876543210 \
    --instance-type-specification '{"SupportedInstanceTypes": ["m6i.*", "m7i.*", "r6i.*", "r7i.*"], "UnsupportedInstanceTypes": ["m6i.large", "m7i.large"]}'

効果: サポート対象ファミリーを許可しつつ最小サイズを除外することで、検証済みスペックでのみ製品が起動され、サポート範囲外の構成に起因する問い合わせを削減。

💰 料金と利用可能リージョン

💵 料金

本機能の利用に追加料金はありません。EC2 インスタンスや AMI (基盤となる EBS スナップショットのストレージ) に対する標準料金がそのまま適用されます。

🌍 利用可能リージョン

すべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

📄 EC2 起動テンプレート

AMI とインスタンスタイプの組み合わせを定義する起動テンプレートは、AMI 側の指定と矛盾すると起動に失敗するため、指定設定時に整合性の確認が必要。

📈 Amazon EC2 Auto Scaling

Auto Scaling グループが参照する AMI に指定を設定する場合、グループに構成されたインスタンスタイプ (混合インスタンスポリシー含む) が許可されているか事前検証を推奨。

🏭 EC2 Image Builder

ゴールデン AMI のビルドパイプラインに指定の付与を組み込むことで、配布される AMI に一貫したガードレールを適用できる。

🏢 AMI の共有 / AWS Organizations

組織内・アカウント間で共有する AMI に指定を設定することで、利用者側の誤ったインスタンスタイプ選択を配布元で防止できる。

🎯 まとめ

AMI への互換インスタンスタイプ指定のサポートにより、AMI 所有者は非互換なインスタンスタイプでの起動を EC2 のコントロールプレーンで確実にブロックできるようになり、起動失敗や起動後の障害を未然に防止できます。 デフォルト動作は変わらないオプトイン方式かつ追加料金なしのため、GPU 依存 AMI や共有ゴールデン AMI を 運用しているチームは、利用側の起動テンプレートや Auto Scaling グループとの互換性を確認したうえで、本機能によるガードレールの導入を検討することを推奨します。
