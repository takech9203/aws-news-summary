Amazon SageMaker JumpStart

🧠 Meta Muse Spark Open モデルの提供開始

オープンウェイトのエージェンティックコーディングモデルを自社 AWS アカウント内に数クリックでデプロイ
📅 リリース日: 2026 年 10 月 15 日

📋 概要

Meta のオープンウェイトモデル Muse Spark Open が Amazon SageMaker JumpStart で利用可能になりました。 エージェンティックコーディングワークフロー向けに特化したコーディング最適化モデルであり、 マルチステップ推論とツール呼び出しの能力を AWS インフラストラクチャ上のエンタープライズソフトウェアエンジニアリングにもたらします。 エンドポイントはお客様自身の AWS アカウント内で実行されるため、ソースコードとプロンプトを完全に管理下に置くことができます。

❌ アップデート前の課題

✗大規模オープンウェイトモデルを AWS 上で使うには、モデル入手・推論環境構築・サービング設定を自前で行う必要があった
✗コンテキストウィンドウの制約により、大規模コードベースはタスクを小さく分割する必要があった
✗外部のマネージド API ではソースコードやプロンプトが自社アカウント外に送信される懸念があった

✅ アップデート後の改善

✓モデルカタログから数クリック、または SageMaker Python SDK でデプロイ可能に
✓1M トークンコンテキストで、プロジェクト全体 (依存関係、レガシーコード、数千のファイル) を分割せずに一括投入
✓エンドポイントが自社 AWS アカウント内で稼働し、コードとプロンプトを完全に自社管理下に
✓NVFP4 量子化版により BF16 比で約 4 分の 1 のメモリでコスト効率の高いデプロイが可能に

SageMaker JumpStart のモデルカタログから 2 つのバリアントのいずれかを選択してデプロイすると、お客様自身の AWS アカウント内にエンドポイントが作成され、プロジェクト全体を 1M トークンのコンテキストに取り込んだエージェンティックなコーディングワークフローを実行できます。

⚡ 主要機能

🤖 エージェンティックコーディングに特化した設計
長時間稼働するコーディングエージェントとマルチモーダルなエンジニアリングワークフロー向けに設計。マルチファイルのリファクタリングや長時間のデバッグセッションといった実際の開発者ワークフローで学習し、単発のツール呼び出しではなく、長いタスク期間にわたって計画・行動・観察・自己修正するエージェント動作を実現。
🧩 MoE アーキテクチャによる効率的な推論
総パラメータ数 816B、トークンあたりのアクティブパラメータ数 42B の Mixture-of-Experts 構成。超大規模ネットワークの能力を保ちながら、トークンあたりの計算量をはるかに小さい密モデルに近い水準に抑制。
📚 1M トークンのコンテキストウィンドウ
依存関係、レガシーコード、数千のファイルを含むプロジェクト全体を分割せずに取り込み可能。タスクを小さな断片に分割する前処理が不要。
🎨 マルチモーダル入力対応
入力はテキスト、画像、ドキュメント、音声、音声付き動画に対応。出力はテキスト。
🔀 2 つのデプロイバリアント
BF16 版と NVFP4 量子化版を提供。NVFP4 版は BF16 版の約 4 分の 1 のメモリで動作し、コスト効率の高いデプロイが可能。

🛠️ 設定方法

前提条件

  • AWS アカウントと Amazon SageMaker AI の利用環境 (SageMaker Studio など)
  • SageMaker JumpStart へのアクセス権限を持つ IAM ロール
  • モデルのデプロイに必要な GPU インスタンスのサービスクォータ
1
SageMaker JumpStart モデルカタログでモデルを検索
SageMaker コンソールからモデルカタログを開き、「Muse Spark Open」を検索。BF16 版と NVFP4 版の 2 つのバリアントから要件に合わせて選択します。
2
モデルをデプロイ
コンソールの場合は数クリックでデプロイできます。SageMaker Python SDK を使用する場合の例は以下のとおりです。
Python SageMaker Python SDK でのデプロイ 
from sagemaker.jumpstart.model import JumpStartModel

# JumpStart のモデル ID を指定してモデルオブジェクトを作成し、
# 自身の AWS アカウント内にエンドポイントをデプロイする
model = JumpStartModel(model_id="<Muse Spark Open のモデル ID>")
predictor = model.deploy()
実際のモデル ID とデフォルトのインスタンスタイプは、SageMaker JumpStart のモデルカタログで確認してください。
3
エンドポイントを呼び出して推論を実行
Python 推論リクエストの送信 
# デプロイしたエンドポイントに対して推論リクエストを送信する
response = predictor.predict({
    "inputs": "リポジトリ全体を解析し、非推奨 API の利用箇所をリファクタリングしてください。"
})
print(response)
エンドポイントはお客様のアカウント内で稼働するため、ソースコードとプロンプトは外部に送信されません。

💡 メリット

💼 ビジネス面

✓データ主権の確保: エンドポイントが自社 AWS アカウント内で稼働するため、ソースコードやプロンプトといった機密性の高い知的財産を自社の管理下に置ける
✓導入の迅速化: 数クリックまたは数行のコードでデプロイでき、大規模モデルのサービング環境構築にかかる時間と労力を削減
✓コスト最適化の選択肢: NVFP4 量子化版により、必要なメモリを約 4 分の 1 に抑えた低コストなデプロイを選択可能

⚙️ 技術面

✓プロジェクト全体の一括処理: 1M トークンコンテキストで数千ファイル規模のコードベースを分割せずに扱える
✓長時間のエージェント動作: 計画・実行・観察・自己修正のループを長いタスク期間にわたって継続
✓MoE による推論効率: 816B の総パラメータに対しトークンあたり 42B のみがアクティブで、能力と計算コストのバランスに優れる
✓マルチモーダル対応: 設計資料の画像やドキュメント、音声・動画を入力として扱える

⚠️ デメリット・制約事項

制限事項

✗出力はテキストのみで、画像や音声の生成には対応しない
✗816B 規模の MoE モデルのため、BF16 版のホスティングには大容量メモリを持つ GPU インスタンスが必要
✗利用可能リージョンは発表では明記されておらず、SageMaker JumpStart のモデルカタログでの確認が必要

考慮すべき点

⚠セルフホスト型のため、Amazon Bedrock のようなサーバーレス API と異なり、エンドポイントの稼働時間に応じたインスタンス料金が発生。利用パターンに応じてインスタンスタイプやオートスケーリングの設計が必要
⚠NVFP4 量子化版はメモリ効率に優れる一方、量子化による精度への影響は自社のユースケースで評価することを推奨
⚠必要な GPU インスタンスのサービスクォータを事前に確認し、不足している場合は引き上げ申請が必要

2️⃣ 長時間稼働するデバッグエージェント

シナリオ: 再現条件が複雑な障害の原因調査で、ログ解析、仮説立案、修正、テスト実行を繰り返す長時間のデバッグセッションを自動化。

  • SageMaker エンドポイントをエージェントフレームワークのバックエンド LLM として構成
  • テスト実行やログ取得をツールとしてエージェントに提供
  • モデルが結果を観察しながら自己修正を繰り返し、原因特定と修正案の提示まで実行
✅ 効果: 単発のツール呼び出しでは解決できない複雑な障害調査を、長いタスク期間にわたる自律的な試行錯誤で進められる。
3️⃣ 機密コードを扱うエンタープライズ開発での AI 活用

シナリオ: 規制業種の企業が、ソースコードを外部 API に送信できないポリシーのもとで AI コーディング支援を導入。

  • 自社 AWS アカウント内に Muse Spark Open をデプロイ
  • VPC 内から SageMaker エンドポイントを呼び出す構成とし、コードとプロンプトをアカウント外に出さない
  • コスト要件に応じて NVFP4 版を選択しメモリ使用量を約 1/4 に削減
✅ 効果: データ主権とコンプライアンス要件を満たしながら、最新のエージェンティックコーディングモデルを活用できる。

💰 料金・利用可能リージョン

💵 料金

Muse Spark Open 自体はオープンウェイトモデルであり、SageMaker JumpStart からのデプロイでは、エンドポイントで使用する SageMaker 推論インスタンスの稼働時間に基づく料金が発生します。具体的な料金はインスタンスタイプとリージョンによって異なります。

NVFP4 量子化版は BF16 版と比較して約 4 分の 1 のメモリで動作するため、より小規模なインスタンス構成によるコスト削減が期待できます。

🌍 利用可能リージョン

発表では利用可能リージョンは明記されていません。SageMaker JumpStart のモデルカタログで、利用したいリージョンでの提供状況を確認してください。

📚 Amazon SageMaker JumpStart

コードによるモデルのデプロイと推論呼び出しを行うための SDK。

📝 まとめ

Meta の Muse Spark Open が SageMaker JumpStart に追加されたことで、816B パラメータの MoE アーキテクチャと 1M トークンコンテキストを備えたエージェンティックコーディングモデルを、自社 AWS アカウント内で数クリックでデプロイできるようになりました。 ソースコードを外部に出せない企業でも、大規模コードベースのリファクタリングや長時間のデバッグ自動化に AI エージェントを活用できます。 まずは SageMaker JumpStart のモデルカタログで提供リージョンとバリアントを確認し、NVFP4 版での検証から始めることを推奨します。
