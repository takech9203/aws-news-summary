⚡ 主要機能

📈 ノードあたりの SCP アタッチ数の倍増

ルート、OU、アカウントの各ノードにアタッチ可能な SCP の最大数が 5 から 10 に増加。セキュリティチーム、コンプライアンスチーム、ネットワークチームなど、各チームが個別の SCP を管理する運用が可能になり、変更管理の複雑さが軽減。

📝 SCP ポリシーサイズの倍増

1 つの SCP に記述可能な最大文字数が 5,120 から 10,240 に増加。複数の条件キー (Condition) を組み合わせた高度なアクセス制御ルールを 1 つのポリシー内に記述可能。リソースパターンや Action の列挙が多い場合でも分割が不要に。

🔄 自動適用

すべての既存組織に自動的に適用。オプトインや設定変更は不要。すべての商用リージョン、GovCloud、中国リージョンで利用可能。

SCP の評価ロジック

SCP は継承ベースで評価される。ルートにアタッチされた SCP はすべての OU とアカウントに継承され、各レベルでアタッチされた SCP が追加で評価される。今回のクォータ引き上げにより、各レベルでより多くのポリシーを配置できるが、評価の仕組み自体に変更はない。

API 変更

今回のアップデートに関連する API の変更は確認されなかった。既存の Organizations API (AttachPolicy、CreatePolicy、UpdatePolicy など) はそのまま利用可能で、新しいクォータ値は自動的に反映される。

前提条件

ステップ 1: 現在の SCP 状況の確認

Bash 特定の OU にアタッチされている SCP を一覧表示 
# 特定の OU にアタッチされている SCP を一覧表示
aws organizations list-policies-for-target \
  --target-id ou-xxxx-xxxxxxxx \
  --filter SERVICE_CONTROL_POLICY

ステップ 2: 新しい SCP の作成

Bash 新しい SCP を作成 
# 新しい SCP を作成 (最大 10,240 文字)
aws organizations create-policy \
  --name "DenyUnencryptedStorage" \
  --description "Deny unencrypted storage operations" \
  --type SERVICE_CONTROL_POLICY \
  --content file://scp-deny-unencrypted.json

ステップ 3: SCP のアタッチ

Bash SCP を OU またはアカウントにアタッチ 
# SCP を OU またはアカウントにアタッチ (最大 10)
aws organizations attach-policy \
  --policy-id p-xxxxxxxxxx \
  --target-id ou-xxxx-xxxxxxxx

⚠️ デメリット・制約事項

制限事項

✗組織あたりの SCP 総数の上限は変更されていない (デフォルト 2,048)
✗SCP は許可を付与するものではなく、許可の境界を設定するものという原則は変わらない
✗SCP は管理アカウントには適用されない (従来通り)

考慮すべき点

⚠SCP 数の増加に伴い、ポリシー評価の複雑さが増す可能性がある
⚠多数の SCP をアタッチする場合、IAM Access Analyzer やポリシーシミュレーターでの検証を推奨
⚠SCP の継承チェーンが深くなるほど、トラブルシューティングが複雑に
