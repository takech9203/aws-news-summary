💰 AWS Cost Explorer
請求グループ内アカウントの過去データ保持

AWS Cost Explorer
📅 2026 年 6 月 15 日

📝 概要

請求グループ (Billing Group) に含まれるアカウントが、AWS Cost Explorer 上で元の請求対象料金 (billable rates) による過去請求データへのアクセスを保持できるようになりました。

お客様は AWS Billing Conductor と Billing Transfer を使用してアカウントを請求グループにマッピングし、支払いアカウントまたは Bill-Transfer アカウントが提供するプロフォーマ料金 (pro forma rates) で請求データを表示できます。今回のアップデートにより、これに加えて移行前後の過去データも参照できます。

すでに Billing Conductor および Billing Transfer をオンボーディング済みのアカウントは、追加の操作なしで過去データへアクセスでき、レポート作成の継続性が確保されます。

⚠️ アップデート前の課題
  • 請求グループへのマッピングで、AWS 請求対象料金で算出された過去請求データへのアクセスが制限されていた
  • Billing Transfer 移行後、Cost Explorer・Budgets・Cost Anomaly Detection で過去コストが参照不可になりレポートの継続性が損なわれた
  • 過去データ保持には、移行前の手動ダウンロードなどの対応が必要だった
✅ アップデート後の改善
  • 元の請求対象料金による過去請求データへのアクセスを Cost Explorer 上で保持できる
  • オンボーディング済みアカウントは追加操作なしで過去データにアクセス可能
  • レポート作成の継続性が確保され、移行前後のコスト分析を中断なく実施できる

Bill-Source アカウントは Cost Explorer で、Bill-Transfer アカウントが提供するプロフォーマ料金ビューに加えて、元の請求対象レートによる過去請求データへもアクセスできるようになりました。

⭐ 主要機能

🗄️ 過去請求データへのアクセス保持
  • 請求グループに含まれるアカウントが、元の請求対象料金 (billable rates) による過去請求データへのアクセスを保持
  • Cost Explorer 上で移行前後のコスト分析を継続して実施可能
  • レポート作成の継続性を確保
🔄 既存アカウントへの自動適用
  • すでに Billing Conductor および Billing Transfer をオンボーディング済みのアカウントは追加操作不要
  • 自動的に過去データへのアクセスを取得
💰 プロフォーマ料金と請求対象料金の併存
  • Bill-Transfer アカウントが提供するプロフォーマ料金で請求データを表示
  • 同時に、元の請求対象レートによる過去データも参照可能

API 変更履歴

今回のアップデートに直接関連する新規 API メソッドの追加は確認されていません。Billing Transfer の構成は AWS Billing Conductor および Billing Transfer の既存 API で実施します。

⚙️ 設定方法

前提条件

✓AWS Organizations の管理アカウントを保有していること
✓Bill-Transfer アカウントと Bill-Source アカウント間で Billing Transfer の招待を承諾済みであること
✓プロフォーマ料金を表示するために AWS Billing Conductor を構成していること (コンソール構成には Billing Conductor の利用が必要)

手順

Billing Transfer のセットアップ

Bill-Transfer アカウントから Bill-Source アカウントへ招待を送信。招待には連結請求書の管理・支払いを開始する開始日を含めます。招待は移管開始日の 24 時間前 (UTC) までに承諾する必要があります。

Billing Conductor によるプロフォーマ料金の構成

Bill-Transfer アカウントは、Bill-Source アカウントに表示されるプロフォーマ料金を AWS Billing Conductor で構成。ベース料金または既存のカスタム料金のいずれかを選択できます。

Cost Explorer での過去データ確認

Bill-Source アカウントは Cost Explorer 上で、プロフォーマ料金ビューに加えて元の請求対象レートによる過去請求データを参照可能。既存のオンボーディング済みアカウントは追加操作なしでアクセスできます。

📈 メリット

💼 ビジネス面

✓レポート作成の継続性: 移行前後でコスト分析を中断なく実施でき、過去傾向との比較が可能
✓手動対応の削減: 移行前のコストデータ手動ダウンロードが不要に
✓既存ユーザーへの即時適用: オンボーディング済みなら追加操作なしで恩恵

🛠️ 技術面

✓データの一貫性: 請求対象レートとプロフォーマ料金の両方を参照可能
✓運用負荷の軽減: 移行時の過去データ消失への対処が不要
✓既存構成との互換性: 既存の Billing Conductor / Billing Transfer 構成をそのまま活用

⚠️ デメリット・制約事項

🚫 制限事項

!Billing Transfer は GovCloud、China (Beijing)、China (Ningxia) では利用不可
!コンソールでの構成には AWS Billing Conductor の利用が必要で、利用料金が発生
!プロフォーマ請求データはサポートプラン料金、AWS クレジット、無料利用枠など一部の料金要素を反映しない場合がある

🔍 考慮すべき点

iCost Anomaly Detection (CAD) は Bill-Source アカウントではサポートされない
iプロフォーマデータの粒度は日次・月次のみ。時間単位の分析には Cost and Usage Report を使用
iRI / Savings Plans の推奨はパブリック料金に基づくため、予測節約額が実際より高く表示される場合がある

🎯 ユースケース

1. AWS パートナーによるリセール時のコスト継続性確保
シナリオAWS パートナーがエンドカスタマーの請求を Bill-Transfer アカウントへ移管した後も、エンドカスタマー (Bill-Source アカウント) が過去のコスト傾向を Cost Explorer で参照したい。
効果元の請求対象レートによる過去データを保持できるため、移行後もレポート作成と分析を継続できる。
2. 企業の組織再編に伴う請求集約
シナリオ複数の AWS Organizations の連結請求を単一の Bill-Transfer アカウントへ集約しつつ、各組織が過去のコストデータを継続して分析したい。
効果各 Bill-Source アカウントが過去データを保持するため、組織再編後も一貫したコスト管理が可能。
3. ショーバック / チャージバック運用
シナリオBill-Transfer アカウントが Billing Conductor でプロフォーマ料金を構成し、各部門 (Bill-Source アカウント) にチャージバックを実施しつつ、過去の実コストとの差分を確認したい。
効果プロフォーマ料金ビューと過去データの両方を参照でき、より正確なコスト配賦と分析が可能。

💵 料金・利用可能リージョン

料金

今回の過去データ保持機能自体に関する追加料金の記載はありません。ただし、コンソールでの Billing Transfer 構成には AWS Billing Conductor の利用が必要であり、Billing Conductor の利用料金が発生します。詳細は AWS Billing Conductor の料金ページを参照してください。

利用可能リージョン

Billing Transfer は本日より、以下を除くすべての AWS リージョンで利用可能です。

✓ ほぼすべての AWS リージョン ✗ GovCloud ✗ China (Beijing) ✗ China (Ningxia)

🔗 関連サービス・機能

  • AWS Billing Conductor: プロフォーマ料金の構成と請求グループの作成に使用するカスタム請求サービス
  • AWS Billing Transfer: 管理アカウントの連結請求を外部の管理アカウントへ移管する仕組み
  • AWS Cost Explorer: コストと使用状況を可視化、分析するツール。今回の機能で過去データの参照性が向上
  • AWS Cost and Usage Report (CUR): 時間単位の粒度でのコスト分析が必要な場合に使用

✅ まとめ

Billing Transfer や Billing Conductor を利用して請求グループにマッピングされたアカウントが、Cost Explorer 上で元の請求対象レートによる過去請求データへのアクセスを保持できるようになりました。これによりレポート作成の継続性が確保され、移行に伴う過去データ消失への懸念が解消されます。

すでにオンボーディング済みのアカウントは追加操作なしで恩恵を受けられるため、Billing Transfer を利用中のお客様は Cost Explorer での過去データ参照状況を確認することをお勧めします。
