Kiro CLI 2.7

🎯 /goal・Queue Steering・
強化された /rewind

リリース日
2026-06-12

📌 概要

Kiro CLI 2.7 では、エージェントの動作方向と自律性に対する制御を強化する 3 つの機能が追加されました。

開発者はエージェントの実行を待つことなく方向を修正したり、完了を検証する反復ループを実行したり、過去のターンを詳細に確認して巻き戻したりできます。特に、長時間実行されるマルチステップのタスクや、エージェントの方向性をきめ細かく制御したいユーザーにメリットがあります。

😓 アップデート前の課題
  • 誤った方向に気づいても、キャンセルして最初からやり直す必要があった
  • エージェントが完了を自己検証する仕組みがなく、不完全な状態で停止することがあった
  • /rewind でターン内容を把握するには個々のメッセージを展開する必要があった
🚀 アップデート後の改善
  • Queue Steering でエージェントを停止せずに次のツール境界で軌道修正できる
  • /goal で完了を検証してから停止する反復ループを実行できる
  • /rewind プレビューでターンの要約を確認し、分岐点を素早く特定できる

🔄 アーキテクチャ図: Queue Steering の動作フロー

sequenceDiagram
    participant U as 👤 開発者
    participant K as 🤖 Kiro エージェント
    participant T as 🔧 ツール

    U->>K: タスクを依頼
    activate K
    K->>T: ツール呼び出し 1
    T-->>K: 実行結果
    Note over U,K: 作業中に方向修正が必要と気づく
    U->>K: 修正メッセージをキューに送信
    K->>K: 次のツール境界で取り込み
    K->>T: ツール呼び出し 2 修正後
    T-->>K: 実行結果
    K-->>U: 軌道修正して継続
    deactivate K

開発者はエージェントを停止せずに修正メッセージを送信し、エージェントは次のツール境界でそれを取り込んで軌道修正します。

⚙️ 主要機能

🎯 /goal コマンド

  • 目標に向かって反復的に作業し、完了前にタスク完了を検証する目標駆動型ループを開始
  • 受け入れ基準が満たされるまで実装と自己チェックの複数サイクルを繰り返す
  • デフォルトの反復回数は 5 回、--max オプションで設定可能
  • 自律実行と品質ゲートを組み込んだマルチステップタスクに有用

🧭 Queue Steering

  • エージェントの作業中にメッセージを送信し、次のツール境界で取り込ませる
  • キャンセル・再起動の代わりに修正をキューに入れ、ターンの途中で軌道修正
  • Ctrl+S で steer モード (即座に注入) と queue モード (ターン終了までバッファリング) を切替

⏪ 強化された /rewind プレビュー

  • ターン選択機能が各ターンの高レベルな要約を表示
  • ツール呼び出し、変更されたファイル、実行されたコマンド、中間メッセージを表示
  • 個々のメッセージを展開せず、適切な分岐点を素早く特定できる

🔧 技術仕様: 各機能の概要

項目詳細
/goal デフォルト反復回数5 回
/goal 反復回数設定--max オプションで変更可能

/rewind プレビュー表示内容ツール呼び出し、変更ファイル、実行コマンド、中間メッセージ

🛠️ 設定方法・コマンド例

前提条件: Kiro CLI 2.7 以降がインストールされ、エージェント駆動のチャットセッションが利用可能であること。

Bash ステップ 1: 目標駆動型ループを開始 
/goal テストカバレッジを 80% 以上に引き上げる
Bash ステップ 2: 反復回数を指定して実行 
# 最大反復回数を 10 回に設定 (デフォルト 5 回で不足する大規模タスク向け)
/goal --max 10 すべての failing テストを修正する
🧭 ステップ 3: Queue Steering で軌道修正
  • 作業中にメッセージを入力・送信すると、次のツール境界で取り込まれる
  • Ctrl+S で steer モード (即座に注入) と queue モード (ターン終了までバッファリング) を切替

✅ メリット

💼 ビジネス面

  • 生産性の向上: キャンセル・再起動が不要となり、軌道修正の待ち時間を削減
  • 品質の担保: 完了検証ループで不完全な成果物のリスクを低減
  • 作業の透明性: /rewind プレビューで過去のターンを素早く把握、意思決定を迅速化

🔩 技術面

  • きめ細かい制御: ツール境界での取り込みで実行を妨げず方向性を制御
  • 自律実行と品質ゲートの両立: 検証ステップで品質を確保しつつ自律実行
  • 効率的なデバッグ: 要約表示で適切な分岐点を特定してやり直し

⚠️ デメリット・制約事項

制限事項
  • Kiro CLI 2.7 以降で利用可能 (それ以前のバージョンでは使用不可)
  • Queue Steering の取り込みはツール境界で行われ、即座に反映されるわけではない
  • /goal の反復実行はエージェント稼働時間を増やすため、クレジット消費が増加する可能性
考慮すべき点
  • 反復回数を多く設定すると想定以上のクレジットを消費するため、--max は慎重に設定
  • 目標駆動型ループの受け入れ基準を明確に指定すると検証の精度が向上する

💡 ユースケース

1. 大規模リファクタリングの自律実行

シナリオ: 複数ファイルにまたがるリファクタリングを行い、すべてのテストがパスすることを確認したい。
実装例
/goal --max 8 ユーザー認証モジュールをリファクタリングし、すべての既存テストがパスすることを確認する
効果: 実装と自己検証を繰り返し、受け入れ基準を満たすまで自律的に作業を継続。

2. 作業中の軌道修正

シナリオ: 実装を進めている途中で、別のアプローチを採用すべきだと気づいた。
実装例
エージェント作業中にメッセージを入力:
「REST API ではなく GraphQL で実装してください」
→ 次のツール境界で取り込まれ軌道修正
効果: キャンセルして最初からやり直すことなく、作業を継続したまま方向性を変更。

3. 過去のターンへの巻き戻し

シナリオ: 複数ターンにわたり進行した後、特定のターンの状態に戻したい。
実装例
/rewind
→ 各ターンの要約 (ツール呼び出し、変更ファイル、コマンド) を確認
→ 適切な分岐点を選択
効果: 個々のメッセージを展開せず、要約から適切な分岐点を素早く特定して巻き戻し。

📝 まとめ

Kiro CLI 2.7 は、エージェントの方向制御と自律性を大きく向上させるアップデートです。Queue Steering による作業中の軌道修正、/goal による完了検証ループ、強化された /rewind プレビューにより、エージェント駆動開発の効率と品質が向上します。Kiro CLI を利用している開発者は、CLI を 2.7 以降に更新し、これらの機能をワークフローに取り入れることを推奨します。
