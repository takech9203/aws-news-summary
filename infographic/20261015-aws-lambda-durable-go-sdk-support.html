⚡ AWS Lambda Durable Execution SDK for Go
一般提供開始

📅 リリース日: 2026 年 10 月 15 日
AWS Lambda ✅ 一般提供 GA

📝 概要

AWS Lambda Durable Execution SDK for Go が一般提供 (GA) になりました。Go 開発者は、Lambda durable functions を使用した耐障害性のある長時間実行ワークフローを、独自の進捗管理の実装なしに Go コードで直接構築できます。インフラストラクチャ自動化、承認ゲート付きのデプロイロールアウト、AI モデルを呼び出して人間のレビューを待機するパイプラインといったマルチステップアプリケーションが対象です。

Lambda durable functions は進捗を自動的にチェックポイントとして保存し、外部イベントの待機時には最長 1 年間実行を一時停止できます。SDK は step、コールバック統合、durable invocation、wait を提供し、go get で導入して provided.al2023 ランタイム上に単一の静的バイナリとしてデプロイします。

❌ アップデート前の課題

✗SDK は JavaScript、TypeScript、Python、Java、C# (.NET) のみ対応で、Go 開発者は durable functions をネイティブに利用できなかった
✗Go での長時間実行ワークフローには独自の進捗管理 (チェックポイント保存・再開ロジック) の実装や Step Functions などの外部オーケストレーションが必要だった
✗人間の承認待ちや外部イベント待ちには、ポーリング用インフラや状態管理用データストアを別途用意する必要があった

✅ アップデート後の改善

✓step、wait、コールバック、durable invocation を通常の Go コードとして記述できるネイティブな開発体験を実現
✓進捗が自動チェックポイント保存され、障害時はリプレイで完了済み処理をスキップして再開。独自実装が不要に
✓durabletest で AWS 認証情報・ネットワークなしのローカルテストが可能に
✓durablelint で再開時にワークフローを壊す非決定的コードを静的解析で検出

ローカルで開発・テスト・静的解析した Go コードを単一の静的バイナリとしてデプロイし、durable execution が step や wait の進捗をチェックポイントとして自動保存、障害や一時停止からリプレイで再開する流れを示しています。

🔧 主要機能

🪜 Step による進捗管理

durable.Step / StepAsync でラップした処理の結果を自動チェックポイント保存。組み込みリトライは指数バックオフがデフォルトで、NoRetry やカスタム RetryConfig も指定可能。実行セマンティクスは AtLeastOncePerRetry (デフォルト) と AtMostOncePerRetry から選択。

⏸️ Wait による効率的な一時停止

durable.Wait / WaitAsync でコンピュートを保持せずに一時停止。待機中はコンピュート料金が発生せず、数時間から数日の待機でもコスト効率が高い。最小待機時間は 1 秒 (秒単位に切り上げ)。

🤝 コールバック統合

CreateCallback と WaitForCallback で人間の承認やエージェントの応答を待機。外部システムは SendDurableExecutionCallbackSuccess / Failure API で解決。タイムアウトとハートビートをサポート。

🔗 Durable invocation による関数チェーン

Invoke により、別の durable function を独立した実行として信頼性高く呼び出し可能。

🧵 並行処理のサポート

Go、RunInChildContext、Map、Parallel、ParallelMixed などのプリミティブに加え、All、AllSettled、Any、Race、Join、Select のコンビネータを提供。

🧪 ローカルテストと静的解析

durabletest の NewLocalRunner で、認証情報・ネットワークなしに複数回の呼び出しをまたぐ実行を再現 (step 結果 262,144 バイトなどのサービス上限も検証)。durablelint が非決定的コードを検出。

ハンドラーの実装

Godurable function ハンドラー例
package main

import (
	"fmt"
	"time"

	"github.com/aws/aws-durable-execution-sdk-go/durable"
)

func handler(ctx durable.Context, _ any) (string, error) {
	name, err := durable.Step(ctx, "fetch-name", func(_ durable.StepContext) (string, error) {
		return "world", nil
	})
	if err != nil {
		return "", err
	}
	if err := durable.Wait(ctx, "cooldown", 2*time.Second); err != nil {
		return "", err
	}
	return durable.Step(ctx, "format", func(_ durable.StepContext) (string, error) {
		return fmt.Sprintf("hello, %s", name), nil
	})
}

func main() {
	durable.Start(handler)
}

durable.Context を受け取るハンドラーを実装し、durable.Start で登録します。Step でラップした処理は自動的にチェックポイントされ、Wait はコンピュート課金なしで実行を一時停止します。

💡 メリット

💼 ビジネス面

✓開発工数の削減: 進捗管理、リトライ、障害復旧の仕組みを独自実装する必要がなくなり、ビジネスロジックに集中できる
✓コスト効率: wait による一時停止中はコンピュート料金が発生せず、数日間待機するワークフローでも実処理時間分のみの支払い
✓人間参加型ワークフローの実現: 承認ゲート付きデプロイや人間のレビューを待つ AI パイプラインを追加インフラなしで構築

🔬 技術面

✓ネイティブな Go 体験: go get での導入、単一静的バイナリ、通常の Go 関数と同じデプロイフローで既存ワークフローと自然に統合
✓ローカルテスト可能: チェックポイントとリプレイを含むワークフロー全体を CI やローカルで検証し、デプロイ前に品質を確保
✓静的解析による安全性: 順序が不定な map のイテレーションなど、再開時にワークフローを壊す非決定的コードを事前検出

⚠️ デメリット・制約事項

🚧 制限事項

⚠ランタイムは provided.al2023 (カスタムランタイム) を使用する必要がある
⚠Go 1.24 以降が必要
⚠insight と analysis (durablelint) は pre-v1 で、リリース間で破壊的変更の可能性
⚠wait の最小時間は 1 秒で、秒単位に切り上げ

🤔 考慮すべき点

→リプレイの一貫性のため、durable operation は毎回同じ順序で作成する (map のキーはソート、非決定的処理は step 本体に閉じ込める)
→デフォルトの AtLeastOncePerRetry では step 本体が複数回実行される可能性があるため、冪等に実装する
→durable.Context はゴルーチンに紐づいており、誤用すると ErrWrongGoroutine / ErrWrongContext で失敗
→社内標準が Step Functions の場合は、ビジネスロジックとの密結合度やビジュアル設計・220 以上のサービス統合の必要性で使い分けを検討

🎯 ユースケース

1️⃣ 承認ゲート付きのデプロイロールアウト

シナリオ: 本番環境へのデプロイを段階的に実行し、各ステージの間に運用担当者の承認を挟みたい。

Go承認コールバックの例
cb, _ := durable.CreateCallback[string](ctx, "approval")
_, _ = durable.Step(ctx, "notify-approver", func(_ durable.StepContext) (any, error) {
	return nil, notifyApprover(cb.ID()) // 承認者に通知
})
result, err := durable.WaitForCallback(ctx, cb) // 承認を待機
✅ 効果: 承認待ちの間はコンピュート課金なしで一時停止し、承認後に自動的に再開。ポーリング用インフラや状態管理用データベースが不要に。
2️⃣ 人間のレビューを待つ AI パイプライン

シナリオ: AI モデルを呼び出してコンテンツを生成し、人間のレビューを経てから公開する多段パイプラインを Go で構築したい。

GoAI 生成と人間レビューの例
draft, _ := durable.Step(ctx, "generate", func(_ durable.StepContext) (string, error) {
	return invokeModel(prompt) // AI モデル呼び出し
})
cb, _ := durable.CreateCallback[Review](ctx, "human-review")
review, _ := durable.WaitForCallback(ctx, cb) // 人間のレビューを待機
✅ 効果: モデル呼び出しの結果がチェックポイントに保存されるため、障害時も再呼び出しが発生しない。レビュー待ちは最長 1 年間、課金なしで待機できる。
3️⃣ インフラストラクチャ自動化

シナリオ: リソースのプロビジョニング、完了のポーリング、後続設定という複数ステップのインフラ自動化を、リトライとロールバックを含めて信頼性高く実行したい。

Goプロビジョニングフローの例
id, _ := durable.Step(ctx, "provision", provisionResource)
_ = durable.WaitForCondition(ctx, "ready", func(c durable.StepContext) (bool, error) {
	return isReady(id) // 完了をポーリング
})
_, _ = durable.Step(ctx, "configure", func(_ durable.StepContext) (any, error) {
	return nil, configure(id)
})
✅ 効果: 各ステップの完了状態が保存されるため、途中で失敗しても完了済みの処理をスキップして安全に再開できる。ポーリング間の待機にコンピュート料金は発生しない。

💰 料金・利用可能リージョン

💵 料金

SDK 自体は Apache-2.0 ライセンスのオープンソースで、追加料金なしで利用できます。Lambda durable functions の利用料金は AWS Lambda の料金体系に従います。wait による一時停止中はコンピュート料金が発生せず、実際の処理時間に対してのみ課金されます。

📌 まとめ

AWS Lambda Durable Execution SDK for Go の一般提供により、Go 開発者も進捗管理の独自実装なしで、最長 1 年間実行できる耐障害性のあるマルチステップワークフローを構築できるようになりました。durabletest によるローカルテストと durablelint による静的解析が開発体験を支えており、既存の Go ツールチェーンにそのまま組み込めます。承認ゲートや人間参加型の AI パイプラインを Go で構築しているチームは、GitHub の SDK と開発者ガイドから評価を始めることを推奨します。
