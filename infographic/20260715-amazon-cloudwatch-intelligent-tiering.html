Amazon CloudWatch Logs

📊 ストレージのインテリジェント階層化

2026-07-15
Intelligent Tiering

🎯 概要

Amazon CloudWatch Logs が ストレージのインテリジェント階層化 を発表しました。ログデータのアクセス頻度に応じて、3 つのストレージ階層 (Standard、Infrequent Access、Archive Instant Access) に自動的に分類します。追加の運用作業なしに、ログをより長期間・低コストで保持できます。

ログを CloudWatch にネイティブに保持したまま、どの階層にデータが存在していても 同一のクエリ体験 を維持できます。ログを一つのツールに集約して完全な可視性を確保でき、運用オーバーヘッドの削減と MTTR (平均修復時間) の短縮 に貢献します。

Before / After 比較

❌ アップデート前の課題
  • 大容量で冗長なログの長期保持でストレージコストが増大
  • コスト抑制のため、ログのフィルタリングや外部エクスポートが必要
  • ログが複数の場所に分散し、可視性が低下して運用オーバーヘッドが増加
✅ アップデート後の改善
  • アクセス頻度に応じて 3 階層へ自動分類し、長期保持コストを低減
  • どの階層にデータがあっても同一のクエリ体験を維持
  • CloudWatch に集約したまま保持でき、可視性向上と MTTR 短縮を実現

⚙️ 主要機能

1. 📚 3 つのストレージ階層への自動分類
  • Standard: 頻繁にアクセスされるログデータ向けの既存の階層
  • Infrequent Access: 30 日間アクセスされなかったデータが移行
  • Archive Instant Access: 90 日間アクセスされなかったデータが移行
2. 🔄 アクセスパターンに基づく自動階層移行
  • CloudWatch Logs が使用状況をモニタリングし、データを自動的に再分類
  • 30 日間未アクセス → Infrequent Access へ移行
  • 90 日間未アクセス → Archive Instant Access へ移行
3. ⬆️ アクセス時の自動昇格
  • 古いデータにアクセスすると、自動的に Standard 階層へ昇格
  • 昇格後は 30 日間 Standard 階層に保持される
4. 🔍 一貫したクエリ体験
  • データがどの階層に存在していても、同一のクエリ体験を維持
  • 階層を意識せずに CloudWatch Logs Insights などでログを分析可能

📋 技術仕様

ストレージ階層の移行条件

階層移行条件用途
📗 Standardログ取り込み時の既定の階層頻繁にアクセスされるログ
📘 Infrequent Access30 日間アクセスなしアクセス頻度が低いログ
📕 Archive Instant Access90 日間アクセスなし長期保持のためのログ
⬆️ Standard へ昇格古いデータにアクセスアクセス後 30 日間 Standard に保持
💡 有効化のスコープ: インテリジェント階層化は アカウントレベル で有効化します。AWS マネジメントコンソール、AWS SDK、または AWS CLI から設定できます。

✨ メリット

💼 ビジネス面

✓ストレージコストの最適化: アクセス頻度が低いログを低コスト階層へ自動移行
✓運用オーバーヘッドの削減: フィルタリングやエクスポートが不要に

⚠️ デメリット・制約事項

制限事項

✗Middle East (Bahrain) および Middle East (UAE) リージョンでは利用不可
✗有効化はアカウントレベルでの設定となる
✗階層移行は自動処理であり、個別の細かい制御はできない

考慮すべき点

ℹ低頻度階層のデータへアクセスすると Standard へ昇格し 30 日間保持される
ℹ各階層のストレージ料金体系を確認し、コスト最適化効果を見積もる
ℹ移行条件 (30 日 / 90 日) と既存のログ保持ポリシーの整合性を確認

💡 ユースケース

1. 大容量ログの長期保持
シナリオコンプライアンス要件のため、大容量で冗長なアプリケーションログを長期間保持する必要がある
効果アクセス頻度が低いログが自動的に Infrequent Access / Archive Instant Access へ移行し、フィルタリングやエクスポートなしで低コストの長期保持を実現
2. インシデント調査時の過去ログ参照
シナリオ過去に発生した事象を調査するため、数か月前のログを参照する
効果Archive Instant Access の古いデータへアクセスすると自動的に Standard へ昇格し、同一のクエリ体験で即座に分析可能
3. ログの一元管理による運用効率化
シナリオ複数の場所に分散していたログを CloudWatch に集約し、単一のツールで監視したい
効果すべてのログを CloudWatch にネイティブ保持したままコストを最適化でき、分析とアラートを一箇所で実行して MTTR を短縮

💰 料金と利用可能リージョン

料金

ログデータが存在するストレージ階層に応じた料金が適用されます。アクセス頻度の低い階層へ移行することで、Standard 階層と比較して ストレージコストを削減 できます。

正確な料金は Amazon CloudWatch 料金ページ を参照してください。

利用可能リージョン

✓すべての AWS 商用リージョンで利用可能
✗Middle East (Bahrain) は対象外
✗Middle East (UAE) は対象外

🔗 関連サービス・機能

🔍 Amazon CloudWatch Logs Insights

ログデータをインタラクティブに検索・分析するクエリ機能。どの階層のデータに対しても一貫したクエリ体験を提供。

📁 CloudWatch Logs ロググループ

ログを整理・保持する単位。保持ポリシーと組み合わせてログのライフサイクルを管理。

🪣 Amazon S3

従来ログのエクスポート先として利用されていたストレージ。インテリジェント階層化により、エクスポートせずに CloudWatch 内で低コスト保持が可能。

📝 まとめ

Amazon CloudWatch Logs のストレージのインテリジェント階層化により、ログデータをアクセス頻度に応じて自動的に最適な階層へ分類し、追加の運用作業なしに長期保持のコストを削減 できるようになりました。大容量のログを CloudWatch にネイティブ保持したまま一貫したクエリ体験を維持できるため、ログの保持戦略とコスト最適化を検討しているお客様は、対象リージョンでアカウントレベルでの有効化を検討することをお勧めします。
