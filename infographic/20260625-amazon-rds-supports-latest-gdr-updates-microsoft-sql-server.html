Amazon RDS for SQL Server

🛡️ 最新の GDR アップデートをサポート

📅 2026 年 6 月 25 日

📌 概要

Amazon RDS for SQL Server が、Microsoft SQL Server の最新の General Distribution Release (GDR) アップデートのサポートを開始しました。

GDR は、機能追加を伴う累積的更新プログラム (CU) とは異なり、セキュリティ修正など重要な修正のみを提供する更新プログラムです。今回のリリースでは、SQL Server 2016 / 2017 / 2019 / 2022 の各バージョンに対応する GDR アップデートが利用可能になりました。

今回の GDR アップデートは、以下の脆弱性に対処します。本番環境で SQL Server を運用するお客様にとって重要なセキュリティ対策です。

⛔ アップデート前の課題

  • 最新の GDR が RDS で利用できず、CVE-2026-32167 / CVE-2026-32176 に対処できなかった
  • 自己管理の SQL Server 環境では、セキュリティパッチを手動で適用する必要があった
  • 最新のセキュリティ修正が反映された RDS エンジンバージョンが提供されていなかった

✅ アップデート後の改善

  • 最新の GDR を含む RDS エンジンバージョンへのアップグレードが可能に
  • CVE-2026-32167 / CVE-2026-32176 の脆弱性への対処が可能に
  • コンソール・SDK・CLI から容易にセキュリティ更新を適用できるように

⚙️ 主要機能

🗂️ 対応する SQL Server バージョンと GDR アップデート

  • SQL Server 2016 SP3+GDR KB5084821 (RDS 13.00.6485.1.v1)
  • SQL Server 2017 CU31+GDR KB5084818 (RDS 14.00.3525.1.v1)
  • SQL Server 2019 CU32+GDR KB5084816 (RDS 15.00.4465.1.v1)
  • SQL Server 2022 CU24+GDR KB5083252 (RDS 16.00.4250.1.v1)

🔒 対処されるセキュリティ脆弱性

  • CVE-2026-32167 で説明されている脆弱性に対処
  • CVE-2026-32176 で説明されている脆弱性に対処

🚀 アップグレード方法

  • Amazon RDS Management Console からのエンジンバージョン変更
  • AWS SDK を利用したプログラムによるアップグレード
  • AWS CLI を利用したアップグレード

🛠️ 設定方法

前提条件

  • 対象の SQL Server バージョンを実行している RDS for SQL Server インスタンスが存在すること
  • エンジンバージョン変更を実行する権限 (rds:ModifyDBInstance など) を持つ IAM 権限があること
  • アップグレードに伴うダウンタイムを許容できるメンテナンスウィンドウを計画していること

② 🎯 アップグレード先確認

③ ⬆️ バージョン変更実行

ステップ 1: 現在のエンジンバージョンを確認する

Bash現行バージョンの確認
aws rds describe-db-instances \
  --db-instance-identifier my-sqlserver-instance \
  --query "DBInstances[].EngineVersion"

出力されたバージョンが GDR 適用済みバージョンより古い場合、アップグレードの対象となります。

ステップ 2: 利用可能なアップグレード先バージョンを確認する

Bashアップグレード先の確認
aws rds describe-db-engine-versions \
  --engine sqlserver-se \
  --engine-version 15.00.4465.1.v1 \
  --query "DBEngineVersions[].ValidUpgradeTarget[].EngineVersion"

--engine には対象エディション (例: sqlserver-se、sqlserver-ee、sqlserver-ex、sqlserver-web) を指定します。

ステップ 3: エンジンバージョンをアップグレードする

Bashエンジンバージョンの変更
aws rds modify-db-instance \
  --db-instance-identifier my-sqlserver-instance \
  --engine-version 15.00.4465.1.v1 \
  --apply-immediately
💡 --apply-immediately を指定すると即時に適用され、省略すると次回のメンテナンスウィンドウで適用されます。本番環境では事前にスナップショットを取得し、メンテナンスウィンドウでの適用を検討してください。

✅ メリット

💼 ビジネス面

  • セキュリティリスクの低減: 既知の脆弱性 (CVE-2026-32167 / 32176) に対処
  • コンプライアンス対応: 最新のセキュリティ修正でセキュリティ基準への対応が容易に
  • 運用負荷の軽減: マネージドサービスの仕組みでパッチ作業の負担を軽減

🔧 技術面

  • 機能影響の最小化: GDR は重要な修正のみで CU より機能変更の影響が小さい
  • 複数の適用手段: コンソール・SDK・CLI で自動化やワークフロー組込みが容易
  • 幅広いバージョン対応: SQL Server 2016 から 2022 までの主要バージョンに対応

⚠️ デメリット・制約事項

制限事項

  • エンジンバージョンの変更にはダウンタイムが発生する
  • GDR は重要な修正に限定され、新機能は含まれない
  • 元のバージョンへ戻すのは容易ではないため、事前のスナップショット取得が推奨

考慮すべき点

  • 本番適用前に、ステージング環境などで動作検証を実施することが望ましい
  • マルチ AZ / シングル AZ でダウンタイムの挙動が異なるため、構成に応じた計画が必要
  • アプリ側の接続再試行ロジックを確認し、アップグレード時の瞬断に備える

🎯 ユースケース

① 本番データベースのセキュリティパッチ適用

シナリオ: SQL Server 2019 を本番運用しており、CVE-2026-32167 / 32176 への対処が必要なケース。

実装例: スナップショット取得 → メンテナンスウィンドウ設定 → エンジンバージョンを 15.00.4465.1.v1 に変更

✨ 計画的なメンテナンスウィンドウ内でセキュリティパッチを適用し、脆弱性リスクを低減できる。

② 複数インスタンスへの一括適用の自動化

シナリオ: 多数の RDS for SQL Server インスタンスを運用し、GDR を統一的に適用したいケース。

実装例: AWS CLI / SDK で対象インスタンスのリストに対し modify-db-instance を順次実行するスクリプトを作成

✨ 手動操作を減らし、適用漏れを防ぎながら効率的にセキュリティ更新を展開できる。

③ コンプライアンス要件への対応

シナリオ: セキュリティ監査で、DB エンジンが最新のセキュリティ修正を適用済みであることを示す必要があるケース。

実装例: describe-db-instances で全インスタンスのエンジンバージョンを取得し、GDR 適用済みであることを確認

✨ 最新の GDR 適用状況を可視化し、監査やコンプライアンス報告に活用できる。

💰 料金・リージョン・関連サービス

💵 料金

GDR アップデートの適用自体に追加料金は発生しません。Amazon RDS for SQL Server の通常の料金 (インスタンス・ストレージ・ライセンスなど) が適用されます。

🌍 利用可能リージョン

Amazon RDS for SQL Server が提供されているリージョンで利用可能です。詳細な提供状況は AWS の公式情報を参照してください。

🔗 関連サービス・機能

  • Amazon RDS: 本アップデートの対象となるマネージドリレーショナルデータベースサービス
  • AWS CLI / AWS SDK: エンジンバージョンのアップグレードをプログラム的に実行する手段
  • Amazon RDS マルチ AZ 配置: アップグレード時の可用性とダウンタイムに影響する構成オプション

📝 まとめ

本アップデートにより、Amazon RDS for SQL Server で CVE-2026-32167 および CVE-2026-32176 に対処する最新の GDR が利用可能になりました。対象バージョン (SQL Server 2016 / 2017 / 2019 / 2022) を運用しているお客様は、セキュリティリスクを低減するため、スナップショット取得などの準備を行ったうえで、計画的にエンジンバージョンのアップグレードを実施することが推奨されます。
