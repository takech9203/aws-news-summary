AWS Local Zones

🇨🇴 コロンビア・ボゴタの新しい AWS Local Zone が一般提供開始

📅 リリース日: 2026 年 11 月 20 日 | 機能: ボゴタ (コロンビア) Local Zone の一般提供開始

📝 概要

AWS は、コロンビアの首都ボゴタにおける新しい AWS Local Zone の一般提供開始を発表しました。 Local Zones はコンピューティング、ストレージ、データベースなどの AWS サービスを大都市圏の近くに配置するインフラストラクチャで、 エンドユーザーに対して 1 桁ミリ秒のレイテンシーを実現します。 標準リージョンと同じ API・ツールで運用でき、低レイテンシーが必要なワークロードのみをユーザーの近くに配置するハイブリッド構成を容易に実現できます。

❌ アップデート前の課題

✗コロンビア国内に AWS リージョンや Local Zone がなく、最寄りリージョン (バージニア北部やサンパウロなど) までのレイテンシーが避けられなかった
✗リアルタイムゲームやライブ配信など 1 桁ミリ秒を要求するアプリの国内提供が困難だった
✗低レイテンシー要件を満たすにはオンプレミスや国内データセンターでの自前運用が必要だった

✅ アップデート後の改善

✓ボゴタ都市圏のエンドユーザーに 1 桁ミリ秒のレイテンシーでアプリケーションを提供可能に
✓EC2、EBS、ECS、EKS、ALB など使い慣れたサービスを標準リージョンと同じ API・ツールで運用可能に
✓最低利用料金やコミットメントなしの従量課金で低レイテンシーインフラを利用可能に

ボゴタのエンドユーザーは Local Zone 内のリソースに低レイテンシーでアクセスし、Local Zone は親リージョンであるバージニア北部リージョンと同一 VPC 内でシームレスに接続されます。

⚡ 主要機能

📍 ボゴタ Local Zone の開設
ゾーン ID は us-east-1-bog-1a、親リージョンは米国東部 (バージニア北部、us-east-1)。コロンビア初の AWS Local Zone として、国内ユーザーへの 1 桁ミリ秒レイテンシーを実現します。
🧰 利用可能なサービス
Amazon EC2 (C7i / M7i / R7i)、Amazon EBS (gp3 / gp2 / io1 とローカルスナップショット)、Amazon S3 (One Zone-IA)、Amazon ECS / EKS によるコンテナワークロード、Amazon VPC、AWS Direct Connect、Application Load Balancer を利用できます。
🔧 標準リージョンと同じ運用体験
標準の AWS リージョンと同じ API、ツール、マネジメントコンソールで利用可能。最低利用料金やコミットメントなしの従量課金で、オンデマンド、Savings Plans、スポットインスタンスの購入オプションに対応します。

🛠️ 設定方法

前提条件

  • AWS アカウントを保有していること
  • 親リージョンであるバージニア北部リージョン (us-east-1) を利用できること
  • Local Zone の利用には明示的なオプトイン (有効化) が必要

STEP 1Local Zone の有効化

Bash ゾーングループのオプトイン 
aws ec2 modify-availability-zone-group \
  --region us-east-1 \
  --group-name us-east-1-bog-1 \
  --opt-in-status opted-in

ModifyAvailabilityZoneGroup API でゾーングループを有効化します。EC2 コンソールの AWS Global View にある [Regions and Zones] タブからも有効化できます。

STEP 2Local Zone にサブネットを作成

Bash サブネット作成 
aws ec2 create-subnet \
  --region us-east-1 \
  --vpc-id vpc-xxxxxxxx \
  --cidr-block 10.0.10.0/24 \
  --availability-zone us-east-1-bog-1a

既存の VPC 内にボゴタ Local Zone を指定してサブネットを作成します。同一 VPC 内でリージョンのリソースと Local Zone のリソースを組み合わせて利用できます。

STEP 3EC2 インスタンスの起動

Bash インスタンス起動 
aws ec2 run-instances \
  --region us-east-1 \
  --image-id ami-xxxxxxxx \
  --instance-type m7i.xlarge \
  --subnet-id subnet-xxxxxxxx

作成したサブネットを指定して EC2 インスタンスを起動します。C7i、M7i、R7i インスタンスタイプを利用できます。

💡 メリット

💼 ビジネス面

✓コロンビア市場への低レイテンシー展開: 国内データセンターを自前で構築することなく、ボゴタのユーザーに低レイテンシーなサービスを提供できる
✓初期投資不要の従量課金: 最低利用料金やコミットメントなしで開始でき、Savings Plans やスポットインスタンスによるコスト最適化も可能
✓ユーザー体験の向上: ゲーム、動画配信、金融取引などレイテンシーに敏感なサービスの応答性を改善できる

⚙️ 技術面

✓標準リージョンと同じ運用: 既存の API、ツール、IaC テンプレートをそのまま利用でき、学習コストや運用負荷の増加を抑えられる
✓ハイブリッド構成が容易: 同一 VPC 内で Local Zone とリージョンのリソースを組み合わせ、低レイテンシー処理とバックエンド処理を分離できる
✓コンテナワークロード対応: ECS / EKS が利用でき、既存のコンテナベースのアーキテクチャを低レイテンシー環境に展開しやすい

⚠️ デメリット・制約事項

制限事項

✗利用可能なサービスとインスタンスタイプは標準リージョンより限定される (EC2 は C7i、M7i、R7i のみ)
✗利用前にゾーングループへのオプトインが必要
✗S3 は One Zone-IA ストレージクラスのみで、ストレージの冗長性は単一ゾーンに限定される

考慮すべき点

⚠Local Zone のリソース料金は親リージョンと異なるため、料金ページで事前に確認が必要
⚠親リージョン (us-east-1) との間の通信にはレイテンシーが発生するため、アーキテクチャ設計時にデータ配置の検討が必要
⚠単一ゾーン構成となるため、高可用性が必要なワークロードでは親リージョンとの組み合わせを検討する

🎯 ユースケース

🎮 ユースケース 1: リアルタイムゲームサーバー

シナリオ: コロンビア国内のプレイヤー向けに対戦型オンラインゲームを提供しており、サーバー応答のレイテンシーがプレイ体験を左右する。

実装例: ゲームセッションサーバー (EC2 C7i) をボゴタ Local Zone に配置し、マッチメイキングやプレイヤーデータ管理は親リージョン us-east-1 で実行。

効果: プレイヤーとゲームサーバー間のレイテンシーを 1 桁ミリ秒に抑え、快適な対戦体験を提供できる。

📺 ユースケース 2: ライブ動画ストリーミング

シナリオ: スポーツイベントなどのライブ配信で、ボゴタ都市圏の視聴者に低遅延の映像を届けたい。

実装例: エンコード・パッケージング処理を Local Zone 内の EC2 / ECS で実行し、アーカイブは S3 One Zone-IA およびリージョンの S3 に保存。

効果: 配信遅延を最小化し、視聴者のリアルタイム性の高い視聴体験を実現できる。

💹 ユースケース 3: 金融取引処理

シナリオ: 金融機関がボゴタの取引システム向けに低レイテンシーの注文処理基盤を必要としている。

実装例: 注文処理アプリケーションを Local Zone の EC2 R7i + EBS io1 で稼働させ、Direct Connect でオンプレミスの基幹システムと接続。

効果: 取引処理のレイテンシーを削減しつつ、AWS の運用モデルとオンプレミス環境を安全に統合できる。

💰 料金

AWS Local Zones は従量課金制で、最低利用料金や前払いのコミットメントはありません。 ボゴタ Local Zone の EC2 インスタンスには、オンデマンド、Savings Plans、スポットインスタンスの購入オプションが利用できます。 Local Zone のリソース料金は親リージョンと異なる場合があるため、詳細は AWS Local Zones 料金ページ を参照してください。

✅ まとめ

コロンビア・ボゴタに新しい AWS Local Zone が開設され、同国のエンドユーザーに対して 1 桁ミリ秒のレイテンシーでアプリケーションを提供できるようになりました。 リアルタイムゲーム、ライブ配信、金融取引など低レイテンシーが要件となるワークロードをコロンビア向けに展開している場合は、 ゾーングループを有効化し、Local Zone へのワークロード配置を検討することをお勧めします。
