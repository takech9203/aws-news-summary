🏢 サブシダリーアカウント認可

1 回の出品で複数子会社アカウントからの販売が可能に ｜ 📅 リリース日: 2026 年 10 月 29 日

📝 概要

複数の法人を運営する AWS パートナー向けに、サブシダリーアカウント認可機能が登場。 プライマリアカウントで製品を 1 回出品するだけで、接続された子会社のセラーアカウントが その製品のダイレクトプライベートオファーを作成して販売できます。

各サブシダリーアカウントは自身の現地税務アイデンティティで取引し、現地通貨での請求、 独自の送金設定と銀行口座を利用可能。プライマリアカウントは Marketplace insights レポートで 全アカウントのオファー・契約・更新を一元的に把握できます。

❌ Before: アップデート前の課題

  • 複数法人でのグローバル販売には、同一製品のリスティングを各セラーアカウントに複製する必要があった
  • 製品変更のたびに全アカウントのリスティングを個別更新・保守する必要があり、運用負荷と不整合リスクが大きかった
  • 販売実績の横断把握にはアカウントごとにレポート確認が必要だった

✅ After: アップデート後の改善

  • プライマリアカウントで 1 回出品するだけで、認可されたサブシダリーがプライベートオファーを作成・販売可能
  • リスティングの所有・保守をプライマリに一元化、重複リスティング管理が不要に
  • 各サブシダリーは独自の税務・通貨・送金・銀行口座で取引し、現地財務処理と整合
  • Marketplace insights で全アカウントの契約を一元把握

プライマリアカウントが製品を出品して認可を発行し、サブシダリーアカウントが独自の価格・通貨でプライベートオファーを作成します。 購入者からの支払いはサブシダリーアカウント自身の銀行口座に送金され、 プライマリアカウントは統合レポートで全体を把握できます。

⚙️ 主要機能

🎯 1. 製品の一元管理と販売の分散 (Subsidiary Authorization)

  • リスティングの所有・保守はプライマリアカウントが担い、サブシダリーは内容を変更できない
  • 認可ごとに「対象製品」「販売アカウント」「販売可能な国」「価格ディメンション」「オファータイプ (現時点ではプライベートオファーのみ)」を指定
  • 認可は送信後数分で有効化、サブシダリー側の承諾操作は不要

💱 2. サブシダリーアカウントによる独立した取引

  • サブシダリーは自身のオファーで Seller of Record (記録上の販売者) となり、顧客との契約を所有
  • 独自の税務インタビューと KYC 検証を完了し、独自のローカル通貨・送金設定・銀行口座で取引
  • 出品手数料・取引手数料は取引したアカウントに課金 (アカウント間でプール・相殺・再請求なし)

🔄 3. 認可の更新と取り消し

  • 認可の名前・説明・対象国・価格ディメンションはいつでも変更可能 (以後作成されるオファーにのみ適用)
  • 取り消しはいつでも可能。取り消し後は新規オファーを作成不可
  • 取り消しは既存の公開済みオファーや締結済み契約 (更新・送金を含む) には影響なし。取り消しは恒久的で、再認可には新しい認可の作成が必要

📊 4. 統合レポーティング

  • AWS Partner Central の Marketplace insights セクションで、全接続アカウントのパートナー帰属収益とレポートを一元確認
  • 各アカウントに個別にサインインする必要なし

🛠️ 設定方法

📋 前提条件

✓プライマリ・サブシダリーの両アカウントが AWS Marketplace の有償セラーとして登録済み
✓サブシダリーアカウントが税務インタビューと KYC 検証を完了し、銀行口座と 1 つ以上の送金通貨を含む支払い設定済み
✓両アカウント間で AWS Partner Central のサブシダリー接続が承諾済み
✓両アカウントに AWSMarketplaceSubsidiaryAuthorizationServiceRole サービスロールが存在

1

アカウントの接続

AWS Partner Central にプライマリアカウントでサインインし、[Account Connections] から接続リクエストを送信 (1 回の送信で最大 10 件の AWS アカウント ID を指定可能)。サブシダリー側管理者が承諾すると接続が有効化。承諾により、パートナー帰属収益と Marketplace insights レポートの共有に同意したことが記録されます。

2

サブシダリーアカウントへの製品認可

プライマリアカウントで [Subsidiary account connections] ページを開き、対象の接続を選択して [Add authorization] を選択。製品タイプと製品、認可の名前、利用できる価格ディメンション、販売可能な国を指定して [Submit]。認可は数分以内に有効化。AWS Marketplace Catalog API によるプログラム操作も可能です。

3

サブシダリーアカウントによるプライベートオファーの作成

サブシダリーアカウントで [Sell] の [Private offers] から [Create private offer] を選択。オファータイプとして [Subsidiary private offer] を選択し、認可された製品と使用する認可を選択。認可でカバーされた価格ディメンションのみで価格を設定し、認可された国の購入者を指定して公開。購入者が承諾すると、契約は購入者とサブシダリーアカウントの間で締結されます。

💡 メリット

💼 ビジネス面

✓出品作業の大幅削減: 製品を 1 回出品するだけで複数の現地法人から販売でき、リスティングの複製と重複保守が不要に
✓現地の商習慣への適合: 各子会社が現地の税務アイデンティティ、現地通貨、現地の銀行口座で取引でき、地域の法人構造と財務処理の整合性を維持
✓グローバル展開の加速: 新しい国・地域の子会社にも認可を追加するだけで販売を開始でき、市場参入のリードタイムを短縮

🔧 技術面

✓一元的なガバナンス: 製品内容と価格ディメンションの管理をプライマリアカウントに集約し、認可の付与・更新・取り消しで販売範囲を統制
✓統合された可視性: Marketplace insights レポートで全接続アカウントのオファー・契約・更新を一元把握、アカウントごとのサインイン不要
✓API による自動化: Catalog API の ListEntities で SubsidiaryAuthorization エンティティを一覧でき、認可管理やオファー作成をプログラムで自動化可能

⚠️ デメリット・制約事項

🚧 制限事項

✗サブシダリーアカウントが作成できるのはダイレクトプライベートオファーのみ (パブリックオファーは非対応)
✗認可された製品に対するチャネルパートナー向け再販認可は作成不可
✗認可対象国は国単位のみ (州や国内地域単位の指定は不可)
✗認可の取り消しは恒久的で、元に戻すには新しい認可の作成が必要
✗サブシダリーが既に持つ重複リスティング上の既存契約を、プライマリの製品に移行することは不可

🤔 考慮すべき点

⚠認可を縮小 (国や価格ディメンションの削除) すると、作成中のドラフトオファーの公開が失敗する可能性があるため、事前に該当チームへ周知を推奨
⚠製品の変更 (価格ディメンションの追加など) は認可に自動反映されないため、認可の更新が別途必要
⚠税務インタビューと KYC 検証はプライマリが代行できず、各サブシダリーが自身で完了する必要がある
⚠インドのセラーには固有の登録要件があり、送金通貨は INR のみ設定可能

🎯 ユースケース

🌏 ユースケース 1: 国別法人を持つグローバル ISV の販売統合

シナリオ: 米国本社の ISV が日本、ドイツ、シンガポールに現地販売法人を持ち、各国の顧客と現地通貨で契約したい。

実装例
1. 本社のプライマリアカウントで SaaS 製品を出品
2. 日本法人のセラーアカウントに「販売可能国: 日本、価格ディメンション: 全ユーザー数ベース」の認可を作成
3. 日本法人が JPY 建てのプライベートオファーを国内顧客に提示
4. 売上は日本法人の銀行口座に JPY で送金される

効果: リスティングは 1 つのまま、各国法人が現地の税務・通貨要件に沿って販売でき、重複リスティングの保守コストが解消される。

🤝 ユースケース 2: M&A で取得したセラーアカウントの統合

シナリオ: パートナー企業が他の AWS パートナーを買収し、買収先のセラーアカウントから自社製品を販売させたい。

実装例
1. 買収元のプライマリアカウントから買収先アカウントへ接続リクエストを送信
2. 買収先アカウントが承諾し、Level 1 接続が有効化
3. プライマリアカウントが自社製品の認可を買収先アカウントに付与
4. 買収先アカウントが既存顧客基盤に対してプライベートオファーを作成

効果: 買収先のリスティング複製やアカウント統廃合を行わずに、買収先の販売チャネルと顧客関係を活用して製品を展開できる。

📊 ユースケース 3: プライマリアカウントによる全社販売状況の把握

シナリオ: 複数のサブシダリーアカウントで販売するパートナーの本社管理部門が、全世界の契約・更新状況を一元的に把握したい。

実装例
1. 全サブシダリーアカウントとの接続を承諾済みの状態にする
2. プライマリアカウントで AWS Partner Central の Marketplace insights を開く
3. 接続済み全アカウントのオファー、契約、更新データを統合レポートで確認

効果: 各アカウントへ個別にサインインすることなく、全社の AWS Marketplace 販売実績と更新パイプラインを可視化できる。

💰 料金・利用可能リージョン

💵 料金

本機能は追加料金なしで利用できます。AWS Marketplace の出品手数料・取引手数料は、 取引を行った各アカウント (サブシダリーの販売分はサブシダリーアカウント) にそれぞれ課金され、 アカウント間でプール・相殺されることはありません。

🌐 利用可能リージョン

AWS Marketplace が利用可能なすべての AWS リージョンで利用できます。

🔗 関連サービス・機能

🏛️ AWS Partner Central

サブシダリーアカウントの接続リクエスト送信・承諾、認可の作成・更新・取り消し、Marketplace insights での統合レポート確認に使用する。

🔌 AWS Marketplace Catalog API

ListEntities オペレーションで SubsidiaryAuthorization エンティティタイプがサポートされ、認可の一覧取得やオファー作成をプログラムで実行できる。

🔁 チャネルパートナー再販認可 (Resale Authorization)

第三者のチャネルパートナーが卸価格ベースで再販する仕組み。サブシダリー認可は自社グループ内のアカウントが独自価格で販売する点が異なる。

✨ まとめ

本アップデートにより、複数法人で AWS Marketplace 販売を行うパートナーは、製品リスティングを 1 つに集約しながら、 各現地法人が独自の税務・通貨・送金設定で販売できるようになりました。 複数のセラーアカウントで重複リスティングを運用しているパートナーは、サブシダリー接続と認可の設定を検討し、 リスティング保守の一元化と統合レポーティングの活用を進めることを推奨します。
