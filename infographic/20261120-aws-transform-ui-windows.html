🖥️ ASP.NET Web サイトモダナイゼーション
サードパーティ UI コンポーネントの移植に対応

📅 リリース日: 2026 年 11 月 20 日 | 対象: DevExpress / Infragistics / Telerik by Progress など

📌 概要

AWS Transform の ASP.NET Web サイトモダナイゼーションにおいて、サードパーティ UI コンポーネント移植機能が GA されました。 レガシー ASP.NET サイトが DevExpress、Infragistics、Telerik by Progress などのベンダー UI ライブラリに依存している場合でも、 ASP.NET Core への変換作業を継続できます。

.NET モダナイゼーションエージェントが依存を検出すると、2 つの選択肢が提示されます。 ライセンス不要の Microsoft ネイティブ / オープンソースコントロールへの置き換え、またはベンダーライブラリの継続利用です。 ベンダー UI コントロールを多用するエンタープライズアプリの Linux 対応やライセンスコスト削減を目指す組織にとって重要な強化です。

❌ Before: アップデート前の課題
  • サードパーティ UI 依存のサイトは、UI 層変換時にコンポーネントの移植を手動で実施
  • 独自コントロールの置き換えは、コントロールごとに調査と書き換えが必要
  • ベンダーライブラリ継続時も、対応方針を自力で整理する必要があった
✅ After: アップデート後の改善
  • エージェントが依存を自動検出し、対応方針を選択可能に
  • オープンソースのみのオプションで自動置換、元の依存関係を削除
  • ベンダー継続時はコードコメントと Next Steps を挿入、AI コーディングコンパニオンで完了
  • モダナイゼーションプランに各コントロールの変換先とステータスを一覧表示

.NET モダナイゼーションエージェントがサードパーティ UI ライブラリへの依存を検出し、オープンソースコントロールへの置き換え、またはベンダーライブラリ継続のための移行ガイド挿入のいずれかを実行するフローです。

🔀 2 つの移行パス

🆓 ネイティブコントロールへ変換既定
  • Microsoft ネイティブ / オープンソースコントロールに置換
  • 元のサードパーティ依存関係をプロジェクトから削除
  • ライセンス費用が不要な構成でモダナイゼーションを完了
📝 ベンダーライブラリ継続オプション
  • コードコメントと Next Steps 手順をエージェントが挿入
  • AI コーディングコンパニオンで移植を完了
  • 移行先 UI ライブラリのライセンスはベンダーと別途契約

⚙️ 主要機能

🔍 サードパーティ UI ライブラリの自動検出

ASP.NET サイトの変換時に DevExpress、Infragistics、Telerik by Progress などの独自 UI コンポーネントへの依存を検出。モダナイゼーションプランに各ベンダーコントロールと変換先、ステータスが一覧表示され、既定の動作はプランの編集で変更できます。

🔄 ネイティブコントロールへの変換 (既定)

各独自コントロールを、移行先 UI フレームワーク上の Microsoft ネイティブまたはオープンソースのコントロールに置き換え。元の依存関係は削除され、ライセンス費用が不要な構成で完了できます。

📦 ベンダーライブラリ継続オプション

移行先フレームワーク向けの同等なベンダーライブラリへ移行するためのコードコメントと Next Steps の手順を挿入。ライセンスはベンダーと別途契約し、AI コーディングコンパニオンを使用して移植を完了します。

📋 Next Steps ファイル

AWS Transform が移植または検証できなかった UI コンポーネントについて、AI コーディングコンパニオンでフォローアップするためのタスクが Markdown ファイルに記録されます。

🛠️ 設定方法

前提条件

✓AWS Transform が利用可能なリージョンでジョブを実行できること
✓対象が Web Application プロジェクト (.csproj ファイルを含む) であること (Web Site プロジェクトは非対応)
✓ベンダーライブラリ継続オプションを選択する場合、移行先 UI ライブラリのライセンスをベンダーと手配すること

手順

  1. .NET モダナイゼーションジョブの作成 AWS Transform でジョブを作成し、対象の ASP.NET Web サイトを含むリポジトリを指定。エージェントがコードベースを解析し、UI 層の構成とサードパーティ UI ライブラリへの依存を検出します。
  2. モダナイゼーションプランの確認と調整 検出された各ベンダーコントロールの変換先とステータスを確認。既定ではネイティブ / オープンソースコントロールへの変換が選択されています。変更する場合はチャットでの指示、プランの編集、またはステアリングドキュメントのアップロードで調整します。
  3. 変換の実行と Next Steps の対応 UI 層が ASP.NET Core 対応フレームワークに移植されます。移植・検証できなかったコンポーネントは Next Steps ファイルに記録されるため、AI コーディングコンパニオンで残作業を完了します。

💡 メリット

💼 ビジネス面

✓ライセンスコストの削減: 既定のオープンソースのみのオプションで、サードパーティ UI ライブラリのライセンス費用を削減した構成に移行
✓モダナイゼーションの加速: 手作業だったベンダーコントロールの置き換えが自動化され、移行期間を短縮
✓追加コストなし: AWS Transform の追加料金なしで利用可能

⚙️ 技術面

✓柔軟な移行パス: オープンソース置換とベンダー継続の 2 つの選択肢から要件に応じて選択
✓可視性の向上: モダナイゼーションプランで変換先とステータスを一覧表示、移行範囲を事前把握
✓Linux 対応への道筋: ASP.NET Core 移行により Windows Server 依存を減らし Linux 上での稼働が可能に

⚠️ デメリット・制約事項

制限事項

✗.svc ファイル (サービスファイル) および .ashx ファイル (汎用ハンドラーファイル) は非対応
✗サービス参照と Web 参照 (reference.map、reference.cs、.wsdl ファイル) は非対応
✗同一プロジェクト内での .aspx (Web Forms) と .cshtml (Razor) の混在は非対応
✗Web Site プロジェクトは非対応 (Web Application プロジェクトへの事前変換が必要)

考慮すべき点

⚠️ベンダーライブラリ継続オプションでは、AWS Transform はコードコメントと手順の挿入までを実施。残りの移植作業は AI コーディングコンパニオンなどで実施する必要がある
⚠️移行先 UI ライブラリのライセンス手配はユーザーがベンダーと直接行う必要がある
⚠️オープンソースコントロールへの置換後は、独自コントロール固有の機能や外観の差異を検証する必要がある

🎯 ユースケース

1️⃣ ベンダー UI コントロール依存の Web Forms アプリの脱 Windows 化

シナリオ: Telerik のグリッドコントロールを多用する ASP.NET Web Forms の社内業務アプリを、Windows Server のサポート終了に合わせて ASP.NET Core (Blazor) へ移行し、Linux コンテナで稼働させたい。

  1. AWS Transform で .NET モダナイゼーションジョブを作成
  2. モダナイゼーションプランで検出された Telerik コントロールの一覧を確認
  3. 既定のネイティブコントロールへ変換オプションを選択
  4. Web Forms から Blazor Server への変換を実行
  5. Next Steps ファイルの残タスクを AI コーディングコンパニオンで対応
✅ 効果: ベンダーライセンス費用を削減しつつ、Linux 上で稼働する Blazor アプリケーションへ移行できる。
2️⃣ ベンダーライブラリの最新版を継続利用する移行

シナリオ: DevExpress コンポーネントの高度な機能に依存した ASP.NET MVC アプリを ASP.NET Core に移行するが、UI の機能性維持のためベンダーライブラリは継続利用したい。

  1. モダナイゼーションプランでベンダーライブラリ継続オプションを選択
  2. AWS Transform が ASP.NET Core 向け DevExpress ライブラリへの移行用コードコメントと Next Steps 手順を挿入
  3. ベンダーと移行先ライブラリのライセンスを契約
  4. AI コーディングコンパニオンで Next Steps に従い移植を完了
✅ 効果: UI の機能性を維持したまま、体系的な手順に沿って ASP.NET Core への移行を完了できる。
3️⃣ VB.NET 製レガシーサイトの一括モダナイゼーション

シナリオ: VB.NET で記述された ASP.NET Web Forms サイトが複数あり、サードパーティ UI コントロールも含まれている。これらを C# の ASP.NET Core アプリケーションに統一したい。

  1. AWS Transform で各サイトのモダナイゼーションジョブを作成
  2. VB.NET の UI 層は自動的に C# へ変換される
  3. サードパーティコントロールはオープンソースコントロールへ置換
  4. 変換後のプロジェクト構造 Components フォルダ配下を確認し、動作検証を実施
✅ 効果: 言語変換 (VB.NET から C#)、フレームワーク変換 (Web Forms から Blazor)、UI コンポーネント置換を 1 つのワークフローで実施できる。

🔗 関連サービス・機能

⚙️ AWS Transform for .NET

.NET Framework アプリケーションを .NET (ASP.NET Core) へ変換するエージェント型モダナイゼーション機能。本アップデートはその UI 層移植機能の強化です。

🤖 Amazon Q Developer

AI コーディングコンパニオンとして、Next Steps ファイルに記載された残作業の移植を支援できます。

🏢 AWS Transform for VMware / メインフレーム

AWS Transform が提供する他のモダナイゼーション領域。Windows 以外のレガシーワークロードにも対応します。

📝 まとめ

AWS Transform のサードパーティ UI コンポーネント移植機能により、DevExpress、Infragistics、Telerik などのベンダー UI ライブラリに依存する ASP.NET サイトのモダナイゼーションにおける大きな障壁が解消されました。 ライセンス不要のオープンソースコントロールへの置換と、ベンダーライブラリ継続の 2 つの移行パスから選択できるため、 コスト削減と機能維持のいずれの方針にも対応できます。

👉 ASP.NET Web サイトの ASP.NET Core 移行を検討している場合は、モダナイゼーションプランでベンダーコントロールの検出結果を確認することから始めることを推奨します。
