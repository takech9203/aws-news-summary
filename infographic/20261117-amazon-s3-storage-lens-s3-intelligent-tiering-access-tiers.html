Amazon S3 / S3 Storage Lens

📊 S3 Storage Lens が S3 Intelligent-Tiering のアクセス階層別メトリクスをサポート

リリース日: 2026 年 11 月 17 日 | 機能: アクセス階層別ストレージメトリクス + Billing and Cost Management へのプレフィックスメトリクス発行

📝 概要

Amazon S3 Storage Lens が、S3 Intelligent-Tiering の各アクセス階層ごとのストレージメトリクスを提供するようになりました。バケット全体を横断して、5 つのアクセス階層それぞれのオブジェクト数とストレージバイト数を確認でき、階層間のデータ移動の追跡、ストレージコストの見積もり、コスト削減効果の測定が可能になります。

あわせて、S3 Storage Lens はプレフィックスメトリクスを AWS Billing and Cost Management に発行できるようになり、S3 の分割コスト配分データを使用して、共有バケットのコストをチームやアプリケーションに配分できるようになりました。

❌ Before: アップデート前の課題
  • ストレージクラス単位の可視化はできたが、S3 Intelligent-Tiering 内部のアクセス階層ごとの内訳を組織横断で確認できなかった
  • コスト削減効果の測定には S3 Inventory や CloudWatch メトリクスの個別集計が必要だった
  • 共有バケットのコスト配分に使えるプレフィックスレベルの課金連携がなかった
✅ After: アップデート後の改善
  • 全バケット横断で各アクセス階層のオブジェクト数とストレージバイト数をダッシュボードとエクスポートで確認可能
  • 階層間のデータ移動の追跡、コスト見積もり、削減効果の測定が容易に
  • プレフィックスメトリクスの Billing and Cost Management 発行で共有バケットのコスト配分が可能に

👥 対象ユーザー: S3 Intelligent-Tiering を大規模に利用する組織のストレージ管理者、FinOps 担当者、コスト最適化を推進する Solutions Architect

S3 Intelligent-Tiering の各アクセス階層に分散したデータを S3 Storage Lens が階層別に集計し、ダッシュボード、メトリクスエクスポート、AWS Billing and Cost Management へ出力する流れ

⚡ 主要機能

1️⃣ アクセス階層別ストレージメトリクス
✓S3 Intelligent-Tiering ストレージクラス内の対象コアストレージメトリクスを、アクセス階層別に分解して提供
✓対象は高頻度アクセス、低頻度アクセス、アーカイブインスタントアクセス、アーカイブアクセス、ディープアーカイブアクセスの 5 階層
✓バケット横断で各階層のオブジェクト数とストレージバイト数を確認可能
2️⃣ ダッシュボードとメトリクスエクスポートへの統合
✓既存メトリクスとともに S3 Storage Lens ダッシュボードに表示
✓メトリクスエクスポートにも含まれるため、Amazon Athena などの分析ツールで詳細分析が可能
✓階層間のデータ移動追跡や、コスト削減効果の測定に活用
3️⃣ AWS Billing and Cost Management へのプレフィックスメトリクス発行
✓S3 の分割コスト配分データで、共有バケットのコストをチームやアプリケーション単位で配分
✓API では CostAndUsageReportsPublish 設定の PrefixLevel で有効化し、MinDepth / MaxDepth でプレフィックスの深さを指定

🔧 技術仕様

🗂️ S3 Intelligent-Tiering アクセス階層

アクセス階層特徴
🔥 高頻度アクセス階層デフォルトの階層。頻繁にアクセスされるオブジェクトを格納
🌤️ 低頻度アクセス階層連続 30 日間アクセスがないオブジェクトが自動的に移動
🧊 アーカイブインスタントアクセス階層連続 90 日間アクセスがないオブジェクトが自動的に移動
📦 アーカイブアクセス階層オプトイン。非同期アクセスが許容されるデータ向け
🏔️ ディープアーカイブアクセス階層オプトイン。長期アーカイブ向けの最低コスト階層

🛠️ 設定方法

✅ 前提条件

✓S3 Storage Lens のダッシュボード設定でアドバンストティアを選択していること (追加料金が発生)
✓s3:PutStorageLensConfiguration および s3:GetStorageLensConfiguration の IAM 権限があること
✓組織全体で集計する場合は、AWS Organizations の信頼されたアクセスが有効化されていること
1
既存の Storage Lens 設定を確認する
Bash AWS CLI 
aws s3control get-storage-lens-configuration \
  --account-id 111122223333 \
  --config-id my-dashboard

現在の S3 Storage Lens 設定を取得し、既存の設定内容をベースにアクセス階層メトリクスの設定を追加します。

2
アクセス階層メトリクスを有効化する
Bash AWS CLI 
aws s3control put-storage-lens-configuration \
  --account-id 111122223333 \
  --config-id my-dashboard \
  --storage-lens-configuration '{
    "Id": "my-dashboard",
    "IsEnabled": true,
    "AccountLevel": {
      "ActivityMetrics": {"IsEnabled": true},
      "BucketLevel": {
        "ActivityMetrics": {"IsEnabled": true}
      }
    },
    "IntAccessTiers": {"IsEnabled": true}
  }'

IntAccessTiers の IsEnabled を true に設定して収集を有効化します。マネジメントコンソールの場合は、ダッシュボード設定のアドバンストティア設定から有効化します。

3
ダッシュボードまたはエクスポートでメトリクスを確認する

S3 コンソールの Storage Lens ダッシュボードで、アクセス階層別にオブジェクト数とストレージバイト数を確認します。メトリクスエクスポート設定済みの場合は CSV / Parquet ファイルにも含まれます。メトリクスは日次集計のため、有効化後の反映には時間がかかる点に注意してください。

💡 メリット

💼 ビジネス面

✓コスト削減効果の定量化: 低コスト階層へのデータ移動量と削減効果を測定できる
✓コスト配分の精緻化: 共有バケットのコストをチームやアプリケーション単位で配分できる
✓ストレージ戦略の意思決定支援: 階層ごとのデータ分布をもとに、アーカイブ階層のオプトイン可否やライフサイクルポリシーの見直しを判断できる

⚙️ 技術面

✓組織横断の可視性: バケット単位の個別調査なしに、組織・アカウント・バケットレベルで一元把握
✓既存ワークフローとの統合: エクスポート (CSV / Parquet) に階層メトリクスが含まれ、Athena などの既存パイプラインをそのまま活用可能
✓運用負荷の軽減: S3 Inventory やカスタムスクリプトによる集計が不要になり、日次で自動更新

⚠️ デメリット・制約事項

🚫 制限事項

✗アクセス階層メトリクスの利用には、アドバンストティア (有料) の設定が必要
✗AWS 中国リージョンおよび AWS GovCloud (US) リージョンでは利用不可
✗メトリクスは日次集計であり、リアルタイムの階層分布は確認できない

🤔 考慮すべき点

⚠アドバンストティアは監視対象オブジェクト数に応じた追加料金が発生。大規模環境では事前にコストを見積もること
⚠ダッシュボード設定ごとに有効化が必要。既存ダッシュボードには自動適用されない
⚠分割コスト配分を利用する場合は、AWS Billing and Cost Management 側の設定もあわせて確認すること

🎯 ユースケース

📈 ユースケース 1: S3 Intelligent-Tiering の削減効果レポート

シナリオ: データレイクの大部分を S3 Intelligent-Tiering に移行した企業が、経営層向けにコスト削減効果を定期報告したい。

実装例: アドバンストティアで IntAccessTiers を有効化 → メトリクスエクスポートを Parquet 形式で S3 に出力 → Athena で階層別ストレージバイト数を月次集計し、高頻度アクセス階層の料金で保存した場合との差分を算出

✅ 効果: 低頻度アクセス階層以下に移動したデータ量と削減額を定量的に示し、ストレージ戦略の妥当性を客観的に報告できる。
🧊 ユースケース 2: アーカイブ階層オプトインの判断

シナリオ: アーカイブアクセス階層とディープアーカイブアクセス階層のオプトインを検討しているが、対象データ量が不明で判断できない。

実装例: アクセス階層メトリクスでアーカイブインスタントアクセス階層のオブジェクト数とバイト数を確認 → 90 日以上アクセスのないデータ量の推移をダッシュボードで追跡 → データ量が十分大きいバケットからアーカイブ階層をオプトイン

✅ 効果: 長期間アクセスされないデータ量を根拠として、取り出し時間とのトレードオフを考慮したオプトイン判断ができる。
💰 ユースケース 3: 共有バケットのチーム別コスト配分

シナリオ: 複数チームがプレフィックスで領域を分けて共有しているバケットのストレージコストを、チームごとに配分したい。

実装例: Storage Lens 設定で CostAndUsageReportsPublish の PrefixLevel を有効化 (MinDepth / MaxDepth でプレフィックス深さを指定) → AWS Billing and Cost Management で S3 の分割コスト配分データを確認 → プレフィックス単位のコストをチーム別にチャージバック

✅ 効果: バケットを分割することなく、プレフィックス単位でチームやアプリケーションへの正確なコスト配分を実現できる。

💵 料金・利用可能リージョン

💰 料金

アクセス階層メトリクスは S3 Storage Lens のアドバンストティアの機能であり、監視対象のオブジェクト数に基づいて課金されます。フリーティアのメトリクスは引き続き無料で利用できます。

最新の料金詳細は S3 の料金ページ を参照してください。

🌍 利用可能リージョン

AWS 中国リージョンと AWS GovCloud (US) リージョンを除く、すべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

  • S3 Intelligent-Tiering: アクセスパターンに応じてオブジェクトを自動的に最適な階層へ移動するストレージクラス。本アップデートの可視化対象
  • AWS Billing and Cost Management: プレフィックスメトリクスの発行先。S3 の分割コスト配分データによるコスト配分を実現
  • Amazon Athena: メトリクスエクスポート (CSV / Parquet) を SQL で分析し、階層別のカスタムレポートを作成可能
  • Amazon CloudWatch: アドバンストティアで Storage Lens メトリクスを発行し、アラームやダッシュボードと連携可能

📌 まとめ

S3 Storage Lens のアクセス階層メトリクスにより、S3 Intelligent-Tiering 内のデータ分布と削減効果を組織横断で定量的に把握できるようになりました。S3 Intelligent-Tiering を利用中でアドバンストティアを有効化している場合は、追加設定でアクセス階層メトリクスを有効化し、コスト最適化の効果測定に活用することを推奨します。

共有バケットを運用している組織は、あわせてプレフィックスメトリクスの Billing and Cost Management 発行によるコスト配分の導入も検討してください。
