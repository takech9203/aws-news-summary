📋 概要

Amazon FSx for Lustre は、Intelligent-Tiering ストレージクラスを使用するファイルシステムで最大 192,000 メタデータ IOPS をサポートするようになりました。従来の上限 12,000 の 16 倍にあたります。メタデータ IOPS は、ファイルシステムが 1 秒あたりに作成、一覧表示、読み取り、削除できるファイル数とディレクトリ数を決定する重要な性能指標です。

FSx for Lustre Intelligent-Tiering は、クラウドで最も低コストかつ唯一のフルエラスティックな Lustre ファイルストレージです。今回のアップデートにより、大量の小さなファイルを扱う 機械学習の研究開発や HPC (ハイパフォーマンスコンピューティング) のようなメタデータ集約型ワークロードで、性能のスケール、結果取得までの時間短縮、ストレージコストの削減を同時に実現できます。

❌ Before (アップデート前)
✗メタデータ IOPS は最大 12,000 に制限され、メタデータ操作がボトルネックになる可能性
✗12,000 を超える場合は高コストな SSD ストレージクラスを選択する必要があった
✗Automatic モードは非サポートで、User-provisioned モードの 6,000 または 12,000 のみ
✅ After (アップデート後)
✓最大 192,000 メタデータ IOPS (従来比 16 倍) をプロビジョニング可能
✓スループットキャパシティに基づく Automatic モードが利用可能に
✓低コストな Intelligent-Tiering のままメタデータ集約型 ML / HPC ワークロードに対応

ファイルの作成・一覧表示・削除などのメタデータ操作はメタデータサーバーが処理し、その処理能力はプロビジョニングされたメタデータ IOPS で決まります。今回のアップデートで、この上限が 12,000 から 192,000 に引き上げられました。

🚀 主要機能

1️⃣ 最大 192,000 メタデータ IOPS のサポート
  • Intelligent-Tiering ファイルシステムのメタデータ IOPS 上限が 12,000 から 192,000 に向上 (16 倍)
  • User-provisioned モードの有効な値は 6,000、12,000、および 12,000 の倍数 (最大 192,000)
  • 12,000 を超えてスケールする際は、FSx for Lustre がメタデータサーバーを追加し、新規メタデータを全サーバーに自動分散
2️⃣ Automatic モードによる自動プロビジョニング
  • ファイルシステムのスループットキャパシティに基づいてメタデータ IOPS を自動プロビジョニング
  • 4,000〜8,000 MBps で 6,000 IOPS、12,000〜44,000 MBps で 12,000 IOPS、48,000 MBps 以上では 24,000 MBps ごとに 12,000 IOPS を提供
3️⃣ 無停止でのメタデータ性能スケーリング
  • コンソール、AWS CLI、API からメタデータ構成を更新可能で、増加した性能は数分以内に利用可能
  • スケーリング中にファイルシステムが数分間利用できない場合があるが、クライアントのファイル操作は透過的に再試行され、完了後に成功する
  • CloudWatch の Metadata IOPS Utilization グラフや詳細メトリクスで使用状況をモニタリング可能

🔧 技術仕様

📊 メタデータ IOPS と操作レート

プロビジョニングしたメタデータ IOPS 1 あたりに実行できる操作数は以下のとおりです。

操作の種類プロビジョニングされたメタデータ IOPS あたりの 1 秒間の操作数
ファイルの作成、オープン、クローズ2
ファイルの削除1
ディレクトリの作成、名前変更0.1
ディレクトリの削除0.2

⚙️ Intelligent-Tiering ファイルシステムの Automatic モード

4,000〜8,000 MBps6,000
12,000〜44,000 MBps12,000
48,000 MBps 以上24,000 MBps ごとに 12,000 IOPS

🎚️ User-provisioned モードの有効な値

ストレージクラス有効なメタデータ IOPS 値
Intelligent-Tiering6,000、12,000、および 12,000 の倍数 (最大 192,000)
SSD1,500、3,000、6,000、12,000、および 12,000 の倍数 (最大 192,000)

🛠️ 設定方法

✅ 前提条件

→Persistent 2 デプロイメントタイプおよび Intelligent-Tiering ストレージクラスを使用する
→Lustre バージョン 2.15 のファイルシステムであること (メタデータ構成は 2.15 ファイルシステムのみサポート)
→2026 年 11 月 5 日以降に作成された Intelligent-Tiering ファイルシステムであること (それ以前のものは User-provisioned モードの 6,000 または 12,000 のみサポート)

ステップ 1: メタデータ IOPS を指定してファイルシステムを作成

BashAWS CLI - ファイルシステム作成
aws fsx create-file-system \
  --file-system-type LUSTRE \
  --file-system-type-version 2.15 \
  --storage-type INTELLIGENT_TIERING \
  --subnet-ids subnet-0123456789abcdef0 \
  --lustre-configuration "DeploymentType=PERSISTENT_2,ThroughputCapacity=4000,MetadataConfiguration={Mode=USER_PROVISIONED,Iops=96000}"

User-provisioned モードで 96,000 メタデータ IOPS をプロビジョニングしています。Automatic モードを使用する場合は MetadataConfiguration={Mode=AUTOMATIC} を指定します。

ステップ 2: 既存ファイルシステムのメタデータ IOPS を増加

BashAWS CLI - メタデータ IOPS 更新
aws fsx update-file-system \
  --file-system-id fs-0123456789abcdef0 \
  --lustre-configuration "MetadataConfiguration={Mode=USER_PROVISIONED,Iops=192000}"

メタデータ性能の増加リクエストは、前回のリクエストから 6 時間以上の間隔を空ける必要があります。

ステップ 3: メタデータ構成の確認

BashAWS CLI - メタデータ構成の確認
aws fsx describe-file-systems \
  --file-system-ids fs-0123456789abcdef0 \
  --query "FileSystems[0].LustreConfiguration.MetadataConfiguration"

現在のメタデータ構成 (モードとプロビジョニング済みメタデータ IOPS) を確認できます。コンソールではファイルシステム詳細ページの Summary パネルでも確認可能です。

💡 メリット

💼 ビジネス面

✓コスト効率の向上: 高コストな SSD ストレージクラスを選択する必要がなくなり、低コストな Intelligent-Tiering のままメタデータ集約型ワークロードを実行できる
✓結果取得までの時間短縮: メタデータ操作のボトルネックが解消され、ML 研究や HPC ワークロードの処理時間を短縮できる
✓スモールスタートが可能: Automatic モードで開始し、ワークロードの成長に合わせて User-provisioned モードで段階的にスケールできる

⚙️ 技術面

✓16 倍のメタデータ性能: 最大 192,000 メタデータ IOPS により、1 秒あたり最大 384,000 のファイル作成・オープン・クローズ操作に対応可能
✓無停止スケーリング: エンドユーザーやアプリケーションへの影響を最小限に抑えながらメタデータ IOPS を増加可能
✓可視性の向上: Metadata IOPS Utilization グラフや、ファイル・ディレクトリの作成、stat、読み取り、削除などの詳細な CloudWatch メトリクスで使用状況を把握できる

⚠️ デメリット・制約事項

🚫 制限事項

✗2026 年 11 月 5 日より前に作成された Intelligent-Tiering ファイルシステムは対象外 (User-provisioned モードの 6,000 または 12,000 のみサポート)。バックアップから復元したファイルシステムは、バックアップ元のサポート内容を継承する
✗メタデータ IOPS は増加のみ可能で、減少はできない
✗メタデータ性能の増加リクエストは前回のリクエストから 6 時間以上の間隔が必要
✗Automatic モードがプロビジョニングする数より少ないメタデータ IOPS は指定できない

🤔 考慮すべき点

→12,000 を超えてスケールすると新しいメタデータサーバーが追加されるが、スケール前に作成された既存のメタデータやサブディレクトリは元のサーバーに残り、それらのメタデータ IOPS は増加しない
→スループットキャパシティを増加すると、ファイルシステムの最小メタデータ IOPS が増加する場合がある
→スケーリング中、ファイルシステムが数分間利用できない場合がある (クライアントの操作は透過的に再試行される)
→Intelligent-Tiering ファイルシステムでは、Automatic モードでプロビジョニングされる分を含むすべてのメタデータ IOPS に課金される (SSD ファイルシステムは Automatic モードの提供分を超えた分のみ課金)

🎯 ユースケース

🤖 ユースケース 1: 機械学習の学習データ処理

シナリオ: 数百万件の小さな画像ファイルやテキストファイルで構成される学習データセットを、多数の GPU インスタンスから並列に読み込む。エポックごとのファイルオープンやディレクトリ一覧の操作がボトルネックになっている。

Bashメタデータ IOPS を 96,000 に増加
aws fsx update-file-system \
  --file-system-id fs-0123456789abcdef0 \
  --lustre-configuration "MetadataConfiguration={Mode=USER_PROVISIONED,Iops=96000}"

効果: 1 秒あたりのファイルオープン・クローズ操作数が大幅に向上し、GPU の待機時間を削減して学習ジョブ全体の実行時間を短縮できる。

🧬 ユースケース 2: HPC シミュレーションの結果出力

シナリオ: 気象シミュレーションやゲノム解析などの HPC ワークロードで、多数の計算ノードが同時に大量の中間ファイルや結果ファイルを作成・削除する。

BashCloudWatch メトリクスで必要な IOPS を見積もる
# CloudWatch メトリクスでメタデータ操作の内訳を確認し、必要な IOPS を見積もる
aws cloudwatch get-metric-statistics \
  --namespace AWS/FSx \
  --metric-name DiskWriteOperations \
  --dimensions Name=FileSystemId,Value=fs-0123456789abcdef0 \
  --start-time 2026-11-04T00:00:00Z \
  --end-time 2026-11-05T00:00:00Z \
  --period 3600 \
  --statistics Sum

効果: メタデータ操作の実測値に基づいて適切なメタデータ IOPS をプロビジョニングし、計算ノードのスケールアウトに合わせてファイルシステムのメタデータ性能を拡張できる。

🔬 ユースケース 3: ホット・コールドデータが混在する研究環境

シナリオ: 研究部門の共有ストレージとして、アクセス頻度の高いデータと長期間アクセスされないアーカイブデータが混在する大規模ファイルシステムを低コストで運用したい。

BashAutomatic モードでファイルシステムを作成
aws fsx create-file-system \
  --file-system-type LUSTRE \
  --file-system-type-version 2.15 \
  --storage-type INTELLIGENT_TIERING \
  --subnet-ids subnet-0123456789abcdef0 \
  --lustre-configuration "DeploymentType=PERSISTENT_2,ThroughputCapacity=4000,MetadataConfiguration={Mode=AUTOMATIC}"

効果: フルエラスティックな Intelligent-Tiering ストレージでコストを抑えながら、Automatic モードでメタデータ IOPS を自動管理し、必要に応じて User-provisioned モードで最大 192,000 IOPS までスケールできる。

💰 料金

Intelligent-Tiering ファイルシステムでは、Automatic モードでプロビジョニングされる分を含む、すべてのメタデータ IOPS に対して課金されます (SSD ファイルシステムでは Automatic モードの提供分を超えてプロビジョニングした分のみ課金)。増加したメタデータ性能に対する課金は、その性能が利用可能になった時点から開始されます。 具体的な料金はリージョンごとに異なるため、Amazon FSx for Lustre 料金ページを参照してください。

🌍 利用可能リージョン

Intelligent-Tiering ストレージクラスが提供されているすべての AWS リージョンで、新規に作成する FSx for Lustre Intelligent-Tiering ファイルシステムにて利用可能です。 対象リージョンの詳細は AWS リージョン別サービス一覧を参照してください。

🔗 関連サービス・機能

🖥️ Amazon EC2 / Elastic Fabric Adapter

高スループットが必要な場合、EFA 対応ファイルシステムによりクライアントあたり最大 700 Gbps のスループットを実現可能。

📈 Amazon CloudWatch

Metadata IOPS Utilization やファイル・ディレクトリ操作の詳細メトリクスにより、メタデータ性能の使用状況をモニタリング。

S3 バケットとのデータリポジトリ関連付けにより、S3 上のデータセットを Lustre ファイルシステムとして処理可能。

📝 まとめ

低コストでフルエラスティックな FSx for Lustre Intelligent-Tiering ファイルシステムが、SSD ファイルシステムと同等の最大 192,000 メタデータ IOPS をサポートするようになりました。 大量の小さなファイルを扱う ML 研究や HPC ワークロードを運用している場合、SSD ストレージクラスから Intelligent-Tiering への移行によるコスト最適化を検討する価値があります。 既存の Intelligent-Tiering ファイルシステムは対象外のため、高いメタデータ性能が必要な場合は新規ファイルシステムの作成を検討してください。
