AWS Backup Amazon FSx for NetApp ONTAP

🔒 論理的エアギャップボールトが
FSx for NetApp ONTAP をサポート

📅 リリース日: 2026 年 9 月 28 日 | イミュータブルなバックアップ保護とクロスアカウント直接復元

📋 概要

AWS Backup の論理的エアギャップボールト (Logically Air-Gapped Vault) が Amazon FSx for NetApp ONTAP をサポートしました。デフォルトでロックされた変更不可能 (イミュータブル) なバックアップを保存する特殊なボールトで、AWS 所有キーまたはカスタマーマネージドキーによる暗号化で分離されます。

バックアッププランのプライマリターゲットまたはコピー先として FSx for NetApp ONTAP のバックアップを保存でき、AWS RAM によるボールト共有と事前コピーなしの直接リストアにより、データ損失発生時の復旧時間 (RTO) を短縮できます。ランサムウェア対策や BCP 要件を持つ組織にとって重要なアップデートです。

❌ Before: アップデート前の課題
✗FSx for NetApp ONTAP のバックアップは標準バックアップボールトでの保護に限られていた
✗Vault Lock コンプライアンスモードによるデフォルトの不変性保護の適用には追加の設定が必要だった
✗アカウント侵害時に別アカウントから直接復元する手段が限られ、復旧前にバックアップのコピーが必要だった
✅ After: アップデート後の改善
✓プライマリターゲットまたはコピー先として論理的エアギャップボールトに保存可能に
✓デフォルトで Vault Lock コンプライアンスモードが有効なボールトでイミュータブルに保護
✓AWS RAM 共有と直接復元により事前コピー不要で RTO を短縮
✓Multi-party approval 統合でボールト所有アカウントにアクセスできない場合でも復旧可能

FSx for NetApp ONTAP のバックアップを論理的エアギャップボールトに保存し、AWS RAM で共有した復旧用アカウントから直接リストアするフローを示しています。ボールトは Vault Lock コンプライアンスモードと暗号化で保護されます。

⚙️ 主要機能

1️⃣ 論理的エアギャップボールトへの FSx for NetApp ONTAP バックアップ保存
✓バックアッププランのプライマリターゲットとして直接バックアップを保存可能
✓既存ボールトからのコピー先としても指定可能
✓同一アカウント内、または別アカウント・別リージョンのボールトへの保存に対応
2️⃣ デフォルトの不変性保護
✓すべての論理的エアギャップボールトは Vault Lock コンプライアンスモードでロック
✓バックアップはイミュータブルとなり、保持期間中の削除や変更から保護
✓AWS 所有キー (デフォルト) またはカスタマーマネージド KMS キーで暗号化。キータイプは API とコンソールで確認可能
3️⃣ AWS RAM によるボールト共有と直接復元
✓組織内外の個別の AWS アカウントとボールトを共有可能
✓共有先アカウントは事前コピーなしで直接リストアジョブを開始可能
✓データ損失からの復旧や復元テスト (Restore Testing) に活用可能
4️⃣ Multi-party approval によるアクセス保護
✓多者承認 (MPA) との統合により、アカウント侵害時でもボールトへのアクセスを保護
✓ボールト所有アカウントにアクセスできない状況でも、承認チームの承認を経てバックアップを復旧可能
🔐Vault Lockコンプライアンスモードで常時ロック
🔑暗号化分離AWS 所有キーまたは CMK
✅多者承認侵害時の復旧経路を確保

STEP 1論理的エアギャップボールトの作成

Bash ボールト作成 (最小・最大保持期間の指定が必須) 
aws backup create-logically-air-gapped-backup-vault \
  --backup-vault-name my-lag-vault \
  --min-retention-days 7 \
  --max-retention-days 35

最小保持期間 (7 日以上) と最大保持期間の指定が必須です。カスタマーマネージド KMS キーを使用する場合は --encryption-key-arn パラメータを追加します。指定しない場合は AWS 所有キーが使用されます。

STEP 2バックアッププランでボールトをターゲットに指定

Bash バックアッププラン作成 
aws backup create-backup-plan \
  --backup-plan '{
    "BackupPlanName": "fsx-ontap-lag-plan",
    "Rules": [{
      "RuleName": "daily-to-lag-vault",
      "TargetBackupVaultName": "my-lag-vault",
      "ScheduleExpression": "cron(0 5 * * ? *)",
      "Lifecycle": {"DeleteAfterDays": 30}
    }]
  }'

FSx for NetApp ONTAP のファイルシステムをリソース割り当てで対象に追加すると、スケジュールに従いバックアップがボールトに直接保存されます。既存プランのコピー先として指定することも可能です。

STEP 3AWS RAM でボールトを共有

Bash 復旧用アカウントとのリソース共有 
aws ram create-resource-share \
  --name lag-vault-share \
  --resource-arns arn:aws:backup:us-east-1:123456789012:backup-vault:my-lag-vault \
  --principals 210987654321

共有先アカウントは 12 時間以内に招待を承諾する必要があります。承諾後、共有先アカウントからボールト内のバックアップを直接リストアできます。

⚖️ メリットと制約事項

👍 ビジネス面のメリット

✓ランサムウェア対策の強化: イミュータブルなバックアップで悪意ある削除や暗号化からデータを保護
✓復旧時間の短縮: 直接復元により事前のバックアップコピーが不要となり RTO を短縮
✓コンプライアンス対応: デフォルトの不変性保護により規制要件や DR 要件への対応が容易に

🔧 技術面のメリット

✓多層防御の実現: 暗号化による分離、Vault Lock、Multi-party approval の組み合わせ
✓クロスアカウント復旧の簡素化: AWS RAM 共有で柔軟な復旧体制を構築
✓既存バックアップ戦略との統合: ターゲット指定だけで既存運用に組み込み可能

⚠️ 制限事項

✗最小保持期間は 7 日以上が必須。短期間のみ保持するバックアップには利用不可
✗共有は個別のアカウント ID 単位のみ。組織全体や OU 単位での共有は不可
✗Vault Lock はコンプライアンスモード固定で、解除や緩和は不可
✗一部リージョン (マレーシア、カルガリーなど) では利用不可

💭 考慮すべき点

→バックアップは AWS Backup サービス所有アカウントに保存されるため、CloudTrail ログ上では組織外への共有として記録される
→ストレージ料金は標準ボールトと異なるため、料金ページで事前確認が必要
→保持期間の範囲外のバックアップはコピー不可。既存プランのライフサイクル設定との整合性を確認

🎯 ユースケース

🦠 ユースケース 1: ランサムウェア対策としてのイミュータブルバックアップ

シナリオ: FSx for NetApp ONTAP 上で基幹業務のファイル共有を運用しており、ランサムウェア攻撃によるバックアップ削除リスクに備えたい。

実装例: 最小保持期間 7 日、最大保持期間 90 日のボールトを作成 → 既存バックアッププランにコピールールを追加してコピー先に指定 → Multi-party approval の承認チームを設定し復旧経路を確保。

効果: 認証情報が侵害されても Vault Lock コンプライアンスモードによりバックアップの削除を防止し、確実な復旧ポイントを維持できる。

🏥 ユースケース 2: クロスアカウントでの迅速な災害復旧

シナリオ: 本番アカウントで障害やインシデントが発生した際に、専用の復旧アカウントから FSx for NetApp ONTAP のデータを迅速に復元したい。

実装例: 本番アカウントでボールトを作成しバックアップを保存 → AWS RAM で復旧アカウントと共有 → インシデント発生時、復旧アカウントから直接リストアジョブを実行。

効果: バックアップを事前にコピーする時間が不要となり、復旧時間 (RTO) を大幅に短縮できる。

🧪 ユースケース 3: 定期的な復元テストによる復旧体制の検証

シナリオ: コンプライアンス要件として、バックアップからの復旧可能性を定期的に検証する必要がある。

実装例: ボールトをテスト用アカウントと AWS RAM で共有 → AWS Backup の復元テスト機能で共有ボールト内のバックアップから定期的に復元 → 復元結果を監査レポートとして記録。

効果: 本番環境に影響を与えることなく、実際の復旧手順とバックアップの整合性を継続的に検証できる。

💰 料金

論理的エアギャップボールトに保存されたバックアップのストレージ料金は、標準のバックアップストレージとは別の料金体系が適用されます。FSx for NetApp ONTAP のバックアップを論理的エアギャップボールトに保存する場合の料金は、AWS Backup の料金ページで確認できます。

詳細は AWS Backup 料金ページ を参照してください。

🌏 利用可能リージョン

論理的エアギャップボールトと Amazon FSx for NetApp ONTAP の両方が利用可能なすべての AWS リージョンで利用できます。

⚠️ 論理的エアギャップボールトが利用できないリージョン

アジアパシフィック (マレーシア)、カナダ西部 (カルガリー)、メキシコ (中部)、アジアパシフィック (タイ)、アジアパシフィック (台北)、アジアパシフィック (ニュージーランド)、中国 (北京)、中国 (寧夏)、AWS GovCloud (US-East)、AWS GovCloud (US-West)

最新のリージョン別・リソース別の対応状況は 機能の利用可能状況ドキュメント を参照してください。

🔗 関連サービス・機能

→Amazon FSx for NetApp ONTAP: 今回のアップデートで保護対象となったフルマネージドの NetApp ONTAP ファイルストレージサービス
→AWS Resource Access Manager (AWS RAM): ボールトを他のアカウントと共有するために使用するリソース共有サービス
→AWS Backup Vault Lock: 論理的エアギャップボールトにデフォルトで適用されるコンプライアンスモードの不変性保護機能
→Multi-party approval: アカウント侵害時にもボールトへのアクセスを保護する多者承認機能
→AWS Key Management Service (AWS KMS): ボールトの暗号化に使用するカスタマーマネージドキーを管理するサービス

💡 まとめ

AWS Backup の論理的エアギャップボールトが Amazon FSx for NetApp ONTAP に対応したことで、ONTAP ワークロードのバックアップをイミュータブルに保護し、クロスアカウントでの迅速な復旧体制を構築できるようになりました。

FSx for NetApp ONTAP を利用している組織は、ランサムウェア対策や BCP の観点から、既存のバックアッププランに論理的エアギャップボールトの追加を検討することを推奨します。まずは開発環境でボールトの作成と AWS RAM による共有、直接復元のフローを検証するとよいでしょう。
