📋 概要

AWS Secrets Manager のマネージド外部シークレット機能に、Datadog のベンダーキーおよび Snowflake PAT のサポートが追加。サードパーティサービスの認証情報を AWS で一元管理し、Lambda 関数不要で自動ローテーションを実現。

Datadog

API Key / Application Key / Admin Key の 3 タイプに対応。2 キー交互パターンでゼロダウンタイムローテーション

Snowflake PAT

プログラマティックアクセストークン。キーペア認証でアトミックなトークン生成。猶予期間設定可能

既存パートナー: BigID, Confluent Cloud, MongoDB Atlas, Salesforce

⚡ 主要機能

🐶 Datadog ベンダーキー管理

DatadogApiKey: 32 文字の 16 進 API キーを自動ローテーション。2 キー交互パターンでゼロダウンタイム

DatadogApplicationKey: サービスアカウント所有のアプリケーションキーのローテーション

DatadogAdminKey: API キーとアプリケーションキーのペアを同時にローテーション。自己ローテーション対応

❄️ Snowflake プログラマティックアクセストークン

Snowflake ネイティブ認証 (キーペア認証) を使用した PAT ローテーション

ALTER USER ... ROTATE PAT コマンドによるアトミックなトークン生成

設定可能な猶予期間 (0-720 時間) で旧トークンの段階的な無効化が可能

🚀 Lambda 不要のマネージドローテーション

カスタム Lambda 関数の作成・デプロイ・管理が一切不要

コンソールでシークレット作成時にローテーションが自動的に有効化

AWS CloudTrail による全操作の完全な監査証跡

🛠️ 設定方法

前提条件

1. AWS Secrets Manager へのアクセス権限を持つ IAM ロールまたはユーザー
2. Datadog: サービスアカウントと管理用 API キー + アプリケーションキー (スコープ: api_keys_write, api_keys_delete)
3. Snowflake: キーペア認証が設定されたユーザーと既存の PAT

Datadog API キーのローテーション設定

Bash Datadog API キーシークレットの作成とローテーション 
# シークレット作成
aws secretsmanager create-secret \
  --name "datadog/api-key" \
  --secret-string '{
    "apiKey": "your-32-char-hex-api-key",
    "apiKeyId": "api-key-uuid"
  }' \
  --secret-type DatadogApiKey

# ローテーション設定
aws secretsmanager rotate-secret \
  --secret-id "datadog/api-key" \
  --rotation-rules '{"AutomaticallyAfterDays": 30}' \
  --rotation-metadata '{"adminSecretArn": "arn:aws:secretsmanager:us-east-1:111122223333:secret:datadog/admin-key-AbCdEf"}' \
  --role-arn "arn:aws:iam::111122223333:role/SecretsManagerRotationRole"

Snowflake PAT のローテーション設定

Bash Snowflake PAT シークレットの作成とローテーション 
# シークレット作成
aws secretsmanager create-secret \
  --name "snowflake/pat" \
  --secret-string '{
    "account": "myorg-myaccount",
    "user": "my_user",
    "privateKey": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----",
    "passphrase": "",
    "patTokenName": "my_pat_token",
    "patTokenValue": "current-pat-value"
  }' \
  --secret-type SnowflakePat

# ローテーション設定 (14日ごと、猶予期間24時間)
aws secretsmanager rotate-secret \
  --secret-id "snowflake/pat" \
  --rotation-rules '{"AutomaticallyAfterDays": 14}' \
  --rotation-metadata '{"daysToExpiry": "15", "expireOldTokenAfterHours": "24"}' \
  --role-arn "arn:aws:iam::111122223333:role/SecretsManagerRotationRole"

IAM 信頼ポリシー例

JSON Secrets Manager サービスプリンシパル用信頼ポリシー

⚠️ 制限事項・注意点

制限事項

✗ Datadog の API キー/アプリケーションキーはサービスアカウント所有のものに限定 (個人ユーザー所有は非対応)
✗ Snowflake PAT のローテーションには事前にキーペア認証の設定が必要
✗ Datadog Admin Key には api_keys_write, api_keys_delete, org_app_keys_read, org_app_keys_write, service_account_write スコープが必要

考慮すべき点

⚠ Datadog の 2 シークレットアーキテクチャでは Admin シークレットの管理も必要 - 権限の階層構造設計が重要
⚠ Snowflake: daysToExpiry はローテーションスケジュールより長い値に設定が必要 (ローテーション間隔 < トークン有効期限)
⚠ IP 制限設定時、AWS の IP レンジは変更される可能性があるため定期的な更新が必要

💡 ユースケース

🏢 マルチサービス監視基盤の認証情報管理

シナリオ: Datadog でマルチアカウント AWS 環境を監視。各アカウントに Datadog API キーが配布され、セキュリティポリシーにより 30 日ごとのキーローテーションが必要

効果: 数十アカウントの Datadog API キーの手動ローテーションが不要になり、運用チームの負荷を大幅に削減

🔄 データパイプラインにおける Snowflake アクセス管理

シナリオ: AWS Glue や Lambda から Snowflake にデータロードするパイプラインで PAT 認証を使用。トークンの定期更新が必要だがパイプラインの中断は許容できない

効果: 48 時間の猶予期間により、分散パイプラインコンポーネントが新トークンをキャッシュから取得する時間を確保しつつセキュリティ要件を充足

🔑 Datadog 管理キーの自己ローテーション

シナリオ: セキュリティチームが Datadog の管理用認証情報自体もローテーションしたい。管理キー侵害時の影響範囲最小化のため 90 日ごとの自動ローテーション設定

効果: 管理キー自体のローテーションにより認証情報の侵害リスクを全階層で低減。自己ローテーションモードで追加シークレット管理不要

AWS Secrets Manager の標準料金が適用。マネージド外部シークレットやローテーション機能に対する追加料金なし。
