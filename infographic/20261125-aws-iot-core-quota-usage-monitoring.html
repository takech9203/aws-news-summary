AWS IoT Core

📊 Service Quotas コンソールでクォータと使用状況を可視化

📅 リリース日: 2026 年 11 月 25 日 | 💰 追加料金なし

💡 概要

AWS IoT Core は、最も利用頻度の高いサービスクォータとその現在の使用状況を AWS Service Quotas コンソールに公開するようになりました。 データプレーン API (デバイスメッセージング) とコントロールプレーン API (リソース管理) の両方をカバーし、 CloudWatch 使用量メトリクスでアラームを構築すれば、スロットリング発生前に検知・対処できます。

❌ Before: アップデート前の課題
✗クォータと使用状況がコンソールで可視化されておらず、使用率を把握できない
✗使用状況を知るには AWS サポートへの問い合わせが必要
✗上限接近を検知する標準的な仕組みがなく、突発的なスロットリングによる障害リスク
✅ After: アップデート後の改善
✓Service Quotas コンソールでクォータと使用状況をセルフサービスで確認
✓CloudWatch アラームでスロットリング発生前に通知を受信
✓フリート成長に合わせてクォータ引き上げをプロアクティブに申請

AWS IoT Core がクォータと使用状況を Service Quotas コンソールと CloudWatch に公開し、運用担当者はアラーム通知を受けてスロットリング発生前にクォータ引き上げを申請できます

⚙️ 主要機能

🗂️ Service Quotas コンソールでのクォータ表示

→ 最も利用頻度の高いサービスクォータと現在の使用状況データをコンソールに表示

→ AWS サポートに問い合わせることなく、セルフサービスで使用率を把握できる

🔀 データプレーンとコントロールプレーンの両方をカバー

→ データプレーン API (デバイスメッセージング) のクォータと使用状況を確認

→ コントロールプレーン API (リソース管理) のクォータと使用状況を確認

🚨 CloudWatch 使用量メトリクスによるアラーム

→ 使用量がクォータ上限に近づいた際に通知するアラームを構築

→ スロットリング発生前にクォータ引き上げなどの対処が可能

🔧 設定方法

📌 前提条件: AWS IoT Core を利用中であること、Service Quotas コンソールおよび CloudWatch へのアクセス権限 (IAM ポリシー) があること
1
Service Quotas コンソールで AWS IoT Core を選択

AWS マネジメントコンソールから Service Quotas コンソールを開き、サービス一覧から「AWS IoT Core」を選択。各クォータの適用値と使用状況が表示されます。

2
CLI でクォータを確認
Bash 適用中のクォータ一覧を取得 
# AWS IoT Core の適用中のクォータ一覧を取得
aws service-quotas list-service-quotas \
  --service-code iotcore

クォータ名、適用値、引き上げ可否などの一覧を Service Quotas API で取得できます。

3
使用状況に基づくアラームの作成

Service Quotas コンソールで対象クォータを選択し、CloudWatch アラームの作成画面からしきい値 (例: クォータ使用率 80%) を設定。しきい値超過で通知が送信されます。

4
クォータ引き上げの申請

使用量が上限に近づいている場合は、Service Quotas コンソールから引き上げをリクエスト。デバイスフリートの成長計画に合わせた事前申請が推奨されます。

⚖️ メリットと制約事項

✅ メリット

✓サポート問い合わせの削減: 使用状況の問い合わせが不要になり運用工数を削減
✓サービス停止リスクの低減: デバイス接続障害やメッセージ欠落を未然に防止
✓追加コストなし: 本機能は追加料金なしで利用可能
✓オブザーバビリティ向上: データ/コントロールプレーン両方を一元的に可視化
✓キャパシティプランニング: 実使用データに基づくクォータ引き上げ計画

⚠️ 制約・考慮点

⚠公開されるのは「最も利用頻度の高い」クォータで、すべてのクォータが対象とは明記されていない
⚠引き上げ不可のクォータ (MQTT ペイロードサイズなど) は、可視化されても上限変更はできない
⚠アラームのしきい値は引き上げ申請のリードタイムを考慮し、余裕を持った値 (例: 70-80%) に設定
⚠接続あたり・クライアント ID あたりのきめ細かい制限は、引き続きアプリケーション設計側での考慮が必要

🎯 ユースケース

📈 1. デバイスフリート拡大時のキャパシティプランニング

シナリオ: コネクテッドカーやスマートホーム事業でデバイス数が毎月増加。接続数や Publish レートがいつクォータに到達するかを把握したい。

Bash 定期確認 
# 現在のクォータと使用状況をコンソールまたは CLI で定期確認
aws service-quotas list-service-quotas --service-code iotcore
💡 効果: 使用状況のトレンドを把握し、上限到達前に計画的にクォータ引き上げを申請できる
🚨 2. スロットリング発生前のアラート通知

シナリオ: ファームウェア一斉更新やキャンペーン時に接続・メッセージ量が急増し、過去にスロットリングによる障害が発生したことがある。

💰 料金と利用可能リージョン

✓料金: 本機能は追加料金なし。AWS IoT Core、Service Quotas の利用自体に追加費用は発生しない。CloudWatch アラーム作成時は CloudWatch の標準料金が適用される。
⚠リージョン: 公式発表では対象リージョンの明記なし。利用するリージョンの Service Quotas コンソールで AWS IoT Core を選択し、クォータと使用状況が表示されることを確認する。

🔗 関連サービス・機能

📈 Amazon CloudWatch
使用量メトリクスに基づくアラームを構築し、クォータ上限接近を通知
📱 AWS IoT Device Management
大規模デバイスフリートの管理。フリート拡大時のクォータ計画と併せて利用

📝 まとめ

AWS IoT Core のクォータと使用状況が Service Quotas コンソールで可視化され、 従来は AWS サポートへの問い合わせが必要だった使用率の把握がセルフサービスで可能になりました。 CloudWatch アラームと組み合わせることで、スロットリング発生前の検知とプロアクティブなクォータ引き上げが実現します。

🎯 推奨アクション: IoT ワークロードを運用しているチームは、主要クォータの使用状況確認とアラーム設定をまず実施しましょう。
