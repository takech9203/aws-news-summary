AWS Backup

🛡️ AWS Backup がアジアパシフィック (ニュージーランド) リージョンで Amazon FSx をサポート

4 種類すべての FSx ファイルシステムを単一サービスで一元的にデータ保護
📅 リリース日: 2026 年 10 月 14 日 🌏 対象リージョン: アジアパシフィック (ニュージーランド) 🗄️ 対象: Amazon FSx 全 4 タイプ

📝 概要

AWS Backup が、アジアパシフィック (ニュージーランド) リージョンにおいて Amazon FSx ファイルシステムのサポートを開始しました。 対象は FSx for Lustre、FSx for NetApp ONTAP、FSx for OpenZFS、FSx for Windows File Server の 4 種類すべてです。

ポリシーベースのバックアッププランによるスケジュール設定と保持ルールの適用、暗号化されたバックアップボールトへの保存、必要なときのファイルシステムの復元を、 単一の集中管理されたサービスから実行できます。ニュージーランドでワークロードを運用する企業や、データレジデンシー要件のある組織にとって、 事業継続性、災害対策、規制コンプライアンスの要件を満たすための重要なアップデートです。

⚡ FSx for Lustre
HPC や機械学習向けの高性能ファイルシステム
🔷 FSx for NetApp ONTAP
マルチプロトコル対応の ONTAP ベースファイルシステム
🐧 FSx for OpenZFS
OpenZFS ベースの NFS 対応ファイルシステム
🪟 FSx for Windows File Server
SMB プロトコル対応の Windows ネイティブファイルシステム

❌ Before: アップデート前の課題

✗FSx を AWS Backup で管理できず、FSx ネイティブのバックアップ機能を個別に設定する必要があった
✗EC2 や EBS など他の AWS リソースと FSx のバックアップポリシーを統一的に管理できなかった
✗同リージョン内でコンプライアンス要件に対応したバックアップの一元管理と監査が難しかった

✅ After: アップデート後の改善

✓FSx ファイルシステム 4 種類すべてを AWS Backup で一元管理できるようになった
✓ポリシーベースのバックアッププランで、スケジュール設定と保持ルールの適用を自動化
✓暗号化ボールトへの保存とファイルシステムの復元を単一サービスから実行可能に

AWS Backup のバックアッププランがリージョン内の 4 種類の FSx ファイルシステムを自動的にバックアップし、暗号化されたバックアップボールトに復旧ポイントを保存します。 他の AWS リソースと合わせて単一のポリシーで一元管理できます。

⚙️ 主要機能

🗄️ 4 種類の FSx ファイルシステムのサポート

Lustre (HPC / 機械学習向け)、NetApp ONTAP (マルチプロトコル)、OpenZFS (NFS 対応)、Windows File Server (SMB 対応) の全タイプが AWS Backup の保護対象に。

📋 ポリシーベースのバックアップ管理

バックアッププランによるスケジュール自動化、保持ルールによるライフサイクル管理、タグベースのリソース割り当てによる柔軟な保護対象の指定が可能。

🔐 暗号化ボールトへの保存と復元

バックアップは暗号化されたバックアップボールトに保存され、必要なときにファイルシステムを復元可能。事業継続性、災害対策、規制コンプライアンスの要件に単一サービスで対応。

ステップ 1: バックアップボールトの作成

Bash バックアップボールトの作成 
aws backup create-backup-vault \
  --backup-vault-name fsx-backup-vault \
  --region ap-southeast-6

復旧ポイントはこのボールトに暗号化されて保存されます。

ステップ 2: バックアッププランの作成

Bash 日次バックアッププラン (保持期間 35 日) 
aws backup create-backup-plan \
  --region ap-southeast-6 \
  --backup-plan '{
    "BackupPlanName": "fsx-daily-backup",
    "Rules": [
      {
        "RuleName": "DailyBackup",
        "TargetBackupVaultName": "fsx-backup-vault",
        "ScheduleExpression": "cron(0 17 * * ? *)",
        "StartWindowMinutes": 60,
        "Lifecycle": {
          "DeleteAfterDays": 35
        }
      }
    ]
  }'

毎日定時に実行されるプランを作成します。保持期間 35 日を過ぎた復旧ポイントは自動的に削除されます。

ステップ 3: FSx ファイルシステムをバックアッププランに割り当て

Bash リソースの割り当て 
aws backup create-backup-selection \
  --region ap-southeast-6 \
  --backup-plan-id <backup-plan-id> \
  --backup-selection '{
    "SelectionName": "fsx-selection",
    "IamRoleArn": "arn:aws:iam::123456789012:role/service-role/AWSBackupDefaultServiceRole",
    "Resources": [
      "arn:aws:fsx:ap-southeast-6:123456789012:file-system/*"
    ]
  }'

リソース ARN の指定のほか、タグベースでの割り当ても可能です。対象のファイルシステムがスケジュールに従って自動的にバックアップされます。

📈 ビジネス面

✓事業継続性と災害対策の強化: ポリシーに基づく確実なバックアップ運用で、障害発生時の復旧体制を強化
✓規制コンプライアンスへの対応: データレジデンシー要件のあるワークロードでも、リージョン内で一元的なデータ保護と監査対応が可能
✓運用コストの削減: FSx 固有のバックアップ運用を個別に構築する必要がなくなり、既存の AWS Backup 運用に統合可能

🔧 技術面

✓一元管理: EC2、EBS、RDS など他のリソースと FSx のバックアップを単一のサービスとポリシーで管理
✓自動化: スケジュールと保持ルールにより、取得から削除までのライフサイクルを自動化
✓セキュリティ: 暗号化ボールトへの保存とアクセスポリシーによる保護が可能

⚠️ デメリット・制約事項

制限事項

⚠今回のサポート対象はアジアパシフィック (ニュージーランド) リージョンの FSx ファイルシステム。リージョンごとの機能サポート状況は AWS Backup ドキュメントで確認が必要
⚠クロスリージョンコピーやクロスアカウントコピーなどの個別機能の対応状況は、リージョンおよびリソースタイプごとに異なるため事前確認が必要

考慮すべき点

⚠バックアップストレージには AWS Backup の料金が発生するため、保持期間とバックアップ頻度の設計がコストに影響する
⚠FSx for NetApp ONTAP など一部のタイプでは、バックアップの仕様 (対象ボリュームの扱いなど) が異なるため、ドキュメントでの確認を推奨

🎯 ユースケース

1️⃣ Windows ファイルサーバーの定期バックアップと世代管理

シナリオ: ニュージーランド国内の企業が FSx for Windows File Server を社内ファイルサーバーとして利用し、日次バックアップと 35 日間の世代管理が社内規定で求められている。

実装例: ボールト「corp-file-vault」を作成 → 日次プランを作成 (保持 35 日) → タグ「Backup=Daily」の FSx をプランに割り当て

✅ 効果: 社内規定に準拠したバックアップ運用を自動化し、誤削除やランサムウェア被害からの復旧体制を確立。

2️⃣ HPC ワークロードのデータ保護

シナリオ: 研究機関が FSx for Lustre を HPC クラスターのストレージとして利用し、解析結果データを定期的に保護したい。

実装例: 解析ジョブ完了後の時間帯に合わせたスケジュール設定 → 保持ルールで古い復旧ポイントを自動削除 → 必要に応じてオンデマンドバックアップを追加実行

✅ 効果: 高価な再計算を避けるためのデータ保護を自動化し、ストレージコストと保護レベルのバランスを最適化。

3️⃣ 複数リソースの統合バックアップガバナンス

シナリオ: ニュージーランドで金融系ワークロードを運用する企業が、EC2、RDS、FSx for NetApp ONTAP を含む全リソースのバックアップを一元管理し、監査に対応したい。

実装例: 全リソース共通のプランをタグベースで適用 → 暗号化ボールトにバックアップを集約 → ジョブ履歴と復旧ポイントを監査証跡として活用

✅ 効果: 分散していたバックアップ管理を統合し、規制コンプライアンスの証跡提示を効率化。

💰 料金

AWS Backup の料金は、バックアップストレージの使用量、復元したデータ量などに基づいて課金されます。 FSx ファイルシステムのバックアップはウォームストレージの GB 単価で課金され、リージョンおよびリソースタイプによって単価が異なります。 最新の料金は AWS Backup 料金ページで確認してください。

📌 まとめ

AWS Backup がアジアパシフィック (ニュージーランド) リージョンで 4 種類すべての Amazon FSx ファイルシステムをサポートし、 同リージョンでのデータ保護を単一サービスで一元管理できるようになりました。 ニュージーランドで FSx を利用中、または利用を検討している場合は、既存の FSx ネイティブバックアップ運用を AWS Backup のポリシーベース管理へ統合し、 事業継続性とコンプライアンス対応の強化を検討することを推奨します。
