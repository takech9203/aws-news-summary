AWS Backup Amazon EBS

🔒 論理的エアギャップボールトが EBS Snapshots Archive をサポート

エアギャップ保護と低コストの長期保持を両立 — 📅 リリース日: 2026 年 11 月 12 日

📝 概要

AWS Backup の論理的エアギャップボールト (logically air-gapped vault) が、 Amazon EBS Snapshots Archive をサポートしました。 ボールト内の Amazon EBS バックアップを、アクセス頻度の低いスナップショット向けの低コストストレージ階層へ移行できます。

論理的エアギャップボールトは、コンプライアンスモードのボールトロックが常に有効な不変 (イミュータブル) バックアップ用の特殊なボールトです。 暗号化による分離、AWS RAM を通じたアカウント間共有、共有先アカウントからの直接復元をサポートします。 今回のアップデートで、ランサムウェア対策と長期保持コストの最適化を同時に実現できるようになりました。

❌ アップデート前の課題

✗ボールト内の EBS バックアップはアーカイブ階層へ移行できず、ウォームストレージ料金で保持し続ける必要があった
✗数年単位の長期保持ではアクセス頻度が低いのにストレージコストが高止まり
✗コスト最適化のためにエアギャップ保護を諦めて標準ボールトを選ぶトレードオフが発生

✅ アップデート後の改善

✓EBS バックアップを EBS Snapshots Archive へ移行し、エアギャップ保護と低コスト長期保持を両立
✓ライフサイクル設定でウォームストレージ期間を指定するだけで移行を自動化
✓コピー先だけでなく、プライマリバックアップターゲットとして使用する場合もアーカイブ設定が可能

月次以下の頻度で実行されるバックアップルールにより、Amazon EBS バックアップが論理的エアギャップボールトに保存され、 指定したウォームストレージ期間の経過後に EBS Snapshots Archive 階層へ自動的に移行されます。

⚙️ 主要機能

1️⃣ 論理的エアギャップボールト内での EBS スナップショットアーカイブ

  • ボールトに保存した Amazon EBS バックアップを、低コストの EBS Snapshots Archive 階層へ移行可能
  • ボールトへのコピー完了後、設定したウォームストレージ期間の経過を経てアーカイブ階層に移行
  • アーカイブ後もコンプライアンスモードのボールトロックによる不変性と、暗号化による分離は維持

2️⃣ ライフサイクル設定による自動移行

  • 月次以下の頻度のバックアップルールで、コピーアクションの宛先に論理的エアギャップボールトを指定し、コピーライフサイクルで「Archive Amazon EBS snapshots」を選択
  • ウォームストレージに保持する期間と、合計保持期間を設定
  • プライマリバックアップターゲットとして使用する場合は、バックアップルールのライフサイクルでアーカイブを設定

3️⃣ コンソール・CLI・SDK からの利用

  • AWS Backup コンソール、AWS CLI、AWS SDK のいずれからも設定可能
  • 既存プランの更新 (update-backup-plan) または新規作成 (create-backup-plan) で対応

🔧 技術仕様

📐 ライフサイクル要件

項目詳細
対象リソースAmazon EBS バックアップ (スナップショット)
バックアップルールの頻度月次以下 (月 1 回またはそれより低頻度)
合計保持期間ウォームストレージ期間より 90 日以上長く設定する必要がある
保持期間の範囲ボールトの最小保持期間と最大保持期間の範囲内であること
ボールトの最小保持期間7 日以上で設定 (論理的エアギャップボールト共通の仕様)
暗号化AWS 所有キー (デフォルト) またはカスタマーマネージドキー
課金区分ボールト内のストレージ・データ転送はすべて「AWS Backup」として課金

🔄 API 変更履歴

今回のアップデートに関連する直近の AWS Backup API 変更は、awsapichanges.com では確認されていません (2026 年 11 月 13 日時点)。 既存のバックアッププラン API のライフサイクル設定で対応します。

🔑 カスタマーマネージドキー使用時のキーポリシー

ボールトをカスタマーマネージドキー (CMK) で暗号化している場合、このアーカイブオプションを有効化する前にキーポリシーの更新が必要です。 詳細は 公式ドキュメントのキーポリシー設定を参照してください。

🛠️ 設定方法

✅ 前提条件

  • 論理的エアギャップボールトが利用可能なリージョンであること (中国リージョンおよび AWS GovCloud (US) では利用不可)
  • EBS Snapshots Archive が利用可能なリージョンであること
  • CMK 暗号化のボールトを使用する場合は、事前にキーポリシーを更新していること

ステップ 1: 論理的エアギャップボールトの作成 (未作成の場合)

Bash 論理的エアギャップボールトの作成 
aws backup create-logically-air-gapped-backup-vault \
  --backup-vault-name MyLAGVault \
  --min-retention-days 30 \
  --max-retention-days 3650

最小保持期間 30 日、最大保持期間 3,650 日のボールトを作成します。ボールトロックはコンプライアンスモードで自動的に有効化されます。

ステップ 2: バックアッププランでアーカイブ付きコピーを設定

Bash コピーライフサイクルでアーカイブを有効化 
aws backup update-backup-plan \
  --backup-plan-id <plan-id> \
  --backup-plan '{
    "BackupPlanName": "MonthlyEBSPlan",
    "Rules": [{
      "RuleName": "MonthlyToLAGVault",
      "TargetBackupVaultName": "Default",
      "ScheduleExpression": "cron(0 5 1 * ? *)",
      "Lifecycle": {"DeleteAfterDays": 455},
      "CopyActions": [{
        "DestinationBackupVaultArn": "arn:aws:backup:ap-northeast-1:123456789012:backup-vault:MyLAGVault",
        "Lifecycle": {
          "OptInToArchiveForSupportedResources": true,
          "MoveToColdStorageAfterDays": 90,
          "DeleteAfterDays": 455
        }
      }]
    }]
  }'

毎月 1 日実行のルールに、論理的エアギャップボールトへのコピーアクションを追加。ウォームストレージに 90 日間保持した後アーカイブ階層へ移行し、 合計 455 日間保持します (合計保持期間はウォームストレージ期間 + 90 日以上が必要)。

ステップ 3: 移行状況の確認

Bash リカバリポイントの一覧表示 
aws backup list-recovery-points-by-backup-vault \
  --backup-vault-name MyLAGVault

各リカバリポイントのライフサイクル状態を確認します。ボールト内のリカバリポイント ARN は arn:aws:backup:{region}:{account-id}:recovery-point:* 形式になる点に注意してください。

💡 メリット

💼 ビジネス面

  • ストレージコストの削減: アクセス頻度の低い長期保持バックアップを低コストのアーカイブ階層へ移行
  • コンプライアンス対応: 不変バックアップによる長期保持要件 (監査・規制対応) をコストを抑えながら達成
  • セキュリティとコストの両立: エアギャップ保護をコスト最適化のために諦める必要がない

🔬 技術面

  • ライフサイクルの自動化: ウォームストレージ期間の設定だけで移行が自動実行
  • 一貫した管理: バックアッププランの一元管理でアーカイブ設定が完結し、個別のスナップショット操作が不要
  • 迅速なリカバリ体制の維持: AWS RAM 共有と直接復元はそのまま利用でき、RTO 短縮に貢献

⚠️ デメリット・制約事項

🚫 制限事項

  • アーカイブ階層へ移行した EBS バックアップは、別のボールトや別リージョンへコピー不可 (Multi-party approval による復元アクセスバックアップボールトからのコピーも不可)。別アカウント・別リージョンにコピーを保持したい場合は、ウォームストレージにある間にコピーする必要がある
  • アーカイブ対象は月次以下の頻度で実行されるバックアップルールに限定 (EBS Snapshots Archive 共通の要件)
  • 合計保持期間はウォームストレージ期間より 90 日以上長く設定する必要がある

🤔 考慮すべき点

  • アーカイブ階層からの復元はウォームストレージからの復元より時間がかかるため、RTO 要件と照らして移行タイミングを設計する
  • CMK 暗号化のボールトでは、アーカイブ有効化前にキーポリシーの更新が必要
  • ボールトロックがコンプライアンスモードで固定されるため、保持期間の設計は慎重に行う

🎯 ユースケース

🏦 ユースケース 1: ランサムウェア対策と長期保持の両立

シナリオ金融機関が規制要件により EBS ボリュームのバックアップを 7 年間保持する必要があり、同時にランサムウェア攻撃からバックアップを保護したい。

月次バックアップルール → 論理的エアギャップボールトへコピー
→ ウォームストレージ 90 日 → アーカイブ階層へ自動移行 → 合計保持期間 7 年

効果不変かつ分離されたバックアップを低コストで 7 年間保持でき、規制要件とセキュリティ要件を同時に満たせる。

🏢 ユースケース 2: 組織全体のバックアップコスト最適化

シナリオAWS Organizations 配下の多数のアカウントで論理的エアギャップボールトを運用しており、長期保持バックアップのストレージコストが増大している。

AWS Organizations のバックアップポリシーで
月次ルールのコピーライフサイクルにアーカイブ設定を一括適用

効果組織全体で一貫したアーカイブポリシーを適用し、セキュリティ水準を維持したままストレージコストを削減できる。

🚨 ユースケース 3: 共有ボールトによる迅速な復旧体制

シナリオ本番アカウント侵害に備え、別の復旧用アカウントからバックアップを直接復元できる体制を構築したい。直近のバックアップは迅速に復元し、古いバックアップは低コストで保持したい。

論理的エアギャップボールトを AWS RAM で復旧用アカウントに共有
直近 90 日分: ウォームストレージ (迅速な復元)
90 日以降: アーカイブ階層 (低コスト保持)

効果インシデント時は直近のウォームストレージ上のバックアップから迅速に復旧しつつ、長期保持分のコストを最適化できる。

💰 料金

論理的エアギャップボールト内のストレージおよびデータ転送の料金は、すべて「AWS Backup」の課金として発生します。 EBS Snapshots Archive はウォームストレージ (標準階層) よりも低コストのストレージ階層であり、アクセス頻度の低い長期保持バックアップのコストを削減できます。 アーカイブ階層からの復元には取り出しに関する料金と時間が発生するため、詳細は AWS Backup 料金ページを参照してください。

🌏 利用可能リージョン

論理的エアギャップボールトと Amazon EBS Snapshots Archive の両方が利用可能なすべての AWS リージョンで利用できます。 なお、論理的エアギャップボールトは中国 (北京)、中国 (寧夏)、AWS GovCloud (US-East)、AWS GovCloud (US-West) では現在利用できません。 最新の対応状況は リージョン別機能可用性を確認してください。

🔗 関連サービス・機能

🧊 Amazon EBS Snapshots Archive アクセス頻度の低いスナップショット向けの低コストストレージ階層。今回のアップデートで論理的エアギャップボールトからの移行先として利用可能に。
🔐 AWS Backup Vault Lock バックアップの不変性を保証する機能。論理的エアギャップボールトではコンプライアンスモードが常に有効。
🤝 AWS RAM 論理的エアギャップボールトをアカウント間で共有し、共有先アカウントからの直接復元を可能にするリソース共有サービス。
📋 AWS Backup Audit Manager 特定リソースのバックアップが論理的エアギャップボールトに保存されていることを監査するコントロールを提供。

📌 まとめ

論理的エアギャップボールトが EBS Snapshots Archive をサポートしたことで、 ランサムウェア対策としてのエアギャップ保護と、長期保持バックアップのコスト最適化を両立できるようになりました。 論理的エアギャップボールトで EBS バックアップを長期保持している場合は、月次以下のバックアップルールのライフサイクル設定を見直し、 アーカイブ階層の活用によるコスト削減を検討することを推奨します。 アーカイブ後は別ボールト・別リージョンへのコピーができなくなるため、 コピー戦略はウォームストレージ期間中に完了するよう設計してください。
