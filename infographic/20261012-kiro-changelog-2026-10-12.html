Kiro CLI 2.30.0

🤖 チャット開始時の V3 切り替えプロンプトと
モデルフォールバック通知

V3 デフォルト化に向けた移行支援を本格化するリリース
📅 リリース日: 2026 年 10 月 12 日
🛠️ サービス: Kiro (AI 搭載 IDE / CLI)
🌍 グローバルに利用可能

📋 概要

Kiro CLI 2.30.0 がリリースされ、チャット開始時に V3 への切り替えを促すスタートアッププロンプトの段階的ロールアウトが始まりました。V3 は 10 月末リリース予定の CLI 3.0 でデフォルトハーネスとなる計画であり、今回のプロンプトはその移行を円滑に進めるための準備段階です。

プロンプトで「Switch to V3 and upgrade my configs」を選択すると、V3 のデフォルトハーネス化、エージェント自動アップグレードの有効化、カスタムエージェント設定の移行がワンステップで開始されます。また、V3 セッションにモデルフォールバック通知が追加され、ターンが別のモデルへ移行したことをトランスクリプト上で確認できるようになりました。

❌ アップデート前の課題
  • Classic / V2 ユーザーが V3 へ移行するには、ロールアウト情報を自分で把握し、手動で切り替える必要があった
  • V3 セッションで別モデルにフォールバックしても通知がなく、応答の変化の理由がわからなかった
  • V3 アップグレード時に V2 のワークスペース読み取りアクセスやスキル信頼設定の一部が引き継がれなかった
  • スクリーンリーダーの追従不可、tmux の空白行、小規模ナレッジベースのチャンク欠落などの問題があった
✅ アップデート後の改善
  • スタートアッププロンプトから V3 への切り替えとエージェント設定の移行をワンステップで開始できる
  • 別モデルへの移行時にトランスクリプトへ通知が表示され、どのモデルが応答を継続したかを把握できる
  • V3 アップグレード時に V2 のワークスペース読み取りアクセスとスキル信頼設定が維持される
  • V2 信頼設定の変更時に、未変更の V3 フィールドの権限が自動更新される
  • スクリーンリーダー、tmux、ナレッジ検索、Linux ターミナルの文字化けなどを修正

        K-->>U: 応答 + フォールバック通知を表示

        K-->>U: 応答を表示

V3 セッションにおけるモデルフォールバック通知の流れです。別のモデルがターンを継続した場合、その事実がトランスクリプトに明示されます。

⚡ 主要機能

💬 1. チャット開始時の V3 切り替えプロンプト
  • チャット開始時に V3 への切り替えを促すスタートアッププロンプトを表示 (段階的ロールアウト)
  • 「Switch to V3 and upgrade my configs」の選択で、V3 のデフォルトハーネス化、エージェント自動アップグレードの有効化、設定移行の開始が一度に行われる
  • 10 月末の CLI 3.0 リリースで V3 がデフォルトになる予定
  • プロンプトを待たずに kiro-cli --v3 でいつでも V3 を試用可能
🔔 2. V3 モデルフォールバック通知
  • モデルがリクエストを拒否した場合や利用できない場合に、ターンが別モデルへ移行したことをトランスクリプト上に表示
  • 応答の変化の理由を推測する必要がなくなり、どのモデルが応答を継続したかを明確に把握できる
🔐 3. アップグレード済みエージェントの権限維持と更新 (改善)
  • V2 の信頼設定を変更した際、生成された V3 フィールドが未変更であれば、対応する V3 権限が自動的に更新される
  • V3 アップグレード時に V2 のワークスペース読み取りアクセスとコード / スキル信頼設定が維持されるようになった (修正)
🔧 4. 各種問題の修正
  • スクリーンリーダーが /settings display の Screen reader オプションで、フル TUI のストリーミング応答を追従可能に
  • tmux でのスクロールバック時に、長い応答の後に空白行の画面が表示される問題を修正
  • 末尾に改行のない出力の後に起動すると UI の描画位置がずれる問題を修正
  • Classic / V2 のナレッジ検索で、小規模ナレッジベースからチャンクが暗黙的に欠落する問題を修正
  • 一部の Linux ターミナルやリモートデスクトップでの文字化けや不要な文字の表示を修正

🛠️ 設定方法

前提条件

✓Kiro CLI がインストールされていること
✓最新バージョン (2.30.0 以降) にアップデートされていること

ステップ 1: Kiro CLI を最新バージョンに更新

Bash CLI の更新 
kiro-cli update

更新後に CLI を再起動すると、新機能が利用可能になります。

ステップ 2: スタートアッププロンプトで V3 への切り替えを選択

Bash チャットを開始 
kiro-cli

段階的ロールアウトの対象になっている場合にスタートアッププロンプトが表示されます。「Switch to V3 and upgrade my configs」を選択すると、V3 のデフォルトハーネス化、エージェント自動アップグレードの有効化、カスタムエージェント設定の移行が開始されます。

ステップ 3: プロンプトを待たずに V3 を試用する場合

Bash V3 セッションを直接開始 
kiro-cli --v3

--v3 フラグを付けて起動すると、いつでも V3 セッションを開始できます。デフォルト設定は変更されないため、気軽に試用できます。

💡 メリット

ビジネス面

✓移行コストの低減: ワンステップで V3 への切り替えとエージェント設定の移行が開始でき、チーム全体の V3 移行をスムーズに進められる
✓計画的な移行: 10 月末の CLI 3.0 での V3 デフォルト化に先立って段階的に移行でき、デフォルト変更時の混乱を回避できる
✓アクセシビリティの向上: スクリーンリーダー対応の修正により、より多くの開発者が Kiro CLI を利用できる

技術面

✓透明性の向上: モデルフォールバック通知により、どのモデルが応答を生成したかを把握でき、応答品質の変化を正しく解釈できる
✓権限設定の継続性: V3 アップグレード時に V2 のワークスペース読み取りアクセスとスキル信頼設定が維持され、再設定の手間が不要
✓ターミナル環境の安定性: tmux や Linux ターミナルでの表示問題が修正され、リモート環境での利用体験が向上

⚠️ デメリット・制約事項

制限事項

✗スタートアッププロンプトは段階的ロールアウトのため、すべてのユーザーにすぐ表示されるわけではない
✗10 月末の CLI 3.0 で V3 がデフォルトになる予定のため、Classic / V2 を利用し続けるワークフローは早めの移行計画が必要
✗信頼していないワークスペースでは、一部の V3 機能の動作が制限される場合がある

考慮すべき点

⚠カスタムエージェント設定を利用している場合、V3 への移行で設定がどのように変換されるかを事前にドキュメントで確認することを推奨
⚠モデルフォールバックが発生した場合、意図したモデルと異なるモデルが応答している可能性があるため、通知を確認する運用を取り入れると良い

🎯 ユースケース

📅 ユースケース 1: チームの V3 への計画的移行

シナリオ: 開発チームが Classic / V2 ハーネスで Kiro CLI を利用しており、10 月末の V3 デフォルト化に備えて段階的に移行したい。

Bash実装例
# 各メンバーが最新バージョンに更新
kiro-cli update

# スタートアッププロンプトで「Switch to V3 and upgrade my configs」を選択
kiro-cli

効果: デフォルト化前に V3 への切り替えとエージェント設定の移行を完了でき、CLI 3.0 リリース時の業務影響を最小化できる。

🔍 ユースケース 2: モデルフォールバック発生時の応答品質の検証

シナリオ: V3 セッションでコード生成を行っている際、応答の傾向が急に変化したため、原因を確認したい。

対応: トランスクリプトに表示されるフォールバック通知を確認し、ターンが別のモデルに移行していたかを判断する。

効果: 応答の変化がモデルフォールバックによるものかを即座に判断でき、必要に応じてリクエストの再実行やモデル選択の見直しができる。

🖥️ ユースケース 3: tmux を利用したリモート開発環境での利用

シナリオ: SSH 先のサーバーで tmux セッション内から Kiro CLI を利用しており、長い応答の後にスクロールバックすると空白行が表示されて作業しづらかった。

Bash実装例
# 最新バージョンに更新するだけで修正が適用される
kiro-cli update

効果: tmux スクロールバックの空白行問題と UI 描画オフセット問題が解消され、リモート環境でも快適に過去の応答を参照できる。

📝 まとめ

Kiro CLI 2.30.0 は、10 月末の CLI 3.0 における V3 デフォルト化に向けた移行支援を本格化させるリリースです。スタートアッププロンプトによるワンステップの切り替えとモデルフォールバック通知により、移行の手間と V3 セッションの不透明さが大きく軽減されます。Classic / V2 を利用中のユーザーは、kiro-cli --v3 での試用やエージェント設定の移行確認を早めに進めることを推奨します。
