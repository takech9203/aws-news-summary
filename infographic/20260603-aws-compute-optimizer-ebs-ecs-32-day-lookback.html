AWS Compute Optimizer

EBS / ECS 32 日間ルックバック期間サポート

2026-06-03

📋 概要

AWS Compute Optimizer が、EBS ボリュームおよびECS サービスのライトサイジング推奨において、ルックバック期間をデフォルトの 14 日間から 32 日間に延長する機能をサポート。月次利用パターンを考慮した精度の高い推奨が、追加コストなしで利用可能に。

32
日間のルックバック期間
5
種類の推奨タイプが対応
0
追加コスト (無料)
❌ Before
  • EBS/ECS は最大 14 日間のデータに基づく推奨
  • 月末バッチ処理のピークが反映されない
  • 過小なリソース推奨が生成される可能性
  • EC2/RDS のみ 32 日間対応
✅ After
  • EBS/ECS でも 32 日間のルックバック設定可能
  • 月次パターンを考慮した精度の高い推奨
  • 5 種類すべてで統一的にルックバック管理
  • 追加料金なしで利用可能

⚡ 主要機能

💾 EBS ボリュームの 32 日間ルックバック
  • デフォルト 14 日間から 32 日間に延長可能
  • ボリュームタイプ、サイズ、IOPS、スループットの最適化推奨がより正確に
  • 月次バッチ処理による一時的な I/O スパイクを考慮
🐳 ECS サービスの 32 日間ルックバック
  • CPU およびメモリのライトサイジング推奨で 32 日間の分析期間を利用可能
  • Fargate および EC2 起動タイプの両方に対応
  • コンテナレベルの推奨にも 32 日間のメトリクスが反映
🎛️ 柔軟な設定スコープ
  • 組織レベル: AWS Organizations 全体に一括適用
  • アカウントレベル: 個別アカウントごとに設定
  • リソースレベル: 特定の EBS ボリュームや ECS サービスに個別設定

🛠️ 設定方法

前提条件

  • AWS Compute Optimizer がアカウントまたは組織でオプトインされていること
  • 対象リソース (EBS ボリュームまたは ECS サービス) が存在し、メトリクスが収集されていること
  • 設定変更に必要な IAM 権限があること

ステップ 1: EBS ボリュームの設定

Bash EBS ボリュームに 32 日間ルックバックを設定 
# アカウントレベルで EBS ボリュームの推奨に 32 日間ルックバックを設定
aws compute-optimizer put-recommendation-preferences \
  --resource-type EbsVolume \
  --look-back-period DAYS_32

ステップ 2: ECS サービスの設定

Bash ECS サービスに 32 日間ルックバックを設定 
# アカウントレベルで ECS サービスの推奨に 32 日間ルックバックを設定
aws compute-optimizer put-recommendation-preferences \
  --resource-type EcsService \
  --look-back-period DAYS_32

ステップ 3: 設定の確認

Bash 現在の推奨プリファレンスを確認 
# 現在の推奨プリファレンスを確認
aws compute-optimizer get-recommendation-preferences \
  --resource-type EbsVolume

lookBackPeriod が DAYS_32 になっていれば設定完了。

⚖️ メリット / デメリット

✅ メリット

  • 月次パターンを考慮した精度の高い推奨
  • 追加コストなしで利用可能
  • 5 種類すべてで統一管理可能
  • 月末バッチの I/O スパイクが推奨に反映
  • 柔軟なスコープ設定 (組織/アカウント/リソース)
  • 既存の自動化スクリプトへの影響が最小限

⚠️ 制約事項・注意点

  • GovCloud / 中国リージョンでは利用不可
  • 32 日分のデータ蓄積まで精度が限定的
  • 93 日間は引き続き有料オプションが必要
  • 推奨生成までの初期待機期間が長くなる可能性
  • 月次パターンがないワークロードでは 14 日で十分
  • 組織レベル設定は全アカウントに適用される

💡 ユースケース

📊 ユースケース 1: 月末バッチ処理を行う EBS ボリュームの最適化

シナリオ: 経理部門の月末処理で毎月 25 日から月末にかけて大量の I/O が発生するデータベース用 EBS ボリューム。14 日間のルックバックでは月末ピークが含まれないタイミングで縮小推奨が出てしまう。

効果: 月末の I/O スパイクを含む 32 日間のメトリクスに基づいて推奨が生成されるため、不適切なダウンサイジング推奨を回避。

🐳 ユースケース 2: ECS で稼働する月次レポート生成サービス

シナリオ: 月初にクライアント向けレポートを生成する ECS サービス。月初の 3-5 日間は CPU/メモリ使用率が高いが、それ以外は低利用率。14 日間ルックバックではレポート生成期間が含まれないことがある。

効果: 月初のピーク利用を含めた推奨が生成され、パフォーマンス低下を防止しつつ通常時のコスト最適化も実現。

🏢 ユースケース 3: 組織全体での統一的なルックバック期間管理

シナリオ: マルチアカウント環境で運用している企業が、全アカウントの EBS/ECS リソースに対して一貫した 32 日間ルックバックを適用したい。

Bash 組織レベルでの一括設定 
# 組織レベルで EBS の 32 日間ルックバックを設定
aws compute-optimizer put-recommendation-preferences \
  --resource-type EbsVolume \
  --scope "Name=Organization,Value=r-xxxx" \
  --look-back-period DAYS_32

# 組織レベルで ECS の 32 日間ルックバックを設定
aws compute-optimizer put-recommendation-preferences \
  --resource-type EcsService \
  --scope "Name=Organization,Value=r-xxxx" \
  --look-back-period DAYS_32

効果: 組織全体で月次パターンを考慮した最適化推奨を一括で有効化し、各チームが個別に設定する手間を削減。

💰 料金

項目料金
14 日間ルックバック (デフォルト)無料
32 日間ルックバック無料
93 日間ルックバック (Enhanced Infrastructure Metrics)有料

注: 93 日間のルックバック期間を利用するには Enhanced Infrastructure Metrics のサブスクリプションが必要。

🌍 利用可能リージョン

AWS Compute Optimizer が利用可能なすべての AWS リージョンで提供。

除外リージョン: AWS GovCloud (US) リージョン、中国リージョン (北京、寧夏)
