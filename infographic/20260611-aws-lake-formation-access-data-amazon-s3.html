AWS Lake Formation

Amazon S3 上の基礎データへの
アクセス拡張

🔑 テーブル権限による S3 基礎データファイルへの直接アクセス
📅 リリース日
2026 年 6 月 11 日

💡 概要

AWS Lake Formation は、AWS Glue Data Catalog に登録されたテーブルについて、その基礎となる Amazon S3 上のデータファイルを直接読み書きできる機能を追加しました。 SQL クエリと直接的なファイルアクセスの両方に対して、単一の Lake Formation テーブル権限を利用できます。

Lake Formation がテーブル権限に基づいて、登録済みの S3 ロケーションに対する 一時的でスコープ制限されたクレデンシャルを発行します。 SELECT 権限は読み取り、SUPER 権限は読み取りと書き込みの両方を付与します。 この機能は Amazon EMR 7.13 以降に組み込まれており、モデルトレーニング、特徴量エンジニアリング、データ品質のデバッグといった ファイルレベルのアクセスを必要とするタスクで Spark ジョブから直接データにアクセスできます。 すべてのアクセスは AWS CloudTrail に記録され、統合された監査証跡が得られます。

🔄 アップデート前後の比較

❌ Before
  • テーブル権限は SQL クエリ (Athena、EMR、Redshift など) 経由のアクセスにのみ適用
  • ファイルレベルアクセスには S3 バケットポリシーや IAM ロールを個別に設定・管理する必要
  • SQL 操作とファイルベース操作の監査証跡が分散し、一元把握が困難
✅ After
  • 既存のテーブル権限でファイルアクセスが可能、単一の権限セットを利用
  • 追加の S3 ポリシーや IAM ロールなしで一時的でスコープ制限された安全なアクセス
  • 全クレデンシャル発行が CloudTrail に記録され統合監査証跡を実現

EMR の Spark ジョブが S3 リクエストを発行すると、SDK プラグインがそれを傍受し、Lake Formation の API を呼び出してテーブル権限を評価し、 スコープ制限された一時クレデンシャルを取得して S3 にアクセスする流れを示しています。

⭐ 主要機能

1. テーブル権限に基づくクレデンシャル発行
  • アプリケーションが S3 ファイルへのアクセスを要求すると、Lake Formation が既存のテーブルレベル権限を評価
  • 認可されると、登録済みロケーションに対して短命でスコープ制限された S3 クレデンシャルを返却
  • SELECT → READ クレデンシャル、SUPER → READWRITE クレデンシャルを発行
2. Amazon EMR への組み込みサポート
  • EMR 7.13 以降 (EMR on EC2、EMR on EKS、EMR Serverless) に組み込み
  • 機能フラグ fs.s3a.lakeformation.access.grants.enabled を有効化で即座に読み書き可能
  • モデルトレーニング、特徴量エンジニアリング、データ品質のデバッグで Spark から直接アクセス
3. オープンソースプラグインによる統合
  • Apache Spark や Trino を API または AWS 提供のオープンソースプラグインで統合
  • GitHub の aws-lakeformation-accessgrants-plugin-java-v2 で公開
4. 統合された監査証跡
  • すべてのクレデンシャル発行操作が CloudTrail に記録
  • 記録内容: プリンシパル、タイムスタンプ、S3 ロケーション、関連 Glue テーブル
  • 後続の S3 API 呼び出しも S3 データイベントとして記録され、権限付与に紐づけ

🛠️ 設定方法

前提条件

1.Data Catalog にテーブルをカタログ化し、S3 ロケーションを Lake Formation に登録 (S3 バケットオーナーアカウントを指定)
2.テーブルへの SELECT または SUPER 権限を付与 (Athena/EMR で利用済みなら設定済み)
3.Application Integration with Full Table Access を有効化し、クレデンシャル発行を許可

ステップ 1: 機能フラグの有効化

ConfigEMR 7.13 以降で有効化
fs.s3a.lakeformation.access.grants.enabled = true

ステップ 2: Spark ジョブからのデータアクセス

Python標準のファイルベース API をそのまま使用
# 生データの読み取り (Lake Formation ベースの S3 ロケーションアクセス)
raw_df = spark.read.json("s3://finance-datalake/raw/transactions/dt=2024-03-21/")

# ガバナンス対象データの読み取り
transactions_df = spark.read.parquet("s3://data-lake/transactions/year=2026/")

# 処理済みデータの書き込み
processed_df.write \
    .mode("append") \
    .partitionBy("transaction_date") \
    .parquet("s3://finance-datalake/processed/transactions/")

プラグインが S3 リクエストを傍受し、Lake Formation の権限に基づいてクレデンシャルを取得するため、追加のコード変更は不要です。

🎯 メリット

💼 ビジネス面

✓権限管理の一元化: SQL とファイルで同じ権限を利用
✓コンプライアンス強化: 全アクセスを CloudTrail に記録、統合監査証跡
✓追加コストなし: 追加料金なしで利用可能

⚙️ 技術面

✓設定の簡素化: S3 ポリシーや IAM ロールの個別設定が不要
✓最小権限の実現: 一時的でスコープ制限されたクレデンシャル
✓既存ワークフローとの親和性: 標準 API をそのまま利用、コード変更不要

⚠️ デメリット・制約事項

制限事項

✗クレデンシャル発行はフルテーブルアクセス (行・列フィルタなしの全列 SELECT) を持つ場合のみ。行・列レベルのフィルタが適用されたテーブルは Athena、EMR、Glue、Redshift などの信頼されたエンジンを使用
✗S3 ロケーション向けのクレデンシャル発行はクロスリージョンではサポート外
✗クレデンシャル発行はテーブルのプライマリロケーションとして含まれる S3 ロケーションに対してサポート

考慮すべき点

⚠️同一ロケーションに複数テーブルが登録されると権限の競合でエラー。ロケーション設計に注意
⚠️きめ細かいアクセス制御 (行・列レベル) が必要なシナリオでは従来のクエリエンジン経由のアクセスを併用

Python
training_df = spark.read.parquet("s3://data-lake/features/year=2026/")

shared_df = spark.read.parquet("s3://producer-data-lake/shared/dataset/")

🔗 関連サービス・機能

→AWS Glue Data Catalog: テーブルのメタデータを管理し、登録済み S3 ロケーションとの紐付けを提供
→Amazon EMR: 7.13 以降でこの機能が組み込まれ、Spark ジョブから直接アクセス可能
→Amazon S3: 基礎データファイルの保存先、Lake Formation に登録されたロケーションが対象
→AWS CloudTrail: 全クレデンシャル発行と後続の S3 データイベントを記録し統合監査証跡を提供

📌 まとめ

このアップデートにより、Lake Formation のテーブル権限が SQL クエリだけでなく基礎となる S3 ファイルへの直接アクセスにも適用され、 権限管理と監査が一元化されました。 機械学習や ETL でファイルレベルのアクセスを行うデータチームは、EMR 7.13 以降への更新と機能フラグの有効化を検討し、 既存の IAM ベースのアクセス設定を Lake Formation 権限に統合することを推奨します。
