Amazon Keyspaces (for Apache Cassandra)

🍁 カナダ西部 (カルガリー) リージョンで利用可能に NEW

📅 リリース日: 2026 年 8 月 5 日 | リージョンコード: ca-west-1

📋 概要

Amazon Keyspaces (for Apache Cassandra) が、カナダ西部 (カルガリー) リージョン (ca-west-1) で利用可能になった。カナダのユーザーは Apache Cassandra 互換のアプリケーションを より低いレイテンシーで実行しながら、データをカナダ国内に保持できる。

Amazon Keyspaces は、スケーラブルで高可用性を備えたフルマネージドの Cassandra 互換データベースサービス。 サーバーレスモデルにより、サーバーのプロビジョニング、パッチ適用、管理は不要で、使用したリソースに対してのみ課金される。 使い慣れた Cassandra Query Language (CQL) で毎秒数千リクエストを処理するアプリケーションを構築できる。

❌ Before: アップデート前の課題
✗国内の選択肢は ca-central-1 のみで、カナダ西部のユーザーにはレイテンシーが発生
✗カナダ国内でのマルチリージョン構成 (レプリケーションや DR) を組めなかった
✗カナダ西部の他の AWS ワークロードと同一リージョンで利用できなかった
✅ After: アップデート後の改善
✓地理的に近いカルガリーリージョンの利用でレイテンシーが低減
✓データレジデンシー要件を満たしつつ国内 2 リージョン構成が可能に
✓カナダ国内での DR・高可用性アーキテクチャの選択肢が拡大

🏗️ カナダ国内 2 リージョン構成のイメージ

ca-central-1 と ca-west-1 を組み合わせることで、データをカナダ国外に出さずに冗長構成を実現できる。

ステップ 1: キースペースの作成

BashAWS CLI でキースペースを作成
aws keyspaces create-keyspace \
    --keyspace-name my_keyspace \
    --region ca-west-1

カナダ西部 (カルガリー) リージョンに新しいキースペースを作成する。

ステップ 2: テーブルの作成

Bashスキーマを定義してテーブルを作成
aws keyspaces create-table \
    --keyspace-name my_keyspace \
    --table-name my_table \
    --schema-definition '{
        "allColumns": [
            {"name": "id", "type": "uuid"},
            {"name": "name", "type": "text"},
            {"name": "created_at", "type": "timestamp"}
        ],
        "partitionKeys": [{"name": "id"}]
    }' \
    --region ca-west-1

作成したキースペース内にテーブルを定義する。スキーマは CQL のデータ型に対応している。

ステップ 3: cqlsh での接続

BashTLS でカルガリーリージョンに接続
cqlsh cassandra.ca-west-1.amazonaws.com 9142 \
    --ssl \
    --auth-provider "PlainTextAuthProvider" \
    -u "ServiceUserName" \
    -p "ServicePassword"

TLS を使用してカルガリーリージョンの Amazon Keyspaces エンドポイントに接続する。サービス固有の認証情報は IAM コンソールから生成できる。

🎯 ユースケース

1️⃣ カナダ西部の企業によるデータレジデンシー対応

シナリオ: カナダ西部に拠点を持つ金融・公共系の組織が、データをカナダ国内に保持しながら低レイテンシーで Cassandra 互換データベースを利用したい。

SQLCQL でのキースペース作成例
CREATE KEYSPACE regulated_data
    WITH REPLICATION = {'class': 'SingleRegionStrategy'}
    AND TAGS = {'environment': 'production', 'residency': 'canada'};

効果: データレジデンシー要件を満たしつつ、カナダ西部のユーザーへ低レイテンシーでサービスを提供できる。

2️⃣ 既存 Cassandra クラスターのマネージドサービスへの移行

シナリオ: カナダ西部で自己管理の Cassandra クラスターを運用している企業が、運用負荷を削減するためにマネージドサービスへ移行したい。

Bash接続先を変更するのみ
# 既存の CQL アプリケーションの接続先を変更するのみ
cqlsh cassandra.ca-west-1.amazonaws.com 9142 --ssl

効果: 既存の CQL コードとドライバーを流用しながら、クラスター運用 (プロビジョニング、パッチ適用、スケーリング) から解放される。

3️⃣ カナダ国内 2 リージョンでの DR 構成

シナリオ: ca-central-1 で稼働中のワークロードについて、カナダ国内で完結するディザスタリカバリ構成を検討している。

BashDR 用キースペースの構築
# カルガリーリージョンに DR 用のキースペース・テーブルを構築し、
# アプリケーションレイヤーまたはレプリケーション機能でデータを同期する
aws keyspaces create-keyspace \
    --keyspace-name dr_keyspace \
    --region ca-west-1

効果: データをカナダ国外に出すことなく、リージョン障害に備えた冗長構成を実現できる。
