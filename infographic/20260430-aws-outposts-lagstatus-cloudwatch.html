🔗 AWS Outposts - LagStatus CloudWatch メトリクス

AWS Outposts Amazon CloudWatch
📅 2026-04-30

📋 概要

AWS Outposts ラックが LagStatus Amazon CloudWatch メトリクス をサポート。Outposts の LAG (Link Aggregation Group) 接続状態を CloudWatch コンソールから直接監視できるようになった。

LagStatus メトリクスは、Outposts LAG が運用上 UP (値 "1") か DOWN (値 "0") かを示すシンプルなバイナリメトリクス。既存の VifConnectionStatus および VifBgpSessionState メトリクスと組み合わせることで、障害の根本原因を迅速に特定できる。

3 階層的ネットワークメトリクス
1 / 0 UP / DOWN バイナリ値
全リージョン 商用 + GovCloud 対応

🔄 Before / After 比較

❌ Before - アップデート前

  • LAG 接続状態を CloudWatch から直接監視する手段がなかった
  • 問題の原因が LAG / BGP / VIF のいずれかの切り分けが困難
  • 手動確認や CLI 操作が必要で、トラブルシューティングに時間がかかった

✅ After - アップデート後

  • LagStatus メトリクスで LAG の UP/DOWN を CloudWatch で直接監視可能
  • 3 層メトリクスによる階層的な障害切り分けが実現
  • CloudWatch アラームで LAG 状態変化を即座に検知し自動通知可能

⚙️ 主要機能

📈 LagStatus メトリクス

Outposts LAG の運用状態を示すバイナリメトリクス。値 "1" は UP、値 "0" は DOWN を示す。CloudWatch コンソールから直接確認可能。

🔍 階層的なネットワーク監視

LagStatus (物理層) + VifConnectionStatus (仮想IF層) + VifBgpSessionState (ルーティング層) の 3 つのメトリクスを組み合わせ、障害箇所を迅速に特定。

🔔 CloudWatch 統合

CloudWatch コンソールでのメトリクス表示、アラームによる自動通知、ダッシュボードへの組み込みによる統合的な可視化が可能。

📐 技術仕様

メトリクス詳細

項目詳細
メトリクス名LagStatus
名前空間AWS/Outposts
値の範囲0 (DOWN) または 1 (UP)
関連メトリクスVifConnectionStatus、VifBgpSessionState

障害切り分けマトリクス

LagStatus VifConnectionStatus VifBgpSessionState 推定される問題
0 - - LAG の物理接続またはリンク集約の問題
1 0 - VIF 接続の構成問題
1 1 0 BGP ピアリングの問題
1 1 1 正常

🛠️ 設定方法

前提条件

✓AWS Outposts ラックがデプロイ済みであること
✓CloudWatch へのアクセス権限を持つ IAM ロール/ユーザーがあること
✓Outposts の LAG が構成済みであること

ステップ 1: CloudWatch コンソールでメトリクスを確認

CloudWatch コンソールにアクセスし、AWS/Outposts 名前空間から LagStatus メトリクスを選択する。

ステップ 2: CloudWatch アラームの作成

Bash LAG ダウン検知アラームの作成 
aws cloudwatch put-metric-alarm \
  --alarm-name "OutpostsLagDown" \
  --namespace "AWS/Outposts" \
  --metric-name "LagStatus" \
  --statistic "Minimum" \
  --period 60 \
  --threshold 1 \
  --comparison-operator "LessThanThreshold" \
  --evaluation-periods 1 \
  --alarm-actions "arn:aws:sns:us-east-1:123456789012:OutpostsAlerts"

LagStatus メトリクスが 1 未満 (つまり 0 = DOWN) になった場合に SNS トピックへ通知するアラームを作成する。

ステップ 3: ダッシュボードへの追加

JSON ダッシュボードウィジェット設定 
{
  "widgets": [
    {
      "type": "metric",
      "properties": {
        "metrics": [
          ["AWS/Outposts", "LagStatus"],
          ["AWS/Outposts", "VifConnectionStatus"],
          ["AWS/Outposts", "VifBgpSessionState"]
        ],
        "title": "Outposts Network Health",
        "period": 60,
        "stat": "Average"
      }
    }
  ]
}

3 つのネットワークメトリクスを 1 つのダッシュボードウィジェットにまとめ、統合的にネットワーク健全性を可視化する。

⚠️ デメリット・制約事項

⚠️ メトリクスは LAG の運用状態のみを示し、帯域幅使用率やパケットロスなどの詳細情報は含まない

⚠️ バイナリ値のため、部分的な LAG デグレデーション (一部リンクのみダウン) は検知できない可能性がある

⚠️ CloudWatch メトリクスの標準的な遅延 (数分程度) が適用される

考慮すべき点

→既存の VifConnectionStatus、VifBgpSessionState メトリクスと組み合わせたアラーム戦略の設計が推奨される
→LAG 冗長構成の場合、個別の LAG ごとにメトリクスを監視する必要がある

💡 ユースケース

🚨 ユースケース 1: ネットワーク障害の自動検知と通知

シナリオ: Outposts 上で本番ワークロードを運用しているチームが、LAG 接続の障害を即座に検知してオンコール担当者に通知したい。

効果: LAG ダウンを 1 分以内に検知し、PagerDuty 経由でオンコール担当者に即座に通知される。

🔍 ユースケース 2: 階層的なネットワーク障害切り分け

シナリオ: Outposts への接続に問題が発生した際に、運用チームが問題の原因箇所を迅速に特定したい。

効果: 3 つのメトリクスを同一ダッシュボードで比較し、障害箇所を即座に可視化。LAG が DOWN なら物理層の問題、LAG が UP で VIF が DOWN なら VIF 構成の問題と判断できる。

📊 ユースケース 3: 定期的な接続健全性レポート

シナリオ: インフラチームが Outposts のネットワーク可用性を週次/月次でレポートしたい。

効果: 月間の LAG 可用性を数値化し、99.9% 以上の接続時間を維持しているかを客観的に評価できる。
