Amazon ECS

🧩 フラクショナル GPU スケジューリングをサポート

Amazon EC2 G6f インスタンスで GPU を 1/8 単位から割り当て可能に | リリース日: 2026 年 8 月 6 日

📌 概要

Amazon ECS が EC2 G6f インスタンスを使用したフラクショナル GPU (GPU の分割割り当て) スケジューリングをサポートしました。G6f は NVIDIA L4 Tensor Core GPU をハードウェアレベルで分割したインスタンスで、タスク定義に GPU=0.125 / 0.25 / 0.5 と小数値を指定するだけで、ECS が適切な G6f インスタンスへタスクを自動配置します。

1/8 GPU
最小割り当て単位 (GPU メモリ 3 GB)
3 種類
指定可能な小数値 (0.125 / 0.25 / 0.5)
追加料金なし
機能自体は無料 (インスタンス料金のみ)

❌ アップデート前の課題

✗GPU 要求は整数値のみ。軽量ワークロードでも GPU 1 基全体を占有
✗小規模モデルの推論・実験では GPU 使用率が低く、リソースが無駄に
✗GPU 分割共有には Kubernetes の MIG / タイムスライシングなど複雑な構成が必要

✅ アップデート後の改善

✓小数値の指定だけで 1/8〜1/2 GPU 単位のスケジューリングが可能
✓必要な GPU 容量のみ割り当ててインフラコストを削減
✓G6f とフル GPU インスタンスを同一キャパシティプロバイダーに混在可能。GPU 値で自動ルーティング
✓Managed Instances なら運用管理 (プロビジョニング〜障害時交換) を AWS に委任

⚡ 主要機能

🧩 フラクショナル GPU のスケジューリング

タスク定義の resourceRequirements で GPU 値として 0.125 / 0.25 / 0.5 の小数値を指定可能。G6f は NVIDIA L4 GPU をハードウェアレベルでパーティション分割し、各インスタンスは専用の GPU メモリとコンピュートを持つ固定 GPU スライス (1/8、1/4、1/2) を提供します。

🔀 フル GPU インスタンスとの混在キャパシティプロバイダー

G6f と G5 / G6 などのフル GPU インスタンスを同一のキャパシティプロバイダーに含めることが可能。整数値はフル GPU 要求、小数値はフラクショナル GPU 要求として扱われ、ECS が適切なインスタンスタイプへ自動ルーティング。GPU ファミリーごとにキャパシティプロバイダーを分ける必要がありません。

🛠️ Amazon ECS Managed Instances との統合

プロビジョニング、スケーリング、パッチ適用、ライフサイクル管理を AWS が実施。CloudWatch Container Insights による GPU メトリクスの取得や、GPU ハードウェア障害時にインスタンスを自動交換するGPU auto-repair も利用できます。

🚀 幅広い起動タイプのサポート

Amazon ECS Managed Instances と Amazon ECS on EC2 の両方で利用可能。AWS Management Console、CLI、SDK、CloudFormation などの IaC ツールから設定できます。

スケジューリングの動作

項目詳細
小数値の指定0.125 / 0.25 / 0.5 のみサポート。対応する GPU パーティションを持つ G6f インスタンスに配置
整数値の指定従来どおりフル GPU 要求として扱われ、フル GPU を持つインスタンスにのみ配置
ALL の指定コンテナインスタンス上のすべての GPU をコンテナに割り当て
タスク内の制約フラクショナル GPU を要求できるのは 1 タスクにつき 1 コンテナのみ。小数値を指定した場合、同一タスク定義内の他のコンテナは GPU リソース要求を持てない
対応起動タイプECS Managed Instances、ECS on EC2 (Fargate と ECS Anywhere は非対応)

タスク定義の設定例

JSON NVIDIA L4 GPU の 1/4 (6 GB) を割り当てる軽量推論タスク定義 
{
  "family": "fractional-gpu-inference",
  "networkMode": "awsvpc",
  "executionRoleArn": "arn:aws:iam::account-id:role/ecsTaskExecutionRole",
  "containerDefinitions": [
    {
      "name": "inference",
      "image": "nvidia/cuda:12.0.0-base-ubuntu22.04",
      "essential": true,
      "command": ["nvidia-smi"],
      "resourceRequirements": [
        {
          "type": "GPU",
          "value": "0.25"
        }
      ],
      "logConfiguration": {
        "logDriver": "awslogs",
        "options": {
          "awslogs-group": "/ecs/fractional-gpu-inference",
          "awslogs-region": "region",
          "awslogs-stream-prefix": "ecs"
        }
      }
    }
  ],
  "requiresCompatibilities": [
    "MANAGED_INSTANCES"
  ],
  "cpu": "2048",
  "memory": "4096"
}

📝 設定方法

前提条件: ECS クラスター作成済み / G6f インスタンスを含むキャパシティプロバイダー設定済み / G6f が利用可能なリージョン / タスク実行ロール (ecsTaskExecutionRole) が用意済み
1
G6f インスタンスを含むキャパシティプロバイダーの設定
Bashキャパシティプロバイダーをクラスターに関連付け
aws ecs put-cluster-capacity-providers \
  --cluster my-gpu-cluster \
  --capacity-providers my-g6f-capacity-provider \
  --default-capacity-provider-strategy capacityProvider=my-g6f-capacity-provider,weight=1

フラクショナル GPU インスタンス (G6f) とフル GPU インスタンス (G5、G6 など) を同一のキャパシティプロバイダーに含めることができます。

2
フラクショナル GPU を指定したタスク定義の登録
Bash小数の GPU 値を含む JSON でタスク定義を登録
aws ecs register-task-definition \
  --cli-input-json file://fractional-gpu-inference.json
3
サービスまたはタスクの起動
BashGPU 値 0.25 に基づき g6f.2xlarge へ自動配置
aws ecs create-service \
  --cluster my-gpu-cluster \
  --service-name fractional-inference-service \
  --task-definition fractional-gpu-inference \
  --desired-count 4
4
GPU メトリクスの確認

Managed Instances 使用時は CloudWatch Container Insights で GPU 使用率などを確認可能。GPU ハードウェア障害が検出された場合はインスタンスが自動的に交換されます。

💡 メリット

💼 ビジネス面

✓インフラコストの削減: 必要な分 (最小 1/8 GPU) だけを割り当てて GPU インフラのコストを最適化
✓GPU 利用効率の向上: 遊休 GPU リソースを削減し、投資対効果を向上
✓小規模 AI ワークロードの導入障壁の低下: 推論や実験を低コストで開始でき、AI 活用のスモールスタートが容易に

⚙️ 技術面

✓シンプルな設定: GPU 値を小数にするだけ。MIG やタイムスライシングのような複雑な GPU 分割設定が不要
✓ハードウェアレベルの分離: 専用の GPU メモリとコンピュートを持つパーティションにより、ワークロード間の干渉が起きにくい
✓柔軟なキャパシティ管理: フラクショナルとフル GPU を単一のキャパシティプロバイダーで管理、GPU 値に応じて自動ルーティング
✓運用負荷の軽減: Managed Instances でプロビジョニングから GPU 障害時の自動交換まで AWS に委任

⚠️ デメリット・制約事項

制限事項

サポートされる小数値は 0.125 / 0.25 / 0.5 の 3 種類のみ (G6f インスタンスタイプの GPU パーティションに依存)
フラクショナル GPU を要求できるのは 1 タスクにつき 1 コンテナのみ。同一タスク内の他のコンテナは GPU を要求不可
AWS Fargate と Amazon ECS Anywhere は非対応
利用できるのは EC2 G6f / Gr6f インスタンスが提供されているリージョンに限られる

考慮すべき点

→GPU パーティションは固定サイズ (1/8、1/4、1/2) のため、GPU メモリ要件 (3 GB / 6 GB / 12 GB) を事前に見積もる必要がある
→整数値の GPU 要求はフル GPU インスタンスにのみ配置。G6f への移行にはタスク定義の GPU 値を小数に変更する必要がある
→GPU メモリは最大 12 GB のため、大規模モデルの推論や学習には引き続きフル GPU インスタンスが必要

🎯 ユースケース

1. 🤖 小規模モデルの AI 推論サービス

数億〜数十億パラメータ規模の軽量モデル (画像分類、埋め込み生成、小規模 LLM など) を推論 API として提供。フル GPU では容量が過剰でコストが見合わないケース。

JSON実装例
"resourceRequirements": [
  { "type": "GPU", "value": "0.25" }
]
✅ 効果: 1/4 GPU (6 GB) で推論コンテナを実行し、必要容量に応じたコストに最適化。トラフィック増加時は ECS サービスのスケールアウトで対応。
2. 🧪 モデル実験・開発環境の集約

データサイエンスチームの複数メンバーが軽量な実験用 GPU 環境を必要とするが、メンバーごとのフル GPU 割り当てはコストが高いケース。

JSON実装例
"resourceRequirements": [
  { "type": "GPU", "value": "0.125" }
]
✅ 効果: 最小 1/8 GPU (3 GB) の実験用タスクを多数実行でき、開発・検証環境の GPU コストを大幅に削減。ハードウェアパーティションによりユーザー間の干渉も防止。
3. 🔀 フル GPU と混在した推論プラットフォーム

大規模モデルにはフル GPU、軽量モデルにはフラクショナル GPU を使い分けたいが、キャパシティプロバイダーを分けて管理するのは運用負荷が高いケース。

Plaintext実装例
# 同一キャパシティプロバイダーに G6f と G6 を混在
# 軽量モデル用タスク定義: "value": "0.5"  → g6f.4xlarge に配置
# 大規模モデル用タスク定義: "value": "1"   → G6 などフル GPU に配置
✅ 効果: 単一のキャパシティプロバイダーで異なる GPU 要件のワークロードを管理。ECS が GPU 値に基づいて自動ルーティングし、運用がシンプルに。

💰 料金・利用可能リージョン

フラクショナル GPU スケジューリング機能自体に追加料金はありません。使用した EC2 G6f / Gr6f インスタンスの料金が発生します。G6f は NVIDIA L4 GPU のフラクションを提供するため、フル GPU 搭載の同世代インスタンスより低い時間単価で GPU ワークロードを実行できます。

→ECS on EC2: EC2 インスタンス料金のみ (ECS 自体は追加料金なし)
→ECS Managed Instances: EC2 インスタンス料金に加えて Managed Instances の管理料金が発生
🌍 利用可能リージョン: Amazon EC2 G6f インスタンスが利用可能なすべての AWS リージョン

最新の料金: Amazon EC2 G6 インスタンス / Amazon ECS の料金

🔗 関連サービス・機能

🖥️ Amazon EC2 G6f / Gr6f インスタンス

NVIDIA L4 GPU をハードウェアレベルで分割 (1/8、1/4、1/2) したインスタンスファミリー。本機能の基盤。

🛠️ Amazon ECS Managed Instances

プロビジョニング、スケーリング、パッチ適用などを AWS が管理するキャパシティオプション。GPU 障害時の自動交換にも対応。

📊 Amazon CloudWatch Container Insights

ECS タスク・インスタンスの GPU メトリクスを含む詳細なモニタリングを提供。

📄 AWS CloudFormation

キャパシティプロバイダーやタスク定義を IaC として管理可能。

✅ まとめ

Amazon ECS のフラクショナル GPU スケジューリングにより、タスク定義の GPU 値を小数 (0.125 / 0.25 / 0.5) にするだけで、G6f インスタンスの GPU パーティションを活用した低コストな GPU ワークロード運用が可能になりました。小規模モデルの推論や実験など GPU 1 基をフルに使わないワークロードを ECS で運用している場合は、タスク定義の GPU 値の見直しと G6f インスタンスを含むキャパシティプロバイダーの導入を検討することを推奨します。
