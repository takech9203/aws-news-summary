Amazon Bedrock AgentCore Runtime

Bring-Your-Own File System Support

Amazon S3 Files / Amazon EFS

2026-05-06

📋 概要

Amazon Bedrock AgentCore Runtime が Bring-Your-Own File System 機能をサポート。 開発者が Amazon S3 Files および Amazon EFS のアクセスポイントをエージェントランタイムに直接アタッチでき、 AgentCore Runtime がファイルシステムを指定パスにセッションごとにマウントする。 カスタムマウントコード、特権コンテナ、事前ダウンロードのオーケストレーションは一切不要。

❌ Before

  • セッション開始前にダウンロードオーケストレーションの構築が必要
  • セッション間/エージェント間のデータ共有が複雑
  • 中間結果の永続化と再開が困難
  • カスタムマウントコードや特権コンテナが必要

✅ After

  • アクセスポイント ARN 指定だけで自動マウント
  • 標準ファイル操作 (read/write) でアクセス可能
  • 複数エージェント/セッション間で透過的にデータ共有
  • S3 Files ではバケットとの自動同期を提供

⚡ 主要機能

🪣 Amazon S3 Files アクセスポイントのマウント

  • S3 Files ファイルシステムをエージェントセッションにマウント
  • 標準ファイル操作と S3 API の両方でデータにアクセス可能
  • ファイルシステムと S3 バケット間の変更が自動同期
  • サブミリ秒レイテンシで NFS close-to-open 一貫性を提供

📁 Amazon EFS アクセスポイントのマウント

  • 専用の共有 NFS ファイルシステムとしてマウント
  • 複数エージェント間でのリアルタイムデータ共有
  • EFS の既存アクセス制御とセキュリティモデルを活用
  • サブミリ秒レイテンシで NFS close-to-open 一貫性を提供

🔗 マネージドセッションストレージとの併用

  • 既存のマネージドセッションストレージ (パブリックプレビュー) と組み合わせ可能
  • セッション固有の一時データにはセッションストレージを使用
  • 共有データには Bring-Your-Own ファイルシステムを使用
  • 用途に応じた使い分けが可能

{
  "filesystemConfigurations": [
    {
      "sessionStorage": {
        "mountPath": "/tmp/session"
      },
      "s3FilesAccessPoint": {
        "accessPointArn": "arn:aws:s3:us-east-1:123456789012:accesspoint/my-s3-files-ap",
        "mountPath": "/mnt/s3files"
      },
      "efsAccessPoint": {
        "accessPointArn": "arn:aws:elasticfilesystem:us-east-1:123456789012:access-point/fsap-0123456789abcdef0",
        "mountPath": "/mnt/efs"
      }
    }
  ]
}

AgentCore Runtime の作成

Bash AWS CLI - S3 Files アクセスポイントをマウント 
aws bedrock-agentcore-control create-agent-runtime \
  --agent-runtime-name "my-file-agent" \
  --agent-runtime-artifact '{"containerConfiguration":{"containerUri":"123456789012.dkr.ecr.us-east-1.amazonaws.com/my-agent:latest"}}' \
  --role-arn "arn:aws:iam::123456789012:role/AgentCoreRuntimeRole" \
  --network-configuration '{"networkMode":"VPC","networkModeConfig":{"securityGroups":["sg-xxx"],"subnets":["subnet-xxx"]}}' \
  --filesystem-configurations '[{"s3FilesAccessPoint":{"accessPointArn":"arn:aws:s3:us-east-1:123456789012:accesspoint/my-agent-files-ap","mountPath":"/mnt/data"}}]'

EFS アクセスポイントの追加

Bash AWS CLI - 既存ランタイムに EFS を追加 
aws bedrock-agentcore-control update-agent-runtime \
  --agent-runtime-id "agent-runtime-id" \
  --filesystem-configurations '[{"efsAccessPoint":{"accessPointArn":"arn:aws:elasticfilesystem:us-east-1:123456789012:access-point/fsap-0123456789abcdef0","mountPath":"/mnt/shared"}}]'

🎯 ユースケース

📚 共有スキルライブラリ

複数のエージェントが共通のプロンプトテンプレートやツール定義を使用する環境で、更新を一元管理したいケース。

効果: スキルの更新を S3 バケットにアップロードするだけで、すべてのエージェントセッションに即座に反映。再デプロイやセッション再起動が不要。

💾 長時間ワークフローの中間結果永続化

データ分析エージェントが大規模データセットを処理し、中間結果を保存して翌日のセッションで作業を継続するケース。

効果: エージェントは /workspace に中間結果を書き込み、セッション終了後も EFS 上にデータが永続化。次回セッションで即座に前回の状態から再開可能。

🔄 マルチエージェントパイプライン

データ収集エージェントが出力したファイルを、別の分析エージェントが入力として消費するパイプラインを構築するケース。

効果: 収集エージェントが /pipeline/output/ に書き込んだデータを、分析エージェントが即座に読み取り可能。S3 API 経由での外部システム連携も同時に実現。

⚖️ メリット・制約事項

✅ メリット

  • 開発速度向上: カスタムオーケストレーションコードが不要
  • 運用コスト削減: マネージドマウントでオーバーヘッド軽減
  • マルチエージェント協調: パイプライン型ワークフローを容易に構築
  • サブミリ秒レイテンシ: エージェントのレスポンスに影響なし
  • NFS close-to-open 一貫性: データ整合性を保証
  • S3 デュアルアクセス: NFS と S3 API の両方で利用可能

⚠️ 制約事項

  • VPC モード必須 (PUBLIC ネットワークモードでは不可)
  • アクセスポイント ARN の事前作成が必要
  • IAM ロールに適切な権限設定が必要
  • VPC 設定に伴うネットワーク構成の複雑化
  • S3 Files と EFS の適切な選定が必要
  • NFS close-to-open 一貫性モデルの理解が必要

💰 料金
