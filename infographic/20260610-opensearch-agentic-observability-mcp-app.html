📌 概要

Amazon OpenSearch Service が MCP Apps に対応し、オブザーバビリティのワークフローを Claude Desktop や VS Code などのエージェント型 IDE に直接統合できるようになりました。ローカルで動作する AI エージェントが、OpenSearch ドメイン、コレクション、Amazon Managed Service for Prometheus のログ・トレース・メトリクス・アラートを使ってインシデントを調査します。

最大の特徴は デュアルレスポンス。各ツール呼び出しが「エージェント推論用のテキストサマリー」と「人間が検証できるインタラクティブな可視化」を同時に返します。アラート発報 → 根本原因分析 → 分散トレース → サービスマップ → PromQL チャート → クロスシグナル相関までを、ローカル環境を離れず 1 つの会話内で完結できます。

対象は SRE・運用エンジニア・オブザーバビリティ担当者。Amazon OpenSearch UI が提供されているすべての AWS リージョンで利用できます。

❌ Before（従来の課題）

  • OpenSearch UI のダッシュボードと IDE を行き来する必要があった
  • AI が返すテキストのみの調査結果は可視化を伴わず検証が難しかった
  • アラート → 根本原因分析 → トレース探索が複数ツールに分断
➜

✅ After（改善後）

  • オブザーバビリティワークフローをエージェント型 IDE 内に直接持ち込める
  • テキスト + 可視化を同時に返し、推論結果をその場で検証できる
  • アラート〜相関分析まで単一の会話スレッドで完結

⚙️ 主要機能

1️⃣ デュアルレスポンス

  • 1 回のツール呼び出しで、エージェント推論用のテキストサマリーと人間検証用の可視化を同時に返す
  • 可視化は同じ会話スレッド内にレンダリングされ、その場で確認できる
  • 可視化は OpenSearch UI アプリケーションから生成される

2️⃣ 複数シグナルにまたがる調査

  • ログ・トレース・メトリクス・アラートを横断して調査
  • OpenSearch ドメイン、コレクション、Amazon Managed Service for Prometheus をデータソースに
  • クロスシグナル相関でシグナル間をまたいだ分析が可能

3️⃣ ローカル MCP サーバーによる連携

  • ローカルマシン上の MCP サーバーが IDE と OpenSearch UI を仲介
  • Claude Desktop、VS Code GitHub Copilot、Goose、ChatGPT、Cursor などに対応
  • mcpb ファイルによる設定フロー、または server.js を参照した手動設定に対応

必要な IAM 権限

MCP サーバーが OpenSearch UI アプリケーションへアクセスするため、es:ESHttpGet と es:ESHttpPost を許可する認証情報が必要です。

JSONIAM ポリシー例
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "es:ESHttpGet",
        "es:ESHttpPost"
      ],
      "Resource": "arn:aws:es:<region>:<account-id>:domain/<application>/*"
    }
  ]
}

MCP サーバー設定例

JSONmcpServers 設定
{
  "mcpServers": {
    "opensearch-observability-stack-mcp": {
      "command": "node",
      "args": ["/path/to/opensearch-observability-stack-mcp/server/server.js"],
      "env": {
        "OS_UI_ENDPOINT": "application-foo-bar.us-west-2.opensearch.amazonaws.com",
        "AWS_REGION": "us-west-2",
        "AWS_PROFILE": "my-profile"
      }
    }
  }
}

検証に成功すると Good signature from "OpenSearch MCP ..." が出力されます。

ステップ 2: MCP サーバーの設定

zip を展開し mcpb ファイルを開くと対応 IDE で設定フローが開始されます。機能しない場合は server.js を参照し、IDE の拡張機能セクションから手動設定（OS_UI_ENDPOINT / AWS_REGION / args のパスを置き換え）します。

ステップ 3: 接続の確認

IDE で「List available observability data sources」のような質問を入力して接続を確認します。接続が確立されると、AI エージェントがオブザーバビリティデータを使った調査を実行できます。

🎯 ユースケース

1. アラート発報からの根本原因分析

シナリオ：あるサービスでレイテンシー悪化のアラートが発報。SRE は Claude Desktop 上で発報中のアラートをトリアージしてから調査を開始。

💬 発報中のアラートを表示して、最も重大なものから根本原因を調査して

効果：重大度別の発報状況を確認し、その場で根本原因分析へ移行。調査の起点を素早く特定できる。

2. 分散トレースによる障害箇所の特定

シナリオ：マイクロサービス構成でエラー率が上昇。トレース調査ツールでスパン階層を可視化し障害の発生源を特定。

💬 エラーが多いトレースを見つけて、どのスパンで失敗が起きているか分析して

効果：スパン階層とタイムラインを可視化し、AI 分析とあわせて発生源を特定。サービスマップで影響範囲（ブラストラディウス）も把握。

3. PromQL メトリクスのインタラクティブ調査

シナリオ：Amazon Managed Service for Prometheus のメトリクスでリソース使用率の傾向を調査。

💬 直近 1 時間のサービスごとのエラー数を PromQL で集計してチャートで見せて

効果：PromQL 結果が折れ線・棒・エリア・メトリクスチャートでレンダリングされ、挙動分析とあわせ傾向を把握。

📝 まとめ

本アップデートは、AI エージェントによるオブザーバビリティ調査を、検証可能な可視化とともにローカルの IDE 内へ統合する重要な機能です。アラート対応から根本原因分析までを単一の会話で完結でき、運用チームのインシデント対応を大幅に効率化できます。

まずは OpenSearch UI のオブザーバビリティワークスペースを準備し、対応 IDE に MCP サーバーを設定して、サンプルデータでの調査フローを試すことを推奨します。
