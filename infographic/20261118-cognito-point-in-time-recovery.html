Amazon Cognito

🔐 ポイントインタイムリカバリ (PITR) のサポート

📅 リリース日: 2026 年 11 月 18 日 | ユーザープールのユーザーデータを過去の特定時点に復元

📌 概要

Amazon Cognito が ポイントインタイムリカバリ (PITR) をサポートしました。管理スクリプトの誤実行、アプリケーションのバグ、不正なアクティビティなどでユーザーやその属性、サインイン認証情報が誤って削除・変更された場合に、過去の特定時点の状態にロールバックできます。

リカバリは 2 段階のプロセスです。リカバリポイントを指定して開始すると書き込み操作が一時停止され、作成・更新・削除されるエンティティ数を示すリカバリプレビューが生成されます。管理者は内容を確認したうえで適用またはキャンセルを選択できます。復元されたユーザーは識別子、パスワード、MFA 設定、パスキーを保持するため、認証情報のリセットは不要です。

❌ Before: アップデート前の課題
  • 誤削除・誤変更に備えるには独自のエクスポート・リストアプロセスの構築・維持が必要
  • 独自の方法で復元したユーザーには新しい識別子が割り当てられ、既存 ID との整合性が崩れる
  • 復元後のユーザーはパスワードリセットが必要で、ユーザー体験が損なわれる
✅ After: アップデート後の改善
  • マネージドな機能として、過去の時点の状態にそのまま復元可能
  • 識別子、パスワード、MFA 設定、パスキーを保持し、既存の認証情報でそのままサインイン可能
  • 実行前にプレビューで影響範囲を確認し、適用またはキャンセルを選択可能

🏗️ リカバリフロー

sequenceDiagram
    participant Admin as 👤 管理者
    participant Cognito as 🔐 Amazon Cognito
    participant Pool as 📋 ユーザープール

    Admin->>Cognito: InitiatePointInTimeRecovery
    Note over Pool: 書き込み操作を一時停止
サインインと読み取りは継続
    Cognito->>Cognito: リカバリプレビューを生成
    Admin->>Cognito: DescribePointInTimeRecovery
    Cognito-->>Admin: 影響エンティティ数を返却
    alt リカバリを適用
        Admin->>Cognito: StartPointInTimeRecovery
        Cognito->>Pool: ユーザーデータを復元
        Note over Pool: 完了後に書き込み操作を再開
    else リカバリをキャンセル
        Admin->>Cognito: CancelPointInTimeRecovery
        Note over Pool: データ変更なしで書き込み操作を再開
    end

リカバリの開始からプレビュー確認、適用またはキャンセルまでの流れです。プレビュー生成から復元完了 (またはキャンセル) までの間、ユーザープールへの書き込み操作は一時停止されます。サインインと読み取りは継続されます。

⚡ 主要機能

🕐 特定時点へのユーザーデータ復元

→ リカバリポイントを指定して、ユーザープール内のユーザーデータをその時点の状態に復元

→ リカバリポイント以降に削除されたユーザーは再作成、作成されたユーザーは削除、変更されたユーザーは当時の状態に復元

→ 同一ユーザープール内で実行され、ユーザープールの ID、ARN、設定は維持される

🔍 リカバリプレビューによる事前確認

→ 適用前に、ユーザー、グループ、ユーザー MFA、パスキーの作成・更新・削除件数を確認可能

→ プレビュー確認後、適用 (Start) またはキャンセル (Cancel) を選択

→ 開始から 24 時間以内に適用・キャンセルしない場合、プレビューは失効しデータ変更なしで書き込みが再開

🔑 認証情報を保持した復元

→ 復元されたユーザーは識別子、パスワード、MFA 設定 (認証アプリの TOTP を含む)、パスキーを保持

→ 既存の認証情報でそのままサインインでき、パスワードリセットは不要

→ リカバリポイント以降にユーザー自身が変更したパスワードは巻き戻されない (現在のパスワードが維持)

📜 CloudTrail による監査

→ PITR の各 API 操作は CloudTrail の管理イベントとして記録

→ リカバリ適用時には、変更されたエンティティごとに CognitoPointInTimeRecovery サービスイベントが記録され、変更内容を監査可能

📦 復元対象と対象外

✅ 復元されるデータ
✓ユーザープロファイル (標準属性とカスタム属性)
✓グループとグループメンバーシップ
✓再作成されるユーザーのパスワード
✓ユーザーの MFA 設定 (認証アプリの TOTP を含む)
✓パスキー
❌ 復元されないもの (現在の状態が維持)
✗ユーザープール設定 (属性スキーマ、パスワード・MFA ポリシー、Lambda トリガー、メッセージテンプレート、脅威保護設定、マルチリージョンレプリケーション設定)
✗アプリクライアントとクライアントシークレット
✗ID プロバイダーとリソースサーバー
✗ドメイン、マネージドログインのブランディング、クラシックホスト UI のカスタマイズ
✗暗号化設定 (カスタマーマネージドキーを含む)
✗ログ配信設定と AWS WAF Web ACL の関連付け
✗記憶されたデバイスとユーザー認証イベント履歴
✗ユーザーセッション、発行済み・失効済みトークン、ワンタイムコード
✗ユーザーインポートジョブ

⚠️ リカバリウィンドウは PITR を含む機能プランの利用開始時点から始まります。Plus プランで 14 日前まで復元できるのは、過去 14 日間継続して Plus プランを利用していた場合のみです。プランを変更するとリカバリウィンドウはリセットされます。

🔌 API 操作

API 操作説明
InitiatePointInTimeRecovery書き込み操作を一時停止し、指定したリカバリポイントのプレビューを生成
DescribePointInTimeRecoveryリカバリのステータスとプレビューを取得
StartPointInTimeRecoveryプレビュー確認後にリカバリを適用
CancelPointInTimeRecoveryリカバリを破棄し、書き込み操作を再開
ListPointInTimeRecoveriesユーザープールの現在および過去のリカバリを一覧表示

🛡️ IAM ポリシー例

InitiatePointInTimeRecovery を実行できるプリンシパルは最大 24 時間書き込み操作を停止でき、StartPointInTimeRecovery を実行できるプリンシパルはユーザーデータを巻き戻せるため、これらの権限は信頼できる管理者にのみ付与します。

JSON PITR 用 IAM ポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "ViewPointInTimeRecoveries",
            "Effect": "Allow",
            "Action": [
                "cognito-idp:DescribePointInTimeRecovery",
                "cognito-idp:ListPointInTimeRecoveries"
            ],
            "Resource": "arn:aws:cognito-idp:us-east-1:111122223333:userpool/*"
        },
        {
            "Sid": "ManagePointInTimeRecoveries",
            "Effect": "Allow",
            "Action": [
                "cognito-idp:InitiatePointInTimeRecovery",
                "cognito-idp:StartPointInTimeRecovery",
                "cognito-idp:CancelPointInTimeRecovery"
            ],
            "Resource": "arn:aws:cognito-idp:us-east-1:111122223333:userpool/us-east-1_EXAMPLE"
        }
    ]
}

⚙️ 設定方法

📋 前提条件

✓ユーザープールが Essentials または Plus 機能プランであること (PITR は自動的に有効化される)
✓実行する IAM プリンシパルに PITR 関連の cognito-idp 権限があること
✓カスタマーマネージド KMS キーで暗号化している場合、リカバリ期間中もキーが有効で Cognito からアクセス可能であること
✓ユーザーインポートジョブが実行中でないこと

ステップ 1: リカバリを開始する

Bash リカバリの開始 
aws cognito-idp initiate-point-in-time-recovery \
    --user-pool-id us-east-1_EXAMPLE \
    --restore-timestamp 2026-11-17T12:00:00Z

指定したリカバリポイント (この例では 2026 年 11 月 17 日 12:00 UTC) へのリカバリを開始します。この時点で書き込み操作が一時停止され、レスポンスにリカバリ ID (RestoreId) が返されます。

ステップ 2: プレビューを確認する

Bash プレビューの確認 
aws cognito-idp describe-point-in-time-recovery \
    --user-pool-id us-east-1_EXAMPLE \
    --restore-id a1b2c3d4-5678-90ab-cdef-111111111111

ステータスが PREVIEW_GENERATED になると、RestorePreview にユーザー、グループ、ユーザー MFA、パスキーごとの作成・更新・削除件数が表示されます。

ステップ 3: リカバリを適用またはキャンセルする

Bash 適用またはキャンセル 
# 適用する場合
aws cognito-idp start-point-in-time-recovery \
    --user-pool-id us-east-1_EXAMPLE \
    --restore-id a1b2c3d4-5678-90ab-cdef-111111111111

# キャンセルする場合
aws cognito-idp cancel-point-in-time-recovery \
    --user-pool-id us-east-1_EXAMPLE \
    --restore-id a1b2c3d4-5678-90ab-cdef-111111111111

適用後は describe-point-in-time-recovery でステータスが RESTORE_COMPLETED になるまで監視します。キャンセルした場合はデータ変更なしで書き込み操作が再開されます。

💡 メリット

💼 ビジネス面
✓ディザスタリカバリ体制の強化: 誤操作や不正アクティビティによるデータ損失から追加コストなしで迅速に復旧
✓ユーザー体験の維持: 復元後も既存のパスワード、MFA、パスキーでサインインでき、リセット案内やサポート対応が不要
✓運用コストの削減: 独自のエクスポート・リストアの仕組みの構築・維持が不要に
🔧 技術面
✓識別子の保持: 元の識別子を保持するため、外部システムとの ID 連携や参照整合性が崩れない
✓プレビューによる安全な運用: 適用前に影響範囲を定量的に確認でき、意図しない復元を防止
✓監査性: CloudTrail の管理イベントとサービスイベントでリカバリ操作と変更エンティティを追跡可能

⚠️ デメリット・制約事項

🚫 制限事項

✗Lite 機能プランでは利用できない (Essentials は 1 日、Plus は 14 日のリカバリウィンドウ)
✗リカバリ中は書き込み操作が停止する (サインアップ、ユーザー作成・削除、属性更新、パスワード変更などが拒否される)
✗新しいユーザープール、別リージョン、別アカウントへの復元は不可 (同一ユーザープール内のインプレース復元のみ)
✗ユーザープール設定、アプリクライアント、ID プロバイダー、セッションやトークンなどは復元対象外
✗機能プランを変更するとリカバリウィンドウがリセットされる
✗一部の古いユーザープールや、サポートされない文字・形式のユーザーデータを含む場合は利用できないことがある
✗マルチリージョンレプリケーション構成では、プライマリリージョンでのみ、かつレプリケーション変更が進行中でない場合にのみ開始可能

🤔 考慮すべき点

⚠️書き込み停止中は NEW_PASSWORD_REQUIRED、MFA_SETUP、SOFTWARE_TOKEN_MFA チャレンジを伴うサインインが失敗するため、メンテナンスメッセージ表示などの準備を推奨
⚠️リカバリポイント以降にユーザー自身が変更したパスワードは巻き戻されないため、必要に応じて AdminResetUserPassword でリセットを強制
⚠️PITR は災害復旧用の機能。個別ユーザーの削除や変更の取り消しには AdminDeleteUser や AdminUpdateUserAttributes を使用
⚠️InitiatePointInTimeRecovery と StartPointInTimeRecovery の権限は最小限の管理者に限定

🎯 ユースケース

1️⃣ 管理スクリプトの誤実行からの復旧

シナリオ: クリーンアップ用の管理スクリプトのバグにより、アクティブなユーザーを含む多数のユーザーが誤って削除された。

Bashスクリプト実行直前の時点を指定してリカバリを開始
aws cognito-idp initiate-point-in-time-recovery \
    --user-pool-id us-east-1_EXAMPLE \
    --restore-timestamp 2026-11-18T08:55:00Z

効果: 削除されたユーザーが元の識別子、パスワード、MFA 設定、パスキーとともに再作成され、ユーザーは何も操作することなく従来どおりサインインできる。

2️⃣ 不正アクティビティによるデータ改ざんへの対応

シナリオ: アカウント内の不正なアクティビティにより、多数のユーザー属性やグループメンバーシップが改ざんされた疑いがある。

Bashプレビューで影響範囲を確認してから適用を判断
aws cognito-idp describe-point-in-time-recovery \
    --user-pool-id us-east-1_EXAMPLE \
    --restore-id a1b2c3d4-5678-90ab-cdef-111111111111

効果: 改ざん前の時点にユーザーデータを戻しつつ、CloudTrail の CognitoPointInTimeRecovery サービスイベントで復元によって変更されたエンティティを監査できる。

3️⃣ アプリケーションバグによる属性破損の巻き戻し

シナリオ: アプリケーションの不具合により、デプロイ後にユーザーのカスタム属性が誤った値で上書きされ続けていた。

Bashデプロイ直前の時点へ復元し、完了を監視
aws cognito-idp start-point-in-time-recovery \
    --user-pool-id us-east-1_EXAMPLE \
    --restore-id a1b2c3d4-5678-90ab-cdef-111111111111

効果: 破損した属性値をデプロイ前の状態に一括で戻せる。ユーザープール設定やアプリクライアントは影響を受けないため、修正済みアプリケーションをそのまま運用継続できる。

💰 料金と利用可能リージョン

💵 料金

PITR は Essentials および Plus 機能プランのユーザープールで追加料金なしで自動的に有効化されます。機能プラン自体の料金は月間アクティブユーザー (MAU) に基づく Amazon Cognito の料金体系に従います。

詳細: Amazon Cognito の料金ページ

🌍 利用可能リージョン

Amazon Cognito が利用可能なすべての AWS リージョンで利用できます。

詳細: AWS リージョン別サービス一覧

🔗 関連サービス・機能

📋 Amazon Cognito 機能プラン (Essentials / Plus)

PITR の利用可否とリカバリウィンドウの長さを決定する

📜 AWS CloudTrail

PITR の API 操作とリカバリによるエンティティ変更を記録し、監査を可能にする

🔑 AWS KMS

カスタマーマネージドキーで暗号化されたユーザープールでは、リカバリ中もキーへのアクセスが必要

🗄️ Amazon DynamoDB / Amazon RDS の PITR

他の AWS サービスにも同様のポイントインタイムリカバリ機能があり、システム全体の復旧戦略を統一的に設計できる

📝 まとめ

Amazon Cognito の PITR により、これまで独自に構築する必要があったユーザーデータのバックアップ・リストアが、追加料金なしのマネージド機能として利用できるようになりました。識別子や認証情報を保持したまま復元できる点が大きな特長です。Essentials または Plus プランを利用中のユーザーは、リカバリウィンドウの仕様と書き込み停止の影響を把握したうえで、災害復旧手順に PITR を組み込むことを推奨します。
