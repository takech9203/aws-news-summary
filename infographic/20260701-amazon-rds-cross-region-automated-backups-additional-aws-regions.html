Amazon RDS

クロスリージョン自動バックアップ 対応リージョン拡大

Cross-Region Automated Backups が新たに 4 リージョンで利用可能に
リリース日
2026-07-01

📌 概要

Amazon RDS のクロスリージョン自動バックアップレプリケーションが、 新たに 4 つの AWS リージョンで利用可能になりました。RDS の自動バックアップ (スナップショットおよびトランザクションログ) を 別リージョンへ自動複製し、災害対策 (DR) とビジネス継続性を強化します。

トランザクションログはターゲットリージョンへ頻繁にアップロードされるため、数分以内の RPO を実現。 プライマリリージョンが利用不能になっても、セカンダリリージョンでポイントインタイムリカバリ (PITR) を実行し迅速に業務を再開できます。

Before / After

😟 アップデート前の課題
  • Mexico、Taipei、New Zealand、Thailand を起点としたレプリケーションが設定できなかった
  • これらのリージョンでは独自のバックアップ複製の仕組みを構築する必要があった
  • 離れたリージョンへ自動複製できず、リカバリ地点の選択肢が限られていた
→
😊 アップデート後の改善
  • 上記 4 リージョンを起点に、近隣リージョンへ自動複製が可能に
  • コンソール / SDK / CLI から数クリックでレプリケーションを設定
  • 6 種類の RDS エンジンで、数分以内の RPO を追加インフラなしで実現

プライマリリージョンで作成されたスナップショットとトランザクションログがセカンダリリージョンへ自動的に複製され、 リージョン障害時にセカンダリリージョンで PITR を実行できます。

⚙️ 主要機能

🔄 クロスリージョン自動バックアップレプリケーション
  • スナップショットとトランザクションログを指定した別リージョンへ自動複製
  • スナップショットは準備完了後すぐにクロスリージョンコピーを開始
  • トランザクションログの頻繁なアップロードで数分以内の RPO を達成
🌏 今回追加された対応リージョンペア
  • Mexico (Central) → Europe (Ireland)、US West (N. California)
  • Asia Pacific (Taipei) → Asia Pacific (Singapore)、Asia Pacific (Tokyo)
  • Asia Pacific (New Zealand) → Asia Pacific (Singapore / Sydney / Melbourne)
  • Asia Pacific (Thailand) → Asia Pacific (Singapore)、Asia Pacific (Jakarta)
🗄️ 幅広いデータベースエンジンのサポート
  • RDS for PostgreSQL、MariaDB、MySQL、Db2、Oracle、SQL Server に対応
  • Multi-AZ DB インスタンス構成でもサポート (Multi-AZ DB クラスターは非対応)

🔧 設定方法

前提条件

✓クロスリージョン自動バックアップレプリケーションに対応した RDS DB インスタンスを保有していること
✓ソース DB インスタンスで自動バックアップ (保持期間 1 日以上) が有効になっていること
✓複製先が、ソースリージョンからサポートされている複製先リージョンに含まれていること

ステップ 1: 対応リージョンの確認

describe-source-regions でどのリージョン間でレプリケーションが可能かを確認します。

Bash対応リージョンの確認
aws rds describe-source-regions --region us-west-1

ステップ 2: レプリケーションの開始

start-db-instance-automated-backups-replication で複製設定を開始します。--backup-retention-period で複製先での保持期間を指定します。

Bashレプリケーション開始
aws rds start-db-instance-automated-backups-replication \
    --source-db-instance-arn arn:aws:rds:mx-central-1:123456789012:db:mydbinstance \
    --backup-retention-period 7 \
    --region us-west-1

ステップ 3: 複製されたバックアップからの復元

障害発生時には複製先リージョンで restore-db-instance-to-point-in-time、またはマネジメントコンソールを使用し、 保持期間内の任意の時点にデータベースを復元します。プライマリリージョンが利用不能でも迅速に業務を再開できます。

✅ メリット

💼 ビジネス面

✓災害対策の強化: プライマリ障害時に別リージョンで業務を再開でき、事業継続性を確保
✓地理的な選択肢の拡大: コンプライアンスやデータレジデンシー要件に合わせた DR 設計が可能
✓低い運用コスト: 独自の複製基盤を構築せず、マネージド機能として利用

🛠️ 技術面

✓数分以内の RPO: トランザクションログの頻繁なアップロードでデータ損失を最小化
✓簡単なセットアップ: コンソール / SDK / CLI から数クリックまたは 1 コマンドで設定
✓幅広いエンジン対応: 主要 6 エンジンで一貫した DR 手法を適用

⚠️ デメリット・制約事項

制限事項

✗Multi-AZ DB クラスターではクロスリージョン自動バックアップレプリケーションは非対応
✗デフォルトでは 1 AWS アカウントあたり最大 20 のクロスリージョン自動バックアップに制限
✗レプリケーション可能なリージョンペアは定められた組み合わせに限られる (任意のリージョン間ではない)

考慮すべき点

⚠スナップショットコピーによるデータ転送料金、および複製先リージョンでのストレージ料金が発生
⚠機能とサポートは DB エンジンの特定バージョンおよび AWS リージョンによって異なるため、事前確認が必要

🎯 ユースケース

1. 台北リージョンの DB DR を東京リージョンで構築
シナリオ: AP (Taipei) で本番 DB を稼働する企業が、地理的に近い AP (Tokyo) をセカンダリとして DR を構築したい。
実装: ソース = AP (Taipei) の RDS for PostgreSQL、複製先 = AP (Tokyo)。start-db-instance-automated-backups-replication で複製を開始。
効果: 台北で障害が発生しても、東京で数分以内の RPO により迅速に復元できる。
2. メキシコから米国・欧州への地理的分散 DR
シナリオ: Mexico (Central) で運用する組織が、大陸をまたいだ地理的分散による堅牢な DR を実現したい。
実装: ソース = Mexico (Central) の RDS for MySQL、複製先 = US West (N. California) または Europe (Ireland)。
効果: 大きく離れたリージョンへ複製することで、広域災害に対する耐性を高められる。
3. ニュージーランドを起点としたオセアニア圏 DR
シナリオ: AP (New Zealand) の金融系ワークロードで、規制要件に合わせ域内・近隣リージョンで DR を構成したい。
実装: ソース = AP (New Zealand) の RDS for SQL Server、複製先 = AP (Sydney / Melbourne / Singapore)。
効果: オセアニア圏内での複製でデータレジデンシー要件を満たしつつ、復旧性を確保できる。

💰 料金

クロスリージョン自動バックアップレプリケーション自体に追加の機能料金はありません。ただし、以下の料金が発生します。

使用量月額料金 (概算)
リージョン間データ転送転送量に応じた従量課金 (詳細は RDS 料金ページを参照)
複製先ストレージ複製先リージョンの標準バックアップストレージ料金

正確な料金は対象エンジンとリージョンにより異なるため、RDS 料金ページ を確認してください。

📝 まとめ

今回のアップデートにより、Mexico (Central)、Asia Pacific (Taipei / New Zealand / Thailand) を起点とした クロスリージョン自動バックアップレプリケーションが利用可能になり、これらのリージョンで稼働するデータベースの災害対策の選択肢が広がりました。 ミッションクリティカルなワークロードを運用している場合は、複製先リージョンを選定し、数分以内の RPO を実現する DR 構成の導入を検討することを推奨します。
