🖥️ Amazon EC2

R8i / R8i-flex インスタンスが
ストックホルム・チューリッヒで提供開始

📅 2026 年 7 月 20 日

📌 概要

Amazon EC2 の R8i および R8i-flex インスタンス が、新たに欧州 (ストックホルム) および欧州 (チューリッヒ) の 2 リージョンで利用可能になりました。 これらは AWS 専用にカスタマイズされた第 6 世代 Intel Xeon 6 プロセッサを搭載したメモリ最適化インスタンスです。

R8i は前世代の Intel ベースインスタンスと比較して最大 15% 優れた価格性能比 と 2.5 倍のメモリ帯域幅 を提供します。 R8i-flex は AWS 初のメモリ最適化 Flex インスタンスであり、リソースを常時フル活用しないワークロード向けにさらに 5% 優れた価格性能比と 5% 低い価格を提供します。

⛔ Before：アップデート前の課題
  • ストックホルム・チューリッヒでは最新世代のメモリ最適化インスタンス R8i / R8i-flex を利用できなかった
  • 前世代の R7i ではメモリ帯域幅やコアあたりのパフォーマンスに制約があった
  • リソースを常時フル活用しないワークロード向けのコスト最適化されたメモリ最適化インスタンスの選択肢が限られていた
🎉 After：アップデート後の改善
  • 欧州 (ストックホルム)、欧州 (チューリッヒ) で R8i / R8i-flex を利用可能に
  • 前世代比で最大 15% 優れた価格性能比、2.5 倍のメモリ帯域幅を利用可能に
  • R8i-flex により、リソースをフル活用しないワークロード向けに追加で 5% のコスト削減が可能に

新規対応した 2 つのリージョンで、R8i / R8i-flex がカスタム Intel Xeon 6 プロセッサと第 6 世代 Nitro Card を基盤として利用できることを示している

⚙️ 主要機能

🧠 カスタム Intel Xeon 6 プロセッサ
  • AWS 専用にカスタマイズされた第 6 世代 Intel Xeon 6 プロセッサを搭載
  • 全コアターボ周波数は最大 3.9 GHz (R7i の 3.2 GHz から向上)
  • L3 キャッシュは前世代比で 4.6 倍 に拡大
  • Intel AMX の FP16 データ型をサポート
🖥️ R8i インスタンス
  • large から 96xlarge まで、ベアメタル 2 サイズを含む 13 サイズを提供
  • 新たに 96xlarge サイズ (384 vCPU、3,072 GiB) を追加
  • SAP 認定済みで、142,100 aSAPS のミッションクリティカルな SAP ワークロードに対応
  • メモリ集約型ワークロードや継続的な高 CPU 使用率のワークロードに最適
💡 R8i-flex インスタンス
  • AWS 初のメモリ最適化 Flex インスタンス
  • large から 16xlarge までのサイズを提供
  • CPU パフォーマンスの 95% を最大限まで引き出せる
  • すべてのコンピューティングリソースを常時フル活用しないワークロードに最適
🔧 第 6 世代 AWS Nitro Card
  • 前世代比で最大 2 倍のネットワークおよび EBS 帯域幅を提供
  • ネットワークと Amazon EBS 帯域幅の間で 25% 単位の割り当て調整が可能

✅ メリット

💼 ビジネス面

  • コスト最適化：前世代比で最大 15% 優れた価格性能比により実行コストを削減
  • Flex による追加削減：R8i-flex で追加 5% のコスト削減が可能
  • 欧州リージョンでの選択肢拡大：データレジデンシー要件を満たしつつ最新世代を利用

🔧 技術面

  • メモリ帯域幅の向上：2.5 倍のメモリ帯域幅でメモリ集約型ワークロードが高速化
  • 大規模スケール対応：96xlarge (384 vCPU、3,072 GiB) で大規模ワークロードを単一インスタンスで実行
  • SAP ワークロード対応：SAP 認定済みで SAP HANA などの運用に適合

⚠️ デメリット・制約事項

制限事項

  • R8i-flex はベアメタルサイズを提供していない
  • R8i-flex は 16xlarge が最大サイズであり、それ以上の規模には R8i が必要
  • 継続的に高い CPU 使用率が求められるワークロードには R8i-flex は不適

考慮すべき点

  • ワークロードのリソース使用パターンに応じて R8i と R8i-flex を適切に選択する必要がある
  • リージョンによって提供されるインスタンスサイズが異なる場合があるため、利用前に確認が必要

🎯 ユースケース

1. 大規模インメモリデータベース
シナリオ：SAP HANA や Redis などのインメモリデータベースを欧州リージョンで運用する場合。
効果：2.5 倍のメモリ帯域幅と最大 3,072 GiB のメモリにより、大規模なインメモリデータセットを高速に処理できる。
2. コスト効率重視のウェブスケールキャッシュ
シナリオ：常時フルにリソースを使わない分散キャッシュや中規模のインメモリ分析ワークロード。
効果：R8i-flex を使用することで追加 5% のコスト削減を実現しつつ、必要時には CPU パフォーマンスを最大限に引き出せる。
3. ミッションクリティカルな SAP ワークロード
シナリオ：SAP 認定インスタンスが必要な基幹業務システムを欧州でホスティングする場合。
効果：142,100 aSAPS の SAP 認定パフォーマンスと最大 96xlarge のサイズにより、大規模な SAP 環境を安定して運用できる。

💰 料金・利用可能リージョン

💰 料金
R8i および R8i-flex はオンデマンド、Savings Plans、リザーブドインスタンス、スポットインスタンスなどの各種購入オプションで利用できます。R8i-flex は R8i と比較して 5% 低い価格で提供されます。詳細な料金は各リージョンごとに異なるため、Amazon EC2 の料金ページで確認してください。

📝 まとめ

R8i および R8i-flex インスタンスの欧州 (ストックホルム)、欧州 (チューリッヒ) への提供拡大により、これらのリージョンでも最新世代のメモリ最適化インスタンスを活用できるようになりました。 メモリ集約型ワークロードやコスト最適化を検討しているお客様は、ワークロードの特性に応じて R8i と R8i-flex を使い分けることで、パフォーマンスとコストの両面でメリットを得られます。
