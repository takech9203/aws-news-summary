☁️ Amazon S3

🏷️ S3 アノテーション (Annotations)

オブジェクトに直接、リッチでクエリ可能なビジネスコンテキストを付与
リリース日
2026.06.16

📌 概要

Amazon S3 が、オブジェクトに大規模かつ柔軟にカスタムメタデータを付与できる新機能「アノテーション」を発表。AI エージェントや分析ツールがデータを発見・理解・活用するために必要なコンテキストを、オブジェクトに直接埋め込めます。

1 オブジェクトあたり最大 1 GB のコンテキストを、いつでも追加・変更・削除できる形で保持。JSON、XML、YAML、プレーンテキストに対応し、データの変化に合わせて常に最新の状態に保てます。さらに S3 Metadata と連携すると、フルマネージドの読み取り専用 Apache Iceberg テーブルとして公開され、Athena や AI エージェントから大規模にクエリできます。

⏮️ Before (課題)
  • ❌オブジェクトタグは 10 個まで、キー/値が 128/256 文字までで、リッチなコンテキストを保持できない
  • ❌ユーザー定義メタデータは 2 KB まで、かつアップロード時にしか設定できず後から変更不可
  • ❌ビジネスコンテキスト保持のため、S3 とは別のメタデータ管理システムを構築・運用する必要があった
⏭️ After (改善)
  • ✅1 オブジェクトあたり最大 1 GB (最大 1,000 個 × 各 1 MB) のコンテキストを付与可能に
  • ✅別途メタデータ管理システムを維持する必要がなくなった
  • ✅S3 Metadata 経由で Athena や AI エージェントから大規模にクエリ・自然言語検索が可能に

オブジェクトに付与したアノテーションは、S3 Metadata を有効化すると Apache Iceberg テーブルに自動でインデックスされ、Athena や AI エージェントからクエリ・自然言語検索できます。

⚙️ 主要機能

📈 大規模で変更可能なコンテキストの付与
  • 1 オブジェクトあたり最大 1,000 個の名前付きアノテーション、各最大 1 MB、合計最大 1 GB
  • JSON、XML、YAML、プレーンテキストの各形式に対応
  • いつでも追加・変更・削除でき、オブジェクト本体を書き換えずにコンテキストを最新化
  • 新規オブジェクトと既存オブジェクトのどちらにも適用可能
🛡️ オブジェクトと同等の耐久性・整合性
  • アノテーションはオブジェクトと同じ耐久性・整合性を備える
  • コピーやレプリケーション時にオブジェクトとともに移動し、削除時にあわせて削除
  • 既存メタデータ (システム定義 / オブジェクトタグ / ユーザー定義) を補完しつつ、より大きな規模と柔軟性を提供
🔍 S3 Metadata 連携による大規模クエリと自然言語検索
  • アノテーションテーブルを有効化すると、読み取り専用のフルマネージド Apache Iceberg テーブルとしてインデックス
  • Amazon Athena など Iceberg 互換ツールから SQL で大規模にクエリ可能
  • SageMaker Unified Studio のエージェントや S3 Tables MCP サーバーから自然言語で検索

🛠️ 設定方法

前提条件

✓対象の S3 バケットおよびオブジェクトが存在すること
✓s3:PutObjectAnnotation および s3:GetObjectAnnotation 権限を付与していること
✓大規模クエリ・自然言語検索を行う場合は、S3 Metadata のアノテーションテーブルを有効化していること

ステップ 1: アノテーションを追加する

Bashput-object-annotation
aws s3api put-object-annotation \
  --bucket my-media-bucket \
  --key videos/documentary-2026.mp4 \
  --annotation-name mediainfo \
  --annotation-payload ./mediainfo.json

指定オブジェクトに mediainfo という名前のアノテーションを追加します。同名で再実行すると更新されます。マルチパートアップロードの場合は、完了後に付与します。

ステップ 2: アノテーションを取得・一覧表示する

Bashget / list
aws s3api get-object-annotation \
  --bucket my-media-bucket \
  --key videos/documentary-2026.mp4 \
  --annotation-name mediainfo \
  ./mediainfo-output.json

aws s3api list-object-annotations \
  --bucket my-media-bucket \
  --key videos/documentary-2026.mp4

前者は特定のアノテーションをローカルファイルに取得し、後者は全アノテーションを一覧表示します。

ステップ 3: S3 Metadata のアノテーションテーブルを有効化する

Bashannotation-table-configuration
aws s3api update-bucket-metadata-annotation-table-configuration \
  --bucket my-media-bucket \
  --annotation-table-configuration \
  '{"ConfigurationState":"ENABLED","Role":"arn:aws:iam::123456789012:role/S3MetadataAnnotationRole"}'

有効化すると、アノテーションが Apache Iceberg テーブルにインデックスされ、各アノテーションが 1 行として記録 (内容は text_value 列に格納) されます。アノテーションテーブルは約 1 時間以内、ジャーナルテーブルはほぼリアルタイムで更新。既存オブジェクトに対する有効化はバックグラウンドでバックフィルが走り、数時間〜数日かかる場合があります。

✨ メリット

💼 ビジネス面
  • →データ発見の効率化: AI エージェントや分析ツールがコンテキストを直接理解
  • →運用コストの削減: 別途メタデータ管理システムが不要に
  • →データガバナンスの向上: コンテキストをオブジェクトに紐付けて一元管理
⚙️ 技術面
  • →大規模なコンテキスト保持: 最大 1 GB で従来制約を大幅に超える
  • →変更可能で常に最新: 本体を書き換えず追加・変更・削除
  • →既存ツールとの親和性: Iceberg テーブルとして Athena 等からそのままクエリ

⚠️ デメリット・制約事項

制限事項

!アノテーションは最大 1,000 個 / 各 1 MB / 合計 1 GB まで
!マルチパートアップロードでは、完了後にしか付与できない
!テーブル更新に約 1 時間、既存オブジェクトのバックフィルは数時間〜数日を要する場合あり
!S3 Metadata のアノテーションテーブルは読み取り専用

考慮すべき点

⚠アノテーションのストレージは、親オブジェクトが Glacier 等でも常に S3 標準料金で課金
⚠大規模クエリには S3 Metadata の有効化が前提のため、利用設計時に計画が必要
⚠アノテーションテーブル機能は S3 Metadata が利用可能なリージョンのみ

🎯 ユースケース

1️⃣ メディアアセットの大規模検索

シナリオ: 大量の動画を保管するメディア企業が、音声トラック数や字幕言語などのメタ情報を付与し、特定条件のコンテンツを高速抽出したい。

SQLAthena クエリ例
SELECT DISTINCT bucket, object_key
FROM "s3tablescatalog/aws-s3"."b_my_media_bucket"."annotation"
WHERE name = 'mediainfo'
AND CAST(json_extract_scalar(text_value, '$.audio_tracks') AS INTEGER) > 8
✅ 効果: オブジェクトを取り出すことなく、条件に合致するメディアアセットを Athena から即座に発見。
2️⃣ AI エージェントによる自然言語検索

シナリオ: 開発者やビジネスユーザーが、SQL を書かずに自然言語でオブジェクトを検索したい。

PromptSageMaker Unified Studio / S3 Tables MCP
"2023 年公開のスペイン語字幕付き PG レーティング映画をすべて検索して"
✅ 効果: エージェントや MCP サーバーを通じて、自然言語の問い合わせから数秒で結果を取得。
3️⃣ 直近で更新されたデータの追跡

シナリオ: データパイプラインで、直近 24 時間以内にアノテーションが追加・削除されたオブジェクトを把握したい。

SQLジャーナルテーブルクエリ例
SELECT bucket, key, version_id, record_timestamp, annotation.name
FROM "s3tablescatalog/aws-s3"."b_my_media_bucket"."journal"
WHERE record_timestamp >= (current_date - interval '1' day)
AND annotation.name IS NOT NULL
AND record_type IN ('CREATE_ANNOTATION', 'DELETE_ANNOTATION')
✅ 効果: ほぼリアルタイムで更新されるジャーナルテーブルで、最近変更されたデータだけを効率処理。

💰 料金

アノテーションのストレージ料金は、親オブジェクトのストレージクラスにかかわらず常に S3 標準料金で課金されます。親オブジェクトが Glacier 等にある場合でも、アノテーション部分は S3 標準料金が適用。なお、アノテーションは任意のストレージクラスをまたいでクエリでき、オブジェクトの復元や取り出し料金は発生しません。詳細は S3 の料金ページを参照してください。

📝 まとめ

Amazon S3 アノテーションは、オブジェクトに最大 1 GB の変更可能なコンテキストを直接付与し、AI エージェントや分析ツールによるデータ発見を大幅に強化する機能です。S3 Metadata と連携することで Athena や自然言語検索からの大規模なクエリが可能に。メディア管理やデータカタログ、AI ワークロードを扱うチームは、まず対象バケットでアノテーションテーブルを有効化し、既存ツールとの統合を検討することを推奨します。
