Kiro CLIv2.20.0 / 2.20.1

⌨️ フルスクリーン Spec タスク実行と Preserve scrollback

📅 リリース日: 2026 年 8 月 27 日 | 🛠️ Kiro CLI 2.20.0 (パッチ 2.20.1 同日公開)

📝 概要

Kiro CLI 2.20.0 の目玉は、V3 の Spec 実行に追加された専用のフルスクリーンタスク実行ビューです。 /spec run で Spec を実行すると専用ビューが開き、タスクの進捗をリアルタイムで確認できるほか、実行開始前にタスクスコープを選択できます。

また、/settings display にPreserve scrollback トグルが追加され、ターミナル出力のオーバーフローやリサイズによる再描画後も、スクロールバック履歴 (過去の出力) が保持されるようになりました。 このほか、再開したチャットのターン復元の完全化や MCP OAuth サインインの信頼性向上など多数の修正を含み、/powers コマンドなどを追加したパッチ 2.20.1 も同日公開されています。

❌ アップデート前の課題

✗Spec のタスク実行が通常のチャット画面内で行われ、進捗を俯瞰する専用ビューがなかった
✗実行前にタスクスコープを対話的に選択する手段が限られ、実行範囲のコントロールが困難
✗オーバーフローやリサイズ再描画でスクロールバック上の過去の出力が失われることがあった
✗再開したチャットで中断されたツールやツール出力を含むターンが完全に復元されない
✗MCP OAuth サインインが再接続後に継続されない、認証情報が保持されないなどの問題

✅ アップデート後の改善

✓/spec run で専用のフルスクリーンビューが開き、リアルタイムで進捗を確認可能
✓実行開始前にタスクスコープを選択でき、実行範囲を柔軟にコントロール可能
✓Preserve scrollback トグルで再描画後もターミナル履歴を参照可能
✓再開したチャットで中断されたツールやツール出力を含む完全なターンが復元される
✓過大なリクエストは自動コンパクションとリトライで処理、制限はエラーで明確に説明

🚀 主要機能

🖥️ 1. フルスクリーン Spec タスク実行 (V3)

→/spec run で Spec を実行すると、専用のフルスクリーンタスク実行ビューが開く
→タスクの進捗をリアルタイムで追跡できる
→実行開始前にタスクスコープ (実行対象のタスク範囲) を選択できる

📜 2. Preserve scrollback トグル (Improvements)

→/settings display に新しいトグルとして追加
→出力のオーバーフロー時やリサイズ再描画時にも、ターミナル履歴 (スクロールバック) を保持
→過去の出力をさかのぼって確認したいケースで有効

🔧 3. 修正 (Fixes)

  • 再開したチャットで、中断されたツールとツール出力を含む完全なターンが復元されるように
  • 過大なリクエストは自動的な会話コンパクションとリトライがトリガーされ、単一メッセージが収まらない場合はエラーで制限を明確に説明
  • V3 で大きなシェル出力を完全に保存しても、チャット再開時のパフォーマンスが低下しない
  • V3 の Web 検索、取得したページ、プロセス出力が再開したチャットで正しくリプレイされる
  • V3 のサインインエラーが、汎用メッセージではなく根本原因を表示
  • V3 の Hook ステータスが、チャットの開始時・再開時に正しく表示
  • V3 の MCP OAuth サインインが、再接続後も確実に継続
  • V3 でレジストリから追加した MCP サーバーが、設定済みの認証情報を保持
  • V3 の MCP ツール結果が、再開したチャットで正しくリプレイされる

📦 4. パッチ 2.20.1 (2026 年 8 月 27 日公開)

  • 新しい /powers コマンドで、インストール済みの Powers を一覧表示 (V3)
  • 冗長な認証・プロファイル呼び出しの削除により、チャットの起動が高速化
  • app.disableAutoupdates が Windows でのアップデートダウンロードも抑止し、一時ディレクトリにインストーラーが蓄積しない
  • エージェントモニターの出力ペインでキー長押しによる高速スクロールが停止・スキップしない
  • 長時間セッション中にバックグラウンドで CLI が自己アップグレードした後も、認証が失敗しない
  • ツールと Hook の表示が、切り詰め・失敗・サブエージェントのライブ出力を正確に報告
  • V3 の /chat load と /chat save が ~ で始まるパスを受け付ける
  • V3 がリモートの $$schema 参照を含む JSON ファイルを書き込み可能に
  • V3 がリクエスト中に期限切れとなる認証情報を更新し、ターンを終了させない
  • V3 が停止したモデルレスポンスからハングせずに自動回復
  • V3 が停止したサブエージェントをタイムアウトさせ、親のターンをブロックしない
  • chat.historyMode が kiro-cli settings で無効として拒否されず受け付けられる

💡 メリット

💼 ビジネス面

✓開発生産性の向上: Spec タスクの進捗をリアルタイムで俯瞰でき、長時間のタスク実行でも状況把握が容易
✓手戻りの削減: 実行前にタスクスコープを選択でき、必要な範囲のみを効率的に進められる
✓運用の安定性向上: ストリーム復旧や認証情報の自動更新により、長時間のエージェント作業が中断されにくい

🔬 技術面

✓専用ビューによる視認性: チャットのログに埋もれず、専用のフルスクリーンビューで進捗を追跡
✓ターミナル履歴の保持: 再描画後も過去の出力をさかのぼれて、デバッグやレビューがしやすい
✓チャット再開の信頼性向上: 中断されたツール出力、Web 検索結果、MCP ツール結果などが正しくリプレイされる

⚠️ デメリット・制約事項

🚧 制限事項

•フルスクリーンタスク実行ビューは V3 の Spec 実行が対象
•Preserve scrollback はトグル設定であり、/settings display から明示的に有効化が必要
•/powers コマンドはパッチ 2.20.1 で追加されたため、2.20.0 では利用不可

🎯 ユースケース

📚 ユースケース 1: 大規模な Spec の段階的な実行

シナリオ: 多数のタスクを含む Spec を作成したが、まずは基盤部分のタスクのみを実行して結果を確認したい。/spec run のフルスクリーンビューでタスクスコープを選択し、対象タスクのみを実行する。

✅ 効果: 実行範囲をコントロールしながら段階的に実装を進められ、途中経過をリアルタイムで確認できる。

⏱️ ユースケース 2: 長時間実行タスクの進捗モニタリング

シナリオ: ビルドやテストを含む時間のかかるタスク群を Spec で実行し、進捗を随時把握したい。/spec run のフルスクリーンビューでリアルタイムの進捗表示を確認する。

✅ 効果: 各タスクの状態が専用ビューに集約され、どこまで完了しているかが一目で分かる。

🔍 ユースケース 3: 再描画後のログ確認

シナリオ: エージェントの長い出力やターミナルのリサイズ後に、過去のコマンド出力やエージェントの応答を確認したい。/settings display で Preserve scrollback トグルを有効化する。

✅ 効果: オーバーフローやリサイズ再描画が発生しても、ターミナルのスクロールバックから過去の出力を参照できる。
