⭐ 主要機能

🎯 信頼度レベル設定 (Confidence Level Configuration)

Cell ID、Wi-Fi、Cell+Wi-Fi ソルバーで利用可能。50% から 99% の範囲で信頼度レベルを指定できる。

高い信頼度 (例: 95%) は精度半径が大きくなるが確実性が高まり、低い信頼度 (例: 50%) は精度半径が小さくなるが確実性は低下する。HTTP ベースの位置解決でサポート。

🏷️ 測定タイプ (MeasurementType)

すべてのソルバーのレスポンスに MeasurementType フィールドが追加。位置データのソースを明示し、精度に関する判断を支援する。

返される値: Connected、Neighbor、WiFiHybrid、CellIdHybrid

⚙️ AdvancedConfiguration パラメータ

GetPositionEstimate API に AdvancedConfiguration オブジェクトが追加。WiFiCellular.ConfidencePercent フィールドで信頼度を指定する。

📐 技術仕様

信頼度レベルの動作

信頼度レベル 精度半径 確実性 推奨ユースケース
50% 小さい 低い 大まかな位置で十分な場合
68% 中程度 中程度 標準的な追跡
95% 大きい 高い 高い確実性が必要な場合
99% 最大 非常に高い 安全性重視のアプリケーション

MeasurementType の値

タイプ 説明
Connected 接続中のセルタワーに基づく位置解決
Neighbor 近隣のセルタワーに基づく位置解決
WiFiHybrid Wi-Fi とハイブリッド手法による位置解決
CellIdHybrid Cell ID とハイブリッド手法による位置解決

💻 設定方法・コードサンプル

前提条件

  • ✅ AWS アカウントと適切な IAM 権限 (iotwireless:GetPositionEstimate)
  • ✅ AWS IoT Core for Device Location が有効化されていること
  • ✅ デバイスからセルタワーまたは Wi-Fi アクセスポイント情報を収集する仕組み

Step 1: IAM ポリシーの設定

JSON IAM Policy 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "iotwireless:GetPositionEstimate"
            ],
            "Resource": "*"
        }
    ]
}

Step 2: 信頼度レベルを指定した位置解決リクエスト

Python GetPositionEstimate API 
import boto3

client = boto3.client('iotwireless')

response = client.get_position_estimate(
    CellTowers={
        'Lte': [
            {
                'Mcc': 440,
                'Mnc': 10,
                'EutranCid': 12345678,
                'Tac': 1234
            }
        ]
    },
    AdvancedConfiguration={
        'WiFiCellular': {
            'ConfidencePercent': 95
        }
    }
)

Step 3: レスポンスの MeasurementType を確認

Python Parse Response 
import json

# レスポンスの GeoJSON ペイロードを解析
geo_data = json.loads(response['GeoJsonPayload'].read())

# 位置座標の取得
coordinates = geo_data['coordinates']
print(f"緯度: {coordinates[1]}, 経度: {coordinates[0]}")

# MeasurementType の確認
measurement_type = geo_data.get('properties', {}).get('MeasurementType')
print(f"測定タイプ: {measurement_type}")

💡 ユースケース

🚚 ユースケース 1: 物流アセット追跡
物流会社が配送車両やコンテナの位置を追跡し、顧客にリアルタイムの配送状況を通知。高い確実性で車両がエリア内にいることを保証したい。信頼度 95% を指定して位置解決を行う。
→ 95% の信頼度により、顧客への配送通知の正確性が向上し、誤った到着通知を防止できる。
🔒 ユースケース 2: ジオフェンシングによるセキュリティ管理
工場内の高価な機器が指定エリア外に移動した場合にアラートを発行するセキュリティシステム。信頼度 99% と MeasurementType の組み合わせで誤検知を最小限に抑える。
→ 99% の信頼度と Connected タイプの確認により、誤検知を大幅に削減しつつセキュリティを強化。
🌍 ユースケース 3: IoT センサーの位置基盤データ分析
都市部に設置された環境センサーの位置データを収集し、大まかなエリア分析を実施。精密な位置は不要だがコンパクトな精度半径が望ましい。信頼度 50% を指定。
→ 50% の信頼度で小さな精度半径を取得し、効率的なエリア分類とデータ分析が可能。

⚖️ メリット・デメリット

✅ ビジネス面のメリット

  • 🎯 ユースケースに最適化された位置精度: アセット追跡、ジオフェンシング、物流管理など各ユースケースに最適な精度と確実性のバランスを実現
  • 📈 運用判断の改善: MeasurementType により位置データの品質を把握し、ビジネス判断の信頼性を向上
  • 💰 追加コストなし: 既存の Device Location 料金体系内で利用可能な機能強化

✅ 技術面のメリット

  • ⚙️ 精度制御の柔軟性: 50-99% の範囲で信頼度を指定でき、システム要件に応じた精密な制御が可能
  • 🔍 デバッグの効率化: MeasurementType により位置解決の問題を迅速に特定・診断
  • 📊 データ品質の可視化: 各位置データがどの方法で解決されたかが明示され、アプリケーションロジックの最適化に活用

⚠️ 制限事項・注意点

  • ⚠️ 信頼度レベル設定は HTTP ベースの位置解決のみサポート。MQTT 経由では利用不可
  • ⚠️ 信頼度レベルの範囲は 50% から 99% に限定
  • ⚠️ 信頼度を高くすると精度半径が大きくなるため、狭い範囲での精密な位置特定には不向きな場合あり
  • ⚠️ MeasurementType が Neighbor の場合、Connected と比較して位置精度が低い可能性あり

💰 料金情報

AWS IoT Core Device Location の料金は位置解決リクエスト数に基づく従量課金制。信頼度レベル設定および MeasurementType の利用による追加料金は発生しない。

使用量 月額料金 (概算)
最初の 1,000 回 (無料枠) $0 (アカウント作成後 12 か月間)
1,000 回/月 $1.00 (1K リクエストあたり)

※ 無料利用枠: アカウント作成後 12 か月間、月 1,000 回の位置解決が無料。AWS GovCloud (US) を除く全リージョンで利用可能。
