Amazon Bedrock AgentCore 統合オブザーバビリティ 📅 2026 年 7 月 23 日

🔭 AI エージェントのテレメトリを
単一ロググループに集約

トレース・プロンプト・構造化ログ・標準出力を 1 か所に統合し、デバッグ・アクセス制御・暗号化・エクスポートを大幅に簡素化

📌 概要 - 何が変わったのか

Amazon Bedrock AgentCore は、AI エージェントのトレースとプロンプトを、エージェントのログと同じ Amazon CloudWatch ロググループに配信するようになりました。これにより AI エージェントのテレメトリ (トレース、プロンプト、構造化ログ、標準出力) が単一のロググループに集約され、統合されたオブザーバビリティを実現します。

従来はテレメトリが複数の配信先に分散していたため、1 回のエージェント呼び出しをデバッグするだけでも複数のロググループを横断して検索する必要がありました。今回のアップデートで、すべてのテレメトリがエージェントごとの単一ロググループ /aws/bedrock-agentcore/runtimes/<agent_id>-<endpoint_name> にまとまります。

❌ アップデート前の課題
  • トレーススパンは共有の aws/spans へ、イベントログはリソース固有の別ロググループへ分散
  • 1 回の呼び出しのデバッグに複数ロググループの横断検索が必要
  • エージェント単位のアクセス制御・CMK 暗号化を適用できない
  • エクスポートには複数ロググループを個別にサブスクライブする必要
✅ アップデート後の改善
  • トレース・プロンプト・構造化ログ・標準出力が単一ロググループに集約
  • トレースとログを 1 か所で相関分析できる
  • IAM ポリシーと CMK 暗号化をエージェント単位でスコープ可能
  • 単一ロググループのサブスクライブだけで全テレメトリをエクスポート

従来は共有の aws/spans とリソース固有ロググループに分散していたテレメトリが、エージェント別の単一ロググループに集約される

⚙️ 主要機能

🗄️ 1. 単一ロググループへのテレメトリ集約
  • スパンは共有 aws/spans ではなく、エージェントのロググループ内の spans ログストリームに配信
  • トレース、プロンプト、構造化ログ、標準出力がエージェントごとに 1 か所にまとまる
  • トレースとログを同じロググループ内で相関分析できる
🔒 2. エージェント単位のアクセス制御と暗号化
  • IAM ポリシーを個々のエージェントのロググループにスコープできる
  • CMK (カスタマーマネージドキー) 暗号化をエージェント単位で適用できる
  • セキュリティ要件の異なる複数エージェントを独立した権限・暗号化設定で運用
📤 3. テレメトリの一元エクスポート
  • 単一ロググループをサブスクライブするだけで全テレメトリをエクスポート
  • サブスクリプションフィルターや外部可観測性プラットフォーム連携が簡素化

🔧 技術仕様 - ロググループとデフォルト動作

項目詳細
統合後のロググループ/aws/bedrock-agentcore/runtimes/<agent_id>-<endpoint_name>
スパンのログストリームspans
従来のトレース配信先共有の aws/spans ロググループ
新規エージェントのデフォルト2026 年 7 月 20 日以降、サポート対象リージョンで作成された新規エージェントは統合オブザーバビリティがデフォルトで有効 (設定不要)
既存エージェント環境変数の設定と ADOT のアップグレードが必要
既存データ配信先を変更しても、既に配信済みのスパンデータは元のロググループに残る (移動されない)

✅ 有効化の前提条件

条件内容
CloudWatch Transaction Searchアカウントで有効化し、トレースセグメントを CloudWatch Logs に送信する。無効の場合、スパンはエージェントのロググループに配信されない
実行ロールの権限実行ロールに対象ロググループへの logs:PutResourcePolicy を付与。AgentCore がこの権限で AWS X-Ray からのスパン配信を許可する
ADOT バージョンaws-opentelemetry-distro>=0.18.0 を使用。古いバージョンは配信先設定を無視し、共有 aws/spans に配信する
💡 補足: What's New 発表では ADOT 要件は 0.17.1 以降と案内されていますが、現時点の AgentCore デベロッパーガイドでは 0.18.0 以降が要件として明記されています。実装時は最新のドキュメントに従い、可能な限り新しいバージョンを利用してください。

🔀 環境変数による制御

BashUNIFIED_TRACES_DESTINATION_ENABLED
# 共有 aws/spans を使う既存エージェントをオプトイン
# (スパンをエージェント自身のロググループに配信)
UNIFIED_TRACES_DESTINATION_ENABLED=true

# エージェント自身のロググループを使うエージェントをオプトアウト
# (スパンを共有 aws/spans ロググループに配信)
UNIFIED_TRACES_DESTINATION_ENABLED=false

🚀 設定方法 - 既存エージェントの移行手順

前提 1 CloudWatch Transaction Search の有効化 前提 2 実行ロールに logs:PutResourcePolicy 前提 3 ADOT 0.18.0 以降
1
CloudWatch Transaction Search を有効化する

X-Ray に CloudWatch Logs へのトレース送信権限を付与し、トレースセグメントの配信先を設定します。この設定がないとスパンは配信されません。

Bash
# X-Ray がトレースを CloudWatch Logs に送信できるよう権限を追加
aws logs put-resource-policy --policy-name MyResourcePolicy --policy-document '{...}'

# トレースセグメントの配信先を CloudWatch Logs に設定
aws xray update-trace-segment-destination --destination CloudWatchLogs
2
既存エージェントで統合オブザーバビリティを有効化する

エージェントランタイムに環境変数を設定してオプトインします。

Bash
# エージェントランタイムに環境変数を設定
UNIFIED_TRACES_DESTINATION_ENABLED=true
3
ADOT をアップグレードする

依存関係の ADOT を 0.18.0 以降に更新します。古いバージョンでは配信先設定が無視されるため必須です。

Textrequirements.txt
aws-opentelemetry-distro>=0.18.0
boto3
🎯 2026 年 7 月 20 日以降にサポート対象リージョンで新規作成したエージェントは、統合オブザーバビリティがデフォルトで有効なため、これらの設定は不要です。

💡 メリット

💼 ビジネス面

  • 運用効率の向上: 横断検索が不要になりデバッグ時間を短縮
  • ガバナンスの強化: エージェント単位の IAM 制御・CMK 暗号化でコンプライアンス対応が容易
  • 設定不要の自動適用: 新規エージェントはデフォルト有効で追加コスト不要

🔬 技術面

  • トレースとログの相関分析: 同一ロググループで突き合わせ、根本原因の特定を迅速化
  • エクスポートの簡素化: 単一ロググループのサブスクライブで外部連携
  • マルチエージェントのデバッグ性向上: 各エージェントの完全な実行履歴が 1 か所に

⚠️ デメリット・制約事項

制限事項

  • 配信先を変更しても、既に配信済みのスパンデータは移動されず元のロググループに残る
  • CloudWatch Transaction Search が無効の場合、スパンはエージェントのロググループに配信されない
  • ADOT のバージョンが要件を満たさない場合、設定が無視され共有 aws/spans に配信される
  • サポート対象リージョン対応前に作成されたエージェントは、デフォルトで共有 aws/spans を使い続ける

考慮すべき点

  • 既存エージェント移行時は、環境変数設定・実行ロール権限付与・ADOT アップグレードをすべて実施する必要がある
  • 切り替え前後でスパンデータが分散するため、移行時期を明確に記録しておくとよい

🎯 ユースケース

🔍 1. マルチエージェントシステムのエンドツーエンドデバッグ

シナリオ: 複数エージェントが連携するシステムで、特定のエージェント呼び出しのエラー原因を調査する。

実装: /aws/bedrock-agentcore/runtimes/<agent_id>-<endpoint_name> の spans ストリームでトレースを、同ロググループ内でプロンプト・入出力を確認。

✅ 効果: 横断せずに各エージェントの完全な実行履歴を 1 か所で確認でき、デバッグ時間を短縮。
🔐 2. エージェント単位のセキュリティ要件への対応

シナリオ: 機密データを扱うエージェントと一般エージェントを、異なるアクセス制御・暗号化ポリシーで運用したい。

実装: 機密エージェントのロググループに CMK 暗号化を適用し、対応する IAM ポリシーをそのロググループにスコープ。

✅ 効果: エージェント単位で CMK 暗号化ときめ細かいアクセス制御を適用でき、最小権限とコンプライアンスを満たす。
📤 3. テレメトリの一元エクスポート

シナリオ: エージェントの全テレメトリを外部の可観測性プラットフォームや SIEM へ転送して分析したい。

Bashサブスクリプションフィルター
aws logs put-subscription-filter \
  --log-group-name "/aws/bedrock-agentcore/runtimes/<agent_id>-<endpoint_name>" \
  --filter-name "export-all-telemetry" ...
✅ 効果: 単一ロググループのサブスクライブだけで、トレース・プロンプト・ログを含む全テレメトリをエクスポートでき、連携設定を簡素化。

💰 料金 & 🌏 利用可能リージョン

💰 料金

今回のアップデート自体に追加料金はありません。テレメトリの保存・処理には通常の Amazon CloudWatch Logs および AWS X-Ray (CloudWatch Transaction Search) の料金が適用されます。

🌏 利用可能リージョン

AgentCore ランタイムがサポートされるすべての AWS 商用リージョンで利用可能。2026 年 7 月 20 日以降に作成された新規エージェントはデフォルト有効。それ以前のエージェントは引き続き共有 aws/spans をデフォルト配信先として使用します。

📝 まとめ

Amazon Bedrock AgentCore の統合オブザーバビリティは、これまで分散していたエージェントのテレメトリを単一のロググループに集約し、デバッグ・アクセス制御・暗号化・エクスポートを大幅に簡素化する重要なアップデートです。

新規エージェントはデフォルトで有効になるため追加設定は不要ですが、既存エージェントを利用している場合は、UNIFIED_TRACES_DESTINATION_ENABLED=true の設定、実行ロールへの権限付与、ADOT 0.18.0 以降へのアップグレードを実施して移行することを推奨します。
