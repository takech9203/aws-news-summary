📋 概要

Amazon Bedrock が、OpenAI 互換 API および Anthropic 互換 API に最適化された新しいコンソールエクスペリエンスを発表。開発者が基盤モデルを使ってアプリケーションを構築する際の実際のワークフロー (実験、イテレーション、スケーリング) に合わせて設計されている。

新しいコンソールは bedrock-mantle エンドポイント向けに最適化されており、既存の OpenAI や Anthropic のクライアントライブラリをそのまま使用して Amazon Bedrock 上のモデルにリクエストを送信できる。

⚙️ 主要機能

📋 統合モデルカタログ

Claude、GPT、オープンウェイトモデルを含む全 Bedrock モデルを一覧表示。機能、モダリティサポート、コンテキストウィンドウ、サービスクォータをサイドバイサイドで比較可能。

📁 プロジェクトベースのワークフロー

作業をプロジェクト単位で整理。プロジェクト内で評価の実行とユーセージインサイトの確認が可能。生成 AI アプリケーション構築のライフサイクルに沿ったストリームラインなワークフロー。

📄 プロジェクト対応ドキュメント

コードサンプル、SDK スニペット、API リファレンスがプロジェクトの設定で自動的に事前設定。モデルや設定を変更すると、ドキュメント内のスニペットもリアルタイムで更新。

🔌 互換 API サポート

OpenAI Chat Completions API、OpenAI Responses API、Anthropic Messages API フォーマットをサポート。既存のクライアントライブラリをそのまま利用可能。

💻 設定方法・コードサンプル

認証設定

Bash bedrock-mantle エンドポイント認証設定 
# bedrock-mantle エンドポイントでの認証には Amazon Bedrock API キーを使用
# 既存の OpenAI クライアントライブラリを使用する例
export OPENAI_API_KEY="your-bedrock-api-key"
export OPENAI_BASE_URL="https://bedrock-mantle.us-east-1.amazonaws.com/v1"

OpenAI 互換クライアントの使用

Python OpenAI 互換クライアント例 
from openai import OpenAI

client = OpenAI(
    api_key="your-bedrock-api-key",
    base_url="https://bedrock-mantle.us-east-1.amazonaws.com/v1"
)

response = client.chat.completions.create(
    model="anthropic.claude-sonnet-4-20250514-v1:0",
    messages=[
        {"role": "user", "content": "Hello, world!"}
    ]
)
print(response.choices[0].message.content)

Anthropic 互換クライアントの使用

Python Anthropic 互換クライアント例 
import anthropic

client = anthropic.Anthropic(
    api_key="your-bedrock-api-key",
    base_url="https://bedrock-mantle.us-east-1.amazonaws.com"
)

message = client.messages.create(
    model="anthropic.claude-sonnet-4-20250514-v1:0",
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Hello, world!"}
    ]
)
print(message.content[0].text)

⚠️ デメリット・制約事項

🌍 リージョン制限

bedrock-mantle エンドポイントが提供されているリージョンでのみ利用可能

🔑 認証方式の違い

API キーベースの認証が必要 (IAM 認証とは別の仕組み)。API キーの管理とローテーションのセキュリティポリシーを検討する必要がある

🔧 機能制限

すべての OpenAI / Anthropic API 機能が完全にサポートされているとは限らない。モデル固有のパラメータは互換 API では利用できない場合がある

→ 既存の Bedrock ネイティブ API (InvokeModel 等) は引き続き利用可能であり、新コンソールは追加のオプション

💡 ユースケース

🔄 既存 OpenAI アプリケーションの Bedrock 移行

シナリオ: OpenAI API を使用している既存のチャットボットアプリケーションを、エンタープライズレベルのセキュリティと複数モデルへのアクセスのために Bedrock に移行したい。

効果: エンドポイントと API キーの変更のみで移行が完了し、AWS のセキュリティ、コンプライアンス、スケーラビリティの恩恵を受けられる。

📊 マルチモデル評価とベンチマーク

シナリオ: 生成 AI アプリケーションに最適なモデルを選定するため、複数のモデルを同一条件で評価したい。

効果: 統一された API フォーマットにより、モデル間の公平な比較が容易になり、プロジェクト内で評価結果を一元管理できる。

⬆️ 段階的なモデルアップグレード

シナリオ: 本番環境で使用中のモデルを新しいバージョンに段階的に切り替えたい。

効果: コンソールのモデルカタログで新旧モデルを比較した上で、最小限のコード変更でアップグレードできる。
