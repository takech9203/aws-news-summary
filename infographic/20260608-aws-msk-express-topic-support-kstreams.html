⚡ Amazon MSK Express Brokers

Kafka Streams 自動トピック作成サポート

Amazon MSK
2026-06-08

📋 概要

Amazon MSK Express Brokers が Kafka Streams アプリケーションでの自動トピック作成をサポート。ステートフル操作に必要な内部トピック (状態ストアやリパーティションデータ用) が、アプリケーション起動時に自動的に作成されるようになった。

追加の設定やセットアップは一切不要で、既存の Kafka Streams アプリケーションをそのまま Express Brokers にデプロイ可能。

❌ Before

  • 内部トピックを手動で事前に命名・作成する必要があった
  • アプリデプロイ前のトピック管理が運用負荷を増大
  • 命名規則やパーティション数の個別管理が必要
  • ヒューマンエラーのリスクが存在

✅ After

  • アプリ起動時に必要なトピックが自動作成
  • 手動でのトピック事前作成が不要
  • デプロイワークフローが大幅に簡素化
  • 追加設定は一切不要で即座に利用可能

🚀 主要機能

🔄 自動トピック作成

Kafka Streams が内部的に使用する状態ストアトピックとリパーティショントピックを自動生成。アプリケーション起動時にトピックが自動作成されるため、事前準備が不要。トピックの命名やパーティション設定も Kafka Streams のデフォルト動作に従い自動設定される。

⚙️ ゼロコンフィグレーション

追加の設定やセットアップは一切不要。既存の Kafka Streams アプリケーションをそのまま Express Brokers にデプロイ可能。MSK クラスター側での変更も不要。

⚡ Express Brokers の高性能特性との組み合わせ

ブローカーあたり最大 3 倍のスループットでステートフル処理を高速化。最大 20 倍高速なスケーリングにより、ワークロード変動に迅速に対応。90% 短縮されたリカバリ時間で障害時の状態復旧が高速化。

📝 設定方法

前提条件

✓Amazon MSK クラスターが Express Brokers タイプで作成されていること
✓Kafka Streams アプリケーションが準備されていること
✓適切な IAM 権限が設定されていること

Step 1: Express Brokers クラスターの確認

Bash MSK クラスター情報の確認 
# MSK クラスターの情報を確認
aws kafka describe-cluster --cluster-arn <cluster-arn> \
  --query 'ClusterInfo.BrokerNodeGroupInfo'

Step 2: Kafka Streams アプリケーションのデプロイ

Java Kafka Streams 設定例 
// Kafka Streams の設定例
Properties props = new Properties();
props.put(StreamsConfig.BOOTSTRAP_SERVERS_CONFIG, "<msk-express-bootstrap-servers>");
props.put(StreamsConfig.APPLICATION_ID_CONFIG, "my-streams-app");
// 追加設定は不要 - トピックは自動作成される

KafkaStreams streams = new KafkaStreams(topology, props);
streams.start();

Step 3: 動作確認

Bash 自動作成されたトピックの確認 
# 自動作成されたトピックの確認
kafka-topics.sh --bootstrap-server <msk-express-bootstrap-servers> \
  --list | grep "<application-id>"

⚠️ デメリット・制約事項

制限事項

!Express Brokers タイプのクラスターでのみ利用可能
!自動作成トピックのパーティション数やレプリケーションファクターは Kafka Streams のデフォルト設定に従う
!カスタムトピック設定が必要な場合は引き続き手動作成を推奨

考慮すべき点

💡本番環境では自動作成されるトピックの設定が要件を満たしているか事前に検証することを推奨
💡既存の手動作成済みトピックがある場合、自動作成機能との競合がないか確認が必要

💡 ユースケース

🛒 リアルタイムイベント処理パイプライン

EC サイトでユーザーの購買行動をリアルタイムに分析し、レコメンデーションを生成する Kafka Streams アプリケーションを Express Brokers にデプロイ。

Java 購買イベント分析 
StreamsBuilder builder = new StreamsBuilder();
KStream<String, PurchaseEvent> purchases = builder.stream("purchase-events");

// ステートフル操作 - 内部トピックが自動作成される
KTable<String, Long> purchaseCounts = purchases
    .groupByKey()
    .count(Materialized.as("purchase-counts-store"));

purchaseCounts.toStream().to("recommendation-input");

→ トピックの事前作成なしで即座にステートフルなストリーム処理を開始可能

🔗 マイクロサービスのイベント駆動アーキテクチャ

複数のマイクロサービスが Kafka Streams を使用してイベントを処理する環境で、サービスの追加・更新を頻繁に実施。

YAML Kubernetes Deployment - init container 不要 
# トピック作成の init container が不要に
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-processing-streams
spec:
  template:
    spec:
      containers:
        - name: streams-app
          image: order-processing:latest
          env:
            - name: BOOTSTRAP_SERVERS
              value: "<msk-express-bootstrap-servers>"

→ デプロイマニフェストからトピック管理の依存関係を排除、マイクロサービスの独立性が向上
