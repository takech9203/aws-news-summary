AWS Marketplace Metering Service

🔢 小数点以下の使用量レポートに対応

MeterUsage / BatchMeterUsage API で小数値 (decimal usage quantities) をサポート
📅 リリース日: 2026 年 11 月 16 日

📋 概要

AWS Marketplace Metering Service が、MeterUsage および BatchMeterUsage API で 小数点以下 6 桁までの使用量レポートをサポートしました。 これまで整数値のみだった使用量レポートが、「1.5 TB」のような実消費量をそのままレポートできるようになり、 従量課金型の SaaS・コンテナ製品を販売する ISV・セラーの課金精度と価格設計の柔軟性が向上します。

既存の整数値レポートとの後方互換性は維持されており、既存インテグレーションは変更なしでそのまま動作します。

セラー製品が計測した小数値の使用量を、新しいパラメータ経由で Metering Service にそのままレポートし、実消費量に即した請求が行われる流れ

⚙️ 主要機能

1️⃣ MeterUsage API での小数値サポート
→新しいリクエストパラメータ UsageQuantityAsDecimal を追加
→小数点以下 6 桁までの使用量を文字列として指定可能
→SaaS 製品やコンテナ製品からの単一レコードの使用量レポートに使用
2️⃣ BatchMeterUsage API での小数値サポート
→使用量レコード UsageRecord に新フィールド QuantityAsDecimal を追加
→複数顧客分の使用量を一括レポートする SaaS 製品のメータリングで利用可能
→レスポンスの Results および UnprocessedRecords にも同フィールドが反映
3️⃣ 使用量配分 UsageAllocation での小数値サポート
→タグベースの使用量配分に AllocatedUsageQuantityAsDecimal を追加
→MeterUsage / BatchMeterUsage の両方で利用可能
→顧客側の部門別・プロジェクト別コスト配分も小数精度で実現
4️⃣ 後方互換性の維持
→整数値をレポートする既存のインテグレーションは変更なしで引き続き動作
→既存の UsageQuantity / Quantity / AllocatedUsageQuantity パラメータはそのまま利用可能

🔬 技術仕様

🆕 新規パラメータ

API新規パラメータ説明
MeterUsage UsageQuantityAsDecimal 小数値の使用量 (文字列、小数点以下 6 桁まで)
BatchMeterUsage QuantityAsDecimal UsageRecord 内の小数値の使用量 (文字列)
MeterUsage / BatchMeterUsage AllocatedUsageQuantityAsDecimal UsageAllocation 内の小数値の配分量 (文字列)

🛠️ 設定方法

✅ 前提条件

✓AWS Marketplace に製品 (SaaS、コンテナなど) を出品しており、カスタムメータリングを使用していること
✓製品のメータリング実装が AWS SDK または AWS CLI から MeterUsage / BatchMeterUsage を呼び出せること
✓最新の AWS SDK / AWS CLI にアップデートしていること (新パラメータを利用するため)

📝 手順

1
SDK のアップデート

小数値パラメータに対応した最新バージョンの AWS SDK にアップデートします。

Bash
pip install --upgrade boto3
2
小数値での使用量レポートに切り替え

整数の UsageQuantity の代わりに UsageQuantityAsDecimal に小数値を文字列で指定します。 まず DryRun=True で権限と呼び出しの妥当性を検証します。

PythonMeterUsage の DryRun 検証
import boto3
from datetime import datetime, timezone

client = boto3.client("meteringmarketplace", region_name="us-east-1")

response = client.meter_usage(
    ProductCode="your-product-code",
    Timestamp=datetime.now(timezone.utc),
    UsageDimension="StorageUsageTB",
    UsageQuantityAsDecimal="1.523456",
    DryRun=True,
)
print(response)
3
バッチレポートと使用量配分の更新 (SaaS 製品の場合)

BatchMeterUsage で複数顧客分の使用量を小数値でレポートします。UsageAllocations を使用すると、タグ単位の小数精度でのコスト配分も可能です。

PythonBatchMeterUsage と UsageAllocations
response = client.batch_meter_usage(
    ProductCode="your-product-code",
    UsageRecords=[
        {
            "Timestamp": datetime.now(timezone.utc),
            "CustomerIdentifier": "customer-id",
            "Dimension": "StorageUsageTB",
            "QuantityAsDecimal": "1.5",
            "UsageAllocations": [
                {
                    "AllocatedUsageQuantityAsDecimal": "0.9",
                    "Tags": [{"Key": "Department", "Value": "Engineering"}],
                },
                {
                    "AllocatedUsageQuantityAsDecimal": "0.6",
                    "Tags": [{"Key": "Department", "Value": "Marketing"}],
                },
            ],
        },
    ],
)

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓課金精度の向上: 実消費量と請求額の乖離がなくなり、請求の透明性と信頼性が向上
✓柔軟な価格設計: TB 単位や時間単位など、顧客に直感的な単位をそのまま課金ディメンションに採用可能
✓顧客満足度の向上: 切り上げによる過剰請求がなくなり、「使った分だけ支払う」価値提案を正確に実現

🔧 技術面のメリット

✓実装の簡素化: 小数値を整数化する単位変換ロジック (TB → GB 変換など) が不要に
✓後方互換性: 既存の整数ベース実装はそのまま動作し、段階的な移行が可能
✓コスト配分の精度向上: タグベースの UsageAllocation でも小数値が使え、部門別配分も正確に

🚧 制限事項

✗小数値は小数点以下 6 桁までに制限される
✗小数値は数値型ではなく文字列型としてパラメータに指定する必要がある
✗新パラメータの利用には、対応バージョンの AWS SDK / AWS CLI へのアップデートが必要

⚠️ 考慮すべき点

⚠小数値課金への切り替え時は、製品の価格ディメンション設計 (単価設定) との整合性を確認する
⚠既存の整数パラメータと新しい小数パラメータが混在しないよう、実装方針を統一する
⚠請求金額の計算結果が従来の丸め方式と変わるため、切り替え前に DryRun などで請求影響をテストする

💡 ユースケース

🗄️ ユースケース 1: ストレージ系 SaaS の TB 単位課金

シナリオ: ストレージサービスを提供する SaaS セラーが、顧客の実使用量 1.5 TB を正確に課金したい。従来は GB 単位への変換または TB 単位への丸めが必要だった。

Python
client.meter_usage(
    ProductCode="storage-saas",
    Timestamp=datetime.now(timezone.utc),
    UsageDimension="StorageTB",
    UsageQuantityAsDecimal="1.5",
)

効果: 1 TB や 2 TB への丸めが不要になり、実使用量どおりの請求が可能。単位変換ロジックも削減できる。

⏱️ ユースケース 2: コンピューティング時間の分単位・秒単位課金

シナリオ: 分析ワークロードを提供するコンテナ製品で、ジョブの実行時間 (例: 2.75 時間) に応じて課金したい。

Python
client.meter_usage(
    ProductCode="analytics-container",
    Timestamp=datetime.now(timezone.utc),
    UsageDimension="ComputeHours",
    UsageQuantityAsDecimal="2.75",
)

効果: 時間単位に切り上げることなく、実行時間に比例した公平な課金を実現できる。

🏢 ユースケース 3: マルチテナント SaaS での部門別コスト配分

シナリオ: マルチテナント SaaS で、顧客企業内の部門ごとの使用量をタグで配分し、小数精度でコスト配分レポートを提供したい。

Python
client.batch_meter_usage(
    ProductCode="multi-tenant-saas",
    UsageRecords=[{
        "Timestamp": datetime.now(timezone.utc),
        "CustomerIdentifier": "customer-a",
        "Dimension": "DataProcessedTB",
        "QuantityAsDecimal": "3.2",
        "UsageAllocations": [
            {"AllocatedUsageQuantityAsDecimal": "2.1",
             "Tags": [{"Key": "Team", "Value": "DataScience"}]},
            {"AllocatedUsageQuantityAsDecimal": "1.1",
             "Tags": [{"Key": "Team", "Value": "BI"}]},
        ],
    }],
)

効果: 顧客は AWS Cost Explorer などでタグ別に小数精度のコストを把握でき、社内チャージバックの精度が向上する。

💰 料金・利用可能リージョン

💵 料金

公式発表に料金に関する記載はありません。本機能は MeterUsage / BatchMeterUsage API の拡張であり、追加料金に関するアナウンスはありません。 AWS Marketplace の販売に伴う手数料は、従来どおり AWS Marketplace のセラー向け料金体系に従います。

🌍 利用可能リージョン

AWS Marketplace Metering Service が利用可能なすべての AWS リージョンで利用できます。対象リージョンの一覧は Metering Service のリージョン一覧 を参照してください。

🔗 関連サービス・機能

→AWS Marketplace: 本機能の対象となるマーケットプレイス。SaaS、コンテナ、AMI 製品などの従量課金販売でメータリングを使用
→AWS Marketplace Entitlement Service: 契約ベース製品のエンタイトルメント確認に使用するサービスで、メータリングと組み合わせて利用されることが多い
→AWS Cost Explorer / コスト配分タグ: UsageAllocation のタグと連携し、購入者側でのコスト可視化・配分に活用できる

🎯 まとめ

AWS Marketplace Metering Service が小数点以下 6 桁までの使用量レポートに対応し、 セラーは顧客の実消費量に即した正確な従量課金を実現できるようになりました。 既存の整数値レポートは後方互換で動作するため、移行リスクは小さいアップデートです。

AWS Marketplace で従量課金製品を販売しているセラーは、SDK をアップデートのうえ、 丸め処理を行っている既存のメータリング実装を新しい小数値パラメータへ移行することを推奨します。
