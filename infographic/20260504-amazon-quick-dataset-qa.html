Amazon Quick

Dataset Q&A

会話型アナリティクスで、自然言語からデータインサイトへ
2026-05-04

📋 概要

Amazon Quick に Dataset Q&A が追加されました。エンタープライズデータに対して自然言語で直接質問できる会話型アナリティクス機能です。text-to-SQL エージェントがユーザーの質問を解釈し、適切なデータを特定し、正確な SQL を生成します。すべてが単一の会話ステップで完結し、Row Level Security (RLS) および Column Level Security (CLS) ポリシーを含むガバナンスルールが自動的に適用されます。

🔄 Before / After

❌ Before

  • ダッシュボード外のデータ探索にはアナリストへの依頼が必要で数時間~数日待ち
  • Topic Q&A はトピック構成やフィールド定義の事前設定が必要
  • アドホッククエリのバックログがデータチームの生産性を制約
  • 自然言語クエリの結果検証のための SQL 透明性が欠如

✅ After

  • 事前設定不要で任意のデータセットに即座に自然言語で質問可能
  • text-to-SQL エージェントがエンジン対応の最適化 SQL を自動生成
  • Explain 機能で SQL のステップバイステップの推論過程を確認可能
  • ナレッジグラフによる複数データセットの自動検出と横断クエリ

⭐ 主要機能

🔄 Text-to-SQL エージェント

  • 自然言語を解釈し適切なデータセットを特定
  • エンジン/SQL ダイアレクト対応の最適化 SQL 生成
  • SPICE + Direct Query 両対応
  • 複数質問の同時処理、会話コンテキスト維持

🧠 ナレッジグラフ

  • メタデータ、ビジネス定義、フィールド説明を統合
  • データアセット間の意味的関係を把握
  • 複数データセットからの自動ルーティング
  • All data and apps モードで全アセット横断検索

📝 Dataset Enrichment

  • カスタム指示、ビジネス定義を直接追加
  • YAML/JSON/プレーンテキストでアップロード
  • トピック構成不要でビジネスコンテキスト設定
  • 一度定義すれば全ユーザーに自動適用

🔍 Chat Explainability

  • 生成 SQL のステップバイステップ表示
  • エージェントの仮定やフィルターの説明
  • 非技術者向けプレーンテキスト説明
  • 結果の正確性を確認してから共有可能

📦 Spaces によるクロスアセット分析

  • ファイル、データセット、ダッシュボード、ナレッジベースを統合
  • 構造化データと非構造化コンテンツの横断分析
  • 組織全体のデータサイロを超えた包括的なインサイト

⚙️ 設定方法

前提条件: AWS アカウントで Amazon Quick Enterprise Edition が有効 / Enterprise または Professional ユーザーのアクセス権 / 対象データセットへのアクセス権限

1

Chat インターフェースを開く

右上のナビゲーションにある Open chat アイコンを選択。My Assistant がデフォルトのチャットエージェントとして表示されます。

2

データセットを選択する

チャットフッターのナレッジピッカーから Specific data and apps > Add > Datasets を選択し、対象データセットを選んで Save。

3

自然言語で質問する

例: "How many rides do we have for every month in 2025?" / "What percentage of total trips does each member type account for?"

4

Dataset Enrichment を設定する (オプション)

データオーナーがビジネスコンテキストを追加して精度を向上させます。

YAML dataset_enrichment.yaml の例 
# dataset_enrichment.yaml の例
fields:
  member_casual:
    description: "ユーザーの会員タイプ。member は年間会員、casual は都度利用"
  started_at:
    description: "ライドの開始タイムスタンプ"
  ended_at:
    description: "ライドの終了タイムスタンプ"
custom_instructions:
  - "duration の計算には started_at と ended_at の差分を使用する"
  - "volume は trip_count を意味する"

✅ メリット

ビジネス面

✓ データ民主化の加速: SQL スキルがないビジネスユーザーでも自然言語でデータから直接インサイトを取得可能
✓ アナリストの生産性向上: アドホックリクエストのバックログを大幅に削減し、戦略的分析に集中可能
✓ 意思決定の迅速化: 数時間~数日かかっていたデータリクエストが数秒で完了

技術面

✓ ゼロセットアップ: トピック構成やダッシュボード作成不要で即座にクエリ開始可能
✓ SQL 透明性: 生成された SQL を確認・検証でき、技術的な信頼性を担保
✓ ガバナンス自動適用: 既存の RLS/CLS ポリシーが自動適用、追加設定不要
✓ マルチエンジン対応: SPICE、Redshift、Athena、Aurora PostgreSQL、S3 Tables に最適化 SQL を生成

⚠️ 制限事項・注意点

! コンポジットデータセット (親 SPICE、子 Direct Query) は非対応
! パラメータ付きカスタム SQL データセットは非対応
! Enterprise Edition が必要 (Standard Edition では利用不可)
! 自然言語の曖昧性により、複雑なビジネス用語の解釈が意図と異なる場合あり (Explain 機能で確認推奨)
! 大規模データセットへのクエリはデータソース側のコンピューティングリソースを消費
! Dataset Enrichment によるビジネスコンテキストの追加が精度向上に重要

💡 ユースケース

📊 ユースケース 1: セルフサービス型アドホック分析

シナリオ: 営業マネージャーが四半期末にリージョン別・製品別の売上トレンドを確認したいが、既存ダッシュボードには該当ビューがない。

質問: "What were total sales by region and product category for Q4 2025, and how did they compare to Q3 2025?"

✓ アナリストへのチケット起票なしに、数秒でクロス集計結果を取得。Explain 機能で SQL を確認し経営層への報告に活用。

🔍 ユースケース 2: データエンジニアによるクエリ検証

シナリオ: 「リピート顧客」の定義が Q3 と Q4 の両方に購入があるユーザーなのか、いずれかに購入があるユーザーなのかを検証したい。

Explain で確認: WHERE customer_id IN (SELECT ... INTERSECT SELECT ...)

✓ AND vs OR ロジックの正確性を事前に検証可能。技術的な信頼性を担保してステークホルダーに結果を共有。

🌐 ユースケース 3: マルチデータセット横断分析

シナリオ: 交通計画担当者が自転車シェアリングの利用状況と気象データ、都市イベントの相関を分析。複数データソースが存在するが統合ダッシュボードは未作成。

Spaces にトリップデータ + 気象データ + イベントカレンダーを登録して横断質問

✓ 手動のデータ統合や ETL なしに、複数データサイロを横断したコンテキスト対応のインサイトを取得。

💰 料金情報

  • Dataset Q&A は Amazon Quick Enterprise Edition に含まれる機能 (追加料金不要)
  • Direct Query モードの外部データソース接続時は Redshift、Athena 等のクエリ実行コストが別途発生
  • SPICE 使用量は既存の SPICE 容量プランに基づく

🌍 利用可能リージョン

Dataset Q&A は Amazon Quick が利用可能なすべての AWS リージョンで一般提供 (GA) されています。

📌 まとめ

Amazon Quick Dataset Q&A は、ビジネスユーザーとデータの間にあった最大のボトルネック -- アナリストを介したアドホッククエリの待ち時間 -- を解消する画期的な機能です。text-to-SQL エージェント、ナレッジグラフ、Chat Explainability の組み合わせにより、自然言語から正確で透明性の高い SQL 生成を実現し、エンタープライズガバナンスを維持しながらデータの民主化を推進します。
