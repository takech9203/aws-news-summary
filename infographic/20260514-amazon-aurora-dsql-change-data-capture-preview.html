📋 概要

Amazon Aurora DSQL が Change Data Capture (CDC) のプレビューサポートを開始。データベースのリアルタイム変更を Amazon Kinesis Data Streams に直接ストリーミングできるフルマネージド機能。カスタムストリーミングパイプラインの構築や運用が不要になる。

Aurora DSQL はマルチリージョンでの強整合性を提供する分散型サーバーレス SQL データベースであり、CDC 機能によりイベント駆動型アプリケーションの構築やリアルタイム分析パイプラインの実装が容易になる。

📝 設定方法

前提条件: Aurora DSQL クラスター作成済み / Kinesis Data Streams 作成済み / IAM ロール設定済み

Step 1: Kinesis Data Streams の作成

Bash Kinesis ストリーム作成 
aws kinesis create-stream \
    --stream-name my-dsql-cdc-stream \
    --shard-count 2

Step 2: IAM ポリシーの作成

JSON IAM ポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "kinesis:PutRecord",
                "kinesis:PutRecords",
                "kinesis:DescribeStream"
            ],
            "Resource": "arn:aws:kinesis:us-east-1:123456789012:stream/my-dsql-cdc-stream"
        }
    ]
}

Step 3: CDC ストリームの作成

Bash CDC ストリーム作成 
aws dsql create-stream \
    --cluster-identifier my-dsql-cluster \
    --target-definition '{
        "kinesis": {
            "streamArn": "arn:aws:kinesis:us-east-1:123456789012:stream/my-dsql-cdc-stream",
            "roleArn": "arn:aws:iam::123456789012:role/dsql-cdc-kinesis-role"
        }
    }' \
    --ordering UNORDERED \
    --format JSON

Step 4: ステータス確認

Bash ストリーム確認 
aws dsql get-stream \
    --cluster-identifier my-dsql-cluster \
    --stream-identifier <stream-id>

CreateStream API (Python SDK)

Python SDK 呼び出し例 
client.create_stream(
    clusterIdentifier='my-dsql-cluster',

        'kinesis': {

        }
    },
    ordering='UNORDERED',
    format='JSON',

        'Environment': 'Production'
    }
)

⚠️ デメリット・制約事項

制限事項

⚠️ プレビュー段階であり、本番ワークロードでの使用は推奨されない
⚠️ 順序保証は UNORDERED のみ対応 (厳密な順序が必要な場合は追加考慮)
⚠️ データ形式は JSON のみ対応
⚠️ Kinesis Data Streams のレコードサイズ上限 (1 MB) を超えるレコードはエラー

考慮すべき点

💡 CDC の DPU 課金 + Kinesis 課金が別途発生 (コスト見積もり注意)
💡 Kinesis スループット超過時にストリームが IMPAIRED 状態に (シャード数設計が重要)
💡 IAM ロール権限設定誤りでストリームが FAILED 状態に (事前検証が必要)

🎯 ユースケース

1. マイクロサービス間のデータ同期

注文管理システムで、注文テーブルの変更をリアルタイムに在庫管理サービスや通知サービスに同期する。

Python Lambda ハンドラー例 
import json

def handler(event, context):
    for record in event['Records']:
        payload = json.loads(record['kinesis']['data'])
        operation = payload['operation']  # INSERT, UPDATE, DELETE
        table_name = payload['table']

        if table_name == 'orders' and operation == 'INSERT':
            # 在庫管理サービスに通知
            notify_inventory_service(payload['new_values'])
        elif table_name == 'orders' and operation == 'UPDATE':
            # ステータス変更を通知サービスに送信
            notify_status_change(payload['old_values'], payload['new_values'])

→ カスタムポーリング処理を排除し、ミリ秒単位のデータ同期を実現。サービス間の結合度を低減。

2. リアルタイム分析パイプライン

EC サイトのトランザクションデータをリアルタイムで分析基盤に取り込み、ダッシュボードで即時可視化。

Bash Data Firehose 設定例 
aws firehose create-delivery-stream \
    --delivery-stream-name dsql-to-redshift \
    --redshift-destination-configuration '{
        "RoleARN": "arn:aws:iam::123456789012:role/firehose-redshift-role",
        "ClusterJDBCURL": "jdbc:redshift://...",
        "CopyCommand": {
            "DataTableName": "cdc_events",
            "CopyOptions": "json '\''auto'\''"
        },
        "S3Configuration": {
            "RoleARN": "arn:aws:iam::123456789012:role/firehose-s3-role",
            "BucketARN": "arn:aws:s3:::my-cdc-backup"
        }
    }'

→ バッチ ETL で数時間かかっていたデータ取り込みが準リアルタイムに。意思決定速度が向上。

3. 監査ログと変更追跡

規制要件に基づき、データベースのすべての変更操作を S3 に永続化し、監査証跡として保持。

Bash 監査ログ配信設定 
aws firehose create-delivery-stream \
    --delivery-stream-name dsql-audit-log \
    --extended-s3-destination-configuration '{
        "RoleARN": "arn:aws:iam::123456789012:role/firehose-s3-role",
        "BucketARN": "arn:aws:s3:::audit-logs-bucket",
        "Prefix": "dsql-cdc/year=!{timestamp:yyyy}/month=!{timestamp:MM}/day=!{timestamp:dd}/",
        "BufferingHints": {
            "SizeInMBs": 64,
            "IntervalInSeconds": 300
        }
    }'

→ DB ワークロードに影響なく全変更を自動永続化。コンプライアンス要件を満たしつつ後からの調査も容易。

📌 まとめ

Amazon Aurora DSQL の CDC サポートにより、分散型データベースからのリアルタイム変更ストリーミングがフルマネージドで実現可能に。インフラ管理不要かつDB への影響ゼロの設計は、イベント駆動アーキテクチャの採用を加速させる。プレビュー段階だが、マイクロサービス間のデータ同期やリアルタイム分析パイプラインの構築を検討している場合、早期に検証を開始することを推奨。
