⚡ AWS Lambda

コンソールから IDE への統合を
Kiro と Cursor に拡張

リリース日: 2026 年 8 月 6 日 | 機能: Console-to-IDE Integration (Kiro / Cursor 対応)

📋 概要

AWS Lambda コンソールの console-to-IDE integration が、 Kiro と Cursor の 2 つの IDE に拡張されました。 これまで VS Code のみでサポートされていたコンソールからローカル開発環境へのシームレスな移行が、 AI 搭載 IDE を利用するサーバーレス開発者にも提供されます。

ガイド付きセットアップに従うだけで、既存のコードと設定を保持したままローカル開発を開始でき、 さらに Lambda 関数を AWS SAM テンプレートへ変換して IaC や CI/CD パイプラインへ統合できます。

😣 アップデート前の課題
  • ワンクリック移行は VS Code のみ対応で、Kiro / Cursor ユーザーは対象外
  • Kiro / Cursor では関数コードのダウンロードやプロジェクト構成を手動でセットアップ
  • IaC (AWS SAM テンプレート) への移行に公式のガイド付きパスがなかった
🎉 アップデート後の改善
  • [Open in Kiro] / [Open in Cursor] ボタンからワンクリックでローカル開発を開始
  • 既存のコードと設定を保持したままガイド付きセットアップで移行
  • Lambda 関数を AWS SAM テンプレートへ変換し、IaC / CI/CD へスムーズに統合
  • 選択した IDE は記憶され、次回以降プライマリボタンとして表示

Lambda コンソールを起点に、VS Code に加えて Kiro / Cursor でもローカル開発を開始でき、 AWS SAM テンプレートへの変換を通じて IaC / CI/CD へ統合する流れを示しています。

⚙️ 主要機能

1️⃣ Kiro / Cursor へのワンクリック移行
  • Code タブ / Getting Started ポップアップに [Open in Kiro] / [Open in Cursor] ボタンを追加
  • ドロップダウンから VS Code、Kiro、Cursor のいずれかを選択可能
  • 選択した IDE がローカルデバイス上で自動的に起動し、関数が開かれる
  • IDE の選択は保持され、次回以降はプライマリボタンとして表示
2️⃣ 既存コード・設定を保持したガイド付きセットアップ
  • 関数コード、依存関係、基本的なプロジェクト構造を含むローカルプロジェクトを一時的な場所に自動作成
  • AWS Toolkit や認証情報の設定を含むローカル開発の開始までをガイド
  • コード補完、デバッグ (ブレークポイント、変数インスペクション)、リファクタリングなど IDE の高度な機能を活用
3️⃣ AWS SAM テンプレートへの変換
  • 全対応 IDE で [Convert to AWS SAM Application] アイコンから変換可能
  • 変換後は template.yaml として AWS SAM プロジェクトに保存
  • インフラのバージョン管理、デプロイ自動化、リモートデバッグ、Infrastructure Composer によるビジュアル編集が可能に

🔧 技術仕様

サポート対象 IDE と要件

項目詳細
対応 IDEVisual Studio Code、Kiro、Cursor
エントリポイントLambda コンソールの Code タブ / Getting Started ポップアップ
必須ツールAWS Toolkit (バージョン 3.69.0 以降)、AWS 認証情報、AWS SAM CLI
オプションDocker (ローカルコンテナテスト)、LocalStack (サービス連携のエミュレーション)

追加料金なし

Kiro と Cursor は VS Code をベースに構築されているため、 AWS Toolkit を用いた認証フローは 3 つの IDE で共通です。

⚠️ 注意事項

⚠️ AWS Toolkit が 3.69.0 より古い場合、「Cannot open the handler」と表示されることがある → 最新バージョンへ更新する
⚠️ コンソール上で未デプロイの変更がある場合は、ローカル開発へ移行する前にデプロイを完了する

✓AWS 認証情報が設定されていること
✓AWS SAM CLI がインストールされていること (SAM 変換やローカルテストを行う場合)

1
Lambda コンソールから関数を開く

対象関数の Code タブを開き、ドロップダウンから Open in Kiro / Open in Cursor を選択。ブラウザのプロンプトで IDE を開くことを許可すると、関数コード・依存関係・プロジェクト構造を含むローカルプロジェクトが自動作成され、IDE で開かれます。

2
IDE で AWS に接続する
Command Palette AWS 接続の追加 
Command Palette (Mac: Cmd+Shift+P / Windows・Linux: Ctrl+Shift+P) を開き、
「AWS Add a New Connection」を検索して選択する

サインインパネルで IAM Credentials を選択し、プロファイル名・アクセスキー ID・シークレットアクセスキーを入力。AWS Explorer にリソースが表示されれば接続完了です。

3
ローカルで開発・テスト・デプロイする
  • コード補完を活用した関数コードの編集
  • ブレークポイントと変数インスペクションによるデバッグ
  • AWS SAM CLI によるローカルコンテナテスト、LocalStack による AWS サービス連携のエミュレーション
  • クラウドアイコンからの AWS への再デプロイ
4
AWS SAM テンプレートへ変換する (オプション)

AWS Explorer で関数の横にある Convert to AWS SAM Application アイコンを選択し、保存場所を指定。関数が template.yaml に変換され、IaC ツールや CI/CD パイプラインで管理できます。

✓開発者の選択肢の拡大: AI 搭載 IDE (Kiro / Cursor) を利用するチームもシームレスな開発体験を獲得
✓追加コストなし: 全商用リージョンで追加料金なしで利用可能

🔬 技術面のメリット

✓IaC への移行促進: AWS SAM テンプレートへの簡単な変換で CI/CD 統合・バージョン管理が容易に
✓高度な開発機能の活用: デバッグ、コード補完、リファクタリング、依存関係管理など IDE の機能を活用
✓一貫した開発体験: VS Code ベースの 3 つの IDE で認証・操作フローが共通

🚧 制限事項

✗AWS Toolkit バージョン 3.69.0 以降が必要 (古いバージョンでは「Cannot open the handler」エラー)
✗ローカルプロジェクトは一時的な場所に作成されるため、継続開発では SAM プロジェクトへの変換など適切な管理へ移行を推奨
✗商用リージョンのみで利用可能

🤔 考慮すべき点

⚠️コンソール上の未デプロイ変更は、ローカル開発へ移行する前にデプロイを完了する必要がある
⚠️SAM CLI のローカルコンテナは実際の AWS リソースへアクセスする (エミュレーションには LocalStack 連携を利用)
⚠️ドキュメントでは AdministratorAccess 付与が案内されているが、本番運用では最小権限の原則に基づく権限設計を検討すべき

💡 ユースケース

🧪 ユースケース 1: コンソールで試作した関数の本格開発への移行

シナリオ: コンソールエディタで素早くプロトタイプを作成した Lambda 関数を、Kiro を使った本格的なローカル開発へ移行したい。

Steps実装例
1. Lambda コンソールで関数の Code タブを開く
2. ドロップダウンから「Open in Kiro」を選択
3. ガイド付きセットアップに従って AWS Toolkit と認証情報を設定
4. Kiro 上でコード編集、デバッグ、依存関係の追加を実施
5. クラウドアイコンから AWS へ再デプロイ
✅ 効果: 既存のコードと設定を保持したまま移行でき、手動ダウンロードやプロジェクト構成の再現作業が不要。AI 搭載 IDE の支援を受けながら開発を継続できる。
🔁 ユースケース 2: コンソール管理の関数を IaC / CI/CD へ移行

シナリオ: コンソールで直接管理されてきた Lambda 関数群を、AWS SAM テンプレートに変換して Git 管理と CI/CD パイプラインに統合したい。

Steps実装例
1. 「Open in Cursor」で関数をローカルに展開
2. AWS Explorer の「Convert to AWS SAM Application」アイコンを選択
3. 生成された template.yaml を Git リポジトリにコミット
4. sam build / sam deploy を CI/CD パイプラインに組み込み
✅ 効果: インフラのバージョン管理、デプロイの自動化、環境間の一貫性維持が実現し、コンソール直接編集による構成ドリフトを防止できる。
🤖 ユースケース 3: AI 支援によるサーバーレスアプリケーションの改善

シナリオ: 既存の Lambda 関数のリファクタリングやテストコード追加を、Kiro / Cursor の AI 支援機能を活用して効率的に行いたい。

Steps実装例
1. Lambda コンソールから「Open in Kiro」で関数を開く
2. Kiro のエージェント機能でコードレビュー、リファクタリング、
   テストコード生成を依頼
3. AWS SAM CLI (sam local invoke) でローカルテストを実行
4. 問題がなければ AWS へデプロイ
✅ 効果: AI 搭載 IDE の支援によりコード品質の改善やテスト整備を高速に進められ、ローカルでの検証を経て安全にデプロイできる。

💰 料金・利用可能リージョン

💵 料金: 本機能に追加料金はありません。Lambda の実行には通常の Lambda 料金 (リクエスト数と実行時間に基づく課金) が適用されます。Kiro / Cursor 自体の利用料金は各製品の料金体系に従います。
🌏 利用可能リージョン: AWS Lambda が利用可能なすべての商用 AWS リージョンで利用できます (東京・大阪リージョンを含む)。

🔗 関連サービス・機能

📄AWS Serverless Application Model (AWS SAM): Lambda 関数を SAM テンプレートに変換することで、IaC によるインフラ管理とデプロイ自動化が可能
🧰AWS Toolkit for Visual Studio Code: VS Code / Kiro / Cursor で AWS リソースを操作するための拡張機能。本機能の利用にはバージョン 3.69.0 以降が必要
🟪Kiro: AWS が提供する AI 搭載 IDE。スペック駆動開発やエージェント機能を備え、本アップデートで Lambda コンソールとの統合に対応
🎨AWS Infrastructure Composer: 変換した SAM テンプレートをビジュアルに編集できるツール
🏗️AWS Cloud Development Kit (AWS CDK): ローカル開発環境で利用できるもう 1 つの IaC ツール

📝 まとめ

Lambda コンソールから Kiro / Cursor へのワンクリック移行が可能になり、 AI 搭載 IDE を利用するサーバーレス開発者もコンソールとローカル開発環境をシームレスに行き来できるようになりました。 特に、コンソールで作成した関数を AWS SAM テンプレートへ変換して IaC / CI/CD へ統合できる点は、 開発プロセスの成熟化に直結します。

Kiro や Cursor を利用しているチームは、AWS Toolkit を 3.69.0 以降へ更新した上で、 この統合をローカル開発の標準的な入口として活用することを推奨します。
