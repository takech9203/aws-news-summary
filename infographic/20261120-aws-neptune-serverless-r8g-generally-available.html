🚀 Neptune Serverless が Graviton4 ベースに刷新
最大 30% パフォーマンス向上とスマートなスケーリング

📅 リリース日: 2026 年 11 月 20 日 | 🏷️ Neptune Serverless / AWS Graviton4

📌 概要

Amazon Neptune Serverless が AWS Graviton4 プロセッサベースのプラットフォームに移行し、 Neptune Capacity Unit (NCU) あたりの価格は据え置きのまま、 最大 30% のパフォーマンス向上を実現しました。 あわせて改善されたスケーリングアルゴリズムが導入され、NCU の割り当てがワークロードの需要により精密に追従します。

リアルタイム不正検知、レコメンデーションエンジン、生成 AI アプリケーションなど、多数のグラフクエリを同時に実行するアプリケーションで特に効果を発揮します。 新規に作成される Neptune Serverless インスタンスはすべて Graviton4 上で実行され、既存クラスターは次回リリースで最新バージョンにアップグレードすることで利用できます。

❌ アップデート前の課題
  • 旧世代 Graviton 上で動作し、NCU あたりの処理性能に上限があった
  • スケーリング精度に限界があり、同時実行クエリが多いと容量の割り当てが過剰または不足になる場合があった
  • 性能を引き上げるには MaxCapacity を増やす必要があり、コストが増加していた
✅ アップデート後の改善
  • Graviton4 への移行により、同じ NCU あたり価格で最大 30% 高いパフォーマンス
  • 改善されたアルゴリズムで NCU が需要に正確に追従し、無駄な容量割り当てが減少
  • 新規インスタンスは自動的に Graviton4 で起動し、追加設定が不要

Neptune Serverless のコンピューティング層が Graviton4 ベースの NCU プールに刷新され、スケーリング判定も改善されました。 ストレージ層は従来どおりコンピューティングとは独立しており、サーバーレススケーリングの影響を受けません。

1️⃣ AWS Graviton4 プロセッサへの移行
  • Neptune Serverless の基盤が AWS Graviton4 プロセッサに刷新
  • NCU あたりの価格は変わらず、最大 30% 高いパフォーマンスを実現
  • 新規作成される Neptune Serverless インスタンスはすべて Graviton4 上で実行
2️⃣ 改善されたスケーリングアルゴリズム
  • Graviton4 プラットフォームには更新されたスケーリングアルゴリズムが含まれる
  • NCU の割り当てをワークロード需要に対してより精密に調整
  • 多数のグラフクエリを同時実行するアプリケーションで特に効果が大きい
3️⃣ 既存クラスターのアップグレードパス
  • 既存クラスターは次回リリースで最新バージョンにアップグレードすることで Graviton4 を利用可能
  • 利用者側でインスタンスクラスの変更などの作業は不要

🛠️ 設定方法

✅ 前提条件

✓AWS アカウントと Amazon Neptune へのアクセス権限があること
✓Neptune Serverless がサポートされるリージョンを利用すること
✓Neptune エンジンバージョン 1.2.0.1 以降を利用すること

ステップ 1: Neptune Serverless クラスターの新規作成

Bash クラスター作成 
aws neptune create-db-cluster \
    --db-cluster-identifier my-serverless-cluster \
    --engine neptune \
    --serverless-v2-scaling-configuration MinCapacity=1.0,MaxCapacity=16.0 \
    --region ap-northeast-1

最小 1.0 NCU、最大 16.0 NCU のスケーリング範囲を設定。新規作成されるインスタンスは自動的に Graviton4 ベースのプラットフォームで起動します。

ステップ 2: サーバーレスインスタンスの追加

Bash インスタンス追加 
aws neptune create-db-instance \
    --db-instance-identifier my-serverless-instance \
    --db-cluster-identifier my-serverless-cluster \
    --db-instance-class db.serverless \
    --engine neptune

インスタンスクラスに db.serverless を指定してサーバーレスインスタンスをクラスターに追加。容量はステップ 1 で設定した範囲内で自動調整されます。

ステップ 3: 既存クラスターのアップグレード確認

Bash エンジンバージョン確認 
aws neptune describe-db-clusters \
    --db-cluster-identifier my-existing-cluster \
    --query "DBClusters[0].EngineVersion"

既存クラスターで Graviton4 の恩恵を受けるには、次回リリースで最新バージョンへのアップグレードが必要です。

✓クエリ性能の向上: Graviton4 により、グラフクエリの実行性能が最大 30% 向上する
✓スケーリング精度の向上: 改善されたアルゴリズムが NCU をワークロード需要に精密に追従させ、容量の過不足を抑制する
✓高同時実行ワークロードへの適合: 不正検知やレコメンデーションなど、多数の同時グラフクエリを処理するアプリケーションで効果が大きい

⚠️ デメリット・制約事項

🚧 制限事項

⚠既存クラスターが Graviton4 を利用するには、次回リリースでの最新バージョンへのアップグレードが必要
⚠Neptune Serverless は利用可能なリージョンが限定されている (詳細は料金ページとドキュメントを参照)
⚠既存の制約 (ルックアップキャッシュ非対応、最大 128 NCU など) は引き続き適用される

🤔 考慮すべき点

⚠性能向上は「最大 30%」であり、実際の改善幅はワークロードの特性 (クエリパターン、同時実行数など) に依存する
⚠既存クラスターのアップグレード時はメンテナンスウィンドウや影響範囲を事前に計画することが推奨される
⚠容量の推移が従来と変わる可能性があるため、アップグレード後は CloudWatch メトリクス (ServerlessDatabaseCapacity など) の監視が推奨される

🎯 ユースケース

🔍 ユースケース 1: リアルタイム不正検知

決済トランザクションをグラフとしてモデル化し、取引発生のたびに関連エンティティを探索して不正パターンを検出。トラフィックは時間帯やキャンペーンによって大きく変動する。

Neptune Serverless クラスター (MinCapacity=2.0, MaxCapacity=64.0) 決済イベント → Lambda → Gremlin / openCypher クエリで近傍探索 → スコアリング

効果: Graviton4 によるクエリ性能向上で検知レイテンシーが短縮され、改善されたスケーリングがトランザクション急増時にも容量を精密に追従させる。

🛒 ユースケース 2: レコメンデーションエンジン

ユーザー、商品、行動履歴のグラフから「この商品を見た人はこれも見ている」といった推薦を生成。セール期間中は同時クエリ数が平常時の数倍になる。

Neptune Serverless クラスター (MinCapacity=1.0, MaxCapacity=32.0) アプリケーション → 多数の同時グラフトラバーサル → 推薦候補の取得

効果: 多数の同時グラフクエリに対して NCU が需要どおりにスケールし、ピーク時も安定した応答時間を維持しながら閑散期のコストを抑制できる。

🤖 ユースケース 3: 生成 AI アプリケーションのナレッジグラフ

RAG 構成のナレッジグラフとして Neptune を利用し、LLM からの問い合わせに応じてエンティティ間の関係を探索。利用量はユーザーの質問頻度に依存し予測が難しい。

Neptune Serverless クラスター (MinCapacity=1.0, MaxCapacity=16.0) LLM アプリケーション → グラフ探索クエリ → コンテキストとして LLM に供給

効果: 予測困難なワークロードでも自動スケーリングで対応でき、NCU あたり性能の向上によりグラフ探索ステップの応答が高速化される。

💰 料金

Neptune Serverless は、実際に使用した容量 (NCU 時間) に対してのみ課金される従量課金モデルです。 今回のアップデートで NCU あたりの価格は変更されず、同じ価格で最大 30% 高いパフォーマンスが得られるため、 実質的なプライスパフォーマンスが向上します。

ストレージと I/O は従来どおりコンピューティングとは別に課金されます。最新の単価は Amazon Neptune 料金ページ を参照してください。

📝 まとめ

Neptune Serverless の Graviton4 移行により、追加コストなしで最大 30% の性能向上と、 より精密な自動スケーリングが利用可能になりました。新規クラスターは自動的に恩恵を受けられるため、 グラフデータベースの新規導入では Serverless 構成が従来以上に有力な選択肢になります。 既存の Neptune Serverless 利用者は、次回リリースでの最新バージョンへのアップグレードを計画することを推奨します。
