🤖 Gemma 4 モデルの提供開始

2026-06-10
Google DeepMind 製
オープンウェイトモデル

📌 概要

AWS は、Google DeepMind が開発するオープンウェイトモデルファミリー Gemma 4 を Amazon Bedrock で利用可能にしました。推論、マルチモーダル理解、エージェント、ソフトウェアエンジニアリングといった幅広いワークフローで生成 AI アプリケーションを構築できます。

ファミリーには 3 つのバリアントが含まれ、Dense と Mixture-of-Experts (MoE) の両アーキテクチャをカバー。組み込みの推論、ネイティブな関数呼び出し、35 以上の言語、テキストと画像のマルチモーダル入力に対応します。

⏪ アップデート前の課題

  • Bedrock で使える Google オープンモデルは Gemma 3 ファミリー (12B / 27B / 4B) が中心
  • MoE による高コスト効率の推論や 256K トークンの大きなコンテキストを Gemma 系で利用できなかった
  • ワークロード特性 (推論・コスト・低レイテンシー) に応じた細かな選択肢が限られていた

⏩ アップデート後の改善

  • 最新世代の Gemma 4 をフルマネージド環境で利用可能に
  • Dense と MoE の両アーキテクチャから 3 バリアントを選択可能
  • ネイティブな関数呼び出し・構造化出力・ストリーミングでエージェント構築が容易に

アプリケーションやエージェントは Bedrock の Runtime API を通じて、ワークロード特性に応じた 3 つの Gemma 4 バリアントを呼び出します。

⚡ 主要機能 - 3 つのバリアント

Gemma 4 31B
Dense モデル 307 億 パラメータ / 256K トークン
  • 推論・コーディング中心の高負荷ワークロードに最適
  • 組み込み推論・関数呼び出し・マルチモーダル入力
Gemma 4 26B-A4B
MoE モデル 252 億 総数 / アクティブ 38 億 / 256K
  • コスト効率の高い推論を実現
  • コスト・レイテンシーに敏感なワークロード向け
Gemma 4 E2B
コンパクトモデル 51 億 総数 / 実効 23 億 / 128K
  • 最小バリアント
  • 低レイテンシーのインタラクティブ用途向け

💻 API 呼び出し例

Amazon Bedrock の Converse API で Gemma 4 31B にプロンプトを送信する例です。モデル ID は AWS のモデルカードページで正確な値を確認してください。

Python Converse API 呼び出し例 
import boto3
import json

# Amazon Bedrock Runtime クライアントを作成する
client = boto3.client("bedrock-runtime", region_name="us-east-1")

# Converse API を使用して Gemma 4 31B を呼び出す
response = client.converse(
    modelId="google.gemma-4-31b",  # 実際のモデル ID はモデルカードで確認する
    messages=[
        {
            "role": "user",
            "content": [{"text": "Amazon Bedrock の特徴を 3 点で説明してください。"}],
        }
    ],
    inferenceConfig={"maxTokens": 1024, "temperature": 0.7},
)

print(response["output"]["message"]["content"][0]["text"])

🛠️ 設定方法

前提条件

✓Gemma 4 が利用可能なリージョン (米国東部 (バージニア北部) など) で Bedrock を有効化
✓Bedrock コンソールのモデルアクセスから対象モデルへのアクセスを有効化
✓InvokeModel / Converse を呼び出すための IAM 権限を保持

手順

1

モデルアクセスの有効化

Bedrock コンソールの「モデルアクセス」画面で Gemma 4 各バリアントへのアクセスを有効化し、API から呼び出せるようにします。

2

バリアントの選択

ワークロード特性に応じて適切なバリアントを選択します。

Text選択ガイド
推論・コーディング中心の高負荷ワークロード  -> Gemma 4 31B
コスト・レイテンシーに敏感なワークロード      -> Gemma 4 26B-A4B
低レイテンシーのインタラクティブ用途          -> Gemma 4 E2B
3

アプリケーションへの組み込み

InvokeModel または Converse API でモデルを組み込みます。エージェントワークフローでは、ネイティブな関数呼び出しと構造化出力を活用してツール連携を実装します。

🎯 メリット

💼 ビジネス面

  • モデル選択肢の拡大: 最新の Gemma 4 ファミリーをユースケースに応じて選択
  • コスト最適化: MoE / コンパクトモデルでコストとレイテンシーを抑制
  • マルチリンガル対応: 35 以上の言語でグローバル開発に活用

⚙️ 技術面

  • 長いコンテキスト: 31B / 26B-A4B は 256K トークンで大量ドキュメントを処理
  • エージェント構築: ネイティブ関数呼び出しと構造化出力で容易に
  • フルマネージド運用: インフラ管理なしでオープンウェイトモデルを利用

⚠️ デメリット・制約事項

制限事項

▲提供リージョンは米国東部 (バージニア北部 / オハイオ)、米国西部 (オレゴン)、欧州 (フランクフルト) に限定
▲入力モダリティはモデルカード上でテキストと画像が明記。利用前に最新のモデルカードでサポート範囲を確認
▲Gemma 4 E2B のコンテキストは 128K トークンで、31B / 26B-A4B の 256K より小さい

考慮すべき点

💡モデル ID・正確なパラメータ・料金は AWS のモデルカードおよび料金ページで確認
💡推論重視・コスト重視・低レイテンシー重視のいずれを優先するかでバリアントを選定

🚀 ユースケース

1. 大規模ドキュメントに対する推論

シナリオ: 長文の技術仕様書や契約書を読み込み、要約や質問応答を行う社内アプリ。
実装: Gemma 4 31B で 256K トークンに複数ドキュメントを投入し推論。
効果: 大量コンテキストを一度に処理し、複雑な推論を要する質問にも対応。

2. コスト効率の高いチャットアプリケーション

シナリオ: 高トラフィックなカスタマーサポートチャットをコストとレイテンシーを抑えて運用。
実装: Gemma 4 26B-A4B (MoE) でアクティブパラメータを抑えた推論。
効果: MoE でコスト効率を高めつつ、品質を維持した応答を提供。

3. 低レイテンシーのエージェントワークフロー

シナリオ: ツールを呼び出しながら短い応答を高速に返すインタラクティブなエージェント。
実装: Gemma 4 E2B でネイティブ関数呼び出しと構造化出力によるツール連携。
効果: 低レイテンシー応答と構造化されたツール呼び出しを両立。

💰 料金

Gemma 4 は価格性能を重視して設計されています。具体的な料金は使用するモデルバリアント、リージョン、入力・出力トークン数に基づきます。正確な料金は Amazon Bedrock の料金ページで確認してください。

✅ まとめ

今回のアップデートにより、Google DeepMind の最新オープンウェイトモデル Gemma 4 が Amazon Bedrock で利用可能になり、推論重視・コスト重視・低レイテンシー重視という異なるワークロード特性に合わせて 3 つのバリアントから選択できるようになりました。

エージェントやソフトウェアエンジニアリングのワークフローを Bedrock 上で構築している場合は、ネイティブな関数呼び出しと構造化出力のサポートを活かして評価を進めることを推奨します。まずは対象リージョンでモデルアクセスを有効化し、自社のユースケースに合うバリアントを検証してください。
