Amazon Elastic VMware Service (EVS)

VMware Cloud Foundation
VCF 9.0 / 9.1 のサポート開始

オンプレミスと同じ最新の VMware を AWS 上で完全制御
リリース日
2026 年 7 月 6 日

📌 概要

Amazon EVS は、最新の VCF ソフトウェアをお客様の Amazon VPC 内の EC2 ベアメタルインスタンス上で直接実行できるサービスです。今回のアップデートにより、VCF 9.0 および 9.1 で稼働する VMware 仮想化ソリューションのインストール、運用、管理を完全に制御できるようになりました。

VCF 9.x では AWS のインフラプロビジョニングと VCF ソフトウェア自体が分離されます。EVS が ESX 9.x を実行する EC2 ベアメタルインスタンスを VPC にデプロイし、プライベート VLAN と接続。お客様は Broadcom の VCF Installer をダウンロードしてネイティブなワークフローでインストールを完了するため、既存のデータセンターのツール・プロセス・スキルをそのまま再利用できます。

⛔ アップデート前の課題
🔸 最新 VCF 9.x が EVS 上でサポートされず、オンプレミスと同一バージョンを AWS で稼働できない
🔸 環境構築を迅速に開始するための公式テンプレートや IaC サンプルが未提供
🔸 VCF のバージョン差異で移行元と移行先のアーキテクチャが異なり、大規模移行が複雑化
➡
✅ アップデート後の改善
🔹 VCF 9.0 / 9.1 を EVS 上で実行し、オンプレミスと同じ最新ソフトウェアを AWS で稼働
🔹 Solutions for EVS の GitHub サンプル・IaC で環境構築を迅速にスタート
🔹 移行元と移行先のアーキテクチャ差異を最小化し、大規模移行を簡素化・加速

Amazon EVS が ESX 9.x を実行する EC2 ベアメタルインスタンスを VPC にデプロイし、プライベート VLAN を基盤として VCF 9.0 / 9.1 をお客様自身がインストール・運用する構成

⚡ 主要機能

📦 VCF 9.0 / 9.1 のサポート

  • 最新 VCF を VPC 内の EC2 ベアメタル上で直接実行
  • インストール・運用・管理をお客様が完全に制御
  • 既存のツール・プロセス・スキルを再利用可能
  • 自己管理／AWS パートナーとの協業を選択可能

🧪 評価モード (Evaluation mode)

  • ライセンスキーを事前に用意せず環境構築を開始
  • 本番適用前に設計の検証やテストを実施
  • 評価モードを超える利用はサブスクリプション適用が必要

📚 Solutions for EVS GitHub リポジトリ

  • 環境構築を迅速に開始するサンプル・テンプレート・IaC を提供
  • AWS CloudFormation / HashiCorp Terraform に対応
  • 今後リファレンスアーキテクチャや AWS 統合を拡充予定

🔗 EVS Connector

  • EVS から VCF 管理アプライアンスへの永続的で認証された接続
  • 認証情報は AWS Secrets Manager に保存
  • 環境の状態監視と使用状況レポート (運用パスには非介在)

🛠️ 設定の流れ

STEP 1EVS 環境の作成
EC2 ベアメタル + プライベート VLAN を構成
→
STEP 2VCF のインストール
VCF Installer で 9.0 / 9.1 を導入
→
STEP 3活用と運用開始
IaC 標準化 + Connector で監視
💡 前提条件: EVS 利用可能リージョンの AWS アカウント / EC2 ベアメタルをデプロイする VPC / Broadcom の VCF Installer と VCF 9.0・9.1 のライセンス (評価モードの場合は事前のライセンスキー不要)

🔧 技術仕様 (アーキテクチャ構成)

コンピュート基盤EC2 ベアメタルインスタンス (ESX 9.x を実行)
デプロイ先お客様の Amazon VPC
ネットワークプライベート VLAN (VCF デプロイメントのアンダーレイ)
サポート VCF バージョンVCF 9.0 および 9.1
インストーラーBroadcom VCF Installer (お客様がダウンロードしてデプロイ)
IaC 対応AWS CloudFormation、HashiCorp Terraform
📝 今回のアップデートに関連する awsapichanges.com への API 変更の登録は確認されませんでした。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓迅速なクラウド移行: 契約期限やリフレッシュサイクルなど時間的制約に対し最速級の移行手段
✓既存資産の活用: ツール・プロセス・スキルを再利用し再教育コストを抑制
✓柔軟な運用体制: 自己管理と AWS パートナー協業のいずれも選択可能

🚀 技術面のメリット

＋最新 VCF の利用: オンプレミスと同じ VCF 9.0 / 9.1 を AWS で稼働
＋移行の簡素化: アーキテクチャ差異を最小化し大規模移行を加速
＋迅速な立ち上げ: Solutions for EVS の IaC で環境構築を効率化

⚠️ 制限事項

▲VCF のインストール・運用・管理はお客様の責任 (フルマネージドではない)
▲評価モードを超える利用は VCF サブスクリプション適用が必要
▲VCF Installer や VCF ライセンスは Broadcom から別途調達

🔍 考慮すべき点

▲EC2 ベアメタル利用のためインスタンスの選定とコスト見積もりが必要
▲VCF 9.x の運用には VMware の専門知識が求められる
▲既存バージョンからの移行時は互換性を事前確認することが望ましい

🎯 ユースケース

1️⃣ データセンター契約期限に伴う移行

シナリオ: オンプレミスのデータセンター契約が期限を迎える企業が、短期間で VMware ワークロードをクラウドへ移行したい。
効果: オンプレミスと同じ方法で VCF をデプロイ・運用でき、アーキテクチャ差異を最小化し期限内に迅速な移行を実現。

2️⃣ 最新 VCF 環境の検証

シナリオ: 本番導入前に VCF 9.1 の新機能や設計を評価したい。
効果: 評価モードを利用し、ライセンスキーを事前に用意せず EVS 環境を構築して設計の検証やテストを実施。

3️⃣ IaC による標準化されたデプロイ

シナリオ: 複数の環境で一貫した EVS / VCF 構成を再現可能な形で展開したい。
効果: Solutions for EVS の CloudFormation / Terraform アーティファクトで環境構築を自動化・標準化。

💰 料金・利用可能リージョン・関連サービス

💰 料金

Amazon EVS の利用料金は EC2 ベアメタルインスタンスなどの AWS リソース使用量に基づきます。VCF ソフトウェアのライセンス (サブスクリプション) は Broadcom から別途調達が必要です。

🌏 利用可能リージョン

Amazon EVS が提供されているすべてのリージョンで利用可能です。

🔗 関連サービス・機能

Amazon EC2 ベアメタル Amazon VPC AWS Secrets Manager AWS CloudFormation HashiCorp Terraform

📝 まとめ

Amazon EVS が VCF 9.0 / 9.1 をサポートしたことで、オンプレミスと同じ最新の VMware Cloud Foundation を AWS 上で完全に制御しながら運用できるようになりました。評価モードや Solutions for EVS GitHub リポジトリの提供により、環境構築の検証と迅速な立ち上げが容易です。VMware ワークロードのクラウド移行を検討中の場合は、まず評価モードで設計を検証し、Solutions for EVS の IaC アーティファクトを活用して展開を進めることをおすすめします。
