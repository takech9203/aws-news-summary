Kiro 📅 リリース日: 2026 年 11 月 3 日

⚡ Kiro CLI 3.0: V3 がデフォルトに

V3 エージェントハーネスのデフォルト化 / 単一 kiro-cli バイナリへの移行 / Classic・デスクトップアプリ・インライン補完の廃止

📋 概要

Kiro CLI 3.0.0 がリリースされ、V3 エージェントハーネスが対話型セッションのデフォルトになりました。V3 を実行できるホストでは新規セッションは V3 で開始され、既存の V2 ユーザーには適用前に確認が行われます。V2 形式のカスタムエージェントは、無効化しない限り自動的に V3 形式へアップグレードされます。

あわせて Kiro CLI は単一のスタンドアロン kiro-cli バイナリとなり、Classic (V1) インターフェース、デスクトップアプリ、インライン補完が廃止されました。破壊的変更を含むため、既存のスクリプトやインストール方法への影響確認が必要です。

❌ Before: アップデート前の課題

  • V3 利用には --v3 フラグの明示指定が必要で、Cloud sessions や Memory がデフォルトで有効にならなかった
  • Classic (V1)、V2、V3 の複数世代とデスクトップアプリ / CLI の配布形態が併存し、構成が分かりにくかった
  • V2 形式のカスタムエージェントは手動でのアップグレード作業が必要だった

✅ After: アップデート後の改善

  • --v3 フラグなしで Cloud sessions、Memory、Approve for me、/sandbox、/autonomous on、Workflows を利用可能
  • 単一のスタンドアロン kiro-cli バイナリに統合され、配布形態がシンプルに
  • V2 形式のカスタムエージェントは自動アップグレード (無効化も可能)
  • 事前確認と kiro-cli --v2 により段階的に移行できる

Kiro CLI 3.0 における起動方法ごとのデフォルトハーネスの選択と、V3 で利用できる機能、本リリースで廃止されたコンポーネントの全体像

🚀 主要機能

1️⃣ V3 エージェントハーネスのデフォルト化
  • V3 を実行できるホストでは、--v3 フラグなしで V3 がデフォルトに
  • 対話セッション: 新規セッションは V3 で開始。既存の V2 ユーザーにはデフォルト適用前に確認
  • ヘッドレス: --trust-all-tools を使用するスクリプトはデフォルトで V3。その他のスクリプトは V2 のまま
  • ACP: 新規クライアントはデフォルトで V3。既存クライアントは、すでにサポート済みの場合を除き V2 のまま
2️⃣ V2 形式カスタムエージェントの自動アップグレード
  • V2 形式のカスタムエージェントは、V3 セッション開始時に自動的に V3 形式へアップグレード
  • この自動アップグレードは設定で無効化できる
3️⃣ 単一のスタンドアロン kiro-cli バイナリ
  • Kiro CLI は単一のスタンドアロン kiro-cli バイナリに統合
  • Classic インターフェース、デスクトップアプリ、インライン補完は本バイナリには含まれない

⚡ V3 で利用できる機能 (V2 にはない機能)

☁️ Cloud sessionsセッションを切断し、後から /sessions で再開できる
🧠 Memory有効化すると、リポジトリのコンテキストを以降のセッションに引き継ぐ
✅ Approve for me定型的な操作を承認し、安全でない操作をブロック。deny / ask / allow ルールが常に優先
🛡️ /sandboxシェルコマンドを分離して実行する
🤖 /autonomous onサンドボックス有効時に、コマンドごとの承認なしでタスクを実行
📋 Workflows開始前に計画を提示。/settings > Features で有効化

⚠️ 破壊的変更

🧓 Classic インターフェースの廃止
  • Classic (V1) の対話型エクスペリエンスは動作しなくなった
  • コマンド、エイリアス、設定が Classic を選択している場合、チャット開始時に「Continue with V3」が提示され、スクリプトではその選択が無視される
  • V2 エージェントを使い続けるには kiro-cli --v2 を実行する
💻 デスクトップアプリの廃止
  • Kiro CLI はデスクトップアプリを同梱しなくなった
  • 既存の macOS デスクトップアプリは、次回のアップデートチェック時にスタンドアロンの kiro-cli に切り替わる
  • 再インストールは「Moving from the Kiro CLI desktop app」のドキュメントを参照
⌨️ インライン補完 / インライン提案の廃止
  • シェルのインライン autocomplete とインライン提案は廃止され、単体での代替機能はない
  • autocomplete、inline、translate、theme、dashboard コマンドは利用不可。スクリプトから削除が必要
  • kiro-cli doctor を実行すると、kiro-cli diagnostic または kiro-cli issue の利用が案内される

⚙️ 設定方法

前提条件: Kiro CLI を利用していること、V3 を実行できるホスト環境であること

1
Kiro CLI 3.0 にアップデートする
Bash最新バージョンに更新
kiro-cli update

既存の macOS デスクトップアプリは、次回のアップデートチェック時にスタンドアロンの kiro-cli に切り替わります。

2
対話セッションを開始する
BashV3 がデフォルトで使用される
kiro-cli

--v3 フラグの指定は不要。すでに V2 を使用していた場合は、デフォルト適用前に確認が表示されます。V2 形式のカスタムエージェントは自動的に V3 形式へアップグレードされます (無効化も可能)。

3
必要に応じて V2 を継続利用する
BashV2 エージェントで起動
kiro-cli --v2

コマンドやエイリアスが Classic を選択したままの場合、チャット開始時には「Continue with V3」が提示され、スクリプトではその選択が無視される点に注意してください。

4
既存スクリプトへの影響を確認する

廃止された autocomplete、inline、translate、theme、dashboard コマンドをスクリプトから削除します。kiro-cli doctor は kiro-cli diagnostic または kiro-cli issue への置き換えを検討します。--trust-all-tools を使用するヘッドレス実行はデフォルトで V3 になるため、動作を確認してください。

💡 メリット・制約事項

✅ メリット

✓新機能の標準化: Cloud sessions、Memory、Workflows などがデフォルトで利用可能になり、チーム全体で最新のエージェント体験に統一できる
✓運用のシンプル化: 単一バイナリへの統合により、インストールやアップデートの運用が簡素化される
✓段階的な移行: 事前確認と kiro-cli --v2 によるオプトアウトで、業務影響を抑えながら移行できる
✓フラグ指定が不要: 起動コマンドやドキュメントを簡素化できる
✓自動移行: カスタムエージェントの手動移行作業が不要
✓安全性の向上: /sandbox によるコマンド分離、Approve for me によるルール優先の制御をそのまま利用できる

⚠️ 制約・考慮事項

✗Classic (V1) の対話型エクスペリエンスは動作しない
✗デスクトップアプリは提供されず、インライン補完には単体での代替機能がない
✗autocomplete / inline / translate / theme / dashboard コマンドは利用不可
⚠V3 のデフォルト化は V3 を実行できるホストに限られる
⚠廃止コマンドを使用している既存スクリプトは修正が必要
⚠--trust-all-tools を使うスクリプトはデフォルトが V3 に変わるため、事前検証を推奨
⚠V2 形式を維持したい場合は自動アップグレードの無効化が必要

🎯 ユースケース

📌 ユースケース 1: V3 への全面移行

シナリオ: --v3 フラグを付けて V3 を試用していた開発チームが、チーム全体の標準環境として V3 に移行したい。

  1. kiro-cli update で Kiro CLI 3.0 に更新
  2. エイリアスや起動スクリプトから --v3 フラグを削除
  3. 対話セッションを開始し、V2 からの移行確認に同意
  4. /settings > Features で Workflows を有効化し、Memory や Approve for me を必要に応じて有効化
💡 効果: フラグ指定なしで全メンバーが V3 の Cloud sessions、Memory、Workflows などを利用でき、環境構築手順が簡素化される。
📌 ユースケース 2: デスクトップアプリからの移行

シナリオ: macOS でデスクトップアプリ版の Kiro CLI を利用しており、本リリース後の環境に移行する必要がある。

  1. 次回のアップデートチェックでスタンドアロンの kiro-cli への自動切り替えを確認
  2. 再インストールが必要な場合は「Moving from the Kiro CLI desktop app」のドキュメントに従う
  3. インライン補完に依存していたワークフローを見直す
💡 効果: 単一バイナリ構成に移行し、今後のアップデートを kiro-cli のみで管理できる。
📌 ユースケース 3: 既存スクリプト・CI パイプラインの影響確認

シナリオ: ヘッドレスで Kiro CLI を呼び出すスクリプトや CI パイプラインを運用しており、3.0 へのアップデートによる影響を最小化したい。

  1. スクリプト内の autocomplete / inline / translate / theme / dashboard コマンドを削除
  2. kiro-cli doctor の呼び出しを kiro-cli diagnostic または kiro-cli issue に置き換え
  3. --trust-all-tools を使用するスクリプトは V3 がデフォルトになるため、検証環境で動作確認
  4. V2 の挙動を維持したい対話利用では kiro-cli --v2 を使用
💡 効果: 破壊的変更の影響を事前に洗い出し、パイプラインを停止させることなく 3.0 へ移行できる。

📝 まとめ

Kiro CLI 3.0.0 により、V3 エージェントハーネスが対話セッションのデフォルトとなり、Cloud sessions、Memory、Approve for me、/sandbox、/autonomous on、Workflows を --v3 フラグなしで利用できるようになりました。

一方で、Classic (V1) インターフェース、デスクトップアプリ、インライン補完が廃止される破壊的変更を含むため、廃止コマンドを使用するスクリプトの修正と、--trust-all-tools を使うヘッドレス実行の挙動確認を早めに実施することを推奨します。V2 を継続したい場合は kiro-cli --v2 で起動できます。
