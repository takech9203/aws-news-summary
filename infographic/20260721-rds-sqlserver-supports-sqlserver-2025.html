🗄️ Amazon RDS for SQL Server
Microsoft SQL Server 2025 のサポート

Amazon RDS for SQL Server
📅 リリース日: 2026 年 7 月 21 日

📌 概要

Amazon RDS for SQL Server が、Microsoft SQL Server 2025 の Enterprise / Standard / Developer 各エディションをサポートしました。SQL Server 2025 最大の特徴は、 AI 統合をデータベースエンジンに直接組み込んだ点です。 追加のミドルウェアを介さずに、T-SQL から外部 REST エンドポイントを呼び出せるようになりました。

これにより、アプリケーションを再設計することなく、データベースワークロードを Amazon Bedrock、Amazon SageMaker、 Amazon S3、AWS Lambda といった AWS サービスとセキュアに統合できます。既存のお客様は DB エンジンバージョンを変更することでアップグレードできます。

⚠️ アップデート前の課題
  • DB から AI/ML 推論を呼ぶには Lambda やアプリ層など追加ミドルウェアの構築が必要だった
  • Standard Edition の計算能力は上限が低く、Resource Governor は Enterprise 限定だった
  • ベクトル埋め込みの類似検索や生成 AI には専用のベクトル DB を別途用意する必要があった
✅ アップデート後の改善
  • T-SQL から直接 REST エンドポイントを呼び、AWS サービスと連携できる
  • Standard Edition が最大 32 コア・256 GB へ拡張、Resource Governor も利用可能に
  • ネイティブなベクトルデータ型で埋め込みを DB 内に格納・クエリできる
  • 無償の Standard Developer Edition で開発・テスト環境をコストなしで構築

RDS for SQL Server 2025 の T-SQL から外部 REST エンドポイント呼び出しを通じて、Amazon Bedrock や SageMaker、Lambda などの AWS サービスと連携する構成を示しています。

⚙️ サービスアップデートの詳細 - 主要機能

1️⃣ データベースエンジンへの AI 統合

  • システムストアドプロシージャ sp_invoke_external_rest_endpoint で T-SQL から外部 REST エンドポイントを直接呼び出せる
  • 追加ミドルウェアなしで Bedrock / SageMaker / S3 / Lambda とセキュアに統合
  • CREATE EXTERNAL MODEL で AI 推論エンドポイントを管理し、AI_GENERATE_EMBEDDINGS や AI_GENERATE_CHUNKS から利用

2️⃣ ネイティブなベクトルデータ型

  • ベクトル埋め込みを DB 内に直接格納・クエリできる vector データ型を追加
  • 最適化されたバイナリ形式で格納しつつ、利便性のため JSON 配列として公開
  • VECTOR_DISTANCE / VECTOR_NORM / VECTOR_NORMALIZE によるベクトル演算
  • 近似最近傍探索 (VECTOR_SEARCH) やベクトルインデックスも利用可 (一部は PREVIEW_FEATURES が必要)

3️⃣ Standard Edition の容量拡張と Resource Governor 対応

  • 単一インスタンスの最大計算能力が 4 ソケットまたは 32 コアのいずれか小さい方まで拡張
  • インスタンスあたりのバッファプール最大メモリが 256 GB に拡張
  • Enterprise 限定だった Resource Governor が SE / Dev-SE でも同等機能で利用可能に

4️⃣ 新しい無償の Standard Developer Edition (Dev-SE)

  • 開発向けにライセンスされた無償エディションで、Standard Edition の全機能を含む
  • 新規アプリ開発や、本番デプロイ前のアップグレード検証ステージング環境の構築に活用

外部 REST エンドポイント呼び出しの例

SQLsp_invoke_external_rest_endpoint
-- 外部 REST エンドポイント呼び出しの例
DECLARE @response NVARCHAR(MAX);
EXEC sp_invoke_external_rest_endpoint
    @url = N'https://bedrock-runtime.us-east-1.amazonaws.com/model/...',
    @method = 'POST',
    @payload = N'{ "inputText": "..." }',
    @response = @response OUTPUT;
SELECT @response;

📝 設定方法

前提条件

✓Amazon RDS for SQL Server を利用可能な AWS アカウントと、対象リージョンでの権限
✓アップグレード対象の既存 DB インスタンス、または新規作成用のパラメータグループとセキュリティグループ
✓REST 呼び出し利用時は、対象サービス (Bedrock / Lambda など) へのネットワーク到達性と適切な IAM 権限

ステップ 1: エンジンバージョンの確認

Bashdescribe-db-engine-versions
aws rds describe-db-engine-versions \
    --engine sqlserver-se \
    --query "DBEngineVersions[?contains(EngineVersion, '17.')].EngineVersion"

SQL Server 2025 (メジャーバージョン 17.x) のエンジンバージョンを確認します。エディションに応じて sqlserver-ee (Enterprise)、sqlserver-se (Standard) などを指定します。

ステップ 2: 既存インスタンスのアップグレード

Bashmodify-db-instance
aws rds modify-db-instance \
    --db-instance-identifier my-sqlserver-instance \
    --engine-version <SQL-Server-2025-version> \
    --allow-major-version-upgrade \
    --apply-immediately

メジャーバージョンアップグレードのため --allow-major-version-upgrade を指定します。本番環境では事前のスナップショット取得とステージング環境での検証を推奨します。

ステップ 3: 検証環境での事前検証

無償の Standard Developer Edition を活用し、本番アップグレード前にアプリケーションの互換性を検証します。SQL Server 2025 には linked servers、レプリケーション、ログ配布、PolyBase などに関する破壊的変更が含まれるため、事前検証が重要です。

🎯 メリット

ビジネス面

✓アーキテクチャの簡素化: AI 連携のための追加ミドルウェアが不要となり、開発・運用コストを削減
✓ライセンスコストの最適化: Standard Edition で 32 コア・256 GB・Resource Governor が利用可能になり、Enterprise を選ばずに済むケースが増える
✓開発コストの削減: 無償の Standard Developer Edition により、ライセンス費用なしで開発・テスト環境を構築

技術面

✓データ近接での AI 処理: データを移動させずに DB 内でベクトル検索や埋め込み生成を実行
✓マネージド運用: 自動バックアップ、パッチ適用、Multi-AZ など RDS のマネージド機能をそのまま活用
✓既存資産の活用: アプリを再設計せずに、T-SQL から AWS サービスへ統合

⚠️ デメリット・制約事項

制限事項

!一部のベクトル機能 (VECTOR_SEARCH、CREATE VECTOR INDEX など) はデータベーススコープ構成 PREVIEW_FEATURES の有効化が必要
!SQL Server 2025 では Web Edition が廃止され、linked servers、レプリケーション、ログ配布、PolyBase などに破壊的変更が含まれる
!Data Quality Services (DQS)、Master Data Services (MDS)、Synapse Link は本バージョンで廃止

考慮すべき点

!メジャーバージョンアップグレードのため、本番適用前に必ずステージング環境で互換性を検証する
!外部 REST 呼び出しには、対象 AWS サービスへのネットワーク経路と IAM 権限の適切な設計が必要
!RDS では オンプレミス版の全機能がサポートされるとは限らないため、利用予定機能の対応状況を確認

💡 ユースケース

ユースケース 1: AI を活用したクエリアドバイザー

シナリオ: データベース管理者が、スロークエリの改善提案を自動で得たい。

SQL
-- 実行計画やクエリ統計を Amazon Bedrock に送信し、改善案を取得
EXEC sp_invoke_external_rest_endpoint
    @url = N'https://bedrock-runtime.<region>.amazonaws.com/model/...',
    @method = 'POST',
    @payload = @query_plan_json,
    @response = @advice OUTPUT;

効果: 追加基盤なしに、データベース内から直接生成 AI による分析・提案を受け取れる。

ユースケース 2: ベクトル検索によるセマンティック検索

シナリオ: 製品ドキュメントの類似検索を、専用ベクトルデータベースを用意せずに実現したい。

SQL
-- テキストから埋め込みを生成してベクトル列に格納
UPDATE docs
SET embedding = AI_GENERATE_EMBEDDINGS(content USE MODEL MyEmbeddingModel);

-- 類似ベクトルを検索
SELECT TOP 5 id, content
FROM docs
ORDER BY VECTOR_DISTANCE('cosine', embedding, @query_vector);

効果: 既存の SQL Server 内で埋め込み格納から類似検索まで完結し、データ移動と運用の複雑さを低減。

ユースケース 3: イベント駆動型ワークフロー

シナリオ: 特定のデータ更新をトリガーに、後続処理を AWS Lambda で実行したい。

SQL
-- トリガー内から Lambda を呼び出す
EXEC sp_invoke_external_rest_endpoint
    @url = N'https://lambda.<region>.amazonaws.com/2015-03-31/functions/my-func/invocations',
    @method = 'POST',
    @payload = @event_json;

効果: データベースの変更を起点に、サーバーレスでイベント駆動処理を組み立てられる。

💰 料金 & 利用可能リージョン

料金: Amazon RDS for SQL Server の料金は、選択したエディション (Enterprise / Standard / Developer)、インスタンスクラス、ストレージ、Multi-AZ 構成などに基づきます。Standard Developer Edition はライセンス費用が発生しない無償エディションですが、RDS 上のインスタンス・ストレージ利用料は通常どおり発生します。最新のリージョン別料金は公式の料金ページを参照してください。
リージョン: 対象リージョンの詳細は、Amazon RDS for SQL Server の料金ページおよびドキュメントで最新情報を確認してください。

✅ まとめ

Amazon RDS for SQL Server での SQL Server 2025 サポートにより、データベースエンジンから直接 AWS の AI サービスと連携でき、 ネイティブなベクトルデータ型で生成 AI ワークロードを DB 内に統合できるようになりました。 Standard Edition の容量拡張と Resource Governor 対応、無償の Standard Developer Edition により、コスト面でも柔軟な選択肢が広がります。 まずは無償の Developer Edition や検証環境で破壊的変更と互換性を確認したうえで、DB エンジンバージョンの変更によるアップグレードを計画することを推奨します。
