AWS Elemental MediaConnect

📡 RTMP 対応とルーティング制御の拡張

📅 リリース日: 2026 年 11 月 17 日
RTMP / RTMPS / eRTMP プロトコル対応、PID リマッピング、クリーンスイッチ、SRT マージ入力モード

💡 概要

AWS Elemental MediaConnect が、ライブ映像ワークフロー向けにプロトコル対応とルーティング制御を大幅に拡張しました。 フローとルーターの両方で RTMP / RTMPS / eRTMP がサポートされ、 ルーター向けに 3 つの新しいルーティング機能 (PID リマッピング、クリーンスイッチ、SRT マージ入力モード) が追加されました。

RTMP は OBS をはじめとするライブストリーミングエンコーダーで広く使用されているプロトコルです。 RTMP ソースを MediaConnect に直接取り込み、ソーシャルメディアやライブ配信プラットフォームなどの RTMP エンドポイントへ配信できるようになり、 コントリビューションから配信までのワークフローを MediaConnect に統合しやすくなりました。

❌ アップデート前の課題

✗RTMP / RTMPS / eRTMP 非対応で、OBS などとの連携には別途プロトコル変換の仕組みが必要
✗PID の変更にはトランスコード処理が必要で、遅延とコストが増加
✗ルーター入力の切り替えが映像の境界に揃わず、切り替え時に映像の乱れが発生する可能性
✗損失の多い経路では、フェイルオーバー方式の SRT 冗長化に映像品質維持の限界

✅ アップデート後の改善

✓RTMP / RTMPS / eRTMP ソースを直接取り込み、RTMP エンドポイントへ配信可能
✓PID リマッピングでトランスコードなしに PID をインラインで再割り当て
✓クリーンスイッチで入力切り替えが映像の境界に揃い、シームレスな切り替えを実現
✓SRT マージ入力で冗長ストリームをボンディングし、経路劣化時もクリーンなフィードを再構築

🚀 主要機能

📡 RTMP / RTMPS / eRTMP プロトコル対応

  • フローとルーターの両方でサポート
  • OBS などの RTMP エンコーダーからソースを直接取り込み可能
  • ソーシャルメディアなどの RTMP エンドポイントへの配信に対応
  • API では rtmp-push プロトコルがフロー、ブリッジの入出力に追加

🔢 PID リマッピング

  • MediaConnect Router 上でトランスポートストリームの PID をインラインで再割り当て
  • トランスコード不要で、遅延や追加の処理コストを抑えつつ下流システムの PID 要件に適合
  • SingleProgramTransportStreamPidMap 設定でルールベース (MatchExpression) または自動 (Auto) の割り当てに対応

🎬 クリーンスイッチ

  • ルーター入力の切り替えを映像の境界 (キーフレーム) に揃え、シームレスな切り替えを実現
  • API では KeyFrame 切り替えモードと KeyFrameWaitMilliseconds パラメータが追加

🧩 SRT マージ入力モード

  • 同一コンテンツの冗長な SRT ストリームをボンディングし、経路劣化時にクリーンなフィードを再構築
  • 損失の多い経路や長距離伝送での耐障害性を向上
  • 従来の FAILOVER に加えて MERGE モードが追加、MergeRecoveryWindowMilliseconds で回復ウィンドウを設定可能

⚙️ 設定方法

前提条件

✓AWS アカウントと MediaConnect への適切な IAM 権限があること
✓MediaConnect Router の機能を使用する場合は、MediaConnect Router が利用可能なリージョンであること
✓RTMP ソースを使用する場合は、OBS などの RTMP 対応エンコーダーが用意されていること

ステップ 1: RTMP ソースを持つフローの作成

Bash AWS CLI - フロー作成 
aws mediaconnect create-flow \
  --name "rtmp-ingest-flow" \
  --availability-zone "ap-northeast-1a" \
  --source "Name=rtmp-source,Protocol=rtmp-push,IngestPort=1935"

RTMP Push プロトコルでソースを受け付けるフローを作成します。エンコーダーからは、作成されたフローのインジェストエンドポイントに対して RTMP で映像を送信します。

ステップ 2: RTMP エンドポイントへの出力の追加

Bash AWS CLI - 出力追加 
aws mediaconnect add-flow-outputs \
  --flow-arn "arn:aws:mediaconnect:ap-northeast-1:123456789012:flow:example:rtmp-ingest-flow" \
  --outputs "Name=rtmp-output,Protocol=rtmp-push,Destination=rtmp.example.com,Port=1935"

フローに RTMP 出力を追加し、ソーシャル配信プラットフォームなどの RTMP エンドポイントへ映像を配信します。

ステップ 3: ルーターでのクリーンスイッチと PID リマッピングの設定

MediaConnect Router の入力・出力設定で、キーフレームに揃えた切り替え (クリーンスイッチ) や、SingleProgramTransportStreamPidMap による PID の再割り当てを設定します。 詳細は MediaConnect Router のドキュメントを参照してください。

✨ メリット

💼 ビジネス面

  • 配信先の拡大: RTMP ベースの配信先へ MediaConnect から直接配信できる
  • コスト削減: PID 変更のためだけのトランスコード処理が不要になり、追加のエンコードコストを削減
  • ワークフローの統合: RTMP 変換用の中間サーバーが不要になり、コントリビューションから配信までを MediaConnect に集約

🛠️ 技術面

  • プロトコルの柔軟性: RTMP、RTMPS、eRTMP がフローとルーターの両方で利用でき、既存の SRT、Zixi、RIST などと組み合わせ可能
  • 高品質な切り替え: クリーンスイッチにより視聴者に違和感のない映像切り替えを実現
  • 伝送の耐障害性向上: SRT マージ入力モードにより、冗長経路の一方が劣化してもクリーンなフィードを維持

⚠️ デメリット・制約事項

制限事項

⚠新しいルーティング機能 (PID リマッピング、クリーンスイッチ、SRT マージ入力) は MediaConnect Router が利用可能なリージョンでの提供
⚠SRT マージ入力モードは、同一コンテンツの冗長な SRT ストリームが前提

考慮すべき点

⚠RTMP は比較的レイテンシーが大きいプロトコルであり、超低遅延が求められるワークフローでは SRT などの他プロトコルとの使い分けを検討
⚠マージモードの回復ウィンドウ (MergeRecoveryWindowMilliseconds) は、経路の遅延差を考慮して適切に設定する必要がある

🔗 関連サービス・機能

  • AWS Elemental MediaLive: MediaConnect で取り込んだフィードのトランスコードやチャンネル制作に利用できる
  • AWS Elemental MediaPackage: ライブストリームのパッケージングとオリジン配信に利用でき、MediaConnect と組み合わせたエンドツーエンドのライブ配信が可能
  • Amazon CloudFront: パッケージングされたストリームの視聴者向け配信に利用できる

📝 まとめ

AWS Elemental MediaConnect の RTMP / RTMPS / eRTMP 対応により、OBS などの一般的なエンコーダーからソーシャル配信プラットフォームまで、 RTMP ベースのワークフローを MediaConnect に統合できるようになりました。 あわせて追加された PID リマッピング、クリーンスイッチ、SRT マージ入力モードは、 放送品質のライブ伝送に求められる柔軟性と耐障害性を大きく高めます。 ライブ映像ワークフローを運用しているチームは、既存の中間変換サーバーや冗長化構成を MediaConnect の新機能で置き換えられないか検討することをお勧めします。
