S3 が完全なファイルシステムアクセスを提供する初のクラウドオブジェクトストア
2026 年 4 月 7 日
一般提供 (GA)
Amazon S3 Files が一般提供 (GA) 開始。S3 バケットをファイルシステムとしてアクセス可能にする新機能であり、AWS のあらゆるコンピューティングリソースから S3 上のデータに対してファイルシステムインターフェースで直接アクセスできるようになった。Amazon EFS の技術を基盤として構築されており、データは S3 から移動することなく利用できる。

🔄 Before / After

❌ Before - アップデート前の課題
  • S3 のデータにファイルシステムとしてアクセスするには、EFS や FSx にデータをコピーする必要があった
  • オブジェクトストレージとファイルストレージ間のデータ同期にコストと運用負荷が発生
  • ファイルシステムセマンティクス (ディレクトリリスト、ファイルロック、追記書き込みなど) が必要なアプリでは S3 を直接利用できなかった
✅ After - アップデート後の改善
  • S3 バケット上のデータに NFS プロトコルなどのファイルシステムインターフェースで直接アクセス可能
  • データを S3 から移動させることなく、完全なファイルシステムセマンティクスと低レイテンシを実現
  • オブジェクトストレージとファイルストレージの統合により、データコピーや同期の運用負荷を削減

🏗️ アーキテクチャ図

⚡ 主要機能

📂 ファイルシステムセマンティクスの完全サポート
  • ディレクトリのリスト表示、ファイルのロック、追記書き込みなどの標準的なファイルシステム操作をサポート
  • POSIX 互換のファイルシステムインターフェースを提供
  • 既存のファイルベースのアプリケーションをそのまま利用可能
🚀 低レイテンシパフォーマンス
  • Amazon EFS の技術基盤を活用した高性能なファイルアクセス
  • データは S3 から移動することなく、ファイルシステム経由で低レイテンシでアクセス可能
  • コンピューティングリソースからの直接接続による効率的なデータアクセス
🔗 S3 との統合
  • S3 バケット内のデータに対して、オブジェクト API とファイルシステムインターフェースの両方からアクセス可能
  • S3 のストレージクラス、ライフサイクルポリシー、暗号化などの機能を引き続き利用可能
  • データの二重管理が不要

🛠️ 設定方法

前提条件

1. AWS アカウントと適切な IAM 権限
2. S3 バケット
3. VPC 内のコンピューティングリソース (EC2、ECS、EKS など)

ステップ 1: S3 バケットの準備

既存の S3 バケットを使用するか、新しいバケットを作成する。

Bash S3 バケット作成と S3 Files 有効化 
# AWS CLI を使用して S3 Files を有効化する例
aws s3api create-bucket --bucket my-s3-files-bucket --region us-east-1

ステップ 2: S3 Files の有効化

AWS マネジメントコンソールの S3 セクションから、対象バケットに対して S3 Files を有効化する。有効化後、ファイルシステムエンドポイントが提供される。

ステップ 3: コンピューティングリソースからのマウント

Bash EC2 インスタンスからファイルシステムをマウント 
# EC2 インスタンスからファイルシステムをマウント
sudo mount -t nfs4 -o nfsvers=4.1 \
  <s3-files-endpoint>:/ /mnt/s3data

上記コマンドにより、S3 バケット内のデータをローカルファイルシステムとして利用できるようになる。

⚖️ メリット / デメリット

✅ メリット

ビジネス面

  • コスト削減: データコピーが不要になり、ストレージコストと転送コストを削減
  • 運用効率の向上: データ同期・コピーの運用作業が不要、運用チームの負荷を軽減
  • アプリケーション移行の加速: ファイルシステム依存の既存アプリを修正なしで S3 上のデータにアクセスさせることが可能

技術面

  • 統合データアクセス: オブジェクト API とファイルシステムの両方からアクセス可能
  • S3 の耐久性: イレブンナイン (99.999999999%) の耐久性を維持
  • スケーラビリティ: S3 の事実上無制限のスケーラビリティをファイルシステムワークロードでも活用
⚠️ デメリット・制約事項

制限事項

  • 全てのファイルシステム操作で S3 ネイティブ API と同等のパフォーマンスが得られるとは限らない
  • ファイルシステムアクセス分の追加コストが発生する可能性
  • オンプレミスからの直接マウントには VPN や Direct Connect が必要

考慮すべき点

  • 大量の小さなファイルを扱うワークロードでは、S3 API 直接利用の方が効率的な場合がある
  • 既存の EFS や FSx for Lustre からの移行にはテストと検証が推奨される

💡 ユースケース

🤖 ユースケース 1: AI/ML トレーニングデータの管理
大規模な AI/ML モデルのトレーニングに使用するデータセットが S3 に保存されている。従来はトレーニング前に EFS にデータをコピーする必要があった。
Bash S3 Files で直接トレーニングデータにアクセス 
# S3 Files をマウントして直接トレーニングデータにアクセス
sudo mount -t nfs4 -o nfsvers=4.1 \
  <s3-files-endpoint>:/training-data /mnt/training-data

# トレーニングスクリプトはローカルファイルとしてアクセス
python train.py --data-dir /mnt/training-data
✅ データコピーの時間とコストを削減し、トレーニング開始までの時間を短縮
📦 ユースケース 2: コンテナワークロードでの共有ストレージ
ECS や EKS 上で動作する複数のコンテナが共有ファイルシステムを必要としている。
YAML ECS タスク定義での S3 Files ボリューム設定例 
volumes:
  - name: shared-data
    s3Files:
      fileSystemId: fs-12345678
      rootDirectory: /shared
✅ コンテナ間でのデータ共有をシンプルに実現しつつ、S3 の耐久性とコスト効率を享受
🏢 ユースケース 3: レガシーアプリケーションのクラウド移行
オンプレミスで NFS ファイルサーバーを使用しているアプリケーションを AWS に移行する。
Bash NFS から S3 Files への移行 
# アプリケーションの設定ファイルでマウントポイントを変更
# Before: /mnt/nfs-server/data
# After: /mnt/s3files/data
sudo mount -t nfs4 -o nfsvers=4.1 \
  <s3-files-endpoint>:/data /mnt/s3files/data
✅ アプリケーションコードを変更することなく、NFS から S3 Files への移行が可能。S3 のスケーラビリティとコスト効率を活用

💰 料金情報

S3 Files の料金は、S3 ストレージの料金に加えて、ファイルシステムアクセスに関する追加料金が発生する。

項目説明
S3 ストレージ料金通常の S3 ストレージ料金が適用される
S3 Files アクセス料金ファイルシステムアクセスに対する追加課金
データ転送料金リージョン間転送やインターネットへの転送に対する課金

詳細な料金体系は AWS 公式料金ページ を参照のこと。

🌍 利用可能リージョン

S3 Files は 34 の AWS リージョンで一般提供されている。主要なリージョンを含む幅広いグローバル展開により、世界中のワークロードで利用可能。

🔗 関連サービス

📁
Amazon EFS
S3 Files の基盤技術として使用されているフルマネージドファイルシステムサービス。スタンドアロンのファイルストレージが必要な場合に利用。
⚡
Amazon FSx for Lustre
HPC や機械学習ワークロード向けのファイルシステム。S3 との統合機能を持つが、S3 Files はより直接的なアクセスを提供。
🔄
AWS DataSync
オンプレミスと AWS 間、または AWS サービス間でのデータ転送サービス。S3 Files により一部のデータ転送ユースケースが不要になる可能性がある。

📝 まとめ

Amazon S3 Files は、クラウドストレージにおけるオブジェクトストレージとファイルストレージの統合という長年の課題を解決する画期的なアップデートである。データを S3 に保持したまま完全なファイルシステムアクセスを提供することで、データコピーの削減、運用効率の向上、コスト最適化を実現する。

AI/ML ワークロード、コンテナベースのアプリケーション、レガシーアプリケーションの移行など、ファイルシステムアクセスを必要とするワークロードを持つユーザーは、早期の評価と検証を推奨する。
