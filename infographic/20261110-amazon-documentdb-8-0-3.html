Amazon DocumentDB (with MongoDB compatibility)

🗄️ Amazon DocumentDB 8.0.3

ポスト量子 TLS、ワイルドカードインデックス、$unionWith をサポート
📅 リリース日: 2026 年 11 月 10 日

📝 概要

Amazon DocumentDB 8.0.3 がリリースされ、TLS 1.3 接続における ハイブリッドポスト量子鍵交換 (ML-KEM)、ワイルドカードインデックス、$unionWith 集計ステージ、新しい変更ストリームイベントのサポートが追加された。

ポスト量子 TLS は「今記録しておいて、将来量子コンピュータで復号する」という Harvest Now, Decrypt Later 型の脅威から転送中のデータを保護する。ML-KEM 対応クライアントは自動的にポスト量子鍵交換を使用し、それ以外は従来の鍵交換を継続するため、アプリケーションの互換性を損なわない。MongoDB API 対応の拡大により、コード変更なしで移行できるワークロードも増加した。

❌ アップデート前の課題

✗TLS 接続は従来の鍵交換のみで、将来の量子コンピュータによる復号リスクへの備えがなかった
✗動的スキーマではフィールドごとに個別インデックスが必要で、未知のフィールドへのクエリを効率化できなかった
✗$unionWith が未サポートで、アプリケーション側でのマージ処理や移行時のコード変更が必要だった
✗インデックス削除が変更ストリームのイベントとして通知されなかった

✅ アップデート後の改善

✓TLS 1.3 で ML-KEM ベースのハイブリッドポスト量子鍵交換が利用可能になり、長期的な機密性を確保
✓新メトリクス TLSHandshakesClassical / TLSHandshakesPostQuantum で鍵交換方式ごとに可視化
✓ワイルドカードインデックスで動的スキーマのドキュメントを効率的にクエリ
✓$unionWith で単一パイプライン内の複数コレクション統合、ビューで $lookup / $graphLookup が利用可能
✓インデックス削除が dropIndexes イベントとして変更ストリームに通知

ポスト量子 TLS の動作概要。ML-KEM をサポートするクライアントは自動的にハイブリッドポスト量子鍵交換を使用し、それ以外のクライアントは従来の鍵交換で接続を継続する。ハンドシェイク数は方式ごとに CloudWatch メトリクスで追跡できる。

🚀 主要機能

🔐 1. ポスト量子 TLS (ハイブリッドポスト量子鍵交換)
  • TLS 1.3 接続で ML-KEM (Module-Lattice-Based Key-Encapsulation Mechanism) に基づくハイブリッド鍵交換を使用
  • ML-KEM 対応クライアントは自動的にポスト量子鍵交換を使用、その他は従来の鍵交換を継続
  • Harvest Now, Decrypt Later 型の脅威から転送中のデータを保護
  • 成功ハンドシェイク数を TLSHandshakesClassical / TLSHandshakesPostQuantum の 2 つの CloudWatch メトリクスで追跡可能
🃏 2. ワイルドカードインデックス
  • すべてのフィールド、または特定パス配下のすべてのフィールドをまとめてインデックス化
  • フィールド構成が事前に決まっていない動的スキーマのドキュメントに対するクエリを効率化
🔗 3. 集計機能の強化
  • $unionWith 集計ステージにより、単一パイプライン内で複数コレクションの結果を統合可能
  • createView で作成したビュー内で $lookup と $graphLookup が利用可能
  • 相関 $lookup のサブパイプラインで $unionWith と $facet を使用可能
  • $facet 集計ステージの機能強化
🌊 4. 変更ストリームの拡張
  • dropIndex() / dropIndexes() によるインデックス削除の成功が dropIndexes イベントとして通知されるように変更
📦 5. コレクション単位の圧縮メトリクス
  • collStats / stats() の出力に圧縮メトリクス (input_bytes、output_bytes、compression_operations、compression_ratio) を追加
🐛 6. バグ修正
  • findAndModify が返す retryable write エラーラベルを修正
  • disjoint インデックススキャン使用時のソートに関する問題を修正

ステップ 1: エンジンバージョンの確認

JavaScriptmongo シェル
db.runCommand({getEngineVersion: 1})

8.0.3 のクラスターは 8.0.3+4.0.13572 のような形式でバージョンを返す。保留中のメンテナンスがある場合は、メンテナンスウィンドウまたは手動適用でパッチを適用する。

ステップ 2: ワイルドカードインデックスの作成

JavaScriptワイルドカードインデックス
// すべてのフィールドをインデックス化
db.products.createIndex({ "$**": 1 })

// 特定パス配下のフィールドのみインデックス化
db.products.createIndex({ "attributes.$**": 1 })

ステップ 3: $unionWith による複数コレクションの統合

JavaScript$unionWith 集計ステージ
db.orders.aggregate([
  { $match: { status: "completed" } },
  { $unionWith: {
      coll: "archivedOrders",
      pipeline: [ { $match: { status: "completed" } } ]
  } }
])

💡 メリット

💼 ビジネス面

✓長期的なデータ保護: Harvest Now, Decrypt Later 型の脅威に備え、金融・医療・公共分野などで量子コンピュータ時代を見据えたセキュリティ対策を先行して実施できる
✓移行コストの削減: MongoDB API 対応拡大により、アプリケーションコードを変更せずに MongoDB ワークロードを移行できる
✓追加コスト不要: ポスト量子 TLS は対応クライアントで自動的に有効化され、追加の設定や料金なしで利用できる

🔧 技術面

✓互換性を維持した段階的移行: ML-KEM 非対応クライアントは従来の鍵交換で接続を継続でき、クライアント更新を段階的に進められる
✓可観測性の向上: 鍵交換方式ごとの CloudWatch メトリクスで、ポスト量子対応クライアントへの移行状況を定量的に追跡できる
✓動的スキーマへの対応: ワイルドカードインデックスにより、フィールド構成が頻繁に変化するドキュメントでもインデックス設計の負担を軽減できる
✓ストレージ効率の可視化: コレクション単位の圧縮メトリクスで圧縮効果を詳細に把握し、ストレージコストの分析に活用できる

⚠️ デメリット・制約事項

制限事項

✗ポスト量子鍵交換は TLS 1.3 接続かつ ML-KEM をサポートするクライアントでのみ使用される
✗バージョン 8.0.3 (エンジンバージョン 4.0.13572) 以降が必要で、既存クラスターはパッチ適用が必要
✗変更ストリームの dropIndexes イベントなど、挙動の変更に依存する処理はアプリケーション側での確認が必要

考慮すべき点

!クライアントドライバーや TLS ライブラリの ML-KEM サポート確認が必要 (TLSHandshakesPostQuantum メトリクスで実際の利用状況を検証可能)
!ワイルドカードインデックスは書き込みオーバーヘッドやインデックスサイズへの影響を考慮し、対象パスを絞る設計が推奨される
!パッチ適用のタイミングはメンテナンスウィンドウの設定に依存するため、適用計画の確認を推奨

🛒 ユースケース 2: 動的スキーマを持つ商品カタログの検索

シナリオ: EC サイトの商品カタログで、商品カテゴリごとに属性フィールドが異なり、事前にすべてのフィールドへ個別インデックスを作成することが困難。

JavaScript商品カタログの実装例
// 商品属性配下をまとめてインデックス化
db.products.createIndex({ "attributes.$**": 1 })

// 任意の属性でクエリ
db.products.find({ "attributes.color": "red" })
db.products.find({ "attributes.screenSize": { $gte: 15 } })

効果: 新しい属性フィールドが追加されてもインデックスの再設計が不要になり、動的スキーマに対するクエリ性能を維持できる。

📈 ユースケース 3: アクティブデータとアーカイブデータの横断集計

シナリオ: 直近の注文を保持するコレクションと、過去の注文をアーカイブしたコレクションに対し、期間をまたいだレポートを 1 回のクエリで生成したい。

JavaScript横断レポートの実装例
db.orders.aggregate([
  { $match: { orderDate: { $gte: ISODate("2026-01-01") } } },
  { $unionWith: {
      coll: "archivedOrders",
      pipeline: [ { $match: { orderDate: { $gte: ISODate("2026-01-01") } } } ]
  } },
  { $group: { _id: "$category", total: { $sum: "$amount" } } }
])

効果: アプリケーション側でのデータマージ処理が不要になり、複数コレクションにまたがるレポート生成をデータベース側の単一パイプラインで完結できる。

📋 まとめ

Amazon DocumentDB 8.0.3 は、ML-KEM によるポスト量子 TLS という将来を見据えたセキュリティ強化と、ワイルドカードインデックスや $unionWith などの MongoDB API 対応拡大を同時に提供するアップデートである。機密性の高いデータを長期間扱うワークロードでは、クライアントの ML-KEM 対応状況を確認した上で 8.0.3 への更新とメトリクスによる移行状況の監視を開始することを推奨する。MongoDB からの移行を検討しているワークロードにとっても、互換性の向上により移行の選択肢が広がった。
