🔍 Web Search on Amazon Bedrock
多言語サポート拡大と国別検索対応

日本語を含む 5 言語の新規サポートと、国コード指定による country-aware search が利用可能に

📋 概要

Web Search on Amazon Bedrock は、AI エージェントやアプリケーションに引用付きの最新 Web 情報を提供するビルトインツールです。今回のアップデートで、英語 (米国以外の英語を含む) に加えて スペイン語、フランス語、ドイツ語、イタリア語、日本語の 5 言語が新たにサポートされました。あわせて、ISO 3166-1 alpha-2 形式の国コード (例: JP、DE) を渡して検索結果を特定の国のソースに寄せる国別検索 country-aware search が追加されました。

✗検索結果を特定の国に寄せる仕組みがなく、地域の規制や価格など所在国に依存する質問への回答精度に課題

✓5 言語と米国以外の英語に対応し、各言語のユーザーにローカル言語ソースに基づく検索結果を提供
✓国指定フィールドに ISO 3166-1 alpha-2 コードを渡すことで、特定の国のソースを優先した検索が可能
✓既存のコードを変更せずに新しい言語機能が自動的に有効化され、移行作業が不要
💰 料金はすべての言語で同一。既存のお客様はコード変更なし・追加料金なしで新機能を利用できます。

🔧 技術仕様

📍 user_location パラメータ

Web Search ツールに位置情報を共有するためのオプションパラメータ。未設定または空の場合、位置は米国がデフォルトになります。

フィールド詳細
countryISO 3166-1 alpha-2 の割り当て済みコード。大文字小文字は区別されない (de も DE として受理)。UK や XK など未割り当て・ユーザー割り当てコードは拒否される
region自由形式の文字列として受理
city自由形式の文字列として受理
timezoneIANA タイムゾーン識別子として受理

🔌 Web Search ツールの主なパラメータ

項目詳細
ツールタイプweb_search (Responses API の tools 配列に追加)
エンドポイントbedrock-mantle (サーバーサイドツールのため bedrock-runtime では利用不可)
search_context_sizelow (最大 5 件) / medium (最大 11 件、デフォルト) / high (最大 25 件)
external_web_accesstrue (デフォルト) / false。false に設定すると検索・取得が AWS 境界内で完結
filtersallowed_domains / blocked_domains を各最大 100 件指定可能
IAM アクションbedrock-websearch:InvokeSearch、bedrock-websearch:InvokeFetch、bedrock-websearch:ExternalWebAccess

🛠️ 設定方法

✅ 前提条件

✓Amazon Bedrock API キーを取得し、bedrock-mantle エンドポイントを利用できること
✓IAM アイデンティティに bedrock-websearch:InvokeSearch および bedrock-websearch:InvokeFetch の権限があること (AmazonBedrockFullAccess ポリシーで付与可能)
✓Web Search がサポートされるモデル (米国の商用リージョンでは OpenAI GPT-5.4 以降) を使用すること

ステップ 1: 環境変数の設定

BashAPI キーとエンドポイントの設定
export OPENAI_API_KEY="your-amazon-bedrock-api-key"
export OPENAI_BASE_URL="https://bedrock-mantle.us-west-2.api.aws/openai/v1"

Amazon Bedrock の API キーと bedrock-mantle エンドポイントの URL を環境変数に設定します。OpenAI SDK がこれらの値を参照してリクエストを送信します。

ステップ 2: 国コードを指定して Web Search を呼び出す

Python国コード JP を指定した Web Search 呼び出し
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="openai.gpt-5.6-terra",
    input="最新の電気料金の規制動向を教えてください。",
    tools=[{
        "type": "web_search",
        "external_web_access": False,
        "user_location": {
            "type": "approximate",
            "country": "JP",
        },
    }],
)

print(response.output_text)

tools 配列に web_search ツールを追加し、user_location の country フィールドに ISO 3166-1 alpha-2 コード (この例では日本を示す JP) を指定しています。external_web_access を false に設定することで、検索・取得を AWS 境界内に保っています。

ステップ 3: 引用情報の確認

Pythonurl_citation アノテーションから出典を取得
for item in response.output:
    if item.type == "message":
        for block in item.content:
            if block.type == "output_text":
                for ann in block.annotations:
                    if ann.type == "url_citation":
                        print(f"- {ann.title}: {ann.url}")

レスポンスの url_citation アノテーションから、回答の根拠となった情報源のタイトルと URL を取得します。エンドユーザーに回答を表示する際は、これらの引用と出典リンクを保持して表示する必要があります。

💼 ビジネス面のメリット

✓グローバル展開の加速: 多言語ユーザーにローカル言語ソースに基づく高品質な回答を提供し、対象市場を拡大
✓回答の地域適合性向上: 地域の規制、価格、公的機関など所在国に依存する質問に適切な国のソースで回答

🔬 技術面のメリット

✓シンプルな国指定: 国コードを 1 つ渡すだけで検索結果の国別バイアスを制御
✓データレジデンシー対応: クエリは呼び出し元リージョン内で処理
✓引用付きのグラウンディング: 多言語の検索結果でも出典への引用が付与され、信頼性の検証が容易

🚧 制限事項

✗Amazon Bedrock 側の Web Search は米国リージョンでの提供で、利用可能リージョンが限られる
✗サーバーサイドツールのため bedrock-runtime エンドポイントでは利用不可。bedrock-mantle が必要
✗country には割り当て済みコードのみ指定可能。UK や XK などは拒否される

⚠️ 考慮すべき点

⚠user_location 未設定時のデフォルトは米国。日本のユーザー向けでは明示的に country: "JP" を指定することが望ましい
⚠external_web_access はデフォルト true。機密データを扱う場合は明示的に false を設定することを推奨
⚠位置情報がどの程度結果に反映されるかは、モデルと検索サービスの組み合わせに依存

💡 ユースケース

🇯🇵 ユースケース 1: 日本語ユーザー向けカスタマーサポートエージェント

シナリオ: 日本のエンドユーザー向けに、製品の最新情報や国内の制度・規制について日本語で回答するサポートエージェントを構築する。

Python
tools=[{
    "type": "web_search",
    "external_web_access": False,
    "user_location": {"type": "approximate", "country": "JP"},
}]

効果: 日本語の情報源と日本国内のソースを優先した検索結果に基づき、国内の制度や価格に即した引用付きの回答を提供できる。

🇪🇺 ユースケース 2: 複数国対応のマルチリンガルエージェント

シナリオ: 欧州の複数国 (ドイツ、フランス、イタリア、スペイン) でサービスを展開しており、ユーザーの所在国に応じて適切な国のソースから回答したい。

Python
# ユーザープロファイルの所在国に応じて country を動的に設定
country_code = user_profile.country  # 例: "DE", "FR", "IT", "ES"
tools=[{
    "type": "web_search",
    "external_web_access": False,
    "user_location": {"type": "approximate", "country": country_code},
}]

効果: 1 つのエージェント実装で各国のユーザーにそれぞれの国・言語のソースを優先した回答を提供でき、国ごとの個別実装が不要になる。

🏛️ ユースケース 3: 所在国に依存する質問への正確な回答

シナリオ: 地域の規制、現地価格、公的機関の情報など、回答がユーザーの所在国によって異なる質問を扱う情報提供アプリケーションを運用している。

Python
response = client.responses.create(
    model="openai.gpt-5.6-terra",
    input="現在の消費税率と直近の改定予定を教えてください。",
    tools=[{
        "type": "web_search",
        "external_web_access": False,
        "user_location": {"type": "approximate", "country": "JP"},
    }],
)

効果: 国コードの指定により、質問内容が同じでもユーザーの所在国に応じた正確な情報を返せるようになり、誤った国の情報を提示するリスクを低減できる。
