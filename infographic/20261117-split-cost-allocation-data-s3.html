💰 Split Cost Allocation Data が Amazon S3 に対応

共有 S3 バケットのコストを プレフィックス単位 で CUR に配分 — チャージバック / ショーバックをマネージドに実現
📅 リリース日: 2026 年 11 月 17 日

📝 概要

AWS Split Cost Allocation Data が Amazon S3 に対応しました。共有された S3 汎用バケットの ストレージコスト と Tier 1 / Tier 2 リクエストコスト を、バケット内のプレフィックス単位で AWS Cost and Usage Report (CUR) に配分できます。

marketing/ や finance/ のようにプレフィックスで複数チーム / テナントのデータを 1 つのバケットに格納している組織向けに、S3 Storage Lens がプレフィックスレベルのメトリクスを Billing and Cost Management に発行し、最も深く一致するプレフィックスへコストを自動配分します。各明細行には AWS 生成コスト配分タグが付与され、チームやアプリケーション単位の集計とバケット全体の請求額との照合が可能です。

❌ Before: アップデート前の課題

✗CUR ではバケット単位のコストしか確認できず、プレフィックス単位の配分は不可能
✗S3 Inventory や Storage Lens レポートを基にしたカスタムパイプラインの構築が必要
✗料金計算ロジックを自前で実装・保守する必要があり、正確なチャージバックが困難

✅ After: アップデート後の改善

✓CUR 上でプレフィックス単位のストレージ / Tier 1 / Tier 2 リクエストコストを直接確認
✓カスタムパイプラインや独自の料金計算ロジックが不要に
✓AWS 生成コスト配分タグでチーム / アプリケーション単位の集計が容易に

S3 Storage Lens がプレフィックスレベルのメトリクスを Billing and Cost Management に発行し、バケットのコストをプレフィックス単位に配分して CUR に明細行として出力する流れ

⚡ 主要機能

1️⃣ プレフィックス単位のコスト配分

汎用バケットのストレージコスト (全ストレージクラス対象) と Tier 1 / Tier 2 リクエストコストを、選択したプレフィックスレベル範囲内で 最も深く一致するプレフィックス に配分。バケット自体の明細行は合計の使用量とコストを保持したまま、追加の明細行として配分結果を出力します。

2️⃣ プレフィックスレベル範囲の選択

S3 Storage Lens ダッシュボード設定で MinDepth と MaxDepth (いずれも 1〜15 の整数) を指定。未指定の場合のデフォルトは MinDepth=1、MaxDepth=3。MaxDepth − MinDepth は最大 4 (最大 5 つの隣接レベルを報告可能) です。

3️⃣ AWS 生成コスト配分タグ

プレフィックスの明細行にプレフィックスパスの各セグメントとバケット名をタグとして付与します。

aws:s3:PrefixLevel1 〜 aws:s3:PrefixLevel15 aws:s3:BucketName

タグはデフォルトで非アクティブのため、Billing and Cost Management コンソールでのアクティブ化が必要です (反映まで最大 24 時間)。

4️⃣ 未配分コストの明示

プレフィックスに属さないルートレベルオブジェクトのコストなどは、バケットレベルの未配分 (unattributed) カテゴリとして記録。未配分の明細行では aws:s3:PrefixLevel1 の値は (unattributed) になります。

📈 明細行数の見積もり式

Text 月間の追加明細行数 
月間の追加明細行数 = (使用量のあるプレフィックス数 + 1)
                  × 使用量のある使用タイプ数 (最大 2)
                  × 月の日数

例: 最深レベルに 2,000 プレフィックス、毎日ストレージとリクエストの両方を使用
    → 30 日間で最大 (2,000 + 1) × 2 × 30 = 120,060 行

🔄 API 変更履歴

今回のアップデートに直接対応する API 変更は、AWS API Changes フィード (直近 7 日間) には含まれていません。機能の設定は既存の S3 Storage Lens 設定 API に追加された CostAndUsageReportsPublish メンバーと、Billing and Cost Management コンソールの Cost Management preferences で行います。

🛠️ 設定方法

✅ 前提条件

  • S3 Storage Lens の アドバンストティア ダッシュボードを使用していること (無料ティアでは利用不可)
  • S3 Storage Lens 設定の PrefixDelimiter が / であること
  • 有効化は AWS Organizations の管理アカウントまたはスタンドアロンアカウントから行うこと
  • CUR (レガシー CUR または CUR 2.0) のエクスポート設定で Split Cost Allocation Data とリソース ID を含めること
1

S3 Storage Lens で Billing and Cost Management 発行を有効化

Storage Lens ダッシュボード設定 (アドバンストティア) で AWS Billing and Cost Management への発行を有効化し、対象バケットとプレフィックスレベルの範囲 (MinDepth / MaxDepth) を選択。API では CostAndUsageReportsPublish メンバーを使用します。

2

Billing and Cost Management で Split Cost Allocation Data を有効化

Cost Management preferences で Split Cost Allocation Data の対象として Amazon S3 を選択。あわせて CUR エクスポート設定で Split Cost Allocation Data とリソース ID を含めるよう構成します。

3

コスト配分タグのアクティブ化と CUR の確認

コスト配分タグページで aws:s3:PrefixLevel1 〜 aws:s3:PrefixLevel15 および aws:s3:BucketName をアクティブ化 (反映まで最大 24 時間)。次回の日次 Storage Lens メトリクス発行後、プレフィックスのコストデータが CUR に表示されます。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

  • チャージバック / ショーバックの実現: チーム、アプリケーション、テナント単位で正確に配賦し、コストの説明責任を明確化
  • コスト最適化の促進: コストを押し上げているプレフィックスを特定し、的を絞った最適化が可能
  • 運用コストの削減: カスタムパイプラインの構築・保守が不要になり FinOps チームの工数を削減

🔩 技術面のメリット

  • マネージドな配分処理: Storage Lens のメトリクスを基に自動でコストを計算・配分、独自実装が不要
  • CUR との統合: Amazon Athena や Amazon QuickSight など既存の CUR 分析基盤をそのまま活用可能
  • タグベースの柔軟な集計: 任意のプレフィックスレベルでの集計やバケット全体との照合が容易

⚠️ 制限事項

  • 汎用バケットのみ対応 (ディレクトリ / テーブル / ベクターバケットは対象外)
  • 配分対象はストレージと Tier 1 / Tier 2 リクエストコストのみ (アノテーションやクロスリージョンレプリケーションのリクエストコストは対象外)
  • 設定した深さでバケットあたり 10,000 プレフィックスまで。超過時は浅いレベルへフォールバック、MinDepth でも超過するとデータ生成なし
  • 報告できるのは最大 5 つの隣接プレフィックスレベル
  • S3 Storage Lens アドバンストティアが必要

🤔 考慮すべき点

  • Requester Pays バケットで他アカウントからのリクエスト割合が大きい場合、リクエストコスト見積もりの精度が低下
  • ルート直下へのオブジェクト配置が多いと未配分カテゴリのコストが増加
  • プレフィックス数が多いと CUR の明細行数が大きく増加するため、クエリコストやデータ量に注意
  • コストはあくまで見積もり (estimated cost) であり、正式な請求額の算出基盤ではない

シナリオ: データレイク用共有バケットに marketing/、finance/、engineering/ のように部門別プレフィックスでデータを格納し、部門ごとのコストを可視化したい。

Text実装例

🔍 3. コストを押し上げているプレフィックスの特定と最適化

Text実装例

2. CUR をクエリし、プレフィックス別のストレージコストと

   S3 ライフサイクルポリシーの適用を検討
✨ 効果: コスト増加の原因プレフィックス (ワークロード) をデータに基づいて特定し、効果の大きい箇所から優先的に最適化。

🔗 関連サービス・機能

🔍 Amazon S3 Storage Lens

プレフィックスレベルのストレージ / リクエストメトリクスを Billing and Cost Management に発行する役割。アドバンストティアが必要。

📋 AWS Cost and Usage Report (CUR)

プレフィックス単位の明細行が出力される先。レガシー CUR と CUR 2.0 の両方に対応。

⚙️ Split Cost Allocation Data (ECS / EKS / ネットワーキング)

既存の Split Cost Allocation Data は ECS タスク / EKS ポッド単位のコンテナコスト配分や、NAT ゲートウェイなど共有ネットワークリソースのコスト配分に対応しており、今回 S3 が追加された。

🏷️ AWS コスト配分タグ

aws:s3:PrefixLevel1 〜 aws:s3:PrefixLevel15、aws:s3:BucketName の AWS 生成タグを使用してコストを集計。

🎁 まとめ

共有 S3 バケットの プレフィックス単位コスト配分 が、カスタムパイプライン不要のマネージド機能として CUR に統合されました。複数チームやテナントでバケットを共有している組織は、チャージバック / ショーバックの精度向上とコスト最適化の起点として、S3 Storage Lens アドバンストティアダッシュボードでの Billing and Cost Management 発行の有効化を検討することを推奨します。
