AWS SAM CLI
CloudFormation Language Extensions サポート

Fn::ForEach でテンプレートの DRY 化とローカル開発を両立
AWS Serverless Application Model
リリース日
2026-05-18

📋 概要

AWS SAM CLI が AWS CloudFormation Language Extensions をサポートし、Fn::ForEach などのループ構文を含むテンプレートをローカルでビルド、テスト、デプロイできるようになった。これにより、IaC テンプレートの重複を削減しながら、SAM CLI のローカル開発ワークフローをフル活用できる。

❌ Before
  • Fn::ForEach を含むテンプレートでローカルテストが不可能
  • DRY なテンプレートか SAM CLI のローカル開発か二者択一
  • 類似リソースを手動でコピー&ペースト、テンプレートが肥大化
✅ After
  • sam build, sam local invoke, sam sync など全コマンドが動作
  • リソースを 1 回定義するだけでローカルテスト + デプロイ可能
  • 構文エラーや依存関係の問題をデプロイ前にローカルで検出

🏗️ アーキテクチャ図

SAM CLI は 2 フェーズでテンプレートを処理する。Phase 1 で Language Extensions を展開し、Phase 2 で SAM Transform を適用する。元のテンプレートはデプロイ用にそのまま保持される。

⚡ 主要機能

🔄
Fn::ForEach ループ展開
単一のリソース定義から複数リソースを生成。最大 5 レベルのネスト対応。Resources、Outputs、Conditions で使用可能。
⚙️
2 フェーズ処理
Phase 1 で Language Extensions をメモリ内展開、Phase 2 で SAM Transform を処理。デプロイ時は元テンプレートを CloudFormation がサーバーサイドで処理。
📦
動的アーティファクトプロパティ
ループ変数を含む CodeUri を自動処理。SAM* プレフィックスの Mappings を自動生成し S3 URI とマッピング。
🔍
展開リソースの個別呼び出し
展開されたリソースを名前で直接呼び出し可能。例: sam local invoke AlphaFunction

🛠 設定方法

ステップ 1: SAM CLI のアップデート

Bash SAM CLI アップデート 
# Homebrew (macOS/Linux)
brew upgrade aws-sam-cli

# pip
pip install --upgrade aws-sam-cli

# バージョン確認
sam --version

ステップ 2: テンプレートに Transform を追加

YAML Transform 設定 
Transform:
  - AWS::LanguageExtensions
  - AWS::Serverless-2016-10-31

ステップ 3: Fn::ForEach でリソースを定義

YAML Fn::ForEach による複数 Lambda 定義 
Parameters:
  ServiceNames:
    Type: CommaDelimitedList
    Default: "Users,Orders,Products"

Resources:
  Fn::ForEach::Services:
    - Name
    - !Ref ServiceNames
    - ${Name}Function:
        Type: AWS::Serverless::Function
        Properties:
          Handler: index.handler
          Runtime: python3.12
          CodeUri: ./services/${Name}

ステップ 4: ローカルでビルド・テスト

Bash ローカル実行 
# ビルド
sam build

# 特定の関数をローカル実行
sam local invoke UsersFunction

# API をローカル起動
sam local start-api

# バリデーション
sam validate

📈 メリット

💼 ビジネス面

✓ 開発速度の向上: リソース定義の重複排除でテンプレート作成・変更時間を短縮
✓ デプロイ前のエラー検出: ローカル検証でクラウドデプロイ失敗を事前回避
✓ 運用コスト削減: テンプレートメンテナンスが容易になりチーム全体の生産性が向上

🛠 技術面

✓ DRY 原則の実現: 同一パターンのリソースを 1 回定義するだけで複数生成
✓ 完全なローカル開発ワークフロー: Language Extensions 使用でも全機能利用可能
✓ テンプレート整合性の維持: ローカル展開とクラウドデプロイで同一テンプレート使用

⚠️ 制限事項・注意点

⚠️ コレクションはビルド/パッケージ時に解決可能である必要がある (Fn::GetAtt、Fn::ImportValue、SSM/Secrets Manager 動的参照は使用不可)
⚠️ 動的アーティファクトマッピングはパッケージ時に固定される (パラメータ変更時は再パッケージが必要)
⚠️ Fn::ForEach のネストは最大 5 レベルまで
⚠️ SAM* プレフィックスの Mapping 名は予約済みのため、ユーザー定義では使用不可
⚠️ DeletionPolicy と UpdateReplacePolicy は Ref のみサポートし、他の組み込み関数は使用不可
⚠️ 既存テンプレートへの移行時は、生成されるリソース論理 ID の変更に注意が必要

🎯 ユースケース

🔹 UC1: マイクロサービスの一括定義
複数のマイクロサービス (Users、Orders、Products) を同一パターンの Lambda 関数として定義し、ローカルで個別にテスト。
💡 効果: 3 つのサービスを 1 定義で管理。サービス追加時はパラメータリストに名前を追加するだけ。sam local invoke UsersFunction で個別テスト可能。
🔹 UC2: DynamoDB テーブルとストリームプロセッサの同時定義
複数のドメインエンティティごとに DynamoDB テーブルとそのストリームを処理する Lambda 関数をセットで定義。
💡 効果: テーブルとストリームプロセッサのペアを 1 回の定義で 3 セット生成。テンプレート行数を大幅削減。
🔹 UC3: マルチ環境のネスト定義
Dev、Staging、Prod の各環境に対して複数サービスを定義し、環境変数で識別。2 レベルのネストで 6 関数を生成。
💡 効果: 2 サービス x 3 環境 = 6 関数を簡潔に定義。sam local invoke DevUsersFunction で特定の組み合わせをテスト可能。

💰 料金・リージョン

💰 料金

SAM CLI は無料のオープンソースツール。Language Extensions サポートに追加料金なし。課金されるのはデプロイ先の AWS リソース (Lambda、DynamoDB、API Gateway など) の利用料のみ。

🌎 リージョン

SAM CLI はクライアントサイドツールのため、すべての AWS リージョンで使用可能。CloudFormation Language Extensions Transform がサポートされているリージョンであればデプロイ先として利用可能。
