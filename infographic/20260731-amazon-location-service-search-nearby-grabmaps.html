📍 Amazon Location Service 📅 2026 年 7 月 31 日

🗺️ GrabMaps での Search Nearby サポート

東南アジア向けハイパーローカル地図データで近隣 POI 検索が可能に

📋 概要

Amazon Location Service が、東南アジア向け地図データプロバイダー GrabMaps のデータを使用した SearchNearby (近接ベースの POI 検索) をサポートしました。 指定した座標から一定の半径内にある場所 (POI) を距離順に返す API で、 ガソリンスタンド、病院、レストランなどのカテゴリフィルタリングにも対応しています。

GrabMaps は毎日数百万件の Grab の移動データによって継続的に検証・更新されており、路地裏や狭い側道、バイクがアクセス可能なルートまでカバーします。 デリバリープラットフォーム、ライドヘイリングアプリ、旅行アプリなどでの活用が期待されます。

❌ アップデート前の課題

✗GrabMaps データで SearchNearby を利用できず、東南アジア特有のローカルデータを活用した「周辺検索」を実装できなかった
✗グローバルプロバイダーでは路地裏・狭い側道・バイク向けルートなどハイパーローカル情報のカバレッジに限界
✗周辺の店舗や施設の検索には独自のデータ収集やサードパーティサービスとの個別統合が必要だった

✅ アップデート後の改善

✓GrabMaps のハイパーローカルデータで、指定半径内の場所を距離順に取得可能に
✓カテゴリフィルターにより、アプリケーションに関連する結果のみを取得可能に
✓毎日数百万件の移動データで検証された最新の道路網・住所・POI 情報を利用可能に

アプリケーションは座標と検索半径を指定して SearchNearby API を呼び出し、GrabMaps データに基づく距離順の POI リストを取得します。

⚡ 主要機能

🎯 近接ベースの POI 検索 SearchNearby
  • 指定した座標 (QueryPosition) から検索半径 (QueryRadius) 内の場所を検索
  • 結果は距離順にランク付けされて返却
  • 場所の名称、住所、電話番号、カテゴリ、営業時間などの詳細情報を含む
🔍 カテゴリフィルタリング
  • Filter パラメータでカテゴリ (レストラン、病院、ガソリンスタンドなど) を指定可能
  • ビジネスチェーンやフードタイプによる絞り込みにも対応
  • 関連する結果のみを取得でき、クライアント側の後処理が不要
🌏 GrabMaps のハイパーローカルデータ
  • 東南アジア専用に構築された地図データ
  • 毎日数百万件の Grab の移動データによる継続的な検証・更新
  • 路地裏、狭い側道、バイクがアクセス可能なルートまでカバー
  • シンガポール、マレーシア、タイ、ベトナム、インドネシア、フィリピン、ミャンマー、カンボジアの 500 以上の都市に対応

🔧 技術仕様

📥 SearchNearby API の主要パラメータ

項目詳細
QueryPosition検索の中心となる経度・緯度座標 (必須)
QueryRadius中心座標からの検索半径
Filterカテゴリ、ビジネスチェーン、フードタイプなどによるフィルター
Language結果の言語指定
PoliticalView領土に関する政治的観点の適用
AdditionalFeaturesタイムゾーン、フォニーム (音素表記) などの追加情報の要求
IntendedUse結果の用途指定 (単回利用または保存)。保存する場合は Storage 料金ティアが適用

📤 レスポンスに含まれる主要データ

項目詳細
Address国、通りなどを含む完全な住所情報
Categories場所のカテゴリ (レストラン、学校など)
FoodTypes飲食店の料理の種類
BusinessChains関連するビジネスチェーン
Contactsメール、電話番号、Web サイト
OpeningHours営業時間
TimeZoneタイムゾーン情報

🛠️ 設定方法

✅ 前提条件

  • AWS アカウントを保有していること
  • アジアパシフィック (シンガポール) またはアジアパシフィック (マレーシア) リージョンを使用すること
  • Places API を呼び出す IAM 権限 (geo-places:SearchNearby) または API キーを設定していること
1
SearchNearby API の呼び出し
Bash シンガポール中心部から半径 1,000 m を検索 
aws geo-places search-nearby \
  --query-position 103.8198 1.3521 \
  --query-radius 1000 \
  --region ap-southeast-1

経度 103.8198、緯度 1.3521 から半径 1,000 メートル以内の場所を距離順に取得します。

2
カテゴリフィルターの適用
Bash クアラルンプール中心部のレストランのみを検索 
aws geo-places search-nearby \
  --query-position 101.6869 3.1390 \
  --query-radius 2000 \
  --filter '{"IncludeCategories": ["restaurant"]}' \
  --region ap-southeast-5

半径 2,000 メートル以内のレストランのみを検索します。マレーシアリージョン (ap-southeast-5) を使用しています。

3
結果の確認と活用

レスポンスの Distance (中心からの距離)、Address、OpeningHours などを確認し、 アプリケーションの UI に距離順の POI リストとして表示します。 結果を保存する場合は --intended-use Storage を指定します (Storage 料金ティアが適用される点に注意)。

💡 メリット・制約事項

📈 ビジネス面のメリット

✓品質向上: 現地の実情に即したデータで検索結果の精度と鮮度が向上
✓開発コスト削減: 独自データ収集や個別統合が不要、マネージド API のみで実装
✓鮮度の高いデータ: 毎日数百万件の移動データで道路網・住所・POI が常に最新

⚙️ 技術面のメリット

✓距離順ランキング: クライアント側のソート処理が不要
✓柔軟なフィルタリング: カテゴリ、ビジネスチェーン、フードタイプで絞り込み
✓豊富なレスポンス: 住所、連絡先、営業時間、タイムゾーンを 1 回の呼び出しで取得

⚠️ 制限事項

•GrabMaps での SearchNearby はシンガポール / マレーシアリージョンのみ利用可能
•データカバレッジは東南アジア 8 か国に限定
•検索結果を保存する場合はより高い Storage 料金ティアが適用

🤔 考慮すべき点

•東南アジア以外を対象とする場合は他のデータプロバイダーを検討
•IntendedUse の指定 (SingleUse / Storage) により料金が異なるため設計に注意
•日本など他リージョンからの利用時は対応リージョンのエンドポイントを明示的に指定

🎯 ユースケース

🍜 ユースケース 1: フードデリバリーの店舗検索

東南アジアで展開するフードデリバリープラットフォームが、配達員の現在地から最も近いピックアップポイント (レストラン) を特定する。

Bashバンコク中心部から半径 1,500 m のレストランを検索
aws geo-places search-nearby \
  --query-position 100.5018 13.7563 \
  --query-radius 1500 \
  --filter '{"IncludeCategories": ["restaurant"]}' \
  --region ap-southeast-1
✅ 効果: 配達員の現在地から距離順にレストランを取得でき、ピックアップまでの時間を最小化し配達効率を向上させる。
🚗 ユースケース 2: ライドヘイリングアプリでの周辺スポット提案

ライドヘイリングアプリが、乗車地点や降車地点の周辺にある飲食店をユーザーに提案する。

Bashジャカルタでインドネシア料理店を検索
aws geo-places search-nearby \
  --query-position 106.8456 -6.2088 \
  --query-radius 1000 \
  --filter '{"IncludeFoodTypes": ["indonesian"]}' \
  --region ap-southeast-1
✅ 効果: 降車地点周辺のインドネシア料理店を距離順に提示し、アプリ内での回遊とユーザーエンゲージメントを高める。
🏥 ユースケース 3: 旅行アプリでの緊急施設検索

東南アジアを旅行中のユーザーが、現在地から一定範囲内の病院や薬局を素早く見つける。

Bashシンガポールで半径 3,000 m の病院を検索
aws geo-places search-nearby \
  --query-position 103.8520 1.2966 \
  --query-radius 3000 \
  --filter '{"IncludeCategories": ["hospital"]}' \
  --region ap-southeast-1
✅ 効果: 営業時間や連絡先を含む病院情報を距離順に取得でき、緊急時にユーザーが最寄りの医療機関へ迅速にアクセスできる。

💰 料金

Amazon Location Service の Places 機能は、API リクエスト数に基づく従量課金です。 SearchNearby のリクエストは Places の料金体系に従って課金されます。 検索結果を保存する場合 (IntendedUse: Storage) は、より高い Storage 料金ティアが適用されます。

最新の料金は Amazon Location Service 料金ページ を参照してください。

Amazon Location Service の SearchNearby が GrabMaps データに対応し、 東南アジア向けアプリケーションで高精度な周辺検索を実装できるようになりました。 デリバリー、ライドヘイリング、旅行などのアプリケーションを東南アジア市場で展開している場合は、 シンガポールまたはマレーシアリージョンで SearchNearby と GrabMaps の組み合わせを評価することを推奨します。
