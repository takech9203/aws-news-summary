AWS Transform

🌏 AWS Transform for migrations
移行先リージョンを全商用リージョンへ拡大

📅 2026 年 6 月 22 日

📌 概要

AWS Transform for migrations が、すべての AWS 商用リージョンを移行先リージョン (Migration Target Region) としてサポートするようになりました。移行先リージョンとは、移行されたリソース (ランディングゾーン、ネットワークインフラ、リホストされたサーバー) がデプロイされる AWS リージョンを指します。

AWS Transform for migrations は、VMware ワークロードなどのオンプレミス環境を AWS へ移行するプロセスをエージェント主導で自動化するサービスです。今回のアップデートで、お客様は任意の商用リージョンにワークロードをデプロイでき、データレジデンシー要件への対応が容易になりました。

🔄 Before / After

❌ アップデート前の課題

  • 移行先として選べるリージョンが限られていた
  • データレジデンシー要件のあるリージョンが選択できず、規制対応が困難なケースがあった
  • 対象外の場合、AWS Transform 以外の手段を検討する必要があった
➜

✅ アップデート後の改善

  • すべての AWS 商用リージョンを移行先として選択可能に
  • データを保管すべき国や地域のリージョンにデプロイ可能に
  • ローカルなコンプライアンスやレイテンシー要件に合わせた選択が可能に

AWS Transform の移行ワークフローからターゲットアカウントコネクタを介して、選択した移行先リージョンにランディングゾーン、ネットワークインフラ、リホストされたサーバーがデプロイされます。サーバーのレプリケーションデータは、ソース環境からターゲットアカウントおよびリージョンへ直接転送されます。

⚙️ 主要機能

🌐 全 AWS 商用リージョンの移行先サポート

  • 移行されたリソースのデプロイ先として、すべての商用リージョンを選択可能
  • ランディングゾーン、ネットワークインフラ、サーバーリホストを含む
  • データレジデンシー要件への対応が容易に

🧭 ワークフロー内でのターゲットリージョン選択

  • 移行先リージョンの選択は AWS Transform のワークフローに組み込み済み
  • コネクタ作成時にターゲット AWS リージョンを指定
  • 単一アカウント移行とマルチアカウント移行の両方に対応

📍 新規追加された 16 リージョン

  • 北米、アフリカ、アジアパシフィック、欧州、中東、メキシコの幅広い地域をカバー
  • 既存のサポート対象に加え、商用リージョン全体に拡大

👥 移行に関わるアカウントの役割

アカウント説明
AWS Transform アカウントAWS Transform をセットアップする Organization 内のメンバーアカウント。ワークスペースが実行される。管理アカウントである必要はない
コネクタターゲットアカウントAWS Transform コネクタが構成されるアカウント。移行タイプによって異なる
ターゲットアカウントワークロードが移行される AWS アカウント。単一アカウント移行ではコネクタターゲットアカウントと同一、マルチアカウント移行では各メンバーアカウント

🔁 リージョン間のデータ転送に関する注意

移行先 AWS リージョンが AWS Transform のリージョンと異なる場合、一部のデータがリージョン間で転送されます。なお、サーバーのレプリケーションデータは、ソース環境からターゲットアカウントおよびリージョンへ直接転送されます。

🛠️ 設定方法

✅ 前提条件

✓Organization 内のメンバーアカウントに AWS Transform ワークスペースがセットアップされていること
✓ターゲット AWS アカウントに、移行インフラをサポートする権限・クォータ・構成が備わっていること
✓マルチアカウント移行の場合、組織管理アカウントまたは AWS Transform MGN と CloudFormation StackSets に登録された委任管理者アカウントへの接続

📝 手順

1

移行タイプの選択

単一アカウント移行か、マルチアカウント移行かを選択。マルチアカウント移行では最小権限の原則に従い委任管理者アカウントの利用が推奨されます。

2

ターゲットアカウントとリージョンの指定

ジョブプランペインでターゲットアカウントの接続を展開し、コネクタの作成または選択を選びます。続いて全商用リージョンの中から移行先リージョンを選択します。

3

コネクタの承認と利用

検証リンクをターゲットアカウントの管理者に共有して承認を依頼。承認後、コネクタを選択して AWS Transform に送信します。ネットワーク構成管理、CloudFormation デプロイ、ランディングゾーンのプロビジョニングなどの権限が付与されます。

Text コネクタ作成時に指定する項目 
# 指定する項目
- ターゲット AWS アカウント
- ターゲット AWS リージョン (移行先リージョン)
- 暗号化キー (Amazon S3 マネージドキーまたは独自の KMS キー)

⚖️ メリットと制約事項

👍 メリット

ビジネス面
  • データレジデンシー要件への対応が容易に
  • 移行プロジェクトの選択肢が拡大
  • エンドユーザーに近いリージョンでグローバル展開の柔軟性が向上
技術面
  • 移行先リージョン選択が既存ワークフローに統合済み
  • ランディングゾーン・ネットワーク・サーバーを一貫したプロセスでデプロイ
  • 近接リージョン選択でネットワークレイテンシーを低減

⚠️ 制約事項・考慮点

!対象は商用リージョンのみ。中国リージョンや AWS GovCloud (US) は対象外
!AWS Transform と異なるリージョンの場合、一部データがリージョン間で転送される
!現行のターゲットアカウントコネクタタイプはバージョン 2.0。権限変更時に更新される場合がある
!リージョン間転送が発生する場合、データ転送料金や転送時間を考慮
!作成される S3 バケットはデフォルトで HTTPS のみ (SecureTransport) を強制しない。必要に応じてバケットポリシーを更新
!移行先リージョンで利用したいサービス・インスタンスタイプの提供有無を事前確認

💡 ユースケース

1. データレジデンシー要件のある国へのワークロード移行

国内のデータ保護規制により特定の国のリージョンにデータを保管する必要がある企業が、オンプレミスの VMware ワークロードを移行。規制要件を満たすリージョン (例: ジャカルタ、スペイン) を選択してランディングゾーンとワークロードをデプロイ。

➜ 効果: データレジデンシー要件を満たしながら、自動化された移行プロセスを活用できる

2. エンドユーザーに近いリージョンへの移行によるレイテンシー改善

東南アジアや中東の顧客向けにサービスを提供する企業が、ユーザーに近いリージョン (バンコク、クアラルンプール、テルアビブなど) へ移行し、サーバーリホストとネットワークインフラを構築。

➜ 効果: 地理的に近いリージョンで稼働させ、レイテンシー低減とユーザー体験向上

3. 新規リージョンへのグローバル拡張

欧州での事業拡大に伴い、これまで選択できなかったミラノやチューリッヒなどへ既存ワークロードを展開。マルチアカウント移行と委任管理者アカウントを使用し、各事業地域に対応するリージョンへ統一的にデプロイ。

➜ 効果: 拡大する事業地域に合わせ、一貫した移行プロセスでグローバル展開できる

💰 料金

AWS Transform for migrations の利用自体に追加料金は発生しません。移行先リージョンの拡大に伴う追加料金もありません。ただし、移行されたワークロードが利用する各 AWS サービス (Amazon EC2、Amazon VPC、AWS Control Tower など) の利用料金は、選択した移行先リージョンの料金体系に従って発生します。また、AWS Transform のリージョンと異なる場合はデータ転送料金が発生する可能性があります。

🔗 関連サービス・機能

  • AWS Application Migration Service (MGN): サーバーリホストで利用される、サーバー移行を自動化するサービス
  • AWS Control Tower: ランディングゾーンの構築とガバナンス管理に利用
  • AWS Migration Acceleration Program (MAP): 移行プロジェクトを支援するプログラム。MPE ID 指定で MAP タグが移行リソースに適用される
  • AWS CloudFormation StackSets: マルチアカウント移行で複数アカウントへのリソースデプロイに利用

📝 まとめ

今回のアップデートにより、AWS Transform for migrations はすべての AWS 商用リージョンを移行先としてサポートし、データレジデンシー要件への対応やグローバル展開がより柔軟になりました。移行プロジェクトを計画しているお客様は、規制要件やレイテンシー要件に応じて最適な移行先リージョンを選択できます。VMware ワークロードなどの移行を検討している場合は、AWS Transform for migrations のワークフローで移行先リージョンの選択肢を確認することをお勧めします。
