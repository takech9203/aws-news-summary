📊 CloudWatch OTel Container Insights for Amazon EKS

Amazon CloudWatch Amazon EKS Public Preview

📋 概要

Amazon CloudWatch が Container Insights に OpenTelemetry メトリクスのサポートを導入しました。Amazon EKS クラスターからオープンソースおよび AWS コレクターを通じてより多くのメトリクスを収集し、OTLP を使用して CloudWatch に送信できるようになります。

各メトリクスには Kubernetes メタデータやユーザー定義ラベルを含む最大 150 の記述ラベルが自動的に付与されます。キュレーションダッシュボードとCloudWatch Query Studio での PromQL クエリにより、高度な分析が可能です。

🔄 Before / After 比較

  • CloudWatch Query Studio で PromQL による高度な分析が可能

🚀 主要機能

📡 OpenTelemetry Protocol によるメトリクス収集
オープンソースおよび AWS コレクターから OTLP でメトリクスを送信。各メトリクスに最大 150 の記述ラベルを自動付与。
📋 キュレーションダッシュボード
クラスター、ノード、Pod のヘルスをリアルタイムで可視化。インスタンスタイプ、AZ、ノードグループで集約・フィルタリング。
🔎 PromQL クエリサポート
CloudWatch Query Studio で PromQL クエリを直接記述・実行。OTLP メトリクスに対する PromQL アラームも設定可能。
🎮 アクセラレーテッドハードウェア自動検出
NVIDIA GPU、EFA、AWS Trainium、AWS Inferentia チップを自動認識し、関連メトリクスを収集。
⚡ ワンクリックインストール
CloudWatch Observability EKS アドオンによる簡易セットアップ。EKS コンソール、CloudFormation、CDK、Terraform からデプロイ可能。

Step 1: CloudWatch Observability EKS アドオンのインストール

Bash EKS アドオンのインストール 
aws eks create-addon \
  --cluster-name my-cluster \
  --addon-name amazon-cloudwatch-observability \
  --region us-east-1

Step 2: OTel Enrichment の有効化

Bash OTel Enrichment の開始 
aws cloudwatch start-o-tel-enrichment

Step 3: ダッシュボードでの確認

CloudWatch コンソールの Container Insights セクションにアクセスし、キュレーションダッシュボードでクラスターのヘルスを確認。Query Studio で PromQL クエリを使用してカスタム分析を実行。

新規 API メソッド

Python OTel Enrichment API 
# OTel Enrichment の開始
client.start_o_tel_enrichment()

# OTel Enrichment のステータス取得
response = client.get_o_tel_enrichment()
# response: {'Status': 'Running'|'Stopped'}

# OTel Enrichment の停止
client.stop_o_tel_enrichment()

PromQL アラーム設定例

Python PromQL アラームの作成 
client.put_metric_alarm(
    AlarmName='eks-pod-cpu-high',
    EvaluationCriteria={
        'PromQLCriteria': {
            'Query': 'avg(container_cpu_usage_seconds_total{namespace="production"}) > 0.8',
            'PendingPeriod': 300,
            'RecoveryPeriod': 300
        }
    },
    EvaluationInterval=60,
    AlarmActions=['arn:aws:sns:us-east-1:123456789012:alerts']
)

🎯 ユースケース

🎮 ユースケース 1: AI/ML 推論ワークロードの GPU 監視
EKS 上で NVIDIA GPU を使用した推論ワークロードを運用しており、GPU 使用率やメモリ消費を詳細に監視したいシナリオ。
Bash 
aws eks create-addon \
  --cluster-name ml-inference-cluster \
  --addon-name amazon-cloudwatch-observability

# Query Studio で GPU メトリクスを PromQL で分析
# gpu_utilization{cluster="ml-inference-cluster", instance_type="p5.48xlarge"}
GPU ハードウェアが自動検出され、設定不要で GPU 使用率、メモリ、温度などのメトリクスが送信される。推論レイテンシとリソース利用率の相関分析が可能。
🏢 ユースケース 2: マルチテナント EKS の Namespace 別監視
複数チームが共有する EKS クラスターで、Namespace ごとのリソース使用状況を把握し、コスト配分やキャパシティプランニングに活用。
PromQL 
# Namespace 別の CPU 使用率集計
sum by (namespace) (
  rate(container_cpu_usage_seconds_total{cluster="shared-cluster"}[5m])
)

# Namespace 別のメモリ使用量
sum by (namespace) (
  container_memory_working_set_bytes{cluster="shared-cluster"}
)
最大 150 のラベルにより Namespace、チーム、コストセンターなどでメトリクスを集約・フィルタリングでき、チーム別のリソース使用状況を正確に把握可能。
🧠 ユースケース 3: AWS Trainium を使用した分散トレーニングの監視
AWS Trainium インスタンスを使用した大規模分散モデルトレーニングジョブを EKS 上で実行し、ニューロンデバイスの稼働状況をリアルタイム監視。
Bash 
aws eks create-addon \
  --cluster-name training-cluster \
  --addon-name amazon-cloudwatch-observability

# PromQL アラームで異常を検出
aws cloudwatch put-metric-alarm \
  --alarm-name "trainium-utilization-low" \
  --evaluation-criteria '{
    "PromQLCriteria": {
      "Query": "avg(neuron_device_utilization{cluster=\"training-cluster\"}) < 0.5",
      "PendingPeriod": 600,
      "RecoveryPeriod": 300
    }
  }' \
  --evaluation-interval 60
Trainium デバイスの自動検出により、ニューロンコアの使用率やメモリ消費を設定不要で監視可能。利用率低下時のアラームでトレーニングジョブの異常を早期に検出。
