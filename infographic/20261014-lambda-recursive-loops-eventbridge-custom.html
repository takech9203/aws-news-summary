⚡ Lambda 再帰ループ検出が EventBridge カスタムイベントバスをサポート

📅 リリース日: 2026 年 10 月 14 日
Lambda recursive loop detection for Amazon EventBridge Custom event buses

📝 概要

AWS Lambda の再帰ループ検出が、Amazon EventBridge カスタムイベントバスとの間で発生する再帰ループを自動的に検出・停止できるようになりました。設定ミスやコードの不具合によるランナウェイワークロードから、意図しない課金と同時実行数の枯渇を自動的に防ぎます。

再帰ループ検出はデフォルトで有効・無料で、追加設定は不要です。ループ停止時には AWS Health Dashboard にトラブルシューティング手順を含む通知が送信されます。意図的な再帰設計には PutFunctionRecursionConfig API で関数単位の無効化が可能です。

  • Lambda と EventBridge カスタムイベントバス間の再帰ループを自動検出・停止

  • デフォルトで有効、設定変更や追加コスト不要

Lambda Event Function が処理結果を同じ EventBridge カスタムイベントバスに送信すると再帰ループが発生します。Lambda はイベントに付与されたメタデータで呼び出し回数を追跡し、同一リクエストチェーンで約 16 回の呼び出しを検出すると次の呼び出しを自動停止して通知します。

🔧 主要機能

1️⃣ EventBridge カスタムイベントバスを含む再帰ループの自動検出

Lambda Event Function と EventBridge カスタムイベントバスの間のループを自動識別。同一のトリガーイベントに起因するチェーンで約 16 回の呼び出しに達すると次の呼び出しを自動停止。複数トリガーがある場合、他のトリガーからの呼び出しには影響しません。

2️⃣ X-Ray トレーシングヘッダーによるイベント追跡

イベントにメタデータが自動付与され呼び出し回数をカウント。X-Ray のアクティブトレース有効化は不要で追加料金もなし。検出にはサポート対象バージョンの AWS SDK でのイベント書き込みが必要です。

3️⃣ 通知とモニタリング

ループ停止時に AWS Health Dashboard の「Your account health」に通知 (表示まで最大 3.5 時間)。関数ごとに 24 時間に最大 1 通のメールアラートを送信。CloudWatch メトリクス RecursiveInvocationsDropped で監視可能。

4️⃣ 関数単位でのオプトアウト

意図的な再帰パターンには PutFunctionRecursionConfig API、コンソール、AWS CLI、CloudFormation、AWS SAM で検出を無効化可能。無効化した関数ではメトリクスは発行されません。

⚙️ 設定方法

✅ 前提条件

✓再帰ループ検出はデフォルトで有効のため、保護を受けるための設定は不要
✓検出には、関数がサポート対象バージョンの AWS SDK を使用してイベントを書き込んでいること
✓オプトアウトする場合は、対象関数に対する lambda:PutFunctionRecursionConfig 権限

ステップ 1: 停止された再帰呼び出しの監視

Bash CloudWatch メトリクスの取得 
aws cloudwatch get-metric-statistics \
  --namespace AWS/Lambda \
  --metric-name RecursiveInvocationsDropped \
  --dimensions Name=FunctionName,Value=my-function \
  --start-time 2026-10-14T00:00:00Z \
  --end-time 2026-10-15T00:00:00Z \
  --period 3600 \
  --statistics Sum

Lambda が停止した再帰呼び出しの数を確認します。このメトリクスにアラームを設定しておくと、ループ発生時に迅速に対応できます。

ステップ 2: ループ検出後の対処

Bash 同時実行数をゼロにして呼び出しを抑止 
# 関数の予約済み同時実行数をゼロにしてすべての呼び出しをスロットリング
aws lambda put-function-concurrency \
  --function-name my-function \
  --reserved-concurrent-executions 0

応急処置として関数の同時実行数をゼロに設定して以降の呼び出しを抑止し、同じイベントバスへ書き戻しているコード不具合や設定ミスを特定して修正します。

ステップ 3: 意図的な再帰ループを使用する場合のオプトアウト

Bash 再帰ループ検出の無効化 
aws lambda put-function-recursion-config \
  --function-name my-function \
  --recursive-loop Allow

デフォルトに戻す場合は --recursive-loop Terminate を指定します。再帰ループの使用は実装ミスによるリスクが大きいため、AWS はガードレールの実装を推奨しています。

💡 メリット

💼 ビジネス面

✓予期しない課金の防止: ランナウェイワークロードが自動停止され、意図しない大量実行による課金リスクを低減
✓運用負荷の軽減: デフォルトで有効かつ無料のため、追加の仕組みなしで保護が適用
✓迅速な障害対応: Health Dashboard の通知にトラブルシューティング手順が含まれ、復旧時間を短縮

🔧 技術面

✓検出対象の拡大: SQS、S3、SNS に加えて EventBridge カスタムイベントバスを含むループが検出可能に
✓同時実行数の保護: 無限ループによる枯渇を防ぎ、他のワークロードへの影響を抑止
✓柔軟なオプトアウト: 意図的な再帰パターンの関数のみ API 一つで無効化可能

⚠️ デメリット・制約事項

🚫 制限事項

✗検出対象は SQS、S3、SNS、EventBridge カスタムイベントバス、Lambda Event Function 同士に限られ、DynamoDB など他のサービスを含むループは検出されない
✗検出には、関数がサポート対象バージョン以上の AWS SDK を使用してイベントを書き込む必要がある
✗約 16 回の呼び出しが発生するまではループが継続するため、しきい値到達までの実行分は課金対象

🤔 考慮すべき点

⚠️Health Dashboard への通知表示とメールアラートの送信には最大 3.5 時間かかる場合がある
⚠️SQS がイベントソースの場合、ループ検出後も maxReceiveCount を超過するまでメッセージの再試行が継続する (呼び出し自体はブロックされる)
⚠️検出対象外のサービスを含むループに備えて、CloudWatch アラームや AWS Cost Anomaly Detection による監視を併用することを推奨
⚠️オンフェイラー送信先やデッドレターキューに、関数を呼び出すリソースと同じリソースを指定しないよう注意

3. 意図的な再帰パターンの継続利用

シナリオ: 大きなバッチ処理を分割して、処理の進捗をイベントとして同じカスタムイベントバスに発行しながら自己継続する再帰的なワークフローを意図的に設計している。

Bash 対象関数のみ検出を無効化

💰 料金と利用可能リージョン

💰 料金

再帰ループ検出は無料で、追加料金は発生しません。X-Ray のアクティブトレース有効化も不要です。なお、しきい値 (約 16 回) に到達するまでの Lambda 実行と EventBridge の PutEvents には通常の料金が適用されます。

🌍 利用可能リージョン

EventBridge カスタムイベントバスが利用可能なすべての商用 AWS リージョンで利用できます。再帰ループ検出自体もすべての商用リージョンでサポートされています。

🔗 関連サービス・機能

→Amazon EventBridge: カスタムイベントバスとルールによるイベントルーティング。本アップデートで再帰ループ検出の対象に追加
→AWS X-Ray: トレーシングヘッダーがイベントの呼び出し回数の追跡に利用される (アクティブトレースの有効化は不要)
→AWS Health Dashboard: ループ停止時の通知とトラブルシューティング手順の提供
→Amazon CloudWatch: RecursiveInvocationsDropped メトリクスによる監視とアラーム設定
→AWS Cost Anomaly Detection: 検出対象外のサービスを含むループに備えた異常課金の検知

📌 まとめ

Lambda の再帰ループ検出が EventBridge カスタムイベントバスに対応したことで、イベント駆動アーキテクチャにおける主要なループパターンの多くが自動保護の対象となりました。デフォルトで有効かつ無料のため、ユーザー側での対応は不要ですが、以下の対応を推奨します。

✓RecursiveInvocationsDropped メトリクスへのアラーム設定
✓意図的な再帰パターンを使用する関数の棚卸し
