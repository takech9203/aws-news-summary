Amazon MSK

🚀 Standard ブローカーで Apache Kafka バージョン 4.2 をサポート

📅 リリース日: 2026 年 11 月 20 日 | サービス: Amazon Managed Streaming for Apache Kafka

📝 概要

Amazon MSK の Standard ブローカーが Apache Kafka 4.2 に対応しました。新規クラスター作成時に 4.2.x を選択できるほか、既存の MSK プロビジョンドクラスターもインプレースのローリングアップデートで 4.2 にアップグレードできます。

最大のトピックは、ポイントツーポイント型メッセージングを実現する Queues for Kafka が本番利用可能 (production ready) になったことです。複数のコンシューマーが同一のトピックパーティションから読み取れるようになり、並列性とスループットを大幅に高められます。さらに Eligible Leader Replicas (ELR) の強化、新しいコンシューマーリバランスプロトコル、Streams Rebalance Protocol など、運用の安定性と効率を高める改善が含まれています。

❌ アップデート前の課題

✗1 パーティションを同時に読み取れるコンシューマーは 1 つに限られ、並列性向上にはパーティション数の増加が必要
✗ポイントツーポイント型のキュー処理には Amazon SQS など別サービスとの併用や独自の工夫が必要
✗リバランスやリーダー選出時に処理の一時停止や可用性低下の影響を受けやすい

✅ アップデート後の改善

✓Queues for Kafka により複数コンシューマーが同一パーティションを読み取り可能に。パーティション数を増やさず並列性とスループットを向上
✓ELR の強化でリーダー選出の正確性と可用性が向上
✓新プロトコルでコンシューマーグループのリバランスが高速かつスムーズに
✓Streams Rebalance Protocol でタスク割り当てをブローカー側で調整し効率化

従来は 1 パーティションにつき 1 コンシューマーという制約がありましたが、Kafka 4.2 の Queues for Kafka では複数のコンシューマーが同一パーティションを分担して読み取れるため、パーティション数を増やさずに処理の並列性を高められます。

⭐ 主要機能

📬 Queues for Kafka の本番利用対応
  • 複数のコンシューマーが同一のトピックパーティションから読み取り可能
  • ポイントツーポイント型のメッセージングワークロードで並列性とスループットが向上
  • ジョブキューやタスク分散など、従来はメッセージキュー製品が担っていたユースケースに Kafka を適用可能
🛡️ Eligible Leader Replicas の強化
  • リーダー選出の正確性が向上
  • ブローカー障害時などにおけるクラスターの可用性を強化
⚡ 新しいコンシューマーリバランスプロトコル
  • コンシューマーグループのリバランスがより高速かつスムーズに
  • コンシューマーの参加・離脱時の処理停止時間を低減
🔄 Streams Rebalance Protocol
  • Kafka Streams アプリケーションにブローカー側での調整機能を提供
  • タスク割り当てがより効率的になり、ストリーム処理の安定性が向上

⚙️ 設定方法

✅ 前提条件

  • AWS アカウントと Amazon MSK を操作できる IAM 権限
  • 新規クラスター作成の場合: VPC、サブネット、セキュリティグループの準備
  • 既存クラスターのアップグレードの場合: クライアントが Kafka 4.2 と互換性があることの確認

ステップ 1: 新規クラスターをバージョン 4.2.x で作成

Bash AWS CLI でクラスター作成 
aws kafka create-cluster \
  --cluster-name my-kafka-42-cluster \
  --kafka-version "4.2.x" \
  --number-of-broker-nodes 3 \
  --broker-node-group-info file://brokernodegroupinfo.json

Apache Kafka バージョン 4.2.x を指定して、新しい MSK プロビジョンドクラスターを作成します。AWS マネジメントコンソールや AWS SDK からも同様に作成できます。

ステップ 2: 既存クラスターをインプレースアップグレード

Bash ローリングアップデートの実行 
aws kafka update-cluster-kafka-version \
  --cluster-arn <クラスターの ARN> \
  --current-version <現在のクラスター構成リビジョン> \
  --target-kafka-version "4.2.x"

既存の MSK プロビジョンドクラスターを Kafka 4.2 にローリングアップデートします。MSK がブローカーの再起動をオーケストレーションし、アップグレード中も可用性とデータを保護します。

ステップ 3: アップグレードの進行状況を確認

Bash オペレーション状態の確認 
aws kafka describe-cluster-operation \
  --cluster-operation-arn <オペレーションの ARN>

アップグレードオペレーションの状態を確認します。完了後、クライアント側で Kafka 4.2 の新機能 (シェアグループなど) の利用を検討します。

💡 メリット

💼 ビジネス面
✓アーキテクチャの簡素化: キュー型とストリーミングのワークロードを Kafka に統合でき、運用するミドルウェアを削減
✓スループット向上によるコスト効率: パーティション数を増やさずに並列性を高め、過剰なパーティション設計を回避
✓ダウンタイムの最小化: インプレースのローリングアップデートでサービス停止なしに移行
🔬 技術面
✓並列処理の柔軟性: シェアグループによりコンシューマー数をパーティション数に縛られずスケール
✓可用性の強化: ELR の改善で障害時のリーダー選出がより正確に
✓運用の安定性: リバランス高速化と Kafka Streams のブローカー側調整でデプロイやスケール時の影響を低減

⚠️ デメリット・制約事項

制限事項

⚠️今回のサポート対象は Standard ブローカーであり、他のブローカータイプでの対応状況は別途確認が必要
⚠️Queues for Kafka などの新機能を利用するには、クライアントライブラリ側も対応バージョンへの更新が必要

考慮すべき点

⚠️アップグレード前に、使用中のクライアント、コネクタ、ツール類の Kafka 4.2 互換性を検証する必要がある
⚠️ローリングアップデート中はブローカーが順次再起動されるため、クライアント側の再接続・リトライ設定を確認しておくことが望ましい
⚠️シェアグループは従来のコンシューマーグループとセマンティクスが異なるため、順序保証の要件があるワークロードでは適用可否を慎重に判断する必要がある
