AWS Billing and Cost Management

💳 AWS クレジットの分割と転送

Credit Splitting and Transfers | リリース日: 2026 年 11 月 17 日

📌 概要

AWS クレジットを複数の小さなクレジットに分割 (Split) し、支払いアカウント配下の リンクされたアカウントに転送 (Transfer) できるようになりました。 FinOps チームは金額指定、パーセンテージ指定、均等分割のいずれかの方法でクレジットを分割し、 クレジットを獲得したチームに届けられます。

分割後の各クレジットは元のクレジットと同じ有効期限および対象サービスを継承し、共有設定もデフォルトで保持されます。 転送されたアカウントは、そのクレジットを最優先で消費できます。 クレジットレベル共有やクレジットの一時停止といった既存機能とも組み合わせ可能です。

❌ アップデート前の課題
  • クレジットはまず所有アカウントに適用され、余剰分のみ共有される仕組みで、特定チームへの正確な金額割り当てが困難
  • 1 つの大きなクレジットが複数チーム向けの場合、所有アカウントが他チーム分まで消費する可能性
  • FinOps チームは毎月何時間もの手作業によるチャージバック作業が必要
✅ アップデート後の改善
  • 金額指定、パーセンテージ指定、均等分割で複数の小さなクレジットに分割可能
  • 組織内の任意のアカウントに転送し、チームごとに予測可能なクレジット予算を提供
  • 転送先アカウントが最優先で消費でき、意図したチームに確実にクレジットが届く
  • コンソール、CLI、API から操作でき、チャージバックの自動化が可能

管理アカウントが保有する $1,000,000 のクレジットを $600,000 と $400,000 に分割し、$400,000 分を Media アカウントに転送する例です。 転送を受けた Media アカウントはそのクレジットを最優先で消費し、未使用分は各クレジットの共有設定に従って他アカウントに共有されます。

⚙️ 主要機能

✂️ 1. クレジットの分割 (Split)
  • クレジットの残高を同一アカウント内の複数の新しいクレジットに分割
  • 分割方法は均等分割 (新しいクレジット数を指定)、パーセンテージ指定、金額指定の 3 種類
  • 各新クレジットは独自のクレジット ID、共有設定、消費トラッキングを持つ
  • 分割後、元のクレジットの残高は $0 となり、ステータスが「Expired」として Credits ページに残る
  • 部分的に消費済みのクレジットも分割可能で、残高のみが分割対象
🚚 2. クレジットの転送 (Transfer)
  • クレジットを組織内の別のアカウントに移動し、受領アカウントが新しい所有者となる
  • 転送されたクレジットは受領アカウントの Credits ページに即座に表示
  • 転送時にクレジットレベルの共有設定は削除される (転送後に管理アカウントが新しい共有設定を構成可能)
  • 転送済みクレジットの再転送 (元の所有アカウントへの返却など) も可能
  • 分割と転送は独立した操作であり、分割のみ、転送のみの実行も可能
🧬 3. 分割クレジットの継承プロパティ
  • 有効期限: 分割しても有効期限は変更・延長されない
  • 対象サービス: 元のクレジットが Amazon EC2 のみに適用される場合、分割後も Amazon EC2 のみに適用
  • クレジットレベル共有設定: デフォルトで継承され、分割後に各クレジットごとに個別変更が可能
🧩 4. 既存のクレジット管理機能との組み合わせ
  • クレジットレベル共有: 分割クレジットごとに共有範囲を制御可能
  • クレジットの一時停止: 将来のプロジェクト用に確保したクレジットを一時停止し、必要なときに再開可能

🔧 技術仕様

🔐 操作権限

アクション 管理アカウント (支払いアカウント) メンバーアカウント (リンクされたアカウント)
✂️ 分割 (Split) 組織内の任意のクレジット 自身が所有するクレジットのみ
🚚 転送 (Transfer) 任意のクレジットを組織内の任意のアカウントへ ❌ 利用不可

アクセス制御には IAM アクション billing:SplitCredit および billing:TransferCredit を使用します。

📏 クォータと制限

項目制限
クレジットファミリーあたりの分割回数 (累計)100 回

クレジットファミリーとは、元のクレジットとそこから分割されたすべてのクレジット (分割クレジットからさらに分割されたものを含む) を指します。

💻 SplitCredit API のリクエスト例

Python SplitCredit API 
response = client.split_credit(
    creditId='string',
    portions=[
        {
            'amount': 'string',
            'description': 'string'
        },
    ],
    clientToken='string',
    dryRun=True|False
)

レスポンスには parentCreditId と分割後の childCredits (各クレジットの creditId と amount) が含まれます。 dryRun パラメータにより、実際に分割を実行する前に検証のみを行うことができます。

💻 TransferCredit API のリクエスト例

Python TransferCredit API 
response = client.transfer_credit(
    creditId='string',
    destinationAccountId='string',
    clientToken='string',
    dryRun=True|False
)

レスポンスには sourceCreditId、転送後の newCreditId、destinationAccountId、amount が含まれます。

✂️ ステップ 1: クレジットを分割する

1

AWS Billing and Cost Management コンソール を開く

2

ナビゲーションペインで [Credits] を選択する

3

対象のクレジットを選択して詳細ページを開く

4

[Split credit] を選択する

5

残高の分割方法を選択する。[Equal split] (新しいクレジット数を入力)、[Percentage]、[Amount] のいずれかを指定する

6

サマリーを確認し、分割を確定する。各新クレジットは $100 以上である必要があります

🚚 ステップ 2: クレジットを転送する

1

組織の管理アカウントでコンソールにサインインしていることを確認する

2

ナビゲーションペインで [Credits] を選択する

3

対象のクレジットを選択して詳細ページを開く

4

[Transfer] を選択する

5

クレジットを受け取るアカウントを選択する

6

転送を確定する。転送されたクレジットは、受領アカウントの [Credits] ページに即座に表示されます

🔍 ステップ 3: 分割・転送の追跡

クレジット詳細ページにはクレジットファミリーが表示されないため、どのクレジットがどの元クレジットから分割されたかを追跡するには、 Credits API の parentCreditId フィールド、または AWS CloudTrail の SplitCredit / TransferCredit イベントを使用します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓チャージバック作業の削減: 毎月の手作業が不要になり、数時間分の工数を削減
✓予測可能なクレジット予算: チームやビジネスユニットごとに正確な金額を事前に割り当て
✓公平なクレジット配分: クレジットを獲得したチームに確実に届けられる

🔬 技術面のメリット

✓API による自動化: コンソールに加え CLI と API で操作でき、配分の自動化が可能
✓dryRun による事前検証: 実行前に操作の妥当性を検証できる
✓CloudTrail との統合: イベント記録により監査証跡とファミリー追跡が可能
✓既存機能との組み合わせ: クレジットレベル共有や一時停止と柔軟に併用可能

🚧 制限事項

✗分割は恒久的で取り消し不可。分割したクレジットを 1 つに結合し直すことはできない
✗クレジットファミリーあたりの分割回数は累計 100 回まで。上限到達後はファミリー内のどのクレジットも分割不可
✗分割後の各クレジットは最低 $100 必要
✗転送は組織内に限定され、別の組織のアカウントには転送不可
✗メンバーアカウントは自身所有のクレジットの分割のみ可能で、転送は管理アカウントのみ

⚠️ 考慮すべき点

⚠転送時にクレジットレベルの共有設定が削除されるため、必要に応じて管理アカウントが再構成する
⚠転送先でクレジット共有が無効かつ使用量が不足していると、未使用分は有効期限に失効する
⚠元のクレジット ID を参照する自動化、予算、アラートは新しいクレジット ID への更新が必要
⚠分割前に配分を計画し、ファミリーを追跡しやすく 100 回のクォータ内に収めることを推奨

🔗 関連サービス・機能

🏢 AWS Organizations

分割・転送の対象は同一組織 (支払いアカウント配下) のアカウントに限定され、管理アカウントとメンバーアカウントで実行可能な操作が異なる。

🤝 クレジットレベル共有 (Credit-Level Sharing)

分割後の各クレジットに対して個別に共有範囲を設定でき、分割・転送と組み合わせて柔軟な配分が可能。

📜 AWS CloudTrail

SplitCredit / TransferCredit イベントが記録され、クレジットファミリーの追跡と監査に利用できる。

📊 AWS Cost and Usage Report

各分割クレジットは、使用量に適用された際に独自のクレジット ID を持つ個別の行項目として表示される。

📝 まとめ

クレジットの分割と転送により、FinOps チームは大型クレジットをチームやビジネスユニット単位の正確な予算として配分できるようになり、 毎月の手動チャージバック作業を排除できます。 分割は取り消し不可で最小 $100、ファミリーあたり累計 100 回までという制約があるため、分割前に配分計画を立てることが重要です。 大型クレジットを保有する組織は、AWS Billing コンソールまたは SplitCredit / TransferCredit API での運用を検討することを推奨します。
