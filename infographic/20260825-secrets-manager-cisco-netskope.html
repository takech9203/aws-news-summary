🔐 AWS Secrets Manager

Cisco Security Platform / Netskope の
マネージド外部シークレット対応

📅 リリース日: 2026 年 8 月 25 日 ｜ 機能: マネージド外部シークレットの対応パートナー拡大

📌 概要

AWS Secrets Manager のマネージド外部シークレットが拡張され、 新たに Cisco Security Platform (Security Cloud Control) の API キーと Netskope の API トークンに対応しました。 カスタムのローテーションコードを一切書くことなく、コンソールから直接これらのサードパーティ認証情報を保存し、 Lambda 関数不要で自動ローテーションできます。

両統合とも自己認証型 (self-authenticating) であり、 保存された認証情報自体がローテーションを承認するため、別途管理者認証情報を用意する必要はありません。

🤝 対応パートナー (計 13 パートナー)

🆕 Cisco Security Platform 🆕 Netskope BigID Confluent Cloud Datadog GitLab Jenkins MongoDB Atlas Okta Paddle Salesforce Snowflake SonarQube
❌ Before: アップデート前の課題
  • 各製品の API 仕様に合わせたカスタム Lambda ローテーション関数の開発・保守が必要
  • トークン再発行・検証ロジックの独自実装が必要で、実装ミスによる失効・漏洩リスク
  • ローテーションを自動化しないと長期間有効なトークンを使い続けることになり、ベストプラクティスに反する
✅ After: アップデート後の改善
  • Cisco のリフレッシュトークンを指定スケジュールで自動ローテーション (認証情報を常に有効に維持)
  • Netskope の SCIM API 経由で RBACv3 サービスアカウントの REST API トークンを自動ローテーション (完了前に新トークンを検証)
  • Lambda 関数のデプロイ・保守が不要。コンソールから数クリックで設定完了

Secrets Manager が Lambda 関数なしで Cisco / Netskope の API と直接連携して認証情報をローテーションし、 アプリケーションは常に最新の認証情報を GetSecretValue で取得します。 すべてのローテーション操作は CloudTrail に記録されます。

⚡ 主要機能

🛡️ 1. Cisco Security Platform API キーのマネージドローテーション
✓シークレットタイプ CiscoSecurityPlatformApiKey として保存
✓リフレッシュトークンをユーザー指定のスケジュールでローテーションし、Cisco が再発行する新トークンを取得して常に有効に維持
✓アプリケーションは Cisco の標準 OAuth パターンに従い、リフレッシュトークンを短期有効のアクセストークンに交換して利用
🛡️ 2. Netskope REST API トークンのマネージドローテーション
✓シークレットタイプ NetskopeApiToken として保存
✓Netskope の SCIM API を通じて RBACv3 サービスアカウントの REST API トークンをローテーション
✓ローテーション完了前に新規生成トークンを検証し、無効なトークンへの切り替えを防止
🔑 3. 自己認証型ローテーション
✓保存された認証情報自体がローテーションを承認する自己認証型の仕組み
✓ローテーション用の管理者認証情報 (スーパーユーザーシークレット) の保存・管理が不要
🚀 4. Lambda 不要のマネージドローテーション基盤
✓カスタムローテーション関数の作成・保守が不要。アカウント内に Lambda 関数はデプロイされない
✓コンソールでのシークレット作成時にローテーションがデフォルトで有効化
✓アクセス許可管理、可観測性、ガバナンス、コンプライアンス、DR など Secrets Manager の全機能セットを利用可能

必要な権限

ローテーションを正常に機能させるには、Secrets Manager にシークレットのライフサイクルを管理するための権限を付与する必要があります。 詳細は Security and Permissions を参照してください。

🛠️ 設定方法

前提条件

✓AWS アカウントと Secrets Manager へのアクセス権限 (シークレットの作成・ローテーション設定権限)
✓Cisco Security Platform の API キー、または Netskope の RBACv3 サービスアカウントの REST API トークン
✓Secrets Manager がシークレットのライフサイクルを管理するための権限設定
1
マネージド外部シークレットの作成

コンソールで Secrets Manager を開き、[新しいシークレットを保存する] を選択。シークレットタイプとして統合パートナー (Cisco または Netskope) を選択し、パートナー定義フォーマットに従って認証情報とローテーションメタデータを入力します。コンソール作成時にはローテーションがデフォルトで有効化されます。

2
ローテーションスケジュールの設定
Bash ローテーションスケジュールの確認・更新の例 
# ローテーションスケジュールの確認・更新の例
aws secretsmanager rotate-secret \
  --secret-id MyCiscoApiKeySecret \
  --rotation-rules "ScheduleExpression=rate(30 days)"

この例では 30 日ごとにローテーションを実行するよう指定。Cisco はリフレッシュトークン、Netskope は REST API トークンがスケジュールに従い自動的に再発行されます。

3
アプリケーションからのシークレット取得
Bash 最新のシークレット値を取得 
# 最新のシークレット値を取得
aws secretsmanager get-secret-value \
  --secret-id MyCiscoApiKeySecret \
  --query SecretString

アプリケーションは GetSecretValue API で常に最新の認証情報を取得。Cisco の場合、取得したリフレッシュトークンを Cisco の OAuth エンドポイントで短期有効のアクセストークンに交換して API を呼び出します。

💡 メリット

📈 ビジネス面
✓運用コスト削減: カスタムローテーション Lambda 関数の開発・テスト・保守が不要になり、セキュリティ運用の工数を削減
✓セキュリティ体制の強化: 定期的な自動ローテーションで、長期有効トークンの放置による漏洩リスクを低減
✓コンプライアンス対応: CloudTrail の完全な監査ログで、ローテーション履歴を証跡として提示可能
⚙️ 技術面
✓Lambda 不要のローテーション: VPC 設定やランタイム更新などの管理オーバーヘッドがない
✓自己認証型の設計: 管理者認証情報を別途保存する必要がなく、管理するシークレット数を最小化
✓標準化されたフォーマット: 事前定義されたシークレットフォーマットで実装のばらつきや設定ミスを防止

⚠️ デメリット・制約事項

🚧 制限事項
✗対応は各パートナー定義の特定シークレットタイプのみ (Cisco: CiscoSecurityPlatformApiKey / Netskope: NetskopeApiToken)
✗Netskope のローテーション対象は RBACv3 サービスアカウントの REST API トークンで、SCIM API 経由での操作が前提
✗マネージド外部シークレットがサポートされているリージョンでのみ利用可能
🤔 考慮すべき点
⚠Cisco 統合では、リフレッシュトークンを短期アクセストークンに交換する OAuth フローの実装がアプリケーション側で引き続き必要
⚠ローテーション後に古いトークンは無効化されるため、キャッシュに依存せず Secrets Manager から最新値を取得する設計が必要
⚠既存のカスタム Lambda ローテーションからの移行では、シークレットタイプと保存フォーマットの変更が必要

💰 料金・利用可能リージョン

💵 料金

マネージド外部シークレットの利用に追加料金なし。 AWS Secrets Manager の標準料金体系 (シークレットごとの月額料金 + API 呼び出しごとの料金) が適用されます。 最新の料金は 料金ページを参照してください。

🌍 利用可能リージョン

AWS Secrets Manager のマネージド外部シークレットがサポートされているすべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

→AWS Lambda: 従来のカスタムローテーションで必要だったが、マネージド外部シークレットではデプロイ不要
→AWS CloudTrail: すべてのローテーション操作・シークレット値更新・管理操作を記録し、監査証跡を提供
→AWS IAM: シークレットごとのきめ細かなアクセス許可管理を実現
→AWS KMS: Secrets Manager に保存されるシークレット値の暗号化に使用

📝 まとめ

Cisco Security Platform と Netskope のマネージド外部シークレット対応により、主要なセキュリティ製品の API 認証情報を Lambda 関数なしで自動ローテーションできるようになりました。 これらの製品の API トークンをカスタムコードや手動運用で管理している場合は、マネージド外部シークレットへの移行を検討し、 認証情報管理の標準化とセキュリティ体制の強化を進めることを推奨します。
