📋 概要

Amazon Bedrock AgentCore Runtime に、新しい InvokeAgentRuntimeCommandShell API を通じたインタラクティブシェル機能が追加されました。実行中のエージェントセッション内の分離された microVM に対して、WebSocket 経由で永続的な PTY バック付きターミナルセッションを直接開くことが可能になります。

Claude Code、OpenAI Codex、Amazon Kiro などのコーディングエージェントを AgentCore Runtime 上でホストする開発者にとって重要なアップデートです。カラー表示、タブ補完、Ctrl+C、ターミナルリサイズ、ネットワーク切断時の自動再接続といった完全なターミナル体験を提供します。

⚡ 主要機能

🔗 永続的インタラクティブシェル

WebSocket 経由で microVM 内のシェルプロセスに永続的に接続。環境変数、作業ディレクトリ、コマンド履歴がセッション内で保持されます。バイナリフレームによる生のターミナル I/O ストリーミングで、カラー、カーソル制御、フルスクリーンアプリに対応。

🔄 再接続サポート

session_id と shellId を保持することで同じシェルに再接続可能。短時間のネットワーク切断は自動再接続し、再接続時に最大 256 KB の最近の出力を再生します。SDK の ReconnectConfig による自動再接続設定も利用可能。

📟 複数同時シェルセッション

1 つのランタイムあたり最大 10 個の同時シェルセッション。同一または異なる microVM に対して複数ターミナルを開放でき、エージェントが異なるブランチで並行作業する様子を監視できます。

🔐 認証とセキュリティ

デフォルト AWS 認証情報、事前署名 URL、OAuth ベアラートークンの 3 種類の認証方式をサポート。各セッションは分離された microVM で実行され、CloudTrail / CloudWatch Logs による監査ログを記録。

🚀 設定方法

前提条件

  • bedrock-agentcore:InvokeAgentRuntimeCommandShell IAM 権限が付与されていること
  • AgentCore Runtime エンドポイント ARN があり、ランタイムが READY 状態であること
  • 2026 年 6 月 5 日以降にデプロイされたエージェント

Step 1: CLI でインタラクティブシェルを開く

Bash AgentCore CLI 
agentcore exec --it --runtime <runtime-arn> --region us-west-2

Step 2: シェルからデタッチ・再接続

ターミナル内で Ctrl+] を押すとシェルを閉じずにデタッチ。再接続コマンド:

Bash 再接続コマンド 
agentcore exec --it \
  --runtime <runtime-arn> \
  --region us-west-2 \
  --session-id <uuid> \
  --shell-id <id>

Step 3: Python SDK でプログラム的に操作

Python シェルセッションを開く 
import asyncio
from bedrock_agentcore.runtime import AgentCoreRuntimeClient, ShellChannel

async def main():
    runtime_arn = "arn:aws:bedrock-agentcore:us-west-2:123456789012:runtime/my-agent"
    client = AgentCoreRuntimeClient(region="us-west-2")

    async with client.open_shell(runtime_arn) as shell:
        print(f"Connected. Shell ID: {shell.shell_id}")
        await shell.send("echo Hello from AgentCore Shell\n")

        async for frame in shell:
            if frame.channel == ShellChannel.STDOUT:
                print(frame.text, end="")
                if "Hello from AgentCore Shell" in frame.text:
                    break

asyncio.run(main())

Step 4: 自動再接続を設定

Python ReconnectConfig による自動再接続 
import asyncio
from bedrock_agentcore.runtime import AgentCoreRuntimeClient, ReconnectConfig, ShellChannel

async def on_reconnect(reconnected: bool):
    print(f"Reconnected: {reconnected}")

async def main():
    runtime_arn = "arn:aws:bedrock-agentcore:us-west-2:123456789012:runtime/my-agent"
    config = ReconnectConfig(max_retries=5, base_delay=0.5, on_reconnect=on_reconnect)

    client = AgentCoreRuntimeClient(region="us-west-2")
    async with client.open_shell(runtime_arn, shell_id="my-shell", reconnect_config=config) as shell:
        await shell.send("long-running-command\n")
        async for frame in shell:
            if frame.channel == ShellChannel.STDOUT:
                print(frame.text, end="")

asyncio.run(main())

✅ メリット

ビジネス面

📈 開発生産性の向上

  • コーディングエージェントがローカルターミナルと同等のインタラクティブ体験で動作
  • ネットワーク切断後も自動再接続により作業が中断されない
  • 最大 10 個の同時シェルで複数エージェントを並行監視可能

技術面

⚙️ 技術的優位性

  • 環境変数、作業ディレクトリ、コマンド履歴がセッション内で保持
  • 各セッションが分離された microVM 内で実行されセキュアな分離を実現
  • AWS 認証情報、事前署名 URL、OAuth トークンの 3 種類の認証をサポート

⚠️ デメリット・制約事項

📌 制限事項

  • ランタイムあたり同時シェル数は最大 10 個に制限
  • 最大接続時間は 1 時間で、それ以降は再接続が必要
  • フレームペイロードサイズは 64 KB が上限
  • フレームレートは 250 フレーム/秒に制限
  • 再接続バッファは 256 KB まで
  • 2026 年 6 月 5 日以前のエージェントは再デプロイが必要

🔍 考慮すべき点

  • ターミナル I/O の内容はサービス側でログ記録されないため、独自の監査メカニズムが必要な場合がある
  • シェルコマンドはコンテナのファイルシステムと認証情報にフルアクセスを持つため、IAM ポリシーによるアクセス制御が重要
  • デタッチされたセッションは 10 セッション上限にカウントされるため、不要なセッションは明示的にクローズする

💡 ユースケース

🤖 コーディングエージェントのターミナルアクセス

Claude Code や Amazon Kiro などの AI コーディングエージェントが、AgentCore Runtime 上でコードの記述、実行、テストを反復的に実行。シェル状態を保持したまま反復的に開発を行えるため、各ステップでのコンテキスト再構築が不要になり効率が大幅向上。

🐛 インタラクティブデバッグ

エージェントの実行環境で予期しないエラーが発生した際に、開発者がリアルタイムで環境を調査。ローカルターミナルと同じ感覚でリモート環境をデバッグでき、問題の特定と解決が迅速に行える。

⏱️ 長時間実行プロセスの監視

機械学習モデルのトレーニングなど、長時間実行されるプロセスを開始し、定期的に進捗を確認。再接続機能により、ネットワーク切断や作業中断があっても同じシェルに戻り、継続的に監視可能。

💰 料金

インタラクティブシェル機能の料金は、AgentCore Runtime の使用量に基づきます。シェル接続自体に追加料金は発生しませんが、microVM の稼働時間に応じた課金が適用されます。
