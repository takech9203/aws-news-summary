📋 概要

2026 年 10 月 23 日、Kiro の Changelog に 2 件のアップデートが公開されました。

1️⃣ Claude Haiku 5.5 の提供開始 (Experimental)

MCP ツールが追加入力を求められる MCP Elicitation、Workflows の開始頻度やプラン修正の制御強化、/memories からのメモリ削除、/model edit によるモデルピッカー編集など、多数の改善・修正を含むリリース。

🔄 Before / After

❌ アップデート前の課題

  • 高速・軽量タスク向けの最新世代 Claude モデルがなく、小規模リクエストにも相対的に高いクレジット倍率のモデルが必要
  • MCP ツールが追加情報を必要とすると、呼び出しを中断して手動で情報を渡し、やり直しが必要
  • V3 ワークフロープランは承認か拒否のみで、修正ができなかった
  • /memories で確認はできても CLI から削除できなかった
  • /model ピッカーに使わないモデルも常に表示
  • ヘッドレスモードが対話セッションの MCP サインインを再利用できなかった
  • 再起動後に V3 Workflows が再プランニングや完了済みステップの再実行を行うことがあった

✅ アップデート後の改善

  • Haiku 5.5 により 1M トークンコンテキストと低いクレジット倍率 (0.06x) で高速・大量処理が可能に
  • MCP ツールが実行を中断せずフォームやリンクで追加入力を受け取り、やり直しなしで継続
  • プラン承認時に修正案を直接入力し、ステップ実行前に反映
  • /memories でメモリを選択して Ctrl+D で削除
  • /model edit で不要なモデルを非表示に (ID 指定では利用可能)
  • Workflow use 設定でワークフローの開始頻度を選択可能に
  • V3 Workflows が再起動後に再プランニングなしで再開

⚡ 主要機能

🧠 1. Claude Haiku 5.5 の提供開始 (Experimental)

  • Kiro IDE、CLI、Crew、Web で experimental サポートとして利用可能
  • 対象は us-east-1 (IAD) および eu-central-1 (FRA) の Pro、Pro+、Pro Max、Power プラン顧客
  • 高速なレスポンスが求められる大量処理向けに設計、1M トークンのコンテキストウィンドウ
  • クレジット倍率: 100K トークンまで 0.06x / 100K トークン超 0.3x
  • 最新モデルリストの読み込みには IDE / CLI の再起動、kirocrew restart、ブラウザ更新が必要

🔌 2. MCP Elicitation: MCP ツールが入力を求められるように (CLI 2.34.0)

  • ローカル V3 セッションで、MCP ツールが追加情報を必要とする際に一時停止し、フォームまたはリンクを表示
  • 情報の入力、別ページでのアクション完了、リクエストの拒否を選択可能
  • ツールは呼び出しをやり直すことなく処理を継続

🔁 3. Workflow 制御の強化 (CLI 2.34.0)

  • プランの事前修正: 承認画面で修正案を直接入力すると、ステップ実行前にプランへ反映
  • Workflow use 設定: Only when asked / Only for large tasks / As much as possible から開始頻度を選択
  • ワークフローリカバリー: 再起動後に再プランニングや完了済みステップの繰り返しなしで再開

🗂️ 4. メモリ削除とモデルピッカー編集 (CLI 2.34.0)

  • /memories でメモリを選択し Ctrl+D を押すと削除
  • /model edit で使用しないモデルをピッカーから非表示に (非表示モデルも ID では利用可能)

🔒 5. セキュリティ・承認フローの改善 (CLI 2.34.0)

  • --trust-workspace フラグで、選択を保存せずに 1 回の起動だけ信頼プロンプトをスキップ
  • ツール承認画面で Allow once / Deny once が先頭に表示
  • セッションダッシュボードでセッション削除前に確認を要求
  • 解析できない不明瞭なシェルコマンドは承認を求めず拒否
  • V3 サブエージェントが親エージェントのインライン MCP サーバーを受け取らないよう境界を強化
  • リモート MCP サーバーが HTTP 経由で同一オリジンのリダイレクトのみ追従

🛠️ 6. その他の修正 (CLI 2.34.0 / 全 18 件の Fixes)

  • ツール呼び出し準備中の一時停止時に Working... を表示
  • ヘッドレスモードが自動応答や信頼されていないツールの承認を行わないよう修正、保存済み MCP サインインを再利用
  • 保存済みセッションが多数ある場合でも /sessions がフリーズせず開閉・スクロール可能
  • /usage がエンタープライズの超過ステータスと消費クレジットを表示
  • モデル拒否後も部分的な応答を保持し、フォールバックモデルが続きから継続
  • アクセシビリティ改善 (罫線・ブロック文字の抑制、矢印キーの読み上げ)、Mermaid 描画の改善
  • /rewind の分岐位置修正、kiro-cli acp のシャットダウン問題修正
  • /agent 切り替え時の Skills 読み込み、macOS サンドボックスでの ssh 動作、Windows でのワークスペース外ファイル削除など

⚙️ 設定方法

📌 前提条件

✓Kiro のアカウントを保有 (Haiku 5.5 の利用には us-east-1 または eu-central-1 の Pro 以上のプランが必要)
✓CLI 2.34.0 の新機能を利用する場合は Kiro CLI 2.34.0 以降
✓MCP Elicitation、Workflow 制御などの機能はローカル V3 セッションが対象

ステップ 1: 最新のモデルリストを読み込む

Bashモデルリストの再読み込み
# CLI の場合: CLI を再起動する
kiro-cli

# Crew の場合: Crew を再起動する
kirocrew restart

IDE または CLI を再起動すると、Claude Haiku 5.5 を含む最新のモデルリストが読み込まれます。Web の場合はブラウザでページを更新します。

ステップ 2: モデルピッカーを整理して Haiku 5.5 を選択する

BashV3 セッション内で実行
# モデルピッカーを編集する
/model edit

# モデルを切り替える
/model

/model edit で使用しないモデルを非表示にできます。非表示にしたモデルも ID 指定では引き続き利用可能です。整理後、/model で Claude Haiku 5.5 を選択します。

ステップ 3: ワークフローの開始頻度を設定する

🙋 Only when asked
求められた時のみ
→
📦 Only for large tasks
大きなタスクのみ
→
🚀 As much as possible
可能な限り

CLI のチャット設定から Workflow use を開き、チームの運用方針に合わせてワークフローの自動開始の度合いを制御できます。

ステップ 4: 不要なメモリを削除する

BashV3 セッション内で実行
# メモリ一覧を開く
/memories

削除したいメモリを選択して Ctrl+D を押すと削除できます。

💡 メリットと制約事項

✅ メリット

  • コスト効率の向上: 低いクレジット倍率 (100K トークンまで 0.06x) で定型的・大量タスクを処理
  • 運用統制の強化: Workflow use 設定とプランの事前修正で自動実行の度合いを組織方針に合わせて制御
  • データ管理の改善: 不要なメモリを CLI から削除し、記憶させる情報を整理
  • MCP ツールの対話性向上: Elicitation により呼び出しのやり直しなしで処理を継続、ツール設計の自由度が向上
  • 大規模コンテキストの活用: 1M トークンで大きなコードベースやログを高速処理
  • 堅牢性・アクセシビリティ向上: ワークフローリカバリー、ヘッドレスモードの安全性強化、スクリーンリーダー対応改善

⚠️ 制約・考慮点

  • Haiku 5.5 は Experimental 提供のため、本番ワークロードでの利用には注意が必要
  • 対象は us-east-1 (IAD) / eu-central-1 (FRA) の Pro 以上のプラン顧客に限定
  • MCP Elicitation はローカル V3 セッションが対象
  • 100K トークン超はクレジット倍率が 0.3x に上がるため、コンテキストサイズに応じたコスト設計が必要
  • モデルリスト反映には再起動 / kirocrew restart / ブラウザ更新が必要
  • 解析できないシェルコマンドは承認を求めず拒否されるため、複雑なコマンド運用では挙動変化に注意
  • サブエージェントで MCP サーバーが必要な場合は個別の設定が必要
  • --trust-workspace は信頼を保存しないため、毎回の起動で指定が必要

🎯 ユースケース

💰 ユースケース 1: 大量の軽量タスクのコスト最適化

シナリオ: Pro Max プランの開発チームが、コードレビューコメントの下書きやログの要約など、高速応答が求められる軽量タスクを大量に処理したい。

  1. IDE / CLI を再起動して Claude Haiku 5.5 を含む最新のモデルリストを読み込む
  2. /model edit で使用しないモデルを非表示にし、ピッカーを整理
  3. 軽量タスクでは Haiku 5.5 (0.06x) を選択し、複雑なタスクでは上位モデルを選択
✅ 効果: タスクの性質に応じたモデルの使い分けにより、クレジット消費を抑えながら処理速度を向上できる。

🔌 ユースケース 2: 追加入力が必要な MCP ツールの統合

シナリオ: 社内の MCP ツールがチケット作成時に担当者や優先度などの追加情報を必要とするが、従来はツール呼び出しを中断して情報を渡し直す必要があった。

  1. Kiro CLI を 2.34.0 以降に更新
  2. ローカル V3 セッションで MCP ツールを呼び出す
  3. ツールが表示するフォームに担当者・優先度を入力し、処理を継続
✅ 効果: ツール呼び出しのやり直しが不要になり、対話的な MCP ツールをスムーズに利用できる。

🔁 ユースケース 3: ワークフロー実行の段階的導入

シナリオ: チームで V3 Workflows を導入したいが、最初は限定的に使い、慣れてきたら適用範囲を広げたい。

  1. 導入初期は Workflow use を Only when asked に設定
  2. プラン承認時に修正案を直接入力し、実行前にプランを調整
  3. 運用が安定したら Only for large tasks や As much as possible へ段階的に変更
✅ 効果: ワークフローの自動開始の度合いを段階的に制御しながら、プラン修正機能で実行内容の精度を高められる。
