AWS Security Hub Amazon RDS

🛡️ Security Hub Network Scanning が Amazon RDS DB インスタンスのスキャンに対応

📅 リリース日: 2026 年 11 月 16 日 | 🔍 インターネットからの実プローブで RDS の到達性を検証

📝 概要

AWS Security Hub の Network Scanning が Amazon RDS DB インスタンスのスキャンに対応しました。アカウント内の既存および新規の RDS DB インスタンスを自動的に検出し、パブリックアクセスが有効なインスタンスをインターネット側から実際にプローブします。到達可能なポートが見つかると、インスタンスとポートの詳細を含む検出結果 (Finding) を作成します。

設定からの推定にとどまらず、「実際に到達できるか」を検証する点が特長です。検出結果は Security Hub Exposures によって他の検出結果やリソース設定と相関分析され、より広範なリスク評価に活用されます。Network Scanning 有効化済みの環境では、RDS スキャンが自動的に有効化されるため追加設定は不要です。

😰 Before: アップデート前の課題

  • Network Scanning の対象は EC2、Elastic IP、ロードバランサーなどに限られ、RDS のインターネット到達性を実スキャンで検証できなかった
  • 設定からリスクを推定できても、実際の到達可否確認には手動テストや外部ツールが必要だった
  • データベースの意図しない公開は情報漏えいに直結するにもかかわらず、継続的かつ自動的な到達性検証の仕組みが不足していた

😊 After: アップデート後の改善

  • RDS DB インスタンスを自動検出し、パブリックアクセスが有効なインスタンスをインターネット側から実際にスキャンして到達性を検証
  • 到達可能なポートごとに検出結果が作成され、Security Hub 上で確認・調査が可能に
  • Security Hub Exposures が他の検出結果やリソース設定と相関分析し、広範なリスク評価を実現
  • 有効化済みユーザーには RDS スキャンが自動有効化され、追加設定なしで保護範囲が拡大

Network Scanning は AWS 所有の IP アドレスからインターネット経由で RDS DB インスタンスの DNS 名を解決してプローブし、実際に到達可能なポートを検出して Security Hub に検出結果を作成します。パブリックアクセスが無効なインスタンスはスキャン対象外です。

⚡ 主要機能

🔎 1. RDS DB インスタンスの自動検出とスキャン
  • アカウント内の既存および新規の RDS DB インスタンスを自動的に検出
  • パブリックアクセスが設定されているインスタンスのみをスキャン対象とする
  • DB インスタンスの DNS 名を解決してスキャンを実行
  • 有効化後、既存リソースは約 24 時間以内にスキャン、新規リソースは作成通知の受信後すみやかにスキャン
  • アクティブなリソースは約 12 時間ごとに再スキャンされ、到達性の変化を検出
📋 2. 到達可能ポートごとの検出結果の作成
  • 到達可能なポートごとに、インスタンスとポートの詳細を含む検出結果を OCSF 形式で作成
  • 開いているポートがない場合は重要度 Informational の検出結果を作成し、スキャン済みであることを確認可能
  • エンドポイントのポート変更時は再スキャンして新旧の検出結果を更新、パブリックアクセス無効化時はすべての検出結果をクローズ
🔌 3. エンジン固有ポートのスキャン

DB インスタンスエンドポイントのポートに加え、エンジン固有の既知ポートもスキャンします。

🔗 4. Security Hub Exposures との連携
  • Network Scanning の検出結果を他の検出結果やリソース設定と相関分析
  • 単なるポート到達性の報告にとどまらず、より広範なリスク評価を実現

🛠️ 設定方法

前提条件

✓AWS Security Hub が有効化されていること
✓Network Scanning を有効化する権限 (個別アカウント、または組織の委任管理者による設定ポリシー) があること
✓スキャン対象とする RDS DB インスタンスにパブリックアクセスが設定されていること (スキャン対象の条件)

手順

1
Network Scanning の有効化
BashAWS CLI
aws securityhub enable-security-hub-feature-v2 --feature-name NETWORK_SCANNING

コンソールの場合は、Security Hub コンソールの [General settings] から [Network Scanning] セクションで [Enable] を選択し、アクティブスキャンの承認を確認します。組織全体で有効化する場合は、設定ポリシーの作成または編集で Network Scanning を有効化します。すでに有効化済みの場合、RDS スキャンは自動的に有効化されるためこのステップは不要です。

2
RDS DB インスタンスのパブリックアクセス設定の確認
BashAWS CLI
aws rds describe-db-instances \
  --query "DBInstances[?PubliclyAccessible==\`true\`].[DBInstanceIdentifier,Endpoint.Address,Endpoint.Port]" \
  --output table

アカウント内でパブリックアクセスが有効になっている RDS DB インスタンスの一覧を表示します。これらのインスタンスが Network Scanning のスキャン対象となります。

3
検出結果の確認と対応

Security Hub コンソールで Network Scanning の検出結果を確認します。到達可能なポートが検出された RDS DB インスタンスについては、意図した公開かどうかを調査し、不要な場合はパブリックアクセスの無効化やセキュリティグループの見直しを行います。パブリックアクセスを無効化すると、そのインスタンスのすべての検出結果がクローズされます。

4
スキャン除外設定 (必要な場合)
BashAWS CLI
aws rds add-tags-to-resource \
  --resource-name arn:aws:rds:ap-northeast-1:123456789012:db:my-db-instance \
  --tags Key=SecurityHubNetworkScanExclusion,Value=""

タグキー SecurityHubNetworkScanExclusion を付与すると以降のスキャンが停止し、アクティブな検出結果がクローズされます。タグを削除すると再びスキャン対象になります。

💡 メリット

💼 ビジネス面

✓データ漏えいリスクの低減: 機密データを保持するデータベースの意図しないインターネット公開を早期に検出し、情報漏えいにつながるリスクを低減できる
✓追加コストなし: Network Scanning は Security Hub Essentials に追加料金なしで含まれており、コストを増やさずにデータベースの露出監視を強化できる
✓コンプライアンス対応の強化: データベースのインターネット到達性を継続的に検証する仕組みにより、セキュリティ監査やコンプライアンス要件への対応を支援

⚙️ 技術面

✓実到達性に基づく検証: 設定からの推定ではなく、インターネットからの実際のプローブにより到達性を検証するため、誤検知が少なく実態に即した結果が得られる
✓自動検出と継続的スキャン: 新規 RDS DB インスタンスを自動的に検出し、約 12 時間ごとに再スキャンするため、構成変更による露出の変化を継続的に監視できる
✓運用負荷の最小化: Network Scanning 有効化済みの環境では RDS スキャンが自動的に有効化され、追加の設定やエージェント導入が不要
✓リスクの相関分析: Security Hub Exposures が到達性の検出結果を他の検出結果と相関分析し、優先度付けされたリスク評価を提供

⚠️ デメリット・制約事項

制限事項

✗スキャン対象はパブリックアクセスが有効な RDS DB インスタンスのみ (プライベートなインスタンスはスキャンされない)
✗IPv4 アドレスのみ対応 (IPv6 は現時点で未対応)
✗一時的または短命なリソースは、終了前にスキャンされない場合がある
✗スキャン対象ポートはエンドポイントポートとエンジン固有の既知ポートに限られる

考慮すべき点

⚠️有効化により、TCP ポート接続試行、アプリケーション / プロトコル識別、サービスバナーや TLS 証明書メタデータの収集を含むアクティブスキャンを Security Hub に許可することになる
⚠️設定ポリシーで有効化された場合、メンバーアカウント側で機能を無効化できない
⚠️Network Scanning を無効化しても既存の検出結果は即座にクローズされず、通常のライフサイクルに従って期限切れになるまで表示される
⚠️ポートが断続的に到達可能な場合、検出結果はスキャン時点の肯定的な証拠に基づいて作成される

🎯 ユースケース

1️⃣ 意図しないパブリック公開データベースの検出

シナリオ: 開発チームが検証目的で RDS DB インスタンスのパブリックアクセスを有効化したまま放置しており、セキュリティチームが組織全体でこうしたインスタンスを把握できていない。

Bash実装例
# 組織全体で Network Scanning を有効化する設定ポリシーを適用後、
# 到達可能ポートが検出された RDS インスタンスの検出結果を Security Hub で確認
aws securityhub enable-security-hub-feature-v2 --feature-name NETWORK_SCANNING
✅ 効果: インターネットから実際に到達可能なデータベースポートが検出結果として可視化され、セキュリティチームは意図しない公開を特定してパブリックアクセスの無効化などの是正措置を迅速に実施できる。
2️⃣ 組織全体のアタックサーフェス管理

シナリオ: マルチアカウント環境を運用する企業が、EC2、ロードバランサーに加えてデータベースを含むインターネット露出リソースの全体像を一元的に把握したい。

実装例:

  • 1. 委任管理者アカウントで Security Hub の設定ポリシーを編集
  • 2. Network Scanning 機能を組織のすべてのアカウントとリージョンで有効化
  • 3. Security Hub Exposures で相関分析されたリスクを確認し、優先度順に対応
✅ 効果: EC2、EIP、ロードバランサー、RDS を含むインターネット到達可能リソースが統一されたビューで可視化され、組織全体のアタックサーフェスを継続的に管理できる。
3️⃣ 構成変更による露出の継続監視

シナリオ: 運用チームによるセキュリティグループやエンドポイントポートの変更により、これまで非公開だったデータベースが意図せずインターネットに露出することを防ぎたい。

実装例:

  • 1. Network Scanning を有効化 (約 12 時間ごとの再スキャンと変更時の再スキャンが自動実行)
  • 2. EventBridge で Security Hub の検出結果をトリガーに通知を設定
  • 3. 新たな到達可能ポートの検出時にセキュリティチームへ自動通知
✅ 効果: コントロールプレーンの変更やポート変更が発生しても再スキャンにより露出の変化が検出され、意図しない公開を早期に発見して対応できる。

💰 料金・利用可能リージョン

💵 料金

Network Scanning は Security Hub Essentials に追加料金なしで含まれています。RDS DB インスタンスのスキャンについても追加コストは発生しません。

🌍 利用可能リージョン

Security Hub をサポートするすべての AWS 商用リージョンおよび AWS GovCloud (US) リージョンで利用可能です。リージョンの一覧は AWS Regional Services List を参照してください。

📌 まとめ

AWS Security Hub の Network Scanning が RDS DB インスタンスに対応したことで、機密性の高いデータベースのインターネット露出を実際のプローブに基づいて継続的に検証できるようになりました。Network Scanning を有効化済みの環境では自動的に RDS スキャンが有効化されるため、まずは Security Hub で RDS 関連の検出結果を確認し、意図しないパブリックアクセス設定がないかを点検することを推奨します。まだ Network Scanning を利用していない場合は、追加料金なしで利用できるため、組織全体での有効化を検討する価値があります。
