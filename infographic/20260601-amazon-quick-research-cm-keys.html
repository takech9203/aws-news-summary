Amazon Quick Research

🔐 カスタマーマネージドキー (CMK) サポート

2026 年 6 月 1 日

📋 概要

Amazon Quick Research が AWS KMS を通じたカスタマーマネージドキー (CMK) によるデータ暗号化をサポート。厳格なセキュリティおよびコンプライアンス要件を持つ組織が、自社で暗号化キーを管理しながら AI リサーチエージェントを活用できるようになりました。

Amazon Quick Research は、組織の内部ナレッジと公開インターネットデータを統合し、エキスパートレベルのインサイトを迅速に提供する AI エージェントです。金融機関や医療機関など、データの暗号化管理に厳しい要件を持つ業界でも安心して利用可能になりました。

15 分 キーアクセス取り消し時間
対称キー サポートキータイプ
CloudTrail 全アクセス監査

🔄 Before / After

❌ Before

  • AWS マネージドキーのみ、独自キー使用不可
  • キーアクセス即時取り消し手段なし
  • 自社管理キー必須の組織は採用困難
  • 暗号化キー使用状況の監査が限定的

✅ After

  • 自社 KMS キーでデータ暗号化可能
  • 15 分以内でキーアクセス取り消し可能
  • CloudTrail で全データアクセス追跡可能
  • 複数 CMK サポート、リージョンごとにデフォルトキー設定可能

⚡ 主要機能

🔑 カスタマーマネージドキーによる暗号化

自社の AWS KMS キーを使用して Quick Research のデータを暗号化。対称 KMS キーのみサポート。同一アカウント・リージョンにキーを作成する必要あり。

📋 包括的な監査機能

CloudTrail 統合で全データアクセスを追跡。キー使用状況の可視化とコンプライアンスレポート作成に必要な証跡の自動記録。

🚨 迅速なキーアクセス取り消し

セキュリティインシデント発生時に 15 分以内でキーアクセスを無効化。侵害されたキーの即時失効によるデータ保護。

🗂️ 複数キーのサポート

AWS アカウント・リージョンごとに 1 つのデフォルトキーを設定。用途やデータ分類に応じたキーの使い分けが可能。

🛠️ 設定方法

前提条件

✓AWS KMS で対称キーが作成済みであること
✓キーが Quick Research リソースと同じ AWS アカウント・リージョンに存在すること
✓Quick Research サービスに対するキーポリシーが適切に設定されていること

ステップ 1: KMS 対称キーの作成

Bash KMS キー作成 
aws kms create-key \
  --key-spec SYMMETRIC_DEFAULT \
  --key-usage ENCRYPT_DECRYPT \
  --description "Quick Research encryption key" \
  --region us-east-1

ステップ 2: キーポリシーの設定

Bash キーポリシー適用 
aws kms put-key-policy \
  --key-id <key-id> \
  --policy-name default \
  --policy file://quick-research-key-policy.json

KMS キーポリシー設定例

JSON quick-research-key-policy.json 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowQuickResearchEncryption",
      "Effect": "Allow",
      "Principal": {
        "Service": "quick.amazonaws.com"
      },
      "Action": [
        "kms:Encrypt",
        "kms:Decrypt",
        "kms:GenerateDataKey",
        "kms:DescribeKey"
      ],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "aws:SourceAccount": "123456789012"
        }
      }
    }
  ]
}

ステップ 3: Quick Research での CMK 設定

Quick Research コンソールまたは API を使用して、作成した KMS キーをデフォルトの暗号化キーとして設定します。暗号化設定ページから KMS キー ARN を指定します。

⚖️ メリット・デメリット

✅ ビジネス面のメリット

✓HIPAA, PCI DSS, SOC 2 などの規制要件を満たす暗号化キー管理
✓インシデント時 15 分以内でデータアクセス遮断可能
✓CloudTrail による自動監査証跡で監査対応工数を削減

✅ 技術面のメリット

✓キーの作成、ローテーション、無効化を自社で完全制御
✓IAM + KMS キーポリシーの組み合わせによる多層防御
✓すべてのキー使用操作が CloudTrail に自動記録

⚠️ 制限事項

✗対称 KMS キーのみ (非対称キー使用不可)
✗同一アカウント・リージョンにキー作成が必要
✗デフォルトキーはアカウント・リージョンあたり 1 つ
✗クロスアカウントでのキー共有は非対応

⚠️ 考慮すべき点

!KMS キー削除/無効化でデータアクセス不可能に
!キーポリシー誤設定でサービス停止リスク
!KMS API 呼び出しに対する追加コスト発生
!キーローテーション時の再暗号化プロセス確認必要

💡 ユースケース

🏦 金融機関のマーケットリサーチ

大手金融機関のリサーチチームが市場分析に Quick Research を活用。金融規制により暗号化キーの自社管理が必須の環境で、PCI-DSS 準拠のキーを使用。

Bash 金融規制準拠キー作成 
aws kms create-key \
  --key-spec SYMMETRIC_DEFAULT \
  --key-usage ENCRYPT_DECRYPT \
  --description "Financial research - regulatory compliance" \
  --tags '[{"TagKey":"Compliance","TagValue":"PCI-DSS"}]'

効果: 金融規制に準拠しながら AI リサーチ機能を活用し、市場分析の効率を 90% 以上向上。

💊 医薬品企業の特許調査

製薬企業が Quick Research を使用して特許調査を実施。研究データの機密性確保のため自社管理の暗号化とキーローテーションを活用。

Bash 研究データ用キー作成 
aws kms create-key \
  --key-spec SYMMETRIC_DEFAULT \
  --description "Pharma patent research encryption"

aws kms enable-key-rotation --key-id <key-id>

効果: 機密研究データを保護しながら、PubMed データや特許情報を活用した包括的な調査を実現。

🚨 セキュリティインシデント対応

データ侵害の疑い検知時に、Quick Research に保存されたビジネスインテリジェンスデータへのアクセスを即時遮断。

Bash インシデント対応 
# インシデント発生時にキーを即時無効化
aws kms disable-key --key-id <key-id>

# CloudTrail でアクセスログを確認
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=ResourceType,AttributeValue=AWS::KMS::Key \
  --start-time "2026-06-01T00:00:00Z"

効果: 15 分以内にデータアクセスを完全遮断し、CloudTrail ログで侵害範囲を特定。迅速なインシデントレスポンスを実現。
