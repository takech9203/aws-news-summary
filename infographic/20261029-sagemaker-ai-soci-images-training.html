Amazon SageMaker AI

⚡ SOCI インデックス付きイメージで
トレーニングジョブを数秒起動

📅 リリース日: 2026 年 10 月 29 日 | 🧩 機能: SOCI (Seekable OCI) インデックス付きコンテナイメージのサポート

📝 概要

Amazon SageMaker AI が、トレーニングジョブおよびプロセッシングジョブで SOCI (Seekable OCI) インデックス付きコンテナイメージをサポートしました。 コンテナイメージを遅延読み込み (lazy loading) することで、10 GB を超える深層学習イメージでも数秒でコンテナを起動でき、 イメージプル中の GPU アイドル時間を最大 90% 削減します。トレーニングのパフォーマンスへの影響はありません。

SOCI インデックスはイメージ内の全ファイルの位置を記録したメタデータで、Amazon ECR に OCI 準拠のアーティファクトとして元のイメージに関連付けて保存されます。 SageMaker はジョブ実行時にインデックスを自動検出し、起動に必要なファイルのみを先にプルし、残りはコードの実行中にバックグラウンドでストリーミングします。

😣 アップデート前の課題

✗ジョブ実行前にイメージ全体のダウンロードと展開の完了を待つ必要があった
✗深層学習イメージは 10 GB 超が多く、ジョブ開始のたびに数分の課金対象時間が発生
✗イメージプル中は GPU がアイドル状態となり、高価なアクセラレータの利用効率が低下
✗イメージサイズに比例してダウンロード時間が線形に増加 (例: 35.4 GB で 7 分 17 秒)

😀 アップデート後の改善

✓イメージサイズによらず数秒 (ベンチマークで約 3〜11 秒) でコンテナを起動
✓GPU アイドル時間を最大 90% 削減し、ジョブ全体の完了が 1〜6 分早くなる
✓ジョブ定義、エントリポイント、データチャネルの変更不要。インデックスを自動検出
✓インデックス利用不可時は標準ダウンロードに自動フォールバックし、既存ジョブを壊さない

従来の標準プルではイメージ全体のダウンロード完了を待つ必要がありましたが、SOCI インデックス付きイメージでは起動に必要なファイルのみを先にプルし、 残りをバックグラウンドでストリーミングします。インデックスが利用できない場合は標準ダウンロードに自動フォールバックします。

🔧 主要機能

🗂️ 1. SOCI インデックスによる遅延読み込み
→イメージ内の全ファイルをマッピングしたメタデータを Amazon ECR に OCI 準拠アーティファクトとして保存
→元のイメージのダイジェストや署名は変更されず、イメージの再ビルドは不要
→起動に必要なファイルのみ先にプルし、残りはコードがアクセスした時点でオンデマンドに取得
🔍 2. SageMaker による自動検出とフォールバック
→ジョブ定義、エントリポイント、データチャネルの変更は不要
→ECR プライベートリポジトリのイメージにインデックスが存在すれば自動的に遅延読み込みを使用
→インデックス利用不可時や遅延読み込み失敗時は標準ダウンロードに自動フォールバックしてジョブを継続
📦 3. 事前インデックス済み AWS Deep Learning Containers (DLC)
→イメージタグを -soci サフィックス付きのバリアントに切り替えるだけで利用可能
→PyTorch Training、TensorFlow Training、vLLM、SGLang 向けに提供 (一部 arm64 バリアントあり)
→例: pytorch-training:2.9-gpu-py312-cu130-ubuntu22.04-sagemaker-v1-soci
🛠️ 4. 独自イメージへのインデックス追加
→オープンソースツール (SOCI snapshotter、Finch または nerdctl) で既存の ECR イメージにインデックスを追加可能
→CloudFormation テンプレート「ECR SOCI Index Builder」で、EventBridge ルール経由の ECR プッシュ時自動インデックス化が可能

対応要件

🚀 設定方法

前提条件

✓SageMaker AI トレーニングジョブまたはプロセッシングジョブを実行できる IAM ロールと環境
✓Amazon ECR プライベートリポジトリ (独自イメージを使用する場合)
✓独自イメージにインデックスを追加する場合は、containerd、SOCI snapshotter、Finch または nerdctl をインストールした Linux ホスト

STEP 1事前インデックス済み DLC を使用する場合

Python ModelTrainer で -soci タグの DLC を指定 
from sagemaker.modules.train import ModelTrainer
from sagemaker.modules.configs import Compute

trainer = ModelTrainer(
    training_image="<account>.dkr.ecr.<region>.amazonaws.com/pytorch-training:2.9-gpu-py312-cu130-ubuntu22.04-sagemaker-v1-soci",
    role="arn:aws:iam::<account>:role/SageMakerExecutionRole",
    compute=Compute(instance_type="ml.g5.12xlarge", instance_count=2),
)
trainer.train()

イメージタグを -soci サフィックス付きのバリアントに変更するだけで、SageMaker が SOCI インデックスを自動検出して遅延読み込みを行います。その他のジョブ設定の変更は不要です。

STEP 2独自イメージに SOCI インデックスを追加する場合

Bash 既存イメージの変換と ECR へのプッシュ 
# 必要なツールをインストール (Amazon Linux の例)
sudo dnf install -y containerd fuse soci-snapshotter runfinch-finch

# 既存イメージを SOCI インデックス付きに変換
sudo nerdctl image convert --soci \
  "$REGISTRY/$REPO:$ORIGINAL_TAG" "$REGISTRY/$REPO:$SOCI_TAG"

# ECR にプッシュ
sudo nerdctl push --platform linux/amd64 "$REGISTRY/$REPO:$SOCI_TAG"

containerd と SOCI snapshotter を使用して既存イメージにインデックスを追加し、ECR にプッシュします。イメージの再ビルドは不要で、イメージのダイジェストや署名は維持されます。

STEP 3インデックスの確認

Bash ECR マニフェストで SOCI インデックスを確認 
aws ecr batch-get-image \
  --repository-name "$REPO" \
  --image-ids imageTag="$SOCI_TAG" \
  --query 'images[].imageManifest'

マニフェストに artifactType が application/vnd.amazon.soci.index で始まる子マニフェストが含まれていれば、SOCI インデックスが正しく関連付けられています。

⚠️ デメリット・制約事項

🚧 制限事項
✗Amazon ECR プライベートリポジトリのみ対応 (他のレジストリや VPC モードのプライベート Docker レジストリは対象外)
✗約 4 GB 未満の小さなイメージでは効果が限定的
✗DLC をベースイメージとして FROM でビルドした場合、インデックスは引き継がれないため、最終イメージの再インデックスが必要
🤔 考慮すべき点
⚠コンテナランタイムは containerd ベースのため、Docker 固有の前提 (Docker CLI の呼び出し、/var/run/docker.sock、cgroup パスベースの識別など) を含むスクリプトは確認が必要
⚠エントリポイントがトレーニング開始前にイメージ内の大部分のファイルを読み込む場合は短縮効果が小さくなる (それでも 6 GB のモデル同梱ケースで 2〜2.5 分の短縮を確認)
⚠初回エポックはファイルの初回アクセス時にストリーミングが発生するため、3〜16 秒程度遅くなる場合がある (2 エポック目以降は同等)

🎯 ユースケース

1️⃣ ハイパーパラメータチューニングの高速化

シナリオ: 数十〜数百のトレーニングジョブを並列・連続で起動するハイパーパラメータチューニングでは、ジョブごとに発生するイメージダウンロード時間が累積し、全体のコストと所要時間を押し上げている。

Python チューニングジョブで参照するイメージを -soci バリアントに変更するだけ 
estimator = PyTorch(
    image_uri="<account>.dkr.ecr.<region>.amazonaws.com/pytorch-training:2.9-gpu-py312-cu130-ubuntu22.04-sagemaker-v1-soci",
    ...
)
✅ 効果: ジョブごとに数分かかっていたイメージプルが数秒になり、チューニング全体の所要時間と課金対象時間を大幅に削減できる。
2️⃣ 短時間プロセッシングジョブのオーバーヘッド削減

シナリオ: 実行時間が数分程度の前処理・評価用プロセッシングジョブでは、イメージダウンロード時間が実行時間に占める割合が大きく、オーバーヘッドが支配的になっている。

Python プロセッシングジョブでの指定例 
processor = Processor(
    image_uri="<account>.dkr.ecr.<region>.amazonaws.com/my-processing-image:v1.0-soci",
    role=role,
    instance_type="ml.m5.xlarge",
    instance_count=1,
)
✅ 効果: 起動オーバーヘッドが数秒に短縮され、短時間ジョブの実効コスト効率が大きく向上する。
3️⃣ CI/CD パイプラインでの自動インデックス化

シナリオ: ML プラットフォームチームが独自のトレーニングイメージを頻繁に更新しており、イメージプッシュのたびに手動で SOCI インデックスを作成するのは運用負荷が高い。

🔗 関連サービス・機能

🗄️ Amazon ECR

SOCI インデックスを OCI アーティファクトとして保存するプライベートレジストリ。本機能は ECR プライベートリポジトリのイメージのみが対象。

📦 AWS Deep Learning Containers

PyTorch Training、TensorFlow Training、vLLM、SGLang 向けに -soci タグ付きの事前インデックス済みイメージを提供。

🧩 SOCI Snapshotter (オープンソース)

AWS が公開する遅延読み込み技術。Amazon ECS や AWS Fargate でも同様の高速起動に利用されている。

📡 Amazon EventBridge

ECR SOCI Index Builder と組み合わせることで、イメージプッシュ時の自動インデックス化を実現。

✅ まとめ

Amazon SageMaker AI の SOCI インデックス付きイメージ対応により、10 GB を超える深層学習イメージでも数秒でトレーニングコンテナを起動でき、 GPU アイドル時間を最大 90% 削減できるようになりました。 ジョブ定義の変更が不要で、インデックスがない場合は標準ダウンロードに自動フォールバックするため、導入リスクはほぼありません。
