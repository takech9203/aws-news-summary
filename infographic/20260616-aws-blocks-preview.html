AWS Blocks

🧩 AWS 上にバックエンドを組み立てるオープンソースフレームワークプレビュー

2026-06-16
リリース日

📌 概要

AWS Blocks は、インフラの専門知識がなくても、データベース・認証・リアルタイムメッセージング・AI エージェントなどを「ブロック」として組み合わせ、AWS 上にバックエンドを構築できる オープンソースの TypeScript フレームワーク です。

Postgres・認証・リアルタイムメッセージングを備えたローカル開発環境を提供し、開発開始時に AWS アカウントは不要です。デプロイ時には「同じアプリケーションコードが変更なしで本番環境の AWS サービス上で動作」します。必要に応じて任意のタイミングで AWS CDK に降りてリソースを直接構成できます。

主な対象はインフラの専門知識を持たないアプリケーション開発者で、20 以上の組み合わせ可能なブロックが提供されます。各ブロックにはロジック、型安全な API、ローカルテスト設定、AI コーディングツール向けのステアリングファイルが含まれます。

Before / After

😓 アップデート前の課題
  • AWS の各サービスや IaC ツールを個別に学習する必要があった
  • ローカルと本番の差異により、エミュレータや Docker での環境構築が必要だった
  • スキーマからフロントエンドまでの型安全性確保にコード生成ステップが必要だった
➜
🎉 アップデート後の改善
  • インフラツールを学習せず、ブロックを組み合わせて機能を構築できる
  • AWS アカウントなしでローカル開発を開始し、同じコードを変更なしで本番デプロイ
  • コード生成ステップなしでエンドツーエンドの型安全性を確保

⚡ 主要機能

1️⃣ ローカルファーストの開発体験
  • Postgres・認証・リアルタイムメッセージングを備えたローカル環境を提供 (開発開始時に AWS アカウント不要)
  • PGlite で実 Postgres エンジンをインプロセス実行。エミュレータや Docker、クラウドのクォータ不要で本番動作を再現
  • ローカル JWT は本番と同じクレーム構造。ローカル WebSocket / ファイルシステムがクラウドのストレージ API を再現
  • サブ秒のフィードバックを実現するホットリロードに対応
2️⃣ 同一コードによる本番デプロイ
  • 同じアプリケーションコードが変更なしで本番環境の AWS サービス上で動作
  • デプロイ時にアプリコードからインフラが自動生成され、DB クエリ・認証チェック・ファイル操作が環境間で同一に保たれる
  • フレームワークが CDK のインフラコードをアプリ内にカプセル化するため、IaC の知識は不要
3️⃣ 20 以上の組み合わせ可能なブロック
🗄️ Database型安全な Postgres インターフェース
🔑 Authメール/パスワード、ソーシャル、SSO、外部 IdP
📡 Realtimepub/sub メッセージング
🪣 FileBucketファイルのアップロード/ダウンロード
⏱️ AsyncJob / CronJobバックグラウンド/スケジュール処理
🤖 AgentAI エージェント (本番は Bedrock)
📚 KnowledgeBaseRAG 向けセマンティック検索
✉️ EmailClientメール送信
📈 ObservabilityLogger / Metrics / Tracer / Dashboard
4️⃣ エンドツーエンドの型安全性と AI ステアリング
  • データスキーマからフロントエンドまで、コード生成ステップなしで型安全性が伝播
  • AI コーディングツール向けの組み込みガイダンスにより、カスタム設定なしで正しいアーキテクチャを支援

🛠️ 設定方法

前提条件

✓Node.js および npm がインストールされた開発環境
✓本番デプロイ時の AWS アカウント (ローカル開発のみなら不要)
✓TypeScript の基本的な知識

ステップ 1: プロジェクトの作成

Bashプロジェクト作成
npx @aws-blocks/create-blocks-app

対話的にフロントエンドフレームワークなどを選択できます。

ステップ 2: ローカル開発の開始

Bashローカル開発サーバー起動
npm run dev

Postgres、認証、リアルタイムメッセージングがローカルで動作し、AWS アカウントなしで開発・テストが可能です。

ステップ 3: 本番環境へのデプロイ

同じアプリケーションコードを AWS アカウントにデプロイします。デプロイ時にフレームワークが CDK のインフラコードを自動生成し、マネージドな AWS サービス上で変更なしに動作します。リソースを直接構成したい場合は、任意のタイミングで CDK レイヤーに降りて設定できます。

💡 ユースケース

🚀 1. プロトタイプから本番までの一貫した開発

シナリオ: スタートアップが新しい Web アプリのアイデアを検証し、迅速に本番化したい。

Bash実装例
npx @aws-blocks/create-blocks-app
npm run dev
# Database, Auth, FileBucket ブロックを組み合わせて開発

効果: AWS アカウントなしでローカルにプロトタイプを構築し、同じコードを変更なしで本番にデプロイできるため、検証から本番化までの時間を短縮できます。

🤖 2. AI エージェントを組み込んだアプリケーション

シナリオ: 既存アプリに、ツール呼び出しと会話履歴の永続化を伴う AI エージェント機能を追加したい。

構成実装例
Agent ブロック + KnowledgeBase ブロックを追加
ローカルでは Ollama でテスト
本番では Amazon Bedrock にデプロイ

効果: ローカルで Ollama や OpenAI 互換エンドポイントを使い AI エージェントや RAG を検証し、本番では Amazon Bedrock 上で動作させ、インフラ構成を意識せず AI 機能を組み込めます。

👥 3. インフラ専任者のいないチームでのバックエンド構築

シナリオ: フロントエンド中心のチームが、インフラの専門知識なしでバックエンドを持つアプリを構築したい。

構成実装例
Auth, Database, Realtime, AsyncJob ブロックを組み合わせ
型安全な API を通じてフロントエンドと接続

効果: フレームワークが CDK を自動生成するため、IaC の知識なしでフル機能のバックエンドを構築でき、エンドツーエンドの型安全性により実装ミスを抑えられます。

✅ メリット

ビジネス面

✓学習コストの削減: インフラツールを学習せずにバックエンドを構築でき、開発者の立ち上がりが速い
✓開発スピードの向上: 1 セッションで DB テーブル・認証・AI エージェント・ファイルアップロード・バックグラウンドジョブを追加でき、検証から本番化まで迅速に
✓追加料金なし: AWS Blocks 自体は追加料金なし。発生するのは基盤 AWS サービスの料金のみ

技術面

✓環境差異の最小化: ローカル環境が本番動作を忠実に再現し、同じコードを変更なしで本番デプロイ
✓型安全性: スキーマからフロントエンドまでコード生成なしでエンドツーエンドの型安全性を確保
✓段階的な詳細化: 通常は CDK に触れず、必要に応じて CDK レイヤーで細かく制御・カスタムブロック作成も可能

⚠️ デメリット・制約事項

制限事項

!プレビュー段階のため、本番利用にあたり機能や仕様が変更される可能性がある
!TypeScript ベースで、対応フロントエンドはプレビュー時点で SPA (Vite + React など) と SSR (Next.js、Nuxt、Astro) に限られる

考慮すべき点

!高度なインフラ要件がある場合、CDK レイヤーでの直接構成やカスタムブロックの作成が必要になる可能性がある
!オープンソースのため、本番採用にあたり GitHub リポジトリのサポート状況やロードマップの確認が推奨される

💰 料金 & 🌍 利用可能リージョン

💰 料金

AWS Blocks は追加料金なしで利用できます。料金が発生するのは、アプリケーションが利用する基盤となる AWS サービスの利用分のみです。

🌍 利用可能リージョン

AWS Blocks でデプロイしたアプリケーションは、すべての商用 AWS リージョンで動作します。

📝 まとめ

AWS Blocks は、インフラの専門知識がなくても AWS 上でアプリケーションバックエンドを構築できるオープンソースの TypeScript フレームワークです。ローカルファーストの開発体験と、同じコードを変更なしで本番デプロイできる仕組みにより、アプリケーション開発者の生産性向上が期待できます。

プレビュー段階のため、まずは npx @aws-blocks/create-blocks-app でプロジェクトを作成し、ローカル環境で各ブロックの動作を確認することがお勧めです。
