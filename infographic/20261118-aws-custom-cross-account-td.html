🔄 AWS Transform
変換定義のクロスアカウント共有

AWS Transform custom
📅 2026 年 11 月 18 日
変換定義 (TD) とレッスンを AWS RAM 経由でアカウント・OU・組織全体に共有。TD は「ライブリソース」として一元管理され、組織全体で標準化された変換を展開できます。

📋 概要

AWS Transform custom が、変換定義 (TD) とレッスン (継続学習で蓄積された知見) を AWS RAM を通じて AWS アカウント間で共有できるようになりました。共有先は個別アカウント、OU、組織全体を指定できます。

TD は静的なコピーではなくライブリソースとして共有され、コンシューマーは常に所有者の最新公開バージョンを実行します。所有者は 4 段階のマネージド許可で共有レベルを制御できます。標準化された変換を多数のアカウントに展開するプラットフォームエンジニアリングチームや AWS パートナーに特に有用です。

❌ Before: アップデート前の課題
  • TD は作成したアカウント内でのみ利用可能で、他アカウントでは個別に複製・公開が必要
  • 複製した TD はバージョン管理が分散し、レッスンも各アカウントに分散して蓄積
  • 組織全体で標準化された変換を展開・維持する仕組みがなかった
✅ After: アップデート後の改善
  • AWS RAM で TD をアカウント・OU・組織全体に共有。1 つの ID、1 つのバージョン履歴、1 つのレッスンセットで一元管理
  • 新バージョンの公開が既存の共有を通じてコンシューマーへ自動反映
  • コンシューマーのレッスンを所有者の TD へ還元し、組織全体で変換品質を継続改善

所有者アカウントが公開した TD を AWS RAM 経由でライブリソースとして共有し、各コンシューマーアカウントは自身の環境・認証情報で TD を実行します。許可レベルに応じて、レッスンの利用や所有者へのレッスン還元も可能です。

⚙️ 主要機能

📦 ライブリソースとしての TD 共有

TD は AWS RAM のリソースタイプ transform-custom:Package として共有。コンシューマーは常に所有者の最新公開バージョンを実行 (--tv で特定バージョンの指定も可能)。公開・変更・削除・共有・許可変更・取り消しは所有者のみが実行でき、コンシューマーは TD の変更・削除・公開・再共有ができません。

🔐 4 段階のマネージド許可
Level 1 デフォルト
Execute
TD の実行のみ。レッスンは利用も作成もされない
Level 2
ExecuteWithLearnings
実行に加え、所有者の現在のレッスンを利用できる
Level 3
ExecuteWithLearningsAndContribution
上記に加え、--share-learnings でオプトインした実行のレッスンを所有者の TD に還元できる
Level 4
ExecuteWithLearningsAndPackageDownload
実行とレッスン利用に加え、atx custom def get による TD のダウンロードが可能
🎯 柔軟な共有先の指定

組織全体 (組織 ARN)、OU (OU ARN)、個別アカウント (12 桁アカウント ID) を指定可能。AWS RAM の組織共有が有効なら、組織内の共有は招待不要で即時有効。組織外への共有は招待制 (12 時間以内の承諾が必要)。アカウントが組織や OU を離れるとアクセスは自動的に失われます。

🔁 レッスンの還元 (オプトイン方式)

レッスンの還元は共有の許可 + コンシューマーのオプトインの両方が揃った場合のみ。オプトインは実行ごとに --share-learnings フラグで明示する必要があり、組織内でも自動化されません。コンシューマーのリポジトリや実行トランスクリプトは所有者に共有されず、還元されたレッスンは重複・競合・安全でないコンテンツ・機密データのチェックを経て取り込まれます。

📝 CloudTrail による監査

共有の作成・更新・削除は所有者アカウントの CloudTrail に記録。レッスン参照、TD ダウンロード、レッスン還元はコンシューマーと所有者の両方に記録され、拒否された呼び出しも AccessDenied エラーコードとともに記録されます。

ステップ 1: AWS RAM で組織共有を有効化 (組織・OU と共有する場合)

Bash管理アカウントで一度だけ実行
aws ram enable-sharing-with-aws-organization

AWS Organizations コンソールで AWS RAM の信頼されたアクセスを有効化するだけでは不十分な点に注意してください。

ステップ 2: 所有者が TD を共有

Bash共有の作成
# CLI を最新バージョンに更新
atx update

# 共有を作成 (オプションの詳細は --help で確認)
atx custom def share create --help

共有は TD が公開されたリージョンで行い、CLI は AWS_REGION または AWS プロファイルのリージョンを使用します。CLI が管理できるのは 4 つの AWS マネージド許可のみで、カスタマーマネージド許可を使う場合は AWS RAM を直接操作します。

ステップ 3: コンシューマーが共有された TD を実行

Bash共有 TD の実行
atx custom def exec \
  -n arn:aws:transform-custom:us-east-1:111122223333:package/java17-upgrade \
  -p ./my-repo

実行はコンシューマーの環境・認証情報で行われ、所有者はコンシューマーのリポジトリや実行トランスクリプトにアクセスできません。

ステップ 4: レッスンを所有者へ還元 (オプトイン)

Bashレッスン還元へのオプトイン
atx custom def exec \
  -n arn:aws:transform-custom:us-east-1:111122223333:package/java17-upgrade \
  -p ./my-repo --share-learnings

--share-learnings フラグは実行ごとに指定が必要で、--do-not-learn (-d) とは併用できません。

💡 メリット

💼 ビジネス面

✓標準化された変換の組織展開: 中央チームが TD を一度構築すれば組織全体で利用でき、各チームの重複作業を削減
✓AWS パートナーの効率化: パートナーが構築した変換を複数の顧客アカウントへ展開する運用負荷を軽減
✓継続的な品質向上: 各アカウントのレッスンを所有者の TD に集約し、組織全体の変換精度を継続的に向上

🔧 技術面

✓一元管理: 1 つの TD、1 つのバージョン履歴、1 つのレッスンセットで管理し、コピーの乱立を防止
✓自動バージョン配信: 新バージョンの公開が既存の共有を通じて自動的にコンシューマーへ反映
✓段階的なアクセス制御: 4 段階のマネージド許可で、実行のみからダウンロード可能まで細かく制御
✓監査性: 共有操作、レッスンの参照・還元、TD のダウンロードが CloudTrail に記録され、所有者側でも追跡可能

⚠️ 制限事項・考慮すべき点

🚧 制限事項

✗共有はリージョナルで、クロスリージョン共有はサポートされない (コンシューマーは TD が公開されたリージョンで実行)
✗共有できるのは公開済みの TD のみ (ドラフトや AWS マネージド変換は共有不可)
✗コンシューマーは TD の再共有や、承諾済み共有からの離脱ができない (取り消しは所有者が行う)
✗IAM ロールやユーザー単位での共有はサポートされず、アカウント単位のみ
✗共有された TD は AWS Transform CLI でのみ利用可能 (現時点で Web アプリケーションでは利用不可)
✗組織外アカウントへの招待は 12 時間で期限切れ
✗TD を削除しても AWS RAM のリソース共有は自動削除されない
✗共有された TD は所有者側の TD 数・サイズのクォータにカウントされ、実行は実行したアカウントの月間クォータにカウントされる

🔍 考慮すべき点

⚠共有 TD の実行はサードパーティコードの実行と同等: 所有者の指示・参照・スクリプトがコンシューマーの環境・権限で実行されるため、信頼できる所有者からの共有のみ受け入れる。ExecuteWithLearningsAndPackageDownload 以外の許可では実行前に TD の内容を確認できない
⚠最小権限での実行: --trust-all-tools (-t) を使わず、信頼設定ファイルで必要なツールのみ許可し、最小権限の認証情報を使用
⚠レッスン還元の匿名性: 還元されたレッスンに提供元アカウントの記録は残らない。提供元は所有者側の CloudTrail で ContributeKnowledgeItems イベントを確認
⚠SCP による制御: 組織外の TD へのレッスン還元を禁止するには、transform-custom:ContributeKnowledgeItems を条件付きで拒否する SCP を利用
⚠機密情報の扱い: 共有する TD にシークレットや認証情報などの機密情報を含めない

🎯 ユースケース

1️⃣ プラットフォームエンジニアリングチームによる標準変換の全社展開

シナリオ: 数百のアカウントを持つ企業で、プラットフォームチームが Java 17 へのアップグレード変換を標準化し、全開発チームに展開したい。

Bash組織全体への展開
# プラットフォームチーム: TD を公開し、組織全体に Execute 許可で共有
atx custom def share create  # 組織 ARN と Execute 許可を指定

# 各開発チーム: 承諾不要で即座に実行可能
atx custom def exec -n arn:aws:transform-custom:ap-northeast-1:111122223333:package/java17-upgrade -p ./app-repo

効果: TD の複製が不要になり、プラットフォームチームが新バージョンを公開するだけで全チームに最新の変換が行き渡る。

2️⃣ AWS パートナーによる顧客アカウントへの変換提供

シナリオ: AWS パートナーが独自に開発したフレームワーク移行の変換を、複数の顧客アカウントに提供したい。

Bash顧客アカウントでの実行
# パートナー: 顧客アカウント ID を指定して共有 (組織外のため顧客が 12 時間以内に承諾)
# 顧客: 招待を承諾後、自身の環境で実行
atx custom def exec -n arn:aws:transform-custom:us-east-1:444455556666:package/framework-migration -p ./customer-repo

効果: 顧客のコードは顧客のアカウント内に留まったまま、パートナーの変換ノウハウを活用できる。料金は実行した顧客側に課金される。

3️⃣ 組織横断でのレッスン集約による変換品質の向上

シナリオ: 中央チームが管理する TD に対し、各チームの実行で得られた知見を集約して変換の精度を高めたい。

Bashレッスン還元の運用
# 所有者: ExecuteWithLearningsAndContribution 許可で共有
# コンシューマー: レッスン還元にオプトインして実行
atx custom def exec -n arn:aws:transform-custom:ap-northeast-1:111122223333:package/api-upgrade \
  -p ./team-repo --share-learnings

# 所有者: 集まったレッスンを管理
atx custom def learnings

効果: 各チームのコードパターンや修正から抽出されたレッスンが所有者の TD に蓄積され、すべてのアカウントの以降の実行に活用される。

💰 料金

共有された TD の実行は、エージェント分 (agent minutes) として、実行を開始したコンシューマーアカウントに課金されます。所有者には課金されません。一括請求 (Consolidated Billing) の場合、使用量はコンシューマーのリンクアカウントの下に表示されます。詳細は AWS Transform の料金ページ を参照してください。

🔗 関連サービス・機能

🔗 AWS Resource Access Manager (AWS RAM)

TD の共有基盤。リソース共有の作成、マネージド許可の適用、組織共有の有効化を担う

🌐 AWS Organizations

組織全体や OU 単位での共有に使用。アカウントが組織を離れるとアクセスも失われる

📝 AWS CloudTrail

共有操作、レッスンの参照・還元、TD ダウンロードの監査ログを所有者・コンシューマー双方に記録

🧠 AWS Transform の継続学習 (Continual Learning)

実行から抽出したレッスンを TD に蓄積する仕組み。共有 TD ではレッスンは常に所有者の TD に帰属する

📝 まとめ

AWS Transform custom の変換定義が AWS RAM を通じてクロスアカウント共有に対応し、組織全体で標準化された変換をライブリソースとして一元管理・展開できるようになりました。プラットフォームエンジニアリングチームや AWS パートナーは、TD を一度構築すれば多数のアカウントへ展開でき、レッスンの還元により変換品質を継続的に改善できます。導入にあたっては、共有はリージョナルである点、共有 TD の実行はサードパーティコードの実行と同等のリスクがある点を理解し、適切なマネージド許可の選択と最小権限での運用を推奨します。
