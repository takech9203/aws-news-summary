AWS Security Hub

🛡️ 未使用アクセスによる ID リスク検出

統合コンソールで組織全体の IAM リスクを一元管理

📅 2026 年 5 月 20 日

📋 概要

AWS Security Hub が、統合コンソール上で未使用の IAM 権限、ロール、クレデンシャルを検出する機能をリリース。セキュリティチームは脅威、エクスポージャー、ポスチャーの検出結果と同じ画面で ID リスクを一元管理できるようになる。

IAM Access Analyzer のサービスリンクアナライザーが各メンバーアカウントに自動作成され、過去 90 日間のアクセスアクティビティに基づいて未使用アクセス権限を評価する。追加設定不要、追加コストなしで Security Hub Essentials に含まれる。

90 日 アクセスアクティビティ分析期間
0 円 追加コスト
0 設定 追加の手動設定不要

🔄 Before / After

❌ Before

  • 数百のアカウントにわたる ID リスク管理に複数ツール間の切り替えが必要
  • 未使用権限とリソースエクスポージャーを結びつける統合ビューが不在
  • 最小権限ポリシー策定に手動分析が必要でスケールしない

✅ After

  • 統合コンソールで脅威、エクスポージャー、ポスチャーと並べて ID リスクを確認
  • IAM Access Analyzer がサービスリンクとして自動作成、追加設定不要
  • 実際の使用パターンに基づく最小権限ポリシーのオンデマンド生成

⚡ 主要機能

🔍 未使用アクセスの自動検出
IAM プリンシパルを過去 90 日間の実際のアクセスアクティビティに対して評価。未使用の権限、ロール、クレデンシャルを検出し、組織全体のメンバーアカウントを横断的にスキャンする。
🔧 サービスリンク IAM Access Analyzer の自動プロビジョニング
Security Hub を組織で有効化するだけで、各メンバーアカウントにアナライザーを自動作成。追加設定やデプロイメント不要。ORGANIZATION_UNUSED_ACCESS タイプとして動作。
🔗 ID リスクとエクスポージャーの相関分析
未使用アクセスの検出結果をリソースエクスポージャーのコンテキストと相関。実際の組織リスクに基づく修復の優先順位付けを支援し、脅威、エクスポージャー、ポスチャーの検出結果と統合表示。
📝 最小権限ポリシーのオンデマンド生成
実際の使用パターンに基づくポリシー推奨。IAM 権限の精緻化を支援し、攻撃対象面の削減に貢献する。

💻 API / コードサンプル

サービスリンクアナライザーの作成 API

Python CreateServiceLinkedAnalyzer 
# サービスリンクアナライザーの作成
client.create_service_linked_analyzer(
    type='ORGANIZATION_UNUSED_ACCESS',
    configuration={
        'unusedAccess': {
            'unusedAccessAge': 90,
            'analysisRule': {
                'exclusions': [
                    {
                        'accountIds': ['string'],
                        'resourceTags': [{'string': 'string'}]
                    }
                ]
            }
        }
    }
)

# サービスリンクアナライザーの削除
client.delete_service_linked_analyzer(
    analyzerName='string',
    clientToken='string'
)

CreateServiceLinkedAnalyzer API は Security Hub が内部的に使用し、各メンバーアカウントにアナライザーを自動作成する。GetAnalyzer と ListAnalyzers のレスポンスには新たに managedBy フィールドが追加され、アナライザーの管理元サービスを識別可能。

前提条件

✓AWS Organizations が有効化されていること

ステップ 1: Security Hub の組織レベル有効化

Bash 組織管理の委任 
# Security Hub を組織の管理アカウントで有効化
aws securityhub enable-organization-admin-account \
    --admin-account-id 123456789012

ステップ 2: 自動有効化の確認

Bash 設定確認 
# メンバーアカウントの自動有効化設定を確認
aws securityhub describe-organization-configuration

サービスリンク IAM Access Analyzer は自動的に作成されるため、追加の設定は不要。

ステップ 3: 検出結果の確認

Bash 検出結果の取得 
# 未使用アクセスに関連する検出結果を取得
aws securityhub get-findings \
    --filters '{"Type": [{"Value": "Software and Configuration Checks/AWS Security Best Practices/UnusedAccess", "Comparison": "PREFIX"}]}'

⚖️ メリット・デメリット

✅ メリット

ビジネス面

  • 複数ツール間の切り替え不要で運用効率向上
  • 組織全体の ID リスクを単一ダッシュボードで把握
  • Security Hub Essentials に含まれ追加コストなし

技術面

  • サービスリンクアナライザー自動作成でゼロ設定デプロイ
  • 使用パターンに基づくポリシー推奨で最小権限を実現
  • 既存の自動化ルールと一貫したワークフローで運用可能

⚠️ 制約事項

  • 分析対象期間は 90 日間固定でカスタマイズ不可の可能性
  • サービスリンクアナライザーは Security Hub 管理のため個別カスタマイズに制限
  • 初回は最大 90 日間のデータ蓄積が必要
  • 大規模組織では検出結果が膨大になる可能性あり
  • 既存 IAM Access Analyzer との重複に注意が必要
  • CIEM の基盤機能として今後の拡張を見据えた設計を推奨

🎯 ユースケース

🏢 大規模組織の未使用権限クリーンアップ

500 以上のアカウントを持つ企業が、組織全体で未使用の IAM ロールとアクセスキーを特定し、セキュリティリスクを低減。重要度の高い未使用アクセスから優先的に対応可能。

Bash 重要度順の検出結果取得 
# 未使用アクセスの検出結果を重要度順に取得
aws securityhub get-findings \
    --filters '{
        "Type": [{"Value": "Software and Configuration Checks/AWS Security Best Practices/UnusedAccess", "Comparison": "PREFIX"}],
        "SeverityLabel": [{"Value": "HIGH", "Comparison": "EQUALS"}]
    }' \
    --sort-criteria '{"Field": "SeverityNormalized", "SortOrder": "desc"}'
📋 コンプライアンス監査対応

金融機関が PCI DSS や SOC 2 の監査要件に対応するため、最小権限の原則が組織全体で遵守されていることを証明。統合コンソールから監査証跡として未使用アクセスの検出状況と修復状況をレポート可能。

Bash サマリー取得 
# 組織全体の未使用アクセス検出結果のサマリーを取得
aws securityhub get-insight-results \
    --insight-arn "arn:aws:securityhub:::insight/securityhub/default/unused-access-summary"
🤖 自動化による継続的な権限最適化

DevOps チームが検出された未使用アクセスに対して自動的に通知を送信し、担当者にポリシーの見直しを促すワークフローを構築。検出から通知までを自動化し、継続的な権限最適化サイクルを実現。

JSON 自動化ルール定義 
{
    "RuleName": "UnusedAccessAutoNotification",
    "Criteria": {
        "Type": [{"Value": "Software and Configuration Checks/AWS Security Best Practices/UnusedAccess", "Comparison": "PREFIX"}],
        "SeverityLabel": [{"Value": "MEDIUM", "Comparison": "EQUALS"}]
    },
    "Actions": [
        {
            "Type": "FINDING_FIELDS_UPDATE",
            "FindingFieldsUpdate": {
                "Note": {
                    "Text": "未使用アクセスが検出されました。最小権限ポリシーの確認をお願いします。",
                    "UpdatedBy": "SecurityHubAutomation"
                }
            }
        }
    ]
}
