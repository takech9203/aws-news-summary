Amazon Keyspaces (for Apache Cassandra)

🌏 Amazon Keyspaces が 11 の追加リージョンで一般提供開始

📅 リリース日: 2026 年 9 月 16 日 | 🏷️ カテゴリ: リージョン拡大 / データベース

📌 概要

サーバーレスの Apache Cassandra 互換マネージドデータベースである Amazon Keyspaces が、 大阪・ジャカルタ・ハイデラバードなど 11 の追加リージョンで利用可能になりました。 データをリージョン内に保持してデータレジデンシー要件を満たしながら、 低レイテンシーで Cassandra 互換アプリケーションを構築できます。

❌ Before: アップデート前の課題
  • 追加 11 リージョン (大阪、ジャカルタ、ハイデラバードなど) では Keyspaces を利用できず、他リージョンを使用する必要があった
  • 他リージョンのエンドポイントへのアクセスでネットワークレイテンシーが増加し、リアルタイム性が求められるワークロードで不利だった
  • データレジデンシー要件がある場合は採用できず、自己管理の Apache Cassandra クラスターを運用する必要があった
✅ After: アップデート後の改善
  • アプリケーションと同一リージョンに Keyspaces テーブルを配置でき、低レイテンシーでのアクセスが可能に
  • データをリージョン内に保持でき、各国のデータレジデンシー要件やコンプライアンス要件を満たしやすくなった
  • 自己管理 Cassandra からマネージドサービスへの移行の選択肢が広がり、運用負荷を削減できるように

⚙️ 主要機能

🌏 11 リージョンへの提供拡大

公式発表に具体的なリージョン名の記載はなく、最新の提供リージョンは AWS Capabilities by Region での確認が案内されています。 開発者ガイドのエンドポイント一覧に基づくと、デュアルスタックエンドポイントのみで新たに掲載された 11 リージョン (アジアパシフィック 6、ヨーロッパ 3、中東 1、中南米 1) が今回の追加分と考えられます。東京・大阪の国内 2 リージョン体制も実現しました。

☁️ サーバーレスな Cassandra 互換データベース

Apache Cassandra 互換 (CQL) のため、既存の Cassandra アプリケーションコードやドライバーをほぼ変更せずに利用可能。 サーバーのプロビジョニング、パッチ適用、クラスター管理が不要で、使用した読み込み/書き込みリクエストとストレージに対してのみ課金されます。

🚀 エンタープライズグレードの可用性とスケーラビリティ

事実上無制限のスループットとストレージにより、毎秒数千リクエストを処理するアプリケーションに対応。 オンデマンドモードではトラフィックに応じてテーブルが自動スケーリングします。

ステップ 1: キースペースの作成

Bash 大阪リージョンにキースペースを作成 
aws keyspaces create-keyspace \
    --keyspace-name 'my_keyspace' \
    --region ap-northeast-3

ステップ 2: テーブルの作成

Bash パーティションキー id を持つテーブルを作成 (未指定時はオンデマンドモード) 
aws keyspaces create-table \
    --keyspace-name 'my_keyspace' \
    --table-name 'my_table' \
    --schema-definition 'allColumns=[{name=id,type=text},{name=data,type=text}],partitionKeys=[{name=id}]' \
    --region ap-northeast-3

ステップ 3: cqlsh での接続確認

Bash TLS 経由でエンドポイントに接続 (サービス固有認証情報または SigV4 プラグイン) 
cqlsh cassandra.ap-northeast-3.api.aws 9142 -u <username> -p <password> --ssl

💡 メリット

💼 ビジネス面
  • データレジデンシー要件への対応: データを対象国・地域のリージョン内に保持でき、規制やコンプライアンス要件を満たしやすい
  • 運用コストの削減: 自己管理の Cassandra クラスターが不要になり、インフラ運用の人的コストを削減
  • サーバーレスの従量課金: 使用したリクエストとストレージのみの支払いで、初期投資や過剰なキャパシティ確保が不要
🔬 技術面
  • 低レイテンシー: アプリケーションと同一リージョンにデータベースを配置し、ネットワークレイテンシーを削減
  • 国内マルチリージョン構成: 東京に加えて大阪でも利用可能になり、国内完結の DR 構成の選択肢が拡大
  • Cassandra 互換: 既存の CQL コードや Cassandra ドライバーを活用でき、移行コストが低い

⚠️ デメリット・制約事項

制限事項

⚠公式発表には追加された 11 リージョンの具体名が記載されておらず、正確な最新リストは AWS Capabilities by Region で確認が必要
⚠新規追加リージョンのエンドポイントはデュアルスタック (.api.aws) 形式のみが掲載されており、従来の cassandra.{region}.amazonaws.com 形式の IPv4 エンドポイントは掲載されていないため、接続設定時に注意が必要
⚠一部の追加リージョン (ハイデラバード、メルボルン、台北など) はオプトインリージョンのため、事前にアカウントでの有効化が必要

考慮すべき点

⚠リージョンによって料金単価が異なるため、利用前に対象リージョンの料金を確認することを推奨
⚠マルチリージョンレプリケーションなどの一部機能が新規リージョンで利用可能かは、個別にドキュメントで確認が必要

💰 料金

Amazon Keyspaces はサーバーレスの従量課金制で、使用した分にのみ料金が発生します。

オンデマンドキャパシティ書き込みリクエストユニット (WRU、1 KB/行まで) と読み込みリクエストユニット (RRU、LOCAL_QUORUM で 4 KB まで、LOCAL_ONE は半額) に基づく課金

🔗 関連サービス・機能

🗄️ Amazon DynamoDB

同じくサーバーレスの NoSQL データベース。Cassandra 互換性が不要な場合の選択肢。

🔄 Amazon Keyspaces CDC streams

テーブルの変更データキャプチャ機能。新規追加リージョンでもストリームエンドポイントが提供されている。

📦 AWS Glue / DSBulk

自己管理 Cassandra から Keyspaces へのデータ移行に活用できるツール。
