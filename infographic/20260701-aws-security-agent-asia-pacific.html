AWS Continuum の一部

📌 概要

AWS は AWS Security Agent (現在は AWS Continuum の一部) を、新たに 3 つの AWS リージョンで提供開始しました。対象は アジアパシフィック (ムンバイ)、アジアパシフィック (シンガポール)、南米 (サンパウロ) です。

AWS Security Agent は、設計からデプロイまでの各段階でセキュリティを継続的に検証するフロンティアエージェントです。自動セキュリティレビュー、脅威モデリング、オンデマンドのペネトレーションテストを提供し、脆弱性を早期に防止します。

対象ユーザーは、開発速度に合わせてセキュリティ専門性を展開したいセキュリティチーム、DevSecOps 担当者、クラウドセキュリティアーキテクトです。開発者は Kiro または Claude Code から、IDE プラグインと MCP 統合を通じてセキュリティ機能を直接トリガーできます。

⚠️ アップデート前の課題
  • ムンバイ、シンガポール、サンパウロのお客様はコア機能を利用できなかった
  • データ所在地や低レイテンシーを重視する組織で、近接リージョンでの検証手段が限られていた
  • 開発ライフサイクル全体でのプロアクティブな検証を一貫して実施しにくかった
✅ アップデート後の改善
  • 3 リージョンでコア機能が利用可能となり、地理的に近い環境で保護できる
  • STRIDE ベースの脅威モデリング (プレビュー) で早期にリスクを特定
  • GitHub、GitLab、Bitbucket、Confluence などでコードレビュー (プレビュー) が利用可能
  • Kiro / Claude Code から IDE プラグイン・MCP 統合で直接呼び出し可能

AWS Security Agent は、設計ドキュメント、ソースコード、デプロイ済みアプリケーションを入力として受け取り、脅威モデリング・コードレビュー・ペネトレーションテストを実行して、検証済みの検出結果と修復 PR を提供します。

⚡ 主要機能

🎯 STRIDE ベースの脅威モデリング プレビュー
  • 設計ドキュメントとソースコードを分析し、アーキテクチャ、コンポーネント、トラスト境界、データフロー、セキュリティ状態を記述したシステム概要を生成
  • STRIDE カテゴリ (なりすまし、改ざん、否認、情報漏洩、サービス妨害、権限昇格) で脅威を分類し、深刻度と実行可能な推奨事項を提示
  • 脅威モデルは再利用可能な設定として保存でき、コードや設計の進化に合わせて再実行可能
🔍 フルリポジトリおよび PR レベルのコードレビュー プレビュー
  • GitHub、GitLab、GitHub Enterprise Server、Bitbucket、Confluence にわたって利用可能
  • フルリポジトリスキャンで脆弱性と組織要件への準拠を検証
  • プルリクエストのコメントとして検出結果を直接投稿し、修復用の PR / MR を自動生成可能
  • マネージドコンプライアンスパックとカスタムセキュリティ要件をサポート
🧪 オンデマンドのペネトレーションテスト
  • 再現可能な攻撃パスを伴う検証済みの検出結果を提供
  • すぐに実装可能な修正を含む
  • 再テストにより、適用された修復が有効であることを確認
🧩 IDE プラグインと MCP 統合
  • Kiro または Claude Code から、脅威モデリング、コードレビュー、修復を直接トリガー可能
  • 新しい IDE プラグインと MCP (Model Context Protocol) 統合を通じて、開発者のワークフロー内でセキュリティ機能を利用

⚙️ 設定方法

前提条件

  • AWS Security Agent (AWS Continuum) を利用可能なリージョンで AWS アカウントを保有していること
  • コードレビュー機能を利用する場合、対象リポジトリ (GitHub、GitLab、GitHub Enterprise Server、Bitbucket) への接続設定
  • IDE 統合を利用する場合、Kiro または Claude Code と対応する IDE プラグインおよび MCP 統合のセットアップ

  • STEP 2: 対象リポジトリを接続し、設計ドキュメントまたはソースコードを指定して STRIDE ベースの脅威モデリングを実行。生成されたシステム概要と分類された脅威を確認

💡 メリット

📈 ビジネス面
  • 地理的な近接性: ムンバイ、シンガポール、サンパウロで近接環境の検証が可能
  • セキュリティ専門性のスケール: 限られた人材で広範なアプリをカバー
  • 早期のリスク発見: 手戻りとコストを削減
🔧 技術面
  • 開発者ワークフローへの統合: Kiro / Claude Code から直接呼び出し、コンテキストスイッチを削減
  • 実行可能な修復: 再現可能な攻撃パスとすぐ実装できる修正を含む
  • 複数リポジトリ対応: 5 つのソースで一貫したレビュー

⚠️ デメリット・制約事項

制限事項

▲脅威モデリング (STRIDE) およびフルリポジトリ / PR レベルのコードレビューはプレビュー段階
▲シミュレーションによる検証は米国東部 (バージニア北部) でのみ利用可能で、追加 3 リージョンでは提供されない
▲拡大されたのはコア機能であり、全機能がすべてのリージョンで同一に提供されるわけではない

考慮すべき点

◆プレビュー機能を本番環境で利用する際は、機能の成熟度と提供条件を事前に確認する
◆ペネトレーションテストの実施には、対象 URL、認証情報、ソースコード、ドキュメントの提供が必要
◆コードレビュー機能の利用には、対象リポジトリへの接続設定が前提となる

🎬 ユースケース

1. 設計段階での脅威モデリング

シナリオ: アジアパシフィック (シンガポール) の開発チームが、新しいマイクロサービスの設計段階でセキュリティリスクを早期に特定したい。

手順
1. 設計ドキュメント (スコープドキュメント) を AWS Security Agent に提供
2. 既存システムのソースコードをコンテキストとして指定
3. STRIDE ベースの脅威モデルを生成し、深刻度別に分類された脅威を確認
効果: コードを書く前に設計上のリスクを特定し、後工程でのアーキテクチャ変更を削減。
2. プルリクエストの自動セキュリティレビュー

シナリオ: 南米 (サンパウロ) のチームが、GitHub 上のプルリクエストごとにセキュリティレビューを自動化したい。

手順
1. AWS Security Agent と GitHub リポジトリを接続
2. PR レベルのコードレビュー (プレビュー) を有効化
3. 検出結果を PR コメントとして受け取り、必要に応じて修復 PR を自動生成
効果: 開発パイプラインを止めることなく、コード変更ごとにセキュリティ検証を実施。
3. IDE からのオンデマンドセキュリティ検証

シナリオ: アジアパシフィック (ムンバイ) の開発者が、Kiro を使いながら開発中アプリのセキュリティを都度確認したい。

手順
1. Kiro に AWS Security Agent の IDE プラグインと MCP 統合をセットアップ
2. IDE 内から脅威モデリングやコードレビューを直接トリガー
3. 検出された脆弱性の修復を IDE のワークフロー内で実施
効果: コンテキストスイッチを最小限に抑え、開発と並行してセキュリティ検証を継続。

📝 まとめ

今回のアップデートにより、AWS Security Agent のコア機能が アジアパシフィック (ムンバイ、シンガポール) および南米 (サンパウロ) で利用可能になり、これらのリージョンのお客様が開発ライフサイクル全体を通じてプロアクティブなセキュリティ検証を実施できるようになりました。STRIDE ベースの脅威モデリングやコードレビューはプレビュー段階のため、機能の提供条件を確認しながら、まずは開発ワークフローへの統合を検証することを推奨します。
