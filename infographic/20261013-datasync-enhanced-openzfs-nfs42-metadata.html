AWS DataSync

🚀 Enhanced モードが FSx for OpenZFS・NFS 4.2・ObjectMetadata に対応

📅 リリース日: 2026 年 10 月 13 日 | Enhanced モードにおける Amazon FSx for OpenZFS サポート、NFS 4.2 サポート、ObjectMetadata オプション

📋 概要

AWS DataSync の Enhanced モードが機能拡張され、Amazon FSx for OpenZFS を転送元または転送先として利用できるようになりました。あわせて、オンプレミスの NFS サーバーおよび FSx for OpenZFS に対する NFS 4.2 サポートと、オブジェクトのユーザーメタデータのコピー可否を制御する ObjectMetadata オプションが追加されました。

Storage Gateway 配下のバケットや Azure Blob Storage など、メタデータの取り扱いに注意が必要な転送先への移行も柔軟に制御できます。なお、既存のタスクには影響がなく、スケジュールどおりに引き続き実行されます。

📁
FSx for OpenZFS 対応
転送元・転送先の両方で Enhanced モードを利用可能に
🔌
NFS 4.2 サポート
最新プロトコルのまま再設定不要でデータ転送
📋
ObjectMetadata オプション
PRESERVE / NONE でメタデータコピーを制御
❌ Before: アップデート前の課題
  • FSx for OpenZFS のデータ移動は Basic モード限定で、Enhanced モードの性能を活用できなかった
  • Enhanced モードは NFS 4.2 非対応のため、古いプロトコルバージョンへの再設定が必要だった
  • オブジェクトのユーザーメタデータのコピー可否を制御できず、メタデータ互換性の問題が発生していた
✅ After: アップデート後の改善
  • FSx for OpenZFS を含む Enhanced モードタスクで大規模なデータ転送を高速に実行可能
  • NFS 4.2 のままプロトコルバージョンを変更せずに Enhanced モードで転送可能
  • ObjectMetadata オプション PRESERVE / NONE でタスク単位のメタデータ制御が可能

Enhanced モードタスクが FSx for OpenZFS や NFS 4.2 対応の NFS サーバーを転送元・転送先として扱えるようになり、オブジェクトストレージ転送時には ObjectMetadata オプションでユーザーメタデータのコピー可否を制御できます。

⚡ 主要機能

1️⃣ Amazon FSx for OpenZFS の Enhanced モードサポート
  • FSx for OpenZFS を転送元または転送先として Enhanced モードのタスクを作成可能
  • これまで Basic モードに限定されていた FSx for OpenZFS のデータ移動で、高いスケーラビリティとパフォーマンスを活用可能
  • 大規模なファイルシステムの移行やデータレイクへのデータ集約を高速化
2️⃣ NFS 4.2 サポート
  • オンプレミスの NFS サーバーおよび FSx for OpenZFS に対して NFS バージョン 4.2 で接続可能
  • 最新バージョンの NFS サーバーからの転送時に、古いプロトコルバージョンへの再設定が不要
  • ロケーション作成時の MountOptions.Version に NFS4_2 を指定可能
3️⃣ ObjectMetadata オプションによるメタデータ制御
  • オブジェクトストレージ転送で、ユーザーメタデータをコピーするかどうかを制御する新しいタスクオプション
  • PRESERVE (コピーする) または NONE (コピーしない) を指定可能
  • Storage Gateway 配下のバケットのように転送先のメタデータを維持したい場合や、Azure Blob Storage のようにメタデータキーの互換性がない場合に有効

}

🛠️ 設定方法

前提条件

  • AWS DataSync を利用できる AWS アカウントと IAM 権限があること
  • オンプレミス NFS サーバーを転送元とする場合は、DataSync エージェントがデプロイ済みであること
  • FSx for OpenZFS を利用する場合は、ファイルシステムが作成済みで、DataSync からアクセス可能なセキュリティグループが設定されていること

ステップ 1: FSx for OpenZFS ロケーションの作成 (NFS 4.2 指定)

Bash AWS CLI 
aws datasync create-location-fsx-open-zfs \
  --fsx-filesystem-arn arn:aws:fsx:ap-northeast-1:123456789012:file-system/fs-0123456789abcdef0 \
  --protocol '{"NFS": {"MountOptions": {"Version": "NFS4_2"}}}' \
  --security-group-arns arn:aws:ec2:ap-northeast-1:123456789012:security-group/sg-0123456789abcdef0 \
  --subdirectory /fsx/

MountOptions.Version に新しくサポートされた NFS4_2 を指定して、FSx for OpenZFS を DataSync のロケーションとして登録します。

ステップ 2: Enhanced モードタスクの作成

Bash AWS CLI 
aws datasync create-task \
  --source-location-arn arn:aws:datasync:ap-northeast-1:123456789012:location/loc-source \
  --destination-location-arn arn:aws:datasync:ap-northeast-1:123456789012:location/loc-dest \
  --name "openzfs-enhanced-transfer" \
  --task-mode ENHANCED

--task-mode ENHANCED で Enhanced モードのタスクを作成します。FSx for OpenZFS を含むタスクでも Enhanced モードを選択できるようになりました。

ステップ 3: ObjectMetadata オプションを指定したオブジェクトストレージ転送

Bash AWS CLI 
aws datasync create-task \
  --source-location-arn arn:aws:datasync:ap-northeast-1:123456789012:location/loc-azure-blob \
  --destination-location-arn arn:aws:datasync:ap-northeast-1:123456789012:location/loc-s3 \
  --name "object-transfer-no-metadata" \
  --task-mode ENHANCED \
  --options '{"ObjectMetadata": "NONE"}'

ObjectMetadata に NONE を指定し、転送元オブジェクトのユーザーメタデータをコピーしないように設定します。転送先のメタデータを維持したい場合や、メタデータキーの互換性に問題がある場合に使用します。

💡 メリット

💼 ビジネス面
  • 移行プロジェクトの短縮: FSx for OpenZFS を含む大規模データ移行で Enhanced モードの高速転送を利用でき、移行期間とコストを削減
  • 既存環境の変更が不要: NFS 4.2 サーバーをそのまま転送元にでき、プロトコルのダウングレード作業や検証コストが不要
  • マルチクラウド移行の信頼性向上: Azure Blob Storage などからの移行時にメタデータ互換性の問題を回避し、移行失敗のリスクを低減
⚙️ 技術面
  • スケーラビリティの向上: Enhanced モードは Basic モードよりも高い並列性を提供し、大量のファイルやオブジェクトの転送に適する
  • きめ細かなメタデータ制御: ObjectTags に加えて ObjectMetadata もタスクオプションで制御可能
  • タスク実行単位での上書き: StartTaskExecution の OverrideOptions でも指定でき、実行ごとに動作を変更可能

⚠️ デメリット・制約事項

制限事項
  • ObjectMetadata オプションはオブジェクトストレージ転送に適用されるオプションで、ファイルシステム間の転送には関係しない
  • Enhanced モードが利用可能なリージョンでのみ今回の機能を利用できる
  • Basic モードと Enhanced モードではサポートされるロケーションの組み合わせや動作に差異があるため、既存タスクの置き換えには事前確認が必要
考慮すべき点
  • ObjectMetadata: NONE ではユーザーメタデータがコピーされないため、メタデータに依存するアプリケーションへの影響を確認する
  • NFS 4.2 を指定する場合、転送元・転送先が実際に NFS 4.2 をサポートしていることを確認する
  • 既存のタスクは影響を受けないが、新機能の利用にはタスクまたはロケーションの設定変更 (もしくは新規作成) が必要

🎯 ユースケース

📁 ユースケース 1: FSx for OpenZFS への大規模データ移行

シナリオ: オンプレミスの NAS に保存された数千万ファイルを Amazon FSx for OpenZFS に移行したい。従来は Basic モードしか使えず、転送スループットとタスクあたりのファイル数制限が課題だった。

Bash実装例
aws datasync create-task \
  --source-location-arn arn:aws:datasync:ap-northeast-1:123456789012:location/loc-onprem-nfs \
  --destination-location-arn arn:aws:datasync:ap-northeast-1:123456789012:location/loc-fsx-openzfs \
  --name "nas-to-openzfs-migration" \
  --task-mode ENHANCED

効果: Enhanced モードの高いスケーラビリティにより、大量のファイルを含む移行を高速かつ安定して実行できる。

🔌 ユースケース 2: NFS 4.2 サーバーからの再設定不要なデータ転送

シナリオ: 最新の Linux ディストリビューションで構築した NFS 4.2 サーバーからデータを S3 に転送したい。従来はプロトコルを古いバージョンに再設定する必要があった。

Bash実装例
aws datasync create-location-nfs \
  --server-hostname nfs42.example.local \
  --on-prem-config '{"AgentArns": ["arn:aws:datasync:ap-northeast-1:123456789012:agent/agent-0123456789abcdef0"]}' \
  --mount-options '{"Version": "NFS4_2"}' \
  --subdirectory /export/data

効果: NFS サーバー側の設定変更なしで Enhanced モードの転送を開始でき、運用負荷と移行準備期間を削減できる。

🌐 ユースケース 3: Azure Blob Storage から S3 への移行時のメタデータ制御

シナリオ: Azure Blob Storage から Amazon S3 へオブジェクトを移行する際、転送元のメタデータキーが転送先の仕様と互換性がなく、転送エラーや不整合が発生する懸念がある。

Bash実装例
aws datasync start-task-execution \
  --task-arn arn:aws:datasync:ap-northeast-1:123456789012:task/task-0123456789abcdef0 \
  --override-options '{"ObjectMetadata": "NONE"}'

効果: 互換性のないユーザーメタデータをコピー対象から除外することで、マルチクラウド移行をスムーズに完了できる。AWS Storage Gateway 配下のバケットなど、転送先のメタデータを維持したいケースにも適用できる。

💰 料金と利用可能リージョン

料金

今回の発表に料金変更の記載はありません。AWS DataSync の料金は、転送したデータ量 (GB 単位) に基づく従量課金です。Enhanced モードと Basic モードでは GB あたりの料金が異なるため、詳細は AWS DataSync 料金ページを参照してください。

利用可能リージョン

DataSync Enhanced モードが利用可能なすべての AWS リージョンで、Enhanced モードタスクに対して利用できます。

🔗 関連サービス・機能

📁 Amazon FSx for OpenZFS
今回 Enhanced モードの転送元・転送先として新たにサポートされた、OpenZFS ベースのフルマネージドファイルストレージ
🌉 AWS Storage Gateway
ObjectMetadata オプションの代表的な適用先。Storage Gateway 配下の S3 バケットでは転送先のメタデータを維持する必要がある
🪣 Amazon S3
DataSync のオブジェクトストレージ転送における主要な転送先。ObjectMetadata オプションによりメタデータのコピー可否を制御可能
📂 Amazon FSx for NetApp ONTAP
API 変更により NFS プロトコル設定で NFS4_2 が指定可能になったロケーションタイプ

📝 まとめ

AWS DataSync Enhanced モードが FSx for OpenZFS、NFS 4.2、ObjectMetadata オプションに対応し、より多くのストレージ環境で高スケーラビリティな転送を利用できるようになりました。

FSx for OpenZFS への移行を Basic モードで運用しているユーザーや、最新の NFS サーバーからの転送を計画しているユーザーは、Enhanced モードへの移行を検討することを推奨します。オブジェクトストレージ間の移行では、転送先の要件に応じて ObjectMetadata オプションの設定を確認してください。
