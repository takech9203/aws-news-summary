🔒 AWS Backup 論理的エアギャップボールトが
Amazon RDS をサポート

リリース日: 2026 年 11 月 16 日
AWS Backup Amazon RDS 🛡️ ランサムウェア対策 / サイバーレジリエンス

📌 概要

AWS Backup の論理的エアギャップボールト (logically air-gapped vault) が Amazon RDS DB インスタンスをサポートしました。 コンプライアンスモードの AWS Backup Vault Lock がデフォルトで有効化された、 不変 (イミュータブル) かつ分離されたバックアップを保存できる特殊なボールトです。 リカバリポイントは AWS Backup サービス所有アカウントに保存され、本番環境のセキュリティ境界の外側で保護されます。

ランサムウェア、内部不正、アカウント侵害といった脅威から RDS バックアップを保護し、 AWS RAM によるボールト共有と共有先アカウントからの直接復元により復旧時間を短縮できます。 アカウント全体が侵害された場合でも Multi-party approval により独立したアクセス経路を確保できます。

❌ Before: アップデート前の課題
  • RDS バックアップは論理的エアギャップボールトに保存できず、エアギャップ保護を適用できなかった
  • 不変性の確保には標準ボールトで個別にボールトロック設定が必要で、お客様アカウント内のため侵害時のリスクが残存
  • 別アカウントからの直接復元ができず、復旧前にスナップショットのコピーが必要で RTO が長かった
✅ After: アップデート後の改善
  • RDS バックアップを論理的エアギャップボールトに保存し、不変性と分離による保護を適用可能に
  • バックアッププランで同一リージョン内のエアギャップボールトをコピー先に指定するだけで利用開始
  • AWS RAM でボールトを共有し、コピー不要の直接復元や復元テストを実行可能に

RDS バックアップは一時スナップショットを経由して同一リージョン内の論理的エアギャップボールトへコピーされ、 AWS RAM で共有された復旧用・フォレンジックアカウントから直接復元できます。

⚙️ 主要機能

1️⃣ Amazon RDS バックアップの不変・分離保管
  • RDS DB インスタンスのバックアップを論理的エアギャップボールトに保存可能
  • コンプライアンスモードのボールトロックが常に有効。保持期間終了までリカバリポイントの変更・削除は不可
  • リカバリポイントは AWS Backup サービス所有アカウントに保存され、本番環境のセキュリティ境界から分離
  • AWS 所有キー (デフォルト) またはカスタマーマネージドキー CMK による暗号化
2️⃣ RDS 専用のコピーワークフロー
  • バックアッププランで RDS を割り当て、同一リージョン内のエアギャップボールトをコピー先に指定
  • 標準ボールトに DELETE_AFTER_COPY ライフサイクルの一時スナップショットを作成後、エアギャップボールトへコピー
  • コピー失敗時は一時リカバリポイントを指定保持期間で保持 (利用可能だがエアギャップ保護はなし)
  • エアギャップボールトをプライマリバックアップターゲットとして指定することも可能
3️⃣ AWS RAM 共有と直接復元
  • 復旧用・フォレンジックアカウントへボールトを共有可能 (AWS Organizations 外のアカウントもサポート)
  • 共有先からコピー操作なしで直接復元ジョブを開始。大規模データベースでも復旧を即座に開始
  • 復元テスト機能と統合し、リカバリポイントの定期検証が可能 (EventBridge + Lambda のカスタムチェックを PutRestoreValidationResult API で報告)
4️⃣ Multi-party approval によるアクセス保護
  • アカウントや AWS Organization 全体が侵害されても、IAM Identity Center の承認者チームの承認を経て復旧用アカウントにアクセス付与
  • 単独のユーザーだけではアクセスを許可できないため、内部不正にも有効

🔑 CMK 暗号化ボールトからの復元時のキーポリシー

カスタマーマネージドキーで暗号化された共有論理的エアギャップボールトから RDS DB インスタンスを復元する場合、 キーポリシーで復元ロールとアカウントの AWS Backup サービスリンクロールにキーの使用を許可する必要があります。 詳細は公式ドキュメントのキーポリシー設定を参照してください。

STEP 1論理的エアギャップボールトの作成 (未作成の場合)

Bash ボールト作成 
aws backup create-logically-air-gapped-backup-vault \
  --backup-vault-name MyRDSLAGVault \
  --min-retention-days 30 \
  --max-retention-days 3650

最小保持期間 30 日、最大保持期間 3,650 日で作成。ボールトロックはコンプライアンスモードで自動的に有効化され、解除できません。

STEP 2バックアッププランで RDS のコピーアクションを設定

Bash コピーアクション追加 
aws backup update-backup-plan \
  --backup-plan-id <plan-id> \
  --backup-plan '{
    "BackupPlanName": "DailyRDSPlan",
    "Rules": [{
      "RuleName": "DailyRDSToLAGVault",
      "TargetBackupVaultName": "Default",
      "ScheduleExpression": "cron(0 5 * * ? *)",
      "Lifecycle": {"DeleteAfterDays": 35},
      "CopyActions": [{
        "DestinationBackupVaultArn": "arn:aws:backup:ap-northeast-1:123456789012:backup-vault:MyRDSLAGVault",
        "Lifecycle": {"DeleteAfterDays": 365}
      }]
    }]
  }'

コピー先の保持期間 (365 日) はボールトの最小・最大保持期間の範囲内である必要があります。RDS の場合、AWS Backup は一時スナップショットを標準ボールトに作成した後、エアギャップボールトへコピーします。

STEP 3復旧用アカウントへのボールト共有

Bash AWS RAM リソース共有 
aws ram create-resource-share \
  --name RDSLAGVaultShare \
  --resource-arns "arn:aws:backup:ap-northeast-1:123456789012:backup-vault:MyRDSLAGVault" \
  --principals "999999999999"

共有先アカウントでは、コピー操作なしでボールト内のリカバリポイントから RDS DB インスタンスを直接復元できます。

STEP 4共有先アカウントからの直接復元

Bash 復元ジョブの開始 
aws backup start-restore-job \
  --recovery-point-arn "arn:aws:backup:ap-northeast-1:123456789012:recovery-point:xxxxxxxx" \
  --iam-role-arn "arn:aws:iam::999999999999:role/BackupRestoreRole" \
  --metadata '{"DBInstanceIdentifier": "restored-db", "DBInstanceClass": "db.r6g.large"}'

CMK 暗号化のボールトの場合は、事前にキーポリシーで復元ロールとサービスリンクロールにキーの使用を許可しておく必要があります。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓ランサムウェア・サイバー攻撃への耐性: 不変かつ分離されたバックアップで、攻撃者による削除・暗号化リスクを低減し事業継続性を確保
✓コンプライアンス対応: 保持期間中のバックアップの改変・削除が不可能であることを監査に対して示せる
✓復旧時間の短縮: コピー待ち時間なしの直接復元でダウンタイムを削減

🔧 技術面のメリット

✓既存ワークフローとの統合: コピーアクションの追加だけで利用可能。一時スナップショットは AWS Backup が自動処理
✓多層防御のアクセス制御: AWS RAM 共有 + Multi-party approval で侵害時にも独立した承認経路を確保
✓復元テストの自動化: フォレンジックアカウントでの定期検証を自動実行

🚧 制限事項

✗コピー先は DB インスタンスと同一アカウント・同一リージョンのエアギャップボールトに限定
✗RDS バックアップを含む場合、エアギャップボールトとの間のクロスリージョンコピーは現在利用不可
✗継続バックアップ PITR は利用不可。スナップショットのみ保存され、RPO は取得頻度に依存
✗aws/rds で暗号化された DB インスタンスはコピー不可。CMK への移行 (スナップショットのコピー・復元やブルー/グリーンデプロイメント) が必要

💡 考慮すべき点

⚠PITR が必要な場合は、標準ボールトでの継続バックアップとスナップショットコピーの併用設計を推奨
⚠コピー失敗時の一時リカバリポイントにはエアギャップ保護が適用されない
⚠ボールトロックはコンプライアンスモード固定。保持期間終了まで削除不可のため設計は慎重に
⚠脅威モデルに応じ、ローカル標準ボールト (運用復旧・PITR)、同一リージョンエアギャップボールト (サイバー復旧)、クロスリージョン標準コピー (リージョン障害対策) の組み合わせを検討

🎯 ユースケース

🦠 ユースケース 1: ランサムウェア対策としての RDS バックアップ保護

シナリオ: 基幹システムのデータベースを Amazon RDS で運用しており、ランサムウェア攻撃によるバックアップの削除・暗号化リスクに備えたい。

日次バックアップルール → 標準ボールト (運用復旧用、PITR 併用) → 同一リージョンの論理的エアギャップボールトへコピー (保持期間 1 年) → ボールトを AWS RAM で復旧用アカウントに共有

効果: 本番アカウントが侵害されてもバックアップは不変かつ分離された状態で保護され、復旧用アカウントから直接復元して迅速に業務を再開できる。

🔐 ユースケース 2: アカウント侵害時の独立した復旧経路の確保

シナリオ: AWS Organization 全体が侵害される最悪のシナリオに備え、単独の管理者では解除できない復旧アクセスの仕組みを構築したい。

Multi-party approval チームを IAM Identity Center で構成 承認者と復旧用アカウントを別の復旧専用 Organization に配置 侵害発生時: 承認者チームの承認を経て復旧用アカウントにボールトアクセスを付与

効果: ボールト所有アカウントや Organization が信頼できない状況でも、複数の承認者による独立した承認経路で RDS バックアップへのアクセスを確保できる。

🔬 ユースケース 3: フォレンジックアカウントでの定期復元テスト

シナリオ: 規制要件により、RDS バックアップが実際に復元可能であることを定期的に検証し、証跡を残す必要がある。

論理的エアギャップボールトをフォレンジックアカウントに共有 復元テストプランでテスト用 VPC・サブネットグループに定期復元 EventBridge + Lambda で行数・スキーマ整合性を検証し PutRestoreValidationResult API で結果を記録

効果: 復元可能性の検証を自動化し、テスト後のリソースは自動クリーンアップされるため、低コストで監査証跡を継続的に取得できる。

💰 料金と利用可能リージョン

料金

論理的エアギャップボールト内のストレージおよび復元の料金は、AWS Backup の料金体系に基づいて課金されます。 エアギャップボールトのストレージ料金は標準のウォームストレージとは異なる料金区分が適用されるため、 詳細は AWS Backup 料金ページを参照してください。 RDS のコピーワークフローで作成される一時スナップショットは DELETE_AFTER_COPY ライフサイクルによりコピー完了後に削除されます。

🌍 利用可能リージョン

論理的エアギャップボールトと Amazon RDS の両方が利用可能なほとんどの AWS リージョンで利用できます。 詳細なリージョン別対応状況は、AWS Backup ドキュメントのリソース別機能可用性を確認してください。

🔗 関連サービス・機能

🗄️ Amazon RDS:今回のアップデートで論理的エアギャップボールトの保護対象に追加されたマネージドリレーショナルデータベースサービス
🔒 AWS Backup Vault Lock:バックアップの不変性を保証する機能。論理的エアギャップボールトではコンプライアンスモードが常に有効

✅ Multi-party approval:アカウント侵害時に承認者チームの承認を経てボールトアクセスを付与する機能。IAM Identity Center と連携
🧪 AWS Backup 復元テスト:リカバリポイントの復元可能性を定期的に自動検証する機能。フォレンジックアカウントでのテストと組み合わせ可能

📝 まとめ

論理的エアギャップボールトが Amazon RDS をサポートしたことで、ランサムウェアやアカウント侵害からデータベースバックアップを保護する 多層防御戦略を RDS にも適用できるようになりました。

✓RDS を基幹システムで利用している場合は、既存のバックアッププランに同一リージョンのエアギャップボールトへのコピーアクションを追加し、AWS RAM による復旧用アカウントへの共有を構成することを推奨
⚠PITR はエアギャップボールトでは利用できないため、標準ボールトでの継続バックアップとの併用設計を事前に確認
⚠AWS マネージドキー aws/rds で暗号化されたインスタンスは CMK への移行を事前に確認
