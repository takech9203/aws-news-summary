AWS Security Hub CSPM

🛡️ CRI Profile v2.2 セキュリティ基準のサポート開始

📅 リリース日: 2026 年 10 月 15 日 | 金融サービスセクター向けサイバーセキュリティフレームワークに対応

📝 概要

AWS Security Hub CSPM が、Cyber Risk Institute (CRI) プロファイル version 2.2 に準拠した自動セキュリティチェックをサポートしました。CRI Profile は、金融機関と業界団体の非営利連合体である Cyber Risk Institute が開発したサイバーセキュリティフレームワークで、金融サービスセクターの多数の規制要件を共通の要件セットに調和 (ハーモナイズ) させることで、一度の自己評価で複数の規制に報告できるようにします。

❌ Before: アップデート前の課題
  • CRI Profile 対応の基準が存在せず、準拠状況の評価に個別ツールや手動のマッピング作業が必要だった
  • 規制ごとに個別の評価を実施する運用負荷が大きかった
  • FSBP や CIS の結果を CRI Profile 要件に手動で対応付ける必要があり、監査対応に時間がかかっていた
✅ After: アップデート後の改善
  • 基準を有効化するだけで 404 個のコントロールによる自動セキュリティチェックが実行可能に
  • 「一度評価して複数の規制に報告する」思想に沿ってコンプライアンス評価を効率化
  • 中央設定で全アカウント・全リンクリージョンに単一アクションで基準を有効化可能に

中央設定で CRI Profile v2.2 基準を有効化すると、組織内の対象アカウントと全リンクリージョンに単一のアクションで展開され、404 個のコントロールが AWS リソースを自動チェックします。

⚡ 主要機能

1️⃣ CRI Profile v2.2 基準の提供

Cyber Risk Institute が策定した金融サービスセクター向けサイバーセキュリティフレームワーク v2.2 に対応。要件のサブセットをサポートする 404 個のコントロールを提供します。手動チェックが必要な要件は対象外 (自動チェック可能な要件のみをカバー) です。

2️⃣ 幅広い AWS サービスをカバーするコントロール

IAM、CloudTrail、CloudWatch、GuardDuty、Inspector、Macie などのセキュリティ関連サービスに加え、EC2、S3、RDS、DynamoDB、EKS、Lambda などの主要サービス、さらに CloudFront、ELB、Network Firewall、WAF などのネットワーク・配信サービスまで広範囲にチェックします。

3️⃣ 中央設定による組織全体への一括展開

Security Hub の中央設定 (central configuration) により、組織の全アカウントまたは一部のアカウントに対して基準を有効化可能。リンクされたすべての AWS リージョンへ単一のアクションで展開できます。AWS 公式も中央設定の利用を推奨しています。

📋 基準の概要

項目詳細
基準名CRI Profile v2.2
策定団体Cyber Risk Institute (金融機関と業界団体の非営利連合体)
対象セクター金融サービス (銀行、保険、証券、フィンテックなど)
コントロール数404 個
カバー範囲CRI Profile v2.2 要件のサブセット (自動チェック可能な要件のみ)
有効化方法Security Hub CSPM コンソール、API、中央設定

🔍 代表的なコントロールの例

カテゴリコントロール例
👤 アカウント管理Account.1 (セキュリティ連絡先の設定)、Account.2 (Organizations への参加)
🔑 ID・アクセス管理IAM.1 (管理者権限ポリシーの禁止)、IAM.9 (ルートユーザーの MFA)

🛠️ 設定方法

✅ 前提条件

✓AWS Security Hub CSPM が有効化されていること
✓コントロールの評価に必要な AWS Config の記録が有効であること
✓組織全体に展開する場合は、Security Hub の中央設定と委任管理者アカウントが設定されていること

📝 手順

1
利用可能な基準の確認
Bash基準一覧から CRI Profile v2.2 の ARN を確認
aws securityhub describe-standards \
  --query "Standards[?contains(Name, 'CRI')]"
2
CRI Profile v2.2 基準の有効化
Bash単一アカウント・単一リージョンで有効化
aws securityhub batch-enable-standards \
  --standards-subscription-requests \
  '[{"StandardsArn": "<ステップ 1 で確認した基準 ARN>"}]'

有効化すると、404 個のコントロールによる自動チェックが開始されます。

3
中央設定による組織全体への展開 (推奨)

委任管理者アカウントで Security Hub コンソールの [設定] から中央設定の設定ポリシーを作成または更新し、有効化する基準に CRI Profile v2.2 を追加します。設定ポリシーを対象の組織単位 (OU) またはアカウントに関連付けることで、リンクされたすべてのリージョンに単一のアクションで基準が展開されます。

4
コンプライアンスステータスの確認
BashFAILED ステータスの検出結果を確認
aws securityhub get-findings \
  --filters '{"ComplianceStatus": [{"Value": "FAILED", "Comparison": "EQUALS"}], "RecordState": [{"Value": "ACTIVE", "Comparison": "EQUALS"}]}' \
  --max-items 10

要件を満たしていないリソースを特定して修復します。コンソールの基準詳細ページではセキュリティスコアも確認できます。

💡 メリット

💼 ビジネス面

✓規制対応の効率化: 「一度評価して複数の規制に報告する」設計思想により、複数の規制・ガイドラインへの対応工数を削減
✓監査対応の迅速化: 継続的な自動チェック結果を監査のエビデンスとして活用でき、監査準備の期間を短縮
✓コスト効率: AWS 無料利用枠により 30 日間無料で試用でき、導入前に効果を検証可能

⚙️ 技術面

✓自動化された継続的評価: 構成変更を継続的に監視し、準拠状況をほぼリアルタイムに把握
✓組織全体への一括展開: 中央設定により単一アクションで有効化でき、設定漏れを防止
✓既存運用との統合: 検出結果は FSBP、CIS、NIST などと同じ形式で集約され、既存の通知・修復ワークフローをそのまま活用可能

⚠️ デメリット・制約事項

🚫 制限事項

✗手動チェックが必要な CRI Profile v2.2 要件はコントロールでサポートされず、別途組織的・運用的な評価が必要
✗提供されるコントロールは要件のサブセットであり、フレームワーク全体を網羅するものではない
✗コントロールのチェックに合格しても、それ自体が CRI Profile v2.2 への準拠を確立・証明するものではない (準拠は Security Hub CSPM が評価できない組織的・運用的なプラクティスに依存)

🤔 考慮すべき点

⚠404 個の多数のコントロールが有効化されるため、既存環境では大量の検出結果が生成される可能性があり、優先度付けと修復計画が必要
⚠評価には AWS Config の記録が必要であり、記録対象リソースが増えることによるコストへの影響を考慮
⚠他の基準 (FSBP、CIS など) と重複するコントロールが多いため、統合コントロールビューの活用や通知の重複排除を検討

🎯 ユースケース

🏦 ユースケース 1: 金融機関のマルチアカウント環境における規制対応

シナリオ: 複数の AWS アカウントを運用する銀行が、金融規制当局への報告に向けて CRI Profile v2.2 に基づく自己評価を実施したい。

Text実装例
1. 委任管理者アカウントで Security Hub 中央設定を構成
2. 設定ポリシーで CRI Profile v2.2 基準を有効化し、本番系 OU に関連付け
3. 全リンクリージョンに基準が自動展開され、404 コントロールのチェックが開始
4. セキュリティスコアと FAILED の検出結果を定期レビュー
💡 効果: 全アカウント・全リージョンの準拠状況を一元的に可視化し、自動チェック可能な範囲の評価工数を大幅に削減できる。
🚀 ユースケース 2: フィンテック企業のコンプライアンス体制の立ち上げ

シナリオ: 金融サービスへ参入するスタートアップが、限られたセキュリティ人員で業界標準のサイバーセキュリティフレームワークに沿った体制を構築したい。

Text実装例
1. AWS 無料利用枠で Security Hub CSPM を 30 日間試用
2. CRI Profile v2.2 基準を有効化し、現状のギャップを把握
3. FAILED のコントロールを重大度順に修復
4. 手動チェックが必要な要件は CRI Profile の文書に基づき別途評価
💡 効果: 金融業界の規制期待事項を集約したフレームワークを基準として、技術的対策のベースラインを短期間で確立できる。
🔄 ユースケース 3: 既存の Security Hub 運用への CRI Profile の追加

シナリオ: すでに FSBP と CIS AWS Foundations Benchmark を運用している金融機関が、CRI Profile v2.2 への対応を追加したい。

Text実装例
1. 既存の中央設定の設定ポリシーに CRI Profile v2.2 を追加
2. 統合コントロールビューで基準間の重複コントロールを確認
3. EventBridge 経由の既存通知・自動修復ワークフローをそのまま活用
4. CRI Profile のセキュリティスコアを監査レポートに組み込み
💡 効果: 既存の検出・修復の仕組みを変更することなく、CRI Profile v2.2 の観点でのコンプライアンス評価を追加できる。

💰 料金と利用可能リージョン

💵 料金

Security Hub CSPM の料金は、セキュリティチェック数と取り込まれた検出結果の件数に基づく従量課金です。CRI Profile v2.2 基準の有効化自体に追加料金はありませんが、404 個のコントロールによるセキュリティチェック数が増加するため、チェック対象リソース数に応じた課金が発生します。AWS 無料利用枠により 30 日間無料で試用できます。

🌏 利用可能リージョン

AWS GovCloud (US) および中国リージョンを含む、Security Hub CSPM が現在利用可能なすべての AWS リージョンで利用できます (東京・大阪リージョンを含む)。

🔗 関連サービス・機能

⚙️ AWS Config

Security Hub CSPM のコントロール評価の基盤。リソースの構成記録が有効になっている必要がある。

🏢 AWS Organizations / Security Hub 中央設定

組織内の複数アカウント・複数リージョンへ基準を一括展開する仕組み。

📨 Amazon EventBridge / Amazon SNS

検出結果の通知や自動修復ワークフローとの連携。Security Hub SNS トピックを購読すると新機能・新コントロールの通知を受け取れる。

📚 他のセキュリティ基準

AWS Foundational Security Best Practices (FSBP)、CIS AWS Foundations Benchmark、NIST SP 800-53、PCI DSS など、同一の仕組みで併用可能。

📌 まとめ

AWS Security Hub CSPM が金融サービスセクター向けフレームワークである CRI Profile v2.2 に対応し、404 個のコントロールによる自動セキュリティチェックが可能になりました。金融機関やフィンテック企業は、中央設定を利用して組織全体に基準を一括展開することを推奨します。ただし、コントロールのチェック合格のみでは準拠の証明にはならないため、手動チェックが必要な要件を含めた包括的なコンプライアンスプログラムの一部として活用してください。
