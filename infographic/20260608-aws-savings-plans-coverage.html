💰 Savings Plans Purchase Analyzer
ターゲットカバレッジ分析

目標カバレッジ率を指定するだけで、最適な Savings Plans 購入額を自動推奨

📅 2026-06-08

📋 概要

AWS は Savings Plans Purchase Analyzer にターゲットカバレッジ分析機能を追加。オンデマンド支出のうち Savings Plans でカバーしたい割合 (目標カバレッジ率) を指定すると、過去の使用実績に基づいて必要な購入額を推奨する。

「80% のオンデマンド支出を Savings Plans でカバーしたい」といった目標ベースの計画立案が可能に。

❌ Before

  • 最大削減額やカスタムコミットメント額からしか分析できなかった
  • 目標カバレッジ率の達成に必要な購入額を手動で試行錯誤
  • 複数のカバレッジ目標の比較に個別シミュレーションが必要

✅ After

  • 目標カバレッジ率を指定するだけで推奨購入額を自動取得
  • ルックバック期間や除外条件を柔軟にカスタマイズ
  • 異なるカバレッジ目標間でコスト・削減額を比較可能

⚡ 主要機能

🎯 ターゲットカバレッジ率の指定

オンデマンド支出のうち Savings Plans でカバーしたい割合をパーセンテージで指定。過去の使用実績に基づき、目標達成に必要な購入額を自動算出。整数値でカバレッジ率を指定 (例: 80 で 80% カバレッジ)。

🔧 カスタマイズ可能な分析パラメータ

カスタムルックバック期間の設定、期限切れ予定の Savings Plans を除外するオプション、アカウントスコープの指定 (PAYER または LINKED) が可能。

📊 複数目標の比較分析

異なるカバレッジ目標を設定し、コスト、カバレッジ、使用率、削減額の 4 つの指標で結果を並べて比較。インタラクティブチャートで可視化。

🔌 API アクセス

Purchase Analyzer API 経由でプログラマティックに分析を実行。自動化ワークフローへの組み込みが可能。

📐 分析タイプ一覧

分析タイプ 説明 ユースケース
MAX_SAVINGS 最大の削減額を達成する購入額を推奨 コスト最適化を最大化したい場合
CUSTOM_COMMITMENT 指定したコミットメント額での影響を分析 予算枠が決まっている場合
TARGET_AVERAGE_COVERAGE 🆕 目標カバレッジ率を達成する購入額を推奨 カバレッジ目標がある場合

💻 実装例

ターゲットカバレッジ分析の開始

Bash AWS CLI - 分析開始 
# ターゲットカバレッジ分析を開始 (80% カバレッジ目標)
aws ce start-commitment-purchase-analysis \
  --commitment-purchase-analysis-configuration '{
    "SavingsPlansPurchaseAnalysisConfiguration": {
      "AccountScope": "PAYER",
      "AnalysisType": "TARGET_AVERAGE_COVERAGE",
      "SavingsPlansTargetCoverage": 80,
      "LookBackTimePeriod": {
        "Start": "2026-05-01",
        "End": "2026-06-01"
      }
    }
  }'

期限切れ Savings Plans を除外した分析

Bash AWS CLI - 除外オプション付き 
# 期限切れ予定の Savings Plans を除外して分析
aws ce start-commitment-purchase-analysis \
  --commitment-purchase-analysis-configuration '{
    "SavingsPlansPurchaseAnalysisConfiguration": {
      "AccountScope": "PAYER",
      "AnalysisType": "TARGET_AVERAGE_COVERAGE",
      "SavingsPlansTargetCoverage": 75,
      "SavingsPlansToExclude": ["sp-expiring-001", "sp-expiring-002"]
    }
  }'

複数カバレッジ目標の比較 (Python)

Python boto3 - 複数シナリオ比較 
import boto3

client = boto3.client('ce')
targets = [70, 80, 90]

for target in targets:
    response = client.start_commitment_purchase_analysis(
        CommitmentPurchaseAnalysisConfiguration={
            'SavingsPlansPurchaseAnalysisConfiguration': {
                'AccountScope': 'PAYER',
                'AnalysisType': 'TARGET_AVERAGE_COVERAGE',
                'SavingsPlansTargetCoverage': target
            }
        }
    )
    print(f"Target {target}%: Analysis ID = {response['AnalysisId']}")

🎯 ユースケース

📅 ユースケース 1: 年度予算計画に基づく Savings Plans 購入

年度のクラウド予算策定時に、オンデマンド支出の 80% を Savings Plans でカバーするという目標を設定し、年間の使用実績に基づく推奨により予算計画の精度が向上。過剰購入や不足を防止できる。

🔄 ユースケース 2: Savings Plans 更新時のカバレッジ最適化

期限切れとなる Savings Plans がある場合、SavingsPlansToExclude で除外し、更新と同時にカバレッジ率を 70% から 85% に引き上げる分析を実行。更新と新規購入を合わせた最適なコミットメント額を算出。

📊 ユースケース 3: 複数カバレッジ目標の比較による最適値の決定

カバレッジ率 70%、80%、90% の 3 パターンで分析し、コストと削減額のバランスが最も良い目標を選定。Python スクリプトで一括実行し、コスト効率と柔軟性のバランスが取れた目標を特定。

⚖️ メリット・デメリット

✅ ビジネス面のメリット

  • 目標ベースの計画立案で財務目標との整合性が向上
  • 複数シナリオの比較分析で最適な購入を迅速に特定
  • 過去実績ベースの推奨で過剰購入・不足リスクを軽減

✅ 技術面のメリット

  • API による定期的なカバレッジ分析の自動化
  • ルックバック期間や除外条件の柔軟な設定
  • 時系列メトリクスによるトレンド分析

⚠️ 制限事項・注意点

  • カバレッジ目標値は整数値で指定する必要あり (小数点以下は不可)
  • 分析は非同期処理のため、結果取得まで待機が必要
  • 過去の使用実績が十分にない場合、推奨の精度が低下する可能性
  • カバレッジ率を高く設定しすぎると使用率が低下し無駄が発生する可能性
  • ワークロード変動が大きい環境では推奨額が実際のニーズと乖離する場合あり
