📊 Amazon Neptune - openCypher クエリによる S3 データ読み取りサポート

neptune.read() プロシージャで S3 データを直接グラフクエリに統合
📅 2026/03/16

📝 概要

Amazon Neptune Database が、openCypher クエリ内で S3 データを直接読み取る機能をサポート開始。新しい neptune.read() プロシージャにより、S3 の外部データを Neptune にロードすることなく、グラフクエリの中でフェデレーションして利用可能に。

リアルタイムのグラフ分析で S3 データと既存のグラフ構造を組み合わせたり、外部データセットからノードやエッジを動的に作成したり、複雑なグラフクエリの実行が可能に。

アプリケーションから openCypher クエリを実行すると、neptune.read() が IAM 認証情報を使用して S3 上のデータを直接読み取り、グラフエンジンのデータと組み合わせて結果を返す。

⭐ 主要機能

1
neptune.read() プロシージャ
openCypher クエリ内で S3 データを直接読み取り。Neptune へのロード不要でフェデレーションクエリを実現。既存グラフ構造と S3 データの組み合わせが可能。
2
包括的なデータ型サポート
String, Integer, Float, Boolean などの標準型に加え、geometry や datetime など Neptune 固有型もサポート。
3
IAM ベースのセキュリティ
呼び出し元の IAM 認証情報で S3 アクセスを制御。既存の IAM ポリシーとロールベースのアクセス制御を活用。追加の認証設定は不要。
4
動的データ統合
リアルタイムで S3 データを動的参照。外部データセットからノードやエッジを動的作成。複雑なグラフクエリに対応。

⚙️ 設定方法

前提条件:

  • Neptune Database クラスターが作成済み
  • openCypher エンドポイントにアクセス可能
  • S3 バケットとデータが準備済み
  • IAM ロールに S3 読み取り権限が付与済み

Step 1: IAM ロール設定

Bash IAM ポリシーのアタッチ 
aws iam attach-role-policy \
  --role-name NeptuneClusterRole \
  --policy-arn arn:aws:iam::123456789012:policy/NeptuneS3ReadPolicy

Step 2: S3 データ読み取りクエリ

Cypher 基本的な読み取り 
CALL neptune.read({
  source: 's3://example-bucket/data/customers.csv'
})
YIELD node
RETURN node

Step 3: グラフデータとの結合

Cypher 既存グラフとの結合 
CALL neptune.read({
  source: 's3://example-bucket/data/external-attributes.csv'
})
YIELD row
MATCH (p:Person {id: row.person_id})
SET p.external_score = row.score
RETURN p

🔑 IAM ポリシー設定例

JSON S3 読み取り権限 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::example-bucket",
        "arn:aws:s3:::example-bucket/*"
      ]
    }
  ]
}

Neptune クラスターの IAM ロールに S3 読み取り権限を付与する必要がある。

✨ メリット

💼 ビジネス面

📈運用効率の向上: データロードの複数ステップが不要になり、パイプライン管理コスト削減
⚡リアルタイム分析: S3 上の最新データを即座にグラフ分析に組み込み、意思決定を迅速化
💰ストレージコスト最適化: 参照頻度の低いデータは S3 に保持したまま利用可能

🔧 技術面

🏗️シンプルなアーキテクチャ: ETL パイプライン構築不要でシステム構成が簡素化
🔐IAM 統合: 既存 IAM ポリシーをそのまま活用、追加セキュリティ設定不要
🔄データ型の互換性: geometry, datetime を含む包括的サポートで変換の手間を軽減

⚠️ デメリット・制約事項

📌openCypher でのみ利用可能 (Gremlin / SPARQL の対応は要確認)
📌大量データ時のクエリレイテンシーへの影響を考慮
📌S3 データのスキーマ・形式制約は公式ドキュメントで確認が必要

💡 頻繁アクセスの大量データは、Neptune ロード vs フェデレーションクエリのパフォーマンス比較検証を推奨。S3 バケットのアクセス権限管理にも注意。

💡 ユースケース

🏦 1. リアルタイム不正検知
金融機関が Neptune の取引関係グラフと S3 の最新市場データ・信用スコアを組み合わせて不正検知分析。リスクスコアとグラフの取引関係をリアルタイムに統合。
🛒 2. 動的レコメンデーション
EC サイトが S3 の商品カタログとユーザー行動グラフを組み合わせてレコメンデーション。カタログ更新をロードなしで即座に反映。
🚚 3. サプライチェーン最適化
物流企業が Neptune のサプライチェーングラフと S3 の地理情報・配送コストデータで最適ルート分析。コスト最適化されたルートを動的に分析。

📝 まとめ

Neptune の neptune.read() プロシージャにより、S3 の外部データをグラフクエリ内で直接参照可能に。従来のマルチステップデータロードが不要になり、リアルタイムグラフ分析での外部データ統合が大幅に簡素化。Neptune Database でグラフ分析を行う場合は、S3 データとのフェデレーションクエリを活用し、データパイプラインの簡素化を推奨。
