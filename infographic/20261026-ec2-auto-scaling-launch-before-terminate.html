Amazon EC2 Auto Scaling

⚙️ アカウントレベルでの Launch Before Terminate サポート

📅 リリース日: 2026 年 10 月 26 日 | 機能: アカウントレベル設定 launchBeforeTerminate

📝 概要

Launch Before Terminate をアカウント内のすべての Auto Scaling グループに対するデフォルトの置換動作として有効化できるようになりました。有効化すると、Auto Scaling は置換先のインスタンスを起動し、ヘルスチェックに合格するのを待ってから置換元のインスタンスを終了します。これにより、インスタンス置換イベント中もフルキャパシティと可用性を維持できます。

インスタンスリフレッシュ、AZ リバランシング、ヘルスチェック置換、最大インスタンス存続時間置換など、さまざまな置換イベントに適用されます。新 API PutAccountSetting / DescribeAccountSettings により、コンソール・CLI・SDK から管理できます。

❌ アップデート前の課題

  • Launch Before Terminate 相当の動作には、グループごとのインスタンスメンテナンスポリシー設定や、リフレッシュごとの最小・最大正常パーセンテージ指定が必要だった
  • 多数のグループを運用する環境では、同じ置換ポリシーの適用作業が煩雑で設定漏れが発生しやすかった
  • デフォルト動作では終了が先行するため、置換中に一時的にキャパシティが希望容量を下回るリスクがあった

✅ アップデート後の改善

  • アカウント設定 launchBeforeTerminate を有効化するだけで、リージョン内すべてのグループのデフォルト置換動作を統一できる
  • リフレッシュだけでなく、ヘルスチェック置換、最大存続時間置換、リバランシングでもフルキャパシティを維持
  • 置換先の起動に失敗した場合は置換元をサービス内に維持して再試行するため、キャパシティ喪失を防げる

アカウント設定 launchBeforeTerminate を有効化すると、インスタンス置換時に新インスタンスの起動とヘルスチェック合格を待ってから旧インスタンスを終了するため、置換中もキャパシティが希望容量を下回りません。

🚀 主要機能

1️⃣ アカウントレベルのデフォルト置換動作
  • launchBeforeTerminate を enabled にすると、リージョン内すべての Auto Scaling グループで Launch Before Terminate がデフォルトに
  • 設定はリージョン単位で適用されるため、有効化したいすべてのリージョンで設定が必要
  • インスタンスメンテナンスポリシー未設定のグループ、およびリフレッシュで正常パーセンテージ未指定の場合に適用
2️⃣ 幅広い置換イベントへの適用
  • インスタンスリフレッシュ
  • ヘルスチェックによる置換
  • 最大インスタンス存続時間 Maximum Instance Lifetime による置換
  • アベイラビリティーゾーンのリバランシング
3️⃣ デフォルトの正常パーセンテージ
  • アカウント設定が有効な場合、最小 100% / 最大 110% がデフォルトとして使用される
  • グループにインスタンスメンテナンスポリシーがあればそちらが優先
  • リフレッシュで明示的に指定した場合はその指定が優先
4️⃣ 置換失敗時の安全な動作
  • 置換先の起動に必要なキャパシティを確保できない場合、置換元をサービス内に維持したまま再試行
  • オンデマンドキャパシティ不足やキャパシティ予約の空き不足でも、グループのキャパシティは失われない

💻 設定方法

✅ 前提条件

✓AWS CLI がインストールされ、認証情報が設定されていること
✓IAM 権限 (autoscaling:PutAccountSetting および autoscaling:DescribeAccountSettings 相当のアクション) を持っていること
✓有効化したいリージョンを確認していること (設定はリージョンごとに必要)

ステップ 1: Launch Before Terminate を有効化する

Bash アカウント設定の有効化 
aws autoscaling put-account-setting \
    --name launchBeforeTerminate \
    --value enabled

現在のリージョン内でインスタンスメンテナンスポリシーを持たないすべての Auto Scaling グループのデフォルト置換動作が Launch Before Terminate になります。

ステップ 2: 現在の設定状態を確認する

Bash 設定状態の確認 
aws autoscaling describe-account-settings \
    --name launchBeforeTerminate

有効化されていれば enabled が返されます。

ステップ 3: 他のリージョンにも設定を適用する

アカウント設定は単一リージョン内のアカウント全体に適用されます。複数リージョンで運用している場合は、--region オプションを指定して、有効化したいすべてのリージョンでステップ 1 と 2 を繰り返します。

💡 メリット

💼 ビジネス面

✓可用性の向上: 置換イベント中もフルキャパシティを維持でき、パフォーマンス低下やサービス影響のリスクを軽減
✓運用コストの削減: グループごとの個別設定が不要になり、多数のグループを運用する組織での設定・管理工数を削減
✓ガバナンスの標準化: アカウントレベルで安全な置換動作を一括適用し、組織全体で一貫した可用性ポリシーを実現

🔩 技術面

✓設定漏れの防止: 新規作成されたグループにもデフォルトで適用され、ポリシー設定漏れによるキャパシティ低下を防止
✓柔軟な優先順位: グループのポリシーやリフレッシュの個別設定が優先されるため、グループごとの細かい制御も引き続き可能
✓安全な失敗時動作: 置換先の起動に失敗しても置換元が維持され、キャパシティ不足時でもグループの容量が失われない

⚠️ デメリット・制約事項

🚫 制限事項

✗設定はリージョン単位で適用されるため、複数リージョンで利用する場合はリージョンごとに設定が必要
✗インスタンスメンテナンスポリシーが設定されているグループには、アカウント設定ではなくグループのポリシーが適用される
✗置換中は一時的に追加インスタンスが 1 台起動するため、その間は追加インスタンス分の料金が発生する

🤔 考慮すべき点

⚠キャパシティのヘッドルーム: 置換のたびに追加インスタンスが短時間稼働するため、サービスクォータ (vCPU 上限など) に余裕があるか確認が必要
⚠キャパシティ予約との組み合わせ: 予約 ID を直接指定するターゲット型のオンデマンドキャパシティ予約では、置換後のインスタンスが予約外の通常のオンデマンドキャパシティとして稼働し続ける可能性がある。オープン型の予約か、CapacityReservationResourceGroupArns でのリソースグループ経由の参照が推奨
⚠置換失敗の低減策: 希望容量より多めの予約、オンデマンドキャパシティの確保、インスタンスタイプと AZ の選択肢を増やすといった対策で、置換先の起動失敗の可能性を減らせる

🎯 ユースケース

1. 多数の Auto Scaling グループを持つ組織での可用性標準化

シナリオ: 数十のグループを運用しており、すべてのグループで置換時の可用性低下を防ぎたいが、グループごとのポリシー設定は管理負荷が高い。

Bashリージョンごとに一度だけ実行
aws autoscaling put-account-setting \
    --name launchBeforeTerminate \
    --value enabled \
    --region ap-northeast-1

効果: リージョン内のすべてのグループ (ポリシー未設定のもの) に一括適用され、個別設定なしで置換時の可用性を標準化できる。

2. 最大インスタンス存続時間を使用したワークロードの安定運用

シナリオ: コンプライアンス要件で最大インスタンス存続時間を設定し定期的に入れ替えているが、置換のたびにキャパシティが低下し、ピーク時間帯のパフォーマンスに影響が出ている。

Bashアカウント設定の有効化と確認
# アカウント設定を有効化
aws autoscaling put-account-setting \
    --name launchBeforeTerminate \
    --value enabled

# 最大インスタンス存続時間が設定されたグループは
# 置換時に新インスタンス起動後に旧インスタンスが終了される
aws autoscaling describe-auto-scaling-groups \
    --auto-scaling-group-names my-asg \
    --query "AutoScalingGroups[].MaxInstanceLifetime"

効果: 定期置換でも新インスタンスのヘルスチェック合格後に旧インスタンスが終了されるため、ピーク時間帯でもフルキャパシティを維持できる。

3. ヘルスチェック置換時のキャパシティ保護

シナリオ: ELB ヘルスチェックで異常と判定されたインスタンスの置換時、従来は終了が先行するため、残りのインスタンスへの負荷集中が発生していた。

Bash設定状態の確認
# アカウント設定を有効化した上で、設定状態を確認
aws autoscaling describe-account-settings \
    --name launchBeforeTerminate

効果: 異常インスタンスの置換時も置換先がサービスインしてから終了が行われるため、残存インスタンスへの負荷集中を緩和し、連鎖的な障害のリスクを低減できる。

🔗 関連サービス・機能

🛠️ インスタンスメンテナンスポリシー

グループ単位で最小・最大正常パーセンテージを制御する既存機能。設定されている場合はアカウント設定より優先される。

🔄 インスタンスリフレッシュ

グループ内のインスタンスをローリング置換する機能。リフレッシュ開始時に正常パーセンテージを指定した場合はその指定が優先される。

📦 オンデマンドキャパシティ予約

Launch Before Terminate と併用する場合、オープン型予約またはキャパシティ予約リソースグループ経由での参照が推奨される。

⚖️ Elastic Load Balancing

ELB ヘルスチェックと組み合わせることで、置換先インスタンスのサービスイン確認後に旧インスタンスを終了できる。

📌 まとめ

アカウントレベルの launchBeforeTerminate 設定により、グループごとの個別設定なしで、すべての Auto Scaling グループのインスタンス置換時にフルキャパシティと可用性を維持できるようになりました。

✓多数の Auto Scaling グループを運用している場合は有効化を検討
✓ヘルスチェック置換・最大インスタンス存続時間置換での一時的なキャパシティ低下が課題の場合にも有効
✓キャパシティ予約利用時は、オープン型予約またはキャパシティ予約リソースグループ経由での参照への見直しも併せて実施
