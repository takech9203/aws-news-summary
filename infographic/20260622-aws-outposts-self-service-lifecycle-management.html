機能: Self-Service Lifecycle Management

📌 概要

AWS Outposts のライフサイクル全体を、お客様自身でセルフサービス管理できるようになりました。

構成 (Configuration)、見積もり (Quoting)、注文 (Ordering)、サブスクリプション管理、更新 (Renewal)、廃止 (Decommissioning) の各操作を、AWS Management Console / CLI / API から直接実行できます。新しい構成・見積もりツールは、複数の支払いオプションと契約期間にわたるリアルタイムのコスト見積もりを生成し、注文前にアカウントおよびリージョンの制約を事前に提示します。

Before / After 比較

🔴 アップデート前の課題

  • 見積もり・注文・契約確認・廃止のたびに AWS チームへの問い合わせが必要
  • 支払いオプションや契約期間ごとのコスト比較に時間がかかる
  • アカウント準備状況やリージョン制約がプロセス後段で判明
  • 契約期間や請求情報の確認に AWS への問い合わせが必要

🟢 アップデート後の改善

  • 構成〜廃止のすべてをコンソール / CLI / API でセルフサービス実行
  • 複数の支払いオプション・契約期間のコストを数秒で算出
  • 注文送信前にアカウント不足・リージョン制約を事前検出
  • 契約期間・請求情報を GetOutpostBillingInformation で参照

⚙️ 主要機能

📝 1. 構成・見積もりツール (Configuration & Quoting)
  • 構成を作成し、リアルタイムのコスト見積もりを確認してコンソール / API から注文
  • 複数の構成・支払いオプション・契約期間のコストをリアルタイムに比較
  • 注文送信前にアカウント準備状況の不足やリージョン制約を事前検証
  • 見積もりは数秒で生成、有効期間は 30 日間 (期限切れは現在価格で再生成可能)
  • 新規デプロイと容量追加の両方に対応 (容量追加は既存 Outpost 情報を事前入力)
  • 出力に推奨ラック構成・全支払いオプションのコスト・契約期間・PDF を含む
🛒 2. 注文 (Ordering)
  • 見積もりを注文に変換。注文後は内容を変更できない
  • 前提条件: サイトに関連付けられた Outpost、有効な Enterprise Support または Unified Operations、完全なサイト詳細 (住所・ラックの物理的特性)
  • 注文後、AWS が責任共有モデルに基づきサイト評価・設置・接続検証を実施
📋 3. サブスクリプション管理 (Subscription Management)
  • 契約期間は 1 年・3 年・5 年から選択
  • 開始日・終了日・支払い条件・前払い費用・月額料金をコンソールと CLI/API で参照
  • 容量追加を行った場合は複数のサブスクリプションが表示される
  • [Billing] タブでステータス (Active / Pending) でフィルタし CSV をダウンロード
🔄 4. 更新 (Renewal)
  • 契約終了日の 3 か月前から更新可能
  • 元の契約と異なる契約期間・支払いオプションを選択できる
  • 前払い (全額・一部) は送信時に課金、月額料金は更新開始日から発生
🗑️ 5. 廃止 (Decommissioning)
  • 契約期間中いつでも実行可能
  • EC2 インスタンス・RAM 共有・仮想インターフェイスなどアクティブなリソースを確認
  • 自動削除 (Delete Resources) または手動削除を選択できるガイド付きワークフロー
  • 自動削除時はスナップショットを取得せず、削除後は復元不可
  • 廃止前の EBS スナップショット作成を推奨 (親リージョンに同一 KMS キーで暗号化保存)

サブスクリプション情報の取得 (CLI 例)

Bashget-outpost-billing-information
aws outposts get-outpost-billing-information \
    --outpost-identifier op-1234567890abcdefg

レスポンスには SubscriptionId、SubscriptionType (ORIGINAL / RENEWAL / CAPACITY_INCREASE)、SubscriptionStatus、OrderIds、開始日・終了日、MonthlyRecurringPrice、UpfrontPrice などが JSON で含まれます。

🚀 設定方法

前提条件

  • サイトに関連付けられた Outpost が作成済みであること
  • 有効な AWS Enterprise Support または AWS Unified Operations プランに加入
  • 完全なサイト詳細 (運用・配送先住所、ラックの物理的特性) が登録済み
  • 必要に応じて IAM ポリシーで見積もり生成や請求情報 API へのアクセスを制限

ステップ 1: 見積もりの作成

Bashcreate-quote
aws outposts create-quote \
    --country-code "JP" \
    --requested-capacities '[{"QuoteCapacityType":"EC2","Unit":"vCPU","Quantity":960}]' \
    --requested-payment-options "ALL_UPFRONT" "NO_UPFRONT" \
    --requested-payment-terms "THREE_YEARS" "ONE_YEAR" \
    --description "New Outpost for Tokyo DC"

レスポンスには支払いオプション・契約期間ごとの価格 (UpfrontPrice、MonthlyRecurringPrice)、推奨ラック構成、注文要件の検証結果 (OrderingRequirements) が含まれます。

ステップ 2: 見積もり内容の確認と検証

Bashget-quote
aws outposts get-quote --quote-identifier "<QuoteId>"

OrderingRequirements の各項目の Status (PASS / FAIL / EXEMPT) を確認。FAIL がある場合は Enterprise Support の有無や住所、ラックの物理的特性などの不足を解消します。

ステップ 3: 注文への変換

Bashcreate-order
aws outposts create-order \
    --outpost-identifier "<OutpostId>" \
    --quote-identifier "<QuoteId>" \
    --quote-option-identifier "<QuoteOptionIdentifier>" \
    --payment-option "ALL_UPFRONT" \
    --payment-term "THREE_YEARS"

注文後は内容を変更できないため、送信前に支払い条件と構成を確認してください。注文送信後、AWS がサイト評価・設置・接続検証を実施します。

✅ メリット

💼 ビジネス面

  • 調達リードタイムの短縮: 問い合わせ不要で数秒で見積もり取得・注文
  • コストの透明性向上: 複数の支払いオプション・契約期間を事前比較
  • 計画の容易化: ダウンロード可能な PDF で社内承認・予算策定が容易に

🔧 技術面

  • API による自動化: 見積もり・注文・参照・更新を API/CLI で自動化
  • 事前検証によるエラー削減: 注文前に制約を検出し手戻りを防止
  • ガイド付き廃止: アクティブなリソースを確認しながら安全に廃止

⚠️ デメリット・制約事項

制限事項

  • 注文後は注文内容を変更できない
  • 世代の異なるハードウェアは混在できない (例: C7i/M8i を第 1 世代に追加不可)
  • 容量追加にはサブスクリプションの残存期間が 30 日以上必要。月単位の契約は先に更新が必要
  • ストレージの削減や個別ホストの廃止 (容量削減) はサポートされない
  • EBS と S3 は固定ティアでプロビジョニングされ、要求量は切り上げられる
  • 最小構成あり: 第 1 世代は EBS なしで 4 / EBS ありで 2 コンピュートホスト、第 2 世代は最小 960 vCPU。容量追加は 3 ホストまたは任意のストレージティア増加

考慮すべき点

  • 自動削除ではスナップショットを取得しないため、廃止前に必要な EBS スナップショットを作成
  • 廃止しても残存する支払い義務は取り消されず、月単位の課金は日割りされない。追加課金回避には次回請求日の少なくとも 5 日前に廃止リクエストを送信
  • 価格情報は機密性が高いため、GetOutpostBillingInformation へのアクセスを IAM で制限することを検討
  • 容量計画ではインスタンスファミリーごとに少なくとも N+1 のホストをプロビジョニング推奨

🎯 ユースケース

① 新規 Outpost の迅速な調達

シナリオ: 国内データセンターにオンプレミス環境を構築する企業が、複数の支払いプランを比較しながら Outpost を発注したい。

実装: CreateQuote で複数の支払いオプション・契約期間の見積もり取得 → PDF をダウンロードして社内承認 → CreateOrder で発注。

💡 効果: AWS チームとのやり取りを待たずに数秒で見積もりを取得し、社内承認後すぐに発注できる。
② 容量追加の自動化

シナリオ: 既存 Outpost のワークロード増加に伴い、運用チームが定期的に容量を追加する必要がある。

実装: 既存 Outpost ID を指定して CreateQuote (既存情報が事前入力) → 残存期間に合わせた日割りコストを確認 → CreateOrder で容量追加を発注。

💡 効果: 残存期間に合わせた日割りコストを把握しながら、API 経由で容量追加を自動化できる。
③ 契約更新と廃止の計画的な管理

シナリオ: 契約終了が近づく複数の Outpost について、更新するものと廃止するものを判断したい。

実装: GetOutpostBillingInformation で契約終了日を確認 → 更新は GetRenewalPricing で価格確認後 CreateRenewal、廃止は EBS スナップショット作成後にガイド付きワークフロー。

💡 効果: 契約情報をプログラムで把握し、更新と廃止を計画的にセルフサービスで実行できる。

💰 料金と利用可能リージョン

料金

セルフサービスライフサイクル管理機能の利用に追加料金はかかりません。Outposts の料金は構成・支払いオプション (全額前払い / 前払いなし / 一部前払い) ・契約期間 (1・3・5 年) に基づきます。構成・見積もりツールで前払い費用 (UpfrontPrice) と月額料金 (MonthlyRecurringPrice) をリアルタイム確認できます。

🌍 利用可能リージョン

AWS Outposts をサポートするすべての商用 AWS リージョンで利用可能です。

🔗 関連サービス・機能

  • Amazon EC2: Outpost 上のコンピュート。廃止時のクリーンアップ対象
  • Amazon EBS / S3 on Outposts: 見積もりで指定するストレージ。EBS は必須、S3 は任意
  • AWS Resource Access Manager (RAM): Outpost の共有。廃止時のクリーンアップ対象
  • AWS IAM: 見積もり生成や請求情報 API へのアクセス制御に使用
  • AWS Enterprise Support / Unified Operations: 注文の前提条件となるサポートプラン

📝 まとめ

AWS Outposts のライフサイクル全体 (構成・見積もり・注文・サブスクリプション管理・更新・廃止) を、コンソール / CLI / API からセルフサービスで管理できるようになりました。AWS チームへの問い合わせに依存していた従来の調達プロセスが大幅に簡素化され、コストの透明性と自動化の両面でメリットがあります。新しい構成・見積もりツールで複数の支払いオプションを比較し、API による調達・更新の自動化を検討することをお勧めします。
