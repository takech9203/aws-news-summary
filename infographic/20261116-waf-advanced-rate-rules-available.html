🛡️ AWS WAF 高度なレートベースルールが
GovCloud・タイ・メキシコに拡大

リリース日: 2026 年 11 月 16 日
AWS WAF 🌍 リージョン拡大 / DDoS・ボット対策

📌 概要

AWS WAF の高度なレートベースルール (Advanced Rate-Based Rules) が、 新たにアジアパシフィック (タイ)、メキシコ (中部)、AWS GovCloud (US-East)、AWS GovCloud (US-West) の 4 つのリージョンで利用可能になりました。これらのリージョンでも、カスタムキーによるリクエスト集約と、 1 分または 2 分の短い評価ウィンドウを利用できるようになります。

レートベースルールは、受信リクエストをカウントし、設定したしきい値をトラフィックが超過した場合に Block や CAPTCHA などのアクションを実行する機能です。今回の拡大により、IP アドレス単体での集約だけでなく、 HTTP ヘッダー、Cookie、クエリ文字列、URI パス、HTTP メソッド、ラベル名前空間などを 最大 5 つ組み合わせた複合キーでの集約が対象リージョンでも可能になります。 規制要件により AWS GovCloud (US) を利用する政府機関や関連事業者、タイ・メキシコリージョンのユーザーにとって、 より精緻なレート制限による DDoS 対策・ボット対策が可能になる点が主な価値です。

❌ Before: アップデート前の課題
  • リクエストの集約キーが IP アドレスのみに制限されており、User-Agent やセッション Cookie などを組み合わせた精緻なレート制限ができなかった
  • 評価ウィンドウが 5 分または 10 分のみで、短時間に急増するリクエストフラッドへの迅速な検知・対応が難しかった
  • 複数の IP アドレスから送信される分散型攻撃に対して、IP アドレス単位の集約では効果的な制限が困難だった
✅ After: アップデート後の改善
  • アジアパシフィック (タイ)、メキシコ (中部)、AWS GovCloud (US-East / US-West) でカスタムキーによるリクエスト集約が利用可能に
  • HTTP ヘッダー、Cookie、クエリ文字列、URI パス、HTTP メソッド、ラベル名前空間を最大 5 つ組み合わせた複合キーで集約可能に
  • 従来の 5 分・10 分に加えて 1 分・2 分の評価ウィンドウを選択でき、急激なリクエスト増加へ迅速に対応可能に

高度なレートベースルールは、複合キーでリクエストを集約し、選択した評価ウィンドウ内でしきい値を超過したトラフィックに対して Block や CAPTCHA などのアクションを実行します。

⚙️ 主要機能

1️⃣ カスタムキーによるリクエスト集約
  • IP アドレスに加えて、HTTP ヘッダー、Cookie、クエリ文字列、URI パス、HTTP メソッド、ラベル名前空間でリクエストを集約可能
  • 最大 5 つのコンポーネントを組み合わせた複合キーを作成可能
  • 例: IP アドレスと User-Agent ヘッダーの組み合わせごとにログイン試行を制限
2️⃣ 短い評価ウィンドウの選択
  • 従来の 5 分・10 分に加えて、1 分・2 分の評価ウィンドウを選択可能
  • 短いウィンドウはリクエストフラッドの迅速な検知に有効
  • 長いウィンドウは低速で持続的な攻撃の検知に有効
3️⃣ 新規対応リージョン
  • アジアパシフィック (タイ)
  • メキシコ (中部)
  • AWS GovCloud (US-East)
  • AWS GovCloud (US-West)

📋 技術仕様

集約キーと評価ウィンドウ

項目詳細
集約キーの種類IP アドレス、HTTP ヘッダー、Cookie、クエリ文字列、URI パス、HTTP メソッド、ラベル名前空間など
複合キー最大 5 つのコンポーネントを組み合わせ可能
評価ウィンドウ1 分、2 分、5 分、10 分
実行可能なアクションBlock、CAPTCHA、Challenge、Count など
設定方法AWS WAF コンソール、AWS CLI、SDK、AWS CloudFormation

設定例: 複合キーを使用したレートベースルール

JSON IP + User-Agent の複合キーで 60 秒 / 100 リクエストを超えたらブロック 
{
  "Name": "LoginRateLimit",
  "Priority": 1,
  "Statement": {
    "RateBasedStatement": {
      "Limit": 100,
      "EvaluationWindowSec": 60,
      "AggregateKeyType": "CUSTOM_KEYS",
      "CustomKeys": [
        { "IP": {} },
        {
          "Header": {
            "Name": "User-Agent",
            "TextTransformations": [
              { "Priority": 0, "Type": "NONE" }
            ]
          }
        }
      ]
    }
  },
  "Action": { "Block": {} },
  "VisibilityConfig": {
    "SampledRequestsEnabled": true,
    "CloudWatchMetricsEnabled": true,
    "MetricName": "LoginRateLimit"
  }
}

IP アドレスと User-Agent ヘッダーの組み合わせごとに、60 秒間で 100 リクエストを超えた場合にブロックするルールの例です。

STEP 1既存の Web ACL を確認する

Bash Web ACL 一覧の取得 
aws wafv2 list-web-acls \
  --scope REGIONAL \
  --region ap-southeast-7

アジアパシフィック (タイ) リージョンのリージョナルスコープの Web ACL 一覧を取得します。 GovCloud (US) の場合は対応するリージョン名を指定します。

STEP 2高度なレートベースルールを追加する

Bash Web ACL の更新 
aws wafv2 update-web-acl \
  --scope REGIONAL \
  --region ap-southeast-7 \
  --id <web-acl-id> \
  --name <web-acl-name> \
  --lock-token <lock-token> \
  --default-action Allow={} \
  --visibility-config SampledRequestsEnabled=true,CloudWatchMetricsEnabled=true,MetricName=MyWebACL \
  --rules file://rate-based-rule.json

複合キーと評価ウィンドウを定義したルール (前述の JSON 例) を含むファイルを指定して、Web ACL を更新します。 --lock-token には get-web-acl で取得した値を指定します。

STEP 3動作確認

CloudWatch メトリクスとサンプルリクエストを確認し、ルールが意図したとおりにリクエストを集約・制限しているかを検証します。 まず Count アクションで挙動を確認してから Block に切り替えると、誤遮断のリスクを抑えられます。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓規制対応環境での高度な保護: AWS GovCloud (US) を利用する政府機関や規制業界のユーザーが、商用リージョンと同等の高度なレート制限機能を利用可能
✓新興リージョンでのセキュリティ強化: タイ・メキシコリージョンのワークロードでも精緻なボット対策・DDoS 対策が可能
✓追加コストなし: 標準の AWS WAF 料金のみで利用可能

🔧 技術面のメリット

✓分散型攻撃への対応力向上: IP アドレス単体では検知が難しい分散型攻撃に対し、複合キーによる集約で効果的な制限が可能
✓迅速な検知: 1 分・2 分の短い評価ウィンドウにより、リクエストフラッドへの対応時間を短縮
✓柔軟な制御: セッション Cookie 単位、API キー単位など、アプリケーションの特性に合わせたレート制限を設計可能

🚧 制限事項

✗複合キーに組み合わせられるコンポーネントは最大 5 つまで
✗評価ウィンドウは 1 分、2 分、5 分、10 分の 4 種類から選択 (任意の値は指定不可)
✗レートベースルールのカウントは近似値であり、しきい値到達後のブロック開始には若干の遅延が生じる場合がある

💡 考慮すべき点

⚠集約キーの設計を誤ると、正当なユーザーを誤ってブロックする可能性があるため、まず Count アクションでの検証を推奨
⚠ヘッダーや Cookie は攻撃者が偽装可能なため、集約キーの選択時には回避リスクを考慮する必要がある

🎯 ユースケース

🔐 ユースケース 1: ログイン試行のレート制限

シナリオ: GovCloud (US) 上の政府系 Web アプリケーションで、ブルートフォース攻撃によるログイン試行を制限したい。

集約キー: IP アドレス + User-Agent ヘッダー 評価ウィンドウ: 1 分 しきい値: 50 リクエスト アクション: Block スコープダウン: URI パスが /login に一致するリクエストのみ

効果: IP アドレスと User-Agent の組み合わせ単位で制限することで、単一 IP からの大量試行を迅速にブロックしつつ、同一 NAT 配下の正当なユーザーへの影響を軽減できます。

🛒 ユースケース 2: セッション単位の API レート制限

シナリオ: タイリージョンで運用する EC サイトの API に対し、セッションごとの過剰なリクエストを制限したい。

集約キー: セッション Cookie 評価ウィンドウ: 2 分 しきい値: 300 リクエスト アクション: CAPTCHA

効果: セッション Cookie 単位で集約することで、複数 IP を使い分けるボットによるスクレイピングや在庫買い占めを抑制できます。

🐢 ユースケース 3: 低速で持続的な攻撃の検知

シナリオ: メキシコ (中部) リージョンのワークロードで、しきい値を下回る速度で長時間継続するリクエストを検知したい。

集約キー: IP アドレス + URI パス 評価ウィンドウ: 10 分 しきい値: 1,000 リクエスト アクション: Count でラベル付与後、別ルールで Challenge

効果: 長い評価ウィンドウにより、短時間の観測では検知できない持続的な攻撃パターンを捕捉できます。

💰 料金と利用可能リージョン

料金

追加料金は発生せず、標準の AWS WAF 料金が適用されます。 Web ACL、ルール、リクエスト数に応じた既存の料金体系のまま、高度なレートベースルールを利用できます。

📝 まとめ

AWS WAF の高度なレートベースルールが AWS GovCloud (US)、タイ、メキシコの各リージョンに拡大され、 複合キーによる集約と 1 分・2 分の短い評価ウィンドウが利用可能になりました。

✓対象リージョンでワークロードを運用している場合は、既存の IP アドレスベースのレートベースルールを見直し、アプリケーション特性に合わせた複合キーと評価ウィンドウへの移行を検討することを推奨
⚠誤遮断を避けるため、まず Count アクションで挙動を検証してから Block や CAPTCHA への切り替えを実施
