📌 概要

Amazon SageMaker Studio のノートブックが G7e インスタンスタイプをサポートしました。 これにより、生成 AI やグラフィックスワークロードを開発・実験する際に、最新世代の NVIDIA GPU を直接利用できます。

G7e は最大 8 基の NVIDIA RTX PRO 6000 Blackwell Server Edition GPU (GPU あたり 96 GB)、 第 5 世代 Intel Xeon による最大 192 vCPU、最大 1600 Gbps の EFA 帯域幅を備え、 LLM・エージェント型 AI・マルチモーダル生成 AI・フィジカル AI などの要求の高いワークロードをノートブック上で直接デプロイ・実験できます。

⛔ アップデート前の課題

  • 最新の Blackwell アーキテクチャ GPU を備えた G7e を選択できなかった
  • ノートブック上で大規模モデルを扱う際に GPU メモリの制約があった
  • マルチ GPU の高速通信を活かしたインタラクティブ開発が難しかった
  • フィジカル AI など高負荷ワークロード向けの GPU 選択肢が不足

✅ アップデート後の改善

  • 最大 8 基の NVIDIA RTX PRO 6000 Blackwell GPU を利用可能に
  • 最大 768 GB の合計 GPU メモリで大規模モデルを直接ロード・実験
  • NVIDIA GPUDirect P2P でマルチ GPU 性能が向上
  • EC2 UltraClusters で EFAv4 による GPUDirect RDMA をサポート

🛠️ 設定方法

① サービスクォータの確認

SageMaker で利用可能な G7e 関連のクォータを一覧表示します。不足時は Service Quotas コンソールから引き上げをリクエストします。

BashG7e クォータの確認
aws service-quotas list-service-quotas \
  --service-code sagemaker \
  --query "Quotas[?contains(QuotaName, 'g7e')]"

② ノートブックアプリケーションを起動

SageMaker Studio コンソールで JupyterLab または CodeEditor のスペースを作成し、インスタンスタイプとして G7e (例: ml.g7e.xlarge) を選択して起動します。

③ GPU の利用を確認

起動したノートブックのターミナルで以下を実行し、Blackwell GPU が認識され GPU メモリ (96 GB / GPU) が確保されていることを確認します。

BashGPU 認識の確認
nvidia-smi

💡 ユースケース

1. 大規模言語モデルのインタラクティブな実験

数百億パラメータ規模の LLM をノートブック上で直接ロードし、プロンプトや推論パラメータを試行錯誤しながら検証します。

Python大規模モデルのロードと推論
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

# G7e の大容量 GPU メモリを活用して大規模モデルをロード
model_name = "meta-llama/Llama-3-70B"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype=torch.float16,
    device_map="auto"  # 複数 GPU に自動分散
)

inputs = tokenizer("生成 AI の活用方法について", return_tensors="pt").to("cuda")
outputs = model.generate(**inputs, max_new_tokens=256)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

→ 最大 768 GB の GPU メモリで、追加インフラなしに単一ノートブックで大規模モデルを実験できる

2. マルチモーダル生成 AI モデルの開発

画像とテキストを組み合わせたマルチモーダルモデルを、複数 GPU を活用して高速にプロトタイピングします。

Pythonマルチ GPU 並列処理
import torch

# 複数 GPU を活用したマルチモーダルモデルの並列処理
device_count = torch.cuda.device_count()

# GPUDirect P2P により GPU 間データ転送を効率化
model = MultimodalModel().to("cuda")
model = torch.nn.DataParallel(model)

→ GPUDirect P2P によるマルチ GPU 間の高速通信でプロトタイピングを効率化できる

3. フィジカル AI・空間コンピューティングワークロード

ロボティクスやシミュレーション向けのフィジカル AI モデルを、グラフィックスと AI 処理の両方を必要とするワークロードとして開発します。

# Blackwell GPU のグラフィックス・AI 処理能力を活用

⚠️ デメリット・制約事項

!米国東部 (バージニア北部、オハイオ) と米国西部 (オレゴン) のみ利用可能 (東京リージョンは対象外)
!G7e のサービスクォータがデフォルトで低い可能性があり、事前の引き上げリクエストが必要な場合がある
!NVIDIA RTX PRO 6000 は A100 / H100 とアーキテクチャが異なり、ワークロードによって性能特性が異なる
!オンデマンド料金が高額になるため、利用後はスペースをシャットダウンしてコストを抑える運用が重要
!大規模な本番トレーニングには SageMaker HyperPod やトレーニングジョブの利用を検討
!マルチノードの GPUDirect RDMA 活用には EC2 UltraClusters 構成が前提

📝 まとめ

SageMaker Studio ノートブックが G7e をサポートしたことで、データサイエンティストは最新の NVIDIA RTX PRO 6000 Blackwell GPU をインタラクティブな開発環境で直接利用できます。 最大 768 GB の GPU メモリ、最大 1600 Gbps の EFA 帯域幅、GPUDirect P2P / RDMA により、 LLM やマルチモーダル生成 AI、フィジカル AI などの要求の高いワークロードを効率的に開発・実験できます。 現時点では米国の 3 リージョンに限定されているため、対象リージョンとサービスクォータを確認したうえで、 コスト管理のためにスペースの適切なシャットダウン運用を推奨します。
