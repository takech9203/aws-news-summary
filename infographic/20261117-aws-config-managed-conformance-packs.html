AWS Config

⚙️ マネージドコンフォーマンスパック

AWS が構築・保守するコンプライアンスフレームワーク向け事前定義ルールセット
📅 2026 年 11 月 17 日
Managed Conformance Packs — 選んでデプロイするだけ、更新は AWS におまかせ

📋 概要

AWS Config がマネージドコンフォーマンスパックを発表しました。 PCI DSS や SOC 2 などのコンプライアンス・ガバナンスフレームワーク向けに AWS が構築・保守する事前定義済みの AWS Config ルールのコレクションです。 デプロイ時にフレームワークを選択するだけで、AWS Config がリソースをそのフレームワークに照らして評価します。

最大の特長は、AWS がパックの内容を継続的に最新の状態に保つ点です。 新しいマネージドルールの登場やフレームワークの改訂に応じて、デプロイ済みのパックが自動的に更新されます。 また、サポートされるすべてのリージョンで一貫したパック定義が維持されるため、 リージョンごとのルールセット管理なしで同じフレームワークを複数リージョンに展開できます。

😓 Before: サンプルテンプレート方式

  • サンプルテンプレートを起点に環境向けのカスタマイズが必要
  • 新ルール登場やフレームワーク変更のたびにテンプレートを手動更新
  • リージョンごとに利用可能なルールが異なり、リージョン別テンプレート管理が必要なケースも

🚀 After: マネージドパック

  • フレームワークを選択してデプロイするだけ。テンプレートの作成・更新作業が不要
  • 新ルールのマッピングやフレームワーク改訂に応じてデプロイ済みパックが自動更新
  • デプロイ先リージョンで利用可能なルールを自動的に含み、リージョン別テンプレートが不要
  • ルールパラメータは環境に合わせて設定・更新可能。結果とスコアはコンソールで統合表示

従来はサンプルテンプレートのカスタマイズと手動更新が必要でしたが、マネージドコンフォーマンスパックでは フレームワークを選択してデプロイするだけで、AWS がパック定義の保守と自動更新を行います。

⭐ 主要機能

🛠️ AWS によるパックの構築・保守

AWS がフレームワークごとに事前定義されたパックを構築・保守。ユーザーはフレームワークを選択してデプロイするだけで、 AWS Config がリソースを評価。テンプレートの作成やカスタマイズは不要。

🔄 デプロイ済みパックの自動更新

フレームワークのコントロールに対応する新しいマネージドルールが登場すると、デプロイ済みのパックに自動追加。 フレームワーク改訂時も AWS がパックを自動更新。新ルールはデフォルトパラメータ値でデプロイされ即時評価。 ルールの追加・更新・削除は Amazon CloudWatch メトリクスで通知。

🌍 リージョン間で一貫したパック定義

AWS がサポートされるすべてのリージョンで一貫したパック定義を維持。各パックはデプロイ先リージョンで 利用可能なマネージドルールを含み、新ルールが利用可能になると追加。リージョン別のルールセット管理なしで 同じフレームワークを複数リージョンに展開可能。

🎛️ ルールパラメータのカスタマイズ

デプロイ時にパック内ルールのパラメータを環境に合わせて設定でき、デプロイ後もサポートされるパラメータを更新可能。 未指定の場合はデフォルト値が使用される。

📊 コンソールでの統合された可視化

コンプライアンス結果とコンプライアンススコアが AWS Config コンソールに表示され、 既存のルールやコンフォーマンスパックと並べて確認可能。

🔌 API 変更 (2026/11/17)

AWS Config - 3 updated api methods

PutConformancePack に Source と Scope パラメータが追加。 DescribeConformancePacks と DescribeConformancePackStatus に Type フィールドと type フィルターが追加。 DescribeConformancePackStatus にオプションの StackArn が追加。

🚀 設定方法

✅ 前提条件

✓AWS Config が有効化されており、コンフィギュレーションレコーダーが実行中であること
✓評価対象のリソースタイプに対して AWS Config レコーディングが有効であること (すべてのサポート対象リソースタイプの記録が推奨)
✓コンフォーマンスパックのデプロイに必要な IAM 権限 (config:PutConformancePack など) があること

📝 手順

1
AWS Config コンソールでコンフォーマンスパックを開く
ナビゲーションペインから [Conformance packs] を選択し、マネージドコンフォーマンスパックのカタログからデプロイしたいフレームワークを選択します。
2
ルールパラメータの設定とデプロイ
デプロイ時にパック内ルールのパラメータを環境に合わせて設定します。未指定の場合はデフォルト値が使用されます。設定後、デプロイを実行します。
3
CLI でのデプロイ (オプション)
AWS CLI からもデプロイとステータス確認が可能です。
Bash AWS CLI でのデプロイ例 
# マネージドコンフォーマンスパックをデプロイ
# Source パラメータでマネージドパックのフレームワークを指定する
aws configservice put-conformance-pack \
  --conformance-pack-name my-managed-pack \
  --source <マネージドパックのソース指定>

# デプロイ済みコンフォーマンスパックを種類でフィルタリングして確認
aws configservice describe-conformance-packs

# デプロイステータスを確認
aws configservice describe-conformance-pack-status

put-conformance-pack は今回のアップデートで追加された Source パラメータによりマネージドパックのデプロイに対応。 describe-conformance-packs と describe-conformance-pack-status では、新しい Type フィールドにより マネージドパックとカスタムパックを区別できます。具体的なパラメータ形式は AWS CLI リファレンスを確認してください。

4
コンプライアンス結果の確認
デプロイ後、[Conformance packs] ダッシュボードでコンプライアンス結果とコンプライアンススコアを確認します。結果は既存のルールやコンフォーマンスパックと並べて表示されます。

💡 メリット

💼 ビジネス面

✓コンプライアンス運用コストの削減: フレームワークの変更追跡やルールの手動更新が不要になり、コンプライアンスチームの運用負荷が削減される
✓準拠状況の鮮度維持: AWS がパックを自動更新するため、フレームワーク改訂への追従漏れによる評価の陳腐化リスクが低減される
✓AI ガバナンスへの対応: EU AI Act や NIST AI RMF などの AI ガバナンスフレームワークに対する評価を迅速に開始できる

⚙️ 技術面

✓マルチリージョン展開の簡素化: リージョンごとのテンプレート管理が不要になり、同一フレームワークを複数リージョンへ一貫して展開できる
✓新ルールの自動取り込み: 新しいマネージドルールがフレームワークのコントロールにマッピングされると自動的にパックへ追加され、評価が開始される
✓既存ワークフローとの統合: コンプライアンス結果とスコアが AWS Config コンソールに統合表示され、既存の運用フローを変えずに利用できる

⚠️ デメリット・制約事項

🚫 制限事項

🔸マネージドパックに含まれるルールの追加・削除はできない (ルール構成を制御したい場合はカスタムコンフォーマンスパックを使用)
🔸組織コンフォーマンスパックによる AWS Organizations 全体への一括デプロイには非対応 (個別のアカウント・リージョン単位でデプロイ)
🔸中東 (UAE) と中東 (バーレーン) リージョンでは利用不可
🔸デプロイされるルールは、リージョンでの AWS Config ルールの利用可否に応じてリージョンごとに異なる場合がある

🤔 考慮すべき点

💭法令・規制・業界標準への準拠を保証するものではなく、準拠の判断はユーザーの責任
💭新しいルールはデフォルトパラメータ値で自動デプロイされ即時評価されるため、意図しない非準拠検出が増える可能性がある (CloudWatch メトリクスによる更新通知の監視を推奨)
💭評価対象リソースタイプの AWS Config レコーディングが有効でないと正しく評価されない
💭パックのデプロイにより AWS Config ルール評価が発生し、評価数に応じた料金が発生する

🎯 ユースケース

💳 1. PCI DSS v4 準拠状況の継続的モニタリング

決済システムを運用する企業が PCI DSS v4 への準拠状況を継続的に評価。従来はサンプルテンプレートをカスタマイズし、ルールの追加のたびに手動更新していた。

📋 PCI DSS v4 パックを選択
→
🎛️ パラメータ設定してデプロイ
→
📊 スコアを継続確認
✨ 効果: テンプレート保守が不要になり、PCI DSS v4 の改訂や新ルール追加にも自動追従。監査準備の工数を削減。
🌍 2. マルチリージョン環境への NIST SP 800-53 の一括適用

複数リージョンでワークロードを運用する組織が、NIST SP 800-53 Rev. 5 に基づくガバナンスを全リージョンで統一的に適用。 各リージョンではそのリージョンで利用可能なルールが自動的に含まれ、新ルールが利用可能になると自動追加される。

✨ 効果: リージョン別のテンプレート管理が不要になり、全リージョンで一貫したフレームワーク評価を維持。
🤖 3. 生成 AI ワークロードの AI ガバナンス評価

生成 AI アプリケーションを運用する企業が、EU AI Act や NIST AI RMF のマネージドパックを AI ワークロードが稼働するリージョンにデプロイし、 コンプライアンス結果をもとにガバナンス上のギャップを特定。

✨ 効果: AI ガバナンスフレームワークに対応するルールセットを自前で構築することなく、評価を迅速に開始。

💰 料金

標準のコンフォーマンスパック評価レートで課金。パック内の AWS Config ルールによる リソース評価 1 回ごとに料金が発生する従量課金で、評価数に応じた段階的な料金体系です。

0.001 USD
1 評価あたり (最初の 100,000 評価、バージニア北部)
15 USD / 月
パック 5 個 × 各 10 ルール × ルールあたり 300 評価 = 15,000 評価の場合

最新の料金と 100,000 評価を超える場合の段階料金は AWS Config 料金ページ を参照してください。

🗺️ 利用可能リージョン

中東 (UAE) と中東 (バーレーン) を除くすべての AWS 商用リージョンで利用可能です。 🇯🇵 東京・大阪リージョンを含みます。サポートされるリージョンの完全なリストは AWS Capabilities by Region を参照してください。

🔗 関連サービス・機能

📐 AWS Config マネージドルール

マネージドパックを構成する評価ルール。新しいルールがフレームワークのコントロールにマッピングされるとパックに自動追加される。

📄 カスタムコンフォーマンスパック

ルール構成を自分で制御したい場合に YAML テンプレートで作成。AWS Organizations 全体へのデプロイにも対応。

🛡️ AWS Security Hub

セキュリティ標準に基づくチェックとセキュリティ態勢の統合管理を提供。AWS Config と連携してコンプライアンス可視化を補完。

📈 Amazon CloudWatch

マネージドパック内のルールの追加・更新・削除をメトリクスで通知。

📌 まとめ

AWS Config のマネージドコンフォーマンスパックにより、PCI DSS v4 や SOC 2、NIST SP 800-53 などの主要フレームワークに対する評価が、 テンプレートの作成・保守なしで利用できるようになりました。 AWS がパックを自動更新するため、フレームワーク改訂や新ルール追加への追従作業が不要になります。 現在サンプルテンプレートベースのコンフォーマンスパックを手動で保守している場合は、 マネージドコンフォーマンスパックへの移行を検討することを推奨します。
