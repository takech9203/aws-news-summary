AWS CloudFormation 📅 2026 年 11 月 20 日リリース

⚙️ サービスマネージド StackSets の
カスタム実行ロール対応

最小権限デプロイとネストスタック、マクロ、トランスフォームのサポートを実現

📌 概要

AWS CloudFormation StackSets が、サービスマネージド型のスタックセットでカスタム実行ロールをサポートしました。 StackSets が各ターゲットアカウントで実行できる操作を、お客様自身が定義した IAM ロールの権限の範囲に制限できます。

実行ロールを定義したテンプレートを指定すると、StackSets がデプロイに先立って各アカウントにそのロールを作成し、以降のデプロイで使用します。 さらに、カスタム実行ロールの使用により、サービスマネージド StackSets でもネストスタック、マクロ、トランスフォームが利用可能になります。

❌ アップデート前の課題
✗組み込みの実行ロールは、テンプレート内のあらゆるリソースをプロビジョニングできる広範な権限を保持
✗ターゲットアカウントごとに権限を制限する手段がなく、最小権限の原則を適用できない
✗ネストスタック、マクロ、トランスフォームが利用できず、既存テンプレートを再利用できない場合がある
✅ アップデート後の改善
✓実行ロールのテンプレートを指定し、各アカウントでの操作を必要最小限の権限に制限
✓実行ロールのテンプレート更新が、デプロイ済みのすべてのアカウントに自動反映
✓ネストスタック、マクロ、トランスフォームが利用可能になり、既存テンプレートの組織全体への再利用が容易に

管理者が実行ロールテンプレートとメインテンプレートを StackSets に指定すると、StackSets はまず各ターゲットアカウントにカスタム実行ロールを作成し、そのロールの権限の範囲内でスタックインスタンスをデプロイします。

🔧 主要機能

🔒 1. カスタム実行ロールによる権限の制限
→実行ロールを定義した CloudFormation テンプレートを指定すると、StackSets がデプロイ前に各ターゲットアカウントへそのロールを作成
→StackSets が各アカウントで実行できる操作を、定義したロールの権限の範囲内に制限
→例: S3 バケットを作成するスタックセットには、CloudFormation と S3 の権限のみを持つロールを使用可能
→デフォルトの組み込みロール (追加設定なしで任意のリソースをプロビジョニング可能) も引き続き利用可能
🔄 2. 実行ロールの自動更新
→実行ロールのテンプレートを変更すると、デプロイ済みのすべてのアカウントに更新後のロールを自動反映
→アカウントごとに手動でロールを更新する運用負荷が不要に
📦 3. ネストスタック、マクロ、トランスフォームのサポート
→カスタム実行ロールの使用で、サービスマネージド StackSets でもネストスタック、マクロ、トランスフォームが利用可能に
→個別スタック向けに作成した既存テンプレートを、組織全体へのデプロイに再利用可能

📝 実行ロールテンプレートの例

YAML S3 のみに権限を制限した実行ロール 
AWSTemplateFormatVersion: "2010-09-09"
Resources:
  StackSetExecutionRole:
    Type: AWS::IAM::Role
    Properties:
      AssumeRolePolicyDocument:
        Version: "2012-10-17"
        Statement:
          - Effect: Allow
            Principal:
              Service: cloudformation.amazonaws.com
            Action: sts:AssumeRole
      Policies:
        - PolicyName: S3OnlyPolicy
          PolicyDocument:
            Version: "2012-10-17"
            Statement:
              - Effect: Allow
                Action:
                  - s3:CreateBucket
                  - s3:DeleteBucket
                  - s3:PutBucketTagging
                Resource: "*"

S3 バケットのみを管理するスタックセット向けに、S3 関連の操作に権限を制限した実行ロールの定義例です。実際の信頼ポリシーや必要なアクションは、公式ドキュメントで最新の要件を確認してください。

実行ロール (IAM ロール) を定義したテンプレートを作成し、テンプレート URL として参照できるよう S3 バケットにアップロードします。

2
カスタム実行ロールを指定してスタックセットを作成
Bashcreate-stack-set
aws cloudformation create-stack-set \
  --stack-set-name my-stackset \
  --template-url https://my-templates-bucket.s3.amazonaws.com/main-template.yaml \
  --execution-role-template-url https://my-templates-bucket.s3.amazonaws.com/execution-role.yaml \
  --permission-model SERVICE_MANAGED \
  --auto-deployment Enabled=true,RetainStacksOnAccountRemoval=false \
  --capabilities CAPABILITY_NAMED_IAM

--execution-role-template-url で実行ロールテンプレートを指定し、サービスマネージド型のスタックセットを作成します。StackSets はデプロイ前に各ターゲットアカウントへ実行ロールを作成します。マネジメントコンソールの場合は、スタックセット作成時に [Set execution role] を選択します。

3
スタックインスタンスのデプロイ
Bashcreate-stack-instances
aws cloudformation create-stack-instances \
  --stack-set-name my-stackset \
  --deployment-targets OrganizationalUnitIds=ou-xxxx-xxxxxxxx \
  --regions ap-northeast-1 us-east-1

対象の OU とリージョンを指定してスタックインスタンスをデプロイします。各アカウントでは、作成されたカスタム実行ロールの権限の範囲内でリソースがプロビジョニングされます。

💡 メリット

💼 ビジネス面
✓セキュリティガバナンスの強化: 権限を必要最小限に制限し、セキュリティポリシーやコンプライアンス要件への準拠が容易に
✓監査対応の簡素化: 各アカウントで StackSets が実行可能な操作が明確になり、説明責任を果たしやすく
✓既存資産の活用: ネストスタックを含む既存テンプレートを組織全体に再利用でき、再作成コストを削減
⚙️ 技術面
✓最小権限の原則の適用: デプロイするリソースに応じた権限のみを定義でき、意図しないリソース操作を防止
✓ロール管理の自動化: テンプレートの変更が全アカウントに自動反映され、手動更新作業が不要に
✓モジュール化されたテンプレート設計: ネストスタック、マクロ、トランスフォームの利用で保守性が向上

⚠️ デメリット・制約事項

🚧 制限事項
⚠サービスマネージド型のスタックセットで利用する機能であり、実行ロールのテンプレートを別途作成・管理する必要がある
⚠実行ロールの権限が不足している場合はデプロイが失敗するため、リソースに応じた権限設計が必要
⚠ネストスタックやマクロ、トランスフォームの利用にはカスタム実行ロールの使用が前提
🤔 考慮すべき点
⚠権限を絞り込みすぎるとテンプレート変更時にデプロイが失敗する可能性があるため、テンプレートとロールの権限を合わせて管理する運用が必要
⚠実行ロールテンプレートの更新は全アカウントに自動反映されるため、変更時は影響範囲の事前確認を推奨
⚠具体的な制約の詳細は公式ドキュメントで確認が必要

💰 料金・利用可能リージョン

💵 料金

本機能は追加料金なしで利用できます。CloudFormation 自体の利用料金 (サードパーティリソースのハンドラーオペレーションなど) は通常どおり適用されます。

🌏 利用可能リージョン

すべての商用 AWS リージョン、AWS GovCloud (US) リージョン、中国リージョンで利用可能です。最新の対応状況は AWS リージョン別サービス表を参照してください。

🔗 関連サービス・機能

→AWS Organizations: サービスマネージド StackSets のターゲット選択の基盤となるサービス。OU 単位でのデプロイや新規アカウントへの自動デプロイと連携
→AWS IAM: カスタム実行ロールは IAM ロールとして定義され、最小権限の原則に基づく権限設計が中心
→AWS Control Tower: 組織全体のガバナンスを提供するサービスで、内部的に StackSets を利用してベースラインを展開

📝 まとめ

サービスマネージド StackSets のカスタム実行ロール対応により、マルチアカウント環境でのデプロイに最小権限の原則を適用できるようになり、同時にネストスタック、マクロ、トランスフォームの利用も解禁されました。 AWS Organizations で StackSets を運用している組織は、セキュリティ要件の厳しいワークロードから順にカスタム実行ロールの導入を検討することを推奨します。
