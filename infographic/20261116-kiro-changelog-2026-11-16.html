Kiro CLI 3.4.0 のフック強化 / Kiro Enterprise のリアルタイム OpenTelemetry イベントとプライベート接続

📋 概要

Kiro のチェンジログに 2 件のアップデートが公開されました。

1. Kiro CLI 3.4.0: フックによるツール入力の書き換えと権限プロンプトへの応答

ツール呼び出しの入力を実行前に書き換えたり、権限プロンプトにスクリプトで応答したりできるフックが追加。V3 セッションのすべてのツール呼び出しに対して、手動承認を待たずにチームのルールをスクリプトで自動適用できます。あわせて /memories の 4 択化、クラウドセッションの改善、各種修正を含みます。

2. Kiro Enterprise: リアルタイムイベントとプライベート接続

各 LLM リクエストと完了したツール呼び出しをリアルタイムの OpenTelemetry イベントとしてストリーミング可能に。クレジット、モデル、会話、応答時間、ツールの実行結果、クライアントバージョン、エージェントモードを追跡でき、AWS PrivateLink / Amazon VPC Lattice によるプライベート接続も選択できます。

🔄 Before / After

❌ アップデート前の課題
  • V3 セッションで権限が必要なツール呼び出しは、ユーザーが 1 件ずつ手動で承認する必要があった
  • フックからツール呼び出しの入力内容を実行前に変更する手段がなかった
  • /memories は 3 レベル + 自動更新チェックボックスに分かれ、意図を表現しにくかった
  • Enterprise の利用状況データは日次ベース中心で、リクエスト単位のリアルタイム可視化ができなかった
✅ アップデート後の改善
  • PreToolUse フックが updatedInput を返し、ツール実行前に入力を書き換え可能に
  • 新しい PermissionRequest フックが権限プロンプトに allow / deny で自動応答
  • /memories が 4 つの選択肢に整理
  • LLM リクエストとツール呼び出し単位のリアルタイム OpenTelemetry イベントをストリーミング可能に
  • AWS PrivateLink と Amazon VPC Lattice によるプライベート接続を選択可能に

⚡ 主要機能 1: Kiro CLI 3.4.0

🪝 PreToolUse フックによる入力の書き換え
  • V3 セッションで updatedInput を返すことで、ツール実行前に入力を置き換え可能
  • 従来からの allow / ask / deny の判断と組み合わせて使用できる
  • コマンドの書き換えや安全なパラメータへの変換など、チームルールを全ツール呼び出しに自動適用
🔐 PermissionRequest フックによる権限プロンプトへの応答
  • ツール呼び出しがユーザーに権限を求める場面で実行される新しいフック
  • allow または deny で応答し、承認待ちの呼び出しをスクリプトが許可・拒否
  • いずれかのフックの deny は allow より優先
  • フックによる権限応答は、その 1 回のツール呼び出しにのみ適用
🧠 /memories の 4 つの選択肢
  • 「自動的に使用・作成」「求められたときに作成」「使用のみ」「オフ」の 4 択に再編
  • 従来の 3 レベル (read & write / read only / off) と別個の自動更新チェックボックスを置き換え
☁️ クラウドセッションの改善
  • --cloud --resume が --no-interactive (ヘッドレス) でも最新のクラウドセッションを再開 (セッションがない場合は終了コード 1)
  • --no-interactive --cloud 実行時に、ローカル mcp.json で有効化されたサーバーのうち使用されないものの数を通知
  • クラウドの /knowledge add / /knowledge update はインデックス対象がクラウドサンドボックス内であることを明示
  • クラウドセッションで実行できないコマンドは / メニュー、Tab 補完、/help から除外
🔧 修正
  • プロンプトがコンテキストウィンドウに収まらない場合、--no-interactive セッションは終了コード 1 で失敗するように変更
  • 起動中に別のツールが作成した cli.json を上書きしないように修正
  • ヘッドレス、MCP、検索、/tangent、/rewind、表示に関する修正を含む

📡 主要機能 2: Kiro Enterprise

📊 リアルタイム OpenTelemetry イベント
  • 各 LLM リクエストと完了したツール呼び出しをリアルタイムイベントとしてストリーミング
  • クレジット、モデル、会話、応答時間、ツールの実行結果、クライアントバージョン、エージェントモードを追跡
  • 整合済みのトレンド把握には日次 CSV レポートと OpenTelemetry メトリクスを利用可能
🔒 プライベート接続
  • 配信経路をパブリック配信、AWS PrivateLink、Amazon VPC Lattice から選択可能
  • プライベート接続はパブリック配信にフォールバックしない
  • 各エクスポートは Kiro コンソールで有効化とテストが可能
🛡️ データの範囲
  • エクスポートには利用状況データとユーザー識別子が含まれる
  • プロンプト、応答、コード、ファイルは含まれない
🕐 日次メトリクスのスケジュール変更
  • 日次メトリクスは 2026 年 11 月 26 日に 00:30 UTC へ移行 (それまでは Dynatrace と Grafana Cloud が「古すぎる」として拒否)
  • CSV レポートは 02:00 UTC のまま変更なし

ステップ 1: Kiro CLI を 3.4.0 に更新する

Bash バージョン確認 
kiro --version

現在の CLI バージョンを確認します。3.4.0 未満の場合は、最新版に更新してから V3 セッションを開始します。

ステップ 2: フックを設定する

PreToolUse フックで updatedInput を返すスクリプト、または PermissionRequest フックで allow / deny を返すスクリプトを作成し、フック設定に登録します。詳細は Hooks Types ドキュメントを参照してください。

ステップ 3: Kiro Enterprise のエクスポートを有効化する

Kiro コンソールで、リアルタイムイベントまたは OpenTelemetry メトリクスのエクスポートを有効化し、配信経路 (パブリック、AWS PrivateLink、Amazon VPC Lattice) を選択してテストします。詳細は User Activity ドキュメントを参照してください。

💡 メリット

💼 ビジネス面
  • ガバナンスの自動化: チームルールをフックで強制し、手動承認のボトルネックを解消しつつ統制を維持
  • 利用状況の可視化: クレジット消費やモデル利用をリアルタイムに把握し、コスト管理と利用最適化に活用
  • コンプライアンス対応: プロンプトやコードを含まない利用状況データを、プライベート接続経由で安全に集約
⚙️ 技術面
  • きめ細かな制御: 拒否するだけでなく「安全な形に修正して実行」という選択肢が追加
  • CI/CD との親和性: ヘッドレスでのクラウドセッション再開や明確な失敗 (終了コード 1) により挙動が予測可能に
  • 標準技術の採用: OpenTelemetry (OTLP) ベースのため、Dynatrace、Grafana Cloud など既存ツールと統合しやすい

⚠️ デメリット・制約事項

制限事項

✗フックによる入力書き換えと権限応答は V3 セッションでのみ利用可能
✗リアルタイムイベントとプライベート接続は、米国東部 (バージニア北部) と欧州 (フランクフルト) の Kiro プロファイルでのみ利用可能
✗日次メトリクスが 00:30 UTC に移行する 2026 年 11 月 26 日までは、Dynatrace と Grafana Cloud が日次メトリクスを「古すぎる」として拒否する

考慮すべき点

⚠PermissionRequest フックで自動承認を行う場合、承認ロジックの誤りがそのまま実行につながるため、スクリプトのレビューとテストが重要
⚠フックの deny は allow より常に優先されるため、複数フック併用時は判断の競合を設計段階で整理
⚠プライベート接続はパブリック配信にフォールバックしないため、接続障害時のイベント欠落を考慮した監視設計が必要
⚠エクスポートにはユーザー識別子が含まれるため、組織の個人情報の取り扱いポリシーに沿った運用が必要

🎯 ユースケース

1️⃣ チームルールによるコマンドの自動書き換え

シナリオ: 開発チームで、エージェントが実行するコマンドに必ず安全なオプションを付与したい。

実装: PreToolUse フックで対象ツールの入力を検査し、updatedInput でチーム標準のオプションを付与した入力に書き換えて allow を返す。

効果: 開発者ごとの設定差異に依存せず、すべてのツール呼び出しにチームルールを強制できる。

2️⃣ CI でのヘッドレス自動承認

シナリオ: CI パイプラインの --no-interactive 実行で、権限プロンプトにより処理が止まるのを避けたい。

実装: PermissionRequest フックで許可リストに一致する呼び出しに allow、それ以外に deny を返すスクリプトを登録する。

効果: 人の承認を待たずにパイプラインが完走しつつ、許可リスト外の操作は確実に拒否される。

3️⃣ Kiro 利用状況の組織横断ダッシュボード

シナリオ: エンタープライズ管理者として、部門ごとのクレジット消費、モデル利用、応答時間を既存の Grafana ダッシュボードで監視したい。

実装: Kiro コンソールでリアルタイムイベントのエクスポートを有効化し、AWS PrivateLink 経由で OTLP コレクターに送信、Grafana でクレジット・モデル・エージェントモード別に可視化する。

効果: LLM リクエスト単位の粒度でほぼリアルタイムに利用状況を把握でき、異常な消費の早期検知や部門別のコスト配分が可能になる。
