Amazon SageMaker AI

🤖 トレーニング/処理ジョブの
インスタンス優先リスト対応

📅 リリース日: 2026 年 9 月 15 日 ｜ 機能: Instance Preference Lists (インスタンス優先リスト)

📌 概要

SageMaker AI のトレーニングジョブ/処理ジョブで、優先順位を付けた最大 5 種類のインスタンスタイプを 1 回のジョブ送信で指定できるようになりました。SageMaker AI がリストを順に評価し、最初に容量を確保できた構成で自動起動します。

容量ソースとしてオンデマンドと SageMaker Flexible Training Plans を同一リスト内で組み合わせ可能。予約済みの ml.p5.48xlarge を第 1 優先とし、確保できなければオンデマンドの ml.p4d.24xlarge へフォールバックする、といった戦略を宣言的に構成できます。

✗夜間の再トレーニングパイプラインが InsufficientCapacityError で失敗し、手動での再実行が発生していた

✓予約容量を優先しつつオンデマンドへフォールバックする戦略を宣言的に構成可能に

優先順位付きのインスタンスリストを指定してジョブを送信すると、SageMaker AI がリストを順に評価し、最初に容量を確保できた構成でジョブを起動します。どのタイプでも容量を確保できない場合は、MaxPendingTimeInSeconds を上限として自動的に再試行します。

⚡ 主要機能

1️⃣ 優先順位付きインスタンスリストの指定
  • ResourceConfig の InstanceType の代わりに InstancePreferences で最大 5 種類を優先順位順にリスト
  • 起動後のモニタリングや課金は、そのタイプを直接指定した場合と同一
  • CreateTrainingJob API、AWS SDK、AWS CLI、SageMaker Python SDK、コンソールから利用可能。処理ジョブは ClusterConfig で同じ仕組みを利用
2️⃣ 柔軟なインスタンス台数の指定
  • 均一指定: ResourceConfig に 1 つの InstanceCount を設定し、選択タイプに関わらず同じ台数を使用
  • エントリごとの指定: 各エントリに個別の InstanceCount を設定し、GPU 数の異なるタイプ間で合計スループットを揃えられる (例: 4 GPU の ml.g5.12xlarge と 1 GPU の ml.g5.16xlarge で台数を変える)
  • 両方に設定、どちらにも未設定、一部のエントリのみ設定、といったリクエストは拒否される
3️⃣ オンデマンドと Flexible Training Plans の組み合わせ
  • エントリに TrainingPlanArns を付与すると、トレーニングプランの予約容量から確保 (タイプはプランと一致が必要)
  • プランなしのエントリはオンデマンド容量を使用。プラン付きエントリを先頭に置けば予約容量を優先試行
  • プランに空きがない場合は予約を待たずに次のエントリへ進み、オンデマンドで即座に開始
  • ジョブレベルの TrainingPlanArn も利用可能だが、エントリレベルの指定と併用不可
4️⃣ 容量待機と自動再試行
  • どのタイプにも容量がない場合、ジョブは待機して容量の解放に応じて再試行
  • MaxPendingTimeInSeconds はリスト全体での合計待機時間の上限 (タイプごとではない)
  • 待機は ml.p、ml.g、ml.trn などのアクセラレーテッドインスタンスを 1 つ以上含む場合のみ。CPU のみのリストは 1 回だけ評価され、容量がなければ失敗
5️⃣ 選択結果の確認
  • DescribeTrainingJob のレスポンスに読み取り専用の SelectedInstanceType / SelectedInstanceCount が返される
  • コンソールの「Instance type preferences」テーブルに選択済みタイプが「Selected」、選択前は「Pending selection」と表示

設定例: 均一台数での指定

ml.g6.48xlarge に容量がなければ ml.g5.48xlarge にフォールバックする例です。

JSON ResourceConfig - 均一台数 
"ResourceConfig": {
  "InstanceCount": 2,
  "VolumeSizeInGB": 500,
  "InstancePreferences": [
    { "InstanceType": "ml.g6.48xlarge" },
    { "InstanceType": "ml.g5.48xlarge" }
  ]
}

設定例: トレーニングプランとオンデマンドの組み合わせ

第 1 優先をトレーニングプランの予約容量、第 2 優先をオンデマンドとする例です。

JSON ResourceConfig - プラン + オンデマンド 
"ResourceConfig": {
  "InstanceCount": 4,
  "VolumeSizeInGB": 500,
  "InstancePreferences": [
    {
      "InstanceType": "ml.p5.48xlarge",
      "TrainingPlanArns": ["arn:aws:sagemaker:us-west-2:111122223333:training-plan/p5-plan"]
    },
    { "InstanceType": "ml.p4d.24xlarge" }
  ]
}

🛠️ 設定方法

前提条件

  • SageMaker AI のトレーニングジョブまたは処理ジョブを実行できる IAM 権限があること
  • リストに含めるすべてのインスタンスタイプについて、要求する台数を満たすサービスクォータが確保されていること (1 つでも不足するとリクエストが拒否される)
  • トレーニングコンテナがリスト内のすべてのインスタンスタイプで動作すること (SageMaker は GPU アーキテクチャ等の互換性を検証しない)
1
サービスクォータの確認
BashAWS CLI
aws service-quotas list-service-quotas \
  --service-code sagemaker \
  --query "Quotas[?contains(QuotaName, 'g6.48xlarge')]"

リストに含める予定のインスタンスタイプごとにトレーニングジョブ用のクォータを確認し、不足している場合は事前に引き上げをリクエストします。

2
優先リストを指定してジョブを作成
BashAWS CLI
aws sagemaker create-training-job \
  --training-job-name my-training-job \
  --algorithm-specification TrainingImage=<training-image-uri>,TrainingInputMode=File \
  --role-arn arn:aws:iam::111122223333:role/SageMakerExecutionRole \
  --output-data-config S3OutputPath=s3://my-bucket/output/ \
  --resource-config '{
    "InstanceCount": 2,
    "VolumeSizeInGB": 500,
    "InstancePreferences": [
      { "InstanceType": "ml.g6.48xlarge" },
      { "InstanceType": "ml.g5.48xlarge" }
    ]
  }' \
  --stopping-condition '{
    "MaxRuntimeInSeconds": 86400,
    "MaxPendingTimeInSeconds": 1800
  }'

InstanceType の代わりに InstancePreferences で優先リストを指定します。MaxPendingTimeInSeconds により容量待機の合計時間を 30 分に制限しています。

3
選択されたインスタンスタイプの確認
BashAWS CLI
aws sagemaker describe-training-job \
  --training-job-name my-training-job \
  --query "ResourceConfig.{Selected:SelectedInstanceType,Count:SelectedInstanceCount}"

実際に選択されたタイプと台数を確認します。これらのフィールドはタイプが選択された後にのみ返され、容量待機中は含まれません。

4
SageMaker Python SDK での利用 (オプション)
PythonModelTrainer + Compute
from sagemaker.core.shapes import InstancePreference
from sagemaker.core.training.configs import Compute
from sagemaker.train.model_trainer import ModelTrainer

compute = Compute(
    volume_size_in_gb=500,
    instance_preferences=[
        InstancePreference(
            instance_type="ml.p5.48xlarge",
            instance_count=4,
            training_plan_arns=["arn:aws:sagemaker:us-west-2:111122223333:training-plan/p5-plan"],
        ),
        InstancePreference(instance_type="ml.p4d.24xlarge", instance_count=8),
    ],
)

trainer = ModelTrainer(
    training_image="<training-image-uri>",
    compute=compute,
)
trainer.train()

トレーニングプランの ml.p5.48xlarge を 4 台で優先し、確保できない場合はオンデマンドの ml.p4d.24xlarge を 8 台で起動する例です。

💡 メリット

📈 ビジネス面

✓ジョブ開始までの時間短縮: 需要の高い GPU が確保できなくても代替タイプで自動起動し、開発やパイプラインの停滞を削減
✓運用コストの削減: 独自のリトライ機構や並行ジョブ送信が不要になり、リソースを本来の ML 開発に集中
✓予約容量の有効活用: Training Plans を優先しつつオンデマンドへフォールバックし、コミットメント割引と可用性を両立

⚙️ 技術面

✓宣言的なフォールバック構成: 容量フォールバックのロジックを InstancePreferences の 1 つの設定として表現
✓GPU 数の違いを台数で吸収: エントリごとの InstanceCount で合計 GPU 数やスループットを揃えた構成が可能
✓既存 API との統合: 既存のトレーニング/処理ジョブ API の拡張のため、既存ワークフローへの組み込みが容易
✓可観測性: SelectedInstanceType / SelectedInstanceCount とコンソール表示で起動構成を簡単に追跡

⚠️ デメリット・制約事項

制限事項

✗リストに指定できるのは最大 5 種類で、各タイプは 1 回しか指定できない
✗InstancePreferences は InstanceType、InstanceGroups、InstancePlacementConfig、EnableManagedSpotTraining と併用できない
✗リスト内の全タイプでサービスクォータが検証され、1 つでも不足するとリクエスト全体が拒否される (先頭タイプで起動可能な場合でも同様)
✗Flexible Training Plans との統合はトレーニングジョブのみで、処理ジョブでは利用不可
✗ビルトインアルゴリズム使用時は、リスト内の全タイプがそのアルゴリズムでサポートされている必要がある

考慮すべき点

⚠️SageMaker AI は容量の有無のみで選択し、GPU アーキテクチャ、アクセラレータメモリ、EFA 対応、ドライバーバージョンなどの互換性は比較しない。コンテナが全タイプで動作することを事前確認する
⚠️CPU のみのリストは 1 回だけ評価され、容量がなければ再試行せずに失敗する (待機と再試行はアクセラレーテッドインスタンスを含む場合のみ)
⚠️torchrun --nproc_per_node=auto のように、選択されたタイプの GPU 数に応じて動作を調整できるスクリプトにしておくと差異を吸収しやすい
⚠️VolumeSizeInGB、VolumeKmsKeyId、KeepAlivePeriodInSeconds は選択されたタイプにそのまま適用される

🎯 ユースケース

1. GPU 需要ピーク時の大規模モデルトレーニング

シナリオ: H100 搭載の ml.p5.48xlarge でトレーニングしたいが容量を確保できないことが多い。A100 搭載インスタンスでも許容できる。

JSON実装例
"InstancePreferences": [
  { "InstanceType": "ml.p5.48xlarge", "InstanceCount": 2 },
  { "InstanceType": "ml.p4de.24xlarge", "InstanceCount": 4 },
  { "InstanceType": "ml.p4d.24xlarge", "InstanceCount": 4 }
]

効果第 1 希望が確保できなくても代替 GPU 構成で即座に開始でき、エントリごとの台数指定で合計スループットも近い水準に保てる。

2. 夜間の再トレーニングパイプラインの安定化

シナリオ: 毎晩実行される再トレーニングパイプラインが容量不足エラーで失敗し、翌朝の手動再実行が度々発生している。

JSON実装例
"ResourceConfig": {
  "InstanceCount": 1,
  "VolumeSizeInGB": 200,
  "InstancePreferences": [
    { "InstanceType": "ml.g6.12xlarge" },
    { "InstanceType": "ml.g5.12xlarge" },
    { "InstanceType": "ml.g4dn.12xlarge" }
  ]
},
"StoppingCondition": {
  "MaxRuntimeInSeconds": 43200,
  "MaxPendingTimeInSeconds": 3600
}

効果複数世代の GPU タイプをフォールバック先に指定して容量起因の失敗を大幅に削減し、リトライ用のカスタムコードも撤去できる。

3. 予約容量とオンデマンドのハイブリッド戦略

シナリオ: Flexible Training Plans で ml.p5.48xlarge を予約しているが、プランの容量を使い切っている期間もトレーニングを止めたくない。

JSON実装例
"InstancePreferences": [
  {
    "InstanceType": "ml.p5.48xlarge",
    "TrainingPlanArns": ["arn:aws:sagemaker:us-west-2:111122223333:training-plan/p5-plan"]
  },
  { "InstanceType": "ml.p4d.24xlarge" }
]

効果予約済みの割引容量を最優先で使用しつつ、空きがなければ予約を待たずにオンデマンドへ自動フォールバックし、コスト効率と開発速度を両立できる。

💰 料金・利用可能リージョン

追加料金なし: インスタンス優先リスト機能自体に追加料金はありません。ジョブは選択されたインスタンスタイプを直接指定した場合とまったく同様に課金されます。
  • オンデマンド: 選択されたインスタンスタイプの標準の SageMaker 料金が適用される
  • Flexible Training Plans: プランから容量が確保された場合は、事前購入済みの割引料金が適用される

🌏 利用可能リージョン: Amazon SageMaker が利用可能なすべての AWS リージョンで利用できます。各リージョンのインスタンスタイプと料金は 料金ページを参照してください。

🔗 関連サービス・機能

📦 SageMaker Flexible Training Plans

GPU 容量を事前予約する仕組み。今回の機能により、優先リスト内のエントリ単位でプランの容量を指定し、オンデマンドと組み合わせられる。

🏃 SageMaker Training Jobs / Processing Jobs

今回の機能が適用されるフルマネージドのトレーニング/データ処理ジョブ。既存 API の拡張として提供される。

💸 SageMaker Managed Spot Training

スポット容量を利用した低コストトレーニング。インスタンス優先リストとは併用できない点に注意。

📏 AWS Service Quotas

リスト内の全インスタンスタイプでクォータ検証が行われるため、事前のクォータ管理が重要になる。

📝 まとめ

SageMaker AI のインスタンス優先リストは、GPU 容量の確保という ML ワークロード運用上の大きな課題を 1 つの設定変更で解決できる実用性の高いアップデートです。独自のリトライ機構を運用しているチームは、この機能への置き換えによりコードの簡素化とジョブ開始時間の短縮が期待できます。

導入時のチェックポイント: リスト内の全インスタンスタイプに対するサービスクォータの確保と、コンテナの互換性確認を忘れずに行ってください。
