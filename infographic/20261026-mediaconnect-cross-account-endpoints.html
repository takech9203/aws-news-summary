AWS Elemental MediaConnect 📅 2026 年 10 月 26 日リリース

🎛️ MediaConnect Router
エンドポイントレジストリとクロスアカウント共有

ライブ映像ワークフローの外部接続を一元管理し、AWS RAM でアカウントの境界を越えて共有

📌 概要

MediaConnect Router がエンドポイントレジストリによる外部接続管理をサポートしました。 カメラやエンコーダーなどサービス外のデバイスを表す標準エンドポイントと、 ルーター入出力などサービス内リソースを表すマネージドエンドポイントを登録し、 エンドポイント同士を接続するだけでコンテンツを流せます。

さらに、登録したエンドポイントを AWS RAM 経由で他の AWS アカウント、組織、組織単位 (OU) と直接共有可能になり、 クロスアカウントのライブ映像ワークフローが大幅に簡素化されます。中継インスタンスの削減によるコスト低減と、 ネットワークホップ削減によるレイテンシー低下も実現します。

❌ Before: アップデート前の課題

✗ルーター入出力を手動でチェーン接続する必要があった
✗IP アドレスやポートをスプレッドシートやメールで帯域外調整
✗暗号化設定やアクセス制御を利用者側で個別に管理
✗中継用インスタンスが追加で必要になり、コストとレイテンシーが増加
✗ソースや宛先の情報が分散し、全体像の把握が困難

✅ After: アップデート後の改善

✓エンドポイントレジストリで外部デバイスと他アカウント接続を一元管理
✓AWS RAM 経由でアカウント、組織、OU に直接共有
✓直接接続で中継インスタンスが不要になり、コストとレイテンシーを低減
✓暗号化・プロトコル制御の透過的な確認と Connection Manager が組み込みで提供
✓手動チェーン、帯域外調整、独自のセキュリティ管理が不要に

⚙️ 主要機能

📒 エンドポイントレジストリ
ソースと宛先を表すエンドポイントを一元管理。各エンドポイントは接続の片側を表す再利用可能な参照として機能し、ワークフローの構築・変更時に一覧から接続可能。コンソールと MediaConnect API の両方から操作できます。
📍 標準エンドポイント
カメラ、エンコーダー、デコーダー、モニターなどサービス外のデバイスやソフトウェアを表現。MediaConnect がデバイスへ到達するための設定 (プロトコル、アドレス、ポート、ネットワーク設定) を定義します。SRT caller、SRT listener、RTP、RIST をサポート。
🎛️ マネージドエンドポイント
ルーター入力・出力など MediaConnect が管理するリソースを表現。対応リソースでは自動登録される場合があり、ルーター入出力を表すマネージドエンドポイントは Amazon CloudWatch メトリクスを発行します。
🤝 クロスアカウント共有 (AWS RAM 連携)
共有側アカウントがエンドポイントをリソース共有に追加し、アカウント、組織、OU を指定して共有。利用側が受け入れると共有エンドポイントがレジストリに表示されます。共有側は制御を保持し、リソース共有からの削除でいつでも共有を停止できます。
🔗 Connection Manager
ソースと宛先エンドポイントの接続・切断を管理する組み込み機能。接続状態 (接続中・切断など) の追跡と、エンドポイント接続のネットワークトポロジーの可視化が可能です。

🔧 技術仕様

📋 エンドポイントの考慮事項と制限

項目詳細
接続トポロジー1 つの接続は 1 つのソースエンドポイントと 1 つの宛先エンドポイントを結合
サポートプロトコル標準エンドポイントは SRT caller、SRT listener、RTP、RIST をサポート
暗号化シークレット同一アカウント・同一リージョンのカスタマーマネージド、有効化済み、対称 AWS KMS キーが必要。AWS マネージドキー aws/secretsmanager は使用不可
パブリックエンドポイント最大 10 個の CIDR 許可ルールをサポート
VPC エンドポイント1〜5 個のセキュリティグループと、1 つのアベイラビリティーゾーン内の 1 つのサブネットを使用
メトリクスルーター入出力を表すマネージドエンドポイントのみ CloudWatch メトリクスを発行。標準エンドポイントはメトリクスを発行しない

🛠️ 設定方法

✅ 前提条件

✓MediaConnect Router が利用可能なリージョンを使用していること
✓クロスアカウント共有を行う場合、AWS RAM のリソース共有を作成・受け入れる権限があること
✓暗号化を使用する場合、同一アカウント・同一リージョンにカスタマーマネージドの対称 AWS KMS キーがあること

1エンドポイントを登録する

Bash ソースエンドポイントの登録 (SRT listener) 
aws mediaconnect register-source-endpoint \
  --region-name ap-northeast-1 \
  --description "Studio camera feed" \
  --configuration '{
    "Standard": {
      "Name": "studio-camera-01",
      "SourceNetworkingConfiguration": {
        "Public": {
          "SourceAllowRules": [{"Cidr": "203.0.113.0/24"}]
        }
      },
      "ProtocolConfiguration": {
        "SrtListener": {
          "SourceListenerPort": 9000,
          "MinimumLatencyMilliseconds": 200
        }
      }
    }
  }'

カメラなどの外部デバイスを表すソースエンドポイントを登録します。プロトコル、許可する CIDR、ポートなど、MediaConnect がデバイスに到達するための設定を定義します。受信側には同様に宛先エンドポイントを登録します。

2エンドポイントを他アカウントと共有する

Bash AWS RAM リソース共有の作成 
aws ram create-resource-share \
  --name "mediaconnect-endpoint-share" \
  --resource-arns "arn:aws:mediaconnect:ap-northeast-1:111111111111:sourceEndpoint:studio-camera-01" \
  --principals "222222222222"

共有側アカウントでリソース共有を作成し、共有するエンドポイントと共有先 (アカウント ID、組織、OU) を指定します。利用側が受け入れると、自身のエンドポイントレジストリに共有エンドポイントが表示されます。

3エンドポイントを接続する

Bash ソースと宛先エンドポイントの接続 
aws mediaconnect connect-endpoints \
  --source-endpoint-arn "arn:aws:mediaconnect:ap-northeast-1:111111111111:sourceEndpoint:studio-camera-01" \
  --destination-endpoint-arn "arn:aws:mediaconnect:ap-northeast-1:222222222222:destinationEndpoint:router-input-01"

利用側アカウントで、共有されたソースエンドポイントと自アカウントの宛先エンドポイントを接続します。接続が確立されるとコンテンツが流れ、接続状態は Connection Manager で追跡できます。

💡 メリット

💼 ビジネス面

✓コスト削減: 中継用インスタンスが不要になりインフラコストを削減。機能自体は追加料金なし
✓パートナー連携の迅速化: 下流パートナーへのライブフィード共有のセットアップ時間を短縮
✓運用負荷の軽減: IP アドレスの帯域外調整が不要になり、設定ミスや手戻りを削減

⚡ 技術面

✓レイテンシー低下: ネットワークホップが減少し、エンドツーエンドの遅延を低減
✓セキュリティの組み込み管理: 暗号化とプロトコル制御を透過的に確認、個別の設計・管理が不要
✓一元的な可視性: 接続状態の追跡とネットワークトポロジーの可視化が可能

⚠️ デメリット・制約事項

🚧 制限事項

⚠1 つの接続で結合できるのは 1 ソースエンドポイントと 1 宛先エンドポイントのみ
⚠標準エンドポイントのプロトコルは SRT caller、SRT listener、RTP、RIST に限定
⚠暗号化シークレットには同一アカウント・同一リージョンのカスタマーマネージド対称 KMS キーが必要 (aws/secretsmanager は使用不可)
⚠標準エンドポイントは CloudWatch メトリクスを発行しない (メトリクスはルーター入出力のマネージドエンドポイントのみ)
⚠CIDR 許可ルールは最大 10 個、VPC エンドポイントは 1 AZ 内の 1 サブネットのみ

🤔 考慮すべき点

⚠AWS RAM の理解と、共有側・利用側双方での操作 (リソース共有の作成と受け入れ) が必要
⚠共有側が制御を保持するため、共有停止による利用側ワークフローへの影響を考慮した運用設計が必要
⚠標準エンドポイントはメトリクスに依存できないため、接続状態の追跡を中心とした監視設計が必要

🎯 ユースケース

📡 ユースケース 1: コンテンツ配信事業者から下流パートナーへのライブフィード提供

シナリオ: スポーツ中継のライブフィードを、別の AWS アカウントを保有する複数の放送パートナーに配信したい。

  • 配信事業者アカウントでソースエンドポイントを登録
  • AWS RAM のリソース共有に各パートナーのアカウント ID を追加
  • 各パートナーがリソース共有を受け入れ、自アカウントのルーター入力に接続
✨ 効果: 中継用インスタンスや IP アドレスの個別調整なしで、パートナーごとのフィード提供を数ステップで実現。ネットワークホップ削減により低レイテンシーな伝送が可能。
🏢 ユースケース 2: 放送局グループ内の組織横断ワークフロー

シナリオ: 制作部門と送出部門が別々の AWS アカウントを運用しており、制作した番組素材をライブで送出部門に引き渡したい。

  • 制作アカウントでルーター出力のマネージドエンドポイントを共有
  • AWS Organizations の OU 単位でリソース共有を設定
  • 送出アカウントが共有エンドポイントを自身のルーター入力に接続
✨ 効果: OU 単位の共有により、グループ内アカウントの追加・削除時も共有設定の変更が最小限。ルーター入出力の手動チェーンが不要になり、構成がシンプルに。
📹 ユースケース 3: 外部カメラ・機器の一元管理

シナリオ: 複数拠点のカメラやエンコーダーの接続情報がスプレッドシートに分散しており、ワークフロー構築のたびに設定を確認・転記している。

  • 各拠点のカメラ・エンコーダーを標準エンドポイントとして登録 (SRT listener、RTP、RIST など)
  • エンドポイントレジストリで利用可能なエンドポイントを一覧確認
  • 必要に応じて Connection Manager でルーター入力に接続・切断
✨ 効果: 接続情報がレジストリに集約され、再利用可能な参照として管理できる。接続状態とネットワークトポロジーを可視化でき、運用ミスを削減。

🔗 関連サービス・機能

🤝 AWS Resource Access Manager (AWS RAM)
エンドポイントをアカウント、組織、OU と共有するための基盤。リソース共有の作成・受け入れ・削除で共有ライフサイクルを管理。
🔑 AWS KMS
エンドポイント暗号化シークレットの保護に使用。カスタマーマネージド対称キーが必要。
🔒 AWS Secrets Manager
SRT などの暗号化パスフレーズをシークレットとして保管し、エンドポイント設定から参照。
📊 Amazon CloudWatch
ルーター入出力を表すマネージドエンドポイントのメトリクス監視に使用。

📝 まとめ

MediaConnect Router のエンドポイントレジストリとクロスアカウント共有により、これまで手動チェーンや帯域外調整が必要だったアカウント間のライブ映像ワークフローを、追加コストなしで簡素化できます。 複数アカウントや外部パートナーとライブ映像を受け渡している場合は、中継インスタンスの削減によるコスト・レイテンシー改善の効果が大きいため、AWS RAM によるエンドポイント共有への移行を検討することを推奨します。
