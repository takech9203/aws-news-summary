📋 Overview

Amazon EventBridge Scheduler has significantly expanded its AWS SDK integrations, now supporting 13 additional services and 619 new API actions. This enables scheduling direct calls to more AWS services without writing custom integration code.

EventBridge Scheduler is a serverless scheduler capable of creating, executing, and managing billions of scheduled events and tasks across 270+ AWS services. This expansion notably supports Lambda Managed Instances scaling operations, enabling precise capacity provisioning through time-based schedules.

⚡ Key Features

✨ 619 New API Actions

New and existing AWS services now have 619 additional API actions available via Universal Target. Schedule direct AWS API calls without custom integration code. Targets write-type actions (excludes get, describe, list, etc.).

🆕 13 New Service Support

13 additional services are now callable from EventBridge Scheduler's Universal Target, bringing the total to 270+ supported AWS services. Availability depends on each service's regional presence.

🚀 Lambda Managed Instances Scaling

Control Lambda Managed Instances scale-up/scale-down via time-based schedules. Enables precise capacity provisioning, pre-warming before peak hours, and automatic scale-down during off-peak.

Scale-Up Schedule (Daily 8:00 UTC)

Bash Lambda Managed Instances Scale-Up 
aws scheduler create-schedule \
  --name "lambda-managed-instance-scale-up" \
  --schedule-expression "cron(0 8 * * ? *)" \
  --target '{
    "RoleArn": "arn:aws:iam::123456789012:role/EventBridgeSchedulerRole",
    "Arn": "arn:aws:scheduler:::aws-sdk:lambda:scaleManagedInstance",
    "Input": "{\"ManagedInstanceName\":\"my-instance\",\"DesiredCapacity\":10}"
  }' \
  --flexible-time-window '{"Mode": "OFF"}'

Scale-Down Schedule (Daily 22:00 UTC)

Bash Lambda Managed Instances Scale-Down 
aws scheduler create-schedule \
  --name "lambda-managed-instance-scale-down" \
  --schedule-expression "cron(0 22 * * ? *)" \
  --target '{
    "RoleArn": "arn:aws:iam::123456789012:role/EventBridgeSchedulerRole",
    "Arn": "arn:aws:scheduler:::aws-sdk:lambda:scaleManagedInstance",
    "Input": "{\"ManagedInstanceName\":\"my-instance\",\"DesiredCapacity\":2}"
  }' \
  --flexible-time-window '{"Mode": "FLEXIBLE", "MaximumWindowInMinutes": 15}'

🎯 Use Cases

1. Lambda Managed Instances Time-Based Scaling

An e-commerce site experiences peak traffic from 9:00-21:00 daily. Using Lambda Managed Instances to eliminate cold starts during peak while minimizing overnight costs.

Bash Peak Hours Auto-Scaling 
# Scale up at 8:45 (pre-peak preparation)
aws scheduler create-schedule \
  --name "ecommerce-scale-up" \
  --schedule-expression "cron(45 8 * * ? *)" \
  --target '{
    "RoleArn": "arn:aws:iam::123456789012:role/SchedulerRole",
    "Arn": "arn:aws:scheduler:::aws-sdk:lambda:scaleManagedInstance",
    "Input": "{\"ManagedInstanceName\":\"ecommerce-api\",\"DesiredCapacity\":20}"
  }' \
  --flexible-time-window '{"Mode": "OFF"}'
Effect: Eliminates cold starts during peak, reduces off-peak costs by up to 85%. No custom scaling logic required.

2. Automated Data Processing Pipeline

Trigger daily data lake partition restructuring and ETL jobs at midnight. Multiple AWS services need coordination, but not complex enough for Step Functions.

Bash Daily Glue Crawler Trigger 
# Start Glue Crawler daily at AM 2:00
aws scheduler create-schedule \
  --name "daily-glue-crawler" \
  --schedule-expression "cron(0 2 * * ? *)" \
  --target '{
    "RoleArn": "arn:aws:iam::123456789012:role/SchedulerRole",
    "Arn": "arn:aws:scheduler:::aws-sdk:glue:startCrawler",
    "Input": "{\"Name\":\"data-lake-crawler\"}"
  }' \
  --flexible-time-window '{"Mode": "FLEXIBLE", "MaximumWindowInMinutes": 30}'
Effect: Simplifies architecture by calling AWS APIs directly from Scheduler without Lambda functions or state machines.

3. Multi-Service Weekend Maintenance

Stop development environment resources on weekends and restart on Monday. Control RDS instances, ECS services, and SageMaker endpoints across multiple services.

Bash Weekend RDS Stop/Start 
# Stop RDS on Friday 22:00
aws scheduler create-schedule \
  --name "dev-rds-stop-weekend" \
  --schedule-expression "cron(0 22 ? * FRI *)" \
  --target '{
    "RoleArn": "arn:aws:iam::123456789012:role/SchedulerRole",
    "Arn": "arn:aws:scheduler:::aws-sdk:rds:stopDBInstance",
    "Input": "{\"DBInstanceIdentifier\":\"dev-database\"}"
  }' \
  --flexible-time-window '{"Mode": "OFF"}'
Effect: Reduces development environment weekend costs by up to 60%. Individual schedules per service, no custom scripts needed.

⚠️ Limitations & Considerations

  • Read-only APIs not supported (get, describe, list, poll, receive, search, scan, query, select, read, lookup, discover, validate)
  • API action availability depends on target service's regional presence
  • Universal Target Input requires correct JSON format for request parameters
  • Payload billed per 64 KB as 1 event
  • IAM execution role must have appropriate permissions for target API calls
  • Service identifier in Universal Target ARN must match AWS SDK service identifier (may differ from endpoint prefix)
