Kiro CLI 3.2

👻 Kiro CLI 3.2 アップデート
Output Details・全画面ダイアグラムビューア・MCP サインイン拡張

📅 リリース日: 2026 年 11 月 11 日 | Kiro (AWS が提供する AI 搭載 IDE) | CLI 3.2.0 系 / 3.2.1

📋 概要

Kiro CLI 3.2 系の 2 件のチェンジログが公開されました。Output Details により、ツール呼び出しの表示詳細度を /settings から自由に選択可能になりました。また、ターミナル幅に収まらない Mermaid ダイアグラムを表示する全画面ビューア、OAuth 設定なしでサインインできる MCP サーバーの範囲拡大 (CIMD 対応) が追加され、ワークフローループの継続操作や環境変数設定前の確認など、運用性とセキュリティも改善されています。

❌ Before (アップデート前の課題)
✗ツール呼び出しの出力表示量を細かく調整できず、チャットが読みにくい、または詳細が見えない
✗ターミナル幅より広い Mermaid ダイアグラムは正しく描画できなかった
✗動的クライアント登録のない MCP サーバーには oauth ブロックの手動設定が必要だった
✗イテレーション上限に達したワークフローループを継続・完了する手段がなかった
✗グラフィカルセッションのない Linux ホストや Identity Center フラグ使用時にサインインが失敗することがあった
✗XDG_CONFIG_HOME や HOME を書き換えるシェルコマンドが確認なしに実行されていた
✅ After (アップデート後の改善)
✓collapsed / lean / default / full のプリセットや個別設定で表示量を選択可能に
✓Ctrl+] または /diagram で幅広ダイアグラムを全画面表示、矢印キーやマウスホイールで移動
✓Kiro ホストのクライアントメタデータで OAuth 設定なしに CIMD 対応 MCP サーバーへサインイン
✓イテレーション上限到達時に「もう 1 回実行」か「完了として継続」を選択可能に
✓自律モードでワークフローを要求すると、非対応である旨を明示
✓V2 シェルコマンドが XDG_CONFIG_HOME や HOME を設定する前に確認を要求

ターミナル幅に収まらない Mermaid ダイアグラムを全画面ビューアで表示するまでの流れです。ビューアを閉じても入力中のドラフトはそのまま保持されます。

⚡ 主要機能

1️⃣ Output Details (ツール呼び出し表示の詳細度設定)

→ /settings から Output details を開くか、/settings output-details を直接実行して設定

→ collapsed、lean、default、full の 4 つのプリセットから選択可能

→ ツール引数、推論 (reasoning)、出力フィルター、サブエージェント詳細、切り詰め (truncation) の個別設定にも対応

→ 思考 (thinking) 表示の設定は /settings display から Output details 配下に移動

2️⃣ ツール呼び出し表示の統一

→ シェル、検索、汎用ツールの出力がツール呼び出しの直下にまとまって表示

→ read 呼び出しは返却したファイル行を表示

→ 連続する完了済みツール呼び出しは 1 つのサマリー行に折りたたまれ、Ctrl+O で展開可能

→ ファイル書き込みの承認時は上限付きプレビューではなく完全な差分を表示

→ スクロールバック内の完了済み検索はファイル名を列挙せず結果件数のみを保持

3️⃣ 全画面ダイアグラムビューア

→ Mermaid ダイアグラムがターミナル幅に収まらない場合、ソースと通知、プロンプト上部のエントリを表示

→ Ctrl+] または /diagram で最新の幅広ダイアグラムを全幅レイアウトで表示

→ 矢印キーやマウスホイールで移動、Tab で過去のダイアグラムへ切り替え、Esc でチャットに復帰 (ドラフト保持)

→ キーバインドは chat.keybindings.viewDiagram で変更可能

4️⃣ MCP サーバーへのサインイン拡張 (CIMD 対応)

→ Tableau のホステッド MCP のように、Client ID Metadata Documents をサポートするが動的クライアント登録を提供しないサーバーに対応

→ Kiro 自身がホストするクライアントメタデータドキュメントを使用し、oauth ブロックなしでサインイン可能

→ 動的クライアント登録を提供するサーバーは従来どおり、設定済みの clientId / clientMetadataUrl が優先

5️⃣ ワークフローループの継続操作

→ イテレーションを使い切って一時停止したループに対し、ワークフローモニターと一時停止行の下に 2 つの選択肢を表示

→ 「もう 1 回イテレーションを実行する」または「ループを完了としてマークし実行を継続する」を選択可能

6️⃣ 自律モードでのワークフロー非対応の明示

→ 自律モードでワークフローを要求した場合、リクエストを引き渡す代わりに、ワークフローが利用できない旨を明示的に通知

7️⃣ 環境変数設定時の確認 (セキュリティ強化)

→ V2 シェルコマンドが XDG_CONFIG_HOME または HOME を設定する前に、実行してよいか確認を要求

→ 設定ファイルの参照先を変更できる環境変数による、意図しない設定の上書きを防止

🔧 主な修正

✓グラフィカルセッションのない Linux ホストでのサインインを修正
✓IAM Identity Center フラグを使用した場合のサインインを修正
✓/model fallback の設定が現在のエージェントで引き続き機能するように修正
✓ワークフロー、スペック、Skills、ファイル検索、権限 (permissions)、セッションリロードに関する問題を修正 (3.2.1)
✓ファイル検索、カスタムエージェント、ワークフロー、スペック、Hook、クリップボード、ヘルプテキスト、セッションに関する問題を修正 (3.2.0 系)

🛠️ 設定方法

📌 前提条件

  • Kiro CLI 3.2.1 以降がインストールされていること (3.2.0 系の機能は 3.2.0 以降)
  • MCP サインイン拡張を利用する場合は、対象サーバーが Client ID Metadata Documents をサポートしていること
1
Kiro CLI を最新バージョンに更新

Kiro CLI を再起動するか、アップデートを確認して 3.2.1 以降に更新します。

2
Output details を設定
BashOutput details の設定画面を開く
/settings output-details

collapsed、lean、default、full のプリセットを選択するか、ツール引数、推論、出力フィルター、サブエージェント詳細、切り詰めを個別に調整します。

3
全画面ダイアグラムビューアを使用
Bash直近の幅広ダイアグラムを全画面で開く
/diagram

このコマンド (または Ctrl+]) で全画面表示し、矢印キーで移動、Tab で過去のダイアグラムへ切り替え、Esc でチャットに戻ります。

4
CIMD 対応 MCP サーバーを追加

MCP 設定にサーバーを追加し、サインインを実行します。CIMD 対応サーバーであれば oauth ブロックの記述は不要で、Kiro がホストするクライアントメタデータドキュメントによりサインインが完了します。

💡 メリット

💼 ビジネス面

✓レビュー効率の向上: 表示量を用途に応じて調整でき、エージェントの作業内容の確認が速くなる
✓MCP 導入の簡素化: OAuth 設定を手動で用意せずに企業向け MCP サーバーへ接続でき、チームへの展開が容易になる
✓長時間ワークフローの柔軟な運用: イテレーション上限に達したループを途中で打ち切らず、延長または完了を選択できる

⚙️ 技術面

✓ターミナル体験の改善: 幅広の Mermaid ダイアグラムを全画面で確認でき、アーキテクチャ図の視認性が向上する
✓安全なシェル実行: XDG_CONFIG_HOME や HOME の設定前に確認が入り、設定ファイルの意図しない書き換えを防げる
✓サインインの信頼性向上: グラフィカルセッションのない Linux ホストや Identity Center フラグ使用時でもサインインが機能する

⚠️ デメリット・制約事項

🚧 制限事項

⚠️全画面ダイアグラムビューアは、ターミナル幅に収まらない Mermaid ダイアグラムが対象で、Kiro CLI がサポートする Mermaid 記法の範囲内で動作する
⚠️CIMD によるサインインは、サーバー側が Client ID Metadata Documents をサポートしている場合にのみ利用できる
⚠️ワークフローは自律モードでは実行されない (今回のアップデートはその旨を明示する改善であり、自律モードでの実行を可能にするものではない)

🤔 考慮すべき点

💭Output details を full に設定すると出力量が増え、長時間のセッションではスクロールバックが長くなる
💭collapsed 設定では詳細が省略されるため、トラブルシューティング時は一時的に詳細度を上げることが望ましい
💭clientId や clientMetadataUrl 設定済みのサーバーは従来の設定が優先されるため、CIMD へ切り替える場合は設定の見直しが必要

📜 ユースケース 1: 長時間セッションでの表示量の最適化

シナリオ: 大規模なリファクタリングで多数のツール呼び出しが発生し、チャットのスクロールバックが読みにくい。

Text実装例

詳細を確認したいときはサマリー行で Ctrl+O を押して展開する。

効果: 通常はコンパクトな表示で作業の流れを把握し、必要な箇所だけ展開して詳細を確認できる。

📊 ユースケース 2: ターミナルでのアーキテクチャ図レビュー

シナリオ: エージェントが生成した幅の広いアーキテクチャ図 (Mermaid) をターミナル上で確認したい。

Text実装例
幅広ダイアグラムの通知が表示されたら Ctrl+] を押す。
全画面ビューアで矢印キーとマウスホイールを使って図全体を確認し、
Tab で過去の図と比較して、Esc でチャットに戻る。

効果: ターミナル幅の制約を受けずに図全体を確認でき、入力中のプロンプトも失われない。

シナリオ: Tableau のホステッド MCP のような、動的クライアント登録を提供しない CIMD 対応 MCP サーバーへ接続したい。

Text実装例
MCP 設定にサーバーの URL を追加する (oauth ブロックは不要)。
サインインを実行すると、Kiro がホストするクライアントメタデータ
ドキュメントにより認証が完了する。

効果: クライアント ID の発行やメタデータの手動設定なしで、対応サーバーへのサインインが完了する。

📝 まとめ

Kiro CLI 3.2 系のアップデートは、ツール呼び出し表示の詳細度を自由に選べる Output Details、幅広 Mermaid ダイアグラムの全画面ビューア、OAuth 設定不要の MCP サインイン拡張など、ターミナルでの日常的な開発体験を大きく改善するものです。環境変数設定前の確認やサインイン修正により、安全性と信頼性も向上しています。

Kiro CLI ユーザーは 3.2.1 へ更新し、まず /settings output-details で自分の作業スタイルに合った表示設定を試すことを推奨します。
