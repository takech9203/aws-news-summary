Amazon S3 ▲ Vercel 📅 2026 年 10 月 14 日

🪣 Amazon S3 が Vercel Marketplace と v0 by Vercel で利用可能に

S3 Tables と S3 Vectors を含む 3 種類のストレージを、開発環境を離れずに数秒でプロビジョニング

📋 概要

Amazon S3 (S3 Tables および S3 Vectors を含む) が Vercel Marketplace と v0 by Vercel で利用可能になりました。開発者は開発環境を離れることなく、数秒で S3 リソースを作成し、Vercel プロジェクトに接続できます。認証には OIDC トークンと AWS STS による一時認証情報を使用するため、静的なアクセスキーの保存は不要です。

既存の Amazon Aurora、Amazon DynamoDB、Amazon OpenSearch Serverless の統合と合わせて、1 つの AWS アカウント・1 つの請求で管理できます。Web フロントエンドに Vercel、ストレージやデータ基盤に AWS を利用したい開発者や、v0 による AI 駆動開発で迅速にアプリケーションを構築したい開発者が主な対象です。

😣 アップデート前の課題

  • AWS マネジメントコンソールに移動してバケット作成、IAM ポリシーや認証情報の設定が必要だった
  • アクセスキーなどの静的な認証情報を環境変数として手動で管理する必要があり、セキュリティ上の負担があった
  • Vercel と AWS のリソース管理・請求が分断され、開発ワークフローが中断されていた

😊 アップデート後の改善

  • Vercel ダッシュボードや v0 から離れることなく、数秒で S3 リソースの作成と接続が可能に
  • プロビジョニングと接続設定 (環境変数の注入) が自動化され、手動設定が不要に
  • OIDC トークンと AWS STS による短命の一時認証情報が標準となり、静的なアクセスキーの保存が不要に
  • v0 で自然言語からアプリ生成時に、適切な S3 リソースが自動プロビジョニングされる

Vercel Marketplace または v0 から S3 リソースを自動プロビジョニングし、Vercel Functions は実行時に OIDC トークンを AWS STS で一時認証情報と交換して S3 にアクセスします。静的なアクセスキーは保存されません。

⚡ 主要機能

🛒 Vercel Marketplace からの S3 プロビジョニング

→ Vercel ダッシュボードの Storage タブから AWS を選択し、バケットタイプとリージョンを指定するだけで数秒でバケットを作成可能

→ プロビジョニングと接続設定が自動化され、環境変数がプロジェクトに自動注入される

→ 既存の Amazon Aurora、Amazon DynamoDB、Amazon OpenSearch Serverless の統合に加わる形で提供

🗄️ 3 種類の S3 ストレージタイプに対応
📦 S3 汎用バケット

ファイル、画像、動画、ドキュメントなどほぼあらゆるユースケースに対応。イレブンナイン (99.999999999%) のデータ耐久性と 99.99% の可用性を標準提供

📋 S3 Tables

分析ワークロード向けのフルマネージド Apache Iceberg テーブル。自動メンテナンスとコンパクション機能を備え、DuckDB など Iceberg REST catalog API 互換エンジンから直接クエリ可能

🧭 S3 Vectors

RAG やセマンティック検索向けに、ベクトルをネイティブに大規模保存・クエリ可能。ベクトルのアップロード、保存、クエリのコストを最大 90% 削減

🔐 OIDC ベースのセキュアな認証

→ @vercel/functions/oidc の awsCredentialsProvider が、実行時に短命の OIDC トークンを AWS STS と交換

→ 対象リソースにスコープされた一時認証情報を取得するため、静的なアクセスキーの保存が不要

🤖 v0 by Vercel での自動プロビジョニング

→ 自然言語で作りたいものを記述すると、v0 が適切な S3 リソースを自動的に選択してプロビジョニング

→ 接続設定と動作するコードも合わせて生成される

💰 新規 AWS アカウント向けクレジット

→ Vercel 経由で作成された新規 AWS アカウントには、最大 6 か月間有効な 100 ドルのクレジットを付与

→ クレジットは Amazon S3、Amazon OpenSearch Serverless、AWS データベースサービスで利用可能

→ 既存の AWS 顧客はアカウントをリンクして、現行の請求を維持したまま利用可能

Vercel ダッシュボードから S3 リソースを作成

Vercel ダッシュボードの Storage タブから Create を選択し、AWS を選びます。S3 のバケットタイプ (汎用バケット、S3 Tables、S3 Vectors) とリージョンを指定すると、数秒でバケットが作成されます。

2
プロジェクトに接続して環境変数を取得
Bash Vercel CLI で環境変数を取得 
vercel link
vercel env pull .env.local

vercel link でローカルのコードベースを Vercel プロジェクトに関連付け、vercel env pull で統合により注入された環境変数をローカルの .env.local ファイルに取得します。

3
アプリケーションコードから S3 にアクセス
TypeScript OIDC 認証による S3 アクセス例 
import { awsCredentialsProvider } from "@vercel/functions/oidc";
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({
  region: process.env.AWS_REGION,
  credentials: awsCredentialsProvider({
    roleArn: process.env.AWS_ROLE_ARN!,
  }),
});

await s3.send(
  new PutObjectCommand({
    Bucket: process.env.S3_BUCKET_NAME,
    Key: "uploads/sample.png",
    Body: fileBuffer,
  })
);

awsCredentialsProvider が実行時に OIDC トークンを AWS STS と交換し、対象リソースにスコープされた一時認証情報を取得します。なお、Next.js のルートで DuckDB を使用して S3 Tables にクエリする場合は、next.config.mjs の serverExternalPackages に該当パッケージの追加が必要です。

💡 メリット

💼 ビジネス面

✓開発速度の向上: 開発環境を離れずに数秒でストレージをプロビジョニングでき、プロトタイプから本番までの時間を短縮
✓コスト最適化の機会: 新規 AWS アカウントに 6 か月有効な 100 ドルのクレジット、S3 Vectors はベクトル関連コストを最大 90% 削減
✓請求の一元化: リソースは自分の AWS アカウント内に作成され、AWS の請求・管理体系に統合

⚙️ 技術面

✓セキュリティの向上: OIDC トークンと AWS STS による短命の一時認証情報を使用し、静的なアクセスキーを保存しない設計
✓自動化された接続設定: 環境変数の注入が自動化され、設定ミスのリスクを低減
✓AWS ネイティブツールとの併用: AWS CLI やマネジメントコンソールでの管理も可能
✓AI 駆動開発との統合: v0 でのアプリ生成時に、ユースケースに応じた適切な S3 リソースが自動選択される

⚠️ デメリット・制約事項

🚫 制限事項

✗既存の AWS アカウントをリンクした場合、Vercel が扱えるのはプラットフォーム経由で作成した新規バケットのみで、既存のバケットは対象外
✗S3 Vectors には埋め込みを生成する機能はなく、埋め込みモデル (Amazon Bedrock など) で別途作成する必要がある
✗提供リージョンは Vercel がサポートする商用 AWS リージョンに限定される

🤔 考慮すべき点

⚠️100 ドルのクレジットは Vercel 経由で作成した新規 AWS アカウントが対象で、有効期間は最大 6 か月
⚠️Next.js で DuckDB を使用して S3 Tables にアクセスする場合、serverExternalPackages の設定が必要
⚠️本番運用では、Vercel 側と AWS 側の両方でアクセス権限や監視体制を整理しておくことが望ましい

📝 まとめ

Amazon S3 (S3 Tables、S3 Vectors を含む) が Vercel Marketplace と v0 by Vercel に統合され、開発環境を離れることなく数秒で S3 リソースの作成と接続が可能になりました。OIDC ベースの一時認証情報により静的なアクセスキーが不要となり、セキュリティと開発体験の両面で優れた統合です。Vercel で Web アプリケーションや AI アプリケーションを構築しているチームは、Vercel ダッシュボードの Storage タブまたは v0 から試してみることを推奨します。
