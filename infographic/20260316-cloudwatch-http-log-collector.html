各種ログソースから HTTP ベースのエンドポイントを経由して CloudWatch Logs にログを取り込むデータフロー

📝 概要

Amazon CloudWatch Logs が HTTP ベースプロトコルによるログ取り込みをサポート。新たに 4 つのエンドポイントが追加されました。

Before

  • AWS SDK / エージェント統合が困難なソフトからのログ取り込みが難しい
  • 中間的なログ転送レイヤーが必要
  • OTEL 形式の直接送信手段がない

After

  • HTTP で SDK 統合なしにログを直接送信
  • 4 形式対応で様々なログソースに対応
  • ベアラートークンでシンプルに認証

🌐 4 つの HTTP エンドポイント

📥 HLC
JSON イベント形式
既存パイプラインの移行に最適
/services/collector/event
📥 ND-JSON
改行区切り JSON
大量ログのバルク取り込み
/ingest/bulk
📥 Structured JSON
JSON オブジェクト/配列
構造化ログデータ
/ingest/json
📥 OTEL
OTLP JSON/Protobuf
OpenTelemetry 統合
/v1/logs

🔑 API キー設定

項目詳細
認証方式ベアラートークン
API キー生成AWS コンソール CloudWatch Settings
有効期限1、5、30、90、365 日
IAM ユーザーCloudWatch が自動作成
ロググループベアラートークン認証の有効化が必要
セキュリティ制御SCP で認証情報の作成をブロック可能

🛠️ 設定方法

前提: AWS アカウント、対象リージョン、ロググループ作成済み

1
API キーの生成
CloudWatch Settings で有効期限を選択して生成。IAM ユーザーとサービス固有認証情報は自動作成されます。
2
ベアラートークン認証を有効化
ロググループの設定から有効化。意図しないログ取り込みを防止できます。
Bash ロググループ作成 
aws logs create-log-group \
  --log-group-name /my/app-logs
3
ログの送信
HTTP + ベアラートークンでエンドポイントにリクエストを送信します。
Bash HLC エンドポイントへの送信例 
curl -X POST \
  "https://logs.us-east-1.amazonaws.com/services/collector/event" \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "logGroup": "/my/log-group",
    "logEvents": [{
      "timestamp": 1710590400000,
      "message": "Application started"
    }]
  }'
4
OpenTelemetry Collector からの送信
OTLP エクスポーターを設定して自動送信します。
YAML OTel Collector 設定例 
exporters:
  otlphttp:
    endpoint: "https://logs.us-east-1.amazonaws.com"
    headers:
      Authorization: "Bearer <API_KEY>"
    compression: gzip

service:
  pipelines:
    logs:
      receivers: [filelog]
      processors: [batch]
      exporters: [otlphttp]

💡 ユースケース

UC1

📦 サードパーティソフトのログ収集

AWS SDK をサポートしない ERP / CRM 等のパッケージソフトウェアから、HTTP ログ転送機能で直接 CloudWatch Logs に送信。設定変更のみで収集開始。

UC2

📡 OpenTelemetry 統合

既存の OTel Collector パイプラインに OTLP エクスポーターを追加し、ログ、メトリクス、トレースを一元管理。

UC3

📊 大量ログのバルク取り込み

バッチ処理やデータパイプラインから ND-JSON 形式で数千件のログを一括送信。効率的なストリーミングを実現。

Python バルク取り込み例 
import requests

endpoint = "https://logs.us-east-1.amazonaws.com/ingest/bulk"
log_events = [
    f'{{"logGroup":"/batch/processing",'
    f'"message":"Record {i}",'
    f'"timestamp":{1710590400000 + i * 1000}}}'
    for i in range(1000)
]

response = requests.post(
    endpoint,
    headers={
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/x-ndjson"
    },
    data="\n".join(log_events)
)

⚠️ デメリット・制約事項

制限事項

  • 利用可能リージョンが 米国 4 リージョンのみに限定
  • API キーの最大有効期限が 365 日 (定期ローテーション必要)
  • 各ロググループで個別にベアラートークン認証を有効化が必要

考慮すべき点

  • API キーのローテーション運用計画
  • SCP による認証情報作成の制御検討
  • AWS 署名 v4 と異なるセキュリティモデルの評価
