Amazon WorkSpaces Applications (旧 AppStream 2.0)

💳 スマートカードリダイレクトをサポート

📅 リリース日: 2026 年 11 月 17 日 | マルチセッションフリートでのスマートカードサインインにも対応

📝 概要

Amazon WorkSpaces Applications が、シングルセッションとマルチセッションの両フリートでスマートカードリダイレクトをサポートしました。ローカルデバイスに接続したスマートカードを、ストリーミングセッション内のアプリケーションから直接利用できます。さらに、これまでシングルセッションフリート限定だった Active Directory へのスマートカードサインインが、マルチセッションフリートでも利用可能になりました。

管理者はスタックごとに「スマートカードサインイン」と「スマートカードリダイレクト」の 2 つの設定を個別に制御できます。リダイレクトされたスマートカードは、セッション内での認証、電子署名、メール暗号化に利用できます。Common Access Card (CAC) や Personal Identity Verification (PIV) カードを利用する公共部門、医療機関などの規制の厳しい組織に特に有効です。

❌ アップデート前の課題

✗スマートカードサインインはシングルセッションフリートに限定
✗CAC / PIV カード必須の組織は、コスト効率の高いマルチセッションフリートへ移行できなかった
✗セッション内でのスマートカード利用をスタック設定として明示的に制御する手段が限られていた

✅ アップデート後の改善

✓マルチセッションフリートでもサインインとセッション内リダイレクトが利用可能に
✓スタックごとに 2 つの設定を個別に有効化 / 無効化可能
✓認証要件を維持したままマルチセッションフリートへ移行可能

ローカルデバイスのスマートカードは Windows クライアント経由でストリーミングセッションにリダイレクトされ、サインイン認証とセッション内でのアプリケーション利用の両方に使用できます。2 つの設定はスタック単位で個別に制御します。

⚙️ 主要機能

🔁 1. スマートカードリダイレクト

  • ローカルデバイスに接続されたスマートカードをストリーミングセッション内にリダイレクト
  • セッション内アプリケーションでの認証、電子署名、メール暗号化に利用可能
  • シングルセッションフリートとマルチセッションフリートの両方に対応

🔑 2. マルチセッションフリートでのスマートカードサインイン

  • これまでシングルセッションフリート限定だったサインインをマルチセッションフリートに拡大
  • パスワードの代わりにスマートカードでドメイン参加済みのストリーミングインスタンスへ認証

🎛️ 3. スタック単位での個別制御

  • 「Active Directory へのスマートカードサインイン」と「スマートカードリダイレクト」を独立して有効化 / 無効化可能
  • 新規作成するスタックでは両設定ともデフォルトで無効
  • リダイレクトを既に利用している既存スタックでは、後方互換性のため有効のまま維持

🔧 技術仕様

📋 要件

項目詳細
フリートタイプWindows シングルセッションフリートおよびマルチセッションフリート
イメージ最新の WorkSpaces Applications エージェントを実行する Windows イメージ
クライアントWorkSpaces Applications の Windows 用クライアント
設定単位スタックごと (サインインとリダイレクトを個別に設定)
デフォルト値新規スタックでは両設定とも無効

🔄 API 変更履歴 (2026/11/17 - appstream2)

3 つの API が更新され、UserSettings の Action に SMART_CARD_REDIRECTION 列挙値が追加されました。

→CreateStack: リクエストとレスポンスに SMART_CARD_REDIRECTION を追加
→UpdateStack: リクエストとレスポンスに SMART_CARD_REDIRECTION を追加
→DescribeStacks: レスポンスの Stacks リスト内 UserSettings.Action に追加

📄 設定例

JSON スタックの UserSettings 設定例 
{
  "Name": "my-stack",
  "UserSettings": [
    {
      "Action": "SMART_CARD_REDIRECTION",
      "Permission": "ENABLED"
    }
  ]
}

🛠️ 設定方法

✅ 前提条件

✓最新の WorkSpaces Applications エージェントを実行する Windows イメージを使用していること
✓ユーザーが WorkSpaces Applications の Windows 用クライアントで接続すること
✓スマートカードサインインを利用する場合、フリートが Active Directory ドメインに参加していること
1

スタックでスマートカードリダイレクトを有効化

BashAWS CLI
aws appstream update-stack \
  --name my-stack \
  --user-settings "Action=SMART_CARD_REDIRECTION,Permission=ENABLED"

既存スタックの UserSettings に SMART_CARD_REDIRECTION アクションを追加し、ローカルデバイスのスマートカードをセッション内へリダイレクトできるようにします。

2

設定の確認

BashAWS CLI
aws appstream describe-stacks --names my-stack \
  --query "Stacks[0].UserSettings"

スタックの UserSettings を取得し、SMART_CARD_REDIRECTION が ENABLED になっていることを確認します。

3

クライアントからの動作確認

ユーザーは WorkSpaces Applications の Windows 用クライアントでセッションに接続し、ローカルのスマートカードがセッション内のアプリケーションから認識されることを確認します。無効化する場合は Permission を DISABLED に設定して UpdateStack を実行します。

💡 メリット

💼 ビジネス面

✓コスト最適化: CAC / PIV カード必須の組織でも、複数ユーザーでインスタンスを共有するマルチセッションフリートへ移行可能
✓コンプライアンス維持: 公共部門や医療機関の規制要件であるスマートカードベースの多要素認証をクラウドでも継続
✓移行の簡素化: シングルからマルチセッションへの移行時に認証方式の変更が不要

🔧 技術面

✓柔軟な制御: サインインとリダイレクトをスタック単位で個別に有効化 / 無効化
✓多用途利用: 認証に加え、電子署名やメール暗号化にも利用可能
✓API での管理: CreateStack / UpdateStack で自動化でき、IaC にも組み込みやすい

⚠️ デメリット・制約事項

🚧 制限事項

⚠最新の WorkSpaces Applications エージェントを実行する Windows イメージが必要
⚠クライアントは Windows 用クライアントに限定 (Web ブラウザアクセスでは利用不可)
⚠スマートカードサインインにはドメイン参加済みフリートが必要

🤔 考慮すべき点

⚠既存のリダイレクト利用スタックでは設定が有効のまま維持されるため、不要な場合は明示的に DISABLED へ変更が必要
⚠無効化には最新エージェントバージョンのイメージが必要
⚠イメージにスマートカードミドルウェア / ドライバーのインストールが必要な場合がある

🎯 ユースケース

🏛️ ユースケース 1: 政府機関の CAC ユーザーのマルチセッション移行

シナリオ: 政府機関が、CAC サインインを利用しているシングルセッションフリートのユーザーを、コスト効率の高いマルチセッションフリートへ移行したい。

Bash実装例
# マルチセッションフリートに関連付けたスタックでサインインとリダイレクトを有効化
aws appstream update-stack \
  --name gov-multi-session-stack \
  --user-settings "Action=SMART_CARD_REDIRECTION,Permission=ENABLED"

効果: CAC によるサインイン要件を維持したままマルチセッションフリートへ移行でき、インスタンスコストを削減できる。

🏥 ユースケース 2: 医療機関での電子署名

シナリオ: 医療機関で、ストリーミングセッション内の電子カルテアプリケーションから、職員の PIV カードで電子署名を行いたい。

Bash実装例
aws appstream update-stack \
  --name healthcare-stack \
  --user-settings "Action=SMART_CARD_REDIRECTION,Permission=ENABLED"

効果: ローカルのスマートカードをセッション内にリダイレクトし、電子署名やメール暗号化を安全に実行できる。

🔐 ユースケース 3: セキュリティポリシーに応じたスタック別制御

シナリオ: 同一組織内で、機密性の高い業務用スタックのみスマートカード認証を必須とし、一般業務用スタックではリダイレクトを無効化したい。

Bash実装例
# 一般業務用スタックではリダイレクトを無効化
aws appstream update-stack \
  --name general-stack \
  --user-settings "Action=SMART_CARD_REDIRECTION,Permission=DISABLED"

効果: スタック単位の個別設定により、業務のセキュリティ要件に応じた柔軟なアクセス制御を実現できる。

💰 料金

スマートカードリダイレクト機能自体に追加料金はありません。WorkSpaces Applications の標準料金 (インスタンスタイプとフリートタイプに応じた従量課金、およびユーザー料金) が適用されます。マルチセッションフリートは複数ユーザーで 1 つのインスタンスを共有するため、シングルセッションと比較してコストを削減できます。

🌍 利用可能リージョン

WorkSpaces Applications が提供されているすべての AWS 商用リージョンおよび AWS GovCloud (US) リージョンで利用可能です。

🔗 関連サービス・機能

→Amazon WorkSpaces: フルマネージドの仮想デスクトップサービス。Windows WorkSpaces へのスマートカード認証をサポート
→AWS Directory Service / Active Directory: スマートカードサインインの前提となるドメイン参加とユーザー認証基盤
→AWS Certificate Manager / PKI: スマートカード認証に使用する証明書の発行・管理基盤との連携

📌 まとめ

スマートカードリダイレクトのサポートとマルチセッションフリートへのスマートカードサインイン拡大により、CAC / PIV カードを必須とする公共部門や医療機関などの組織が、認証要件を維持したままコスト効率の高いマルチセッションフリートを採用できるようになりました。該当する組織は、最新エージェントの Windows イメージと Windows 用クライアントを前提に、スタック設定でのリダイレクト有効化とマルチセッション移行の検討を推奨します。
