Amazon OpenSearch Service

🔍 OpenSearch Ingestion が
欧州 (パリ) リージョンで利用可能に

リリース日
2026-06-25

📌 概要

2026 年 6 月 25 日、Amazon OpenSearch Ingestion が 欧州 (パリ) リージョン eu-west-3 で利用可能になりました。 パリリージョンのお客様は、マネージドクラスターやサーバーレスコレクションへデータを取り込む際に OpenSearch Ingestion を使用できます。

OpenSearch Ingestion は、インデックス作成前にデータを取り込み・処理するための フルマネージド・サーバーレスなデータ収集サービスです。 オープンソースの Data Prepper をベースとし、ノーコードでフィルタリング・変換・秘匿化 (redact)・ルーティングを実行できます。

❌ アップデート前の課題

  • パリリージョンで OpenSearch Ingestion が利用できず、マネージドな取り込み層を構築できなかった
  • データレジデンシー要件があるお客様は Logstash や Jaeger を自前運用する必要があった
  • スケーリングやパッチ適用などのインフラ管理が必要だった

✅ アップデート後の改善

  • パリリージョンで Ingestion パイプラインを直接構築できる
  • データレジデンシー要件を満たしつつフルマネージドな取り込み層を利用できる
  • ノーコードで加工し、インフラ管理なしでパイプラインを運用できる

パイプラインは Source (取り込み元) → Processor (加工処理) → Sink (出力先) の 3 要素で構成され、 パリリージョン内でログ・メトリクス・トレースを処理して OpenSearch Service へ配信します。

⚡ 主要機能

🚀 フルマネージド・サーバーレスなデータ取り込み

  • インフラ管理・ソフトウェアのパッチ適用・手動スケーリングが不要
  • リアルタイムのログ・メトリクス・トレースを OpenSearch Service / Serverless へストリーミング
  • Logstash や Jaeger などのサードパーティツールを置き換え可能

🛠️ ノーコードでのデータ加工

  • フィルタリング・変換・秘匿化 (redact)・ルーティングをコード不要で実行
  • オープンソースの Data Prepper ベースで、エンリッチ・正規化・集計に対応
  • 一般的なユースケース向けのパイプライン設定ブループリントを提供

📈 自動プロビジョニングとスケーリング

  • 定義したキャパシティ上限に基づいてパイプラインを自動スケール
  • ワークロードの変動に応じてキャパシティを増減
  • パイプラインの停止・開始によりコストを制御可能

パイプライン設定例

YAML pipeline-config.yaml 
version: "2"
log-pipeline:
  source:
    http:
      path: "/log/ingest"
  processor:
    - grok:
        match:
          message: ["%{COMMONAPACHELOG}"]
  sink:
    - opensearch:
        hosts: ["https://search-my-domain.eu-west-3.es.amazonaws.com"]
        index: "apache_logs"

version で Data Prepper のメジャーバージョンを指定。最新マイナーバージョンが自動選択されます。

⚙️ 設定方法

前提条件

  • →取り込み先となる OpenSearch Service ドメインまたは Serverless コレクションが存在すること
  • →パイプラインがアクセスするための IAM ロールとアクセスポリシーが設定されていること
  • →パリリージョン (eu-west-3) で作業を行うこと

ステップ 1: パイプラインの作成

Bash create-pipeline 
aws osis create-pipeline \
  --pipeline-name my-paris-pipeline \
  --min-units 1 \
  --max-units 4 \
  --pipeline-configuration-body file://pipeline-config.yaml \
  --region eu-west-3

--min-units / --max-units で Ingestion OCU の範囲を指定し、その範囲内で自動スケールされます。

ステップ 2: パイプラインの状態確認

Bash get-pipeline 
aws osis get-pipeline \
  --pipeline-name my-paris-pipeline \
  --region eu-west-3

ステータスが ACTIVE になればデータの取り込みを開始できます。

ステップ 3: データソースの接続とモニタリング

データプロデューサーをエンドポイントに接続して送信。CloudWatch でパフォーマンスを、CloudWatch Logs でエラーログを監視します。コスト制御のためにパイプラインの停止・開始も可能です。

💡 メリット

ビジネス面

  • ✓データレジデンシー対応: フランス国内で取り込みを完結。欧州圏の選択肢が拡大
  • ✓運用コスト削減: 自前運用の人的リソースを削減
  • ✓コスト制御の柔軟性: 停止・開始や OCU 上限でコストを最適化

技術面

  • ✓インフラ管理の不要化: スケーリング・パッチ・クラスター管理が自動化
  • ✓ノーコード加工: 複雑な変換・秘匿化・ルーティングをコードなしで実現
  • ✓セキュリティ強化: VPC 接続オプションでネットワークレベルの保護を追加

⚠️ デメリット・制約事項

制限事項

  • !OpenSearch Service 利用可能リージョンの一部 (今回 17 リージョン) でのみ提供
  • !サポートは Data Prepper 2.x。すべてのマイナーバージョンがサポートされるわけではない
  • !メジャーバージョンは version を手動変更しない限り自動アップグレードされない

考慮すべき点

  • !データが流れていなくても、割り当てた Ingestion OCU 分だけ課金される
  • !コスト最適化のため、不要なパイプラインは停止を検討
  • !最小・最大 OCU はピークと平常時のバランスを考慮して決定

🎯 ユースケース

1. 欧州圏のアプリケーションログ集約基盤

フランス国内でサービスを展開する企業が、データレジデンシー要件を満たしながらログを集約・分析。

アプリケーション → OpenSearch Ingestion (eu-west-3) → OpenSearch Service ドメイン
（grok でパース、機密情報を redact）

効果: フランス国内でログ取り込みを完結させつつ、ノーコードで機密情報を秘匿化。

2. オブザーバビリティ (トレース・メトリクス) パイプライン

マイクロサービスの分散トレースとメトリクスを、Jaeger を自前運用せずに OpenSearch で可視化。

OpenTelemetry Collector → OpenSearch Ingestion (OTel trace source) → OpenSearch Serverless コレクション

効果: サードパーティツールの運用負荷を排除し、サーバーレスでトレースを取り込み。

3. S3 データのストリーミング取り込み

Amazon S3 に蓄積されたログを定期的に OpenSearch へ取り込み、検索・分析可能に。

Amazon S3 (SQS 通知) → OpenSearch Ingestion (S3 source) → OpenSearch Service ドメイン

効果: S3 のイベント通知をトリガーに、自動スケールするパイプラインで取り込み。

💰 料金

料金はパイプラインに割り当てられた Ingestion OCU (OpenSearch Compute Unit) の数に基づきます。 データがパイプラインを流れているかどうかにかかわらず、割り当てられた OCU 分が課金されます。 利用状況に応じてキャパシティは自動的にスケールアップ・ダウンします。

詳細は Amazon OpenSearch Service の料金ページ を参照してください。

📝 まとめ

Amazon OpenSearch Ingestion がパリリージョン (eu-west-3) で利用可能になり、 欧州圏のデータレジデンシー要件を持つお客様もフルマネージドなデータ取り込み層を活用できるようになりました。 サードパーティツールの自前運用が不要になり、ノーコードでのデータ加工とコスト制御が可能です。 パリリージョンでログやオブザーバビリティ基盤を構築するお客様は、 既存パイプラインの OpenSearch Ingestion への移行 を検討する価値があります。
