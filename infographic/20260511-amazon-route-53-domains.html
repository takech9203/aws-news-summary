Amazon Route 53 Domains

34 の新しいトップレベルドメインをサポート

.app, .dev, .health 等 34 種類の TLD が Route 53 で直接登録・管理可能に

2026-05-11

📋 概要

Amazon Route 53 Domains が新たに 34 のトップレベルドメイン (TLD) の登録と管理をサポート。業界固有・テクノロジー特化・目的別のドメイン名オプションが AWS 上で直接利用可能になった。

Route 53 コンソール、AWS CLI、SDK に加え、AWS Agent Toolkit を使用してフルマネージド MCP サーバー経由でプログラマティックにドメインを登録・管理することも可能。

  • .app や .dev など人気 TLD は外部レジストラで登録が必要

  • AI エージェントからのドメイン管理が標準化されていない
AFTER
  • 34 の新 TLD を Route 53 内で直接登録・管理可能
  • DNS ホストゾーンとドメイン登録を統合管理、自動更新対応
  • MCP サーバー経由で AI エージェントからドメイン操作が可能

⚡ 主要機能

🏷️ 34 の新規 TLD サポート
テクノロジー系 (.app, .dev, .page)、クリエイティブ系 (.art, .diy)、業界特化系 (.health, .realty, .food)、コミュニティ系 (.forum, .earth) など多彩な TLD に対応
🌐 統合 DNS 管理
ドメイン登録と同時にホストゾーンが自動作成。Route 53 の DNS レコード管理と完全に統合され、ネームサーバーの設定が不要
🔄 自動更新機能
登録したドメインの有効期限管理を自動化し、更新忘れによるドメイン失効リスクを低減
🤖 AWS Agent Toolkit 連携
フルマネージド MCP サーバーを通じてドメイン操作を自動化。AI エージェントワークフローからプログラマティックにドメイン登録・管理が可能

🔌 登録インターフェース

方法 説明
🖥️ Route 53 コンソール GUI ベースのドメイン検索・登録
⌨️ AWS CLI aws route53domains コマンドによる操作
📦 AWS SDK 各言語の SDK を使用したプログラマティック操作
🤖 AWS Agent Toolkit MCP サーバー経由の AI エージェント統合

🛠️ 設定方法

前提条件

  • AWS アカウント
  • Route 53 Domains へのアクセス権限 (IAM ポリシー)
  • ドメイン登録に必要な連絡先情報

Step 1: ドメインの可用性を確認

Bash ドメイン可用性チェック 
aws route53domains check-domain-availability \
  --domain-name myproject.app

Step 2: ドメインを登録

Bash ドメイン登録 (自動更新有効) 
aws route53domains register-domain \
  --domain-name myproject.app \
  --duration-in-years 1 \
  --admin-contact '{
    "FirstName": "Taro",
    "LastName": "Yamada",
    "ContactType": "PERSON",
    "OrganizationName": "Example Corp",
    "AddressLine1": "1-1-1 Shibuya",
    "City": "Tokyo",
    "State": "Tokyo",
    "CountryCode": "JP",
    "ZipCode": "150-0002",
    "PhoneNumber": "+81.312345678",
    "Email": "admin@example.com"
  }' \
  --registrant-contact '{...}' \
  --tech-contact '{...}' \
  --auto-renew

Step 3: DNS レコードを設定

Bash ホストゾーン確認 + A レコード追加 
# ホストゾーン ID を確認
aws route53 list-hosted-zones-by-name \
  --dns-name myproject.app

# A レコードを追加
aws route53 change-resource-record-sets \
  --hosted-zone-id Z1234567890 \
  --change-batch '{
    "Changes": [{
      "Action": "CREATE",
      "ResourceRecordSet": {
        "Name": "myproject.app",
        "Type": "A",
        "TTL": 300,
        "ResourceRecords": [{"Value": "203.0.113.1"}]
      }
    }]
  }'

Step 4: AWS Agent Toolkit を使用した登録 (オプション)

Python AI エージェントからのドメイン管理 
# AWS Agent Toolkit MCP サーバーを使用した例
import boto3

client = boto3.client('route53domains')

# 複数ドメインの可用性チェック
domains = ['property1.realty', 'property2.realty', 'property3.realty']
for domain in domains:
    response = client.check_domain_availability(DomainName=domain)
    if response['Availability'] == 'AVAILABLE':
        print(f'{domain} is available for registration')

⚖️ メリット・デメリット

✅ メリット

  • 業界に適した TLD でブランド価値向上
  • AWS 内でドメイン登録から DNS 設定まで完結
  • Agent Toolkit で大規模ドメイン管理を自動化
  • ホストゾーン自動作成でネームサーバー設定不要
  • Terraform / CloudFormation での IaC 管理が容易
  • MCP サーバーで DevOps ワークフローに統合

⚠️ 制約・注意点

  • アカウントあたりデフォルト 20 件の登録上限
  • TLD ごとに料金が異なり年単位課金
  • プロモーショナルクレジットは使用不可
  • 一部 TLD に登録要件あり (.health 等)
  • .zip / .mov はフィッシングリスクの懸念
  • WHOIS プライバシー保護は TLD により異なる

💡 ユースケース

🚀 SaaS アプリケーションのブランディング
スタートアップが新しい SaaS 製品のドメインを .app TLD で取得し、AWS 上で完全に管理。CloudFront との ALIAS レコード連携でシームレスな HTTPS 配信を実現。
→ .app ドメインによりアプリケーション製品としての認知度が向上
👨‍💻 開発者ポートフォリオサイト
開発者が技術ポートフォリオや OSS プロジェクトのドキュメントサイト用に .dev ドメインを取得。GitHub Pages や S3 静的サイトへの CNAME 設定で運用を簡素化。
→ .dev ドメインにより技術者としてのブランディングが強化
🏢 AI エージェントによるマルチドメイン管理
不動産企業が複数の物件サイト用に .realty ドメインを一括登録し、AI エージェントで管理を自動化。Agent Toolkit の MCP サーバー連携で大量のドメイン管理作業を委譲。
→ 運用負荷を大幅に削減し、ドメインポートフォリオ管理を効率化

💰 料金情報

ドメイン登録料金は TLD ごとに異なり、年単位で課金。ボリュームディスカウントは提供されていない。

TLD 用途 年間料金
.app デジタルプロダクト TLD により異なる (公式料金ページ参照)
.dev 開発プロジェクト TLD により異なる (公式料金ページ参照)
.health ヘルスケア TLD により異なる (公式料金ページ参照)
⚠️ 注意

プロモーショナルクレジットはドメイン登録料金には使用できません。正確な料金は Route 53 料金ページ を参照してください。

🌍 利用可能リージョン

Amazon Route 53 Domains はグローバルサービスとして提供されており、すべての AWS リージョンから利用可能。ドメイン登録の API エンドポイントは us-east-1 (バージニア北部) を使用する。

🌐 グローバルサービス 📍 API エンドポイント: us-east-1
