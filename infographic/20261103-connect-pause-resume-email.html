📧 メールの一時停止・再開機能

⏸️ Pause / ▶️ Resume でエージェントの時間を有効活用 | リリース日: 2026 年 11 月 3 日

📌 概要

エージェントがメール対応を一時停止 (Pause) し、後から再開 (Resume) できる機能が利用可能になりました。承認待ちや情報待ちの間にメールを一時停止して優先度の高いコンタクトに対応し、準備が整った時点で作業を再開できます。

一時停止中の時間はアクティブな処理時間とは別に記録されるため、スーパーバイザーはエージェントがメール対応に費やした実時間を正確に把握できます。しきい値を超えて一時停止されたメールは、フローで自動的に再開・転送することも可能です。

❌ Before: アップデート前の課題
  • 承認待ち・情報待ちが発生しても対応を中断する手段がなく、他の優先度の高いコンタクトへ切り替えにくかった
  • 待ち時間も処理時間 (ハンドリングタイム) に含まれ、実作業時間を正確に測定できなかった
  • 長時間放置されたメールを検知して自動的に対処する仕組みがなかった
✅ After: アップデート後の改善
  • Agent Workspace / CCP からワンクリックで一時停止・再開でき、優先度の高いコンタクトへ即座に切り替え可能
  • 一時停止時間が処理時間と分離して記録され、メール対応の実時間を正確に可視化
  • イベントフローで、しきい値超過メールの自動再開・転送が可能
  • PauseContact / ResumeContact API によるプログラム制御に対応

エージェントはメールを一時停止して着信などに対応し、後から再開できます。スーパーバイザーによるリアルタイム監視、イベントフローによる自動再開・転送、API によるプログラム制御にも対応しています。

⚡ 主要機能

⏸️ 1. エージェントによる一時停止・再開
  • Agent Workspace / CCP のメールコンタクト上部にある [Pause] ボタンで一時停止、[Resume] ボタンで再開
  • 一時停止するとハンドリングタイマーが停止し、本文と返信コンポーザーは「Paused」バナーの背後に隠され、[Send] は再開までブロック
  • 作成途中の返信の下書きは保持され、再開時にそのまま編集を継続可能
  • コンタクトリストには一時停止インジケーターと件名が表示され、一時停止中のメールを識別可能
⏱️ 2. 一時停止時間の分離計測と監視
  • 一時停止中の時間はアクティブな処理時間とは別に記録
  • エージェントは各メールの一時停止時間を確認可能
  • スーパーバイザーは一時停止中のメールと一時停止時間をリアルタイムに監視可能
🔄 3. フローによる自動化
  • 「Set event flow」ブロックで「Flow at contact pause」イベントフックを選択し、一時停止時に自動実行されるフローを設定
  • しきい値を超えて一時停止されたままのメールをフローで自動的に再開または転送
🔌 4. API によるプログラム制御
  • PauseContact / ResumeContact API により、エージェントの操作なしで一時停止・再開が可能
  • 対象にはインバウンドメールコンタクトのコンタクト ID を指定
  • 下書き返信が進行中のインバウンドメールを一時停止すると、関連するエージェント返信コンタクトも同時に一時停止・再開

💻 API の利用例

Bash AWS CLI によるメールの一時停止・再開 
# インバウンドメールコンタクトを一時停止する
aws connect pause-contact \
  --instance-id <インスタンス ID> \
  --contact-id <インバウンドメールのコンタクト ID>

# 一時停止したメールコンタクトを再開する
aws connect resume-contact \
  --instance-id <インスタンス ID> \
  --contact-id <インバウンドメールのコンタクト ID>

指定するのはインバウンドメールコンタクトのコンタクト ID であり、エージェント返信コンタクトを直接一時停止・再開することはできません。

🛠️ 設定方法

前提条件

✓Amazon Connect インスタンスでメールチャネルを利用していること
✓エージェントが Agent Workspace または CCP でメールコンタクトを処理できるよう設定済みであること
✓自動再開・転送を行う場合は、フローを編集できる権限があること

手順

1
エージェントがメールを一時停止する
Agent Workspace または CCP で対応中のメールコンタクト上部にある [Pause] ボタンを選択。ハンドリングタイマーが停止し、下書きが保持された状態で一時停止されます。
2
メールを再開する
一時停止中のメールコンタクト上部にある [Resume] ボタンを選択。本文と返信コンポーザーが復元され、下書きの続きから返信作業を再開できます。
3
一時停止時の自動フローを設定する (任意)
フローデザイナーで「Set event flow」ブロックを追加し、イベントフックに「Flow at contact pause」を選択。一定時間を超えて一時停止されたままのメールを自動的に再開または転送できます。

💼 ビジネス面

✓正確なパフォーマンス測定: 一時停止時間が処理時間と分離されるため、実作業時間に基づいた KPI 管理やキャパシティプランニングが可能になる

✓リアルタイム監視: スーパーバイザーが一時停止中のメールと一時停止時間をリアルタイムに把握し、滞留を早期に検知できる
✓フローによる自動化: しきい値を超えて放置されたメールの自動再開・転送により、SLA 違反のリスクを低減できる
✓API 対応: 外部システムの状態 (承認完了など) と連動した自動制御を実装できる

⚠️ デメリット・制約事項

制限事項

✗1 つのメールを一時停止できる回数は最大 10 回まで。上限に達すると、それ以降の一時停止リクエストは拒否される
✗一時停止中のメールも、インスタンスのアクティブメールコンタクト数の上限にカウントされる
✗一時停止・再開の対象はインバウンドメールコンタクトであり、エージェント返信コンタクトを単独で一時停止・再開することはできない
✗AWS GovCloud (US) リージョンおよび中国リージョンでは利用できない

考慮すべき点

⚠️一時停止に時間制限はないため、放置を防ぐにはしきい値ベースの自動再開・転送フローの設定を検討する必要がある
⚠️一時停止中のメールがアクティブコンタクト数を消費するため、同時処理数の設計時には一時停止中のメールも考慮する必要がある
