👀 SageMaker Capacity Reservations の閲覧サポート

Amazon SageMaker AI 📅 リリース日: 2026 年 11 月 23 日

📝 概要

SageMaker Capacity Reservations (予約済みキャパシティ) を SageMaker コンソール、AWS CLI、AWS SDK から閲覧できるようになりました。SageMaker Capacity Reservation は、On-Demand Capacity Reservation を通じて SageMaker AI がアカウント向けに確保するコンピュートキャパシティであり、SageMaker AI でキャパシティを予約しているエンタープライズのお客様が対象です。

管理者は、ステータス、インスタンスタイプ、アベイラビリティーゾーン、インスタンス数、開始時刻・終了時刻とともに予約を一覧表示できます。詳細ページでは、予約を利用できる SageMaker AI リソース (HyperPod クラスターや Inference エンドポイント) と関連付けステータス、使用中・利用可能なインスタンス数も確認できます。

GPU キャパシティの計画が重要な大規模基盤モデルのトレーニングや推論を運用する組織にとって、予約状況をセルフサービスで即座に把握できることは、ワークロード計画の迅速化とキャパシティの有効活用に直結します。

❌ アップデート前の課題

✗予約済みキャパシティの期間やインスタンスの可用性をセルフサービスで確認する方法がなかった
✗ワークロード計画時に、予約情報の確認のため AWS Support への問い合わせが必要だった
✗どの SageMaker AI リソースが予約を利用しているか、何台が使用中かを把握しにくかった

✅ アップデート後の改善

✓コンソール、AWS CLI、AWS SDK から予約の一覧と詳細をセルフサービスで確認できる
✓ステータス、インスタンスタイプ、AZ、インスタンス数、開始・終了時刻を即座に把握できる
✓HyperPod クラスターや推論エンドポイント、インスタンスの使用状況まで確認できる

管理者がコンソール、CLI、SDK のいずれかから Capacity Reservation API を呼び出し、予約の詳細、使用状況、関連付けられた HyperPod クラスターや推論エンドポイントを確認する流れ

⚙️ 主要機能

📋 1. 予約の一覧表示

→ SageMaker コンソールの Reserved Capacity セクションで、アカウント内の SageMaker Capacity Reservations を一覧表示

→ ステータス、インスタンスタイプ、アベイラビリティーゾーン、インスタンス数、開始時刻・終了時刻を確認可能

→ AWS CLI や AWS SDK からも同じ情報をプログラムで取得可能

📄 2. 予約詳細の確認

→ 個々の予約を開くと、予約の ARN を含む詳細情報を確認できる

→ SageMaker Inference に関連付けられた予約では、エンドポイント設定で使用する ML reservation ARN も表示

→ ステータスは開始・終了時刻に基づいて自動設定

🟡 開始前
Scheduled
→
🟢 期間中
Active
→
⚪ 終了後
Expired
🔗 3. リソース関連付けの可視化

→ 予約を利用できる SageMaker AI リソース (HyperPod クラスター、Inference エンドポイント) と関連付けステータスを確認

→ 関連付けステータスは、サービスが予約を利用できる状態なら Active、それ以外は Pending または Inactive

📊 4. 使用状況のモニタリング

→ 予約ごとに、使用中・利用可能なインスタンス数をリソースタイプ別に確認

→ エンドポイント稼働中のインスタンス、または HyperPod クラスターに組み込まれているインスタンス (ワークロード未実行でも) が「使用中」としてカウント

→ 使用状況は定期更新され、コンソールに最終更新時刻を表示 (API では LastRefreshTime として返却)

🔬 技術仕様

予約詳細に含まれる情報

項目詳細
インスタンスタイプ予約済みインスタンスの SageMaker AI インスタンスタイプ (例: ml.p5.48xlarge)
アベイラビリティーゾーン / AZ ID予約済みインスタンスの配置場所。AZ ID (例: use1-az1) はアカウント間で同一のゾーンを示す
合計インスタンス数予約に含まれるインスタンスの数
開始時刻 / 終了時刻予約済みインスタンスが利用可能な期間。終了時刻のない予約も存在する
ステータスScheduled (開始前)、Active (期間中)、Expired (終了後)
ARNarn:aws:sagemaker:{region}:{account-id}:sm-capacity-reservation/{smcr-id} 形式

🛠️ 設定方法

前提条件

→SageMaker AI でキャパシティを予約していること (エンタープライズのお客様が対象)
→SageMaker の該当 API (ListCapacityReservations など) を呼び出す IAM 権限があること
→AWS CLI を使用する場合は、新 API に対応したバージョンへ更新しておくこと
1予約の一覧を表示する
Bash予約の一覧表示
aws sagemaker list-capacity-reservations \
  --region us-east-1

各予約のステータス、インスタンスタイプ、AZ、インスタンス数、開始・終了時刻を確認できます。

2予約の詳細を確認する
Bash予約詳細の取得
aws sagemaker describe-capacity-reservation \
  --sm-capacity-reservation-arn arn:aws:sagemaker:us-east-1:123456789012:sm-capacity-reservation/smcr-xxxxxxxx

SageMaker Inference に関連付けられた予約の場合は、エンドポイント設定で使用する ML reservation ARN も確認できます。

3使用状況とリソース関連付けを確認する
Bash使用状況と関連付けの確認
# 使用中・利用可能インスタンス数の確認
aws sagemaker get-capacity-reservation-usage \
  --sm-capacity-reservation-arn arn:aws:sagemaker:us-east-1:123456789012:sm-capacity-reservation/smcr-xxxxxxxx

# 関連付けられたリソースの確認
aws sagemaker describe-resource-associations \
  --sm-capacity-reservation-arn arn:aws:sagemaker:us-east-1:123456789012:sm-capacity-reservation/smcr-xxxxxxxx

前者は使用状況をリソースタイプ別に返し、更新時刻は LastRefreshTime で確認できます。後者は関連付けられた HyperPod クラスターや推論エンドポイントと、関連付けステータス (Active / Pending / Inactive) を返します。コンソールの場合は Reserved Capacity セクションから同じ情報を GUI で確認できます。

💼 ビジネス面

✓キャパシティ計画の迅速化: 予約の期間や空き状況を即座に確認でき、AWS Support への問い合わせを待たずに計画を進められる
✓予約キャパシティの有効活用: 使用中・利用可能インスタンス数を把握し、高価な GPU キャパシティの遊休を減らして投資対効果を向上

🔧 技術面

✓API によるプログラマブルな可視化: 新 API により、予約情報を社内ダッシュボードや自動化ワークフローに組み込める
✓リソース関連付けの透明性: 予約がどの HyperPod クラスターや推論エンドポイントに利用されているかをステータス付きで追跡
✓AZ ID による正確な配置確認: アカウント間で共通の AZ ID により、他リソースとの AZ 整合性を正確に確認

⚠️ デメリット・制約事項

制限事項

⚠SageMaker AI でキャパシティを予約しているエンタープライズのお客様向けの機能
⚠本アップデートは閲覧 (表示) 機能の提供であり、予約の作成・変更をセルフサービスで行う機能ではない
⚠利用可能リージョンは Amazon SageMaker HyperPod が利用可能なリージョンに限られる

考慮すべき点

⚠使用状況のカウントは定期更新でリアルタイムではないため、LastRefreshTime (コンソールでは最終更新時刻) を確認して判断する
⚠HyperPod クラスターに組み込まれたインスタンスは、ワークロード未実行でも「使用中」としてカウントされる
⚠新 API の利用には、AWS CLI / SDK を対応バージョンへ更新する必要がある

🎯 ユースケース

🚀 ユースケース 1: 大規模トレーニングジョブの実行計画

シナリオ: ML プラットフォームチームが、予約済みの ml.p5.48xlarge キャパシティを使って基盤モデルのトレーニングを計画し、予約期間と空きインスタンス数を確認したい。

Bash実装例
aws sagemaker list-capacity-reservations

aws sagemaker get-capacity-reservation-usage \
  --sm-capacity-reservation-arn <予約の ARN>

効果: 予約の開始・終了時刻と利用可能インスタンス数を即座に確認し、AWS Support への問い合わせなしでトレーニングのスケジュールを確定できる。

⚡ ユースケース 2: 推論エンドポイントへの予約キャパシティの割り当て確認

シナリオ: 推論基盤の管理者が、SageMaker Inference エンドポイントの設定で使用する ML reservation ARN を確認し、予約済みキャパシティ上でエンドポイントを稼働させたい。

Bash実装例
aws sagemaker describe-resource-associations \
  --sm-capacity-reservation-arn <予約の ARN>

コンソールの場合は、Reserved Capacity セクションで予約を開き、詳細ページに表示される ML reservation ARN をエンドポイント設定に使用します。

効果: 予約と推論エンドポイントの関連付け状況 (Active / Pending / Inactive) を確認しながら、予約済みキャパシティを確実に推論に割り当てられる。

📊 ユースケース 3: 予約キャパシティの遊休監視ダッシュボード

シナリオ: FinOps チームが、確保済み GPU キャパシティの使用率を定期的に監視し、遊休が発生している予約を検出して各チームに利用を促したい。

Python実装例
import boto3

sm = boto3.client("sagemaker")

reservations = sm.list_capacity_reservations()
for r in reservations["SMCapacityReservations"]:
    usage = sm.get_capacity_reservation_usage(
        SMCapacityReservationArn=r["SMCapacityReservationArn"]
    )
    # 使用中 / 利用可能インスタンス数を集計してダッシュボードへ送信

効果: 予約ごとの使用状況を自動収集し、遊休キャパシティの早期発見とコスト効率の改善につなげられる。

💵 料金

閲覧機能自体に関する追加料金の記載はありません。SageMaker Capacity Reservations は、SageMaker AI とのキャパシティ予約契約に基づくもので、料金の詳細は Amazon SageMaker AI の料金ページおよび契約内容を確認してください。

🌍 利用可能リージョン

Amazon SageMaker HyperPod が利用可能なすべての AWS リージョンで利用できます。対象リージョンの一覧は SageMaker HyperPod のドキュメントを参照してください。

🔗 関連サービス・機能

🖥️ Amazon SageMaker HyperPod

予約済みキャパシティを利用できるリソースの 1 つ。クラスターに組み込まれたインスタンスが予約の使用分としてカウントされる。

⚡ Amazon SageMaker Inference

予約に関連付けられた ML reservation ARN をエンドポイント設定で指定することで、予約済みキャパシティ上で推論エンドポイントを稼働できる。

☁️ Amazon EC2 On-Demand Capacity Reservations

SageMaker Capacity Reservation の基盤となる仕組み。SageMaker AI がアカウント向けにキャパシティを確保する際に使用される。

✅ まとめ

これまで AWS Support への問い合わせが必要だった SageMaker の予約済みキャパシティの確認が、コンソール、AWS CLI、AWS SDK からセルフサービスで行えるようになりました。予約キャパシティを利用しているエンタープライズのお客様は、新しい API (ListCapacityReservations、GetCapacityReservationUsage など) を活用して、キャパシティ計画の迅速化と遊休キャパシティの監視を始めることを推奨します。
