📌 概要

AWS は、Amazon FSx for OpenZFS のオンデマンドデータレプリケーションが AWS オプトインリージョンに対応したことを発表しました。 これにより、ボリュームの増分ポイントインタイムスナップショットを、オプトインリージョンとの間で 双方向に転送できるようになりました。

オプトインリージョンは、標準リージョンと異なりアカウントごとに明示的な有効化が必要なリージョンです。 今回のアップデートにより、災害対策 (DR) やデータ配布を構築できる範囲が大きく広がりました。

Before / After

⛔ アップデート前の課題
  • レプリケーションはデフォルト有効リージョン間のみで利用可能
  • オプトインリージョンを DR サイトやデータ保管先として活用できない
  • 規制・データ所在地要件で利用する組織は別手段で転送が必要
➡
✅ アップデート後の改善
  • オプトインリージョンとの双方向で増分スナップショットを複製
  • オプトインリージョンを DR サイト / 配布先としてマネージド活用
  • FSx for OpenZFS 提供の全リージョンでクロスリージョン保護を構築

ソースリージョンのファイルシステムから取得した増分スナップショットを、オプトインリージョンの宛先ファイルシステムへ転送する構成。別アカウントへ複製する場合は AWS RAM を介してボリュームを共有します。

⚙️ 主要機能

🌐 オプトインリージョンとの双方向レプリケーション
  • デフォルト無効のオプトインリージョンへ増分ポイントインタイムスナップショットを複製
  • オプトインリージョンへ (to) / から (from) の両方向に対応
  • FSx for OpenZFS が提供される全リージョン (対応オプトインリージョン含む) で利用可能
🔒 マネージドな転送と暗号化
  • FSx がネットワーク接続を自動確立 / 維持し、中断時は再開して転送を継続
  • 転送中 (in transit) と保管時 (at rest) の両方でデータを暗号化
  • 増分コピーは差分のみ、フルコピーはクローン / 中間データを削除して全データ転送
🤝 クロスアカウントレプリケーションと AWS RAM 連携
  • AWS Resource Access Manager (RAM) と統合し、別アカウント間でボリュームを共有
  • ソースが共有 → 宛先が招待を承認 → スナップショットを宛先ボリュームへ複製

CLI による更新コマンド例

Bash copy-snapshot-and-update-volume 
aws fsx copy-snapshot-and-update-volume \
     --volume-id fsvol-1234567890abcdef0 \
     --source-snapshot-arn arn:aws:fsx:555555555555:snapshot/fsvol-1234567890abcdef0/fsvolsnap-021345abcdef6789 \
     --options DELETE_INTERMEDIATE_SNAPSHOTS DELETE_CLONED_VOLUMES DELETE_INTERMEDIATE_DATA \
     --copy-strategy INCREMENTAL_COPY

--copy-strategy で増分 / フルコピーを選択し、--options で中間スナップショットやクローンボリューム、中間データの削除を指定します。 進捗は describe-volumes の AdministrativeActions (VOLUME_UPDATE_WITH_SNAPSHOT) の ProgressPercent で確認できます。

前提条件

✓デプロイタイプに応じた最低スループットキャパシティ (シングル AZ 1: 256 MBps 以上、シングル AZ 2 / マルチ AZ: 160 MBps 以上) を満たすこと
✓CreateVolume および CopySnapshotAndUpdateVolume を実行する IAM 権限を持つこと
✓クロスアカウント時はソースが fsx:PutResourcePolicy 等と RAM 共有権限を、宛先が AWSResourceAccessManagerResourceShareParticipantAccess を持つこと

⚖️ メリットと制約事項

💡 メリット

✓災害対策範囲の拡大: オプトインリージョンをパッシブスタンバイ DR サイトとして活用し地理的冗長性を強化
✓データ所在地要件への対応: 規制で利用するオプトインリージョンでもマネージド保護が可能
✓追加料金なし: レプリケーション機能自体は無料 (標準データ転送料は別途)
✓増分転送による効率化: 差分のみ転送し転送量と時間を削減
✓マネージドな接続管理と暗号化: 接続の確立 / 維持 / 再開と暗号化を自動処理

⚠️ 制約・考慮点

✗1 ファイルシステムは同時に 1 レプリケーションタスクのみ
✗リージョンごと最大 20 ジョブの上限
✗子ボリュームは含まれず追加ジョブが必要
✗増分コピー中は宛先が読み取り専用、フルコピー中はアンマウント
⚠スループットを共有するため、通常必要量の 2 倍のプロビジョニングを推奨
⚠リージョン / アカウント間複製で標準データ転送料が発生
⚠CloudWatch で使用率を監視し必要に応じてスケールアップ

🎯 ユースケース

🛡️ 1. オプトインリージョンを利用した災害対策
シナリオ: データ所在地要件からオプトインリージョンを利用する企業が、本番データを複製して DR サイトを構築したい。
効果: 増分スナップショットを定期複製し、パッシブスタンバイ DR 環境を維持。リージョン障害時の復旧に備えられます。
📦 2. クロスアカウントでのデータ配布
シナリオ: 本番アカウントの FSx for OpenZFS データを、別アカウントの開発 / テスト環境やオプトインリージョンへ配布したい。

💰 料金・リージョン・関連サービス

💴 料金

オンデマンドデータレプリケーション機能自体に追加料金はなし。ただしリージョン / アカウントをまたいで複製する場合は、標準の AWS データ転送料金が適用されます。

🌍 利用可能リージョン

Amazon FSx for OpenZFS が提供されるすべての AWS リージョンで利用可能。今回のアップデートで対応するオプトインリージョンが新たに対象に加わりました。

🔗 関連サービス

→AWS RAM: 別アカウント間でボリュームを共有し、クロスアカウントレプリケーションを認可
→Amazon CloudWatch: パフォーマンス使用率を監視し、スループットを適切にスケール
→AWS IAM: CreateVolume や CopySnapshotAndUpdateVolume の権限を制御

📝 まとめ

今回のアップデートにより、FSx for OpenZFS のオンデマンドデータレプリケーションが オプトインリージョンに対応し、クロスリージョンの災害対策やデータ配布を構築できる範囲が大きく広がりました。 データ所在地要件を持つ組織や、より広い地理的冗長性を求めるワークロードでは、増分レプリケーションによる効率的なデータ保護を検討する価値があります。 まずは対象ボリュームと宛先リージョンを絞り、スループットと転送コストを見積もったうえで導入することを推奨します。
