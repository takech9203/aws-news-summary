AWS Pricing Calculator 📅 2026 年 11 月 20 日

💰 ワークロードコストを 1 回の API 呼び出しで見積もる
新 API「GetUsageLinesEstimatedCost」

AWS Billing and Cost Management Pricing Calculator に、保存不要・ステートレスなコスト見積もり API が登場

📝 概要

AWS Pricing Calculator に新しい API GetUsageLinesEstimatedCost が追加されました。 計画中のワークロードの見積もりコストを 1 回の API 呼び出しで返し、 1 リクエストあたり最大 500 件の使用量明細を受け付けます。 見積もりをアカウントに保存することなく、即座にコストを返すのが特徴です。

デプロイ前に設計のコストを確認したり、AI コーディングエージェントが設計段階でワークロードの価格を算出したりといった用途に適しており、 コスト管理の自動化を進める FinOps チームや開発者に価値のあるアップデートです。

500 件
1 リクエストで試算できる使用量明細の上限
3 種類
選択可能なレート種別 (割引・コミットメント対応)
追加料金なし
API の利用は無料・保存リソースも不要
❌ Before: アップデート前の課題
✗自動化には見積もりの作成・保存を行う複数ステップの API 操作 (CreateWorkloadEstimate、BatchCreateWorkloadEstimateUsage など) が必要だった
✗一時的な試算でも見積もりリソースがアカウントに保存され、後片付けや管理が必要だった
✗CI/CD パイプラインや AI エージェントから、軽量かつ即時にコストを確認する手段がなかった
✅ After: アップデート後の改善
✓1 回の API 呼び出しで最大 500 件の使用量明細のコストを即座に取得できる
✓見積もりの保存が不要になり、ステートレスにコスト試算を実行できる
✓パブリック料金に加え、自社の割引後料金や Savings Plans / リザーブドインスタンス適用後の料金でも試算できる

お客様のツールから使用量明細とレート種別を送信すると、API が AWS 料金データとアカウントのレート設定に基づいて即座にコストを算出して返します。見積もりはアカウントに保存されません。

⚡ 主要機能

1️⃣ 単一 API 呼び出しによる即時コスト見積もり
✓新 API GetUsageLinesEstimatedCost が AWS Billing and Cost Management Pricing Calculator (bcm-pricing-calculator) に追加
✓1 リクエストで最大 500 件の使用量明細を一括して試算可能
✓見積もり結果はアカウントに保存されず、ステートレスに利用できる
2️⃣ 3 種類のレート種別
BEFORE_DISCOUNTS
パブリックオンデマンド料金で試算
AFTER_DISCOUNTS
お客様固有の割引適用後の料金で試算
AFTER_DISCOUNTS_AND_COMMITMENTS
割引に加えて Savings Plans とリザーブドインスタンスを考慮した料金で試算
⚠️利用できるレート種別は Pricing Calculator のレート設定 (rate preferences) で許可されているものに限られる
3️⃣ 明細ごとの結果とエラーの分離
✓レスポンスには価格算出に成功した各明細のコスト (lineItems) と合計 (totalCost) が含まれる
✓価格算出できなかった明細は errors に理由付きで返され、部分的な失敗をハンドリングしやすい
✓明細ごとに付与する key でリクエストとレスポンスの明細を突合できる

🔧 技術仕様

項目詳細
API 名GetUsageLinesEstimatedCost (サービス: bcm-pricing-calculator)
使用量明細の上限1 リクエストあたり 1〜500 件
明細の必須フィールドserviceCode (例: AmazonEC2)、usageType (例: BoxUsage:t3.micro)、operation (例: RunInstances)、key (最大 10 文字の英数字)、amount (0 以上の数値)
レート種別BEFORE_DISCOUNTS / AFTER_DISCOUNTS / AFTER_DISCOUNTS_AND_COMMITMENTS
レスポンスrateType、totalCost、currency (USD)、lineItems (明細ごとのコスト)、errors (価格算出できなかった明細)
見積もりの性質AWS 料金データに基づく見積もり。税金は含まれず、実際の請求額は実使用量に依存
制約請求転送 (billing transfer) を請求ソースアカウントとして使用している場合は BEFORE_DISCOUNTS のみ利用可能

🛠️ 設定方法

✅ 前提条件

✓AWS CLI または AWS SDK の最新バージョンがインストールされていること
✓bcm-pricing-calculator の GetUsageLinesEstimatedCost アクションを許可する IAM 権限があること
✓割引後レートを利用する場合は、Pricing Calculator のレート設定で該当レート種別が許可されていること

ステップ 1: 使用量明細を定義して API を呼び出す

Bash パブリックオンデマンド料金で試算 
aws bcm-pricing-calculator get-usage-lines-estimated-cost \
  --rate-type BEFORE_DISCOUNTS \
  --usage '[
    {
      "serviceCode": "AmazonEC2",
      "usageType": "BoxUsage:t3.micro",
      "operation": "RunInstances",
      "key": "line1",
      "amount": 730
    },
    {
      "serviceCode": "AmazonS3",
      "usageType": "TimedStorage-ByteHrs",
      "operation": "StandardStorage",
      "key": "line2",
      "amount": 100
    }
  ]'

EC2 の t3.micro インスタンス 730 時間分と S3 標準ストレージ 100 GB-Mo 分の使用量明細を、パブリックオンデマンド料金で試算しています。各明細には突合用の一意な key を付与します。

ステップ 2: 割引・コミットメント適用後の料金で試算する

Bash 実効レートでの試算 
aws bcm-pricing-calculator get-usage-lines-estimated-cost \
  --rate-type AFTER_DISCOUNTS_AND_COMMITMENTS \
  --usage file://usage-lines.json

レート種別を AFTER_DISCOUNTS_AND_COMMITMENTS に変更し、自社の割引と Savings Plans / リザーブドインスタンスを考慮した料金で同じ使用量明細を試算しています。使用量明細は JSON ファイルから読み込んでいます。

ステップ 3: レスポンスを検証する

Bash JMESPath クエリで結果を抽出 
aws bcm-pricing-calculator get-usage-lines-estimated-cost \
  --rate-type BEFORE_DISCOUNTS \
  --usage file://usage-lines.json \
  --query '{total: totalCost, failed: length(errors)}'

JMESPath クエリで合計コストと価格算出に失敗した明細数を抽出しています。errors に明細が含まれる場合は、errorCode と errorMessage を確認して serviceCode / usageType / operation の組み合わせを修正します。

💡 メリット

📈 ビジネス面
✓デプロイ前のコスト可視化: 設計段階でワークロードのコストを確認でき、予算超過のリスクを事前に低減できる
✓実効レートでの試算: 自社の割引やコミットメントを反映した現実的なコスト見積もりが可能で、意思決定の精度が向上する
✓追加料金なし: API の利用に追加料金は発生しない
⚙️ 技術面
✓ステートレスな試算: 見積もりリソースの作成・保存・削除が不要で、CI/CD パイプラインや自動化ツールに組み込みやすい
✓AI エージェントとの親和性: AI コーディングエージェントが設計中にワークロードの価格を算出する、エージェント型ワークフローに適している
✓堅牢なエラーハンドリング: 価格算出できた明細とできなかった明細がレスポンス内で分離されるため、部分的な失敗にも対応しやすい

⚠️ デメリット・制約事項

🚧 制限事項
✗1 リクエストあたりの使用量明細は最大 500 件
✗利用できるレート種別は Pricing Calculator のレート設定で許可されているものに限られる
✗請求転送を請求ソースアカウントとして使用している場合は BEFORE_DISCOUNTS のみ利用可能
✗通貨は USD のみ
✗AWS GovCloud (US) リージョンと中国リージョンでは利用不可
🤔 考慮すべき点
⚠️見積もりには税金が含まれず、実際の請求額は実使用量によって変動する
⚠️serviceCode / usageType / operation の正確な組み合わせを把握する必要があり、AWS Price List API や Cost and Usage Report の明細を参照して特定するのが現実的
⚠️保存型のワークロード見積もり (共有やレビューが必要なケース) には、従来の Pricing Calculator のワークロード見積もり機能が引き続き適している

🎯 ユースケース

1. CI/CD パイプラインでのデプロイ前コストチェック 🔁

シナリオ: IaC テンプレートの変更をデプロイする前に、新しい構成の月額コストを自動で試算し、しきい値を超える場合はレビューを必須にしたい。

Bash コストしきい値チェック 
TOTAL=$(aws bcm-pricing-calculator get-usage-lines-estimated-cost \
  --rate-type AFTER_DISCOUNTS \
  --usage file://planned-usage.json \
  --query 'totalCost' --output text)

if (( $(echo "$TOTAL > 1000" | bc -l) )); then
  echo "見積もりコスト $TOTAL USD がしきい値を超えています。承認が必要です。"
  exit 1
fi

効果: コスト影響の大きい変更を本番反映前に検知でき、予期しないコスト増加を防止できる。

2. AI コーディングエージェントによる設計時の価格算出 🤖

シナリオ: AI コーディングエージェントがアーキテクチャを提案する際に、候補となる構成ごとのコストを算出して比較提示したい。

実装例: エージェントのツールとして GetUsageLinesEstimatedCost を登録し、構成案ごとに usage lines (serviceCode / usageType / operation / amount) を生成して API を呼び出し、totalCost を比較して提示する。

効果: 設計段階でコストを考慮したアーキテクチャ選定が可能になり、コスト最適化が設計プロセスに組み込まれる。

3. 社内コスト管理ツールへの組み込み 💻

シナリオ: 社内のワークロード申請システムで、申請者が入力したリソース構成から概算コストを即時に表示したい。

Python boto3 からの呼び出し例 
import boto3

client = boto3.client("bcm-pricing-calculator")
response = client.get_usage_lines_estimated_cost(
    usage=[
        {
            "serviceCode": "AmazonEC2",
            "usageType": "BoxUsage:m5.large",
            "operation": "RunInstances",
            "key": "app1",
            "amount": 730.0,
        }
    ],
    rateType="AFTER_DISCOUNTS_AND_COMMITMENTS",
)
print(response["totalCost"], response["currency"])

効果: 見積もりリソースを保存せずにリアルタイムで概算コストを表示でき、申請フローの UX とコスト意識が向上する。
