📌 概要

AWS は、AWS Organizations の宣言型ポリシー (Declarative Policies) を利用して、環境内のすべての VPC に対して VPC Encryption Controls をモニターモードまたは強制モードで有効化できる機能を発表しました。希望する暗号化設定を一元的に定義・管理し、環境全体に適用できます。

VPC Encryption Controls は、Amazon VPC 内および VPC 間の転送中の暗号化 (encryption in transit) を監査・強制するツールを提供します。HIPAA、FedRAMP、PCI などの暗号化標準への準拠証明にも役立ち、アカウント・組織・OU 単位で制御を行使できます。

🔄 アップデートによる変化

❌ Before (課題)
  • 各 VPC で個別に Encryption Controls を有効化する必要があった
  • 除外設定 (exclusions) を VPC ごとに個別に構成
  • 新規作成 VPC に設定が自動継承されず、都度手動対応
→
✅ After (改善)
  • 単一の宣言型ポリシーで既存・将来のすべての VPC に強制
  • VPC ごとの個別設定が不要、一元的な定義と維持が可能
  • 新規参加アカウント・新規 VPC にも設定が自動継承

⚙️ 主要機能

1. 宣言型ポリシーによる一元管理

  • EC2 宣言型ポリシー (ec2_attributes) の vpc_encryption_control 属性で設定を定義
  • 組織全体、特定の OU、または個別アカウントにポリシーをアタッチ可能
  • 組織に参加した新規アカウントは、アタッチ済みポリシーを自動継承

2. モニターモードと強制モードの選択

  • attempt_monitor: 全 VPC をモニターモードへ。暗号化状態を監査し、非暗号化トラフィックを許可するリソースを特定
  • attempt_enforce: 全 VPC を強制モードへ。転送中トラフィックを常に暗号化するサービスのみ許可
  • unmanaged: VPC Encryption Controls を無効化

3. リソースタイプ単位の除外設定

  • 転送中の暗号化をサポートしないリソースタイプを除外 (exclusions) として指定
  • 除外可能: internet_gateway, nat_gateway, vpc_lattice, vpc_peering, lambda, egress_only_internet_gateway, elastic_file_system, virtual_private_gateway
  • 除外の優先順位: 組織 → OU → アカウント → VPC

🔧 技術仕様

mode 属性の値

unmanaged

Encryption Controls を無効化。ポリシーをデタッチすると、アカウントレベルの設定は以前の状態にロールバック。

attempt_monitor

スコープ内の全 VPC をモニターモードへ移行。新規 VPC もモニターモードで作成。

attempt_enforce

全 VPC を強制モードへ移行。まずモニターモードに配置し、その後自動的に強制モードへ遷移。

ポリシー設定例

JSON 宣言型ポリシー (強制モード + 除外) 
{
  "ec2_attributes": {
    "vpc_encryption_control": {
      "mode": {
        "@@assign": "attempt_enforce"
      },
      "exclusions": {
        "@@assign": ["internet_gateway", "nat_gateway", "vpc_lattice"]
      }
    }
  }
}

📝 設定方法

✅ 前提条件

  • AWS Organizations で組織を設定し、すべての機能 (all features) が有効
  • 宣言型ポリシー (Declarative Policies) が組織で有効化済み
  • VPC Encryption Controls をサポートするリージョンで利用
1

モニターモードで全体を検証する

組織全体で attempt_monitor を適用し、非暗号化トラフィックを許可しているリソースを特定。強制モードへ移行する前に、アカウントステータスレポートで除外できない非準拠リソースが存在しないことを確認します。

2

除外設定を構成する

転送中の暗号化をサポートしないリソース (インターネットゲートウェイ、NAT ゲートウェイ、Amazon VPC Lattice など) について、リージョンごとに exclusions を設定。強制モードへの移行時にこれらが原因で失敗することを防ぎます。

3

強制モードへ移行する

準拠状況を確認後、mode を attempt_enforce に変更。対象 VPC を一度モニターモードに配置してから自動的に強制モードへ遷移。移行失敗時は DescribeVpcEncryptionControls で失敗 VPC を、GetVpcResourcesBlockingEncryptionEnforcement で違反リソースを特定します。

💡 メリット

📈 ビジネス面

  • コンプライアンスの証明: HIPAA、FedRAMP、PCI などへの準拠を組織全体で一貫して証明
  • 運用負荷の削減: VPC ごとの個別設定が不要になり運用コストを削減
  • ガバナンスの強化: アカウント・OU・組織単位で暗号化制御を一元適用

🛠️ 技術面

  • 設定の自動維持: コントロールプレーンで強制されるため、新 API 追加後も設定を維持
  • 新規リソースへの自動適用: 新規 VPC や新規参加アカウントにも自動継承
  • 柔軟な除外制御: リソースタイプ・リージョン単位で除外を設定し段階的展開が可能

⚠️ デメリット・制約事項

🚧 制限事項

  • ポリシー使用時、VPC 所有者は VPC レベルで ModifyVpcEncryptionControl、DeleteVpcEncryptionControl、CreateVpcEncryptionControl などを実行できなくなる
  • 除外でカバーされない非準拠リソースが含まれると強制モード移行が失敗し、VPC はモニターモードのまま enforce-failed 状態に
  • VPC Encryption Controls をサポートするリージョンでのみ利用可能

🔎 考慮すべき点

  • ポリシーをデタッチすると、アカウントレベルの設定はアタッチ前の状態にロールバック
  • 除外の優先順位は 組織 → OU → アカウント → VPC の順。上位設定が下位を上書きするため、トップダウンで展開計画を立てる必要がある
  • VPC ピアリングの除外は、強制モードの VPC をモニターモードに戻す前に削除が必要

🎯 ユースケース

1. 規制対象ワークロードのコンプライアンス強制

シナリオ: HIPAA 対象の医療データを扱う組織が、すべての VPC で転送中の暗号化を強制し、監査に備えたい。

JSON
{
  "ec2_attributes": {
    "vpc_encryption_control": {
      "mode": { "@@assign": "attempt_enforce" }
    }
  }
}

✨ 組織全体で転送中の暗号化を一元的に強制し、コンプライアンス要件の充足を継続的に証明できる。

2. 段階的な暗号化制御の展開

シナリオ: 大規模なマルチアカウント環境で、まず暗号化状態を可視化してから強制モードへ段階的に移行したい。

JSON
{
  "ec2_attributes": {
    "vpc_encryption_control": {
      "mode": { "@@assign": "attempt_monitor" }
    }
  }
}

✨ モニターモードで非準拠リソースを特定した後、除外設定を整備して強制モードへ安全に移行できる。

3. 特定 OU への限定適用

シナリオ: 本番環境の OU にのみ厳格な暗号化強制を適用し、開発環境の OU では監査のみにとどめたい。

設定
本番 OU: mode = attempt_enforce
開発 OU: mode = attempt_monitor

✨ 環境の特性に応じて暗号化制御のレベルを OU 単位で柔軟に使い分けられる。

💰 料金・利用可能リージョン

💰 料金

AWS Organizations における宣言型ポリシーの利用に追加料金は発生しません。VPC Encryption Controls 自体の利用にも追加料金はかかりません。

🌍 利用可能リージョン

VPC Encryption Controls をサポートするすべての AWS リージョンで利用可能です。

  • Amazon VPC: 暗号化制御の対象となるネットワーク基盤

📝 まとめ

このアップデートは、VPC 単位で個別に行っていた転送中の暗号化制御を、宣言型ポリシーによって組織全体で一元管理できるようにする重要な機能強化です。まずモニターモードで環境全体の暗号化状態を可視化し、除外設定を整備した上で強制モードへ段階的に移行することを推奨します。

HIPAA、FedRAMP、PCI などの規制要件を持つ組織は、本機能を活用してコンプライアンスの継続的な証明と運用負荷の削減を実現できます。
