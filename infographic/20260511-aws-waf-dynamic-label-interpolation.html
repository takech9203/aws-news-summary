AWS WAF

Dynamic Label Interpolation

動的ラベル補間 - 単一ルールでラベル名前空間全体を転送

2026-05-11

📋 概要

AWS WAF に動的ラベル補間機能が追加された。${namespace:} 構文を使用することで、ラベル名前空間全体を単一のルールでオリジンに転送できるようになった。さらに、合成ラベル (Synthetic Labels) により、クライアント IP や TLS フィンガープリントなどのリクエストコンテキスト情報をカスタムブロックページやヘッダーに直接埋め込むことが可能になった。

Before

  • シグナル値ごとに個別ルールを作成 (ルール数が増加)
  • 静的な 1 対 1 マッピングのハードコードが必要
  • ブロックページにリクエスト固有情報を含められない
  • TLS フィンガープリント転送に追加の仕組みが必要

After

  • 1 つのルールで名前空間全体を動的展開
  • 新しいラベル追加時にヘッダーが自動適応
  • 合成ラベルでリクエストコンテキストを直接埋め込み
  • 追加の API フィールドや設定不要で即座に利用可能

⚡ 主要機能

1. 動的ラベル補間構文

${namespace:}

ラベル名前空間をインラインで解決する構文。カスタムリクエストヘッダー、レスポンスヘッダー、レスポンスボディで使用可能。単一ラベル一致時はその終端値に、複数一致時はカンマ区切りリストに、一致なし時は空文字列に解決される。

2. 合成ラベル (Synthetic Labels)

リクエストコンテキストから自動的に解決される組み込み値:

  • ${awswaf:ip:} クライアント IP アドレス
  • ${awswaf:request_id:} WAF リクエスト ID
  • ${awswaf:ja3:} JA3 TLS フィンガープリント
  • ${awswaf:ja4:} JA4 TLS フィンガープリント

3. 広範な互換性

AWS Managed Rules (Bot Control、ATP)、AWS Marketplace ルールグループ、ユーザー独自のカスタムラベルに対応。名前空間に新しいラベルが追加されると自動的に適応する。

🔧 技術仕様

補間が機能するサーフェス

サーフェス 使用例 用途
カスタムリクエストヘッダー ${awswaf:managed:aws:bot-control:bot:category:} オリジンへのラベル転送
カスタムレスポンスボディ Your IP: ${awswaf:ip:} ブロック/チャレンジページへの値埋め込み
カスタムレスポンスヘッダー /verify?ip=${awswaf:ip:}&rid=${awswaf:request_id:} 動的リダイレクト

解決動作

条件 動作 例
単一ラベル一致 終端値に解決 scraping
複数ラベル一致 カンマ区切りリスト non_browser_user_agent,automated_browser
一致なし 空文字列 (空)

新しい API フィールドは追加されていない。既存の CustomRequestHandling、CustomResponse の値フィールド内で ${namespace:} 構文を使用する形式。

📝 設定方法

動的補間を使用してボット分類やリクエストコンテキストをオリジンに転送するルールの例:

JSON 動的補間ルール - アプリケーションシグナリング 
{
  "Name": "app-signalling",
  "Priority": 500,
  "Statement": {
    "MatchAllStatement": {}
  },
  "Action": {
    "Allow": {
      "CustomRequestHandling": {
        "InsertHeaders": [
          {
            "Name": "x-waf-bot-category",
            "Value": "${awswaf:managed:aws:bot-control:bot:category:}"
          },
          {
            "Name": "x-waf-bot-name",
            "Value": "${awswaf:managed:aws:bot-control:bot:name:}"
          },
          {
            "Name": "x-waf-client-ip",
            "Value": "${awswaf:ip:}"
          },
          {
            "Name": "x-waf-fingerprint",
            "Value": "${awswaf:ja4:}"
          }
        ]
      }
    }
  }
}
JSON カスタムブロックページ - 参照 ID 付き 
{
  "Name": "block-with-custom-page",
  "Priority": 300,
  "Statement": {
    "LabelMatchStatement": {
      "Scope": "LABEL",
      "Key": "awswaf:managed:aws:bot-control:bot:verified:false"
    }
  },
  "Action": {
    "Block": {
      "CustomResponse": {
        "ResponseCode": 403,
        "CustomResponseBodyKey": "block-page",
        "ResponseHeaders": [
          {
            "Name": "x-waf-request-id",
            "Value": "${awswaf:request_id:}"
          }
        ]
      }
    }
  }
}

🎯 ユースケース

1. アプリケーションシグナリング

ボット分類に基づいてアプリケーション側で適応的な処理を行う (スクレイパーには CAPTCHA を表示、検索エンジンには許可)

効果: 1 つのルールで全ボットカテゴリと検出シグナルをオリジンに転送し、カテゴリに応じた処理 (MFA 強制、レート制限、CAPTCHA 表示) を実装できる。

2. カスタムブロックページ with 参照 ID

ブロックされたユーザーが誤検知を報告する際に、サポートチームが迅速に調査できるよう参照情報を提供する。

効果: ブロックページにリクエスト ID を自動埋め込みし、ユーザーがサポートに連絡する際の参照情報を提供。WAF ログとの照合が即座に可能。

3. CloudFront キャッシュセグメンテーション

ボットカテゴリごとに異なるキャッシュエントリを保持し、スクレイパーには低品質のキャッシュコンテンツを返す。

効果: ボットカテゴリ別にキャッシュが分離され、正規ユーザーとスクレイパーに異なるコンテンツを提供。新しいボットカテゴリにも自動対応。

⚠️ デメリット・制約事項

制限事項

一致するラベルがない場合は空文字列に解決されるため、アプリケーション側での空値ハンドリングが必要

複数ラベル一致時のカンマ区切りリストのパースをアプリケーション側で実装する必要がある

合成ラベルは現時点で IP、リクエスト ID、JA3、JA4 の 4 種類に限定

考慮すべき点

カスタムヘッダーに IP アドレスを含める場合、CloudFront やオリジン間の通信が暗号化されていることを確認する

JA3/JA4 フィンガープリントは WAF トークン生成後に利用可能になるため、Challenge ルールとの組み合わせが必要

ラベル値がそのままヘッダーやレスポンスに挿入されるため、下流でのインジェクション対策を考慮すること

動的ラベル補間は追加費用なしで利用可能。AWS WAF の既存料金体系が適用される。

項目 月額料金 (概算)

ルール (1 ルールあたり) $1.00
リクエスト (100 万リクエストあたり) $0.60

動的ラベル補間により従来の数百ルールが 1 ルールに集約できるため、ルール課金の大幅な削減が期待できる。
