Amazon SageMaker JumpStart 📅 リリース日: 2026 年 11 月 11 日

🧠 DeepSeek-V4-Pro / V4-Flash / V4.1-Flash モデルの提供開始

MIT ライセンスのオープンウェイト MoE モデル 3 種を、数クリックで自社 AWS アカウントにデプロイ

📝 概要

DeepSeek の DeepSeek-V4-Pro、DeepSeek-V4-Flash、DeepSeek-V4.1-Flash の 3 つのモデルが Amazon SageMaker JumpStart で利用可能になりました。いずれも MIT ライセンスで公開されたオープンウェイトの Mixture-of-Experts (MoE) 言語モデルで、トークンごとに総パラメータのごく一部のみをアクティブ化することで、推論、コーディング、エージェントワークロードにおいてフロンティアクラスの性能と大規模運用時の高い効率性を両立します。

❌ アップデート前の課題
  • DeepSeek V4 系の最新モデルを AWS 上で利用するには、モデルウェイトを自前でダウンロードし、推論コンテナやサービング基盤を独自に構築する必要があった
  • 1M トークンのコンテキストウィンドウを持つ大規模 MoE モデルのデプロイには、インフラ設計やサービング設定の高度な専門知識が必要だった
  • エージェントワークロードやマルチモーダルタスク向けに、コスト効率と性能のバランスが取れた最新オープンウェイトモデルの選択肢が限られていた
✅ アップデート後の改善
  • SageMaker JumpStart のモデルカタログから数クリックで DeepSeek V4 系モデルをデプロイ可能に
  • 用途に応じて、フラッグシップの V4-Pro、コスト効率重視の V4-Flash、エージェント特化かつマルチモーダル対応の V4.1-Flash を選択可能に
  • MIT ライセンスのオープンウェイトモデルを自社 AWS アカウント内で安全にホストし、データを外部に送信せずに利用可能に

SageMaker JumpStart のモデルカタログから 3 つの DeepSeek V4 系モデルを選択し、自社 AWS アカウント内の SageMaker 推論エンドポイントとしてデプロイする流れ

⚙️ 主要機能

🧠 DeepSeek-V4-Pro
フラッグシップ
  • 総パラメータ数 1.6T の MoE モデル、トークンごとに 49B をアクティブ化
  • 1M トークンのコンテキストウィンドウをサポート
  • 長文ドキュメント分析、マルチステップ推論、最大限のモデル容量を必要とする高度な生成タスクに最適
⚡ DeepSeek-V4-Flash
コスト効率
  • 総パラメータ数 284B の効率的な MoE モデル、トークンごとに 13B をアクティブ化
  • V4-Pro と同じ 1M トークンのコンテキストウィンドウ
  • レイテンシに敏感でコスト重視の本番デプロイメントに最適、幅広い言語タスクに対応
🚀 DeepSeek-V4.1-Flash
エージェント + マルチモーダル
  • 新しい Causal Encoder-Decoder (CED) アーキテクチャ、552B パラメータのバックボーン
  • プリフィル時 8B / デコード時 16B のみをアクティブ化
  • 1M トークンのコンテキストと 384K の最大出力トークン
  • CSA2 + FP4 KV キャッシングで KV キャッシュを V4-Flash の約 1/4 に削減
  • エージェント、コーディング、ビジョンタスクでコスト効率が大幅に向上
📜 MIT ライセンスのオープンウェイトモデル

3 モデルとも MIT ライセンスで公開されており、商用利用やカスタマイズの自由度が高い。自社 AWS アカウント内でホストするため、データのコントロールを維持できます。

🛠️ 設定方法

前提条件

  • AWS アカウントと SageMaker AI を利用できる IAM 権限
  • Amazon SageMaker Studio または SageMaker Python SDK の実行環境
  • デプロイ先リージョンで対象モデルに必要な推論インスタンスのクォータ
1
SageMaker JumpStart モデルカタログでモデルを検索

SageMaker コンソールから SageMaker Studio を開き、JumpStart のモデルカタログで「DeepSeek」を検索します。DeepSeek-V4-Pro、DeepSeek-V4-Flash、DeepSeek-V4.1-Flash から用途に合ったモデルを選択します。

2
モデルをデプロイ

コンソールの場合はモデル詳細ページで [デプロイ] を選択し、インスタンスタイプやエンドポイント名を確認してデプロイします。SageMaker Python SDK を使用する場合の例は以下のとおりです。

Python JumpStart モデルのデプロイ 
from sagemaker.jumpstart.model import JumpStartModel

# JumpStart のモデル ID を指定してモデルを作成
# 実際のモデル ID は JumpStart モデルカタログで確認してください
model = JumpStartModel(model_id="<deepseek-v4-model-id>")

# 推論エンドポイントとしてデプロイ
predictor = model.deploy()
3
推論リクエストの実行

デプロイ済みのエンドポイントに対してチャット形式のリクエストを送信し、モデルの応答を取得します。

Python 推論リクエストの例 
# デプロイしたエンドポイントに推論リクエストを送信
response = predictor.predict({
    "messages": [
        {"role": "user", "content": "AWS の MoE モデル活用のベストプラクティスを教えてください。"}
    ],
    "max_tokens": 1024
})
print(response)

💼 ビジネス面

✓導入までの時間短縮: 数クリックまたは数行のコードで最新の DeepSeek V4 系モデルをデプロイでき、検証や本番導入までのリードタイムを大幅に短縮
✓コスト効率の高い選択肢: 用途に応じて 3 モデルから選択でき、特に V4.1-Flash は KV キャッシュ削減によりエージェントワークロードの運用コストを抑制
✓ライセンスの柔軟性: MIT ライセンスのオープンウェイトモデルのため、商用利用やファインチューニングなどの自由度が高い

🔧 技術面

✓MoE による高効率推論: トークンごとに総パラメータの一部のみをアクティブ化し、モデル容量と推論効率を両立
✓1M トークンの長大コンテキスト: 3 モデルとも 1M トークンをサポートし、長文ドキュメント分析や大規模コードベースの処理に対応
✓データのコントロール: モデルを自社 AWS アカウント内のエンドポイントとしてホストするため、推論データが外部に送信されない

⚠️ デメリット・制約事項

制限事項

⚠公式発表では利用可能リージョンが明記されていないため、利用予定リージョンの JumpStart モデルカタログで提供状況の確認が必要
⚠大規模 MoE モデルのホスティングには高性能な GPU インスタンスが必要となり、インスタンスクォータの引き上げが必要になる場合がある
⚠マルチモーダル対応は V4.1-Flash のみで、V4-Pro と V4-Flash はテキストタスクが中心

考慮すべき点

⚠セルフホスト型のため、Amazon Bedrock のようなサーバーレス従量課金ではなく、エンドポイント稼働時間に応じたインスタンス課金となる
⚠モデルごとにアクティブパラメータ数や KV キャッシュ特性が異なるため、ワークロードの特性 (レイテンシ要件、コンテキスト長、エージェント利用の有無) に応じたモデル選定と負荷テストを実施する

🎯 ユースケース

📄 ユースケース 1: 長文ドキュメントの分析と高品質レポート生成

シナリオ: 金融機関が数百ページに及ぶ契約書や規制文書を分析し、要約や論点整理を自動化したい。

実装例: DeepSeek-V4-Pro を SageMaker JumpStart からデプロイし、1M トークンのコンテキストウィンドウを活用して文書全体を一度に投入し、マルチステップ推論で論点を抽出する。

✅ 効果: 文書を分割せずに全体の文脈を保ったまま分析でき、高精度な要約と論点抽出を実現できる。

💬 ユースケース 2: コスト重視の本番チャットアプリケーション

シナリオ: SaaS 企業が顧客向けチャットアシスタントを提供しており、応答品質を維持しながら推論コストとレイテンシを削減したい。

実装例: DeepSeek-V4-Flash をデプロイし、アクティブパラメータ 13B の効率的な推論でレイテンシに敏感な本番トラフィックを処理する。

✅ 効果: V4-Pro と同じ 1M トークンのコンテキストを維持しつつ、大幅に低い計算コストで本番運用できる。

🤖 ユースケース 3: マルチモーダル対応のコーディングエージェント

シナリオ: 開発チームが、スクリーンショットや設計図を理解しながら長時間動作するコーディングエージェントを構築したい。

実装例: DeepSeek-V4.1-Flash をデプロイし、CED アーキテクチャと CSA2 + FP4 KV キャッシングによる低い KV キャッシュフットプリントを活かして、長いエージェントセッションを処理する。

✅ 効果: ビジョン入力を含むエージェントワークロードを、V4-Flash 比約 1/4 の KV キャッシュで効率的に実行し、コスト効率を大幅に改善できる。
