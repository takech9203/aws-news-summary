Amazon WorkSpaces Applications

☁️ Host-to-Client URL Redirection

🔗 ストリーミングセッション内の URL をローカルブラウザで自動的に開く新機能

2026-05-04
AWS What's New

📋 概要

Amazon WorkSpaces Applications (旧 AppStream 2.0) にホストからクライアントへの URL リダイレクション機能が追加された。ストリーミングセッション内で開かれた URL を自動的にユーザーのローカルブラウザで起動でき、管理者は AWS Management Console を通じて許可/拒否する URL パターンを設定して制御できる。

❌ Before

  • 全ての Web コンテンツがストリーミングインフラを経由して処理
  • 動画視聴など帯域幅大量消費コンテンツもサーバーリソースを消費
  • インフラコストが不必要に高くなる傾向
  • 外部リンクをローカルブラウザで開くための手動操作が必要

✅ After

  • URL パターンに基づいて自動的にローカルブラウザで URL が開かれる
  • 帯域幅大量消費コンテンツをローカルにオフロードしコスト削減
  • Word / Slack 内の埋め込みリンクも自動リダイレクト対象
  • Chrome / Edge ブラウザでのナビゲーションもリダイレクト対象

🏗️ アーキテクチャ図

ストリーミングセッション内のアプリケーションで URL がクリックされると、管理者が設定した許可リストと照合され、一致する場合はユーザーのローカルブラウザで自動的に開かれる。

⭐ 主要機能

🔄 URL リダイレクトの自動化

  • ストリーミングセッション内の URL をローカルデフォルトブラウザで自動的に開く
  • ブラウザナビゲーションおよびアプリ内埋め込みリンクの両方に対応
  • ユーザーの手動操作なしにシームレスにリダイレクト実行

🔒 許可/拒否パターンによるアクセス制御

  • AWS Management Console から URL パターンを設定
  • 許可リスト一致の URL のみがリダイレクト対象
  • 拒否リストにより特定 URL のリダイレクトをブロック可能
  • 機密アプリケーションをストリーミング環境内に保持

💻 幅広いアプリケーションサポート

  • Chrome / Edge ブラウザでのナビゲーション
  • Microsoft Word 内の埋め込みリンク
  • Slack やカスタム LOB アプリケーション内のリンク
  • ブラウザベースおよびアプリケーションベースの両方に対応

⚙️ 技術仕様

項目 詳細
ストリーミングホストブラウザ Chrome、Edge
対応アプリケーション Microsoft Word、Slack、カスタム LOB アプリ
リダイレクト先 ユーザーのローカルデフォルトブラウザ
設定方法 AWS Management Console
URL パターン設定 許可リスト / 拒否リストによるパターンマッチング

📝 設定要素

設定項目 説明
Allow URL Patterns リダイレクト対象とする URL パターンの一覧
Deny URL Patterns リダイレクトをブロックする URL パターンの一覧

🛠️ 設定方法

前提条件: WorkSpaces Applications 環境が構成済み / Console アクセス権限 / Chrome または Edge がインストール済み

1

URL リダイレクトポリシーの設定

AWS Management Console で Amazon WorkSpaces Applications の設定画面を開き、URL リダイレクトのポリシーを構成する。

2

許可 URL パターンの追加

動画ストリーミングサイトや外部 Web コンテンツなど、ローカルブラウザで開くことが望ましい URL パターンを許可リストに追加する。

3

拒否 URL パターンの追加

社内システムや機密データへのアクセス URL など、ストリーミング環境内に保持すべき URL パターンを拒否リストに追加する。

4

動作確認

ストリーミングセッションを開始し、設定した URL パターンに基づいてリダイレクトが正しく動作することを確認する。

💡 ユースケース

🎬 UC1: 動画コンテンツのオフロード

企業の従業員がストリーミングセッション内で業務アプリケーションを使用しながら、研修動画やプレゼンテーション動画を視聴する必要がある。

URL Patterns 許可リスト設定例 
Allow URL Patterns:
  - https://www.youtube.com/*
  - https://vimeo.com/*
  - https://company-training.example.com/videos/*
✨ 動画がローカル再生されることで、ストリーミングサーバーの帯域幅消費を大幅に削減し、他ユーザーのパフォーマンスも向上。

🌐 UC2: 外部 Web サービスへのアクセス

従業員が Slack や Word 内のリンクから外部 Web サービスにアクセスする際、ローカルブラウザで直接開きたい。

URL Patterns 許可/拒否リスト設定例 
Allow URL Patterns:
  - https://docs.google.com/*
  - https://*.sharepoint.com/*
  - https://confluence.example.com/*

Deny URL Patterns:
  - https://internal-crm.example.com/*
  - https://hr-system.example.com/*
✨ 一般 Web サービスはローカルで快適に利用、機密社内システムはストリーミング環境内で安全にアクセス。

💰 UC3: コスト最適化のためのインフラ負荷軽減

大規模組織で数百人が同時にストリーミングセッションを使用し、Web ブラウジングによるインフラコストが課題。

URL Patterns 帯域幅重視の設定例 
Allow URL Patterns:
  - https://*.cdn.example.com/*
  - https://media.example.com/*
  - https://*.streaming-service.com/*

Deny URL Patterns:
  - https://erp.example.com/*
  - https://finance.example.com/*
✨ 帯域幅大量消費コンテンツをローカルに移行し、インスタンスサイジングを最適化、月間インフラコストを削減。

⚖️ メリット / デメリット

✅ ビジネスメリット

💸 インフラコスト削減

帯域幅大量消費の Web ワークロードをローカルにオフロード、ストリーミングインフラのコストを削減

🔒 セキュリティ維持

機密アプリケーションはストリーミング環境内に保持しながら、一般 Web コンテンツのみをリダイレクト

😊 ユーザー体験向上

動画などリッチコンテンツをローカルデバイスで直接再生し快適な視聴体験を提供

⚠️ 制限事項・注意点

制限事項

  • ホスト側ブラウザは Chrome / Edge のみ対応
  • ブラウザ選択はローカル設定に依存
  • 設定は Console 経由のみ

考慮すべき点

  • URL パターン設計はセキュリティポリシーとの整合性が必要
  • ローカルアクセスに対するネットワーク制御が別途必要な場合あり
  • ユーザーのローカルデバイスに適切なブラウザとネットワーク接続が必要

💰 料金情報

🎉 追加料金なし

URL リダイレクション機能自体には追加料金がかからない。
Amazon WorkSpaces Applications の標準料金 (従量課金制) が適用される。
URL リダイレクションにより全体的なコスト削減効果が期待できる。

📝 まとめ

Amazon WorkSpaces Applications のホストからクライアントへの URL リダイレクション機能は、ストリーミング環境のコスト最適化とユーザー体験の向上を両立する実用的なアップデートである。特に動画視聴やリッチ Web コンテンツを扱う組織では、インフラコストの削減効果が大きい。東京リージョンを含む多数のリージョンで利用可能であり、既存の WorkSpaces Applications 環境に追加コストなく導入できるため、早期の評価・導入を推奨する。
