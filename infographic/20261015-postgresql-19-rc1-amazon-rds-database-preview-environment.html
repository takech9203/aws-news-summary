🐘 Amazon RDS for PostgreSQL 📅 2026 年 10 月 15 日

PostgreSQL 19 RC1 が RDS Database Preview Environment で利用可能に

GA (2026 年 11 月 19 日予定) に先立ち、マネージドな RDS 環境で PostgreSQL 19 の互換性と新機能を評価

📋 概要

Amazon RDS for PostgreSQL において、PostgreSQL 19 Release Candidate 1 (RC1) が Amazon RDS Database Preview Environment で利用可能になりました。PostgreSQL 19 の正式リリース (GA) に先立ち、 プレリリース版をマネージドな RDS 環境上で評価できます。

RC1 は安定性に重点を置いたリリースで、Beta 4 のテスト期間中に報告されたバグ修正と改善 (複雑な全文検索式のエラーハンドリング改善、並列 autovacuum の堅牢化、GIN インデックスメンテナンスの信頼性向上) が含まれます。

❌ アップデート前の課題

  • プレリリース版を試すには EC2 やオンプレミスにコミュニティ版を自分でインストールする必要があった
  • RDS 特有の構成 (パラメータグループ、マネージドバックアップなど) と組み合わせた検証を GA 前に行うことが難しかった
  • GA 後に初めて互換性問題が発覚し、アップグレード計画の手戻りが発生するリスクがあった

✅ アップデート後の改善

  • PostgreSQL 19 RC1 をマネージドな RDS 環境でプロビジョニングし、GA 前に互換性やパフォーマンスを評価できる
  • Beta 4 までのフィードバックを反映した安定版候補で、本番移行に近い品質のテストを実施できる
  • dump / load で既存データベースをインポートし、実データに近い条件で検証できる

Preview Environment で PostgreSQL 19 RC1 インスタンスを作成し、既存データベースから dump / load でデータを持ち込んで評価する流れです。 スナップショットは Preview Environment 内でのみ利用でき、インスタンスは最大 60 日で自動削除されます。

⚙️ 主要機能

1️⃣ PostgreSQL 19 RC1 の提供

→ PostgreSQL 19 の Release Candidate 1 を RDS のマネージド環境で評価可能

→ Beta 4 テスト期間のバグ修正と改善を反映した、安定性重視のリリース

→ 複雑な全文検索式のエラーハンドリング改善、並列 autovacuum の堅牢化、GIN インデックスメンテナンスの信頼性向上を含む

2️⃣ PostgreSQL 19 の注目機能 (コミュニティ発表より)

→ REPACK (CONCURRENTLY): テーブルをブロックせずに再編成する新コマンド

→ pg_plan_advice: クエリプランに関するアドバイスを提供する新モジュール

→ 並列 autovacuum: autovacuum_max_parallel_workers により並列ワーカーを利用可能

→ effective_wal_level: wal_level が replica でも論理レプリケーションを自動的に有効化できる挙動

→ COPY ... TO (FORMAT json): JSON 形式出力をサポート。RC1 ではクエリの列名 (エイリアス含む) を JSON キーとして使用するよう修正

→ postgres_fdw の統計インポート: RC1 では ANALYZE 実行ユーザーではなく外部テーブルの所有者として実行されるよう修正

3️⃣ Preview Environment の運用ルール

→ インスタンスは最大 60 日間保持され、保持期間終了後に自動削除

→ スナップショットは Preview Environment 内でのインスタンス作成・復元にのみ使用可能

→ PostgreSQL の dump / load 機能でデータベースのインポート / エクスポートが可能

🛠️ 設定方法

前提条件

✓AWS アカウントと Amazon RDS へのアクセス権限
✓米国東部 (オハイオ) us-east-2 リージョンの利用
✓評価用データを持ち込む場合は pg_dump / pg_restore などの PostgreSQL クライアントツール

ステップ 1: Preview Environment で利用可能なエンジンバージョンを確認する

Bash エンジンバージョンの確認 
aws rds describe-db-engine-versions \
  --engine postgres \
  --region us-east-2 \
  --endpoint-url https://rds-preview.us-east-2.amazonaws.com

Preview Environment 専用のエンドポイントに対してエンジンバージョン一覧を取得し、PostgreSQL 19 RC1 のバージョン識別子を確認します。

ステップ 2: PostgreSQL 19 RC1 のインスタンスを作成する

Bash DB インスタンスの作成 
aws rds create-db-instance \
  --db-instance-identifier pg19-rc1-eval \
  --engine postgres \
  --engine-version <ステップ 1 で確認したバージョン> \
  --db-instance-class db.m5.large \
  --allocated-storage 100 \
  --master-username postgres \
  --manage-master-user-password \
  --region us-east-2 \
  --endpoint-url https://rds-preview.us-east-2.amazonaws.com

マネジメントコンソールの場合は、RDS Database Preview Environment 専用コンソールから作成します。

ステップ 3: 既存データをインポートして評価する

Bash dump / load によるデータ移行 
# 既存環境からエクスポート
pg_dump -h <既存インスタンスのエンドポイント> -U postgres -Fc mydb > mydb.dump

# Preview Environment のインスタンスへインポート
pg_restore -h <Preview インスタンスのエンドポイント> -U postgres -d mydb mydb.dump

この環境でアプリケーションの互換性テスト、拡張機能の動作確認、性能評価を実施します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓アップグレードリスクの低減: GA 前に互換性問題を発見し、本番アップグレード計画の手戻りを防止
✓移行準備期間の確保: GA に先行して評価を開始し、GA 後すみやかに移行判断が可能
✓インフラ構築コストの削減: プレリリース版の検証環境をセルフマネージドで構築・運用する手間が不要

🔬 技術面のメリット

✓マネージド環境での検証: パラメータグループなど RDS の運用モデルに沿って新バージョンを評価
✓安定性重視の RC 品質: Beta 4 までのフィードバックを反映した候補版でテスト可能
✓実データでの評価: dump / load により実ワークロードに近い条件で検証

🚫 制限事項

✗インスタンスは最大 60 日間で自動削除されるため、長期利用はできない
✗スナップショットは Preview Environment 内でのみ使用可能。通常の RDS 環境への復元はできない
✗提供リージョンは米国東部 (オハイオ) のみ
✗RC1 はプレリリース版であり、本番ワークロードでの利用は想定されていない

⚠️ 考慮すべき点

⚠GA 版では RC1 から変更が入る可能性があり、GA 後に最終確認が必要 (2026 年 11 月 12 日に RC2 を予定)
⚠データの持ち出しは dump / load 経由となるため、大規模データベースでは移行時間を考慮
⚠Preview Environment の利用にも米国東部 (オハイオ) リージョンの RDS for PostgreSQL 料金が発生

💡 ユースケース

🔄 ユースケース 1: 既存アプリケーションの互換性検証

シナリオ: PostgreSQL 16 で稼働中の業務アプリケーションを PostgreSQL 19 へアップグレードする計画があり、SQL やドライバの互換性を GA 前に確認したい。

Bash本番データの投入と回帰テスト
# 本番スキーマとデータのサブセットを Preview 環境へ投入
pg_dump -h prod-instance.xxxx.ap-northeast-1.rds.amazonaws.com -Fc appdb > appdb.dump
pg_restore -h pg19-rc1-eval.xxxx.us-east-2.rds-preview.amazonaws.com -d appdb appdb.dump

# アプリケーションの回帰テストスイートを Preview 環境に向けて実行
✅ 効果: GA 前に非互換の SQL や拡張機能の問題を特定し、アップグレード計画に事前に織り込める。
⚡ ユースケース 2: 並列 autovacuum による運用改善の評価

シナリオ: 大規模テーブルで autovacuum の遅延が課題となっており、PostgreSQL 19 の並列 autovacuum による改善効果を測定したい。

SQLautovacuum の実行状況確認
-- パラメータグループで autovacuum_max_parallel_workers を設定し、
-- 大規模テーブルに対する vacuum 処理時間を比較測定する
SELECT relname, last_autovacuum, autovacuum_count
FROM pg_stat_user_tables
ORDER BY last_autovacuum DESC;
✅ 効果: 新機能による autovacuum 処理時間の短縮効果を本番導入前に定量評価できる。
🧹 ユースケース 3: REPACK (CONCURRENTLY) によるメンテナンス戦略の検討

シナリオ: テーブルの肥大化対策として定期的な再編成が必要だが、現行バージョンではロックの影響が大きく実施時間帯が限られている。

SQLブロックしないテーブル再編成
-- PostgreSQL 19 の新コマンドでテーブルをブロックせずに再編成
REPACK (CONCURRENTLY) large_table;
✅ 効果: サービス無停止でのテーブル再編成が可能かを事前に検証し、メンテナンス運用の簡素化を計画できる。

💰 料金と利用可能リージョン

料金

Preview Environment のデータベースインスタンスは、米国東部 (オハイオ) リージョンの Amazon RDS for PostgreSQL 料金に準じて課金されます。 Preview Environment 自体の追加料金はありませんが、インスタンス稼働時間とストレージに応じた通常の RDS 料金が発生します。
