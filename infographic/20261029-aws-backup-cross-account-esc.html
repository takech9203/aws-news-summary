AWS Backup

🔒 AWS European Sovereign Cloud でクロスアカウント管理 & クロスアカウントバックアップが利用可能に

📅 リリース日: 2026 年 10 月 29 日 | 機能: Cross-account management / Cross-account backup / Delegated administrator

📌 概要

AWS Backup のクロスアカウント管理、クロスアカウントバックアップ、委任管理者機能が、AWS European Sovereign Cloud (Germany) リージョンで利用可能になりました。AWS Organizations を利用する組織は、複数アカウントにわたるバックアップの一元的な管理、監視、コピーを実現できます。

データ主権に関する厳格な要件を持つ欧州の規制対象業界の組織は、AWS European Sovereign Cloud 内で完結する形で、マルチアカウント環境のデータ保護ガバナンスを強化できます。

😣 Before: アップデート前の課題

  • ESC (Germany) ではクロスアカウント管理が使えず、アカウントごとに個別にバックアップポリシーを設定・運用
  • 復旧ポイントを別アカウントへコピーできず、削除・侵害への保護が限定的
  • 運用チームに管理アカウントへのアクセスが必要で、最小権限の原則に反する運用になりがち

😊 After: アップデート後の改善

  • 管理アカウントまたは委任管理者から組織全体へポリシーを一括展開し、全ジョブを一元監視
  • 復旧ポイントを別アカウントのボールトへコピーでき、多層防御を実現
  • 委任管理者により、管理アカウントへのアクセスなしで組織全体のバックアップ管理を委任

管理アカウントまたは委任管理者アカウントから組織全体にバックアップポリシーを展開し、メンバーアカウントの復旧ポイントを別アカウントのボールトへコピーする構成です。すべて AWS European Sovereign Cloud 内で完結します。

⚙️ 主要機能

1️⃣ クロスアカウント管理
  • 管理アカウントまたは委任管理者アカウントから、組織全体へバックアップポリシーを展開
  • 全メンバーアカウントのバックアップ・コピー・復元ジョブを単一の場所から監視
  • アカウントごとの個別設定が不要になり、組織全体で一貫したデータ保護基準を適用
2️⃣ クロスアカウントバックアップ
  • 復旧ポイントを組織内の別アカウントのバックアップボールトへコピー
  • ソースアカウントでの偶発的または悪意のある削除に対する保護を追加
  • ランサムウェア対策やアカウント侵害時の復旧性向上に有効
3️⃣ 委任管理者
  • メンバーアカウントを委任管理者として登録可能
  • 運用チームは管理アカウントへのアクセスなしに組織全体のバックアップ管理を実行
  • 最小権限の原則に沿った運用体制を構築

🔬 技術仕様

機能の構成要素

項目詳細
前提サービスAWS Organizations (全機能が有効化されていること)
ポリシー展開元管理アカウントまたは委任管理者アカウント
ポリシータイプAWS Organizations のバックアップポリシー
コピー先組織内の別アカウントのバックアップボールト
監視対象バックアップジョブ、コピージョブ、復元ジョブ
対象リージョンAWS European Sovereign Cloud (Germany) リージョン

バックアップボールトのアクセスポリシー例

クロスアカウントコピーを受け入れるには、コピー先アカウントのボールトでコピー操作を許可します。

JSON コピー先ボールトのアクセスポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCrossAccountCopy",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "backup:CopyIntoBackupVault",
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "aws:PrincipalOrgID": "o-xxxxxxxxxx"
        }
      }
    }
  ]
}

STEP 1クロスアカウント管理の有効化

Bash信頼されたアクセスの有効化
aws organizations enable-aws-service-access \
  --service-principal backup.amazonaws.com

管理アカウントで AWS Backup と AWS Organizations の信頼されたアクセスを有効化します。これにより、組織全体へのバックアップポリシー展開が可能になります。

STEP 2委任管理者の登録 (オプション)

Bash委任管理者の登録
aws organizations register-delegated-administrator \
  --account-id 111122223333 \
  --service-principal backup.amazonaws.com

バックアップ運用を担当するメンバーアカウントを委任管理者として登録します。以降、このアカウントから組織全体のバックアップポリシー管理とジョブ監視が可能になります。

STEP 3バックアップポリシーの作成と展開

Bashポリシー作成とアタッチ
aws organizations create-policy \
  --name "org-backup-policy" \
  --type BACKUP_POLICY \
  --content file://backup-policy.json \
  --description "Organization-wide backup policy"

aws organizations attach-policy \
  --policy-id p-xxxxxxxx \
  --target-id r-xxxx

組織全体に適用するバックアップポリシーを作成し、組織ルートまたは OU にアタッチします。ポリシーはメンバーアカウントに自動的に展開されます。

STEP 4クロスアカウントコピーの設定

バックアッププランのコピーアクションで、コピー先として組織内の別アカウントのボールト ARN を指定します。コピー先ボールトには、前述のアクセスポリシーでコピー操作の許可を設定しておきます。

💡 メリット

💼 ビジネス面

✓ガバナンスの強化: 組織全体で一貫したバックアップ基準を強制でき、コンプライアンス要件への対応が容易に
✓データ主権要件との両立: AWS European Sovereign Cloud 内で完結するマルチアカウントデータ保護により、欧州の規制対象業界の要件を満たしやすい
✓運用コストの削減: アカウントごとの個別設定・監視が不要になり、バックアップ運用の工数を削減

🔧 技術面

✓多層防御の実現: 別アカウントへの復旧ポイントコピーにより、ソースアカウント侵害時にもバックアップを保全
✓一元的な可視性: 全メンバーアカウントのバックアップ、コピー、復元ジョブを単一の場所から監視
✓最小権限の運用: 委任管理者により、管理アカウントへのアクセスを付与せずにバックアップ管理を委任

⚠️ デメリット・制約事項

制限事項

✗AWS Organizations の利用が前提であり、スタンドアロンアカウントでは利用不可
✗クロスアカウントバックアップのコピー先は組織内のアカウントに限定
✗対象は AWS European Sovereign Cloud (Germany) リージョンのみ。ESC は商用リージョンから独立したパーティションとして運用

考慮すべき点

⚡コピー先ボールトのアクセスポリシーと KMS キーの共有設定を適切に構成する必要がある
⚡クロスアカウントコピーにはコピー先でのストレージ料金が発生するため、保持期間設計とコスト見積もりが必要
⚡委任管理者アカウントの権限範囲を明確化し、運用ルールを整備することが望ましい

🎯 ユースケース

🏦 ユースケース 1: 規制対象業界における組織全体のバックアップガバナンス

シナリオ: 欧州の金融機関が、データ主権要件を満たしつつ、数十のメンバーアカウントに一貫したバックアップ基準を適用したい。

  • ESC 上の管理アカウントでクロスアカウント管理を有効化
  • 日次バックアップ + 35 日保持のポリシーを組織ルートにアタッチ
  • 全アカウントのジョブ状況を委任管理者アカウントから一元監視
✅ 効果: アカウントごとの設定漏れを防止し、監査対応に必要な証跡を一元的に確保できる。
🛡️ ユースケース 2: ランサムウェア対策としての別アカウント保管

シナリオ: ソースアカウントが侵害された場合でも復旧ポイントを保全できる体制を構築したい。

  • バックアップ専用のメンバーアカウントを用意し、コピー先ボールトを作成
  • ボールトアクセスポリシーで組織内からのコピーのみを許可
  • 各アカウントのバックアッププランにクロスアカウントコピーアクションを追加
✅ 効果: 偶発的または悪意のある削除からバックアップを保護し、復旧性を高められる。
👥 ユースケース 3: バックアップ運用チームへの権限委任

シナリオ: セキュリティポリシー上、運用チームに Organizations 管理アカウントへのアクセスを付与できない。

  • 運用チーム用のメンバーアカウントを委任管理者として登録
  • 運用チームは委任管理者アカウントからポリシー管理とジョブ監視を実施
  • 管理アカウントへのアクセスは組織管理者のみに限定
✅ 効果: 最小権限の原則を維持しながら、組織全体のバックアップ運用を効率的に委任できる。

💰 料金

✅ これらの機能の利用に追加料金はありません。
バックアップストレージ、クロスアカウントコピー、復元などに対して、標準の AWS Backup 料金が適用されます。

📝 まとめ

AWS European Sovereign Cloud (Germany) リージョンで AWS Backup のクロスアカウント管理、クロスアカウントバックアップ、委任管理者が利用可能になり、データ主権要件を満たしながらマルチアカウント環境のデータ保護ガバナンスを強化できるようになりました。同リージョンで複数アカウントを運用している組織は、バックアップポリシーの一元展開と別アカウントへの復旧ポイントコピーの導入を検討することを推奨します。
