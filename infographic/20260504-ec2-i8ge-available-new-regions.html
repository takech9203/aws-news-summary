🔄 概要: Before / After

AWS Graviton4 プロセッサーを搭載した I8ge インスタンスが、東京リージョンを含む 5 つの新リージョンで利用可能になりました。第 3 世代 AWS Nitro SSD によるローカル NVMe ストレージで、前世代を大幅に上回るストレージ性能を実現します。

❌ Before - アップデート前の課題

  • 東京リージョンで I8ge インスタンスが利用不可
  • 前世代 Im4gn ではストレージ I/O レイテンシーが高い
  • レイテンシーのばらつきが大きく不安定
  • ローカル NVMe ストレージ性能が限定的

✅ After - アップデート後の改善

  • 5 つの新リージョンで Graviton4 の高性能を活用可能
  • TB あたり最大 55% のストレージ性能向上
  • I/O レイテンシーのばらつきが最大 75% 低減
  • コンピューティング性能が最大 60% 向上

🛠️ 設定方法

前提条件

  • 1. AWS アカウントと適切な IAM 権限
  • 2. 対象リージョンへのアクセス (東京: ap-northeast-1 など)
  • 3. Graviton (Arm) アーキテクチャ対応の AMI
  • 4. 必要な VPC およびサブネット設定

ステップ 1: Arm 対応 AMI の確認

Bash 東京リージョンで Arm 対応 AMI を検索 
# 東京リージョンで Arm 対応の Amazon Linux 2023 AMI を検索
aws ec2 describe-images \
  --region ap-northeast-1 \
  --filters "Name=name,Values=al2023-ami-*-arm64*" \
            "Name=state,Values=available" \
  --owners amazon \
  --query "Images | sort_by(@, &CreationDate) | [-1].ImageId" \
  --output text

ステップ 2: I8ge インスタンスの起動

Bash 東京リージョンで I8ge インスタンスを起動 
# I8ge インスタンスを東京リージョンで起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type i8ge.xlarge \
  --region ap-northeast-1 \
  --subnet-id subnet-xxxxxxxxxxxxxxxxx \
  --security-group-ids sg-xxxxxxxxxxxxxxxxx \
  --key-name my-key-pair

ステップ 3: ローカル NVMe ストレージの確認とマウント

Bash NVMe ストレージのフォーマットとマウント 
# インスタンスに接続後、NVMe デバイスを確認
lsblk

# NVMe ストレージをフォーマットしてマウント
sudo mkfs -t xfs /dev/nvme1n1
sudo mkdir /data
sudo mount /dev/nvme1n1 /data

⚠️ ローカル NVMe ストレージはエフェメラルストレージです。インスタンスの停止や終了時にデータが失われるため、永続化が必要なデータは EBS や S3 にバックアップしてください。

⚠️ 制限事項・注意点

  • Arm アーキテクチャのため x86 専用ソフトウェアは動作不可
  • ローカル NVMe はエフェメラル、インスタンス停止時にデータ消失
  • 全リージョンでは利用不可、マルチリージョン構成は要確認
  • Im4gn からの移行時は Graviton4 互換性テストを推奨
  • データ永続化には EBS/S3 バックアップ戦略が必要
