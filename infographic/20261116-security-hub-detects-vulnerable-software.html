AWS Security Hub

🛡️ EC2 インスタンス上で実行中の脆弱なソフトウェアを検出

📅 リリース日: 2026 年 11 月 16 日 | 機能: 実行中の脆弱なソフトウェアの検出とエクスポージャー検出結果への反映

📌 概要

AWS Security Hub が、既知の脆弱性を持つソフトウェアが Amazon EC2 インスタンス上で実際に実行されていることを検出できるようになりました。エクスポージャー検出結果に新しいトレイト「The EC2 instance is running software with a known vulnerability」が追加され、同じ脆弱性でもソフトウェアが実行されていない場合と比べて、より高い重大度が割り当てられます。

Security Hub は、Amazon GuardDuty Runtime Monitoring と Amazon Inspector VM Scanner のデータを相関分析し、過去 30 時間以内のランタイムアクティビティから脆弱なソフトウェアの実行を判定します。数千台規模のインスタンスを管理するセキュリティチームは、実際のランタイムリスクに基づいてパッチ適用の優先順位を決定できます。

❌ アップデート前の課題
  • 検出された脆弱性のソフトウェアが実際に使用されているかどうかは、セキュリティチームが個別に調査する必要があった
  • 実行されていないソフトウェアの脆弱性と実行中の脆弱性が同じ重大度で報告され、優先順位付けが困難だった
  • 大量のインスタンス環境では、膨大な脆弱性検出結果の選別に多くの時間とリソースが必要だった
✅ アップデート後の改善
  • ソフトウェアの実行有無を Security Hub が自動判定し、エクスポージャー検出結果のトレイトとして明示
  • 実行中のソフトウェアの脆弱性に、より高い重大度が割り当てられ、最もリスクの高い脆弱性に集中できる
  • Vulnerability タブで実行中の脆弱性が CVSS スコア順で先頭に表示され、対応順序の判断が容易に

GuardDuty Runtime Monitoring と Amazon Inspector VM Scanner が報告するランタイムアクティビティを Security Hub が相関分析し、実行中の脆弱なソフトウェアを持つインスタンスのエクスポージャー検出結果に高い重大度を割り当てる流れを示しています。

⚙️ 主要機能

1️⃣ 実行中の脆弱なソフトウェアの検出

既知の脆弱性 (CVE) を持つソフトウェアが EC2 インスタンス上で実際に実行されていることを検出。過去 30 時間以内のランタイムアクティビティに基づいて判定し、GuardDuty Runtime Monitoring または Amazon Inspector VM Scanner が報告するデータを使用します。

2️⃣ 新しいエクスポージャートレイト

エクスポージャー検出結果に「The EC2 instance is running software with a known vulnerability」トレイトを追加。同じ脆弱性でもソフトウェアが実行されていない検出結果より高い重大度を割り当て、トレイトの Vulnerability タブでは実行中のソフトウェアの脆弱性を CVSS スコア順で先頭に表示します。

3️⃣ 複数シグナルの相関分析によるリスク優先順位付け

GuardDuty と Inspector のデータを他のシグナル (ネットワーク到達性、設定ミス、影響範囲など) と組み合わせてエクスポージャー検出結果を生成。ソフトウェアが実際に使用されているかどうかの手動調査が不要になり、対応と修復の優先順位付けを支援します。

🛠️ 設定方法

前提条件

✓AWS Security Hub (Essentials プラン) が有効化されていること
✓Amazon GuardDuty Runtime Monitoring または Amazon Inspector VM Scanner が有効化されていること
✓検出結果を取得するための適切な IAM 権限 (securityhub:GetFindingsV2 など) があること

ステップ 1: ランタイムデータソースの有効化を確認

Bash GuardDuty Runtime Monitoring 設定の確認 
# GuardDuty ディテクターの一覧を確認
aws guardduty list-detectors

# ディテクターの Runtime Monitoring 設定を確認
aws guardduty get-detector --detector-id <detector-id>

GuardDuty のディテクター ID を取得し、Runtime Monitoring 機能が有効になっているかを確認します。Amazon Inspector VM Scanner を使用する場合は、Inspector コンソールまたは API でスキャン設定を確認します。

ステップ 2: エクスポージャー検出結果の取得

Bash GetFindingsV2 API でエクスポージャー検出結果を取得 
# Security Hub のエクスポージャー検出結果を取得
aws securityhub get-findings-v2 \
  --filters '{"CompositeFilters": [{"StringFilters": [{"FieldName": "findings.metadata.product.name", "Filter": {"Value": "Exposure", "Comparison": "EQUALS"}}]}]}' \
  --max-results 50

フィルターを使用して、エクスポージャータイプの検出結果に絞り込んでいます。

ステップ 3: トレイトの確認と修復

Security Hub コンソールのエクスポージャー検出結果の詳細画面で、「The EC2 instance is running software with a known vulnerability」トレイトの有無を確認します。トレイトの Vulnerability タブには、実行中のソフトウェアの脆弱性が CVSS スコア順で先頭に表示されるため、上位の脆弱性から順にパッチ適用を実施します。パッチ適用後は、対象のサービスやプロセスを再起動して修正版が実行されるようにします。

✓重大度の自動調整: 実行中のソフトウェアの脆弱性に高い重大度が自動的に割り当てられ、既存の検出結果管理ワークフローにそのまま反映される
✓CVSS スコア順の表示: Vulnerability タブで実行中のソフトウェアの脆弱性が CVSS スコア順に先頭表示され、対応順序の判断が容易になる

⚠️ デメリット・制約事項

制限事項

✗対象リソースは Amazon EC2 インスタンスのエクスポージャー検出結果に限定される
✗ランタイムアクティビティの判定は過去 30 時間のデータに基づくため、それより前にのみ実行されたソフトウェアは「実行中」として扱われない可能性がある
✗検出には GuardDuty Runtime Monitoring または Amazon Inspector VM Scanner のいずれかが有効である必要がある

考慮すべき点

⚠️GuardDuty Runtime Monitoring や Inspector VM Scanner 自体の利用には、それぞれのサービスの料金が発生する
⚠️実行されていないソフトウェアの脆弱性も攻撃対象になり得るため、重大度が低い検出結果を放置してよいわけではなく、計画的なパッチ適用は引き続き必要

🎯 ユースケース

📊 ユースケース 1: 大規模環境でのパッチ適用の優先順位付け

シナリオ: 数千台の EC2 インスタンスを運用する企業で、脆弱性スキャンにより大量の CVE が検出されており、どのインスタンスから対応すべきか判断に時間がかかっている。

  1. Security Hub でエクスポージャー検出結果を重大度順に表示
  2. 「The EC2 instance is running software with a known vulnerability」トレイトを持つ検出結果を優先対応リストとして抽出
  3. Systems Manager Patch Manager で対象インスタンスにパッチを一括適用
  4. パッチ適用後にサービスを再起動し、検出結果の重大度の変化を確認
💡 効果: 実行中の脆弱なソフトウェアを持つインスタンスから優先的に対応することで、実際の攻撃リスクを効率的に低減できる。
🏭 ユースケース 2: 即時パッチ適用が困難な本番環境での暫定リスク低減

シナリオ: 本番環境で実行中のアプリケーションに脆弱性が検出されたが、メンテナンスウィンドウまでパッチを適用できない。

  1. トレイトの Vulnerability タブで対象ソフトウェアと CVE を特定
  2. インスタンスで当該サービスが必須かどうかを確認し、不要であれば停止
  3. 必要なサービスの場合は、セキュリティグループのインバウンドルールを信頼できる IP 範囲に限定してネットワークアクセスを制限
  4. メンテナンスウィンドウでパッチを適用し、サービスを再起動
💡 効果: パッチ適用までの間、攻撃経路を制限することで暫定的にリスクを低減できる。
🔄 ユースケース 3: Auto Scaling グループでの恒久的な脆弱性対応

シナリオ: Auto Scaling グループで起動するインスタンスに、実行中の脆弱なソフトウェアが繰り返し検出される。

  1. エクスポージャー検出結果から対象のソフトウェアとバージョンを特定
  2. パッチ適用済みの新しいゴールデン AMI を作成
  3. Auto Scaling グループの起動テンプレートを新 AMI に更新
  4. インスタンスリフレッシュを実行して既存インスタンスを置き換え
💡 効果: 新規に起動されるインスタンスが脆弱性の影響を受けなくなり、検出結果の再発を防止できる。

💰 料金・利用可能リージョン

💵 料金

本機能は AWS Security Hub Essentials プランに追加料金なしで含まれます。ただし、検出のデータソースとなる Amazon GuardDuty Runtime Monitoring および Amazon Inspector VM Scanner の利用には、それぞれのサービスの料金が別途発生します。詳細は各サービスの料金ページを参照してください。

🌍 利用可能リージョン

Security Hub が利用可能なすべての AWS リージョンで利用できます。最新のリージョン一覧は AWS Regional Services List を参照してください。
