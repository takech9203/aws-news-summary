Amazon RDS for Oracle

🛡️ 2026 年 4 月 Release Update / Supplemental Patch Bundle サポート

Oracle データベースの最新セキュリティパッチと推奨パッチを RDS で簡単に適用
2026-05-29

📋 概要

Amazon RDS for Oracle が Oracle 2026 年 4 月 Release Update (RU) および Supplemental Patch Bundle (SPB) をサポート。RU にはセキュリティ更新、SPB には Oracle Spatial / Data Pump / GoldenGate 向けの追加パッチが含まれる。

SPB は以前「Oracle Spatial Patch Bundle」と呼ばれていたが、2026 年 4 月リリースから名称変更。

❌ Before

  • セキュリティパッチ適用に手動作業が必要
  • 最新の脆弱性に対応できない環境
  • Spatial / Data Pump / GoldenGate の推奨パッチ未適用によるパフォーマンス問題の可能性

✅ After

  • RDS コンソール / SDK / CLI から簡単にパッチ適用
  • SPB で Spatial 等の追加パッチを一括適用
  • Automatic Minor Version Upgrade で自動パッチ適用

⚡ 主要機能

🛡️ Release Update (RU) サポート

Oracle データベース製品向けのセキュリティ更新。Oracle 19c および 21c の両方で利用可能。AWS は最新の RU へのアップグレードを推奨。

📦 Supplemental Patch Bundle (SPB) サポート

Oracle Spatial、Oracle Data Pump、Oracle GoldenGate 向けの追加パッチ。Oracle 19c でのみ利用可能。エンジンバージョン: 19.0.0.0.ru-2026-04.spb-1.r1

🔄 段階的ロールアウトポリシー

AWS Organizations のアップグレードロールアウトポリシーを使用して、非本番環境で検証した後に本番環境へ適用するワークフローを実現。

💻 設定方法

前提条件: RDS for Oracle インスタンスが稼働中 / Oracle 19c または 21c を使用 / RDS インスタンスへの変更権限を保持

Bash Step 1: Release Update の適用 
aws rds modify-db-instance \
  --db-instance-identifier my-oracle-instance \
  --engine-version 19.0.0.0.ru-2026-04.r1 \
  --apply-immediately
Bash Step 2: Supplemental Patch Bundle の適用 
# SPB は RU を含むため、個別に RU を適用する必要はない
aws rds modify-db-instance \
  --db-instance-identifier my-oracle-instance \
  --engine-version 19.0.0.0.ru-2026-04.spb-1.r1 \
  --apply-immediately
Bash Step 3: Automatic Minor Version Upgrade の有効化 
aws rds modify-db-instance \
  --db-instance-identifier my-oracle-instance \
  --auto-minor-version-upgrade \
  --apply-immediately

💡 コンソールでの SPB 適用: RDS コンソールでインスタンス作成時に「Supplemental Patch Bundle Engine Versions」チェックボックスを選択し、SPB バージョンを指定する。

✅ メリット

📈 ビジネス面

  • セキュリティコンプライアンスの維持: 最新パッチで規制要件への準拠を維持
  • 運用コストの削減: 手動パッチ作業不要、自動アップグレードで運用負荷軽減
  • ダウンタイムリスクの低減: 段階的ロールアウトで本番環境への影響を最小化

🔧 技術面

  • 脆弱性対策の最新化: Oracle CPU 2026 年 4 月のセキュリティ修正を含む
  • Oracle 関連機能の安定性向上: SPB で Spatial / Data Pump / GoldenGate の推奨パッチ一括適用
  • 柔軟なデプロイメント: 即時 / メンテナンスウィンドウ / 自動から選択可能

⚠️ 制約事項・注意点

制限事項

  • SPB は Oracle 19c のみで利用可能 (21c は非対応)
  • パッチ適用時にインスタンスの再起動が発生し、短時間のダウンタイムが必要
  • SPB の適用には RU が前提条件として必要

💡 考慮すべき点

> パッチ適用前にスナップショットを取得し、ロールバック計画を策定することを推奨
> GoldenGate / Data Pump を使用していない場合でも SPB を適用するとすべてのパッチが含まれる
> 段階的ロールアウトを使用する場合、AWS Organizations の設定が必要

🎯 ユースケース

🏦 セキュリティコンプライアンス対応

シナリオ: 金融機関で Oracle 19c を使用。四半期ごとのセキュリティパッチ適用が規制要件。

効果: 非本番環境で検証後、メンテナンスウィンドウで本番環境に適用。規制要件を満たしつつリスクを最小化。

🗺️ Oracle Spatial を使用した地理空間データ処理

シナリオ: 物流企業で Oracle Spatial を使用したルート最適化システムを運用。Spatial の推奨パッチを適用したい。

効果: SPB 適用により Oracle Spatial の安定性とパフォーマンスが向上。地理空間クエリの信頼性が改善。

🔄 GoldenGate を使用したデータレプリケーション

シナリオ: オンプレミスの Oracle DB から RDS for Oracle へのリアルタイムレプリケーションに GoldenGate を使用。

効果: GoldenGate のレプリケーション安定性が向上し、データ同期の信頼性が改善。
