🛡️ AWS Backup 論理的エアギャップ保管庫
7 つの新規リージョンで利用可能に

AWS Backup Logically Air-Gapped Vault
リリース日
2026-07-16

📌 概要

AWS Backup の論理的エアギャップ保管庫が、新たに 7 つの AWS リージョンで利用可能になりました。これにより、より多くの地域のお客様がデータ保護とランサムウェア対策のためのイミュータブル (変更不可) なバックアップを利用できるようになりました。

論理的エアギャップ保管庫は、デフォルトでロックされたイミュータブルかつ隔離されたバックアップを保存するための保管庫です。AWS 所有のキーまたはカスタマーマネージドキーで暗号化され、アカウント間・リージョン間コピー、AWS RAM による保管庫共有、複数者承認 (Multi-party approval) に対応しています。

🔄 アップデート前後の比較

❌ Before (課題)

  • 対象リージョンでデータレジデンシー要件を満たしつつイミュータブルバックアップを構成しづらかった
  • リージョン外に保管庫を作成すると復旧レイテンシーやコンプライアンス上の懸念があった
➡️
✅ After (改善)
  • 対象 7 リージョンで論理的エアギャップ保管庫を直接構成・保存できるようになった
  • 各リージョン内でデータレジデンシー要件を満たしつつランサムウェア対策が可能に
  • アカウント間・リージョン間コピー、RAM 共有、複数者承認も対象リージョンで活用可能

本番アカウントのリソースを論理的エアギャップ保管庫へ直接バックアップし、RAM 共有と複数者承認によって隔離された安全なリカバリ経路を確保する構成を示しています。

⚙️ 主要機能

🔒 イミュータブルで隔離されたバックアップ
  • デフォルトでロックされ、変更や削除ができないイミュータブルなバックアップを保存
  • 本番環境から論理的に隔離し、アカウント侵害時もクリーンなリカバリソースを維持
  • ランサムウェア・誤操作・悪意のある削除からデータを保護
🔑 柔軟な暗号化オプション
  • AWS 所有のキー、またはカスタマーマネージドキー (CMK) による暗号化に対応
  • 組織の鍵管理ポリシーやコンプライアンス要件に合わせて選択可能
🌐 アカウント間・リージョン間コピー
  • バックアップをアカウント間およびリージョン間でコピー可能
  • ディザスタリカバリやマルチリージョン戦略に対応
🤝 RAM による保管庫共有と復旧
  • AWS Resource Access Manager (RAM) を利用して復旧用に保管庫を他アカウントと共有
  • 復旧専用アカウントへの安全なアクセス経路を提供
👥 複数者承認 (Multi-party approval)
  • アカウント侵害時における保管庫へのアクセスを保護
  • 重要操作に複数者承認を要求し、単一の侵害された認証情報による不正操作を防止

🔧 設定方法

前提条件

  • 対象リージョンで AWS Backup を利用できること
  • バックアップ対象リソースが AWS Backup でサポートされていること
  • 保管庫共有を利用する場合は AWS RAM の設定権限を持つこと

手順

1
論理的エアギャップ保管庫の作成

AWS Backup コンソール、AWS CLI、または AWS SDK を使用して、対象リージョンで保管庫を作成します。以下は AWS CLI を使用した作成例です。

Bash AWS CLI での保管庫作成例 (台北リージョン) 
aws backup create-logically-air-gapped-backup-vault \
    --backup-vault-name my-lag-vault \
    --min-retention-days 7 \
    --max-retention-days 365 \
    --region ap-east-2

指定したリージョンに論理的エアギャップ保管庫を作成し、最小・最大保持期間を指定しています。保持期間の指定は必須です。

2
バックアッププランへの保管庫の指定

作成した保管庫を宛先とするバックアッププランを構成し、対象リソースを割り当てます。バックアップは作成した論理的エアギャップ保管庫へ直接保存されます。

3
RAM による保管庫の共有 (任意)

復旧用に他のアカウントと保管庫を共有する場合は、AWS RAM でリソース共有を作成します。これにより、侵害されていない別アカウントから安全にリストアを実行できます。

⚖️ メリットと制約事項

✅ メリット

💼 ビジネス面

  • コンプライアンス対応: 対象リージョン内でデータレジデンシー要件を満たしつつイミュータブルバックアップを構成
  • 事業継続性の向上: ランサムウェア攻撃後もクリーンなリカバリソースから迅速に復旧
  • ガバナンス強化: 複数者承認で重要操作の統制を強化

🛠️ 技術面

  • 論理的隔離: 本番アカウントから隔離し攻撃対象領域を縮小
  • イミュータビリティ: デフォルトロックで意図しない削除や改ざんを防止
  • マルチリージョン / マルチアカウント対応: コピーと RAM 共有で柔軟な DR 構成が可能

⚠️ 制約事項・考慮点

🚧 制限事項

  • 保持期間の設定が必須
  • 対応リソースタイプは AWS Backup のサポート範囲に依存
  • 保管庫共有は復旧目的の RAM 共有に限定

💡 考慮すべき点

  • 保持期間はストレージコストに直結するため保持ポリシーを慎重に設計
  • 複数者承認の運用には承認者体制・運用フローの事前整備が必要
  • 最新の対応リージョン・リソースは公式ドキュメントで確認を推奨

🎯 ユースケース

1. ランサムウェア対策
シナリオ本番アカウントが侵害されても、隔離されたクリーンなバックアップから復旧したい。
効果イミュータブルバックアップにより攻撃者がバックアップを削除・改ざんできず、確実に復旧可能。
2. データレジデンシー要件への対応
シナリオイスラエルやメキシコなど特定リージョン内にデータを保持する規制要件がある。
効果対象リージョン内で保管庫を構成でき、データレジデンシー要件を満たしながらイミュータブルバックアップを実現。
3. マルチアカウントのディザスタリカバリ
シナリオ復旧専用アカウントを分離し、有事の際に安全にリストアを実行したい。
効果RAM 共有で復旧アカウントへ保管庫を共有し、複数者承認と組み合わせて統制の効いたリカバリ体制を構築。

📝 まとめ

今回のアップデートにより、論理的エアギャップ保管庫が 7 つの新規リージョンで利用可能になり、より多くの地域でランサムウェア対策とデータレジデンシー要件への対応が可能になりました。対象リージョンでデータ保護を検討している組織は、イミュータブルバックアップと複数者承認を組み合わせた堅牢なリカバリ体制の構築を検討することを推奨します。
