🧠 サーバーレスモデルカスタマイズジョブで
カスタムシーケンス長をサポート

📅 リリース日: 2026 年 10 月 21 日 | 🏷️ 機能: シーケンス長のハイパーパラメータ設定

📌 概要

Amazon SageMaker AI のサーバーレスモデルカスタマイズジョブで、シーケンス長をハイパーパラメータとして設定できるようになりました。gpt-oss、Gemma、Llama、Nemotron、Qwen などのオープンウェイトモデルを、インフラストラクチャの管理なしでファインチューニングできます。

SFT (教師ありファインチューニング) / DPO (直接選好最適化) では dataset_max_len、RFT (強化学習ファインチューニング) では max_prompt_length と max_response_length を、モデルと手法ごとの公開最大値まで自由に設定できます。

SageMaker Studio のモデルページまたは Python SDK からサーバーレスカスタマイズジョブを起動し、ファインチューニング手法に応じたシーケンス長ハイパーパラメータを指定してオープンウェイトモデルを学習する流れを示しています。

⚙️ 主要機能

1️⃣ シーケンス長のカスタム設定
→従来は各レシピで固定だったシーケンス長を、ハイパーパラメータとして設定可能
→モデルと手法ごとに公開されている最大値まで任意の値を指定できる
→多くのモデルで最大 16K トークン、一部のモデル / 手法では 32K トークンまで対応
2️⃣ 手法ごとのパラメータ体系
→SFT / DPO ジョブ: dataset_max_len でプロンプトと補完を合わせた全体の最大長を設定
→RFT ジョブ (RLVR / RLAIF): max_prompt_length と max_response_length を個別に設定し、合計がモデルの最大値以内に収まるようにする
→入力と出力の予算を分けて管理できるため、長い生成を必要とするタスクに柔軟に対応
3️⃣ 幅広いオープンウェイトモデルに対応
→gpt-oss、Gemma、Llama、Nemotron、Qwen、Ministral、DeepSeek R1 Distill などのモデルファミリーをサポート
→LoRA とフルファインチューニング FFT の両方の学習タイプに対応 (モデルにより異なる)
→SageMaker Studio のモデルページ、SageMaker Python SDK、エージェントスキル経由で利用可能

🔬 技術仕様

🎛️ シーケンス長ハイパーパラメータ

手法パラメータ説明
SFT / DPOdataset_max_lenプロンプトと補完を合わせた全体の最大トークン長
RFT (RLVR / RLAIF)max_prompt_length入力プロンプトに割り当てる最大トークン長
RFT (RLVR / RLAIF)max_response_lengthモデルの生成に割り当てる最大トークン長
⚠️ RFT では max_prompt_length と max_response_length の合計が、モデルごとの最大シーケンス長以内である必要があります。

🛠️ 設定方法

✅ 前提条件

  • AWS アカウントと Amazon SageMaker AI (SageMaker Studio) のセットアップが完了していること
  • 学習データセットが Amazon S3 に用意されていること
  • 利用可能リージョン (バージニア北部、オレゴン、東京、アイルランド) のいずれかを使用していること

📋 手順

1
ジョブの起動方法を選択する

SageMaker Studio のモデルページから対象のオープンウェイトモデルを選択してカスタマイズジョブを作成するか、SageMaker Python SDK を使用してジョブを定義します。

2
シーケンス長ハイパーパラメータを設定する

SFT / DPO ジョブの場合は、学習データの長さに合わせて dataset_max_len を設定します。

Python SFT / DPO ジョブのハイパーパラメータ設定例 
hyperparameters = {
    "dataset_max_len": 16384,  # プロンプト + 補完の最大トークン長
    # その他のハイパーパラメータ
}

RFT ジョブの場合は、入力と生成の予算を個別に設定します。長い推論出力が必要なタスクでは max_response_length を大きめに確保します。

Python RFT ジョブのハイパーパラメータ設定例 
hyperparameters = {
    "max_prompt_length": 8192,    # 入力プロンプトの最大トークン長
    "max_response_length": 8192,  # 生成の最大トークン長
    # その他のハイパーパラメータ
}
3
ジョブを実行して結果を確認する

サーバーレスカスタマイズジョブを送信します。インフラストラクチャの管理は不要で、ジョブの進捗とメトリクスは SageMaker Studio で確認できます。学習完了後、カスタマイズ済みモデルを評価してデプロイします。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓学習品質の向上: 長文ドキュメントを切り捨てずに学習でき、長いコンテキストを扱うユースケースでモデル品質が向上
✓ユースケース適合性の拡大: 短い Q&A から複数ページのドキュメントまで、業務データの特性に合わせたファインチューニングが可能
✓インフラ管理コストの削減: サーバーレスのため、GPU クラスターの構築や管理なしで長いシーケンス長の学習を実行可能

🔧 技術面のメリット

✓データに合わせた柔軟な設定: 学習データの実際の長さ分布に合わせてシーケンス長を最適化
✓入力と出力の予算を分離: RFT では入力と生成を独立して設定でき、長い生成が必要なタスクに対応
✓幅広いモデルと手法に対応: 主要なオープンウェイトモデルで SFT / DPO / RFT の各手法に利用可能

🚧 制限事項

✗設定可能な最大値はモデルと手法 (SFT / DPO / RLVR / RLAIF、LoRA / FFT) の組み合わせごとに異なる
✗一部のモデルと手法の組み合わせではシーケンス長が 4K に固定 (例: Llama 3.x や GPT OSS の SFT / DPO)
✗利用可能リージョンは現時点で 4 リージョンに限定

🤔 考慮すべき点

→シーケンス長を長くすると、サンプルあたりのメモリと計算リソースの要件が増加し、学習時間とコストに影響する可能性
→実際の学習時間とコストは、バッチ処理、パッキング、ハードウェア使用率、学習設定などの要因に依存
→RFT では期待される出力に十分な max_response_length を確保しつつ、max_prompt_length とのバランスを取る必要がある

💡 ユースケース

📄 ユースケース 1: 長文ドキュメントを扱う社内ナレッジモデルの構築

シナリオ: 複数ページにわたる技術文書や契約書の要約・質問応答に特化したモデルをファインチューニングしたい。従来の固定シーケンス長では長文データが切り捨てられ、文書全体の文脈を学習できなかった。

Python実装例
hyperparameters = {
    "dataset_max_len": 16384,  # 長文ドキュメントに対応
}

✅ 効果: 文書全体を切り捨てなしで学習でき、長文コンテキストを踏まえた高品質な応答が可能なモデルを構築できる。

💻 ユースケース 2: コーディングタスク向けモデルの RFT

シナリオ: コード生成タスクでは、短い指示に対して長いコードを出力する必要がある。従来は生成長を調整できず、長い出力を必要とするタスクで品質が制限されていた。

Python実装例
hyperparameters = {
    "max_prompt_length": 4096,     # 指示とコンテキスト用
    "max_response_length": 12288,  # 長いコード生成用
}

✅ 効果: 生成側に多くのトークン予算を割り当てることで、長いコードや数学的推論の学習品質が向上する。

💬 ユースケース 3: 短い Q&A データでの効率的なファインチューニング

シナリオ: カスタマーサポート向けの短い Q&A ペアでモデルをカスタマイズしたい。データの実際の長さに合わせてシーケンス長を適切に設定し、効率的に学習したい。

Python実装例
hyperparameters = {
    "dataset_max_len": 2048,  # 短い Q&A ペアに最適化
}

✅ 効果: 学習データの長さ分布に合わせた設定により、メモリと計算リソースを有効活用し、効率的にファインチューニングできる。

📝 まとめ

SageMaker AI のサーバーレスモデルカスタマイズジョブでシーケンス長が設定可能になり、短い Q&A から長文ドキュメントまで学習データの特性に合わせたファインチューニングが可能になりました。東京リージョンでも利用できるため、オープンウェイトモデルのカスタマイズを検討している場合は、まず公式ドキュメントでモデルと手法ごとの最大シーケンス長を確認し、学習データの長さ分布に合わせた設定から始めることを推奨します。
