🔒 AWS Batch on EKS が Linux capabilities・seccomp・Pod レベルセキュリティ設定をサポート

Kubernetes セキュリティコンテキスト設定の拡張により、Pod Security Standards の restricted プロファイル環境でもバッチジョブを実行可能に

📝 概要

AWS Batch が、Amazon EKS 上で実行するジョブ定義において、追加の Kubernetes セキュリティコンテキスト設定をサポートしました。コンテナレベルで Linux capabilities と seccomp プロファイルを指定できるようになったほか、fsGroup などの Pod レベルのセキュリティ設定も定義できるようになりました。

これにより、Pod Security Standards の restricted プロファイルを適用している EKS クラスターでも、AWS Batch ジョブを必要最小限の権限とシステムコールのみで実行できます。金融、医療、規制産業など、セキュリティ基準の厳しい環境でのバッチワークロード運用に有効なアップデートです。

❌ アップデート前の課題

✗コンテナの securityContext で capabilities の add / drop や seccomp プロファイルを指定できなかった
✗restricted プロファイルが要求する「全 capabilities の drop」「seccomp の明示設定」を満たせず、restricted 適用クラスターでのジョブ実行が困難だった
✗fsGroup などの Pod レベル設定を定義できず、共有ボリュームのファイル所有権制御に制約があった

✅ アップデート後の改善

✓コンテナレベルで capabilities の add / drop と seccomp プロファイル RuntimeDefault / Localhost / Unconfined を指定可能に
✓podProperties の securityContext で fsGroup、runAsUser、runAsGroup、runAsNonRoot、seccompProfile を定義可能に
✓restricted プロファイル適用クラスターでも最小権限の原則に沿ってジョブを実行可能に
✓コンソール、AWS CLI、AWS SDK、CloudFormation のいずれからも設定可能

💡 設定は RegisterJobDefinition API で行い、コンテナレベルの設定が Pod レベルのデフォルトを上書きします。

ジョブ定義に Pod レベルとコンテナレベルのセキュリティコンテキストを設定し、restricted プロファイルを適用した EKS クラスターでも検証を通過して最小権限でジョブ Pod が実行される流れを示しています。コンテナレベルの設定は Pod レベルのデフォルトを上書きします。

⚡ 主要機能

🧩 1. Linux capabilities の制御 (コンテナレベル)

  • コンテナの securityContext.capabilities で add と drop を指定可能
  • restricted プロファイルで要求される「ALL の drop」と「NET_BIND_SERVICE のみの add」といった構成を実現
  • 不要なカーネル権限を排除し、コンテナエスケープなどのリスクを低減

🛡️ 2. seccomp プロファイルの指定 (コンテナレベル / Pod レベル)

  • seccompProfile.type に RuntimeDefault、Localhost、Unconfined を指定可能
  • Localhost タイプの場合は localhostProfile でノード上のプロファイルパスを指定
  • ジョブが発行できるシステムコールを必要最小限に制限

📦 3. Pod レベルのセキュリティ設定

  • podProperties.securityContext で fsGroup、runAsUser、runAsGroup、runAsNonRoot、seccompProfile を定義可能
  • fsGroup によりボリュームのファイル所有権とアクセス権を Pod 単位で制御
  • Pod レベルの設定はコンテナのデフォルトとして機能し、コンテナレベルの設定が優先される

ジョブ定義の設定例

JSON restricted プロファイル準拠のジョブ定義 
{
  "jobDefinitionName": "restricted-eks-job",
  "type": "container",
  "eksProperties": {
    "podProperties": {
      "securityContext": {
        "fsGroup": 2000,
        "runAsNonRoot": true,
        "seccompProfile": {
          "type": "RuntimeDefault"
        }
      },
      "containers": [
        {
          "image": "public.ecr.aws/amazonlinux/amazonlinux:2023",
          "command": ["sleep", "60"],
          "securityContext": {
            "runAsUser": 1000,
            "runAsGroup": 3000,
            "runAsNonRoot": true,
            "capabilities": {
              "drop": ["ALL"]
            },
            "seccompProfile": {
              "type": "RuntimeDefault"
            }
          }
        }
      ]
    }
  }
}

🛠️ 設定方法

前提条件

  • ✓ AWS Batch on Amazon EKS のセットアップが完了していること (EKS クラスターと AWS Batch コンピューティング環境の接続)
  • ✓ ジョブ定義を登録するための IAM 権限 (batch:RegisterJobDefinition など) があること
  • ✓ Localhost タイプの seccomp プロファイルを使用する場合は、ノード上に該当プロファイルが配置されていること
1

セキュリティコンテキストを含むジョブ定義の登録

Bashジョブ定義の登録
aws batch register-job-definition \
  --job-definition-name restricted-eks-job \
  --type container \
  --eks-properties file://eks-properties.json

eks-properties.json に Pod レベルとコンテナレベルの securityContext を含む EKS プロパティを定義し、ジョブ定義として登録します。

2

ジョブの送信

Bashジョブの送信
aws batch submit-job \
  --job-name secure-batch-job \
  --job-queue my-eks-job-queue \
  --job-definition restricted-eks-job

登録したジョブ定義を指定して EKS 向けジョブキューにジョブを送信します。AWS Batch がセキュリティコンテキストを適用した Pod を EKS クラスター上に作成します。

3

設定内容の確認

Bashジョブ定義の確認
aws batch describe-job-definitions \
  --job-definition-name restricted-eks-job \
  --status ACTIVE

登録済みジョブ定義のセキュリティコンテキスト設定を確認します。DescribeJobs でも実行中ジョブに適用された設定を確認できます。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓コンプライアンス対応の強化: restricted プロファイルなど組織のセキュリティ基準を維持したままバッチ運用が可能
✓運用コストの削減: 例外設定やカスタムコントローラーが不要になり、ガバナンスの一貫性を確保
✓リスク低減: 最小権限の原則により侵害時の影響範囲を限定

⚙️ 技術面のメリット

✓きめ細かな権限制御: capabilities の add / drop でジョブごとに必要なカーネル権限のみ付与
✓システムコールの制限: seccomp により攻撃対象領域を縮小
✓柔軟な設定階層: Pod レベルでデフォルトを定義し、必要なコンテナのみ個別に上書き

⚠️ 制限事項

!対象は AWS Batch on Amazon EKS のジョブ定義のみ。ECS / Fargate ベースの AWS Batch ジョブには適用されない
!capabilities はコンテナレベルのみ、fsGroup は Pod レベルのみで設定可能
!Localhost タイプの seccomp プロファイルは実行先ノードにプロファイルファイルが必要

🤔 考慮すべき点

!capabilities を過度に制限すると実行時エラーになる可能性があるため、必要な権限を事前に検証する
!既存ジョブ定義への設定追加は新しいリビジョンの登録と参照先の更新が必要
!コンテナレベルの設定が Pod レベルのデフォルトを上書きする優先順位を理解して設計する

🎯 ユースケース

1️⃣ restricted プロファイル適用クラスターでのバッチ実行

シナリオ: 全社セキュリティポリシーとして Pod Security Standards の restricted プロファイルを namespace に適用している EKS クラスターで、夜間のデータ処理バッチを AWS Batch で実行したい。

JSON実装例
{
  "securityContext": {
    "runAsNonRoot": true,
    "allowPrivilegeEscalation": false,
    "capabilities": { "drop": ["ALL"] },
    "seccompProfile": { "type": "RuntimeDefault" }
  }
}
✅ 効果: restricted プロファイルの検証を通過する Pod を AWS Batch が作成できるため、ポリシーの例外設定なしでバッチワークロードを運用できる。

2️⃣ 低番号ポートを使用するジョブへの最小権限付与

シナリオ: 1024 番未満のポートへのバインドが必要なネットワーク処理ジョブを、root 実行や特権コンテナを使わずに実行したい。

JSON実装例
{
  "securityContext": {
    "runAsNonRoot": true,
    "capabilities": {
      "drop": ["ALL"],
      "add": ["NET_BIND_SERVICE"]
    }
  }
}
✅ 効果: すべての capabilities を削除した上で NET_BIND_SERVICE のみを追加することで、必要最小限の権限でジョブを実行でき、セキュリティリスクを最小化できる。

3️⃣ 共有ボリュームを使用するマルチコンテナジョブ

シナリオ: init コンテナでデータを準備し、メインコンテナで処理するジョブにおいて、非 root ユーザー間で共有ボリュームのファイルにアクセスしたい。

JSON実装例
{
  "podProperties": {
    "securityContext": {
      "fsGroup": 2000,
      "runAsNonRoot": true
    }
  }
}
✅ 効果: Pod レベルの fsGroup によりボリュームのグループ所有権が統一され、複数コンテナ間で権限エラーなくファイルを共有できる。

💰 料金と利用可能リージョン

💵 料金 AWS Batch 自体に追加料金はありません。本機能にも追加料金は発生せず、バッチジョブの実行に使用する EKS クラスター (コントロールプレーン) と EC2 インスタンスなどのコンピューティングリソースに対してのみ料金が発生します。
🌍 利用可能リージョン AWS Batch が利用可能なすべての AWS リージョンでサポートされます。詳細は AWS リージョン別サービス一覧 を参照してください。

🔗 関連サービス・機能

☸️ Amazon EKS AWS Batch ジョブの実行基盤となるマネージド Kubernetes サービス。Pod Security Standards の適用主体。
🛡️ Kubernetes Pod Security Standards privileged / baseline / restricted の 3 段階で Pod のセキュリティ要件を定義する Kubernetes 標準。
📜 AWS CloudFormation AWS::Batch::JobDefinition リソースで今回のセキュリティコンテキスト設定を IaC として管理可能。
🚢 AWS Batch on Amazon ECS / Fargate EKS 以外の AWS Batch 実行環境。本アップデートの対象外。

💡 まとめ

AWS Batch on Amazon EKS が Linux capabilities、seccomp プロファイル、Pod レベルのセキュリティ設定をサポートしたことで、Pod Security Standards の restricted プロファイルを適用した厳格なセキュリティ環境でもバッチワークロードを実行できるようになりました。

🚀 推奨アクション: EKS 上で AWS Batch を利用しているユーザーは、既存ジョブ定義に capabilities.drop: ["ALL"] と seccompProfile: RuntimeDefault を追加し、最小権限の原則に沿った構成への移行を検討することを推奨します。
