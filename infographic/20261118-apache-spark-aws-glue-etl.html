AWS Glue

⚡ Apache Spark Optimization Agent for AWS Glue ETL

📅 リリース日: 2026 年 11 月 18 日 | AI エージェントが Spark ジョブのコストとパフォーマンスを数分で分析

📋 概要

AWS Glue ETL に Apache Spark Optimization Agent が導入されました。完了した Spark ジョブ実行の設定、ログ、Spark テレメトリを分析し、数分以内にコストとパフォーマンスの最適化レコメンデーションを提供します。コスト最適化またはパフォーマンス最適化の目標を選択するだけで、テレメトリの証拠と理由付きの具体的な設定変更提案を受け取れます。

AWS Glue コンソールの完了したジョブ実行から直接利用できるほか、Amazon SageMaker Unified Studio MCP Server を介して独自のツールからも呼び出せます。追加料金なしで利用可能です。

ユーザーがコンソールまたは MCP クライアントから分析を依頼すると、エージェントが完了したジョブのテレメトリを読み取り専用で収集し、決定論的なレコメンデーションエンジンが証拠付きの最適化提案を返します。

🚀 主要機能

🎯 目標ベースの最適化レコメンデーション

コスト最適化またはパフォーマンス最適化の目標を選択して分析を実行。両者が競合する場合は、選択した指標を最適化しつつ、もう一方の劣化を定義された制限内に抑える。大規模・高コストなジョブにはより厳しいしきい値が適用される。

🔬 決定論的レコメンデーションエンジンによる根本原因分析

設定、ログ、Spark テレメトリを総合分析し、並列度の不足、結合キーのスキュー、スピルを引き起こすメモリ圧迫、アイドル状態のエグゼキューター、過剰プロビジョニングを検出。ルールベースの調査、意図ベースの決定論的モデル、AWS 上の膨大な Spark ジョブのチューニングパターンから構築されたナレッジベースを組み合わせる。

📊 ベースライン比較分析

以前は正常だったジョブが劣化した場合、現在の実行と正常だった実行を指定して比較。設定、メトリクス、ステージの挙動の差分から変化の原因を特定できる。

✅ ベストプラクティスチェック

新しい AWS Glue バージョンへの移行や AWS Graviton プロセッサの採用などのプラットフォームレベルの改善も提案。AWS Glue のパフォーマンスチューニングガイダンスに照らしたチェックを実施する。

🏷️ カテゴリ付きレコメンデーション

infrastructure Spark configuration code data layout

各レコメンデーションは変更対象の領域でラベル付けされ、変更対象のプロパティ、現在値と提案値、根拠となるテレメトリの証拠が表示される。

🤖 MCP 経由の呼び出し

Amazon SageMaker Unified Studio のリモート MCP Server が提供する analyze_spark_workload ツールを使用し、Kiro、Claude Code などの MCP 対応クライアントから自然言語で分析を依頼可能。

1
コンソールから分析を開始する
AWS Glue コンソールで [ETL jobs] から対象のジョブを選択 → [Runs] タブで成功した実行を選択 → [Analyze with AI] を選択します。
2
最適化の目標を選択する
Performance (パフォーマンス) または Cost (コスト) を選択し、必要に応じてベースラインとなる正常だった実行を指定します。目標を指定することで、選択した指標を優先しつつ、もう一方の劣化を制限内に抑えた提案が生成されます。
3
MCP クライアントから利用する場合
analyze_spark_workload ツールを呼び出します。「faster」「cheaper」などの自然言語の表現から目標が設定されます。ジョブ実行 ID (比較の場合はベースライン実行 ID も) を含めて依頼します。
Text MCP クライアントでのプロンプト例 
My job is slow. How do I make this job faster?   # パフォーマンス目標
My bill is too high.                              # コスト目標
Why is my job running slowly today?               # ベースライン比較
4
レコメンデーションを確認して適用する
分析結果には、変更対象のプロパティ、現在値と提案値、根拠となるテレメトリの証拠が表示されます。エージェントは変更を自動適用しないため、内容を確認した上でユーザー自身がジョブ設定やコードに反映し、次回実行で効果を検証します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓コスト削減の機会を可視化: 確保したエグゼキューター数と実際の使用数を比較し、見過ごされがちな過剰プロビジョニングを検出
✓追加料金なし: エージェントの利用自体に追加費用は発生せず、導入のハードルが低い
✓専門家への依存を低減: Spark チューニングの専門知識がないチームでも証拠に基づいた最適化判断が可能

🛠️ 技術面のメリット

✓証拠に基づくレコメンデーション: 各提案にテレメトリの証拠と理由が付属
✓読み取り専用で安全: コードや設定を変更せず、適用の判断は常にユーザー側
✓ベースライン比較による劣化分析: 正常時との差分から原因を効率的に特定
✓IAM と CloudTrail による統制: ガバナンス要件に対応

⚠️ 制限事項

✗AWS Glue 4.0 以降のジョブのみ対応
✗完了したジョブ実行のみが分析対象 (実行中のジョブはリアルタイムに分析できない)
✗AWS GovCloud (US) および中国リージョンでは利用不可

🤔 考慮すべき点

💡レコメンデーションの反映と効果検証はユーザーの作業として残る
💡data カテゴリの提案はジョブの挙動を変えるため、本番適用前に通常の変更管理プロセスでのレビューとテストが必要
💡コストとパフォーマンスはトレードオフになる場合があり、選択した目標によって提案内容が変わる

💡 ユースケース

🌙 ユースケース 1: SLA 遅延が発生した夜間パイプラインの改善

シナリオ: 毎朝 8 時のダッシュボード更新に間に合わせる必要がある夜間の注文データパイプラインが、データ量の増加に伴い徐々に遅くなり、SLA に間に合わなくなってきた。

実装: 対象ジョブの最新の実行を選択 → [Analyze with AI] から Performance を選択して分析 → ボトルネックとなっているステージと推奨設定を確認して適用。

効果: 単純にワーカーを追加するのではなく、ボトルネックのステージに対する具体的な設定変更が提案されるため、コストを抑えながら実行時間を短縮できる。

💰 ユースケース 2: 見過ごされていた過剰プロビジョニングの是正

シナリオ: ジョブは期限内に完了しているため誰もレビューしておらず、Glue ジョブのコストが必要以上に高くなっている可能性がある。

実装: 成功した実行に対して Cost 目標で分析 → 確保されたエグゼキューターとステージで実際に使用されたエグゼキューターの比較結果を確認 → 提案されたワーカータイプ・ワーカー数に変更して次回実行で検証。

効果: 実行時間の劣化を定義された制限内に抑えながら、過剰なキャパシティを適正化してコストを削減できる。

🔍 ユースケース 3: 突然遅くなったジョブの原因特定

シナリオ: 以前は安定して動いていたジョブが、ある日から急に遅くなった。設定、データ、環境のどこに原因があるのかわからない。

実装: 劣化した実行と正常だった過去の実行をベースラインとして指定 → MCP クライアントから「Why is my job running slowly today?」と依頼 → 設定・メトリクス・ステージ挙動の差分レポートを確認。

効果: 正常時との差分が自動で抽出されるため、データスキューの発生や設定変更など、劣化の原因を短時間で特定できる。

💵 料金と利用可能リージョン

料金: Apache Spark Optimization Agent は追加料金なしで利用できます。AWS Glue ジョブの実行自体には通常の AWS Glue の料金が適用されます。
利用可能リージョン: AWS Glue が利用可能なすべての AWS リージョンで利用できます。ただし、AWS GovCloud (US) および中国リージョンは除きます。

🔗 関連サービス・機能

☁️ Amazon EMR Serverless

同じ Apache Spark Optimization Agent が Amazon EMR Serverless の Spark ジョブにも提供されており、EMR Studio の [Analyze with AI] から利用できる。

🧪 Amazon SageMaker Unified Studio

リモート MCP Server を通じて analyze_spark_workload ツールを提供し、外部ツールからのエージェント呼び出しを可能にする。

📜 AWS CloudTrail

エージェントへのアクセスが記録され、監査証跡として利用できる。

💪 AWS Graviton

エージェントのベストプラクティスチェックにより、Graviton ベースのワーカーへの移行が提案される場合がある。

📝 まとめ

Apache Spark Optimization Agent により、これまで専門家の手作業に頼っていた Spark ジョブのチューニングが、数分で得られる証拠付きのレコメンデーションに置き換わります。追加料金なしで利用でき、エージェントは読み取り専用で変更を強制しないため、まずは主要な Glue ジョブや長時間実行されているジョブに対して Cost / Performance の両目標で分析を試し、提案内容と削減効果を確認することを推奨します。
