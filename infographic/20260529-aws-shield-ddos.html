📋 概要

AWS Shield Advanced に DDoS 攻撃フローログ 機能が追加された。DDoS 攻撃中に保護対象リソースへ到達するトラフィックのパケットレベルの詳細を記録し、フォレンジック分析やコンプライアンス目的で活用できる。

フローログには送信元/宛先 IP アドレス、ポート番号、プロトコル、パケット数、バイト数、送信元国情報などが含まれ、攻撃の全容を把握するための重要なデータソースとなる。ログデータはアクティブな攻撃中に 5 分間隔で自動的に配信先へパブリッシュされる。

🔄 Before / After

❌ Before

  • パケットレベルの詳細情報を直接取得する手段がなかった
  • Shield Advanced コンソールのイベント概要や CloudWatch メトリクスに依存
  • コンプライアンス監査で攻撃トラフィックの詳細エビデンス提示が困難

✅ After

  • S3、CloudWatch Logs、Data Firehose の 3 配信先から選択可能
  • 5 分間隔の自動配信でリアルタイムに近い分析が可能

🛠️ 設定方法

前提条件

  • AWS Shield Advanced サブスクリプションが有効であること
  • 保護対象リソースが Shield Advanced で保護されていること
  • 配信先サービスに対する適切な IAM 権限が設定されていること

ステップ 1: 配信先の準備

Bash S3 バケット作成 
# S3 バケットを配信先とする場合の例
aws s3 mb s3://my-shield-flow-logs-bucket --region us-east-1

ステップ 2: フローログ配信の設定

Bash フローログ有効化 
# Shield Advanced でフローログ配信を有効化
aws shield configure-attack-flow-logs \
  --resource-arn arn:aws:elasticloadbalancing:us-east-1:123456789012:loadbalancer/app/my-alb/1234567890 \
  --log-destination-configs "arn:aws:s3:::my-shield-flow-logs-bucket"

ステップ 3: ログの確認

Bash 配信確認 
# S3 に配信されたログを確認
aws s3 ls s3://my-shield-flow-logs-bucket/ --recursive

💡 メリット

📈 ビジネス面

  • コンプライアンス対応の強化 - 規制要件に対して詳細なエビデンスを提示可能
  • インシデント対応の迅速化 - 攻撃パターン分析で再発防止策の策定を効率化
  • 保険・監査対応 - サイバー保険の請求や監査レポートに具体的データを提供

🔬 技術面

  • フォレンジック分析の高度化 - パケットレベルの詳細で攻撃手法を特定
  • 脅威インテリジェンスの充実 - 送信元国情報やパターン分析でプロアクティブな防御
  • 既存ツールとの統合 - SIEM やアナリティクスツールと連携可能

⚠️ デメリット・制約事項

🚧 制限事項
  • Shield Advanced サブスクリプション (月額 $3,000 + データ転送料) が必須
  • ログは攻撃アクティブ時のみ生成 - 平常時のベースライン比較には使用不可
  • 5 分間隔配信のため、完全なリアルタイム分析には遅延あり
💭 考慮すべき点
  • 大規模 DDoS 攻撃時にはフローログのデータ量が膨大になる可能性 - ストレージコストに注意
  • 配信先の IAM ポリシーとリソースポリシーの適切な設定が必要

🎯 ユースケース

🕵️ ユースケース 1: インシデント後のフォレンジック分析

金融機関の Web アプリケーションが DDoS 攻撃を受けた後、セキュリティチームが攻撃の全容を調査する。
SQL Athena でフローログを分析 
-- 攻撃の送信元国別トラフィック量を集計
SELECT source_country, COUNT(*) as packet_count, SUM(bytes) as total_bytes
FROM shield_flow_logs
WHERE attack_id = 'A-12345678'
GROUP BY source_country
ORDER BY total_bytes DESC;
→ 攻撃の送信元国、使用プロトコル、攻撃パターンを特定し、WAF ルールの最適化や防御戦略に活用

📡 ユースケース 2: リアルタイム脅威インテリジェンス連携

SOC チームが DDoS 攻撃中にリアルタイムで脅威情報を SIEM に取り込み、攻撃の進行を監視する。
JSON Data Firehose 設定例 
{
  "DeliveryStreamName": "shield-flow-logs-to-splunk",
  "S3DestinationConfiguration": {
    "BucketARN": "arn:aws:s3:::backup-shield-logs",
    "Prefix": "shield-flow-logs/"
  },
  "HttpEndpointDestinationConfiguration": {
    "EndpointConfiguration": {
      "Url": "https://http-inputs-your-splunk.splunkcloud.com:443"
    }
  }
}
→ Data Firehose 経由で SIEM にストリーミング配信し、攻撃中のリアルタイム可視化と自動アラートを実現

📝 ユースケース 3: コンプライアンスレポートの自動生成

PCI DSS や SOC 2 監査に備えて、DDoS 攻撃イベントの詳細記録を自動的に保存・レポート化する。
Bash CloudWatch Logs Insights クエリ 
# CloudWatch Logs Insights で攻撃サマリーレポートを生成
aws logs start-query \
  --log-group-name "/aws/shield/flow-logs" \
  --start-time $(date -d '30 days ago' +%s) \
  --end-time $(date +%s) \
  --query-string 'stats count(*) as attack_events, sum(bytes) as total_bytes by bin(1d) as day'
→ 監査対応に必要な攻撃の時系列記録とトラフィック詳細を自動蓄積し、レポート作成工数を削減
