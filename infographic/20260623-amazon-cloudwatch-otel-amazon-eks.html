Amazon CloudWatch

OTel Container Insights
for Amazon EKS

2026-06-23 リリース
OpenTelemetry ベースの推奨可観測性ソリューション

📊 概要

Amazon CloudWatch が EKS 向けの OTel Container Insights を発表。 OpenTelemetry をベースに構築された、EKS クラスターの推奨される可観測性ソリューションです。

cAdvisor、Kube State Metrics、NVIDIA DCGM などのオープンソースレシーバーで 30 秒粒度のインフラメトリクスを収集。 各メトリクスは OpenTelemetry セマンティック規約と Kubernetes ラベルを保持するため、 ノード・Pod・ワークロードをまたいだ相関分析を単一の PromQL クエリで実行できます。

従来の Classic が独自のメトリクス名を使用していたのに対し、OTel Container Insights は各ソースの元の名前 (例: cAdvisor の container_cpu_usage_seconds_total) をそのまま保持し、 既存の PromQL ダッシュボードとの互換性が高いのが特徴です。

😟 アップデート前の課題
  • Classic は独自メトリクス名のため既存 PromQL ダッシュボードとの互換性が低かった
  • ノード・Pod・ワークロードをまたいだ相関分析を統一クエリで行いにくかった
  • 既存の Prometheus / Grafana 資産を再利用しにくかった
😄 アップデート後の改善
  • 元のソース名を保持し、既存 PromQL ダッシュボードをそのまま活用可能
  • OTel セマンティック規約 + K8s ラベルで単一 PromQL の相関分析が可能
  • PromQL エンドポイントで Prometheus / Grafana を CloudWatch に直接接続

⭐ 主要機能

1オープンソースレシーバーによるメトリクス収集
  • cAdvisor、Prometheus Node Exporter、Kube State Metrics、Kubernetes API Server、NVIDIA DCGM、AWS Neuron Monitor、AWS Elastic Fabric Adapter、NVMe に対応
  • OTLP を使用して 30 秒粒度で収集
  • CloudWatch 形式ではなく各ソースの元の名前を保持 (例: container_cpu_usage_seconds_total)
2OTel セマンティック規約と Kubernetes ラベルによる強化
  • 各メトリクスは最大 150 個のラベルで強化
  • ラベルは 3 ソースから付与: ネイティブラベル (pod, namespace, container)、OTel リソース属性、K8s の Pod/Node ラベル (k8s.pod.label.*, k8s.node.label.*)
  • 単一の PromQL クエリでノード・Pod・ワークロードをまたいだ相関分析が可能
3事前構築済みダッシュボードと PromQL エンドポイント
  • クラスター健全性、ノード性能、Pod レベルのリソース使用状況を即座に可視化
  • CloudWatch PromQL エンドポイントで既存 Prometheus / Grafana を直接接続
4デュアルパブリッシングによる移行サポート
  • アドオン v6.2.0 以降で Classic と OTel の両方へ同時にメトリクス発行可能
  • 完全移行前に新しいメトリクスパイプラインを検証できる

両者は同じ amazon-cloudwatch-observability EKS アドオンを使用します。違いは別製品ではなく、 アドオンのバージョンと設定にあります。OTel Container Insights はこのアドオンのより新しく活発に開発されている構成です。

🛠️ 設定方法

前提条件

  • Amazon EKS クラスターが稼働していること
  • CloudWatch Observability アドオン v6.2.0 以降を使用できること
  • NVIDIA DCGM や AWS Neuron 等を使う場合は対応デバイスプラグインを導入

ステップ1: EKS コンソールから有効化

クラスター設定画面から有効化。最も簡単に始められる方法で、数分で完全な可観測性を有効化できます。

ステップ2: アドオン設定で有効化 (Classic を無効化)

OTel Container Insights はデフォルトで無効です。otelContainerInsights.enabled を true に設定して有効化します。

Bash OTel のみ有効化 / Classic を無効化 
aws eks update-addon \
  --cluster-name {{cluster-name}} \
  --addon-name amazon-cloudwatch-observability \
  --configuration-values '{"containerInsights":{"enabled":false},"otelContainerInsights":{"enabled":true}}'

デュアルパブリッシング設定 (Classic と OTel を併用)

Bash 移行検証向け: 両方へ同時発行 
aws eks update-addon \
  --cluster-name {{cluster-name}} \
  --addon-name amazon-cloudwatch-observability \
  --configuration-values '{"containerInsights":{"enabled":true},"otelContainerInsights":{"enabled":true}}'

ステップ3: Helm または CloudFormation

GitOps フレンドリーな管理には Helm チャートを、IaC で管理したい場合は CloudFormation テンプレートを使用できます。

💡 メリット

📈 ビジネス面

  • 既存資産の活用: 元のソース名保持で PromQL 資産を再利用し移行コストを抑制
  • 運用の統合: メトリクスとログを単一エージェントで収集
  • 継続的な機能拡充: 活発に開発される構成で新機能を継続受領

⚙️ 技術面

  • OTel ネイティブ: 業界標準の OpenTelemetry Collector 上に構築
  • 高い相関性: 最大 150 ラベルで単一 PromQL の横断分析
  • 段階的な移行: デュアルパブリッシングで検証後に完全移行

⚠️ デメリット・制約事項

制限事項

  • 中東 (UAE)、中東 (バーレーン)、イスラエル (テルアビブ) では利用不可
  • デュアルパブリッシング機能にはアドオン v6.2.0 以降が必要
  • OTel Container Insights はデフォルトで無効のため明示的な有効化が必要

考慮すべき点

  • NVIDIA DCGM / AWS Neuron / EFA 等のレシーバーは対応デバイスプラグインの導入が前提
  • デュアルパブリッシング構成ではメトリクスが二重発行されるため料金への影響を確認

🎯 ユースケース

1. 既存 Grafana ダッシュボードの CloudWatch への接続
シナリオ: 既に Prometheus / Grafana で EKS を監視する組織がメトリクスストアを CloudWatch に集約したい
実装: PromQL エンドポイントを Grafana データソースに登録し、既存クエリベースのダッシュボードをそのまま接続
効果: 書き直しなしで CloudWatch のマネージドストアへ移行し運用負荷を軽減
2. GPU ワークロードの監視
シナリオ: ML トレーニングを EKS 上で実行し GPU 使用率・スロットリング・温度を詳細監視したい
実装: NVIDIA デバイスプラグイン + コンテナツールキットを導入し DCGM レシーバーで 30 秒粒度収集
効果: GPU 各種メトリクスを Pod レベルラベルと相関させ、トレーニングのボトルネックを特定しやすい
3. Classic からの段階的移行
シナリオ: Classic を本番運用しており、ダウンタイムなく OTel ベースへ移行したい
実装: デュアルパブリッシングで併用し、OTel のメトリクスとダッシュボードを検証後に Classic を無効化
効果: 本番データで検証してから切り替えられ移行リスクを最小化

💰 料金 & 🌍 利用可能リージョン

料金

収集されるメトリクスとログに対して CloudWatch の標準料金が適用されます。 デュアルパブリッシング構成では Classic と OTel の両方で発行されるため、料金への影響を事前確認することを推奨します。

利用可能リージョン

除外: 中東 (UAE)、中東 (バーレーン)、イスラエル (テルアビブ)
上記を除くすべての商用 AWS リージョンで利用可能。

🔗 関連サービス・機能

  • Amazon EKS: 監視対象となる Kubernetes クラスターを提供
  • CloudWatch Observability アドオン: OTel Collector を含み、メトリクスとログ収集を担う
  • Amazon Managed Service for Prometheus / Grafana: PromQL ベースの可観測性で補完的に利用

📝 まとめ

OTel Container Insights は OpenTelemetry をベースとした EKS の推奨可観測性ソリューション。 元のメトリクス名と標準セマンティック規約を保持し、既存の PromQL / Grafana 資産をそのまま活用できる点が大きな価値です。 EKS 運用組織は、デュアルパブリッシングで Classic から段階的に移行し、モダンで統一されたテレメトリパイプラインへの集約を検討することが推奨されます。
