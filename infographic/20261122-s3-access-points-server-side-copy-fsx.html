🪣 S3 Access Points によるサーバーサイドコピー対応

S3 バケットと FSx ファイルシステム間のデータ移動が、転送サーバーなしで AWS 内部で完結
📅 リリース日: 2026 年 11 月 22 日

📝 概要

Amazon S3 の汎用バケットと Amazon FSx ファイルシステムの間で、S3 Access Points を使用したサーバーサイドコピー・移動が可能になりました。 同一 AWS リージョン内であれば、S3 標準の CopyObject / UploadPartCopy オペレーションで、 S3 と FSx 間、または FSx ファイルシステム間でデータを直接転送できます。

S3 Access Points for FSx は、FSx ファイルシステムをマウントすることなく S3 API 経由でアクセスできるエンドポイントです。 データ転送が AWS 側で完結するため、従来よりも高速かつ低コストで、簡単にデータ移動を実現できます。AWS CLI、AWS SDK、S3 互換ツールから利用可能です。

❌ Before: クライアント経由の 2 段階転送
  • ✗EC2 などの自前サーバーで各オブジェクトをダウンロードし、再アップロードが必要
  • ✗転送用コンピューティングリソースの準備・運用コストと管理負荷が発生
  • ✗2 段階転送のため大量データの移動に時間がかかる
✅ After: サーバーサイドコピー
  • ✓CopyObject / UploadPartCopy で S3 と FSx 間を直接コピー・移動
  • ✓FSx ファイルシステム間のクロスファイルシステムコピーにも対応
  • ✓転送用サーバーが不要になり、高速・低コスト・シンプルなデータ移動を実現

従来はユーザー管理のサーバーを経由した 2 段階転送が必要でしたが、今回のアップデートにより API 呼び出しのみでデータ転送が AWS 内部で完結します。

⚡ 主要機能

1️⃣ S3 バケットと FSx 間のサーバーサイドコピー
  • 同一 AWS リージョン内の S3 汎用バケットと FSx ファイルシステム間でデータを直接コピー・移動
  • S3 標準の CopyObject / UploadPartCopy オペレーションをそのまま使用可能
  • データがクライアントを経由しないため、転送が高速かつ低コスト
2️⃣ FSx ファイルシステム間のコピー
  • S3 Access Points を介して、FSx ファイルシステム間でもサーバーサイドでデータを転送可能
  • ファイルシステムの移行やチーム間のデータ共有に活用できる
3️⃣ 既存ツールとの互換性
  • AWS CLI、AWS SDK、S3 互換ツールから利用可能
  • S3 の標準 API を使用するため、既存の S3 向けワークフローやスクリプトを流用できる

🛠️ 設定方法

📋 前提条件

  • FSx for NetApp ONTAP または FSx for OpenZFS のファイルシステムが作成済みであること
  • FSx ファイルシステムに S3 Access Point がアタッチされていること
  • コピー元・コピー先に対する適切な IAM 権限 (s3:GetObject、s3:PutObject など) が設定されていること

FSx ファイルシステムに S3 Access Point を作成
Bash S3 Access Point の作成 
aws s3control create-access-point \
  --account-id 111122223333 \
  --name my-fsx-access-point \
  --bucket arn:aws:fsx:ap-northeast-1:111122223333:volume/fs-0123456789abcdef0/fsvol-0123456789abcdef0

FSx ボリュームを指定して S3 Access Point を作成します。これにより、FSx 上のデータに S3 API でアクセスできるエンドポイントが用意されます (既にアタッチ済みの場合はこのステップは不要です)。

2
S3 バケットから FSx へサーバーサイドコピー
Bash CopyObject によるコピー 
aws s3api copy-object \
  --copy-source my-source-bucket/data/input.csv \
  --bucket arn:aws:s3:ap-northeast-1:111122223333:accesspoint/my-fsx-access-point \
  --key data/input.csv

CopyObject オペレーションで、S3 バケット上のオブジェクトを S3 Access Point 経由で FSx ファイルシステムに直接コピーします。データはクライアントを経由せず、AWS 内部で転送されます。

3
大容量オブジェクトのマルチパートコピー
Bash UploadPartCopy によるパート単位コピー 
aws s3api upload-part-copy \
  --copy-source my-source-bucket/data/large-file.bin \
  --bucket arn:aws:s3:ap-northeast-1:111122223333:accesspoint/my-fsx-access-point \
  --key data/large-file.bin \
  --part-number 1 \
  --upload-id "example-upload-id" \
  --copy-source-range bytes=0-5368709119

大容量オブジェクトの場合は、マルチパートアップロードと UploadPartCopy を組み合わせて、パート単位でサーバーサイドコピーを実行します。

💡 メリット

💼 ビジネス面

  • コスト削減: 転送専用サーバー (EC2 など) の運用が不要になり、コンピューティングコストと運用負荷を削減
  • 時間短縮: AWS 内部で転送が完結し、2 段階転送と比較して転送時間を短縮
  • データ活用の促進: パートナーデータの取り込みや部門間のデータ共有がスムーズに

⚙️ 技術面

  • 標準 API の利用: CopyObject / UploadPartCopy を使用するため、既存ツールやスクリプトをそのまま活用
  • アーキテクチャの簡素化: 中間サーバーが不要になり、障害点が減少し運用がシンプルに
  • マウント不要: NFS 等でのマウント設定なしに S3 API 経由でデータ転送を実行

⚠️ デメリット・制約事項

🚫 制限事項

  • サーバーサイドコピーは同一 AWS リージョン内の転送に限定される
  • 対応 FSx は FSx for NetApp ONTAP と FSx for OpenZFS のみ (FSx for Windows File Server、FSx for Lustre は対象外)
  • S3 Access Points for FSx が利用可能なリージョンでのみ使用できる

🤔 考慮すべき点

  • FSx 側のファイルシステム性能 (スループット容量) がコピー速度に影響する可能性があるため、大量データ転送時は性能設定を確認する
  • コピー元・コピー先の双方に対する IAM 権限と Access Point ポリシーの設計が必要
  • クロスリージョンの転送が必要な場合は、従来どおり別の転送手段 (AWS DataSync など) を検討する

🎯 ユースケース

📥 ユースケース 1: パートナーデータの FSx への取り込み

シナリオ: パートナー企業から S3 バケット経由で受領したデータを、社内の分析基盤が利用する FSx for NetApp ONTAP ファイルシステムに取り込みたい。

Bash実装例
aws s3 cp s3://partner-delivery-bucket/dataset/ \
  s3://arn:aws:s3:ap-northeast-1:111122223333:accesspoint/analytics-fsx-ap/dataset/ \
  --recursive
✅ 効果: 転送用サーバーを経由せずにデータを直接取り込めるため、取り込み時間とコストを削減し、パイプラインを簡素化できる。
📤 ユースケース 2: 分析結果の S3 バケットへのエクスポート

シナリオ: FSx for OpenZFS 上で生成された分析結果やレポートを、別チームが利用する S3 バケットに共有したい。

Bash実装例
aws s3api copy-object \
  --copy-source "arn:aws:s3:ap-northeast-1:111122223333:accesspoint/results-fsx-ap/object/reports/monthly.parquet" \
  --bucket team-b-shared-bucket \
  --key reports/monthly.parquet
✅ 効果: ファイルシステムをマウントすることなく、S3 API のみで成果物を他チームに共有でき、データ連携のリードタイムを短縮できる。
🔄 ユースケース 3: FSx ファイルシステム間のデータ移行

シナリオ: 既存の FSx ファイルシステムから新しい FSx ファイルシステムへ、特定ディレクトリのデータを移行したい。

Bash実装例
aws s3 cp \
  s3://arn:aws:s3:ap-northeast-1:111122223333:accesspoint/old-fsx-ap/project-a/ \
  s3://arn:aws:s3:ap-northeast-1:111122223333:accesspoint/new-fsx-ap/project-a/ \
  --recursive
✅ 効果: 中間サーバーやステージング用バケットを用意することなく、ファイルシステム間でデータを直接移動できる。

📌 まとめ

S3 Access Points for FSx がサーバーサイドコピーに対応したことで、S3 バケットと FSx ファイルシステム間のデータ移動から 転送用サーバーが不要になり、高速・低コスト・シンプルなデータ連携が実現しました。 S3 と FSx を併用してデータパイプラインを構築している場合は、既存の転送処理を CopyObject / UploadPartCopy ベースのサーバーサイドコピーに置き換えることを検討してください。
