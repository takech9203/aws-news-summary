Kiro CLIv2.15.0

🛠️ スペックドラフティングとプランの自動実行

📅 リリース日: 2026 年 7 月 27 日 | Spec Drafting and Plan Auto-Execution

📋 概要

Kiro CLI v2.15.0 では、スペック作成とプラン実行のワークフローが改善されました。中心となるのは ガイド付きスペック作成 (v3) と プランの自動実行 (v3) の 2 つの機能です。

/spec new は要件のドラフト前にカバー範囲を質問し、ユーザーの説明を要件生成の基準 (ground truth) として使用します。また、Plan mode で承認済みのプランは手動のモード切り替えなしで即座に実行されます。

😓 アップデート前の課題

  • /spec new がスペック名だけから内容を推測し、意図と異なる要件が生成されることがあった
  • Plan mode でプランを承認した後、実行に移るために手動でモードを切り替える必要があった
  • @prompt 参照が、参照先のプロンプトファイルを読み込まずにプレーンテキストとして送信されることがあった

🚀 アップデート後の改善

  • /spec new がドラフト前にカバー範囲を質問し、ユーザーの説明を基準として要件を生成
  • Plan mode でプランを承認すると即座に実行が開始され、手動のモード切り替えが不要に
  • 新しい chat.showThinkingTips 設定で思考インジケーター下のヒント表示を非表示にできる

ガイド付きスペック作成では、要件のドラフト前にユーザーの説明を収集して基準とします。プランの自動実行では、承認と同時に実行が開始され、手動のモード切り替えが不要になります。

⚙️ 主要機能

📝 1. ガイド付きスペック作成 (Guided Spec Creation) (v3)
  • /spec new が要件をドラフトする前に、そのスペックが何をカバーすべきかを質問
  • スペック名だけから推測せず、ユーザーが入力した説明を要件生成の基準 (ground truth) として使用
  • 意図に沿った要件が最初から生成されやすくなり、スペックの手戻りが減少
⚡ 2. プランの自動実行 (Plan Auto-Execution) (v3)
  • Plan mode でプランを承認すると、即座に実行が開始
  • プランをレビューして承認した後に、手動でモードを切り替える必要がなくなった
💡 3. 改善: 思考ヒントの表示切り替え (Thinking Tips Toggle)
  • 新しい chat.showThinkingTips 設定により、思考インジケーターの下に表示されるヒントを非表示にできる
🔧 4. 修正
  • @prompt 参照が、参照先のプロンプトファイルを読み込まずにプレーンテキストとして送信されることがある問題を修正
  • --classic モードで、信頼プロンプトの権限上書き警告が、新しく信頼したツールだけでなく過去に信頼したすべてのツールに適用されていた問題を修正

設定例

  "chat.showThinkingTips": false
}

chat.showThinkingTips を false に設定すると、思考インジケーターの下に表示されるヒントが非表示になります。

🛠️ 設定方法

前提条件

✓Kiro CLI v2.15.0 以降がインストールされていること
✓ガイド付きスペック作成とプランの自動実行は v3 の機能であること

手順

1

ガイド付きスペック作成を利用する

Bash
/spec new

/spec new を実行すると、要件のドラフト前にカバー範囲を質問されます。入力した説明が要件生成の基準として使用されるため、スペックの目的や範囲を具体的に記述します。

2

Plan mode でプランを承認する

Plan mode でエージェントが提示したプランをレビューし、承認します。承認すると即座に実行が開始されるため、手動でモードを切り替える操作は不要です。

3

思考ヒントの表示を調整する

JSON
{
  "chat.showThinkingTips": false
}

思考インジケーター下のヒント表示が不要な場合は、設定で chat.showThinkingTips を false にします。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

  • 手戻りの削減: ドラフト前に意図を伝えられるため、要件の修正サイクルが減り、スペック駆動開発の立ち上がりが速くなる
  • ワークフローの効率化: プラン承認から実行までがシームレスになり、レビュー後の操作コストが低下
  • 開発体験の向上: @prompt 参照や信頼プロンプト警告の修正により、日常的な操作の信頼性が向上

🔧 技術面のメリット

  • 説明を基準とした要件生成: スペック名からの推測ではなく、ユーザーの説明を ground truth として要件を生成
  • モード切り替えの自動化: Plan mode での承認が実行のトリガーとなる
  • 表示のカスタマイズ: chat.showThinkingTips で思考インジケーター周りの表示を制御

⚠️ 制限事項・考慮すべき点

⚠️ガイド付きスペック作成とプランの自動実行は v3 の機能です
⚠️本リリースは Kiro CLI が対象です
⚠️プランの承認が即座に実行につながるため、承認前にプランの内容を十分にレビューすることが重要です
⚠️/spec new で入力する説明が要件生成の基準となるため、スペックの目的と範囲を明確に記述することが品質向上につながります

🎯 ユースケース

📝 ユースケース 1: 意図を反映したスペックの新規作成

シナリオ: 新機能のスペックを作成したいが、スペック名だけでは意図が伝わらず、生成された要件の修正に時間がかかっている。

Text実装例
/spec new
# 質問に対して、スペックがカバーすべき範囲を具体的に説明する
# 例: 「ユーザー認証機能。メールとパスワードによるサインアップ、
#      ログイン、パスワードリセットをカバーする。SSO は対象外」

効果: 入力した説明が要件生成の基準となるため、意図に沿った要件が最初から生成され、手戻りが減ります。

⚡ ユースケース 2: プランレビューから実装までのシームレスな移行

シナリオ: Plan mode で実装計画をレビューした後、すぐに実装へ移りたいが、毎回モードを手動で切り替えるのが煩雑。

Text実装例
# Plan mode でプランを確認し、承認する
# 承認と同時に実行が自動的に開始される

効果: 承認と同時に実行が開始されるため、レビューから実装までの流れが途切れず、操作の手間が減ります。

🧹 ユースケース 3: 表示をシンプルに保つ

シナリオ: 思考インジケーター下のヒント表示が不要で、出力をシンプルに保ちたい。

JSON実装例
{
  "chat.showThinkingTips": false
}

効果: ヒントが非表示になり、コンソール出力がすっきりします。

📌 まとめ

Kiro CLI v2.15.0 は、/spec new にガイド付きの説明ステップを追加してユーザーの意図を要件生成の基準とし、Plan mode での承認後にプランを自動実行することで、スペック駆動開発とプラン実行のワークフローを効率化するアップデートです。スペック作成時は目的と範囲を具体的に説明し、プランは承認と同時に実行が始まる点を踏まえて十分にレビューすることをお勧めします。
