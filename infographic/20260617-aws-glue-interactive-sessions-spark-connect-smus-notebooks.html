使い慣れた IDE / ノートブックから AWS Glue のサーバーレス Spark を対話実行
リリース日
2026.06.17

📌 概要

AWS Glue Interactive Sessions が Apache Spark Connect をサポート。開発者は使い慣れた環境から Spark アプリを構築・実行しつつ、処理は AWS Glue のサーバーレス基盤で動かせます。クラスター管理は不要です。

Spark Connect は、クライアントを Spark 実行環境から切り離すシンクライアントアーキテクチャを採用。クライアントは gRPC でリモートの Spark に接続し、最小限の依存関係で実行します。アドホックなデータ探索、反復デバッグ、段階的な PySpark ジョブ開発が可能になります。

🔄 アップデートによる変化

😟 Before（課題）
  • ローカル IDE / ノートブックから Glue のサーバーレス Spark へ対話実行しにくい
  • クライアントと Spark 実行環境が密結合し、依存分離・アップグレードが困難
  • 本番前の段階的開発・反復デバッグのワークフローを組みにくい
➜
😊 After（改善）
  • 好みの開発環境から Glue サーバーレス基盤上で Spark を実行できる
  • シンクライアントで依存分離 — アップグレード簡素化と安定性向上
  • アドホック探索・反復デバッグ・段階的ジョブ開発が可能に

クライアント環境（SageMaker Unified Studio や IDE）が gRPC を介して AWS Glue のサーバーレス Spark エンジンに接続し、処理結果は Spark UI / Spark History Server で監視できます。

🚀 主要機能

① Spark Connect によるリモート実行

  • クライアントと Spark 実行環境を分離するシンクライアントアーキテクチャ
  • gRPC で AWS Glue のサーバーレス Spark 環境に接続
  • 最小限のクライアント側依存関係でリモート Spark を実行

② 対話的な開発ワークフローのサポート

  • アドホックなデータ探索
  • ステップごとの反復的なデバッグ
  • 本番デプロイ前の段階的な PySpark ジョブ開発

③ 可観測性（オブザーバビリティ）機能

  • Spark UI によるリアルタイムのセッション監視
  • Spark History Server による履歴トラッキング
  • AWS Glue API / CLI / SDK を用いたセッション管理

④ 幅広い開発環境のサポート

  • Amazon SageMaker Unified Studio のマネージドノートブック
  • Jupyter や Visual Studio Code などのノートブック / IDE
  • Python インタープリターを備えた任意の IDE、AWS API / SDK / CLI

前提条件: Glue Interactive Sessions 用 IAM ロール / 権限、クライアント側の Python と Spark Connect クライアント、SMUS 利用時はドメイン / プロジェクト構成。

BashSTEP 1: Spark Connect セッションの作成（AWS CLI）
aws glue create-session \
    --id my-spark-connect-session \
    --role arn:aws:iam::123456789012:role/GlueInteractiveSessionRole \
    --command Name=glueetl,PythonVersion=3 \
    --session-type SPARK_CONNECT
PythonSDK（boto3）でのセッション作成例
import boto3

glue = boto3.client("glue")

# Spark Connect セッションを作成
response = glue.create_session(
    Id="my-spark-connect-session",
    Role="arn:aws:iam::123456789012:role/GlueInteractiveSessionRole",
    Command={
        "Name": "glueetl",
        "PythonVersion": "3"
    },
    SessionType="SPARK_CONNECT"
)
BashSTEP 2: エンドポイントの取得
aws glue get-session-endpoint --id my-spark-connect-session

STEP 3: 取得したエンドポイントに gRPC で接続後、PySpark を対話実行。GetDashboardUrl API の URL から Spark UI にアクセスしてリアルタイム監視、実行履歴は Spark History Server で確認できます。

⚖️ メリット・制約事項

✅ ビジネス面のメリット

  • 開発生産性の向上 — 使い慣れた環境から直接実行、環境構築の手間を削減
  • インフラ運用コスト削減 — Spark クラスターの構築・管理が不要
  • 本番移行リスクの低減 — 段階的開発と反復デバッグで品質を高めてからデプロイ

✅ 技術面のメリット

  • 依存関係の分離 — アップグレード簡素化と安定性向上
  • 可観測性の確保 — Spark UI と History Server で監視・履歴追跡
  • 柔軟な接続手段 — gRPC ベースで Python 対応 IDE / API / SDK / CLI から利用可能

⚠️ 制限事項

  • 利用可能リージョンが限定されている
  • クライアント側に Spark Connect クライアント / Python 環境の用意が必要

🔍 考慮すべき点

  • gRPC 接続のため、ネットワーク経路やセキュリティ要件の確認が必要
  • 既存の標準 Glue Interactive Sessions との使い分けの検討

💡 ユースケース

① ローカル IDE での対話的データ探索

データエンジニアがローカルの VS Code から Glue のサーバーレス Spark に接続し、大規模データセットを対話的に探索。

Python
from pyspark.sql import SparkSession

# Spark Connect エンドポイントに接続
spark = SparkSession.builder.remote("sc://<glue-spark-connect-endpoint>").getOrCreate()

df = spark.read.parquet("s3://my-bucket/data/")
df.printSchema()
df.show(20)

効果: クラスターを管理せず、使い慣れた IDE から大規模データの探索を即座に開始できる

② PySpark ジョブの段階的開発とデバッグ

本番デプロイ前に、PySpark の変換ロジックをステップごとに実行して結果を確認しながら開発。

Python
# 変換処理を段階的に確認しながら構築
filtered = df.filter(df["status"] == "active")
filtered.show(5)

aggregated = filtered.groupBy("region").count()
aggregated.show()

効果: 反復的なデバッグにより、本番ジョブの品質を高めてからデプロイできる

③ SageMaker Unified Studio での協働分析

データサイエンスチームが SMUS のマネージドノートブックから Glue の Spark エンジンを共有して分析を進める。

Python
# SageMaker Unified Studio ノートブックから Spark Connect セッションを利用
spark.sql("SELECT region, COUNT(*) FROM sales GROUP BY region").show()

効果: マネージド環境で統合的なデータ分析ワークフローを構築し、チーム間の協働を促進できる

📝 まとめ

AWS Glue Interactive Sessions の Spark Connect サポートにより、開発者は使い慣れた IDE / ノートブックから Glue のサーバーレス Spark を対話的に利用できるようになりました。クラスター管理が不要で、アドホックな探索から段階的なジョブ開発までを 1 つのワークフローでカバーできます。まずは東京リージョンなどの対応リージョンで Spark Connect セッションを試し、既存の開発フローへの組み込みを検討することをおすすめします。
