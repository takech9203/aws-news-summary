☁️ 概要

Amazon Managed Grafana がデュアルスタック接続をサポートし、ワークスペースが IPv4 と IPv6 の両方のプロトコルで通信できるようになった。IPv6 への移行を進める組織は IPv4 との互換性を維持しながら段階的に IPv6 経由で Grafana ワークスペースに接続できる。

インターネットの継続的な成長により利用可能な IPv4 アドレスが枯渇しつつある中、ネットワークスタックの簡素化と将来への準備を同時に実現する重要な機能強化である。

❌ Before (アップデート前)

  • IPv4 のみでの接続に限定
  • IPv6 環境からの接続には NAT64 等の変換が必要
  • VPC 内で重複するアドレス空間の管理が複雑
  • Grafana が IPv6 移行のボトルネック

✅ After (アップデート後)

  • IPv4 と IPv6 の両方で通信可能
  • VPC 内の重複アドレス空間管理が不要
  • IPv4 互換性を維持しながら段階的に移行可能
  • コンソール、API、CLI から簡単に有効化

⚡ 主要機能

🔌 デュアルスタックエンドポイント

  • ワークスペースが IPv4 と IPv6 の両方のアドレスで到達可能
  • DNS は A レコード (IPv4) と AAAA レコード (IPv6) の両方を返す
  • クライアントは利用可能なプロトコルで自動的に接続

⚙️ ipAddressType パラメータ

  • ワークスペース作成時または更新時に IPv4 または DualStack を指定可能
  • 既存のワークスペースを IPv4 のみからデュアルスタックに変更可能
  • API、CLI、コンソールのすべてから設定変更が可能

🔄 後方互換性

  • 既存の IPv4 のみの接続は影響を受けない
  • デフォルトは引き続き IPv4 のため、明示的な設定変更が必要
  • IPv6 未対応の環境でも従来通り IPv4 で接続可能

🛠️ 設定方法

前提条件

  • ✓ Grafana バージョン 10.4 以降で稼働していること
  • ✓ AWS CLI v2 が最新バージョンにアップデートされていること
  • ✓ 適切な IAM 権限 (grafana:UpdateWorkspace) が付与されていること

ステップ 1: 現在のワークスペース設定を確認

Bash ワークスペース設定確認 
aws grafana describe-workspace \
  --workspace-id g-XXXXXXXXXX \
  --query 'workspace.{version:grafanaVersion,ipType:ipAddressType,status:status}'

ステップ 2: デュアルスタックを有効化

Bash デュアルスタック有効化 
aws grafana update-workspace \
  --workspace-id g-XXXXXXXXXX \
  --ip-address-type DualStack

ステップ 3: 設定変更の確認

Bash 設定確認 
aws grafana describe-workspace \
  --workspace-id g-XXXXXXXXXX \
  --query 'workspace.ipAddressType'
# "DualStack" が返されることを確認

⚠️ 制約事項・注意点

制限事項

  • ✗Grafana バージョン 10.4 未満のワークスペースではデュアルスタックを利用不可
  • ✗有効化時にワークスペースが一時的に UPDATING 状態になる
  • ✗VPC 設定使用時は、サブネットが IPv6 CIDR ブロックを持っている必要がある

考慮すべき点

  • ⚡クライアント側のネットワーク環境が IPv6 に対応していることの確認が必要
  • ⚡セキュリティグループやネットワーク ACL で IPv6 トラフィックを適切に許可する設定が必要
  • ⚡DNS 解決で AAAA レコードが返されるため、IPv6 接続に問題がある環境ではハッピーアイボール問題に注意

💡 ユースケース

🏢 IPv6 移行中の大規模組織

インフラ全体を IPv6 に段階的に移行しており、監視基盤である Grafana ワークスペースも移行対象に含めたい場合。IPv6 移行済みのチームは IPv6 で、未移行のチームは IPv4 で引き続きアクセスでき、組織全体の移行ペースに合わせた柔軟な運用が可能。

🌐 IPv4 アドレス枯渇への対応

VPC 内で多数のサービスを運用しており、IPv4 プライベートアドレスが不足しつつある場合。IPv6 サブネット上の新規サービスから NAT 変換なしで直接 Grafana にメトリクスデータを送信でき、ネットワーク構成が簡素化される。

🗺️ マルチリージョン監視環境の統合

複数リージョンにまたがるインフラの監視を行っており、一部リージョンでは IPv6 優先の設計を採用している場合。すべてのリージョンで IPv4/IPv6 どちらの環境からもアクセス可能になり、統一的な監視体験を提供できる。
