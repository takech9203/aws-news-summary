Bash Step 1: 現在のエンジンバージョンを確認 
aws rds describe-db-instances \
  --db-instance-identifier my-rds-custom-instance \
  --query 'DBInstances[0].EngineVersion'
Bash Step 2: 利用可能なアップグレードターゲットを確認 
aws rds describe-db-engine-versions \
  --engine custom-sqlserver-ee \
  --engine-version 15.00.4465.1.v1 \
  --query 'DBEngineVersions[0].ValidUpgradeTarget'
Bash Step 3: GDR アップデートを適用 
aws rds modify-db-instance \
  --db-instance-identifier my-rds-custom-instance \
  --engine-version 15.00.4465.1.v1 \
  --apply-immediately
⚠️ --apply-immediately を指定すると即座にアップグレードが開始される。メンテナンスウィンドウで適用する場合はこのオプションを省略すること。アップグレード中はインスタンスの再起動が発生する。

⚠️ 制約事項・注意点

🔄 ダウンタイム発生
アップグレード中にインスタンスの再起動が発生し、一時的なダウンタイムが生じる
🔧 互換性確認必須
RDS Custom 固有のカスタマイズがアップグレードと互換性があることを事前確認する必要がある
↩️ ロールバック困難
GDR アップデートのロールバックは容易ではなく、事前のスナップショット取得が推奨される
💡 推奨事項: 本番環境への適用前にテスト環境での動作確認を実施すること。Multi-AZ 構成の場合はフェイルオーバー手順を計画すること。

🎯 ユースケース

🏦 ユースケース 1: セキュリティコンプライアンス対応

シナリオ: 金融機関の DB 管理チームが PCI DSS 要件に基づき既知の脆弱性を 30 日以内にパッチ適用する義務がある

効果: コンプライアンス要件を満たしつつ、計画的なダウンタイムでリスクを最小化

🔀 ユースケース 2: マルチバージョン環境での段階的パッチ適用

シナリオ: SQL Server 2019 と 2022 の混在環境で、両バージョンにセキュリティパッチを適用する必要がある

効果: バージョンごとに段階的にパッチを適用し、問題発生時の影響範囲を限定

🤖 ユースケース 3: 自動化されたパッチ管理パイプライン

シナリオ: DevOps チームが定期的なセキュリティパッチ適用を自動化し、手動運用を排除したい

効果: 自動化により人的ミスを排除し、迅速かつ確実なパッチ適用を実現

Python 自動パッチ適用の実装例 
import boto3

rds = boto3.client('rds')

# スナップショット取得後にアップグレード実行
rds.create_db_snapshot(
    DBSnapshotIdentifier='pre-gdr-backup-20260521',
    DBInstanceIdentifier='prod-sql-instance'
)

# スナップショット完了後にバージョンアップグレード
rds.modify_db_instance(
    DBInstanceIdentifier='prod-sql-instance',
    EngineVersion='16.00.4250.1.v1',
    ApplyImmediately=True
)
