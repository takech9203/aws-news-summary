📋 概要

Amazon Redshift が AWS Graviton プロセッサを搭載した新世代のプロビジョンドクラスターノード「RG インスタンス」の一般提供を開始。前世代の RA3 インスタンスと比較して最大 2.4 倍高速に実行し、vCPU あたり 30% のコスト削減を実現。

Redshift 独自のベクトル化データレイククエリエンジンが組み込まれており、Apache Iceberg および Parquet データをクラスターノード上で直接処理可能。Redshift Spectrum の別途スキャニングフリートとテラバイトあたりの課金が不要になる。

Before / After 比較

❌ Before (RA3)

  • データレイククエリに Redshift Spectrum が必要 (TB あたり課金)
  • DW とデータレイクで別エンジンを使い分け
  • ANALYZE コマンドによる手動統計更新が必要
  • vCPU あたりのコストが高い

✅ After (RG)

  • 組み込みデータレイクエンジンで追加コスト不要
  • 単一エンジンで DW + S3 オープンフォーマットをクエリ
  • JIT Analyze による自動統計収集
  • vCPU あたり 30% コスト削減

🛠️ 設定方法

ステップ 1: 新規 RG クラスターの作成

Bash 新規クラスター作成 
aws redshift create-cluster \
  --cluster-identifier my-rg-cluster \
  --node-type rg.4xlarge \
  --number-of-nodes 4 \
  --master-username admin \
  --master-user-password <password> \
  --db-name mydb

ステップ 2: Elastic Resize によるマイグレーション

Bash RA3 から RG へのマイグレーション 
aws redshift resize-cluster \
  --cluster-identifier my-ra3-cluster \
  --cluster-type multi-node \
  --node-type rg.4xlarge \
  --number-of-nodes 4

ステップ 3: Snapshot & Restore

Bash スナップショットからのリストア 
# スナップショットの作成
aws redshift create-cluster-snapshot \
  --cluster-identifier my-ra3-cluster \
  --snapshot-identifier my-migration-snapshot

# RG インスタンスでリストア
aws redshift restore-from-cluster-snapshot \
  --cluster-identifier my-rg-cluster \
  --snapshot-identifier my-migration-snapshot \
  --node-type rg.4xlarge \
  --number-of-nodes 4

ステップ 4: データレイクテーブルへのクエリ

SQL Spectrum 不要の直接クエリ 
-- Iceberg テーブルへの直接クエリ (Spectrum 不要)
SELECT *

-- Parquet データへの直接クエリ
SELECT *
FROM my_data_lake_schema.parquet_table

🎯 ユースケース

1. データウェアハウスとデータレイクの統合分析

Redshift テーブルと S3 上の Iceberg テーブルの両方のデータを結合してビジネスインテリジェンスレポートを作成。Spectrum 不要でテラバイトあたりのスキャン課金も不要。

SQL 統合クエリ例 
SELECT
    w.customer_id,
    w.total_revenue,
    dl.clickstream_count
FROM warehouse_schema.customers w
JOIN iceberg_catalog.analytics.clickstreams dl
    ON w.customer_id = dl.customer_id
WHERE w.region = 'APAC'
    AND dl.event_date >= '2026-04-01';

2. 大規模 DW のコスト最適化

大規模な RA3 クラスター (10 ノード以上) を Elastic Resize で RG に移行。vCPU あたり 30% のコスト削減と最大 2.2 倍のパフォーマンス向上を同時に実現。

3. リアルタイム分析基盤の構築

IoT デバイスからのストリーミングデータが S3 に Parquet 形式で保存されている環境で、インテリジェント NVMe キャッシュが頻繁アクセスデータを自動保持し、繰り返しクエリの応答時間を短縮。

⚖️ メリットと制約事項

✅ メリット

ビジネス面

  • vCPU あたり 30% 価格低減 + Spectrum 課金不要
  • JIT Analyze で DBA 手動チューニング削減
  • 単一エンジンで TCO 最適化

技術面

  • Graviton + ベクトル化で最大 2.4 倍高速
  • DW とデータレイクを単一エンジンに統合
  • NVMe + スマートプリフェッチでレイテンシ削減
  • JIT Analyze がワークロード変化に自動適応

⚠️ 制約事項・考慮点

  • 利用可能サイズは rg.xlarge と rg.4xlarge の 2 種類 (発表時点)
  • RA3 からのマイグレーションには Snapshot & Restore / Elastic Resize / Classic Resize が必要
  • DC2/DS2 旧世代からの直接マイグレーションパスは未公表
  • マイグレーション中の一時的ダウンタイム/パフォーマンス影響の評価が必要
  • 既存 Spectrum ワークロードの移行計画とテストが必要
  • Reserved Instance 既存契約がある場合は移行タイミング検討が必要
  • Parquet 改善倍率 (1.5 倍) は Iceberg (2.4 倍) と比較して控えめ

💰 料金

On-Demand、1 年リザーブド、3 年リザーブド (前払いなし) の料金オプションで提供。RMS 料金はデータ使用量に基づき別途課金。
