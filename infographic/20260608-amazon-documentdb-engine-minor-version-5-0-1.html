Amazon DocumentDB
2026-06-08

📋 概要

Amazon DocumentDB がエンジンマイナーバージョニングシステムを導入。最初のリリースとして 5.0.1 を提供開始。メジャーバージョン内できめ細かなバージョン管理が可能になり、新機能やバグ修正の適用タイミングを柔軟にコントロールできるようになった。

新規集計オペレーター
5+

5.0.1
初のマイナーバージョン

Before / After

❌ Before

  • メジャーバージョン単位でしかバージョン管理不可
  • $rand、$pow、$dateToParts、$dateFromParts が利用不可
  • アクティブ接続数を直接監視するメトリクスがない
  • コマンドレベルのパフォーマンスメトリクスが CloudWatch で利用不可

✅ After

  • マイナーバージョン単位での段階的アップグレードが可能
  • 4 つの新しい集計オペレーターでデータ変換の柔軟性が向上
  • アクティブ接続メトリクスでリアルタイム監視が可能
  • コマンドレベルのパフォーマンスメトリクスで個別追跡可能

⚡ 主要機能

🔢 新しい集計オペレーター

🎲
$rand
0 から 1 の間のランダムな浮動小数点値を生成。サンプリングや A/B テスト、ランダム化処理に活用可能。
📐
$pow
べき乗計算を実行。科学計算や統計処理のパイプライン内での利用に対応。
📅
$dateToParts
日付値を年、月、日、時間、分、秒などの構成要素に分解。月別集計、時間帯分析に活用。
🔧
$dateFromParts
個別の日付構成要素から日付値を組み立て。日付正規化やカスタム日付生成に対応。

📡 アクティブ接続メトリクス

  • インスタンスへのアクティブな接続数をリアルタイムで監視
  • 接続プールの使用状況の把握と接続枯渇の早期検知に活用可能
  • CloudWatch で他のメトリクスと組み合わせたアラーム設定が可能

📊 コマンドレベルパフォーマンスメトリクス

  • CloudWatch で個別コマンドのパフォーマンスを追跡
  • 対象コマンド: find、insert、findAndModify、update など
  • オペレーション別のレイテンシーやスループットを可視化し、ボトルネックの特定を支援

🔄 マイナーバージョニングシステム

  • メジャーバージョン内でのインクリメンタルなバージョンリリースを実現
  • ユーザーがアップグレードのタイミングを主体的に選択可能
  • 新機能とバグ修正をより迅速に提供する仕組み

🛠️ 設定方法

前提条件

  • Amazon DocumentDB 5.0.0 クラスターが稼働中であること
  • AWS CLI v2 がインストール済みであること (CLI で操作する場合)
  • クラスターの modify-db-cluster 権限を持つ IAM ロールまたはユーザーであること

ステップ 1: 現在のエンジンバージョンを確認

Bash バージョン確認 
aws docdb describe-db-clusters \
  --db-cluster-identifier my-docdb-cluster \
  --query 'DBClusters[0].EngineVersion'

ステップ 2: クラスターを 5.0.1 にアップグレード

Bash アップグレード実行 
aws docdb modify-db-cluster \
  --db-cluster-identifier my-docdb-cluster \
  --engine-version 5.0.1 \
  --apply-immediately

--apply-immediately を指定しない場合、次のメンテナンスウィンドウで適用される。

ステップ 3: 新規クラスター作成時にマイナーバージョンを指定

Bash 新規クラスター作成 
aws docdb create-db-cluster \
  --db-cluster-identifier my-new-docdb-cluster \
  --engine docdb \
  --engine-version 5.0.1 \
  --master-username adminuser \
  --master-user-password <password>

💡 ユースケース

🛒 E コマースプラットフォームのランダムサンプリング
大量の商品レビューデータからランダムにサンプルを抽出し、品質チェックやレコメンデーションモデルのトレーニングデータとして活用。
JavaScript $rand を使用したサンプリング 
db.reviews.aggregate([
  { $addFields: { randomScore: { $rand: {} } } },
  { $match: { randomScore: { $lt: 0.01 } } },
  { $project: { randomScore: 0 } }
])
📈 時系列データの月別・時間帯別分析
IoT センサーデータを月別・時間帯別に集計し、パターン分析やレポーティングに活用。
JavaScript $dateToParts を使用した時間集計 
db.sensorData.aggregate([
  { $addFields: {
      dateParts: { $dateToParts: { date: "$timestamp" } }
  }},
  { $group: {
      _id: { year: "$dateParts.year", month: "$dateParts.month", hour: "$dateParts.hour" },
      avgValue: { $avg: "$value" },
      count: { $sum: 1 }
  }},
  { $sort: { "_id.year": 1, "_id.month": 1, "_id.hour": 1 } }
])
🔍 CloudWatch メトリクスによるボトルネック検出
本番環境でどの種類のオペレーションがボトルネックになっているかを特定し、適切な対策を迅速に講じる。
Bash find オペレーションのレイテンシー確認 
aws cloudwatch get-metric-statistics \
  --namespace AWS/DocDB \
  --metric-name FindLatency \
  --dimensions Name=DBClusterIdentifier,Value=my-docdb-cluster \
  --start-time 2026-06-08T00:00:00Z \
  --end-time 2026-06-08T23:59:59Z \
  --period 300 \
  --statistics Average

⚖️ メリット・デメリット

✅ メリット

ビジネス面

  • マイナーバージョン単位でのアップグレードにより、変更管理プロセスの負荷を軽減しリスクを最小化
  • コマンドレベルのメトリクスにより、パフォーマンス問題の原因特定と解決が迅速化
  • 新しい集計オペレーターにより、アプリケーション側の処理をデータベース層に委譲でき開発工数を削減

技術面

  • コマンド別のパフォーマンスメトリクスにより、スロークエリやホットスポットの検出精度が向上
  • $rand、$pow、$dateToParts、$dateFromParts により複雑なデータ変換をデータベース内で完結
  • アクティブ接続メトリクスにより、接続プールのサイジングやスケーリングの判断材料を取得

⚠️ 制限事項・注意点

  • 5.0.1 にアップグレードすると 5.0.0 へのダウングレードは不可能
  • 5.0.0 (LTS) から 5.0.1 にアップグレードすると LTS トラックから外れる
  • マイナーバージョンのアップグレードは手動操作が必要 (自動アップグレードは未提供)
  • LTS トラックを維持したい場合は 5.0.0 に留まる必要があり、新機能の恩恵を受けられないトレードオフあり
  • アップグレード時にクラスターの再起動が発生する可能性あり (メンテナンスウィンドウでの実施を推奨)
