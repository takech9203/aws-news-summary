Amazon SageMaker Unified Studio

⚙️ Terraform によるプロビジョニングのサポート

2026-07-02
AWS アップデート

📌 概要

Amazon SageMaker Unified Studio が Terraform によるプロビジョニング に対応しました。 オープンソースの terraform-aws-sagemaker-unified-studio モジュールを使用して、 バージョン管理されたテンプレートからドメインをデプロイできます。プラットフォームチームは既存の Infrastructure as Code (IaC) パイプラインに組み込み、開発・ステージング・本番の 各アカウント間で一貫性を維持できます。

この統合は Terraform AWS Cloud Control Provider (awscc) を通じて実現されており、 AWS Cloud Control API を利用するため新しい AWS 機能を迅速に Terraform から扱えます。 本機能は SageMaker Unified Studio が利用可能なすべての AWS リージョンで提供されます。

❌ アップデート前の課題

  • ドメインを宣言的にプロビジョニングする公式 Terraform モジュールが存在せず、手動構築や独自スクリプトに依存
  • ブループリント、プロジェクトプロファイル、プロジェクトを既存ワークフローで一貫管理するのが困難
  • アカウント間で構成のドリフト (差異) が発生しやすく、環境間の一貫性維持が難しい

✅ アップデート後の改善

  • バージョン管理されたテンプレートからドメインをプロビジョニング可能に
  • ブループリント・プロジェクトプロファイル・プロジェクトをサブモジュールで独立管理
  • 既存 IAM ロールの再利用が可能になり、環境間の一貫性を保ちながら展開できる

プラットフォームチームが Git 管理する Terraform テンプレートから、メインモジュールとサブモジュールを通じて AWS Cloud Control Provider が SageMaker Unified Studio ドメインと IAM ロールをプロビジョニングする流れを示しています。

🚀 主要機能

🧩 メインモジュールによるドメインのプロビジョニング

  • terraform-aws-sagemaker-unified-studio がドメインのインフラを構築
  • ドメインに必要な IAM ロールをモジュールがプロビジョニング
  • バージョン管理されたテンプレートによる宣言的なデプロイが可能

🔧 独立して利用できるサブモジュール

  • blueprint でブループリントを有効化
  • project-profile でブループリントを組み合わせプロファイルを構成
  • project でプロジェクトプロファイルからプロジェクトを作成
  • 必要な単位で構成要素を独立して管理できる

🔑 既存 IAM ロールの利用

  • 新規ロール作成に加え、既存 IAM ロールを指定してプロジェクトを作成できる
  • 標準ロールが既に存在するアカウントでも安全に実行できる

🔌 AWS Cloud Control Provider による統合

  • 統合は Terraform AWS Cloud Control Provider (awscc) を通じて実現
  • AWS Cloud Control API により新しい AWS 機能へ迅速に追従できる

🔬 技術仕様

主なサブモジュール

サブモジュール役割
blueprintドメイン上で環境ブループリントを有効化する
blueprint-bootstrapブループリント用の Provisioning / ManageAccess IAM ロールを作成する
project-profile複数のブループリントを組み合わせてプロファイルを構成する
default-project-profileToolingLite、S3Bucket、S3TableCatalog を有効化しデフォルトプロファイルを作成
projectプロジェクトプロファイルからプロジェクトを作成する
project-membershipプロジェクトにオーナーやコントリビューターを追加する
domain-management-portal管理ポータル用の管理プロジェクトを作成する
policy-grant-create-projectドメインに対して CREATE_PROJECT ポリシーを付与する

サブモジュールの構成はオープンソースリポジトリの内容に基づく。利用時は最新のドキュメントを確認してください。

ステップ 1: メインモジュールの定義

HCL main.tf 
module "domain" {
  source = "aws-ia/sagemaker-unified-studio/aws"

  domain_name = "my-unified-studio-domain"
  vpc_id      = "vpc-0abc123def456"
  subnet_ids  = ["subnet-0aaa111", "subnet-0bbb222"]

  tags = {
    Environment = "dev"
  }
}

vpc_id と subnet_ids が必須。ドメイン名、IAM ロール、S3 バケットなどは省略時に自動生成されます。

ステップ 2: プロビジョニングの適用

Bash
terraform init
terraform plan
terraform apply

init でプロバイダーとモジュールを初期化、plan で作成リソースを確認、apply で実際にドメインをプロビジョニングします。

ステップ 3: リソースの削除時の注意

Bash
aws s3 rm s3://<bucket-name> --recursive
terraform destroy

S3 バケットは force_destroy が無効なため、terraform destroy 前にオブジェクトを空にする必要があります。

✓Cloud Control 活用: 新機能へ迅速に追従できる

✗利用可能リージョンは SageMaker Unified Studio 提供リージョンに限定

🎯 ユースケース

ユースケース 1: マルチアカウントでの一貫した環境構築

シナリオ: 開発・ステージング・本番で別アカウントを利用し、ドメインを同一構成で展開したい。

HCL
module "domain" {
  source      = "aws-ia/sagemaker-unified-studio/aws"
  domain_name = "analytics-${var.environment}"
  vpc_id      = var.vpc_id
  subnet_ids  = var.subnet_ids
}

効果: 環境ごとの変数を切り替えるだけで同一テンプレートを再利用し、アカウント間の一貫性を維持できる。

ユースケース 2: ブループリントとプロジェクトの段階的な管理

シナリオ: ドメイン作成とプロジェクト作成を別チームが担当し、責務を分離して管理したい。

HCL
module "blueprint" {
  source    = "aws-ia/sagemaker-unified-studio/aws//modules/blueprint"
  domain_id = module.domain.domain_id
}

効果: サブモジュールで構成要素を独立管理し、チーム間の責務分離とパイプライン整理が可能。

ユースケース 3: 既存 IAM ロールを利用したプロジェクト作成

シナリオ: 組織で IAM ロールを一元管理しており、SageMaker Unified Studio でも既存ロールを再利用したい。

HCL
module "project" {
  source             = "aws-ia/sagemaker-unified-studio/aws//modules/project"
  domain_id          = module.domain.domain_id
  project_profile_id = module.project_profile.id
  # 既存ロールの ARN を指定して再利用
}

効果: 新規ロールを作成せず既存 IAM ロールを利用でき、組織のガバナンスポリシーに準拠できる。

💰 料金・利用可能リージョン

💰 料金

Terraform モジュール自体は オープンソースで無料 です。 SageMaker Unified Studio ドメインおよびプロビジョニングされる AWS リソース (コンピュート、ストレージなど) には 通常の料金が適用されます。

🌍 利用可能リージョン

Amazon SageMaker Unified Studio が利用可能な すべての AWS リージョン で提供されます。 対応リージョンの一覧は管理者ガイドを参照してください。

🔗 関連サービス・機能

Amazon SageMaker Unified Studio: 本モジュールのプロビジョニング対象。データ、分析、AI/ML の開発を統合する環境
Terraform AWS Cloud Control Provider (awscc): Cloud Control API を通じて新しい AWS リソースを Terraform から迅速に扱えるプロバイダー
AWS Cloud Control API: AWS リソースを標準化された API で作成、参照、更新、削除するためのサービス

📝 まとめ

このアップデートにより、Amazon SageMaker Unified Studio を Terraform ベースの IaC で 宣言的に管理できるようになりました。マルチアカウント環境で一貫した構成を維持したいプラットフォームチームに特に有用です。 まずは terraform-aws-sagemaker-unified-studio モジュールをテスト環境で試し、既存の IaC パイプラインへの 統合方法を検討することをおすすめします。
