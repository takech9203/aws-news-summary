AWS Transform 🌏 アジアパシフィック シンガポール

🤖 AWS Transform for migrations
シンガポールリージョン提供開始

📅 リリース日: 2026 年 10 月 15 日 | エージェント型 AI による移行サービスのリージョン拡大

📝 概要

AWS Transform for migrations が、アジアパシフィック (シンガポール) リージョンで利用可能になりました。移行作業中のデータをリージョン内に保持 (データレジデンシー) できるとともに、ローカルのソースインフラストラクチャに対するレイテンシーを低減しながら移行を進められます。

AWS Transform は、エージェント型 AI を活用したコラボレーション型のエンタープライズ IT トランスフォーメーションサービスです。目的別に構築された AI エージェントが、ディスカバリー、ウェーブプランニングからネットワーク変換、テスト・カットオーバーインスタンスの起動まで、移行ライフサイクル全体を自動化します。

❌ Before: アップデート前の課題
  • 東南アジアのお客様は東京、シドニー、ムンバイなど地理的に離れたリージョンのワークスペースを使用する必要があった
  • 移行ジョブのデータがシンガポール国外で処理・保存されるため、国内データ保持要件を持つお客様は利用のハードルが高かった
  • ソースインフラストラクチャと実行リージョンが離れていることで、ディスカバリーや移行作業時のレイテンシーが大きかった
✅ After: アップデート後の改善
  • シンガポールリージョンに AWS Transform のワークスペースを作成し、移行ジョブをリージョン内で実行可能に
  • 移行作業中のデータをシンガポールリージョン内に保持でき、データレジデンシー要件への対応が容易に
  • ローカルのソースインフラストラクチャに近いリージョンで移行を実行し、レイテンシーを低減

⚡ 主要機能

🌏 シンガポールリージョンでの移行ジョブ実行
✓シンガポールリージョンにワークスペースを作成し、移行ジョブを実行可能
✓ワークスペースを作成したリージョンがジョブの実行リージョンとなり、ディスカバリーもそのリージョンで実行
✓移行作業中のデータをリージョン内に保持でき、データレジデンシー要件に対応
🔄 移行ライフサイクル全体の自動化
✓ディスカバリー: AWS Application Discovery Service のコレクター、オープンソースの Export for vCenter ツール、独自収集データのインポートなど柔軟な選択肢
✓インテリジェントな移行プランニング: アプリケーションの自動グルーピングと移行ウェーブの順序付け
✓AI 駆動のネットワーク移行: ソースのネットワーク構成を本番利用可能な Amazon VPC アーキテクチャへ変換
✓自動化されたサーバーリホスト: ガイド付きのテストとカットオーバーワークフローで Amazon EC2 へ移行
🖥️ 幅広いソース環境のサポート
✓VMware、Hyper-V、KVM、ベアメタル、ハイブリッド環境など事実上あらゆるソースに対応
✓Windows および Linux のサポート対象オペレーティングシステムの移行をサポート
✓チーム、ツール、ワークフローを単一のコラボレーションワークベンチに統合

🔧 技術仕様: リージョンとジョブの関係

項目詳細
ワークスペースとジョブ ジョブを作成したワークスペースのリージョンが、そのジョブの AWS リージョンとなる。別リージョンでジョブを作成するには、そのリージョンに別のワークスペースが必要
ディスカバリー VMware プロジェクトでは、ワークスペースのリージョンがディスカバリーに使用される
移行ターゲット 移行先 (ターゲット) リージョンはワークスペースとは別のリージョンを指定可能。移行完了後のワークロードはターゲットリージョンでホストされる
シンガポールリージョンの対象 VMware (migrations) エージェントのみが対象
クロスリージョン処理 リクエストの内容によっては、データがワークスペースとは異なるリージョンで処理される場合がある

🛠️ 設定方法

📋 前提条件

✓管理者アクセス権を持つ AWS アカウント
✓IAM Identity Center の有効化と AWS Transform へのユーザー・コラボレーターの設定
✓ソース環境のディスカバリーデータ (AWS Application Discovery Service、Export for vCenter、または独自収集データ)

🚀 手順

1
シンガポールリージョンにワークスペースを作成する
AWS Transform のウェブエクスペリエンスにサインインし、アジアパシフィック (シンガポール) リージョンを選択してワークスペースを作成します。ワークスペースのリージョンが移行ジョブの実行リージョンとなります。
2
移行ジョブを作成し、ソースデータを取り込む
ワークスペース内で migrations の移行ジョブを作成し、ディスカバリーデータを取り込みます。会話型インターフェースを通じて AI エージェントがステップごとにガイドします。
3
移行プランの確認からカットオーバーまで実行する
AI エージェントが生成したアプリケーションのグルーピングと移行ウェーブを確認し、ネットワーク変換の結果をレビューした上で、テストインスタンスとカットオーバーインスタンスの起動を実行します。移行先のターゲットリージョンは、要件に応じてワークスペースとは別のリージョンを指定できます。

💡 メリット

💼 ビジネス面
✓データレジデンシー要件への対応: 移行作業中のデータをシンガポールリージョン内に保持でき、国内のデータ保持要件を持つ組織でも採用しやすい
✓移行プロジェクトの加速: AI エージェントによる自動化で、大規模移行で従来必要だった手作業を削減
✓追加コストなしで利用可能: 移行エージェントは無料で提供、リージョン拡大による追加料金もなし
⚙️ 技術面
✓レイテンシーの低減: 東南アジアのローカルソースインフラストラクチャに近いリージョンでディスカバリーと移行を実行
✓移行ライフサイクルの一元化: ディスカバリーからカットオーバーまで単一のワークベンチで完結
✓柔軟なターゲットリージョン指定: ワークスペースはシンガポールに置きつつ、移行先は別リージョンを指定する構成も可能

⚠️ デメリット・制約事項

🚧 制限事項

✗シンガポールリージョンで利用できるのは VMware (migrations) エージェントのみで、メインフレームモダナイゼーションや Windows モダナイゼーションなど他の機能は対象外
✗ジョブのリージョンはワークスペース作成時のリージョンで決まるため、別リージョンでジョブを実行するには別のワークスペースが必要

🔍 考慮すべき点

⚠️リクエストの内容によっては、データがワークスペースとは異なるリージョンで処理される場合があるため、厳格なデータレジデンシー要件がある場合はクロスリージョン処理に関するドキュメントの確認を推奨
⚠️AWS Transform の出力により作成される EC2 インスタンスや VPC などの AWS リソースには、各サービスの通常の利用料金が発生

🎯 ユースケース

1️⃣ シンガポール国内のデータ保持要件を満たす VMware 移行

シナリオ: シンガポールの金融機関が、オンプレミスの VMware 環境を Amazon EC2 へ移行するにあたり、移行作業中のデータを国内に保持する必要がある。

Text実装例
1. アジアパシフィック (シンガポール) リージョンに AWS Transform ワークスペースを作成
2. VMware 環境のディスカバリーデータを取り込み、移行ジョブを実行
3. ターゲットリージョンにもシンガポールを指定し、国内で移行を完結
💡 効果: 移行作業中のデータと移行後のワークロードの両方をシンガポール国内に保持し、規制要件を満たしながら移行を加速できる。
2️⃣ 東南アジア拠点のハイブリッド環境の大規模移行

シナリオ: 東南アジアに複数拠点を持つ企業が、VMware、Hyper-V、ベアメタルが混在するハイブリッド環境を AWS へ移行したい。

Text実装例
1. シンガポールリージョンのワークスペースで各ソース環境のディスカバリーデータを統合
2. AI エージェントがアプリケーションをグルーピングし、移行ウェーブを自動計画
3. ネットワーク変換とサーバーリホストをウェーブごとに実行
💡 効果: 混在環境の移行計画を自動化し、拠点に近いリージョンで低レイテンシーに移行作業を進められる。
3️⃣ ローカルソースへの低レイテンシーなディスカバリー

シナリオ: シンガポールのデータセンターで稼働する大規模な VMware 環境に対して、ディスカバリーとウェーブプランニングを効率的に実施したい。

Text実装例
1. AWS Application Discovery Service のコレクターまたは Export for vCenter でソースデータを収集
2. シンガポールリージョンのワークスペースにデータを取り込み、依存関係を分析
3. 7Rs 戦略レポートや構成図を生成し、移行プランを策定
💡 効果: ソースインフラストラクチャに近いリージョンで処理することで、ディスカバリーから計画策定までを低レイテンシーで実行できる。

🔗 関連サービス・機能

🔍 AWS Application Discovery Service

ソース環境のディスカバリーデータ収集に使用されるサービス。AWS Transform のアシスト付きディスカバリーと連携。

🔄 AWS Application Migration Service (MGN)

サーバーリホストの基盤となる移行サービス。テスト・カットオーバーインスタンスの起動を支える。

⚙️ Amazon EC2

移行先のコンピューティングサービス。Windows および Linux サーバーをネイティブに実行。

✅ まとめ

AWS Transform for migrations がアジアパシフィック (シンガポール) リージョンで利用可能になり、東南アジアのお客様はデータレジデンシー要件を満たしながら、ローカルのソースインフラストラクチャへの低レイテンシーな移行を実行できるようになりました。シンガポール国内でのデータ保持が必要な移行プロジェクトを検討しているお客様は、シンガポールリージョンにワークスペースを作成し、AI エージェントによる移行ライフサイクルの自動化を活用することを推奨します。
