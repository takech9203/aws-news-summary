AWS End User Messaging

📨 RCS リッチメディア＆インタラクティブメッセージング

SendRcsMessage API で会話の中に Web / アプリ体験を取り込む
リリース日
2026.06.30

🎯 概要

AWS End User Messaging が RCS (Rich Communication Services) のリッチメディアおよびインタラクティブメッセージングに対応しました。新しい SendRcsMessage API で、リッチカード、カルーセル、画像、動画、インタラクティブな提案ボタンを送信でき、受信者はメッセージングアプリ内で直接アクションを実行できます。

RCS は SMS の後継となるメッセージング標準です。受信者はアプリを離れることなく、予約確認・カタログ閲覧・Webview での支払い・現在地共有・AI エージェントとの対話を完結できます。RCS 非対応の受信者には SMS / MMS フォールバックで到達性を確保します。

🔄 Before / After

⛔ アップデート前の課題
  • テキスト中心のメッセージングが主体で、リッチカードやカルーセルを活用しにくかった
  • アクションを促す際、アプリ外部 (Web / 別アプリ) への遷移が必要で離脱が発生しやすかった
  • 双方向ワークフローでメッセージごとの課金がコスト面の懸念だった
✅ アップデート後の改善
  • 4 種のメッセージタイプ × 6 種のアクションを組み合わせ、リッチでインタラクティブに送信可能
  • 予約確認・カタログ閲覧・Webview 支払い・現在地共有・AI 対話をアプリ内で完結
  • 24 時間セッション内メッセージ数無制限の定額制 RCS Conversation 料金を導入

⭐ 主要機能

📇 4 種類の RCS メッセージタイプ
  • テキスト: 従来同様のテキストメッセージ
  • ファイル: 画像や動画などのメディアファイルを送信
  • リッチカード: タイトル・説明・メディア・提案ボタンを含む単一カード
  • カルーセル: 複数のリッチカードを横並びでスワイプ表示
👆 6 種類のアクション (提案)
返信 Replies URL Webview 電話発信 地図 Maps カレンダーイベント

ワンタップ返信、Web 表示、アプリ内での支払い完結、発信促進、現在地共有、予定登録などを実現。任意のメッセージタイプと組み合わせて利用できます。

🔁 設定可能な SMS / MMS フォールバック
  • 受信者が RCS 非対応の場合に備え、メッセージごとに SMS / MMS フォールバックを設定可能
  • 受信者の環境に依存せず到達性を確保
🤖 AI エージェントとの連携
  • RCS をバックエンド・データ・AI をエンドユーザーに接続するインターフェイス層として活用
  • 受信者はメッセージングアプリを離れることなく AI エージェントと対話可能

⚙️ 設定方法

前提条件

✓AWS End User Messaging が利用可能なリージョンでアカウントが有効化されていること
✓RCS for business のオンボーディングが完了し、RCS エージェントが登録されていること
✓送信元の電話番号またはオリジネーションアイデンティティが構成済みであること

導入の流れ

📋 STEP 1
エージェント確認
→
📤 STEP 2
リッチメッセージ送信
→
📥 STEP 3
アクションのハンドリング
BashSTEP 1: RCS エージェントの確認
aws pinpoint-sms-voice-v2 describe-rcs-agents

登録済みエージェントの状態を確認します。リッチメッセージの送信には承認済みエージェントが必要です。

BashSTEP 2: リッチメッセージの送信
aws pinpoint-sms-voice-v2 send-rcs-message \
  --destination-phone-number "+81XXXXXXXXXX" \
  --origination-identity "your-rcs-agent-id" \
  --rcs-message-content file://rich-card.json

rich-card.json にリッチカードやカルーセル、提案ボタンの定義を記述。RCS 非対応の受信者向けにはメッセージコンテンツ内でフォールバック設定を指定します。

STEP 3: 受信者アクションのハンドリング

受信者が提案ボタンをタップした際の返信やアクションは、設定セットに紐づけたイベント送信先 (Amazon SNS、Amazon Kinesis Data Firehose など) を通じて受け取れます。これにより AI エージェントやバックエンドワークフローと連携できます。

📈 ビジネス面

✓顧客エンゲージメント向上: リッチカード / カルーセルでテキスト SMS より訴求力の高いコミュニケーション
✓コンバージョン率向上: 予約確認・支払いをアプリ内で完結し、外部遷移による離脱を削減
✓コスト予測の容易化: RCS Conversation 料金により 24 時間セッション内のメッセージ数が無制限の定額制

🛠️ 技術面

✓単一 API での実装: SendRcsMessage でリッチメディアとインタラクティブ要素をまとめて送信
✓到達性の確保: SMS / MMS フォールバックで受信者の対応状況に依存せず配信
✓AI / バックエンド連携: イベント送信先で受信者アクションを取得し統合可能

⚠️ デメリット・制約事項

制限事項

▲利用には RCS for business のオンボーディングと承認済みエージェントが必要
▲リッチメディア / インタラクティブメッセージングはサポート対象の 22 か国に限定
▲RCS Conversation 料金は 21 か国が対象で、対応国は料金体系が異なる場合がある

考慮すべき点

▲RCS 非対応端末・キャリアではフォールバックが発生するため、料金とメッセージ設計を考慮
▲リッチコンテンツに使用するメディアファイルのホスティングとサイズ要件を事前確認
▲国ごとに対応状況や規制が異なるため、配信対象国ごとの要件確認が必要

📋 ユースケース

1. 予約確認とリマインダー

飲食店や医療機関が予約リマインダーをリッチカードで送信し、受信者がワンタップで予約確定・カレンダー登録できるようにする。

構成例
リッチカード (店舗画像 + 予約日時)
  + 提案ボタン: [予約を確定する]   (返信)
  + 提案ボタン: [カレンダーに追加] (カレンダーイベント)
  + 提案ボタン: [地図を見る]       (地図)
➜ 効果: 予約のノーショー (無断キャンセル) を削減し、顧客の利便性を向上
2. 商品カタログと購入

EC 事業者が複数商品をカルーセルで提示し、受信者が Webview で支払いまで完結できるようにする。

構成例
カルーセル (複数のリッチカード)
  各カード: 商品画像 + 価格
  + 提案ボタン: [今すぐ購入]   (Webview)
  + 提案ボタン: [詳細を見る]   (URL)
➜ 効果: アプリ内のシームレスな購買体験でコンバージョン率を向上
3. AI エージェントによるカスタマーサポート

サポート窓口が RCS を通じて AI エージェントとの対話を提供し、よくある問い合わせを自動応答する。

構成例
テキストメッセージ (AI エージェントの応答)
  + 提案ボタン: [はい / いいえ]   (返信)
  + 提案ボタン: [担当者に電話]     (電話発信)
➜ 効果: 24 時間セッションの定額料金を活用し、コストを抑えつつ双方向サポートを実現

💰 料金・利用可能リージョン

RCS Conversation 料金 (新規導入)

21 か国向けに導入。24 時間セッション内でメッセージ数無制限の定額制料金体系で、双方向のやり取りが多いワークフローのコストを予測しやすくします。料金は国や送信内容で異なり、SMS / MMS フォールバック発生時はそれぞれの料金が別途適用されます。

AWS End User Messaging が利用可能なすべての AWS リージョンで利用できます。リッチメディア / インタラクティブメッセージングは 22 か国、RCS Conversation 料金は 21 か国で利用可能です。

📝 まとめ

今回のアップデートにより、AWS End User Messaging の RCS でリッチカード、カルーセル、インタラクティブな提案ボタンを活用でき、メッセージングアプリ内で予約確認・購入・AI 対話などを完結できるようになりました。双方向ワークフロー向けの定額制 RCS Conversation 料金も導入されています。SMS や MMS を活用している企業は、SendRcsMessage API と RCS エージェントの構成を確認し、リッチでインタラクティブな顧客コミュニケーションの導入を検討することをおすすめします。
