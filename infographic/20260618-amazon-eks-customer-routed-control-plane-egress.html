📌 概要

Amazon EKS は、Kubernetes API サーバーからのアウトバウンドトラフィックを お客様自身の Amazon VPC 経由でルーティングできる新機能を発表しました。 コントロールプレーンが外部リソースへ通信する際の経路・セキュリティグループ・エグレスパスをお客様が制御できます。

対象トラフィックは アドミッション Webhook のコールバック、 OpenID Connect (OIDC) プロバイダーのルックアップ、 集約 API サーバー (Aggregate API server) へのリクエストです。 これらをお客様の VPC 経由に切り替えることで、VPC 内にのみ存在するプライベートな OIDC プロバイダーや Webhook サーバーへ到達できるようになります。

🎯 主な対象は、データ境界 (data perimeter) 要件・コンプライアンス要件・ プライベートネットワークインフラを持つ組織。すべての EKS 利用可能リージョンで追加費用なしで利用できます。

😟 アップデート前の課題

  • コントロールプレーンからのアウトバウンド経路をお客様が制御できなかった
  • VPC 内のみのプライベート OIDC プロバイダーや Webhook サーバーへ到達困難だった
  • エグレストラフィックに独自のセキュリティグループやデータ境界ポリシーを適用できなかった

😄 アップデート後の改善

  • API サーバーのアウトバウンドトラフィックを VPC 経由でルーティング可能に
  • プライベート OIDC プロバイダー / Webhook サーバーへ到達可能に
  • 経路・セキュリティグループ・エグレスパスを制御可能に

コントロールプレーンのアウトバウンドトラフィックを CUSTOMER_ROUTED モードに設定することで、 API サーバーからのトラフィックがお客様の VPC を経由し、VPC 内のプライベートリソースへ到達できるようになります。

⚡ 主要機能

🛣️ コントロールプレーンエグレスのカスタマールーティング

  • Kubernetes API サーバーのアウトバウンドトラフィックをお客様の VPC 経由でルーティング
  • トラフィックの経路・セキュリティグループ・エグレスパスをお客様が制御
  • クラスター作成時または既存クラスターの更新時に有効化可能

📡 対象トラフィックの拡大

  • アドミッション Webhook のコールバック
  • OpenID Connect (OIDC) プロバイダーのルックアップ
  • 集約 API サーバー (Aggregate API server) へのリクエスト

🏢 組織全体での適用制御

  • eks:controlPlaneEgressMode IAM 条件キーを利用
  • AWS Organizations の SCP と組み合わせて、組織全体で適用を強制可能

⚙️ 技術仕様

設定項目

項目詳細
設定名controlPlaneEgressMode
設定値CUSTOMER_ROUTED (カスタマールーティングを有効化)
適用タイミングクラスター作成時または既存クラスターの更新時
IAM 条件キーeks:controlPlaneEgressMode
制御単位AWS Organizations の SCP による組織全体への適用
📋 API 変更履歴: 本レポート作成時点で awsapichanges.com 上の対応する EKS API 変更履歴は確認できませんでした。 controlPlaneEgressMode の設定は、EKS クラスターの作成・更新 API を通じて指定します。

設定例 (新規クラスター作成)

Bash create-cluster でカスタマールーティングを有効化 
# 新規クラスター作成時にカスタマールーティングを有効化
aws eks create-cluster \
  --name my-cluster \
  --role-arn arn:aws:iam::111122223333:role/eks-cluster-role \
  --resources-vpc-config subnetIds=subnet-aaaa,subnet-bbbb \
  --control-plane-egress-mode CUSTOMER_ROUTED

正確なパラメータ名や指定方法は、Amazon EKS ユーザーガイドおよび最新の AWS CLI / API リファレンスで確認してください。

🔧 設定方法

前提条件

EKS クラスターを利用できる環境 トラフィックを通す VPC とサブネット クラスター作成・更新の IAM 権限

手順

コントロールプレーンエグレスモードの設定

既存クラスターのエグレスモードを CUSTOMER_ROUTED に更新し、アウトバウンドトラフィックを VPC 経由でルーティング。

Bash
aws eks update-cluster-config \
  --name my-cluster \
  --control-plane-egress-mode CUSTOMER_ROUTED

VPC のルーティングとセキュリティグループの確認

プライベート OIDC プロバイダーや Webhook サーバーへ到達できる構成かを検証。

Bash
aws eks describe-cluster --name my-cluster \
  --query 'cluster.resourcesVpcConfig'

組織全体での適用強制 (任意)

eks:controlPlaneEgressMode IAM 条件キーを利用した SCP を AWS Organizations に適用し、組織内のすべてのアカウントで意図しないエグレス設定を防止。

⚖️ メリット・デメリット

✅ メリット

💼 ビジネス面

  • コンプライアンス対応: エグレスを自社ネットワークポリシーに準拠
  • 追加費用なし: コスト増を抑えつつセキュリティ強化
  • ガバナンス強化: SCP と IAM 条件キーで組織全体に一貫適用

🛠️ 技術面

  • ネットワーク制御の向上: 経路・SG・エグレスパスを細かく制御
  • プライベートリソースへの到達: VPC 内の OIDC / Webhook を利用
  • 既存クラスターへの適用: 新規だけでなく既存でも有効化可能

⚠️ デメリット・考慮点

制限事項

  • 対象は Webhook コールバック / OIDC ルックアップ / 集約 API サーバーリクエストに限定
  • 有効化後はお客様側で適切な VPC ルーティングと SG 構成が必要

考慮すべき点

  • ルーティング / SG 設定が不適切だと Webhook・OIDC 通信が失敗し、クラスター動作に影響の可能性
  • 組織全体適用前に、検証環境でエグレス経路の動作確認を推奨

💡 ユースケース

1. プライベート OIDC プロバイダーの利用

シナリオ社内ネットワーク内 (VPC 内) にのみ公開された OIDC プロバイダーで API サーバーの認証連携を行いたい。

Bash
aws eks update-cluster-config \
  --name corp-cluster \
  --control-plane-egress-mode CUSTOMER_ROUTED

効果 → コントロールプレーンが VPC 経由でプライベート OIDC プロバイダーへ到達。外部公開を伴わずに認証連携を実現。

2. プライベート Webhook サーバーとの連携

シナリオVPC 内にのみ配置したアドミッション Webhook サーバーで、ポリシー検証やリソース変更を行いたい。

Bash
# Webhook サーバーが配置された VPC 経由でエグレスをルーティング
aws eks update-cluster-config \
  --name secure-cluster \
  --control-plane-egress-mode CUSTOMER_ROUTED

効果 → API サーバーから VPC 内の Webhook サーバーへ到達。プライベートネットワーク内でアドミッション制御を完結。

3. 組織全体でのデータ境界の強制

シナリオ規制業種の企業が、すべての EKS クラスターでコントロールプレーンのエグレスを自社 VPC 経由に統一したい。

JSONSCP 例
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Action": ["eks:CreateCluster", "eks:UpdateClusterConfig"],
      "Resource": "*",
      "Condition": {
        "StringNotEquals": {
          "eks:controlPlaneEgressMode": "CUSTOMER_ROUTED"
        }
      }
    }
  ]
}

効果 → SCP により、カスタマールーティング以外の設定でのクラスター作成・更新を拒否し、組織全体でデータ境界を強制。

🔗 関連サービス・機能

🌐 Amazon VPC

コントロールプレーンのアウトバウンドトラフィックをルーティングする経路として使用。

🏢 AWS Organizations (SCP)

eks:controlPlaneEgressMode 条件キーと組み合わせ、組織全体でエグレスポリシーを強制。

🔑 OpenID Connect (OIDC)

コントロールプレーンが認証連携のために参照するプロバイダー。

🛡️ AWS IAM

条件キーによりエグレスモードの設定を制御。

📝 まとめ

カスタマールーティング型コントロールプレーンエグレスは、コントロールプレーンのアウトバウンドトラフィックをお客様の VPC 経由に切り替え、 ネットワーク制御とデータ境界の強制を可能にする重要な機能です。

データ境界要件やコンプライアンス要件を持つ組織は、まず検証環境で controlPlaneEgressMode を CUSTOMER_ROUTED に設定し、プライベート OIDC プロバイダーや Webhook サーバーへの到達性を確認することを推奨します。 組織全体への展開には、SCP と IAM 条件キーによる適用強制を検討してください。
