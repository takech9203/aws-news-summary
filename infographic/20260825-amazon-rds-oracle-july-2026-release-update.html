Amazon RDS for Oracle

🛡️ Oracle 2026 年 7 月 Release Update サポート

📅 リリース日: 2026 年 8 月 25 日 | 対象: Oracle Database 19c / 21c / 26ai

📋 概要

Amazon RDS for Oracle が Oracle 2026 年 7 月 Release Update (RU) をサポート。Oracle Database 19c、21c、26ai の 3 バージョンで利用可能で、セキュリティ更新が含まれるため AWS は速やかなアップグレードを推奨している。

今回から Oracle Database 19c の RU 命名形式が <version>.ru-<YYYY-MM>.mrp-<YYYY-MM>.r<N> に変更され、月次 Critical Security Patch Update (CSPU) を MRP (Monthly Recommended Patch) バージョンとして提供する体系が導入された。21c は従来の命名形式を維持する。

❌ Before: アップデート前の課題
  • 以前の RU では 2026 年 7 月時点の最新セキュリティ脆弱性に未対応
  • 四半期 RU の間に公開されるセキュリティ修正を迅速に適用する標準的な仕組みが限定的
  • 手動パッチ適用は運用負荷が高く、環境間で適用状況にばらつき
✅ After: アップデート後の改善
  • 19c / 21c / 26ai で最新セキュリティパッチをコンソール、SDK、CLI から適用可能
  • 月次 CSPU が MRP として提供され、四半期 RU を待たずにセキュリティ修正を適用
  • Automatic Minor Version Upgrade + Organizations ロールアウトポリシーで段階的な自動適用

2026 年 7 月 RU と月次 MRP バージョンを、コンソール、CLI、自動アップグレード、Organizations ロールアウトポリシーを通じて Oracle 19c / 21c / 26ai インスタンスに適用するフロー。

⭐ 主要機能

1️⃣ 2026 年 7 月 Release Update (RU) のサポート

Oracle データベース製品向けのセキュリティ更新を含む。Oracle Database 19c、21c、26ai の 3 バージョンで利用可能。AWS は最新 RU へのアップグレードを推奨。

2️⃣ Oracle Database 19c の RU 命名形式の変更

2026 年 7 月リリースから 19c の命名形式が <version>.ru-<YYYY-MM>.mrp-<YYYY-MM>.r<N> に変更。7 月四半期 RU のエンジンバージョンは 19.0.0.0.ru-2026-07.mrp-2026-07.r1。21c は従来形式を維持。

3️⃣ 月次 Critical Security Patch Update (CSPU) の MRP 提供

Oracle が 19c および 26ai 向けに月次 CSPU をリリースした場合、Amazon RDS は CSPU と Oracle 推奨の追加修正をバンドルした MRP バージョンとして提供。四半期 RU の間もセキュリティ修正を継続適用可能。

4️⃣ 段階的ロールアウトポリシー

AWS Organizations のアップグレードロールアウトポリシーで自動マイナーバージョンアップグレードを段階的に適用。非本番環境で検証後、同じ更新を本番環境へ自動適用するワークフローを実現。

⚙️ 設定方法

✅ 前提条件

✓Amazon RDS for Oracle インスタンスが稼働していること
✓Oracle Database 19c、21c、または 26ai を使用していること
✓RDS インスタンスへの変更権限 (IAM) を有していること
1
利用可能なエンジンバージョンの確認
BashAWS CLI
aws rds describe-db-engine-versions \
  --engine oracle-ee \
  --query "DBEngineVersions[].EngineVersion" \
  --output table

Oracle Enterprise Edition で利用可能なエンジンバージョンの一覧を取得し、2026 年 7 月 RU のバージョン文字列を確認する。

2
Release Update の適用
BashAWS CLI
aws rds modify-db-instance \
  --db-instance-identifier my-oracle-instance \
  --engine-version 19.0.0.0.ru-2026-07.mrp-2026-07.r1 \
  --apply-immediately

Oracle 19c インスタンスに 2026 年 7 月の RU を即時適用。--no-apply-immediately に変更すると次のメンテナンスウィンドウで適用される。

3
Automatic Minor Version Upgrade の有効化
BashAWS CLI
aws rds modify-db-instance \
  --db-instance-identifier my-oracle-instance \
  --auto-minor-version-upgrade \
  --apply-immediately

今後の RU や MRP がメンテナンスウィンドウ中に自動的に適用されるように設定する。

4
AWS Organizations ロールアウトポリシーの活用

アップグレードロールアウトポリシーを設定すると、自動マイナーバージョンアップグレードを組織内で段階的に展開できる。非本番アカウントの環境へ先に適用して検証した後、同じ更新を本番アカウントの環境へ自動適用する運用が可能。詳細は Amazon RDS for Oracle ドキュメントを参照。

✓柔軟なデプロイメント: 即時適用、メンテナンスウィンドウ適用、自動適用、組織全体での段階的適用から選択可能

⚠️ デメリット・制約事項

🚧 制限事項

✗パッチ適用時にインスタンスの再起動が発生するため、短時間のダウンタイムが必要
✗月次 CSPU の MRP 提供は 19c および 26ai が対象であり、21c は対象外
✗21c は Oracle のサポートポリシー上イノベーションリリースであるため、長期運用には 19c または 26ai の利用を検討する必要がある

🤔 考慮すべき点

⚠19c の RU 命名形式の変更に伴い、エンジンバージョンを指定する IaC テンプレートや運用スクリプトの更新が必要になる場合がある
⚠パッチ適用前にスナップショットを取得し、ロールバック計画を策定することを推奨
⚠段階的ロールアウトを使用する場合、AWS Organizations の設定が必要
