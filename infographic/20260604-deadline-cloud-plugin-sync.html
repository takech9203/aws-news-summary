🎬 サービスマネージドフリートのプラグイン同期

Plugin Sync for Service-Managed Fleets

📅 2026 年 6 月 4 日

📋 概要

AWS Deadline Cloud にサービスマネージドフリート向けのプラグイン同期機能が追加された。S3 バケットの所定パスにプラグインファイルをアップロードするだけで、ジョブセッション開始時にワーカーへ自動的に同期される。

ワークステーション上の共有フォルダにプラグインをコピーするのと同じ感覚で利用でき、VFX、アニメーション、ゲームなどのコンピュートインテンシブなワークロードのパイプライン構築を大幅に簡素化する。

⚡ 主要機能

🔄 自動プラグイン同期

ジョブセッション開始時にワーカーのセッションディレクトリへ自動同期。DCC アプリケーション用の conda パッケージが、同期されたディレクトリからプラグインを読み込むよう自動設定される。手動介入なしで正しいプラグインがワーカーに配置される。

🪣 S3 ベースのプラグイン管理

キューのジョブアタッチメント S3 バケット内の規定パス構造に従ってアップロード。OS、DCC アプリケーション名、バージョンごとにフォルダを分離し、共有フォルダ感覚でプラグインファイルを配置可能。

📦 マルチバージョン対応

同一 DCC アプリケーションの複数バージョンを同時にサポート。メジャーバージョン単位での管理 (例: Maya 2025.3 は 2025 フォルダを使用)。Linux と Windows の両 OS に対応。

API 変更

直近 7 日間で Deadline Cloud に関連する API 変更は検出されなかった。本機能は既存の S3 およびジョブアタッチメントの仕組みを活用しており、新規 API の追加なしで実現されている。

🛠️ 設定方法

前提条件

  • AWS Deadline Cloud ファームとキューが作成済み
  • キューにジョブアタッチメント S3 バケットが関連付けられている
  • サービスマネージドフリートが設定済み
  • プラグインファイルが手元に用意されている

Step 1: S3 バケットとルートプレフィックスの確認

Bash キューの詳細を取得 
# AWS CLI でキューの詳細を取得し、ジョブアタッチメントバケット情報を確認
aws deadline get-queue \
  --farm-id farm-xxxxxxxxxxxx \
  --queue-id queue-xxxxxxxxxxxx \
  --query 'jobAttachmentSettings'

Step 2: プラグインフォルダ構造の作成

Bash Maya 2025 用フォルダ作成 
# 例: Maya 2025 用のプラグインフォルダを Linux 向けに作成
aws s3api put-object \
  --bucket my-farm-attachments \
  --key "Data/plugins/linux/maya/2025/"

Step 3: プラグインファイルのアップロード

Bash プラグインアップロード 
# プラグインファイルを S3 にアップロード
aws s3 cp ./my-plugin.py \
  s3://my-farm-attachments/Data/plugins/linux/maya/2025/my-plugin.py

# ディレクトリごとアップロードする場合
aws s3 sync ./my-plugins/ \
  s3://my-farm-attachments/Data/plugins/linux/maya/2025/

Step 4: ジョブの送信と動作確認

Bash ジョブ送信 
# ジョブを送信してプラグイン同期の動作を確認
aws deadline create-job \
  --farm-id farm-xxxxxxxxxxxx \
  --queue-id queue-xxxxxxxxxxxx \
  --template file://job-template.yaml

✅ メリット

ビジネス面

🚀 パイプライン構築時間の短縮

カスタムスクリプト開発が不要になり、新規プロジェクトの立ち上げが迅速化される。

💰 運用コスト削減

プラグイン配信の手動管理が不要になり、パイプライン TD の負担が軽減される。

🎯 品質向上

設定ミスによるレンダリング失敗が減少し、やり直しコストが削減される。

技術面

🏗️ シンプルなアーキテクチャ

カスタムスクリプトやカスタム AMI の管理が不要。S3 アップロードのみで完結する。

📂 バージョン管理の明確化

OS とバージョンごとにフォルダが分離されるため、プラグインの管理が容易になる。

⚙️ 自動化との統合

CI/CD パイプラインから S3 にプラグインをデプロイするだけで全ワーカーに反映される。

⚠️ デメリット・制約事項

制限事項

  • 現時点で GA 対応しているのは Blender と Autodesk Maya のみ
  • サービスマネージドフリート専用 (カスタマーマネージドフリートは conda レシピサンプルで対応)
  • S3 パスは大文字・小文字を厳密に区別する (全て小文字で指定)
  • パッチバージョン単位での分離は不可 (メジャーバージョン単位)

考慮すべき点

  • プラグインファイルのサイズが大きい場合、セッション開始時の同期に時間がかかる可能性
  • S3 ストレージコストが追加で発生 (標準 S3 料金)
  • 実行中のジョブセッションには反映されない (次回セッション開始時に反映)

💡 ユースケース

🎬 VFX スタジオでのレンダリングプラグイン配布

Maya 用のカスタムシェーダープラグインを多数のクラウドワーカーに配布するシナリオ。Linux/Windows 両方のワーカーに同じプラグインを自動配布し、レンダリング時に必要なシェーダーを確実に利用可能にする。

Bash マルチ OS プラグイン配置 
# カスタムシェーダープラグインをアップロード
aws s3 sync ./studio-shaders/ \
  s3://vfx-farm-attachments/Data/plugins/linux/maya/2025/

# Windows ワーカー用にも同じプラグインを配置
aws s3 sync ./studio-shaders-win/ \
  s3://vfx-farm-attachments/Data/plugins/windows/maya/2025/

🎨 Blender アドオンのバージョン管理

アニメーションスタジオが複数の Blender バージョンを併用し、各バージョンに対応するアドオンを管理。バージョンごとにフォルダが分離されるため、プラグインの混在リスクを排除できる。

Bash マルチバージョン管理 
# Blender 5.0 用アドオン
aws s3 sync ./addons-5.0/ \
  s3://anim-farm-attachments/Data/plugins/linux/blender/5.0/

# Blender 5.1 用アドオン
aws s3 sync ./addons-5.1/ \
  s3://anim-farm-attachments/Data/plugins/linux/blender/5.1/

🔄 CI/CD パイプラインとの統合

プラグインのビルドとデプロイを自動化。Git でソースコードを管理し、変更が push されると自動的に S3 へデプロイ、次のジョブセッションから最新プラグインが利用可能に。

YAML GitHub Actions デプロイ例 
name: Deploy Plugins
on:
  push:
    paths: ['plugins/**']
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789012:role/plugin-deploy
      - run: |
          aws s3 sync ./plugins/maya/2025/ \
            s3://farm-attachments/Data/plugins/linux/maya/2025/

📝 まとめ

AWS Deadline Cloud のプラグイン同期機能は、サービスマネージドフリートにおけるプラグイン配信の複雑さを解消する重要なアップデート。S3 バケットへのアップロードのみで自動的にワーカーへプラグインが同期されるため、VFX やアニメーションスタジオのパイプライン構築と運用が大幅に効率化される。

Blender と Maya を利用しているチームは、既存のカスタムスクリプトをこの機能に置き換えることで、運用負担の軽減と設定ミスの削減を実現できる。
