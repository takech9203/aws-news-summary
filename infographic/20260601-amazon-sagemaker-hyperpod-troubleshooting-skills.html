📋 概要

Amazon SageMaker HyperPod が AI コーディングアシスタント向けのトラブルシューティングスキルを提供開始。Claude Code、Cursor、Kiro などの AI コーディングアシスタントにエキスパートレベルの AI/ML クラスター診断機能を直接統合し、自然言語でクラスターの問題を診断・解決できるようになる。

オープンソース (Apache 2.0) として GitHub awslabs/agent-plugins で公開。Slurm および Amazon EKS の両方に対応。

❌ Before

  • GPU 障害、NCCL エラー、パフォーマンスボトルネック特定は複雑で時間がかかる
  • 手動で各ノードに SSM 接続し、多数のインスタンスにまたがるログを解析
  • 分散トレーニング・推論インフラのトラブルシューティングには高度な専門知識が必要

✅ After

  • 自然言語でクラスター問題を診断・解決、必要な時間と専門知識を大幅削減
  • クラスターヘルス検証、ハードウェア・通信診断、バージョンドリフト検出を統合利用
  • 既存の HyperPod インフラにそのまま適用、変更不要

🔧 主要機能 - 8 つの診断スキル

🖥️ HyperPod Cluster Debugger
  • クラスター作成・デプロイ障害の診断
  • EFA ヘルスチェック
  • ライフサイクルスクリプトエラーの特定
  • キャパシティ問題の分析
🔗 HyperPod NCCL Debugger
  • AllReduce タイムアウトの診断
  • EFA/libfabric エラーの特定
  • ランデブー障害の分析
  • コンテナ OOM の検出
🔬 HyperPod Node Debugger
  • GPU ハードウェア障害 (XID, ECC, NVLink)
  • EFA 問題の特定
  • ディスク・メモリプレッシャーの検出
  • コンテナランタイム問題の分析
📈 HyperPod Performance Debugger
  • ノード間の NCCL 帯域幅不均一性の検出
  • ファイルシステムスループット問題
  • ストラグラーノードの特定
📋 HyperPod Slurm Debugger
  • ノードの down/drain 状態の診断
  • ジョブペンディング停止の問題
  • GRES ミスカウントの検出
  • auto-resume 障害の分析
🛠️ 補助スキル
  • hyperpod-ssm: リモートコマンド実行・ファイル転送
  • hyperpod-version-checker: バージョンドリフト検出
  • hyperpod-issue-report: 診断レポート自動生成

💡 ユースケース

🔥 ユースケース 1: GPU ハードウェア障害の迅速な診断

大規模分散トレーニング中に特定のノードで XID エラーが発生し、トレーニングジョブが停止。

入力例: "A node in my cluster is unhealthy, I'm seeing XID errors. Diagnose it."

→ hyperpod-node-debugger が GPU 状態、ECC エラー、NVLink ステータスを確認し、障害ハードウェアを特定して交換推奨を提示

🔗 ユースケース 2: NCCL 通信障害のトラブルシューティング

数百 GPU の分散トレーニングで AllReduce 操作がタイムアウトし、トレーニングが進まない。

入力例: "Training is hanging with NCCL timeout errors on my 256-GPU cluster"

→ hyperpod-nccl が EFA 設定、ネットワークトポロジー、NCCL 環境変数を検査し、通信障害の根本原因と修正手順を提供

🔄 ユースケース 3: ソフトウェアバージョンドリフトの検出

クラスター拡張後に一部のノードで異なるバージョンの CUDA ドライバーが動作し、パフォーマンスが不安定。

入力例: "Check the software versions on all nodes in my HyperPod cluster"

→ hyperpod-version-checker がクラスター全ノードのバージョンを比較し、ドリフト検出ノードと修正手順を報告

⚠️ 制限事項・注意点

制限事項

✗AI コーディングアシスタント (Claude Code, Cursor, Kiro) のいずれかが必要
✗SSM エージェントがクラスターノードに正しく設定されている必要あり
✗AmazonSageMakerFullAccess 相当の IAM 権限が必要
✗Slurm Debugger は EKS オーケストレーションのクラスターでは使用不可

考慮すべき点

⚡複雑な問題では AI 推論に依存するため、追加の手動調査が必要な場合あり
⚡クラスター規模やノード数によって診断時間が変動
⚡Kiro IDE では "vibe" モードで正しくトリガーされるが、"spec" モードでは一貫性が低い場合あり

📌 まとめ

Amazon SageMaker HyperPod のトラブルシューティングスキルは、分散 AI/ML インフラの運用における障害診断の複雑さを、AI コーディングアシスタントとの統合によって解決するアップデート。GPU 障害、NCCL 通信エラー、パフォーマンスボトルネックなどの問題を自然言語で診断でき、専門知識の有無にかかわらず迅速な問題解決が可能に。

推奨: HyperPod を利用している組織は、既存のインフラを変更することなく即座にこのスキルを導入し、運用効率の向上を図ることを推奨。
