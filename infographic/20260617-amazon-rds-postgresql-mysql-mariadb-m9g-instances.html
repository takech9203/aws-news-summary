🛢️ M9g データベースインスタンスのサポート

AWS Graviton5 プロセッサ搭載 M9g インスタンスが PostgreSQL / MySQL / MariaDB で一般提供開始
リリース日
2026.06.17

📌 概要

AWS は、独自設計のカスタムプロセッサ最新世代 AWS Graviton5 を搭載した M9g データベースインスタンスを、Amazon RDS for PostgreSQL / MySQL / MariaDB の 3 つのオープンソースエンジン向けに一般提供開始しました。Graviton5 は AWS Nitro System 上に構築されています。

M9g は汎用ワークロード向けに最適化されたインスタンスです。新たに 24xlarge / 48xlarge サイズが追加され、最大 192 vCPU、最大 100Gbps の拡張ネットワーク帯域幅、Amazon EBS への最大 72Gbps の帯域幅を提供します。 これにより大規模トランザクション処理や高い同時実行性が求められるワークロードに対応できます。

🔄 アップデート前後の比較

❌ アップデート前 (M8g / Graviton4)

  • 最大規模ワークロードで vCPU 数やネットワーク帯域幅に上限
  • 高同時実行・大規模トランザクションでコスパ改善の余地
  • 24xlarge / 48xlarge が未提供で垂直スケーリングに上限
➡️

✅ アップデート後 (M9g / Graviton5)

  • 最大 192 vCPU の 24xlarge / 48xlarge が利用可能に
  • Graviton4 比で最大 30% の性能向上
  • オンデマンド料金で最大 23% の価格性能比向上

🛠️ 設定方法

前提条件

✓利用可能リージョンで Amazon RDS を使用していること
✓M9g インスタンスをサポートするエンジンバージョンを使用していること
✓インスタンスクラスを変更する権限を持つ IAM ユーザーまたはロール

ステップ 1: 新規 DB インスタンスの作成

BashAWS CLI
aws rds create-db-instance \
  --db-instance-identifier my-postgres-db \
  --db-instance-class db.m9g.24xlarge \
  --engine postgres \
  --allocated-storage 100 \
  --master-username admin \
  --manage-master-user-password

M9g インスタンスクラス (db.m9g.24xlarge) を指定して PostgreSQL の DB インスタンスを新規作成します。

ステップ 2: 既存インスタンスのインスタンスクラス変更

BashAWS CLI
aws rds modify-db-instance \
  --db-instance-identifier my-existing-db \
  --db-instance-class db.m9g.48xlarge \
  --apply-immediately

既存の DB インスタンスを M9g (db.m9g.48xlarge) に変更します。--apply-immediately を指定するとメンテナンスウィンドウを待たずに即時適用されます。本番環境では、ダウンタイムを最小化するためメンテナンスウィンドウでの適用を検討してください。

💡 メリット

ビジネス面

✓コスト最適化: オンデマンド料金で最大 23% の価格性能比向上により、同じワークロードをより低コストで実行
✓大規模ワークロード対応: 24xlarge / 48xlarge により垂直スケーリングの上限が拡大し、大規模 DB を単一インスタンスで運用
✓マネージドサービスの活用: 自動バックアップ、パッチ適用、モニタリングを引き続き利用可能

技術面

✓性能向上: Graviton4 比で最大 30% 向上し、クエリ処理やトランザクションスループットが改善
✓高いネットワーク性能: 最大 100Gbps と EBS 72Gbps により I/O 集約型ワークロードに対応
✓互換性: インスタンスクラスの変更のみで移行でき、アプリケーションコードの変更は不要

⚠️ デメリット・制約事項

制限事項

!提供リージョンが限定されています
!M9g をサポートするエンジンバージョンが限定されます (RDS ドキュメントで確認が必要)
!Graviton (ARM ベース) のため、x86 専用拡張や一部のサードパーティ製拡張は互換性の確認が必要

考慮すべき点

!x86 からの移行時は、事前にエンジン拡張機能やワークロードの互換性を検証することを推奨
!インスタンスクラス変更には再起動を伴う (Multi-AZ 構成でダウンタイムを短縮可能)
!性能向上幅はワークロード依存のため、本番移行前にベンチマークを推奨

🎯 ユースケース

1. 大規模 OLTP データベースの集約
シナリオ: 複数の中規模インスタンスのトランザクション処理を、より大規模な単一インスタンスに集約してコストと運用負荷を削減したい。
db.m9g.48xlarge (最大 192 vCPU) に集約し、高い同時接続数とスループットを単一インスタンスで処理。
⚡ 効果: 運用対象のインスタンス数を削減し、Graviton5 の性能向上で処理能力を確保。
2. コスト最適化を目的とした Graviton5 への移行
シナリオ: x86 ベースまたは Graviton4 ベースのインスタンスで運用しているデータベースのコストを削減したい。
modify-db-instance でインスタンスクラスを db.m9g.* に変更し、最大 23% の価格性能比向上を活用。
⚡ 効果: アプリケーションコードを変更せず、インスタンスクラスの変更のみでコスパを改善。
3. I/O 集約型分析ワークロード
シナリオ: 大量のデータ読み書きを伴う分析クエリやバッチ処理で、ストレージ帯域幅がボトルネック。
EBS への最大 72Gbps、ネットワーク最大 100Gbps の M9g インスタンスを利用。
⚡ 効果: 高い帯域幅により I/O 待ちを削減し、分析処理を高速化。

💰 料金

M9g データベースインスタンスは、Amazon RDS の標準的な料金モデル (オンデマンド、リザーブドインスタンス) に従って課金されます。 Graviton4 ベースの同等インスタンスと比較して、オンデマンド料金で 最大 23% の価格性能比の向上 が得られます。 正確な料金とリージョンごとの価格は、Amazon RDS の料金ページを参照してください。

📝 まとめ

Amazon RDS for PostgreSQL / MySQL / MariaDB が AWS Graviton5 搭載の M9g インスタンスに対応したことで、 最大 30% の性能向上と最大 23% の価格性能比向上を、 アプリケーションコードの変更なしに享受できるようになりました。新たな 24xlarge / 48xlarge サイズは大規模データベースの垂直スケーリングを可能にします。 コスト最適化や性能改善を検討している場合は、対応リージョンとエンジンバージョンを確認したうえで、ベンチマークによる検証を経て移行を進めることを推奨します。
