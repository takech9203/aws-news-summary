AWS Interconnect一般提供開始 GA

🔗 AWS Interconnect - multicloud
Microsoft Azure 対応が一般提供開始

📅 リリース日: 2026 年 11 月 17 日 | ☁️ マルチクラウド接続のマネージドサービス

📋 概要

AWS Interconnect - multicloud は、AWS の VPC と他のクラウドプロバイダー CSP のプライベートネットワークを直接接続するマネージド接続サービスです。物理ルーターや仮想ルーターの構成、クロスコネクトの手配、BGP ピアリングの管理を行うことなく、回復性とスケーラビリティを備えたプライベート接続を数分でプロビジョニングできます。

Microsoft Azure は 2026 年 8 月にパブリックプレビューとして対応を開始し、今回の GA により、Azure、Google Cloud、Oracle Cloud Infrastructure OCI の 3 つのクラウドに対して一貫したシンプルな体験でワークロードを相互接続できるようになりました。

3 CSP
Azure / Google Cloud / OCI に同一体験で接続
数分
従来数週間〜数か月かかった接続構築を短縮
500 Mbps
CSP / リージョンごとに無料利用枠を 1 つ提供
❌ アップデート前の課題
✗専用線の手配、ルーター構成、BGP ピアリングを自前で設計・構築・運用する「DIY 型」アプローチが必要
✗グローバルで多層的なネットワーク管理が複雑で、プロビジョニングに数週間から数か月を要した
✗Azure 接続はパブリックプレビューで 1 Gbps に制限され、本番利用には不向きだった
✅ アップデート後の改善
✓Azure との Interconnect が一般提供となり、本番ワークロードで利用可能に
✓コンソール、CLI、API から数分で回復性のあるプライベート接続をプロビジョニング
✓Azure、Google Cloud、OCI の 3 つの CSP に同一の一貫したエクスペリエンスで接続を構成

AWS 側では Direct Connect Gateway がアタッチポイントとなり、VPC は Transit Gateway、Virtual Private Gateway、または Cloud WAN 経由で接続します。AWS と Azure の間は、2 つ以上の物理的に独立した施設にまたがる冗長なネットワークデバイス上に MACsec で暗号化された接続が自動的にプロビジョニングされ、お客様からは単一の「Interconnect」オブジェクトとして見えます。

⚙️ 主要機能

1️⃣ Microsoft Azure との Interconnect の一般提供
  • 2026 年 8 月のパブリックプレビューを経て GA に到達
  • us-east-1、ap-southeast-2、eu-central-1 の 3 つの AWS リージョンで利用可能
  • AWS Management Console、CLI、API から作成できる
2️⃣ フルマネージドなプロビジョニングと運用
  • ルーター構成、クロスコネクト、VLAN・BGP 設定、メンテナンスを AWS とプロバイダーが管理
  • 容量が事前プロビジョニングされているため、新しい Interconnect は通常数分で作成
  • 再プロビジョニング不要でコンソールから帯域幅を増減可能
3️⃣ 組み込みの回復性とセキュリティ
  • 独立した電源とネットワークを持つ 2 つ以上の物理施設にまたがる冗長構成
  • ECMP 等コストマルチパスによる 4 接続モデルで、計画メンテナンス中も少なくとも 1 つのリンクが稼働
  • IEEE 802.1AE MACsec でデフォルト暗号化。暗号化セッションがアクティブな場合のみトラフィックを転送
4️⃣ オープン仕様による CSP 間連携
  • GitHub で公開されているオープン仕様に基づき、Azure は最新の採用 CSP
  • Azure、Google Cloud、OCI に対して同じ操作体験で接続を作成可能
5️⃣ モニタリング機能
  • CloudWatch Network Synthetic Monitor が追加料金なしで 1 つ付属。レイテンシーとパケットロスを計測
  • 帯域幅使用率 % のメトリクスでしきい値アラームを設定し、輻輳を未然に防止

📜 API 変更履歴

AWS API Changes フィード (過去 30 日間) には、本アップデートに対応する AWS Interconnect の API 変更エントリは確認できませんでした。Interconnect の操作は AWS Direct Connect コンソールおよび Interconnect の API / CLI 経由で提供されます。

🛠️ 設定方法

✅ 前提条件

✓Virtual Private Gateway、Transit Gateway、Cloud WAN のいずれを使用するかネットワークアーキテクチャを決定 (VGW / TGW はリージョナル、Cloud WAN はグローバルに到達可能)
✓既存の IP アドレス割り当てを確認し、Azure 側のアドレス空間と競合しないことを確認
✓アタッチポイントとして使用する Direct Connect Gateway を新規作成するか、既存のものを再利用

📝 手順

1
multicloud Interconnect の作成を開始する
AWS Direct Connect コンソールのナビゲーションペインから [AWS Interconnect] を選択し、[Create new multicloud Interconnect] を選択。接続先の CSP として Microsoft Azure のカードを選択します。
2
接続パラメータを指定する
AWS リージョン (ソース) と Azure 側のリージョン (デスティネーション) を選択。続いて Interconnect の名前、必要な帯域幅、アタッチポイントとなる Direct Connect Gateway (新規作成も可能)、および Azure 側の ID を指定します。
3
作成リクエストとアクティベーション
[Finish] を選択すると AWS が Azure へ作成リクエストを送信し、アクティベーションキーが表示されます。Azure 側でこのキーを使用して承認すると、両側で自動プロビジョニングが行われ作成が完了。以降の操作は不要です。Azure 側から開始した場合は、[Accept multicloud Interconnect] からキーを入力して受け入れます。

💡 メリット

💼 ビジネス面

✓マルチクラウド戦略の加速: 接続構築の複雑さに妨げられることなくアプリケーションを展開
✓リードタイムの大幅な短縮: 従来数週間〜数か月の構築が数分のプロビジョニングに
✓コストの最適化: ワークロードの変動に合わせて帯域幅を増減し、コストを管理

🔧 技術面

✓運用負荷の削減: ルーター構成、クロスコネクト、BGP、VLAN、メンテナンスをフルマネージドで提供
✓高い回復性: 冗長デバイスと ECMP の 4 接続モデルで単一障害点を排除
✓デフォルトのセキュリティ: MACsec 暗号化がデフォルトで有効

⚠️ デメリット・制約事項

🚧 制限事項

✗Azure との GA 提供リージョンは us-east-1、ap-southeast-2、eu-central-1 の 3 リージョンに限定
✗VGW / TGW 使用時はローカルリージョン内の接続に限定 (リモートリージョンへは TGW ピアリングまたは Cloud WAN が必要)
✗サポートされる帯域幅はリージョンとプロバイダーの組み合わせによって異なる
✗無料利用枠の Interconnect (500 Mbps) は有料の Interconnect に変換できない

🤔 考慮すべき点

⚠️料金は AWS 側のみが対象。Azure 側のインフラは Azure が独自に料金を設定・請求するため、両側の料金を事前に確認する必要がある
⚠️リモートリージョンの TGW から TGW ピアリング経由で到達する構成では、リージョン間データ転送料金と TGW データ処理料金が別途発生
⚠️接続スコープ (Tier) が広がるほど時間料金が高くなるため、ワークロードの配置リージョンと Interconnect のローカルリージョンの関係を設計段階で考慮

🎯 ユースケース

1️⃣ AWS と Azure にまたがるアプリケーション連携

シナリオ: 基幹データベースは AWS 上の VPC で運用し、Microsoft Entra ID や Azure 上の SaaS 連携ワークロードと低レイテンシーかつプライベートに通信したい。

手順実装例
1. us-east-1 で multicloud Interconnect を作成し、Azure を接続先 CSP として選択
2. Direct Connect Gateway を Transit Gateway に関連付け
3. VPC を Transit Gateway にアタッチし、Azure VNet とのルーティングを構成

✨ 効果: インターネットを経由しないプライベートで暗号化された接続により、クラウド間のアプリケーション連携をセキュアかつ低運用負荷で実現。

2️⃣ Cloud WAN によるグローバルマルチクラウドネットワーク

シナリオ: 複数の AWS リージョンにワークロードが分散しており、グローバルネットワーク全体から Azure 上のワークロードへ到達させたい。

手順実装例
1. eu-central-1 で Azure への Interconnect を作成し Direct Connect Gateway にアタッチ
2. その Direct Connect Gateway を Cloud WAN の Core Network セグメントに関連付け
3. 各リージョンの Core Network Edge から最短パスで Interconnect に到達

✨ 効果: 任意のリージョンの Core Network Edge からグローバルに Interconnect へ到達でき、リージョンごとに接続を重複構築する必要がなくなる。

3️⃣ 無料利用枠によるマルチクラウド接続の検証

シナリオ: 本格導入の前に、AWS と Azure 間のプライベート接続の動作やレイテンシーを低コストで検証したい。

手順実装例
1. Direct Connect コンソールで AWS Interconnect - multicloud - Free Tier を選択
2. 500 Mbps のローカル Tier 1 Interconnect を作成 (AWS 側は無料)
3. CloudWatch Network Synthetic Monitor でレイテンシーとパケットロスを計測

✨ 効果: AWS 側は追加料金なしで接続を検証でき、CloudWatch メトリクスに基づいて本番導入時の帯域幅を適切にサイジング可能。

💰 料金

選択した帯域幅と接続の地理的スコープという 2 つの入力に基づく単一料金モデル。料金は時間単位で計算され、転送データ量に対する個別の課金はありません。各「AWS リージョンと Interconnect のパス」に Tier が割り当てられ、Tier と帯域幅の組み合わせごとに時間料金が決まります。

Tier接続スコープ説明
Tier 1ローカルInterconnect のローカルリージョン内のエンドポイント
Tier 2リージョナル同一の地理的エリア内のリージョンのエンドポイント
Tier 3大陸大陸・地理的エリアをまたぐ、より遠方のリージョン
Tier 4長距離広大な地理的エリアまたは異なる大陸にまたがるリージョン
Tier 5最大スコープ最も遠方のリージョン間のパス
✓一般提供されている CSP ごと・AWS リージョンごとに、ローカル Tier 1 の 500 Mbps Interconnect を 1 つ無料で利用可能 (AWS 側のみ。Azure 側の料金は Azure が独自に設定)

🌍 利用可能リージョン

Microsoft Azure との Interconnect - multicloud は、以下の AWS リージョンで一般提供されています。

us-east-1バージニア北部
ap-southeast-2シドニー
eu-central-1フランクフルト

なお、AWS Interconnect - multicloud 全体としては Google Cloud、Oracle Cloud Infrastructure OCI との接続も利用可能です。

📝 まとめ

AWS Interconnect - multicloud の Microsoft Azure 対応が GA となり、Azure、Google Cloud、OCI の 3 大クラウドに対して一貫した体験でプライベート接続を数分でプロビジョニングできるようになりました。DIY 型のマルチクラウドネットワーク構築に伴う複雑さと運用負荷を大幅に削減できるため、マルチクラウド戦略を推進する組織は、まず無料利用枠の 500 Mbps Interconnect で接続性とレイテンシーを検証することをお勧めします。
