自律型セキュリティ

2026年6月17日
サービスアップデート

📌 概要

AWS は、ソフトウェアライフサイクル全体にわたってセキュリティリスクをマシンスピードで検出、優先順位付け、検証、修復する新サービス AWS Continuum を発表しました。お客様が定義したガードレールの範囲内でエージェントが自律的に動作し、脆弱性を発見してから対処するまでのギャップを埋めます。

これにより、セキュリティチームは手作業のトリアージから、戦略策定と結果の承認へと役割をシフトできます。中核となる AWS Continuum for code vulnerabilities は gated preview として提供され、Capital One、MongoDB、Rivian、Robinhood などがデザインパートナーとして参加しています。

⚠️ アップデート前の課題
  • 大量の検出結果のうち、どれが実際に悪用可能かを人手で検証する必要があった
  • 検出から修復までのリードタイムが長く、ペネトレーションテストに数週間を要した
  • 脅威モデリングやコードスキャンが手作業中心で、ライフサイクル全体の継続的カバーが困難だった
✅ アップデート後の改善
  • 検出・優先順位付け・検証・修復の一連をエージェントがマシンスピードで実行
  • 隔離サンドボックスでの再現可能な実証により、悪用可能な脆弱性に集中
  • ペネトレーションテストを数週間から数時間へ短縮し、修正案まで提示

AWS Continuum は、検出ソースからの入力を受けて検出、優先順位付け、検証、修復の 4 フェーズを進め、修復アクションはお客様が定義したガードレール (人間による承認) を経てデプロイされます。

⚙️ 主要機能

🛡️ AWS Continuum for code vulnerabilities gated preview
  • 既存のセキュリティツールに加え、独自スキャンによる検出結果を取り込む
  • 環境とビジネスのコンテキストグラフを用いて各課題の優先順位を判断
  • 隔離されたサンドボックス内で再現可能な実証を構築し、悪用可能性を検証
  • 確認された露出に「高速かつ可逆的な緩和策」を適用し、その後レビューとデプロイを通じて恒久修正
  • 複数のフロンティアモデルを使い分ける、モデルに依存しない設計
🎯 Continuum penetration testing 提供中
  • 旧 AWS Security Agent のペネトレーションテスト機能を改称
  • オンデマンドのテストにより、従来数週間を要したテストを数時間に短縮
  • 再現可能な実証と、すぐに実装可能な修正案を提供
🔍 Continuum code scanning preview
  • コンプライアンス要件、悪用パターン、脅威ベクトルに対する詳細分析を実施
  • 検証済みの修正案 (validated fixes) を提示
📐 Continuum threat modeling preview
  • 設計ドキュメントまたはソースコードから、コンテキストを考慮した脅威モデルを生成
  • 結果を STRIDE 形式で出力し、6 カテゴリすべてにわたる緩和策を提示

信頼モデルとガードレール

AWS Continuum における信頼は段階的であり、お客様が設定します。初期状態ではエージェントが提案し人間が承認するワークフローで動作し、自律実行できる範囲をお客様が選択します。

1初期段階: エージェントが提案し、人間が承認
2段階的拡大: お客様の判断で自律実行の範囲を拡大
3修復は「可逆的な緩和策」として適用し、その後恒久対応へ移行

✨ メリット

💼 ビジネス面

✓対処までの時間短縮: 検出から修復までをマシンスピードで進め、脆弱性が露出する時間を最小化
✓セキュリティチームの役割転換: 手作業トリアージから戦略策定と結果承認へ人材をシフト
✓テスト工数の削減: ペネトレーションテストを数週間から数時間へ短縮し運用コストを抑制

🔧 技術面

✓悪用可能性の検証: サンドボックスでの再現可能な実証により誤検知を削減し、真に対処すべきリスクに集中
✓コンテキストに基づく優先順位付け: 環境とビジネスのコンテキストグラフで影響度の高いリスクを特定
✓ライフサイクル全体のカバー: 設計段階の脅威モデリングからコードスキャン、稼働中のリスク検出まで一貫してカバー

⚠️ デメリット・制約事項

制限事項

✗code vulnerabilities は gated preview であり、利用には事前申請とアクセス承認が必要
✗code scanning および threat modeling は preview 段階のため、本番利用には注意が必要
✗公式発表時点で料金体系は公開されていない
✗利用可能リージョンは明示されておらず、提供は一部のお客様に限定

考慮すべき点

!自律実行の範囲はお客様が設定するため、ガバナンスポリシーと整合するガードレール設計が重要
!可逆的な緩和策が稼働中アプリケーションに与える影響を事前に評価する必要がある

🎬 ユースケース

1. 出荷前のリスク検出

シナリオ: 新機能のリリース前に、設計ドキュメントやソースコードに潜むセキュリティリスクを洗い出したい。

効果: Continuum threat modeling が設計段階で STRIDE 形式の脅威モデルを生成し、出荷前に緩和策を組み込めるため本番環境へのリスク流出を防止。

2. 悪用可能な脆弱性への集中対応

シナリオ: 複数のスキャンツールから大量の検出結果が報告され、優先対処の判断に時間がかかっている。

効果: code vulnerabilities がコンテキストグラフで優先順位を付け、サンドボックスで悪用可能性を検証するため、真に対処すべき脆弱性に集中できる。

3. レビュー間のセキュリティ態勢維持

シナリオ: 定期的なセキュリティレビューの間に発生する新たなリスクへの対応が遅れがちである。

効果: 稼働中環境のリスクを継続的に検出し、可逆的な緩和策をガードレールの範囲内で適用することで、レビュー間の態勢を維持できる。

💰 料金・利用可能リージョン

i料金: 公式発表時点で料金体系は公開されていません。最新情報は AWS 公式ページを確認してください。
iリージョン: 公式発表時点で利用可能リージョンは明示されていません。code vulnerabilities は gated preview として一部のお客様に提供されています。

🔗 関連サービス・機能

AWS Security Agent
Continuum の基盤となるフロンティアエージェント。ペネトレーションテスト機能は Continuum penetration testing へ改称。
Amazon GuardDuty
脅威検出サービス。セキュリティ運用全体の中で Continuum と組み合わせて活用可能。
AWS Security Hub
セキュリティ検出結果の集約・管理サービス。検出結果ソースとして連携可能。

🚀 まとめ

AWS Continuum は、検出から修復までをマシンスピードで進める新しいセキュリティサービスであり、セキュリティチームの役割を手作業のトリアージから戦略策定へとシフトさせます。現時点では code vulnerabilities が gated preview、code scanning と threat modeling が preview 段階のため、まずは gated preview への申請を行い、自社のガバナンスポリシーに合わせたガードレール設計を検討することを推奨します。
