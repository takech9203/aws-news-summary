📡 CloudWatch Omni が追加 8 リージョンで利用可能に

🗾 東京リージョン対応で合計 11 リージョンに拡大 | 📅 リリース日: 2026 年 10 月 19 日

📋 概要

Amazon CloudWatch Omni が新たに 8 つの AWS リージョンで利用可能になった。 CloudWatch Omni は、チームとアプリケーションを中心に構成された AI ファーストのオブザーバビリティ体験であり、 アプリケーションと AI エージェントを単一の場所で観測・トラブルシューティングできる。 OpenTelemetry の相互運用性と CloudWatch のスケール・信頼性を融合し、SSO 対応のスタンドアロン Web 体験と ローカルの IDE 拡張 (VS Code、Cursor、Kiro) の両方で利用できる。

日本のユーザーにとっては、東京リージョンで Omni のスペースをホストできるようになった点が今回の最大のポイント。 データレジデンシーやレイテンシーの観点から国内リージョンでの利用を待っていたチームが、導入を本格的に検討できるようになった。

今回の拡大により東京を含む 8 リージョンが追加され、東京リージョンの中央アカウントにスペースをホストし、 複数アカウント・他クラウドのテレメトリを集約する構成が可能になった。

⚡ 主要機能

🌏 1. 8 リージョンへの提供拡大
カナダ (中部)、ムンバイ、シンガポール、シドニー、東京、フランクフルト、ロンドン、サンパウロが追加。既存の 3 リージョンと合わせて合計 11 リージョンで利用可能。東京リージョンでスペースをホストできるため、日本国内でのデータ保持要件に対応しやすくなった。
🔭 2. マルチアカウント・マルチクラウドの一元可視化 (全リージョン共通)
中央アカウントにスペースを作成し、複数の AWS アカウント・リージョンのテレメトリを横断表示。Azure や GCP のワークロードも OpenTelemetry で計装して OTLP エンドポイントに送信すれば観測対象に。サービスの自動検出、依存関係マッピング、ゴールデンメトリクスの自動表示に対応する。
🤖 3. AI による操作と根本原因調査 (全リージョン共通)
チャット、ポイント & クリック操作、Agent Toolkit for AWS 経由の外部ツールでテレメトリを操作できる。AWS DevOps Agent による根本原因分析を開始できる。
🧠 4. AI エージェント向けオブザーバビリティ (全リージョン共通)
LangGraph、CrewAI、OpenAI Agents SDK、Vercel AI SDK、Strands などに対応した評価駆動のエージェント観測体験を提供。VS Code、Cursor、Kiro 向けの無料拡張により、ローカルでエージェントの計装・デバッグ・評価が可能。

前提条件

✓CloudWatch Omni 提供リージョンのいずれかを利用できること
✓ドメインのセットアップに使用する ID プロバイダー (SSO) を用意していること
✓複数アカウント・リージョンを観測する場合、CloudWatch の集約ルールを設定できる権限があること

1
東京リージョンで Omni スペースを作成: CloudWatch コンソールでアジアパシフィック (東京) を選択し、スペースを作成。ドメイン名を設定すると組織専用のサインイン URL が発行される。
2
SSO のセットアップとサインイン: 発行されたドメイン URL に ID プロバイダーを接続し、既存の ID で Web 体験にサインイン。AWS マネジメントコンソールへのサインインは不要。
3
テレメトリの集約: 既に CloudWatch に送信しているテレメトリは再設定なしで表示。複数アカウント・リージョン横断は集約ルールで東京リージョンの中央アカウントに集約。他クラウドは OTLP エンドポイントに送信。
4
IDE 拡張のインストール (エージェント開発者向け): VS Code、Cursor、Kiro に無料の CloudWatch Omni 拡張をインストールすると、ローカルでエージェントの計装・デバッグ・評価ができる。

💡 メリット

💼 ビジネス面

✓データレジデンシー要件への対応: 東京リージョンでスペースをホストでき、日本国内にデータを保持する要件があるワークロードでも導入を検討しやすくなった
✓グローバル展開企業での採用拡大: 北米・欧州・アジア・南米の主要リージョンをカバーし、各拠点に近いリージョンでの運用が可能に
✓ツール統合の推進: リージョン制約で見送っていたチームも、アプリケーション監視・マルチクラウド可視化・AI エージェント評価の統合を進められる

⚙️ 技術面

✓レイテンシーの低減: 地理的に近いリージョンのスペースを利用でき、Web 体験や IDE 拡張の操作レイテンシーが改善
✓テレメトリ転送の最適化: 東京リージョンのワークロードのテレメトリを同一リージョン内で集約・分析でき、リージョン間データ転送を抑制
✓既存資産との互換性: 既存の CloudWatch のメトリクス・アラーム・ダッシュボード・API はそのまま動作し、計装の変更も不要

⚠️ デメリット・制約事項

制限事項

✗提供リージョンは 11 リージョンであり、大阪リージョンなど上記以外のリージョンでは引き続きスペースをホストできない
✗スペースは 1 つのアカウント・リージョンにマッピングされるため、複数アカウント・リージョンの横断観測には CloudWatch の集約ルールによる中央化設定が別途必要

考慮すべき点

→インジェスト・ストレージ・分析の従量課金が発生するため、テレメトリ量の多い環境では事前にコスト試算を推奨。リージョンごとに料金が異なる場合があるため、料金ページで東京リージョンの単価を確認すること
→ドメインのサインイン URL は AWS コンソール外のエンドポイントとなるため、組織のセキュリティポリシー (アクセス制御、監査) との整合を確認する必要がある

🎯 ユースケース

🗾 ユースケース 1: 日本国内で完結するオブザーバビリティ基盤

シナリオ: 東京リージョンで複数アカウントのワークロードを運用する企業が、データレジデンシーの観点から国内リージョンでの監視基盤統合を求めている。

1.東京リージョンの中央アカウントに Omni ドメインとスペースを作成
2.CloudWatch の集約ルールで各アカウントのテレメトリを東京リージョンに中央化
3.アプリケーションマップで依存関係とゴールデンメトリクスを確認
4.アラートを Slack または Amazon SNS で通知
✅ 効果: テレメトリの保持と分析を日本国内で完結させつつ、SSO 対応の単一のオブザーバビリティ体験を実現できる。
🌏 ユースケース 2: アジアパシフィック全域のマルチリージョン監視

シナリオ: 東京・シンガポール・シドニー・ムンバイにワークロードを展開する企業が、リージョンごとに分散した監視を統合したい。

1.東京リージョンに中央スペースを作成
2.集約ルールで各リージョンのテレメトリを東京に集約
3.他クラウド Azure / GCP のワークロードは OTLP エンドポイントに送信
4.単一のアプリケーションマップでリージョン横断の依存関係を可視化
✅ 効果: アジアパシフィック全域のワークロードを単一のスペースで観測でき、障害の影響範囲特定が高速化する。
🤖 ユースケース 3: 国内チームによる AI エージェントの評価駆動開発

シナリオ: 日本の開発チームが Strands や LangGraph で構築した AI エージェントを、国内リージョンで本番運用しながら品質評価したい。

1.VS Code / Cursor / Kiro に CloudWatch Omni 拡張をインストール
2.エージェントを計装し、プロンプト・モデル呼び出し・ツール呼び出しをトレース
3.東京リージョンのスペースで本番トレースと評価スコアを継続監視
4.修正後はエクスペリメントでリリース前に品質を検証
✅ 効果: ローカル開発から東京リージョンでの本番監視まで、一貫した評価駆動開発ワークフローを低レイテンシーで利用できる。

💰 料金

CloudWatch Omni の料金は インジェスト・ストレージ・分析の 3 つのディメンションで構成される従量課金。 リージョン拡大自体による追加料金はないが、リージョンごとに単価が異なる場合があるため、東京リージョンの単価は料金ページで確認すること。

ディメンション参考単価 (米国東部 バージニア北部)
ログ・メトリクスのインジェスト0.50 USD/GB
ストレージ0.030 USD/GB - 月
ログ・トレースのクエリ0.005 USD/スキャン GB
🎁 Omni を有効化すると、30 日間有効な 1,000 USD の無料トライアルクレジットが自動適用される (OpenTelemetry インジェストのみ対象、1 AWS Organization あたり 10 アカウントまで)。

🔗 関連サービス・機能

☁️ Amazon CloudWatch
Omni は CloudWatch 上に構築されたインターフェイスであり、既存のメトリクス・ログ・アラーム・ダッシュボードをそのまま活用する。
🤖 AWS DevOps Agent
アラート発報時の根本原因調査を担う AI エージェント。Omni から調査を開始できる。
📡 OpenTelemetry
Omni の基盤となるテレメトリ標準。OTLP エンドポイント経由で Azure や GCP のワークロードも観測できる。
💻 Kiro
AWS が提供する AI 搭載 IDE。CloudWatch Omni 拡張に対応し、ローカルでのエージェント開発・評価に利用できる。

📝 まとめ

Amazon CloudWatch Omni が東京リージョンを含む 8 リージョンに拡大し、合計 11 リージョンで利用可能になった。 日本のユーザーはデータレジデンシーと低レイテンシーの両面で導入のハードルが下がったため、 無料トライアルクレジットを利用して東京リージョンにスペースを作成し、 自動検出されるアプリケーションマップと AI による調査体験を評価することを推奨する。 AI エージェントを開発しているチームは、AWS アカウント不要の IDE 拡張から評価駆動開発ワークフローを試すことができる。
