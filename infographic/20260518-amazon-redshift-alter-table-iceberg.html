Iceberg テーブルへの ALTER TABLE サポートと AWS Glue Data Catalog マウント経由の書き込み

Apache Iceberg テーブルの DDL サポートおよび awsdatacatalog マウント経由の書き込みアクセス

📋 概要

Amazon Redshift が Apache Iceberg テーブルに対する ALTER TABLE DDL ステートメントのサポートと、AWS Glue Data Catalog (awsdatacatalog) マウントを介した直接書き込み機能を追加。外部スキーマを作成することなく、Redshift の変換結果をデータレイクに直接書き込み、他のエンジンからクエリ可能な状態にできる。

データレイクアーキテクチャにおいて Redshift を中核の ETL/ELT エンジンとして活用するユーザーに特に有用。AWS Lake Formation と連携した Iceberg テーブルのフェデレーテッドアクセス管理にも対応。

❌ Before

  • Iceberg テーブルの構造変更にはテーブルとデータを削除して再作成が必要
  • データパイプラインに複雑性とレイテンシが追加され運用負荷が高い
  • Iceberg テーブルへ書き込むには外部スキーマの作成が必要
  • パーティション戦略の変更がデータ量の増加に伴い困難

✅ After

  • ALTER TABLE でスキーマ、パーティション、プロパティをインプレース変更可能
  • awsdatacatalog マウント経由で外部スキーマなしに直接書き込み可能
  • テーブル再作成なしにパーティション戦略を動的に適応
  • EMR や Athena など他の Iceberg 対応エンジンとの互換性を維持

🚀 主要機能

🔗 awsdatacatalog マウント経由の書き込みアクセス
  • 自動マウントされた awsdatacatalog を通じて Iceberg テーブルへ直接書き込み可能
  • 外部スキーマの作成が不要
  • Redshift の変換結果をデータレイクに直接ランディング
  • AWS Lake Formation と連携したフェデレーテッドテーブルに特に有用
📝 ALTER TABLE DDL サポート
  • Iceberg テーブルのスキーマ、パーティション、テーブルプロパティの変更が可能
  • テーブルとデータの再作成が不要
  • クロスエンジン互換性を維持したままテーブル構造を変更
🔒 Lake Formation 権限統合
  • Iceberg テーブルへの書き込み操作に Lake Formation の権限が適用
  • 一貫したアクセス制御を維持しながらデータレイクへの書き込みが可能

🔧 技術仕様 - サポートされる ALTER TABLE 操作

操作 説明
ADD COLUMN Iceberg テーブルに新しいカラムを追加

ALTER COLUMN カラムの定義を変更

⚙️ 設定方法

前提条件

✔Amazon Redshift クラスターまたは Redshift Serverless ワークグループが稼働していること
✔AWS Glue Data Catalog に Iceberg テーブルが登録されていること
✔Redshift クラスターの IAM ロールに Glue Data Catalog および S3 へのアクセス権限が付与されていること
✔Lake Formation を使用する場合、適切な権限が設定されていること

SQL テーブル参照 
-- awsdatacatalog マウントを使用してテーブルを参照
SELECT * FROM awsdatacatalog.my_database.my_iceberg_table LIMIT 10;

ステップ 2: Iceberg テーブルへの書き込み

SQL データ書き込み 
-- Redshift の変換結果を Iceberg テーブルに書き込み
INSERT INTO awsdatacatalog.my_database.my_iceberg_table
SELECT
    customer_id,
    order_date,
    total_amount,
    CURRENT_TIMESTAMP AS processed_at
FROM staging_orders
WHERE order_date >= DATEADD(day, -1, CURRENT_DATE);

ステップ 3: ALTER TABLE でスキーマ変更

SQL スキーマ変更 
-- カラムの追加
ALTER TABLE awsdatacatalog.my_database.my_iceberg_table
ADD COLUMN region VARCHAR(50);

-- カラム名の変更
ALTER TABLE awsdatacatalog.my_database.my_iceberg_table
RENAME COLUMN total_amount TO order_total;

-- 圧縮タイプの変更
ALTER TABLE awsdatacatalog.my_database.my_iceberg_table
SET TABLE PROPERTIES ('write.parquet.compression-codec' = 'zstd');

-- パーティションフィールドの追加
ALTER TABLE awsdatacatalog.my_database.my_iceberg_table
ADD PARTITION FIELD month(order_date);

💡 ユースケース

1. データレイクへの ETL パイプライン簡素化

データエンジニアリングチームが Redshift で変換処理を行い、結果を Iceberg テーブルに書き戻してデータサイエンスチームが EMR で分析する。

SQL 集計結果をデータレイクに直接書き込み 
-- Redshift で集計・変換してデータレイクに直接書き込み
INSERT INTO awsdatacatalog.analytics_db.daily_metrics
SELECT
    date_trunc('day', event_time) AS metric_date,
    product_category,
    COUNT(*) AS event_count,
    SUM(revenue) AS total_revenue
FROM raw_events
WHERE event_time >= DATEADD(day, -1, CURRENT_DATE)
GROUP BY 1, 2;

→ 外部スキーマ作成や別途 ETL ツールでの書き込みが不要になり、パイプラインのステップ数と管理コストを削減

2. スキーマエボリューションへの対応

ビジネス要件の変化により、既存の Iceberg テーブルにカラムを追加し、パーティション戦略を月次から日次に変更する必要がある。

SQL スキーマエボリューション 
-- 新しいビジネス要件に合わせてカラムを追加
ALTER TABLE awsdatacatalog.sales_db.transactions
ADD COLUMN loyalty_tier VARCHAR(20);

-- データ量増加に伴いパーティション粒度を変更
ALTER TABLE awsdatacatalog.sales_db.transactions
REPLACE PARTITION FIELD month(transaction_date)
WITH day(transaction_date);

→ テーブルとデータの削除・再作成が不要になり、スキーマ変更のリードタイムを数時間から数秒に短縮

3. Lake Formation による統合ガバナンス

複数の部門が Redshift、EMR、Athena を使い分けてデータレイクの Iceberg テーブルにアクセスする環境で、Lake Formation で一元的にアクセス制御を行う。

SQL ガバナンス統合 
-- Lake Formation 権限で保護された Iceberg テーブルに書き込み
INSERT INTO awsdatacatalog.governed_db.customer_360
SELECT
    customer_id,
    segment,
    lifetime_value,
    last_activity_date
FROM redshift_staging.customer_analysis;

→ Lake Formation の権限モデルにより、Redshift からの書き込みも他のエンジンからのアクセスも統一的に管理でき、ガバナンスが向上

⚖️ メリットと制約事項

✅ ビジネスメリット

  • データパイプラインの簡素化 - 運用コスト削減
  • ダウンタイムの排除 - データ可用性向上
  • マルチエンジン活用の促進

✅ 技術メリット

  • 外部スキーマ不要 - 設定手順が大幅に簡素化
  • クロスエンジン互換性の維持
  • 動的パーティション管理
  • Lake Formation による一貫したアクセス制御

⚠️ 制限事項

  • Iceberg テーブルフォーマット固有の制約に従う必要あり
  • awsdatacatalog マウントは Glue Data Catalog に登録されたテーブルのみ対象
  • Lake Formation 使用時は事前の権限設定が必要

⚠️ 考慮すべき点

  • 外部スキーマからの移行計画の検討
  • パーティション変更後のコンパクションが必要な場合あり
  • 他の Iceberg 対応エンジンとの互換性テストを推奨
