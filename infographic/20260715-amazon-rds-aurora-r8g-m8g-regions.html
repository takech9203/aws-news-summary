📌 概要

AWS Graviton4 ベースの R8g (メモリ最適化) および M8g (汎用) データベースインスタンスが、Amazon RDS と Amazon Aurora の多数の追加リージョンで一般提供を開始しました。

R8g は Amazon Aurora (MySQL / PostgreSQL 互換) および Amazon RDS for PostgreSQL・MySQL・MariaDB で、M8g は Amazon RDS for PostgreSQL・MySQL・MariaDB で利用できます。Graviton4 ベースのインスタンスは、同等サイズの Graviton3 ベースのインスタンスと比較して、データベースエンジン・バージョン・ワークロードに応じて最大のパフォーマンスとコスト効率を提供します。

🔄 アップデートによる変化

❌ アップデート前の課題

  • 対象リージョンでは最新の Graviton4 ベースの R8g / M8g インスタンスを利用できなかった
  • これらのリージョンで運用する組織は旧世代のインスタンスを選択する必要があった
  • 最新ハードウェアによるパフォーマンス向上とコスト効率の改善が地域的に制限されていた

✅ アップデート後の改善

  • 追加された多数のリージョンで R8g (Aurora / RDS) を利用可能に
  • 追加された多数のリージョンで M8g (RDS) を利用可能に
  • 対象リージョンでも最大 40% の性能向上・最大 29% の価格性能向上を享受可能に

⭐ 主要機能

💾 R8g インスタンス (メモリ最適化)

  • AWS Nitro System 上に構築、AWS Graviton4 プロセッサを採用
  • 24xlarge・48xlarge を導入し、最大 192 vCPU に対応
  • 8:1 のメモリ対 vCPU 比率と DDR5 メモリ
  • 最大 50Gbps のネットワーク帯域幅、最大 40Gbps の EBS 帯域幅
  • Aurora (MySQL / PostgreSQL 互換) および RDS for PostgreSQL・MySQL・MariaDB で利用可能

⚙️ M8g インスタンス (汎用)

  • Amazon RDS for PostgreSQL・MySQL・MariaDB で利用可能
  • 汎用ワークロード向けにバランスの取れたコンピューティングとメモリを提供
  • 今回のアップデートで多数のリージョンに拡大

📈 パフォーマンスとコスト効率の向上

  • 同等サイズの Graviton3 ベースと比較して最大 40% のパフォーマンス向上
  • 同等サイズの Graviton3 ベースと比較して最大 29% の価格 / パフォーマンス向上
  • データベースエンジン・バージョン・ワークロードに応じて異なる

🛠️ 設定方法 (AWS CLI 例)

Bash M8g インスタンスで新規起動 (ロンドン) 
# RDS for PostgreSQL で M8g インスタンスを起動
aws rds create-db-instance \
  --db-instance-identifier my-postgres-instance \
  --engine postgres \
  --db-instance-class db.m8g.2xlarge \
  --master-username admin \
  --master-user-password MyPassword123 \
  --allocated-storage 100 \
  --region eu-west-2
Bash 既存インスタンスを R8g にアップグレード 
# 既存の RDS インスタンスを R8g にアップグレード
aws rds modify-db-instance \
  --db-instance-identifier my-existing-instance \
  --db-instance-class db.r8g.4xlarge \
  --apply-immediately
Bash CloudWatch でパフォーマンスを確認 
# 過去 24 時間の CPU 使用率の平均を取得
aws cloudwatch get-metric-statistics \
  --namespace AWS/RDS \
  --metric-name CPUUtilization \
  --dimensions Name=DBInstanceIdentifier,Value=my-postgres-instance \
  --start-time 2026-07-15T00:00:00Z \
  --end-time 2026-07-16T00:00:00Z \
  --period 3600 \
  --statistics Average

💡 ユースケース

1. メモリ集約型ワークロードの高性能化

ヨーロッパ (ロンドン) で大規模データセットを扱う Aurora PostgreSQL を R8g (8:1 メモリ比率) に移行。

効果: 最大 40% の性能向上・最大 29% の価格性能向上

2. 汎用ワークロードのコスト最適化

アジアパシフィック (シドニー) の RDS for MySQL Web バックエンドを汎用 M8g に移行し、CloudWatch で比較。

効果: Graviton4 による価格 / パフォーマンス改善

3. リージョン展開に伴う基盤刷新

メキシコ (中部) や南米 (サンパウロ) での事業拡大に伴い、新規 DB で最新の R8g を採用。

効果: 低レイテンシで高性能・コスト効率の高い DB 基盤

⚠️ デメリット・制約事項

✗すべてのデータベースエンジンバージョンで R8g / M8g がサポートされているわけではない
✗M8g は Amazon RDS でのみ利用可能で、Amazon Aurora では対象外
✗一部リージョンでは特定のインスタンスサイズが利用できない場合がある
!Graviton ベースのインスタンスは ARM64 アーキテクチャを使用。アプリの互換性確認が必要
!パフォーマンステストを実施し、適したインスタンスファミリーとサイズを選択すること

💰 料金

R8g および M8g インスタンスの料金は、インスタンスサイズ・データベースエンジン・リージョンによって異なります。Graviton4 ベースのインスタンスは、同等サイズの Graviton3 ベースと比較して最大 29% の価格 / パフォーマンス向上を提供します。

📝 まとめ

Amazon RDS および Aurora が追加リージョンで R8g・M8g をサポートしたことで、より多くの地域で最新の AWS Graviton4 ベースのインスタンスを活用できるようになりました。R8g はメモリ集約型、M8g は汎用ワークロードに適しており、最大 40% のパフォーマンス向上と最大 29% の価格 / パフォーマンス向上を提供します。対象リージョンで運用する組織は、ワークロードの特性に応じた移行を検討することをお勧めします。
