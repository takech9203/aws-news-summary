Amazon OpenSearch Service

VPC Egress によるプライベート接続

OpenSearch ドメインから VPC 内リソースへの完全プライベート通信を実現

2026-05-07
VPC Egress for Private Connectivity

📋 概要

Amazon OpenSearch Service が VPC Egress をサポートし、OpenSearch ドメインから顧客の VPC 内のリソースへプライベートに接続できるようになりました。アウトバウンドトラフィックがパブリックインターネットを経由せずに、VPC 内のリソースへ直接ルーティングされます。

アラート通知、カスタムプラグイン、インジェストパイプラインなどが VPC 内のリソース (データベース、アプリケーションサーバー、内部 API) にプライベートアクセス可能に。セキュリティとコンプライアンスの要件が厳しい環境で全通信をプライベートネットワーク内に閉じることが可能。

Before (従来)

  • VPC 内リソースへの通信にパブリックインターネット経由が必要
  • 追加のネットワーク制御 (セキュリティ要件)
  • NAT Gateway、VPN、プロキシ等の複雑な構成が必要

After (VPC Egress)

  • プライベートネットワーク経由で通信完結
  • EgressEnabled: true を設定するだけで有効化
  • データ漏洩リスク低減とセキュリティ強化

🏗️ アーキテクチャ図

VPC Egress を有効にすると、OpenSearch ドメインは ENI を介して VPC 内のリソースへプライベートに接続します。パブリックインターネットを経由する従来のルートは不要になります。

⚡ 主要機能

🔧 VPC Egress の有効化

  • ドメイン作成時または VPC エンドポイント作成時に EgressEnabled: true を指定
  • 既存ドメインに対しても設定変更で有効化可能
  • セキュリティグループとサブネットの指定と組み合わせて利用

🔒 プライベートアウトバウンド接続

  • 全アウトバウンドトラフィックがプライベートルート経由
  • VPC ピアリング、Transit Gateway 経由の他 VPC リソースへの接続も可能
  • セキュリティグループによるトラフィック制御が適用

🔗 既存 VPC 機能との統合

  • 既存の VPC アクセス (インバウンド) と併用可能
  • サブネット、セキュリティグループ、ルートテーブルの既存設定を活用
  • VPC Flow Logs によるトラフィック監視に対応

🔧 技術仕様

項目 詳細
新規パラメータ VPCOptions.EgressEnabled (boolean)
対象 API CreateDomain, CreateVpcEndpoint, DescribeDomain, UpdateDomainConfig 等
変更 API 数 10 メソッド (全て updated)
デフォルト値 false (従来と同じ動作)
API 変更日 2026/05/05

VPCOptions 設定例

JSON VPCOptions 設定 
{
  "VPCOptions": {
    "SubnetIds": [
      "subnet-0123456789abcdef0",
      "subnet-0123456789abcdef1"
    ],
    "SecurityGroupIds": [
      "sg-0123456789abcdef0"
    ],
    "EgressEnabled": true
  }
}

🚀 設定方法

前提条件

  • 1. OpenSearch ドメインが VPC アクセスモードで構成されていること
  • 2. VPC 内に適切なサブネットとセキュリティグループが存在すること
  • 3. ターゲットリソースが同一 VPC 内、またはピアリング/Transit Gateway 経由でアクセス可能であること

Step 1: セキュリティグループの準備

Bash セキュリティグループ作成 
# OpenSearch ドメイン用のセキュリティグループを作成
aws ec2 create-security-group \
  --group-name opensearch-egress-sg \
  --description "Security group for OpenSearch VPC egress" \
  --vpc-id vpc-0123456789abcdef0

# アウトバウンドルールの設定
aws ec2 authorize-security-group-egress \
  --group-id sg-0123456789abcdef0 \
  --protocol tcp \
  --port 443 \
  --cidr 10.0.0.0/16

Step 2: ドメイン作成時に VPC Egress を有効化

Bash 新規ドメイン作成 
aws opensearch create-domain \
  --domain-name my-domain \
  --engine-version OpenSearch_2.17 \
  --cluster-config InstanceType=r6g.large.search,InstanceCount=2 \
  --ebs-options EBSEnabled=true,VolumeType=gp3,VolumeSize=100 \
  --vpc-options SubnetIds=subnet-0123456789abcdef0,subnet-0123456789abcdef1,SecurityGroupIds=sg-0123456789abcdef0,EgressEnabled=true

Step 3: 既存ドメインの更新

Bash 既存ドメイン設定更新 
aws opensearch update-domain-config \
  --domain-name my-existing-domain \
  --vpc-options EgressEnabled=true

⚖️ メリット・デメリット

✅ メリット

  • 金融、医療、政府機関のコンプライアンス要件に対応
  • NAT Gateway やプロキシ等の中間インフラが不要でコスト削減
  • セキュリティ監査への対応が容易に
  • ネットワーク構成のシンプル化
  • パブリックインターネット経由しないためレイテンシー低減
  • データ漏洩やフィッシング攻撃リスクの低減

⚠️ 制約・注意点

  • VPC アクセスモードのドメインでのみ利用可能
  • アウトバウンドトラフィックは VPC ルーティングルールに従う
  • セキュリティグループとルートテーブルの適切な設定が必須
  • 外部インターネットアクセスには別途 NAT Gateway が必要
  • VPC ピアリングや Transit Gateway 利用時は適切なルーティング設定が必要

💡 ユースケース

🔔 ユースケース 1: アラート通知の内部 API 連携

OpenSearch のアラートモニターが異常を検知した際に、VPC 内の社内 Webhook サーバーへ通知を送信

JSON Webhook 設定例 
{
  "type": "custom_webhook",
  "custom_webhook": {
    "url": "https://internal-alerts.private.example.com/webhook",
    "method": "POST",
    "header_params": {
      "Content-Type": "application/json"
    }
  }
}

効果: アラート通知がプライベートネットワーク経由で内部 API へ到達し、セキュリティ向上とレイテンシー低減

🗄️ ユースケース 2: インジェストパイプラインからの内部データソースアクセス

OpenSearch Ingestion パイプラインが VPC 内の RDS データベースからデータを取得し、インデックスに格納

YAML パイプライン設定例 
pipeline:
  source:
    jdbc:
      hostname: "my-rds-instance.cluster-abc123.us-east-1.rds.amazonaws.com"
      port: 5432
      database: "analytics_db"
      table: "events"

効果: 機密データがパブリックインターネットに露出するリスクがなくなる

🌐 ユースケース 3: マルチ VPC アーキテクチャでの検索基盤

Transit Gateway 経由で複数 VPC に接続された環境で、OpenSearch が各 VPC 内のマイクロサービスからデータを収集

Bash Transit Gateway ルート設定 
# Transit Gateway 経由で他 VPC のリソースにアクセスするルートテーブル設定
aws ec2 create-route \
  --route-table-id rtb-0123456789abcdef0 \
  --destination-cidr-block 10.1.0.0/16 \
  --transit-gateway-id tgw-0123456789abcdef0

効果: 複数 VPC のデータソースにプライベートかつ低レイテンシーでアクセス可能

💰 料金情報

VPC Egress 機能自体に追加料金は発生しません。標準的な AWS ネットワーキング料金が適用されます。

項目 料金
同一 AZ 内の VPC 内通信 無料
異なる AZ 間の通信 $0.01/GB (送受信各)
VPC ピアリング経由の通信 $0.01/GB (同一リージョン)
Transit Gateway 経由の通信 $0.02/GB

🌍 利用可能リージョン

Amazon OpenSearch Service が利用可能なすべての AWS リージョンで VPC Egress 機能を利用できます。
