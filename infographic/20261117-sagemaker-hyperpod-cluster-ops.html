Amazon SageMaker HyperPod

🧭 クラスターオペレーション
スケーリング・オンデマンド Deep Health Check リクエストの追跡

リリース日: 2026 年 11 月 17 日 | 機能: クラスターオペレーション (Cluster Operations)

📌 概要

SageMaker HyperPod にクラスターオペレーションが登場。スケーリングリクエストとオンデマンド Deep Health Check リクエストを、送信から完了まで一貫して可視化できます。エラー発生時は SageMaker AI コンソールにアラートが表示され、該当リクエストのエラーイベントへ直接移動できます。

継続的プロビジョニング (Continuous Provisioning) はバックグラウンドでノードをオンライン化し、失敗ノードを自動リトライし、複数のスケーリングリクエストを同時実行します。本機能により、各リクエストの完了時刻や、クラスター上のアクティビティがどのリクエストによるものかを把握できます。新しい ListClusterOperations / DescribeClusterOperation API で独自のダッシュボード、アラート、CI/CD パイプラインにも統合可能です。

❌ Before: アップデート前の課題
  • スケーリングリクエストの進行状況を一貫して追跡する手段がなく、クラスターイベント全体から手作業で情報を探す必要があった
  • 同じインスタンスグループへの複数リクエストのうち、どれが実際にクラスターを変更したか判別できなかった
  • スケールアップが目標台数に達しない場合、無関係なアクティビティの中から失敗理由を特定する必要があった
  • オンデマンド Deep Health Check の完了時刻や影響インスタンスを確認する専用の仕組みがなかった
✅ After: アップデート後の改善
  • リクエストごとにオペレーションが自動作成され、状態 (進行中・完了・置き換え) と各インスタンスグループへの変更内容を追跡可能に
  • イベントがオペレーションに紐付き、特定リクエストのイベントのみを絞り込み可能に
  • エラー発生時はコンソールのアラートから該当エラーイベントへ直接移動可能に
  • ListClusterOperations / DescribeClusterOperation API で独自の監視基盤に統合可能に

スケーリングやオンデマンド Deep Health Check のリクエストごとにクラスターオペレーションが自動作成され、継続的プロビジョニングが記録するイベントがオペレーションに紐付けられます。結果はコンソールの Events タブと API の両方から確認できます。

⚙️ 主要機能

1️⃣ リクエスト単位の追跡 (クラスターオペレーション)
  • スケーリングまたはオンデマンド Deep Health Check のリクエストごとにオペレーションが自動作成
  • 送信から完了までの状態 (InProgress / Superseded / Done) を追跡
  • 各インスタンスグループに対する変更内容 (現在数・目標数・最小数の変化) を確認可能
  • 既存ワークフローへの変更は不要、すべてのリクエストに対して自動作成
2️⃣ イベントのオペレーション紐付け
  • HyperPod がリクエスト処理中に記録するイベントが、そのオペレーションにリンク
  • 特定リクエストのイベントのみを絞り込み、無関係なクラスターアクティビティを除外
  • スケールアップが目標台数に達しない場合、該当オペレーションから失敗理由に直接アクセス
3️⃣ 同時リクエストの判別
  • Karpenter などが同じインスタンスグループに複数リクエストを送信しても、完了か置き換え (Superseded) かを判別可能
  • どのリクエストが実際にクラスターを変更したのかを明確に特定
4️⃣ コンソールと API の両方で確認可能
  • SageMaker AI コンソールのクラスター Events タブにオペレーションを表示
  • エラー発生時はアラートから該当リクエストのエラーイベントへ直接移動
  • ListClusterOperations / DescribeClusterOperation API と ListClusterEvents の OperationId フィルターで独自ダッシュボード、アラート、CI/CD パイプラインに統合

🚦 オペレーションのステータス遷移

InProgress 進行中。継続的プロビジョニングが処理を実行中
Superseded より新しいリクエストに置き換えられた状態
Done 完了。クラスターを実際に変更したリクエスト

🔬 技術仕様

📋 クラスターオペレーションの属性

項目詳細
オペレーションタイプScaling (スケーリング)、DeepHealthCheck (オンデマンド Deep Health Check)
ステータスInProgress (進行中)、Superseded (新しいリクエストに置き換え)、Done (完了)
スケーリング詳細インスタンスグループごとの変更前後の CurrentCount / TargetCount / MinCount
Deep Health Check 詳細対象インスタンスグループ、インスタンス ID、チェック種別 (InstanceStress / InstanceConnectivity / MultiNodeTrainingValidation)
作成条件すべてのスケーリング・オンデマンド Deep Health Check リクエストに対して自動作成
前提継続的プロビジョニング (NodeProvisioningMode: Continuous) を使用するクラスター

ステップ 1: クラスターオペレーションの一覧を取得する

Bash スケーリングオペレーションの一覧 
aws sagemaker list-cluster-operations \
  --cluster-name my-hyperpod-cluster \
  --type Scaling \
  --sort-by CreationTime \
  --sort-order Descending

スケーリングオペレーションを作成日時の降順で一覧表示します。--status InProgress を指定すれば進行中のオペレーションのみに絞り込めます。

ステップ 2: 特定のオペレーションの詳細を確認する

Bash オペレーション詳細の取得 
aws sagemaker describe-cluster-operation \
  --cluster-name my-hyperpod-cluster \
  --operation-id <operation-id>

ステータスと、各インスタンスグループの変更前後のインスタンス数 (スケーリングの場合) や対象インスタンス (Deep Health Check の場合) を確認します。スケールアップが目標台数に達していない場合の調査起点になります。

ステップ 3: オペレーションに紐付くイベントを絞り込む

Bash OperationId によるイベントのフィルタリング 
aws sagemaker list-cluster-events \
  --cluster-name my-hyperpod-cluster \
  --operation-id <operation-id> \
  --sort-by EventTime \
  --sort-order Descending

--operation-id フィルターにより特定リクエストのイベントのみを取得し、無関係なアクティビティを除外して失敗理由やエラーイベントに直接アクセスできます。コンソールの場合はクラスターの Events タブから同じ情報を確認できます。

💡 メリット

💼 ビジネス面
  • 運用調査時間の短縮: スケーリング失敗時の原因特定が迅速になり、トレーニングジョブの開始遅延を最小化
  • 追加コストなし: 継続的プロビジョニング使用クラスターでは追加料金なし、既存ワークフローの変更も不要
  • 大規模トレーニングの信頼性向上: Deep Health Check の完了と影響範囲を確認してからジョブを開始可能
🔧 技術面
  • リクエストとクラスター変更の対応付け: 複数の同時リクエストのうち、どれが実際にクラスターを変更したか (Done / Superseded) を API で判別
  • 監視基盤への統合: 新 API で独自ダッシュボード、アラート、CI/CD パイプラインに組み込み可能
  • イベントのノイズ除去: OperationId フィルターでトラブルシューティングの精度が向上

⚠️ デメリット・制約事項

制限事項

⚠継続的プロビジョニングを使用する SageMaker HyperPod クラスターが対象
⚠対象となるオペレーションタイプはスケーリングとオンデマンド Deep Health Check の 2 種類
⚠新しい API を使用するには AWS CLI / SDK の更新が必要

考慮すべき点

💭Karpenter などのオートスケーラー使用時は短時間に多数のオペレーションが作成されるため、監視基盤への統合時はフィルタリング (タイプ・ステータス・期間) を活用するとよい
💭ステータスが Superseded の場合、その変更は新しいリクエストに置き換えられているため、最終的なクラスター状態は最新のオペレーションで確認する必要がある

🎯 ユースケース

1. スケールアップ失敗の原因調査

シナリオ: トレーニング用インスタンスグループを 8 台から 16 台にスケールアップしたが、目標台数に達していない。原因を特定したい。

Bash失敗したオペレーションの調査
# 進行中・完了済みのスケーリングオペレーションを確認
aws sagemaker list-cluster-operations \
  --cluster-name training-cluster \
  --type Scaling

# 該当オペレーションのイベントのみを抽出
aws sagemaker list-cluster-events \
  --cluster-name training-cluster \
  --operation-id <operation-id>

効果: 無関係なアクティビティを除外し、失敗理由 (キャパシティ不足、設定エラーなど) に直接アクセス。コンソールではアラートからエラーイベントへ直接移動できる。

2. 大規模トレーニング前の Deep Health Check 確認

シナリオ: 大規模トレーニングジョブの開始前にオンデマンド Deep Health Check を実行し、完了と対象インスタンスを確認してからジョブを投入したい。

Bash最新の Deep Health Check を確認
aws sagemaker list-cluster-operations \
  --cluster-name training-cluster \
  --type DeepHealthCheck \
  --sort-by CreationTime \
  --sort-order Descending \
  --max-results 1

aws sagemaker describe-cluster-operation \
  --cluster-name training-cluster \
  --operation-id <operation-id>

効果: いつ完了したか、どのインスタンスが対象だったか、どのチェック (InstanceStress、InstanceConnectivity、MultiNodeTrainingValidation) が実行されたかを確認し、健全性を担保した状態でジョブを開始できる。

3. Karpenter によるオートスケーリングの可視化

シナリオ: 推論トラフィックのバーストに応じて Karpenter が同じインスタンスグループに複数のスケーリングリクエストを送信している。どのリクエストが実際にクラスターを変更したかを CI/CD や監視ダッシュボードで追跡したい。

Bash直近 1 時間のオペレーションを取得
# 直近 1 時間のスケーリングオペレーションを取得して監視基盤へ連携
aws sagemaker list-cluster-operations \
  --cluster-name inference-cluster \
  --type Scaling \
  --creation-time-after "$(date -u -d '1 hour ago' +%Y-%m-%dT%H:%M:%SZ)"

効果: 各オペレーションが Done (クラスターを変更) か Superseded (新しいリクエストに置き換え) かを判別でき、オートスケーリングの挙動を正確に可視化できる。

💰 料金・利用可能リージョン

💵 料金

クラスターオペレーションは追加料金なしで利用できます。継続的プロビジョニングを使用する HyperPod クラスターで自動的に有効になり、既存のワークフローへの変更は不要です。HyperPod 自体の料金は、使用するインスタンスタイプと稼働時間に基づいて課金されます。

🌍 利用可能リージョン

SageMaker HyperPod が利用可能なすべての AWS リージョンで提供されます。

🔗 関連サービス・機能

🔄 SageMaker HyperPod 継続的プロビジョニング

本機能の前提となるプロビジョニングモード。キャパシティが利用可能になり次第バックグラウンドでノードをオンライン化し、失敗したノードを自動リトライする。

🩺 SageMaker HyperPod Deep Health Check

インスタンスのストレステストや接続性、マルチノードトレーニングの検証を行うヘルスチェック機能。オンデマンド実行分が本機能の追跡対象となる。

⚙️ Karpenter (HyperPod オートスケーリング)

HyperPod クラスターのオートスケーラー。Karpenter が送信したスケーリングリクエストもオペレーションとして追跡できる。

📊 Amazon EventBridge / CloudWatch

ListClusterOperations API と組み合わせて、独自のアラートやダッシュボードを構築できる。

📝 まとめ

SageMaker HyperPod のクラスターオペレーションにより、継続的プロビジョニング環境でのスケーリングとオンデマンド Deep Health Check のリクエストを、送信から完了まで追加コストなしで追跡できるようになりました。複数の同時リクエストやオートスケーラー経由の変更が多い環境では、トラブルシューティングの効率が大きく向上します。

✓継続的プロビジョニングを使用している場合は自動的に有効化
✓まずはコンソールの Events タブでオペレーションを確認
✓必要に応じて ListClusterOperations API を監視基盤に統合することを推奨
