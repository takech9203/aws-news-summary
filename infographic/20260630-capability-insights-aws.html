📌 概要

AWS は、リージョンごとのケイパビリティデータをお客様自身の Amazon VPC 内にデプロイできるオープンソースソリューション「Capability Insights for AWS」を発表しました。自社のネットワーク内かつ自社のガバナンス下にデータを配置したいニーズに応える、セルフホスト型ダッシュボードです。

ダッシュボードは全リージョンの AWS ケイパビリティデータを 24 時間ごとに自動更新します。対象はサービス、機能、API オペレーション、AWS CloudFormation リソースタイプを網羅。さらに Workload Analysis が CloudTrail ログと CloudFormation スタックをスキャンし、200 以上のサービスを実際に使用しているサービスへ絞り込みます。すべてのデータは VPC 境界内に留まります。

🔄 アップデート前後の変化

⚠️ Before（課題）
  • リージョンごとのケイパビリティ情報を自社所有インフラ上で参照する手段が限られていた
  • データレジデンシー / コンプライアンス要件下で外部データソースへの依存が制約に
  • ギャップ分析に数週間を要し、200 以上のサービスからの特定が煩雑
✅ After（改善）
  • リージョンケイパビリティデータを自社 VPC 内に配置し、自社ガバナンス下で管理
  • 全データが VPC 境界内に留まり、データレジデンシー要件を満たしやすい
  • Workload Analysis で実使用サービスへ絞り込み、分析を短時間のレビューへ短縮

🔍 DataFetch Lambda が EventBridge のスケジュールに基づき AWS Capabilities By Region のデータを取得して S3 に保存し、ユーザーは VPC 内から API Gateway と API Lambda を経由してダッシュボードにアクセスします。すべてのデータは VPC 境界内に留まります。

⚙️ 主要機能

📊 リージョンケイパビリティダッシュボード
  • 全リージョンの AWS ケイパビリティデータを 24 時間ごとに自動更新
  • サービス、機能、API オペレーション、CloudFormation リソースタイプを網羅
  • データソース「AWS Capabilities By Region」から情報を取得
🔬 Workload Analysis (Usage Analysis)
  • CloudTrail ログと CloudFormation スタックをスキャンし、実使用サービスを特定
  • 200 以上のサービスを実使用サービスの数まで絞り込み
  • 数週間規模のギャップ分析を短時間のレビューへ短縮
  • パーソナライズ機能 ("My Stuff") をオプトインで追加
🏠 セルフホスト型デプロイ
  • お客様自身の VPC 内にデプロイし、自社ネットワークとガバナンス下で運用
  • すべてのデータが VPC 境界内に留まる
  • オープンソース (Apache-2.0) として提供され、追加ライセンス費用は不要
🧩 オプトイン拡張スタック
  • Policy Enforcer: IAM マネージドポリシーまたは SCP を生成
  • Chat: Amazon Bedrock のツール利用ループで動作する読み取り専用の会話型アシスタント

🔧 技術仕様

CloudFormation スタック構成

スタック区分主な構成要素
Capability Insights StackコアS3、API Gateway (VPC エンドポイント)、API Lambda、DataFetch Lambda、EventBridge ルール、S3 ゲートウェイエンドポイント
Sample Environment StackオプションVPC、サブネット、EC2 インスタンス、IAM ロール (開発・テスト用)
Usage Analysis StackオプトインStep Functions、CloudTrail / CloudFormation アナライザ Lambda、Glue、Lake Formation、EventBridge スケジュール
Policy Enforcer StackオプトインDynamoDB、GSI、VPC 外の IAM ヘルパー Lambda
Chat StackオプトインVPC 外の Lambda 上で動作する Amazon Bedrock ツール利用ループ

必要な AWS サービス

区分サービス
コアスタックAWS Lambda、Amazon S3、Amazon API Gateway、Amazon EventBridge、VPC / VPC エンドポイント、AWS CloudFormation
オプトインスタックAWS Step Functions、Amazon Athena、AWS Glue、AWS Lake Formation、AWS CloudTrail、Amazon DynamoDB、AWS IAM、Amazon Bedrock

🚀 設定方法

前提条件

  • ✅ ローカル環境に AWS CLI (設定済み) と Node.js (自動インストール用)
  • ✅ DNS 解決を有効化した VPC
  • ✅ インターネット GW ありサブネット (ユーザーアクセス用) と GW なしサブネット (Lambda コンピュート用)
  • ✅ オンボーディング時に提供される S3 アクセスポイントの ARN（パブリックデータは不要、PREVIEW データは AWS アカウントチームとの連携が必要）

デプロイ手順

1
リポジトリのクローンと依存関係のインストール
Bashclone & install
git clone https://github.com/aws/capability-insights-for-aws.git
cd capability-insights-for-aws
npm install

GitHub からソースコードを取得し、デプロイに必要な依存関係をインストールします。

2
デプロイの実行
Bashdeploy
# 基本デプロイ
npm run deploy

# オプトイン機能を有効化する場合のフラグ
npm run deploy --enable-usage-analysis --enable-policy-enforcer --enable-chat

アセットのビルド、パラメータ入力受付、スタックのデプロイ、ウェブサイトのアップロード、初回同期のトリガーを実行します。

3
ダッシュボードへのアクセス

ウェブサイトは S3 にホストされ、VPC 内からのみアクセス可能です。VPN、AWS Direct Connect、AWS Client VPN、EC2 SOCKS プロキシ経由でアクセスします。手動デプロイの場合はリリースから build-assets.zip をダウンロードし、aws cloudformation deploy で AWS CLI と CloudFormation のみでデプロイできます。

⚠️ デメリット・制約事項

制限事項

✕
ウェブサイトは VPC 内からのみアクセス可能で、VPN / Direct Connect / Client VPN / SOCKS プロキシなどのアクセス経路が必要
✕
IAM と Amazon Bedrock には VPC エンドポイントが存在しないため、Policy Enforcer の IAM ヘルパー Lambda と Chat の Lambda は VPC 外で動作
✕
PREVIEW データの利用には AWS アカウントチームとの連携によるオンボーディングが必要

考慮すべき点

⚠
セルフホスト型のため、デプロイと運用はお客様の責任で実施
⚠
Chat 機能の利用には Amazon Bedrock の Claude モデルへのアクセスが必要
⚠
必要な AWS サービスが存在するリージョンへのデプロイが前提

🎯 ユースケース

1. データレジデンシー要件への対応
シナリオ: 規制対象業界の組織が、リージョンケイパビリティ情報を外部に送信せず、自社のネットワーク内で参照したい。
✅ すべてのデータが VPC 境界内に留まるため、データレジデンシーおよびコンプライアンス要件を満たしながらリージョンケイパビリティを把握できます。
2. マルチリージョンリカバリ戦略の計画
シナリオ: マルチリージョンの DR 構成を計画しているチームが、リカバリ先リージョンで必要なサービスや機能が利用可能かを確認したい。
✅ 全リージョンのサービス、機能、API オペレーション、CloudFormation リソースタイプを横断比較し、リカバリ戦略のギャップを迅速に特定できます。
3. リージョン拡張前のギャップ分析
シナリオ: 新しいリージョンへの拡張を検討しているチームが、現行で使用中のサービスが拡張先リージョンで利用可能かを確認したい。
✅ Workload Analysis が CloudTrail と CloudFormation をスキャンして実使用サービスへ絞り込むため、200 以上のサービスを精査することなく短時間で拡張可否を判断できます。

💰 料金と利用可能リージョン

💵 料金

Capability Insights for AWS 自体はオープンソースとして提供され、追加のライセンス費用は発生しません。標準的な AWS サービス料金 (Lambda、S3、API Gateway、EventBridge、Step Functions、Athena、Glue など) のみが発生し、有効化するスタックや更新頻度、データ量に応じて変動します。

🌍 利用可能リージョン

必要なサービス (AWS Lambda、Amazon S3、Amazon API Gateway、Amazon EventBridge、AWS Step Functions、Amazon Athena、AWS Glue) が存在する任意のリージョンにデプロイ可能です。

📝 まとめ

Capability Insights for AWS は、リージョンケイパビリティデータを自社の VPC 内にデプロイできるオープンソースのセルフホスト型ソリューションであり、データレジデンシーやコンプライアンス要件を持つ組織にとって有力な選択肢となります。

マルチリージョンアーキテクチャの設計やリージョン拡張、DR 戦略の計画を進めているチームは、GitHub リポジトリからソリューションをデプロイし、Workload Analysis によるギャップ分析の効率化を検討することをお勧めします。
