AWS Glue プレビュー

AWS Glue Data Catalog
ビジネスコンテキスト と セマンティック検索

📅 リリース日
2026 年 6 月 17 日

📌 概要

AWS Glue Data Catalog に、ビジネスコンテキスト と セマンティック検索 がプレビューとして追加されました。 データをスキーマやテーブル形式といった技術的な構造だけでなく、データが持つ 意味 (セマンティクス) に基づいて発見・理解できるようになります。

テーブルに グロッサリー用語 や カスタムメタデータフィールド を付与し、技術メタデータとあわせてインデックス化。新しい Glue Search API で意味ベースの検索が可能になります。S3 Tables を基盤とするテーブルにも対応します。

さらに Claude Code、Kiro、Cursor、Codex などの MCP 互換エージェントが aws-data-analytics プラグインを通じてほぼ設定なしで接続でき、推測ではなく 信頼できる定義 に基づいてデータを扱えます。

🔄 アップデート前後の変化

⛔ Before
  • スキーマやテーブル名など 技術メタデータでしか検索できず、ビジネス上の意味で探すのが困難
  • データの意味や正しい使い方が 体系的に整理されておらず、把握しにくい
  • AI エージェントが文脈を 推測に頼る 必要があった
➜
✅ After
  • グロッサリー用語やカスタムメタデータで ビジネス上の意味で検索 できる
  • テーブルの定義・内容・使い方を 1 ステップで取得 できる
  • MCP 互換エージェントが 信頼できる定義 に基づいて動作できる

⚙️ 主要機能

🏷️ ビジネスコンテキストのエンリッチメント

  • テーブルにグロッサリー用語やカスタムメタデータフィールドを追加
  • S3 Tables を基盤とするテーブルにも付与可能
  • ビジネスコンテキストを技術メタデータとあわせてインデックス化
  • エージェント向けの追加コンテキストを示す「スキル」をカタログに紐付け

🔍 セマンティック検索

  • 新しい Glue Search API でデータを「意味」で探せる
  • 構造 (スキーマ/テーブル形式) と ビジネス上の意味 の両方で発見
  • 定義・データが表す内容・適切な使い方を 1 ステップで取得
  • AI エージェントを推測ではなく信頼できる定義で動作させる

🤖 エージェントとの互換性

  • Claude Code、Kiro、Cursor、Codex などの MCP 互換エージェントが接続
  • aws-data-analytics プラグインでほぼ設定なしで接続
  • exploring-data-catalog / finding-data-lake-assets などのスキルがワークフローを支援

🧩 技術仕様 - 主要な構成要素

項目詳細
グロッサリー (Glossary)標準化されたビジネス定義をまとめる入れ物
グロッサリー用語 (Glossary Term)「アクティブユーザー」などの個別のビジネス定義
フォーム (Form Type)データ所在地や保持ポリシーなどメタデータを標準化する仕組み
アセット (Asset)カタログ上で検索・タグ付けの対象となるテーブルなどの資産
スキル (Skill)AI エージェントにドメインコンテキストを提供するためのアセット

🛠️ 設定方法

前提条件

✓サポートされているリージョンで Glue Data Catalog が設定された AWS アカウント
✓インストールおよび設定済みの AWS CLI
✓Data Catalog に登録された 1 つ以上のテーブル
✓Glue Data Catalog のアクションに対する権限を持つ IAM ロール/ユーザー

📋 手順フロー

① グロッサリー / 用語の作成
→
② 用語とアセットの関連付け
→
③ セマンティック検索の実行

ステップ 1: グロッサリーとグロッサリー用語の作成

Bashグロッサリー作成
aws glue create-glossary \
  --name "Enterprise Data Glossary" \
  --description "Standardized business definitions for enterprise data assets."

企業全体のビジネス定義を標準化するグロッサリーを作成。出力の Id を次で使用します。

Bashグロッサリー用語の登録
aws glue create-glossary-term \
  --glossary-identifier "d7xm3np5rk2w9j" \
  --name "Active User" \
  --short-description "A user with at least one login in the last 30 days." \
  --long-description "An account that has logged in at least once within the trailing 30-day window."

「アクティブユーザー」というビジネス用語を短い説明と詳細な説明とともに登録します。

ステップ 2: 用語とアセットの関連付け

Bash用語の関連付け
aws glue associate-glossary-terms \
  --identifier "arn:aws:glue:us-east-1:123456789012:table/mydb/sales_transactions" \
  --glossary-term-identifiers "c2fymbu18rtsx5"

グロッサリー用語を対象テーブル (アセット) に関連付け、ビジネス上の意味を付与します。

ステップ 3: セマンティック検索の実行

Bash基本検索
aws glue search \
  --search-text "active users"

Search API でビジネス上の意味でアセットを検索します。

Bashフィルタ付き検索
aws glue search \
  --search-text "active users" \
  --filter-clause '{"AttributeFilter":{"Attribute":"assetTypeId","Operator":"equals","Value":{"StringValue":"glue-table"}}}' \
  --max-results 10

結果を glue-table アセットタイプに限定し、最大 10 件を返します。

💡 メリット

📈 ビジネス面

  • データディスカバリーの効率化: 意味でデータを検索し素早く発見
  • データガバナンス向上: グロッサリーで定義を標準化し一貫した理解を促進
  • セルフサービス分析の促進: スキーマに詳しくなくても意味で到達

⚡ 技術面

  • AI エージェントの信頼性向上: 信頼できる定義で動作
  • 既存資産の活用: S3 Tables 含む既存資産に付与可能
  • 容易な統合: プラグインでほぼ設定なしで接続

🎯 ユースケース

① ビジネス用語によるデータ発見

シナリオ: 大規模なデータレイクで「アクティブユーザー」を表すテーブルを探したいが、テーブル名やスキーマからは判別できない。

Bash
aws glue search --search-text "active users"

効果: 意味で検索することで、技術的な名称を知らなくても目的のテーブルに到達できます。

② AI エージェントによるデータ分析

シナリオ: Claude Code や Kiro などの MCP 互換エージェントに、信頼できる定義に基づいてデータ分析を行わせたい。

Setup
Agent Toolkit for AWS の aws-data-analytics プラグインを導入し、
エージェントを Glue Data Catalog に接続する

効果: エージェントがカタログのビジネスコンテキストを参照し、推測に頼らず正確な分析を実行できます。

③ データガバナンスの標準化

シナリオ: 部門ごとに異なる用語でデータが管理されており、組織全体で定義を統一したい。

Bash
aws glue create-glossary \
  --name "Enterprise Data Glossary" \
  --description "Standardized business definitions for enterprise data assets."

効果: 全社共通グロッサリーを整備し用語を関連付けることで、一貫したデータ理解を実現します。

📝 まとめ

AWS Glue Data Catalog のビジネスコンテキストとセマンティック検索は、データを スキーマだけでなく意味で発見・理解 できるようにする重要なアップデートです。 特に MCP 互換の AI エージェントを 信頼できる定義 に基づいて動作させられる点は、生成 AI 時代のデータ活用において大きな価値があります。

まずは プレビュー対象リージョン でグロッサリーを整備し、既存テーブルへの用語付与とセマンティック検索を試すことを推奨します。
