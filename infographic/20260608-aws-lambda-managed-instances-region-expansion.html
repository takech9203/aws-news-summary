⚡ AWS Lambda

Lambda Managed Instances
利用可能リージョンの拡大

2026 年 6 月 8 日
機能: LMI
(Lambda Managed Instances)

📌 概要

AWS Lambda Managed Instances (LMI) が、新たに多くの AWS リージョンで利用可能になりました。今回の拡大により、4 つのリージョンを除くすべての商用 AWS リージョンで LMI を利用できるようになりました。

LMI は、Lambda 関数を AWS がマネージドで管理する Amazon EC2 インスタンス上で実行できる機能です。Lambda が提供する運用のシンプルさを維持しながら、特殊なコンピューティング構成へのアクセスや EC2 の料金面でのメリットを得られます。インスタンスのライフサイクル、OS とランタイムのパッチ適用、ルーティング、ロードバランシング、オートスケーリングは AWS が完全にマネージドで管理します。

各実行環境内で複数のリクエストを並列処理できるため、リソース使用率を最大化し価格性能比を向上させます。さらに Compute Savings Plans やリザーブドインスタンスなどの EC2 料金モデルを活用することで、コストをさらに最適化できます。特殊なハードウェア構成を必要とするお客様や、定常的で予測可能なワークロードに最適です。

Before / After

😟 アップデート前の課題
  • 特定のリージョンでしか LMI を利用できず、データ処理・レイテンシー要件を満たせないケースがあった
  • 標準の Lambda では GPU や大容量メモリといった特殊な構成を利用できなかった
  • 定常的なワークロードに対して、従量課金では EC2 のような長期コミットメントでのコスト最適化ができなかった
➜
🎉 アップデート後の改善
  • ほぼすべての商用リージョンで LMI を利用でき、データレジデンシーやレイテンシー要件に対応しやすくなった
  • 各リージョンで特殊なインスタンスタイプを活用した関数を実行できる
  • 各リージョンで Compute Savings Plans やリザーブドインスタンスを活用し、定常ワークロードのコストを最適化できる

イベントソースからの呼び出しを受けた Lambda 関数が、キャパシティプロバイダーで定義したコンピューティング設定に基づいてマネージド EC2 インスタンス上で実行され、CloudWatch、X-Ray、AWS Config と統合される構成を示しています。

🚀 主要機能

🖥️ マネージド EC2 インスタンス上での Lambda 実行
  • Lambda 関数を AWS がマネージドで管理する EC2 インスタンス上で実行
  • インスタンスのライフサイクル、OS とランタイムのパッチ適用、ルーティング、ロードバランシング、オートスケーリングを AWS が完全に管理
  • Lambda の運用のシンプルさを維持したまま、EC2 の柔軟性を活用
⚙️ 特殊なコンピューティング構成へのアクセス
  • 標準の Lambda では選択できない特殊なハードウェア構成を持つ EC2 インスタンスタイプを利用可能
  • x86_64 と arm64 の両アーキテクチャに対応
  • キャパシティプロバイダーで許可または除外するインスタンスタイプを指定可能
⚡ 並列リクエスト処理による価格性能比の向上
  • 各実行環境内で複数のリクエストを並列処理
  • リソース使用率を最大化し、価格性能比を改善
💰 EC2 料金モデルの活用
  • EC2 の料金面でのメリットを獲得
  • Compute Savings Plans やリザーブドインスタンスを活用してコストをさらに最適化
  • 定常的または予測可能なワークロードに適合

🔧 技術仕様

API 変更履歴

日付サービス変更内容
2026/06/02 lambda 5 updated api methods - Lambda マネージドリソースへのタグ伝播設定を追加

キャパシティプロバイダー関連の API (CreateCapacityProvider、UpdateCapacityProvider、GetCapacityProvider、ListCapacityProviders、DeleteCapacityProvider) に、Lambda がマネージドするリソースへタグを伝播するための PropagateTags 設定が追加されています。

🛠️ 設定方法

前提条件

✓利用するリージョンが LMI のサポート対象であること
✓キャパシティプロバイダーがインスタンスを起動するための VPC、サブネット、セキュリティグループが構成されていること
✓キャパシティプロバイダー運用ロールなど、必要な IAM 権限が設定されていること

3 ステップで導入

ステップ 1: キャパシティプロバイダーの作成
VPC 設定、インスタンス要件、スケーリングポリシーを定義したキャパシティプロバイダーを作成します。
ステップ 2: Lambda 関数のアタッチ
作成したキャパシティプロバイダーに Lambda 関数を関連付け、マネージド EC2 上で実行されるよう設定します (コンソール / API / IaC からも設定可)。
ステップ 3: 動作確認と可観測性の設定
関数呼び出し後、CloudWatch のメトリクス・ログ、X-Ray のトレース、AWS Config の構成変更を確認し、想定どおりに実行されているか検証します。
Bashステップ 1: キャパシティプロバイダーの作成
aws lambda create-capacity-provider \
  --capacity-provider-name my-capacity-provider \
  --vpc-config 'SubnetIds=["subnet-xxxxxxxx"],SecurityGroupIds=["sg-zzzzzzzz"]' \
  --instance-requirements 'Architectures=["arm64"]' \
  --capacity-provider-scaling-config 'MaxVCpuCount=128,ScalingMode=Auto'
Bashステップ 2: Lambda 関数のアタッチ
aws lambda update-function-configuration \
  --function-name my-function \
  --capacity-provider-name my-capacity-provider

⚖️ メリットと制約事項

✅ ビジネス面のメリット

✓コスト最適化: EC2 料金モデル + Savings Plans / リザーブドインスタンスで定常ワークロードのコストを削減
✓対応リージョンの拡大: データレジデンシーやレイテンシー要件に対応しやすい
✓運用負荷の低減: インスタンス管理やパッチ適用を AWS に委任

✅ 技術面のメリット

✓特殊ハードウェアの活用: 標準 Lambda では使えないインスタンスタイプを利用
✓価格性能比の向上: 並列リクエスト処理でリソース使用率を向上
✓既存ツールとの統合: 全 Lambda イベントソース、CloudWatch、X-Ray、AWS Config と統合

⚠️ 制限事項

✗イスラエル (テルアビブ)、中東 (バーレーン)、中東 (UAE)、アジアパシフィック (オークランド) では利用不可
✗VPC、サブネット、セキュリティグループの事前構成が必要
✗EC2 ベースのため、純粋な従量課金の標準 Lambda とはコスト構造が異なる

💡 考慮すべき点

!定常的・予測可能なワークロード向き。極端に変動が大きい場合は標準 Lambda が適する場合あり
!Savings Plans / リザーブドインスタンスの活用には利用量の見積もりとコミットメント計画が必要
!インスタンスタイプ選定とスケーリングポリシー設計がコスト・パフォーマンスに影響

💼 ユースケース

🧠 ユースケース 1: GPU を必要とする機械学習推論
シナリオ: ML モデルの推論を Lambda で実装したいが、標準 Lambda では GPU を利用できない
実装: GPU 搭載インスタンスタイプを許可するキャパシティプロバイダーを作成し、推論用 Lambda 関数をアタッチ
効果: Lambda のイベント駆動モデルと運用のシンプルさを保ちながら GPU 推論を実行
📉 ユースケース 2: 定常的なバックエンド処理のコスト最適化
シナリオ: 一定負荷で継続稼働するバックエンド API を Lambda で運用しており、コストを削減したい
実装: キャパシティプロバイダーに Compute Savings Plans を適用し、定常稼働分を長期コミットメントで最適化
効果: 予測可能なワークロードに EC2 料金メリットを適用し、コストを削減
🌍 ユースケース 3: データレジデンシー要件への対応
シナリオ: 特定の国・地域でデータを処理する必要があるが、これまで LMI が利用できないリージョンで運用していた
実装: 今回拡大されたリージョンでキャパシティプロバイダーを作成し、対象リージョン内でマネージド EC2 上で実行
効果: データレジデンシー・レイテンシー要件を満たしながら LMI のメリットを活用

💵 料金と利用可能リージョン

料金

LMI は EC2 の料金体系に基づいて課金されます。利用するインスタンスタイプの料金が適用され、Compute Savings Plans やリザーブドインスタンスを活用することで定常ワークロードのコストをさらに最適化できます。詳細は AWS Lambda の料金ページを参照してください。

利用可能リージョン

以下の 4 リージョンを除く、すべての商用 AWS リージョンで利用可能です。

イスラエル (テルアビブ) 中東 (バーレーン) 中東 (アラブ首長国連邦) アジアパシフィック (オークランド)

📝 まとめ

今回のリージョン拡大により、AWS Lambda Managed Instances がほぼすべての商用リージョンで利用できるようになり、特殊なハードウェアを必要とするワークロードや定常的なワークロードを、より多くの地域でコスト効率よく実行できるようになりました。特殊なインスタンスタイプの活用や Compute Savings Plans による最適化を検討しているチームは、対象リージョンでキャパシティプロバイダーを作成し、既存の Lambda 関数への適用を評価することをおすすめします。
