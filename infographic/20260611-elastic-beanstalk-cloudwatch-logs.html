AWS Elastic Beanstalk

☁️ コンソールの Logs タブで
CloudWatch Logs を統合表示

リリース日
2026 年 6 月 11 日

📝 概要

AWS Elastic Beanstalk は、環境ごとの Logs タブに Amazon CloudWatch Logs との統合機能を追加しました。 これにより、Elastic Beanstalk コンソールを離れることなく、環境がストリーミングしている CloudWatch のログイベントを直接確認できるようになりました。

Logs タブ内でロググループの選択・ログストリームの切り替え・フィルタリングを行い、必要に応じて CloudWatch コンソールへスムーズに遷移できます。 日常的にトラブルシューティングを行う開発者・運用担当者・ソリューションアーキテクトのコンテキストスイッチ削減を目的としています。

🔴 Before（課題）

  • ログ確認のたびに CloudWatch コンソールへ移動が必要だった
  • 対象ロググループ・ログストリームを自力で探す必要があった
  • コンソール間移動でコンテキストスイッチが発生し効率が低下

🟢 After（改善）

  • Logs タブで CloudWatch ログイベントを直接閲覧できる
  • aws/elasticbeanstalk/<env-name>/* に一致するロググループを自動表示
  • ストリーム切り替え・フィルタリング・Logs Insights への直接リンクが利用可能

⚡ 主要機能

📂 Logs タブでのロググループ表示

  • 環境がログをストリーミングしているロググループを Logs タブに表示
  • aws/elasticbeanstalk/<env-name>/* プレフィックスに一致するロググループも表示
  • CloudWatch コンソールへ移動せずに対象ロググループを把握できる

🔽 ログストリームの選択と切り替え

  • ロググループを選択すると、属するログストリームを閲覧できる
  • 既定では最も直近にアクティブだったストリームが選択される
  • ドロップダウンでストリーム間の切り替えと結果のフィルタリングが可能

🔗 View in CloudWatch ドロップダウン

  • ロググループ / ログストリーム / Logs Insights への直接リンクを提供
  • より詳細な分析が必要な場合に CloudWatch コンソールへスムーズに遷移

🔧 技術仕様

📋 ロググループの命名規則

Linux プラットフォームでは、インスタンス上のログファイルのパスにプレフィックスを付与してロググループ名が決まります。

項目詳細
ロググループプレフィックスaws/elasticbeanstalk/<env-name>/*
Linux のロググループ名/aws/elasticbeanstalk/{environment_name} + オンインスタンスのログファイルパス
既定で選択されるストリーム最も直近にアクティブなログストリーム
切り替え操作ログストリームドロップダウンによる選択とフィルタリング
外部遷移View in CloudWatch（ロググループ / ログストリーム / Logs Insights）
💡 例: Linux 環境で /var/log/nginx/error.log を取得する場合、ロググループ名は /aws/elasticbeanstalk/{environment_name}/var/log/nginx/error.log となります。

🔒 IAM 権限

Logs タブで CloudWatch のログを表示するには、ログのストリーミングが有効化されている必要があります。AWSElasticBeanstalkWebTier または AWSElasticBeanstalkWorkerTier の管理ポリシー、もしくは以下の権限がインスタンスプロファイルに必要です。

JSON インスタンスプロファイルに必要な権限 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "logs:CreateLogStream",
        "logs:PutLogEvents",
        "logs:DescribeLogGroups",
        "logs:DescribeLogStreams"
      ],
      "Resource": [
        "*"
      ]
    }
  ]
}

🚀 設定方法

✅ 前提条件

  • Elastic Beanstalk 環境が作成済みであること
  • インスタンスログの CloudWatch Logs へのストリーミングが有効化されていること
  • インスタンスプロファイルに CloudWatch Logs への書き込み権限が付与されていること
1️⃣ストリーミング有効化
↓
2️⃣Logs タブで確認
↓
3️⃣必要に応じ CloudWatch へ

① インスタンスログのストリーミングを有効化

Bash EB CLI でストリーミングを有効化 
eb logs --cloudwatch-logs enable

コンソールから設定する場合は、環境の [Configuration] → [Updates, monitoring, and logging] カテゴリで [Log streaming] を有効にします。

② Logs タブでログを確認

対象環境を開き [Logs] タブを選択。表示されたロググループ一覧から確認したいものを選ぶと、ログストリームとログイベントが表示されます。既定では最も直近にアクティブなストリームが選択されます。

③ 必要に応じて CloudWatch へ遷移

詳細分析が必要な場合は [View in CloudWatch] ドロップダウンから、ロググループ・ログストリーム・CloudWatch Logs Insights への直接リンクを選択します。

💡 メリット

📈 ビジネス面

  • 運用効率の向上: コンソール間移動が不要になり調査時間を短縮
  • トラブルシューティングの迅速化: Logs タブから即座にログ確認し障害対応を加速
  • 学習コストの低減: CloudWatch に不慣れでも EB コンソール内で参照可能

⚙️ 技術面

  • コンテキストスイッチの削減: 環境単位でロググループが整理表示される
  • 柔軟なログ参照: ストリーム切り替えやフィルタリングを Logs タブから直接実行
  • 詳細分析への導線: Logs Insights への直接リンクで高度なクエリへスムーズに移行

⚠️ デメリット・制約事項

🚧 制限事項

  • 表示には事前にインスタンスログのストリーミング有効化が必要
  • ストリーミング対象はプラットフォームごとの既定ファイルに限定
  • カスタムログは統合では直接サポートされない（CloudWatch エージェントの個別設定が必要）

🔍 考慮すべき点

  • 多数インスタンス同時起動時、CloudWatch API がスロットリングされる可能性
  • rsyslog / journald の既定レート制限でログ欠落や断続が発生する場合がある
  • CloudWatch Logs の保持期間・ライフサイクル設定で保存挙動が変わる

🎯 ユースケース

① 本番環境の障害調査

シナリオ: 本番環境でアプリケーションエラーが発生し、原因を素早く特定したい。

1対象環境を開く
2Logs タブで該当ロググループを選ぶ
3直近のログストリームでエラーを確認
✨ 効果: CloudWatch へ移動せずにエラーログを確認でき、初動対応を迅速化。

② 複数ストリームの横断確認

シナリオ: 複数インスタンスにまたがる環境で、特定時間帯のログを横断的に確認したい。

1ロググループを選択
2ドロップダウンでストリームを切り替え
3キーワードでフィルタリングして抽出
✨ 効果: ストリームを Logs タブ内で切り替えながら確認でき、調査効率が向上。

③ 高度なログ分析への移行

シナリオ: ログの傾向を集計し、特定パターンの発生頻度を分析したい。

1対象ロググループを選択
2View in CloudWatch から Logs Insights を選ぶ
3クエリで集計・分析を実行
✨ 効果: Logs タブから直接 Logs Insights へ遷移し、クエリベースの詳細分析へ移行。

💰 料金 & 利用可能リージョン

💵 料金

本機能自体に追加料金はありません。Elastic Beanstalk の利用にも追加費用はかからず、ログのストリーミングと保存には Amazon CloudWatch Logs の標準料金が適用されます。取り込みデータ量・保存量・Logs Insights でのスキャンデータ量に応じて課金されます。

🌍 リージョン

Elastic Beanstalk が利用可能なすべての商用リージョンおよび GovCloud (US) リージョンの、すべてのプラットフォームブランチで利用可能。

全 AWS 商用リージョン AWS GovCloud (US) 全プラットフォームブランチ

🔗 関連サービス・機能

📊 Amazon CloudWatch Logs

Elastic Beanstalk 環境のログを保存・参照するためのバックエンドサービス。

🔍 Amazon CloudWatch Logs Insights

ロググループに対してクエリベースの分析を実行する機能。

❤️ AWS Elastic Beanstalk Enhanced Health

拡張ヘルスを有効化すると、環境のヘルス情報も CloudWatch Logs へストリーミングできる。

📌 まとめ

今回のアップデートにより、Elastic Beanstalk コンソールの Logs タブから CloudWatch のログイベントを直接確認でき、ログ調査時のコンテキストスイッチが大幅に削減されます。

すべての商用リージョンと GovCloud (US) で追加料金なく利用できるため、運用中の環境ではインスタンスログのストリーミングを有効化し、Logs タブを活用したトラブルシューティングフローへの移行を検討することをおすすめします。
