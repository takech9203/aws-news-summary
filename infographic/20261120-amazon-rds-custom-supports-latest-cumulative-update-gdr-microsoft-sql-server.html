Amazon RDS Custom for SQL Server

🗄️ Microsoft SQL Server 最新 CU / GDR 更新プログラムをサポート

📅 リリース日: 2026 年 11 月 20 日 | SQL Server 2019 CU32 + GDR / SQL Server 2022 CU27 + GDR

📋 概要

Amazon RDS Custom for SQL Server が、Microsoft SQL Server の最新の Cumulative Update (CU) および GDR (General Distribution Release) 更新プログラムをサポートしました。SQL Server 2019 向けの CU32 + GDR (KB5128494) と、SQL Server 2022 向けの CU27 + GDR (KB5126934) が利用可能です。

RDS Custom for SQL Server は、OS やデータベース環境へのアクセスを必要とするレガシーアプリケーションやサードパーティ製アプリケーション向けに、基盤環境のカスタマイズを可能にするマネージドデータベースサービスです。既存のインスタンスは、マネジメントコンソール、AWS SDK、または AWS CLI からアップグレードできます。

📖 CU と GDR の違い

更新タイプ 内容
CU (Cumulative Update) セキュリティ修正に加え、バグ修正や機能改善を含む累積的な更新プログラム
GDR (General Distribution Release) セキュリティ関連の重要な修正に限定した更新プログラム

🛠️ 設定方法

✅ 前提条件

✓Amazon RDS Custom for SQL Server のインスタンスが稼働していること
✓アップグレード対象のエンジンバージョン (SQL Server 2019 または 2022) を使用していること
✓アップグレード前にスナップショットなどのバックアップを取得しておくこと (推奨)
1
利用可能なエンジンバージョンの確認
Bash エンジンバージョン一覧の取得 
aws rds describe-db-engine-versions \
    --engine custom-sqlserver-ee \
    --query 'DBEngineVersions[].EngineVersion'

新しいバージョン (15.00.4500.2.v1 または 16.00.4305.5.v1) が表示されることを確認します。エディションに応じて custom-sqlserver-se や custom-sqlserver-web を指定します。

2
インスタンスのアップグレード
Bash エンジンバージョンの変更 
aws rds modify-db-instance \
    --db-instance-identifier my-custom-sqlserver-instance \
    --engine-version 16.00.4305.5.v1 \
    --apply-immediately

--apply-immediately を指定すると即時に適用され、指定しない場合は次のメンテナンスウィンドウで適用されます。

3
アップグレード結果の確認
Bash ステータスとバージョンの確認 
aws rds describe-db-instances \
    --db-instance-identifier my-custom-sqlserver-instance \
    --query 'DBInstances[0].[DBInstanceStatus,EngineVersion]'

ステータスが available に戻り、エンジンバージョンが新しいバージョンになっていることを確認します。

⚙️ 技術面
✓累積的な修正の一括適用: CU は累積的なため、1 回のアップグレードでこれまでの修正をまとめて適用
✓複数のアップグレード手段: コンソール / CLI / SDK から実行でき、自動化パイプラインへの組み込みが容易
✓2019 / 2022 両バージョン対応: 利用中の SQL Server バージョンに関わらず最新パッチを適用可能

⚠️ デメリット・制約事項

🚧 制限事項
✗対象は SQL Server 2019 (CU32 + GDR) と SQL Server 2022 (CU27 + GDR) のみで、それ以外のバージョンは今回の発表の対象外
✗アップグレードは自動では適用されず、利用者側での実行が必要
🤔 考慮すべき点
⚠アップグレード中は一時的にインスタンスが利用できないため、メンテナンスウィンドウの計画が必要
⚠RDS Custom は OS / DB への変更が可能なため、独自のカスタマイズがアップグレードに影響しないか事前検証を推奨
⚠適用前に Microsoft の KB 記事で修正内容と既知の問題の確認を推奨

🎯 ユースケース

🏦 ユースケース 1: セキュリティパッチ適用ポリシーへの準拠

シナリオ: 金融機関などで、公開から一定期間内に最新セキュリティパッチの適用が義務付けられている SQL Server データベースを RDS Custom で運用している。

Bash本番環境への適用
aws rds modify-db-instance \
    --db-instance-identifier prod-sqlserver-2022 \
    --engine-version 16.00.4305.5.v1

効果: GDR に含まれるセキュリティ修正を適用し、社内のパッチ適用ポリシーと監査要件を満たせる。

🧪 ユースケース 2: 検証環境での事前テストを伴う段階的アップグレード

シナリオ: 本番適用前に、検証環境で CU32 の修正内容がアプリケーションに影響しないかを確認したい。

Bash検証環境へ先行適用
# 検証環境へ先行適用
aws rds modify-db-instance \
    --db-instance-identifier staging-sqlserver-2019 \
    --engine-version 15.00.4500.2.v1 \
    --apply-immediately

効果: 検証環境で動作確認を行った上で本番環境に適用でき、アップグレードに伴うリスクを最小化できる。

🌙 ユースケース 3: メンテナンスウィンドウでの計画的適用

シナリオ: 業務時間外のメンテナンスウィンドウでパッチを適用し、業務影響を避けたい。

Bashメンテナンスウィンドウでの適用
aws rds modify-db-instance \
    --db-instance-identifier prod-sqlserver-2019 \
    --engine-version 15.00.4500.2.v1 \
    --no-apply-immediately

効果: 次回のメンテナンスウィンドウでアップグレードが実行され、業務時間中のダウンタイムを回避できる。
