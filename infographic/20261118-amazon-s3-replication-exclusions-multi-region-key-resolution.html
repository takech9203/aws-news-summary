Amazon S3

🪣 S3 Replication に除外設定と
Multi-Region キー解決が登場

📅 リリース日: 2026 年 11 月 18 日 | 機能: Exclusions / Multi-Region Key Resolution

📝 概要

Amazon S3 Replication に 2 つの新機能が追加されました。除外設定 (Exclusions) は、バケット全体をレプリケーションしながら、特定のプレフィックスやタグ付きオブジェクト (ログや実験用データなど) をスキップできます。Multi-Region キー解決 は、レプリケーション先リージョンでソースオブジェクトに対応する AWS KMS Multi-Region キーを自動的に使用して各レプリカを暗号化します。

多数のテナントを収容するマルチテナントバケットや共有バケットで特に有効で、従来は多数のレプリケーションルールが必要だった構成を単一のルールに集約できます。後から追加されるテナントにも自動的に適用されます。

数百 → 1
テナントごとのルールを単一ルールに集約
追加料金なし
両機能ともオプションで無料
全リージョン
すべての AWS リージョンで利用可能
❌ アップデート前の課題
✗バケット全体のレプリケーションでは不要なデータ (ログや一時データ) も複製され、ストレージ・転送コストが増加
✗特定データのみ複製するには、プレフィックスやタグごとに多数のルールを作成・管理する必要があった
✗テナントごとに異なる KMS キーを使う場合、キーごとにルールを分け、テナント追加のたびに更新が必要だった
✅ アップデート後の改善
✓除外設定で、バケット全体を複製しつつ特定プレフィックスやタグ付きオブジェクトをスキップ可能に
✓レプリケーション先で対応する KMS Multi-Region キーを自動的に使用してレプリカを暗号化
✓多数のルールを単一ルールに集約でき、後から追加されるテナントにも自動対応

単一のレプリケーションルールで、除外対象 (特定プレフィックスやタグ付きオブジェクト) をスキップしながらバケット全体をレプリケーションし、レプリケーション先では対応する KMS Multi-Region キーでレプリカを暗号化する流れ

⚡ 主要機能

🚫 1. 除外設定 (Exclusions)
✓バケット全体を対象としながら、特定のプレフィックス配下のオブジェクトをレプリケーションから除外
✓特定のタグが付与されたオブジェクトの除外も可能
✓ログや実験用データのスキップにより、ストレージコストと転送コストを削減
🔑 2. Multi-Region キー解決 (Multi-Region Key Resolution)
✓KMS Multi-Region キーで暗号化されたオブジェクトを、レプリケーション先の対応するレプリカキーで自動的に暗号化
✓ソースオブジェクトの暗号化要件に準拠した状態でレプリカを維持
✓テナントごとに固有のキーを使うマルチテナントバケットでも単一ルールでレプリケーション可能
🔄 3. ルールの集約と自動追従
✓従来は多数のレプリケーションルールが必要だった構成を単一ルールに集約
✓数百のテナントを収容するバケットでも、後から追加されるテナントを含めて単一ルールで対応

🛠️ 設定方法

✅ 前提条件

✓ソースバケットとレプリケーション先バケットの両方でバージョニングが有効であること
✓S3 がオブジェクトをレプリケーションするための IAM ロール (KMS キー使用時は対象キーへの復号・暗号化権限を含む) が設定されていること
✓Multi-Region キー解決を使用する場合、レプリケーション先リージョンに対応する KMS Multi-Region レプリカキーが作成されていること

📋 手順

1
レプリケーションルールの作成

S3 コンソールでソースバケットの [管理] タブから [レプリケーションルール] を作成し、ルールのスコープとしてバケット全体を指定

2
除外設定の追加

除外するプレフィックス (例: logs/) や除外対象のオブジェクトタグ (例: environment=experimental) を指定。該当オブジェクトは自動的にスキップされる

3
Multi-Region キー解決の有効化

ルールの暗号化設定で有効化すると、KMS Multi-Region キーで暗号化されたソースオブジェクトは、レプリケーション先の対応するレプリカキーで暗号化される

Bash レプリケーション設定の確認 
# 設定後、レプリケーション設定を確認する
aws s3api get-bucket-replication --bucket my-source-bucket

このコマンドは、ソースバケットに設定されたレプリケーション設定 (ルール、除外設定、暗号化設定を含む) を取得して表示します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓コスト削減: 不要データの複製スキップでレプリカのストレージコストとリージョン間転送コストを削減
✓運用負荷の軽減: 多数のルールを単一ルールに集約し、作成・更新・監査の負荷を軽減
✓コンプライアンス維持: レプリカが暗号化要件に準拠した状態を自動維持し、監査対応が容易に

⚙️ 技術面のメリット

✓シンプルな構成: 「全体を複製し、一部を除外」という直感的な設計が可能に
✓自動スケール: 新テナントやプレフィックス追加時も設定変更が不要
✓暗号化の一貫性: S3 がキーの対応関係を自動解決し、リージョンごとのキー指定ミスを防止

🚧 制限事項

⚠️Multi-Region キー解決は KMS Multi-Region キー使用時に有効な機能で、通常の単一リージョンキーには適用されない
⚠️レプリケーション先リージョンに対応する Multi-Region レプリカキーの事前作成が必要
⚠️除外されたオブジェクトは複製されないため、DR 要件の対象データを誤って除外しないよう設計時の確認が必要

🤔 考慮すべき点

⚠️既存ルールを集約する場合、除外条件が既存の包含条件と等価になるかを事前に検証することを推奨
⚠️除外によりレプリケーションされないデータは、別途バックアップが必要か検討する
⚠️詳細な設定要素や制限値は公式ドキュメントの最新情報を確認する

💡 ユースケース

🏢 1. マルチテナント SaaS バケットのリージョン間レプリケーション

シナリオ数百のテナントをプレフィックスで分離し、テナントごとに固有の KMS Multi-Region キーで暗号化しているバケットを、DR 目的で別リージョンにレプリケーションしたい。

実装各テナントのレプリカキーを DR リージョンに作成 → バケット全体を対象とする単一ルールを作成 → Multi-Region キー解決を有効化

効果テナントごとのルール作成が不要になり、新規テナント追加時もルール変更なしで自動的にレプリケーション。各レプリカはテナント固有のキーで暗号化された状態を維持。

💰 2. ログ・一時データを除外したコスト効率の高い DR 構成

シナリオアプリケーションデータとアクセスログが同一バケットに保存されており、DR リージョンにはアプリケーションデータのみをレプリケーションしたい。

実装バケット全体を対象とするルールを作成 → 除外設定に logs/ プレフィックスを指定 → 実験用データには experimental タグを付与してタグ除外を設定

効果重要データのみをレプリケーションすることで、DR リージョンのストレージコストとリージョン間データ転送コストを削減。

🔐 3. 本番環境から分析環境への選択的データ共有

シナリオ本番バケットのデータを分析用アカウントのバケットに SRR で共有するが、個人情報を含む特定プレフィックスは共有対象から除外したい。

実装本番バケットから分析バケットへのクロスアカウント SRR ルールを作成 → 除外設定に個人情報を含むプレフィックス (例: pii/) を指定

効果共有してはいけないデータをレプリケーション段階で確実に除外でき、データガバナンス要件を満たしながら分析環境へのデータ提供を自動化。

💵 料金

除外設定と Multi-Region キー解決の両機能は、追加料金なしで利用できます。S3 Replication 自体の標準料金は従来どおり適用されます。

料金項目内容
除外設定 / Multi-Region キー解決追加料金なし
レプリカのストレージレプリケーション先の storage class に応じた標準料金
リージョン間データ転送 (CRR)標準のデータ転送料金
KMS リクエストレプリカ暗号化に伴う KMS API リクエスト料金

💡 除外設定によりレプリケーション対象データが減ることで、これらの既存コストの削減が期待できます。S3 RTC 使用時は RTC 料金も適用されます。詳細は S3 料金ページ を参照してください。

🌏 利用可能リージョン

✅ すべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

🔑 AWS KMS Multi-Region キー

複数リージョンで同一のキーマテリアルを共有するキー。Multi-Region キー解決機能の前提となる

⏱️ S3 Replication Time Control

15 分以内のレプリケーションを SLA で保証。本アップデートの機能と組み合わせて利用可能

📦 S3 Batch Replication

既存オブジェクトをオンデマンドでレプリケーション。ルール設定前の既存データの同期に使用

🌐 S3 Multi-Region Access Point

リージョン間フェイルオーバーを実現。双方向レプリケーションと組み合わせた高可用性構成に使用

🎯 まとめ

S3 Replication の除外設定と Multi-Region キー解決により、マルチテナントバケットや共有バケットのレプリケーション設計が大幅に簡素化されます。多数のルールで運用している既存環境では、単一ルールへの集約によるコスト削減と運用負荷軽減の効果が大きいため、現在のレプリケーション構成の見直しを推奨します。
