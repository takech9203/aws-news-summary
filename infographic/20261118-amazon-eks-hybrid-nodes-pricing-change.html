☁️ EKS Hybrid Nodes の大規模ホスト向け料金値下げ

📅 リリース日: 2026 年 11 月 18 日 | 課金対象 vCPU 数を 1 ノードあたり最大 32 vCPU に制限する料金改定

📝 概要

Amazon EKS Hybrid Nodes の料金が改定され、1 ノードあたりの課金対象 vCPU 数に 32 vCPU の上限 が設定されました。これまではノードが Kubernetes に報告する vCPU 数に比例して料金が発生していましたが、32 vCPU を超える大規模ノードでは超過分に課金されなくなります。

データレジデンシー、低レイテンシー、規制要件などの理由でオンプレミスに残す必要がある 大規模ベアメタルサーバーや GPU サーバー 上で AI/ML のトレーニングや推論を実行するユーザーにとって、コスト面のメリットが大きいアップデートです。

❌ アップデート前の課題

  • ✗ノードの全 vCPU 数に比例して課金され、大規模なベアメタル / GPU サーバーの接続コストが高額に
  • ✗ハイパースレッディング有効なベアメタルでは物理コアあたり 2 vCPU とカウントされ、課金対象が増大しやすい
  • ✗オンプレミス GPU サーバーの AI/ML ワークロードで vCPU 数ベースの課金が大きな負担に

✅ アップデート後の改善

  • ✓課金対象 vCPU 数が最大 32 vCPU に制限され、大規模ホストのコストが vCPU 数に比例しなくなった
  • ✓第 1 ティアで 64 vCPU ノードは 50%、256 vCPU ノードは 88% のコスト削減
  • ✓段階的な従量課金ティアも引き続き適用され、使用量が増えるほど実効単価がさらに低下

オンプレミスの各サーバーを EKS Hybrid Nodes として接続した場合の課金イメージです。32 vCPU を超えるノードはすべて 32 vCPU 分として課金されるため、大規模ホストほど削減率が大きくなります。

⚙️ 主要機能

🔢 1 ノードあたり 32 vCPU の課金上限

  • ノードが Kubernetes に報告する vCPU 数が 32 を超えても、課金対象は 32 vCPU まで
  • 64 vCPU、256 vCPU のノードはいずれも 32 vCPU 分として課金される
  • 32 vCPU 以下のノードは従来どおり実際の vCPU 数で課金される

📉 既存の段階的料金ティアとの併用

  • 月間の累積 vCPU 時間に応じた段階的な割引ティアは従来どおり適用される
  • 使用量が増えるほど実効単価が下がるため、大規模環境では二重のコスト削減効果がある

🔄 新規ノードへの自動適用

  • 新しく接続するハイブリッドノードには自動的に新料金が適用される
  • 接続済みの既存ノードに適用するには、ノードを一度削除して再接続する必要がある

🧮 課金の仕組み

項目詳細
課金対象Kubernetes に報告される vCPU 数 (1 ノードあたり最大 32 vCPU)
ハイパースレッディングベアメタルで有効な場合、物理コアあたり 2 vCPU としてカウント
課金期間ノードがクラスターに参加してから削除されるまで

EC2 利用時EC2 インスタンスをハイブリッドノードのインフラとして使用した場合も Hybrid Nodes 料金が発生

🛠️ 設定方法

✅ 前提条件

✓Amazon EKS クラスターが作成済みであること
✓オンプレミスまたはエッジ環境のサーバーが Hybrid Nodes の要件 (対応 OS、AWS へのネットワーク接続など) を満たしていること
✓既存ノードに新料金を適用する場合は、ノードの削除・再接続によるワークロードへの影響を計画しておくこと
1

新規ノードの接続

Bashnodeadm でクラスターに接続
# ハイブリッドノード上で nodeadm を使用してクラスターに接続
sudo nodeadm init -c file://nodeConfig.yaml

nodeadm init はノード設定ファイルに基づいてオンプレミスサーバーを EKS クラスターに参加させるコマンドです。新規に接続するノードには新料金が自動適用されます。

2

既存ノードへの新料金適用 (削除と再接続)

Bashdrain → 削除 → 再接続
# ノードを安全に退避してからクラスターから削除
kubectl drain <node-name> --ignore-daemonsets --delete-emptydir-data
kubectl delete node <node-name>

# ノード上でクリーンアップ後、再接続
sudo nodeadm uninstall
sudo nodeadm install <k8s-version> --credential-provider <provider>
sudo nodeadm init -c file://nodeConfig.yaml

kubectl drain で Pod を他ノードへ退避し、kubectl delete node でクラスターから削除します。その後 nodeadm でノードを再セットアップして再接続すると、新料金が適用されます。

3

課金の確認

AWS Billing and Cost Management コンソールまたは Cost Explorer で、EKS Hybrid Nodes の vCPU 時間の課金が上限 32 vCPU で計算されていることを確認します。

💡 メリット

💼 ビジネス面

✓大規模ホストの大幅なコスト削減: 第 1 ティアで 64 vCPU ノードは 50%、256 vCPU ノードは 88% の削減
✓オンプレミス投資の有効活用: 既存の大規模ベアメタル / GPU サーバーをコストを気にせず EKS の管理下に統合
✓予測しやすいコスト構造: ノードあたりの課金上限が明確になり、大型ホスト追加時の見積もりが容易に

🔧 技術面

✓AI/ML ワークロードとの親和性: vCPU 数が多い GPU サーバーでの推論・トレーニングのコスト効率が向上
✓運用の一元化: オンプレミスの大規模ノードも EKS コントロールプレーンで一元管理し、クラウドと同じツールチェーンを利用
✓段階的ティアとの相乗効果: 使用量ベースのティア割引と組み合わせ、スケールするほど実効単価が低下

⚠️ デメリット・制約事項

🚧 制限事項

✗既存の接続済みノードには自動適用されず、ノードの削除と再接続が必要
✗32 vCPU 以下のノードには料金面の変化はない
✗EC2 インスタンスをハイブリッドノードとして使用した場合も Hybrid Nodes 料金は発生する

🤔 考慮すべき点

→既存ノードの再接続時はワークロードの退避 (drain) が必要なため、メンテナンスウィンドウの計画が必要
→ハイパースレッディング有効時は物理コアあたり 2 vCPU とカウントされるため、16 コア超のサーバーは上限 32 vCPU の恩恵を受ける
→vCPU 数は Kubernetes に報告される値に基づくため、課金確認時はノードの capacity を確認するとよい

🎯 ユースケース

1️⃣ オンプレミス GPU サーバーでの AI/ML 推論

シナリオ: データレジデンシー要件により顧客データを国内データセンターから持ち出せない企業が、256 vCPU の GPU サーバーで推論ワークロードを実行する。

実装例: GPU サーバー (256 vCPU) を EKS Hybrid Nodes として接続し、NVIDIA device plugin を導入して GPU ワークロードをスケジューリング。

✨ 効果: 従来 256 vCPU 分の課金が 32 vCPU 分となり、第 1 ティアで約 88% のコスト削減。EKS によるクラウドと一貫した運用も実現。

2️⃣ エッジ拠点の大型ベアメタルサーバー統合

シナリオ: 低レイテンシーが要求される工場やエッジ拠点の 64 vCPU ベアメタルサーバーを EKS で統合管理したい。

実装例: 各拠点のベアメタルサーバーを nodeadm で EKS クラスターに接続し、ノードラベルで拠点別にワークロードを配置。

✨ 効果: 第 1 ティアで 50% のコスト削減。拠点のサーバーをクラウド側の EKS コントロールプレーンから一元管理できる。

3️⃣ 既存ハイブリッドノードの料金最適化

シナリオ: すでに 32 vCPU 超のハイブリッドノードを複数運用しており、新料金を適用してコストを削減したい。

実装例: メンテナンスウィンドウ中に kubectl drain でワークロードを退避し、ノードを削除・再接続して新料金を適用。

✨ 効果: 再接続のみで追加コストなしに新料金が適用され、以降の月額費用が削減される。

💰 料金

EKS Hybrid Nodes は、ノードが Kubernetes に報告する vCPU 数に基づく vCPU 時間課金です。今回の改定で 1 ノードあたりの課金対象は 最大 32 vCPU に制限されました。月間の累積 vCPU 時間に応じた段階的ティア (0.020 USD 〜 0.006 USD/vCPU 時間) は従来どおり適用されます。

🔗 関連サービス・機能

⚙️ Amazon EKS Hybrid Nodes

オンプレミス・エッジのサーバーを EKS クラスターのノードとして接続する機能。今回の料金改定の対象。

🏠 Amazon EKS Anywhere

オンプレミスで Kubernetes クラスター全体を実行するオプション。Hybrid Nodes はコントロールプレーンをクラウド側に置く点が異なる。

🏢 AWS Outposts

AWS 管理のハードウェアをオンプレミスに設置するサービス。自社保有ハードウェアを活用したい場合は Hybrid Nodes が選択肢となる。

📌 まとめ

EKS Hybrid Nodes の課金対象 vCPU 数が 1 ノードあたり最大 32 vCPU に制限され、大規模なオンプレミスサーバーや GPU サーバーの利用コストが 最大 88% 削減 されました。32 vCPU 超のノードを運用中の場合は、メンテナンスウィンドウを計画してノードの削除・再接続を行い、新料金の適用を推奨します。
