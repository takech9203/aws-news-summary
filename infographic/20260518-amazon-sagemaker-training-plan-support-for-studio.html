📋 概要

Amazon SageMaker Studio の IDE (JupyterLab および Code Editor) が、SageMaker Flexible Training Plans (FTP) を通じた GPU キャパシティ予約に対応。需要の高い高性能 GPU コンピューティングリソースへの予測可能なアクセスが実現し、予算内で ML ワークフローを実行できるようになる。

FTP を活用することで、オンデマンドインスタンスと比較して最大 65% のコスト削減が可能。完全なセルフサービスのプロキュアメント体験が提供され、インフラストラクチャ管理は不要。

🔄 Before / After 比較

❌ Before

✗ Studio IDE での GPU 利用はオンデマンド料金のみ、コスト高
✗ 高性能 GPU (p5, p4d 等) は需要が高く確保困難

✅ After

✓ FTP で最大 65% のコスト削減を実現

⚡ 主要機能

🛒 セルフサービスプロキュアメント
SageMaker FTP コンソールから直接キャパシティ予約を購入可能。インスタンスタイプ、予約期間、開始日をユーザーが選択でき、AWS サポートへの問い合わせや手動プロセスが不要。
🔗 Studio IDE との統合
購入したプランが Studio UI のインスタンスドロップダウンに自動表示。JupyterLab および Code Editor の両方で利用可能で、インフラストラクチャ管理は SageMaker が自動処理。
🔔 プロアクティブな期限通知
予約期間の終了が近づくと IDE 内で通知を表示。ユーザーは作業を保存する時間を確保でき、予期しないリソース解放を防止。

⚠️ デメリット・制約事項

✗予約開始後のインスタンスタイプ変更は不可 (購入時に確定)
✗予約期間終了後はリソースが解放、事前のデータ保存が必要
✗利用率が低い場合、オンデマンドよりコスト高になる可能性
✗長期コミットメントが必要、ワークロードの見積もりが重要
✗予約キャパシティは他ワークロードとの共有が不可の場合あり

🎯 ユースケース

🧠 大規模モデルのインタラクティブ開発
AI/ML チームが大規模言語モデルの微調整を JupyterLab 上でインタラクティブに実施するため、数週間にわたり GPU リソースが必要。
インスタンス: ml.p5.48xlarge / 期間: 4 週間 / 開始日: プロジェクト開始日
→ 高性能 GPU を確実に確保しつつ、最大 65% のコスト削減。リソース不足リスクを排除。
🔄 定期的な ML ワークフローの実行
データサイエンスチームが毎月のモデル再トレーニングとハイパーパラメータチューニングを Code Editor で実施。
インスタンス: ml.g5.24xlarge / 期間: 月次で繰り返し購入 / 開始日: 月初
→ 予測可能なコストで定期的な ML ワークフローを安定的に実行。
👥 複数メンバーでの GPU リソース共有
小規模な ML チームが限られた予算内で GPU リソースを確保し、チームメンバー間でスケジュールを調整して利用。
インスタンス: ml.g6.12xlarge / 期間: 8 週間 / 開始日: 四半期開始
→ オンデマンドより大幅にコスト削減。チーム全体の GPU 利用計画を可視化。
