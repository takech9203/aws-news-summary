AWS Glue Data Quality

📊 Distribution Analyzer による
分布統計データプロファイリング

リリース日: 2026 年 7 月 27 日 | 機能: Distribution Analyzer による分布統計 (Distribution Statistics) のデータプロファイリング

💡 概要

AWS Glue Data Quality が新しい Distribution Analyzer をサポート。DQDL の Analyzers ブロックに Distribution アナライザーを記述するだけで、数値カラムには ヒストグラム (等幅ビンによる度数分布)、カテゴリカル / 日付 / ブールカラムには 値の頻度分布 を自動生成します。

歪度 (スキュー)、外れ値、予期しないパターンを カスタムコードなし で特定でき、既存の DQDL ルールセットと統合されているため 1 回の評価実行 で品質チェックと分布プロファイリングを両方実行できます。生成された統計は S3 に保存され、Athena でのクエリや SageMaker Unified Studio での可視化に活用できます。

❌ アップデート前の課題

  • 統計は Mean、Sum、StandardDeviation などのスカラー値中心で、データの「形状」を直接プロファイリングできなかった
  • ヒストグラムや頻度分布には Spark / Pandas のカスタムコードと別ジョブの運用が必要だった
  • 歪度・外れ値・カテゴリ値の偏りの検出に品質チェックとは別の仕組みが必要だった
  • 実行ごとにビン境界が変わると時系列での分布比較が困難だった

✅ アップデート後の改善

  • DQDL の Analyzers ブロックに 1 行追加するだけでヒストグラムと値分布を生成
  • bins パラメータでカスタムビン数 (最大 20) を指定可能
  • 1 回の評価実行で品質チェックと分布プロファイリングを同時実行
  • 統計は S3 保存 + Athena クエリ、ListDataQualityStatistics / GetDataQualityResult API で取得可能
  • ビン境界の固定 (frozen edges) と自動リビニングで一貫した分布比較とレンジ変化への追従を両立

DQDL ルールセット内の Distribution Analyzer が品質チェックと同じ評価実行の中で分布統計を生成し、結果を S3 と API 経由で Athena や可視化ツールに連携するフロー

🚀 主要機能

📈 1. 数値カラムのヒストグラム生成

カラムの値レンジを等幅の区間 (ビン) に分割し、各ビンの件数をカウント。bins パラメータでビン数を指定可能 (デフォルト 20、最大 20)。歪度や外れ値、値レンジのシフトをカスタムコードなしで検出できます。

🏷️ 2. カテゴリカル / 日付 / ブールカラムの値分布生成

各ディスティンクト値の出現頻度をカウントし、頻度の降順でソートして上位 20 件の最頻値を返却。カテゴリ値の偏りや予期しない値の混入を把握できます。

🔗 3. 既存 DQDL ルールセットとの統合

Rules ブロックの品質チェックと Analyzers ブロックの分布プロファイリングを 1 回の評価実行で処理。Distribution AllColumns で全カラムの分布を一括生成できます。NULL 値は分布計算から除外されます。

🧊 4. ビン境界の固定 (Frozen Edges) と自動リビニング

初回実行時にビン境界を計算し、以降は同じ境界を再利用して実行間の分布比較を可能に。範囲外の値はオーバーフロービンにカウントされ、2% 超で情報レベル、5% 超でより強い Observation を生成。5% 超が 3 回連続すると自動でビン境界を再計算します (rebin = false でオプトアウト可能)。

💾 5. 分布統計の保存と活用

分布統計は Amazon S3 に保存され Amazon Athena でクエリ可能。ListDataQualityStatistics / GetDataQualityResult API でも取得でき、SageMaker Unified Studio などの可視化ツールやモニタリングワークフローと統合できます。

DQDL Distribution アナライザーの構文

ルールセットの記述例

DQDL 品質チェックと分布プロファイリングを 1 回の評価で処理 
Rules = [
    RowCount > 100,
    Completeness "Salary" > 0.9
]
Analyzers = [
    Mean "Salary",
    StandardDeviation "Salary",
    Distribution "Salary" with bins = 15,
    Distribution "Department"
]

👍 メリット

💼 ビジネス面

✓データ品質問題の早期発見: 分布の歪みや外れ値を可視化し、下流の分析や ML モデルに影響が及ぶ前に検出
✓開発・運用コストの削減: カスタムコードや別ジョブが不要になり、既存の品質評価パイプラインに統合
✓データへの信頼性向上: 「データがどのような形をしているか」を継続的に把握し、データドリブンな意思決定を支援

🔧 技術面

✓1 回の評価で完結: Analyzer を追加するだけで品質チェックと分布プロファイリングを同一実行で処理
✓実行間で比較可能な統計: frozen edges により時系列での分布比較やデータドリフト検出が有効に機能
✓自動リビニングによる運用レス: 恒常的なレンジ変化には自動再計算、一時的な変動ではビンを安定維持
✓エコシステムとの統合: S3 + Athena、API、SageMaker Unified Studio などと連携可能

⚠️ デメリット・制約事項

🚫 制限事項

✗Analyzers は AWS Glue ETL でのみサポートされ、Data Catalog ベースの Data Quality では使用不可
✗Distribution は Analyzers ブロック専用で、ルールとしての合否判定やジョブ停止アクションは設定不可
✗数値カラムのビン数は最大 20
✗非数値カラムの値分布は上位 20 件の最頻値のみ返却
✗NULL 値は分布計算から除外される

🤔 考慮すべき点

⚠frozen edges では初回実行時のデータレンジが基準となるため、初回データが代表的なレンジを持つことを確認する
⚠レンジが恒常的に変化するデータでは、自動リビニングの挙動を理解した上で rebin = false の要否を判断する
⚠オーバーフロービンへの集中 (2% 超 / 5% 超) で Observation が生成されるため、モニタリングでの活用設計が望ましい
⚠S3 ストレージ料金と Athena スキャン料金が別途発生する

🎯 ユースケース

💰 ユースケース 1: 給与データの歪度・外れ値検出

シナリオ: 人事データレイクの給与カラムに、桁誤りなどの異常値が混入していないかを継続的に監視したい。

DQDL
Rules = [
    Completeness "Salary" > 0.95
]
Analyzers = [
    Distribution "Salary" with bins = 20
]

効果: ヒストグラムにより給与分布の形状を毎回の評価で記録し、末尾ビンへの異常な集中や分布の歪みからデータ入力ミスや上流システムの不具合を早期に検出できる。

🛒 ユースケース 2: カテゴリカラムのデータドリフト監視

シナリオ: EC サイトの注文データで、注文ステータスや地域コードなどのカテゴリ値の構成比が想定外に変化していないかを監視したい。

DQDL
Rules = [
    RowCount > avg(last(3))
]
Analyzers = [
    Distribution "order_status",
    Distribution "region_code"
]

効果: 値の頻度分布 (上位 20 件) を実行ごとに記録し、Athena で時系列比較することで、新しいステータス値の出現や地域構成比の急変といったデータドリフトを検出できる。

🤖 ユースケース 3: ML 特徴量の分布プロファイリングと可視化

シナリオ: SageMaker で学習する ML モデルの特徴量について、学習データの分布を定期的にプロファイリングし、モデル再学習の判断材料にしたい。

DQDL
Rules = [
    RowCount > 0
]
Analyzers = [
    Distribution AllColumns
]

効果: 全カラムの分布統計を 1 回の評価で一括生成し、S3 に保存された統計を SageMaker Unified Studio で可視化することで、特徴量の分布シフトを踏まえた再学習タイミングの判断ができる。

本機能の基盤となるルール定義言語。Rules と Analyzers を組み合わせて品質チェックと統計生成を宣言的に記述できる。

📌 まとめ

AWS Glue Data Quality の Distribution Analyzer により、DQDL ルールセットに 1 行追加するだけで、数値カラムのヒストグラムとカテゴリカルカラムの値分布を カスタムコードなしで生成できるようになりました。frozen edges と自動リビニングにより実行間で比較可能な統計が得られるため、データドリフト検出や ML 特徴量の監視に特に有効です。

既存の Glue Data Quality 評価を運用しているチームは、まず主要な数値・カテゴリカラムに Distribution アナライザーを追加し、Athena や SageMaker Unified Studio での分布モニタリングを試すことを推奨します。
