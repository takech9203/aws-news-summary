データ損失防止 DLP

📅 リリース日: 2026 年 8 月 12 日 ｜ Purview の秘密度ラベルで Quick のファイル共有を自動制御

📌 概要

Amazon Quick が Microsoft Purview と統合され、組織の DLP ポリシーを Quick 環境全体に適用できるようになりました。Purview テナントを接続すると、チャット・スペース・ナレッジベースで共有される機密ファイルを秘密度ラベル (Sensitivity Labels) に基づいて分類・保護します。

管理者はラベルごとに強制アクションを設定でき、「機密ファイルが承認されていないチャネルの外に共有されない」ことを追加ツールなしで保証できます。主な対象は、Microsoft 365 / Purview で情報ガバナンスを運用する組織の IT 管理者およびセキュリティチームです。

ファイルを拒否

制限なしで許可
❌ Before (アップデート前)
  • Purview の DLP ポリシーを Quick 内のファイル共有に適用する手段がなかった
  • 機密ラベル付きファイルがチャット・スペース・ナレッジベース同期で意図しない範囲に共有されるリスクを自動防止できなかった
  • Quick 向けに別のガバナンスツールや手動レビュープロセスが必要だった
✅ After (アップデート後)
  • 既存の Purview 秘密度ラベルをそのまま利用し、Quick でのファイル取り扱いを自動制御
  • ラベルごとに Block / Warn / Allow を設定。未マッピング・無ラベルにはデフォルトアクションが適用され、保護の漏れがない
  • Purview 到達不能時の動作も指定でき、フェイルクローズ運用が可能

⚙️ 主要機能

🏷️ 1. 秘密度ラベルに基づく強制アクション

Purview で定義・公開済みの秘密度ラベル (例: Public、Confidential、Highly Confidential) をテナントからライブで読み取り、ラベルごとに Block / Warn / Allow をマッピング。親ラベルと子ラベルの階層に対応し、明示的に上書きしない限りサブラベルは親のアクションを継承します。

🎯 2. 3 つの適用対象機能 (Capabilities)
  • スペース: コラボレーションワークスペースにアップロードされるファイル
  • チャット: チャット会話を通じて共有されるファイル
  • ナレッジベース: SharePoint、OneDrive などのコネクタ経由で同期されるコンテンツ

設定ごとに適用対象を選択可能。1 つの機能に適用できる設定は 1 つのみ。

🛡️ 3. デフォルトアクションによる保護の網羅

未マッピングのラベル、無ラベルファイル、サポート外のファイル形式にはデフォルトアクションを適用。セットアップ後に新しく公開されたラベルも即座にカバーされ、保護の空白期間が発生しません。

🔌 4. プロバイダー停止時アクション (Provider Outage Action)

Purview が一時的に到達不能な場合の動作を Block (フェイルクローズ)、Warn、Allow (フェイルオープン) から選択可能。機密データを扱うナレッジベースでは Block が推奨されています。

🔍 5. テスト機能と可観測性

ダッシュボードのテストアイコンから、ラベル付きファイルの S3 URI を指定してドライランを実行し、本番適用前に期待どおりのアクションを確認できます。ナレッジベース同期の判定結果は Quick Observability レポートで確認できます (BLOCKED / ADDED / MODIFIED)。

📋 強制アクションの動作 (機能別)

アクション チャット / スペース (対話型) ナレッジベース (バックグラウンド同期)
🚫 Block ファイルが拒否され、エラーメッセージが表示される インデックスに取り込まれず、Observability レポートに BLOCKED と記録される
⚠️ Warn 警告が表示され、続行またはキャンセルを選択できる 警告プロンプトはなく、ファイルは取り込まれる (ユーザーが待機しないため)
✅ Allow 制限なしで共有される 通常どおり取り込まれる

📡 API 変更履歴 (2026/08/12 - Amazon QuickSight 名前空間)

16 new / 4 updated API メソッドが追加されました。DLP 設定管理に直接関連する API は以下の 5 つです。

→CreateDlpSetting: DLP 設定を作成
→UpdateDlpSetting / DeleteDlpSetting: 更新・削除
→DescribeDlpSetting / ListDlpSettings: 詳細取得・一覧表示
＋同日に承認ワークフロー (CreateApprovalPolicy など 5 メソッド) とリミット管理 (CreateLimitsProfile、BatchDescribeUserLimits など 6 メソッド) の API も追加

🔐 Secrets Manager シークレットの形式

JSON Purview 認証情報 (キー名は正確に 3 つ) 
{
    "clientId": "abcdef12-3456-7890-abcd-ef1234567890",
    "clientSecret": "<client secret value>",
    "tenantId": "11111111-1111-1111-1111-111111111111"
}

キー名の変更や欠落は検証エラーになります。Quick が保持するのはシークレットの ARN のみで、認証情報は実行時に読み取られ、コンソール表示・API 応答・ログ出力されることはありません。

🛠️ 設定方法

✅ 前提条件

✓Purview / Microsoft 365 テナントで秘密度ラベルを公開済みであること
✓Entra ID でアプリ登録を作成し、必要な API 権限 (UnifiedPolicy.Tenant.Read、SensitivityLabels.Read.All、必要に応じて Files.Read.All) を付与していること
✓Quick アカウントと同じ AWS アカウントの Secrets Manager に JSON 形式で認証情報を保存していること
✓Quick 管理コンソールの [Permissions] → [AWS resources] でシークレットの読み取り権限を付与していること (顧客管理 KMS キー使用時はサービスロールに kms:Decrypt を IAM で直接追加)

📝 手順

1
DLP 設定ウィザードを開く

Quick 管理コンソールで [Governance] → [Data loss prevention] → [Create DLP configuration] を選択。ウィザードは Provider、Credentials、Label mapping、Review の 4 ステップ構成。

2
プロバイダーと認証情報を設定する

[Microsoft Purview] を選択し、設定名とシークレットの ARN を入力。[Validate] で接続と権限を検証。検証が成功するまで次へ進めず、不足はインラインで指摘される。

3
ラベルマッピングを設定する

Capabilities (適用対象機能)、Default action (保守的運用では Block 推奨)、Sensitivity labels (ラベルごとのアクション、サブラベルは親を継承)、Provider outage action (機密データでは Block 推奨) を選択。

4
確認と有効化

設定内容を確認し、Active / Inactive トグルで即時強制するかを選択して [Create]。Active のままにすると新規ファイルアップロードに対して即座に強制が開始される。

5
動作をテストする

ダッシュボードの設定カード → テストアイコン → s3://bucket/key を指定してドライランを実行。読み取り専用の実行で、ファイルや実データには影響しない。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓既存ガバナンス投資の活用: Purview の秘密度ラベル体系と DLP ポリシーを追加ツールなしで Quick に拡張
✓コンプライアンス強化: 規制産業で求められる統制を AI アシスタント環境にも適用
✓監査可能性: DLP 判定結果が Observability レポートに記録され追跡可能

🔧 技術面のメリット

✓一元的なラベル管理: ラベルはライブ読み込みで二重管理が不要。新規ラベルもデフォルトアクションで即カバー
✓フェイルクローズ設計が可能: デフォルトと停止時の両アクションを Block に設定して漏れを防止
✓セキュアな認証情報管理: Secrets Manager + 実行時読み取りでログや API 応答に露出しない

🚧 制限事項

✗対応 DLP プロバイダーは現時点で Microsoft Purview のみ
✗アクティブにできる DLP 設定はアカウントあたり 1 つ (作成上限は 10)
✗500 MB 超のファイルはスキャンされない (デフォルトアクションを適用)
✗ナレッジベースでは Warn の警告は表示されず、ファイルは取り込まれる
✗Azure Rights Management 保護付きラベルのファイルはスキャンされない

⚠️ 考慮すべき点

⚠ファイルを評価するすべてのリージョンへのシークレットのレプリケートと、全レプリカ ARN へのアクセス付与が必要。顧客管理 KMS キー使用時はマルチリージョンキーなどの追加設計が必要
⚠顧客管理 KMS キーの kms:Decrypt はコンソールから付与できず IAM で直接編集が必要。手動編集後はコンソールからのロール管理が不可になる
⚠Observability レポートの BLOCKED は DLP 拒否と内部エラーの両方を示すため、原因の切り分けに注意
⚠新しいラベルは明示的にマッピングするまでデフォルトアクションが適用され、ダッシュボードに未マッピング警告が表示される

💡 ユースケース

🏦 ユースケース 1: 金融サービス企業における機密ファイルの共有制御

シナリオ: スペースとチャットの全社展開時に、「Highly Confidential」は共有禁止、「Internal」は警告付きで許可したい。

Text設定例
Label mapping:
  Highly Confidential → Block
  Internal            → Warn
  Public              → Allow
Default action        → Block
Provider outage action → Block
Capabilities          → Spaces、Chat
✅ 効果: 最高機密ファイルは即座に拒否、社内限定ファイルには警告でユーザーの自覚を促進。無ラベルファイルもブロックされ、ラベル付け運用の徹底につながる。
📚 ユースケース 2: SharePoint 連携ナレッジベースのフェイルクローズ運用

シナリオ: SharePoint / OneDrive のドキュメントを AI 検索に活用したいが、機密文書のインデックス取り込みは絶対に避けたい。

Text設定例
Entra ID アプリ権限: UnifiedPolicy.Tenant.Read、SensitivityLabels.Read.All、Files.Read.All
Capabilities          → Knowledge bases
Default action        → Block
Provider outage action → Block
同期後: Quick Observability レポートで BLOCKED / ADDED / MODIFIED を確認
✅ 効果: 同期のたびに各ファイルのラベルが評価され、機密ラベル・無ラベル・Purview 障害時のファイルは一切取り込まれない。判定結果はレポートで監査可能。
🧪 ユースケース 3: 段階的なロールアウトと本番前検証

シナリオ: DLP を全社適用する前に、ラベルマッピングが意図どおり動作するかを検証したい。

Text検証フロー
1. Inactive 状態で DLP 設定を作成 (強制は開始されない)
2. テストアイコンから s3://test-bucket/labeled-sample.docx を指定してドライラン
3. Allow / Warn / Block の判定結果を確認
4. 問題なければトグルを Active に切り替えて強制を開始
✅ 効果: 実データに影響を与えずにラベル判定を検証でき、誤ブロックによる業務影響や誤許可による情報漏えいリスクを本番適用前に排除。

💰 料金と利用可能リージョン

💵 料金

DLP 機能自体の追加料金に関する記載は公式発表にはありません。Amazon Quick の利用料金は既存の料金体系に従います。なお、AWS Secrets Manager のシークレット保管・API 呼び出し、および顧客管理 KMS キー使用時の AWS KMS 料金が別途発生します。

🔗 関連サービス・機能

→Microsoft Purview: 秘密度ラベルの定義・公開を行う DLP プロバイダー。Quick はテナントからラベルをライブで読み取る
→Microsoft Entra ID: Quick が Purview に接続するためのアプリ登録と API 権限を管理する ID 基盤

🎯 まとめ

Amazon Quick の Microsoft Purview 連携 DLP は、既存の Purview 秘密度ラベル体系を AI アシスタント環境にそのまま拡張できる、エンタープライズ導入の障壁を下げる重要なガバナンス機能です。
