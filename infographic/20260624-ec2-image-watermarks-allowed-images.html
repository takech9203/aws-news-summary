Amazon EC2

🖼️ AMI ウォーターマーク

リリース日
2026 年 6 月 24 日

📌 概要

Amazon EC2 は、プライベート AMI にカスタム識別子を埋め込む AMI ウォーターマークを発表しました。 一度適用すると、識別子は派生したすべての AMI に自動的に引き継がれ、リージョン間コピー、実行中インスタンスからの再作成、他アカウントとの共有でも保持されます。

各ウォーターマークには AMI ID、所有者 ID、リージョン、作成タイムスタンプなどのメタデータが含まれ、何回コピーされても来歴 (プロベナンス) が維持されます。 Allowed AMIs と組み合わせて承認済みウォーターマークを持つ AMI のみに起動を制限でき、宣言型ポリシーで組織全体に大規模適用できます。

⚠️ Before — アップデート前の課題
  • タグで出所を示していたが、コピーや派生時に確実に引き継がれず、改ざんも容易だった
  • リージョン間コピーや再作成された AMI と元ソースの関連付け追跡が困難
  • 共有 AMI が組織承認の正規 AMI であることを示す仕組みがなかった
✅ After — アップデート後の改善
  • ウォーターマークが派生・コピー・共有 AMI に自動継承され、出所追跡が確実に
  • ImageWatermarks 条件で承認済み AMI のみに起動を制限可能に
  • 宣言型ポリシーで複数アカウント・複数リージョンに大規模適用

ソースアカウントで適用したウォーターマークが派生 AMI に継承され、利用アカウントの Allowed AMIs が評価し、承認済み AMI のみ起動を許可する流れ。

⚙️ 主要機能

🏷️ カスタム識別子の埋め込み
  • プライベート AMI にカスタム識別子 (ウォーターマーク) を埋め込む
  • ウォーターマークキーは account-id:watermark-name の形式
  • 信頼できる AMI の識別、出所追跡、ガバナンスポリシー適用に活用
🔄 派生 AMI への自動継承
  • 元の AMI から派生したすべての AMI に自動で引き継がれる
  • リージョン間コピー、実行中インスタンスからの再作成でも継承
  • 他アカウントと共有した AMI でも表示されたまま保持
📋 メタデータの保持
  • AMI ID、所有者 ID、リージョン、作成タイムスタンプなどを含む
  • 何回コピーされても来歴 (プロベナンス) が維持される
  • アカウントをまたいで関連 AMI を検索・フィルタリング可能
🔗 Allowed AMIs および宣言型ポリシーとの統合
  • ImageWatermarks 条件で承認済み AMI のみに起動を制限
  • 宣言型ポリシーで複数アカウント・複数リージョンに大規模適用
  • Console、CLI、SDK、EC2 Image Builder のビルドパイプラインから適用

🔧 技術仕様

Allowed AMIs の ImageWatermarks フィルタ

いずれかのウォーターマークがいずれかのフィルタエントリに一致すれば AMI を許可します (OR ロジック)。

フィールド詳細
WatermarkKey一致させるウォーターマークキー (account-id:watermark-name)
SourceImageRegionウォーターマークを最初に適用した AMI のリージョン
MaximumDaysSinceSourceImageCreated適用時のソース AMI の最大経過日数
MaximumDaysSinceWatermarkCreatedウォーターマーク適用からの最大経過日数

Allowed AMIs の制限

項目上限
ImageCriteria あたりの ImageCriterion 数10
ImageCriterion あたりの ImageWatermarks 値数50
ImageCriterion あたりの ImageProviders 値数200

API 変更履歴

日付サービス変更内容
2026/06/22 ec2 GetAllowedImagesSettings と ReplaceImageCriteriaInAllowedImagesSettings がウォーターマークによる AMI フィルタリングに対応

ウォーターマーク条件の設定例

JSON 承認済みウォーターマークを持つ AMI のみ許可 
{
    "ImageCriteria": [
        {
            "ImageWatermarks": [
                {
                    "WatermarkKey": "111122223333:prod-baseline",
                    "MaximumDaysSinceWatermarkCreated": 90
                }
            ]
        }
    ]
}

アカウント 111122223333 の prod-baseline ウォーターマークを持ち、適用から 90 日以内の AMI のみが許可されます。

🚀 設定方法

前提条件

✓ウォーターマークを適用する対象のプライベート AMI が存在すること
✓Allowed AMIs 操作用の IAM 権限 (GetAllowedImagesSettings、EnableAllowedImagesSettings、ReplaceImageCriteriaInAllowedImagesSettings など) を保有
✓組織全体に適用する場合は AWS Organizations と宣言型ポリシーを利用できること
1
AMI にウォーターマークを適用する

Console、CLI、SDK、または EC2 Image Builder のビルドパイプラインから適用。適用後は派生したすべての AMI に自動で引き継がれます。

2
Allowed AMIs を監査モードで評価する
Bash監査モードで有効化
# 実際の制限をかけずに影響を事前確認する
aws ec2 enable-allowed-images-settings \
    --allowed-images-settings-state audit-mode

describe-images のレスポンスの ImageAllowed フィールドで各 AMI が利用可能になるかを判断できます。

3
ウォーターマーク条件を設定して有効化する
Bash条件設定と有効化
# ウォーターマーク条件を含む ImageCriteria を設定
aws ec2 replace-image-criteria-in-allowed-images-settings \
    --image-criteria file://image-criteria.json

# 評価後、Allowed AMIs を有効化
aws ec2 enable-allowed-images-settings \
    --allowed-images-settings-state enabled

影響がないことを確認したうえで有効化。組織全体には宣言型ポリシーで複数アカウント・複数リージョンに一括設定します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓ガバナンス強化: 承認済み正規 AMI のみに制限し、コンプライアンスを満たしやすい
✓追加コストなし: 全リージョンで追加料金なく全顧客が利用可能
✓大規模適用: 宣言型ポリシーで一貫したガバナンスを適用

🛠️ 技術面のメリット

✓来歴の確実な追跡: 派生・コピー・共有 AMI に自動継承
✓既存機能との統合: Allowed AMIs や EC2 Image Builder と統合
✓アカウント横断の検索: メタデータで関連 AMI を検索・フィルタ

🚧 制限事項・考慮点

✗ウォーターマークを適用できるのはプライベート AMI のみ
✗1 つの ImageCriterion の ImageWatermarks は最大 50 件
✗Allowed AMIs は自アカウント所有 AMI の利用を制限せず、公開/共有 AMI の検出・利用のみ制御
⚠有効化前に必ず監査モードで影響範囲を確認することを推奨
⚠ECS / EKS / Lambda Managed Instances は Amazon 発行 AMI に依存するため amazon エイリアスの併用を推奨
⚠過度に厳しい条件 (短すぎる経過日数) はインスタンス起動失敗の可能性

💡 ユースケース

1. ゴールデン AMI のガバナンス

シナリオ: セキュリティチームが標準化したゴールデン AMI を作成し、全アカウントで承認済み AMI のみを利用させたい。

実装: Image Builder でゴールデン AMI をビルドしウォーターマーク適用 → ImageWatermarks 条件にキーを指定 → 宣言型ポリシーで組織全体に適用。

効果: 派生 AMI を含め承認済みゴールデン AMI のみが起動に使用され、未承認 AMI の使用を防止。

2. 鮮度を考慮した AMI 制限

シナリオ: パッチ適用が最近行われた新しい AMI のみを許可し、古い AMI からの起動を防ぎたい。

JSON30 日以内に限定
{
    "ImageWatermarks": [
        {
            "WatermarkKey": "111122223333:prod-baseline",
            "MaximumDaysSinceWatermarkCreated": 30
        }
    ]
}

効果: 適用から 30 日以内の AMI のみ許可され、常に最新ベースイメージを利用する運用を強制。

3. クロスアカウント共有 AMI の信頼性確認

シナリオ: 別アカウントから共有された AMI が信頼するソースに由来するか確認したい。

実装: 信頼できる発行元が適用した AMI を共有 → 利用側で ImageWatermarks 条件を設定 → メタデータ (所有者 ID、リージョン、作成タイムスタンプ) で来歴確認。

効果: 共有 AMI でもウォーターマークが保持されるため、出所が確認できる信頼できる AMI のみを利用。

💰 料金・利用可能リージョン

料金: AMI ウォーターマークはすべての AWS リージョンで追加料金なしで全顧客が利用できます。

利用可能リージョン: AWS China (北京、Sinnet 運営) および AWS China (寧夏、NWCD 運営)、AWS GovCloud (US) を含むすべての AWS リージョンで利用可能です。

🔗 関連サービス・機能

Allowed AMIs AWS Organizations 宣言型ポリシー EC2 Image Builder
  • Allowed AMIs: ImageWatermarks を評価条件として承認済み AMI のみに起動を制限
  • 宣言型ポリシー: 複数アカウント・複数リージョンに Allowed AMIs 設定を大規模適用
  • EC2 Image Builder: AMI ビルドパイプラインの一部としてウォーターマークを適用

📝 まとめ

AMI ウォーターマークは、AMI の来歴を確実に追跡し、組織全体で AMI ガバナンスを強化する重要な機能です。 派生 AMI、リージョン間コピー、共有 AMI に自動継承されるため、信頼できる AMI の識別が容易になります。 まずは Allowed AMIs を監査モードで有効化してウォーターマーク条件の影響を確認したうえで、 宣言型ポリシーによる組織全体への展開を検討することをお勧めします。
