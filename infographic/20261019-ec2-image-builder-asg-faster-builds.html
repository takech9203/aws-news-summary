⚙️ EC2 Image Builder

🚀 Auto Scaling Group 連携による高速イメージビルド

📅 リリース日: 2026 年 10 月 19 日 | 機能: ASG の既存インスタンスを利用したイメージビルド (Parent Instance)

📝 概要

EC2 Image Builder が、Amazon EC2 Auto Scaling Group (ASG) 内で既に稼働中のインスタンスを利用してイメージをビルドする機能をサポートしました。インフラストラクチャ設定に ASG を指定すると、ビルドのたびに新しいインスタンスを起動する代わりに、ASG から稼働中のインスタンスを 1 台選択してビルドコンポーネントを適用します。インスタンスの起動とブートストラップの待ち時間が不要になるため、ビルド時間を短縮できます。

ASG はインスタンスがビルドに使用されるたびにプールを自動的に補充するため、ウォームなインスタンスプールを常に維持できます。本機能は完全にオプトインであり、既存のパイプラインには影響しません。

ASG を指定したパイプラインでは、Image Builder が稼働中インスタンスを選択してタグ付与とデタッチを行い、SSM 経由でビルドを実行します。ASG の希望容量は変わらないため、代替インスタンスが自動起動されてプールが補充されます。

⭐ 主要機能

1️⃣ ASG からの稼働中インスタンスの選択

インフラストラクチャ設定の parentInstance に ASG 名を指定すると、ビルド時に ASG 内のインスタンスをランダムに 1 台選択します (インスタンスの指定は不可)。選択条件は「InService 状態」「SSM Agent がオンライン」「同じプラットフォームとアーキテクチャ」の 3 点です。コンテナビルドの場合、コンテナレシピのインスタンス設定でイメージが指定されているときのみアーキテクチャを比較します。

2️⃣ タグ付与とデタッチによるプール管理

ビルド開始前に対象インスタンスへ Name、CreatedBy、Ec2ImageBuilderArn とインフラストラクチャ設定のリソースタグを付与し、ASG からデタッチします。希望容量は変更されないため、ASG が代替インスタンスを自動起動してプールを補充します (デタッチされたインスタンスは ASG に戻りません)。本機能が適用されるのはビルドフェーズのみで、テストインスタンスは従来どおり起動されます。

3️⃣ 容量待機タイムアウト capacityWaitTimeoutSeconds

条件を満たすインスタンスがない場合、capacityWaitTimeoutSeconds (最大 1 時間) まで待機し、利用可能にならなければビルドは失敗します。新規インスタンス起動へのフォールバックは行われません。値が 0 または未指定の場合は即座に失敗します。チェック間隔は最初の 5 分間が約 15 秒ごと、その後は約 45 秒ごとです。

4️⃣ ビルド後のインスタンス保持 terminateInstanceOnCompletion

今回の API 更新で追加された terminateInstanceOnCompletion を false に設定すると、ビルド成功後もインスタンスを保持できます。AMI ビルドでは CreateImage ステップがイメージ作成前にインスタンスを停止するため、保持されたインスタンスはビルド後に stopped 状態となります。

📋 ビルドインスタンスに適用される設定

稼働中のインスタンスを使用するため、ビルドインスタンスは ASG の起動テンプレートの設定を維持します。以下の設定は適用されません。変更が必要な場合は ASG の起動テンプレートを更新します。

設定ソース適用されない設定

イメージレシピベースイメージ、ブロックデバイスマッピング、ユーザーデータ (出力 AMI はインスタンス自身のボリュームから作成される)
コンテナレシピインスタンス設定

🔐 実行ロールに必要な権限

EC2ImageBuilderExecutionPolicy マネージドポリシーに加えて、以下の権限が必要です。

JSON 実行ロール追加ポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "TagInstanceInASG",
            "Effect": "Allow",
            "Action": [
                "ec2:CreateTags",
                "ec2:DeleteTags"
            ],
            "Resource": "arn:aws:ec2:*:*:instance/*",
            "Condition": {
                "StringEquals": {
                    "ec2:ResourceTag/aws:autoscaling:groupName": "my-build-pool"
                }
            }
        },
        {
            "Sid": "DescribeASG",
            "Effect": "Allow",
            "Action": "autoscaling:DescribeAutoScalingGroups",
            "Resource": "*"
        },
        {
            "Sid": "DetachFromASG",
            "Effect": "Allow",
            "Action": "autoscaling:DetachInstances",
            "Resource": "arn:aws:autoscaling:*:*:autoScalingGroup:*:autoScalingGroupName/my-build-pool"
        }
    ]
}

ポリシーを自作する代わりに、EC2ImageBuilderParentInstanceASGRoleTemplate ロールテンプレートから必要な権限を持つロールを作成することもできます (コンソールの「Create new role with required permission」または AWS CLI の acquire-role コマンド)。なお、このロールテンプレートは AWS GovCloud (US) リージョンおよび中国リージョンでは利用できません。

🛠️ 設定方法

📌 前提条件

  • ビルド用のインスタンスプールとなる ASG を、インフラストラクチャ設定と同じアカウント・リージョンに作成済みであること
  • ASG の起動テンプレートに SSM Agent とビルドに必要な権限を持つインスタンスプロファイルが設定されていること
  • パイプラインに EC2ImageBuilderExecutionPolicy と ASG 操作権限を持つ実行ロールを指定できること
1
ASG の起動テンプレートにインスタンスプロファイルを設定
Bash起動テンプレート更新とインスタンスリフレッシュ
# 起動テンプレートの新バージョンを作成し IAM インスタンスプロファイルを設定
aws ec2 create-launch-template-version \
    --launch-template-name my-build-pool-template \
    --source-version 1 \
    --launch-template-data '{"IamInstanceProfile":{"Name":"EC2InstanceProfileForImageBuilder"}}'

# 稼働中のインスタンスを新しい設定に置き換えるためインスタンスリフレッシュを開始
aws autoscaling start-instance-refresh \
    --auto-scaling-group-name my-build-pool

新しいインスタンスプロファイルは新規起動インスタンスにのみ適用されるため、インスタンスリフレッシュで稼働中のインスタンスを新しい設定に置き換えます。

2
実行ロールを作成
Bashロールテンプレートからロールを作成
# ロールテンプレートから ASG 連携に必要な権限を持つロールを作成
aws iam acquire-role \
    --template-arn arn:aws:iam::aws:role-template/imagebuilder.amazonaws.com/EC2ImageBuilderParentInstanceASGRoleTemplate:3 \
    --replacement-values \
    'AutoScalingGroupName={Values=[my-build-pool]},RoleNameSuffix={Values=[my-build-pool]}'

EC2ImageBuilderExecutionPolicy と ASG 操作権限を持つ実行ロール EC2ImageBuilderParentInstanceASG-my-build-pool を作成します。

3
インフラストラクチャ設定に ASG を指定
BashparentInstance に ASG を指定
# parentInstance に ASG 名と容量待機タイムアウトを指定してインフラストラクチャ設定を作成
aws imagebuilder create-infrastructure-configuration \
    --name my-asg-infra-config \
    --instance-profile-name EC2InstanceProfileForImageBuilder \
    --parent-instance '{"autoScalingGroup":{"name":"my-build-pool","capacityWaitTimeoutSeconds":600}}'

利用可能なインスタンスがない場合に最大 600 秒待機するように設定しています。既存のインフラストラクチャ設定に追加する場合は update-infrastructure-configuration を使用します。

4
パイプラインに実行ロールを設定して実行
Bashパイプラインの更新と実行
# パイプラインに実行ロールを設定
aws imagebuilder update-image-pipeline \
    --image-pipeline-arn arn:aws:imagebuilder:ap-northeast-1:123456789012:image-pipeline/my-pipeline \
    --image-recipe-arn arn:aws:imagebuilder:ap-northeast-1:123456789012:image-recipe/my-recipe/1.0.0 \
    --infrastructure-configuration-arn arn:aws:imagebuilder:ap-northeast-1:123456789012:infrastructure-configuration/my-asg-infra-config \
    --execution-role arn:aws:iam::123456789012:role/EC2ImageBuilderParentInstanceASG-my-build-pool

# パイプラインを実行
aws imagebuilder start-image-pipeline-execution \
    --image-pipeline-arn arn:aws:imagebuilder:ap-northeast-1:123456789012:image-pipeline/my-pipeline

Image Builder は ASG から条件を満たすインスタンスを選択し、ビルドコンポーネントを適用してイメージを作成します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓ビルド時間の短縮: 起動とブートストラップの時間が不要になり、イメージの提供リードタイムを短縮
✓追加コストなし: 本機能自体に追加料金はなく、全リージョンで利用可能
✓既存環境への影響なし: 完全オプトインのため、リスクなく段階的に導入可能

🔧 技術面のメリット

✓ウォームプールの活用: 常にビルド可能なインスタンスプールを維持し、連続実行にも対応
✓自動補充: 希望容量が維持されるため、代替インスタンスが自動起動されプールが枯渇しない
✓インスタンス保持オプション: ビルド後のインスタンスを保持してデバッグや再利用に活用可能

⚠️ 制限事項

✗インスタンスはランダムに選択され、指定は不可 (特定インスタンスを使う場合は LaunchInstance ステップアクションの parentInstanceId 入力を使用)
✗利用可能なインスタンスがない場合、新規起動へのフォールバックは行われずビルドは失敗 (待機は最大 1 時間)
✗適用されるのはビルドフェーズのみで、テストインスタンスは従来どおり起動
✗ASG はインフラストラクチャ設定と同じアカウント・リージョンに存在する必要がある
✗ロールテンプレートは AWS GovCloud (US) と中国リージョンでは利用不可

🤔 考慮すべき点

!ビルドインスタンスは ASG の起動テンプレート設定を維持するため、インフラ設定やレシピの該当項目は適用されない。出力 AMI もインスタンス自身のボリュームから作成される
!ビルドプール用 ASG の常時稼働インスタンスに EC2 利用料金が発生。プールサイズとビルド頻度のバランスを検討
!サービスリンクロールでは ASG を操作できないため、実行ロールの指定が必須
!ビルドのたびにデタッチと代替起動が発生するため、ASG のスケーリングアクティビティやモニタリングへの影響を確認

💡 ユースケース

🏆 ユースケース 1: ゴールデン AMI パイプラインの高速化

シナリオ: セキュリティパッチ適用のため、毎日複数のゴールデン AMI をビルドしている。インスタンス起動と SSM Agent 登録の待ち時間がビルド時間の大きな割合を占めている。

  • ベース AMI を起動する ASG (希望容量 2〜3 台) をビルドプールとして作成
  • インフラストラクチャ設定の parentInstance に ASG を指定
  • 既存の日次パイプラインのインフラストラクチャ設定を差し替え
✅ 効果: 起動とブートストラップの待ち時間が排除され、日次のイメージ提供サイクルが短縮される。
🔁 ユースケース 2: CI/CD パイプラインでの頻繁なイメージビルド

シナリオ: アプリケーションのリリースごとに AMI をビルドする CI/CD パイプラインがあり、1 日に何度もビルドが実行される。ビルド時間がデプロイ全体のボトルネックになっている。

  • ビルド頻度に合わせた希望容量の ASG を作成 (消費されると自動補充)
  • capacityWaitTimeoutSeconds を設定し、同時実行時の待機を許容
  • パイプラインの実行ロールに ASG 操作権限を付与
✅ 効果: 連続するビルドでも常にウォームなインスタンスが利用でき、リリースのリードタイムが安定して短縮される。
🔍 ユースケース 3: ビルド失敗時のデバッグ効率化

シナリオ: ビルドコンポーネントの開発中で、ビルド結果の検証やトラブルシューティングのためにビルド後のインスタンスを確認したい。

  • インフラストラクチャ設定で terminateInstanceOnCompletion を false に設定
  • ビルド完了後、stopped 状態のインスタンスを起動して内容を確認
  • 確認後は手動でインスタンスを終了 (ボリューム料金と稼働中の料金が発生)
✅ 効果: ビルド成果物の検証やコンポーネントのデバッグが実機で行えるようになり、開発サイクルが効率化される。

💰 料金と利用可能リージョン

💵 料金

本機能に追加料金はありません。EC2 Image Builder 自体は無料で、ビルドに使用する EC2 インスタンス、EBS ボリューム、作成されたイメージの保存などの基盤リソースに対して通常の料金が発生します。

ASG のビルドプールとして常時稼働させるインスタンスの EC2 利用料金が発生する点に注意が必要です。また、terminateInstanceOnCompletion を false にして保持したインスタンスは、終了するまでボリューム料金 (および起動中はインスタンス料金) が発生します。

🌏 利用可能リージョン

すべての AWS リージョンで利用可能です (AWS GovCloud (US) を含む)。

ただし、実行ロール作成用のロールテンプレートは AWS GovCloud (US) リージョンと中国リージョンでは利用できないため、これらのリージョンでは実行ロールのポリシーを手動で作成する必要があります。

🔗 関連サービス・機能

📈 Amazon EC2 Auto Scaling

ビルドプールとなるインスタンス群を管理し、デタッチ後の自動補充を担う。起動テンプレートでビルドインスタンスの設定を制御する。

🛠️ AWS Systems Manager

Image Builder はビルドコンポーネントを Systems Manager 経由で実行するため、ASG のインスタンスで SSM Agent がオンラインである必要がある。

🔐 AWS IAM

実行ロールに ASG 操作権限が必要。EC2ImageBuilderParentInstanceASGRoleTemplate ロールテンプレートで必要な権限を持つロールを作成できる。

🎯 まとめ

EC2 Image Builder が ASG の稼働中インスタンスを利用したビルドに対応し、インスタンス起動とブートストラップの待ち時間を排除してイメージビルドを高速化できるようになりました。完全オプトインで既存パイプラインに影響しないため、イメージビルドの頻度が高い環境ではまず 1 つのパイプラインで効果を検証することを推奨します。

導入時は ASG の起動テンプレートへのインスタンスプロファイル設定と、実行ロールへの ASG 操作権限の付与を忘れずに行ってください。
