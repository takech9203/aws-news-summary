🧪 サーバーレスモデルカスタマイズ向け
Training Session API

📅 リリース日: 2026 年 10 月 22 日 | GPU インフラ管理なしでポストトレーニングアルゴリズムを完全制御

📝 概要

SageMaker AI のサーバーレスモデルカスタマイズで Training Session API が GA になりました。 forward_backward()、optim_step()、sample() といったトレーニング操作を、 ステートフルなライブセッションへの API 呼び出しとして実行でき、GPU インフラのプロビジョニングや管理なしに、 カスタム損失関数、新しい RL 報酬シグナル、データカリキュラムなど任意のトレーニング手順を Python コードで実装できます。

sample()
🎲 ロールアウト生成 (オンポリシーサンプリング)
forward_backward()
🔁 順伝播と勾配計算 (損失関数を指定可能)
optim_step()
⚙️ オプティマイザによる重み更新

🎯 対象ユーザー: 新しいトレーニング手法を実験する ML 研究者、本番 RL システムを運用する高度な ML チーム、GRPO、DRO、DAPO などのカスタム損失関数を構築するチーム。 すぐに実行できる SFT / RL レシピ集 SageMaker training sessions cookbook も公開されています。

😣 Before: アップデート前の課題

❌高レベル API ではトレーニングループが SFT などの事前定義ワークフローに制約され、カスタム損失関数や最先端 RL を実行できない
❌カスタムアルゴリズムには GPU クラスターのプロビジョニング、分散実行、障害復旧、チェックポイント管理を自前で構築する必要があった
❌API が決めたインフラ構成に縛られ、反復実験やリージョンをまたぐ RL のスケールにはコードの書き換えが必要だった

😊 After: アップデート後の改善

✅トレーニング操作を API 呼び出しとして実行し、SFT、PPO、GRPO、マルチターン RL、独自手法を Python で自由に構成
✅GPU 割り当て、モデルと LoRA のロード、分散実行、障害復旧、チェックポイント、セキュリティは SageMaker が管理
✅ステートフルセッションでモデルが GPU 上に維持され、ロールアウト生成とポリシー更新の間のコールドスタートが解消
✅課金は処理トークン単位。報酬スコアリングなどのローカル計算は GPU 時間として課金されない

🏗️ アーキテクチャ: カスタムトレーニングループの流れ

開発者は自身の Python コードから Training Session API を呼び出し、ステートフルなサーバーレス GPU セッション上でカスタムトレーニングループを直接オーケストレーションします。

sequenceDiagram
    participant Dev as 👤 開発者の Python コード
    participant API as 🔌 Training Session API
    participant GPU as ⚡ サーバーレス GPU セッション

    Dev->>API: create_lora_training_client
    API->>GPU: ベースモデルと LoRA をロード
    Note over GPU: モデルは GPU 上に<br/>ロードされたまま維持
    loop 学習ステップ
        Dev->>API: sample
        API->>GPU: ロールアウト生成
        GPU-->>Dev: 生成トークンを返却
        Note over Dev: 報酬スコアリングはローカルで実行<br/>GPU 時間として課金されない
        Dev->>API: forward_backward
        API->>GPU: 順伝播と勾配計算
        Dev->>API: optim_step
        API->>GPU: 重みを更新
    end
    Dev->>API: stop
    API->>GPU: チェックポイント保存とセッション解放

💡 主要機能

1️⃣ 操作レベルの API によるトレーニング制御
  • forward_backward() (順伝播と勾配計算)、optim_step() (重み更新)、sample() (ロールアウト生成) を個別の API 呼び出しとして実行
  • モノリシックなスクリプト提出ではなく、操作を自由に組み合わせて任意のトレーニング手順を構成
  • 損失の発散や報酬ハッキングをステップ単位でデバッグ可能
2️⃣ ステートフルなサーバーレスセッション
  • モデルは API 呼び出しをまたいで GPU 上に維持され、コールドスタートが発生しない
  • インスタンス選択、クラスター管理、キャパシティプランニング不要。GPU はサービス側が自動プロビジョニング
  • 分散実行、勾配同期、テナント分離はサービスが処理
3️⃣ 手法に依存しない柔軟性
  • SFT、PPO、GRPO、マルチターン RL、独自のカスタム手法などアルゴリズム選択に制限なし
  • 複数の手順を 1 つのセッション内で連結するマルチステージパイプラインに対応
  • チェックポイントと再開機能を標準で提供
4️⃣ SageMaker training sessions cookbook の公開
  • すぐに実行できる SFT および RL のレシピを GitHub で公開
  • 独自のトレーニング手法を構築するためのブループリントとして活用可能

💻 コード例: カスタム強化学習ループ

Python オンポリシーサンプリングを用いたカスタム RL ループ 
from sagemaker.train.training_session import ServiceClient, AdamParams

svc = ServiceClient(region="us-west-2", role_arn="arn:aws:iam::111122223333:role/MyRole")
tc = svc.create_lora_training_client(base_model="openai/gpt-oss-20b", rank=32, alpha=64)

# オンポリシーサンプリングを用いたカスタム強化学習ループ
sc = tc.create_sampling_client()
for step in range(num_steps):
    ops = [sc.sample(p, num_samples=4, sampling_params=params) for p in prompts]
    rollouts = [op.result() for op in ops]
    tc.forward_backward(build_batch(rollouts), loss_fn="ppo").result()
    tc.optim_step(AdamParams(learning_rate=5e-5)).result()
    sc = tc.save_weights_and_get_sampling_client()

tc.stop()

🛠️ 設定方法

✅ 前提条件

✓AWS アカウントと、SageMaker AI Training Session API に必要な権限を持つ IAM ロール
✓SageMaker Python SDK のインストール (または SageMaker Studio ノートブック環境)
✓利用可能リージョン (us-east-1、us-west-2、ap-south-1) でのサービス利用
1
SageMaker Python SDK のインストールと cookbook の取得
Bash
pip install sagemaker
git clone https://github.com/aws/sagemaker-training-sessions-cookbook.git

SDK をインストールし、SFT および RL のレシピを収録した cookbook をクローンします。SageMaker Studio ノートブックを起動してコーディングエージェントを接続する方法も利用できます。

2
トレーニングクライアントの作成
Python
from sagemaker.train.training_session import ServiceClient

svc = ServiceClient(region="us-west-2", role_arn="arn:aws:iam::111122223333:role/MyRole")
tc = svc.create_lora_training_client(base_model="openai/gpt-oss-20b", rank=32, alpha=64)

ベースモデルと LoRA パラメータ (rank、alpha) を指定してトレーニングクライアントを作成します。この時点で SageMaker が GPU を割り当て、モデルと LoRA をロードします。

3
トレーニングループの実装とセッションの終了
Python
tc.forward_backward(batch, loss_fn="ppo").result()
tc.optim_step(AdamParams(learning_rate=5e-5)).result()
tc.stop()

forward_backward() と optim_step() を組み合わせて独自のトレーニングループを実装し、完了後は stop() で終了します。チェックポイントの保存と再開は組み込みで提供されます。

🤔 考慮すべき点

⚠トレーニングループを駆動する Python コードの記述が必要。プログラミング不要のワークフローにはサーバーレスモデルカスタマイズの既存機能が適している
⚠完結したトレーニングスクリプトをジョブとして投入したい場合は、従来の SageMaker AI Training Jobs が引き続き選択肢となる
⚠課金は Prefill、Sample、Train の 3 ディメンションで発生するため、トレーニングループの設計 (サンプリング数やステップ数) がコストに直結する

🚀 ユースケース

1. カスタム報酬シグナルを用いた強化学習

シナリオ: 独自のビジネス指標に基づく報酬関数で LLM をアラインメントしたいが、既存のマネージド RL 手法では報酬計算をカスタマイズできない。

Python
sc = tc.create_sampling_client()
for step in range(num_steps):
    rollouts = [sc.sample(p, num_samples=4, sampling_params=params).result() for p in prompts]
    # 報酬計算はローカルで実行 (GPU 課金なし)
    rewards = [custom_reward_fn(r) for r in rollouts]
    tc.forward_backward(build_batch(rollouts, rewards), loss_fn="ppo").result()
    tc.optim_step(AdamParams(learning_rate=5e-5)).result()

効果: GPU インフラを管理せずに独自の報酬ロジックを組み込んだオンポリシー RL を実行。報酬スコアリングはローカル計算のため GPU 時間として課金されない。

2. 最新研究アルゴリズムの迅速な検証

シナリオ: GRPO や DAPO など、論文で発表された新しいポストトレーニング手法を自社モデルで検証したいが、分散トレーニング環境の構築に時間がかかる。

Python
# cookbook のレシピをベースに損失関数と更新手順をカスタマイズ
tc.forward_backward(batch, loss_fn="custom_grpo").result()
tc.optim_step(AdamParams(learning_rate=1e-5)).result()

効果: 分散実行や勾配同期はサービスが処理するため、アルゴリズムのロジックのみに集中して数日ではなく数時間で検証を開始できる。

3. マルチステージトレーニングパイプライン

シナリオ: SFT で基礎的な指示追従能力を獲得した後、同じセッション内で RL による選好最適化を続けて実行したい。

Python
# ステージ 1: SFT
for batch in sft_dataloader:
    tc.forward_backward(batch, loss_fn="sft").result()
    tc.optim_step(AdamParams(learning_rate=2e-5)).result()

# ステージ 2: 同一セッションで RL に移行 (モデルはロードされたまま)
sc = tc.save_weights_and_get_sampling_client()

効果: モデルが GPU 上にロードされたまま複数の手順を連結でき、ステージ間のモデル再ロードやコールドスタートが発生しない。

💰 料金

課金は処理トークン単位で行われます。報酬スコアリングなどのローカル計算は GPU 時間として課金されません。料金は以下の 3 つのディメンションに基づきます。

📥 Prefill
各トレーニングステップの開始時にモデルへ入力されるトークン (プロンプト、会話履歴、コンテキスト) の処理コスト
🎲 Sample
トレーニングロールアウト中にモデルが生成するトークンのコスト
🏋️ Train
報酬シグナルに基づいてモデルの重みを更新するバックワードパスのコスト

最新の料金詳細は SageMaker AI 料金ページ を参照してください。
