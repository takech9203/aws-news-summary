AWS Transfer Family

SFTP / AS2 コネクタと Web アプリの IPv6 サポート

デュアルスタック対応で IPv6 移行を円滑に実現
2026-04-07
AWS What's New

📋 概要

AWS Transfer Family の SFTP コネクタ、AS2 コネクタ、および Transfer Family Web アプリ が IPv6 をサポートしました。 IPv4 アドレスの枯渇が進む中、IPv6 に移行した取引先との接続障壁が解消され、デュアルスタックにより段階的な移行にも対応します。

🔄 Before / After

❌ アップデート前

  • コネクタは IPv4 のみサポート
  • IPv6 採用済みの取引先と接続不可
  • IPv6 ネイティブ環境から Web アプリにアクセス不可
  • IPv4 アドレス枯渇に伴うコスト増への選択肢が限定的
→

✅ アップデート後

  • SFTP / AS2 コネクタで IPv6 経由の接続が可能
  • Web アプリが IPv6 アクセスをサポート
  • デュアルスタックで IPv4/IPv6 両方に対応
  • IpAddressType でコネクタごとに柔軟に選択可能

🏗️ アーキテクチャ図

Transfer Family のコネクタと Web アプリがデュアルスタックに対応し、IPv4 と IPv6 の両方のネットワークからの接続を受け付けることで、取引先やエンドユーザーのネットワーク環境に依存しない柔軟な接続を実現します。

⚡ 主要機能

🔌 SFTP コネクタの IPv6 サポート

  • リモート SFTP サーバーに IPv6 経由で接続可能
  • IpAddressType で IPV4 または DUALSTACK を選択
  • デュアルスタック設定で両方のサーバーに接続

🔌 AS2 コネクタの IPv6 サポート

  • 取引先の AS2 エンドポイントに IPv6 経由で接続可能
  • B2B データ交換における IPv6 移行をサポート
  • 既存の AS2 設定 (暗号化、署名、MDN) はそのまま維持

🌐 Web アプリの IPv6 サポート

  • IPv6 ネットワークから Web アプリにアクセス可能
  • IPv6 ネイティブデバイスからのファイル操作をサポート
  • デュアルスタックで IPv4 ユーザーとの互換性も維持

🛠️ 設定方法

前提条件

✓AWS Transfer Family が利用可能なリージョンの AWS アカウント
✓既存の SFTP / AS2 コネクタ (既存コネクタを更新する場合)
✓IPv6 対応のリモートサーバーまたは取引先エンドポイント
✓AWS CLI v2 の最新バージョン

Step 1: デュアルスタック対応の SFTP コネクタを作成

Bash SFTP コネクタ作成 
aws transfer create-connector \
  --url "sftp://partner-sftp-server.example.com" \
  --access-role "arn:aws:iam::123456789012:role/TransferConnectorRole" \
  --sftp-config '{
    "UserSecretId": "arn:aws:secretsmanager:us-east-1:123456789012:secret:SFTPCredentials",
    "TrustedHostKeys": ["ssh-rsa AAAAB3..."]
  }' \
  --ip-address-type "DUALSTACK"

Step 2: 既存コネクタをデュアルスタックに更新

Bash 既存コネクタの更新 
aws transfer update-connector \
  --connector-id "c-1234567890abcdef0" \
  --ip-address-type "DUALSTACK"

Step 3: コネクタの設定を確認

Bash 設定確認 
aws transfer describe-connector \
  --connector-id "c-1234567890abcdef0"

IAM ポリシー例

JSON コネクタ操作に必要な IAM ポリシー 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "transfer:CreateConnector",
        "transfer:UpdateConnector",
        "transfer:DescribeConnector"
      ],
      "Resource": "arn:aws:transfer:*:*:connector/*"
    }
  ]
}

✅ メリット

💼 ビジネス面

✓取引先との接続障壁の解消: IPv6 に移行した取引先との通信が可能に
✓将来のネットワーク移行への対応: IPv4 枯渇に備え、段階的な IPv6 移行を実現
✓コスト最適化: IPv4 アドレスの取得・維持コストを削減する選択肢を提供

⚙️ 技術面

✓デュアルスタック対応: 既存システムとの互換性を維持しながら IPv6 を導入
✓既存設定との互換性: セキュリティ設定はそのまま、IP アドレスタイプのみ変更可能
✓柔軟な構成: コネクタごとに個別設定でき、段階的な移行が可能
✓Web アプリの IPv6 対応: ネットワーク環境に依存しないアクセスを実現

⚠️ 制限事項・考慮点

制限事項

✗IPv6 のみ (シングルスタック IPv6) のオプションは提供されていない (IPV4 または DUALSTACK の選択)
✗リモートサーバーが IPv6 非対応の場合、デュアルスタック設定の効果は限定的
✗Web アプリの IPv6 設定の詳細は公式ドキュメントの更新を確認する必要あり

考慮すべき点

⚠デュアルスタック変更前に、リモートサーバーや取引先の IPv6 対応状況を確認
⚠VPC 環境では、VPC とサブネットが IPv6 に対応していることを確認
⚠セキュリティグループやネットワーク ACL で IPv6 トラフィックを許可する設定が必要
⚠DNS の AAAA レコードが正しく設定されていることを確認

💡 ユースケース

🏦 UC1: IPv6 移行済み取引先との SFTP ファイル転送

金融機関が取引先との間で日次のデータファイルを SFTP で交換。取引先が IPv6 に移行し、IPv4 接続を廃止予定。デュアルスタック対応のコネクタを作成して対応。
→ 取引先の IPv6 移行後も SFTP ファイル転送が中断されず、ビジネスの継続性を維持

🌍 UC2: IPv6 ネイティブ環境からの Web アプリアクセス

グローバル企業の社内ネットワークが IPv6 ネイティブに移行。従業員が Transfer Family Web アプリでファイルをアップロード・ダウンロード。
→ 追加の NAT やプロキシなしで直接 Web アプリにアクセスでき、ネットワーク構成を簡素化

🚚 UC3: 段階的な IPv6 移行

物流企業が複数の取引先と AS2 でデータを交換。取引先ごとに IPv4/IPv6 の対応状況が異なる。コネクタごとに IP アドレスタイプを個別に設定。
→ 取引先ごとの対応状況に合わせて段階的な IPv6 移行を実現
