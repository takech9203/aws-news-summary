📌 概要

AWS は、OpenAI の GPT-5.4 および GPT-5.5 モデルを Amazon Bedrock の米国東部 (バージニア北部) リージョン (us-east-1) で利用できるようになったと発表しました。推論、コーディング、コンピューター操作、ドキュメントワークフロー、長時間実行されるエージェントタスクなど、幅広い生成 AI アプリケーションを構築できます。

両モデルとも 272K トークンのコンテキストウィンドウをサポートし、テキストと画像の入力に対応。Responses API を通じて、サーバーサイド/クライアントサイドのツール呼び出し、プロジェクト、レスポンスストリーミングを利用できます。

🔄 アップデート前後の変化

❌ Before
  • GPT-5.4 / GPT-5.5 は限られたリージョンのみで利用可能
  • us-east-1 中心のワークロードはクロスリージョンアクセスの検討が必要
  • 特定リージョン要件下での高度なエージェントワークフロー構築が困難
➜
✅ After
  • us-east-1 で In-Region 推論として利用可能に
  • 既存ワークロードから低レイテンシー・データレジデンシー要件を満たして呼び出し可能
  • 用途に応じて GPT-5.4 と GPT-5.5 を使い分けて構築できる

アプリケーションは Responses API を通じて bedrock-mantle エンドポイントにリクエストを送信し、GPT-5.4 または GPT-5.5 を呼び出します。モデルはツールや外部システムと連携してエージェントタスクを実行します。

エンドポイントとアクセスパス

両モデルとも bedrock-mantle エンドポイントの openai/v1/responses パスで利用します。これは他モデルが使用する v1/responses パスとは異なる点に注意が必要です。

項目詳細
エンドポイントbedrock-mantle
In-Region エンドポイント URLhttps://bedrock-mantle.{region}.api.aws/openai/v1
アクセスパスopenai/v1/responses
Geo 推論非対応
Global 推論非対応

⚠️ 今回のアップデートは既存モデルの提供リージョン拡大であり、新規 API メソッドの追加はありません。Responses API を通じてアクセスします。

⚙️ 設定方法

前提条件

✓AWS アカウントを保有していること
✓米国東部 (バージニア北部) で Amazon Bedrock のモデルアクセスが有効化されていること
✓Python がインストールされていること (SDK 経由で Responses API を利用する場合)

導入ステップ

1
Amazon Bedrock の API キーを生成

Amazon Bedrock コンソールの API キー作成画面から長期 API キーを発行します。

2
SDK のインストール
BashOpenAI Python SDK
pip install openai
3
環境変数の設定
Bash認証情報とベース URL
OPENAI_API_KEY="<Bedrock の API キーを指定>"
OPENAI_BASE_URL="https://bedrock-mantle.us-east-1.api.aws/openai/v1"
4
推論リクエストの実行
Pythonbedrock-first-request.py
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="openai.gpt-5.5",
    input="Can you explain the features of Amazon Bedrock?"
)
print(response)

model を openai.gpt-5.4 に変更すると GPT-5.4 を呼び出せます。

💡 メリット

📈 ビジネス面
  • 最新モデルへの即時アクセス: us-east-1 のアプリから最新フロンティアモデルをすぐ活用
  • 用途に応じたモデル選択: 最高性能は GPT-5.5、本番の信頼性は GPT-5.4
  • エージェント開発の加速: 少ないオーケストレーションで実装し、コスト削減
🔬 技術面
  • 長コンテキスト対応: 272K トークンで長文・大規模コードベースに対応
  • マルチモーダル入力: テキスト + 画像でドキュメント/視覚タスクに活用
  • 柔軟なツール呼び出し: ストリーミング対応で応答性の高いアプリを構築

⚠️ デメリット・制約事項

制限事項

✗In-Region 推論のみ対応。Geo / Global Cross-Region 推論は非対応
✗サービスティアは Standard のみ。Priority、Flex、Reserved は非対応
✗対応 API は Responses のみ。Converse / Chat Completions / Invoke API は非対応
✗出力モダリティはテキストのみ (画像・音声・動画の出力は非対応)

考慮すべき点

!openai/v1/responses パスを使用する点が他モデルの v1/responses と異なるため、実装時に正しく指定する必要がある
!GPT-5.4 と GPT-5.5 で利用可能リージョンが異なる (下記リージョン表を参照)
!料金はトークン量に応じた従量課金のため、長コンテキスト利用時のコストを事前見積もり

🎯 ユースケース

1. 長時間実行されるエージェントタスクの自動化

シナリオ: 複数システムを横断する業務プロセスを自動化。複数ステップにわたりツールや外部 API を呼び出して結果を検証。

Python
response = client.responses.create(
    model="openai.gpt-5.5",
    input="調達依頼を承認フローに沿って処理し、各ステップの結果を検証してください。"
)
✅ GPT-5.5 がオープンエンドな目標を理解し、少ないオーケストレーションで完了まで遂行。手順制御の実装負荷を軽減。
2. 大規模ドキュメントワークフロー

シナリオ: 数百ページの契約書や技術文書を読み込み、要約・分析・抽出を行う。

Python
response = client.responses.create(
    model="openai.gpt-5.4",
    input="添付の契約書群からリスク条項を抽出し、要約してください。"
)
✅ 272K トークンで長文をまとめて処理。画像入力対応で図表を含む文書も扱える。
3. コーディング支援とソフトウェア操作

シナリオ: 既存の大規模コードベースへの機能追加やリファクタリングを、ツール連携で自動化。

Python
response = client.responses.create(
    model="openai.gpt-5.5",
    input="このリポジトリに新しい認証機能を追加し、テストを実行して結果を確認してください。"
)
✅ 高度なコーディングとソフトウェア操作に対応する GPT-5.5 が、コード生成からテスト実行までを支援。

🌎 利用可能リージョン

GPT-5.5 と GPT-5.4 で利用可能リージョンが異なります。いずれも In-Region 推論のみに対応します。

リージョンGPT-5.4GPT-5.5
米国東部 (バージニア北部) us-east-1 ★ 今回追加対応対応
米国東部 (オハイオ) us-east-2対応対応
米国西部 (オレゴン) us-west-2対応非対応
AWS GovCloud (米国西部) us-gov-west-1対応非対応

🔗 関連サービス・機能

Amazon Bedrock

各種基盤モデルを単一の API で利用できるフルマネージドサービス。今回のモデルもこの基盤上で提供されます。

Amazon Bedrock サービスティア

Standard、Priority、Flex、Reserved の各ティアから要件に応じて選択 (本モデルは Standard のみ対応)。

Amazon Bedrock Agents

エージェントワークフローの構築・運用を支援。GPT-5.4 / GPT-5.5 の長時間エージェントタスク機能と組み合わせて活用できます。

📝 まとめ

今回のアップデートにより、OpenAI の GPT-5.4 / GPT-5.5 が Amazon Bedrock の米国東部 (バージニア北部) で利用可能になり、同リージョンのワークロードから最新フロンティアモデルを In-Region で活用できるようになりました。推論、コーディング、長時間エージェントタスクなど用途に応じて 2 つのモデルを使い分けられる点が魅力です。Responses API と bedrock-mantle エンドポイントの利用方法、モデルごとの利用可能リージョンの違いを確認したうえで、自社のユースケースに合わせた検証を進めることをおすすめします。
