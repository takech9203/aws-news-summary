📋 概要

Amazon Braket が、Braket を利用可能な AWS US リージョンにおいて FedRAMP Class C のスコープに含まれるようになりました。FedRAMP (Federal Risk and Authorization Management Program) は、クラウド製品・サービスのセキュリティ評価、認証、継続的モニタリングに対する標準的なアプローチを提供する米国政府全体のプログラムです。

Braket の AWS 運用コンポーネント (API と SDK、ジョブオーケストレーションと管理、コンパイル、Amazon S3 への結果保存) は認定境界内に含まれます。量子ワークロード自体はサードパーティの量子ハードウェアプロバイダー (QHP) 上で実行されるため境界外ですが、QHP に送信されるデータには PII 除去・転送時/保存時の暗号化・AWS 標準のデータ保持ポリシーが適用されます。

💡 FedRAMP 用語の変更 (CR26)
FedRAMP の 2026 年統合ルール (CR26) により「FedRAMP Authorized」は「FedRAMP Certified」に名称変更。Class C は従来の Moderate ベースライン、Class D は従来の High ベースラインに相当します。AWS US East-West リージョンは Class C、AWS GovCloud (US) は Class D で認定されています。
❌ Before: アップデート前の課題
  • 政府機関や政府向け組織は、認定境界外の Braket を公式ワークロードで利用することが困難だった
  • 量子コンピューティングの検証時に、コンプライアンス要件との整合性を個別に評価する必要があった
  • 公的セクターでの量子ワークロード採用にコンプライアンス面のハードルが存在した
✅ After: アップデート後の改善
  • FedRAMP Class C 認定境界内で Braket の AWS 運用コンポーネントを利用可能に
  • API、SDK、オーケストレーション、コンパイル、S3 保存が境界内となり、コンプライアンス評価が容易に
  • QHP へのデータに PII 除去や暗号化などの AWS セキュリティ要件が適用されることが明確化され、リスク評価の透明性が向上

FedRAMP Class C 認定境界内に Braket の AWS 運用コンポーネント (API/SDK、ジョブオーケストレーション、コンパイル、S3 への結果保存) が含まれ、量子ワークロードの実行のみが境界外のサードパーティ QHP で行われます。QHP へのデータ送信時には PII 除去と暗号化が適用されます。

🔧 主要機能

1️⃣ FedRAMP Class C 認定境界内での Braket 運用コンポーネントの提供
  • Braket API および SDK が認定境界内に含まれる
  • 量子タスク/ジョブのオーケストレーションと管理が境界内で実行される
  • 量子回路のコンパイル処理が境界内で実行される
  • 実行結果の Amazon S3 への保存が境界内で行われる
2️⃣ サードパーティ QHP に対するセキュリティ要件の適用
  • 量子ワークロード自体は境界外の QHP ハードウェアで実行される
  • QHP に送信されるデータは PII を除去 (匿名化)。回路の処理に必要なコンテンツのみ送信され、AWS アカウント情報は非送信
  • データは転送時および保存時に暗号化され、処理時のみ復号
  • QHP は回路処理以外の目的でコンテンツを保存・使用することが不可
  • AWS 標準のデータ保持・削除ポリシーに準拠
3️⃣ FedRAMP 用語の変更 CR26 への対応
  • 2026 年統合ルール (CR26) により「FedRAMP Authorized」は「FedRAMP Certified」に名称変更
  • Class C = 従来の Moderate ベースライン、Class D = 従来の High ベースライン
  • AWS US East-West リージョンは Class C、AWS GovCloud (US) は Class D で認定

⚠️ デメリット・制約事項

🚧 制限事項

✗量子ワークロードの実行自体はサードパーティ QHP 上で行われ、FedRAMP 認定境界外である
✗対象は Braket が利用可能な AWS US リージョン (バージニア北部、北カリフォルニア、オレゴン) に限られる
✗Class C は従来の Moderate ベースライン相当であり、High ベースライン (Class D) 相当の要件を持つワークロードには適用できない

🤔 考慮すべき点

→境界外の QHP で処理されるデータの取り扱いについて、組織のセキュリティポリシーとの整合性を確認する必要がある
→Braket は 90 日後に量子タスク ID とメタデータを自動削除するため、長期間の参照が必要な場合はタスク ID などの記録を別途保存しておく必要がある
→機密情報をタグや名前などの自由入力フィールドに入力しないという AWS の一般的なデータ保護推奨事項に従う必要がある

🏛️ ユースケース 1: 政府機関による量子アルゴリズム研究

シナリオ: 米国連邦機関の研究部門が、最適化問題に対する量子アルゴリズムの有効性を FedRAMP 準拠環境で検証したい。

Python Braket SDK による量子回路の実行 
from braket.aws import AwsDevice
from braket.circuits import Circuit

# FedRAMP Class C スコープのリージョンでデバイスを指定
device = AwsDevice("arn:aws:braket:::device/quantum-simulator/amazon/sv1")

# 量子回路を作成して実行
circuit = Circuit().h(0).cnot(0, 1)
task = device.run(circuit, shots=1000)
print(task.result().measurement_counts)

効果: 認定境界内の API、オーケストレーション、S3 保存を通じて、コンプライアンス要件を満たしながら量子アルゴリズムの研究を実施できる。

🔬 ユースケース 3: 規制産業における量子古典ハイブリッドワークロードの検証

シナリオ: 政府要件に準拠する必要がある組織が、Braket Hybrid Jobs を用いて量子古典ハイブリッドアルゴリズムを検証する。

Python Braket Hybrid Jobs の実行 
from braket.aws import AwsQuantumJob

# ジョブオーケストレーション (認定境界内) を利用してハイブリッドジョブを実行
job = AwsQuantumJob.create(
    device="arn:aws:braket:::device/quantum-simulator/amazon/sv1",
    source_module="algorithm_script.py",

効果: ジョブオーケストレーションと管理が認定境界内で行われるため、ハイブリッドワークロードについても一貫したコンプライアンス評価が可能になる。

📝 まとめ

Amazon Braket が FedRAMP Class C (従来の Moderate ベースライン相当) のスコープに含まれたことで、米国政府機関およびその関連組織は、認定境界内で量子コンピューティングの検証・活用を開始できるようになりました。量子ワークロード自体は境界外のサードパーティ QHP で実行されますが、PII 除去や暗号化などの AWS セキュリティ要件が適用されます。

FedRAMP 準拠が求められる組織は、AWS Artifact や FedRAMP Marketplace で認定状況を確認した上で、量子コンピューティングの PoC 計画を検討することを推奨します。
