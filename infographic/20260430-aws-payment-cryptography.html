AWS PAYMENT CRYPTOGRAPHY

Physical Key Exchange

紙ベース暗号鍵交換 - PCI PIN / P2PE 準拠のマネージドキーセレモニー

2026-04-30

📋 概要

AWS Payment Cryptography が Physical Key Exchange をサポート。電子的な鍵交換に対応していないパートナーとの暗号鍵交換を、AWS のマネージドサービスとして実行可能に。PCI PIN および P2PE に準拠したセキュア施設で、訓練を受けた AWS の鍵管理者がキーセレモニーを実施する。

Before

  • 電子鍵交換非対応パートナーのために自社で HSM / KLD を維持
  • 年に数回の鍵交換のためにコストのかかるインフラを運用
  • PCI PIN / P2PE 準拠の物理セキュリティ環境を自社で管理

After

  • 自社で HSM や KLD を維持する必要がなくなった
  • AWS が運営するセキュア施設でキーセレモニーを実施
  • 紙ベース鍵交換が AWS マネージドサービスとして提供

⚡ 主要機能

📄 Physical Key Exchange

PCI PIN および P2PE 準拠の紙ベース暗号鍵交換機能。電子鍵交換に対応していないパートナーとの鍵交換を実現し、AWS が運営するセキュア施設での安全なキーセレモニーを実施。

🔑 リソースベースポリシー

AWS Payment Cryptography の鍵にリソースベースポリシーを設定可能。クロスアカウントでの鍵共有を実現。PutResourcePolicy / GetResourcePolicy / DeleteResourcePolicy API を追加。

👥 Multi-Party Approval チーム連携

ルート公開鍵のインポート操作を保護するための MPA チーム連携 API。AssociateMpaTeam / DisassociateMpaTeam / GetMpaTeamAssociation API を追加し、機密操作に対する承認ワークフローを実装。

Bash Step 1: AWS サポートケースの作成 
aws support create-case \
  --subject "Physical Key Exchange Request" \
  --communication-body "Physical Key Exchange を利用した紙ベース鍵交換のリクエスト" \
  --service-code "payment-cryptography" \
  --category-code "general-guidance"
Bash Step 2: リソースベースポリシーの設定 
aws payment-cryptography put-resource-policy \
  --resource-arn "arn:aws:payment-cryptography:us-east-1:123456789012:key/example-key-id" \
  --policy '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":"arn:aws:iam::987654321098:root"},"Action":["payment-cryptography:UseKey"],"Resource":"*"}]}'
Bash Step 3: MPA チームの関連付け 
aws payment-cryptography associate-mpa-team \
  --action "IMPORT_ROOT_PUBLIC_KEY_CERTIFICATE" \
  --mpa-team-arn "arn:aws:mpa:us-east-1:123456789012:team/example-team-id" \
  --requester-comment "Physical Key Exchange 用のルート公開鍵インポートに MPA を適用"

📊 メリット / デメリット

✅ ビジネス面のメリット

✓ インフラコスト削減: HSM / KLD の購入・維持コストが不要に
✓ 移行の加速: レガシーパートナーとの鍵交換もクラウドで実行可能
✓ コンプライアンス負担軽減: PCI PIN / P2PE 環境の管理を AWS に委任

✅ 技術面のメリット

✓ 運用簡素化: キーセレモニーを AWS 専門スタッフに委任
✓ セキュリティ強化: AWS のセキュア施設と訓練を受けた鍵管理者
✓ クロスアカウント共有: リソースベースポリシーによる柔軟な鍵共有

⚠️ 制限事項・考慮点

! 利用開始には AWS サポートケースの作成が必要 (セルフサービスではない)
! 紙の鍵コンポーネントの物理的な送付が必要なため、電子鍵交換と比較してリードタイムが長い
! 電子鍵交換が利用可能な場合はそちらが推奨される
! キーセレモニーのスケジュール調整が必要になる可能性がある

💡 ユースケース

🏦 レガシー決済ネットワークとの接続

大手銀行が AWS に決済システムを移行したいが、一部の決済ネットワークパートナーが電子鍵交換に対応しておらず、紙ベースでの鍵交換を要求しているケース。

→ 自社で HSM / KLD を維持することなく、レガシーパートナーとの鍵交換を完了しクラウド移行を実現

💳 カード発行会社の鍵管理統合

カード発行会社が複数のベンダーとの鍵交換を行っているが、一部のベンダーは紙ベースの鍵交換のみ対応しており、専用の HSM 設備を維持しているケース。電子鍵交換対応ベンダーは ImportKey API、紙ベースのみ対応ベンダーは Physical Key Exchange を利用。

→ すべてのベンダーとの鍵交換を AWS Payment Cryptography に統合し、自社の HSM 設備を廃止

🖥️ POS 端末管理会社のクラウド化

POS 端末管理会社が P2PE 準拠の鍵注入サービスを提供しており、一部の端末メーカーが紙ベースでの鍵コンポーネント交換を要求しているケース。ロードされた鍵から派生鍵を生成し、端末への鍵注入に使用。

→ P2PE 準拠環境の自社維持が不要になり、端末管理サービスのコスト構造を改善

🌐 利用可能リージョン / 関連サービス

AWS Payment Cryptography が利用可能なリージョンで Physical Key Exchange を利用可能。

関連サービス

AWS KMS

汎用的な暗号鍵管理サービス。Payment Cryptography は決済業界特化の鍵管理を提供。

AWS CloudHSM

専用 HSM クラスター。Physical Key Exchange は HSM の自社管理を不要にする代替手段。

AWS Multi-Party Approval

機密操作に対する承認ワークフロー。Payment Cryptography のルート公開鍵インポートの保護に統合。
