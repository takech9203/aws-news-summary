Amazon RDS for SQL Server

🗄️ 最新の累積更新プログラム CU および GDR 更新のサポート

📅 リリース日: 2026 年 11 月 3 日 | Microsoft SQL Server の最新 Cumulative Update と General Distribution Release に対応

📋 概要

Amazon RDS for SQL Server が、Microsoft SQL Server の最新の 累積更新プログラム (CU) および GDR (General Distribution Release) 更新をサポートしました。SQL Server 2017 / 2019 / 2022 / 2025 の 4 つのメジャーバージョンに対応する新しい RDS エンジンバージョンが提供されます。

CU は機能修正やパフォーマンス改善を含む累積的な更新、GDR はセキュリティ修正を中心とした更新です。これらを適用することで、Microsoft が公開した最新のセキュリティ修正とバグ修正を RDS for SQL Server インスタンスに反映できます。

ステップ 1: 利用可能なアップグレードターゲットの確認

Bashアップグレード可能バージョンの一覧表示
aws rds describe-db-engine-versions \
    --engine sqlserver-se \
    --engine-version <現在のエンジンバージョン> \
    --query "DBEngineVersions[].ValidUpgradeTarget[].{EngineVersion:EngineVersion,Description:Description,AutoUpgrade:AutoUpgrade}" \
    --output table

エディションに応じて sqlserver-ee、sqlserver-se、sqlserver-ex、sqlserver-web を指定します。

ステップ 2: DB インスタンスのアップグレード

BashSQL Server 2022 CU27+GDR へのアップグレード
aws rds modify-db-instance \
    --db-instance-identifier my-sqlserver-instance \
    --engine-version 16.00.4305.5.v1 \
    --apply-immediately

--apply-immediately を指定すると即時適用、指定しない場合は次回のメンテナンスウィンドウで適用されます。

ステップ 3: 自動マイナーバージョンアップグレードの有効化 (任意)

Bash自動マイナーバージョンアップグレードの有効化
aws rds modify-db-instance \
    --db-instance-identifier my-sqlserver-instance \
    --auto-minor-version-upgrade \
    --apply-immediately

有効化すると、重要なセキュリティ更新を含む新しいマイナーバージョンが利用可能になった際に、メンテナンスウィンドウ中に自動的にアップグレードされます。

💡 メリット

💼 ビジネス面
✓セキュリティコンプライアンスの維持: GDR の最新セキュリティ修正でパッチ適用要件に対応
✓運用リスクの低減: 修正済みの既知の不具合に起因する障害を未然に防止
✓運用負荷の軽減: 自動マイナーバージョンアップグレードでパッチ適用作業を省力化
⚙️ 技術面
✓後方互換性のある更新: 既存アプリケーションとの互換性を維持したまま適用可能
✓OS 更新の同時適用: エンジンアップグレード時に最新の OS 更新も自動適用
✓複数の適用手段: コンソールのほか CLI / SDK でアップグレード作業を自動化

⚠️ デメリット・制約事項

🚧 制限事項

✗アップグレード中は DB インスタンスの再起動が発生するため、短時間のダウンタイムが生じる
✗16.00.4120.1、15.00.4365.2、14.00.3465.1 以降では TLS 1.0 / TLS 1.1 / RC4 などの古いプロトコルがデフォルト無効となり、古いクライアントからの接続に影響する可能性がある
✗SQL Server 2016 以前の非推奨バージョンには今回の更新は提供されない

🤔 考慮すべき点

⚠️本番環境に適用する前に、検証環境で動作確認を行うことが推奨される
⚠️自動アップグレードの適用タイミングはメンテナンスウィンドウに依存するため、業務影響の少ない時間帯に設定しておく
⚠️Multi-AZ 構成ではフェイルオーバーを伴う場合があるため、アプリケーション側の再接続処理を確認しておく

🎯 ユースケース

1. セキュリティパッチの定期適用 🔒

金融系システムなど、セキュリティポリシーで最新パッチの適用が義務付けられている環境で、GDR 更新を速やかに適用。

Bash
aws rds modify-db-instance \
    --db-instance-identifier prod-sqlserver \
    --engine-version 16.00.4305.5.v1
✅ 効果: 次回のメンテナンスウィンドウで SQL Server 2022 CU27+GDR が適用され、最新のセキュリティ修正を反映した状態を維持できる
2. パッチ適用の自動化による運用省力化 🔄

多数の RDS for SQL Server インスタンスを運用しており、個別の手動アップグレード作業を削減したい場合。

Bash
aws rds modify-db-instance \
    --db-instance-identifier dev-sqlserver \
    --auto-minor-version-upgrade
✅ 効果: 重要なセキュリティ更新を含むマイナーバージョン提供時にメンテナンスウィンドウ中に自動適用され、手動運用の負荷を削減できる
3. SQL Server 2025 の最新 CU への追随 🚀

SQL Server 2025 を RDS で利用しており、CU10 に含まれる修正を適用して安定性を高めたい場合。

Bash
aws rds modify-db-instance \
    --db-instance-identifier sql2025-instance \
    --engine-version 17.00.5035.5.v1 \
    --apply-immediately
✅ 効果: SQL Server 2025 CU10 (KB5125471) の修正が即時適用され、既知の不具合による影響を回避できる

💰 料金

CU / GDR 更新の適用自体に 追加料金は発生しません。Amazon RDS for SQL Server の通常の料金 (インスタンス料金、ストレージ料金、ライセンス込みモデルの場合はライセンス料金) が引き続き適用されます。
