Amazon SageMaker

🤖 AI データ準備機能

高品質なトレーニング・評価データセットを AI で自動構築
📅 リリース日
2026 年 11 月 17 日

📌 概要

Amazon SageMaker が、モデル開発向けの高品質なデータセットを構築するための AI データ準備機能をサポートしました。 データサイエンティストや ML エンジニアは、テキストベースのモデルカスタマイズと従来型 ML の両方を対象に、 トレーニングデータセットおよび評価データセットを構築できます。

少数のサンプル、本番トレース、または Amazon S3 / Amazon Athena / AWS Glue Data Catalog 上の既存データから開始でき、 ソースデータ、生成されたデータセット、ラベルはすべてユーザー自身が管理する IAM ロールで制御された S3 バケット内に保持されます。

S3、Athena、Glue Data Catalog の既存データや少数のサンプルを入力として、合成データ生成・自動ラベリング・品質評価・データ変換を実行し、 低信頼度の行は人間のレビューを経て、最終的なデータセットがユーザー管理の S3 バケットに出力される流れを示しています。

⚡ 主要機能

✨ 合成データ生成

自社ドキュメントに基づく仕様からトレーニング・評価・テストデータを生成。少数のサンプル、本番トレース、既存データからの開始が可能。テキストベースのモデルカスタマイズと従来型 ML の両方に対応。

🏷️ 自動ラベリング

信頼度スコア付きで大規模にラベリング。組み込みタスクタイプは分類、固有表現認識 NER、抽出型質問応答、順序評価、要約の 5 種類。カスタムタスクにも対応。

👤 ヒューマンレビュー

信頼度がしきい値未満の行は、SageMaker AI Studio 内の Label Studio Community Edition のレビューキューに送信。専門家のフィードバックをデータセットに反映。

✅ データ品質評価

重複データの検出に加え、トーンの不一致や多様性不足などの問題を品質メトリクスとルールの両方で検出。

🔧 データ変換

選択したトレーニング手法や評価手法に合わせてデータをクリーニング・再構成。dedupe、filter、フォーマット変換などのオペレーターを提供。

🔐 アクセス方法とデータ管理

SageMaker Python SDK API から直接、または Agent Toolkit for AWS の AWS AI-ML スキルを通じて自然言語で利用可能。データはユーザー管理の S3 バケットに保持。

ステップ 1: データソースの準備

Bash サンプルデータを S3 にアップロード 
aws s3 cp ./seed-examples/ s3://my-bucket/seed-data/ --recursive

少数のサンプルや既存データを Amazon S3 にアップロードします。Amazon Athena や AWS Glue Data Catalog 上の既存データをそのまま使用することもできます。

ステップ 2: データ準備ジョブの作成

Python CreateJob API でジョブを作成 
import boto3

client = boto3.client("sagemaker")

response = client.create_job(
    JobName="my-synthetic-data-job",
    RoleArn="arn:aws:iam::123456789012:role/SageMakerDataPrepRole",
    JobCategory="SyntheticDataGeneration",
    JobConfigSchemaVersion="<schema-version>",
    JobConfigDocument="<job-config-json>",
)
print(response["JobArn"])

JobCategory に SyntheticDataGeneration、 DataQualityEvaluation、DataTransformation のいずれかを指定し、 ジョブの設定内容は JobConfigDocument で指定します。 具体的な設定スキーマは AI データ準備ドキュメントを参照してください。

ステップ 3: 自動ラベリングとヒューマンレビュー

自動ラベリングの実行後、信頼度スコアがしきい値未満の行は SageMaker AI Studio 内の Label Studio Community Edition のレビューキューに送られます。 専門家がレビューキューでラベルを確認・修正することで、フィードバックをデータセットに反映できます。

⚖️ メリットと制約事項

👍 ビジネス面のメリット

✓データ準備期間の短縮: 数週間かかっていた手動作業を自動化し、モデル開発の立ち上げを高速化
✓少ない初期データからの開始: 少数のサンプルや本番トレースから着手可能
✓データ主権の維持: ユーザー管理の S3 バケットに保持され、IAM ロールで制御

🔧 技術面のメリット

✓自社ドキュメントへのグラウンディング: ドメインに即したデータセットを構築可能
✓品質管理の仕組みを内蔵: 信頼度スコアによる振り分けと、メトリクス・ルールによる品質評価
✓複数のアクセス手段: Python SDK と自然言語 (AWS AI-ML スキル) を選択可能

⚠️ 制限事項

✗利用可能リージョンは米国東部 (バージニア北部) と米国西部 (オレゴン) の 2 リージョンのみ (東京リージョンは未対応)
✗組み込みタスクタイプはテキスト系の 5 種類が中心で、それ以外はカスタムタスクでの対応

💡 考慮すべき点

⚠合成データや自動ラベルの品質は、最終的に人間のレビューで担保する運用設計が重要
⚠Label Studio Community Edition は SageMaker AI Studio 内で動作するため、Studio 環境の整備が必要
⚠料金の詳細は公式発表に記載がないため、利用前に SageMaker の料金ページで確認が必要

🎯 ユースケース

1️⃣ 社内ドキュメントに基づくモデルカスタマイズ用データセットの構築

シナリオ: 社内ナレッジベースに特化したテキスト生成モデルをファインチューニングしたいが、トレーニングデータがほとんど存在しない。

  1. 社内ドキュメントと少数のサンプルを S3 にアップロード
  2. 合成データ生成ジョブ (JobCategory: SyntheticDataGeneration) でトレーニング・評価・テストデータを生成
  3. データ品質評価で重複や多様性不足を確認
  4. 生成されたデータセットでモデルカスタマイズを実行
💡 効果: 手作業でのデータ作成なしに、ドメインに即したトレーニングデータセットを短期間で構築できる。
2️⃣ 大量の未ラベルデータの自動ラベリング

シナリオ: カスタマーサポートの問い合わせログが大量にあり、分類モデルのトレーニングに使用したいが、ラベル付けの工数が確保できない。

  1. 問い合わせログを S3 または Athena 経由で入力として指定
  2. 組み込みの分類タスクタイプで自動ラベリングを実行
  3. 信頼度しきい値を設定し、低信頼度の行のみ Label Studio のレビューキューで専門家が確認
  4. 確定したラベル付きデータセットを S3 に出力
💡 効果: 全件の手動ラベリングが不要になり、専門家は低信頼度のデータのレビューに集中できる。
3️⃣ 本番トレースを活用した評価データセットの整備

シナリオ: 本番環境のトレースを評価データとして活用したいが、重複やフォーマットの不統一が多く、そのままでは評価に使用できない。

  1. 本番トレースを入力として指定
  2. データ品質評価ジョブで重複やトーンなどの問題を検出
  3. データ変換ジョブで dedupe、filter、フォーマット変換を適用し、評価手法に合わせた形式に整形
  4. 整形済み評価データセットを S3 に出力
💡 効果: 実トラフィックに基づく高品質な評価データセットを、手作業のクリーニングなしで整備できる。

📝 まとめ

Amazon SageMaker の AI データ準備機能により、従来数週間を要していたトレーニングデータセットの構築を、 合成データ生成・自動ラベリング・品質評価・データ変換の組み合わせで大幅に効率化できます。

モデルカスタマイズや ML プロジェクトでデータ不足やラベリング工数が課題となっているチームは、 us-east-1 または us-west-2 リージョンで SageMaker Python SDK から試用を開始することを推奨します。
