マネージドルールで API / MCP 脅威を検出

AWS WAF AWS Marketplace AI Agent & API Security MCP 保護

📌 概要

AWS WAF が Salt Security のマネージドルールグループ「Salt Managed Rules for AWS WAF - AI Agent & API Security」を AWS Marketplace 経由でサポート。 API を標的とした攻撃と、AI エージェントや MCP (Model Context Protocol) エンドポイント由来のトラフィックに対する保護を、カスタムルールの構築・維持なしで Web ACL に追加できます。

検出対象はクレデンシャルブルートフォース、過剰な GraphQL クエリ、SSRF、プロトタイプ汚染、JWT 異常などの API 攻撃ベクトル。さらに MCP トラフィックの識別・ラベル付けと未認証 MCP アクセスのブロックにより、WAF 上で MCP 通信の可観測性を高めます。

😰 Before: アップデート前の課題

✗API 列挙攻撃・GraphQL 過剰クエリ・JWT 異常への対策はカスタムルールを独自に作成・維持する必要があった
✗MCP トラフィックを WAF レイヤーで識別・制御する標準的な手段がなく、未認証 MCP アクセスの検出が困難
✗ユーザー識別子やメールアドレスなど機密パラメータ単位のレート制限には高度なルール設計が必要

🎉 After: アップデート後の改善

✓Marketplace でサブスクライブするだけで Salt Security の API 攻撃検出ルールを Web ACL に追加可能
✓MCP トラフィックの識別・ラベル付け、未認証 MCP アクセスのブロック、可観測性向上を WAF 上で実現
✓機密パラメータに対するレート制限で列挙攻撃・不正利用を緩和
✓認可ヘッダー・ユーザー識別子・GraphQL クエリなどのラベル付けで検出精度向上と下流分析に活用

Salt Security マネージドルールグループが Web ACL 内でリクエストを検査し、API 攻撃や未認証 MCP アクセスをブロックしつつ、正常なトラフィックにはラベルを付与してバックエンドへ転送する構成です。

⚡ 主要機能

🔍 API 攻撃ベクトルの検出
  • クレデンシャルブルートフォース攻撃
  • 過剰な GraphQL クエリ
  • SSRF (サーバーサイドリクエストフォージェリ)
  • プロトタイプ汚染 (Prototype Pollution)
  • JWT (JSON Web Token) の異常
🧩 MCP エンドポイント保護
  • MCP エンドポイントトラフィックを識別しラベル付け
  • 未認証の MCP アクセスをブロック
  • AWS WAF 上で MCP 通信の可観測性を追加
⏱️ 機密パラメータに対するレート制限
  • ユーザー識別子やメールアドレスなど機密性の高いリクエストパラメータ単位で適用
  • 列挙攻撃 (Enumeration) や不正利用の緩和に有効
🏷️ リクエスト属性のラベル付け
  • 認可ヘッダー、ユーザー識別子、GraphQL クエリなどにラベルを付与
  • 検出精度の向上と後続ルール・分析基盤での活用が可能
🔄 バージョニングのサポート
  • マネージドルールグループのバージョン指定が可能
  • Salt Security の専門家 (Salt Lab) が新たな脅威に応じてルールを継続的に更新

マネージドルールグループの特性

  • → ルールグループはセラー (Salt Security) が所有・管理し、知的財産保護のため個々のルールの詳細はすべては公開されない
  • → AWS WAF の基本料金に加えて、セラーが設定するサブスクリプション料金が発生する
  • → 多くのセラーは新しい脆弱性や脅威の出現に応じてルールグループを自動更新する

🛠️ 設定方法

前提条件

  • ✓ AWS アカウントと AWS WAF を利用可能な環境
  • ✓ 保護対象リソース (CloudFront、ALB、API Gateway、AWS AppSync など) に関連付ける Web ACL
  • ✓ AWS Marketplace でのサブスクリプション手続きを行う IAM 権限 (aws-marketplace 関連)

  1. AWS Marketplace でサブスクライブ: AWS WAF コンソールまたは Marketplace から製品ページにアクセスし、料金と利用条件を確認して契約
  2. Web ACL にルールグループを追加: [Rules] タブから [Add rules] > [Add managed rule groups] を選択し、AWS Marketplace セクションから Salt Security のルールグループを追加。追加設定は不要でそのまま利用開始可能
  3. バージョンとアクションの設定 (オプション): 必要に応じてバージョンを固定し、導入初期は Count モードで検証してからブロックを有効化
  4. ラベルとログの活用: 付与されるラベルを後続カスタムルールの条件に利用し、WAF ログを CloudWatch Logs や S3 に出力して分析

⚠️ デメリット・制約事項

制限事項

✗AWS WAF の基本料金に加えて Salt Security が設定するサブスクリプション料金が発生する
✗知的財産保護のため、ルールグループ内の個々のルールの詳細をすべて確認することはできない
✗サポートは AWS ではなく Salt Security が提供する

考慮すべき点

📝本番環境への適用前に Count モードで検証し、正常トラフィックの誤検出 (False Positive) がないか確認することが推奨される
📝ルールグループは Web ACL の WCU (Web ACL Capacity Unit) を消費するため、既存ルールとの合計容量に注意が必要
📝MCP や AI エージェント関連の脅威は進化が速いため、バージョン固定運用の場合は定期的なバージョン更新の検討が必要

🎯 ユースケース

1️⃣ 公開 API に対する列挙攻撃・ブルートフォース対策

シナリオ: ログイン API やユーザー情報 API を公開している SaaS 企業が、クレデンシャルブルートフォースやメールアドレス列挙攻撃への対策を強化したい。

  • → Salt Managed Rules をサブスクライブし、ログイン API を保護する Web ACL に追加
  • → ユーザー識別子・メールアドレスに対するレート制限で列挙攻撃を緩和
  • → WAF ログで検出状況をモニタリング
✅ 効果: カスタムルールの開発なしに、アカウントテイクオーバーにつながるブルートフォースや列挙攻撃を WAF レイヤーで緩和
2️⃣ MCP サーバーの保護と可観測性の確保

シナリオ: 社内外の AI エージェントと連携する MCP サーバーを ALB や API Gateway の背後で公開しており、未認証アクセスの遮断とトラフィックの可視化が必要。

  • → MCP サーバー前段の Web ACL に Salt Managed Rules を追加
  • → MCP トラフィックの識別・ラベル付けを有効化し、未認証の MCP アクセスをブロック
  • → ラベルを活用して MCP トラフィックの分析ダッシュボードを構築
✅ 効果: MCP という新しいプロトコルの通信を WAF で識別・制御でき、AI エージェント連携のセキュリティガバナンスを確立
3️⃣ GraphQL API の過剰クエリ・JWT 異常対策

シナリオ: GraphQL API を提供するモバイルアプリバックエンドで、コストの高いクエリの乱用や改ざんされた JWT によるアクセスを検出・遮断したい。

  • → AWS AppSync や API Gateway に関連付けた Web ACL にルールグループを追加
  • → 過剰な GraphQL クエリの検出ルールを Count モードで検証し、確認後にブロックモードへ切り替え
  • → GraphQL クエリや認可ヘッダーのラベルを後続ルールで活用
✅ 効果: GraphQL 特有のリソース枯渇攻撃や JWT の異常を検出し、API バックエンドの安定性とセキュリティを向上
