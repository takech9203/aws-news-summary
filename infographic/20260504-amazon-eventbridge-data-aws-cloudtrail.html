Amazon EventBridge

データプレーン API の AWS CloudTrail ロギングサポート

PutEvents API 呼び出しの完全な監査証跡を実現し、セキュリティ監査とオペレーショナルトラブルシューティングの可視性を大幅に向上

2026-05-04

📋 概要

Amazon EventBridge がデータプレーン API の AWS CloudTrail ロギングをサポートした。EventBridge のイベントバスに対する PutEvents API 呼び出しが CloudTrail に記録されるようになり、「誰が」「いつ」「どこから」イベントを送信したかを追跡可能になった。

従来はコントロールプレーン API のみが記録されていたが、今回のアップデートにより実際のイベント発行操作も監査できるようになった。

🔄 Before / After

❌ Before

  • PutEvents API 呼び出しが CloudTrail に記録されず追跡不可
  • 不正なイベント発行の検出が困難
  • 呼び出し元 IP アドレスや IAM アイデンティティの特定不可
  • SOC 2、PCI DSS 等のコンプライアンス要件を満たせない

✅ After

  • PutEvents が CloudTrail データイベントとして記録可能
  • 送信元 IP、IAM アイデンティティ、日時を特定可能
  • 高度なイベントセレクタで特定バスのみフィルタリング
  • セキュリティ監視・トラブルシューティング精度向上

⚡ 主要機能

📨 PutEvents API ロギング

イベントバスへの PutEvents 呼び出しをデータイベントとして記録。IP アドレス、IAM アイデンティティ、日時を記録。detail フィールドはリダクション処理。

🔌 PutPartnerEvents 対応

パートナーイベントソースからの PutPartnerEvents API 呼び出しもデータイベントとして記録可能。SaaS 連携のイベント発行を追跡。

🌐 グローバルエンドポイント対応

EventBridge グローバルエンドポイント経由の PutEvents も記録可能。成功した呼び出しのみ記録される。

🎯 高度なイベントセレクタ

resources.type、eventName、readOnly、resources.ARN でフィルタリング。特定のイベントバスのみを対象にしたロギング設定が可能。

🔧 技術仕様

サポートされるリソースタイプ

リソースタイプ resources.type 値 記録される API
EventBridge event bus AWS::Events::EventBus PutEvents
EventBridge partner event source AWS::Events::EventSource PutPartnerEvents
EventBridge endpoint AWS::Events::Endpoint PutEvents (成功時のみ)

CloudTrail データイベントの仕様

項目 詳細
eventSource events.amazonaws.com
eventName PutEvents / PutPartnerEvents
readOnly false (書き込み操作)
データ保護 detail フィールドはリダクションされる
クロスアカウント API 呼び出し元アカウントにのみ配信

⚙️ 設定方法

前提条件

  • 既存の CloudTrail トレイルまたは CloudTrail Lake イベントデータストアが作成済み
  • CloudTrail トレイルのログ配信先 S3 バケットが設定済み
  • IAM ユーザーまたはロールに CloudTrail の設定変更権限あり

Step 1: データイベントロギングを有効化

Bash 全イベントバスのデータイベントを記録 
aws cloudtrail put-event-selectors \
  --trail-name my-trail \
  --advanced-event-selectors '[
    {
      "Name": "EventBridge PutEvents logging",
      "FieldSelectors": [
        {
          "Field": "eventCategory",
          "Equals": ["Data"]
        },
        {
          "Field": "resources.type",
          "Equals": ["AWS::Events::EventBus"]
        }
      ]
    }
  ]'

Step 2: 特定のイベントバスのみ対象にする場合

Bash 特定バスに絞ったロギング (コスト最適化) 
aws cloudtrail put-event-selectors \
  --trail-name my-trail \
  --advanced-event-selectors '[
    {
      "Name": "Specific EventBus logging",
      "FieldSelectors": [
        {
          "Field": "eventCategory",
          "Equals": ["Data"]
        },
        {
          "Field": "resources.type",
          "Equals": ["AWS::Events::EventBus"]
        },
        {
          "Field": "resources.ARN",
          "Equals": ["arn:aws:events:ap-northeast-1:123456789012:event-bus/my-event-bus"]
        }
      ]
    }
  ]'

Step 3: ロギングの確認

Bash 設定確認 
aws cloudtrail get-event-selectors --trail-name my-trail

IAM ポリシー設定

JSON 必要な IAM 権限 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "cloudtrail:PutEventSelectors",
        "cloudtrail:GetEventSelectors",
        "cloudtrail:DescribeTrails"
      ],
      "Resource": "arn:aws:cloudtrail:*:*:trail/*"
    }
  ]
}

💡 メリット

ビジネス面

  • コンプライアンス要件の充足: SOC 2、PCI DSS、HIPAA などの規制要件で求められるデータプレーンレベルの監査証跡を実現
  • セキュリティインシデント対応の迅速化: 不正なイベント発行の検出と発信元の特定が可能になり、対応時間を短縮
  • ガバナンスの強化: イベント駆動アーキテクチャにおける全アクティビティの可視化により、組織全体のガバナンス体制を強化

技術面

  • デバッグ効率の向上: PutEvents の呼び出し履歴を CloudTrail で確認でき、トラブルシューティングが容易
  • 細粒度のフィルタリング: 高度なイベントセレクタにより、ログ量とコストを最適化
  • 既存ツールとの統合: CloudTrail Lake、Athena、CloudWatch Logs など既存の分析基盤をそのまま活用可能
  • クロスリージョン対応: マルチリージョントレイルで全リージョンのデータイベントを一元管理

⚠️ 制約事項・注意点

  • データイベントのロギングはオプトイン方式。デフォルトでは無効で明示的な設定が必要
  • イベントの detail フィールドはリダクションされ、ペイロード内容は CloudTrail から確認不可
  • クロスアカウント送信時、データイベントは API 呼び出し元アカウントにのみ配信 (リソースオーナーには配信されない)
  • グローバルエンドポイント経由の PutEvents は成功した呼び出しのみ記録 (AccessDenied は記録されない)
  • CloudTrail Event history にはデータイベントは表示されない (トレイルまたは Lake の設定が必要)
  • 高ボリューム環境では追加の CloudTrail 料金が発生。特定バスへのフィルタリングを推奨
  • CloudTrail データイベントの配信には若干の遅延があり、リアルタイム監視には CloudWatch アラームとの組み合わせが必要

🎯 ユースケース

1. セキュリティ監査とコンプライアンス

金融機関が PCI DSS コンプライアンスのために、EventBridge を経由するすべての決済関連イベントの発行元を追跡する必要があるシナリオ。

Bash 決済用イベントバスの監査ログ設定 
aws cloudtrail put-event-selectors \
  --trail-name compliance-trail \
  --advanced-event-selectors '[
    {
      "Name": "Payment EventBus audit",
      "FieldSelectors": [
        {"Field": "eventCategory", "Equals": ["Data"]},
        {"Field": "resources.type", "Equals": ["AWS::Events::EventBus"]},
        {"Field": "resources.ARN", "Equals": ["arn:aws:events:ap-northeast-1:123456789012:event-bus/payment-events"]}
      ]
    }
  ]'

-> 決済イベントの発行元を完全に追跡可能。監査レポートの自動生成と不正アクセスの早期検知が実現。

2. イベント駆動アーキテクチャのデバッグ

マイクロサービスアーキテクチャで、特定のイベントが期待通りにイベントバスに到達しているか確認し、イベント消失の原因を特定するシナリオ。

Bash CloudTrail Lake でイベント発行状況を調査 
aws cloudtrail-data start-query \
  --query-statement "SELECT eventTime, userIdentity.arn, requestParameters \
    FROM event_data_store_id \
    WHERE eventName = 'PutEvents' \
    AND eventTime > '2026-05-04T10:00:00Z' \
    AND eventTime < '2026-05-04T11:00:00Z'"

-> イベントの発行タイミングと発行元を正確に把握。イベント消失やタイミング問題の原因特定時間を大幅に短縮。

3. 異常検知とアラート

通常のイベント発行パターンから逸脱したアクティビティ (深夜の大量イベント発行や未知の IP からのアクセス) を検知してアラートを発報するシナリオ。

Bash 異常な PutEvents 呼び出しの検知 
aws logs put-metric-filter \
  --log-group-name "CloudTrail/EventBridgeDataEvents" \
  --filter-name "UnusualPutEvents" \
  --filter-pattern '{ ($.eventName = "PutEvents") && ($.sourceIPAddress != "10.0.*") }' \
  --metric-transformations \
    metricName=UnusualPutEventsCount,metricNamespace=Security,metricValue=1

-> 異常なイベント発行パターンをリアルタイムで検知。セキュリティチームに即座にアラートを送信し、潜在的な脅威への対応時間を短縮。

💰 料金情報

CloudTrail データイベントのロギングには追加料金が発生する。EventBridge 自体の料金に変更はない。

料金体系

項目 料金
データイベント (S3 配信) $0.10 / 100,000 イベント
データイベント集約 (S3 配信) $0.03 / 100,000 イベント
CloudWatch Logs 配信 $0.25/GB
CloudTrail Insights $0.03 / 100,000 イベント

コスト試算例

~$1 小規模 (月 100 万回)
~$10 中規模 (月 1,000 万回)
~$100 大規模 (月 1 億回)

高ボリューム環境では、高度なイベントセレクタで特定のイベントバスのみにフィルタリングを適用し、コストを最適化することを推奨。
