🤖 Reflection 社の Beam モデルが SageMaker JumpStart で利用可能に

📅 リリース日: 2026 年 10 月 16 日 | フロンティア水準のオープンウェイトモデルを自社 AWS アカウント内で実行

📝 概要

米国の AI 企業 Reflection が提供する初のオープンウェイトモデル Beam が、Amazon SageMaker JumpStart で利用可能になりました。Reflection によると、Beam は同クラスのオープンウェイトモデルの中でフロンティア水準の性能を持ち、推論、コーディング、エージェント系ベンチマークで高い性能を発揮します。

Apache 2.0 ライセンスで公開されており、モデルの中身を検査・カスタマイズした上で自社の AWS アカウント内で実行できます。さらに AWS Trainium3 向けに移植・最適化されており、初日から高性能かつコスト効率の高いデプロイ・スケーリングの選択肢が提供されます。

⚡ 主要機能

🏆 1. フロンティア水準のオープンウェイトモデル

  • Reflection 初のオープンウェイトモデルで、推論、コーディング、エージェント系ベンチマークで高い性能を発揮 (Reflection 発表による)
  • 総パラメータ数 5,010 億、アクティブパラメータ数 230 億のスパース MoE アーキテクチャ
  • 実効コンテキスト長は 100 万トークン (Reflection 発表による)
  • BF16、FP8、NVFP4 の 3 種類のチェックポイントバリアントを提供

🧩 2. SageMaker JumpStart からの簡単なデプロイ

  • Amazon SageMaker Studio 内の JumpStart で「Beam」を検索してデプロイ可能
  • 既存の SageMaker AI 上の他モデルと並行して運用でき、本番需要に合わせてスケール
  • SageMaker AI の統制、監査証跡、モニタリングがすべてのデプロイに組み込み済み
  • SageMaker HyperPod Inference 上でのホスティング (AWS 管理コンテナ、または SGLang / vLLM による自己管理サービング) にも対応

🚀 3. AWS Trainium3 への移植・最適化

  • Beam は AWS Trainium3 向けに移植・最適化済み
  • 高性能かつコスト効率の高いデプロイ・スケーリングの選択肢を初日から提供

🔓 4. Apache 2.0 ライセンスによるオープン性

  • モデルの重みは Hugging Face 上で Apache 2.0 ライセンスで公開
  • モデルの検査・カスタマイズが可能で、自社ビジネスへの適応ができる
  • 自社 AWS アカウント内での実行によりデータのプライバシーと管理権を確保

🛠️ 設定方法

✅ 前提条件

✓AWS アカウントと、IAM、ネットワーク、ストレージに関する適切な権限
✓モデル利用条件への同意
✓対象インスタンスタイプのサービスクォータと容量の確保
✓(CLI/SDK でのデプロイの場合) AWS CLI と Python 3.11 以上

ステップ 1: SageMaker Studio で Beam を検索

Amazon SageMaker Studio を開き、SageMaker JumpStart で「Beam」を検索します。モデルカードから数クリックでエンドポイントをデプロイできます。

ステップ 2: サンプルコードでデプロイ (CLI の場合)

Bash JumpStart リアルタイムエンドポイントのデプロイ 
git clone https://github.com/aws-samples/sagemaker-genai-hosting-examples.git
cd sagemaker-genai-hosting-examples/01-models/ReflectionAI/Beam-1.0-501B-A23B-NVFP4/
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -r requirements.txt
python jumpstart_real_time.py --variant fp8 --endpoint-name reflection-beam-fp8-smoke

スクリプトはテストリクエストを送信して応答を表示し、リソースをクリーンアップします。バリアントは bf16、fp8、nvfp4 (デフォルト) から選択できます。

ステップ 3: SageMaker HyperPod Inference でのデプロイ (オプション)

Bash HyperPod クラスター上に SGLang サービングでデプロイ 
cd sagemaker-genai-hosting-examples/SageMakerHyperpod/reflection-beam/
cp config/deployment.env.example config/deployment.env
cp config/release.env.example config/release.env
python hyperpod_tool.py --config config/deployment.env --config config/release.env validate sglang
python hyperpod_tool.py --config config/deployment.env --config config/release.env deploy sglang --timeout-seconds 1800

sglang の代わりに vllm や jumpstart を指定することもできます。smoke サブコマンドでヘルスチェックと短いテストリクエストを実行できます (推奨初期サンプリング設定: temperature 1.0、top-p 0.7)。

💡 メリット

💼 ビジネス面

✓データ主権の確保: 自社 AWS アカウント内で実行するため、データが外部に出ることなく、既存の AWS セキュリティ・コンプライアンス機能で保護される
✓ベンダーロックインの回避: API 経由の「借用」ではなく、Apache 2.0 ライセンスでモデル自体を管理・適応できる
✓ミッションクリティカルな用途への適用: 公共機関や規制業種でもクライアント固有のセキュリティと統制の下で高度な AI をデプロイ可能 (Accenture Federal Services のコメントによる)

⚙️ 技術面

✓運用の一貫性: SageMaker AI 上の他モデルと並行運用でき、同じ統制、監査証跡、モニタリングを利用できる
✓コスト効率の選択肢: AWS Trainium3 向け最適化により、GPU 以外の高性能・低コストな推論基盤を初日から選択できる
✓柔軟なサービング方式: JumpStart のマネージドエンドポイントから HyperPod 上の SGLang / vLLM による完全な自己管理サービングまで選択可能

⚠️ デメリット・制約事項

🚧 制限事項

✗初期提供リージョンは米国東部 (バージニア北部) と米国東部 (オハイオ) の 2 リージョンのみで、東京リージョンでは利用できない
✗5,010 億パラメータの大規模モデルであり、ml.p5 / ml.p6 系などの大型インスタンスが必要 (BF16 はマルチノード構成が必要)
✗大型 GPU インスタンスのサービスクォータと容量の確保が前提となる

🤔 考慮すべき点

⚠️大型インスタンスの常時稼働はコストが高額になるため、検証後は不要なエンドポイントを削除するなどコスト管理が重要
⚠️ベンチマーク性能に関する記述は Reflection 社の発表に基づくため、自社ユースケースでの評価の実施を推奨
⚠️チェックポイントバリアント (BF16 / FP8 / NVFP4) により必要なインスタンスタイプと精度特性が異なるため、要件に応じた選定が必要

📌 まとめ

フロンティア水準のオープンウェイトモデル Beam が SageMaker JumpStart で利用可能になり、データとインフラストラクチャを自社管理下に置いたままエージェント型コーディングや複雑なワークフロー自動化を実現できるようになりました。AWS Trainium3 への最適化によりコスト効率の高い選択肢も用意されています。

コーディングエージェントの内製化やセキュアな AI 活用を検討している場合は、まず us-east-1 / us-east-2 で JumpStart からデプロイし、自社ユースケースでの性能とコストを評価することを推奨します。
