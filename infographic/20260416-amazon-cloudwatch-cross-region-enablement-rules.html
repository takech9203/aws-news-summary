Auditing & Enablement Rules

複数リージョンのテレメトリ設定を単一リージョンから一元管理
📅 リリース日: 2026 年 4 月 16 日

📊 概要

Amazon CloudWatch に、複数の AWS リージョンにまたがるテレメトリ設定の監査と有効化を単一リージョンから一元管理できる機能が追加されました。EC2、VPC、CloudTrail などの AWS サービスからのテレメトリ (ログ、メトリクス、トレース) を、複数リージョンに対して一括で有効化・監査できます。

有効化ルールを作成することで、選択したリージョンまたはすべてのリージョンにテレメトリ設定を自動適用でき、新しいリージョンが追加された際にもルールが自動的に拡張されます。

⚠️ アップデート前

  • テレメトリ設定を各リージョンで個別に確認・有効化が必要
  • 新しいリージョン追加時にテレメトリ設定を手動で追加
  • 組織全体のテレメトリ一貫性の確保が困難
  • リージョンごとに監査状態を個別確認が必要

✨ アップデート後

  • 単一リージョンから複数リージョンを一元的に監査・有効化
  • 有効化ルールにより全リージョンに自動適用
  • 新リージョン追加時にルールが自動拡張
  • AWS Organizations で組織全体のポリシーを一括適用

🔧 主要機能

🔍 クロスリージョンテレメトリ監査

  • 単一のホームリージョンから全リージョンの設定状態を一元確認
  • アカウント単位または Organizations 全体での監査をサポート
  • 各リージョンの有効化状態、ルール適用状態、エラー情報をまとめて取得
  • GetTelemetryEvaluationStatus API で一括確認

📋 テレメトリ有効化ルール

  • リソースタイプ、テレメトリタイプ、対象リージョンを指定してルール作成
  • 選択リージョンまたは全リージョンに適用可能
  • AllRegions フラグで新リージョンに自動拡張
  • 送信先設定でログ保持期間やフォーマットをカスタマイズ

🏢 AWS Organizations 統合

  • 組織全体に対するテレメトリルールの一括作成・適用
  • CreateTelemetryRuleForOrganization API で組織レベル管理
  • 組織内の全アカウントにテレメトリポリシーを統一適用

🎯 幅広いリソースタイプ

  • EC2、VPC、Lambda、CloudTrail、EKS など 11 種類以上に対応
  • テレメトリタイプはログ、メトリクス、トレースの 3 種類
  • WAFv2、ELB、Route 53 Resolver、Bedrock AgentCore なども対応

💻 設定方法

テレメトリ監査の有効化から有効化ルールの作成まで、4 ステップで設定できます。

ステップ 1: テレメトリ監査の有効化

Bash アカウント単位でテレメトリ監査を開始 
# アカウント単位でテレメトリ監査を開始
aws observabilityadmin start-telemetry-evaluation

ステップ 2: テレメトリ監査ステータスの確認

Bash テレメトリ監査のステータスを確認 
# テレメトリ監査のステータスを確認
aws observabilityadmin get-telemetry-evaluation-status

ステップ 3: テレメトリ有効化ルールの作成

Bash 特定リージョンに対する EC2 メトリクスの有効化ルール 
# 特定リージョンに対する EC2 メトリクスの有効化ルールを作成
aws observabilityadmin create-telemetry-rule \
    --rule-name "ec2-metrics-apac" \
    --rule '{
        "ResourceType": "AWS::EC2::Instance",
        "TelemetryType": "Metrics",
        "Regions": ["ap-northeast-1", "ap-southeast-1", "ap-southeast-2"],
        "AllRegions": false
    }'

ステップ 4: 組織全体へのルール適用

Bash 組織全体に CloudTrail ログの有効化ルールを作成 
# 組織全体に CloudTrail ログの有効化ルールを作成
aws observabilityadmin create-telemetry-rule-for-organization \
    --rule-name "cloudtrail-logs-org-wide" \
    --rule '{
        "ResourceType": "AWS::CloudTrail",
        "TelemetryType": "Logs",
        "DestinationConfiguration": {
            "DestinationType": "cloud-watch-logs",
            "DestinationPattern": "/aws/cloudtrail",
            "RetentionInDays": 365
        },
        "AllRegions": true
    }'

🐍 Python SDK サンプルコード

Python 全リージョンに VPC フローログの有効化ルールを作成 
import boto3

client = boto3.client('observabilityadmin')

# 全リージョンに VPC フローログの有効化ルールを作成
response = client.create_telemetry_rule(
    RuleName='vpc-flow-logs-all-regions',
    Rule={
        'ResourceType': 'AWS::EC2::VPC',
        'TelemetryType': 'Logs',
        'TelemetrySourceTypes': ['VPC_FLOW_LOGS'],
        'DestinationConfiguration': {
            'DestinationType': 'cloud-watch-logs',
            'DestinationPattern': '/aws/vpc/flowlogs',
            'RetentionInDays': 90,
            'VPCFlowLogParameters': {
                'TrafficType': 'ALL',
                'MaxAggregationInterval': 60
            }
        },
        'AllRegions': True
    },
    Tags={
        'Environment': 'production',
        'ManagedBy': 'observability-team'
    }
)

print(f"Rule ARN: {response['RuleArn']}")

⚖️ メリットと制約事項

✅ メリット

運用コストの削減: 各リージョンでの個別設定作業が不要になり、マルチリージョン環境のオブザーバビリティ管理工数を大幅に削減
コンプライアンス遵守の効率化: 組織全体でテレメトリポリシーを統一的に適用し、監査要件への準拠を効率的に維持
新リージョン展開の迅速化: 全リージョン設定のルールにより、新リージョンへの展開時にテレメトリ追加作業が不要
自動拡張: AllRegions フラグで新リージョン利用可能時にルールが自動拡張
API 自動化: 8 つの API メソッドでテレメトリルールの CRUD をプログラマティックに管理

⚠️ 制約事項と注意点

送信先タイプの制限: 現時点で cloud-watch-logs のみサポート
リージョン制限: GovCloud や中国リージョンは対象外。AWS 商用リージョンのみ対応
非同期適用: ルール適用は非同期のため、全リージョンへの反映に時間がかかる場合がある
コスト考慮: 全リージョン有効化により、意図しないリージョンでもテレメトリが有効化される可能性あり。コストへの影響を事前に見積もること
権限管理: Organizations レベルのルールは管理アカウントからのみ作成可能

🎯 ユースケース

🌍 ユースケース 1: マルチリージョンワークロードの統一オブザーバビリティ

グローバルに展開された Web アプリケーションが複数リージョンで EC2 インスタンスと VPC を使用しており、すべてのリージョンでメトリクスとログを一貫して収集する必要がある。

全リージョンの EC2 インスタンスメトリクスと VPC フローログを AllRegions: true で有効化。

💡 効果: 新リージョンへの展開時にテレメトリ設定を手動追加する必要がなくなり、常に全リージョンで一貫したオブザーバビリティが確保される

🔒 ユースケース 2: 組織全体のセキュリティ監査ログの一元化

セキュリティチームが AWS Organizations 配下の全アカウント・全リージョンで CloudTrail ログと Security Hub の検出ログを確実に有効化し、コンプライアンス監査に対応。

create-telemetry-rule-for-organization で CloudTrail と Security Hub のログを 365 日保持で全リージョンに適用。

💡 効果: 組織内の全アカウントとリージョンで監査ログが確実に有効化され、新規アカウント・リージョン追加時も自動的にポリシーが適用される

📦 ユースケース 3: EKS クラスターのマルチリージョン監視

複数リージョンに展開された EKS クラスターの監査ログ、API サーバーログ、コントローラーマネージャーログを一元的に有効化し、Kubernetes 運用チームに一貫した可視性を提供。

APAC リージョンを指定して EKS の各種ログタイプを一括有効化。

💡 効果: 対象リージョンの EKS クラスターに一貫したログ設定が適用され、リージョンごとの個別設定が不要になる
