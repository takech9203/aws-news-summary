Amazon DynamoDB Streams

⏰ タイムスタンプベースのストリーム処理

AT_TIMESTAMP シャードイテレータで、指定時刻以降の最初のレコードからストリーム読み取りを開始可能に
📅 リリース日: 2026 年 10 月 15 日

📋 概要

Amazon DynamoDB Streams がタイムスタンプベースのストリーム処理をサポートしました。 AT_TIMESTAMP シャードイテレータタイプを使用すると、ApproximateCreationDateTime が指定時刻以降である最初のレコードから読み取りを開始できます。

DynamoDB Streams Kinesis アダプターを通じて Kinesis Client Library (KCL) からも利用でき、障害からの復旧、デバッグ・監査のためのデータ再生、バックログのスキップ、PITR エクスポート後の同期といったユースケースに対応します。

❌ Before: 開始位置の選択肢が限定的
✗開始位置は最古のレコード (TRIM_HORIZON) か新規レコード (LATEST) のみ
✗中断後の再開は「全体を再処理」か「レコードを失う」かのトレードオフ
✗PITR エクスポート後、エクスポート時点以降の変更だけを正確に適用する手段がない
✅ After: 時刻を指定した柔軟な読み取り開始
✓タイムスタンプ指定で、その時刻以降の最初のレコードから読み取り開始
✓復旧時にストリーム全体の再処理や取りこぼしを回避
✓データ再生 (デバッグ・監査)、バックログのスキップ、PITR エクスポート時刻からの同期が可能

⚙️ 主要機能

🕐 AT_TIMESTAMP シャードイテレータタイプ
  • GetShardIterator API に新しいイテレータタイプ AT_TIMESTAMP が追加
  • タイムスタンプを指定すると、ApproximateCreationDateTime が指定時刻以降である最初のレコードからイテレータが開始
  • 取得したイテレータを GetRecords に渡し、指定時点以降のレコードを順に読み取り
📚 Kinesis Client Library (KCL) との統合
  • DynamoDB Streams Kinesis アダプター バージョン 2.5.0 以降で KCL アプリケーションから利用可能
  • InitialPositionInStreamExtended.newInitialPositionAtTimestamp でタイムスタンプを指定し、StreamTracker を ConfigsBuilder に登録
  • アダプターは新しいリースごとに AT_TIMESTAMP を初期位置として初期化し、指定タイムスタンプで GetShardIterator を呼び出す
🛡️ 安全なタイムスタンプ処理
  • タイムスタンプが保持期間 (24 時間) より古い場合、エラーにならず各シャードの最古のレコードから開始
  • タイムスタンプが未来の場合、アダプターが初期化時に検証し API 呼び出しなしで拒否
  • 追加の IAM 権限は不要、既存のアダプターアプリケーションと同じ権限で動作

🔬 技術仕様

読み取り開始位置の比較

イテレータタイプ読み取り開始位置主な用途
TRIM_HORIZON保持されている最古のレコード (最大 24 時間前)全レコードの処理
LATEST消費開始後に書き込まれた新しいレコードリアルタイム処理
AT_SEQUENCE_NUMBER / AFTER_SEQUENCE_NUMBER指定したシーケンス番号の位置チェックポイントからの再開
AT_TIMESTAMP 🆕指定時刻以降の最初のレコード時刻指定による再開・再生

タイムスタンプのシナリオ別動作

シナリオ動作
タイムスタンプが保持期間内指定時刻以降の最初のレコードから読み取り開始
タイムスタンプが保持期間より古いエラーにならず、各シャードの最古のレコードから開始
タイムスタンプが未来アダプターが初期化時に拒否し、処理を開始しない

🛠️ 設定方法

前提条件

✓DynamoDB テーブルで DynamoDB Streams が有効化されていること
✓KCL で利用する場合は DynamoDB Streams Kinesis アダプターのバージョン 2.5.0 以降を使用すること
✓既存のアダプターアプリケーションと同じ IAM 権限 (追加の API 権限は不要)
1
AWS CLI でタイムスタンプ指定のシャードイテレータを取得
BashGetShardIterator を AT_TIMESTAMP で呼び出し
aws dynamodbstreams get-shard-iterator \
  --stream-arn arn:aws:dynamodb:ap-northeast-1:123456789012:table/MyTable/stream/2026-10-15T00:00:00.000 \
  --shard-id shardId-00000001 \
  --shard-iterator-type AT_TIMESTAMP \
  --timestamp 2026-10-15T09:00:00+09:00

指定したタイムスタンプ以降の最初のレコードを指すシャードイテレータを取得します。

2
取得したイテレータでレコードを読み取る
BashGetRecords でレコードを取得
aws dynamodbstreams get-records \
  --shard-iterator <ステップ1で取得したシャードイテレータ>

レスポンスには ApproximateCreationDateTime が指定時刻以降である最初のレコードから順に含まれます。

3
KCL アプリケーションでタイムスタンプを設定 (Java)
JavaKCL 初期位置の設定
// 開始タイムスタンプを指定して初期位置を作成
InitialPositionInStreamExtended initialPosition =
    InitialPositionInStreamExtended.newInitialPositionAtTimestamp(
        Date.from(Instant.ofEpochMilli(1790467200000L)));

// ストリームトラッカーを作成
StreamTracker streamTracker = StreamsSchedulerFactory.createSingleStreamTracker(
    streamArn,
    initialPosition);

// スケジューラが指定タイムスタンプからシャードを読み取るよう登録
configsBuilder.streamTracker(streamTracker);

アダプターは新しいリースごとに指定タイムスタンプで GetShardIterator を呼び出し、レコードの読み取りを開始します。

💡 メリット

⚡ 復旧短縮
必要な時点からのみ再開し、ダウンタイム後のキャッチアップが高速に
🔍 監査効率化
過去の特定時点からデータを再生し、調査作業を効率化
💰 追加料金なし
標準の GetRecords API リクエスト料金のみで利用可能

🏢 ビジネス面

✓復旧時間の短縮: 障害や中断からの復旧時に、必要な時点からのみ処理を再開できる
✓監査対応の効率化: 過去の特定時点からデータを再生でき、監査やデバッグの調査を効率化
✓追加コストなし: 標準の GetRecords API リクエスト料金以外に追加料金は発生しない

🔧 技術面

✓再処理の削減: ストリーム全体の再処理が不要になり、重複処理や下流システムへの負荷を削減
✓PITR との連携: PITR エクスポートのタイムスタンプを開始位置に指定し、復元後のテーブルとストリーム消費を正確に同期
✓バックログのスキップ: 最新レコードに近いタイムスタンプを指定し、処理しきれないバックログをスキップして追いつき可能

⚠️ デメリット・制約事項

制限事項

✗DynamoDB Streams の保持期間は最大 24 時間のままで、保持期間を過ぎたレコードはタイムスタンプを指定しても復元できない
✗KCL で利用する場合は DynamoDB Streams Kinesis アダプターのバージョン 2.5.0 以降が必要
✗未来のタイムスタンプは指定できない (アダプターが初期化時に拒否する)

考慮すべき点

⚠️稼働中のアプリケーションでは、リーステーブルに状態が保存されているため、タイムスタンプや初期位置 (AT_TIMESTAMP、TRIM_HORIZON、LATEST) を変更してはならない。チェックポイント済みのシャードは既存のチェックポイントから継続し、シャードごとに異なる開始位置で処理される可能性がある
⚠️設定を安全に変更するには、アプリケーションを停止したうえで、リーステーブルを削除して再起動する (推奨)、または新しいアプリケーション名で新しいリーステーブルを作成する
⚠️現在時刻に近いタイムスタンプを指定する場合は、アプリケーションホストとサービス間のクロック差を考慮する

🎯 ユースケース

1️⃣ 障害・中断からの復旧

シナリオ: ストリームコンシューマーが数時間停止した後、停止時点から処理を再開したい。チェックポイント情報が失われていても停止時刻は把握している。

Java停止時刻 (例: 3 時間前) から再開
InitialPositionInStreamExtended initialPosition =
    InitialPositionInStreamExtended.newInitialPositionAtTimestamp(
        Date.from(Instant.now().minus(Duration.ofHours(3))));

効果: 再処理による重複や取りこぼしを避けつつ、停止時点から正確に処理を再開できる。

2️⃣ デバッグ・監査のためのデータ再生

シナリオ: 本番環境で特定の時刻に発生した問題を調査するため、その時刻以降の変更レコードを別のコンシューマーで再生して分析したい。

Bash問題発生時刻以降のレコードを取得
aws dynamodbstreams get-shard-iterator \
  --stream-arn <ストリーム ARN> \
  --shard-id <シャード ID> \
  --shard-iterator-type AT_TIMESTAMP \
  --timestamp 2026-10-15T03:00:00Z

効果: 問題発生時刻以降の変更履歴だけをピンポイントで取得でき、調査時間を短縮できる。

3️⃣ PITR エクスポート後の同期

シナリオ: PITR エクスポートでテーブルデータを別システムに複製した後、エクスポート時点以降の変更をストリームから適用して同期を維持したい。

JavaPITR エクスポートのタイムスタンプから開始
InitialPositionInStreamExtended initialPosition =
    InitialPositionInStreamExtended.newInitialPositionAtTimestamp(
        exportTimestamp);

効果: エクスポート時点と読み取り開始位置が正確に一致し、変更の欠落や重複なく同期を継続できる。

💰 料金・利用可能リージョン

💵 料金

この機能自体に追加料金はありません。標準の GetRecords API リクエスト料金のみが適用されます。詳細は DynamoDB 料金ページを参照してください。

🌍 利用可能リージョン

すべての商用 AWS リージョン、AWS GovCloud (US) リージョン、中国リージョンで利用可能です。

🔗 関連サービス・機能

📜 Amazon DynamoDB Streams

テーブルの項目レベルの変更をキャプチャするストリーム機能。本アップデートの対象。

📚 Kinesis Client Library (KCL)

DynamoDB Streams Kinesis アダプターを介してストリームを消費するためのライブラリ。バージョン 2.5.0 以降のアダプターで本機能に対応。

🕰️ DynamoDB ポイントインタイムリカバリ (PITR)

特定時点へのテーブル復元・エクスポート機能。エクスポートタイムスタンプを本機能の開始位置として利用できる。

🌊 Amazon Kinesis Data Streams

Kinesis では以前から AT_TIMESTAMP イテレータが利用可能であり、DynamoDB Streams でも同等の操作性が実現された。

📝 まとめ

DynamoDB Streams の AT_TIMESTAMP シャードイテレータにより、時刻を指定したストリーム読み取りが可能になり、障害復旧・データ再生・PITR 後の同期といった運用上の課題が大きく改善されます。

✓追加料金なしで利用可能。復旧手順やリプレイ手順への組み込みを検討することを推奨
✓KCL 利用時はアダプターをバージョン 2.5.0 以降に更新
⚠️稼働中アプリケーションの初期位置変更時はリーステーブルの扱いに注意
