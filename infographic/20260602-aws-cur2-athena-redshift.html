💰 AWS CUR 2.0
Athena / Redshift インテグレーション

CUR 1.0 との機能パリティを実現し、コストデータの SQL 分析が手軽に

2026-06-02
AWS Billing and Cost Management

📋 概要

AWS Cost and Usage Report 2.0 (CUR 2.0) に Amazon Athena および Amazon Redshift との統合オプションが追加された。S3 に保存された CUR 2.0 データを標準 SQL で直接クエリ可能となり、カスタムデータウェアハウスの構築が不要に。

統合選択時、CUR 2.0 エクスポートはクエリエンジンに最適なフォーマット (Parquet / GZIP) で自動配信される。インフラストラクチャテンプレート、テーブル定義、データロード手順が付属し、手動設定なしでクエリを開始できる。

❌ Before

  • CUR 2.0 に Athena / Redshift 直接統合なし
  • カスタム ETL パイプラインの構築が必要
  • テーブル定義やデータロードを手動設定
  • CUR 1.0 → CUR 2.0 移行が困難

✅ After

  • Athena / Redshift を選択するだけで自動配信
  • テンプレート・テーブル定義が自動提供
  • データ更新が自動反映、追加 ETL 不要
  • CUR 1.0 との機能パリティ達成

⚡ 主要機能

🔍 Athena 統合

  • CUR 2.0 データを Athena で直接クエリ可能
  • Parquet 形式で最適化されたデータ配信
  • テーブル定義とパーティション設定が自動生成
  • データ更新時に Athena テーブルへ自動反映

🏢 Redshift 統合

  • CUR 2.0 データを Redshift で直接クエリ可能
  • Redshift に最適化されたフォーマットでデータ配信
  • データロード手順とテーブル定義が自動提供
  • 定期的なデータリフレッシュが自動反映

⚙️ 自動化リソースの提供

  • インフラストラクチャテンプレート (CloudFormation 等)
  • テーブル定義 (DDL)
  • データロード手順
  • サポートメタデータ
  • 手動設定不要で即座にクエリ開始可能

ステップ 1: CUR 2.0 エクスポートの作成

AWS Billing and Cost Management コンソールから Data Exports セクションに移動し、新しいエクスポートを作成する。

Bash AWS CLI でのエクスポート作成 
aws bcm-data-exports create-export \
  --export '{
    "Name": "my-cur2-athena-export",
    "DataQuery": {
      "QueryStatement": "SELECT * FROM COST_AND_USAGE_REPORT",
      "TableConfigurations": {
        "COST_AND_USAGE_REPORT": {
          "TIME_GRANULARITY": "DAILY"
        }
      }
    },
    "DestinationConfigurations": {
      "S3Destination": {
        "S3Bucket": "my-cur2-bucket",
        "S3Prefix": "cur2-reports",
        "S3Region": "us-east-1"
      }
    }
  }'

ステップ 2: 自動化リソースの適用

エクスポート作成後に提供されるインフラストラクチャテンプレートを使用して、テーブルをセットアップする。

Bash CloudFormation テンプレートのデプロイ 
aws cloudformation deploy \
  --template-file cur2-athena-integration.yaml \
  --stack-name cur2-athena-setup \
  --capabilities CAPABILITY_IAM

ステップ 3: クエリの実行

Athena コンソールまたは Redshift でコストデータをクエリする。

SQL Athena でのクエリ例: サービス別月次コスト 
SELECT
  line_item_product_code,
  SUM(line_item_unblended_cost) AS total_cost
FROM cur2_report
WHERE billing_period = '2026-06'
GROUP BY line_item_product_code
ORDER BY total_cost DESC
LIMIT 10;

⚖️ メリット・デメリット

✅ メリット

  • 移行障壁の解消: CUR 2.0 への移行が容易に
  • 分析の迅速化: 手動設定なしで即座に分析開始
  • 運用コスト削減: カスタム ETL の構築・維持が不要
  • ゼロ ETL: データ更新が自動反映
  • 最適フォーマット自動選択: Parquet / GZIP 自動切替
  • セットアップ自動化: テンプレートでインフラ構築

⚠️ 制限事項・注意点

  • AWS GovCloud リージョンでは利用不可
  • 中国リージョンでは利用不可
  • データ量に応じた Athena / Redshift クエリコスト
  • CUR 1.0 → 2.0 移行時はスキーマ差異でクエリ修正が必要な場合あり
  • 更新頻度は CUR 2.0 リフレッシュスケジュールに依存
  • 大規模データでは Athena スキャン料金に注意

🎯 ユースケース

📊 マルチアカウントコスト分析

シナリオ: AWS Organizations で複数アカウントを管理し、全アカウントのコストを横断的に分析したい。

効果: カスタムデータウェアハウスなしで、Athena から直接マルチアカウントのコスト傾向を分析可能。

SQL アカウント別・サービス別の月次コスト 
SELECT
  line_item_usage_account_id,
  line_item_product_code,
  SUM(line_item_unblended_cost) AS total_cost
FROM cur2_report
WHERE billing_period = '2026-06'
GROUP BY line_item_usage_account_id, line_item_product_code
ORDER BY total_cost DESC;

💵 RI / Savings Plans 活用状況の可視化

シナリオ: Reserved Instances や Savings Plans の利用状況をモニタリングし、最適化の余地を特定したい。

効果: Redshift のダッシュボード機能と組み合わせ、RI / Savings Plans の活用率を継続的にモニタリングできる。

SQL Savings Plans のカバレッジ分析 
SELECT
  savings_plan_savings_plan_a_r_n,
  SUM(savings_plan_savings_plan_effective_cost) AS effective_cost,
  SUM(savings_plan_total_commitment_to_date) AS commitment
FROM cur2_report
WHERE billing_period = '2026-06'
  AND savings_plan_savings_plan_a_r_n IS NOT NULL
GROUP BY savings_plan_savings_plan_a_r_n;

🚨 コスト異常検知の基盤構築

シナリオ: 日次でコストデータを分析し、異常な支出パターンを早期に検知したい。

効果: 追加の ETL なしで、CUR 2.0 データの自動更新を活用した日次コスト異常検知が実現可能。

SQL 日次コストの前日比較 
WITH daily_costs AS (
  SELECT
    line_item_usage_start_date::date AS usage_date,
    SUM(line_item_unblended_cost) AS daily_cost
  FROM cur2_report
  WHERE billing_period = '2026-06'
  GROUP BY line_item_usage_start_date::date
)
SELECT
  usage_date,
  daily_cost,
  LAG(daily_cost) OVER (ORDER BY usage_date) AS prev_day_cost,
  daily_cost - LAG(daily_cost) OVER (ORDER BY usage_date) AS cost_change
FROM daily_costs
ORDER BY usage_date DESC;

💲 料金情報

CUR 2.0 エクスポート自体には追加料金は発生しない。関連サービスの料金が適用される。

項目 料金
CUR 2.0 エクスポート 無料
S3 ストレージ S3 標準料金 (保存量に応じて)
Athena クエリ スキャンしたデータ 1TB あたり $5.00
Redshift インスタンスタイプ・時間に応じた料金
Redshift Serverless RPU 時間あたりの料金

💡 Tip: Parquet 形式は列指向・圧縮されているため、Athena のスキャン量を大幅に削減でき、コスト効率が高い。
