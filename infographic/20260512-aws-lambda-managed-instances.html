スケジュールスケーリング

AWS Lambda
2026-05-12

📋 概要

AWS Lambda は、Lambda Managed Instances 上で実行される関数に対するスケジュールスケーリング機能を発表。Amazon EventBridge Scheduler を使用して、予想されるトラフィックに先立ってキャパシティ制限をプロアクティブに調整できるようになった。

Lambda Managed Instances は、マネージド Amazon EC2 インスタンス上で Lambda 関数を実行し、ルーティング、ロードバランシング、オートスケーリングを組み込みで提供するサービス。今回のアップデートにより、ビジネスアワーやマーケティングイベントなど、予測可能なトラフィックパターンに対して事前にキャパシティを自動調整できる。

Before / After

❌ BEFORE
  • 手動でキャパシティ制限を調整
  • カスタム自動化の構築が必要
  • 事前準備の標準的な方法が不在
  • アイドル期間中もコスト発生
✅ AFTER
  • EventBridge Scheduler で自動調整
  • カスタム自動化の構築が不要
  • ビジネスアワー前にキャパシティ準備
  • ゼロスケールでコスト削減

🎯 主要機能

📅 スケジュールベースのキャパシティ調整

1 回限り (one-time) または定期的 (recurring) なスケジュールを定義し、キャパシティの最小値と最大値の実行環境制限を事前に調整。

🔗 EventBridge Scheduler との統合

Amazon EventBridge Scheduler を使用してスケジュールを管理。cron 式や rate 式による柔軟な定義と、既存の EventBridge エコシステムとの統合。

📉 ゼロスケーリング対応

アイドル期間中にキャパシティをゼロにスケールダウン可能。トラフィック再開前にスケールアップをスケジュールし、アクティブ時のみ課金。

⚙️ 設定方法

前提条件

✓ Lambda Managed Instances が有効化されている Lambda 関数が存在すること
✓ Amazon EventBridge Scheduler を使用するための IAM 権限が設定されていること
✓ Lambda Managed Instances がサポートされているリージョンを使用していること

スケールアップ (ビジネスアワー開始前)

Bash 平日朝 8 時にキャパシティ増加 
aws scheduler create-schedule \
  --name "scale-up-business-hours" \
  --schedule-expression "cron(0 8 ? * MON-FRI *)" \
  --schedule-expression-timezone "Asia/Tokyo" \
  --target '{
    "Arn": "arn:aws:lambda:ap-northeast-1:123456789012:function:my-function",
    "RoleArn": "arn:aws:iam::123456789012:role/scheduler-role",
    "Input": "{\"MinCapacity\": 10, \"MaxCapacity\": 100}"
  }' \
  --flexible-time-window '{"Mode": "OFF"}'

スケールダウン (ビジネスアワー終了後)

Bash 平日夜 20 時にキャパシティをゼロに 
aws scheduler create-schedule \
  --name "scale-down-after-hours" \
  --schedule-expression "cron(0 20 ? * MON-FRI *)" \
  --schedule-expression-timezone "Asia/Tokyo" \
  --target '{
    "Arn": "arn:aws:lambda:ap-northeast-1:123456789012:function:my-function",
    "RoleArn": "arn:aws:iam::123456789012:role/scheduler-role",
    "Input": "{\"MinCapacity\": 0, \"MaxCapacity\": 0}"
  }' \
  --flexible-time-window '{"Mode": "OFF"}'

💡 ユースケース

🏢 ユースケース 1: ビジネスアワーアプリケーション

社内の業務システムが平日の 9:00 - 18:00 にのみ使用され、夜間や週末はほぼトラフィックがない。平日朝 8:45 にスケールアップ、19:00 にスケールダウン。
✅ 効果: 夜間・週末のコストを完全に削減しつつ、ビジネスアワー開始 15 分前にキャパシティを準備してコールドスタートを回避。

🛒 ユースケース 2: マーケティングイベント対応

EC サイトで特定日時にタイムセールを実施し、通常の 10 倍のトラフィックが予想される。セール開始 30 分前に 1 回限りのスケジュールでキャパシティを拡大。
✅ 効果: 1 回限りのスケジュールで特定イベントに備え、セール開始時のキャパシティ不足によるレイテンシー増加を防止。

🔄 ユースケース 3: バッチ処理のスケジュール最適化

毎日深夜 2:00 に大量のデータ処理バッチが実行され、日中は軽量なリクエストのみ処理。バッチ処理開始 10 分前にキャパシティを拡大し、完了後に縮小。
✅ 効果: バッチ処理時に十分なキャパシティを確保し、処理完了後は日中の軽量トラフィックに適したサイズに自動調整。

⚖️ メリット・デメリット

✅ メリット

  • コスト最適化: アイドル期間にゼロスケールでコスト回避
  • 運用負荷の軽減: カスタム自動化の構築・保守が不要
  • 予測可能なパフォーマンス: ピーク前にキャパシティ準備で SLA 達成
  • コールドスタート最小化: 事前確保でトラフィック急増時の遅延削減
  • IaC 対応: CDK / CloudFormation でコード管理可能
  • エコシステム統合: EventBridge の再試行、DLQ 等を活用可能

⚠️ 制約・注意点

  • Lambda Managed Instances 上の関数のみ対象
  • サポートリージョンでのみ利用可能
  • EventBridge Scheduler の制限が適用
  • 不適切な設定でキャパシティ不足やコスト超過のリスク
  • 予測不可能なトラフィックにはリアクティブスケーリングとの併用が必要
  • EventBridge Scheduler の追加費用が発生

💰 料金

スケジュールスケーリング機能自体には追加料金は発生しない。関連するコストは以下の通り。

項目 料金
Lambda Managed Instances EC2 インスタンスの実行時間に基づく課金
EventBridge Scheduler スケジュール呼び出しごとに課金
アイドル時キャパシティゼロ トラフィックを処理していない場合は課金なし

🌍 利用可能リージョン

Lambda Managed Instances がサポートされているすべての AWS リージョンで利用可能。
