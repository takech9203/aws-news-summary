🤖 SageMaker Data Agent
ビジネスコンテキスト統合

ビジネス用語でデータを発見し、より正確なコード生成を実現

📅 2026-06-04

📋 概要

Amazon SageMaker Data Agent が SageMaker Catalog のビジネスコンテキストおよびメタデータと統合。データ実務者がビジネス用語を使用してデータセットを発見し、より正確な SQL および Python コードを生成できるようになった。

企業が SageMaker Catalog で数か月かけてキュレーションしたビジネスコンテキスト (Collibra、Atlan、Alation から同期されたものを含む) を活用し、データガバナンスを尊重しながらデータ検出とコード生成を実現する。

❌ Before

  • 技術的なテーブル名やカラム名を把握する必要あり
  • SageMaker Catalog のビジネスコンテキストが未活用
  • コード生成時に手動でテーブル識別、初回精度が低い
  • データガバナンスの確認が手動プロセス

✅ After

  • ビジネス用語での質問が可能に
  • 用語集、メタデータフォーム、アセットサマリーを自動検索
  • 初回コード生成精度が向上、ワークフロー計画も正確
  • サブスクリプションチェック・アクセスリクエスト自動化

⚡ 主要機能

💬 ビジネス用語による自然言語クエリ

「顧客リテンション率を計算して」「顧客離脱に関するデータは何がある?」といった質問に対応。用語集を検索してビジネス用語と技術的なテーブル/カラム名をマッピングし、カスタムメタデータフォーム・アセットサマリー・README も検索対象とする。

🎯 初回精度の高いコード生成

ビジネスコンテキストの理解により、最初の試行でより正確な SQL/Python コードを生成。テーブルの正しい識別と適切なカラムの選択を自動化し、複雑な計算ロジックもビジネス定義に基づいて正確に実装する。

📋 マルチステップワークフロー計画

複数テーブルにまたがる分析の場合、正しい順序でテーブルと変換を計画。データの結合条件やフィルタリング条件をビジネスコンテキストから推定し、ステップバイステップの実行計画を自動生成する。

🔒 データガバナンスの自動遵守

サブスクリプションステータスを自動的に確認し、アクセス権限がない場合はアクセスリクエストリンクを提供。組織のデータポリシーに準拠した形でデータ検出を実行する。

🔄 外部カタログツールとの統合

Collibra、Atlan、Alation から SageMaker Catalog に同期されたメタデータを活用。既存のカタログ投資を最大限に活用し、ワークフローの変更は不要。

💡 ユースケース

📊 ユースケース 1: ビジネスアナリストによるアドホック分析

シナリオ: マーケティング部門のビジネスアナリストが顧客リテンション率のトレンドを分析。技術的なテーブル名 (dim_customer_lifecycle_v3) は知らないが、ビジネス用語は理解している。

SQL Data Agent が生成するコード例 
SELECT
    DATE_TRUNC('month', activity_date) AS month,
    COUNT(DISTINCT CASE WHEN is_retained = 1 THEN customer_id END) * 100.0
        / COUNT(DISTINCT customer_id) AS retention_rate
FROM customer_lifecycle.dim_customer_lifecycle_v3
WHERE activity_date >= DATEADD(month, -12, CURRENT_DATE)
GROUP BY 1
ORDER BY 1;

✅ 効果: テーブル名の調査に費やしていた 30 分以上の時間が不要になり、即座に分析を開始

🔄 ユースケース 2: 外部カタログ統合によるデータ検出

シナリオ: Collibra でデータカタログを管理している企業が、SageMaker Unified Studio でデータ分析を実施。Collibra に登録されたビジネス用語定義を活用して Data Agent でデータを検出する。

✅ 効果: Collibra への既存投資を最大限に活用しながら、SageMaker 環境でのデータ作業効率が向上

🔒 ユースケース 3: データガバナンスを考慮した分析

シナリオ: データエンジニアが機密性の高い顧客データにアクセスしようとするが、サブスクリプション申請が未完了。Data Agent がアクセス権限を自動チェックし、リクエストリンクを提供する。

✅ 効果: データガバナンスポリシーに違反することなく、適切なアクセスフローに誘導

⚖️ メリット・デメリット

✅ ビジネス面のメリット

  • Time-to-Insight の短縮: ビジネス用語で直接質問でき調査時間を大幅削減
  • 既存カタログ投資の最大活用: Collibra/Atlan/Alation のメタデータをそのまま活用
  • データ民主化の促進: 技術知識が少ないユーザーでも自然言語で分析開始可能

✅ 技術面のメリット

  • 初回コード生成精度の向上: ビジネスコンテキストに基づく正確なテーブル/カラム識別
  • ワークフロー変更不要: 既存のデータワークフローをそのまま維持
  • データガバナンスの自動化: アクセス権限確認とリクエストフローを自動化

⚠️ 制限事項・考慮点

  • SageMaker Unified Studio が利用可能なリージョンのみで使用可能
  • SageMaker Catalog のメタデータ品質に依存 - 不十分な場合は精度が低下する可能性
  • 外部カタログツールとの同期は Collibra、Atlan、Alation の 3 ツールに限定
  • ビジネスコンテキスト整備には初期投資が必要 (用語集やメタデータフォームの設計・登録)
  • 組織内でビジネス用語が統一されていない場合、検索精度に影響の可能性
  • 外部カタログツールからの同期遅延が発生する可能性あり

📝 まとめ

Amazon SageMaker Data Agent のビジネスコンテキスト統合は、データチームがビジネス言語で直接データ分析を開始できる重要なアップデート。Collibra、Atlan、Alation などの既存カタログ投資を活用しながら、ワークフローを変更せずに導入できる点が大きな利点。

SageMaker Catalog に十分なビジネスコンテキストを整備している組織にとっては、Time-to-Insight を大幅に短縮し、データ民主化を推進する有効な手段となるため、早期の検証を推奨する。
