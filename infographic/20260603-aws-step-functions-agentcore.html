📋 概要

AWS Step Functions に、Amazon Bedrock AgentCore のマネージドハーネスとの最適化された統合による AI エージェント推論ステップが追加された。ワークフロー内でドキュメント分類や非構造化フォームからの要素抽出といった推論タスクを自動化できるようになった。

AgentCore ハーネスは、モデル、ツール、動作を設定で宣言するだけでエージェントを定義できる仕組みであり、AgentCore がエージェントループをエンドツーエンドで実行するマネージド環境を提供する。Step Functions の視覚的なワークフローオーケストレーション機能と組み合わせることで、複数のエージェントを並列・逐次実行し、重要なアクション前には人間の承認ステップを挟むといった高度なワークフローを構築できる。

Before / After 比較

❌ アップデート前の課題

  • Lambda 関数や外部サービスを介した複雑なカスタム実装が必要
  • エージェントの推論ループの管理、エラーハンドリング、リトライロジックを自前で構築
  • 各決定ポイントでエージェント設定を個別管理、設定の重複が発生
  • コンテキスト永続化の仕組みを独自に構築する必要

✅ アップデート後の改善

  • Step Functions のステートとして直接 AgentCore ハーネスを呼び出し可能
  • AgentCore がエージェントループ全体をマネージドで実行、インフラ管理不要
  • 呼び出しごとにモデル、システムプロンプト、ツールをオーバーライド可能
  • セッション ID でコンテキストを実行内/実行間で永続化
  • Workflow Studio から直接ハーネスを作成・再利用可能

🚀 主要機能

1. AgentCore マネージドハーネスとの最適化統合

Workflow Studio から直接ハーネスを作成、または既存のハーネスを再利用可能。モデル、ツール、動作を宣言的に設定するだけでエージェントを定義し、AgentCore がエージェントループをエンドツーエンドで管理・実行する。

2. 呼び出しごとのオーバーライド

モデル、システムプロンプト、ツールを呼び出し単位で変更可能。ワークフローのコンテキストに応じてエージェントの動作を適応させ、1 つのハーネスを複数の用途で再利用できる。

3. セッション ID によるコンテキスト永続化

エージェントのコンテキストを呼び出し間で保持。同一ワークフロー実行内、または異なるワークフロー実行間で動作し、会話の継続性を保ちながら複数ステップで推論を実行。

4. 並列・逐次実行と人間の承認

複数のエージェントをワークフロー内で並列または逐次に実行。単一ワークフロー内の異なる決定ポイントにエージェントを配置し、重要なアクション前に人間の承認ステップを追加可能。

5. 包括的なオブザーバビリティ

ワークフロー実行履歴にエージェントの入力、出力、トークン使用量、実行時間を表示。Amazon CloudWatch へのリンクからエージェントターンの詳細を確認でき、推論プロセス全体の監査とデバッグが可能。

💻 ワークフロー定義例

Step Functions のステート定義で AgentCore ハーネスを呼び出す例。オーバーライドとセッション ID を活用。

JSON AgentCore ハーネス呼び出しステート 
{
  "Type": "Task",
  "Resource": "arn:aws:states:::bedrock-agentcore:harness:invoke",
  "Parameters": {
    "HarnessArn": "arn:aws:bedrock-agentcore:us-east-1:123456789012:harness/my-classifier",
    "Input": {
      "message": "Classify this document and extract key fields"
    },
    "Overrides": {
      "Model": "anthropic.claude-sonnet-4-20250514",
      "SystemPrompt": "You are a document classifier specialized in invoices.",
      "Tools": ["extract_fields", "validate_data"]
    },
    "SessionId": "workflow-session-001"
  },
  "Next": "ProcessResult"
}

✨ メリット

💼 ビジネス面

  • 開発期間の短縮: エージェントループのカスタム実装が不要、AI ワークフロー構築期間を大幅に短縮
  • 運用コストの削減: マネージドサービスによるインフラ管理の排除、追加統合料金なし
  • 品質管理の強化: 人間の承認ステップとオブザーバビリティにより AI 推論結果の品質を担保

🔧 技術面

  • 宣言的なエージェント定義: コード不要で設定のみによりエージェントを定義、再利用、オーバーライド可能
  • ネイティブな並列処理: Step Functions の並列実行機能を活用し、複数エージェントの同時実行が容易
  • 完全な監査証跡: 入出力、トークン使用量、実行時間の記録と CloudWatch によるターンレベルの追跡

⚠️ デメリット・制約事項

制限事項

  • 現在プレビュー段階、GA 時に仕様変更の可能性あり
  • 利用可能リージョンが 4 リージョンに限定 (東京リージョン未対応)
  • AgentCore マネージド環境に依存、カスタムランタイム要件がある場合は制約

考慮すべき点

  • Bedrock モデル推論料金と AgentCore 料金が別途発生、大量呼び出し時のコスト管理が重要
  • セッション ID のデータ保持期間やサイズ制限は GA 時に明確化予定
  • プレビュー段階のため、本番ワークロードへの適用は慎重に検討

💡 ユースケース

📄 インテリジェントなドキュメント処理パイプライン

企業が大量の受信ドキュメント (請求書、契約書、申請書) を自動分類し、各タイプに応じたデータ抽出と検証を行う。手動分類作業を排除し、ドキュメント処理のスループットを向上。エラー率の低減と処理時間の短縮を実現。

💬 マルチステップの顧客対応自動化

カスタマーサポートワークフローで、問い合わせ内容の分析、回答案の生成、上長承認、回答送信を自動化。セッション ID でチケット単位のコンテキストを保持しつつ、重要な回答前に人間の承認を挟むことで、品質と効率の両立を実現。

🔍 データ品質検証パイプライン

ETL パイプラインで取り込んだデータの品質を AI エージェントが並列で検証し、異常を検出した場合はアラートを発行。同一ハーネスをオーバーライドで使い分けることで設定の重複を排除し、並列実行で検証時間を短縮。
