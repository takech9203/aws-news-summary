🔄 バージョンアップグレードの検証とロールバック機能

クローンベースアップグレード (事前検証・カットオーバー・ロールバック) | リリース日: 2026 年 11 月 10 日

📌 概要

Amazon OpenSearch Service が、バージョンアップグレードを本番トラフィックに影響を与えずに検証し、問題があればロールバックできる「クローンベースアップグレード」を発表しました。 既存クラスター (プライマリ) のデータが新バージョンのクローンクラスターにコピーされ、プライマリが本番トラフィックを処理し続けている間に、同一クエリを実行して Amazon CloudWatch メトリクスで結果を比較できます。

検証に満足した時点でカットオーバーを実行し、新バージョンへ切り替えます。カットオーバー前であればいつでもキャンセルでき、カットオーバー後も保持期間内であれば旧バージョンへロールバックできます。操作は AWS Management Console、AWS CLI、OpenSearch Service API から実行できます。

❌ Before: インプレースアップグレードの課題
  • 一時停止・キャンセル・ロールバックができず、完了と同時に新バージョンが本番を引き継ぐ
  • 事前検証にはスナップショット復元でテスト環境を手動構築する必要があった
  • 旧バージョンへ戻すには別ドメインへの復元が必要で、エンドポイント変更とアプリ側の切り替えが発生
  • アップグレード中に書き込みパフォーマンスが低下する可能性があった
✅ After: クローンベースアップグレード
  • 本番トラフィックを処理しながら、新バージョンのクローンを隔離環境で検証
  • プライマリとクローンに同一クエリを実行し、CloudWatch メトリクスで比較してからカットオーバーを判断
  • カットオーバー前のキャンセル、カットオーバー後の保持期間内ロールバックが可能。エンドポイント変更不要
  • アップグレード中もプライマリへの書き込みは影響なし (ブロックはカットオーバー完了までの間のみ)

クローンベースアップグレードでは、プライマリクラスターが本番トラフィックを処理し続ける間にターゲットバージョンのクローンクラスターが作成・同期され、検証後にカットオーバー、問題があればキャンセルまたはロールバックが可能です。

⚙️ 主要機能

1️⃣ クローンクラスターによる事前検証
✓アップグレード開始時に、プライマリのデータがターゲットバージョンのクローンにコピーされ、継続的に同期される
✓クローンは隔離環境 (Blue/Green デプロイにおける Green 環境) として維持され、本番トラフィックに影響しない
✓プライマリとクローンに同一の読み取りクエリを実行し、CloudWatch メトリクスで性能・結果を比較できる
✓検証できるのは読み取りリクエストのみ。オプションで読み取りトラフィックの一部をクローンに振り分け可能
2️⃣ 任意のタイミングでのカットオーバー
✓検証に満足したタイミングで、ユーザーが明示的にカットオーバーを実行する
✓カットオーバー中は書き込みがブロックされ、クローンがデータ同期を完了した後にトラフィックが切り替わる
✓ドメインエンドポイントは変更されないため、アプリケーション側の変更は不要
3️⃣ キャンセルとロールバック
✓カットオーバー前はいつでもキャンセル可能。クローンは削除され、ドメインは元の状態のまま維持される
✓カットオーバー後は、設定した保持期間内であればいつでも旧バージョンのプライマリへロールバック可能
⚠️保持期間はカットオーバー完了時点から開始。保持期間を設定しない場合はカットオーバー直後にプライマリが削除される

🔬 技術仕様

📊 インプレースアップグレードとの比較

項目 インプレースアップグレード クローンベースアップグレード
動作方式 既存クラスターを Blue/Green デプロイでアップグレード クローンを Green 環境として作成・同期し、検証後にカットオーバー
対応バージョン OpenSearch 1.0 以降、Elasticsearch 5.1 以降 OpenSearch 1.1 以降、Elasticsearch 7.10
事前検証 ❌ 不可 (完了と同時に切り替え) ✅ 可能 (本番トラフィック処理中に検証)
キャンセル ❌ 不可 ✅ カットオーバー前はいつでも可能
ロールバック ❌ 不可 (スナップショットから別ドメインに復元が必要) ✅ 保持期間内はいつでも可能
アップグレード中の書き込み 書き込みパフォーマンスが低下する可能性あり 影響なし (カットオーバー完了まで一時的にブロック)

🛠️ 設定方法

✅ 前提条件

  • ドメインが Elasticsearch 7.10 または OpenSearch 1.1 以降で稼働していること (それより古い場合はまずインプレースアップグレードで対応バージョンに到達)
  • アップグレード前に手動スナップショットを取得しておくこと (旧バージョンに戻すための最終的なバックアップ)
  • 対象ドメインが制限事項 (OR1/OR2、UltraWarm、クロスクラスターレプリケーション、カスタムプラグイン、SAML/Cognito 認証など) に該当しないこと
  • マネージド型ディザスタリカバリを使用している場合は、事前にレプリケーション関係を解除しておくこと

ステップ 1: 事前チェックとアップグレードの開始

Bash UpgradeDomain でクローンベースアップグレードを開始 
aws opensearch upgrade-domain \
  --domain-name my-domain \
  --target-version "OpenSearch_2.19" \
  --deployment-strategy-options Strategy=CLONE

サービスは事前チェックとスナップショット取得を行った後、ターゲットバージョンのクローンクラスターを作成し、データのコピーと同期を開始します。この間、プライマリクラスターは読み取り・書き込みを通常どおり処理し続けます。

ステップ 2: クローンクラスターの検証

Bash 進行状況の確認とトラフィック振り分け 
# アップグレードの進行状況を確認
aws opensearch describe-domain-change-progress \
  --domain-name my-domain

# オプション: 読み取りトラフィックの一部をクローンに振り分け
aws opensearch update-clone \
  --domain-name my-domain \
  --search-traffic-percentage 10

クローンの準備完了を確認した後、クローンに対して読み取りクエリを実行して動作を検証します。UpdateClone API で読み取りトラフィックの一部をクローンへ振り分け、CloudWatch メトリクスでプライマリとクローンの性能を比較できます。

ステップ 3: カットオーバーまたはキャンセル

Bash カットオーバー / キャンセルの実行 
# 検証に問題がなければカットオーバー (保持期間を設定してロールバックに備える)
aws opensearch update-clone \
  --domain-name my-domain \
  --action CUTOVER \
  --retention-period-hours 72

# 問題があればカットオーバー前にキャンセル
aws opensearch update-clone \
  --domain-name my-domain \
  --action CANCEL

カットオーバーを実行すると、書き込みが一時的にブロックされ、クローンがデータ同期を完了した後にトラフィックが切り替わります。保持期間を設定しておけば、期間内であればロールバックが可能です。キャンセルした場合はクローンが削除され、ドメインは元の状態のまま維持されます。

⚠️ 注意: 上記の CLI パラメータは説明用の例です。実際のパラメータ名・値は UpgradeDomain などの API リファレンスおよび 開発者ガイドで確認してください。

💡 メリット

💼 ビジネス面

✓アップグレードリスクの最小化: 本番環境に影響を与える前に新バージョンを実データで検証でき、問題発生時もロールバックで迅速に復旧できるため、サービス停止や性能劣化のリスクを大幅に低減
✓アップグレードの先送り解消: ロールバック手段がないことを理由にバージョンアップを延期してきた組織でも、安全にアップグレードを計画・実行できる
✓運用工数の削減: スナップショット復元による検証用ドメインの手動構築や、切り戻し用の復元手順の準備が不要になる

🔧 技術面

✓エンドポイント不変: カットオーバー後もドメインエンドポイントが変わらないため、アプリケーションやデータ取り込みパイプラインの設定変更が不要
✓データ同期の自動化: クローンはプライマリのデータと継続的に同期されるため、検証中も最新データでテストできる
✓メトリクスベースの比較検証: 同一クエリを実行し、CloudWatch メトリクスでレイテンシーやエラー率を定量的に比較してからカットオーバーを判断できる
✓書き込みへの影響を限定: アップグレード実行中の書き込み性能への影響がなく、書き込みがブロックされるのはカットオーバー完了までの短時間のみ

⚠️ デメリット・制約事項

🚫 制限事項

✗Elasticsearch 7.10 または OpenSearch 1.1 以降のドメインのみ対応 (それより古いバージョンはインプレースアップグレードで対応バージョンへの到達が必要)
✗OpenSearch Optimized インスタンス (OR1、OR2) を使用するドメインは非対応
✗UltraWarm インスタンスを使用するドメインは非対応
✗クロスクラスターレプリケーションを使用するドメインは非対応
✗カスタムプラグインまたはサードパーティプラグインパッケージが関連付けられたドメインは非対応
✗OpenSearch Dashboards で SAML 認証または Amazon Cognito 認証を使用するドメインは非対応
✗アップグレード中はドメインの構成変更ができない
✗クローンクラスターで検証できるのは読み取りリクエストのみ

🤔 考慮すべき点

⚠️検証期間中はプライマリとクローンの両方に課金が発生するため、検証期間を計画的に設定する必要がある
⚠️ロールバックに備えてプライマリを保持する場合、保持期間が終了するまで両クラスター分の課金が継続する
⚠️保持期間を設定しない場合、カットオーバー直後にプライマリが削除され、ロールバックできなくなる
⚠️カットオーバー中は書き込みがブロックされるため、書き込みが集中する時間帯を避けて実行することが望ましい
⚠️マネージド型ディザスタリカバリを使用している場合は、レプリケーション関係の解除と再設定の手順が追加で必要

🎯 ユースケース

📊 ユースケース 1: ログ分析基盤のメジャーバージョンアップグレード

シナリオ: OpenSearch 2.19 で稼働するログ分析基盤を OpenSearch 3.x にアップグレードしたいが、ダッシュボードやアラートクエリの互換性に不安があり、問題発生時に即座に切り戻せる手段を確保したい。

実装例:

  1. 手動スナップショットを取得
  2. クローンベースアップグレードで OpenSearch 3.x のクローンクラスターを作成
  3. 主要なダッシュボードクエリ・集計クエリをクローンに対して実行し、CloudWatch メトリクスでレイテンシーとエラー率をプライマリと比較
  4. 問題がなければ保持期間 72 時間を設定してカットオーバー
  5. 本番運用で問題を検知した場合は保持期間内にロールバック
✅ 効果: 本番トラフィックへの影響なしに互換性を検証でき、万一の問題発生時も保持期間内なら即座に旧バージョンへ復旧できる。
⚡ ユースケース 2: 性能回帰の事前検出

シナリオ: 検索レイテンシーの SLA が厳しい EC サイトの検索基盤で、新バージョンへのアップグレードによる性能回帰を本番切り替え前に検出したい。

実装例:

  1. クローンベースアップグレードを開始し、クローンクラスターを作成
  2. UpdateClone API で読み取りトラフィックの一部 (例: 10%) をクローンに振り分け
  3. CloudWatch でプライマリとクローンの検索レイテンシー p50/p90/p99 を比較
  4. ピーク時間帯を含む数日間の検証後、性能が同等以上であればカットオーバー
  5. 性能回帰を検出した場合はキャンセルし、チューニング後に再実行
✅ 効果: 実際の本番クエリパターンの一部を使った現実的な性能検証ができ、性能回帰によるユーザー体験の悪化を未然に防げる。
🔀 ユースケース 3: Elasticsearch 7.10 から OpenSearch への安全な移行

シナリオ: Elasticsearch 7.10 で稼働するドメインを OpenSearch 1.3 へ移行したいが、クライアントライブラリやプラグインの互換性を本番データで確認してから切り替えたい。

実装例:

  1. クローンベースアップグレードで OpenSearch 1.3 のクローンクラスターを作成
  2. アプリケーションのステージング環境からクローンに接続し、クライアントライブラリの互換性と主要 API の動作を検証
  3. 検証完了後、メンテナンスウィンドウ内にカットオーバーを実行
  4. 保持期間を設定し、本番で問題がないことを確認してから保持期間を終了
✅ 効果: Elasticsearch から OpenSearch への移行に伴う互換性リスクを本番データで事前に排除でき、エンドポイント変更なしで移行を完了できる。

💰 料金

クローンベースアップグレード自体に追加機能料金はありませんが、クローンクラスターのインスタンスとストレージに対して、ドメインの他のノードと同様の標準料金が適用されます。

🔍 検証期間中
プライマリクラスターとクローンクラスターの両方に課金
🔄 カットオーバー後の保持期間中
ロールバック用に保持するプライマリクラスターとクローンクラスター (新しい本番クラスター) の両方に課金 (保持期間終了まで)
⚙️ インプレースアップグレード
追加料金なし

なお、検証・保持期間を短くするほど二重課金の期間を抑えられます。詳細は Amazon OpenSearch Service の料金ページを参照してください。

📝 まとめ

Amazon OpenSearch Service のクローンベースアップグレードにより、バージョンアップグレードを本番トラフィックに影響なく検証し、カットオーバー前のキャンセルやカットオーバー後のロールバックが可能になりました。 これまで「戻せない」ことがアップグレードの最大の障壁だった運用チームにとって、大きなリスク低減となるアップデートです。 対応バージョン (Elasticsearch 7.10、OpenSearch 1.1 以降) と制限事項 (OR1/OR2、UltraWarm、カスタムプラグインなどは非対応) を確認のうえ、次回のバージョンアップグレード計画への組み込みを推奨します。
