AWS Security Hub CSPM

🛡️ AI セキュリティベストプラクティス標準

AI リソースのセキュリティ態勢を自動評価する 31 の自動コントロール
2026-06-30
リリース日

📌 概要

AWS は、AWS Security Hub CSPM の新しいセキュリティ標準として AI Security Best Practices standard を発表しました。 デプロイ済みの AI リソースがセキュリティのベストプラクティスに準拠していない状態を検出する、 31 個の自動セキュリティコントロールのセットです。

AWS のセキュリティ専門家によって策定され、Amazon Bedrock、 Amazon Bedrock AgentCore、Amazon SageMaker のワークロードを推奨されるセキュリティ設定に照らして継続的に評価します。手動の評価やカスタムルールの作成は不要です。

Before / After

❌ アップデート前の課題
  • Bedrock や SageMaker のセキュリティ設定を手動でレビューする必要があった
  • 生成 AI 特有の要件に対応するため独自のカスタムチェックルールが必要だった
  • AI リソースの設定逸脱を継続監視する標準化された仕組みがなかった
➡
✅ アップデート後の改善
  • 31 個の事前定義コントロールで AI リソース評価を自動化
  • カスタムルール不要で 3 サービスの準拠状況を継続評価
  • 専門家定義の標準に基づき設定逸脱を検出結果として一元把握

⚙️ 主要機能

🔢 31 の自動セキュリティコントロール
  • AWS のセキュリティ専門家が策定した事前定義コントロールを提供
  • デプロイ済みの AI リソースがベストプラクティスに準拠していない場合を自動検出
  • 手動評価やカスタムルールの作成が不要
🎯 対象サービスの広範なカバレッジ
  • Amazon Bedrock: ワークロード全般を評価
  • Bedrock AgentCore: ランタイム、ゲートウェイ、メモリストア、カスタムブラウザを評価
  • Amazon SageMaker: ノートブックインスタンス、エンドポイント、モデル、モニタリングジョブ、フィーチャーグループを評価
🔒 重要なセキュリティドメインの網羅
🌐 ネットワーク分離 🔐 保存時・転送時の暗号化 🏠 VPC 配置 🔑 KMS キーの使用 📦 プライベートコンテナレジストリ ✋ 認可コントロール
🚨 検出結果の生成とカテゴリ分類
  • 各コントロールにセキュリティカテゴリが割り当てられる
  • リソースがベストプラクティスから逸脱すると検出結果 (findings) を生成
  • Security Hub の一元的なダッシュボードで設定逸脱を把握可能

🔧 設定方法

前提条件

✓対象リージョンで AWS Security Hub CSPM が有効化されていること
✓Amazon Bedrock、Bedrock AgentCore、または Amazon SageMaker のリソースをデプロイしていること
✓Security Hub の標準を有効化するための適切な IAM 権限を保有していること

手順

1
Security Hub CSPM の有効化

対象リージョンで Security Hub CSPM を有効化します。すでに有効化済みの場合は不要です。

BashSecurity Hub の有効化
aws securityhub enable-security-hub
2
AI Security Best Practices standard の有効化

標準を有効化すると、対象の AI リソースに対する 31 のコントロールによる自動評価が開始されます。<region> には対象リージョンのコードを指定します。

Bash標準の有効化
aws securityhub batch-enable-standards \
  --standards-subscription-requests \
  StandardsArn="arn:aws:securityhub:<region>::standards/ai-security-best-practices/v/1.0.0"
3
検出結果の確認

Security Hub のコンソールまたは API で生成された検出結果を確認します。ベストプラクティスから逸脱したリソースについて、セキュリティカテゴリごとに整理された検出結果が表示されるため、内容に応じて該当リソースの設定を修正します。

✨ メリット

💼 ビジネス面

✓AI ワークロードのガバナンス強化: セキュリティリスクを標準化された方法で継続管理
✓コンプライアンス対応の効率化: 専門家定義の基準に準拠し監査対応が容易に
✓運用コストの削減: カスタムルールの開発・保守が不要で工数を削減

🔬 技術面

✓自動化された継続的評価: 手動評価を排除しリソース変更を継続監視
✓広範なリソースカバレッジ: AgentCore からメモリストア、フィーチャーグループまで網羅
✓Security Hub への統合: 既存のワークフローや検出結果集約をそのまま活用

⚠️ デメリット・制約事項

制限事項

●評価対象は Amazon Bedrock、Amazon Bedrock AgentCore、Amazon SageMaker のリソースに限定されます
●標準のバージョンは v1.0.0 であり、コントロールの内容は将来のバージョンで更新される可能性があります
●Security Hub CSPM が有効化されているリージョンでのみ利用可能です

考慮すべき点

●30 日間の無料トライアル終了後は、Security Hub CSPM の通常のセキュリティチェック料金が適用されます
●検出結果は逸脱を示すものであり、組織の要件に応じてコントロールの抑制 (suppress) や例外管理を検討する必要があります

🎬 ユースケース

🧠 1. 生成 AI アプリケーションのセキュリティ態勢管理

シナリオ: Amazon Bedrock を利用した生成 AI アプリを本番運用しており、暗号化や VPC 配置などの設定がベストプラクティスに準拠しているか継続確認したい。

実装例: 標準を有効化し、Bedrock リソースの保存時暗号化・KMS キー使用・ネットワーク分離の設定を自動評価。

💡 設定逸脱が発生した時点で検出結果が生成され、迅速な是正が可能になります。
🤖 2. AI エージェント基盤のガバナンス

シナリオ: Bedrock AgentCore を用いた AI エージェント基盤を構築しており、ランタイム、ゲートウェイ、メモリストア、カスタムブラウザの設定を一元監査したい。

実装例: AgentCore の各コンポーネントに対する認可コントロールとプライベートコンテナレジストリ要件のコントロールを評価。

💡 エージェント基盤の各コンポーネントを専門家定義の基準で継続的に検証できます。
📊 3. 機械学習パイプラインのコンプライアンス確認

シナリオ: SageMaker でモデル開発から推論エンドポイントまで運用しており、社内のセキュリティ要件を満たしているか定期確認したい。

実装例: ノートブックインスタンス・エンドポイント・モデル・モニタリングジョブ・フィーチャーグループに対する VPC 配置と暗号化のコントロールを評価。

💡 パイプライン全体のセキュリティ設定を自動監査し、コンプライアンス監査の工数を削減できます。

💰 料金・利用可能リージョン

💵 Security Hub CSPM のセキュリティチェック料金体系に従う (評価対象のチェック数に基づく従量課金)

🆓 AWS 無料利用枠を通じて 30 日間無料で試用可能

🌍 Security Hub CSPM が利用可能なすべての AWS リージョン (AWS GovCloud (US) および中国リージョンを含む)

🎯 まとめ

AI Security Best Practices standard は、生成 AI および機械学習ワークロードのセキュリティ態勢管理を 自動化する重要なアップデートです。Bedrock、Bedrock AgentCore、SageMaker を本番運用している組織は、 本標準を有効化することで、カスタムルールを作成することなく専門家定義のベストプラクティスに基づいた継続的な評価を開始できます。

まずは 30 日間の無料トライアルで対象リソースの設定逸脱状況を可視化することを推奨します。
