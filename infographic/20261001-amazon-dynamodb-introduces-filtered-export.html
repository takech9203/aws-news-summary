Amazon DynamoDB

🗄️ Amazon S3 へのフィルタ付きエクスポート

キー条件式・フィルタ式・射影式で、必要な項目と属性だけを S3 へ直接出力
📅 2026 年 10 月 1 日

📝 概要

Amazon DynamoDB が、Amazon S3 へのテーブルデータエクスポートでフィルタリング機能をサポートしました。 Query / Scan と同じ構文のキー条件式・フィルタ式・射影式を使い、 エクスポート対象の項目と属性を絞り込めます。エクスポートはポイントインタイムリカバリ (PITR) のバックアップデータから読み取るため、 テーブルのキャパシティを消費せず、本番トラフィックに影響しません。

特定テナントのデータ復旧、機密属性を除外したデータ共有、コンプライアンス要件に沿った分析など、 テーブルの一部データだけが必要なユースケースに適しており、マルチテナント構成の大規模テーブルを運用する SaaS 事業者に特に有用です。

❌ Before: アップデート前の課題

  • エクスポートはテーブル全体または期間内の全変更分のみで、特定の項目・属性だけを取り出せなかった
  • 一部データのみ必要でも、全体エクスポート後に Athena や Glue で後処理が必要となり、追加コストと手間が発生
  • 機密属性を含むテーブルの外部共有では、エクスポート後に別途マスキングや属性除去が必要だった

✅ After: アップデート後の改善

  • キー条件式・フィルタ式・射影式の組み合わせで、必要な項目と属性のみを直接 S3 にエクスポート
  • キー条件式でパーティションキーを指定すると、一致データのみ読み取られ、処理データ量と課金額を削減
  • 射影式で機密属性を除外した状態でエクスポートでき、データ共有時の後処理が不要
  • フルエクスポートと増分エクスポートの両方でフィルタリングを利用可能

PITR データからの読み取り時にキー条件式でデータ量を削減し、その後フィルタ式と射影式で項目・属性を絞り込んで S3 に出力します。 出力データは Athena での分析や DynamoDB Import from S3 による別テーブルへの取り込みに利用できます。

⚡ 主要機能

🔑 キー条件式 (KeyConditionExpression)

プライマリキーに基づいて項目を選択。Query 操作と同じ構文で、単一のパーティションキー値を等価比較で指定し、オプションでソートキー条件を追加できます。 一致するパーティションのみが読み取られるため、読み取りデータ量と課金額を削減できます。非キー属性の参照や複数パーティションキー値の指定は不可。

🔍 フィルタ式 (FilterExpression)

キー属性・非キー属性の両方に条件を適用可能。Scan 操作と同じ構文で、等価・不等価・OR に加え、 contains、IN、begins_with、BETWEEN、attribute_exists、size をサポート。 データの読み取り後に適用されるため、処理データ量は削減されません。キー条件式で使用したキー属性の再参照は不可。

✂️ 射影式 (ProjectionExpression)

エクスポート出力に含める属性を指定。他の DynamoDB 操作の射影式と同じ構文で、メールアドレスや電話番号などの機密属性を除外したエクスポートが可能です。

🔄 フル / 増分エクスポートの両対応

フィルタリングはフルエクスポートと増分エクスポートの両方で動作します。増分エクスポートでは変更された各項目の最新イメージに対してフィルタを評価し、 削除された項目は新イメージが存在しないため旧イメージに対して評価します。

📏 式の制限

項目制限
式のサイズ最大 4 KB
属性名最大 250 バイト
属性値最大 2 MB
式に含められる演算子数最大 300 個
キー条件式単一のパーティションキー値のみ (等価比較)、ソートキー条件はオプション
エクスポート形式DynamoDB JSON または Amazon Ion

🛠️ 設定方法

✅ 前提条件

  • エクスポート元の DynamoDB テーブルでPITR が有効になっていること
  • エクスポート先の S3 バケットが存在し、適切な書き込み権限があること (クロスアカウント・クロスリージョンの宛先もサポート)
  • dynamodb:ExportTableToPointInTime および S3 への書き込みに必要な IAM 権限があること
1

PITR の有効化を確認

Bash 継続バックアップ設定の確認 
aws dynamodb describe-continuous-backups \
  --table-name MyTable

PointInTimeRecoveryStatus が ENABLED であることを確認。無効の場合は update-continuous-backups で有効化します。

2

フィルタ付きエクスポートの実行

Bash 特定テナントのみをエクスポート 
aws dynamodb export-table-to-point-in-time \
  --table-arn arn:aws:dynamodb:ap-northeast-1:123456789012:table/MyTable \
  --s3-bucket my-export-bucket \
  --s3-prefix exports/tenant-4213 \
  --export-format DYNAMODB_JSON \
  --export-type FULL_EXPORT \
  --filter-specification '{
    "KeyConditionExpression": "#tid = :tid",
    "ExpressionAttributeNames": {"#tid": "TenantId"},
    "ExpressionAttributeValues": {":tid": {"S": "tenant-4213"}}
  }'

パーティションキー TenantId が tenant-4213 に一致する項目のみをエクスポート。キー条件式により一致するパーティションのみが読み取られます。

3

エクスポートステータスの確認

Bash 進行状況の確認 
aws dynamodb describe-export \
  --export-arn arn:aws:dynamodb:ap-northeast-1:123456789012:table/MyTable/export/01234567890123-abcdefgh

ExportStatus が COMPLETED で完了。レスポンスには指定した FilterSpecification も含まれ、エクスポート条件を後から確認できます。

💡 メリット

💼 ビジネス面

✓コスト削減: キー条件式の使用時は一致したデータ量のみ課金。フィルタリングによる追加料金なし
✓データ共有の安全性向上: 射影式で機密属性を除外でき、外部提供時のリスクと後処理コストを低減
✓障害復旧の迅速化: 影響を受けた特定テナント・キー範囲のみを抽出でき、復旧時間を短縮

⚙️ 技術面

✓本番環境への無影響: PITR データから読み取るため、テーブルのキャパシティを消費しない
✓既存スキルの活用: Query / Scan と同じ式構文で、新しい構文の学習が不要
✓パイプラインの簡素化: Athena / Glue による後処理工程を削減

⚠️ デメリット・制約事項

🚧 制限事項

✗エクスポート元テーブルで PITR の有効化が必須 (エクスポート可能な期間は最大 35 日間)
✗キー条件式は単一のパーティションキー値の等価比較のみ。複数値や不等価条件はフィルタ式で指定が必要
✗フィルタ式は読み取り後に適用されるため、非キー属性のフィルタでは課金対象データ量は削減されない
✗セカンダリインデックスに対するエクスポートはサポートされない
✗式のサイズは最大 4 KB、演算子は最大 300 個までの制限
✗AWS GovCloud (US) リージョンでは利用不可

🤔 考慮すべき点

⚠️エクスポートはパーティション間で結果整合性となり、トランザクションを考慮しない
⚠️射影式は属性値の中身を検査しない。フリーテキスト属性内の個人情報は属性ごと除外しない限り出力される
⚠️エクスポートごとに 10 MB の最低課金データ量がある
⚠️エクスポート出力の S3 ライフサイクル管理はユーザー側で実施。エクスポートのメタデータは 90 日で期限切れ

🎯 ユースケース

1️⃣ マルチテナントテーブルにおける特定テナントの復旧

不具合のあるデプロイにより、4 TB のマルチテナントテーブルのうち 1 テナントの約 48,000 項目が破損。該当テナントのデータのみを障害発生前の状態に復旧したいケース。

Bash 障害期間の増分エクスポート + テナントフィルタ 
aws dynamodb export-table-to-point-in-time \
  --table-arn arn:aws:dynamodb:ap-northeast-1:123456789012:table/MultiTenantTable \
  --export-type INCREMENTAL_EXPORT \
  --incremental-export-specification '{
    "ExportFromTime": "2026-09-30T00:00:00Z",
    "ExportToTime": "2026-09-30T06:00:00Z",
    "ExportViewType": "NEW_AND_OLD_IMAGES"
  }' \
  --s3-bucket my-recovery-bucket \
  --export-format DYNAMODB_JSON \
  --filter-specification '{
    "KeyConditionExpression": "#tid = :tid",
    "ExpressionAttributeNames": {"#tid": "TenantId"},
    "ExpressionAttributeValues": {":tid": {"S": "tenant-4213"}}
  }'

効果NEW_AND_OLD_IMAGES で影響項目と障害前イメージの両方を抽出。Athena で破損レコードを特定し、条件付き PutItem で旧イメージを書き戻すことで、テーブル全体を復元せずに特定テナントのみを復旧できます。

2️⃣ 機密属性を除外したパートナーへのデータ共有

特定テナントの注文履歴をパートナー企業に提供したいが、顧客のメールアドレスや電話番号などの個人情報は除外する必要があるケース。

JSON 射影式で必要な属性のみを指定 
{
  "KeyConditionExpression": "#tid = :tid",
  "ProjectionExpression": "TenantId, OrderId, OrderDate, OrderAmount, OrderStatus",
  "ExpressionAttributeNames": {"#tid": "TenantId"},
  "ExpressionAttributeValues": {":tid": {"S": "tenant-100"}}
}

効果CustomerEmail や CustomerPhone などの機密属性を含まないエクスポートを直接生成。エクスポート後のマスキング処理が不要になり、情報漏えいリスクを低減できます。

3️⃣ テナントの別リージョンへの移行

特定テナントのデータレジデンシー要件に対応するため、該当テナントのデータのみを別リージョンの新しいテーブルに移行したいケース。

Bash クロスリージョン S3 へのフィルタ付きエクスポート 
# 1. 移行先リージョンの S3 バケットへフィルタ付きフルエクスポート
aws dynamodb export-table-to-point-in-time \
  --table-arn arn:aws:dynamodb:ap-northeast-1:123456789012:table/MultiTenantTable \
  --export-type FULL_EXPORT \
  --s3-bucket my-eu-bucket \
  --export-format DYNAMODB_JSON \
  --filter-specification '{
    "KeyConditionExpression": "#tid = :tid",
    "ExpressionAttributeNames": {"#tid": "TenantId"},
    "ExpressionAttributeValues": {":tid": {"S": "tenant-eu-55"}}
  }'

# 2. 移行先リージョンで DynamoDB Import from S3 を実行して新テーブルを作成

効果クロスリージョンの S3 を宛先にしたフィルタ付きエクスポートと DynamoDB Import from S3 の組み合わせで、特定テナントのみを別リージョンへ移行。中間処理用の ETL ジョブが不要になります。

💰 料金

既存のフルエクスポート / 増分エクスポートと同じ GB 単位の料金体系で、フィルタリングに対する追加料金はありません。

追加料金 0 円
フィルタリング機能自体は無料。既存のエクスポート料金のみ
一致分のみ課金
キー条件式の使用時は一致したデータ量に基づいて課金 (最低 10 MB / エクスポート)
削減なし
フィルタ式のみの場合は読み取り後の適用のため、課金対象データ量は変わらない

その他、S3 のストレージ / リクエスト料金、Athena のスキャン料金、PITR の継続バックアップ料金が別途発生します。 詳細は DynamoDB 料金ページ を参照してください。

🌏 利用可能リージョン

AWS GovCloud (US) リージョンを除くすべての AWS リージョンで利用可能です (東京・大阪リージョンを含む)。

🔗 関連サービス・機能

🪣 Amazon S3

エクスポートの出力先。クロスアカウント・クロスリージョンのバケットも指定可能。

🕐 DynamoDB ポイントインタイムリカバリ (PITR)

エクスポートのデータソース。フィルタ付きエクスポートの利用には PITR の有効化が必須。

📊 Amazon Athena

エクスポートされた DynamoDB JSON / Ion データを S3 上で直接クエリして分析可能。

📥 DynamoDB Import from S3

エクスポートしたデータから新しいテーブルを作成でき、テナント移行などに活用可能。

📌 まとめ

DynamoDB のフィルタ付きエクスポートにより、テーブル全体をエクスポートせずに必要な項目と属性のみを S3 に出力できるようになり、 特定テナントの復旧、安全なデータ共有、コンプライアンス対応の分析が大幅に簡素化されました。 特にキー条件式を使用した場合はエクスポートコストの削減効果も大きいため、マルチテナントテーブルを運用しているユーザーは、 既存のエクスポートパイプラインへのフィルタ適用を検討することを推奨します。 利用には PITR の有効化が前提となるため、対象テーブルの PITR 設定を事前に確認してください。
