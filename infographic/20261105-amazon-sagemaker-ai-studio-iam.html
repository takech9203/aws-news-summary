Amazon SageMaker AI

🧪 SageMaker AI Studio が IAM Identity Center の
マルチリージョンレプリケーションに対応

📅 リリース日: 2026 年 11 月 5 日 | 機能: IAM Identity Center マルチリージョンレプリケーションのサポート

📋 概要

Amazon SageMaker AI Studio が、AWS IAM Identity Center (IdC) のマルチリージョンレプリケーションに対応しました。プライマリ IdC インスタンスを任意のリージョンにレプリケートし、そのレプリケート先リージョンで Studio ドメインを運用できます。

ワークフォース ID 管理を一元化したまま、データレジデンシー要件やコンプライアンス要件に応じたリージョンへ Studio ドメインを展開可能に。グローバル組織や規制業種のお客様が、SSO 機能を損なうことなく柔軟にリージョンを選択できる重要なアップデートです。

❌ Before: アップデート前の課題
  • IdC 認証の Studio ドメインは、プライマリ IdC インスタンスと同じリージョンに作成する必要があった
  • データレジデンシー要件への対応と ID 管理の一元化の両立が困難だった
  • グローバル組織では、ユーザー所在地やデータ保管場所に合わせた展開が制限されていた
✅ After: アップデート後の改善
  • プライマリ IdC を維持したまま追加リージョンへレプリケートし、そのリージョンで Studio を運用可能に
  • ワークフォースの所在地やデータレジデンシー要件に合わせた展開が可能に
  • SSO 機能を維持しながら、データ主権・コンプライアンス要件を満たす構成を実現

プライマリリージョンの IAM Identity Center インスタンスがワークフォース ID、許可セット、割り当てなどを追加リージョンへ自動レプリケートし、追加リージョンの SageMaker AI Studio ドメインがレプリカを利用して SSO 認証を行う構成です。

⭐ 主要機能

1️⃣ IdC プライマリインスタンスと異なるリージョンでの Studio ドメイン運用
  • プライマリ IdC のレプリケート先リージョンに Studio ドメインを作成可能
  • 「同一リージョン」制約が解消され、リージョン選択の自由度が向上
  • 既存の一元的なワークフォース ID 管理をそのまま活用可能
2️⃣ IAM Identity Center のマルチリージョンレプリケーション
  • ワークフォース ID、許可セット、割り当て、セッションなどを自動レプリケート
  • インスタンス作成時または作成後にレプリケーションを有効化可能
  • 追加リージョンでは ID 情報をローカル参照するため、パフォーマンスと信頼性が向上
3️⃣ コンプライアンスとデータレジデンシーへの対応
  • データ主権要件のあるリージョンに Studio を配置しつつ、ID 管理は既存リージョンに集約
  • SSO 機能を維持したまま、規制要件を満たすリージョン構成を実現

🔧 技術仕様

IAM Identity Center マルチリージョンレプリケーションの前提条件

項目詳細
インスタンスタイプ組織インスタンスのみ対応。アカウントインスタンスは非対応
ID ソース外部 IdP (Okta、Microsoft Entra ID など) または Identity Center ディレクトリ。Active Directory は非対応
対応リージョンマルチリージョン対応は一部リージョンのみ。プライマリと追加リージョン双方の対応状況の確認が必要
暗号化キーマルチリージョンのカスタマーマネージド KMS キー (CMK) が必須。IdC と同一アカウント内に配置
アプリケーション互換性利用中の AWS マネージドアプリケーションが CMK 構成とレプリカリージョンでのデプロイに対応している必要がある
外部 IdP の要件複数のアサーションコンシューマーサービス (ACS) URL をサポートする IdP が推奨 (Okta、Microsoft Entra ID、PingFederate など)

レプリケートされる情報

✓ワークフォース ID (ユーザー・グループ)
✓許可セット
✓ユーザーおよびグループの割り当て
✓セッションおよびその他のメタデータ

⚙️ 設定方法

前提条件

✓IAM Identity Center の組織インスタンスが有効化されていること
✓ID ソースが外部 IdP または Identity Center ディレクトリであること (Active Directory は不可)
✓マルチリージョンのカスタマーマネージド KMS キーで IdC の保管時暗号化が構成されていること
✓プライマリおよび追加リージョンがマルチリージョン対応リージョンであること
1
マルチリージョン CMK の準備
Bash マルチリージョン KMS キーの作成とレプリケート 
# マルチリージョン対応のカスタマーマネージドキーを作成
aws kms create-key \
  --multi-region \
  --description "IdC multi-region key" \
  --region us-east-1

# 追加リージョンへレプリカキーを作成
aws kms replicate-key \
  --key-id <プライマリキーの KeyId> \
  --replica-region ap-northeast-1 \
  --region us-east-1

マルチリージョン対応の KMS キーをプライマリリージョンに作成し、Studio ドメインを配置する追加リージョンへレプリカキーを作成します。IdC のマルチリージョンレプリケーションには、このマルチリージョン CMK の構成が必須です。

2
IAM Identity Center のレプリケーション設定
  • IAM Identity Center コンソールを開き、インスタンス設定を表示
  • 保管時の暗号化キーをステップ 1 で作成したマルチリージョン CMK に変更
  • 追加リージョンとして Studio ドメインを配置するリージョンを選択し、レプリケーションを有効化

レプリケーションが完了すると、ワークフォース ID や割り当て情報が追加リージョンから参照可能になります。

3
追加リージョンでの SageMaker AI Studio ドメイン作成
Bash IdC 認証モードで SageMaker ドメインを作成 (追加リージョン) 
aws sagemaker create-domain \
  --domain-name my-studio-domain \
  --auth-mode SSO \
  --default-user-settings '{"ExecutionRole": "arn:aws:iam::123456789012:role/SageMakerExecutionRole"}' \
  --vpc-id vpc-xxxxxxxx \
  --subnet-ids subnet-xxxxxxxx \
  --region ap-northeast-1

認証モードに SSO (IAM Identity Center) を指定して、レプリケート先リージョンに Studio ドメインを作成します。作成後、IdC のユーザーまたはグループをドメインに割り当てることで、ユーザーは SSO で Studio にアクセスできます。

💡 メリット

💼 ビジネス面
✓コンプライアンス対応の強化: データ主権要件のあるリージョンで Studio を運用しつつ、ID 管理を一元化
✓グローバル展開の柔軟性: ワークフォースの所在地に合わせた Studio ドメイン展開が容易に
✓ガバナンスの一元化: 複数リージョンの ML 環境でも、アクセス権限管理を単一の IdC に集約
🛠️ 技術面
✓SSO 体験の維持: リージョン構成を変更しても、これまでどおり SSO でサインイン可能
✓ローカル参照による性能向上: レプリケートされた ID 情報をローカル参照し、認証遅延や依存リスクを低減
✓耐障害性の向上: プライマリリージョン障害時にもレプリカ経由でのアクセス継続が期待できる

⚠️ デメリット・制約事項

🚫 制限事項
✗組織インスタンスのみ対応。アカウントインスタンスでは利用不可
✗ID ソースに Active Directory を使用している場合は対象外
✗マルチリージョンの CMK 構成が必須 (AWS 所有キーのままでは利用不可)
✗対応は一部リージョンに限定され、レプリケート可能なリージョン数にはクォータがある
🤔 考慮すべき点
⚠複数の ACS URL をサポートする IdP (Okta、Entra ID、PingFederate など) でないと機能を最大限活用できない
⚠利用中の他の AWS マネージドアプリケーションの CMK 対応状況を事前確認する必要がある
⚠CMK レプリカキーはリージョンごとに課金されるため、KMS のコストが増加する
⚠レプリケーション先の選定では、コンプライアンス、ユーザーへの近接性、地理的分散を考慮する

🎯 ユースケース

🏦 ユースケース 1: データレジデンシー要件下での ML 開発環境の提供

シナリオ: 金融機関が、学習データを国内リージョン (東京) に保持する規制要件を満たしつつ、米国リージョンで運用中の IdC による一元的な ID 管理を継続したい。

実装例:

  1. us-east-1 のプライマリ IdC インスタンスを ap-northeast-1 へレプリケート
  2. ap-northeast-1 に SSO 認証モードの SageMaker AI Studio ドメインを作成
  3. 既存の IdC グループ (data-scientists) をドメインに割り当て

効果: 学習データと ML 環境を国内に保持しながら、ID 管理・アクセス統制は既存の IdC 運用をそのまま利用でき、規制対応と運用効率を両立できる。

🌏 ユースケース 2: グローバル組織での地域別 Studio 展開

シナリオ: 欧米アジアに開発拠点を持つ企業が、各拠点のデータサイエンティストに低レイテンシーな Studio 環境を提供したい。

実装例:

  1. プライマリ IdC インスタンス (eu-west-1) を us-west-2 と ap-northeast-1 へレプリケート
  2. 各リージョンに Studio ドメインを作成し、拠点ごとの IdC グループを割り当て
  3. 許可セットとグループ管理はプライマリリージョンで一元運用

効果: 各拠点のユーザーは近接リージョンの Studio を SSO で利用でき、管理者は単一の IdC インスタンスでグローバルのアクセス権限を統制できる。

🛡️ ユースケース 3: ID 基盤の耐障害性を考慮した ML 基盤設計

シナリオ: ミッションクリティカルな ML ワークロードを運用する企業が、ID 基盤のリージョン障害時にも Studio へのアクセス継続性を確保したい。

実装例:

  1. プライマリ IdC インスタンスのリージョンと地理的に離れたリージョンへレプリケート
  2. レプリケート先リージョンに Studio ドメインを配置
  3. レプリケートされた ID 情報をローカル参照する構成で認証依存を低減

効果: プライマリリージョンの IdC に障害が発生しても、レプリカリージョンの ID 情報により Studio へのアクセス継続が期待でき、ML 運用の可用性が向上する。

💰 料金

IAM Identity Center のマルチリージョンレプリケーション機能自体、および SageMaker AI Studio の IdC 連携に追加料金は発生しません。ただし、以下のコストに注意が必要です。

🔑 AWS KMS

マルチリージョンのカスタマーマネージドキーが必須となるため、プライマリキーおよび各リージョンのレプリカキーに対して KMS のキー保管料金と API リクエスト料金が発生します。

🧪 SageMaker AI Studio

Studio で起動するノートブックやジョブなどのコンピューティングリソースには、通常どおり SageMaker AI の料金が適用されます。

🌍 利用可能リージョン

SageMaker AI Studio が利用可能なすべての標準 AWS リージョンで利用できます。主なリージョンは以下のとおりです。

  • 🇺🇸 米国東部 (バージニア北部、オハイオ)、米国西部 (オレゴン)
  • 🌏 アジアパシフィック (東京、ソウル、シンガポール、シドニー、ムンバイ)
  • 🇪🇺 欧州 (アイルランド、フランクフルト、ロンドン、パリ、ストックホルム)
  • 🌎 カナダ (中部)、南米 (サンパウロ)
ℹ️ IAM Identity Center のマルチリージョンレプリケーション自体は一部リージョンのみの対応となるため、最新の対応状況は AWS Capabilities by Region で確認してください。

🔗 関連サービス・機能

🔐 AWS IAM Identity Center

本アップデートの基盤となるワークフォース ID 管理サービス。マルチリージョンレプリケーションにより ID 情報を複数リージョンへ自動複製する。

🔑 AWS KMS

IdC のマルチリージョン構成に必須のマルチリージョンカスタマーマネージドキーを提供する。

🧪 Amazon SageMaker AI

Studio ドメインのほか、トレーニングや推論など ML ライフサイクル全体を支えるマネージドサービス。

🏢 AWS Organizations

IdC の組織インスタンスの前提となるマルチアカウント管理サービス。

📝 まとめ

Amazon SageMaker AI Studio が IAM Identity Center のマルチリージョンレプリケーションに対応したことで、ID 管理の一元化とデータレジデンシー要件への対応を両立したリージョン設計が可能になりました。グローバル展開や規制対応で Studio のリージョン配置に制約を感じていた場合は、IdC の組織インスタンスとマルチリージョン CMK の要件を確認のうえ、レプリケーション構成の導入を検討することを推奨します。
