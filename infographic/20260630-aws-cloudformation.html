AWS CloudFormation / AWS CDK

☁️ 全スタック操作でのデプロイ前検証

Create Stack / Update Stack でも自動でエラーを数秒で検出
📅 2026-06-30 リリース

📌 概要

AWS CloudFormation が、デプロイ前検証 (pre-deployment validation) を Create Stack および Update Stack 操作で自動実行するようになりました。 リソースのプロビジョニングが始まる前に、よくあるデプロイエラーを数秒で検出できます。

従来、デプロイ前検証は変更セット (change set) 作成時にのみ利用可能でした。今回のアップデートで同じ検証が Create Stack / Update Stack でも動作し、手動デプロイ・CI/CD パイプライン・AI エージェントによる自動プロビジョニングの フィードバックループを大幅に短縮します。検証エラーが検出されると、操作はプロビジョニング開始前に停止し、 論理リソース ID とプロパティパスを含む詳細なフィードバックが返されます。

❌ アップデート前の課題
  • デプロイ前検証は変更セット作成時のみ。Create / Update Stack を直接実行すると恩恵を受けられなかった
  • 構文エラーやリソース名競合を見つけるため、実際にプロビジョニングを試みてロールバックを待つ必要があった
  • 試行錯誤や AI エージェントの自動化で、エラー検出までが遅くフィードバックループが長かった
✅ アップデート後の改善
  • Create / Update Stack でも検証が自動実行され、数秒でエラーのフィードバックを得られる
  • プロビジョニング前に停止するため、無駄なロールバックが不要に
  • 変更セット作成時にサービスクォータ・Config Recorder 競合・ECR 削除準備の 3 つの警告チェックを追加
  • CDK で構造化された結果を取得でき、AI エージェントが自己修正できる

🚀 主要機能

1️⃣ Create / Update Stack へのデプロイ前検証の拡張
  • プロパティ構文検証とリソース名の競合検出が、Create Stack / Update Stack / Create Change Set のすべての操作で実行
  • FAIL モードでは、エラー検出時にプロビジョニング前に操作が停止し、スタックステータスに検証失敗が反映される
  • 各エラーには論理リソース ID とテンプレート内のプロパティパスが含まれ、問題の特定を支援
2️⃣ 3 つの新しい警告 (WARN) モード検証 (変更セット作成時)
  • サービスクォータ検証: 新規リソース作成がアカウントのサービスクォータを超過する可能性がある場合に警告
  • Config Recorder 競合検出: 記録が無効なアカウントに Config ルールを追加、または Recorder が既に有効なアカウントで Recorder を定義する場合に警告
  • ECR リポジトリ削除準備検証: 削除対象の ECR リポジトリにイメージが残っている場合に警告
3️⃣ AWS CDK での統合検証レポート
  • cdk deploy と cdk validate の両方が、コンストラクトレベルのトレーシングを含む統合レポートで検証結果を表示
  • AI エージェントや自動化ツールが構造化された応答を解析し、自己修正できる
4️⃣ 検証結果の確認方法
  • DescribeEvents API に操作 ID を指定して取得
  • コンソールでスタックの Events タブから操作 ID を選択し、Operation ビューの Deployment validations タブで確認

🔧 技術仕様: 検証タイプと実行対象操作

検証タイプモード実行対象操作
プロパティ構文検証FAILCreateStack / UpdateStack / CreateChangeSet
リソース名の競合検出FAILCreateStack / UpdateStack / CreateChangeSet
S3 バケットの空チェックWARNCreateChangeSet のみ
サービスクォータWARNCreateChangeSet のみ
Config Recorder 競合WARNCreateChangeSet のみ
ECR リポジトリ削除準備WARNCreateChangeSet のみ
💡 FAIL モードはエラー検出時に操作を停止し、WARN モードは操作を継続しながら警告を提供します。 デプロイ前検証は Create / Update Stack に数秒程度の小さなレイテンシを追加します。

⚙️ 設定方法

デプロイ前検証はデフォルトで有効のため、追加設定は不要です。通常どおりスタックを操作するだけで検証が走ります。

ステップ 1: 通常どおりスタックを作成・更新

Bash
aws cloudformation create-stack \
  --stack-name MyStack \
  --template-body file://template.yaml

ステップ 3: 必要に応じて検証をスキップ

Bash--disable-validation フラグ
aws cloudformation create-stack \
  --stack-name MyStack \
  --template-body file://template.yaml \
  --disable-validation

既に cfn-lint / cdk validate / CI チェックでテンプレートを検証済みの場合、 レイテンシを最小化したい場合、既知の誤検知を回避したい場合に --disable-validation (API では DisableValidation パラメータ) を使用します。

💡 メリット

📈 ビジネス面

✓開発サイクルの短縮: エラーのフィードバックを数秒で得られ、手動の試行錯誤や CI/CD の待ち時間を削減
✓運用コストの削減: プロビジョニング前にエラーを検出し、無駄なリソース作成とロールバックを回避
✓AI 自動化の信頼性向上: 構造化された検証結果で AI エージェントが自己修正し、安全にプロビジョニング

🛠️ 技術面

✓早期のエラー検出: 論理リソース ID とプロパティパスを含む詳細フィードバックで問題箇所を迅速に特定
✓追加設定不要: デフォルトで有効化され、既存ワークフローにそのまま組み込める
✓CDK との統合: コンストラクトレベルのトレーシングを含む統合レポートを利用可能

⚠️ デメリット・制約事項

!3 つの新しい警告チェックと S3 バケット空チェックは、現時点では変更セット作成時のみ実行 (Create / Update Stack では非対応)
!デプロイ前検証はよくある失敗シナリオに焦点を当てており、デプロイの成功を保証するものではない
!S3 バケット検証はオブジェクトの存在のみ確認。バケットポリシーなど他の削除制約は確認しない
!Create / Update Stack に数秒程度の小さなレイテンシが追加される
!一部のリソースタイプ (CustomResource / Macro / AppMesh::Mesh など) は検証対象外
🔎 考慮点: 変更セットを使うと WARN モードを含む 6 種類すべての検証を利用できます。 テンプレートを変更した場合は新しい変更セットを作成して検証し直す必要があります。 なお、中国リージョンでは利用できません。

🎯 ユースケース

1. CI/CD パイプラインでのデプロイ前チェック

シナリオ: CI/CD パイプラインで CloudFormation をデプロイ。従来はプロビジョニング失敗とロールバックを待つ必要があった。

Bash
aws cloudformation create-change-set \
  --stack-name MyStack \
  --change-set-name PreDeployCheck \
  --change-set-type CREATE \
  --template-body file://template.yaml
# 検証結果を describe-events で確認してから execute-change-set

効果: 変更セット作成時に 6 種類の検証 (警告含む) が実行され、パイプラインの失敗を削減。

2. AI エージェントによるインフラプロビジョニング

シナリオ: AI エージェントが CDK / CloudFormation で自動的にインフラをプロビジョニングし、エラーを解析して自己修正する。

Bash
cdk deploy
# または検証のみ実行
cdk validate

効果: コンストラクトレベルのトレーシングを含む構造化レポートで、AI エージェントがテンプレートを自動修正。

3. 時間制約のあるデプロイでの検証スキップ

シナリオ: 既に cfn-lint や CI チェックで検証済みで、本番デプロイのレイテンシを最小化したい。

Bash
aws cloudformation update-stack \
  --stack-name MyStack \
  --template-body file://template.yaml \
  --disable-validation

効果: --disable-validation で検証をスキップし、検証によるレイテンシを排除。

  • AWS CDK: cdk deploy / cdk validate がコンストラクトレベルのトレーシングと共に結果を表示
  • AWS Service Quotas: リソース作成がアカウントのクォータを超過する可能性を事前チェック
  • AWS Config: Config Recorder 競合検出で、テンプレートと既存 Config 設定の競合を検出
  • Amazon ECR: 削除対象リポジトリにイメージが残っているかをチェック

📝 まとめ

このアップデートにより、CloudFormation のデプロイ前検証が Create Stack / Update Stack 操作にも拡張され、 リソースのプロビジョニング前に数秒でエラーを検出できるようになりました。デフォルトで有効化されており追加設定は不要なため、 手動デプロイ・CI/CD パイプライン・AI エージェントによる自動化のいずれにおいてもフィードバックループの短縮が期待できます。 変更セットを併用すれば 3 つの新しい警告チェックを含む包括的な検証が可能になるため、デプロイの信頼性向上のために活用を検討してください。
