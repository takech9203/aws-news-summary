Amazon Connect Customer

📊 ビジネスアウトカムメトリクス

顧客維持と収益に直結するインタラクションアウトカムの測定機能

リリース日: 2026 年 10 月 26 日
サービス: Amazon Connect Customer
カテゴリ: コンタクトセンター分析

💡 概要

Amazon Connect Customer が、顧客インタラクションのアウトカム (成果) をスコアリングする新しいメトリクスを発表しました。顧客が満足して対応を終えたか、解約 (チャーン) のリスクがあるか、購入に至ったか、セルフサービスで解決できたかを可視化できます。

従来の「どれだけ効率的に処理されたか」に加えて、「インタラクションが実際に成果を生んだか」を把握できるようになります。デフォルト定義が用意されており、ビジネス固有の成功の定義に合わせた調整も可能です。

❌ アップデート前の課題

  • 平均処理時間や応答率などの効率指標では、顧客が満足して終了したかを判断できなかった
  • 解約リスク顧客や購入につながったインタラクションの特定には、別途の調査や外部ツールが必要だった
  • セルフサービスでの解決を含む「成果ベース」の評価を標準メトリクスとして取得できなかった

✅ アップデート後の改善

  • インタラクションごとのアウトカム (満足、解約リスク、購入、セルフサービス解決) をスコアとして確認可能に
  • デフォルト定義で追加設定なしに開始でき、ビジネス独自の成功定義にカスタマイズ可能に
  • 分析ダッシュボードと API の両方で取得でき、既存の分析基盤に組み込み可能に

顧客インタラクションがスコアリングされ、4 種類のアウトカムメトリクスとして分析ダッシュボードと API の両方から利用できる流れ

🚀 主要機能

🧮 インタラクションアウトカムのスコアリング

  • 個々の顧客インタラクションの「成果」をスコアとして測定
  • 満足・解約リスク・購入・セルフサービス解決を可視化
  • 効率指標だけでは見えなかった「インタラクションが機能したかどうか」を把握可能

⚙️ デフォルト定義とカスタマイズ

  • デフォルト定義付きで、追加設定なしに利用開始が可能
  • ビジネスごとの成功の定義に合わせてメトリクス定義を調整可能
  • 業種や KPI 設計に応じた柔軟な運用が可能

📈 ダッシュボードと API の両対応

  • 分析ダッシュボードでアウトカムメトリクスを確認可能
  • API 経由で取得し、外部の BI ツールやデータ基盤に連携可能

📝 設定方法

前提条件

✓Amazon Connect Customer インスタンスが作成済みであること
✓ダッシュボードおよびレポートを閲覧するためのセキュリティプロファイル権限が付与されていること
✓メトリクス定義を調整する場合は、該当する管理権限を持つユーザーで操作すること

手順

1

デフォルト定義でメトリクスを確認する

管理 Web サイトにサインインし、分析ダッシュボードでアウトカムメトリクスを確認。デフォルト定義により追加設定なしで利用を開始できます。

2

ビジネスの成功定義に合わせて調整する

デフォルト定義が自社の「成功」の定義と異なる場合は、メトリクス定義をビジネス要件に合わせて調整します。詳細は管理者ガイドを参照してください。

3

API で外部システムに連携する

アウトカムメトリクスを API で取得し、既存の BI ツールやデータウェアハウスに取り込んで他の業務データと組み合わせた分析に活用します。

⚖️ メリットと制約事項

✅ ビジネス面のメリット

✓成果ベースの運営: 「インタラクションが成果を生んだか」でコンタクトセンターを評価できる
✓解約の予防: 解約リスク顧客を特定し、プロアクティブなリテンション施策につなげられる
✓収益貢献の可視化: 購入につながったインタラクションを把握し、収益貢献部門として位置付けられる

✅ 技術面のメリット

✓即時利用可能: デフォルト定義により複雑な初期設定なしで開始できる
✓柔軟なカスタマイズ: 固有の成功定義に合わせて調整できる
✓API 連携: 既存の分析基盤に統合しやすい

⚠️ 制限事項

✗Amazon Connect Customer が提供されているリージョンでのみ利用可能
✗デフォルト定義のままではスコアリング精度がビジネスの実態と乖離する可能性があり、定義の調整が必要になる場合がある

💭 考慮すべき点

⚠「満足」「解約リスク」などの定義は組織の KPI 設計と整合させる必要があるため、導入前に関係部門と成功の定義を合意しておくことが望ましい
⚠スコアはあくまで指標であり、重要な意思決定には他のデータと組み合わせた検証を推奨
⚠対応チャネルやスコアリングの仕組みの詳細は、管理者ガイドで最新情報を確認すること

🎯 ユースケース

1. 解約リスク顧客への早期フォロー

シナリオ: サブスクリプションサービスで、解約の予兆がある顧客を早期に発見し、リテンションチームにエスカレーションしたい。

  1. 「解約リスク」を分析ダッシュボードでモニタリング
  2. 解約リスクが高いと判定されたインタラクションを API で抽出
  3. リテンションチームの CRM にリストを連携し、フォローアップを実施

💡 効果: 解約予兆の早期検知により、プロアクティブな顧客維持施策が可能になり、チャーンレートの低減が期待できる。

2. セルフサービスの効果測定

シナリオ: チャットボットや IVR などのセルフサービスチャネルへの投資効果を、実際の「解決率」で評価したい。

  1. 「セルフサービス解決」メトリクスをダッシュボードで確認
  2. セルフサービスで解決したインタラクションと、オペレーター対応にエスカレーションされたインタラクションを比較
  3. 解決率の低いシナリオを特定し、ボットのフローや FAQ を改善

💡 効果: セルフサービスの実効性をデータで把握でき、改善の優先順位付けとオペレーターコストの最適化につながる。

3. 収益貢献に基づくコンタクトセンター評価

シナリオ: コンタクトセンターをコストセンターではなく収益貢献部門として評価するため、インタラクションと購入の関係を可視化したい。

  1. 「購入」アウトカムメトリクスを API で取得
  2. BI ツールでキャンペーンやキュー別の購入率を分析
  3. 購入につながりやすい対応パターンを特定し、トレーニングに反映

💡 効果: 収益貢献を定量的に示すことができ、経営層への報告や投資判断の根拠として活用できる。

📌 まとめ

Amazon Connect Customer のアウトカムメトリクスにより、コンタクトセンターを「効率」だけでなく「成果」で評価できるようになりました。顧客満足、解約リスク、購入、セルフサービス解決という 4 つの観点がデフォルト定義付きで提供され、ダッシュボードと API の両方から利用できます。

まずはデフォルト定義でダッシュボードを確認し、自社の成功の定義に合わせてメトリクスを調整することから始めることを推奨します。
