COPY クエリに対するコンカレンシースケーリングのサポート

Concurrency Scaling for COPY - Batch Workloads

2026 年 5 月 7 日

📋 概要

Amazon Redshift のコンカレンシースケーリング機能が拡張され、Parquet および ORC ファイル形式での S3 からの COPY クエリによる大量データ取り込みワークロードをサポート。ピーク時でもデータパイプラインがインジェスト速度とクエリパフォーマンスのどちらかを犠牲にする必要がなくなった。

Before

  • COPY での Parquet/ORC 取り込みはスケーリング対象外
  • メインクラスターのリソースに制約
  • ピーク時にインジェスト遅延が発生
  • 読み取り/書き込みのリソース競合
  • 手動クラスターリサイズが必要

After

  • Parquet/ORC の COPY がスケーリング対象に
  • 自動で追加コンピュート容量をプロビジョニング
  • 複数ファイルの同時ロードが遅延なし
  • 手動リサイズ/スケジューリング不要
  • Serverless/Provisioned 両対応

⚡ 主要機能

🗂️ Parquet/ORC 形式の COPY サポート
  • Amazon S3 からの Parquet/ORC ファイルでの COPY クエリがコンカレンシースケーリング対象に追加
  • 複数ファイルの並列ロードがキューイング遅延なく実行可能
  • バッチワークロードにおける COPY パフォーマンスが大幅に向上
🔄 自動スケーリング
  • Serverless: デマンドに基づいて自動的にスケーリングを有効化/無効化
  • Provisioned: 事前設定された構成に基づいてスケーリングを制御
  • 手動でのクラスターリサイズやワークロードスケジューリングが不要
🚀 ゼロオペレーションオーバーヘッド
  • 既存のコンカレンシースケーリング設定がそのまま適用
  • マイグレーションや設定変更は不要
  • コンカレンシースケーリングを有効にするだけで即座にインジェストワークロードに適用

WLM キュー設定 (Provisioned)

JSON WLM Configuration 
{
  "WLMConfiguration": [
    {
      "queue_name": "etl_queue",
      "concurrency_scaling": "auto",
      "query_group": ["etl", "data_ingestion"],
      "slots": 5
    }
  ]
}

COPY コマンド実行例

SQL Parquet ファイルの COPY 
-- データ取り込みクエリを特定のキューに振り分け
SET query_group TO 'data_ingestion';

-- S3 からの COPY コマンドを実行
COPY my_table
FROM 's3://my-bucket/data/'
IAM_ROLE 'arn:aws:iam::123456789012:role/MyRedshiftRole'
FORMAT AS PARQUET;
SQL Serverless での ORC ファイル COPY 
-- Serverless ではデフォルトでコンカレンシースケーリングが有効
-- 追加設定なしで COPY クエリが自動スケーリングの対象
COPY my_table
FROM 's3://my-bucket/data/files/'
IAM_ROLE 'arn:aws:iam::123456789012:role/MyRedshiftServerlessRole'
FORMAT AS ORC;

💡 ユースケース

1. リアルタイムデータレイク取り込み
IoT デバイスや Web アプリケーションから S3 に Parquet ファイルが出力され、5 分ごとに Redshift へ COPY で取り込むパイプライン。日中のピーク時にはファイル数が 10 倍に増加。
✓ ピーク時でもインジェスト遅延が解消、ダッシュボードのデータ鮮度が 5 分以内に維持
2. 大規模 ETL バッチ処理
毎日深夜に数百 GB の ORC ファイルを Redshift にロードする ETL ジョブ。同時にレポート生成クエリも実行されるため、リソース競合により完了時間が不安定。
✓ レポートクエリとリソース競合せずに ETL ジョブが安定して完了、朝のレポート配信 SLA を確実に遵守
3. 高頻度レポーティング基盤
金融機関で取引データを 1 分間隔で S3 に Parquet 形式で出力し Redshift に取り込み。市場オープン時間帯にデータ量が急増し、多数のアナリストが同時にクエリを実行。
✓ 市場オープン時のスパイクでもインジェストと分析クエリが互いに影響せず、リアルタイムデータにアクセス可能

⚠️ 制限事項・注意点

制限事項
•RA3 ノードタイプのみサポート (DC2 ノードでは非対応)
•シングルノードクラスターでは利用不可
•制限的な IAM ポリシー (aws:sourceVpc, aws:sourceVpce, aws:sourceIp) が設定されている場合、COPY クエリがスケーリングクラスターに送信されない可能性
•インターリーブソートキーを使用するテーブルへの COPY は非対応
•DISTSTYLE ALL のテーブルへの書き込みは非対応
•COPY での ANALYZE オプションはスケーリングクラスターで非対応
•Identity 列を持つテーブルへの書き込みは非対応
考慮すべき点
•スケーリングクラスターでの実行時間に対して追加料金が発生 (1 日あたりの無料クレジットあり)
•制限的なネットワーク/VPC 構成で IAM ポリシーの調整が必要になる場合がある
•明示的トランザクション内で非サポート DDL と COPY を混在させると、スケーリングクラスターで実行されない
