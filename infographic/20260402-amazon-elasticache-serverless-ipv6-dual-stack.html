🌐 ElastiCache Serverless
IPv6 / Dual Stack

IPv6 およびデュアルスタック接続のサポート
📅 2026 年 4 月 2 日
🏷️ Amazon ElastiCache

📝 概要

Amazon ElastiCache Serverless が IPv6 およびデュアルスタック接続をサポート。キャッシュ作成時に 3 つのネットワークタイプから選択可能に。

IPv4 IPv6 Dual Stack

デュアルスタックは IPv4/IPv6 両方を同時受付。段階的な IPv6 移行に最適。IPv6 のみを選択すると IPv4 アドレスが不要になり、枯渇問題やコンプライアンスに対応可能。

🔄 Before / After

❌ Before
  • IPv4 接続のみ
  • IPv6 サブネットに配置不可
  • IPv6 コンプライアンス要件を満たせない
  • IPv4 アドレス枯渇に対処不可
→
✅ After
  • 3 つのネットワークタイプから選択可能
  • IPv6 のみのサブネットに配置可能
  • デュアルスタックで段階的移行
  • 全リージョンで追加料金なし

3 つのネットワークタイプと対応するサブネット構成・クライアント接続パターン

⚡ 主要機能

1. 3 つのネットワークタイプの選択
📋NetworkType パラメータで ipv4 / ipv6 / dual_stack を指定
⚠️キャッシュ作成時のみ設定可能 (後から変更不可)
🔧デフォルト値は ipv4 (既存互換)
2. デュアルスタック接続
🔗IPv4 / IPv6 両方で同時接続を受付
🔄段階的な IPv6 移行に最適
3. IPv6 ネイティブ接続
🌐IPv6 のみのサブネットに配置可能
✅IPv4 アドレス不要 / コンプライアンス準拠

📊 技術仕様: ネットワークタイプ比較

項目 IPv4 IPv6 Dual Stack
NetworkType 値 ipv4 ipv6 dual_stack
プロトコル IPv4 のみ IPv6 のみ IPv4 + IPv6
必要なサブネット IPv4 IPv6 Dual Stack
IPv4 アドレス 必要 不要 必要
IPv6 移行適合性 低 高 高 (段階移行)
API 変更 (2026/04/01): CreateServerlessCache、DeleteServerlessCache、DescribeServerlessCaches、ModifyServerlessCache に NetworkType パラメータを追加

💻 API / 設定例

Python CreateServerlessCache API 
client.create_serverless_cache(
    ServerlessCacheName='my-cache',
    Engine='valkey',
    SubnetIds=['subnet-xxxxxxxxx'],
    SecurityGroupIds=['sg-xxxxxxxxx'],
    NetworkType='dual_stack'
    # 'ipv4' | 'ipv6' | 'dual_stack'
)
Bash AWS CLI - Dual Stack Cache 
aws elasticache create-serverless-cache \
  --serverless-cache-name my-dualstack-cache \
  --engine valkey \
  --subnet-ids subnet-xxx subnet-yyy \
  --security-group-ids sg-xxx \
  --network-type dual_stack

📋 設定手順

1 VPC に IPv6 CIDR ブロックが割り当てられていることを確認
2 使用するサブネットに IPv6 CIDR ブロックがあることを確認
3 --network-type を指定してキャッシュを作成
4 describe-serverless-caches で NetworkType を確認

✨ メリット

💼 ビジネス面
  • 📜 コンプライアンス: OMB M-21-07 等の IPv6 要件を充足
  • 💰 コスト最適化: IPv6 のみで IPv4 課金 ($0.005/IP/時間) を回避
  • 🆓 追加料金なし: ネットワークタイプ選択による追加料金ゼロ
🔧 技術面
  • 🏗️ VPC 設計の柔軟性向上: IPv6 のみのサブネットに配置可能
  • 🔄 段階的移行: デュアルスタックで IPv4 維持しつつ IPv6 導入
  • 🌍 グローバル対応: GovCloud / 中国含む全リージョン
  • 🔌 API 一貫性: NetworkType パラメータ追加のみ

⚠️ 制約事項・考慮点

🔒ネットワークタイプは作成時のみ設定可能 (後から変更不可)
🔄既存 IPv4 キャッシュの変更にはデータ移行が必要
🌐IPv6 / Dual Stack は VPC / サブネットの IPv6 CIDR 対応が必要
🚫IPv6 のみのキャッシュには IPv4 クライアントから接続不可
🔍デュアルスタックは A / AAAA 両レコードを返すため DNS 動作要確認
🛡️セキュリティグループに IPv6 インバウンドルールの追加が必要な場合あり

💡 ユースケース

📜 UC1: IPv6 コンプライアンス充足
連邦政府機関向けアプリで OMB M-21-07 準拠が必要
✅ IPv6 のみで運用し、コンプライアンス要件を満たしつつ IPv4 管理負荷を排除
🔄 UC2: 段階的 IPv6 移行
既存 IPv4 マイクロサービスから順次 IPv6 に移行
✅ Dual Stack で既存 IPv4 に影響なく新規を IPv6 で接続。低リスクな移行を実現
💰 UC3: IPv4 アドレスコスト最適化
大規模 VPC で多数の ElastiCache を運用、IPv4 課金を削減
✅ IPv6 のみで IPv4 アドレス課金を回避。大規模環境では年間で大きなコスト削減

💴 料金

データストレージ $0.125/GB/時間
ECPU $0.0034/100 万 ECPU
IPv6 / Dual Stack 追加料金 無料

※ us-east-1 の例。IPv6 のみの構成で IPv4 課金 ($0.005/IP/時間) を回避可能。
