🛡️ Malware Protection for AWS Backup
S3 継続的バックアップ対応

PITR タイムライン全体のマルウェアスキャンでクリーンな復旧ポイントを特定

📅 2026 年 5 月 26 日

📋 概要

Amazon GuardDuty Malware Protection for AWS Backup が Amazon S3 の継続的バックアップ (PITR) に対応しました。S3 継続的バックアップのタイムライン全体にわたってマルウェアスキャンを実行し、安全にリストア可能なクリーンなポイントインタイムを特定できるようになりました。

新しい GetPITRMalwareScanResults API により、継続的バックアップ内の任意の時点におけるマルウェアスキャンの状態を照会でき、リストアを開始する前に特定の復旧時点がクリーンであるかどうかを検証できます。

❌ Before

  • S3 継続的バックアップに対するマルウェアスキャンが利用不可
  • PITR リストア時にバックアップデータの安全性を事前確認できなかった
  • タイムライン上のどの時点がクリーンかを特定する手段がなかった

✅ After

  • フルスキャンおよび増分スキャンを自動実行可能に
  • API で任意の時点のスキャン結果を照会し、クリーンなリストアポイントを特定
  • オンデマンドスキャンで任意のポイントインタイムまでスキャン実行可能に

⚡ 主要機能

🔎
S3 継続的バックアップのマルウェアスキャン
バックアッププラン内で S3 継続的バックアップに対するフルスキャンと増分スキャンの両方をサポート。スケジュール頻度に従って自動実行。
🔑
GetPITRMalwareScanResults API
任意のポイントインタイムのスキャン状態を照会。リストア前に復旧時点がクリーンであるかを検証可能。未スキャン時は unknown を返却。
▶️
オンデマンドスキャン
任意のリストア可能なポイントインタイムに対してスキャンを実行。S3 継続的バックアップではフルスキャンのみ対応。
✅
クリーンなポイントインタイムの特定
バックアップタイムライン全体にわたってクリーンな復旧ポイントを識別。コンソールまたは API で最新のクリーンな時点を確認可能。

⚙️ 設定方法

前提条件

✓Amazon GuardDuty が有効化されたアカウント
✓AWS Backup で S3 継続的バックアップが設定済み
✓バックアップロールに AWSBackupServiceRolePolicyForScans ポリシーがアタッチ済み
✓スキャナーロールに AWSBackupGuardDutyRolePolicyForScans ポリシーがアタッチ済み

Step 1: スキャナーロールの作成

Bash スキャナーロール作成 
# スキャナーロールの信頼ポリシーを作成
cat > trust-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "malware-protection.guardduty.amazonaws.com"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}
EOF

# IAM ロールを作成
aws iam create-role \
    --role-name BackupScannerRole \
    --assume-role-policy-document file://trust-policy.json

# マネージドポリシーをアタッチ
aws iam attach-role-policy \
    --role-name BackupScannerRole \
    --policy-arn arn:aws:iam::aws:policy/AWSBackupGuardDutyRolePolicyForScans

Step 2: バックアッププランでマルウェアスキャンを有効化

JSON バックアッププラン設定例 
{
  "BackupPlan": {

        "RuleName": "s3-continuous-full-scan",

        "EnableContinuousBackup": true,
        "ScanActions": [
          {
            "MalwareScanner": "GUARDDUTY",
            "ScanMode": "INCREMENTAL_SCAN"

      {
        "MalwareScanner": "GUARDDUTY",

🎯 ユースケース

🦠 ユースケース 1: ランサムウェア攻撃後の安全な復旧
ランサムウェアに感染した S3 バケットを感染前のクリーンな状態に復旧する必要がある。GetPITRMalwareScanResults API で感染前のクリーンな時点を特定し、確認後にリストアを実行。
→ 感染前の正確な時点を特定してリストアすることで、データ損失を最小限に抑えつつ安全な復旧を実現
📋 ユースケース 2: コンプライアンス監査のためのスキャン自動化
医療データを保持する S3 バケットに対して、規制要件に基づき定期的なマルウェアスキャンを実施し、監査証跡を残す。日次の増分スキャンと週次のフルスキャンを組み合わせ。
→ コスト効率と包括的なセキュリティカバレッジの両立を実現
🔔 ユースケース 3: EventBridge 連携による自動アラート
マルウェアが検出された場合に自動で通知を送信し、該当バケットのリストア操作を一時停止するワークフローを構築。Backup Scan Job State Change イベントをトリガーに利用。
→ マルウェア検出時に即座に対応チームへ通知が届き、感染データのリストアを未然に防止

⚠️ 制限事項・注意点

✗S3 継続的バックアップのオンデマンドスキャンでは増分スキャンが非対応 (フルスキャンのみ)
✗アカウントあたり同時実行スキャン数は最大 150、リソースタイプあたりは最大 5
✗スキャン未実施の時点を GetPITRMalwareScanResults で照会した場合、結果は unknown
✗GuardDuty の検出結果の保持期間は 365 日間

💰 コストに関する注意

  • マルウェアスキャンの料金は GuardDuty 側で課金され、フリーティアやフリートライアルは提供されない
  • フルスキャンは全データを対象とするため、大容量バケットでは処理時間とコストが増大する可能性がある
  • スキャナーロールとバックアップロールの両方を適切に設定する必要があり、IAM 設定の管理が複雑になる

📝 まとめ

Amazon GuardDuty Malware Protection for AWS Backup が S3 継続的バックアップに対応したことで、PITR タイムライン全体にわたるマルウェアスキャンとクリーンな復旧ポイントの特定が可能になりました。

ランサムウェアやマルウェア攻撃への備えとして、S3 の継続的バックアップを利用している組織はバックアッププランでのスキャン有効化を検討することを推奨します。新しい GetPITRMalwareScanResults API を活用することで、リストア前の安全性確認を自動化し、インシデント対応の迅速化が期待できます。
