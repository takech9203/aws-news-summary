General Availability

📋 概要

AWS Transform composability イニシアチブの一環として、Agent Builder Toolkit (Kiro power) が一般提供 (GA) されました。AWS パートナー、ISV、お客様が自社固有のモダナイゼーション要件に合わせたカスタム変換エージェントを構築し、AWS Transform とシームレスに連携できるようになります。

独自のエージェント、ツール、ナレッジベース、ワークフローを AWS Transform のエージェント AI 機能と統合することで、差別化されたトランスフォーメーションソリューションを構築できます。

Before / After

Before

  • 変換機能は AWS 提供の組み込みエージェントに限定
  • パートナー独自のモダナイゼーション手法を統合する手段がない
  • カスタムエージェントの構築・共有・ディスカバリーのライフサイクルが統一されていない

After

  • Kiro power で特定要件に合わせたカスタムエージェントを構築可能
  • チーム・パートナーネットワーク間で共有し、AWS Transform に登録可能
  • Kiro power マーケットプレイスでエージェントを公開・発見可能

⚡ 主要機能

🤖 カスタム変換エージェントの構築

Kiro power を使用してモダナイゼーション要件に特化したエージェントを構築。独自のツール、ナレッジベース、ワークフローを統合し、AWS Transform のエージェント AI 機能と連携を保証。

🔄 エンドツーエンドのライフサイクル管理

構築 (Build) → 共有 (Share) → 登録 (Register) の一貫したワークフロー。Kiro power でエージェントを開発し、チームやパートナーネットワーク間で配布、AWS Transform に登録してディスカバリーを有効化。

🛒 Kiro power マーケットプレイス

構築したエージェントの公開と発見のためのマーケットプレイス。パートナーやお客様が作成したエージェントを検索・利用可能。エコシステム全体での再利用性を促進。

🧩 AWS Transform composability イニシアチブ

パートナーと ISV がエコシステムに貢献するための枠組み。差別化されたトランスフォーメーションソリューションの構築を支援し、組み合わせ可能な変換機能による柔軟な対応を実現。

🛠️ 設定方法

前提条件

→AWS Transform へのアクセス権限
→Kiro power マーケットプレイスへのアクセス
→エージェント構築に必要なドメイン知識とツール

手順

  1. Kiro power でエージェントを構築
    カスタム変換エージェントを開発。独自のツール、ナレッジベース、ワークフローを定義し、AWS Transform のエージェント AI 機能と統合するための設定を実施。
  2. エージェントの共有
    構築したエージェントをチームメンバーやパートナーネットワークと共有。アクセス制御を設定し、適切な範囲で利用可能に。
  3. AWS Transform への登録
    エージェントを AWS Transform に登録してディスカバリーを有効化。Kiro power マーケットプレイスへの公開により、他のユーザーがエージェントを発見・利用可能に。

⚖️ メリット・制約事項

✅ メリット

  • 差別化されたソリューション: パートナーや ISV が独自の変換ソリューションを構築し、市場での差別化を実現
  • エコシステムの拡大: マーケットプレイスを通じた新しい収益機会の創出
  • 迅速なモダナイゼーション: 特定ドメインに最適化されたエージェントにより効率向上
  • 柔軟な統合: 独自のツール、ナレッジベース、ワークフローを組み合わせ可能
  • 再利用性: 構築したエージェントを組織全体で再利用

⚠️ 制約事項・考慮点

  • Kiro power マーケットプレイスへのアクセスが必要
  • カスタムエージェントの品質と動作保証はビルダーの責任
  • AWS Transform のエージェント AI との互換性維持が必要
  • 構築にはモダナイゼーションのドメイン知識が必要
  • パートナーネットワーク間共有にはガバナンス・セキュリティの考慮が必要
  • エージェントの更新・メンテナンスのライフサイクル計画が必要

💡 ユースケース

🏦 パートナーによる業界特化型変換エージェント

シナリオ: Migration and Modernization Competency パートナーが、金融業界特有の COBOL メインフレームアプリケーションを Java マイクロサービスに変換するためのエージェントを構築。

→ 業界固有のコンプライアンス要件やビジネスロジックの変換パターンをナレッジベースとして組み込み、汎用ツールでは困難なケースを効率的に処理。

🏢 ISV によるフレームワーク移行エージェント

シナリオ: ISV が自社の SaaS プラットフォームへの移行を支援するカスタムエージェントを構築し、Kiro power マーケットプレイスで公開。

→ 顧客がマーケットプレイスからエージェントを発見して利用でき、ISV の顧客獲得と移行プロジェクトの効率化を同時に実現。

🏗️ エンタープライズ顧客による社内標準化

シナリオ: 大規模エンタープライズが自社のコーディング標準、アーキテクチャパターン、セキュリティポリシーに準拠した変換エージェントを構築し、社内の複数チームで共有。

→ 組織全体で一貫したモダナイゼーション品質を維持しながら、各チームが自律的に変換プロジェクトを推進可能に。
