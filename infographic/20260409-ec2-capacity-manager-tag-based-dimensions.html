📋 概要

Amazon EC2 Capacity Manager がタグベースディメンションをサポートし、EC2 リソースのタグを使用してキャパシティメトリクスのグループ化やフィルタリングが可能になりました。オンデマンドインスタンス、Spot インスタンス、キャパシティ予約にわたるキャパシティ使用状況を、ビジネス属性に基づいて分析できます。

最大 5 つのカスタムタグキーをアクティベートし、既存のビルトインディメンション (Region, Instance Type, AZ) と組み合わせて使用できます。また、Account Name が新しいビルトインディメンションとして追加され、組織全体のクロスアカウント分析がより容易になりました。

Before

  • グループ化はビルトインディメンション (Region, Instance Type, AZ) に限定
  • チーム・環境・コストセンターでの分析が困難
  • クロスアカウント分析時はアカウント ID のみ表示
  • S3 データエクスポートにタグ情報を含められない

After

  • 最大 5 つのカスタムタグキーでグループ化・フィルタリング
  • ASG 名、EKS クラスタ名など 4 つの提供タグが利用可能
  • Account Name ディメンションでアカウント名識別
  • S3 エクスポートにタグデータを追加カラムで出力

🛠️ 設定方法

EC2 Capacity Manager にアクセス

AWS マネジメントコンソールから EC2 Capacity Manager にアクセスします。

https://console.aws.amazon.com/ec2/home#CapacityManagerHome

カスタムタグキーのアクティベート

設定画面でカスタムタグキーをアクティベートします。使用したいタグキー (例: environment, team, cost-center) を最大 5 つまで選択します。

設定 > タグベースディメンション > カスタムタグキーを追加

タグベースディメンションでフィルタリング

ダッシュボードでビルトインディメンションとカスタムタグディメンションを組み合わせてメトリクスを分析します。

例: Region = ap-northeast-1 AND environment = production

S3 データエクスポートの設定

タグデータを含む S3 データエクスポートを新規作成します。Amazon Athena や QuickSight での分析が可能になります。

設定 > データエクスポート > 新規エクスポートを作成 > タグカラムを選択

💡 ユースケース

🏢 ユースケース 1: チーム別キャパシティコスト配分

複数のチームが共有 AWS アカウントで EC2 インスタンスを運用しており、チームごとのキャパシティ使用状況を把握したい

  • EC2 インスタンスに "team" タグを付与 (team=platform, team=data, team=ml)
  • Capacity Manager でカスタムタグキーとして "team" をアクティベート
  • ダッシュボードで team ディメンションでグループ化して分析

チームごとのオンデマンド、Spot、キャパシティ予約の使用状況を可視化し、公平なコスト配分を実現

🌐 ユースケース 2: 環境別キャパシティ管理

本番環境、ステージング環境、開発環境でキャパシティの使用状況が異なり、環境ごとに適切なキャパシティ戦略を策定したい

  • EC2 インスタンスに "environment" タグを付与 (production, staging, development)
  • Capacity Manager でカスタムタグキーとして "environment" をアクティベート
  • environment=production でフィルタリングし、本番環境のキャパシティ使用傾向を分析
  • S3 データエクスポートにタグデータを含めて定期的なレポートを生成

環境ごとのキャパシティ使用パターンを把握し、過剰プロビジョニングの削減や適切なキャパシティ計画を実現

☸️ ユースケース 3: EKS クラスタのキャパシティ最適化

複数の EKS クラスタを運用しており、クラスタごとのキャパシティ使用状況と Spot 中断の影響を分析したい

  • Capacity Manager 提供タグの "EKS cluster name" と "Karpenter node pool" を使用
  • クラスタ名でグループ化し、各クラスタのインスタンスタイプ別使用状況を分析
  • Karpenter ノードプール別の Spot インスタンス使用率を確認
  • Account Name ディメンションと組み合わせてマルチアカウントの EKS キャパシティを横断分析

EKS クラスタごとのキャパシティ効率を把握し、Karpenter のノードプール設定やインスタンスタイプの多様化を最適化

✅ メリット

📈 ビジネス面

  • チーム、プロジェクト、コストセンターごとにキャパシティ使用状況を正確に把握し、コスト配分の精度を向上
  • 環境ごとのキャパシティ使用状況を監視し、リソースの適正利用を促進
  • Account Name ディメンションにより、組織全体のキャパシティ分析が直感的になり意思決定を加速

🔧 技術面

  • カスタムタグとビルトインディメンションの組み合わせで多次元分析が可能
  • EKS クラスタ名や Karpenter ノードプールでコンテナワークロードのキャパシティ分析が容易
  • S3 エクスポートへのタグデータ追加で既存の分析パイプラインとの統合が容易

⚠️ 制限事項・考慮点

  • カスタムタグキーは最大 5 つまでに制限
  • S3 データエクスポートへのタグデータ追加は新規作成のエクスポートのみ対象 (既存エクスポートは非対応)
  • タグが付与されていないリソースはタグベースディメンションでのグループ化に含まれない場合がある
  • タグの命名規則を組織全体で統一する必要がある ("Environment" と "environment" は別タグとして扱われる)
  • カスタムタグキーの変更が反映されるまでに時間がかかる場合がある
  • 5 つのカスタムタグキーの選択は組織のタグ戦略と整合させて慎重に決定する必要がある

💰 料金

追加料金なし
タグベースディメンション機能は EC2 Capacity Manager の基本機能に含まれています。
S3 データエクスポートについては、S3 のストレージ料金とデータ転送料金が別途発生します。

🌍 利用可能リージョン

EC2 Capacity Manager が利用可能なすべての AWS リージョンで利用できます。
