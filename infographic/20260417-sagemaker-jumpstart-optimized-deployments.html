2026 年 4 月 17 日

概要

Amazon SageMaker JumpStart に Optimized Deployments 機能が追加されました。基盤モデルを特定のユースケースやパフォーマンス要件に合わせた事前構成済みの設定でデプロイできるようになります。

従来はインスタンスタイプ、推論コンテナ、量子化オプション、バッチサイズなどを手動で選定・調整する必要がありましたが、今回のアップデートにより、ユースケースと最適化ターゲットを選択するだけで最適な構成が自動的に適用されます。

応答時間を最小限に抑える構成。リアルタイム対話型アプリに最適

設定方法

前提条件

AWS アカウントと Amazon SageMaker へのアクセス権限
SageMaker JumpStart のモデルカタログへのアクセス権限
SageMaker エンドポイントまたは HyperPod クラスターの作成権限

ステップ 1: モデルを選択

AWS マネジメントコンソールから Amazon SageMaker サービスを開き、「JumpStart」を選択します。モデルカタログから対象の基盤モデルを検索し、モデル詳細ページを開きます。

ステップ 2: Optimized Deployments の構成を選択

モデル詳細ページで「Optimized Deployments」セクションを確認し、ユースケースと最適化ターゲットを選択します。

ステップ 3: パフォーマンスメトリクスを確認

選択した構成の P50 レイテンシー、TTFT、スループットの値を確認し、要件を満たしているか検証します。

ステップ 4: デプロイの実行

Python Optimized Deployments を使用したデプロイ例 
from sagemaker.jumpstart.model import JumpStartModel

# Optimized Deployments を使用したデプロイ例
model = JumpStartModel(
    model_id="meta-textgeneration-llama-3-2-8b",
    model_version="*"
)

# エンドポイントにデプロイ
predictor = model.deploy()

# 推論を実行
response = predictor.predict({
    "inputs": "Explain the benefits of optimized model deployment.",
    "parameters": {
        "max_new_tokens": 512,
        "temperature": 0.7
    }
})

JumpStartModel クラスを使用して Llama 3.2 モデルを SageMaker エンドポイントとしてデプロイし、推論リクエストを送信します。Optimized Deployments の構成はコンソールで設定した内容が反映されます。

ユースケース

💬 リアルタイムチャットボットのデプロイ
EC サイトの顧客対応チャットボットを構築しており、ユーザー体験向上のため低レイテンシーが最重要要件である場合。レイテンシー最適化でチャットモデルをデプロイします。
Python レイテンシー最適化でチャットモデルをデプロイ 
from sagemaker.jumpstart.model import JumpStartModel

model = JumpStartModel(
    model_id="meta-textgeneration-llama-3-2-8b"
)
predictor = model.deploy()

# チャット形式の推論
response = predictor.predict({
    "inputs": (
        "<|system|>You are a helpful customer service assistant "
        "for an e-commerce platform.</s>\n"
        "<|user|>I'd like to return the shoes I ordered last week. "
        "What's the process?</s>\n"
        "<|assistant|>"
    ),
    "parameters": {
        "max_new_tokens": 256,
        "temperature": 0.3
    }
})
TTFT が最小化され、ユーザーがメッセージを送信してから最初の応答が表示されるまでの待ち時間が短縮。SLA 要件を満たす構成を事前に選択可能
📝 大量コンテンツ生成パイプライン
マーケティング部門が数百件の商品説明文やブログ記事を一括生成するバッチ処理パイプラインを構築したい場合。スループット最適化でライティングモデルをデプロイします。
Python スループット最適化でコンテンツ生成 
from sagemaker.jumpstart.model import JumpStartModel

model = JumpStartModel(
    model_id="mistral-small-24b-instruct-2501"
)
predictor = model.deploy()

# バッチ処理でコンテンツを生成
products = [
    {"name": "Wireless Headphones", "features": ["noise-canceling", "30h battery"]},
    {"name": "Smart Watch", "features": ["heart rate", "GPS", "waterproof"]},
]

for product in products:
    response = predictor.predict({
        "inputs": (
            f"Write a compelling product description for {product['name']} "
            f"with features: {', '.join(product['features'])}."
        ),
        "parameters": {
            "max_new_tokens": 512,
            "temperature": 0.8
        }
    })
単位時間あたりの処理リクエスト数が最大化され、大量のコンテンツ生成タスクを効率的に処理。バッチジョブの完了時間を短縮
🧪 コスト効率の良い開発・プロトタイピング環境
AI 開発チームが複数の基盤モデルを評価・比較するためのプロトタイピング環境を低コストで構築したい場合。コスト最適化で複数モデルを評価します。
Python コスト最適化で複数モデルを評価 
from sagemaker.jumpstart.model import JumpStartModel

model_ids = [
    "meta-textgeneration-llama-3-2-8b",
    "google-gemma-7b",
    "tii-falcon3-7b"
]

for model_id in model_ids:
    model = JumpStartModel(model_id=model_id)
    predictor = model.deploy()

    response = predictor.predict({
        "inputs": "Summarize the key benefits of cloud computing in 3 bullet points.",
        "parameters": {
            "max_new_tokens": 256,
            "temperature": 0.5
        }
    })
    print(f"Model: {model_id}")
    print(f"Response: {response}")

    # 評価完了後にエンドポイントを削除
    predictor.delete_endpoint()
各モデルの評価に必要な最小限のインフラコストでデプロイが可能。デプロイ前のメトリクス表示により不要なデプロイを回避

メリット・デメリット

ビジネス面のメリット

ユースケースと最適化ターゲットを選択するだけでモデルデプロイまでの時間を大幅に短縮
デプロイ前にパフォーマンスメトリクスを確認でき、インフラコストの見積もり精度が向上
事前構成済みの最適化設定により、ML インフラの専門知識がなくても適切な構成を選択可能

技術面のメリット

P50 レイテンシー、TTFT、スループットの事前表示で SLA 要件に基づいたデプロイ判断が可能
Managed Inference と HyperPod の 2 つのデプロイ先でワークロードの規模に応じた環境を選択可能
主要モデルプロバイダーのモデルに対応し、単一のインターフェースで管理可能

制限事項

対応モデルは現時点で公表されているモデルに限定。すべての JumpStart モデルが対応しているわけではない
ユースケース構成の種類は事前定義されたものに限られ、特殊なユースケースでは手動最適化が必要な場合がある
パフォーマンスメトリクスは標準的なベンチマーク条件下の値であり、実際のワークロードと異なる可能性がある

考慮すべき点

最適化ターゲットはトレードオフの関係。コスト最適化ではレイテンシーやスループットが犠牲になる可能性
HyperPod へのデプロイは大規模 GPU リソースが前提。サービスクォータ引き上げが必要になる場合がある
マルチモーダルモデルはテキストのみとマルチモーダル推論でパフォーマンス特性が異なる

料金

Optimized Deployments 機能自体に追加料金は発生しません。料金はモデルをホストする SageMaker エンドポイントまたは HyperPod クラスターのインスタンスタイプと稼働時間に基づいて課金されます。
