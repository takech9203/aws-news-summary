📋 概要

Amazon EC2 C8gn インスタンスが、東京、ジャカルタ、ハイデラバード、サンパウロ、チューリッヒの 5 つの追加リージョンで利用可能になりました。 C8gn は AWS Graviton4 プロセッサーと第 6 世代 AWS Nitro Cards を搭載し、EC2 ネットワーク最適化インスタンスの中で最高となる最大 600 Gbps のネットワーク帯域幅を実現します。

Before / After

❌ Before
•東京リージョンでは C8gn が利用不可。Graviton4 ベースのネットワーク最適化インスタンスを活用できなかった
•C7gn では最大 200 Gbps に制限。超高帯域幅のワークロードに対応が難しかった
•ジャカルタ、ハイデラバード等でもネットワーク最適化 Graviton インスタンスの選択肢が限定的
✅ After
•5 つの追加リージョンで C8gn が利用可能に。ネットワーク集約的ワークロードの選択肢が拡大
•最大 600 Gbps のネットワーク帯域幅で超高帯域幅アプリケーションに対応
•Graviton4 で C7gn 比最大 30% のパフォーマンス向上。第 6 世代 Nitro Cards によるアクセラレーション

C8gn インスタンスが新たに利用可能になった 5 つのリージョンと、主要コンポーネント、対象ワークロードの関係を示しています。

⭐ 主要機能

🔧 Graviton4 プロセッサー搭載
  • AWS 独自開発の Arm ベースプロセッサー Graviton4 を搭載
  • C7gn と比較して最大 30% 優れたコンピューティングパフォーマンス
  • 電力効率に優れ、同等の x86 ベースインスタンスと比較してコストパフォーマンスが向上
🌐 最大 600 Gbps ネットワーク帯域幅
  • EC2 ネットワーク最適化インスタンスの中で最高のネットワーク帯域幅
  • 第 6 世代 AWS Nitro Cards によるハードウェアアクセラレーション
  • ネットワーク集約的なワークロードで卓越したスループットを実現
🔗 Elastic Fabric Adapter サポート
  • 16xlarge 以上のインスタンスサイズで EFA をサポート
  • HPC や分散機械学習トレーニングなど、ノード間通信が重要なワークロードに最適
  • 低レイテンシー / 高帯域幅のノード間通信を実現

⚙️ 設定方法

前提条件

✔ AWS アカウントと適切な IAM 権限
✔ 対象リージョンへのアクセス
✔ Arm (aarch64/arm64) アーキテクチャ対応の AMI

ステップ 1: 利用可能なインスタンスタイプを確認

Bash 東京リージョンで C8gn を確認 
# 東京リージョンで利用可能な C8gn インスタンスタイプを確認
aws ec2 describe-instance-types \
  --filters "Name=instance-type,Values=c8gn.*" \
  --region ap-northeast-1 \
  --query "InstanceTypes[].{Type:InstanceType,vCPU:VCpuInfo.DefaultVCpus,Memory:MemoryInfo.SizeInMiB,Network:NetworkInfo.NetworkPerformance}" \
  --output table

ステップ 2: C8gn インスタンスを起動

Bash Graviton4 対応 AMI でインスタンス起動 
# Graviton4 対応 AMI で C8gn インスタンスを起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type c8gn.16xlarge \
  --region ap-northeast-1 \
  --subnet-id subnet-xxxxxxxxxxxxxxxxx \
  --security-group-ids sg-xxxxxxxxxxxxxxxxx \
  --key-name my-key-pair

ステップ 3: EFA を有効にして起動 (16xlarge 以上)

Bash EFA 付きで C8gn.48xlarge を起動 
# EFA 付きで C8gn インスタンスを起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type c8gn.48xlarge \
  --region ap-northeast-1 \
  --network-interfaces "DeviceIndex=0,SubnetId=subnet-xxxxxxxxxxxxxxxxx,Groups=sg-xxxxxxxxxxxxxxxxx,InterfaceType=efa" \
  --key-name my-key-pair

✅ メリット

💼 ビジネス面

✔東京リージョンでの低レイテンシー: 日本国内のお客様がネットワーク集約的なワークロードを低レイテンシーで実行可能。データ主権要件にも対応
✔コスト効率の向上: Graviton4 の電力効率により、同等の x86 ベースインスタンスと比較して優れたコストパフォーマンス
✔グローバル展開の拡大: 5 つの追加リージョンにより、グローバル分散アプリケーションの展開が容易に

🔨 技術面

✔最高のネットワーク帯域幅: EC2 ネットワーク最適化インスタンスの中で最高となる 600 Gbps
✔30% のパフォーマンス向上: Graviton4 により C7gn 比で最大 30% のコンピューティング改善
✔EFA による高性能通信: HPC や分散 ML トレーニングの通信効率を最大化
✔最新の Nitro アーキテクチャ: 第 6 世代 Nitro Cards でネットワーク処理のアクセラレーション向上

⚠️ 制約事項・考慮点

制限事項

⚠Arm (arm64) アーキテクチャのため、x86 専用ソフトウェアは動作しない。Arm 対応の AMI とアプリケーションが必要
⚠EFA サポートは 16xlarge 以上のインスタンスサイズに限定
⚠すべてのリージョンで利用可能ではない (今回 5 リージョンに拡大)

考慮すべき点

💡既存 x86 ワークロード移行には Arm アーキテクチャへの対応 (コンパイル、依存関係確認) が必要
💡600 Gbps 帯域幅の活用には 48xlarge が必要。小さいサイズでは帯域幅も比例して小さくなる
💡スポットインスタンスの可用性は新規リージョンでは安定するまで時間がかかる場合がある

🎯 ユースケース

🔌 ネットワーク仮想アプライアンス
通信事業者が日本国内でネットワーク機能仮想化 (NFV) 基盤を構築し、VPN ゲートウェイやファイアウォールを高スループットで運用
Bash NFV 用インスタンス起動例 
# 東京リージョンで NFV 用の C8gn インスタンスを起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type c8gn.16xlarge \
  --region ap-northeast-1 \
  --network-interfaces \
    "DeviceIndex=0,SubnetId=subnet-aaa,Groups=sg-xxx" \
    "DeviceIndex=1,SubnetId=subnet-bbb,Groups=sg-yyy"
✔ 最大 600 Gbps のネットワーク帯域幅と Graviton4 の高性能処理により、ハードウェアアプライアンスに匹敵するスループットを仮想環境で実現
🤖 分散機械学習トレーニング
AI 企業が大規模言語モデルの分散トレーニングを、ノード間の高速通信を活用して実行
Bash EFA 付き分散トレーニングクラスタ 
# EFA 付きで複数の C8gn インスタンスを起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type c8gn.48xlarge \
  --count 4 \
  --region ap-northeast-1 \
  --network-interfaces "DeviceIndex=0,SubnetId=subnet-xxxxxxxxxxxxxxxxx,Groups=sg-xxxxxxxxxxxxxxxxx,InterfaceType=efa" \
  --placement "GroupName=ml-cluster"
✔ EFA による低レイテンシー / 高帯域幅通信と Graviton4 の高いコンピューティング性能で、分散トレーニングのスループットが大幅に向上
📡 リアルタイムメディアストリーミング
動画配信サービスが東京リージョンからライブストリーミングコンテンツを大量の視聴者に配信
Bash メディアストリーミング用インスタンス 
# メディアストリーミング用の C8gn インスタンスを起動
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type c8gn.8xlarge \
  --region ap-northeast-1 \
  --subnet-id subnet-xxxxxxxxxxxxxxxxx \
  --security-group-ids sg-xxxxxxxxxxxxxxxxx
✔ 高いネットワーク帯域幅で同時接続数の多いライブストリーミングでも安定配信。Graviton4 によるエンコーディング処理の効率化でコスト削減
