🛡️ AWS WAF

Amazon Bedrock AgentCore Gateway を
AWS WAF で保護

📅 2026 年 6 月 29 日 GA
AWS Web Application Firewall

📌 概要

AWS は、Amazon Bedrock AgentCore Gateway に対する AWS WAF 保護の一般提供 (GA) を発表しました。 エージェント型 AI ワークロードを一般的な Web エクスプロイトや不正利用から保護できます。

AgentCore Gateway に AWS WAF の保護パック (Web ACL) を関連付けることで、IP ベースのアクセス制御、 レートベースルール、AWS マネージドルールグループ を適用できます。 Gateway レベルで一度設定するだけで、配下のすべてのターゲットに一貫して保護が適用されます。

👥 対象ユーザー: 本番環境でエージェント型 AI アプリケーションを運用するセキュリティ担当者やプラットフォームエンジニア。 AWS WAF と AgentCore Gateway の両方が提供されるすべての AWS リージョンで利用可能です。

🔄 アップデート前後の変化

❌ Before (課題)

  • Gateway に統合された WAF 保護を関連付ける標準手段がなく、不正アクセス対策が個別実装に依存
  • Gateway 配下の複数のツール / エージェント / 統合それぞれに保護を個別検討する必要があった
  • IP 制御やレート制限を、エージェント型 AI のエントリポイントに一貫して適用しづらい

✅ After (改善)

  • WAF 保護パックを AgentCore Gateway に直接関連付けて Web 脅威・濫用から保護
  • Gateway レベルで一度設定するだけで配下のすべてのターゲットに一貫適用、個別設定不要
  • IP 制御 / レートルール / マネージドルールを統一的に適用可能

Gateway に到達するトラフィックは、ツールやエージェントなどの配下ターゲットに渡る前に、IP 制御・レート制限・マネージドルールによる検査が行われます。

⚡ 主要機能

🌐 IP ベースのアクセス制御
  • 特定の IP アドレスや IP レンジに基づいてトラフィックを許可・拒否
  • 信頼できるネットワークからのアクセスのみ許可するなど、到達制御を実現
⏱️ レートベースルール
  • 一定期間内のリクエスト数に基づき、濫用的なトラフィックをスロットリング
  • エージェント型 AI エンドポイントへの過剰リクエストや乱用を緩和
📦 AWS マネージドルールグループ
  • コモンルールセット: 一般的な Web アプリケーションの脆弱性に対応
  • 既知の不正な入力: 既知の悪意あるリクエストパターンをブロック
  • Bot Control: 自動化されたボットトラフィックを検出・管理
🚪 Gateway レベルの一括適用
  • 保護パックを Gateway に一度関連付けるだけで、配下のすべてのターゲットに一貫適用
  • ターゲットごとの個別設定が不要となり、一貫性と運用効率が向上

🔧 技術仕様

AWS WAF の保護パック (Web ACL) は、リージョナルリソースの 1 つとして AgentCore Gateway をサポートします。 保護パックおよび関連リソースは、保護対象リソースと同じリージョンに配置する必要があります。

項目詳細
リソースタイプAmazon Bedrock AgentCore Gateway (リージョナルリソース)
関連付け単位Gateway 単位 (1 つの Gateway に 1 つの保護パック)
保護パックの配置保護対象 Gateway と同一リージョン
適用範囲Gateway 配下のすべてのターゲット (ツール / エージェント / 統合)
データ保持監視・管理する Web リクエストデータは保護対象と同一リージョン内に保持
💡 各 AWS リソースに関連付けできる保護パックは 1 つのみ (保護パックとリソースの関係は 1 対多)。

設定や権限 (関連付けの操作例)

BashWeb ACL を Gateway に関連付け
# 既存の Web ACL (保護パック) を AgentCore Gateway に関連付ける
aws wafv2 associate-web-acl \
  --web-acl-arn arn:aws:wafv2:ap-northeast-1:123456789012:regional/webacl/my-agentcore-protection/xxxxxxxx \
  --resource-arn arn:aws:bedrock-agentcore:ap-northeast-1:123456789012:gateway/my-gateway-id

Web ACL と Gateway は同一リージョンである必要があります。

🛠️ 設定方法

前提条件

✓Amazon Bedrock AgentCore Gateway が作成済みであること
✓AWS WAF の保護パック (Web ACL) を作成する権限があること
✓保護パックと Gateway が同一リージョンに存在すること

手順

1
保護パック (Web ACL) の作成
Bashリージョナルスコープで Web ACL を作成
aws wafv2 create-web-acl \
  --name my-agentcore-protection \
  --scope REGIONAL \
  --region ap-northeast-1 \
  --default-action Allow={} \
  --visibility-config SampledRequestsEnabled=true,CloudWatchMetricsEnabled=true,MetricName=agentcoreWAF \
  --rules file://rules.json

IP セット参照・レートベースルール・マネージドルールグループを含むルールセットを定義。--scope REGIONAL を指定する点に注意。

2
AgentCore Gateway への関連付け
Bash保護パックを Gateway に関連付け
aws wafv2 associate-web-acl \
  --web-acl-arn <作成した Web ACL の ARN> \
  --resource-arn <AgentCore Gateway の ARN>

実行すると Gateway 配下のすべてのターゲットに保護が一貫適用されます。

3
モニタリングとルール調整

CloudWatch メトリクスとサンプリングされたリクエストを確認し、誤検知や濫用パターンに応じてレートベースルールのしきい値やマネージドルールの設定を調整。本番適用前にはカウントモードでの評価を推奨します。

🎯 メリット

💼 ビジネス面

✓本番移行の加速: プロトタイプから本番へのセキュリティ要件をマネージドな保護で充足
✓運用負荷の軽減: Gateway レベルの一元設定で個別保護の手間を削減
✓ガバナンスの強化: 一貫したポリシーをエージェント型ワークロードに適用

⚙️ 技術面

✓一貫した保護適用: 単一の保護パックで配下のすべてを保護
✓多層的な防御: IP 制御 / レート制限 / マネージドルールを組み合わせ
✓既存 WAF 機能の活用: Web ACL / ルールグループ / IP セットをそのまま適用

⚠️ デメリット・制約事項

制限事項

✗1 つの AgentCore Gateway に関連付けできる保護パックは 1 つのみ
✗保護パックと Gateway は同一リージョンに配置する必要がある
✗AWS WAF と AgentCore Gateway の両方が提供されるリージョンに限られる

考慮すべき点

⚠️ルール設定によっては正当なトラフィックが影響を受ける可能性。本番適用前はカウントモードでの評価が望ましい
⚠️AWS WAF の利用には別途料金が発生 (ルール数やリクエスト数などに基づく)

💡 ユースケース

1. 本番エージェント API の濫用防止
シナリオ: 公開 Gateway 経由でエージェントを提供し、過剰なリクエストによる濫用やコスト増加を防ぎたい
実装例: レートベースルールを設定し、単一 IP からの一定期間内リクエストがしきい値を超えたらブロック / スロットリング
✅ 効果: 過剰リクエストを抑制し、安定した運用とコスト管理を実現
2. 信頼できるネットワークからのアクセス限定
シナリオ: 社内システムや特定パートナーのみが利用する Gateway へのアクセスを許可 IP レンジに制限したい
実装例: IP セットを作成し許可リスト方式で保護パックに組み込み、許可外 IP からのリクエストを拒否
✅ 効果: 想定外のネットワークからのアクセスを遮断し、攻撃対象領域を縮小
3. 一般的な Web 脅威とボットへの対策
シナリオ: エージェント型アプリを一般的な Web 攻撃や自動化されたボットトラフィックから保護したい
実装例: マネージドルールグループ (コモンルールセット / 既知の不正な入力 / Bot Control) を保護パックに追加して有効化
✅ 効果: 継続的に更新される防御を、運用負荷を抑えて適用

💰 料金 & 利用可能リージョン

💰 料金

本アップデートに固有の追加料金はなし。AWS WAF の標準料金 (Web ACL・ルール・処理リクエスト数などに基づく従量課金) が適用されます。マネージドルールグループや Bot Control など一部機能には追加料金が発生する場合があります。

🌍 利用可能リージョン

AWS WAF と Amazon Bedrock AgentCore Gateway の両方が利用可能なすべての AWS リージョンで提供されます。

🔗 関連サービス・機能

🚪 Amazon Bedrock AgentCore Gateway
  • エージェント型 AI がツールや統合にアクセスするためのゲートウェイ。本機能の保護対象
📦 AWS WAF マネージドルール
  • コモンルールセット / 既知の不正な入力 / Bot Control など、AWS が管理・更新するルールグループを提供
📊 Amazon CloudWatch
  • AWS WAF のメトリクスやサンプリングされたリクエストを可視化し、ルールチューニングに活用

📝 まとめ

本アップデートにより、AgentCore Gateway に AWS WAF の保護パックを関連付けて、エージェント型 AI ワークロードを一般的な Web 脅威や濫用から保護できるようになりました。

Gateway レベルで一度設定するだけで配下のすべてのターゲットに一貫した保護が適用されるため、運用負荷を抑えながら本番環境のセキュリティ要件を満たせます。 本番展開時は、レートベースルールや AWS マネージドルールグループの導入を検討し、まずはカウントモードでの評価から始めることを推奨します。
