Amazon DocumentDB

📋 Amazon DocumentDB が
台北・ニュージーランドリージョンで利用可能に

MongoDB 互換のフルマネージドドキュメントデータベースが 2 つの新リージョンへ拡大
📅 リリース日: 2026 年 11 月 4 日

📝 概要

Amazon DocumentDB (with MongoDB compatibility) が、アジアパシフィック (台北) および アジアパシフィック (ニュージーランド) リージョンで利用可能になりました。 台湾・ニュージーランドのユーザーは、ローカルリージョンでフルマネージドなドキュメントデータベースを利用できます。

Amazon DocumentDB はフルマネージドのネイティブ JSON データベースであり、インフラストラクチャを管理することなく、 重要なドキュメントワークロードをほぼあらゆる規模でシンプルかつコスト効率よく運用できます。 ストレージはアプリケーションへの影響なしに最大 128 TiB まで自動スケールします。

❌ Before: アップデート前の課題
  • 台北・ニュージーランドリージョンでは利用できず、東京やシドニーなど近隣リージョンを利用する必要があった
  • 他リージョン利用時はネットワークレイテンシーが増加し、現地ユーザー向けアプリの応答性能に影響
  • データを国内に保持するデータレジデンシー要件を満たすことが困難
✅ After: アップデート後の改善
  • 台北・ニュージーランドリージョンで DocumentDB クラスターを直接作成・運用可能に
  • アプリケーションとデータベースを同一リージョンに配置し、レイテンシーを低減
  • 台湾・ニュージーランド国内のデータレジデンシー要件に対応したアーキテクチャを構築可能

新たに利用可能になった 2 つのリージョンで Amazon DocumentDB クラスターを構築し、現地ユーザーに低レイテンシーでサービスを提供する構成です。 各クラスターは CloudWatch、CloudTrail、Lambda、AWS Backup などの AWS サービスとネイティブに統合されます。

🛠️ 設定方法

📋 前提条件

  • AWS アカウントを保有していること
  • 台北リージョンまたはニュージーランドリージョンが AWS アカウントで有効化されていること (オプトインリージョンの場合)
  • クラスターを配置する VPC とサブネットグループが対象リージョンに作成されていること
1
対象リージョンでクラスターを作成
Bash クラスター作成 
aws docdb create-db-cluster \
  --db-cluster-identifier my-docdb-cluster \
  --engine docdb \
  --master-username myuser \
  --master-user-password mypassword \
  --region ap-east-2
台北リージョンに DocumentDB クラスターを作成するコマンドです。--region にはニュージーランドリージョンのリージョンコードも指定できます。リージョンコードは公式ドキュメントで確認してください。
2
インスタンスを追加
Bash インスタンス追加 
aws docdb create-db-instance \
  --db-instance-identifier my-docdb-instance \
  --db-instance-class db.r6g.large \
  --engine docdb \
  --db-cluster-identifier my-docdb-cluster \
  --region ap-east-2
作成したクラスターにプライマリインスタンスを追加します。読み取り負荷が高い場合は、同様のコマンドでリードレプリカを最大 15 個まで追加できます。
3
アプリケーションから接続
クラスターのエンドポイントを取得し、MongoDB 互換ドライバーを使用してアプリケーションから接続します。接続文字列はクラスター詳細画面または describe-db-clusters コマンドで確認できます。

⚠️ デメリット・制約事項

🚧 制限事項
⚠新規リージョンでは、既存リージョンと比較して利用可能なインスタンスタイプや機能に差異がある場合があるため、事前確認が必要
⚠台北およびニュージーランドリージョンはオプトインリージョンであり、利用前にアカウントでの有効化が必要になる場合がある
🤔 考慮すべき点
⚠既存の他リージョンのクラスターから移行する場合は、AWS Database Migration Service (DMS) などを利用した移行計画が必要
⚠リージョンごとに料金が異なる場合があるため、料金ページで対象リージョンの料金を確認することを推奨

🎯 ユースケース

🛒 ユースケース 1: 台湾国内向け Web アプリケーションのデータベース

シナリオ: 台湾のユーザーを対象とした EC サイトで、商品カタログやユーザープロファイルを JSON ドキュメントとして管理。データは台湾国内に保持する必要がある。

実装例: 台北リージョンにクラスターを作成 → 同一リージョンの ECS / EKS 上のアプリケーションから接続 → 読み取り負荷に応じてリードレプリカを追加

✅ 効果: データレジデンシー要件を満たしつつ、現地ユーザーへの低レイテンシーなレスポンスを実現
🏦 ユースケース 2: ニュージーランドの公共・金融系ワークロード

シナリオ: ニュージーランド国内の規制要件により、データを国内リージョンで管理する必要がある金融系アプリケーションでドキュメントデータベースを利用。

実装例: ニュージーランドリージョンにクラスターを作成 → CloudTrail で監査ログを取得し AWS Backup でバックアップを一元管理 → CloudWatch でパフォーマンスをモニタリング

✅ 効果: 国内データ保持の要件に対応しながら、フルマネージドサービスによる運用負荷の軽減と監査対応を両立
🔄 ユースケース 3: 既存 MongoDB ワークロードの移行

シナリオ: 台湾またはニュージーランドでオンプレミスの MongoDB を自己運用しており、インフラ管理の負担を軽減するためマネージドサービスへ移行したい。

実装例: 対象リージョンにクラスターを作成 → AWS DMS またはネイティブツールでデータを移行 → MongoDB 互換ドライバーを利用し、アプリケーション変更を最小限に抑えて切り替え

✅ 効果: MongoDB 互換性によりアプリケーション改修を最小限に抑えつつ、パッチ適用やバックアップなどの運用作業から解放

💰 料金

Amazon DocumentDB の料金は、インスタンス料金 (オンデマンド、秒単位課金)、ストレージ使用量、I/O、 バックアップストレージ、データ転送量に基づく従量課金制です。 リージョンごとに料金が異なるため、台北およびニュージーランドリージョンの最新料金は 料金ページで確認してください。

✅ まとめ

Amazon DocumentDB がアジアパシフィック (台北) およびアジアパシフィック (ニュージーランド) リージョンで利用可能になり、 両国のユーザーは低レイテンシーかつデータレジデンシー要件に対応した ドキュメントデータベースを利用できるようになりました。 該当地域でドキュメントワークロードや MongoDB 互換データベースの利用を検討している場合は、 料金とインスタンスタイプの提供状況を確認のうえ、ローカルリージョンでのクラスター構築を検討することを推奨します。
