📞 Outbound Campaigns マルチコンタクトタイムゾーン検出

顧客プロファイルの全連絡先情報からタイムゾーンを包括的に判定し、コンプライアンスリスクを大幅に低減

2026-05-07

📋 概要

Amazon Connect Outbound Campaigns に、顧客プロファイル上のすべての電話番号と住所を使用してタイムゾーンを検出するマルチコンタクトタイムゾーン検出機能が追加された。複数のタイムゾーンにまたがる場合は最も厳格な配信ウィンドウを適用し、追加料金なしで全リージョンで利用可能。

❌ Before - アップデート前の課題

  • プライマリ電話番号のみでタイムゾーンを検出
  • モバイル番号のエリアコードと実際の居住地が異なる顧客に不適切な時間帯に連絡
  • TCPA などの規制への準拠が不完全になる可能性

✅ After - アップデート後の改善

  • 全ての電話番号と住所からタイムゾーンを検出
  • 全タイムゾーンで許容範囲内となる時間帯のみに配信を制限
  • 重複ウィンドウが存在しない場合はプロファイルをスキップ

⚡ 主要機能

🔍 マルチコンタクトタイムゾーン検出

  • 顧客プロファイルのすべての電話番号 (モバイル、自宅、ビジネスなど) からエリアコードを分析
  • 登録された住所情報 (ZIP コード) からもタイムゾーンを判定
  • プライマリ連絡先に限定せず、包括的なタイムゾーン検出を実現

🧮 重複ウィンドウの自動計算

  • 検出されたすべてのタイムゾーンに対して配信ウィンドウとの重複時間を自動計算
  • すべてのタイムゾーンで許容される時間帯のみにメッセージを配信
  • 例: Eastern と Pacific の両方が検出された場合、9am-5pm の設定では 12pm-5pm ET のみ配信

⏭️ スキップロジック

  • 有効な重複ウィンドウが存在しない場合、そのプロファイルへの配信をスキップ
  • 規制違反のリスクを完全に排除
  • スキップされたプロファイルはキャンペーンレポートで確認可能

⚙️ 設定方法

前提条件

1. Amazon Connect インスタンスが作成済みであること
2. Amazon Connect Outbound Campaigns が有効化されていること
3. Amazon Connect Customer Profiles が設定済みで、顧客の連絡先情報が登録されていること

communicationTimeConfig の設定構造

JSON communicationTimeConfig 
{
  "communicationTimeConfig": {
    "localTimeZoneConfig": {
      "defaultTimeZone": "America/New_York",
      "localTimeZoneDetection": [
        "ZIP_CODE",
        "AREA_CODE"
      ]
    },
    "telephony": {
      "openHours": {
        "dailyHours": {
          "MONDAY": [
            {
              "startTime": "09:00",
              "endTime": "17:00"
            }
          ]
        }
      }
    }
  }
}

キャンペーン作成コマンド

Bash AWS CLI - キャンペーン作成 
aws connectcampaignsv2 create-campaign \
  --name "multi-timezone-campaign" \
  --connect-instance-id "arn:aws:connect:us-east-1:123456789012:instance/abc-def" \
  --channel-subtype-config '{"telephony": {"capacity": 1.0, "outboundMode": {"agentless": {}}}}' \
  --communication-time-config '{
    "localTimeZoneConfig": {
      "defaultTimeZone": "America/New_York",
      "localTimeZoneDetection": ["ZIP_CODE", "AREA_CODE"]
    },
    "telephony": {
      "openHours": {
        "dailyHours": {
          "MONDAY": [{"startTime": "09:00", "endTime": "17:00"}],
          "TUESDAY": [{"startTime": "09:00", "endTime": "17:00"}],
          "WEDNESDAY": [{"startTime": "09:00", "endTime": "17:00"}],
          "THURSDAY": [{"startTime": "09:00", "endTime": "17:00"}],
          "FRIDAY": [{"startTime": "09:00", "endTime": "17:00"}]
        }
      }
    }
  }' \
  --type MANAGED

Customer Profiles に複数連絡先情報を登録

ビジネス面

⚠️ 制限事項・考慮点

! 重複ウィンドウが存在しないプロファイルは配信対象外 (到達率低下の可能性)
! VoIP 番号や番号ポータビリティ利用の番号では精度が低下する場合あり
! 検出ロジックは北米番号計画 (NANP) 地域のエリアコードに最適化
! 配信ウィンドウが狭い場合、マルチタイムゾーン検出により配信可能時間がさらに狭くなる
! 大量の連絡先情報が登録されたプロファイルでスキップケースが増加する可能性

💡 ユースケース

🏦 全米展開の金融サービス企業

大手銀行が支払いリマインダーを全米の顧客に送信。モバイル番号が東海岸のエリアコードだが、実際には西海岸に住んでいるケースが多い。

配信ウィンドウ: 8am-9pm / defaultTimeZone: America/New_York

効果: 配信ウィンドウを広く設定し、マルチタイムゾーン検出により各顧客に適切な時間帯を自動計算。コンプライアンス違反リスクを排除しつつ到達率を最大化。

🏥 ヘルスケア企業の予約リマインダー

全米に拠点を持つヘルスケア企業が、患者に予約リマインダーを SMS で送信。患者プロファイルには自宅電話、携帯電話、勤務先電話が登録。

配信ウィンドウ: 9am-6pm / defaultTimeZone: America/Chicago

効果: 複数の電話番号から検出されたタイムゾーンを考慮し、すべてのタイムゾーンで営業時間内に収まる時間帯のみに SMS を送信。HIPAA 関連のコミュニケーション規制への準拠を強化。

🛒 E コマースのプロモーションキャンペーン

E コマース企業がセール情報をアウトバウンドコールで通知。顧客は購入時と配送先で異なる住所を登録しており、プロファイルに複数の住所が存在。

配信ウィンドウ: 土日 10am-6pm / defaultTimeZone: America/Los_Angeles

効果: 週末のプロモーションキャンペーンで、顧客の請求先住所と配送先住所の両方のタイムゾーンを考慮。すべての住所が許容範囲内となる時間帯のみ発信し顧客体験を損なわない。
