OpenSearch UI Cross-Region Data Access

単一の UI から複数リージョンの OpenSearch ドメインに統合アクセス

2026-05-01
AWS What's New

📋 概要

Amazon OpenSearch Service の OpenSearch UI がクロスリージョンデータアクセスをサポート。単一の OpenSearch UI アプリケーションから異なる AWS リージョンにホストされた OpenSearch ドメインにアクセスし、クエリの実行やダッシュボードの構築が可能に。

2026 年初頭にリリースされたクロスアカウントデータアクセス機能と組み合わせることで、アカウント x リージョンの柔軟な組み合わせで統合分析が可能。エンドポイントの切り替えやデータのレプリケーションは不要。

0 レプリケーション不要
IAM + IdC 認証方式をサポート
Public + VPC 両構成に対応

🔄 Before / After

❌ Before

  • 複数リージョンのデータ統合にはレプリケーションが必要
  • クロスリージョンレプリケーション設定やデータパイプラインの構築が煩雑
  • リージョンごとにエンドポイントを切り替える運用が必要

✅ After

  • データレプリケーション不要でストレージコストと遅延を削減
  • クロスアカウント + クロスリージョンの統合分析が実現

⚡ 主要機能

🌐 クロスリージョンドメインアソシエーション

単一の OpenSearch UI アプリケーションから異なるリージョンの OpenSearch ドメインに接続可能。同一パーティション内のリージョン間でデータ可視化を一元化。エンドポイントの切り替えやデータレプリケーションが不要。

🔌 パブリック / VPC 両構成のサポート

パブリックアクセス構成および VPC 構成の OpenSearch ドメインに対応。VPC エンドポイントアクセスに SupportedRegions オプションが追加され、リージョン間のアクセスを許可可能。

🔗 クロスアカウントとの併用

クロスアカウントデータアクセス機能と組み合わせて使用可能。アカウントとリージョンの柔軟な組み合わせでドメインにアクセスし、組織全体の分散データを単一 UI から統合分析。

🔑 柔軟な認証方式

IAM 認証および IAM Identity Center によるエンドユーザー認証に対応。既存の認証基盤をそのまま活用可能。

🛠️ 設定方法

前提条件

✓OpenSearch UI アプリケーションが作成済みであること
✓アクセス先のリージョンに OpenSearch ドメインが存在すること
✓VPC 構成の場合、VPC エンドポイントアクセスでリモートリージョンが許可されていること
✓IAM または IAM Identity Center による認証が設定済みであること

Step 1: VPC エンドポイントアクセスの許可 (VPC 構成の場合)

ターゲットリージョンの OpenSearch ドメインに対して、ソースリージョンからの VPC エンドポイントアクセスを許可する。パブリックアクセス構成の場合はこのステップは不要。

Bash VPC エンドポイントアクセス許可 
aws opensearch authorize-vpc-endpoint-access \
    --domain-name my-target-domain \
    --service "application.opensearchservice.amazonaws.com" \
    --service-options '{"SupportedRegions": ["ap-northeast-1"]}'

Step 2: OpenSearch UI にリモートドメインをデータソースとして追加

OpenSearch UI アプリケーションに異なるリージョンの OpenSearch ドメインをデータソースとして登録する。

Bash リモートドメイン追加 
aws opensearch update-application \
    --id <application-id> \
    --data-sources '[{
        "dataSourceArn": "arn:aws:es:us-east-1:<account-id>:domain/remote-domain",
        "dataSourceDescription": "Cross-region data source in us-east-1"
    }]'

Step 3: OpenSearch UI からクエリを実行

OpenSearch UI にログインし、追加したクロスリージョンデータソースを選択してクエリやダッシュボードの構築を行う。クロスアカウントデータソースと同様の操作でリージョン横断的なデータ分析が可能。

💡 メリット

📈 ビジネス面

  • クロスリージョンレプリケーション不要でストレージコストとデータ転送コストを削減
  • 複数リージョンのデータを単一ダッシュボードから分析しグローバルなインサイトを迅速取得
  • DR/BCP シナリオでマルチリージョン構成の可視性が向上

🔧 技術面

  • レプリケーションパイプライン不要でアーキテクチャがシンプルに
  • レプリケーション遅延なく各リージョンの最新データに直接クエリ可能
  • クロスアカウント併用でアカウント x リージョンの任意の組み合わせに対応

⚠️ 制約事項・考慮点

制限事項

⚠クロスリージョンアクセスは同一パーティション内に限定
⚠リージョン間ネットワークレイテンシにより同一リージョン比でレスポンスタイム増加の可能性
⚠VPC 構成ドメインへのアクセスでは VPC エンドポイントの追加設定が必要

考慮すべき点

⚠クロスリージョンクエリではリージョン間データ転送料金が発生する可能性あり
⚠大量データのクロスリージョンクエリはレイテンシに影響するためクエリの粒度設計が重要
⚠コンプライアンス要件による特定データのリージョン外転送制約を事前確認

🎯 ユースケース

🌍 グローバルオブザーバビリティダッシュボード

グローバルに展開するアプリケーションが各リージョンの OpenSearch ドメインにログを保存しており、SRE チームが全リージョンのログを一元的にモニタリングしたい場合。単一のダッシュボードから全リージョンのアプリケーションログを横断的に分析でき、グローバルな障害の影響範囲把握と根本原因の特定が迅速化。

🏢 マルチリージョン・マルチアカウント統合分析

大規模な組織で各事業部門が異なるアカウントとリージョンで OpenSearch を運用しており、セキュリティチームが組織全体のセキュリティログを統合的に分析したい場合。クロスアカウント + クロスリージョンを組み合わせ、グローバルな脅威検出が可能に。

🔄 DR サイトのデータ検証

プライマリリージョンと DR リージョンの両方に OpenSearch ドメインを配置し、DR サイトのデータ整合性を日常的に検証したい場合。単一の UI からプライマリと DR のデータを比較分析でき、フェイルオーバー時のデータ整合性を継続的に監視可能。

実装例: グローバルオブザーバビリティ

Bash 各リージョンのドメインを統合 
# 各リージョンのドメインを東京リージョンの OpenSearch UI に統合
aws opensearch update-application \
    --id <app-id> \
    --data-sources '[
        {"dataSourceArn": "arn:aws:es:us-east-1:<account-id>:domain/prod-us", "dataSourceDescription": "US East Production"},
        {"dataSourceArn": "arn:aws:es:eu-west-1:<account-id>:domain/prod-eu", "dataSourceDescription": "EU West Production"},
        {"dataSourceArn": "arn:aws:es:ap-northeast-1:<account-id>:domain/prod-apac", "dataSourceDescription": "APAC Production"}
    ]'

OpenSearch UI のクロスリージョンデータアクセス機能自体に追加料金は発生しない。ただし、以下の料金が適用される。

項目 料金
クロスリージョンデータアクセス機能追加料金なし
