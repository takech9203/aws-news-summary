AWS Entity Resolution

🔗 高度なリアルタイムマッチングに対応

2026-07-22
Advanced Real-Time Matching

📌 概要

AWS Entity Resolution が高度なマッチングワークフローを通じたリアルタイムマッチングに対応。 複雑なルールセットを使ったレコードのマッチングを、GenerateMatchId API 経由でミリ秒単位で実行できるようになりました。

AWS Entity Resolution は、複数のアプリケーション、チャネル、データストアに分散したレコードを、機械学習の専門知識なしでマッチング・リンク・拡張するサービスです。 今回のアップデートは、不正検知・リアルタイムのアカウント照会・Web サイトのパーソナライゼーションなど、 低レイテンシと高精度の両方を必要とするユースケースを対象としています。 別途マッチング用インフラを維持したりアプリケーションを再設計したりせずに、リアルタイムで結果を得られる点が主要な価値です。

❌ アップデート前の課題

  • リアルタイムマッチングは単純なルールベースのワークフローのみ
  • 高度なルールセットはバッチ処理限定で、処理に数分〜数時間
  • 高度なロジックとリアルタイムの両立には、別途マッチング用インフラの構築・維持が必要
➡

✅ アップデート後の改善

  • 高度なルールセットのマッチングをミリ秒単位でリアルタイム実行
  • Exact / ExactManyToMany と AND/OR ロジックをリアルタイムで利用可能
  • 新エンドポイント追加やアプリ移行なしで、既存の GenerateMatchId API をそのまま活用

アプリケーションが GenerateMatchId API へレコードを送信すると、リアルタイムマッチングを有効化した高度なマッチングワークフローが複雑なルールセットを評価し、Match ID をミリ秒単位で同期的に返却します。

⚡ 主要機能

1. 高度なルールセットによるリアルタイムマッチング

  • 複雑なルールセットを使用したマッチングをミリ秒単位で実行
  • バッチ処理でのみ利用できた高度なルールセットを、リアルタイム処理でも利用可能に
  • 数分から数時間かかっていた処理をリアルタイムに短縮

2. 柔軟なマッチング演算子とロジック

  • Exact (完全一致) および ExactManyToMany (多対多の完全一致) 演算子をサポート
  • AND / OR ロジックを組み合わせた高度なマッチング条件を定義可能
  • 不正検知やアカウント照会など、精度が求められるユースケースに対応

3. 既存 API の活用による容易な導入

  • enableRealTimeMatching パラメータを true に設定するだけで有効化
  • 既存の GenerateMatchId API をそのまま呼び出し
  • 新しいエンドポイントの追加やアプリケーションの移行は不要

🔧 技術仕様

対応する演算子とロジック

項目詳細
演算子Exact (完全一致)、ExactManyToMany (多対多の完全一致)
論理演算AND / OR の組み合わせ
有効化パラメータenableRealTimeMatching (boolean)
呼び出し APIGenerateMatchId
レイテンシミリ秒単位

API 変更履歴 (2026/07/21)

以下の 3 つの API メソッドに resolutionTechniques 配下の enableRealTimeMatching (boolean) パラメータが追加されました。

→CreateMatchingWorkflow: ワークフロー作成時にリアルタイムマッチングを有効化
→UpdateMatchingWorkflow: 既存ワークフロー設定を更新して有効化
→GetMatchingWorkflow: 設定として enableRealTimeMatching の値を取得

ワークフロー設定例

JSON Matching Workflow 設定 
{
  "workflowName": "customer-match-workflow",
  "inputSourceConfig": [
    {
      "inputSourceARN": "arn:aws:glue:us-east-1:123456789012:table/db/customers",
      "schemaName": "customer-schema"
    }
  ],
  "resolutionTechniques": {
    "resolutionType": "RULE_MATCHING",
    "ruleBasedProperties": {
      "attributeMatchingModel": "MANY_TO_MANY",
      "rules": [
        {
          "ruleName": "email-phone-match",
          "matchingKeys": ["email", "phone"]
        }
      ]
    },
    "enableRealTimeMatching": true
  }
}

🛠️ 設定方法

前提条件

✓AWS Entity Resolution が利用可能なリージョンでアカウントを利用できること
✓スキーママッピングと入力データソース (AWS Glue テーブルなど) が構成済みであること
✓マッチングワークフローを作成・更新するための IAM 権限を保有していること
STEP 1

リアルタイムマッチングを有効化したワークフローを作成

Bashcreate-matching-workflow
aws entityresolution create-matching-workflow \
  --workflow-name customer-match-workflow \
  --input-source-config file://input-source.json \
  --resolution-techniques '{"resolutionType":"RULE_MATCHING","enableRealTimeMatching":true,"ruleBasedProperties":{"attributeMatchingModel":"MANY_TO_MANY","rules":[{"ruleName":"email-phone-match","matchingKeys":["email","phone"]}]}}' \
  --role-arn arn:aws:iam::123456789012:role/EntityResolutionRole
STEP 2

既存ワークフローでリアルタイムマッチングを有効化する場合

Bashupdate-matching-workflow
aws entityresolution update-matching-workflow \
  --workflow-name customer-match-workflow \
  --input-source-config file://input-source.json \
  --resolution-techniques '{"resolutionType":"RULE_MATCHING","enableRealTimeMatching":true,"ruleBasedProperties":{"attributeMatchingModel":"MANY_TO_MANY","rules":[{"ruleName":"email-phone-match","matchingKeys":["email","phone"]}]}}' \
  --role-arn arn:aws:iam::123456789012:role/EntityResolutionRole
STEP 3

GenerateMatchId API でリアルタイムマッチングを実行 (新しいエンドポイントは不要)

Bashgenerate-match-id
aws entityresolution generate-match-id \
  --workflow-name customer-match-workflow \
  --records file://records.json

💡 メリット

📈 ビジネス面

✓リアルタイムな意思決定: 不正検知やアカウント照会で即座にエンティティを解決
✓顧客体験の向上: リアルタイムに顧客を識別し最適な体験を提供
✓導入コストの低減: 別途マッチング用インフラの構築・維持が不要

⚙️ 技術面

✓低レイテンシと高精度の両立: 高度なルールの精度を保ちミリ秒レスポンス
✓既存資産の活用: 既存 API をそのまま利用でき再設計が不要
✓シンプルな有効化: パラメータを true にするだけで利用開始

⚠️ デメリット・制約事項

制限事項

!サポート演算子は Exact / ExactManyToMany で、AND / OR ロジックとの組み合わせで構成
!利用可能リージョンは AWS Entity Resolution が提供されているリージョンに限られる
!利用には enableRealTimeMatching の明示的な有効化が必要

考慮すべき点

!ルールセットの設計はマッチング精度に直結するため、事前に十分検証することが望ましい
!リアルタイム処理とバッチ処理でスループット・コスト特性が異なるため、ユースケースに応じた選択が必要

🎯 ユースケース

1. 不正検知

シナリオ: 金融機関が取引申請時の顧客情報を既存プロファイルとリアルタイム照合し、なりすましや重複アカウントの兆候を検知。

実装: GenerateMatchId API に取引申請レコードを送信し、Exact / ExactManyToMany と AND/OR ロジックで既存顧客との一致をミリ秒判定。

効果: 取引フローを止めることなく、リアルタイムで不正の兆候を検知し迅速に対応。

2. リアルタイムのアカウント照会

シナリオ: コンタクトセンターで、問い合わせ中の顧客情報を複数システムの既存レコードと即座に突き合わせ、統合顧客ビューを表示。

実装: enableRealTimeMatching を有効化したワークフローに顧客の識別情報を送信し、関連する Match ID を同期取得。

効果: オペレーターが待ち時間なく顧客を特定でき、応対品質と処理速度が向上。

3. Web サイトのパーソナライゼーション

シナリオ: EC サイトが訪問者の識別情報から既存顧客プロファイルをリアルタイム解決し、パーソナライズしたコンテンツやレコメンドを提示。

実装: 訪問者のリクエスト時に GenerateMatchId API を呼び出し、高度なルールセットで Match ID をミリ秒取得しコンテンツ表示に反映。

効果: ページ表示を遅延させることなく、リアルタイムでパーソナライズされた体験を提供。
