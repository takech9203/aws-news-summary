Amazon CloudFront

🔐 Viewer mTLS パススルーモード

クライアント証明書をオリジンに転送し、既存の mTLS 検証インフラをそのまま活用

📅 2026-05-14

📋 概要

Amazon CloudFront が Viewer mTLS 認証のパススルーモードをサポート。CloudFront がクライアント証明書の検証を行わず、クライアント証明書をそのままオリジンに転送して、オリジン側で認証を実行できるようになった。

❌ Before

  • オリジンに既存の mTLS 検証インフラがあっても CloudFront 側にトラストストア設定が必要
  • 信頼する CA 証明書を CloudFront のトラストストアにアップロードが必要
  • 独自の証明書検証ロジックとの二重検証が発生

✅ After

  • トラストストア設定なしにクライアント証明書チェーン全体をオリジンに転送可能
  • オリジンの既存 mTLS 検証インフラをそのまま活用
  • Connection Functions で証明書データの検査・変換も利用可能
  • キャッシュ無効化でエンドツーエンド認証を保証

⚡ 主要機能

🔓 パススルーモード

CloudFront がクライアント証明書の検証を行わず、オリジンに転送する新しい mTLS モード。トラストストア設定不要。ViewerMtlsConfig の Mode に passthrough を指定して有効化。

📜 完全な証明書チェーン転送

クライアントの完全な証明書チェーン (中間 CA 証明書を含む) をオリジンに転送。オリジン側で自由に証明書検証ロジックを実行可能。

🚫 キャッシュの自動無効化

パススルーモードではキャッシュが自動的に無効化。すべてのリクエストがオリジンに到達し、エンドツーエンドの認証を保証。

🔗 Connection Functions との連携

Connection Functions による証明書データの検査・変換がパススルーモードでも利用可能。証明書属性の抽出やヘッダーへの変換をエッジで実行。

  --if-match <ETAG>

💡 ユースケース

🏦 既存の mTLS インフラを持つ金融機関

シナリオ: 金融機関が既にオンプレミスで厳格な mTLS 検証インフラ (カスタム CRL、HSM ベースの検証) を運用しており、CloudFront を CDN として導入したいが、証明書検証ロジックの移行は困難。

効果: 既存の検証インフラを変更せずに CloudFront の DDoS 防御、WAF 連携、グローバルエッジネットワークを活用可能。

📡 IoT デバイス認証

シナリオ: IoT デバイスがクライアント証明書を使用してバックエンドに接続する環境で、デバイス証明書の有効性をデバイス管理プラットフォームと連携して検証する必要がある。

効果: デバイス証明書の検証をデバイス管理プラットフォームと連携したオリジンで実行しつつ、CloudFront のグローバルエッジを通じて接続の最適化が可能。

🔄 Connection Functions による証明書データ変換

シナリオ: オリジンが特定のヘッダー形式でクライアント証明書情報を期待しており、証明書チェーンからの属性抽出をエッジで実行したい。

効果: オリジンアプリケーションの変更なしに、エッジで証明書データを適切な形式に変換して転送可能。

JavaScript Connection Function での証明書属性抽出例 
// Connection Function でクライアント証明書の属性を抽出してヘッダーに設定
function handler(event) {
  var cert = event.viewer.tlsConnection.clientCertificate;
  // 証明書の Subject DN をカスタムヘッダーとして追加
  event.request.headers['x-client-cert-subject'] = { value: cert.subjectDN };
  return event.request;
}

⚖️ メリット・デメリット

✅ メリット

  • 移行コスト削減: 既存の mTLS 検証インフラを変更せずに CloudFront を導入可能
  • 運用簡素化: CloudFront 側でのトラストストア管理が不要
  • 追加コストなし: 通常の CloudFront 料金のみ
  • 柔軟な検証: カスタム CRL、OCSP、証明書属性チェックなど独自ロジックを維持
  • エンドツーエンド認証: すべてのリクエストがオリジンで認証

⚠️ デメリット・制約

  • キャッシュ無効: レスポンスキャッシュによる高速化は利用不可
  • オリジン負荷増加: すべてのリクエストがオリジンに到達
  • エッジでの防御なし: 不正な証明書もオリジンまで到達
  • レイテンシ: CDN のキャッシュメリットが限定的
  • スケーラビリティ: オリジンの可用性とスケーラビリティが重要

📝 まとめ

Amazon CloudFront の Viewer mTLS パススルーモードは、既存の mTLS 検証インフラを維持しながら CloudFront を導入したい顧客にとって重要なアップデート。トラストストア設定なしにクライアント証明書をオリジンに転送でき、追加コストも不要。金融機関や IoT デバイス認証など、独自の証明書検証ロジックを持つ環境で特に有用であり、CloudFront 導入のハードルを下げる機能と言える。
