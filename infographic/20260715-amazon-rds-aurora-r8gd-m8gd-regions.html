📌 概要

Amazon RDS および Amazon Aurora は、AWS Graviton4 ベースの R8gd インスタンスを新たに 12 リージョン、 M8gd インスタンスを新たに 6 リージョンで利用可能にしました。 これらは Aurora PostgreSQL、RDS for PostgreSQL / MySQL / MariaDB において Optimized Reads に対応しています。

R8gd / M8gd は、ローカル NVMe ベースの SSD ブロックストレージを搭載した Graviton4 世代のインスタンスです。 Aurora PostgreSQL において R6g 比で最大 165% 高いスループットと 最大 120% 優れた価格性能比を実現します。 Optimized Reads は一時テーブルなどのエフェメラルデータをローカルストレージに格納することで、 ネットワークストレージへのアクセスを削減し、クエリレイテンシーを改善します。

❌ アップデート前の課題
  • R8gd / M8gd の利用可能リージョンが限定され、多くの地域で最新 Graviton4 世代と Optimized Reads の恩恵を受けられなかった
  • 対象外リージョンでは一時テーブルなどがネットワークストレージ経由でアクセスされ、複雑なクエリのレイテンシーが高くなる場合があった
  • データ所在地要件により特定リージョンでの稼働が求められるワークロードでは、旧世代インスタンスを選ばざるを得なかった
➜
✅ アップデート後の改善
  • R8gd を追加 12 リージョン、M8gd を追加 6 リージョンで利用可能に
  • より多くのリージョンでローカル NVMe SSD による Optimized Reads を活用し、クエリレイテンシーを改善できる
  • R6g 比 最大 165% のスループット向上と最大 120% の価格性能比改善を、より広い対応リージョンで享受できる

⚡ 主要機能

🧠 R8gd インスタンスの追加リージョン対応 (12 リージョン)
  • AWS Graviton4 プロセッサとローカル NVMe SSD ストレージを搭載したメモリ最適化インスタンス
  • Aurora PostgreSQL で R6g 比 最大 165% のスループット向上、最大 120% の価格性能比改善
  • Optimized Reads によりクエリレイテンシーとインデックス再構築を高速化
⚙️ M8gd インスタンスの追加リージョン対応 (6 リージョン)
  • AWS Graviton4 プロセッサとローカル NVMe SSD ストレージを搭載した汎用インスタンス
  • メモリと vCPU のバランスが求められるワークロードに適合
  • R8gd と同様に Optimized Reads に対応
🚀 Optimized Reads による性能向上
  • 一時テーブルなどのエフェメラルデータをローカル NVMe SSD に格納
  • ネットワークストレージへのアクセスを削減し、複雑なクエリのレイテンシーを改善
  • Aurora PostgreSQL の I/O-Optimized 構成では、バッファキャッシュからエビクトされたページをローカルにキャッシュしてキャッシュ容量を拡張

🔌 API 変更履歴

今回のアップデートはインスタンスタイプの対応リージョン拡大であり、新規 API メソッドの追加はありません。 既存の ModifyDBInstance および CreateDBInstance API でインスタンスクラスを指定して利用できます。

🛠️ 設定方法

前提条件

  • 対象リージョンで Amazon RDS または Amazon Aurora を利用可能であること
  • 対応エンジン (Aurora PostgreSQL, RDS for PostgreSQL / MySQL / MariaDB) の対応バージョンを使用していること
  • AWS Management Console、AWS CLI、または SDK にアクセスできること

ステップ 1: 新規インスタンスの作成

Bash R8gd インスタンスクラスを指定して新規作成 
aws rds create-db-instance \
  --db-instance-identifier my-db-instance \
  --db-instance-class db.r8gd.2xlarge \
  --engine postgres \
  --allocated-storage 100 \
  --master-username admin \
  --master-user-password <password>

ステップ 2: 既存インスタンスの変更

Bash 既存インスタンスを M8gd に変更 
aws rds modify-db-instance \
  --db-instance-identifier my-db-instance \
  --db-instance-class db.m8gd.2xlarge \
  --apply-immediately

--apply-immediately を指定すると即時に、指定しない場合は次回のメンテナンスウィンドウで適用されます。

⚖️ メリットと制約事項

👍 メリット

ビジネス面

  • コスト効率の向上: R6g 比 最大 120% の価格性能比改善で、同一予算でより高い処理能力
  • 対応リージョンの拡大: データ所在地やレイテンシー要件を満たしつつ最新世代を選択可能
  • 移行の容易さ: 既存インスタンスのクラス変更のみで導入可能

技術面

  • スループット向上: R6g 比 最大 165% 向上で高負荷ワークロードに対応
  • クエリレイテンシーの改善: Optimized Reads でエフェメラルデータをローカル NVMe SSD に格納
  • キャッシュ容量の拡張: Aurora PostgreSQL I/O-Optimized 構成でローカルストレージをキャッシュ活用

⚠️ 制約・考慮点

制限事項

  • Optimized Reads の対応エンジンは Aurora PostgreSQL, RDS for PostgreSQL / MySQL / MariaDB に限定
  • ローカル NVMe SSD 上のデータはエフェメラル (一時的) で、永続化には利用できない
  • エンジンバージョンによっては非対応の場合があり、事前確認が必要

考慮すべき点

  • インスタンスクラス変更時にダウンタイムや再起動が発生する場合があり、メンテナンスウィンドウを考慮
  • 性能向上の効果はワークロード特性 (一時テーブルの利用頻度、クエリの複雑さ) に依存
  • 各リージョン・エンジンバージョンでの提供状況は料金ページとドキュメントで確認

🎯 ユースケース

1. 複雑な分析クエリの高速化

シナリオ: 大量の一時テーブルを生成する分析クエリを実行する PostgreSQL ワークロードで、クエリレイテンシーが課題となっている。

💡 Optimized Reads により一時テーブルがローカル NVMe SSD に格納され、ネットワークストレージへのアクセスが削減されてクエリレイテンシーが改善
2. コスト最適化を伴う性能向上

シナリオ: R6g インスタンスで稼働する Aurora PostgreSQL クラスターのコストと性能の両立を図りたい。

💡 R8gd への移行により最大 165% のスループット向上と最大 120% の価格性能比改善を実現し、同一予算でより高い処理能力を獲得
3. データ所在地要件を満たすワークロード

シナリオ: 欧州 (アイルランド、ロンドン) や南米 (サンパウロ) など特定リージョンでのデータ保持が求められるワークロードで、最新世代インスタンスを利用したい。

💡 今回のリージョン拡大により対象リージョンで R8gd / M8gd を選択でき、要件を満たしつつ性能を向上

💰 料金

R8gd および M8gd インスタンスの料金は、インスタンスタイプ、リージョン、エンジン、および課金モデル (オンデマンド / リザーブドインスタンス) により異なります。ローカル NVMe SSD ストレージは インスタンス料金に含まれます。正確な料金は Amazon RDS および Amazon Aurora の料金ページを参照してください。
