🔍 Web Answer on Amazon Bedrock AgentCore

1 回のツール呼び出しで、最新の Web ソースに基づく引用付きの合成回答を返すマネージドツール
📅 リリース日: 2026 年 11 月 5 日

📋 概要

Amazon Bedrock AgentCore の新しいマネージドツール「Web Answer」が一般提供 (GA) されました。自然言語の質問を 1 回のツール呼び出しで受け取り、最新の Web ソースに基づいて合成された引用 (citation) 付きの回答を返します。AgentCore Gateway のターゲットとして追加するだけで、標準の MCP ツールとしてエージェントから呼び出せます。

2026 年 6 月リリースの Web Search が「Web コンテンツを見つける」機能だったのに対し、Web Answer は「完成した引用付きの回答を届ける」機能です。Web Answer 自身がエージェント的に動作し、複数の検索を並行して計画・実行し、十分な証拠が集まった時点で回答を生成します。

❌ アップデート前の課題
  • 検索、ページ取得、合成、引用抽出のパイプラインを自前で構築・保守する必要があった
  • Web Search はランク付けされた検索結果を返すため、エージェント側モデルが生の検索結果を処理し、トークン消費と複雑性が増加
  • 回答の根拠を検証する引用管理を開発者自身が実装する必要があった
✅ アップデート後の改善
  • 1 回のツール呼び出しで合成済み・引用付きの完成した回答を取得
  • Web Answer 自身が検索を計画・並行実行・自律判断するため、生の検索結果の処理が不要
  • ドメイン包含 / 除外リストや公開日フィルタで管理者がソースを統制
  • IAM 認証と AWS 内完結のデータパス (データエグレスなし) でセキュア

エージェントは AgentCore Gateway 経由で Web Answer を MCP ツールとして 1 回呼び出すだけで、検索計画、並行検索、ページ読解、回答合成がすべて AWS 内部で実行され、引用付きの回答が返されます。質問が第三者の検索エンジンに送信されることはありません。

⚡ 主要機能

🤖 ビルトインのエージェント型 Web 検索
  • 1 回のツール呼び出しで、質問をカバーする複数の検索を並行実行
  • 関連ページを読み込んで根拠を収集し、証拠が十分と判断した時点で回答を生成
  • 質問ごとに新しい検索を実行するため、常に最新のソースに基づく回答を取得可能
📝 引用付きの回答
  • 回答はインライン引用マーカー付きの Markdown として返却 (形式: [[N](url)])
  • 引用元 URL の構造化リスト (structuredContent) も同時に返却され、プログラムによる検証が可能
  • コンプライアンスレビューで主張の根拠を検証可能
🎛️ ドメイン・日付・ロケーション制御 (コネクタ 1.1.0 以降)
  • ターゲットレベルのドメイン包含 / 除外リスト (各最大 50 ドメイン)。エージェントからは参照不可で、すべてのリクエストに強制適用
  • リクエストレベルのドメインフィルタと公開日フィルタ (ISO-8601 形式、UTC 解釈)
  • リクエストレベルのフィルタはターゲットレベルの設定を上書きできず、管理者の統制が常に優先
  • userLocation.country (ISO 3166-1 alpha-2) による国単位の結果調整
🔒 プライバシーとセキュリティ
  • 質問は AWS インフラストラクチャ内のみで処理 (データエグレスゼロ)。第三者の検索エンジンには送信されない
  • Amazon が構築・運用する Web インデックスを検索し、Amazon Bedrock 上のモデルで回答を合成
  • IAM 認証のため、外部 API キーのプロビジョニングやローテーションが不要
  • 地理的クロスリージョン推論により、データ処理は地理的境界 (US、EU、APAC など) 内のリージョンに留まる
🚀 ゼロインフラストラクチャ管理とフレームワーク非依存
  • 検索 API、モデルエンドポイント、アウトバウンド認証情報のプロビジョニングが不要
  • Strands Agents、LangChain、LangGraph、CrewAI など、MCP 互換のあらゆるクライアントから利用可能
  • 検索・読解・回答品質の改善は、アップグレードやマイグレーションなしで自動的に反映

📥 入力スキーマ (tools/call)

フィールド型必須説明
querystringはい回答対象の質問または検索クエリ。1〜30,000 文字
filters.domainFilter.includearrayいいえ包含するドメイン。1〜50 件 (バージョン 1.1.0 以降)

⚖️ ドメインフィルタの合成ルール

▸ターゲットレベルまたはリクエストレベルのいずれかの除外リストに含まれるドメインは除外される (マージ後の除外リストは最大 100 ドメイン)
▸両方に包含リストが設定されている場合、両方に含まれるドメインのみが使用される。共通ドメインがない場合はバリデーションエラー
▸publishedDateFilter.from が to より後の場合はバリデーションエラー

🛠️ 設定方法

前提条件: ① AgentCore Gateway が作成済み ② Gateway サービスロールに Web Answer コネクタの呼び出しを許可する IAM 権限を設定済み ③ エージェント (MCP クライアント) が Gateway エンドポイントに接続可能

1Web Answer ターゲットを Gateway に追加

Bash AWS CLI でターゲットを作成 
aws bedrock-agentcore-control create-gateway-target \
  --gateway-identifier <gateway-id> \
  --name web-answer-target \
  --target-configuration '{
    "mcp": {
      "connector": {
        "connectorId": "web-answer",
        "parameterValues": {
          "domainFilter": {
            "include": ["docs.example.com"],
            "exclude": ["forum.example.com"]
          }
        }
      }
    }
  }'

既存の AgentCore Gateway に connectorId: "web-answer" を指定してターゲットを追加します。Gateway がツールスキーマのスナップショットを取得し、統合をプロビジョニングします。parameterValues.domainFilter はターゲットレベルのドメインフィルタ設定です (任意)。

2エージェントからツールを検出

Python tools/list でツールを検出 
# MCP クライアントで Gateway エンドポイントのツール一覧を取得
tools = await session.list_tools()
web_answer_tool = next(
    t for t in tools.tools if t.name.endswith("___WebAnswer")
)

<target-name>___WebAnswer という名前のツールが入力スキーマとともに検出されます。Gateway がセマンティック検索を使用している場合はリストの順序に依存せず、名前の末尾 ___WebAnswer で一致させます。

3質問を送信して引用付き回答を取得

Python tools/call で質問を送信 
result = await session.call_tool(
    web_answer_tool.name,
    {
        "query": "バーゼル III における CET1 比率の最低要件は?",
        "filters": {
            "publishedDateFilter": {"from": "2024-01-01"}
        }
    }
)
print(result.content[0].text)  # 引用マーカー付き Markdown 回答

Gateway はサービスロールでバックエンドに認証し、ターゲット設定を適用します。Web Answer が検索・読解・合成を実行し、引用付きの回答を返します。

💡 メリット

💼 ビジネス面

✓開発工数の削減: 検索 API 呼び出し、結果フィルタリング、ページ整形、合成プロンプト、引用抽出のパイプライン構築・保守が不要になり、1 回の API 呼び出しに集約
✓予測可能なコスト: トークン数ではなくツール呼び出し単位の課金のため、回答の長短にかかわらずコストが一定で予算計画が容易
✓コンプライアンス対応: すべての回答に引用が付くため、金融・医療・公共部門などの規制業界でレビュー担当者が主張の根拠を検証可能

⚙️ 技術面

✓運用負荷ゼロ: 検索 API、モデルエンドポイント、外部認証情報の管理が不要。品質改善も自動的に反映
✓エージェントモデルの負荷軽減: 生の検索結果を処理する必要がなく、トークン消費とレイテンシーの要因を削減
✓セキュアなデータパス: IAM 認証、AWS 内で完結する処理、第三者検索エンジンへの送信なし。クエリと結果は保存されず、モデル学習にも使用されない

⚠️ デメリット・制約事項

🚧 制限事項

✗利用可能リージョンは米国東部 (バージニア北部) us-east-1 のみ (今後拡大予定)
✗リリース時点では英語のみ対応 (今後多言語対応予定)
✗query は最大 30,000 文字、ドメインフィルタは各リスト最大 50 ドメイン
✗結果の大量抽出・保存・複製、および競合するインデックスやデータベースの構築は利用規約で禁止

🤔 考慮すべき点

▸エンドユーザーに回答を表示する際は、提供されたソース引用とリンクを保持・表示する必要がある (Acceptable Use)
▸専門的助言の代替にはならないため、規制対象の文脈では出力を利用する前にレビューが必要
▸エージェント自身のモデルで検索結果を推論させたい場合 (回答の構成を自分で制御したい場合) は、Web Answer ではなく Web Search ツールが適している
▸地理的クロスリージョン推論を使用するため、データ処理が地理的境界内の複数リージョンで行われる点をデータレジデンシー要件と照合する必要がある

🏦 ユースケース 1: 規制業界の Q&A (銀行・医療・公共部門)

銀行のコンプライアンス部門が、規制や基準の変更に関する質問に引用付きで回答するエージェントを構築。

Python公式ドメインに限定した質問
result = await session.call_tool(tool_name, {
    "query": "2026 年のバーゼル III 最終化で変更された自己資本要件は?",
    "filters": {
        "domainFilter": {"include": ["bis.org", "fsa.go.jp"]},
        "publishedDateFilter": {"from": "2025-01-01"}
    }
})
✅ 効果: 信頼できる公式ドメインに限定した引用付き回答により、コンプライアンスレビュー担当者がすべての主張を情報源で検証できる。
🎧 ユースケース 2: カスタマーサポートエージェント

外部の変化する情報 (公的な要件、サードパーティ製品、交通・市場状況など) についてリアルタイムに回答。

Python国コードを指定した質問
result = await session.call_tool(tool_name, {
    "query": "日本からドイツへの渡航に必要な入国要件は?",
    "userLocation": {"country": "JP"}
})
# result.structuredContent.answer[0].citations を顧客に提示
✅ 効果: サポート担当者が顧客に情報源を提示でき、最新の公開情報に基づく信頼性の高い回答を提供できる。
🔄 ユースケース 3: 大規模エージェントワークフロー内の事実確認サブタスク

マルチステップのエージェントワークフローの中で、1 つの事実確認ステップだけ Web 上の最新情報が必要になるケース。

PythonStrands Agents での利用例
# Strands Agents などのフレームワークで Gateway を MCP ツールとして登録
# エージェントがワークフロー内の事実確認で自律的に Web Answer を呼び出す

📝 まとめ

Web Answer は、エージェントに「引用付きの完成した回答」を 1 回のツール呼び出しで提供するマネージドツールであり、検索・取得・合成パイプラインの構築・保守を不要にします。IAM 認証、AWS 内で完結するデータパス、管理者によるドメイン統制により、規制業界でも採用しやすい設計です。

AgentCore Gateway を利用中であればターゲット追加だけで導入可能なため、まずは us-east-1 でエージェントワークフロー内の事実確認ステップへの適用を検証することを推奨します。
