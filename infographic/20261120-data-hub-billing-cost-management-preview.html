💰 Data Hub (プレビュー)

📅 リリース日: 2026 年 11 月 20 日
🌎 米国東部 (バージニア北部) リージョン

コスト・使用状況データに対する SQL ベースのマネージドデータレイヤー。AWS FinOps Agent がリソースレベル・時間単位のコストに関する質問に回答できるようになります。

📝 概要

Data Hub は、コスト・使用状況データに対する SQL ベースのマネージドデータレイヤーです。プレビュー期間中は AWS FinOps Agent 向けに提供され、コスト変動の原因リソースの特定、チームやコスト配分タグ別の支出内訳、リソース単位のコスト・使用状況の時間単位での推移の把握が可能になります。

データのプロビジョニング、毎日の更新、AWS マネージドストレージへの保存、新しいサービス・コミットメント・課金タイプ登場時のスキーマ維持は、すべて AWS が自動で実施します。

❌ Before: アップデート前の課題
  • FinOps Agent は Cost Explorer API 経由のため、サービス・アカウントレベルの質問にしか回答できなかった
  • リソースレベルの分析には CUR 2.0 を S3 にエクスポートし、Athena や独自データウェアハウスで基盤を構築・保守する必要があった
  • 新サービスや課金タイプの追加のたびに、スキーマやパイプラインの保守が利用者側の負担だった
✅ After: アップデート後の改善
  • パイプラインの構築・保守なしに、FinOps Agent がリソースレベル・時間単位のコストの質問に回答
  • プロビジョニング・毎日の更新・スキーマ維持を AWS が行うマネージドなデータレイヤーを利用可能
  • 管理アカウントでのセットアップにより、Organizations 配下の全アカウントを単一データセットでカバー

AWS FinOps Agent は、リソースレベルや時間単位の詳細が必要な質問には Data Hub のデータセットを SQL でクエリし、サービス・アカウントレベルの質問には従来どおり Cost Explorer API を使用します。データセットへのデータ投入と更新は AWS が自動的に行います。

⚙️ 主要機能

🗄️ SQL ベースのマネージドデータレイヤー
  • エージェント向けにコスト・使用状況データへの SQL クエリアクセスを提供
  • 13 か月分の時間単位・リソースレベルのデータを保持
  • リソース識別子とコスト配分タグを含む CUR 2.0 スキーマ (cost_usage) に準拠
🔄 フルマネージドなデータ運用
  • AWS がデータのプロビジョニングと毎日の更新を実施
  • データは AWS マネージドストレージに保存
  • 新しいサービス・コミットメント・課金タイプが登場しても AWS がスキーマを維持
🤖 AWS FinOps Agent との連携 (プレビュー期間中)
  • コスト変動の背後にある個々のリソースを特定
  • チームやコスト配分タグ別に支出を内訳表示
  • リソースのコストと使用状況の時間単位の変化を提示
🏢 AWS Organizations 対応
  • 管理アカウントで作成したデータセットは組織内の全アカウントをカバー
  • メンバーアカウントで作成したデータセットはそのアカウントのみをカバー
  • 委任管理者アカウントで組織全体のエージェントを実行でき、FinOps チームが管理アカウントの権限を持つ必要がない
🏷️ データセットのリソース管理
  • データセットは固有の ARN を持つ AWS リソースとして扱われる
  • タグ付け、アクセススコープの設定、削除が可能

メンバーアカウントのユーザーは、サービスコントロールポリシー (SCP) で bcm-data-hub:CreateDataset が拒否されていない限り、自身のアカウント用のデータセットを作成できます。

既存の AWS Data Exports との関係

✓Data Hub は既存の AWS Data Exports を読み取らず、変更もしない
✓既存の Data Exports は同じフィールド・値・配信方法で動作し続ける
✓S3 へのエクスポート、独自変換、AWS 外のデータとの結合、データウェアハウスや BI ツールへのロードには、引き続き AWS Data Exports を使用する

🛠️ 設定方法

前提条件

✓データセットを作成するユーザーに bcm-data-hub:CreateDataset を含む Data Hub の権限があること
✓エージェントロールにデータセットの読み取り権限があること
✓組織全体をカバーする場合は、AWS Organizations の管理アカウントでデータセットを作成すること

手順

1
データセットを作成する

Billing and Cost Management コンソールの Data Hub ページ、または AWS FinOps Agent のウィザードで作成します。

  • 組織全体のエージェント向け: 管理アカウントでデータセットを作成
  • 単一アカウントのエージェント向け: エージェントを実行するアカウントでデータセットを作成

⚠️ エージェントを作成してもデータセットは自動では作成されません。

2
エージェントをデータセットに接続する
  • 新規エージェント作成時: ウィザードで [Use Data Hub for this agent] を選択
  • 既存エージェント: エージェントの Data Hub タブで [Connect] を選択
3
組織全体で利用する場合のセットアップ
  • 管理アカウントで組織全体のエージェント向けのセットアップを行い、データセットを作成
  • 委任管理者アカウントで組織全体のエージェントを作成し、Data Hub 設定を有効化
  • エージェントが管理アカウントのデータセットをクエリし、組織内の全アカウントのデータに回答

💡 メリット

📈 ビジネス面
✓パイプライン構築・保守コストの削減: データエクスポートの設定や Athena などによる分析基盤の構築・運用が不要になり、FinOps チームはコスト最適化そのものに集中できる
✓コスト変動への迅速な対応: コスト増加の原因リソースを自然言語の質問から特定でき、調査時間を短縮できる
✓チャージバックの精緻化: コスト配分タグやリソース所有チーム別の支出内訳を容易に把握でき、部門別のコスト配賦を正確に行える
🔧 技術面
✓マネージドなスキーマ維持: 新しいサービス・コミットメント・課金タイプが追加されても AWS がスキーマを自動で維持
✓標準スキーマへの準拠: 公開済みの CUR 2.0 データディクショナリに準拠し、既存の CUR 2.0 の知識をそのまま活用できる
✓最小権限での組織運用: 委任管理者アカウントでエージェントを実行し、管理アカウントの権限なしで組織全体のコストを分析できる

⚠️ デメリット・制約事項

制限事項

✗プレビュー期間中、Data Hub をクエリできるのは AWS FinOps Agent のみ
✗プレビューで提供されるスキーマは cost_usage の 1 種類のみ
✗組織全体をカバーするデータセットを作成できるのは管理アカウントのみ (プレビュー期間中)
✗機能の利用は米国東部 (バージニア北部) リージョンのみ (データは全リージョンのコスト・使用状況をカバー)

考慮すべき点

⚠️プレビュー機能のため、一般提供 (GA) 時に仕様や料金が変更される可能性がある
⚠️データ保持期間は 13 か月。より長期の履歴分析には引き続き AWS Data Exports などの利用が必要
⚠️独自の変換処理、AWS 外のデータとの結合、BI ツールへの取り込みが必要な場合は従来どおり AWS Data Exports を使用
⚠️SCP で bcm-data-hub:CreateDataset を制御している場合は、ポリシーの見直しが必要になることがある

🎯 ユースケース

1. コスト急増の原因リソースの特定

シナリオ: 前月比で Amazon EC2 のコストが大幅に増加した。どのリソースが原因かを迅速に特定したい。

TextAWS FinOps Agent への質問例
「先月 EC2 のコストが増加した原因となったリソースを特定して、
時間単位の使用状況の変化を教えてください」

効果: 時間単位・リソースレベルのデータにより、エージェントがコスト変動の背後にある個々のリソースと増加のタイミングを特定し、調査時間を大幅に短縮できる。

2. コスト配分タグによるチーム別チャージバック

シナリオ: 複数チームが共有する AWS アカウントで、コスト配分タグに基づいてチームごとの支出を把握し、月次のチャージバックを行いたい。

TextAWS FinOps Agent への質問例
「コスト配分タグ team 別に今月の支出を内訳表示して、
各チームで最もコストの高いリソースを教えてください」

効果: CUR 2.0 スキーマに含まれるコスト配分タグを利用して、データパイプラインを構築することなくチーム別の支出内訳とチャージバックの根拠データを取得できる。

3. 組織全体のコスト分析を最小権限で実現

シナリオ: AWS Organizations で多数のアカウントを運用しており、FinOps チームに管理アカウントの権限を付与せずに組織全体のリソースレベルのコスト分析を行いたい。

Textセットアップ手順
1. 管理アカウントで組織全体をカバーするデータセットを作成
2. メンバーアカウントを委任管理者として登録
3. 委任管理者アカウントで組織全体のエージェントを作成し、
   Data Hub 設定を有効化

効果: FinOps チームは委任管理者アカウントのエージェント経由で組織内全アカウントのコストデータに質問でき、管理アカウントへのアクセス権限を最小化しつつガバナンスを維持できる。

💲 料金・利用可能リージョン

✓料金: プレビュー期間中、Data Hub は追加料金なしで利用可能。一般提供 (GA) 時の料金体系は現時点では未公表
✓リージョン: 米国東部 (バージニア北部) リージョンで利用可能。ただし、データセットは全リージョンのコスト・使用状況データをカバー

🔗 関連サービス・機能

AWS FinOps Agent: プレビュー期間中に Data Hub をクエリできるエージェント。Data Hub なしではサービス・アカウントレベルの質問に Cost Explorer API で回答する
AWS Data Exports (CUR 2.0): コスト・使用状況データを S3 にエクスポートする既存機能。独自変換や BI ツール連携には引き続きこちらを使用。Data Hub は既存の Data Exports に影響しない
AWS Cost Explorer: サービス・アカウントレベルのコスト可視化と分析を提供する機能
AWS Organizations: 管理アカウントと委任管理者アカウントを利用した組織全体のデータセット運用の基盤

📌 まとめ

Data Hub は、コストデータパイプラインの構築・保守なしに、リソースレベル・時間単位のコスト分析を AWS FinOps Agent 経由で実現するマネージドデータレイヤーです。

プレビュー期間中は無料で利用できるため、FinOps の実践に取り組む組織は、米国東部 (バージニア北部) リージョンでデータセットを作成し、エージェントによるリソースレベルのコスト分析を試すことを推奨します。既存の AWS Data Exports には影響しないため、現行の分析基盤と並行して安全に評価できます。
