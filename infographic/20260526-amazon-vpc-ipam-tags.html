Amazon VPC IPAM

📋 概要

Amazon VPC IP Address Manager (IPAM) が、IPAM プール割り当てに対するタグ付けをサポート。個々の IP アドレス割り当てに対して、他の AWS リソースと同じタグ付けワークフローを使用して整理、ガバナンス、アクセス制御を行うことが可能に。

❌ Before

  • プール割り当てにタグ付与不可
  • IAM/SCP でタグベースのアクセス制御不可
  • 大規模環境での IP 検索に手動対応
  • 環境別・チーム別の体系的管理手段なし

✅ After

  • AWS 標準タグ付けワークフローで付与可能
  • IAM/SCP でタグ条件による割り当てレベル制御
  • 全プール横断のタグベース検索・フィルタリング
  • 追加コストなし、全リージョン対応

⚡ 主要機能

🏷️ プール割り当てへのタグ付与

  • 割り当て作成時にタグを指定可能
  • 既存の割り当てに後からタグを追加・変更可能
  • AWS 標準のタグ付けワークフローと一貫した操作

🔑 タグベースのアクセス制御

  • IAM ポリシーの条件キーとしてタグを参照可能
  • SCP でのタグ条件による組織レベルのガバナンス
  • 環境・チーム・プロジェクト等の属性に基づく細粒度制御

🔍 タグによる検索・フィルタリング

  • すべての IPAM プールにわたるタグベースの横断検索
  • 大規模マルチアカウント環境での IP 範囲の迅速な特定
  • 複数のタグキー・バリューの組み合わせフィルタリング

🔧 技術仕様

項目 詳細
対象リソース IPAM プール割り当て (pool allocations)
タグ付与タイミング 作成時および作成後
IAM 条件キー aws:ResourceTag、aws:RequestTag、aws:TagKeys
SCP サポート タグ条件によるアクセス制御に対応
追加コスト なし
タグ制限 リソースあたり最大 50 タグ / キー最大 128 文字 / バリュー最大 256 文字

対応する IAM 条件キー

条件キー 用途
aws:ResourceTag/${TagKey} リソースに付与されたタグに基づくアクセス制御
aws:RequestTag/${TagKey} リクエスト時に指定されたタグに基づく制御
aws:TagKeys リクエストに含まれるタグキーの制限

⚙️ 設定方法

前提条件

✓VPC IPAM が有効化されていること
✓IPAM プールが作成済みであること
✓IAM ポリシーまたは SCP を管理する権限があること
Bash Step 1: 割り当て作成時にタグを付与 
aws ec2 allocate-ipam-pool-cidr \
    --ipam-pool-id ipam-pool-0123456789abcdef0 \
    --netmask-length 24 \
    --tag-specifications 'ResourceType=ipam-pool-allocation,Tags=[{Key=Environment,Value=Production},{Key=Team,Value=NetworkOps}]'
Bash Step 2: 既存の割り当てにタグを追加 
aws ec2 create-tags \
    --resources ipam-pool-alloc-0123456789abcdef0 \
    --tags Key=Environment,Value=Production Key=CostCenter,Value=CC-1234
JSON Step 3: タグベースの IAM ポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowProductionPoolAllocation",
            "Effect": "Allow",
            "Action": ["ec2:AllocateIpamPoolCidr"],
            "Resource": "arn:aws:ec2:*:*:ipam-pool/*",
            "Condition": {
                "StringEquals": {
                    "aws:RequestTag/Environment": "Production"
                }
            }
        },
        {
            "Sid": "DenyNonProductionTagOnProductionPool",
            "Effect": "Deny",
            "Action": ["ec2:AllocateIpamPoolCidr"],
            "Resource": "arn:aws:ec2:*:*:ipam-pool/ipam-pool-prod*",
            "Condition": {
                "StringNotEquals": {
                    "aws:RequestTag/Environment": "Production"
                }
            }
        }
    ]
}
JSON Step 4: SCP によるタグ強制 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "RequireEnvironmentTag",
            "Effect": "Deny",
            "Action": ["ec2:AllocateIpamPoolCidr"],
            "Resource": "*",
            "Condition": {
                "Null": {
                    "aws:RequestTag/Environment": "true"
                }
            }
        }
    ]
}
Bash Step 5: タグによる割り当ての検索 
aws ec2 get-ipam-pool-allocations \
    --ipam-pool-id ipam-pool-0123456789abcdef0 \
    --filters Name=tag:Environment,Values=Production

💡 ユースケース

🏭 ユースケース 1: 環境別アクセス制御

ネットワーク管理者が本番環境と開発環境の IP アドレスプールを管理しており、開発チームが誤って本番プールから IP を割り当てることを防止したい。

効果: 本番ネットワーキングロールのみが本番プールから割り当てを行い、開発チームは開発プールに限定される。環境間の IP アドレスの混在を防止し、本番環境の安定性を確保。

🏢 ユースケース 2: マルチアカウント IP 管理

100 以上のアカウントを持つ組織で、各事業部門に割り当てられた IP アドレス範囲を追跡し、特定のアカウントや事業部門の割り当て状況を迅速に把握したい。

効果: マルチアカウント環境で事業部門ごとの IP 使用状況を一覧化でき、キャパシティプランニングや IP アドレスの重複検出が容易に。

🔒 ユースケース 3: コンプライアンス・監査対応

PCI DSS や SOC 2 などのコンプライアンス要件に基づき、セグメント化されたネットワークの IP アドレス割り当てが適切に管理されていることを証明する必要がある。

効果: すべての IP アドレス割り当てに対してコンプライアンス関連タグの付与を強制し、監査時にネットワークセグメンテーションの証跡を提供可能。

⚖️ メリット・デメリット

✅ メリット

  • ガバナンス強化: 環境・チーム・プロジェクト別のアクセス制御
  • 運用効率向上: タグベース検索で管理時間削減
  • コスト管理改善: IP 使用量のプロジェクト別追跡
  • 細粒度制御: 割り当て単位の IAM/SCP 権限管理
  • 既存統合: AWS 標準タグと同じ操作で学習コスト低
  • スケーラブル: マルチアカウント横断検索

⚠️ 制約・注意点

  • リソースあたり最大 50 タグの制限
  • 既存割り当ての一括タグ付けは手動対応
  • タグ変更後のポリシー伝播時間を考慮
  • タグ命名規則の事前統一が必要 (大文字小文字区別あり)
  • SCP 適用前に既存ワークフローへの影響検証を推奨
  • 委任管理者アカウントでのタグ管理権限設計が重要

📝 まとめ

Amazon VPC IPAM のプール割り当てタグサポートにより、大規模なマルチアカウント環境での IP アドレスガバナンスが大幅に強化された。IAM ポリシーや SCP とタグ条件を組み合わせることで、環境別・チーム別のきめ細かなアクセス制御を追加コストなしで実装できる。

推奨アクション: IP アドレス管理を行うネットワーク管理者は、既存の割り当てにタグを付与し、タグベースのポリシーを段階的に導入することを推奨。
