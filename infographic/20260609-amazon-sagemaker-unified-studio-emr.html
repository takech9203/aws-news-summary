Amazon SageMaker Unified Studio

📓 Notebooks が EMR Serverless をサポート

Apache Spark Connect 経由で Spark ランタイムを柔軟に選択
🗓️ リリース日: 2026年6月9日

🔍 概要

Amazon SageMaker Unified Studio の Notebooks が、Apache Spark Connect を経由した Amazon EMR Serverless をサポートするようになりました。データエンジニアやアナリストは、 インタラクティブ分析やデータエンジニアリングのワークロードに対して、Spark ランタイムをより柔軟に選択できます。

従来 Notebooks の Spark ランタイムは Amazon Athena for Apache Spark が中心でしたが、今回 Amazon EMR Serverless も選択可能に。Notebook のセル内で PySpark と Spark SQL を EMR Serverless 上で実行でき、ランタイムは サイドパネルから選択します (Python セルと SQL セルの両方に適用)。 さらに組み込み AI アシスタント SageMaker Data Agent が自然言語からコードや実行プランを生成します。

⚠️ アップデート前の課題
  • Spark ランタイムの選択肢が限られ、ワークロードに応じた切り替えが難しかった
  • デフォルトの Athena Spark は VPC 接続非対応で、ネットワーク分離ワークロードを実行できなかった
  • 既存の EMR Serverless 環境を Notebook から直接利用する統合手段が不足
✅ アップデート後の改善
  • Athena Spark に加え EMR Serverless を選択でき、要件に応じた最適なエンジン選択が可能に
  • EMR Serverless が VPC 接続をサポートし、ネットワーク分離ワークロードを実行可能に
  • 事前初期化済みキャパシティで起動を短縮、統一 Spark UI で一貫した監視が可能に

Notebook のサイドパネルから Spark ランタイムを選択し、Spark Connect 経由で Amazon Athena Spark または Amazon EMR Serverless 上で PySpark / Spark SQL を実行する構成。

🚀 主要機能

⚡ EMR Serverless を Spark ランタイムとして選択

  • Athena for Apache Spark に加えて EMR Serverless を選択可能
  • セル内で PySpark と Spark SQL を EMR Serverless 上で実行
  • ワークロードの要件に応じて最適なエンジンを選択

⚙️ サイドパネルからのランタイム選択

  • Notebook のサイドパネルから Spark ランタイムを選択
  • 選択したランタイムは Python セルと SQL セルの両方に適用
  • 接続は Apache Spark Connect を介して行われる

🤖 SageMaker Data Agent による AI 支援

  • 組み込みの AI アシスタントを利用可能
  • 自然言語プロンプトからコードや実行プランを生成
  • エラー診断やデータ分析の推奨も提供

🏎️ 事前初期化済みキャパシティと統合モニタリング

  • 事前初期化済みキャパシティでセッション起動時間を短縮
  • 統一された Spark UI でジョブの実行状況を一貫監視
  • VPC 接続をサポートし、ネットワーク分離ワークロードに対応

⚠️ デメリット・制約事項

制限事項

✗デフォルトの Athena for Apache Spark は VPC 接続非対応。ネットワーク分離が必要な場合は EMR Serverless 等を選択する必要がある
✗選択した Spark ランタイムは Python セルと SQL セルに一括適用され、セル単位での使い分けはできない
✗EMR Serverless を利用するには、対応する Spark アプリケーションの準備が必要

考慮すべき点

💰 事前初期化済みキャパシティは起動時間を短縮する一方で、待機中のキャパシティに対するコストが発生する点に注意。
→ワークロードの特性 (インタラクティブ性、データ量、ネットワーク要件) に応じて、Athena Spark と EMR Serverless のどちらが適切かを評価することが望ましい

🎯 ユースケース

① ネットワーク分離が必要なデータエンジニアリング

シナリオ: VPC 内のプライベートなデータソースに対して、Notebooks からインタラクティブに Spark 処理を実行したい。

実装例: サイドパネルで EMR Serverless を選択し、VPC 接続を構成した Spark アプリケーション上で PySpark を実行する。

効果: ネットワーク分離要件を満たしつつ、Notebook から直接インタラクティブな分析を実行できる。

② 自然言語によるデータ分析コードの生成

シナリオ: Spark の記述に不慣れなアナリストが、自然言語の指示でデータ変換コードを作成したい。

実装例: Data Agent に「S3 の売上データを月別に集計して」と指示し、生成された PySpark コードを EMR Serverless 上で実行する。

効果: コーディングの負担を軽減し、分析に集中できるようになる。

③ 起動時間を重視したインタラクティブ分析

シナリオ: 反復的な探索的データ分析において、Spark セッションの起動待ち時間を短縮したい。

実装例: EMR Serverless の事前初期化済みキャパシティを構成し、Notebook から繰り返しセッションを起動する。

効果: セッション起動時間が短縮され、探索的分析のサイクルを高速化できる。

📝 まとめ

Amazon SageMaker Unified Studio の Notebooks が Amazon EMR Serverless をサポートしたことで、 データエンジニアやアナリストは Spark ランタイムをワークロードの要件に応じて柔軟に選択できるようになりました。 特に VPC 接続や事前初期化済みキャパシティを必要とするワークロードに有効です。 利用中のチームは、自身のワークロード特性に基づいて Athena Spark と EMR Serverless の使い分けを検討することをお勧めします。
