Amazon Route 53 Profiles

🌐 VPC あたり複数 Profile の関連付けをサポート

📅 リリース日: 2026 年 11 月 9 日 | Multiple Profiles per VPC

📋 概要

Route 53 Profiles で、1 つの VPC に最大 2 つの Profile を優先度付きで関連付けられるようになりました。 Profile はプライベートホストゾーン、Resolver 転送ルール、DNS Firewall ルールグループなどの DNS 設定をまとめて多数の VPC やアカウントに適用できる機能です。 組織共通の設定とチーム固有の設定をマージせずに同じ VPC へ適用でき、きめ細かな IAM 権限と組み合わせることで各チームが最小権限で Profile を所有・管理できます。

❌ Before: アップデート前の課題
  • 1 つの VPC には 1 つの Profile しか関連付けられなかった
  • チームごとに管理対象が異なっても、全チームが単一の Profile を共有する必要があった
  • 全設定を同じ Profile に集約する必要があり、所有権分離や最小権限での管理が難しかった
✅ After: アップデート後の改善
  • 同じ VPC に複数の Profile を優先度付きで関連付け可能に
  • 共通設定とチーム固有設定を別々の Profile のままマージせずに適用可能に
  • きめ細かな IAM 権限と組み合わせ、各チームが最小権限で自分の Profile を管理可能に

⚡ 主要機能

1️⃣ VPC あたり最大 2 つの Profile の関連付け

1 つの VPC に最大 2 つの Profile を関連付け可能。1 つの Profile は最大 1,000 の VPC に関連付けでき、VPC 数のクォータは引き上げ申請が可能。共通設定用とチーム固有設定用の Profile を分離したまま同じ VPC に適用できます。

2️⃣ 優先度による評価順序の制御

関連付けごとに 100 から 9900 の優先度を設定でき、値が小さいほど優先度が高い。他の関連付けがない場合は省略可能 (優先度 100 が設定)。既存の関連付けがある場合は VPC 内で一意の優先度の指定が必須。優先度は UpdateProfileAssociation API で後から変更できます。

3️⃣ リソースタイプごとの評価ルール
  • Resolver ルール / プライベートホストゾーン: クエリに一致する最も優先度の高い Profile のみ使用。他の Profile により具体的な一致があっても評価されない。選ばれた Profile とローカル VPC 設定ではより具体的なドメイン名が勝ち、同等ならローカル設定が優先
  • DNS Firewall ルールグループ: VPC 直接関連付けと、一致ルールを持つ最優先 Profile のルールグループを一緒に評価。優先度が同じ場合は VPC 直接関連付けが優先
  • Resolver クエリログ設定: 優先度に関係なく、すべての Profile のログ設定に記録
  • Profile 構成設定: 逆引き DNS、DNS Firewall 障害モード、DNSSEC 検証は、設定を指定している最優先 Profile の値を適用。どの Profile も未設定なら VPC 自身の設定を適用
4️⃣ きめ細かな IAM 権限との組み合わせ

2026 年 3 月リリースの Route 53 Profiles のきめ細かな IAM 権限と組み合わせて、チームごとに Profile の所有と管理を分離。各チームが最小権限で自チームの Profile のみを管理でき、セキュリティ態勢が向上します。

AssociateProfile API のパラメータ

パラメータ必須説明
Nameはい関連付けの名前
ProfileIdはいProfile の ID
ResourceIdはいVPC の ID
Priorityいいえ関連付けの優先度 (100 - 9900)。VPC に既存の関連付けがある場合は必須

⚠️ 優先度の省略時に既存の関連付けがある場合、優先度の重複、範囲外 (100 - 9900 以外) は ValidationException、VPC がすでに最大数の関連付けを持つ場合は LimitExceededException が返されます。
📝 API 変更履歴: 今回のアップデートは既存の AssociateProfile API への Priority パラメータ追加と UpdateProfileAssociation API で実現されており、awsapichanges.com では対応する API 変更エントリは確認できませんでした (2026 年 11 月 10 日時点)。

🛠️ 設定方法

前提条件

✓Route 53 Profiles が利用可能なリージョンで Profile を作成済みであること
✓route53profiles:AssociateProfile などの必要な IAM 権限を持っていること
✓関連付け対象の VPC が存在すること
1
1 つ目の Profile を VPC に関連付け
Bash 組織共通 Profile を優先度 100 で関連付け 
aws route53profiles associate-profile \
  --name shared-base-association \
  --profile-id rp-1111111111example \
  --resource-id vpc-0af3b96b3example \
  --priority 100

VPC に他の Profile 関連付けがない場合は --priority を省略でき、その場合は自動的に優先度 100 が設定されます。

2
2 つ目の Profile を同じ VPC に関連付け
Bash チーム固有 Profile を優先度 200 で関連付け 
aws route53profiles associate-profile \
  --name team-specific-association \
  --profile-id rp-2222222222example \
  --resource-id vpc-0af3b96b3example \
  --priority 200

VPC にすでに Profile が関連付けられているため優先度の指定は必須。既存の関連付けと重複しない値を指定します。

3
関連付けの確認と優先度の変更
Bash 一覧確認と優先度変更 
# VPC に関連付けられた Profile の一覧を確認
aws route53profiles list-profile-associations \
  --resource-id vpc-0af3b96b3example

# 関連付けの優先度を変更
aws route53profiles update-profile-association \
  --id rpassoc-489ce212fexample \
  --priority 150

優先度の変更には関連付けの ID を使用します。

⚖️ メリットと制約事項

💼 ビジネス面のメリット

✓責任分界の明確化: 各チームが自分の Profile を所有し、DNS 設定の管理責任を明確に分離
✓セキュリティ態勢の向上: きめ細かな IAM 権限で最小権限の管理委任が可能
✓運用の俊敏性向上: チーム固有の変更が他チームに影響せず、調整コストを削減

🔬 技術面のメリット

✓設定のマージが不要: 共通設定とチーム固有設定を別々の Profile のまま適用
✓明示的な優先度制御: 100 - 9900 の優先度で評価順序を制御、後から変更も可能
✓既存環境への影響なし: 既存の関連付けは優先度 100 として扱われ、動作は不変

🚫 制限事項

✗1 つの VPC に関連付けられる Profile は最大 2 つまで
✗同じ VPC 内の各関連付けには一意の優先度が必要
✗FAILED / DELETING 状態の関連付けも削除までクォータにカウント

⚠️ 考慮すべき点

⚠Resolver ルールとプライベートホストゾーンは一致する最初の Profile のみ使用。低優先度 Profile により具体的な一致があっても評価されないため、ドメイン設計と優先度設計を事前に検討
⚠同等の具体性ではローカル VPC 設定が優先されるため、移行時は既存ローカル設定との関係を確認
⚠クエリログはすべての Profile のログ設定に記録されるため、ログの重複と保存コストを考慮
⚠関連付けごとに標準の Profiles 料金が発生し、2 つ目の Profile は課金対象の関連付け数を増加させる

🎯 ユースケース

1. セキュリティチームとネットワークチームの管理分離 🛡️

シナリオ: セキュリティチームが全社標準の DNS Firewall ルールグループ、ネットワークチームがプライベートホストゾーンと Resolver 転送ルールを管理。従来は単一 Profile の共有で変更のたびに調整が必要だった。

  • セキュリティチームが DNS Firewall 用 Profile A を優先度 100 で VPC に関連付け
  • ネットワークチームがホストゾーン / 転送ルール用 Profile B を優先度 200 で同じ VPC に関連付け
  • きめ細かな IAM 権限で各チームに自チーム Profile のみの管理権限を付与

効果: 各チームが最小権限で独立管理でき、チーム間調整なしに設定変更を展開可能。

2. 組織共通設定とアプリケーション固有設定の階層化 🏢

シナリオ: プラットフォームチームが AWS RAM で共有する組織共通の DNS 設定 (オンプレミスへの転送ルールなど) を維持しつつ、アプリケーションチームが自チームの VPC に固有のプライベートホストゾーンを適用したい。

  • 共通 Profile を AWS RAM で各アカウントに共有し、優先度 100 で VPC に関連付け
  • アプリケーション固有 Profile を優先度 200 で同じ VPC に関連付け
  • 共通設定の更新はプラットフォームチームの Profile 更新だけで全 VPC に伝播

効果: 共通設定の一元管理とチームの自律性を両立。マージ不要で階層化を実現。

3. DNS 設定の段階的な移行 🔄

シナリオ: 既存 Profile で運用中の環境に新しい DNS 設計を導入するにあたり、既存設定を維持したまま段階的に検証したい。

  • 既存 Profile (優先度 100) はそのまま維持し、新 Profile を優先度 200 で関連付け
  • 既存 Profile でカバーされないドメインから新 Profile の動作を検証
  • 検証完了後、update-profile-association で優先度を入れ替えて切り替え

効果: 運用を止めずに検証でき、優先度変更だけで切り替えとロールバックが可能。

💰 料金

各 Profile と VPC の関連付けは、標準の Route 53 Profiles 料金で課金されます。

  • 1 アカウントあたり 1 時間あたり 0.75 USD で、リージョンごとに最大 100 の Profile-VPC 関連付けをカバー
  • 100 を超える関連付けは、1 関連付けあたり 1 時間あたり 0.0014 USD (リージョンごと)
  • AWS RAM で共有された Profile を他アカウントが VPC に関連付けた場合、その関連付けは Profile 所有アカウントの合計にカウント
使用量月額料金 (30 日 = 720 時間の概算)
100 関連付けまで0.75 USD x 720 時間 = 540 USD
200 関連付け[0.75 USD + 100 x 0.0014 USD] x 720 時間 = 640.80 USD
⚠️ 同じ VPC に 2 つの Profile を関連付けると、関連付け数は 2 としてカウントされる点に注意してください。

🌍 利用可能リージョンと関連サービス

利用可能リージョン: Route 53 Profiles が利用可能なすべての AWS リージョンで利用できます。リージョンごとの提供状況は AWS General Reference の Route 53 サービスエンドポイントを参照してください。

🔗 関連サービス・機能

🔍 Amazon Route 53 Resolver

Profile に関連付けた転送ルールやシステムルールにより、VPC からの DNS クエリの解決動作を制御

🛡️ Route 53 Resolver DNS Firewall

Profile 経由で DNS Firewall ルールグループを VPC に適用し、DNS レベルの脅威からワークロードを保護

🤝 AWS Resource Access Manager (AWS RAM)

Profile を同一リージョン内の他の AWS アカウントと共有し、マルチアカウント環境で一貫した DNS 設定を実現

🔑 AWS IAM

2026 年 3 月リリースのきめ細かな IAM 権限により、Profile 単位での最小権限の管理委任を実現

📜 AWS CloudFormation

新規プロビジョニングする VPC への一貫した DNS 設定の適用に利用可能

💡 まとめ

Route 53 Profiles の VPC あたり複数 Profile サポートにより、組織共通の DNS 設定とチーム固有の設定をマージせずに同じ VPC へ優先度付きで適用できるようになりました。 きめ細かな IAM 権限と組み合わせることで、セキュリティチームとネットワークチームがそれぞれの Profile を最小権限で所有・管理でき、マルチチーム体制での DNS 運用が大きく改善されます。 複数チームで単一の Profile を共有している組織は、リソースタイプごとの評価ルールと優先度設計を確認したうえで、Profile の分割を検討してください。
