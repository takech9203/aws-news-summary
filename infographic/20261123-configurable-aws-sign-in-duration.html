AWS Sign-In

🔐 最大 90 日間の設定可能なサインイン期間

📅 リリース日: 2026 年 11 月 23 日 | 機能: Configurable Sign-in duration

📝 概要

AWS Sign-In に、OAuth サインインセッションの有効期間を最大 90 日間まで設定できる新しい「Sign-in duration」設定が導入されました。開発者や AI エージェントは、繰り返しサインインしたり同意プロンプトに応答したりすることなく、長期間にわたり認証状態を維持できます。管理者は、この設定を IAM ユーザーまたは IAM ロールごとに個別に構成できます。

AWS CLI の aws login コマンド、AWS MCP Server、その他の OAuth 対応アプリケーションに適用され、セッション有効期間中は短期アクセストークンがリフレッシュトークンにより自動更新されるため、静的なアクセスキーより安全な代替手段となります。なお、AWS Management Console のセッションには適用されず、デフォルトの動作も変更されません。

❌ アップデート前の課題
✗OAuth セッションのデフォルト期間 (12 時間) を超える認証維持ができず、長時間ワークフローで再サインインが頻発
✗長期認証のために静的アクセスキーに頼るケースがあり、認証情報漏えいリスクが高い
✗AI エージェントや自動化ツールが、認証の中断や同意プロンプトで処理を継続できない場合があった
✅ アップデート後の改善
✓IAM ユーザー / ロールごとに最大 90 日間のセッション期間を設定でき、再認証なしで作業を継続可能
✓短期間かつ更新可能な認証情報を利用する、より安全な認証方式を採用可能
✓セッションの一覧表示・詳細取得・取り消しを API で管理、CloudTrail でトークン発行・更新を監視可能

🏗️ アーキテクチャ図

sequenceDiagram
    participant Dev as 👤 開発者・AI エージェント
    participant CLI as 💻 AWS CLI や OAuth アプリ
    participant SignIn as 🔐 AWS Sign-In
    participant SVC as ⚙️ AWS サービス

    Dev->>CLI: aws login
    CLI->>SignIn: OAuth 認証リクエスト
    SignIn-->>CLI: サインインセッション確立 最大 90 日
    loop セッション有効期間中
        CLI->>SignIn: リフレッシュトークンでトークン更新
        SignIn-->>CLI: 短期アクセストークンを発行
        CLI->>SVC: 一時認証情報で API 呼び出し
    end
    Note over Dev,SignIn: セッション失効または取り消し後は再認証が必要

一度のサインインでセッションが確立された後は、設定された期間内であればリフレッシュトークンにより短期アクセストークンが自動更新され、再認証なしで AWS サービスへのアクセスを継続できます。

⚡ 主要機能

1️⃣ プリンシパル単位のサインイン期間設定
  • IAM ユーザーまたは IAM ロールごとに、OAuth サインインセッションの最大期間を設定可能
  • デフォルト 12 時間、最大 90 日間まで延長可能
  • 長期アクセスが必要なユーザーには長いセッション、その他には短いセッションなど、きめ細かな制御が可能
2️⃣ 短期認証情報による安全な長期認証
  • セッション有効期間中は、短期間の OAuth アクセストークンで AWS サービスにアクセス
  • リフレッシュトークンにより、ユーザーの再認証なしでトークンを更新
  • AWS CLI の認証情報デーモン (credential daemon) でリフレッシュトークンを暗号化保存し、CLI / SDK からの直接アクセスを防止可能
3️⃣ セッション管理 API
  • aws signin list-sessions: アクティブなセッションを一覧表示
  • aws signin get-session: セッション ARN を指定して詳細を取得
  • aws signin batch-revoke-sessions: 不要・不審なセッションを取り消し (一括取り消し対応)
4️⃣ CloudTrail によるモニタリング
  • CreateOAuth2Token イベントで OAuth トークンの発行・更新を記録
  • additionalEventData に SignInSessionExtended (延長設定の有無)、SignInDuration (セッション期間、秒単位)、signInSessionArn (セッション識別子) を含む
  • セッション作成、トークンアクティビティ、管理設定の変更を監査可能

🔗 Maximum Session Duration との関係

💡 サポートされる CLI および OAuth 認証フローでは、サインイン期間 (Sign-in duration) が既存の IAM ロールの「Maximum Session Duration」設定より優先されます。ただし、Maximum Session Duration は引き続き、個々の AWS STS 一時認証情報の有効期間を制御します。

📊 CloudTrail イベント例

JSON CreateOAuth2Token イベント 
{
  "eventSource": "signin.amazonaws.com",
  "eventName": "CreateOAuth2Token",
  "additionalEventData": {
    "signInSessionArn": "arn:aws:signin:us-west-2:111122223333:session/a1b2c3d4-...",
    "SignInSessionExtended": "true",
    "grant_type": "authorization_code",
    "success": "true",
    "SignInDuration": "7775999"
  }
}

🛠️ 設定方法

✅ 前提条件

  • IAM ユーザーまたはロールの設定を変更できる IAM 権限を持つ管理者であること
  • 利用者側は aws login コマンドに対応したバージョンの AWS CLI、または OAuth 対応アプリケーションを使用すること
  • セッション管理操作 (一覧表示、取り消しなど) には適切な IAM 権限が必要であること
1
IAM ロールまたはユーザーのサインイン期間を設定する

IAM コンソールで [ロール] または [ユーザー] を選択し、サインインセッション期間の設定で [編集] を選択。最大 90 日間までの期間を指定して保存します。設定は新しく確立されるサインインセッションに適用されます。AWS CLI や IAM API からも設定可能です。

2
サインインしてセッションを確立する
Bash サインイン 
aws login

認証に成功すると、AWS Sign-In がセッションを確立します。AWS CLI は一時認証情報を取得し、セッションが有効な間は自動的に更新します。

3
アクティブなセッションを管理する
Bash セッション管理コマンド 
# ロールに関連付けられたセッションを一覧表示
aws signin list-sessions \
  --principal-arn arn:aws:iam::123456789012:role/DeveloperRole

# セッションの詳細を取得
aws signin get-session \
  --session-arn arn:aws:signin:us-east-1:123456789012:session/my-session-id

# セッションを取り消し
aws signin batch-revoke-sessions \
  --session-arns arn:aws:signin:us-east-1:123456789012:session/my-session-id

セッションの一覧表示で既存の認証済みセッション (識別子、有効期限、ステータス) を確認し、不要または不審なセッションは取り消しできます。取り消し後はアクセストークンの更新が停止されます。

💡 メリット

💼 ビジネス面

✓生産性の向上: 再認証による中断なしに最大 90 日間作業を継続でき、長時間実行ワークフローの運用負荷が軽減
✓セキュリティリスクの低減: 静的アクセスキーの代わりに短期間かつ更新可能な認証情報を使用し、漏えい時の影響を抑制
✓ガバナンスの維持: プリンシパル単位の期間設定とセッション取り消し機能で、利便性と統制を両立

⚙️ 技術面

✓自動トークン更新: リフレッシュトークンによる短期アクセストークンの自動更新で、認証情報管理が簡素化
✓集中的なセッション管理: 一覧表示・詳細取得・取り消しを API で実行可能。管理者はアカウント全体を、ユーザーは自身のセッションを管理
✓監査性の確保: CloudTrail の CreateOAuth2Token イベントで延長セッションの利用状況を追跡可能

⚠️ デメリット・制約事項

🚫 制限事項

✗AWS Management Console のセッションには適用されない (コンソールは既存のセッション期間設定に従う)
✗セッション取り消しの反映まで最大 1 時間かかる場合があり、発行済みトークンは有効期限まで有効な場合がある
✗取り消しは対象セッションのみに作用し、同じプリンシパルの他のセッションは自動的には取り消されない

🤔 考慮すべき点

⚠期間を延長するほど、端末やリフレッシュトークン侵害時の影響期間が長くなるため、必要最小限の期間設定が望ましい
⚠延長セッション使用時は、リフレッシュトークンを暗号化保存する認証情報デーモンの利用を推奨
⚠サインイン期間は Maximum Session Duration より優先されるため、既存のセッション管理ポリシーとの整合性確認が必要

🎯 ユースケース

🤖 ユースケース 1: AI エージェントによる長時間の自律実行

シナリオ: AWS MCP Server を利用する AI エージェントが、数日から数週間にわたるタスク (継続的なモニタリング、定期的なリソース操作など) を自律的に実行する。

Bash実装例
# 管理者: エージェント用ロールのサインイン期間を 30 日に設定 (IAM コンソール)
# エージェント側: 一度サインインしてセッションを確立
aws login
✅ 効果: 認証の中断や同意プロンプトによるタスクの停止がなくなり、AI エージェントが長期間安定して動作する。
🔑 ユースケース 2: 静的アクセスキーからの移行

シナリオ: 開発者が長期間の CLI アクセスのためにアクセスキーを使い続けており、キーのローテーションや漏えいリスクが課題となっている。

Bash実装例
# アクセスキーの代わりにサインインセッションを利用
aws login

# 認証情報デーモンでリフレッシュトークンを安全に管理
# (暗号化保存、CLI/SDK には短期認証情報のみを提供)
✅ 効果: 長期の静的認証情報を廃止し、短期間・更新可能な認証情報に移行することで、セキュリティ態勢を改善できる。
🛡️ ユースケース 3: 管理者によるセッションの集中管理と監査

シナリオ: セキュリティ管理者が、組織内の延長サインインセッションの利用状況を監視し、退職者や不審なアクティビティに対して迅速にアクセスを遮断したい。

Bash実装例
# 対象プリンシパルのセッションを確認
aws signin list-sessions \
  --principal-arn arn:aws:iam::123456789012:role/DeveloperRole

# 不審なセッションを取り消し
aws signin batch-revoke-sessions \
  --session-arns arn:aws:signin:us-east-1:123456789012:session/suspicious-session
✅ 効果: CloudTrail の記録と組み合わせて、延長セッションの可視性を確保しつつ、必要時に迅速なアクセス遮断が可能になる。

🔐 AWS IAM

サインイン期間を IAM ユーザーまたはロールごとに設定する。ロールの Maximum Session Duration は引き続き STS 一時認証情報の有効期間を制御する。

💻 AWS CLI (aws login)

サインインセッションを利用する主要なクライアント。認証情報デーモンによるリフレッシュトークンの安全な管理に対応。

🤖 AWS MCP Server

AI エージェントが AWS にアクセスする際の認証にサインインセッションを利用可能。

📊 AWS CloudTrail

CreateOAuth2Token イベントなどにより、トークン発行・更新やセッション管理操作を監査。

📌 まとめ

AWS Sign-In のサインイン期間設定により、開発者や AI エージェントは最大 90 日間、再認証なしで AWS にアクセスできるようになり、静的アクセスキーに代わる安全な長期認証の選択肢が提供されました。長時間実行ワークフローや AI エージェントを運用している場合は、対象の IAM ユーザーまたはロールに適切なサインイン期間を設定し、認証情報デーモンや CloudTrail によるモニタリングと組み合わせて導入することを推奨します。
