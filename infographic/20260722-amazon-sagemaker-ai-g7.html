📌 概要

Amazon SageMaker AI の推論機能が、NVIDIA RTX PRO 4500 Blackwell Server Edition GPU を搭載した G7 インスタンスをサポートしました。前世代の G6 と比較して最大 4.6 倍の AI 推論パフォーマンスで機械学習モデルをデプロイできます。

GPU あたり 32 GB のメモリと第 5 世代 Tensor Core、最大 700 Gbps の EFA 対応ネットワーキング、最大 7.6 TB のローカル NVMe SSD を提供し、7B〜30B パラメータ規模のモデルサービング、画像・動画生成、マルチモデル推論に適しています。

❌ Before (アップデート前の課題)

  • GPU メモリ制約に収めるため、高価な計算リソースを過剰プロビジョニングする必要があった
  • メモリに合わせてモデルを量子化する必要があった
  • 中規模〜大規模の生成 AI モデルをコスト効率よくサービングするのが難しかった

✅ After (アップデート後の改善)

  • GPU あたり 32 GB のメモリで 7B〜30B パラメータ規模のモデルを効率的にサービング
  • 最大 4.6 倍のパフォーマンスで過剰プロビジョニングや量子化を回避しやすい
  • 最大 700 Gbps の EFA と 7.6 TB の NVMe SSD で大規模モデルを計算リソースの近くに保持

SageMaker AI のエンドポイント設定で G7 インスタンスタイプを指定すると、NVIDIA RTX PRO 4500 Blackwell GPU を搭載した推論エンドポイントがデプロイされ、大規模モデルをローカル NVMe SSD に保持しながら低レイテンシで推論を提供します。

⚡ 主要機能

1. NVIDIA RTX PRO 4500 Blackwell Server Edition GPU の搭載

  • GPU あたり 32 GB の GPU メモリを提供
  • 第 5 世代 Tensor Core を搭載
  • 前世代 G6 インスタンスと比較して最大 4.6 倍の AI 推論パフォーマンス

2. 高帯域ネットワーキングとストレージ

  • 最大 700 Gbps の EFA 対応ネットワーキング (G6 と比較して 7 倍)
  • 最大 7.6 TB のローカル NVMe SSD ストレージ
  • 大規模モデルを計算リソースの近くに保持し、モデルロードの効率を向上

3. 柔軟なインスタンスサイズと簡単なデプロイ

  • ml.g7.xlarge から ml.g7.48xlarge までのインスタンスサイズを提供
  • SageMaker AI 推論コンソール、API、または SDK からデプロイ可能
  • エンドポイント設定でインスタンスタイプを指定するだけで利用可能

ステップ 1: モデルの作成

Bashcreate-model
aws sagemaker create-model \
  --model-name my-generative-ai-model \
  --primary-container Image=<推論コンテナのイメージ URI>,ModelDataUrl=<モデルアーティファクトの S3 URI> \
  --execution-role-arn <SageMaker 実行ロールの ARN>

ステップ 2: エンドポイント設定の作成

Bashcreate-endpoint-config
aws sagemaker create-endpoint-config \
  --endpoint-config-name g7-inference-config \
  --production-variants VariantName=AllTraffic,ModelName=my-generative-ai-model,InstanceType=ml.g7.12xlarge,InitialInstanceCount=1

ステップ 3: エンドポイントのデプロイ

Bashcreate-endpoint
aws sagemaker create-endpoint \
  --endpoint-name g7-inference-endpoint \
  --endpoint-config-name g7-inference-config

デプロイ完了後、InService 状態になると推論リクエストを受け付けられます。

💡 メリット

💰 ビジネス面

  • コスト効率の向上: 最大 4.6 倍の性能で同じスループットをより少ないインスタンスで実現
  • 本番運用の簡素化: メモリ制約による量子化が不要になり精度を維持しやすい
  • 幅広いワークロード対応: LLM、画像・動画生成、マルチモデルなど多様な生成 AI に対応

⚙️ 技術面

  • 十分な GPU メモリ: GPU あたり 32 GB で中〜大規模モデルを量子化せず収容
  • 高いネットワーク帯域: 最大 700 Gbps の EFA で分散推論の通信ボトルネックを軽減
  • 高速なローカルストレージ: 最大 7.6 TB の NVMe SSD でモデルロード時間を短縮

⚠️ デメリット・制約事項

制限事項

▲利用可能リージョンは米国東部 (バージニア北部、オハイオ)、米国西部 (オレゴン) に限定
▲東京を含むアジアパシフィックリージョンは記事公開時点で未対応
▲高性能 GPU のため、小規模モデルや低トラフィックではコストが割高になる可能性

考慮すべき点

▲モデル規模・スループット要件に応じて適切なインスタンスサイズを選択
▲30B を大きく超えるモデルでは複数 GPU への分散やより大きなサイズの検討が必要
▲料金は最新の SageMaker AI 料金ページで確認することが推奨される

🎯 ユースケース

1. 中規模 LLM の本番推論

シナリオ: 13B パラメータ規模のオープンソース LLM を本番でサービングしたいが、前世代ではメモリ制約により量子化が必要だった。

実装例: ml.g7.8xlarge (GPU メモリ 32 GB) / 13B パラメータの LLM (量子化なし)

✅ 32 GB の GPU メモリで量子化せずにモデルをロードでき、精度を維持したまま高スループット推論を提供

2. 画像・動画生成ワークロード

シナリオ: テキストから画像・動画を生成する生成 AI モデルを、複数リクエストに対して低レイテンシで提供したい。

実装例: ml.g7.12xlarge (GPU 2 基、GPU メモリ 64 GB) / 拡散モデルベースの画像・動画生成

✅ 高いメモリ帯域幅と GPU 性能で処理時間を短縮し、多数の同時リクエストを処理

3. マルチモデル推論エンドポイント

シナリオ: 複数の機械学習モデルを 1 つのエンドポイントでホストし、リソースを共有しながらコストを最適化したい。

実装例: ml.g7.24xlarge (GPU 4 基、GPU メモリ 128 GB) / 複数モデルを 1 エンドポイントに配置

✅ 大容量 GPU メモリと高スループットで複数モデルを効率的にホストし、インスタンス数を削減

💵 料金 & 利用可能リージョン

G7 インスタンスの SageMaker AI 推論での料金は、使用するインスタンスタイプと稼働時間に基づく従量課金制です。具体的な時間単価はリージョンおよびインスタンスサイズによって異なります。正確な料金は AWS SageMaker AI 料金ページで確認してください。

Amazon SageMaker AI 推論での G7 インスタンスサポートにより、NVIDIA RTX PRO 4500 Blackwell GPU の高い性能とメモリ容量を活用し、7B〜30B パラメータ規模のモデルや画像・動画生成ワークロードをコスト効率よくデプロイできるようになりました。生成 AI モデルを本番でサービングしている、または検討中のお客様は、まず米国リージョンで G7 の推論パフォーマンスを評価し、既存の G6 ベースのエンドポイントからの移行を検討することをお勧めします。
