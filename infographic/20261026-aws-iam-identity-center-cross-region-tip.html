AWS IAM Identity Center

🌏 クロスリージョン信頼できる ID 伝播のサポート

📅 リリース日: 2026 年 10 月 26 日 | 機能: Cross-Region Trusted Identity Propagation

📋 概要

IAM Identity Center の信頼できる ID 伝播がクロスリージョンに対応。 ユーザーの ID をリクエストに付加して AWS サービスが「どのユーザーが、どのグループに所属しているか」に基づき アクセスを認可・監査できる機能を、異なる AWS リージョンで実行されるサービスへも伝播できるようになりました。

コンピューティングとデータの分離、キャパシティ活用、ディザスタリカバリ、グローバル展開など、 マルチリージョン構成でもユーザーごとのきめ細かなアクセス制御と監査を維持できます。

追加料金なし
IAM Identity Center 自体も無料
全リージョン
IAM Identity Center 利用可能なすべてのリージョンで提供
自動伝播
ID コンテキストがリクエストとともにリージョンをまたいで伝わる

😰 Before: 単一リージョンに閉じた機能

✗ID にアクセスする全サービスが同一リージョンに存在する必要があった
✗別リージョンへは個々のユーザーを区別できない広範な IAM ロールを使用
✗あるいは全サービスを単一リージョンに集約する構成変更が必要
✗ユーザー単位のアクセス制御や監査ログの記録ができなかった

😊 After: クロスリージョンで ID ベース制御

✓ID コンテキストが自動的にリージョンをまたいで伝播
✓受信側リージョンのサービスがユーザーとグループ関連付けで認可
✓クロスリージョンでもユーザー単位のきめ細かな許可と監査が可能
✓広範な IAM ロールへのフォールバックや単一リージョン集約が不要

💡 マルチリージョン IAM Identity Center インスタンスを使用すると、リージョン A で認証したユーザーの ID コンテキストが、リージョン B の AWS サービスへのリクエストとともに伝播され、 受信側サービスがユーザーとグループ属性に基づいてアクセスを認可します。

⚡ 主要機能

🌐 クロスリージョンでの ID コンテキスト伝播

あるリージョンで認証したユーザーの ID コンテキスト (ユーザー識別情報、アクセス対象サービス、アクセススコープ) を別リージョンの AWS サービスへ伝播。受信側はこのコンテキストとユーザーに割り当てられた権限で認可します。

🎯 ユーザーとグループ属性に基づくきめ細かな認可

受信側リージョンのサービスがグループ関連付けなどのユーザー属性に基づいて認可。広範な IAM ロールでは不可能だった「誰がアクセスしたか」の識別が可能になります。

📝 監査の継続性

ユーザー識別子を AWS CloudTrail やサービスログに記録。リージョンをまたいだアクセスでも「どのユーザーがどのデータにアクセスしたか」を監査できます。

🔄 既存設定からの自動的な拡張

マルチリージョンレプリケーションと信頼できる ID 伝播を設定済みであれば、追加リージョンでのクロスリージョン ID 伝播は自動的に機能します。

🛠️ 設定方法

前提条件

  • ✓IAM Identity Center の組織インスタンスが有効化されていること
  • ✓マルチリージョンレプリケーションが有効化されたマルチリージョンインスタンスであること
  • ✓マルチリージョンのカスタマーマネージド KMS キーが設定されていること
  • ✓利用する AWS サービス側で信頼できる ID 伝播の設定が完了していること

手順

1
マルチリージョンインスタンスと KMS キーの確認
Bash インスタンスの確認 
# IAM Identity Center インスタンスの一覧を確認
aws sso-admin list-instances

インスタンスの ARN と設定状態を確認。マルチリージョンレプリケーションが未設定の場合は、コンソールからマルチリージョン対応を有効化し、マルチリージョンのカスタマーマネージド KMS キーを設定します。

2
各 AWS サービスでの信頼できる ID 伝播の設定

Amazon Redshift、Amazon Athena、Amazon QuickSight などの各サービスのドキュメントに従い、サービスを IAM Identity Center に接続して設定します。設定方法はサービスごとに異なります。

3
クロスリージョンでの動作確認

設定済みであれば追加設定なしでレプリケートされたリージョン間の ID 伝播が自動的に機能。別リージョンのサービスへアクセスし、CloudTrail やサービスログにユーザー識別子が記録されることを確認します。

✅ メリット

💼 ビジネス面

✓グローバル展開の柔軟性: コンピューティングとデータを異なるリージョンに配置してもユーザー単位の制御を維持
✓コンプライアンスと監査の強化: 「誰が何にアクセスしたか」を CloudTrail やサービスログで追跡
✓追加コストなし: 全対応リージョンで追加料金なしで利用可能

⚙️ 技術面

✓広範な IAM ロールの排除: 共有ロール不要となり、最小権限の原則に沿った設計が可能
✓アーキテクチャ制約の解消: 単一リージョン集約が不要となり、キャパシティ活用や DR を考慮した設計が可能
✓自動的な ID 伝播: アプリケーション側での独自の ID 引き回し実装が不要

⚠️ デメリット・制約事項

🚫 制限事項

✗マルチリージョン IAM Identity Center インスタンスが必要 (単一リージョンインスタンスでは利用不可)
✗マルチリージョンのカスタマーマネージド KMS キーが必要 (AWS 所有キーでは不可)
✗ID 伝播が動作するのは、インスタンスをレプリケートしたリージョン間に限られる

🤔 考慮すべき点

→利用する各 AWS サービスの信頼できる ID 伝播への対応状況をドキュメントで確認が必要
→マルチリージョン KMS キーの運用 (キーポリシー、ローテーション、コスト) を設計に含める必要がある
→既存の単一リージョンインスタンスからの移行計画が必要になる場合がある

💡 ユースケース

📊 1. コンピューティングとデータを分離したクロスリージョン分析基盤

シナリオデータレイクを東京リージョンに配置し、分析用コンピューティングをキャパシティに余裕のある別リージョンで実行。アナリストごとにアクセスできるデータを制御したい。

Text実装例
1. IAM Identity Center をマルチリージョンインスタンスとして構成し、
   東京リージョンと分析実行リージョンへレプリケート
2. マルチリージョンのカスタマーマネージド KMS キーを設定
3. 分析サービスとデータサービスの両方で信頼できる ID 伝播を設定
4. データ側でユーザーのグループ関連付けに基づくアクセス許可を定義
✨ 効果: 分析リージョンで認証されたアナリストの ID が東京リージョンのデータサービスまで伝播され、グループに基づくきめ細かなデータアクセス制御とユーザー単位の監査ログ記録が可能になります。
🛡️ 2. ディザスタリカバリ構成での ID ベースアクセス制御の維持

シナリオプライマリリージョンの障害に備え、セカンダリリージョンにワークロードをスタンバイ配置。フェイルオーバー後もユーザー単位のアクセス制御と監査を維持したい。

Text実装例
1. IAM Identity Center のマルチリージョンレプリケーションで
   プライマリとセカンダリの両リージョンをカバー
2. 両リージョンのサービスで信頼できる ID 伝播を設定
3. フェイルオーバー後も同じユーザー・グループベースの
   アクセス許可が自動的に適用されることを確認
✨ 効果: フェイルオーバー時にも広範な IAM ロールへ切り替えることなく、通常時と同じ ID ベースのアクセス制御と監査証跡を維持できます。
🔒 3. 広範な IAM ロールからの移行によるセキュリティ強化

シナリオ現在、別リージョンのサービスへのアクセスに共有の IAM ロールを使用しており、個々のユーザーを区別したアクセス制御や監査ができていない。

Text実装例
1. 既存の IAM Identity Center インスタンスをマルチリージョン構成に拡張
2. 対象リージョンの AWS サービスで信頼できる ID 伝播を設定
3. 共有 IAM ロールによるアクセスを、ユーザー・グループベースの
   アクセス許可に段階的に置き換え
4. CloudTrail でユーザー単位のアクセスログを確認
✨ 効果: 共有ロールを廃止し、最小権限の原則に沿ったユーザー単位のアクセス制御へ移行することで、セキュリティポスチャと監査能力が向上します。

💰 料金・利用可能リージョン

💵 料金

クロスリージョン信頼できる ID 伝播は追加料金なし。IAM Identity Center 自体も無料。 ただし前提条件のマルチリージョンカスタマーマネージド KMS キーには、AWS KMS の標準料金 (キー保管料金および API リクエスト料金) が適用されます。

🌍 利用可能リージョン

IAM Identity Center が利用可能なすべての AWS リージョンで利用可能。クロスリージョン ID 伝播は、マルチリージョンインスタンスをレプリケートしたリージョン間で動作します。

🔗 関連サービス・機能

🔐 IAM Identity Center マルチリージョンインスタンス

本機能の前提となる構成。インスタンスを複数リージョンへレプリケートする機能で、2026 年に対応リージョンが順次拡大。

🔑 AWS KMS

マルチリージョンのカスタマーマネージドキーが前提条件。ID コンテキストの保護に使用。

📜 AWS CloudTrail

伝播されたユーザー識別子を記録し、リージョンをまたぐアクセスの監査を実現。

📊 Amazon Redshift / Amazon Athena / Amazon QuickSight など

信頼できる ID 伝播に対応する分析系サービス。ユーザー・グループベースのデータアクセス制御のユースケースで利用。
