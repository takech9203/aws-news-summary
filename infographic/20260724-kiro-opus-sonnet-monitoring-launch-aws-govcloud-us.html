Kiro AWS GovCloud (US)

Kiro に Opus 4.8 / Sonnet 5 と
ユーザーアクティビティモニタリングが登場

AWS GovCloud (US) で最新 Claude モデルとエンタープライズ向けガバナンス機能が一般提供
リリース日
2026 年 7 月 24 日

📌 概要

AWS は、AI 搭載 IDE である Kiro において、2 つの新しい Claude モデル (Claude Opus 4.8 および Claude Sonnet 5) と、エンタープライズ向けのユーザーアクティビティモニタリング機能を AWS GovCloud (US) リージョンで一般提供 (GA) 開始しました。これらの機能は Kiro の IDE と CLI の両方で利用できます。

Claude Opus 4.8 は「最も知的な Opus モデル」と位置付けられ、自己検証能力の向上、より効率的なツール呼び出し、長期プロジェクトにおける追従性の改善を実現します。編集の前に計画を立てるアプローチを取り、複雑で多段階のタスクに適しています。一方 Claude Sonnet 5 は「最もエージェント的な Sonnet モデル」として、より強力な推論・ツール利用・コーディング能力を Sonnet レベルの価格で提供し、ベンチマークで Opus 4.8 に近い性能を低コストで実現します。

ユーザーアクティビティモニタリングは、エンタープライズ管理者に組織全体の利用状況を可視化する機能です。集計メトリクスを表示する使用状況ダッシュボード、ユーザーごとの日次 CSV レポート、オプションのプロンプトログ記録などを提供し、規制対象の政府機関ワークロードにおけるコンプライアンスと監査の要件に対応します。

🔄 Before / After

😰 アップデート前の課題
  • AWS GovCloud (US) 環境では、Kiro の最新 Claude モデル (Opus 4.8、Sonnet 5) を利用できなかった
  • 管理者が組織全体の Kiro 利用状況を一元的に可視化する手段が限られていた
  • コンプライアンスや監査のために、プロンプトとレスポンスのログを取得する標準的な仕組みがなかった
➡
😊 アップデート後の改善
  • AWS GovCloud (US) で Claude Opus 4.8 および Claude Sonnet 5 が利用可能に
  • 使用状況ダッシュボードと日次 CSV レポートで、クレジット消費とモデル利用状況を把握できる
  • オプションのプロンプトログ記録により、コンプライアンス/デバッグ用データを自社アカウントに保存できる

🚀 設定方法

前提条件: AWS GovCloud (US) で Kiro を利用できる環境 / Kiro IDE または CLI のインストール / モニタリングを利用する場合はレポート配信先の S3 バケットの準備。

1

Kiro IDE または CLI の更新

最新バージョンに更新し、再起動します。再起動後、モデルセレクターに新しいモデル (Opus 4.8、Sonnet 5) が表示されます。

2

モデルの選択

モデルセレクターからタスクに応じて選択します。複雑で多段階のタスクには Opus 4.8、コスト効率を重視する場合は Sonnet 5 を選びます。

3

ユーザーアクティビティモニタリングの設定

管理者は使用状況ダッシュボードで利用状況を確認します。日次 CSV レポートの配信先となる S3 バケットを指定し、必要に応じてプロンプトログ記録を有効化します。詳細は GovCloud のドキュメントとモニタリングガイドを参照してください。

✅ メリット

💼 ビジネス面

  • 規制対応の強化: GovCloud (US) で最新 AI モデルを利用でき、規制対象ワークロードでも先進的な開発支援を活用
  • コスト最適化: ダッシュボードと日次レポートでクレジット消費を可視化し、利用を最適化
  • コンプライアンスと監査: プロンプトログ記録で監査要件に対応するデータを取得

🔧 技術面

  • 高性能なモデルの選択肢: 複雑タスク向けの Opus 4.8 とコスト効率の Sonnet 5 を用途で選択
  • 長いコンテキスト: 両モデルとも 100 万トークンで大規模なコードベースを扱える
  • データの自社管理: 自社の AWS アカウントに保存され、S3 以外の追加料金なし

⚖️ デメリット・制約事項

⚠️ 制限事項

  • Claude Sonnet 5 は実験的サポートのため、動作や仕様が変更される可能性がある
  • 新モデルの利用には IDE または CLI を最新版へ更新し、再起動が必要
  • 各モデルにクレジット倍率が設定され (Opus 4.8: 2.2 倍、Sonnet 5: 1.3 倍)、消費量が異なる

🔍 考慮すべき点

  • プロンプトログ記録の有効化時は、組織のデータ取り扱いポリシーとの整合性を確認
  • CSV レポートやログの保存には S3 ストレージ料金が発生する
  • タスクの複雑さとコストのバランスを考慮し、適切なモデルを選択する

💡 ユースケース

1️⃣ 政府機関の大規模開発プロジェクト

シナリオ: 規制対象のワークロードを扱う政府機関のチームが、複雑で多段階の開発タスクを AWS GovCloud (US) 環境で進める。

効果: Opus 4.8 の計画能力と自己検証能力で複雑なリファクタリングや機能追加を効率化。100 万トークンのコンテキストで大規模なコードベース全体を考慮した支援を受けられる。

2️⃣ コスト効率を重視した日常的な開発

シナリオ: 開発チームが日常的なコーディングタスクをコストを抑えつつ効率的に進めたい。

効果: Sonnet 5 で Opus 4.8 に近い性能を Sonnet レベルの価格で得られ、クレジット消費を抑えながら生産性を維持できる。

3️⃣ 組織全体の利用状況の監査と最適化

シナリオ: 管理者が組織全体の Kiro 利用状況を把握し、コスト最適化とコンプライアンス対応を行いたい。

効果: ダッシュボードと日次 CSV レポートでユーザーごとのクレジット消費とモデル利用状況を把握し、プロンプトログ記録で監査要件に対応できる。

💰 料金 & 利用可能リージョン

料金: 各 Claude モデルにはクレジット倍率が設定されています (Opus 4.8: 2.2 倍 / Sonnet 5: 1.3 倍)。ユーザーアクティビティモニタリングのデータは自社の AWS アカウントに保存され、S3 ストレージ料金以外の追加料金は発生しません。
