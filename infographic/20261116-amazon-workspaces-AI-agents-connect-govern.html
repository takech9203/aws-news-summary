📝 概要

Amazon WorkSpaces for AI agents に、AI エージェントのセットアップ・接続・ガバナンスを強化する複数の新機能が追加されました。2026 年 6 月に GA された本機能は、AI エージェントがマネージドなデスクトップ環境経由で業務アプリケーションを操作できるものです。今回のアップデートは、パイロット段階のエージェントをエンタープライズの ID 管理・ポリシー・監査統制のもとで本番運用へ移行させることを目的としています。

❌ アップデート前の課題

✗エージェント用 WorkSpace は手動でマシン構成が必要で、セットアップに手間がかかった
✗認証は SAML と IAM が中心で、OIDC ベースの ID プロバイダーとの統合が難しかった
✗特定ユーザーの権限・グループポリシーのもとでエージェントを動作させる標準的な仕組みがなかった
✗監査証跡はスクリーンショットやツール呼び出しログ中心で、セッション全体のレビュー手段が限られていた

✅ アップデート後の改善

✓Claude Code、Codex、Kiro に要件を記述するだけで WorkSpace を構築可能
✓Bedrock AgentCore のエージェントはコード不要で AWS 認証情報により直接接続
✓1 回の呼び出しで複数アクションを実行し、computer use アクション活用でコスト低減・精度向上
✓OIDC 互換の任意の ID プロバイダーで認証し、組織の IdP へ直接ルーティング
✓On-Behalf-Of サインインでユーザーのディレクトリ ID・権限・グループポリシーを継承
✓セッションリプレイで動画 + トランスクリプトを S3 に独自キーで暗号化保存

AI コーディングアシスタントが MCP スキルのガイドに従って WorkSpace 環境を構築し、Bedrock AgentCore のエージェントは AWS 認証情報で直接接続します。認証は OIDC / SAML IdP 経由で行われ、On-Behalf-Of サインインによりユーザーの権限がエージェントに適用されます。セッションは動画とトランスクリプトとして S3 に暗号化保存されます。

⚡ 主要機能

1️⃣ AI コーディングアシスタントによる簡易セットアップ
  • Claude Code、Codex、Kiro に必要な要件を記述するだけでセットアップ可能
  • アシスタントは AWS の MCP スキルにガイドされ、調整可能なデフォルト設定で WorkSpace を構築
  • 環境構築の試行錯誤が減り、本番投入までの時間を短縮
2️⃣ Amazon Bedrock AgentCore との直接接続
  • AgentCore 上のエージェントをエージェントコードを書かずに AWS 認証情報で直接接続
  • 新しいツーリングにより 1 回の呼び出しで複数アクションを実行、基盤モデルの computer use アクションを活用
  • 呼び出し回数が減り、コストの低減と精度の向上につながる
3️⃣ OIDC 認証と On-Behalf-Of サインイン
  • 既存の SAML に加えて OIDC 互換の任意の ID プロバイダーで認証可能
  • サインインを組織の IdP に直接ルーティングし、普段の企業認証情報をそのまま使用
  • On-Behalf-Of サインインで、エージェントがサインインユーザーのディレクトリ ID・権限・グループポリシーを継承
4️⃣ セッションリプレイによる監査
  • セッションのスクリーンショットを動画に変換し、操作内容を平易な文章のトランスクリプトで記録
  • 記録は自組織の S3 バケットに保存され、独自の KMS キーで暗号化可能
  • セキュリティレビューやコンプライアンス監査でエージェントの行動を効率的に確認
5️⃣ イメージビルダーでのエージェントアクセス
  • API 変更により、イメージビルダーでもエージェントアクセス設定をサポート
  • AI エージェントがイメージ作成前にアプリケーションのインストール・設定・テストを実行可能

⚙️ 設定方法

✅ 前提条件

✓AWS アカウントと Amazon WorkSpaces Applications (AppStream 2.0) を利用できる権限
✓エージェント用のスタック・フリートを構成できる IAM 権限
✓OIDC / SAML 認証を使用する場合は、連携先 ID プロバイダーの設定情報
✓セッションリプレイを使用する場合は、保存先の S3 バケットと KMS キー

ステップ 1: AI コーディングアシスタントで環境を構築

AWS の MCP スキルを導入した Claude Code、Codex、Kiro などの AI コーディングアシスタントに、エージェントに必要な環境 (アプリケーション、ネットワーク、権限など) を自然言語で記述します。アシスタントが調整可能なデフォルト設定を使用して WorkSpace を構築します。

ステップ 2: セッションリプレイを有効化

Bash スタックのエージェントアクセス設定を更新 
aws appstream update-stack \
  --name my-agent-stack \
  --agent-access-config '{
    "Settings": [
      {"AgentAction": "COMPUTER_VISION", "Permission": "ENABLED"},
      {"AgentAction": "COMPUTER_INPUT", "Permission": "ENABLED"},
      {"AgentAction": "FORWARD_MCP_TOOLS", "Permission": "ENABLED"}
    ],
    "S3BucketArn": "arn:aws:s3:::my-agent-replay-bucket",
    "ScreenshotsUploadEnabled": true,
    "ReplaySessionEnabled": true,
    "KmsKeyArn": "arn:aws:kms:us-east-1:123456789012:key/xxxx",
    "UserControlMode": "VIEW_STOP"
  }'

記録は指定した S3 バケットに保存され、指定した KMS キーで暗号化されます。UserControlMode を VIEW_STOP にすると、人間の監視者がセッションを閲覧し、必要に応じて停止できます。

ステップ 3: ID プロバイダーと On-Behalf-Of サインインを設定

組織の OIDC 互換 ID プロバイダーをサインイン先として設定し、エージェントがサインインユーザーの ID・権限・グループポリシーを継承して動作するように構成します。具体的な設定手順は エージェントアクセスのドキュメント を参照してください。

✓データ主権の確保: リプレイ記録は自組織の S3 バケットに独自 KMS キーで暗号化保存

⚠️ デメリット・制約事項

🚧 制限事項

⚠Bedrock AgentCore とのコード不要の直接接続は、AgentCore 上に構築されたエージェントが対象
⚠セッションリプレイの保存には自組織の S3 バケットの用意が必要で、ストレージコストが発生
⚠公式発表では利用可能リージョンが明示されていないため、利用前に対応状況の確認が必要

🤔 考慮すべき点

⚠On-Behalf-Of サインインではユーザー権限をそのまま継承するため、最小権限の原則に基づく権限設計がこれまで以上に重要
⚠セッションリプレイには画面情報が含まれるため、S3 バケットのアクセス制御と KMS キーポリシーの厳格な管理が必要
⚠AI アシスタントによるセットアップはデフォルト設定を使用するため、本番投入前にネットワーク・セキュリティ設定のレビューを推奨
