Bot Control の新機能

📌 概要

AWS WAF が、AI ボットやエージェントによるコンテンツや API へのアクセスに対して、価格設定・計測・支払い収集を可能にする新しい Bot Control 機能を発表しました。

AI エージェントが消費するコンテンツや API について自律的な支払いをサポートするケースが増えるなか、コンテンツ所有者やパブリッシャーは、アクセスへの価格を設定し、サードパーティプロバイダーを通じて支払いを受け取り、スコープを限定したアクセスをエッジで直接付与できます。

AI ボットが保護対象リソースをリクエストすると、AWS WAF はマシン間支払い向けのオープンプロトコル x402 を使用し、機械可読な HTTP 402 Payment Required レスポンス (価格・支払い方法・ライセンス条項を含む) を返します。エージェントが支払い証明を提示すると、エッジで検証してスコープ限定のアクセストークンを発行し、単一のリクエストサイクル内でレスポンスを提供します。

⚠️ アップデート前の課題
  • AI トラフィックは「許可」か「ブロック」の二択のみで、価値に応じた課金ができなかった
  • 支払い収集には独自の認証・課金・決済の仕組みをアプリ側で構築する必要があった
  • 支払い検証やアクセス制御をオリジンまで到達させる必要があり、エッジでの即時処理ができなかった
➡️
✅ アップデート後の改善
  • 保護対象リソースに価格を設定し、AI ボットから支払いを収集できる
  • x402 ベースの HTTP 402 をエッジで返し、検証とトークン発行を単一サイクルで完結
  • エージェントの ID や意図に基づく差別化価格と、コンソール上での収益分析が可能

⚙️ 主要機能

💳 x402 プロトコルによる支払いフロー
  • 保護対象リソースへのリクエストに対し、機械可読な HTTP 402 Payment Required を返す
  • レスポンスには価格、受け入れ可能な支払い方法、ライセンス条項が含まれる
  • エージェントが支払い証明を提示すると、エッジで検証しスコープ限定トークンを発行
🎛️ コンソールでの価格設定とポリシー定義
  • AWS WAF コンソールから価格を設定できる
  • 検証ステータス (Web Bot Auth 署名を含む) に基づき AI ボットのポリシーを定義できる
  • エージェントの ID や意図に基づいて差別化された価格設定を適用できる
📊 決済プロバイダー連携と収益分析
  • 支払いの決済と検証は Coinbase の x402 Facilitator が提供
  • ステーブルコインで希望するウォレットに支払いを受け取れる
  • 収益分析を AWS WAF コンソールで直接確認できる

🛠️ 設定方法

前提条件

✓AWS WAF の Web ACL が Amazon CloudFront ディストリビューションに関連付けられていること
✓AWS WAF Bot Control が有効化されていること
✓支払いを受け取るためのウォレット (ステーブルコイン対応) を準備していること

導入手順

① 価格設定の構成
  • 記事、データフィード、ライセンス管理されたアーカイブなど、対象リソースごとにアクセス価格を定義
② ボット/エージェントポリシーの定義
  • 検証ステータス (Web Bot Auth 署名を含む) に基づきポリシーを定義。ID や意図に応じた差別化価格を適用
③ 決済連携と収益確認
  • Coinbase x402 Facilitator で決済・検証を行い、ステーブルコインで受け取り。収益分析はコンソールで確認

🎯 メリット

💼 ビジネス面

✓新たな収益源の創出: AI アクセスを単なるトラフィックではなく収益機会に転換
✓柔軟な価格戦略: エージェントの ID や意図に基づいた差別化価格
✓収益の可視化: コンソールで収益分析を直接確認し意思決定に活用

🔩 技術面

✓エッジでの即時処理: 検証〜トークン発行を単一サイクルで完結
✓オープンプロトコル: x402 採用でエージェントとの相互運用性が高い
✓追加開発の削減: 独自の課金・決済基盤を構築せずに課金を実現

⚠️ デメリット・制約事項

制限事項

✗CloudFront に関連付けられた WAF Web ACL のエッジロケーションでのみ利用可能
✗現時点の決済連携は Coinbase x402 Facilitator のみ (Stripe / MPP は近日対応)
✗支払いの受け取りはステーブルコイン対応ウォレットが前提

考慮すべき点

!AI エージェント側が x402 / HTTP 402 に対応している必要がある
!ステーブルコイン受け取りの会計・税務・規制上の取り扱いを事前確認
!価格・ポリシーが正規クローラー (検索エンジン等) に与える影響を考慮

💡 ユースケース

📰 1. メディアパブリッシャーによる記事課金
シナリオ: ニュースメディアが AI エージェントによる記事アクセスに課金したい
実装例: 記事 URL を保護対象に設定し 1 リクエスト単価を定義。学習目的の未検証クローラーには高価格、検証済み検索クローラーには別価格
効果: コンテンツの価値に応じた収益を AI トラフィックから得られる
🔌 2. データプロバイダーによる API 課金
シナリオ: データフィードを提供する企業が AI エージェントの API 利用を従量課金したい
実装例: API エンドポイントを保護対象に設定し x402 でアクセス価格と条項を提示。支払い証明後、スコープ限定トークンでアクセス許可
効果: 独自の課金基盤を構築せず、エッジで API アクセスをマネタイズ
🗄️ 3. ライセンスアーカイブへのスコープ付きアクセス
シナリオ: ライセンス管理アーカイブ事業者が、エージェントの意図に応じてアクセス条件を変えたい
実装例: エージェント ID と意図に基づく差別化価格を設定。Web Bot Auth 署名の検証ステータスでポリシーを分岐
効果: エージェント属性に応じた柔軟なアクセス制御と収益化を両立

💰 料金・利用可能リージョン

追加料金なし
AI traffic monetization は AWS WAF のお客様に追加料金なしで提供され、標準の AWS WAF 料金が適用されます。なお、決済・検証はサードパーティ (Coinbase x402 Facilitator) を通じて行われるため、決済手数料はプロバイダーの条件に従います。

利用可能リージョン

AWS WAF の Web ACL が Amazon CloudFront ディストリビューションに関連付けられているすべてのエッジロケーションで利用可能です。

📝 まとめ

AWS WAF の AI traffic monetization は、増加する AI ボットやエージェントのトラフィックを、「許可かブロックか」の二択から「課金して収益化する」という第三の選択肢へと拡張する重要なアップデートです。x402 プロトコルと HTTP 402 レスポンスにより、支払い検証からアクセストークン発行までをエッジで完結できます。

CloudFront と AWS WAF を利用しているコンテンツ所有者やパブリッシャーは、まずはコンソールで価格設定とポリシー定義を試し、収益分析を確認しながら本番導入を検討することを推奨します。
