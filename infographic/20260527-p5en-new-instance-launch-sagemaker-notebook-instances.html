Notebook Instances で P5en.48xlarge インスタンスタイプをサポート

2026 年 5 月 27 日

📋 概要

Amazon SageMaker Notebook Instances で NVIDIA H200 GPU を 8 基搭載した P5en.48xlarge インスタンスタイプが一般利用可能 (GA) になった。従来の P5 インスタンス (H100 GPU) と比較して、GPU メモリが 1.7 倍、GPU メモリ帯域幅が 1.4 倍に強化されている。

第 3 世代 EFA (Elastic Fabric Adapter) と Nitro v5 を採用し、最大 3200 Gbps のネットワーク帯域幅を提供。分散トレーニングワークロードにおけるレイテンシが最大 35% 削減される。

❌ アップデート前の課題

  • 最上位 GPU は P5.48xlarge (H100) で大規模 LLM 実験に GPU メモリ不足
  • 分散トレーニングの通信性能が限定的
  • CPU-GPU 間帯域幅がボトルネックでデータ前処理に時間がかかる

✅ アップデート後の改善

  • H200 の 1128 GB HBM3e で大規模モデルを直接実験可能
  • 3200 Gbps EFA で分散トレーニングコードの検証が高速化
  • Gen5 PCIe で CPU-GPU 間帯域幅 4 倍改善

⚡ 主要機能

🎮 NVIDIA H200 GPU 搭載

  • Nitro v5 による低レイテンシ通信
  • P5 比でレイテンシ最大 35% 削減
  • GPUDirect RDMA サポートによる GPU 間直接通信

🔧 設定方法

前提条件

  • P5en.48xlarge インスタンスが利用可能なリージョンに AWS アカウントがあること
  • SageMaker Notebook Instances 用の IAM ロールが設定されていること
  • P5en インスタンスのサービスクォータが確保されていること (デフォルトは 0 の場合あり)

ステップ 1: サービスクォータの確認

Bash クォータ確認コマンド 
# 現在のクォータを確認
aws service-quotas get-service-quota \
    --service-code sagemaker \
    --quota-code L-12345678 \
    --region us-east-1

ステップ 2: ノートブックインスタンスの作成

Bash P5en.48xlarge でノートブック作成 
# P5en.48xlarge でノートブックインスタンスを作成
aws sagemaker create-notebook-instance \
    --notebook-instance-name "my-p5en-notebook" \
    --instance-type ml.p5en.48xlarge \
    --role-arn arn:aws:iam::123456789012:role/SageMakerExecutionRole \
    --volume-size-in-gb 500 \
    --region us-east-1

ステップ 3: ステータス確認

Bash インスタンスステータス確認 
# インスタンスのステータスを確認
aws sagemaker describe-notebook-instance \
    --notebook-instance-name "my-p5en-notebook" \
    --region us-east-1

💡 ユースケース

🧠 大規模言語モデルのファインチューニング実験

70B パラメータの基盤モデルをドメイン固有データでファインチューニングするためのコード開発とパラメータ探索。

Python 70B モデルのロード例 
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

# H200 の大容量 GPU メモリを活用して 70B モデルをロード
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3-70B",
    torch_dtype=torch.bfloat16,
    device_map="auto"
)

# 1128 GB GPU メモリで全パラメータをロード可能
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3-70B")

✅ 効果: H100 では量子化やモデル並列化が必要だったモデルを、H200 の大容量メモリで直接ロードして実験可能

画像・テキスト・音声を統合するマルチモーダルモデルの開発。大量のデータパイプラインと推論テストを実施。

from torch.utils.data import DataLoader

# 大容量 NVMe SSD にデータセットをキャッシュ

マルチノード分散トレーニングのコードをノートブック環境で開発・デバッグし、本番トレーニングジョブへの移行前に動作確認。

Python 分散トレーニング検証例 
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel

# 8 GPU での分散トレーニングを単一ノードで検証
# NVSwitch 900 GB/s による高速 All-Reduce
dist.init_process_group(backend="nccl")

model = DistributedDataParallel(
    model,
    device_ids=[local_rank],
    output_device=local_rank
)

✅ メリット

💼 ビジネス面

  • 開発サイクルの短縮: 大規模モデルのプロトタイピングをノートブック環境で直接実行
  • インフラ管理の簡素化: マネージド環境で最新ハードウェアを利用可能
  • コスト効率: 必要な時だけインスタンスを起動、未使用時間の課金回避

🔬 技術面

  • 大規模モデル対応: 1128 GB GPU メモリで 100B パラメータ超モデル対応
  • 高速データ転送: Gen5 PCIe + 100 Gbps EBS で大規模データセット高速ロード
  • 低レイテンシ通信: Nitro v5 + 第 3 世代 EFA で同期オーバーヘッド削減

⚠️ デメリット・制約事項

制限事項

  • 高コストなインスタンスタイプ。小規模な実験には過剰スペックとなる可能性あり
  • サービスクォータがデフォルトで低く設定されている場合があり、引き上げ申請が必要
  • 利用可能リージョンが限定的 (4 リージョンのみ)

考慮すべき点

  • ノートブックインスタンスは単一インスタンス実行。マルチノード分散トレーニングには SageMaker Training Jobs を推奨
  • GPU メモリ最大活用にはモデル精度設定 (FP8, BF16 など) やバッチサイズの最適化が必要
  • 長時間トレーニングには SageMaker HyperPod や Training Jobs の利用を検討

📝 まとめ
