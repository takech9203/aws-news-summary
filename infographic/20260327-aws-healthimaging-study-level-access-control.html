🏥 スタディレベルのきめ細かなアクセス制御

DICOM Study/Series UID を IAM 条件キーに指定し、医療画像への最小権限アクセスを実現

2026.03.27 リリース日

📋 概要

AWS HealthImaging が DICOM スタディおよびシリーズレベルでのきめ細かなアクセス制御をサポートしました。IAM ポリシーで DICOM Study Instance UID や Series Instance UID を直接指定してアクセス権限を管理できるようになり、個々のイメージセット ARN を列挙する必要がなくなります。

AWS STS セッションポリシーを使用した動的な一時的アクセス許可の発行が可能となり、低レイテンシーの認証を実現します。データストア全体ではなく特定のスタディやシリーズにアクセスをスコープすることで、保護対象医療情報 (PHI) のセキュリティが強化されます。

❌ Before

  • 個々のイメージセット ARN を IAM ポリシーに列挙する必要があり管理が煩雑
  • DICOM スタディやシリーズ単位でのアクセス制御不可、データストア全体への許可が必要
  • 外部パートナーとの画像共有で最小権限の付与が困難

✅ After

  • DICOM Study/Series Instance UID を IAM ポリシーの条件キーとして直接使用可能
  • AWS STS セッションポリシーによる動的な一時的アクセス許可で低レイテンシー認証
  • スタディ/シリーズ単位のスコープで PHI の保護を強化

⚙️ 設定方法

ステップ 1: スタディレベルのアクセスを許可する IAM ポリシーを作成

特定の DICOM Study Instance UID に対するアクセスを許可する IAM ポリシーを作成します。Condition ブロックで medical-imaging:StudyInstanceUID 条件キーを指定します。

JSON IAM ポリシー設定例 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "medical-imaging:SearchImageSets",
                "medical-imaging:GetImageSet",
                "medical-imaging:GetImageFrame"
            ],
            "Resource": "arn:aws:medical-imaging:us-east-1:123456789012:datastore/datastoreId/*",
            "Condition": {
                "StringEquals": {
                    "medical-imaging:StudyInstanceUID": "1.2.840.113619.2.55.3.604688119.969.1234567890.123"
                }
            }
        }
    ]
}

ステップ 2: STS で一時的なアクセス認証情報を発行

外部パートナーや一時的なアクセスが必要なユーザーに対して、STS セッションポリシーでスコープされた一時認証情報を発行します。

Bash STS セッションポリシーの使用例 
aws sts assume-role \
    --role-arn arn:aws:iam::123456789012:role/HealthImagingAccess \
    --role-session-name radiologist-session \
    --policy '{
        "Version": "2012-10-17",
        "Statement": [{
            "Effect": "Allow",
            "Action": [
                "medical-imaging:SearchImageSets",
                "medical-imaging:GetImageSet",
                "medical-imaging:GetImageFrame"
            ],
            "Resource": "arn:aws:medical-imaging:us-east-1:123456789012:datastore/datastoreId/*",
            "Condition": {
                "StringEquals": {
                    "medical-imaging:StudyInstanceUID": "1.2.840.113619.2.55.3.604688119.969.1234567890.123"
                }
            }
        }]
    }'

ステップ 3: DICOMweb API でスタディデータにアクセス

発行された一時認証情報を使用して、DICOMweb API 経由でスタディデータにアクセスします。

Bash DICOMweb API でスタディ検索 
# 一時認証情報を環境変数に設定後、DICOMweb API で検索
aws medical-imaging search-image-sets \
    --datastore-id datastoreId \
    --search-criteria '{
        "filters": [{
            "operator": "EQUAL",
            "values": [{
                "DICOMStudyInstanceUID": "1.2.840.113619.2.55.3.604688119.969.1234567890.123"
            }]
        }]
    }'

💡 ユースケース

🔬 ユースケース 1: 病理医のケースレベルアクセス

病理診断において、特定の患者のケースを担当する病理医に対し、該当するスタディのみへのアクセスを許可。他の患者データへの不正アクセスを防ぎながら、必要な画像データに効率的にアクセスさせます。

✓ 担当ケースのスタディのみにアクセスを限定し、PHI の保護を強化しつつ病理医の業務効率を維持
🏥 ユースケース 2: 外部放射線科医とのスタディ共有

遠隔読影のために外部の放射線科医と特定のスタディを共有。STS セッションポリシーで 1 時間の有効期限付き一時認証情報を発行し、読影完了後にアクセスを自動的に失効させます。

✓ 有効期限付き一時認証情報により、外部放射線科医に特定スタディのみへの時限アクセスを安全に提供
🧪 ユースケース 3: 研究データの制御された配布

医療研究プロジェクトにおいて、研究者に対して特定のシリーズレベルでデータアクセスを許可。研究対象の画像シリーズのみにアクセスを限定し、同一スタディ内の他のシリーズへのアクセスを制限します。

✓ シリーズレベルのアクセス制御で研究目的に必要な画像データのみを提供し、PHI 保護と研究データ管理を両立

🎯 メリット

ビジネス面

  • 最小権限の原則に基づく PHI アクセス管理で HIPAA コンプライアンス遵守を支援
  • STS セッションポリシーによる一時的かつスコープされたアクセス許可で外部パートナーとの安全な連携
  • イメージセット ARN の個別管理が不要になり IAM ポリシー管理工数を大幅に削減

技術面

  • DICOM 標準の UID を条件キーとして使用しイメージセット ARN の列挙が不要に
  • STS セッションポリシーによる動的アクセス許可で 低レイテンシー認証を実現
  • DICOM の標準的な識別体系に沿ったアクセス制御で既存ワークフローとの統合が容易

⚠️ 制限事項・考慮点

制限事項

  • ⚠ 利用可能リージョンが 5 リージョンに限定、アジア太平洋では東京リージョンが未対応
  • ⚠ DICOM Study/Series Instance UID の管理はユーザー側の責任、UID の正確な把握が必要
  • ⚠ IAM ポリシーの条件キーで指定できる UID の数にはポリシーサイズの上限が適用

考慮すべき点

  • 💡 既存のイメージセット ARN ベースから UID ベースへの移行には段階的な移行計画が必要
  • 💡 STS セッションポリシーの有効期限管理を適切に行い、期限切れによるアクセス中断を防止
  • 💡 複数のスタディやシリーズにまたがるアクセスが必要な場合、ポリシー設計の複雑さが増す可能性
