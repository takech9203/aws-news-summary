🚀 主要機能

🔀 タスク並列実行

「Run all Tasks」クリック時に Kiro がタスクリストを解析し、依存関係グラフを自動構築。独立したタスクを Wave にグループ化して同時実行する。

  • 同じファイルに書き込むタスクは並列実行されない (競合防止)
  • セットアップ・インフラ関連のタスクが最初に実行される
  • テストは検証対象のコードの後に実行される
  • 各タスクは独立したコンテキストで実行、状態のリークなし
  • タスクが失敗しても他のタスクは継続して実行される
  • 設定不要 - 「Run all Tasks」をクリックするだけで自動最適化
  • 大規模スペック: 1 時間以上 → 約 15 分 (約 4 倍の高速化)

⚡ クイックプランモード

従来の 3 フェーズ (要件 → 設計 → タスク) の承認フローを 1 パスで完了。ワークスペースを自動スキャンし、言語・フレームワーク・プロジェクト構造を検出する。

  • プロンプトに基づいて 2-4 個の明確化質問を事前に提示
  • 質問は 4 つの次元: スコープと制約、記述の曖昧さ、実装フォーク、方向性の決定
  • 要件・設計・タスクのアーティファクトは引き続き作成・保存され、実装時の根拠として使用
  • 選択的再生成: タスク変更 → タスクのみ、設計変更 → 設計+タスク、スコープ変更 → 全パイプライン再実行

🔍 要件分析 (Neurosymbolic AI)

LLM と自動推論を組み合わせた Neurosymbolic AI による深層分析。「Analyze Requirements」ボタンから実行可能。

  • 曖昧性検出: 各要件の複数の解釈をサンプリングし、異なる開発者が異なる実装を行う可能性のある箇所を特定
  • 論理的分析: 自動推論により要件の整合性を数学的に検証し、矛盾する要件や記述の欠落を検出
  • 検出された問題に対して修正提案を提示

分析項目 説明

⚖️ メリット / デメリット

✅ メリット

ビジネス面:

  • 大規模スペックの実装時間が約 4 分の 1 に短縮
  • 品質と速度のトレードオフが解消
  • 実装前に矛盾や曖昧さを検出し、手戻り削減
  • 事前の明確化で無駄なトークン消費を回避

技術面:

  • ゼロコンフィグの並列実行
  • 障害耐性 (部分的成功の活用)
  • 選択的再生成でフィードバックループ高速化
  • 数学的論理検証で要件の整合性保証

⚠️ 制限事項・考慮点

  • 同一ファイルへの書き込みが多いスペックでは効果が限定的
  • 未知の技術領域探索にはステップバイステップの方が適切な場合あり
  • Neurosymbolic AI は 100% の検出率を保証しない
  • タスク間の依存が多い場合は速度向上が限定的
  • クイックプランモードでは生成結果の事後レビューが重要
  • シンプルな機能に対して要件分析は過剰な場合がある
  • 並列実行中のタスク失敗時に依存タスクが待機状態となるケースあり

💡 ユースケース

🎯 ユースケース 1: 大規模 API エンドポイントの一括実装

シナリオ: REST API の 10 個のエンドポイントをスペックとして定義し、実装する。

✅ 効果: 各エンドポイントが異なるファイルに実装される場合、6-8 個のタスクが同時に実行。従来 60-90 分 → 約 15 分で完了。

🎯 ユースケース 2: 明確な仕様がある機能の高速実装

シナリオ: チーム内で既に議論済みのユーザー認証機能を実装。スコープ、制約、エッジケースが明確に定まっている。

✅ 効果: 2-4 個の確認質問に答えるだけで要件・設計・タスクが一括生成。アイデアからタスクリストまでが 1 パスで完了。

🎯 ユースケース 3: 複雑なビジネスルールの要件検証

シナリオ: EC サイトの割引ルールを複数定義したが、特定の条件の組み合わせで矛盾が発生する可能性がある。

✅ 効果: 「会員割引 30% + クーポン割引 20% = 合計 50%」と「最大割引率 40%」のような矛盾を自動検出し、修正提案を提示。
