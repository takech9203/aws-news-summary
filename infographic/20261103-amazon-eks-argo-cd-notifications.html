Amazon EKS

🔔 EKS Capability for Argo CD が
Argo CD Notifications をサポート

📅 リリース日: 2026 年 11 月 3 日

📝 概要

Amazon EKS の Capability for Argo CD が Argo CD Notifications をサポートしました。アプリケーションの同期成功・同期失敗・ヘルス状態の変化をトリガーに、通知を自動送信できます。アップストリームの Argo CD と同じ方法で、トリガーとテンプレートを定義し、Application のアノテーションでサブスクライブします。

Slack、PagerDuty、Opsgenie、Amazon SQS、Amazon EventBridge を含む 16 種類の通知サービスに配信可能。AWS サービスへは IAM Capability Role で認証され、サードパーティのトークンは AWS Secrets Manager の ARN 参照で自動解決されるため、クラスター内に認証情報を保存しない安全な構成を実現できます。

❌ アップデート前の課題
  • 通知機能がなく、デプロイ結果を知るには Argo CD の UI を監視するか独自の仕組みが必要
  • 同期失敗やヘルス変化を Slack や PagerDuty へ自動連携する標準的な方法がなかった
  • AWS のイベント駆動ワークフローへの取り込みには認証情報管理を含むカスタム実装が必要
✅ アップデート後の改善
  • マネージドな通知コントローラーで同期・失敗・ヘルス変化を 16 種類のサービスへ自動配信
  • SQS / EventBridge への送信は IAM Capability Role で認証、クラスターに認証情報不要
  • サードパーティ認証情報は Secrets Manager の ARN 参照で管理、トークン本体の保存が不要

マネージド通知コントローラーが、ConfigMap で定義したトリガーとテンプレートに基づき、Application のイベントを各通知サービスへ配信します。AWS サービスへは IAM Capability Role で認証し、サードパーティの認証情報は Secrets Manager の ARN 参照で解決できます。

⚡ 主要機能

🔔 マネージドな通知コントローラー

通知コントローラーを EKS がマネージドで実行。同期成功・同期失敗・ヘルス状態の変化をトリガーに通知を送信します。アップストリームと同じ方式で argocd-notifications-cm にサービス・トリガー・テンプレートを定義し、Application のアノテーションでサブスクライブ。事前定義されたトリガー・テンプレートのカタログはインストールされないため、必要なものを自分で定義します。

👤 IAM Capability Role による AWS サービスへの認証

Amazon SQS と Amazon EventBridge への送信は IAM Capability Role で認証され、サービス定義に認証情報は不要。クラスター内に認証情報を保存することなくデプロイイベントをイベント駆動ワークフローへルーティングできます。適切な権限とリソースポリシーがあれば、別リージョン・別アカウントのキューやイベントバスへも送信可能です。

🔑 AWS Secrets Manager との統合

Slack トークンなどの認証情報は、Secret の値に Secrets Manager の ARN を指定可能。EKS が送信時に IAM Capability Role で ARN を自動解決するため、クラスター内にトークン本体を保存する必要がありません。解決された値は約 5 分間再利用され、ローテーションされたシークレットは約 5 分以内に反映されます。

🔬 技術仕様

📋 通知の構成要素

構成要素詳細
argocd-notifications-cmArgo CD の namespace に作成する ConfigMap。サービス、トリガー、メッセージテンプレートを定義
オプトインラベルConfigMap に eks.amazonaws.com/managed-notifications: "enabled" ラベルが必須。値は正確に enabled である必要がある
argocd-notifications-secret同じ namespace に作成するオプションの Secret。認証情報または Secrets Manager ARN を保持
Application のアノテーションnotifications.argoproj.io/subscribe.{トリガー}.{サービス}: {宛先} 形式で各 Application をサブスクライブ

⚖️ アップストリーム Argo CD との主な差異

項目詳細
非対応サービスemail、teams、webhook、rocketchat、nats、alertmanager は利用不可
サポートされる設定キーservice.、trigger.、template.、subscriptions、defaultTriggers、context のみ。その他のキーは無視される
サイズ制限template. / trigger. 値は 64 KiB まで。ConfigMap 全体は 256 KiB まで
テンプレート関数Sprig 関数の一部 (env、merge、乱数生成系など) は利用不可
宛先 URL の要件https 必須、ホスト名はパブリックに解決される FQDN のみ。TLS 証明書検証は常に有効
gcppubsubインライン認証情報 (keyJSON の $ 参照) が必須。keyFile や Application Default Credentials は拒否される

🛡️ IAM Capability Role のポリシー例

JSON SQS / EventBridge への送信権限 
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "SendToQueue",
      "Effect": "Allow",
      "Action": [
        "sqs:GetQueueUrl",
        "sqs:SendMessage"
      ],
      "Resource": "arn:aws:sqs:us-west-2:111122223333:my-queue"
    },
    {
      "Sid": "PutEvents",
      "Effect": "Allow",
      "Action": "events:PutEvents",
      "Resource": "arn:aws:events:us-west-2:111122223333:event-bus/my-event-bus"
    }
  ]
}

コントローラーは送信前にキュー名から URL を取得するため、sqs:SendMessage だけでなく sqs:GetQueueUrl も必要です。キューがカスタマーマネージド KMS キーで暗号化されている場合は、kms:GenerateDataKey と kms:Decrypt の許可も追加します。

🛠️ 設定方法

✅ 前提条件

✓Argo CD Capability が作成済みの EKS クラスター
✓クラスターと通信できるように設定された kubectl CLI
✓少なくとも 1 つの Argo CD Application

STEP 1通知設定の ConfigMap と Secret を作成

YAML argocd-notifications-cm / argocd-notifications-secret 
apiVersion: v1
kind: ConfigMap
metadata:
  name: argocd-notifications-cm
  namespace: argocd
  labels:
    eks.amazonaws.com/managed-notifications: "enabled"
data:
  service.slack: |
    token: $slack-token
  trigger.on-sync-succeeded: |
    - when: app.status.operationState.phase in ['Succeeded']
      send: [app-sync-succeeded]
  template.app-sync-succeeded: |
    message: "Application {{.app.metadata.name}} synced successfully."
---
apiVersion: v1
kind: Secret
metadata:
  name: argocd-notifications-secret
  namespace: argocd
type: Opaque
stringData:
  slack-token: arn:aws:secretsmanager:us-west-2:111122223333:secret:my-secret

通知コントローラーはオプトインラベル eks.amazonaws.com/managed-notifications: "enabled" のない ConfigMap を無視するため、ラベルの付与が必須です。この例では Slack トークンの代わりに Secrets Manager の ARN を指定しており、EKS が送信時に自動解決します。

STEP 2Secrets Manager へのアクセス権限を付与

JSON IAM Capability Role に付与するポリシー 
{
  "Effect": "Allow",
  "Action": "secretsmanager:GetSecretValue",
  "Resource": "arn:aws:secretsmanager:us-west-2:111122223333:secret:my-secret-*"
}

シークレットがカスタマーマネージド KMS キーで暗号化されている場合は、そのキーに対する kms:Decrypt の許可も必要です。

STEP 3Application をサブスクライブ

YAML Application のアノテーション 
metadata:
  annotations:
    notifications.argoproj.io/subscribe.on-sync-succeeded.slack: my-channel

アノテーション名でトリガーとサービスを指定し、値に宛先 (この例では Slack チャンネル名) を指定します。Application を同期し、チャンネルにメッセージが届くことを確認します。

STEP 4トラブルシューティング

Bash ConfigMap のイベント確認 
kubectl describe configmap argocd-notifications-cm -n argocd

通知が届かない場合、ConfigMap に記録される Kubernetes イベント (NotificationConfigInvalid、NotificationSecretRejected など) を確認します。より詳細な調査には、EKS Capability のログタイプ EKS_CAPABILITY_ARGOCD_NOTIFICATION_LOGS を使用して、通知コントローラーのログを CloudWatch Logs、Amazon S3、Amazon Data Firehose に配信できます。

💡 メリット

💼 ビジネス面

✓デプロイの可視性向上: Argo CD の UI を監視し続けることなく、チームがデプロイ結果を即座に把握でき、障害対応の初動が早くなる
✓運用コストの削減: 通知の仕組みを自前で構築・運用する必要がなく、追加料金なしで利用できる
✓セキュリティリスクの低減: 認証情報をクラスター内に保存せず、IAM と Secrets Manager で一元管理できる

⚙️ 技術面

✓アップストリーム互換の設定方法: トリガー・テンプレート・アノテーションの定義方法が同じため、既存の知識や設定資産を活用できる
✓イベント駆動アーキテクチャとの統合: EventBridge や SQS 経由でデプロイイベントを後続のワークフロー (自動テスト、監査記録、ChatOps など) に接続できる
✓シークレットの自動ローテーション対応: Secrets Manager の ARN 参照により、ローテーションされた認証情報が約 5 分以内に自動反映される

⚠️ デメリット・制約事項

🚫 制限事項

✗アップストリームが対応する email、teams、webhook、rocketchat、nats、alertmanager サービスは利用できない
✗事前定義されたトリガー・テンプレートのカタログは提供されず、必要な定義をすべて自分で作成する必要がある
✗template. / trigger. 値は 64 KiB、ConfigMap 全体は 256 KiB のサイズ制限があり、一部の Sprig テンプレート関数は利用できない
✗宛先 URL は https かつパブリックに解決されるホスト名のみ許可され、TLS 証明書検証は無効化できない

🤔 考慮すべき点

⚠ConfigMap にオプトインラベル eks.amazonaws.com/managed-notifications: "enabled" がないと設定が一切読み込まれないため、設定時の付け忘れに注意が必要
⚠無効なサービス定義は該当 namespace の設定全体を無効化する (未対応のサービスタイプは単独で無視される) ため、設定変更時はイベントで NotificationConfigValid を確認することが望ましい
⚠namespace ごとのセルフサービス設定を有効化すると、テンプレートから {{ .secrets }} 変数が利用できなくなるため、認証情報はサービス定義の $ 参照で扱う必要がある
⚠EventBridge はイベント詳細に JSON オブジェクトを要求するため、テンプレートの message が有効な JSON を出力するように記述する必要がある

🎯 ユースケース

💬 ユースケース 1: Slack によるデプロイ結果の共有

シナリオ: 開発チームが GitOps で複数のマイクロサービスをデプロイしており、同期の成功・失敗をチームの Slack チャンネルで共有したい。

YAML同期失敗を Slack へ通知
data:
  service.slack: |
    token: $slack-token
  trigger.on-sync-failed: |
    - when: app.status.operationState.phase in ['Error', 'Failed']
      send: [app-sync-failed]
  template.app-sync-failed: |
    message: "Application {{.app.metadata.name}} の同期に失敗しました。"

効果: Argo CD の UI を監視することなく、デプロイの失敗をチーム全員が即座に認識でき、障害対応が迅速化する。Slack トークンは Secrets Manager の ARN 参照で管理できる。

🚌 ユースケース 2: EventBridge 経由のイベント駆動ワークフロー

シナリオ: 同期成功イベントをトリガーに、E2E テストの自動実行や CMDB への記録などの後続処理を自動化したい。

YAMLEventBridge への配信設定
data:
  service.eventbridge: |
    region: us-west-2
    eventBusName: my-event-bus
    source: argocd
    detailType: argocd-sync
  template.app-sync-succeeded: |
    message: '{"app": "{{.app.metadata.name}}", "phase": "Succeeded"}'

効果: 認証情報をクラスターに保存することなく、デプロイイベントを EventBridge ルール経由で Lambda や Step Functions に接続し、デプロイ後の処理を完全に自動化できる。

🚨 ユースケース 3: PagerDuty による本番障害のエスカレーション

シナリオ: 本番環境の Application のヘルス状態が Degraded になった場合に、オンコール担当者へ自動でインシデントを起票したい。

YAMLヘルス低下を PagerDuty へ連携
metadata:
  annotations:
    notifications.argoproj.io/subscribe.on-health-degraded.pagerdutyv2: my-service-key

効果: 本番環境の異常を人手の監視に頼らず検知し、インシデント管理ツールと連携した迅速なエスカレーションフローを実現できる。

💰 料金・利用可能リージョン

💵 料金

Argo CD Notifications 機能自体は追加料金なしで利用できます。通知で使用するサービスに関連するリソースには標準料金が適用されます。たとえば Amazon SQS のメッセージ送信、Amazon EventBridge のイベント発行、AWS Secrets Manager のシークレット保存・API 呼び出しには、各サービスの標準料金が発生します。

🌍 利用可能リージョン

EKS Capability for Argo CD が利用可能なすべての AWS リージョンで利用できます。

🔗 関連サービス・機能

→EKS Capability for Argo CD: 本機能の前提となる、Argo CD をマネージドで提供する EKS の Capability
→Amazon EventBridge: デプロイイベントを受け取り、ルールに基づいて Lambda や Step Functions などへルーティングするイベントバス
→Amazon SQS: デプロイイベントをキューイングし、独自のコンシューマーで処理するためのメッセージキュー
→AWS Secrets Manager: サードパーティ認証情報を安全に保管し、ARN 参照で自動解決されるシークレット管理サービス
→AWS IAM: Capability Role を通じて SQS、EventBridge、Secrets Manager へのアクセスを制御

📌 まとめ

EKS Capability for Argo CD に Argo CD Notifications が追加され、デプロイ結果を Slack、PagerDuty、Amazon SQS、Amazon EventBridge など 16 種類のサービスへ追加料金なしで通知できるようになりました。IAM Capability Role による認証と Secrets Manager の ARN 参照により、クラスター内に認証情報を保存しない安全な構成が可能です。
