⚡ レスポンスストリーミングが全商用リージョンに拡大

InvokeWithResponseStream API でデータを段階的にストリーミング配信
2026 年 4 月 7 日
Response Streaming

📋 概要

AWS Lambda のレスポンスストリーミングが、すべての商用 AWS リージョンで利用可能になりました。InvokeWithResponseStream API を使用して、Lambda 関数のレスポンスペイロードを段階的にストリーミングする機能です。

従来のバッファリング方式では、関数の実行が完全に終了するまでクライアントにレスポンスが返されませんでしたが、ストリーミングを使用することで、データが生成されるとすぐにクライアントに送信を開始できます。レスポンスペイロードはデフォルトで最大 200 MB までサポートされています。

現在、Node.js マネージドランタイムとカスタムランタイムでサポートされており、リアルタイムデータ処理、大規模レポート生成、生成 AI アプリケーションなどに最適です。

🔧 主要機能

🔌 InvokeWithResponseStream API
Lambda 関数のレスポンスをストリーミング形式で返す API です。クライアントは関数の実行完了を待たずに、部分的なレスポンスを受信できます。Lambda 関数 URL と統合して、HTTP ストリーミングレスポンスを直接返すことも可能です。
📦 大容量ペイロードサポート
レスポンスペイロードはデフォルトで最大 200 MB まで対応。従来のバッファリングモードの 6 MB 制限と比較して大幅に拡大されており、大規模なデータセットやファイルの転送に適しています。
🌍 全商用リージョンでの利用可能性
すべての商用 AWS リージョンで利用可能になりました。グローバルなアプリケーションで一貫したストリーミング体験を提供でき、マルチリージョンデプロイメントでの設計が簡素化されます。

💻 コード例

Lambda 関数側 - レスポンスストリーミングハンドラー

JavaScript Node.js Lambda Handler 
// Lambda 関数側 - レスポンスストリーミングのハンドラー
export const handler = awslambda.streamifyResponse(
  async (event, responseStream, context) => {
    // Content-Type を設定
    const metadata = {
      statusCode: 200,
      headers: {
        "Content-Type": "application/json",
        "Transfer-Encoding": "chunked"
      }
    };

    responseStream = awslambda.HttpResponseStream.from(
      responseStream,
      metadata
    );

    // データを段階的にストリーミング
    for (let i = 0; i < 10; i++) {
      responseStream.write(
        JSON.stringify({ chunk: i, data: `Processing ${i}...` }) + "\n"
      );
      await new Promise(resolve => setTimeout(resolve, 500));
    }

    responseStream.end();
  }
);

クライアント側の呼び出し例

JavaScript AWS SDK v3 Client 
import {
  LambdaClient,
  InvokeWithResponseStreamCommand
} from "@aws-sdk/client-lambda";

const client = new LambdaClient({ region: "ap-northeast-1" });

const command = new InvokeWithResponseStreamCommand({
  FunctionName: "my-streaming-function",
  Payload: JSON.stringify({ query: "example" })
});

const response = await client.send(command);

// ストリーミングレスポンスを処理
for await (const event of response.EventStream) {
  if (event.PayloadChunk) {
    const chunk = new TextDecoder().decode(
      event.PayloadChunk.Payload
    );
    console.log("Received chunk:", chunk);
  }
}

🛠️ 設定方法

前提条件

  • AWS アカウントを持っていること
  • Lambda 関数を作成する IAM 権限があること
  • Node.js マネージドランタイムまたはカスタムランタイムを使用していること
  • AWS CLI v2 または AWS SDK がインストールされていること

ステップ 1: Lambda 関数の作成

Bash Lambda 関数作成 
# ストリーミング対応の Lambda 関数を作成
aws lambda create-function \
  --function-name my-streaming-function \
  --runtime nodejs20.x \
  --role arn:aws:iam::123456789012:role/lambda-execution-role \
  --handler index.handler \
  --zip-file fileb://function.zip \
  --region ap-northeast-1

ステップ 2: Lambda 関数 URL の作成

Bash 関数 URL 作成 - ストリーミングモード有効化 
# 関数 URL を作成してストリーミングを有効化
aws lambda create-function-url-config \
  --function-name my-streaming-function \
  --auth-type AWS_IAM \
  --invoke-mode RESPONSE_STREAM \
  --region ap-northeast-1

ステップ 3: ストリーミング呼び出しのテスト

Bash ストリーミングテスト 
# InvokeWithResponseStream API で呼び出し
aws lambda invoke-with-response-stream \
  --function-name my-streaming-function \
  --payload '{"key": "value"}' \
  --region ap-northeast-1 \
  output.json

✅ メリット・デメリット

✅ メリット

ビジネス面

  • 📈 ユーザー体験の向上: レスポンスを段階的に配信し、体感待ち時間 (TTFB) を短縮
  • 🌍 グローバル展開の簡素化: 全商用リージョン対応でアプリケーション設計が容易に
  • 💰 大規模データ転送のコスト効率: 200 MB まで直接ストリーミング可能

技術面

  • ⚡ 低レイテンシー: データ生成と同時に配信開始、TTFB が大幅短縮
  • 💾 メモリ効率: 一括バッファリング不要でメモリ使用量を最適化
  • 📦 ペイロード拡大: 6 MB から 200 MB に拡大
  • 🔄 リージョンパリティ: 全商用リージョンで同一機能を使用可能

⚠️ 制限事項・注意点

制限事項

  • 🔒 Node.js マネージドランタイムとカスタムランタイムのみ対応 (Python、Java 等は非対応)
  • ⛔ 非同期呼び出しではストリーミング使用不可
  • 🏛️ GovCloud / 中国リージョンは対象外

考慮すべき点

  • 🔧 ストリーム途中でのエラー処理の実装が必要
  • 📏 API Gateway 経由の場合、ペイロード制限 10 MB が適用される場合あり
  • 💻 クライアント側でストリーミング処理の実装が必要

🎯 ユースケース

🤖 生成 AI チャットアプリケーション

生成 AI モデルの推論結果をリアルタイムでクライアントにストリーミング。ユーザーは AI の回答を一文字ずつリアルタイムで受信でき、体感待ち時間が大幅に短縮されます。

JavaScript AI ストリーミング例 
export const handler = awslambda.streamifyResponse(
  async (event, responseStream, context) => {
    const metadata = {
      statusCode: 200,
      headers: { "Content-Type": "text/event-stream" }
    };
    responseStream = awslambda.HttpResponseStream.from(
      responseStream, metadata
    );

    // AI モデルの推論結果をストリーミング
    const aiResponse = await invokeAIModel(event.prompt);
    for await (const token of aiResponse.tokens) {
      responseStream.write(
        `data: ${JSON.stringify({ token })}\n\n`
      );
    }
    responseStream.end();
  }
);
📊 大規模レポート生成

データベースから大量のデータを取得し、CSV や JSON 形式のレポートをストリーミングで配信。200 MB までのレポートをストリーミングで配信でき、クライアントはダウンロードをすぐに開始できます。

JavaScript CSV レポートストリーミング例 
export const handler = awslambda.streamifyResponse(
  async (event, responseStream, context) => {
    const metadata = {
      statusCode: 200,
      headers: {
        "Content-Type": "text/csv",
        "Content-Disposition": "attachment; filename=report.csv"
      }
    };
    responseStream = awslambda.HttpResponseStream.from(
      responseStream, metadata
    );

    // CSV ヘッダーを送信
    responseStream.write("id,name,value\n");

    // ページネーションでデータを取得しストリーミング
    let lastKey = null;
    do {
      const result = await queryDatabase(lastKey);
      for (const item of result.items) {
        responseStream.write(
          `${item.id},${item.name},${item.value}\n`
        );
      }
      lastKey = result.lastKey;
    } while (lastKey);

    responseStream.end();
  }
);
📡 リアルタイムダッシュボード

Server-Sent Events (SSE) を使用して、リアルタイムのメトリクスやステータス更新をクライアントに配信。WebSocket を使用せずに、サーバーレスアーキテクチャでリアルタイムのデータ配信が可能になります。

JavaScript SSE メトリクスストリーミング例 
export const handler = awslambda.streamifyResponse(
  async (event, responseStream, context) => {
    const metadata = {
      statusCode: 200,
      headers: { "Content-Type": "text/event-stream" }
    };
    responseStream = awslambda.HttpResponseStream.from(
      responseStream, metadata
    );

    // メトリクスを定期的にストリーミング
    for (let i = 0; i < 60; i++) {
      const metrics = await fetchMetrics();
      responseStream.write(
        `data: ${JSON.stringify(metrics)}\n\n`
      );
      await new Promise(r => setTimeout(r, 1000));
    }
    responseStream.end();
  }
);
