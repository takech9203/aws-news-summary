Amazon ECR

📦 プライベートレジストリ向けグローバル認証トークン

🗓️ リリース日: 2026 年 11 月 17 日 | Amazon Elastic Container Registry

📝 概要

Amazon ECR がプライベートレジストリ向けのグローバル認証トークンをサポート。AWS Sign-In の CreateBearerToken API で取得した単一のトークンを、同一 AWS パーティション内のすべての ECR プライベートレジストリで利用できるようになりました。

1 つ
全リージョン対応のトークン数
5 分〜12 時間
設定可能な有効期間
追加料金なし
既存の ECR 料金のまま利用可能

❌ アップデート前の課題

✗リージョンごとに GetAuthorizationToken API で個別の認証トークンを取得する必要があった
✗クロスリージョンプルのプロキシサービスでは、リージョンごとのトークン取得・更新・有効期限調整で運用負荷が高かった
✗マルチリージョン CI/CD パイプラインで、リージョン数に比例して認証処理が増加

✅ アップデート後の改善

✓単一のトークンを同一パーティション内のすべての ECR プライベートレジストリで利用可能
✓プロキシサービスは 1 つのトークン管理だけでよく、運用負荷が大幅に軽減
✓有効期間を 5 分〜12 時間で設定でき、セキュリティ要件に応じた短命トークン運用が可能

従来はリージョンごとに個別のトークンを取得・管理する必要がありましたが、今回のアップデートにより、AWS Sign-In の CreateBearerToken API で取得した 1 つのグローバルトークンで、同一パーティション内のすべての ECR プライベートレジストリに認証できるようになりました。

⚙️ 主要機能

🔑 グローバル認証トークンの発行
→AWS Sign-In の CreateBearerToken API または aws signin create-bearer-token CLI コマンドで取得
→ecr.amazonaws.com リソース向けのベアラートークンとして発行され、同一パーティション内の全リージョンで有効
⏱️ 設定可能なトークン有効期間
→デフォルトの有効期間は 12 時間、最短 5 分まで短縮可能
→セキュリティ要件に応じた短命トークンの運用が可能
🔄 既存ツールとの互換性
→Docker CLI の docker login でユーザー名 AWS と組み合わせて利用可能
→Amazon ECR Docker Credential Helper はリージョントークンとグローバルトークンの両方に対応
→Docker Registry HTTP API でも HTTP Basic 認証ヘッダーとして利用可能
🔍 セキュリティと監査機能
→CloudTrail の signInSessionArn フィールドで、トークンを要求した AWS セッションとトークンの使用を関連付け可能
→IntrospectOAuth2TokenWithIAM API でトークンのアクティブ状態とメタデータを確認可能

📐 技術仕様: トークンの比較

項目 🌍 グローバルトークン 📍 リージョントークン
トークンの取得 AWS Sign-In CreateBearerToken または aws signin create-bearer-token Amazon ECR GetAuthorizationToken または aws ecr get-login-password
リージョンスコープ 同一パーティション内のすべての AWS リージョンで有効 トークンを発行したリージョンのみで有効
有効期間 デフォルト 12 時間、最短 5 分まで設定可能 12 時間固定
権限スコープ 要求した IAM プリンシパルの権限に準拠 要求した IAM プリンシパルの権限に準拠
⚠️注意: どちらのトークンも権限スコープは IAM 権限と一致します。認証トークンによって追加の ECR 権限が付与されることはなく、要求する ECR 操作の権限を別途保有している必要があります。

🔐 必要な IAM 権限

グローバルトークンの取得には signin:CreateBearerToken 権限と、イメージまたはリポジトリ操作に必要な Amazon ECR 権限が必要です。

JSON IAM ポリシー例 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "CreateECRGlobalToken",
            "Effect": "Allow",
            "Action": "signin:CreateBearerToken",
            "Resource": "arn:aws:signin:*:*:service-principal/ecr.amazonaws.com"
        }
    ]
}

🛠️ 設定方法

前提条件: AWS CLI が設定済みであること、IAM プリンシパルに signin:CreateBearerToken 権限と対象の ECR 操作に必要な権限が付与されていること。

1
グローバルトークンの取得
Bash AWS Sign-In でトークンを取得 
TOKEN=$(aws signin create-bearer-token \
     --grant-type client_credentials \
     --resource ecr.amazonaws.com \
     --region us-east-1 \
     --query accessToken \
     --output text)

デフォルトでは 12 時間有効なトークンが発行されます。

2
Docker への認証
Bash docker login で任意リージョンに認証 
printf '%s' "$TOKEN" | docker login \
     --username AWS \
     --password-stdin \
     123456789012.dkr.ecr.ap-northeast-1.amazonaws.com

トークンを発行したリージョンに関係なく、同一パーティション内の任意のリージョンのレジストリエンドポイントに認証できます。

3
HTTP API での利用 (オプション)
Bash Docker Registry HTTP API で Basic 認証 
GLOBAL_TOKEN=$(aws signin create-bearer-token \
     --grant-type client_credentials \
     --resource ecr.amazonaws.com \
     --query accessToken \
     --output text)
TOKEN=$(printf 'AWS:%s' "$GLOBAL_TOKEN" | base64 | tr -d '\n')

curl -i \
     -H "Authorization: Basic $TOKEN" \
     https://123456789012.dkr.ecr.ap-northeast-1.amazonaws.com/v2/my-repo/tags/list

ユーザー名 AWS、コロン、グローバルトークンを連結して Base64 エンコードし、HTTP Basic 認証ヘッダーとして渡します。

💡 メリット

💼 ビジネス面

✓運用コストの削減: リージョンごとのトークン管理が不要になり、マルチリージョン環境のプロキシサービスや CI/CD パイプラインの運用負荷が軽減
✓可用性向上の支援: クロスリージョンのイメージプルをルーティングするプロキシ構成が簡素化され、レイテンシーや可用性の最適化パターンを導入しやすくなる
✓追加費用なし: 既存の Amazon ECR の料金体系のまま利用可能

🔧 技術面

✓認証処理の一元化: 単一の CreateBearerToken 呼び出しで、同一パーティション内のすべてのリージョンに対する認証が完結
✓柔軟な有効期間: 最短 5 分の短命トークンから最長 12 時間まで、セキュリティ要件に応じた設定が可能
✓監査性の向上: CloudTrail の signInSessionArn によるトークン使用の追跡や、IntrospectOAuth2TokenWithIAM API によるトークン状態の確認が可能
✓既存環境との互換性: 既存のリージョントークンは従来どおり動作するため、段階的な移行が可能

⚠️ デメリット・制約事項

🚧 制限事項

✗グローバルトークンの有効範囲は同一 AWS パーティション内に限定される (パーティションをまたぐ利用は不可)
✗Amazon ECR Docker Credential Helper は現時点で多要素認証 MFA をサポートしていない
✗グローバルトークンの取得には、従来の ECR 権限に加えて signin:CreateBearerToken 権限の付与が必要

🤔 考慮すべき点

⚠️トークンの権限スコープは IAM 権限と一致するため、トークン自体が追加の ECR 権限を付与することはない
⚠️1 つのトークンが全リージョンで有効になるため、トークン漏えい時の影響範囲が広がる。短い有効期間の設定や CloudTrail による監査の活用を検討する
⚠️既存のリージョントークンベースの運用を直ちに変更する必要はなく、ユースケースに応じて使い分けが可能

🎯 ユースケース

1️⃣ クロスリージョンプルを行うプロキシサービスの認証簡素化

レイテンシーや可用性を最適化するため、複数リージョンの ECR レジストリへのコンテナプルをルーティングするプロキシサービスを運用。従来はリージョンごとにトークンを取得・更新する必要があった。

Bash プロキシサービス側で単一トークンを定期更新 
# プロキシサービス側で単一のグローバルトークンを定期更新
TOKEN=$(aws signin create-bearer-token \
     --grant-type client_credentials \
     --resource ecr.amazonaws.com \
     --query accessToken \
     --output text)
# このトークンを全リージョンのレジストリエンドポイントへのリクエストに使用
✅ 効果: リージョンごとのトークン取得・更新・調整が不要になり、プロキシの実装と運用が大幅に簡素化される。
2️⃣ マルチリージョン CI/CD パイプラインでのイメージ配布

ビルドしたコンテナイメージを複数リージョンの ECR リポジトリにプッシュするデプロイパイプラインを運用。

Bash 1 回の認証で全リージョンへプッシュ 
TOKEN=$(aws signin create-bearer-token \
     --grant-type client_credentials \
     --resource ecr.amazonaws.com \
     --query accessToken \
     --output text)

for REGION in us-east-1 ap-northeast-1 eu-west-1; do
  printf '%s' "$TOKEN" | docker login --username AWS --password-stdin \
       123456789012.dkr.ecr.${REGION}.amazonaws.com
  docker push 123456789012.dkr.ecr.${REGION}.amazonaws.com/my-app:latest
done
✅ 効果: 1 回の認証トークン取得で全リージョンへのプッシュが可能になり、パイプラインの認証ステップが削減される。
3️⃣ 短命トークンによるセキュアな一時アクセス

自動化ジョブや一時的な作業で ECR へのアクセスが必要だが、長時間有効なトークンの発行はセキュリティポリシー上避けたい。

Bash 短命トークンの取得 
# 有効期間を短く設定したグローバルトークンを取得
# 最短 5 分まで設定可能
aws signin create-bearer-token \
     --grant-type client_credentials \
     --resource ecr.amazonaws.com \
     --query accessToken \
     --output text
✅ 効果: ジョブの実行時間に合わせた短命トークンを利用することで、トークン漏えい時の影響を最小化できる。

💰 料金と利用可能リージョン

💵 料金

グローバル認証トークンの利用に追加料金はかかりません。Amazon ECR の料金は、従来どおりストレージ使用量とインターネットへのデータ転送量に基づいて課金されます。

🌏 利用可能リージョン

Amazon ECR がサポートされているすべての商用 AWS リージョンで利用可能。グローバルトークンは、同一 AWS パーティション内のすべてのリージョンで有効です。

🔗 関連サービス・機能

→AWS Sign-In: グローバルトークンを発行する CreateBearerToken API を提供。トークンの状態確認には IntrospectOAuth2TokenWithIAM API を利用できる
→Amazon ECR Docker Credential Helper: Docker の認証情報管理を簡素化するツール。リージョントークンとグローバルトークンの両方に対応
→AWS CloudTrail: signInSessionArn フィールドにより、グローバルトークンの使用をトークンを要求した AWS セッションと関連付けて監査できる
→AWS IAM: トークンの権限スコープは IAM 権限と一致するため、最小権限の原則に基づいたポリシー設計が重要

📌 まとめ

Amazon ECR のグローバル認証トークンにより、単一のトークンで同一 AWS パーティション内のすべてのプライベートレジストリに認証できるようになりました。特にクロスリージョンのイメージプルをルーティングするプロキシサービスや、マルチリージョンの CI/CD パイプラインを運用するチームにとって、トークン管理の運用負荷を大きく削減できるアップデートです。

✓既存のリージョントークンは引き続き利用可能
✓まずは signin:CreateBearerToken 権限の付与とトークン有効期間の設計を検討した上で、段階的な導入がおすすめ
