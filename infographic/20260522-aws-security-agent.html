🛡️ AWS Security Agent

ペネトレーションテスト検出結果に対する検証スクリプト機能

AWS Security Agent
📅 2026-05-22

📋 概要

AWS Security Agent に、ペネトレーションテストの検出結果に対する検証スクリプト (Verification Scripts) 機能が追加された。セキュリティチームは検出された脆弱性が実際に悪用可能かどうかを確認するための検証スクリプトを自動生成・実行できるようになる。

❌ Before - アップデート前の課題

  • 脆弱性の悪用可能性を手動で検証
  • 誤検知の判別に多大な工数
  • 再現手順の作成が属人化
  • 検出結果の優先度付けが困難

✅ After - アップデート後の改善

  • 検証スクリプトが自動生成
  • 即座に検証を開始可能
  • 真の脆弱性に集中可能
  • 一貫した検証プロセスを実現

⚡ 主要機能

📜 1. 検証スクリプトの自動生成

ペネトレーションテストの各検出結果に対して、実行可能な検証スクリプトを自動生成。スクリプトタイプ (scriptType) により実行環境が明示され、署名付き URL (scriptUrl) からダウンロード可能。

📖 2. 実行手順の提供

各検証スクリプトに対して、具体的な実行手順 (instructions) を提供。ターゲット環境に合わせた環境変数 (envVars) が定義済みで、手順に従うだけで検証を実施可能。

🔄 3. 検出結果ステータスとの連携

検証結果に基づいて、検出結果のステータスを ACTIVE、RESOLVED、ACCEPTED、FALSE_POSITIVE に更新可能。信頼度 (confidence) フィールドと組み合わせて優先度を判断。

🔧 技術仕様

API レスポンス構造

検証スクリプト情報は BatchGetFindings API のレスポンスに含まれる verificationScript オブジェクトとして提供される。

項目 型 説明
scriptType string スクリプトの種類・実行環境
scriptUrl string スクリプトのダウンロード URL
instructions string 実行手順の説明
envVars array 必要な環境変数のリスト
envVars[].name string 環境変数名
envVars[].value string 環境変数の値

🚀 設定方法

前提条件

  • AWS Security Agent の Agent Space が構築済み
  • ペネトレーションテストが実行済みで検出結果が存在
  • BatchGetFindings API を呼び出す IAM 権限が付与済み

ステップ 1: 検出結果の取得

Bash 検出結果の取得 
aws securityagent batch-get-findings \
  --finding-ids "finding-abc123" \
  --agent-space-id "space-xyz789"

ステップ 2: 検証スクリプトのダウンロード

Bash スクリプトのダウンロード 
# レスポンスから scriptUrl を取得してスクリプトをダウンロード
curl -o verify_finding.sh "https://security-agent-scripts.s3.amazonaws.com/verify-abc123.sh"
chmod +x verify_finding.sh

ステップ 3: 環境変数の設定と実行

Bash 環境変数の設定と実行 
# レスポンスに含まれる環境変数を設定
export TARGET_URL="https://app.example.com/api/login"
export PAYLOAD_TYPE="union-based"

# 検証スクリプトの実行
./verify_finding.sh

⚠️ デメリット・制約事項

🚧 制限事項

  • 検証スクリプトの実行はユーザー側の環境で行う必要があり、AWS マネージドな実行環境は提供されない
  • すべての検出結果に対して検証スクリプトが生成されるわけではなく、スクリプト生成可能な脆弱性タイプに限定
  • スクリプト URL には有効期限がある可能性があり、取得後は速やかに実行する必要がある

💡 考慮すべき点

  • 本番環境に対して実行する場合、サービスへの影響を考慮しメンテナンスウィンドウ内での実行を推奨
  • 検証スクリプトの実行結果は環境に依存するため、ステージング環境での事前検証を推奨
  • 環境変数に含まれる情報のセキュリティ管理に注意が必要

🎯 ユースケース

🏢 大規模ペネトレーションテスト後の効率的なトリアージ

エンタープライズ環境で数百件の検出結果が報告されたペネトレーションテスト後に、セキュリティチームが限られた時間で真の脆弱性を特定する。HIGH/CRITICAL のみ検証スクリプトを実行し、修正優先度を明確化。

Python HIGH/CRITICAL 検出結果の自動検証 
import boto3

client = boto3.client('securityagent')

# 全検出結果を取得
response = client.batch_get_findings(
    findingIds=finding_ids,
    agentSpaceId='space-xyz789'
)

# HIGH/CRITICAL のみ検証スクリプトを実行
for finding in response['findings']:
    if finding['riskLevel'] in ['HIGH', 'CRITICAL']:
        script = finding.get('verificationScript')
        if script:
            print(f"Verifying: {finding['name']}")
            print(f"Script URL: {script['scriptUrl']}")
            print(f"Instructions: {script['instructions']}")

🔄 CI/CD パイプラインへの検証プロセス統合

DevSecOps チームが、ペネトレーションテスト後の検証プロセスを CI/CD パイプラインに組み込み、自動的に脆弱性の再現性を確認。リリースサイクルを遅延させることなくセキュリティ検証を継続的に実施。

YAML GitHub Actions 例 
- name: Verify Security Findings
  run: |
    FINDINGS=$(aws securityagent batch-get-findings \
      --finding-ids ${{ env.FINDING_IDS }} \
      --agent-space-id ${{ env.AGENT_SPACE_ID }} \
      --query 'findings[?verificationScript!=null]')

    echo "$FINDINGS" | jq -r '.[].verificationScript.scriptUrl' | while read url; do
      curl -o verify.sh "$url"
      chmod +x verify.sh
      ./verify.sh || echo "Vulnerability confirmed"
    done

🔧 セキュリティ修正の効果確認

開発チームが脆弱性の修正を適用した後、検証スクリプトを再実行して修正が有効であることを確認。修正の有効性を客観的に確認でき、修正漏れや不完全な対策を早期に検出。

Bash 修正前後の検証 
# 修正前: 脆弱性が確認される
export TARGET_URL="https://app.example.com/api/login"
./verify_finding.sh
# Output: VULNERABLE - SQL injection confirmed

# 修正適用後: 再度検証
./verify_finding.sh
# Output: NOT VULNERABLE - Input properly sanitized
