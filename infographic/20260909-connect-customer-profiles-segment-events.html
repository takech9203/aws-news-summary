Amazon Connect Customer Profiles

📣 セグメントメンバーシップイベント

顧客のセグメント参加・離脱を Kinesis Data Streams へ自動配信 — リリース日: 2026 年 9 月 9 日

📌 概要

Amazon Connect Customer Profiles が、顧客プロファイルがセグメントに 参加 (JOINED) または 離脱 (LEFT) した際に、イベントを Amazon Kinesis Data Streams に自動配信する機能を発表しました。 「高価値顧客」や「満足度の低い顧客」といったセグメントのメンバーシップ変化を、ニアリアルタイムまたはスケジュールベースで検知し、下流のシステムに通知できます。

各イベントにはプロファイル ID、セグメント名、操作タイプ、検知方法が含まれるため、アウトバウンドキャンペーン、パーソナライゼーションワークフロー、リテンション施策を 数時間ではなく数秒で起動できます。

プロファイルの更新をトリガーに Customer Profiles がセグメントメンバーシップを評価し、参加・離脱イベントを Kinesis Data Streams へ配信、下流システムが数秒以内にアクションを起動できる構成です。

⚙️ 主要機能

⚡ LIVE イベント (ニアリアルタイム)
標準条件で構築されたセグメント (CLASSIC) が対象。プロファイル属性、関連オブジェクト、計算属性の変更発生時に即時評価し、変化があった場合のみ通知
🕐 SCHEDULE イベント (定期評価)
Spark SQL の拡張セグメント (ENHANCED) や時間ベース条件のセグメントが対象。定期スナップショットを前回と比較して変化を検出
🎯 ニアリアルタイムのメンバーシップ変化検知
プロファイル属性、関連オブジェクト、計算属性の変更が発生すると、影響を受けたプロファイルのメンバーシップを即時に評価。スケジュール実行とは独立してニアリアルタイムに通知を送信します。
📅 スケジュールベースの評価
実行間隔は 1 時間〜24 時間で設定可能 (API 経由のサブスクリプションはデフォルト 24 時間、Amazon Connect 管理者 Web サイトからはデフォルト 1 時間)。スケジュール実行はベストエフォートで、前回実行が未完了の場合は遅延・スキップの可能性があります。
🌊 Kinesis Data Streams への自動配信
ドメイン設定 (データエクスポートタブ) でストリーミングを有効化し、配信先ストリームと IAM ロールを指定。同一ドメイン内の全サブスクライブ済みセグメントで同じストリームを共有します。サブスクリプション作成時は初期スナップショットを取得 (STARTING 状態) します。
📊 CloudWatch メトリクスによるモニタリング
ProfilesJoined (参加数) / ProfilesLeft (離脱数) / NotificationsFailed (通知失敗数) / ScheduledRunsSucceeded (成功したスケジュール実行数) を標準提供。

IAM ロールの設定

Customer Profiles が Kinesis データストリームに書き込むために引き受ける IAM ロールには、以下の信頼ポリシーと権限が必要です。

JSON 信頼ポリシー 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "Service": "profile.amazonaws.com"
            },
            "Action": "sts:AssumeRole"
        }
    ]
}
JSON Kinesis への書き込み権限 
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "kinesis:PutRecord",
                "kinesis:PutRecords",
                "kinesis:DescribeStreamSummary"
            ],
            "Resource": "arn:aws:kinesis:us-west-2:123456789012:stream/my-segment-events-stream"
        }
    ]
}
💡 補足
ストリーミングを有効化する IAM プリンシパルには iam:PassRole 権限が必要です。Kinesis データストリームがカスタマーマネージド AWS KMS キーで暗号化されている場合は、ロールに kms:GenerateDataKey および kms:Decrypt 権限も付与します。

🛠️ 設定方法

前提条件

  • Amazon Connect Customer Profiles ドメインが作成済みであること
  • 配信先の Amazon Kinesis データストリームが作成済みであること (設定中に新規作成も可能)
  • Customer Profiles が Kinesis に書き込むための IAM ロールが用意されていること
  • セグメンテーションビルダーを利用するための適切なセキュリティプロファイル権限が設定されていること
1
セグメントメンバーシップストリーミングの有効化
Customer Profiles コンソールの [Data export] タブで [Enable event streaming] を選択。Kinesis データストリームと IAM ロールを指定して保存します。ドメインごとに管理者が 1 回だけ行う設定で、これだけではイベントは送信されず、個々のセグメントのサブスクライブが別途必要です。
2
セグメントのメンバーシップ変化トラッキングを有効化
Amazon Connect 管理者 Web サイトで対象セグメントを開き、[Track membership changes] を選択。有効化すると初期スナップショットが取得され、完了後にメンバーシップ変化の検知と通知が開始されます。
3
イベントの確認とモニタリング
初期スナップショット完了後、ストリーミングイベントや個々のプロファイルのメンバーシップイベント詳細を確認。CloudWatch メトリクスでドメイン・セグメント単位のイベント状況をモニタリングします。不要になったら [Stop tracking changes] で停止できます。

👍 メリット

✓対応スピードの向上: 条件充足から数秒以内にキャンペーンやリテンション施策を起動でき、機会損失を削減
✓運用コストの削減: 全件エクスポートと差分検出スクリプトの開発・運用が不要に
✓顧客体験の向上: 満足度の低下した顧客をリアルタイムに検知し、プロアクティブなフォローアップへ
✓イベント駆動アーキテクチャとの統合: Lambda や Data Firehose と組み合わせた柔軟なパイプラインを構築可能
✓豊富なイベント情報: 追加のルックアップなしで下流処理を実装可能
✓モニタリングの標準化: CloudWatch メトリクスで通知の失敗やスケジュール実行の成否を可視化

⚠️ 制約・考慮点

•セグメントサブスクリプションはドメインあたり最大 10 個まで
•サブスクリプションはセグメント作成後にのみ作成可能
•スケジュール実行の間隔は最小 1 時間、最大 24 時間
•拡張セグメント (Spark SQL ベース) はニアリアルタイム検知に非対応 (スケジュール評価のみ)
•スケジュール実行はベストエフォートで、遅延・スキップの可能性がある
•変化発生からイベント一覧への表示までに遅延が生じる場合がある
•全セグメントが 1 つのストリームを共有するため、シャード数やスループット設計に注意
•Kinesis Data Streams の利用料金が別途発生

💡 ユースケース

1️⃣ 高価値顧客への優先対応

累計購入金額が閾値を超えた顧客を「高価値顧客」セグメント (CLASSIC) として定義。JOINED イベントを Lambda で検知し、Amazon Connect のアウトバウンドキャンペーンやタスク作成 API で専任チームに割り当てます。

✅ 効果: 条件充足から数秒でフォローアップを開始でき、顧客ロイヤルティの向上と売上機会の最大化につながる
2️⃣ 低満足度顧客のリテンション施策

計算属性 (平均満足度スコアなど) を条件にセグメントを作成。JOINED イベントをトリガーにパーソナライズしたクーポン送付やスーパーバイザーへのエスカレーションを実行し、LEFT イベントで施策の効果を測定します。

✅ 効果: 解約リスクの検知から対応までのリードタイムを数時間から数秒に短縮。JOINED と LEFT の両イベント活用で効果測定も自動化
3️⃣ 外部マーケティングシステムとのリアルタイム連携

Spark SQL で定義した拡張セグメント (ENHANCED) をスケジュール間隔 1 時間でサブスクライブ。Kinesis から Amazon Data Firehose 経由でイベントを集約し、JOINED / LEFT の差分のみを外部マーケティングオートメーションツールの API に連携します。

✅ 効果: 全件エクスポートと差分検出スクリプトが不要になり、差分イベントのみの効率的な連携でデータ転送量と処理コストを削減

💰 料金と利用可能リージョン

💵 料金
本機能自体の追加料金に関する個別の記載はありませんが、Amazon Connect Customer Profiles の利用料金と、配信先である Amazon Kinesis Data Streams の利用料金 (シャード時間、PUT ペイロードユニットなど) が発生します。詳細は Customer Profiles 料金ページ と Kinesis Data Streams 料金ページ を確認してください。
🌏 利用可能リージョン
Amazon Connect Customer Profiles が利用可能なすべての AWS リージョンで利用できます。日本では東京リージョン (ap-northeast-1) を含みます。

📝 まとめ

Amazon Connect Customer Profiles のセグメントメンバーシップイベントにより、これまで数時間の遅延と手動の差分検出を要していたセグメント変化の検知が、Kinesis Data Streams への自動配信によって数秒で実現できるようになりました。 顧客のセグメント参加・離脱をトリガーとしたキャンペーンやリテンション施策の自動化を検討している場合は、まずドメインのデータエクスポート設定でストリーミングを有効化し、重要度の高いセグメントからサブスクリプションを試すことを推奨します。
