🗄️ AMD ベース M8a データベースインスタンスをサポート

📅 リリース日: 2026 年 9 月 30 日 | 対象: RDS for PostgreSQL / MySQL / MariaDB

📝 概要

Amazon RDS が、第 5 世代 AMD EPYC プロセッサ (コードネーム Turin) を搭載した M8a データベースインスタンスをサポートしました。 M8a は AWS Nitro System 上に構築され、第 6 世代 Nitro Card により I/O 処理をオフロード・高速化します。 各 vCPU が物理 CPU コアにマッピングされるため、一貫したコアあたり性能を得られます。

AMD ベースのインスタンスはコストパフォーマンスに優れる選択肢として知られており、 既存の M7a (AMD) や M8g (Graviton4) と並ぶ新たな選択肢となります。

❌ アップデート前の課題

  • RDS で利用できる AMD ベース汎用インスタンスは第 4 世代 AMD EPYC 搭載の M7a 世代まで
  • 帯域幅要件が高いワークロードでは旧世代の帯域幅上限が制約になる場合があった
  • 最新世代による価格性能比の改善を AMD ベースのまま享受できなかった

✅ アップデート後の改善

  • 第 5 世代 AMD EPYC 搭載の M8a を RDS for PostgreSQL、MySQL、MariaDB で利用可能に
  • 最大 75 Gbps のネットワーク帯域幅、最大 60 Gbps の EBS 帯域幅で高スループットに対応
  • vCPU = 物理コアの設計により一貫したコアあたり性能を実現

RDS の各エンジンが M8a インスタンス上で動作し、AWS Nitro System の第 6 世代 Nitro Card が I/O 処理をオフロードして EBS との高帯域幅通信を実現する構成

⚡ 主要機能

💻 第 5 世代 AMD EPYC プロセッサの採用

コードネーム Turin の第 5 世代 AMD EPYC を搭載。各 vCPU が物理 CPU コアにマッピングされ、 一貫したコアあたり性能を提供。EC2 の M8a は前世代 M7a 比で最大 30% 高いコンピューティング性能を実現。

🌐 高いネットワーク・ストレージ帯域幅

最大 75 Gbps のネットワーク帯域幅と最大 60 Gbps の EBS 帯域幅を提供し、 高スループットが要求されるデータベースワークロードに対応。

🧩 AWS Nitro System と第 6 世代 Nitro Card

I/O 機能をオフロード・高速化する第 6 世代 Nitro Card を採用。 ホストリソースをデータベース処理に最大限活用可能。

🗄️ 主要 3 エンジンでのサポート

Amazon RDS for PostgreSQL、MySQL、MariaDB で利用可能。 サポートされるエンジンバージョンの詳細は RDS ドキュメントの DB インスタンスクラスのページを参照。

🛠️ 設定方法

前提条件

✓利用可能リージョン (東京リージョンを含む) で RDS を利用していること
✓RDS for PostgreSQL、MySQL、MariaDB のいずれかで M8a をサポートするエンジンバージョンを使用していること
✓既存インスタンスを変更する場合は、メンテナンスウィンドウまたは即時適用による再起動の影響を考慮すること

ステップ 1: サポート対象の確認

Bash 利用可能なエンジンバージョンと AZ の確認 
aws rds describe-orderable-db-instance-options \
  --engine postgres \
  --db-instance-class db.m8a.large \
  --query "OrderableDBInstanceOptions[].{Engine:Engine,Version:EngineVersion,Class:DBInstanceClass,AZ:AvailabilityZones[].Name}" \
  --region ap-northeast-1

ステップ 2: 新規 DB インスタンスの作成

Bash db.m8a.large で RDS for PostgreSQL を作成 
aws rds create-db-instance \
  --db-instance-identifier my-postgres-m8a \
  --db-instance-class db.m8a.large \
  --engine postgres \
  --engine-version 17.4 \
  --master-username admin \
  --manage-master-user-password \
  --allocated-storage 100 \
  --region ap-northeast-1

マスターユーザーのパスワードは AWS Secrets Manager で管理します。

ステップ 3: 既存インスタンスのインスタンスクラス変更

Bash 既存 DB インスタンスを db.m8a.large に変更 
aws rds modify-db-instance \
  --db-instance-identifier my-existing-db \
  --db-instance-class db.m8a.large \
  --apply-immediately

--apply-immediately を指定すると即時適用されますが、再起動が発生するためダウンタイムに注意してください。 Multi-AZ 構成の場合はフェイルオーバーによりダウンタイムを短縮できます。

💡 メリット

ビジネス面

✓コスト効率の向上: AMD ベースは一般に同等の Intel ベースより低価格であり、最新世代の性能向上と合わせて価格性能比の改善が期待できる
✓ワークロードの成長への対応: 高い帯域幅上限により、負荷増加にスケールアップで対応しやすい
✓選択肢の拡大: Intel、AMD、Graviton からワークロードやコスト要件に応じて最適なインスタンスを選択できる

技術面

✓一貫した性能: vCPU = 物理コアのため SMT による性能変動がなく、安定した性能を発揮
✓高帯域幅: 最大 75 Gbps のネットワークと最大 60 Gbps の EBS 帯域幅で I/O 集約型ワークロードのボトルネックを緩和
✓Nitro System による効率化: 第 6 世代 Nitro Card が I/O をオフロードし、ホストリソースをデータベース処理に集中可能

⚠️ デメリット・制約事項

制限事項

✗対象エンジンは RDS for PostgreSQL、MySQL、MariaDB であり、Oracle や SQL Server は対象外
✗利用可能リージョンは現時点で 9 リージョンに限定される
✗サポートされるエンジンバージョンに制限があり、古いバージョンではエンジンのアップグレードが必要になる場合がある

考慮すべき点

⚠既存インスタンスからの変更には再起動が伴うため、メンテナンスウィンドウや Multi-AZ フェイルオーバーを活用した計画的な移行が必要
⚠公式発表には RDS で利用可能なインスタンスサイズの一覧が未記載のため、利用前に describe-orderable-db-instance-options やドキュメントで対象サイズの確認を推奨
⚠リザーブドインスタンス利用時は、インスタンスファミリー変更により既存の予約が適用されなくなる点に注意

🎯 ユースケース

1️⃣ 汎用 Web アプリケーションのデータベース基盤刷新

シナリオ: M7a や M6a で RDS for MySQL を運用しており、トラフィック増加に伴いコアあたり性能と価格性能比を改善したい。

Bash次回メンテナンスウィンドウで適用
aws rds modify-db-instance \
  --db-instance-identifier webapp-mysql \
  --db-instance-class db.m8a.xlarge \
  --no-apply-immediately

効果: 最新世代の性能向上によりレスポンスタイムの改善とコスト効率の向上が期待できる。

2️⃣ I/O 集約型の分析系 PostgreSQL ワークロード

シナリオ: 大量データの読み書きを行う RDS for PostgreSQL で、EBS 帯域幅がボトルネックになっている。

Bashio2 ストレージとの組み合わせ
aws rds create-db-instance \
  --db-instance-identifier analytics-postgres \
  --db-instance-class db.m8a.8xlarge \
  --engine postgres \
  --storage-type io2 \
  --allocated-storage 2000 \
  --iops 40000 \
  --master-username admin \
  --manage-master-user-password

効果: 最大 60 Gbps の EBS 帯域幅と io2 ストレージの組み合わせにより、I/O スループットのボトルネックを緩和できる。

3️⃣ マルチアーキテクチャでのコスト最適化評価

シナリオ: Graviton (M8g)、Intel、AMD (M8a) の各インスタンスで性能とコストを比較し、ワークロードに最適な構成を選定したい。

Bash本番スナップショットから検証用 M8a を復元
aws rds restore-db-instance-from-db-snapshot \
  --db-instance-identifier perf-test-m8a \
  --db-snapshot-identifier prod-snapshot \
  --db-instance-class db.m8a.2xlarge

効果: 本番相当のデータでアーキテクチャごとのベンチマークを実施し、証拠に基づいて最適なインスタンスファミリーを選択できる。

💰 料金

M8a インスタンスの料金は、インスタンスサイズ、リージョン、エンジン、デプロイオプション (Single-AZ / Multi-AZ) により異なります。 従量課金のオンデマンドのほか、リザーブドインスタンスによる割引も利用できます。 具体的な料金は Amazon RDS 料金ページを参照してください。

📌 まとめ

Amazon RDS で第 5 世代 AMD EPYC プロセッサ搭載の M8a インスタンスが利用可能になり、 PostgreSQL、MySQL、MariaDB のワークロードで最新世代の性能と帯域幅を活用できるようになりました。 東京リージョンでも初期ローンチから利用可能であるため、 M7a や M6a などの旧世代 AMD インスタンスを利用中のユーザーは、エンジンバージョンの対応状況を確認のうえ、 検証環境でのベンチマークを通じた移行検討を推奨します。
