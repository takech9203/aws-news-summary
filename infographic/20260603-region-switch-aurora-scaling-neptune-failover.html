Region Switch に Aurora スケーリングと Neptune フェイルオーバーを追加

2026-06-03

📋 概要

ARC Region Switch に 3 つの新しい実行ブロック が追加された。マルチリージョンワークロードにおけるデータベースのスケーリングとフェイルオーバーを自動化し、リージョン障害時のリカバリ時間を大幅に短縮する。

6 更新 API メソッド
全商用 対応リージョン

Before / After 比較

❌ Before

  • セカンダリクラスターを手動でスケールアップする必要があった
  • スケーリング完了まで リクエストルーティング不可でリカバリ遅延
  • Neptune フェイルオーバーの種類を手動/スクリプトで判断

✅ After

  • Aurora Serverless/Provisioned のスケーリングが自動実行
  • Neptune フェイルオーバーが計画的/非計画的の両方で自動化
  • クロスアカウントオーケストレーションに対応

⚡ 主要機能

1. Aurora Serverless スケーリング実行ブロック

  • Aurora Serverless v2 のセカンダリクラスターを自動スケールアップ
  • targetPercent パラメータでプライマリに対する目標容量の割合を指定
  • グローバルクラスター識別子とリージョンごとの DB クラスター ARN を設定
  • タイムアウト時間の設定に対応

2. Aurora Provisioned スケーリング実行ブロック

  • Aurora Provisioned のセカンダリクラスターのインスタンスサイズを自動適正化
  • instanceArns パラメータで対象インスタンスを明示的に指定
  • グローバルクラスター識別子による統合管理
  • リージョンごとの DB クラスター ARN マッピングをサポート

3. Neptune グローバルデータベースフェイルオーバー実行ブロック

  • 計画的スイッチオーバー (switchoverOnly) と非計画的フェイルオーバー (failover) の両方をサポート
  • ungraceful 設定によりプライマリ応答不能時の動作を定義
  • 障害の種類に応じた自動判断で手動スクリプト不要
  • クロスアカウントロールによるマルチアカウント対応

🛠️ 設定方法

前提条件: ARC Region Switch プランが作成済み / Aurora または Neptune グローバルデータベースがマルチリージョンで構成済み / クロスアカウント使用時は適切な IAM ロールが設定済み

Step 1: Aurora Serverless スケーリング実行ブロックの追加

Python Aurora Serverless Scaling Block 
import boto3

client = boto3.client('arc-region-switch')

response = client.create_plan(
    name='my-multi-region-plan',
    recoveryApproach='activePassive',
    primaryRegion='us-east-1',
    regions=['us-east-1', 'us-west-2'],
    workflows=[
        {
            'workflowTargetAction': 'activate',
            'workflowTargetRegion': 'us-west-2',
            'steps': [
                {
                    'name': 'scale-aurora-serverless',
                    'executionBlockType': 'AuroraServerlessScaling',
                    'executionBlockConfiguration': {
                        'auroraServerlessScalingConfig': {
                            'timeoutMinutes': 30,
                            'globalClusterIdentifier': 'my-global-cluster',
                            'regionDatabaseClusterArns': {
                                'us-west-2': 'arn:aws:rds:us-west-2:123456789012:cluster:my-secondary'
                            },
                            'targetPercent': 100
                        }
                    }
                }
            ]
        }
    ]
)

targetPercent を調整することで、段階的なスケーリングも可能。

Step 2: Neptune グローバルデータベースフェイルオーバー実行ブロック

Python Neptune Global Database Failover Block 
{
    'name': 'neptune-failover',
    'executionBlockType': 'NeptuneGlobalDatabase',
    'executionBlockConfiguration': {
        'neptuneGlobalDatabaseConfig': {
            'timeoutMinutes': 20,
            'globalClusterIdentifier': 'my-neptune-global',
            'behavior': 'failover',
            'regionDatabaseClusterArns': {
                'us-west-2': 'arn:aws:neptune:us-west-2:123456789012:cluster:my-neptune-secondary'
            },
            'ungraceful': {
                'ungraceful': 'failover'
            }
        }
    }
}

⚠️ デメリット・制約事項

制限事項:
  • 既存の Aurora Global Database フェイルオーバー実行ブロック (globalAuroraConfig) とは別機能。スケーリングのみを自動化する点に注意
  • タイムアウト設定値によっては、大規模クラスターのスケーリング完了前にタイムアウトする可能性
  • Neptune の ungraceful フェイルオーバーではデータ損失の可能性あり。RPO 要件を慎重に検討
考慮すべき点:
  • クロスアカウントロールの権限設定には最小権限の原則を適用
  • フェイルオーバー後のフォールバック手順は別途計画が必要
  • targetPercent の値はワークロード特性に応じてチューニング

💡 ユースケース

🏦 UC1: コスト最適化されたアクティブ-パッシブ Aurora 構成

シナリオ: 金融機関が Aurora グローバルデータベースをアクティブ-パッシブで運用。セカンダリリージョンは最小構成で維持し、DR 時には本番同等の処理能力が必要。

効果: フェイルオーバー時にセカンダリクラスターが自動的に本番サイズにスケールアップ。手動作業なしに 15 分以内でトラフィック受け入れ準備が完了。

🌐 UC2: マルチアカウント Neptune グラフデータベースの DR

シナリオ: ソーシャルメディアプラットフォームが Neptune グローバルデータベースで関係性データを管理。本番環境と DR 環境が異なる AWS アカウントに存在。

効果: リージョン障害時にアカウントをまたいだ Neptune フェイルオーバーが自動実行。スイッチオーバーかデタッチかの判断含め人的介入なしに復旧完了。

📈 UC3: 段階的スケーリングによるサーバーレス Aurora の復旧

シナリオ: SaaS プロバイダーが Aurora Serverless v2 でマルチテナント環境を運用。フェイルオーバー時には段階的にトラフィックを移行したい。

効果: まず 50% にスケールアップして一部テナントのトラフィックを受け入れ、次に 100% にスケールアップして全トラフィックを処理する段階的復旧を自動化。

💲 料金

ARC Region Switch の料金は既存の料金体系に準拠。新しい実行ブロック自体に追加料金は発生しない。

項目 説明
ARC Region Switch プランの実行に対する課金
Aurora スケーリング スケールアップ後のインスタンス/ACU に応じた Aurora 利用料金
Neptune フェイルオーバー フェイルオーバー後のセカンダリクラスターの利用料金
クロスアカウント通信 IAM ロールの AssumeRole 呼び出し自体は無料

📝 まとめ

ARC Region Switch に Aurora スケーリングと Neptune フェイルオーバーの実行ブロックが追加されたことで、マルチリージョンデータベースワークロードの DR 自動化が大幅に強化された。特にアクティブ-パッシブ構成でコスト最適化のためにセカンダリクラスターを縮小運用している組織にとって、フェイルオーバー時のスケーリング自動化は RTO 短縮に直結する改善 である。

マルチリージョン DR 戦略を持つ組織は、既存の Region Switch プランにこれらの新しい実行ブロックを追加し、フェイルオーバー訓練を実施することを推奨する。
