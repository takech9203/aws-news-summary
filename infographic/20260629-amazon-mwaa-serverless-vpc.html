Amazon MWAA Serverless

☁️ 共有 VPC 構成のサポート

2026-06-29
リリース日

📌 概要

Amazon Managed Workflows for Apache Airflow (MWAA) Serverless が、共有 VPC サブネットをサポートしました。 AWS Resource Access Manager (AWS RAM) を通じて別アカウントから共有されたサブネットを使用して、MWAA Serverless ワークフローを作成できるようになります。

これまで AWS RAM で共有されたサブネットを指定すると検証エラーが発生していましたが、今回のアップデートで MWAA Serverless はサブネットの所有権を正しく検証するようになり、MWAA Provisioned 環境と同じ動作になりました。 共有 VPC を採用するマルチアカウントランディングゾーンの組織が、回避策なしでワークフローを起動できます。

⚠️ アップデート前の課題
  • 共有サブネット指定時にワークフロー作成で検証エラーが発生
  • メンバーアカウントに専用 VPC・サブネットを作る回避策が必要
  • Provisioned 環境と Serverless でネットワーク挙動に差異
➜
✅ アップデート後の改善
  • AWS RAM 共有サブネットで Serverless ワークフローを作成可能
  • 共有 VPC 利用の回避策が不要に
  • Provisioned 環境と一貫した所有権検証を実現

ネットワークアカウントが AWS RAM で共有したサブネットを、メンバーアカウントの MWAA Serverless ワークフローおよび SageMaker Unified Studio Workflows が直接利用できるようになったことを示しています。

🔧 主要機能

🔗 1. 共有 VPC サブネットのサポート
  • AWS RAM を通じて別アカウントから共有されたサブネットを MWAA Serverless ワークフローで指定できる
  • これまで発生していた、共有サブネット指定時の検証エラーが解消された
  • メンバーアカウント内に独自の VPC やサブネットを用意する回避策が不要になった
✅ 2. サブネット所有権検証の改善
  • 共有 VPC 構成におけるサブネットの所有権を正しく検証するようになった
  • MWAA Provisioned 環境と一貫した検証動作になり、プロビジョンドとサーバーレスでネットワーク設計を統一できる
🧪 3. SageMaker Unified Studio Workflows への波及効果
  • 共有 VPC でプロジェクトを構成している SageMaker Unified Studio Workflows のユーザーも恩恵を受けられる
  • Unified Studio のワークフローは内部的に MWAA Serverless を利用するため、同じネットワーク検証の改善が適用される

🛠️ 設定方法

前提条件

→AWS Organizations 上でアカウント間のリソース共有が有効になっていること
→ネットワーク管理アカウントで VPC とプライベートサブネットが作成されていること
→AWS RAM を使用して対象のサブネットがメンバーアカウントへ共有されていること
→MWAA のネットワーク要件 (異なる AZ に配置された複数サブネットなど) を満たしていること

ステップ 1: ネットワークアカウントでサブネットを共有する

BashAWS RAM でサブネットを共有
# AWS RAM でサブネットをメンバーアカウントに共有する
aws ram create-resource-share \
  --name mwaa-shared-subnets \
  --resource-arns arn:aws:ec2:ap-northeast-1:111122223333:subnet/subnet-aaaa1111 \
                  arn:aws:ec2:ap-northeast-1:111122223333:subnet/subnet-bbbb2222 \
  --principals 444455556666

ネットワーク管理アカウント (111122223333) が保有する 2 つのプライベートサブネットを、メンバーアカウント (444455556666) に AWS RAM 経由で共有します。MWAA は異なる AZ の複数サブネットを必要とするため、複数共有します。

ステップ 2: メンバーアカウントで共有サブネットを確認する

Bash共有サブネットの確認
# メンバーアカウントで利用可能な共有サブネットを確認する
aws ec2 describe-subnets \
  --filters "Name=owner-id,Values=111122223333"

メンバーアカウントから参照できる共有サブネットの一覧を表示します。owner-id が共有元アカウントになっていることを確認します。

ステップ 3: 共有サブネットを指定してワークフローを作成する

メンバーアカウントで MWAA Serverless ワークフローを作成する際に、ステップ 2 で確認した共有サブネットの ID を指定します。今回のアップデートにより、共有サブネットを指定しても検証エラーが発生せず、所有権が正しく検証されてワークフローを作成できます。詳細は Amazon MWAA Serverless ユーザーガイドのネットワークセクションを参照してください。

💡 メリット

📈 ビジネス面

  • ガバナンスの維持: 集中管理ポリシーを維持したまま MWAA Serverless を導入できる
  • 導入の迅速化: 回避策が不要になり、ワークフロー立ち上げの手間と時間を削減
  • 標準アーキテクチャへの適合: マルチアカウントランディングゾーンにそのまま対応

⚙️ 技術面

  • ネットワーク設計の統一: Provisioned と Serverless でネットワーク設計を共通化
  • 重複リソースの削減: メンバーアカウントごとの専用 VPC・サブネットが不要に
  • Unified Studio との連携: 共有 VPC を使う SageMaker Unified Studio Workflows でも同じ恩恵

⚠️ デメリット・制約事項

🚧 制限事項

  • 共有 VPC 利用には AWS RAM によるサブネット共有が事前設定されている必要がある
  • MWAA のネットワーク要件 (異なる AZ への複数サブネット配置など) は引き続き必須
  • Amazon MWAA Serverless がサポートされているリージョンでのみ利用可能

🤔 考慮すべき点

  • ルートテーブル・セキュリティグループ・NACL は共有元アカウント設定に依存。責任分界を明確にする
  • 共有サブネットの IP アドレス枯渇に注意。複数ワークロードが共有する場合は CIDR 設計を見直す

🎯 ユースケース

1. マルチアカウントランディングゾーンでのデータパイプライン
シナリオ: 大企業がネットワーク専用アカウントで VPC を一元管理し、事業部ごとのメンバーアカウントでデータパイプラインを運用。
実装: ネットワークアカウントが共有 VPC + サブネットを AWS RAM で共有し、各事業部アカウントが共有サブネットを指定してワークフローを作成。
効果: 集中管理されたネットワークガバナンスを維持しながら、各事業部が独立してパイプラインを運用できる。
2. 専用 VPC 作成の回避によるコスト最適化
シナリオ: 従来はメンバーアカウントごとに専用 VPC・NAT ゲートウェイ・VPC エンドポイントを用意しており、運用コストと重複が課題。
実装: 共有 VPC のサブネットと VPC エンドポイントを複数メンバーアカウントで再利用し、各アカウントはワークフローのみ作成。
効果: NAT ゲートウェイや VPC エンドポイントなどの共有可能リソースを集約し、重複コストを削減。
3. SageMaker Unified Studio Workflows での共有ネットワーク利用
シナリオ: データサイエンスチームが SageMaker Unified Studio を使い、プロジェクトを組織の共有 VPC で構成。
実装: Unified Studio プロジェクトを共有 VPC ネットワークで構成し、内部の Workflows が共有サブネットを利用して実行。
効果: 別途ネットワークを構築せず、組織の標準ネットワーク上で機械学習ワークフローを実行できる。

💰 料金 と 利用可能リージョン

💵 料金

本アップデート自体による追加料金は発生しません。MWAA Serverless はワークフロー実行に応じた従量課金、AWS RAM のリソース共有自体は追加料金なし。共有 VPC 内の NAT ゲートウェイや VPC エンドポイントには、それぞれのサービス料金が別途発生します。

🌍 利用可能リージョン

Amazon MWAA Serverless がサポートされているすべての AWS リージョンで利用できます。

🔗 関連サービス・機能

→AWS Resource Access Manager (AWS RAM): アカウント間で VPC サブネットなどを共有するサービス。本アップデートの前提となる
→Amazon VPC: MWAA Serverless ワークフローが利用するネットワーク基盤。共有 VPC の所有権検証が改善された
→Amazon SageMaker Unified Studio Workflows: 共有 VPC で構成されたプロジェクトが本アップデートの恩恵を受ける
→Amazon MWAA Provisioned 環境: サーバーレスとプロビジョンドでサブネット所有権検証の動作が一貫した

📝 まとめ

AWS RAM で共有された VPC サブネットを使用して Amazon MWAA Serverless ワークフローを作成できるようになり、マルチアカウントランディングゾーンでの導入障壁が解消されました。 MWAA Provisioned 環境と一貫したサブネット所有権検証が行われるため、ネットワークを一元管理する組織は回避策なしで MWAA Serverless を利用できます。

共有 VPC を採用している場合は、専用 VPC を作成する既存の回避策を見直し、共有サブネットを直接利用する構成への移行を検討することを推奨します。
