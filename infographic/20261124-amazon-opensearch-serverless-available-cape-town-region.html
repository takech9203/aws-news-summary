次世代 Amazon OpenSearch Serverless がアフリカ (ケープタウン) リージョン (af-south-1) で利用可能になった。数秒でリソースをプロビジョニングできる フルマネージドの検索・ベクトル・分析エンジンであり、Scale-to-zero により 未使用時のコンピュートコストをゼロまで縮小できる。

⚡ 主要機能

🚀 次世代 OpenSearch Serverless の提供

数秒でのリソースプロビジョニングと即時オートスケーリング。未使用時は Scale-to-zero によりコンピュートコストがゼロになり、実際に消費したコンピュートのみ支払う使用量ベースの課金。

🛠️ クラスター管理不要のワークロード実行

エージェント型 AI、検索、オブザーバビリティのワークロードに対応。クラスターのプロビジョニング、パッチ適用、キャパシティプランニングが不要。

🧩 コンピュートとストレージの分離

コンピュートはストレージから独立してスケール。低トラフィック期間のコスト削減とトラフィックスパイクへの即応性を両立し、ピーク負荷プロビジョニング比で最大 60% のコスト削減。

ステップ 1: ケープタウンリージョンでコレクショングループを作成

Bash コレクショングループ作成 (min 0 OCU で Scale-to-zero を有効化) 
aws opensearchserverless create-collection-group \
  --region af-south-1 \
  --name "my-group" \
  --generation "NEXTGEN" \
  --capacity-limits '{
    "maxIndexingCapacityInOCU": 10,
    "maxSearchCapacityInOCU": 10,
    "minIndexingCapacityInOCU": 0,
    "minSearchCapacityInOCU": 0
  }'

ステップ 2: コレクションの作成

Bash ベクトル検索は VECTORSEARCH、全文検索は SEARCH を指定 
aws opensearchserverless create-collection \
  --region af-south-1 \
  --name "my-collection" \
  --type "VECTORSEARCH" \
  --collection-group-name "my-group"

ステップ 3: コレクションの状態確認

Bash ACTIVE になればデータの取り込みと検索が可能 
aws opensearchserverless batch-get-collection \
  --region af-south-1 \
  --names "my-collection"

🎯 ユースケース

1️⃣ アフリカ域内向け AI エージェントの RAG バックエンド

シナリオ: アフリカの顧客向けに AI エージェントを提供しており、ナレッジベースのデータを域内に保持しつつ、低レイテンシなベクトル検索を実現したい場合。

BashVECTORSEARCH コレクションの作成
aws opensearchserverless create-collection \
  --region af-south-1 \
  --name "agent-knowledge-base" \
  --type "VECTORSEARCH" \
  --collection-group-name "agent-rag-group"

✅ 効果: データレジデンシー要件を満たしながら、エンドユーザーに近い場所で低レイテンシの RAG を実現。トラフィックの少ない時間帯は Scale-to-zero によりコストが発生しない。

2️⃣ ケープタウンリージョンのログ分析・オブザーバビリティ基盤

シナリオ: ケープタウンリージョンで稼働するアプリケーションのログを、同一リージョン内で検索・分析したい場合。

BashSEARCH コレクションの作成
aws opensearchserverless create-collection \
  --region af-south-1 \
  --name "app-logs" \
  --type "SEARCH" \
  --collection-group-name "log-analytics-group"

✅ 効果: ログデータをリージョン外に転送することなく分析でき、転送コストとレイテンシを削減。クラスター管理が不要なため運用負荷も最小限。

3️⃣ トラフィック変動の大きい検索サービス

シナリオ: 日中と夜間でトラフィックが大きく変動する EC サイトの商品検索を、ケープタウンリージョンで運用する場合。

Bash自動スケーリング対応のコレクショングループ作成
aws opensearchserverless create-collection-group \
  --region af-south-1 \
  --name "ecommerce-search-group" \
  --generation "NEXTGEN" \
  --capacity-limits '{
    "maxIndexingCapacityInOCU": 20,
    "maxSearchCapacityInOCU": 20,
    "minIndexingCapacityInOCU": 0,
    "minSearchCapacityInOCU": 0
  }'

✅ 効果: ピーク時には自動スケーリングで即座に対応し、トラフィックの少ない時間帯はコンピュートを縮小してコストを削減。ピーク負荷プロビジョニング比で最大 60% のコスト削減が可能。

💰 料金

OpenSearch Serverless は使用量ベースの課金モデルを採用しており、実際に消費したコンピュートに対してのみ課金される。 Scale-to-zero により未使用時のコンピュートコストは発生しない。

ケープタウンリージョンの具体的な単価は Amazon OpenSearch Service 料金ページを参照。
