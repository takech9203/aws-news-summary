Amazon Route 53 Resolver DNS Firewall 📅 2026 年 11 月 17 日

🛡️ DNS Firewall が自動許可リスト生成をサポート

Automated Allowlists - 実トラフィックに基づく最小権限の DNS アクセス制御

📋 概要

Amazon Route 53 Resolver DNS Firewall が、VPC で観測された DNS クエリトラフィックから ドメイン許可リストを自動生成する機能をサポートしました。 最小権限の DNS アクセス制御を容易に実現し、DNS を悪用したデータ漏えい (DNS Exfiltration) のリスクを低減できます。

1 時間から 7 日間のルックバックウィンドウで DNS クエリを分析して観測済みドメインを一覧化し、 その後も新たに観測されたドメインを継続的にフラグ付けします。管理者はレビューしてから許可リストに追加できるため、 許可されたドメイン以外をすべてブロックする「ウォールドガーデン」構成への移行を、 運用負荷を抑えながら段階的に進められます。

❌ Before: アップデート前の課題

  • 最小権限モデルの実装には、DNS クエリログを手動で分析し、依存ドメインを特定してからルールを展開する必要があった
  • 手動分析の運用負荷が大きく、デフォルト拒否 (deny-by-default) 体制の適用が遅延していた
  • 必要なドメインを事前に網羅できず、正規の通信を誤ってブロックするリスクがあった

✅ After: アップデート後の改善

  • DNS Firewall が VPC の DNS クエリトラフィックを自動分析し、許可リスト候補を自動生成
  • 新規ドメインが自動的にフラグ付けされ、レビュー後に許可リストへ追加するワークフローを実現
  • AWS Firewall Manager や Route 53 Profiles で複数の VPC・アカウントへ一括展開が可能に

VPC からの DNS クエリを DNS Firewall が分析して観測済みドメインを生成し、管理者がレビューして許可リストに追加します。 既知の脅威ブロックルールを最も高い優先度、ワイルドカードのブロックルールを最も低い優先度に配置することで、ウォールドガーデン構成を実現します。

🔄 ドメインのステータス管理

🔍 OBSERVED 観測済み → ✅ ALLOWED 許可済み / ⛔ DENIED 拒否済み

⚡ 主要機能

1️⃣ ルックバックウィンドウによる初期許可リストの自動生成
  • ルール作成時に 1 時間から 7 日間のルックバックウィンドウ (分析タイムフレーム) を指定
  • ルールグループに関連付けられたすべての VPC の DNS クエリトラフィックを分析し、クエリされたドメインを「観測済みドメイン OBSERVED」として一覧化
  • Route 53 Profiles 経由の VPC や、AWS Firewall Manager / AWS RAM で共有された他アカウントの VPC も分析対象
  • ⚠️ ルックバックウィンドウはルール作成後に変更不可
2️⃣ 新規ドメインの継続的な検出とレビューワークフロー
  • ルール作成後、いずれかの DNS Firewall ルールがクエリをブロックすると、そのドメインが観測済みドメインに追加される
  • 総リクエスト数、日次頻度、初回観測日時を表示し、フィルタリングやソートが可能
  • レビュー後に「許可リストに追加 (ADD)」または「拒否 (DENY)」を選択
  • ドメインは OBSERVED / ALLOWED / DENIED の 3 ステータスで管理
3️⃣ 既存の許可リストからのインポート
  • 既存のドメインリストから Automated Allowlist ルールへドメインを一度だけコピーして開始可能
  • インポート元は自身が所有する完成済みのリージョナルなドメインリストが必要 (AWS マネージドドメインリストは不可)
  • インポート後、2 つのリストは独立して管理される
4️⃣ ワイルドカードドメインのサポート
  • *.example.com のようなワイルドカードドメインでサブドメインを一括許可
  • 観測されていないドメインの手動追加も可能 (1 回あたり最大 1,000 ドメイン)
5️⃣ マルチアカウント・マルチ VPC への展開
  • AWS Firewall Manager または Route 53 Profiles で複数の VPC やアカウントにルールを展開
  • 共有ルールグループでは、すべての VPC のトラフィックが統合されて分析される

ステップ 1: Automated Allowlist ルールの作成

AWS CLI ルックバックウィンドウ 24 時間でルールを作成 
aws route53resolver create-firewall-rule \
    --creator-request-id my-request-id \
    --firewall-rule-group-id rslvr-frg-0123456789example \
    --name my-automated-allowlist \
    --priority 100 \
    --action ALLOW \
    --firewall-rule-type '{"AutoAllowlist":{"InitialDataTimeframeHours":24}}'

InitialDataTimeframeHours でルックバックウィンドウを指定します。レスポンスに含まれる FirewallThreatProtectionId と AutoAllowlistFirewallDomainListId を以降のレビューと更新に使用します。 既存リストからインポートする場合は "ImportFromFirewallDomainListId":"{ドメインリスト ID}" を追加します。

ステップ 2: 観測済みドメインのレビュー

AWS CLI 総リクエスト数の多い順に一覧表示 
aws route53resolver list-firewall-rule-domains \
    --firewall-rule-group-id rslvr-frg-0123456789example \
    --firewall-threat-protection-id 0123456789example \
    --query-options DomainStatus=OBSERVED,SortBy=TOTAL_REQUESTS,SortOrder=DESC

各ドメインには直近 24 時間のリクエスト数、総リクエスト数、追加日時が含まれます。 DomainStatus を ALLOWED または DENIED に変更すると、許可済み・拒否済みドメインを確認できます。

ステップ 3: ドメインの承認・拒否

AWS CLI レビュー済みドメインを許可リストに追加 
aws route53resolver update-firewall-domains \
    --firewall-domain-list-id rslvr-fdl-0123456789example \
    --operation ADD \
    --domains example.com "*.example.org"

拒否する場合は --operation DENY、削除する場合は --operation REMOVE を指定します。 許可の反映には最大 1 時間かかる場合があります。

ステップ 4: ワイルドカードブロックルールの追加

必要なドメインをすべて許可リストに追加した後、ワイルドカード * を含むドメインリストを使用した BLOCK アクションのルールを、Automated Allowlist ルールより低い優先度 (大きい優先度番号) で追加します。 これにより、許可リストにないドメインへの DNS クエリがすべてブロックされるウォールドガーデン構成が完成します。

⚠️ 追加前に、コンソールの Analysis タブと許可済みドメインを比較し、Resolver クエリログで CNAME などのリダイレクト先ドメインも許可リストに追加されていることを確認してください。

💡 メリット

💼 ビジネス面

✓セキュリティ体制の迅速な強化: 手動のログ分析が不要になり、デフォルト拒否体制への移行を大幅に加速
✓運用コストの削減: DNS クエリログの手動分析と許可リストメンテナンスの工数を削減
✓追加コストなし: DNS Firewall Advanced の利用者は追加料金なしで利用可能

⚙️ 技術面

✓最小権限の DNS アクセス制御: 実トラフィックに基づく許可リストで、DNS 経由のデータ漏えいや C2 通信のリスクを低減
✓継続的なモニタリング: ルール作成後も新規ドメインが自動フラグ付けされ、レビューワークフローに組み込める
✓スケーラブルな展開: Firewall Manager や Route 53 Profiles でマルチアカウント環境へ一貫したポリシーを展開

⚠️ デメリット・制約事項

制限事項

✗DNS Firewall Advanced の利用者のみが対象 (Advanced ルールとしての課金が発生)
✗1 つのルールグループに作成できる Automated Allowlist ルールは 1 つのみ
✗ルックバックウィンドウはルール作成後に変更不可
✗各ステータスの保持上限は 10,000 件。上限到達後は、既存ドメインへのクエリが止まるまで新しいドメインは追加されない
✗ルール用のドメインリストは直接削除・他ルールでの再利用・内容の置き換えが不可で、ドメインリストのクォータにカウントされる
✗AWS GovCloud (US) および中国リージョンでは利用不可

考慮すべき点

⚠️CNAME などのリダイレクトチェーンのドメインも検査対象。ワイルドカードブロックルールを追加する前に、Resolver クエリログでリダイレクト先を確認して許可リストに追加する
⚠️観測済みドメインには他ルールがブロックしたドメインも含まれるため、脅威ブロックルールを Automated Allowlist ルールより高い優先度に配置し、脅威ドメインを誤って許可しない
⚠️ルール作成後に関連付けた VPC の過去トラフィックは分析されず、関連付け以降のクエリのみが対象
⚠️共有ルールグループでは全 VPC のトラフィックが統合され、どの VPC やアカウントがクエリしたかは表示されない
⚠️ルールを削除するとドメインリストも削除され、観測済み・拒否済みドメインは新しいルールに引き継がれない
⚠️ブロックされないままクエリされ続けるドメインは、ルール作成から約 1 日で ALLOWED に移行するため、作成後は早めに観測済みドメインをレビューする

🎯 ユースケース

🏦 ユースケース 1: 本番 VPC のウォールドガーデン化

シナリオ: 金融系ワークロードの本番 VPC で、承認済みドメイン以外へのすべての DNS 解決をブロックし、DNS 経由のデータ漏えいを防止したい。しかし、依存する外部ドメインを網羅的に把握できていない。

AWS CLI 7 日間のルックバックウィンドウでルールを作成 
aws route53resolver create-firewall-rule \
    --creator-request-id prod-allowlist-request \
    --firewall-rule-group-id rslvr-frg-0123456789example \
    --name prod-auto-allowlist \
    --priority 100 \
    --action ALLOW \
    --firewall-rule-type '{"AutoAllowlist":{"InitialDataTimeframeHours":168}}'
✅ 効果: 7 日分の実トラフィックに基づく許可リストが自動生成され、正規の通信を遮断するリスクを抑えながらデフォルト拒否体制へ移行できる。

シナリオ: ウォールドガーデン構成の運用中に、マルウェア感染などによる未知のドメインへの DNS クエリを早期に検出し、対応したい。

AWS CLI 新たに観測されブロックされたドメインを定期的に確認 
aws route53resolver list-firewall-rule-domains \
    --firewall-rule-group-id rslvr-frg-0123456789example \

    --query-options DomainStatus=OBSERVED,SortBy=ADDED_TIME,SortOrder=DESC
✅ 効果: ブロックされた新規ドメインがフラグ付けされるため、正規のドメインは承認し、不審なドメインは拒否するトリアージ運用を確立でき、インシデントの早期発見につながる。

💰 料金・利用可能リージョン

💵 料金

Automated Allowlist ルールは DNS Firewall Advanced ルールとして課金されます。 本機能自体は DNS Firewall Advanced の利用者に追加料金なしで提供されます。 詳細は Amazon Route 53 の料金ページを参照してください。

🌍 利用可能リージョン

Route 53 DNS Firewall がサポートされているすべての AWS リージョンで利用可能です。 ただし、AWS GovCloud (US) および中国リージョンは除きます。

🔗 関連サービス・機能

→Route 53 Resolver DNS Firewall Advanced: 本機能の前提となるティア。DGA や DNS トンネリングなどの高度な DNS 脅威の検出も提供
→AWS Firewall Manager: 組織内の複数アカウントと VPC へのルールグループの一括展開と統制

→Route 53 Resolver クエリログ: CNAME などのリダイレクト先ドメインの確認や、許可リストの網羅性検証に使用

📝 まとめ

Route 53 Resolver DNS Firewall の自動許可リスト生成により、これまで手動のログ分析が必要だった デフォルト拒否 (ウォールドガーデン) 構成への移行を、実トラフィックに基づいて効率的に進められるようになりました。

DNS Firewall Advanced を利用中で DNS 経由のデータ漏えい対策を強化したい場合は、まず本番前環境でルックバックウィンドウを設定して 観測済みドメインのレビュー運用を試し、脅威ブロックルールとの優先度設計を確認した上で、 ワイルドカードブロックルールの追加によるウォールドガーデン化を検討することを推奨します。
