Smithy-Java Client Framework GA

Smithy モデルからプロダクショングレードの Java クライアントを自動生成するオープンソースフレームワーク
2026 年 4 月 6 日
一般提供開始

📋 概要

AWS は Smithy-Java クライアントフレームワーク の一般提供開始 (GA) を発表した。Smithy モデルからタイプセーフな Java クライアントおよびスタンドアロンクラスを生成するオープンソースフレームワークであり、エンタープライズ Smithy ユーザーから最も要望の多かったプロダクショングレードの Java SDK 生成機能を提供する。

Java 21 の仮想スレッド (Virtual Threads) を基盤に構築されており、ブロッキングスタイルの API で非同期処理と同等のパフォーマンスを実現する。

🔄 Before / After

Before - アップデート前
  • Smithy モデルから Java クライアントを生成する公式フレームワークが存在しなかった
  • 手動でシリアライゼーションやプロトコル処理コードを記述する必要があった
  • 非同期 API の使用が複雑で認知負荷とメンテナンス負担が大きかった
  • プロトコル間の移行にはコード変更が必要だった
After - アップデート後
  • Smithy モデルからタイプセーフなクライアントコードを自動生成
  • 手動コーディングが不要に
  • Java 21 仮想スレッドによるブロッキングスタイル API でシンプルかつ高性能
  • ランタイムでのプロトコル切り替えでコード変更なしの移行が可能

⚡ 主要機能

🔧 タイプセーフなクライアント自動生成
Smithy モデルからオペレーション、シリアライザー、デシリアライザー、プロトコル処理を含む完全な Java クライアントを生成。API 変更時はモデルを更新してクライアントを再生成するだけで、手動のコード変更は不要。リトライ、エラーマッピング、カスタムインターセプターなどを標準サポート。
🔌 プロトコル柔軟性とランタイム切り替え
AWS JSON 1.0/1.1、REST-JSON、REST-XML、AWS Query、Smithy RPCv2-CBOR をサポート。クライアントの再ビルドなしにランタイムでプロトコルを切り替え可能。段階的なプロトコル移行をコード変更なしで実現。
🔀 ダイナミッククライアント
ビルド時のコード生成なしに Smithy モデルをランタイムで読み込んで任意のサービス API を呼び出し可能。ツール、サービスアグリゲーター、ビルド時に未知のサービスと連携するシステムの構築に有用。
📋 スタンドアロン型コード生成
サービスコンテキストなしで Smithy シェイプからタイプセーフな Java クラスを生成。複数サービス間での型の共有やデータモデリングに活用可能。モデルファーストアプローチをデータ層やロジック層にも拡張。
📊 スキーマ駆動シリアライゼーション
SDK サイズを削減しつつパフォーマンスを向上させるアーキテクチャイノベーション。シリアライゼーション処理をスキーマ情報に基づいて最適化。
🌳 BDD によるエンドポイント解決
エンドポイントルール解決にバイナリ決定図を採用し、レイテンシを大幅に改善。従来のルールエンジンと比較して高速なエンドポイント解決を実現。

🛠 設定方法

前提条件: Java 21 以上、Gradle、Smithy モデルファイル

Step 1: Smithy モデルの定義

Smithy サービスモデル定義 
namespace com.example

use aws.api#service
use smithy.protocols#rpcv2Cbor

@title("Coffee Shop Service")
@rpcv2Cbor
@service(sdkId: "CoffeeShop")
service CoffeeShop {
    version: "2024-08-23"
    operations: [
        GetMenu
    ]
}

@readonly
operation GetMenu {
    output := { items: CoffeeItems }
}

Step 2: クライアントの生成と使用

Java 生成されたクライアントの使用 
var client = CoffeeShopClient.builder()
    .endpointProvider(EndpointResolver.staticEndpoint("http://localhost:8888"))
    .build();

var menu = client.getMenu();

Step 3: ダイナミッククライアント (オプション)

Java ランタイムでモデルを読み込み 
var model = Model.assembler()
    .addImport("model.smithy")
    .assemble()
    .unwrap();
var serviceId = ShapeId.from("com.example#CoffeeShop");
var client = DynamicClient.builder()
    .model(model)
    .serviceId(serviceId)
    .build();
var result = client.call("GetMenu");

Step 4: イベントストリーム (仮想スレッド活用例)

Java 仮想スレッドとイベントストリーム 
var client = TranscribeClient.builder().build();
var audioStream = EventStream.<AudioStream>newWriter();
var request = StartStreamTranscriptionInput.builder()
    .audioStream(audioStream)
    .build();

// 仮想スレッドで音声データを送信
Thread.startVirtualThread(() -> {
    try (var audioStreamWriter = audioStream.asWriter()) {
        for (var chunk : iterableAudioChunks()) {
            var event = AudioEvent.builder()
                .audioChunk(chunk).build();
            audioStreamWriter.write(
                AudioStream.builder().audioEvent(event).build()
            );
        }
    }
});

// リクエスト送信
var response = client.startStreamTranscription(request);

// 仮想スレッドで文字起こし結果を読み取り
Thread.startVirtualThread(() -> {
    try (var results = response.getTranscriptResultStream().asReader()) {
        for (var event : results) {
            // イベント処理
        }
    }
});

⚖ メリット / デメリット

✅ メリット

  • 開発期間の大幅短縮: 数か月 → 数週間 (Amazon 社内実績)
  • メンテナンスコスト削減: モデルからの自動生成でボイラープレート管理不要
  • 段階的な技術移行: ランタイムプロトコル切り替えでリスクなく移行
  • 仮想スレッドによる高性能化: ブロッキングスタイルで非同期と同等性能
  • SDK サイズ最適化: スキーマ駆動シリアライゼーションで不要コード排除
  • エンドポイント解決の高速化: BDD でレイテンシ大幅改善
  • 型安全性の保証: コンパイル時の型チェックでランタイムエラー防止

⚠ 制限事項・考慮点

  • Java 21 以上が必須 (それ以前のバージョンは使用不可)
  • 仮想スレッド非対応ライブラリとの組み合わせに注意
  • GA 時点のプロトコルサポートは AWS 関連が中心
  • AWS SDK for Java 2.x との使い分けや移行パスの検討が必要
  • Smithy モデルの学習コストが存在
  • コード生成ベースのためカスタマイズに制約がある場合がある

🎯 ユースケース

1. マイクロサービスのクライアント SDK 自動生成
シナリオ: 複数のマイクロサービスで構成されたシステムにおいて、各サービスのクライアント SDK を手動で作成・メンテナンスする負担が大きい。
→ Smithy モデルを API の正規定義として管理し、クライアントコードを自動生成。サービス間の型の一貫性を保ちつつメンテナンスコストを大幅に削減。
2. プロトコル移行の段階的実施
シナリオ: 既存の REST-JSON ベースのサービスを Smithy RPCv2-CBOR へ移行したいが、一括移行はリスクが高い。
→ ランタイムでのプロトコル切り替えにより、コード変更なしで段階的にトラフィックを新プロトコルに移行。問題発生時も即座にロールバック可能。
3. サービスアグリゲーターの構築
シナリオ: 複数の AWS サービスや社内サービスの情報を集約するダッシュボードツールを構築したい。ビルド時にはすべてのサービス定義が確定していない。
→ ダイナミッククライアントにより、ビルド時に未知のサービスにもランタイムで接続可能。新しいサービスの追加時にもコード変更や再ビルドが不要。

💰 料金・リージョン

料金: Smithy-Java はオープンソースフレームワーク (Apache 2.0 ライセンス) であり、フレームワーク自体の利用に料金は発生しない。AWS サービスを呼び出す場合は、各サービスの通常利用料金が適用される。

リージョン: オープンソースフレームワークであり、AWS リージョンに依存しない。GitHub からグローバルに利用可能。生成されたクライアントから接続する AWS サービスのリージョン可用性は各サービスのドキュメントを参照。
