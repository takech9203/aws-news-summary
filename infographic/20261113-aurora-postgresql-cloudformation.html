🐘 Aurora PostgreSQL Express Configuration が CloudFormation に対応

📅 リリース日: 2026 年 11 月 13 日

AWS::RDS::DBCluster リソースに追加された WithExpressConfiguration プロパティ 1 つの宣言で、クラスターとプライマリ DB インスタンスを一括作成。数秒で利用可能になる Serverless データベースを IaC パイプラインに組み込めます。

📋 概要

Express configuration は、事前設定済みのデフォルト構成により Aurora PostgreSQL Serverless データベースを数秒で作成し、すぐにクエリを実行できる簡素化されたデータベース作成エクスペリエンスです。これまでコンソール、AWS CLI、SDK で利用可能でしたが、今回のアップデートにより CloudFormation テンプレートからも利用できるようになりました。

❌ Before: アップデート前の課題
  • Express configuration はコンソール、AWS CLI、SDK からのみ利用可能で、CloudFormation では作成できなかった
  • CloudFormation では DBCluster と DBInstance の 2 リソースを個別に定義する必要があった
  • 数秒で作成できる利点を IaC ベースのワークフローに組み込めなかった
✅ After: アップデート後の改善
  • WithExpressConfiguration の宣言だけで、クラスターとプライマリ DB インスタンスの両方を作成
  • DB インスタンスを個別にモデル化する必要がなくなり、テンプレートが簡素化
  • 高速な作成体験を CloudFormation によるデプロイ自動化と組み合わせ可能に

従来は DBCluster と DBInstance の 2 リソースを個別に定義する必要がありましたが、WithExpressConfiguration プロパティにより DBCluster リソース 1 つの宣言でクラスターと Serverless ライターインスタンスが一括作成されます。

⚙️ 主要機能

1️⃣ WithExpressConfiguration プロパティ
  • AWS::RDS::DBCluster リソースに追加された Boolean 型のプロパティ
  • createOnly プロパティであり、作成後に変更するとリソースの置き換え (Replacement) が発生
  • ライター DB インスタンスを作成し、残りのプロパティにデフォルト値を設定
  • Aurora PostgreSQL DB クラスターのみサポート
2️⃣ テンプレートの簡素化
  • AWS::RDS::DBInstance リソースを個別に定義する必要がない
  • ライター DB インスタンスは CloudFormation の管理対象外。管理が必要な場合は AWS::RDS::DBInstance リソースとしてスタックにインポート可能
  • CloudFormation が DB クラスターを削除すると、ライター DB インスタンスも併せて削除される
3️⃣ Express configuration のデフォルト構成
  • Aurora Serverless インスタンスとして作成され、数秒で利用可能
  • インターネットアクセスゲートウェイがデフォルトで有効化され、VPN や AWS Direct Connect なしでセキュアに接続可能
  • IAM データベース認証が有効化され、一時トークンベースのアクセスでデータを保護
  • VPC には関連付けられず、アベイラビリティーゾーンは自動的に選択される

項目詳細

プロパティ名WithExpressConfiguration
型Boolean
必須いいえ
更新動作Replacement (createOnly)

Express configuration の主なデフォルト設定

設定デフォルト値と制約
DB インスタンスクラスAurora Serverless インスタンス (作成後に変更可能)
エンジンバージョンデフォルトのメジャー/マイナーバージョン (アップグレードは可能、ダウングレードは不可)

テンプレート例

YAML CloudFormation テンプレート 
AWSTemplateFormatVersion: "2010-09-09"
Resources:
  ExpressCluster:
    Type: AWS::RDS::DBCluster
    Properties:
      DBClusterIdentifier: sample-express-cluster
      Engine: aurora-postgresql
      WithExpressConfiguration: true

WithExpressConfiguration: true を宣言するだけで、クラスターと Serverless ライターインスタンスの両方が作成されます。

🛠️ 設定方法

前提条件

✓Aurora PostgreSQL express configuration が利用可能なリージョンであること
✓CloudFormation スタックの実行ロールに rds:CreateDBCluster、rds:CreateDBInstance、rds:EnableInternetAccessGateway、ec2:DescribeAvailabilityZones、iam:CreateServiceLinkedRole の権限があること
✓データベースに接続する IAM アイデンティティに rds-db:connect 権限があること
1
テンプレートの作成
YAMLtemplate.yaml
Resources:
  ExpressCluster:
    Type: AWS::RDS::DBCluster
    Properties:
      DBClusterIdentifier: my-express-cluster
      Engine: aurora-postgresql
      WithExpressConfiguration: true

AWS::RDS::DBInstance リソースの定義は不要です。

2
スタックのデプロイ
Bashスタックのデプロイ
aws cloudformation deploy \
  --template-file template.yaml \
  --stack-name my-express-db-stack

クラスターと Serverless ライターインスタンスが一括で作成され、インターネットアクセスゲートウェイと IAM 認証が自動的に構成されます。

3
データベースへの接続
BashIAM 認証トークンの生成
# IAM 認証トークンを生成して psql で接続
aws rds generate-db-auth-token \
  --hostname <クラスターのライターエンドポイント> \
  --port 5432 \
  --username postgres

インターネットアクセスゲートウェイ経由で IAM 認証トークンを使用して接続します。RDS コンソールの「接続とセキュリティ」タブからコードスニペットや CloudShell による接続も利用できます。

💡 メリット

💼 ビジネス面

✓開発スピードの向上: 数秒で利用可能になる express configuration を IaC パイプラインに組み込むことで、開発環境や検証環境の立ち上げを高速化
✓運用コストの削減: テンプレートのリソース定義が減り、レビューやメンテナンスの負担を軽減
✓ガバナンスの強化: 手動のコンソール操作に頼らず、再現可能で監査可能なデプロイを実現

🔧 技術面

✓テンプレートの簡素化: 2 リソース定義が 1 つのプロパティ宣言に集約
✓一貫した構成: インターネットアクセスゲートウェイ、IAM 認証、暗号化などベストプラクティスに沿ったデフォルト構成を自動適用
✓柔軟な拡張: 作成後にリーダーインスタンスの追加、インスタンスタイプやストレージタイプの変更が可能

⚠️ デメリット・制約事項

制限事項

✗Aurora PostgreSQL のみサポートされ、Aurora MySQL では利用できない
✗WithExpressConfiguration は createOnly プロパティのため、作成後に値を変更するとクラスターの置き換えが発生
✗CloudFormation はライター DB インスタンスを直接管理しない。管理するにはスタックへのインポートが必要
✗クラスターは VPC に関連付けられず、カスタマーマネージド KMS キー、特定のエンジンバージョン指定、Secrets Manager によるパスワード管理は使用不可
✗Aurora Global Database、Aurora Limitless Database、RDS Proxy、Zero-ETL 統合、Blue/Green Deployments、Babelfish などの VPC を前提とする機能は非サポート
✗IPv6 はサポートされず、IPv4 のみ利用可能

考慮すべき点

⚠️クラスター削除時にライター DB インスタンスも併せて削除されるため、削除保護やスナップショット運用を検討する必要がある
⚠️インターネットアクセスゲートウェイは無効化できないため、VPC 内に閉じたネットワーク構成が必須の本番環境では full configuration を検討する必要がある
⚠️認証は IAM データベース認証のみで、トークンの有効期限は 15 分のため、接続ツール側の対応状況を確認する必要がある

🎯 ユースケース

1. 開発環境の迅速なプロビジョニング

シナリオ: 開発チームごとに検証用の Aurora PostgreSQL 環境を CloudFormation で払い出したいが、テンプレートの定義量を最小限にしたい。

YAML実装例
Resources:
  DevCluster:
    Type: AWS::RDS::DBCluster
    Properties:
      DBClusterIdentifier: dev-team-a-cluster
      Engine: aurora-postgresql
      WithExpressConfiguration: true

効果: 最小限のテンプレートで数秒で利用可能なデータベースを払い出せる。VPC やサブネットグループの設計が不要なため、ネットワーク構成の調整を待たずに開発を開始できる。

2. CI/CD パイプラインでの一時的なテスト用データベース

シナリオ: 統合テストの実行ごとに独立したデータベースを作成し、テスト完了後に破棄したい。

Bash実装例
# テスト開始時にスタックを作成
aws cloudformation deploy \
  --template-file test-db.yaml \
  --stack-name test-db-${BUILD_ID}

# テスト完了後にスタックを削除 (ライターインスタンスも併せて削除される)
aws cloudformation delete-stack --stack-name test-db-${BUILD_ID}

効果: 作成も削除も 1 スタック操作で完結し、インスタンスの削除漏れによるコスト発生を防止できる。Serverless のため、テスト負荷に応じて自動的にスケーリングする。

3. プロトタイピング環境のコード管理

シナリオ: 新規プロダクトのプロトタイピングで、外部の開発ツールや SaaS から直接接続できるデータベースを IaC で管理したい。

YAML実装例
Resources:
  PrototypeCluster:
    Type: AWS::RDS::DBCluster
    Properties:
      DBClusterIdentifier: prototype-cluster
      Engine: aurora-postgresql
      WithExpressConfiguration: true
      DeletionProtection: false

効果: インターネットアクセスゲートウェイと IAM 認証により、VPN なしでセキュアに外部ツールから接続できる環境を、テンプレートとしてバージョン管理できる。

💰 料金

CloudFormation サポート自体に追加料金はありません。Express configuration で作成されるクラスターには、Aurora Serverless の通常の料金 (ACU 時間、ストレージ、I/O) が適用されます。

🎁 Aurora PostgreSQL の express configuration は AWS Free Tier でも利用できます。

🌍 利用可能リージョン

Aurora PostgreSQL の express configuration が提供されているすべての AWS リージョンで利用可能です。ドキュメントによると、express configuration は AWS GovCloud (US)、中東 (UAE)、中東 (バーレーン) を除くすべての AWS リージョンでサポートされています。

🔗 関連サービス・機能

⚙️ AWS CloudFormation

今回のアップデートの対象。AWS::RDS::DBCluster リソースで express configuration を宣言的に管理できるようになった。

⚡ Amazon Aurora Serverless v2

Express configuration で作成されるインスタンスのバックエンド。ワークロードに応じて自動的にスケーリングする。

🔐 AWS Identity and Access Management (IAM)

Express configuration クラスターの認証方式。一時トークンによるパスワードレス認証を提供する。

🎁 AWS Free Tier

Aurora PostgreSQL の express configuration は無料利用枠の対象。

📝 まとめ

Aurora PostgreSQL の express configuration が CloudFormation に対応し、WithExpressConfiguration プロパティの宣言だけでクラスターとプライマリ DB インスタンスを一括作成できるようになりました。数秒で利用可能になるデータベースを IaC パイプラインに組み込めるため、開発環境や CI/CD でのテスト用データベースの管理が大幅に簡素化されます。

VPC 非関連付けや IAM 認証のみといった express configuration 固有の制約を確認した上で、開発・検証用途から活用を検討することを推奨します。
