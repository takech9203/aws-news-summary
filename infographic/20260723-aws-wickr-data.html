AWS Wickr データ保持サービス
リリース日
2026-07-23

📌 概要

AWS Wickr は Premium ユーザー向けにマネージド型の Data Retention Service (データ保持サービス) を発表しました。組織はネットワーク全体の会話をアーカイブし、コンプライアンスや監査に必要な記録を保持できます。

AWS Wickr は、エンドツーエンドの暗号化メッセージング、ファイル管理、画面共有、音声・ビデオ会議を提供するエンタープライズグレードのセキュアなコラボレーション製品です。今回の機能は サーバーレスアーキテクチャ上に構築され、従来のコンテナベース方式に代わるクラウドベースの選択肢を提供します。

規制対応やガバナンスの観点から会話記録の保持と監査証跡を必要とする 金融・医療・公共部門などの組織にとって、エンドツーエンドの暗号化基準を維持しながらデータ保持を実現できる点が主要な価値提案です。

🔄 アップデートによる変化

😰 Before: 従来の課題
  • コンテナベースの保持ボットを自前でデプロイ・運用し、インフラ管理負担が大きい
  • 会話量の増減に応じたスケーリングを手動で考慮する必要があった
  • データ保持基盤の監視・メンテナンスを組織側で継続的に実施
➡
😊 After: 改善
  • マネージド型のサーバーレスアーキテクチャでインフラ管理が不要に
  • 会話量に応じた自動スケーリングで容量計画・手動対応が不要
  • デプロイの簡素化と包括的なモニタリングで運用負担を軽減

内部・外部を含むネットワーク全体の会話が、E2E 暗号化を維持したままマネージド型サーバーレス基盤で保持・アーカイブされます。

⭐ 主要機能

💬 ネットワーク全体の会話保持

  • ダイレクトメッセージと Groups・Rooms 内の会話を対象
  • 内部メンバーに加え、外部フェデレーションチームとの会話も保持対象
  • コンプライアンスや監査証跡のため組織全体のコミュニケーション記録を保存

⚡ サーバーレスアーキテクチャ

  • デプロイの簡素化を実現し、従来のコンテナベース方式より導入が容易
  • マネージドインフラにより、組織側でのサーバー管理が不要
  • 会話量に応じた自動スケーリングと包括的なモニタリングを提供

🔒 エンドツーエンド暗号化の維持

  • Wickr の E2E 暗号化基準を保持したままデータ保持を実現
  • セキュリティ要件を満たしながらアーカイブと監査が可能

🎯 対象範囲

対象会話ダイレクトメッセージ、Groups、Rooms
対象ユーザー内部メンバー、外部フェデレーションチーム
有効化単位ネットワーク単位 (管理者がオプトインで有効化)
対象プランPremium プランのみ

⚙️ 設定方法

📋 前提条件
  • AWS Wickr の Premium プランを利用していること
  • ネットワーク管理者権限を持っていること
  • 対象ネットワークが利用可能リージョンで運用されていること

📝 有効化の手順

1
Wickr 管理コンソールにアクセス Wickr Admin コンソールにログインし、対象ネットワークの設定画面を開きます。Premium プランのネットワークで Data Retention の設定項目が利用可能です。
2
Data Retention のオプトイン ネットワーク設定からデータ保持機能を有効化 (オプトイン) します。有効化により、以降のネットワーク全体の会話がマネージド型サーバーレス基盤で保持対象となります。
3
モニタリングと運用 有効化後は、包括的なモニタリング機能を通じてデータ保持の状況を確認します。詳細な設定手順は Wickr 管理者ドキュメントを参照してください。

✅ メリット

💼 ビジネス面

  • コンプライアンス対応: 規制業界で求められる会話記録の保持と監査証跡をセキュアに実現
  • 運用コストの削減: マネージド型サービスでインフラ管理・運用の負担を軽減
  • 外部連携も対象: 外部フェデレーションチームとの会話も保持し、組織全体のガバナンスを強化

🛠️ 技術面

  • インフラ管理不要: サーバーレスによりサーバーやコンテナの運用が不要
  • 自動スケーリング: 会話量の増減に応じて自動的にスケールし、容量計画が不要
  • セキュリティ維持: E2E 暗号化を維持したままデータ保持を実現

⚠️ デメリット・制約事項

🚧 制限事項

  • Premium プランのユーザーのみが利用可能
  • 利用可能リージョンが限定されている
  • データ保持はネットワーク単位でのオプトインが必要

🤔 考慮すべき点

  • 有効化の際は、組織のプライバシーポリシーや従業員への通知など法的・倫理的な配慮が必要
  • 保持データの管理・アクセス制御について、内部統制の観点から運用ルールを整備することが望ましい

💡 ユースケース

🏦 1. 金融機関のコンプライアンス対応

シナリオ: 金融規制により従業員間のコミュニケーション記録の保持が義務付けられている金融機関が、セキュアなコラボレーションを維持しつつ監査証跡を確保したい。

効果: E2E 暗号化を維持したまま、ダイレクトメッセージや Rooms の会話をアーカイブでき、規制要件を満たしながら運用負担を抑えられる。

🏛️ 2. 公共部門のガバナンス強化

シナリオ: 公共部門の組織が、外部のパートナー組織 (フェデレーションチーム) との会話も含めた記録保持を必要としている。

効果: 内部・外部を問わずネットワーク全体の会話を保持でき、情報公開請求や監査に対応できる。

🔀 3. コンテナ運用からの移行

シナリオ: 従来のコンテナベースのデータ保持ボットを自前で運用しており、インフラ管理の負担を軽減したい組織。

効果: マネージド型サーバーレスへ移行することで、デプロイが簡素化され、自動スケーリングとモニタリングにより運用負担が大幅に削減される。

💰 料金

Data Retention Service は AWS Wickr の Premium プランのユーザーが利用でき、管理者がネットワーク単位でオプトインすることで有効化できます。公式発表では具体的な追加料金の記載はありません。詳細な料金については AWS Wickr の料金ページを参照してください。

🎯 まとめ

AWS Wickr の Data Retention Service は、E2E 暗号化を維持しながらネットワーク全体の会話をマネージド型サーバーレス基盤でアーカイブできる機能です。規制対応や監査証跡を必要とする組織は、従来のコンテナベース運用から移行することで運用負担を大幅に削減できます。Premium プランを利用している組織は、対象リージョンでのオプトインによる有効化を検討することをお勧めします。
