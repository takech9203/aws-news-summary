# AWS MCP Server - 6 つの追加リージョンで利用可能に

**リリース日**: 2026 年 10 月 2 日
**サービス**: AWS MCP Server (Agent Toolkit for AWS)
**機能**: リージョン拡大 (東京を含む 6 リージョン追加)

📊 [このアップデートのインフォグラフィックを見る](https://takech9203.github.io/aws-news-summary/20261002-aws-mcp-server-six-additional-regions.html)

## 概要

AWS MCP Server が、新たに 6 つの AWS リージョンで利用可能になりました。追加されたのは、アジアパシフィック (シンガポール)、アジアパシフィック (シドニー)、アジアパシフィック (東京)、欧州 (アイルランド)、欧州 (ロンドン)、米国西部 (オレゴン) の各リージョンです。既存の米国東部 (バージニア北部) と欧州 (フランクフルト) と合わせて、合計 8 リージョンでの提供となります。

AWS MCP Server は、Agent Toolkit for AWS の一部として提供されるマネージド型の Model Context Protocol (MCP) サーバーです。AWS API への単一のインターフェイスを提供し、AI コーディングエージェントがサービスごとの個別インテグレーションを構築することなく、AWS サービスを発見して呼び出すことができます。エージェントはこのエンドポイントを通じて、インフラストラクチャのプロビジョニング、ワークロードの検査、障害のデバッグなどを実行できます。

今回のリージョン拡大により、日本のユーザーは東京リージョンのエンドポイントを利用できるようになり、低レイテンシーでの利用とリクエストデータの国内保持が可能になります。

**アップデート前の課題**

- 以前は米国東部 (バージニア北部) と欧州 (フランクフルト) の 2 リージョンのみで提供されており、アジアパシフィックのユーザーは地理的に離れたエンドポイントを利用する必要があった
- 遠隔リージョンのエンドポイント利用により、エージェントとのやり取りでレイテンシーが大きくなっていた
- リクエストデータが国外のリージョンで処理されるため、データレジデンシー要件を持つ組織では利用が難しいケースがあった

**アップデート後の改善**

- 東京を含む 6 リージョンが追加され、開発者により近い場所でサーバーが稼働することでレイテンシーが低減された
- リクエストデータをリージョン内に保持できるため、データレジデンシー要件への対応が容易になった
- サーバー自体は 8 リージョンでの稼働だが、すべての商用 AWS リージョンのサービスにアクセス可能

## サービスアップデートの詳細

### 主要機能

1. **6 リージョンの追加**
   - アジアパシフィック (シンガポール、シドニー、東京)、欧州 (アイルランド、ロンドン)、米国西部 (オレゴン) が追加
   - 既存のバージニア北部、フランクフルトと合わせて合計 8 リージョンで利用可能
   - 各リージョンに専用の HTTPS エンドポイントを提供

2. **AWS API への単一インターフェイス**
   - AI エージェントが AWS サービスを発見し、API を呼び出すための統一されたインターフェイスを提供
   - サービスごとの個別インテグレーションの構築が不要
   - インフラストラクチャのプロビジョニング、ワークロードの検査、障害のデバッグに活用可能

3. **全商用リージョンへのアクセス**
   - MCP サーバーのエンドポイントは 8 リージョンで稼働
   - 接続先のエンドポイントがどのリージョンであっても、すべての商用 AWS リージョンのサービスを操作可能

## 技術仕様

### 利用可能なエンドポイント

| リージョン名 | リージョンコード | エンドポイント | 備考 |
|------|------|------|------|
| 米国東部 (バージニア北部) | us-east-1 | aws-mcp.us-east-1.api.aws/mcp | 既存 |
| 米国西部 (オレゴン) | us-west-2 | aws-mcp.us-west-2.api.aws/mcp | **新規** |
| アジアパシフィック (シンガポール) | ap-southeast-1 | aws-mcp.ap-southeast-1.api.aws/mcp | **新規** |
| アジアパシフィック (シドニー) | ap-southeast-2 | aws-mcp.ap-southeast-2.api.aws/mcp | **新規** |
| アジアパシフィック (東京) | ap-northeast-1 | aws-mcp.ap-northeast-1.api.aws/mcp | **新規** |
| 欧州 (フランクフルト) | eu-central-1 | aws-mcp.eu-central-1.api.aws/mcp | 既存 |
| 欧州 (アイルランド) | eu-west-1 | aws-mcp.eu-west-1.api.aws/mcp | **新規** |
| 欧州 (ロンドン) | eu-west-2 | aws-mcp.eu-west-2.api.aws/mcp | **新規** |

すべてのエンドポイントは HTTPS プロトコルで提供されます。

## メリット

### ビジネス面

- **データレジデンシー要件への対応**: リクエストデータをリージョン内に保持できるため、国内でのデータ処理が求められる業界や組織でも AI エージェントの活用を進めやすくなる
- **開発者体験の向上**: レイテンシーの低減により、エージェントを使った開発ワークフローの応答性が向上する
- **グローバル展開の容易化**: 米国、欧州、アジアパシフィックの主要リージョンをカバーし、グローバルに分散した開発チームでも最寄りのエンドポイントを利用可能

### 技術面

- **低レイテンシー**: 東京リージョンのエンドポイントを利用することで、日本国内からのアクセスのレイテンシーが大幅に低減される
- **統一インターフェイス**: サービスごとの MCP サーバーやカスタムインテグレーションを構築せずに、単一のエンドポイントから AWS API 全般にアクセス可能
- **広範なサービスカバレッジ**: どのエンドポイントに接続しても、すべての商用 AWS リージョンのサービスを操作可能

## デメリット・制約事項

### 制限事項

- サーバーが稼働するリージョンは 8 リージョンに限定される (他リージョンのサービス操作は可能)
- サービスクォータ (レート制限など) が設定されているため、大量のリクエストを行う場合は [クォータドキュメント](https://docs.aws.amazon.com/agent-toolkit/latest/userguide/aws-mcp-limits.html) の確認が必要

### 考慮すべき点

- エージェントに付与する IAM 権限は最小権限の原則に従って設計する必要がある
- データレジデンシー要件がある場合は、利用するエンドポイントのリージョンを明示的に指定する運用ルールの整備が推奨される

## ユースケース

### ユースケース 1: 日本国内からの低レイテンシーなエージェント開発

**シナリオ**: 日本の開発チームが AI コーディングエージェントから AWS リソースの操作やデバッグを行う。

**実装例**:
```json
{
  "mcpServers": {
    "aws-mcp": {
      "url": "https://aws-mcp.ap-northeast-1.api.aws/mcp"
    }
  }
}
```

**効果**: 東京リージョンのエンドポイントを利用することで、従来の米国・欧州エンドポイント利用時と比べてレイテンシーが低減され、エージェントの応答性が向上する。

### ユースケース 2: データレジデンシー要件のある環境での AI エージェント活用

**シナリオ**: 金融機関や公共機関など、リクエストデータの国内処理が求められる組織で AI エージェントを導入する。

**実装例**:
```text
エージェントの MCP 設定で東京リージョンのエンドポイント
(aws-mcp.ap-northeast-1.api.aws/mcp) のみを許可し、
リクエストデータをリージョン内に保持する
```

**効果**: リクエストデータがリージョン内で処理されるため、データレジデンシー要件を満たしながら AI エージェントによる運用自動化を実現できる。

### ユースケース 3: グローバル分散チームでの統一されたエージェント運用

**シナリオ**: 米国、欧州、アジアに開発拠点を持つ企業が、各拠点から AWS MCP Server を利用する。

**実装例**:
```text
各拠点の最寄りエンドポイントを利用。
- 米国拠点: us-east-1 または us-west-2
- 欧州拠点: eu-central-1、eu-west-1、eu-west-2
- アジア拠点: ap-northeast-1、ap-southeast-1、ap-southeast-2
```

**効果**: 全拠点で同一のインターフェイスを利用しつつ、各拠点で低レイテンシーなアクセスを実現できる。

## 関連サービス・機能

- **Agent Toolkit for AWS**: AWS MCP Server を含む、AI エージェント開発を支援するツール群
- **Model Context Protocol (MCP)**: AI エージェントと外部ツール・データソースを接続するためのオープンプロトコル。AWS MCP Server はこのプロトコルのマネージド実装
- **AWS IAM**: エージェントが AWS API を呼び出す際の認証・認可を担い、最小権限での運用に不可欠
