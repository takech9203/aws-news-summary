⚡ 主要機能

📅 90 日先までのタスクスケジュール

StartTaskContact API の ScheduledTime パラメータの上限が 6 日から 90 日に拡張。Unix Epoch 秒形式で日時を指定し、過去の日時は指定不可。

🔧 複数のスケジュール方法

StartTaskContact API (プログラム自動化)、フロー内の Create task ブロック (ビジュアル設定)、エージェントワークスペース (手動作成) の 3 通りに対応。

📎 コンテキスト情報の付与

スケジュールタスクにカスタム属性を設定可能。PreviousContactId / RelatedContactId で関連コンタクトとリンクし、タスクテンプレートで構造化管理。

💻 実装例

Bash AWS CLI でタスクをスケジュール 
aws connect start-task-contact \
  --instance-id "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" \
  --name "修理完了フォローアップ" \
  --description "自動車修理完了後の顧客確認コール" \
  --contact-flow-id "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx" \
  --scheduled-time 1753833600 \
  --attributes '{"ClaimId":"CLM-2026-001","RepairType":"Auto"}' \
  --references '{"ClaimDoc":{"Type":"URL","Value":"https://example.com/claims/001"}}'
Python Boto3 で段階的タスクをスケジュール 
import boto3
from datetime import datetime, timedelta

client = boto3.client('connect')

phases = [
    {"name": "査定員訪問確認", "days": 7},
    {"name": "部品入荷確認", "days": 30},
    {"name": "修理完了フォローアップ", "days": 60},
]

for phase in phases:
    scheduled = datetime.now() + timedelta(days=phase["days"])
    client.start_task_contact(
        InstanceId="instance-id",
        Name=phase["name"],
        ContactFlowId="flow-id",
        ScheduledTime=scheduled,
        Attributes={"ClaimId": "CLM-2026-001"}
    )

🎯 ユースケース

🚗 保険クレーム処理のフォローアップ

自動車保険のクレーム処理において、査定訪問 (7 日後)、部品確認 (30 日後)、修理完了確認 (60 日後) の各フェーズで異なるチームにフォローアップタスクを自動スケジュール。対応漏れを防止しエージェント負荷を軽減。

📄 契約更新リマインダー

SaaS サブスクリプションの契約更新が迫っている顧客に対し、60 日前、30 日前、7 日前の段階的なリマインダータスクをスケジュール。契約更新率の向上と顧客離脱の防止。

🏥 医療機関の定期フォローアップ

患者の退院後、1 週間後の状態確認、1 ヶ月後の経過観察、3 ヶ月後の定期検診リマインダーを自動スケジュール。患者ケアの継続性を確保し再入院リスクを低減。
