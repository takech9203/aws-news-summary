# Amazon EC2 - M9gd インスタンスがアジアパシフィック (ソウル) リージョンで利用可能に

**リリース日**: 2026 年 11 月 25 日
**サービス**: Amazon EC2
**機能**: Amazon EC2 M9gd インスタンスのアジアパシフィック (ソウル) リージョン対応

📊 [このアップデートのインフォグラフィックを見る](https://takech9203.github.io/aws-news-summary/20261125-amazon-ec2-m9gd-asiapacific-seoul.html)

## 概要

AWS Graviton5 プロセッサを搭載した汎用インスタンス Amazon EC2 M9gd が、アジアパシフィック (ソウル) リージョンで利用可能になりました。M9gd は AWS が独自設計した第 5 世代 CPU である Graviton5 を搭載し、ローカル NVMe ベース SSD ストレージを備えた汎用インスタンスファミリーです。

M9gd インスタンスは、Graviton4 ベースの M8gd インスタンスと比較して、コンピューティング性能が最大 25% 向上し、データベースでは最大 30%、Web アプリケーションでは最大 35%、機械学習では最大 35% 高速に動作します。また、第 6 世代 AWS Nitro System 上に構築されており、形式検証 (formal verification) により顧客ワークロードの分離を数学的に保証する Nitro Isolation Engine を初めて搭載したインスタンスファミリーです。

ソウルリージョンでワークロードを運用するお客様は、アプリケーションサーバー、マイクロサービス、ゲームサーバー、キャッシュ、コンテナといった汎用ワークロードに加え、リアルタイム推論、コード生成、マルチステップオーケストレーションなどのエージェント型 AI ワークロードでも、最新世代の価格性能比を活用できるようになりました。

**アップデート前の課題**

- 以前はソウルリージョンで Graviton5 ベースの M9gd インスタンスを利用できず、米国や東京などの提供済みリージョンを選択する必要があった
- ソウルリージョンの Graviton ベース汎用インスタンス (ローカルストレージ付き) は前世代の M8gd までに限られ、最新世代の性能向上を享受できなかった
- 韓国国内のユーザー向けに低レイテンシーでサービスを提供しつつ、最新世代インスタンスを利用することができなかった

**アップデート後の改善**

- ソウルリージョンで M9gd インスタンスを起動できるようになり、M8gd 比で最大 25% のコンピューティング性能向上を活用できるようになった
- データ所在地要件やレイテンシー要件によりソウルリージョンを利用するワークロードでも、Graviton5 と Nitro Isolation Engine による最新の性能・セキュリティを利用できるようになった
- Savings Plans、オンデマンド、スポットインスタンス、Dedicated Instances、Dedicated Hosts の各購入オプションをソウルリージョンで選択できるようになった

## サービスアップデートの詳細

### 主要機能

1. **AWS Graviton5 プロセッサ**
   - AWS が独自設計した第 5 世代のカスタム CPU
   - M8gd (Graviton4 ベース) と比較してコンピューティング性能が最大 25% 向上
   - データベースで最大 30%、Web アプリケーションで最大 35%、機械学習で最大 35% の高速化
   - 常時有効なメモリ暗号化、vCPU ごとの専用キャッシュ、ポインタ認証をサポート

2. **ローカル NVMe SSD ストレージ**
   - ブロックレベルのローカル NVMe ベース SSD ストレージを搭載
   - スクラッチスペース、一時ファイル、キャッシュなど、高速・低レイテンシーなアクセスが必要なデータに最適
   - EBS のみの M9g と異なり、インスタンスに物理的に接続されたストレージを利用可能

3. **第 6 世代 AWS Nitro System と Nitro Isolation Engine**
   - 第 6 世代の AWS Nitro System 上に構築
   - 形式検証を用いて、顧客ワークロードが他の顧客および AWS オペレーターから分離されていることを数学的に保証する Nitro Isolation Engine を搭載

### M9g と M9gd の違い

| 項目 | M9g | M9gd |
|------|-----|------|
| ストレージ | EBS のみ | ローカル NVMe SSD + EBS |

| vCPU / メモリ / 帯域 | サイズごとに M9gd と同一 | サイズごとに M9g と同一 |

## 設定方法

### 前提条件

1. AWS アカウントを保有していること
2. アジアパシフィック (ソウル) リージョン (ap-northeast-2) を利用できること
3. Arm (aarch64) アーキテクチャに対応した AMI を用意していること

### 手順

#### ステップ1: ソウルリージョンでの利用可能状況を確認

```bash
aws ec2 describe-instance-type-offerings \
  --region ap-northeast-2 \
  --filters "Name=instance-type,Values=m9gd.*" \
  --query "InstanceTypeOfferings[].InstanceType" \
  --output table
```

ソウルリージョンで提供されている M9gd インスタンスサイズの一覧を表示します。

#### ステップ2: M9gd インスタンスを起動

```bash
aws ec2 run-instances \
  --region ap-northeast-2 \
  --instance-type m9gd.xlarge \
  --image-id <Arm 対応 AMI の ID> \
  --key-name <キーペア名> \
  --subnet-id <サブネット ID>
```

ソウルリージョンで m9gd.xlarge インスタンスを起動します。AMI は Arm アーキテクチャ対応のものを指定する必要があります。

#### ステップ3: ローカル NVMe SSD ストレージの初期化

```bash
# インスタンス内でローカル NVMe デバイスを確認
lsblk

# ファイルシステムを作成してマウント
sudo mkfs -t xfs /dev/nvme1n1
sudo mkdir /scratch
sudo mount /dev/nvme1n1 /scratch
```

インスタンスストアボリュームを確認し、ファイルシステムを作成してマウントします。インスタンスストアのデータはインスタンスの停止・終了時に失われるため、一時データ用途に限定してください。

## メリット

### ビジネス面

- **価格性能比の向上**: M8gd 比で最大 25% の性能向上により、同じワークロードをより少ないインスタンス数・コストで処理できる可能性があります
- **韓国国内ワークロードの最新化**: データ所在地要件や低レイテンシー要件でソウルリージョンを利用するお客様が、リージョンを変えずに最新世代へ移行できます
- **柔軟な購入オプション**: Savings Plans、オンデマンド、スポットインスタンス、Dedicated Instances、Dedicated Hosts から選択できます

### 技術面

- **Graviton5 の性能向上**: データベースで最大 30%、Web アプリケーションと機械学習で最大 35% の高速化が期待できます
- **Nitro Isolation Engine によるセキュリティ強化**: 形式検証に基づくワークロード分離の数学的保証により、セキュリティ要件の厳しいワークロードにも適しています
- **ローカル NVMe SSD**: キャッシュやスクラッチスペースなど、低レイテンシーなローカルストレージを必要とするワークロードの性能を向上できます

## デメリット・制約事項

### 制限事項

- Arm (aarch64) アーキテクチャのため、x86 向けにビルドされたバイナリやコンテナイメージはそのままでは動作せず、再ビルドまたはマルチアーキテクチャ対応が必要です
- ローカル NVMe SSD はインスタンスストアであり、インスタンスの停止・終了時にデータが失われます
- 公式発表にはソウルリージョンで提供されるインスタンスサイズの明記がないため、利用前に対象サイズを確認する必要があります

### 考慮すべき点

- 性能向上率 (最大 25% など) はワークロードにより異なるため、本番移行前に実際のワークロードでベンチマークを実施することを推奨します
- 商用ソフトウェアやエージェントを利用している場合は、Arm 対応状況を事前に確認してください
- 永続化が必要なデータは EBS または Amazon S3 に保存する設計が必要です

## ユースケース

### ユースケース1: 韓国国内向け Web アプリケーション基盤の最新化

**シナリオ**: ソウルリージョンで M8gd インスタンス上の Web アプリケーションを運用しており、トラフィック増加に伴い性能とコスト効率の改善が必要。

**実装例**:
```
1. ステージング環境で m9gd インスタンスを起動し、M8gd と性能を比較
2. Auto Scaling グループの起動テンプレートのインスタンスタイプを m9gd に変更
3. 段階的にインスタンスを入れ替えて移行
```

**効果**: Web アプリケーションで最大 35% の性能向上が期待でき、必要インスタンス数の削減によるコスト最適化が見込めます。

### ユースケース2: ローカルストレージを活用したログ・バッチ処理

**シナリオ**: 大量のログデータや中間ファイルを処理するバッチジョブで、EBS の I/O レイテンシーがボトルネックになっている。

**実装例**:
```
1. m9gd インスタンスを起動し、ローカル NVMe SSD をスクラッチ領域としてマウント
2. バッチジョブの中間ファイル出力先をローカル NVMe SSD に変更
3. 最終結果のみ Amazon S3 に保存
```

**効果**: 低レイテンシーなローカル NVMe SSD により中間処理の I/O 性能が向上し、ジョブの実行時間を短縮できます。

### ユースケース3: エージェント型 AI ワークロードの実行基盤

**シナリオ**: リアルタイム推論、コード生成、マルチステップオーケストレーションを行うエージェント型 AI アプリケーションをソウルリージョンで低レイテンシーに提供したい。

**実装例**:
```
1. Arm 対応のコンテナイメージをビルドし、Amazon ECR に登録
2. Amazon EKS / ECS のノードとして m9gd インスタンスを利用
3. モデルやキャッシュデータをローカル NVMe SSD に配置して読み込みを高速化
```

**効果**: 機械学習ワークロードで最大 35% の高速化が期待でき、韓国国内ユーザーへの低レイテンシーな応答と価格性能比の向上を両立できます。

## 料金

M9gd インスタンスは、ソウルリージョンにおいて以下の購入オプションで利用できます。料金は EC2 の通常の課金体系に従い、インスタンスサイズと購入オプションに応じて異なります。最新の料金は料金ページを確認してください。

- **オンデマンド**: 初期費用なしの従量課金
- **Savings Plans**: 1 年または 3 年のコミットメントによる割引
- **スポットインスタンス**: 未使用キャパシティを割引価格で利用
- **Dedicated Instances / Dedicated Hosts**: 専有ハードウェアでの実行

## 関連サービス・機能

- **AWS Graviton**: M9gd を支える Arm ベースのカスタムプロセッサファミリー。第 5 世代が Graviton5 です
- **AWS Nitro System**: インスタンスの基盤となるハードウェアおよびソフトウェアのプラットフォーム。第 6 世代で Nitro Isolation Engine を搭載しています
- **Amazon EC2 M9g インスタンス**: ローカル NVMe SSD を持たない EBS のみの兄弟ファミリー。ローカルストレージが不要な場合の選択肢です
- **Amazon EC2 M8gd インスタンス**: Graviton4 ベースの前世代インスタンス。移行時の性能比較の基準になります
