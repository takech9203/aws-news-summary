# Amazon EC2 - M9g インスタンスが追加の 4 リージョンで利用可能に

**リリース日**: 2026 年 11 月 25 日
**サービス**: Amazon EC2
**機能**: Amazon EC2 M9g インスタンスのリージョン拡大 (北カリフォルニア、カナダ中部、サンパウロ、ソウル)

📊 [このアップデートのインフォグラフィックを見る](https://takech9203.github.io/aws-news-summary/20261125-amazon-ec2-m9g-instances-additional-regions.html)

## 概要

AWS Graviton5 プロセッサを搭載した汎用インスタンス Amazon EC2 M9g が、新たに米国西部 (北カリフォルニア)、カナダ (中部)、南米 (サンパウロ)、アジアパシフィック (ソウル) の 4 リージョンで利用可能になりました。Graviton5 は AWS が独自設計した第 5 世代のカスタム CPU で、M9g は Graviton4 ベースの M8g インスタンスと比較して最大 25% 高い性能を発揮し、データベースでは最大 30% の高速化を実現します。

M9g インスタンスは第 6 世代の AWS Nitro System 上に構築されており、Nitro Isolation Engine を初めて搭載したインスタンスファミリーです。Nitro Isolation Engine は形式検証 (formal verification) を用いて、顧客ワークロードが相互に、また AWS のオペレーターから分離されていることを数学的に保証します。

M9g はオープンソースデータベース、インメモリキャッシュ、ビッグデータ分析などのメモリ集約型アプリケーションに加え、アプリケーションサーバー、マイクロサービス、コンテナといった幅広い汎用ワークロードに適しています。今回の拡大により、北米西海岸、カナダ、南米、韓国のユーザーに近いリージョンで最新世代の価格性能比を活用できるようになりました。

**アップデート前の課題**

- M9g インスタンスは米国東部・西部、欧州、アジアパシフィックの一部 (東京、シンガポール、シドニーなど) に限られ、北カリフォルニア、カナダ中部、サンパウロ、ソウルの各リージョンでは利用できなかった
- これらのリージョンにデータ所在地要件や低レイテンシー要件を持つワークロードは、Graviton4 ベースの M8g など前世代インスタンスが実質的な最新選択肢だった
- 複数リージョンにまたがるシステムで、Graviton5 ベースの統一したインスタンスファミリーを採用しにくかった

**アップデート後の改善**

- 米国西部 (北カリフォルニア)、カナダ (中部)、南米 (サンパウロ)、アジアパシフィック (ソウル) の 4 リージョンで M9g インスタンスを起動できるようになった
- 各リージョンのワークロードで、M8g 比最大 25% (データベースでは最大 30%) の性能向上と Nitro Isolation Engine による分離保証を利用できるようになった
- Savings Plans、オンデマンド、スポットインスタンス、Dedicated Instances、Dedicated Hosts の各購入オプションを新リージョンでも選択できるようになった

## サービスアップデートの詳細

### 主要機能

1. **AWS Graviton5 プロセッサ**
   - AWS が独自設計した第 5 世代のカスタム CPU
   - M8g (Graviton4 ベース) と比較してコンピューティング性能が最大 25% 向上
   - データベースで最大 30% の高速化
   - 常時有効なメモリ暗号化、vCPU ごとの専用キャッシュ、ポインタ認証をサポート

2. **第 6 世代 AWS Nitro System と Nitro Isolation Engine**
   - 第 6 世代の AWS Nitro System 上に構築
   - 形式検証を用いて、顧客ワークロードが他の顧客および AWS オペレーターから分離されていることを数学的に保証する Nitro Isolation Engine を初めて搭載

3. **4 リージョンへの提供拡大**
   - 米国西部 (北カリフォルニア)、カナダ (中部)、南米 (サンパウロ)、アジアパシフィック (ソウル) を追加
   - 既存リージョンと合わせて、より多くの地域で Graviton5 ベースの汎用インスタンスを選択可能に

## 技術仕様

### M9g インスタンスサイズ

| サイズ | vCPU | メモリ (GiB) | ネットワーク帯域 (Gbps) | EBS 帯域 (Gbps) |
|--------|------|--------------|--------------------------|------------------|
| m9g.medium | 1 | 4 | 最大 15 | 最大 12 |
| m9g.large | 2 | 8 | 最大 15 | 最大 12 |
| m9g.xlarge | 4 | 16 | 最大 15 | 最大 12 |
| m9g.2xlarge | 8 | 32 | 最大 17 | 最大 12 |
| m9g.4xlarge | 16 | 64 | 最大 17 | 最大 12 |
| m9g.8xlarge | 32 | 128 | 17 | 12 |
| m9g.12xlarge | 48 | 192 | 25 | 18 |
| m9g.16xlarge | 64 | 256 | 34 | 24 |
| m9g.24xlarge | 96 | 384 | 50 | 36 |
| m9g.48xlarge | 192 | 768 | 100 | 72 |
| m9g.metal-48xl | 192 | 768 | 100 | 72 |

M9g は EBS のみのストレージ構成です。ローカル NVMe SSD が必要な場合は、同一スペックにローカルストレージを追加した M9gd ファミリーを選択できます (M9gd も同日にソウルリージョンへ拡大)。

### 今回追加されたリージョン

| リージョン | リージョンコード |
|------------|------------------|
| 米国西部 (北カリフォルニア) | us-west-1 |
| カナダ (中部) | ca-central-1 |
| 南米 (サンパウロ) | sa-east-1 |
| アジアパシフィック (ソウル) | ap-northeast-2 |

## 設定方法

### 前提条件

1. AWS アカウントを保有していること
2. 追加されたリージョン (us-west-1、ca-central-1、sa-east-1、ap-northeast-2) のいずれかを利用できること
3. Arm (aarch64) アーキテクチャに対応した AMI を用意していること

### 手順

#### ステップ1: 対象リージョンでの利用可能状況を確認

```bash
aws ec2 describe-instance-type-offerings \
  --region ap-northeast-2 \
  --filters "Name=instance-type,Values=m9g.*" \
  --query "InstanceTypeOfferings[].InstanceType" \
  --output table
```

対象リージョン (例: ソウル) で提供されている M9g インスタンスサイズの一覧を表示します。リージョンごとに提供サイズが異なる場合があるため、利用前に確認してください。

#### ステップ2: M9g インスタンスを起動

```bash
aws ec2 run-instances \
  --region ap-northeast-2 \
  --instance-type m9g.xlarge \
  --image-id <Arm 対応 AMI の ID> \
  --key-name <キーペア名> \
  --subnet-id <サブネット ID>
```

対象リージョンで m9g.xlarge インスタンスを起動します。AMI は Arm アーキテクチャ対応のものを指定する必要があります。

#### ステップ3: アプリケーションの動作確認と性能比較

```bash
# アーキテクチャの確認
uname -m
# 出力例: aarch64
```

起動したインスタンス上でアプリケーションを動作させ、既存の M8g や x86 インスタンスと性能・コストを比較します。性能向上率はワークロードにより異なるため、実際のワークロードでの検証を推奨します。

## メリット

### ビジネス面

- **価格性能比の向上**: M8g 比で最大 25% の性能向上により、同じワークロードをより少ないインスタンス数・コストで処理できる可能性があります
- **データ所在地・低レイテンシー要件への対応**: カナダ、南米、韓国などの要件でリージョンが固定されているワークロードでも、リージョンを変えずに最新世代へ移行できます
- **柔軟な購入オプション**: Savings Plans、オンデマンド、スポットインスタンス、Dedicated Instances、Dedicated Hosts から選択できます

### 技術面

- **Graviton5 の性能向上**: 汎用ワークロードで最大 25%、データベースで最大 30% の高速化が期待できます
- **Nitro Isolation Engine によるセキュリティ強化**: 形式検証に基づくワークロード分離の数学的保証により、セキュリティ要件の厳しいワークロードにも適しています
- **マルチリージョン構成の統一**: 提供リージョンの拡大により、複数リージョンで同一のインスタンスファミリーを採用しやすくなります

## デメリット・制約事項

### 制限事項

- Arm (aarch64) アーキテクチャのため、x86 向けにビルドされたバイナリやコンテナイメージはそのままでは動作せず、再ビルドまたはマルチアーキテクチャ対応が必要です
- 公式発表には各リージョンで提供されるインスタンスサイズの明記がないため、利用前に対象サイズを確認する必要があります
- M9g は EBS のみのストレージ構成であり、ローカル NVMe SSD が必要な場合は M9gd を選択する必要があります

### 考慮すべき点

- 性能向上率 (最大 25% など) はワークロードにより異なるため、本番移行前に実際のワークロードでベンチマークを実施することを推奨します
- 商用ソフトウェアや監視エージェントを利用している場合は、Arm 対応状況を事前に確認してください
- スポットインスタンスを利用する場合、新規追加リージョンでは当初キャパシティが限られる可能性があります

## ユースケース

### ユースケース1: 韓国国内向け Web アプリケーション基盤の最新化

**シナリオ**: ソウルリージョンで M8g インスタンス上の Web アプリケーションを運用しており、トラフィック増加に伴い性能とコスト効率の改善が必要。

**実装例**:
```
1. ステージング環境で m9g インスタンスを起動し、M8g と性能を比較
2. Auto Scaling グループの起動テンプレートのインスタンスタイプを m9g に変更
3. 段階的にインスタンスを入れ替えて移行
```

**効果**: M8g 比最大 25% の性能向上が期待でき、必要インスタンス数の削減によるコスト最適化が見込めます。

### ユースケース2: サンパウロリージョンでのオープンソースデータベース運用

**シナリオ**: 南米のユーザー向けに、サンパウロリージョンで PostgreSQL や MySQL などのセルフマネージドデータベースを運用している。

**実装例**:
```
1. m9g.4xlarge などメモリ要件に合うサイズでレプリカを構築
2. レプリケーションで既存環境とデータを同期
3. フェイルオーバーにより M9g ベースの環境へ切り替え
```

**効果**: データベースワークロードで最大 30% の高速化が期待でき、クエリレイテンシーの改善とコスト効率の向上を両立できます。

### ユースケース3: カナダのデータ所在地要件を満たすコンテナ基盤

**シナリオ**: データ所在地要件によりカナダ (中部) リージョンでの運用が必須のコンテナワークロードで、最新世代インスタンスによるコスト最適化を図りたい。

**実装例**:
```
1. Arm 対応のマルチアーキテクチャコンテナイメージをビルドし、Amazon ECR に登録
2. Amazon EKS / ECS のノードグループに m9g インスタンスを追加
3. 段階的にワークロードを M9g ノードへ移行
```

**効果**: データ所在地要件を維持したまま、Graviton5 の価格性能比と Nitro Isolation Engine によるセキュリティ強化を活用できます。

## 料金

M9g インスタンスは、今回追加されたリージョンにおいて以下の購入オプションで利用できます。料金は EC2 の通常の課金体系に従い、リージョン、インスタンスサイズ、購入オプションに応じて異なります。最新の料金は料金ページを確認してください。

- **オンデマンド**: 初期費用なしの従量課金
- **Savings Plans**: 1 年または 3 年のコミットメントによる割引
- **スポットインスタンス**: 未使用キャパシティを割引価格で利用
- **Dedicated Instances / Dedicated Hosts**: 専有ハードウェアでの実行

## 利用可能リージョン

**今回追加されたリージョン**: 米国西部 (北カリフォルニア)、カナダ (中部)、南米 (サンパウロ)、アジアパシフィック (ソウル)

**これまでの主な提供リージョン** (2026 年 9 月時点): 米国東部 (バージニア北部、オハイオ)、米国西部 (オレゴン)、欧州 (フランクフルト、アイルランド)、アジアパシフィック (シンガポール、シドニー、東京)

最新の提供リージョンは [M9g インスタンスページ](https://aws.amazon.com/ec2/instance-types/m9g/) で確認してください。

## 関連サービス・機能

- **AWS Graviton**: M9g を支える Arm ベースのカスタムプロセッサファミリー。第 5 世代が Graviton5 です
- **AWS Nitro System**: インスタンスの基盤となるハードウェアおよびソフトウェアのプラットフォーム。第 6 世代で Nitro Isolation Engine を搭載しています
- **Amazon EC2 M9gd インスタンス**: M9g と同一スペックにローカル NVMe SSD を追加した兄弟ファミリー。低レイテンシーなローカルストレージが必要な場合の選択肢です
- **Amazon EC2 M8g インスタンス**: Graviton4 ベースの前世代インスタンス。移行時の性能比較の基準になります

## まとめ

AWS Graviton5 搭載の M9g インスタンスが米国西部 (北カリフォルニア)、カナダ (中部)、南米 (サンパウロ)、アジアパシフィック (ソウル) の 4 リージョンに拡大し、これらの地域のワークロードでも M8g 比最大 25% (データベースでは最大 30%) の性能向上を活用できるようになりました。対象リージョンで Graviton ベースの汎用インスタンスを運用しているお客様は、M9g への移行による性能とコストパフォーマンスの改善効果を検証することをお勧めします。
