# Amazon EC2 - C9g インスタンスがシドニー、アイルランド、スペイン、サンパウロの各リージョンで利用可能に

**リリース日**: 2026 年 11 月 25 日
**サービス**: Amazon Elastic Compute Cloud (Amazon EC2)
**機能**: AWS Graviton5 プロセッサ搭載 C9g インスタンスのリージョン拡大

📊 [このアップデートのインフォグラフィックを見る](https://takech9203.github.io/aws-news-summary/20261125-amazon-ec2-c9g-instances-additional-regions.html)

## 概要

AWS Graviton5 プロセッサを搭載した Amazon EC2 C9g インスタンスが、アジアパシフィック (シドニー)、欧州 (アイルランド)、欧州 (スペイン)、南米 (サンパウロ) の 4 リージョンで新たに利用可能になりました。Graviton5 は AWS がカスタム設計した第 5 世代 CPU であり、コンピューティング負荷の高いワークロードに対して Amazon EC2 上で最高のコストパフォーマンスを提供します。

C9g インスタンスは、Graviton4 ベースの C8g インスタンスと比較して最大 25% 高いコンピューティング性能を実現し、データベースで最大 30%、Web アプリケーションで最大 35%、機械学習で最大 35% の高速化を達成します。第 6 世代 AWS Nitro System 上に構築されており、Nitro Isolation Engine を初めて搭載した世代のインスタンスです。Nitro Isolation Engine は形式的検証 (formal verification) を活用し、お客様のワークロードが相互に、および AWS オペレーターから分離されていることを数学的に保証します。

HPC、バッチ処理、ゲーミング、動画エンコーディング、科学技術モデリング、分散分析、CPU ベースの機械学習 (ML) 推論、リアルタイム分析、広告配信などのコンピューティング集約型ワークロードが想定されています。

**アップデート前の課題**

- C9g インスタンスはシドニー、アイルランド、スペイン、サンパウロの各リージョンで提供されておらず、これらのリージョンのワークロードで Graviton5 の性能を活用できなかった
- オセアニア、欧州、南米のデータレジデンシー要件や低レイテンシー要件のあるワークロードでは、他リージョンの C9g を利用しにくかった
- これらのリージョンでは Graviton4 ベースの C8g が最新の選択肢であり、さらなるコストパフォーマンス向上の余地があった

**アップデート後の改善**

- アジアパシフィック (シドニー)、欧州 (アイルランド)、欧州 (スペイン)、南米 (サンパウロ) の各リージョンで C9g インスタンスを起動できるようになり、C8g 比で最大 25% の性能向上を活用可能になった
- 各地域内でデータを保持したまま、コンピューティング集約型ワークロードを Graviton5 で実行できるようになった
- Nitro Isolation Engine による形式的検証に基づく分離保証を、これらのリージョンのワークロードでも利用可能になった

## サービスアップデートの詳細

### 主要機能

1. **4 リージョンでの提供開始**
   - AWS Graviton5 搭載の C9g インスタンスがアジアパシフィック (シドニー)、欧州 (アイルランド)、欧州 (スペイン)、南米 (サンパウロ) の各リージョンで利用可能に
   - 各地域のユーザーやシステムに近い場所で、低レイテンシーを維持しながら Graviton5 の性能を活用できる
   - Savings Plans、オンデマンド、スポットインスタンス、Dedicated Instances、Dedicated Hosts で購入可能

2. **AWS Graviton5 プロセッサによる性能向上**
   - C8g 比でコンピューティング性能が最大 25% 向上
   - データベースで最大 30%、Web アプリケーションで最大 35%、機械学習で最大 35% 高速化
   - コンピューティング負荷の高いワークロードで Amazon EC2 上最高のコストパフォーマンスを提供

3. **Nitro Isolation Engine**
   - 第 6 世代 AWS Nitro System 上に構築され、Nitro Isolation Engine を初めて搭載
   - 形式的検証により、ワークロードが相互に、および AWS オペレーターから分離されていることを数学的に保証

## 設定方法

### 前提条件

1. AWS アカウントを保有し、アジアパシフィック (シドニー: ap-southeast-2)、欧州 (アイルランド: eu-west-1)、欧州 (スペイン: eu-south-2)、南米 (サンパウロ: sa-east-1) のいずれかのリージョンで EC2 インスタンスを起動できる IAM 権限があること
2. Arm64 (aarch64) アーキテクチャに対応した AMI を使用すること
3. 必要に応じて、対象アプリケーションが Arm アーキテクチャで動作することを事前に検証しておくこと

### 手順

#### ステップ 1: 利用可能なインスタンスタイプを確認する

```bash
aws ec2 describe-instance-type-offerings \
  --region ap-southeast-2 \
  --filters "Name=instance-type,Values=c9g.*" \
  --query "InstanceTypeOfferings[].InstanceType" \
  --output table
```

アジアパシフィック (シドニー) リージョンで提供されている C9g のインスタンスサイズの一覧を取得します。他のリージョンを確認する場合は `--region eu-west-1`、`--region eu-south-2`、`--region sa-east-1` のように指定します。

#### ステップ 2: Arm64 対応の AMI を確認する

```bash
aws ec2 describe-images \
  --region ap-southeast-2 \
  --owners amazon \
  --filters "Name=name,Values=al2023-ami-2023*-arm64" "Name=state,Values=available" \
  --query "sort_by(Images, &CreationDate)[-1].{ImageId:ImageId,Name:Name}" \
  --output table
```

対象リージョンで利用可能な最新の Arm64 版 Amazon Linux 2023 AMI を検索します。

#### ステップ 3: C9g インスタンスを起動する

```bash
aws ec2 run-instances \
  --region ap-southeast-2 \
  --instance-type c9g.xlarge \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --key-name my-key-pair \
  --subnet-id subnet-xxxxxxxx \
  --security-group-ids sg-xxxxxxxx
```

ステップ 2 で確認した Arm64 対応 AMI を指定し、アジアパシフィック (シドニー) リージョンで c9g.xlarge インスタンスを起動します。起動後は既存の C8g や x86 ベースのワークロードと性能を比較し、移行効果を確認します。

## メリット

### ビジネス面

- **各地域のワークロードのコストパフォーマンス向上**: C8g 比で最大 25% の性能向上により、同一ワークロードをより少ないリソースで実行し、コストを削減できる
- **データレジデンシー要件への対応**: オーストラリア、欧州、ブラジルの各地域内でデータを保持したまま、最新世代の Graviton5 インスタンスを利用できる
- **柔軟な購入オプション**: Savings Plans やスポットインスタンスなど複数の購入モデルにより、コスト最適化の選択肢が広い

### 技術面

- **ワークロード別の大幅な高速化**: データベースで最大 30%、Web アプリケーションで最大 35%、機械学習で最大 35% の高速化を実現
- **形式的検証に基づく分離**: Nitro Isolation Engine により、ワークロード間および AWS オペレーターからの分離を数学的に保証
- **低レイテンシーの地域展開**: 各地域のエンドユーザーに近いリージョンで高性能なコンピューティングを提供可能

## デメリット・制約事項

### 制限事項

- Arm アーキテクチャ (AWS Graviton) ベースであるため、x86 依存のバイナリや商用ソフトウェアは Arm 向けのビルド・ライセンス確認・検証が必要
- 本発表は C9g インスタンスのリージョン拡大であり、今回追加されたのはシドニー、アイルランド、スペイン、サンパウロの 4 リージョン
- C9g は EBS のみのストレージ構成であり、ローカル NVMe ストレージが必要な場合は C9gd を選択する必要がある (C9gd の提供リージョンは別途確認が必要)

### 考慮すべき点

- 既存の C8g や x86 ベースワークロードから移行する場合は、性能・互換性の検証を事前に実施することが推奨される
- 新しいインスタンスファミリーはリージョンやアベイラビリティーゾーンによって在庫状況が異なる場合があるため、大規模利用時はキャパシティの確保方法 (オンデマンドキャパシティ予約など) を検討する
- スポットインスタンスの供給量や割引率はリージョン・サイズによって変動するため、利用前に Spot Instance Advisor などで確認する

## ユースケース

### ユースケース 1: オセアニア向けゲーミング / リアルタイム処理基盤

**シナリオ**: オーストラリア・ニュージーランドのプレイヤー向けにゲームサーバーを運用しており、低レイテンシーを維持しながらサーバーコストを削減したい事業者。

**実装例**:
```
アジアパシフィック (シドニー) リージョンのゲームサーバーフリートを
c8g から c9g に変更し、同時接続数あたりの性能とコストを比較検証する
```

**効果**: C8g 比で最大 25% の性能向上により、同一プレイヤー数をより少ないインスタンス数で収容でき、レイテンシーを維持しながらコストを削減できます。

### ユースケース 2: 欧州のデータレジデンシー要件に対応した分析基盤

**シナリオ**: 欧州 (アイルランド、スペイン) リージョンで分散分析やバッチ処理を実行しており、データを欧州域内に保持したまま処理性能を向上させたい企業。

**実装例**:
```
Amazon EMR や AWS Batch のコンピューティング環境に c9g インスタンスを追加し、
既存の c8g ノードと処理スループットを比較して段階的に移行する
```

**効果**: 欧州域内でデータを保持したまま、分析ジョブの処理時間を短縮できます。スポットインスタンスと組み合わせることでコストをさらに抑制できます。

### ユースケース 3: 南米向け Web アプリケーション / ML 推論

**シナリオ**: ブラジルのユーザー向けに Web アプリケーションと CPU ベースの ML 推論 API を提供しており、応答性能の改善と推論コストの削減が課題となっているアプリケーション。

**実装例**:
```
Amazon ECS / Amazon EKS のノードグループに南米 (サンパウロ) リージョンの
c9g インスタンスを追加し、Arm64 対応コンテナをデプロイして性能を検証する
```

**効果**: Web アプリケーションで最大 35%、機械学習で最大 35% の高速化により、南米ユーザー向けの低レイテンシーを維持しながらインフラコストを削減できます。

## 関連サービス・機能

- **AWS Graviton**: C9g を支える AWS カスタム設計 CPU ファミリー。第 5 世代の Graviton5 を搭載
- **AWS Nitro System**: 第 6 世代 Nitro System 上に構築。Nitro Isolation Engine による形式的検証ベースの分離を提供
- **Amazon EC2 C9gd インスタンス**: C9g にローカル NVMe SSD を追加したバリアント。高速なローカルストレージが必要な場合に選択
- **Amazon EC2 Savings Plans**: C9g のコスト最適化に活用できる柔軟な料金モデル
- **Amazon EC2 Auto Scaling / AWS Batch**: C9g を組み込んだスケーラブルなコンピューティング基盤の構築に活用
