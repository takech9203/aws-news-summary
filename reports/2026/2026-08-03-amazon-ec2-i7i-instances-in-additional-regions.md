# Amazon EC2 - I7i インスタンスがアジアパシフィック (タイ) およびイスラエル (テルアビブ) リージョンで利用可能に

**リリース日**: 2026 年 8 月 3 日
**サービス**: Amazon EC2
**機能**: ストレージ最適化 I7i インスタンス

📊 [このアップデートのインフォグラフィックを見る](https://takech9203.github.io/aws-news-summary/20260803-amazon-ec2-i7i-instances-in-additional-regions.html)

## 概要

AWS は、高性能なストレージ最適化インスタンスである Amazon EC2 I7i インスタンスを、アジアパシフィック (タイ) リージョンおよびイスラエル (テルアビブ) リージョンで利用可能にしたことを発表しました。I7i インスタンスは、第 5 世代 Intel Xeon プロセッサを搭載し、全コアターボ周波数 3.2 GHz で動作します。前世代の I4i インスタンスと比較して、最大 23% 高いコンピューティング性能と 10% 以上優れた価格性能を提供します。

ストレージ面では、第 3 世代 AWS Nitro SSD を採用しており、最大 45TB の NVMe ストレージを利用できます。I4i インスタンスと比較して、最大 50% 優れたリアルタイムストレージ性能、最大 50% 低いストレージ I/O レイテンシー、最大 60% 低いストレージ I/O レイテンシーのばらつきを実現しています。

I7i インスタンスは、非常に高いランダム IOPS 性能とリアルタイムのレイテンシーを必要とする、I/O 集約型かつレイテンシーに敏感なワークロードに最適です。小規模から中規模のデータセットへのアクセスを伴うデータベースやリアルタイム分析などのワークロードを対象としています。今回の 2 リージョンへの拡大により、タイやイスラエルでデータレジデンシー要件を持つお客様も、これらの高性能インスタンスを利用できるようになりました。

**アップデート前の課題**

- アジアパシフィック (タイ) およびイスラエル (テルアビブ) リージョンでは、最新世代のストレージ最適化 I7i インスタンスを利用できませんでした。
- 両リージョンでデータレジデンシー要件を持つお客様は、I7i の高いストレージ性能を活用できませんでした。
- I/O 集約型ワークロードにおいて、前世代インスタンスのストレージ I/O レイテンシーやそのばらつきがボトルネックとなる場合がありました。

**アップデート後の改善**

- アジアパシフィック (タイ) およびイスラエル (テルアビブ) リージョンで I7i インスタンスを利用できるようになり、最新世代のストレージ性能を活用できます。
- 前世代の I4i と比較して、最大 23% 高いコンピューティング性能と 10% 以上優れた価格性能を享受できます。
- Torn Write Prevention 機能により、最大 16KB のブロックサイズに対応し、データベースの性能ボトルネックを解消できます。

## サービスアップデートの詳細

### 主要機能

1. **第 5 世代 Intel Xeon プロセッサ**
   - 全コアターボ周波数 3.2 GHz で動作する第 5 世代 Intel Xeon プロセッサを搭載しています。
   - 前世代 I4i インスタンスと比較して、最大 23% 高いコンピューティング性能を提供します。
   - 10% 以上優れた価格性能を実現しています。

2. **第 3 世代 AWS Nitro SSD ストレージ**
   - 最大 45TB の NVMe ストレージを提供します。
   - I4i と比較して、最大 50% 優れたリアルタイムストレージ性能を実現します。
   - 最大 50% 低いストレージ I/O レイテンシーと、最大 60% 低いレイテンシーのばらつきを提供します。

3. **Torn Write Prevention (TWP)**
   - 最大 16KB のブロックサイズの書き込みアトミシティをサポートします。
   - データベースの性能ボトルネックの解消に寄与します。

4. **高いネットワークおよび EBS 帯域幅**
   - 最大 100Gbps のネットワーク帯域幅を提供します。
   - 最大 60Gbps の Amazon Elastic Block Store (EBS) 帯域幅を提供します。

## 技術仕様

### インスタンスサイズ

I7i インスタンスは、9 つの仮想サイズ (最大 48xlarge) と 2 つのベアメタルサイズの合計 11 サイズで提供されます。

| 項目 | 詳細 |
|------|------|
| プロセッサ | 第 5 世代 Intel Xeon、全コアターボ 3.2 GHz |
| ローカルストレージ | 第 3 世代 AWS Nitro SSD、最大 45TB NVMe |
| インスタンスサイズ | 仮想 9 サイズ (最大 48xlarge) + ベアメタル 2 サイズ |
| ネットワーク帯域幅 | 最大 100Gbps |
| EBS 帯域幅 | 最大 60Gbps |
| Torn Write Prevention | 最大 16KB ブロックサイズをサポート |

## 設定方法

### 前提条件

1. アジアパシフィック (タイ) またはイスラエル (テルアビブ) リージョンを利用できる AWS アカウント。
2. I7i インスタンスを起動するための EC2 関連の IAM 権限。
3. 適切な VPC、サブネット、セキュリティグループの構成。

### 手順

#### ステップ1: 利用可能なインスタンスタイプの確認

```bash
aws ec2 describe-instance-type-offerings \
  --location-type availability-zone \
  --filters "Name=instance-type,Values=i7i.*" \
  --region ap-southeast-7
```

このコマンドは、アジアパシフィック (タイ) リージョンで利用可能な I7i インスタンスタイプの一覧をアベイラビリティーゾーン単位で確認します。イスラエル (テルアビブ) リージョンの場合は `--region il-central-1` を指定します。

#### ステップ2: I7i インスタンスの起動

```bash
aws ec2 run-instances \
  --image-id ami-xxxxxxxxxxxxxxxxx \
  --instance-type i7i.4xlarge \
  --key-name my-key-pair \
  --region ap-southeast-7
```

このコマンドは、アジアパシフィック (タイ) リージョンで i7i.4xlarge インスタンスを起動します。実際の利用時には、適切な AMI ID、キーペア、サブネット、セキュリティグループを指定してください。

#### ステップ3: ローカル NVMe ストレージの準備

起動後、インスタンスストアボリュームはマウントされていない状態のため、ファイルシステムの作成とマウントを行います。データベースや分析エンジンのデータ配置先として、低レイテンシーのローカル NVMe ストレージを活用できます。

## メリット

### ビジネス面

- **価格性能の向上**: 前世代 I4i と比較して 10% 以上優れた価格性能により、同等のワークロードをより低コストで実行できます。
- **データレジデンシー対応**: タイおよびイスラエル国内でのデータ保管要件を満たしつつ、高性能インスタンスを利用できます。
- **ユーザー体験の改善**: 東南アジアや中東のエンドユーザーに近い場所で低レイテンシーなサービスを提供できます。

### 技術面

- **高いストレージ性能**: 最大 45TB の NVMe ストレージと最大 50% 低い I/O レイテンシーにより、I/O 集約型ワークロードを高速化できます。
- **レイテンシーの安定性**: 最大 60% 低いストレージ I/O レイテンシーのばらつきにより、リアルタイム処理の予測可能性が向上します。
- **データベース性能の改善**: Torn Write Prevention により最大 16KB ブロックサイズの書き込みアトミシティが保証され、データベースの性能ボトルネックを解消できます。

## デメリット・制約事項

### 制限事項

- インスタンスストア (ローカル NVMe) は揮発性ストレージのため、インスタンスの停止や終了時にデータが失われます。永続化が必要なデータは EBS や S3 などに保存する必要があります。
- 最大のネットワーク帯域幅 (100Gbps) および EBS 帯域幅 (60Gbps) は、大きいインスタンスサイズでのみ利用できます。

### 考慮すべき点

- ローカルストレージを前提とするため、ワークロードのデータ永続化戦略を検討する必要があります。
- I7i は I/O 集約型ワークロード向けに最適化されており、CPU やメモリ中心のワークロードには他のインスタンスファミリーの方が適している場合があります。

## ユースケース

### ユースケース1: 高性能リレーショナルデータベース

**シナリオ**: タイまたはイスラエル国内でデータを保管する必要がある MySQL や PostgreSQL、SQL Server などのデータベースを、低レイテンシーかつ高 IOPS で運用したいケース。

**効果**: ローカル NVMe ストレージと Torn Write Prevention により、書き込み性能のボトルネックを解消し、トランザクション処理を高速化できます。

### ユースケース2: NoSQL データベースとリアルタイム分析

**シナリオ**: Cassandra、MongoDB、Redis などの NoSQL データベースや、リアルタイム分析基盤を現地リージョンで運用するケース。

**効果**: 高いランダム IOPS とリアルタイムのレイテンシーにより、大量のデータストリームを安定して処理できます。

### ユースケース3: 検索エンジンとインデックス処理

**シナリオ**: Elasticsearch や OpenSearch などの検索エンジンを運用し、小規模から中規模のデータセットに高速アクセスするケース。

**効果**: 大規模なインデックスへの高速アクセスにより、インデックス構築やクエリ応答時間を短縮できます。

## 料金

I7i インスタンスは、オンデマンド、Savings Plans、リザーブドインスタンス、スポットインスタンスの各購入オプションで利用できます。料金はリージョンとインスタンスサイズによって異なります。最新の料金は、Amazon EC2 の料金ページで確認してください。

## 利用可能リージョン

今回のアップデートにより、I7i インスタンスは以下のリージョンで新たに利用可能になりました。

- アジアパシフィック (タイ) リージョン
- イスラエル (テルアビブ) リージョン

その他の利用可能リージョンについては、AWS の公式ドキュメントを確認してください。

## 関連サービス・機能

- **Amazon EBS**: I7i インスタンスは最大 60Gbps の EBS 帯域幅を提供し、永続データの保存先として利用できます。
- **AWS Nitro System**: 第 3 世代 AWS Nitro SSD によって高いストレージ性能とセキュリティを実現しています。
- **Amazon EC2 I7ie インスタンス**: より大容量のストレージを必要とするワークロード向けの派生ファミリーです。
