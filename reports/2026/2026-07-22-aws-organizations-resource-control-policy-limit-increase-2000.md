# AWS Organizations - リソースコントロールポリシー (RCP) の上限を組織あたり 2,000 に引き上げ

**リリース日**: 2026 年 7 月 22 日
**サービス**: AWS Organizations
**機能**: リソースコントロールポリシー (RCP) のクォータ引き上げ

## 概要

AWS Organizations は、組織あたりのリソースコントロールポリシー (RCP) の上限を、従来の 1,000 から 2 倍の 2,000 に引き上げました。RCP は、組織内のメンバーアカウントに存在するリソースに対して、利用可能な最大権限を一元的に管理するためのポリシーです。今回のクォータ引き上げにより、大規模で複雑なマルチアカウント環境を管理するお客様は、ポリシー数の上限に達することなく、よりきめ細かなリソースアクセス制御を定義できるようになります。

RCP を使用すると、組織のメンバーアカウントにまたがるリソースに対して、どの外部プリンシパルがアクセスできるかを制限できます。これにより、個々のリソースベースポリシーを更新することなく、組織全体のアクセス制御ガイドラインを大規模に適用できます。特に、数百のアカウントにまたがる詳細で一元的な権限管理を必要とする組織にとって価値が高く、従来の 1,000 ポリシーという上限が障壁となっていた課題を解消します。

引き上げ後の 2,000 RCP という上限は、AWS Organizations がサポートされるすべての AWS リージョンで追加費用なしで利用できます。お客様側での対応は不要で、既存の組織は自動的に引き上げ後の上限を利用できます。

**アップデート前の課題**

- 従来は組織あたり最大 1,000 個の RCP しか作成できず、大規模なマルチアカウント環境ではポリシー数の上限に達する可能性があった
- 数百のアカウントを持つ組織で、きめ細かいアクセス制御を定義しようとすると、ポリシー数の制限が障壁となっていた
- 上限に達した場合、複数の制御ルールを 1 つのポリシーに集約するなどの運用上の工夫が必要だった

**アップデート後の改善**

- 組織あたりの RCP 上限が 2,000 に倍増し、より多くのポリシーを作成できるようになった
- より詳細で粒度の細かいリソースアクセス制御を、上限を気にせず定義できるようになった
- 既存の組織は自動的に新しい上限を利用でき、追加の設定や費用は不要になった

## サービスアップデートの詳細

### 主要機能

1. **RCP クォータの倍増**
   - 組織あたりの RCP 上限が 1,000 から 2,000 に引き上げられた
   - 全機能が有効化された組織 (all features enabled) で利用可能
   - 追加費用なしで、AWS Organizations がサポートされる全リージョンで利用できる

2. **自動適用**
   - お客様側での対応は不要
   - 既存の組織は自動的に引き上げ後の上限にアクセスできる
   - ポリシーの再作成や移行作業は発生しない

3. **大規模環境でのきめ細かいアクセス制御**
   - 数百のアカウントにまたがる一元的な権限管理を、ポリシー数の制約なく実現
   - 外部プリンシパルによるリソースアクセスの制限を、より粒度細かく定義可能

## 技術仕様

### RCP の基本概念

RCP (Resource Control Policy) は、AWS Organizations が提供する組織ポリシーの一種で、メンバーアカウント内のリソースに対する「最大権限のガードレール」を設定します。SCP との使い分けは以下のとおりです。

| 項目 | 詳細 |
|------|------|
| RCP の役割 | 組織外部の IAM プリンシパルからメンバーアカウント内のリソースへのアクセスを制限する |
| SCP の役割 | 組織内メンバーアカウントの IAM プリンシパルの権限を制限する |
| 権限付与 | RCP は権限を付与しない。あくまで利用可能な最大権限の上限 (ガードレール) を定義する |
| 実効権限 | RCP/SCP で許可された権限と、アイデンティティベース/リソースベースポリシーで許可された権限の論理積 (intersection) |
| 適用対象 | メンバーアカウントのリソースのみ。管理アカウントのリソースには影響しない |
| アタッチ先 | 組織のルート、OU、個別アカウントに直接アタッチ可能 (継承される) |
| 対象サービス | Amazon S3、Amazon SQS、AWS KMS、AWS Secrets Manager、AWS STS など、RCP をサポートするサービスのサブセット |

### RCP の適用範囲に関する注意点

- **管理アカウントは対象外**: RCP はメンバーアカウントのリソースにのみ影響し、管理アカウントのリソースには適用されない (委任管理者に指定されたメンバーアカウントには適用される)
- **サービスリンクロールは対象外**: サービスリンクロールによる呼び出しには RCP は適用されない
- **AWS マネージドキーは対象外**: AWS KMS の AWS マネージドキーには RCP が適用されない
- **クォータの引き上げは上限値の変更のみ**: RCP の構文、評価ロジック、サポート対象サービスなどの仕様は変更されていない

## メリット

### ビジネス面

- **大規模組織のガバナンス強化**: 数百のアカウントを持つ組織でも、ポリシー数の制約なく組織全体のアクセス制御ガイドラインを適用できる
- **追加コストなし**: 上限引き上げは追加費用なしで提供され、コスト増を伴わずにガバナンスを拡張できる
- **運用負荷の軽減**: 個々のリソースベースポリシーを更新することなく、一元的な制御を実現できる

### 技術面

- **きめ細かい制御**: 1 つのポリシーに複数のルールを詰め込む必要がなくなり、目的ごとに整理された RCP を作成できる
- **対応不要の自動適用**: 既存組織は自動的に新しい上限を利用でき、移行作業が発生しない
- **スケーラビリティ**: マルチアカウント環境の成長に合わせて、より多くのアクセス制御ポリシーを定義できる

## デメリット・制約事項

### 制限事項

- 全機能が有効化された組織 (all features enabled) でのみ RCP を利用できる。一括請求機能のみを有効にした組織では利用できない
- RCP は管理アカウント、サービスリンクロール、AWS マネージドキーには適用されない
- RCP はサポート対象サービスのサブセットにのみ適用される (すべての AWS サービスが対象ではない)

### 考慮すべき点

- RCP を組織のルートに直接アタッチする前に、テストアカウントや下位の OU から段階的に適用し、影響範囲を十分に検証することが強く推奨される
- 影響の確認方法として、AWS CloudTrail のログで Access Denied エラーをレビューする手法が有効
- ポリシー数が増えるほど、ポリシーの管理・棚卸しの運用設計が重要になる

## ユースケース

### ユースケース1: 大規模マルチアカウント環境での外部アクセス制御

**シナリオ**: 数百のアカウントを持つ企業が、S3 バケットや KMS キーへの組織外プリンシパルからのアクセスを、アカウントやチームごとに細かく制限したい。従来は 1,000 ポリシーの上限に近づいていた。

**効果**: 上限が 2,000 に引き上げられたことで、各チームやワークロードの要件に応じた個別の RCP を、上限を気にせず定義できる。

### ユースケース2: コンプライアンス要件に基づくきめ細かいガードレール

**シナリオ**: 規制産業の組織が、リソースごとに異なるコンプライアンス要件 (例: 特定リージョンへのアクセス制限、特定の VPC エンドポイント経由のみ許可など) を RCP で表現したい。

**効果**: 要件ごとに整理された RCP を作成でき、1 つの巨大なポリシーに集約する必要がなくなるため、可読性と保守性が向上する。

### ユースケース3: 組織構造の拡大に伴うポリシー拡張

**シナリオ**: M&A やチーム増加によりアカウント数が急増し、新しい OU やアカウントに対する RCP を追加していく必要がある。

**効果**: RCP の上限に余裕が生まれることで、組織の成長に合わせてアクセス制御ポリシーを継続的に拡張できる。

## 料金

RCP の利用およびクォータ引き上げは追加費用なしで提供されます。AWS Organizations 自体も無料で利用できます。

## 利用可能リージョン

AWS Organizations がサポートされるすべての AWS リージョンで利用可能です。お客様側での対応は不要で、既存の組織は自動的に引き上げ後の上限 (2,000) を利用できます。

## 関連サービス・機能

- **サービスコントロールポリシー (SCP)**: 組織内メンバーアカウントの IAM プリンシパルの権限を制限するポリシー。RCP と組み合わせて実効権限を定義する
- **AWS IAM**: RCP はリソースベースポリシーに最も近い IAM ポリシーの一種であり、IAM の権限評価ロジックの一部として機能する
- **AWS CloudTrail**: RCP 適用による Access Denied エラーの確認に利用でき、影響範囲の検証に役立つ
- **AWS KMS / Amazon S3 / AWS Secrets Manager など**: RCP のサポート対象サービス。これらのリソースへの外部プリンシパルからのアクセスを制御できる
